## 内核真机启动修复（QEMU 11.1.0，从三重故障到 boot complete）
按崩溃顺序逐一修掉 8 个启动阻塞缺陷，最终 QEMU 实测跑到 `boot complete — halting`，
13/13 启动自检 + 各域自检（cpu 9/9、mem 10/10、sched 9/9、proc 11/11、storage 10/10、
input 9/9、display 10/10、net 15/15、security 15/15）全绿；开中断后 20s 内稳定处理
10200+ 次定时器中断无异常。

1. `cpu/gdt.rs` `reload_segments()`：`push {sel:x}` 中 SEL_KERNEL_CODE 是 u16 → 实际只
   `push ax`（RSP -2），而 `retfq` 弹 16 字节 → 栈永久错位 +6，后续 kinfo! 格式化整数时
   解引用垃圾指针 #PF → 三重故障。改为 `push {sel}` + `SEL_KERNEL_CODE as u64`。
2. `cpu/apic.rs` / `cpu/clock.rs`：LAPIC/IOAPIC/HPET 的 MMIO 直接用了物理地址，高半区内核
   必须过 `mem::paging::phys_to_virt()`。修 `ApicBase::mmio_vaddr()`、`IoApic::attach()`、`Hpet::init()`。
3. `platform.rs` + `cpu/cpuinfo.rs`：cpuinfo 硬编码 `osxsave/xsave = true`，qemu64 无 XSAVE，
   `mov cr4,rax` 触发 #GP 死循环。Features 增加 xsave/osxsave（CPUID leaf1 ECX bit26/27）。
4. `mem/pmm.rs` + `mem.rs`：`FrameBitmap` 是 [u64;8192] = 64KB，boot_bitmaps 栈上放两份 +
   pmm::init 再 clone 一份 = 192KB，超出 Limine 64KB 启动栈 → 页表被踩坏。改为 static
   存储（USABLE/RESERVED/MERGED_MAP），`pmm::init()` 改为无参。宿主测试不炸是因为宿主栈 1MB。
5. `display.rs`：`fps: CLOCK.lock().fps(), worst_frame_us: CLOCK.lock().worst_us()` 同一语句
   里两个临时 guard 活到语句末 → 自旋锁自死锁。改单 guard 块。
6. `smbios.rs`：`next_struct_offset` 用单 NUL 计数，遇到无字符串的结构体（如 type 16）就
   错位。SMBIOS 规范字符串区即使为空也是两个 NUL，改为扫描连续双 NUL。
7. `cpu/idt.rs`：IDTR 指向了 Rust 结构体数组而非 16 字节门描述符 → 首个硬件中断 #GP(0x102)
   三重故障。Idt 增加 `wire: UnsafeCell<[[u64;2];256]>`，set() 写入 wire 表，descriptor()
   指向 wire 表。
8. `cpu/idt.rs` + `linker.ld`：stub 表在 `.data`（Limine 映射为 NX）→ 中断入口 `e=0x11`
   取指保护违例。linker.ld 新增页对齐 `.stubs` 段，STUBS 用
   `#[cfg_attr(target_os="none", link_section=".stubs")]`；生成完代码后
   `harden_stub_mapping()` 走 CR3+HHDM 页表把该页清 NX、清 P_WRITE 收紧成 R-X（大页则只清 NX）。
9. `cpu/idt.rs` `common_entry()`：只保存了 rbp，而 `isr_dispatch` 是 C ABI 会破坏
   RAX/RCX/RDX/RSI/RDI/R8-R11 → 定时器中断落在 `core::fmt::write` 里，返回后写者指针已死 →
   #PF(CR2=0x3c84)。改为完整保存 9 个易失寄存器；注意新增 9 次 push 后恢复要用
   `mov rsp,rbp; sub rsp,72`（只 `mov rsp,rbp` 会让 iretq 报 #GP(0)）。
10. `cpu/idt.rs` 可观测性：致命异常现在打印 `err / rip / cr2`（`has_error_code` 判断错误码
    是否入栈以定位 RIP 偏移），否则只有 "fatal exception 14" 无法定位。

### 本会话踩到的坑（值得记）
- **CheckSet 断言里的"末态读取"陷阱（反复踩了 5 次）**：`set.add("…", cond1 && obj.field == X, …)` 里对可变对象字段的读取**全部发生在表达式求值末尾**，即读到的是**末态**。凡是"操作→读状态→再操作"的写法必须先把中间读数存进独立 `let` 变量。本次 F158/F159/F164/F165/F183/F185/F186/F190/F191 都是这么挂的。

### 本会话踩到的坑（值得记）
- **`Result<&mut T, E>` 不能 `assert_eq!(…, Err(e))`**：`&mut T` 不实现 `PartialEq`/`Debug`，`Option<Result<(), E>>` 之类的嵌套比较也会连带失败。改用 `is_err()` 或先解引用取值。
- **非 `Copy` 类型的数组重复初始化**：`[None; N]` 要求 `Option<T>: Copy`；`T` 非 Copy 时必须写 `[const { None }; N]`（inline const block）。
- **探针/单测里的"读取顺序"再次咬人**：同一个 `buf` 先做 round-trip 断言、再被 partial-copy 写入，断言就变成读末态。凡是"断言 A 的缓冲"和"会被后续操作覆写的缓冲"必须分开。
- **fuzz 必须偏置到有效号段**：纯 `u64` 随机数落在 `0x4000-0x40FF` 的概率是 256/2^64 ≈ 0，于是每轮都进 `ENOSYS`，处理体一次都没被跑到。正确做法是 1/4 完全野生、1/4 原生带 `BASE + rng%40`、1/4 兼容带、1/4 低位全谱——否则"零 panic"是空证明。
- **`const fn` 里不能用 `Ord::min`**（`1u64 << kind.min(63)` 报 E0658「Ord 还不是 const trait」）。手写 `if kind > 63 { 63 } else { kind }`。
- **内层 crate 自带 `[workspace]`**：`kernel/userspace/varix-std` 在 `kernel/` 的 workspace 目录树内又不是成员，会报「believes it's in a workspace when it's not」；给它加一个空 `[workspace]` 表即可自成一棵。`.gitignore` 同步加 `kernel/userspace/*/target/`。
- **清"未用导入"告警要连带查测试模块**：从 `addrspace.rs` 顶部删掉 `P_PRESENT` 后，`#[cfg(test)] mod tests` 里还在用它 → E0425。正确做法是把导入下沉到 `mod tests` 里（`use crate::mem::paging::P_PRESENT;`）。
- **共享文件被并行会话 `git add .` 卷走**：本会话的源文件被 AI-04~08 的提交 61a135c 一起提交了。提交前务必 `git log --oneline -1` + `git status` 复查，判断"我的改动是否已在 HEAD"，避免重复提交或漏提交。
