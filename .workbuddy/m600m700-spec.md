# M600/M700 域模块施工规范（AI-01~AI-10 通用，2026-09-12）

本文件是给并行实现代理的统一规范。目标：在 `kernel/varix/src/` 新增域模块文件，
风格与既有 `m5boot.rs` / `m400boot.rs` 完全一致。

## 硬性规则
1. **只创建自己的一个文件** `kernel/varix/src/<模块名>.rs`。
   **禁止**修改 lib.rs、robust.rs、checks.rs、其他域文件、docs/ 下任何文件（集成由主会话完成）。
2. no_std 安全：**禁止** `Vec` / `String` / `Box` / `alloc` / `std` / 懒静态。
   全部固定容量数组；`Option<T>` 数组初始化必须写 `[const { None }; N]`。
3. `const fn` 内禁止 `Ord::min/max`（E0658），手写 `if`。
4. 不得 `panic!`/`unwrap`/`expect` 出现在非测试代码路径；接口失败一律返回 `bool`/`Option`/`Result<_, &'static str>`（`Result<&mut T,_>` 不可 `assert_eq!`，`&mut T` 无 PartialEq/Debug）。
5. 域内自包含：只 `use crate::checks::CheckSet;`，不依赖其他域模块。
6. 模块头：`//! VARIX-M6XX AI-XX <域名>域（Fxxx~Fyyy，Wx/Kx）。` + 2~4 行中文定位说明。

## 25 项功能结构
- 按全景图逐项定义实现；每项一个分区注释 `// Fxxx — <功能名>`（`// Fxxx —` 短横线后接名称）。
- 每项 = 核心数据结构（`pub struct`，`Copy`，固定容量）+ 操作方法 + **至少一个仪表**
  （计数器/直方图/水位线字段或方法，如 `pub fn stats()` / `count` / `peak`）。
- 实现质量对标 m5boot.rs：结构体方法齐全、语义真实（不是空壳）、有洞察类方法
  （top/gap/percentile 类）。行数参考 1100~1500 行。
- 登记类接口（register/record/add）必须自带去重（重复登记返回 false 或更新原条目，不得静默膨胀计数）。

## 自检（必须）
- 导出 `pub fn run_<模块名去m前缀>_checks() -> CheckSet`（如 `m600boot` → `run_m600boot_checks`；
  `m700proc` → `run_m700proc_checks`）。用 `CheckSet::new("<模块名>")` + `set.add("Fxxx …", cond, "detail")`。
- **≥ 26 条 add**：25 个功能各至少 1 条 + 仪表/边界若干。断言真实操作后的状态，不是恒真。
- **末态读取铁律**：`set.add("…", a && obj.field == X, …)` 中对可变对象的字段读取发生在
  表达式求值末尾。凡"操作→读状态→再操作→断言"，中间读数必须先 `let` 存进独立变量再参与布尔表达式。
- 自检不通过会 panic 出 `CheckSet::render` 内容，因此断言必须真实可过。

## 单测（必须）
- 模块内 `#[cfg(test)] mod tests`，测试名 `f<编号>_<要点>`（如 `f001_bucket_attribution`）。
- 25 项每项至少 1 条单测（可合并相近项，但覆盖全部 25 个 F 编号）。
- 测试里同样遵守末态读取铁律；`Result<&mut T,E>` 用 `is_err()` 断言。

## 完成判据
文件写完即算交付；编译与 `cargo ktest --lib` 由主会话统一跑。若你能在本地编译验证更好
（`cd kernel && RUSTUP_TOOLCHAIN=1.97.1-x86_64-pc-windows-msvc cargo kcheck` 需要 lib.rs 挂载，
故挂载前无法整体验证——改为自查代码：类型、借用、无 std 依赖、数组初始化语法）。
