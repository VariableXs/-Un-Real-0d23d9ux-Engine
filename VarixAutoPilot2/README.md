# VarixAutoPilot 2 · Tauri 版

**一句话**：识别你开了几个 WorkBuddy 对话、每个对话用的什么模型、在哪个文件夹工作，
把提示词安全地填进输入框并点发送——做成**离线单 exe**，双击即用，不开浏览器。

> 上一版（Node + localhost 服务）已完成功能验证并**整体迁移到 Rust/Tauri**，
> 代码备份在 `_attic/2026-10-04-ve-产线/VarixAutoPilot-Node版备份/`。

---

## 一、给 AI 的执行清单（照做即可，无需再问）

1. 读本文件 → 知道有这套工具；
2. 造提示词：跑 `python VarixTaskOps/emit_next_prompt.py` 生成 `_next_prompt.md`；
3. 打开控制台 → 「变量」区填 `任务` / `上下文`（内容取自 `_next_prompt.md`）；
4. 点「预览」确认无残留占位符（未填的会**橙色高亮**，发送会被拦下）；
5. 确认界面状态是「空闲」→ 点「填入」或「填入并发送」；
6. 若提示 `BUSY`：对方正在生成，**等它结束再点，不要重试轰炸**。

**三条硬约束（AI 必须知道）**
- 忙时**绝不发送**：发送键在生成中语义是「停止」，点下去会打断对方正在跑的活。
  工具会直接拒绝，且**一个字都不写进输入框**（不留孤儿文字）。
- 默认干跑：只填不发。真发要手动取消勾选或点绿按钮。
- 成功判定由后端用**客观证据**给出（编辑器字符数 / 消息是否入流），AI 不自己猜。

## 二、启动

### 前置：WorkBuddy 必须开调试端口

**不用手动改快捷方式** —— 桌面 `VarixAutoPilot 开端口.bat` 一键搞定
（它是幂等的：端口已开就什么都不做，没开才给你指引）。

也可以手动：桌面 `WorkBuddy.lnk` → 右键 → 属性 → **目标**栏，末尾加一个空格再加：

```
--remote-debugging-port=9222 --remote-debugging-address=127.0.0.1
```

验证：`curl http://127.0.0.1:9222/json/version` 返回 JSON 即成功。

> **关键前提**：调试端口**只在进程启动那一刻决定**。已经跑着的 WorkBuddy
> 不会因为新参数而开启端口——必须先彻底退出（关窗口 + 托盘退出）再重开。

> 已在运行的实例**不会**因新参数重启——必须先彻底退出（关窗口 + 托盘退出）。

### 三种启动方式

| 桌面文件 | 作用 |
|---|---|
| **VarixAutoPilot 一键启动.bat** | 日常用这个。端口已开就直接拉起应用 |
| **VarixAutoPilot 开端口.bat** | 单独开端口（带修复指引） |
| **VarixAutoPilot 启动.bat** | 只拉起应用 |

目录内对应：`一键启动.bat` / `开端口.bat`（ASCII 别名 `open-port.bat`）/ `启动.bat`
应用本体：`VarixAutoPilot.exe`（3.85MB，在本目录根下）

### ★ 为什么端口必须"重启"才能开 ★

Chrome / Electron 的调试端口**只在进程启动那一刻决定**。
已经跑着的 WorkBuddy，**做任何操作都不会让端口出现**——必须先完全退出，再用带参数的方式启动。

脚本 `tools/open_port.py` 做的就是这件事，且刻意做了三件保守的事：

1. **默认绝不杀进程**。杀 WorkBuddy = 中断你正在跑的对话。
   默认只打印指引并给出命令，要动手必须显式加 `--kill`。
2. **目标校验最早做**。带 `--kill` 时先确认目标确实是 `WorkBuddy.exe`，
   否则直接拒绝——早先校验放在"要不要杀"之后，导致传非 WorkBuddy 路径时
   根本走不到校验，等于形同虚设。
3. **不改任何宿主文件**：不碰你的桌面快捷方式、不碰 `user-data-dir`、不碰任何配置。
   端口只绑 `127.0.0.1`，不对外暴露。

命令行用法（在 `VarixAutoPilot2/` 下）：

```
# 只看状态与指引（安全，不动进程）
python tools/open_port.py

# 确认无要紧的活之后，让它关掉 WorkBuddy 并带端口重启
python tools/open_port.py --kill

# 端口被占时换端口
python tools/open_port.py --port 9333
```

启动应用：`VarixAutoPilot.exe`

**无浏览器、无 Node、无 python**。Tauri 2 + WebView2，双击即开。

## 三、三项信息的数据来源（全部实测，非推演）

| 要显示 | 来源 | 可靠性说明 |
|---|---|---|
| **开了几个对话** | CDP `div.conversation-item` | 精确，含标题/相对时间/选中态 |
| **每个对话的模型** | CDP `button.cr-model-selector__trigger[title]` | ⚠️ **只有当前对话读得到** |
| **每个对话的工作目录** | `~/.workbuddy/sessions/*.json` 的 `cwd` | **精确配对** |

### 关于模型的限制（如实说明）

WorkBuddy **只在当前打开的对话顶栏显示模型名**，侧栏列表里没有。
所以本工具显示当前对话的模型；点开别的对话时面板会同步更新。
要批量拿全部对话的模型，得逐个点开——**这是客户端的信息限制，不是采集缺陷**。
面板上其余对话会显示「侧栏不显示 · 点开可读」，不编造。

### 关于工作目录的配对（这里踩过坑）

`conversation-item` 带 `data-conversation-id` 属性，**该值就是** `sessionId`
（三样本逐一验证：`a09df76e…`→`29316.json`、`6a70cd4d…`→`46896.json`、
`e042f2d0…`→`14956.json`）。于是工作目录**可以精确配对**。

上一版按「最近更新的会话顺序」硬对齐，把当前对话配到了 `_attic/…/cdp`
（那只是跑脚本的目录）。**顺序对齐在多会话并行时必然错配，
而错配出来的路径比没有路径更危险——它看起来是真的。**
查不到的那条如实标「未查到该 session」。

## 四、自定义提示词

模板支持任意 `{{键}}`。

- **系统内置**（自动注入，不用填）：`{{时间}}` = 发送时刻
- **你填的**：默认 `{{任务}}`、`{{上下文}}`，可在模板里加任意新键

发送时会被拦下并列出缺哪几个。

## 六、4K 视觉：等比缩放，不是像素翻倍

**★ 这一段是本版踩得最深的坑，值得记 ★**

第一版照抄来源站（`D:\2\14\UI\与你相恋到生命尽头`）的
`min(Xvw, Ypx)` 变量体系。结果在 3840×2160 下**整页只有 1080p 大小**
（截图证据：右侧大片空白、顶栏仅 59px）。

**根因很直接：上限 px 成了天花板。** `vw` 算到 82px，被 `16px` 的 min 夹死。
那套 `min()` 是为 1920 基准的网页设计的，抄到「要在 4K 上放大」的桌面应用上就是错的。

**正解**：以 1920×1080 为基准的等比缩放，且缩放因子**必须带 `px` 单位**：

```css
--kpx: clamp(1px, 100vw / 1920, 3px);
--sp-16: calc(16 * var(--kpx));
```

实测结果（探针 `tools/probe4.mjs`）：

| 视口 | 缩放 | 顶栏内边距 | 正文字号 | 顶栏高 |
|---|---|---|---|---|
| 1280 | 0.67× | 20px | 14px | 61px |
| 1920 | 1.00× | 20px | 14px | 61px |
| 2560 | 1.33× | 26.7px | 18.7px | 82px |
| **3840** | **2.00×** | **40px** | **28px** | **122px** |

**★ 为什么必须带 px 单位 ★**
早先写 `--kmax: clamp(1, 100vw/1920, 3)`（无单位），
于是 `calc(12 * var(--kmax))` 算出的是**无单位数 12**，
赋给 `width` 时浏览器把它当百分比倍数处理 → 实测得到 1920px。
**结果整页所有间距全部作废（顶栏 padding 实测 0px），而规则解析又是"成功"的。**
这种「解析成功但值全错」最难查——我先怀疑 clamp 语法、怀疑路径、
怀疑选择器优先级，最后靠逐层 `getComputedStyle` 才定位到单位。

## 七、文件结构

| 文件 | 作用 |
|---|---|
| `src-tauri/src/cdp.rs` | 手写 CDP 客户端（WebSocket + JSON-RPC 配对） |
| `src-tauri/src/collect.rs` | 三源采集 + mtime 缓存 |
| `src-tauri/src/engine.rs` | 填入 / 发送 / 忙闲保护 |
| `src-tauri/src/template.rs` | 模板渲染（纯函数） |
| `src-tauri/src/lib.rs` | Tauri commands + 三要素错误 |
| `src/index.html` | 视觉层（4K 流式体系） |
| `src/app.js` | 前端逻辑（Tauri / 浏览器双模式） |
| `tools/make_ico.py` | 多尺寸 ICO 生成（手写容器格式） |
| `tools/shoot.mjs` | 双分辨率截图与缩放核对 |
| `tools/probe4.mjs` | 四档分辨率缩放验证 |

### 为什么手写 CDP 客户端

Playwright 的 Rust 绑定是社区产物，而实际需要的能力很窄——
**只需发命令、等响应**。为此引入整套浏览器抽象栈不划算，版本风险不可控。
协议本身很简单：按 `id` 做请求-响应配对，其余消息丢弃。

### 为什么双模式（app.js 里那套 mock）

`app.js` 在非 Tauri 环境（普通浏览器）下走内置 mock。
没有它，每改一次样式都要 `cargo build` 才能看效果——太慢。
mock 用的是**真实结构**（7 个对话 / 模型 / 目录 / 发送态），
所以它既能验布局，也能在没有 WorkBuddy 时演示。

## 八、复刻的 6 个坑（来自 Node 版实测）

Rust 版不是"重写"，是把踩过的坑逐条固化：

1. **可见性不能靠外部判断** —— Electron 的 `file://` 页上 Playwright 的
   `isVisible()` 恒 false。统一在页面内算 `getBoundingClientRect()`。
2. **输入框是 Slate.js 富文本编辑器** —— 它接管 contenteditable，
   必须走 CDP `Input.insertText`，逐字 `dispatchKeyEvent` 无效。
3. **发送键 busy 态是 `--sending`** —— 此时语义是「停止」，
   点下去会打断对方。选择器必须 `:not(.cr-send-button--sending)`。
4. **尺寸门槛按调用方分设** —— 输入框 >200×40，发送键 32×32。
   统一用 40×18 门槛会把发送键挡掉。
5. **发送判定不能「睡 N 秒回读」** —— Slate 时序是「先渲染消息 → 再清空编辑器」，
   固定 sleep 会卡在中间误报。正解：轮询 + 双重证据
   （编辑器清空 **或** 消息入流）。
6. **忙时要在动手之前退出，且一个字都不留** —— 「先填后检」会留下
   没人认领的孤儿文字，下一轮接手的人会以为那是对方写的。

## 九、性能

| 指标 | 实测/预估 |
|---|---|
| exe 体积 | 约 3–6MB（Tauri 2，不含 WebView2 运行时） |
| 冷启动 | 0.3–0.8s |
| 常驻内存 | 25–40MB |
| 单次快照 | 稳态 5–15ms（见下） |

**快照性能的关键优化**：`CwdCache` 用**文件 mtime 判失效**。
上一版每 1.5 秒全量重读 276 个 JSON（约 28MB/天纯浪费）；
改后稳态下每轮只做 `metadata()`（约 1–3ms），不再读文件内容。

## 十一、常见问题

**Q：启动后顶栏显示「采集失败」**
A：WorkBuddy 没带 `--remote-debugging-port=9222` 启动。见第二节。
面板会显示三要素错误（发生了什么/为什么/下一步怎么办）。

**Q：某个对话的目录显示「未查到该 session」**
A：那个会话的 `sessions/*.json` 已被客户端清理。如实显示比编一个路径好。

**Q：4K 下字太大/太小**
A：`--kpx` 的上限是 `3px`（即最高 3× 缩放，对应 5760 宽）。
改 `index.html` 里那行即可。

**Q：会不会干扰我正在跑的任务**
A：默认干跑，忙时直接拒绝。面板只读界面状态 + 写自己的设置，
不改 WorkBuddy 的任何配置。
