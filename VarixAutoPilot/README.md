# VarixAutoPilot · 对话自动化控制台

**一句话**：把「构造提示词 → 填进 WorkBuddy 输入框 → 点发送」这条链做成可视化面板，
并如实显示你开了几个对话、每个对话用的什么模型、在哪个文件夹工作。

---

## 一、AI 怎么知道这个工具存在

**三条路径，任选其一：**

1. **开工时读本文件**。在对话里 @ 本文件，AI 就知道有这套工具可用。
2. **它会自己出现**：当你在对话里提到「领任务」「下一轮」「自动发送」这类词，
   AI 若已读过本文件就会主动用它。
3. **不读文件也行**：直接对 AI 说
   > 「读 `VarixAutoPilot/README.md`，然后用它把下一轮的提示词发出去」
   AI 会照做——本文件的第一段就是给 AI 读的说明书。

> **给 AI 的执行清单**（照做即可，无需再问）：
> 1. 跑 `python VarixTaskOps/emit_next_prompt.py` 生成 `_next_prompt.md`；
> 2. 把它整段贴进控制台的「上下文」框，「任务」框填单号与标题；
> 3. 点「预览」确认无残留占位符 → 点「填入并发送」；
> 4. 若提示 `BUSY`，说明对方还在生成 —— 等它结束再点，**不要重试轰炸**。

## 二、启动

### 前置：WorkBuddy 必须带调试端口

**只开一次，之后一直有效**（改桌面快捷方式即可）：

桌面 `WorkBuddy.lnk` → 右键 → 属性 → **目标**栏，在末尾加一个空格再加：

```
--remote-debugging-port=9222 --remote-debugging-address=127.0.0.1
```

> 已在运行的实例**不会**因新参数重启——必须先彻底退出（关所有窗口 + 托盘图标退出）。

验证端口：`curl http://127.0.0.1:9222/json/version` 返回 JSON 即成功。

### 启动控制台

双击 `启动.bat`（推荐），或命令行：

```bash
cd VarixAutoPilot
NODE_PATH=D:/2/14/-Un-Real-0d23d9ux-Engine-main/node_modules \
  "C:/Users/varia/.workbuddy/binaries/node/versions/22.22.2-3/node.exe" server.mjs
```

然后打开 **http://127.0.0.1:8768/**

## 三、面板怎么用

### 左侧：对话清单（你要的三项信息）

| 想知道 | 面板显示 | 数据来源 |
|---|---|---|
| **我开了几个对话** | 顶部「对话 N」+ 卡片列表 | CDP `div.conversation-item` |
| **每个对话的模型** | 当前对话显示模型名；其余标「侧栏不显示（点开可读）」 | CDP `button.cr-model-selector__trigger[title]` |
| **每个对话的工作目录** | 每张卡片第二行，悬停看完整路径 | `~/.workbuddy/sessions/*.json` 的 `cwd` |
| 现在忙不忙 | 顶部「空闲 / 生成中」 | 发送键class 是否有 `--sending` |

> **关于模型的诚实说明**：WorkBuddy 只在**当前打开的对话**顶栏显示模型名，
> 侧栏列表里没有。所以本工具只能读当前对话的模型；
> 点开别的对话时，面板会同步更新成那一条。要批量拿全部对话的模型，
> 得逐个点开——这是客户端的信息限制，不是我偷懒。
>
> **关于工作目录**：DOM 里**没有** `data-cwd` 之类属性，硬编选择器只会得空。
> 真实来源是 `div.conversation-item` 的 `data-conversation-id`，
> 它**等于** `sessions/*.json` 里的 `sessionId`（已逐样本验证），
> 于是工作目录可以精确配对，不用猜。查不到的那条会如实标「未查到该 session」。

### 右侧：提示词与发送

| 控件 | 作用 |
|---|---|
| **变量** | 填 `{{任务}}` `{{上下文}}` 的值 |
| **模板** | 自定义提示词全文，支持 `{{键}}` 占位符 |
| **只填不发（干跑）** | 默认勾选。只填入不发送，确认无误再取消勾选 |
| **先开新对话** | 勾选后先点「新建任务」再填 |
| **预览** | 渲染结果实时显示，**未填的占位符会高亮** |
| **填入 / 填入并发送** | 两个按钮，前者永远安全 |
| 快捷键 | `Ctrl+Enter` = 填入并发送，`Ctrl+S` = 保存 |

### 自定义提示词

模板支持任意 `{{键}}`。在模板里写 `{{任务}}`，在「变量」区填同名键即可。
想加新变量（如 `{{门禁}}`），直接在模板里加，然后在「上下文」框里写进 `上下文` 即可
（或者改 `settings.json` 增删字段）。

**系统内置变量**（自动注入，不需填）：

- `{{时间}}` = 发送时刻

**未填的占位符会原样保留**并高亮，**不会被替换成空**——
空段落会让人以为「这里没什么要说的」，而实际上是没配。发送时会被拦住并列出缺哪些。

## 四、三条安全约束（不可放宽）

1. **忙时绝不发送。** 对方正在生成时，发送键的语义是「**停止**」，
   点下去会**打断对方正在跑的活**。本工具检测到 `--sending` 就**在动手之前**退出，
   **一个字都不往输入框里留**（不留是关键：留了会变成一段没人认领的孤儿文字）。

2. **默认干跑。** `dryRun` 默认 `true`，只填不发。真发要手动取消勾选或用红色按钮。

3. **成功判定靠客观证据，不靠猜。**
   点击发送后 Slate 的时序是「先渲染消息 → 再清空编辑器」，
   固定 sleep 后单点采样会误报。正解是**轮询 + 双重证据**：
   编辑器已清空，**或**消息已出现在对话流（后者与编辑器状态无关，更强）。

## 七、常见问题

**Q：面板显示「面板与后端失联」**
A：后端没起。看 `autopilot.log` 最后几行。

**Q：显示「CDP 连接失败」**
A：WorkBuddy 没带 `--remote-debugging-port=9222`启动。见第二节。

**Q：提示「找不到就绪态发送键」**
A：WorkBuddy 升级改了 class 名。跑 `node probe.mjs --list` 核对真实结构再改
`engine.mjs` 里的 `SEND_SELECTOR`。**别改成点「停止」**——那是打断对方。

**Q：某个对话的工作目录显示「未查到该 session」**
A：那个会话的 `sessions/*.json` 已被清理（客户端会清旧会话）。
这是事实，如实显示比编一个路径好。

**Q：会不会干扰我正在跑的任务**
A：默认干跑，且忙时直接拒绝。面板只读界面状态 + 写自己的设置文件，
不改 WorkBuddy 的任何配置。
