### 0.1 一句话定义

**Variable 是一个覆盖在 Windows 桌面之上的「私人桌面环境」**：它有自己全屏壁纸层、桌面图标网格、Win11 风格任务栏与开始菜单、文件管理器与回收站、通知中心与快捷面板、硬件状态面板、系统托盘与全局快捷键，内部运行一套完整的**虚拟窗口管理器（VWM）**——四大功能空间与文件管理器全部以虚拟窗口的形式在环境内部打开，第三方 Windows 软件可以被**整体嵌入**到环境里的虚拟窗口中（从系统任务栏与 Alt+Tab 里消失）。它同时内嵌四个彼此独立、又可以通过「引用」互相跳转的生产力空间：**写作库、无限画布思维导图、代码通俗化引擎、命运推演沙盒**。

它不注册、不登录、不上传。所有数据——记录、思维导图、项目分析档案、命运推演树、媒体附件、备份、日志——都只存在于你自己的电脑上；便携模式甚至可以把整个数据目录放进 U 盘随身携带。它同时是一款「审美驱动」的软件：原生 WebGL 星空与极光背景、电影级七层启动氛围、低饱和冷调视觉语言 2.0、自定义无边框窗口与启动剧场，让一个严肃的生产力工具拥有宇宙级的氛围感。

> **一句话总结**：Variable = 一个可以把你现有 Windows「关在门外」的私人操作系统皮肤 + 四个彼此互通的生产力空间 + 一个可以把任意第三方软件「关进」自己窗口里的嵌入式窗口管理器。

## 一、产品定位：四层叠加的私人桌面环境

### 1.1 为什么需要另一个「桌面」

Windows 桌面是一个公共空间：通知横幅随时弹出、任务栏挤满后台常驻、壁纸与图标布局属于「系统」而不属于你、工作窗口与娱乐窗口混在同一层 Z 序里互相干扰。对于需要长时间专注的个人创作者而言，这个公共空间天然是失焦的。

Variable 的答案不是再做一个「专注模式应用」，而是**再造一个完整的桌面层**：它在 Windows 桌面之上全屏铺开自己的环境——壁纸、图标、任务栏、开始菜单、窗口管理全部由自己绘制、自己调度——然后把真实桌面「关在门外」。你需要真实桌面时双击 Esc 即回；回到环境时，一切保持原样。环境与真实系统之间是「软隔离」：第三方应用以独立 OS 进程运行，嵌入只是窗口层级的重父级（SetParent），应用崩溃不影响环境，环境关闭也不牵连应用。

### 1.2 四层结构

Variable 由四个层次叠加而成，每一层都可以独立使用，也可以组合成完整体验：

**第一层：桌面环境层（Desktop Shell）**
全屏壁纸 + 桌面图标网格 + 任务栏 + 开始菜单 + 文件架 + 通知中心 + 快捷面板 + 系统托盘 + 全局快捷键 + 窗口管理（红绿灯 / Win+Tab / 分屏贴靠 / 编组编排）。这一层负责「接管」Windows 桌面，把它改造成属于自己审美与工作流的空间。壁纸支持静态图片、壁纸池轮播、视频、网页、living 活化五种模式，另有多显示器按屏设置；任务栏四向位置可调；开始菜单支持拼音搜索与固定网格拖拽重排。

**第二层：虚拟窗口管理器（VWM）**
环境内部的轻量级窗口系统。四大功能空间、文件管理器、回收站，以及被嵌入的第三方软件，都以虚拟窗口的形式运行，拥有独立的 Z 序、聚焦态、拖拽移动、边缘贴靠、最小化飞行动效、多开、编组与舞台编排能力。虚拟窗口不是 iframe 也不是 OS 窗口，而是 DOM 层的窗口对象——这意味着它可以被环境完全控制（尺寸提示、Esc 回弹、色带标记、画中画），又保持与 OS 窗口一致的交互直觉（Alt+Tab 轮转、Win+方向键贴靠、双击标题栏最大化）。

**第三层：四个功能空间**
- **写作空间（Library）**：层级文件夹 + 富文本记录 + 标签 + 收藏 + 回收站 + 全文搜索 + 本地媒体，基于 TipTap 编辑器；
- **思维导图空间（Mindmap）**：无限画布、自由节点、丰富的连线样式、小地图、节点绑定记录；
- **项目分析空间（PVCCE）**：把任意本地代码项目「翻译成大白话」，七级下钻、逐行解剖、推理链、意图生成、写回源文件；
- **命运推演空间（FTPE）**：基于特质权重与确定性种子的行为树命运模拟引擎。

四个空间通过 **xref 跨空间引用协议**互通：思维导图节点可以「复制为引用」粘贴到写作正文里形成锚点，双击锚点直接跳回导图节点并定位；源节点内容更新后，写作侧的锚点会显示「已更新」徽标提示重校验。引用关系随内容持久化，不依赖任何外部服务。

**第四层：第三方软件子系统**
开始菜单 .lnk 扫描（COM IShellLink 解析）、便携化登记与三级便携性分级、原生图标提取（128px Jumbo 高清）、进程深度检测、Wallpaper Engine 壁纸项目接入，以及把第三方软件窗口**嵌入环境内部**的 embed 子系统。这一层让 Variable 不只是一个「自娱自乐」的环境——你日常真正使用的软件（游戏、IDE、通讯工具）都能被收编进来。

### 1.3 环境级能力中枢

在四大层次之上，v1.x 工作线叠加了一整套环境级能力中枢，它们共同构成「比肩顶级桌面作品」的第二曲线：

- **效率与工具中枢**：命令面板、统一搜索 2.0、剪贴板历史（DPAPI 加密）、截图标注、宏引擎、快捷键中心、基础工具箱七件（时钟/天气/Emoji/取色/换算/系统信息/运行框）；
- **系统中枢**：七页硬件与系统管理工具窗口（概览/显示器/电源/网络/存储/系统/外设）；
- **数据安全中心**：十二面板的数据治理工具窗口（版本时间机/信任链/金丝雀/紧急擦拭……）；
- **兼容性防线**：应用适配等级库（A/B/C）、IME 深度兼容、全屏独占协议、卷 GUID 自愈；
- **开放生态**：variable:// 协议、.vxs 资源包、开放 IPC 网关、数据连接器、variable-cli；
- **无障碍 2.0 与多语言中心**：aria 全标注、四类色觉模拟器、动效缩放、运行时词条覆盖、简繁用户词表；
- **氛围与个性化引擎**：Web Audio 程序化音景、环境辉光、节律助手、情绪引擎、农历节气；
- **声音与通知运行时**：NotifyRuntime 统一管理声音方案、逐应用音量、勿扰日程、通知存档与提醒中心。

## 二、设计哲学：十条贯穿始终的信条

Variable 的每一个功能决策背后都有明确的原则。这些原则不是口号，而是写进代码、门禁与文档的硬约束——违反它们的提交过不了 CI。理解这十条信条，你就能预测这个软件在任何边界情况下的行为。

### 2.1 隐私即默认

**零网络请求、零遥测、零账号**——这不是「可以在设置里关掉」的可选项，而是架构层的默认态。数据库、媒体、备份全部落在本机；便携模式甚至可以把整个数据目录放进 U 盘随身携带。通讯软件提醒也只读取**窗口标题**里的未读计数标记，聊天正文永远不经过 Variable。任何联网能力（出站桥、IPC 网关、事件流）默认关闭，开启必须显式确认且可永久关闭。

这条信条的工程体现是 **netconsent 机制**：任何首次尝试出站请求的动作前都会弹窗确认，确认结果可撤销、可审计；开放 IPC 网关默认零监听，开启后仅绑定 127.0.0.1 环回并要求 token + scope 双重授权；数据连接器只读且仅允许 SELECT 白名单。隐私仪表盘与金丝雀文件（预埋的敏感命名文件，监测任何越权访问尝试）让「谁读过我的数据」变得可见、可验证。

### 2.2 隔离即安全

环境与真实 Windows 之间是「软隔离」：第三方应用被启动为独立 OS 进程（DETACHED spawn），与 Variable 无 WebView 关系；嵌入只是窗口层级的重父级（SetParent），应用崩溃不影响环境，环境关闭也不牵连应用。Variable 对系统能力的边界保持诚实：它能做用户态进程管理与窗口集成，但绝不假装自己是内核。

这条信条在嵌入子系统上体现得最彻底：**失败路径上绝不伤害应用**。捕获超时（30 秒）时应用保持独立窗口运行，进程绝不终止、登记绝不删除；无法嵌入的应用（UWP / 管理员权限 / 无标准窗口）如实回退为独立窗口运行。宏引擎配急停与 UAC 判停（检测到提权弹窗自动暂停，绝不代用户点击安全桌面）；计划任务工坊有动作白名单与 30 秒运行时上限。

### 2.3 审美驱动

原生 WebGL 星空与极光背景、低饱和冷调语义色板（tokens.css 2.0 语义层，禁止裸色值）、材质引擎与微交互矩阵、电影级七层启动氛围（双层极光幕 + 三层尘埃粒子场 + 流星 + 地平线暖光 + 暗角 + 胶片颗粒 + CRT 扫描线）、自定义无边框窗口、启动剧场六件套——桌面环境本身就是作品。四大功能空间的图标各自拥有独立的视觉语言（钢笔尖墨迹 / 青色节点星图 / 像素扫描线 / 金色星盘），桌面、任务栏、开始菜单三处一致（iconRegistry 统一登记）。

审美不是装饰，而是可维护的工程资产：视觉令牌契约由 audit.cjs 视觉门禁静态强制，界面代码里出现裸色值即 CI 拒绝；主题工坊基于 OKLCH 色彩空间构建，强调色对比度守护自动校验 WCAG AA（4.5:1 正文 / 3:1 大字与图形）；材质引擎把玻璃/亚克力/金属/织物的模糊、噪点、高光、阴影参数化，一处调整全局生效。

### 2.4 启动即进入

窗口打开的第一眼就是启动剧场——真实事件驱动，无合成时间线。数据库迁移、库统计、媒体索引等真实进度以 `boot://event` 流式推给前端，进度条走多快取决于机器实际多快。加载完成后进入仪式编排：字母落位 → 任务栏从中央展开 → 桌面图标交错淡入 → 红绿灯由暗态激活。键盘可达、快捷键齐全，打字时背景自动降级渲染保证输入零延迟。

这条信条的反面是「假进度条」——很多软件用 2 秒动画伪装加载。Variable 的立场是：启动体验的每一个数字都必须是真的。启动完成时推送的「本地数据就绪」通知，其中的工作区文件数、记录数、导图数全部来自真实 BootStats 统计。

### 2.5 无模板哲学

尤其在命运推演里，人格、性格、主义思想全部是抽象自构条目，没有任何真人模板——它是一个「思想实验沙盒」，不是算命工具。事件库提供 7 层分类、种子 100+ 条，但它们是「素材」而非「剧本」：用户自定义扩展永远优先于内置条目。项目分析空间同理：通俗翻译的词典七级体系支持 `.dict.json` 离线导入导出，用户词典可以完全替换内置词典——软件提供的是引擎，不是内容权威。

### 2.6 零 AI 依赖

项目分析的「大白话翻译」完全由本地词典 + 规则引擎生成，不调用任何在线大模型，同样的话术在十年后的离线机器上依然可用。这条信条保证了两个属性：**可重现**（同一份代码与词典永远产出同样的翻译）与**可审计**（翻译逻辑的每一步都可以被检查与修改）。命运推演使用 mulberry32 确定性 PRNG，同种子完全可重现；项目分析写回源文件先备份再原子落盘，支持 Ctrl+Z 回滚。

### 2.7 可重现与可追溯

- 命运推演同种子完全可重现（确定性种子是推演参数的一部分）；
- 源文件写入先备份再原子落盘、支持 Ctrl+Z 两级回滚（先撤会话内改动，再回滚已落盘写入）；
- 数据库写操作有事务与恢复文件兜底；异常关闭后重启，恢复提示宿主会列出恢复文件（标题/时间/预览），一键恢复或删除；
- 窗口关闭事件写取证日志，区分「用户请求关闭」与「窗口自行销毁」（webview 崩溃/系统），为异常排查留证据；
- 数据目录内有哈希信任链，文件篡改可见；批量导入导出走传输指挥台（进度/暂停/取消/校验）。

### 2.8 如实降级

全局快捷键被系统/他方占用时逐项注册失败并诚实降级为任务栏 / 开始菜单入口，仅记录日志；硬件能力（Wi-Fi 无线电、蓝牙设备）不可用时面板如实显示状态而不是假装成功；不可嵌入的第三方应用如实回退为独立窗口运行；天气卡数据源不可用时显示离线占位而不是假数据。

**不提供假功能**是贯穿始终的纪律，全局 DoD 口径「无未经实测的 ✅」同样贯穿文档与代码——文档里的勾只代表代码级完成，真机验收统一留待三宿主阶段（B-30 发版门禁）。发布产物里 dev-only 代码零命中（M-80 门禁实测），卸载器钩子经编译级证据链验证。宁可承认做不到，绝不假装成功。

### 2.9 绝不伤害用户进程

嵌入失败、捕获超时等一切异常路径上，Variable 绝不终止第三方进程——应用总是保持运行，用户随时可以手动接管。更进一步：删除护栏仅允许彻底删除数据目录内的文件（防误删系统软件）；卸载采用「回收站式可反悔删除」而不是直接抹掉；关机确认后 10 秒内可反悔。对用户数据的每一次破坏性操作都留有反悔通道。

### 2.10 克制的动效纪律

所有动效遵循 reduce-motion 令牌与 80ms 全局降档规则，动效时长支持全局缩放（--dur-scale 0.5x/1x）；讲述人开启时自动叠加 reduce-motion（动效会干扰屏幕阅读器的焦点追踪）。宁可克制，不堆砌。高刷新率显示器上动效时长按 0.85× 折算保持观感一致；慢速设备（HDD/U 盘）自动切换到保守的渲染档位。动画强度必须与真实状态同步——启动氛围的强度随真实加载进度从 0.35 渐强到 0.55，而不是恒定的「表演」。

### 2.11 信条之间的关系

这十条信条并非并列，而是有优先级的：**隐私与安全 > 诚实 > 克制 > 审美**。当审美与性能冲突时（如打字时背景降帧），审美让位；当功能与边界冲突时（如全屏独占游戏），功能让位；当任何能力与「不伤害用户进程」冲突时，能力让位。这个优先级排序解释了 Variable 在无数细节上的取舍——它宁愿少一个功能，也不越一条红线。

| `app_windows.rs` | 四大空间 + 文件管理器的多窗口创建与标签路由（遗留回退通道） |
| `wallpaper.rs` | 壁纸池目录、多显示器信息、壁纸设置、Wallpaper Engine 扫描与打开 |
| `recycle.rs` | 回收站：系统回收站列举/还原/清除 + 容量统计 |
| `boot.rs` | 真实启动加载编排，进度以 `boot://event` 流式推给前端（无合成时间线） |
| `privacy.rs` / `netconsent.rs` | 联网确认弹窗与隐私横幅 |
| `notify` 族 | 通知存档（SQLite 全文搜索）、提醒中心（重启补发）、逐应用音量记忆、通信设备快切 |
| `a11y.rs` | 系统辅助功能桥：粘滞/筛选键/高对比度/讲述人只读探针（STICKYKEYS 等） |
| `sysinfo.rs` / `xflow.rs` / `appman.rs` | 系统信息与运行态支撑 |

### 3.5 全局交互细节（App 层的工程质量）

- **捕获阶段「点击空白即销毁」状态机**：`App.tsx` 在 capture 阶段监听 `pointerdown`，任何不属于浮层面板（右键菜单/节点菜单/连线气泡/检查器）与文本框的左键点击，都会强制销毁全局激活状态——没有任何浮层能靠 `stopPropagation` 逃避关闭。这一机制根治了「菜单关不掉」类缺陷。
- **打字降级渲染**：监听可编辑区域的单字符按键，1.5 秒内标记 `editing`，让 WebGL 背景自动降帧/降级，保证输入永远跟手；空闲渲染冻结（idle freeze）进一步在无人操作时停掉非必要渲染。
- **关闭前保存兜底**：窗口关闭先走保存流程，失败时弹出「取消关闭 / 重试保存 / 强制关闭」三选模态，绝不静默丢稿。
- **异常关闭恢复**：崩溃或强杀后，重启时恢复提示宿主会列出恢复文件（标题/时间/预览），一键恢复为新记录或删除。
- **宿主齐全性**：桌面分支挂载全部交互宿主（ConfirmHost / ChoiceHost / PromptHost / ConfirmBubbleHost / NetConsentHost），所有 `ask*` Promise 都有 resolve 归宿——历史上曾因漏挂宿主导致「点了没反应」，已根治并有回归意识。
- **错误叙事统一**：EmptyState 空态组件与错误叙事规范让每一处失败都有人话解释与下一步动作，不出现裸报错。错误的呈现遵循三段式：「发生了什么 / 为什么 / 怎么办」。

### 3.6 数据流：一次保存的完整旅程

以「在写作空间按 Ctrl+S」为例，数据流经以下环节：

1. TipTap 编辑器产出当前文档 JSON → `sanitize.ts` 白名单净化（`<script>` 整段剥离、`on*` 事件属性剔除、`javascript:` 危险 URL 拦截）；
2. 双列内容生成：`contentHtml`（渲染用）+ `contentText`（全文搜索用）；
3. `saveQueue` 入队：同键请求串行、同键多个待存项 latest-wins 合并；
4. `ipc.ts` 类型化调用 → Tauri invoke → Rust `library` 模块；
5. rusqlite 事务写入（WAL 模式）→ 成功后跨窗口广播 `settings://changed` 类事件（如涉及设置）；
6. 失败时错误经 `error.rs` 归一化 → 前端 Toast 展示中性文案 → 计入关闭前检查（有专门单测覆盖三种语义）。

这条链路上的每一环都有测试：净化规则（Vitest）、保存队列三语义（Vitest）、CRUD 与 LIKE 转义（cargo test）、迁移幂等性（cargo test）。

### 3.7 为什么是 Tauri 而不是 Electron

| 维度 | Tauri（Variable 的选择） | Electron |
|---|---|---|
| 渲染引擎 | 系统 WebView2（Windows 自带） | 捆绑 Chromium |
| 安装包体积 | 6.5 MB | 80 MB+ |
| 内存占用 | 单 WebView2 进程 | 独立 Chromium 进程树 |
| 系统集成 | Rust 直调 Win32/WinRT，无边界 | 经 Node 层桥接 |
| 后端语言 | Rust（内存安全、无 GC 停顿） | Node.js |

对桌面环境这种「常驻、低资源占用、深度系统集成」的软件形态，Tauri 是结构性更优的选择。Rust 后端让窗口枚举、进程快照、Shell 集成这些高频系统调用拥有原生性能与内存安全保证。

## 四、启动剧场：开机即入场的仪式工程

启动是用户对软件的第一印象，也是最容易暴露「工程不认真」的地方——假进度条、白屏闪烁、布局跳动。Variable 把启动当作一场剧场来设计：真实事件驱动、电影级氛围、游戏级进度反馈。

### 4.1 真实事件驱动（无合成时间线）

启动时执行的是**真实加载**：数据库迁移、库统计、媒体索引等真实进度以 `boot://event` 流式推给前端，全程**没有合成时间线**——进度条走多快取决于机器实际多快。这带来一个工程约束：启动编排器（boot.rs）必须把每个真实阶段的事件按序推送，前端只消费事件、不虚构阶段。启动完成时推送的「本地数据就绪」通知，数字来自真实 BootStats：工作区文件数、记录数、导图数；另有一条「磁盘同步通知」。

### 4.2 启动剧场六件套（U-01…U-06）

- **真实事件驱动剧场**：阶段推进、字标、进度、文件流全部由后端真实事件驱动；
- **品牌字标**：开机字母落位动画，与产品视觉语言一致；
- **CapsuleBar 胶囊进度**：全字标宽度、游戏 HUD 风格加载条——右上角百分比、24px 分段刻度、扫光周期掠过；进度严格跟随真实加载事件；
- **FileTicker 文件流带**：底部滚动的当前加载文件走马灯，纯英文 Consolas 大写字距微文案（无中文分支、零 emoji），与游戏 HUD 风格统一；
- **启动交响三档**：可选的三档启动音效方案（关闭/轻/全），声音方案包有事件白名单与数值范围校验；
- **仪式编排器三节奏**：加载完成后进入阶段 4/5 退出编排——字母落位 → 任务栏从中央展开 → 桌面图标交错淡入 → 红绿灯由暗态激活，三种节奏曲线可选。

### 4.3 启动氛围工程（BootAtmosphere · 七层光效）

启动仪式的背景不是一张静态图，而是电影级七层合成：

| 层 | 内容 | 实现要点 |
|---|---|---|
| ① 双层极光幕 | WebGL 褶皱飘带 | 纯白蓝 → 冰蓝 → 边缘樱花冰晶粉 |
| ② 三层尘埃粒子场 | 不同深度、不同漂移速度的粒子 | 深度感与呼吸感 |
| ③ 偶发流星 | 带头部辉光与拖尾 | 随机但不频繁，克制 |
| ④ 地平线暖光 | 日出前的暖色渐变 | 与冷调极光形成温度对比 |
| ⑤ 电影暗角 | vignette | 视线聚焦中央 |
| ⑥ 胶片颗粒 | film grain | 质感而非噪点 |
| ⑦ CRT 扫描线 | 轻微扫描纹理 | 复古终端氛围 |

动画强度随真实加载进度同步（0.35→0.55 渐强），`reduce-motion` / `safeMode` / `static` 设置下完全停用。这体现了「动画强度必须与真实状态同步」的纪律：氛围是加载状态的函数，不是恒定的表演。

### 4.4 首次启动：欢迎向导

首次启动（向导未完成）显示**欢迎向导**，引导隐私声明与基础设置，点击窗口关闭灯即可跳过并完成向导。向导不强制、不阻塞——你可以直接开始使用，之后再从设置回到任何初始化项。SpotlightTour 新手导览（聚光灯式分步引导）可随时从帮助中心重放。

## 五、桌面环境：分层、红绿灯与窗口管理

### 5.1 桌面 Shell（DesktopShell）

桌面窗口全屏覆盖 Windows 桌面（默认覆盖系统任务栏，实现环境视觉完全独立；可在设置 → 外观切换为「避让任务栏」），纵向分层：

```
壁纸层（静态/轮播/视频/网页/living 活化壁纸，多显示器，1:1 原样渲染无叠加滤镜）
  └─ VWM 虚拟窗口层（z=15：图标之上、任务栏之下）
      └─ 桌面图标网格（三档大小、多选、框选、拖拽、文件架、抖动编辑模式、
          可整体隐藏、排列/锁定/密度/敲字定位/模板中心/归档建议）
          └─ 底部 Win11 风格任务栏（小组件区 + 托盘 + 时钟）
              └─ 开始菜单 / 快捷面板 / 通知中心 / 硬件面板
```

壁纸层对桌面壁纸做了「原样渲染」处理：没有应用内文字背景专用的模糊/暗罩/暗角叠加，壁纸 1:1 清晰锐利；四款软件内部的背景光影不受影响。**living 活化模式**（LivingWallpaper）在静态壁纸之上叠加本地粒子层与 Ken Burns 缓动推拉，让静态图也拥有呼吸感——该模式遵循与动态壁纸相同的性能档位与 reduce-motion 纪律。

### 5.2 窗口红绿灯：三处统一的控制语言

Variable 的窗口控制灯统一为三处：桌面壳层、VWM 虚拟窗口、Modal/浮层（CloseLight 单灯组件），顺序为 **左绿 / 中黄 / 右红**：

- 🟢 **绿灯**：桌面壳层 = 退出选择框（隐藏到托盘 / 完全退出，未保存先走保存冲刷流程）；VWM 窗口 = 关闭本窗口（170ms 缩小淡出关闭仪式）；Modal/浮层 = 关闭本界面（浮层无最小化/最大化语义，不提供假灯）；
- 🟡 **黄灯**：全屏切换（toggleMaximize），VWM 中为最大化/还原，带平滑滑入动效；
- 🔴 **红灯**：最小化——桌面壳层收起；VWM 窗口播放 200ms「飞向任务栏」动效后隐藏（display:none 保活挂载，恢复零重载）。

红绿灯顺序统一（绿|黄|红）是 E-10 批次用户实测缺陷修复的成果——此前 VWM 红绿灯错排曾导致用户误关窗口。

### 5.3 窗口管理

- **虚拟窗口优先**：四大空间、文件管理器、回收站默认在桌面环境内以 VWM 虚拟窗口打开；OS 级独立窗口通道（app-*.html 拆窗入口）完整保留为遗留回退——xref 跳转若发生在非桌面窗口、或用户直接运行独立入口，仍走旧路径，两条通道互不干扰；
- **Win+Tab 切换器**（可选功能）：后端注册 `super+tab` → `sys://wintab` 事件 → 唤起自绘切换器，列出全部 Variable 窗口（已并入 VWM 虚拟窗口的 Z 序），↑/↓ 选择、Enter/点击聚焦、Esc 关闭；
- **分屏贴靠**：拖动虚拟窗口到屏幕边缘出现贴靠预览（SnapPreviewHost），松手即贴靠左右半屏/四角 1/4；顶部最大化；Win+方向键贴靠、Win+M 最小化；双击标题栏切换最大化；Alt+Tab（环境内）轮转窗口；
- **编排中心（Ctrl+Alt+O）**：WindowOrchestrator 提供舞台级窗口编排——StageRail 舞台侧幕列出全部窗口，多选工具条支持互换位置、一起最小化、一起关闭（含确认门）、编组拖拽与组贴靠；焦点历史 Ctrl+Alt+[ / ] 逐级回溯；Esc 退出编组（与拖拽回弹 Esc 互斥仲裁）；
- **全屏应用避让**：检测到全屏应用运行时，任务栏自动避让，不遮挡游戏/视频画面（全屏独占协议详见第二十五章）。

### 5.4 覆盖 Windows 行为

- **联网确认弹窗**：任何首次尝试出站请求的动作前弹窗确认（默认无出站）；
- **Win 键全家桶**：Win+E 文件管理器、Win+D 显示桌面、Win+N 通知中心、Win+S 开始菜单搜索、Win+Tab 窗口切换（默认表采用 ctrl+alt+* 变体规避 Win11 系统保留键，详见第三十五章）；被系统占用时逐项降级并记日志；
- **托盘常驻**：关闭到托盘后 Variable 继续运行（IM 提醒、快捷键等后台能力保持），托盘菜单可随时唤回；
- **桌面图标隐藏模式**：右键「隐藏图标/显示图标」，隐藏时跳过图标与框选渲染（`variable:icons:hidden` 持久化），右键菜单仍可用——纯壁纸观影模式；
- **桌面纯净模式（Ctrl+Alt+P）**：一键收起图标、小组件与通知横幅的深度专注模式（比隐藏图标更进一步，含任务栏最小化选项）。

## 六、桌面图标与文件架

桌面图标是环境里使用频率最高的交互面。Variable 在对齐 Windows 习惯的基础上，补齐了 Windows 没做完的事（敲字定位、模板中心、归档建议），并把每一个细节做到「与系统一致且更清晰」。

### 6.1 图标网格

- **三档图标大小**（32 / 48 / 64px，字形尺寸对齐 Windows 标称值）一键切换，密度档位（紧凑/舒适/宽松）与网格几何（对齐/流水）可调；
- **多选与键盘操作**：Ctrl 点选、Shift 范围选、Ctrl+A 全选、鼠标框选；Delete 删除、F2 重命名、Ctrl+C/X/V 复制剪切粘贴、Ctrl+Z/Y 撤销重做、Alt+Enter 属性；
- **敲字定位（V-96）**：图标网格上直接敲击应用名首字母（拼音）即高亮定位，与开始菜单搜索同源；
- **排列与锁定**：自动排列（名称/类型/频率）与自由布局双模式，布局可锁定防误拖；
- **模板中心（V-08）**：新建右键内提供模板（空白记录/会议纪要/周报…），模板可自定义；
- **归档建议（V-09）**：长期未使用的图标给出归档建议，一键移入文件架；
- **拖拽归架 / 拖入回收站**：把图标拖到文件架上完成归类，拖到回收站删除；
- **长按抖动编辑模式**：类似手机桌面，长按进入抖动状态后可拖拽重排、批量整理；
- **图标质感**：内高光 + 底部投影 + hover 抬起 + active 按压；右键「刷新」重放入场动画；
- **隐藏模式**：右键一键隐藏/显示全部图标。

### 6.2 图标自定义与 128px 高清原生图标

支持 `.ico` / `.png`（≤512KB）替换应用图标；第三方应用无自定义图标时自动从目标 exe 提取 Windows 原生 **Jumbo 128px** 图标（Rust 后端 `icon_dataurl_hd`，HICON → data URL，`.lnk` 先解析目标再提取），桌面/任务栏/开始菜单显示与系统一致且清晰锐利。

这条能力的演进有一段教训史：早期版本提取 32px 图标，在高分屏上明显发糊；整体升级到 128px Jumbo 后，图标在 200% 缩放的 4K 屏上依然锐利。`.lnk` 快捷方式先经 COM IShellLinkW 解析出真实目标 exe，再从目标提取——保证拿到的永远是应用本体的图标而非快捷方式壳图标。

### 6.3 文件架（File Racks）

- **嵌套文件架**：架子可以无限嵌套，像文件夹一样组织桌面入口；
- **六色标识**：每个架子有六种颜色可选，一眼区分用途；
- **链接文件夹**：架子可以直接链接到磁盘上的真实文件夹，打开即文件管理器（环境内以 VWM 窗口呈现）；
- **飞出面板**：点击架子飞出悬浮面板展示内容，拖出即用。

### 6.4 右键菜单

桌面空白处与图标各自拥有完整右键菜单（含悬停展开的子菜单）：新建（记录/导图/文件夹/文件架/从模板）、排序、刷新、显示设置、个性化（壁纸，含「切换到系统桌面」）、任务管理器入口等，与 Windows 桌面习惯一致；右键高级菜单（V-14）补充「以管理员运行/打开文件位置/复制路径」等进阶项。

### 6.5 锁屏与实况场景（N-10 / N-11）

桌面表达域还包含两个仪式级能力：**锁屏与仪式屏**（N-10，闲置/手动锁定的仪式化锁屏界面）与**实况场景组件**（N-11，桌面小组件系统的实时场景卡）。它们与壁纸工坊 2.0、主题工坊、图标包系统（N-07…N-12）共同构成「桌面即作品」的表达层。

## 七、任务栏与开始菜单

### 7.1 任务栏

Win11 风格居中布局：开始按钮 + 固定应用 + 运行中应用 + **小组件区** + 系统托盘 + 时钟；任务栏四向位置可调（上/下/左/右），VWM 工作区边界随之自动推导。

- **小组件区**：CPU 波形图（实时采样）、内存进度条、媒体控制（播放/暂停/上一首/下一首，读取系统媒体会话）、天气卡、今日简报卡（日程/待办/节律摘要，AI-18 氛围组）；
- **运行态**：运行中的应用来自 VWM 虚拟窗口列表，点击开/聚焦/最小化切换，中键多开，多实例徽标（同应用多开时角标计数）；
- **系统托盘**：Variable 托盘图标 + 第三方托盘图标；托盘溢出收纳（M-12）把低频托盘图标收进溢出抽屉；
- **时钟**：点击展开日历与通知中心；日期格式随 i18n 语言（含繁体「週」制）；悬停显示**农历节气节日卡**（本地万年历 2020–2040，含置闰计算，零网络）；时钟细节模式（M-13）可切换秒显/日期组合；

## 八、VWM 虚拟窗口管理器：环境内的一切窗口

VWM（Virtual Window Manager）是 Variable 桌面环境的「窗口系统」：它把原本各自弹 OS 窗口的应用全部收进桌面环境内部，以 DOM 层虚拟窗口的方式托管。它是整个项目里工程密度最高的子系统之一——既要复刻 OS 窗口的全部交互直觉，又要利用 DOM 形态做出 OS 窗口做不到的事。

### 8.1 核心能力

- **独立 Z 序与聚焦态**：点击置顶、点击外部失焦；Alt+Tab 轮转按 Z 序降序；
- **拖拽移动 / 八向缩放**：标题栏拖拽移动（拖拽半透明 + 抬起阴影），边缘八向手柄缩放；**实时尺寸提示**（V-23，px 双列显示，Shift 等比锁定）；**拖拽 Esc 回弹**（V-30，拖拽中按 Esc 撤销本次移动）；
- **边缘贴靠**：拖到屏幕左/右缘 = 半屏，四角 = 1/4，顶部 = 最大化，带实时预览；Win+方向键键盘贴靠；贴靠平滑滑入（.snapping 动效）；
- **最小化到任务栏**：200ms「飞向任务栏」动效后隐藏——**display:none 保活而非卸载**，恢复零重载（Write 的光标与滚动位置、导图的视口都不丢）；
- **同应用多开**：任务栏图标中键 / forceNew 参数新开实例（例如同时开两个 Write 看两篇记录、两个 Explorer 看两个目录）；
- **编组与舞台**：多选编组（V-24）、组贴靠、组拖拽、互换位置（V-26）、一起最小化/关闭（确认门）；StageRail 舞台侧幕 + 焦点历史回溯（V-25）；
- **经典系统菜单（V-21）**：Alt+Space 唤起虚拟窗口的经典菜单（还原/移动/大小/最小化/最大化/关闭），键盘党福音；该键位按 Z-09 处置「yield 桌面层可消费」；
- **画中画（N-04）**：任意虚拟窗口可切画中画小窗置顶；
- **色带（V-29）**：按应用分配窗口色带，多开同类窗口一眼区分，配置带版本号即时重渲染；
- **无响应检测**：窗口内容无响应时的视觉提示与恢复建议（AI-01 窗口手感组）；
- **几何持久化**：每个虚拟窗口的位置/尺寸按 `variable:vwm:geom:v2` 存储，工作区边界按任务栏四向位置自动推导；重开还原；
- **红绿灯**：左绿（关闭）/中黄（最大化）/右红（最小化），与整体视觉一致。

### 8.2 托管对象

| 虚拟窗口 | 打开方式 | 说明 |
|---|---|---|
| Write / Mind / Code / Fate | 桌面图标、开始菜单、launchIndex | 四空间视图原样挂载，CosmicBackground 置于窗口包含块内，多窗口光影零差异 |
| Explorer 文件管理器 | Win+E / Ctrl+E / 任务栏 / 文件架 | 内嵌模式（无自带标题栏），支持带路径新开实例 |
| Recycle 回收站 | Ctrl+Alt+B / 任务栏 | 单实例 |
| 系统中枢 / 数据安全中心 | 快捷面板 / 设置 / 命令面板 | 独立工具窗口（七页 / 十二面板） |
| 第三方应用（tp:\<id\>） | 桌面第三方图标 / 开始菜单 | 占位虚拟窗口 + 原生窗口嵌入（见第十二章） |

### 8.3 关键实现细节

- **translateZ 包含块技巧**：`.vwm-app` 用 `transform: translateZ(0)` 建立包含块，把 `position:fixed` 的 `.bg-root`（WebGL 背景）约束进虚拟窗口——这是「每个窗口自带光影、随窗口移动」的关键；同理，内嵌的 `.ex-window`（Explorer）降级为 `absolute`，避免 fixed 层盖住标题栏；
- **弹簧动画**：打开/恢复用 vwm-in 弹簧动画（scale/translate 使用独立 CSS 属性而非 transform，避免破坏 translateZ 包含块）；
- **任务栏联动**：任务栏运行态 = VWM 窗口列表；点击 = 开/聚焦/最小化切换；中键 = 强制多开；悬停关闭 = 关最上层实例；
- **贴靠与桌面窗口自跳过**：applySnap 对桌面窗口自身跳过，VWM 贴靠与遗留 snap 逻辑互不冲突；
- **编排定时器治理**：orchestrate.ts 全部定时器返回清理句柄，杜绝泄漏（终检会话修复项）。

### 8.4 VWM 的能力边界

VWM 管理的是 DOM 层虚拟窗口；被嵌入的第三方软件窗口是真实 OS 窗口（通过 SetParent 重父级进入虚拟窗口区域），两者在 Z 序、焦点、DPI 上的行为有差异，兼容性防线（第二十五章）负责处理这些差异并如实标注适配等级。

## 九、窗口手感全景：从摇一摇到舞台编排

窗口域是五计划里功能项最密集的域之一（域 2 共 33 项），由 AI-01 窗口手感组（Z-36…Z-42、M-01…M-09）与 AI-02 窗口编排组（U-14、N-01…N-06、V-21…V-30）两个组交付。这一章按「微操作 → 编排 → 空间管理」三层组织全部能力。

- **壁纸工坊 2.0（四引擎 + .vwp）**：壁纸方案存为 `.vwp` 工程文件——图层（静态/视频/网页/粒子四引擎）、变换（Ken Burns 参数）、滤镜、多显示器分配一站式编排，可导入导出分享；
- 右键「切换壁纸」对 image/video 类型在未选过文件时直接弹文件选择框，选完即用；
- 性能档位（`bgTier`）与减少动效（`reduceMotion`）全链路生效。

### 11.2 Wallpaper Engine 扫描与导入（零网络）

- **自动探测安装位置**：注册表 `HKCU\Software\Valve\Steam\SteamPath` 优先，补 C 盘默认路径 + `libraryfolders.vdf` 其余 Steam 库——Steam 装在任意盘都能找到；
- **扫描范围**：创意工坊 `workshop/content/431960/*` 与 `common/wallpaper_engine/projects/{myprojects,projects}/*`；解析 `project.json`（兼容 utf-8-sig BOM）→ 标题/类型/入口文件/preview.jpg；
- **类型如实标注**：video/image → 可导入（视频壁纸/图片壁纸，一键导入后立即生效）；scene/web/application → 标注为不可直接渲染；
- **全类型打开**：
  - video/image → 走 Variable 壁纸链路；
  - web → 网页壁纸 iframe 内嵌；
  - **scene/application** → `wp_engine_open` 命令：前端只传项目目录名 id（校验拒绝路径分隔符/`../`/盘符），Rust 在白名单根内解析 `project.json` 与 `wallpaper64.exe`，生成 `<数据目录>/we-open.cmd` 包装脚本（`chcp 65001` 兼容中文路径），登记为第三方启动项（幂等）后复用既有启动通道独立进程执行 `wallpaper64.exe -control openWallpaper -file <project.json>`——这是 Wallpaper Engine 官方控制接口，壁纸应用在系统桌面；配合「system 让位模式」即可完整体验场景壁纸；
- **安全边界**：路径全部服务端白名单解析，前端输入只有项目 id；进程启动复用已审查的通道，不在壁纸模块新起炉灶。

### 11.3 壁纸兼容的诚实边界

scene 类型是 WE 引擎实时渲染的，Variable 无法在 WebView 里复现（如实标注「不可直接渲染」而非假装支持）；「透明窗口透出 WE 壁纸」方案曾被立项验证并被**证伪**（WebView2 透明与视频渲染冲突），最终采用 system 让位 + 官方控制接口的组合。这段演进记录在批次 E-15/15b，是「如实降级」信条的典型案例。

## 十二、第三方软件启动器与嵌入子系统

### 12.1 登记与便携性三级

- **登记任意第三方 Windows 软件**（exe/lnk/bat/cmd），登记表仅存本机 `<数据目录>/apps.json`；
- **便携性三级**：🟢 portable（数据目录内，随 Variable/U 盘整体迁移）/ 🟡 standalone（自包含单文件但绑定本机路径）/ 🔴 shortcut（安装型），自动判定 + 用户可覆盖；
- **开始菜单扫描**：递归扫描系统 + 用户开始菜单 `.lnk`（COM IShellLinkW 解析目标），跳过卸载器/帮助项，目标去重后返回候选，含名称与图标；UWP 识别去重（M-41）归并商店应用与桌面快捷方式的重复项；
- **拖入添加** + **便携化**（把已安装软件整目录复制进数据目录转为 portable，复制失败如实报错、登记不变）；
- **原生图标**：登记项无自定义图标时自动提取 Windows 原生 128px Jumbo 图标（`icon_dataurl_hd`）；
- **深度检测**：进程级检测应用是否正在运行（含运行中标记）；软件已卸载时图标置灰并提示，可一键清理残留条目；
- **删除护栏**：仅数据目录内的文件允许彻底删除（防误删系统软件）；删除失败（软件运行中/文件被锁）报错并保留登记，绝不半途而废。

### 12.2 启动通道（安全模型）

- **直接启动**：登记 exe 用参数列表方式（`std::process::Command`，无 shell 拼接）以 DETACHED + 新进程组启动，工作目录设为 exe 所在目录；
- **快捷方式启动**：`.lnk` 经 **ShellExecuteExW**（SEE_MASK_NOASYNC | NOCLOSEPROCESS）直接解析启动——不经任何 cmd 字符串拼接，且能取回目标进程 pid（供嵌入的进程树捕获使用）；
- **管理员运行**：ShellExecuteW `lpVerb="runas"`，UAC 弹窗由系统展示，用户取消（SE_ERR_CANCELLED）如实报错；
- 启动时自动撤销桌面窗口置顶，让第三方窗口浮于桌面之上；回到桌面自动恢复。

### 12.3 嵌入子系统（embed.rs）：第三方软件在环境内打开

第三方应用启动后，其主窗口被 **SetParent** 成 Variable 桌面窗口的子窗口（WS_CHILD），随虚拟窗口移动/缩放，从系统任务栏与 Alt+Tab 消失——实现与 Windows 桌面的视觉隔离。

**捕获流程（含启动器型软件的根治方案）**：

1. 启动前记录该应用已有的顶层窗口（避免把旧窗口误嵌）；
2. 通过启动通道取得**根进程 pid**；
3. 以 **Toolhelp32 进程快照展开 pid 树**（根 + 全部后代进程）——启动器型软件（如 Wallpaper Engine 的 wallpaper32/64.exe）真正的窗口属于它派生的子进程，按 exe 名匹配不到，按进程树就能命中；
4. 轮询 EnumWindows 等待新主窗口，**最长约 30 秒**（200ms 一次，命中即返回，慢启动应用不误报）；pid 树为空时按映像名后缀兜底匹配；
5. 命中 → 去标题栏/边框/系统菜单（WS_CAPTION|WS_THICKFRAME|WS_SYSMENU 剥离 + WS_CHILD），SetParent 到桌面 HWND，先给占位边界，随后由前端随虚拟窗口上报精确物理像素边界（embed_bounds）。

**嵌入后的控制**：`embed_bounds`（随虚拟窗口移动缩放）、`embed_visible`（最小化 = SW_HIDE 隐藏，恢复 = SW_SHOW）、`embed_close`（投递 WM_CLOSE，应用自行退出）、`embed_focus`（点击虚拟窗口时移交键盘焦点）。

**失败路径（绝不伤害应用）**：

- 同一时刻只嵌入一个应用；新嵌入前，先前的嵌入先脱离回桌面；
- 捕获超时（30 秒）：应用**保持独立窗口运行，进程绝不终止、登记绝不删除**，提示「应用已在系统桌面独立运行，未受影响；稍后重新从环境内打开即可再试」，前端关闭占位虚拟窗口；
- 无法嵌入的应用（UWP / 管理员权限 / 无标准窗口）如实回退为独立窗口运行。

**嵌入声明协议（variable-embed.json）**：第三方应用可在安装目录放置 `variable-embed.json` 声明自己的主窗口类名/子窗口结构/DPI 行为，Variable 据此优化捕获与缩放；规范见 [`docs/EMBED-MANIFEST.md`](docs/EMBED-MANIFEST.md)。

**隔离边界（如实说明）**：嵌入是用户态窗口层级操作——第三方应用依然运行在系统同一会话的独立进程里，与 Variable 无父子进程关系、无沙箱、无内存配额。Variable 对此保持诚实：它提供的是**视觉与窗口层面的隔离**，不是内核级沙箱（那需要裸机 OS 项目，超出用户态应用的能力边界）。

### 12.4 嵌入验证与兼容分级

C-8 嵌入验证工具（`Compat-Matrix.ps1 -Action Run-Embed/Report-Embed`）提供嵌入能力的批量验证；compat.hint 全链路（探测 → 登记 → IPC → 启动器徽标）把每个应用的嵌入兼容性提示送到 UI；L4（反作弊/全屏独占档）应用强制走独立窗口——tier 路由曾存在「兜底臂吞掉 L4 导致反作弊窗口被强制重父级」的缺陷，已修复并回归覆盖。

## 十三、环境切换：双 Esc 与 Del+Backspace

Variable 提供两组**全局键盘手势**（`kbdhook.rs`，30ms `GetAsyncKeyState` 轮询线程实现，全局状态与焦点/窗口可见性无关）：

| 手势 | 动作 |
|---|---|
| **双击 Esc**（500ms 内两次按下） | 环境 ↔ Windows 切换：环境可见 → 隐藏（露出真实桌面 / Wallpaper Engine 壁纸）；隐藏 → 显示 + 取消最小化 + 置焦 |
| **Delete + Backspace 同按** | 真正退出 Variable：先显示桌面窗口（保证 webview 活跃），再走保存冲刷 + 关闭流程（无确认框，未保存内容已由保存队列兜底） |

**为什么用轮询而不是低级钩子**：WH_KEYBOARD_LL 低级钩子在本环境的宿主进程里会静默失效，且窗口隐藏后 webview 不再处理事件——「隐藏后再切回」不能依赖前端监听。所以切换完全在 **Rust 侧**完成：轮询线程读到双 Esc 直接 show()/hide() 窗口，不经过任何事件链路。该方案经实机按键注入验证（合成 Esc 序列 → 日志 `double-Esc -> toggle environment` → 窗口显隐正确）。

**设计原则**：绝不吞键（钩子/轮询只观察键盘状态，不拦截击键，输入法与其他应用零影响）；轮询频率 30ms（CPU 占用可忽略）；手势状态机与焦点/可见性完全解耦。

## 十四、键盘与输入手感：键位纪律体系

键盘域（域 5，共 29 项）是 Variable 工程纪律的典范：五计划叠加后，全仓有 50+ 处键盘监听，如果没有统一治理，键位冲突会指数级增长。AI-05 键位纪律组的交付把这一切收编进注册表体系。

### 14.1 键位注册表与仲裁（Z-08…Z-14）

- **全局键位注册表（Z-08）**：全仓所有键位监听的单一事实源，`shortcuts.ts` 统一管理；注册表同时是冲突检测的数据源——两个功能不能静默占用同一个 accel；

- **全键盘导航网格（Z-11）**：界面元素的网格化键盘导航（方向键在控件间移动）；
- **上下文键位速查浮层（Z-12）**：长按或快捷键唤起当前上下文的键位速查卡；
- **命令提示条（Z-13）**：操作时底部短暂显示对应快捷键，肌肉记忆的训练器；

### 14.2 输入手感九式（M-28…M-36）

- **键盘全景图（M-28）**：全部键位归属的可视化地图（哪个键被谁占用一目了然）；
- **长按连发（M-29）**、**方向键微移（M-30）**、**Esc 语义栈（M-31，多层浮层时 Esc 逐层退出）**、**Enter 语义（M-32，列表/确认的智能默认）**、**Tab 旅程（M-33，Tab 序的理性排列）**、**浮层栈键位（M-34，浮层堆叠时的键位仲裁）**、**键位冲突急救（M-35，冲突时的可视化引导重绑）**、**键位体检（M-36，扫描全仓键位健康的报告工具）**。

### 14.3 触控与输入基础（U-58 / U-59 / V-61…V-70 / V-94）

- **键盘全景（U-58）**：输入设备与布局的完整画像；

## 十五、写作空间（Library · 记录库）

写作空间是 Variable 的起点功能，也是「私人空间」名字的由来。它是一个完全离线的层级记录库：文件夹树 + 富文本记录 + 标签 + 收藏 + 回收站 + 全文搜索 + 本地媒体。

### 15.1 层级文件夹

- 无限层级文件夹树，支持新建、重命名、拖拽/命令移动、排序；
- 删除进入**回收站**（软删除 `deletedAt` 时间戳），可恢复、可彻底清除、可一键清空；
- 重名拦截、跨层级移动的环检测在 Rust 侧 `library.rs` 以事务保证——把文件夹移进自己的子文件夹这类操作会被数据库层拒绝，而不是制造出孤儿环。

### 15.2 富文本记录

- 基于 TipTap 的所见即所得编辑器：标题层级、粗斜下划线、颜色、对齐、列表、引用、代码块、占位符提示、图片与**内嵌视频节点**（`VideoNode.ts` 自定义 NodeView），字号档位由 `FontSize.ts` 统一管理；
- **跨空间引用锚点**（xref）：Write 中的 `XrefMark.ts` 自定义 Mark 承载 `xref:` 锚点，随正文持久化；点击锚点可打开 Mind 窗口并定位节点；Mind 右键「复制为引用」，Write 中 Ctrl+V 直接插入；引用位置用 ProseMirror Decoration 原地显示「已更新」徽标，保存后自动重校验（xrefStale）；
- 内容双列存储：`contentHtml`（渲染）+ `contentText`（全文搜索），保存前经 `lib/sanitize.ts` 白名单净化——`<script>` 整段剥离、`on*` 事件属性剔除、`javascript:` 等危险 URL 拦截（均有 Vitest 用例覆盖）；
- 元数据：收藏星标、多标签（事务写入标签表）、创建/更新时间。

### 15.3 全局搜索（统一搜索 2.0）

`search_all` 一条命令同时返回四类命中：记录、文件夹、思维导图、导图节点，带片段（snippet）与更新时间；LIKE 转义在 Rust 侧处理，用户输入 `%`、`_` 不会失控。`Ctrl+Shift+F` 唤起全局搜索浮层，`Ctrl+F` 为文内查找；**纯字母查询时启用拼音/首字母回退**，对文档与导图标题做拼音匹配。统一搜索 2.0（N-14）在此基础上支持自然语言式过滤（「本周修改的 带#工作标签」）、结果聚合分组与搜索历史。

### 15.4 本地媒体

- 图片/视频/音频/任意附件通过对话框或**粘贴/拖拽**导入；
- `media.rs` 把文件复制进数据根 `media/`（按内容特征命名避免重名冲突），并在数据库登记媒体与附件两级关系；支持 data-url 直接落盘；
- 删除记录时未被引用的媒体可一并清理；媒体展示走受控的 Tauri asset 协议。

### 15.5 侧栏与工作区面板

- **文件夹树**：层级缩进展示，支持右键菜单、拖拽移动、计数徽标；回收站作为特殊节点出现，条目显示「恢复 / 彻底删除」；
- **记录列表**：标题、收藏星、标签胶囊与相对更新时间，支持排序与筛选；
- **工作区面板**：列出内置工作区目录中的 `.mindmap` / `.project` / `.fatetree` 与任意文本文件，双击直接进入对应空间（环境内即虚拟窗口）；
- **标签云/筛选**：点击任意标签快速过滤全库记录。

### 15.6 保存模型（saveQueue）

- **同键串行**：同一记录/导图的保存请求按序执行，绝不交错；
- **latest-wins**：队列中同键的多个待存项自动合并为最新一次；
- **错误传播**：保存失败抛给调用方并触发 Toast，计入关闭前检查（有专门单测覆盖三种语义）。

这套模型解决的是「连按 Ctrl+S 会不会保存出半截文档」——不会。队列语义保证任何时刻磁盘上的文档都是完整的一次提交。

### 15.7 字数统计与专注模式

- 实时字数统计（中英文混合计数规则在 `format.ts`，有单测）；
- F11 专注全屏；打字期间背景星野降帧，长文写作不因视觉特效掉帧；
- **焦点舱 2.0**（AI-18）：中央任务卡 + 台账（完成项归档）+ 节律顺延（番茄式节奏建议），写作专注的场景化封装。

- 节点/连线采用**批量 upsert**，同一次拖动只提交一次（后端测试验证事务安全）；
- 「导出为 `.mindmap` 文件」把整图（含视口）写入工作区，双击即开；
- 导图右键**「复制为引用」**：把节点变成 `xref:` 锚点，粘贴到 Write 正文，双击锚点跳回本节点；源节点内容更新后，Write 侧徽标提示「已更新」。

### 16.5 与写作空间的协同范式

导图与正文的双向流转是 Variable 独有的生产力范式：灵感先在无限画布上摊开（发散），节点成熟后「复制为引用」挂进正文（收敛），正文写到一半需要回看结构时双击锚点回到导图（往复）。引用关系持久化在内容里，不依赖窗口状态——十年后打开这条记录，锚点依然指向那个节点。

## 十七、项目分析空间（PVCCE · 代码通俗化引擎）

**PVCCE（Project Visualization & Code Comprehension Engine）**：把任意本地代码项目变成一棵「大白话知识树」。整个空间**没有任何弹窗表单**——所有交互就地完成。

### 17.1 导入（四种途径）

整个项目文件夹；单个/多个源文件（增量追加）；工作区拖入；非代码文件（README/配置/设计说明）以「说明书/清单/配置」通俗卡呈现。Rust 侧 `project_scan.rs` 自动跳过 `node_modules`、`.git`、`target` 等噪音目录，**拒绝符号链接越界**、有界读取，`lib/pathGuard.ts` 在前端再做一层防护。双层防护的意义：即使扫描请求被构造恶意路径，Rust 侧的有界读取与越界拒绝也能兜底。

### 17.2 七级无限下钻

```
根 › 目录 › 文件 › 类/结构块 › 函数 › 逻辑块（可折叠）› 逐行
```

- L4 为**双轨制虚拟滚动**：左源码右大白话，6000 行文件也只渲染可视区约 30 行；
- 函数行可**块级折叠**只看大白话总结；`Esc` 逐级返回。

### 17.3 深度语义翻译与词典

- 五维分析（意图/手段/输入/输出/副作用）驱动文件/函数/行级叙述；
- `dedupeCheck` 品控：任意两条比喻文本词级 Jaccard > 0.9 判退化重写——保证「大白话」不千篇一律；
- 通俗风格三选一：**生活比喻 / 故事叙事 / 工程说明**（持久化）；
- 词典七级体系（L1 通用 / L2 语言 / L3 框架 / L4 领域 / L5 意图变换 / L6 惯用短语 / L7 模式识别）+ 十大类扩展包，支持 `.dict.json` 离线导入导出。

### 17.4 意图生成与写回

- 工具栏灯泡放置意图节点 → 双击内联输入大白话 → Enter 生成通俗步骤 + 代码节点；八类意图变换（改颜色/加日志/加注释/改数字/重命名/删行/改文字/加异常）；
- 顶栏「**写入源文件**」二次确认 → 备份 `.backups/*.bak` → **原子写盘**；**Ctrl+Z 两级回滚**：先撤会话内改动，再回滚已落盘写入；
- 推理链三视角（纵向目标步骤/横向依赖/时间因果）全部带真实行号映射。

### 17.5 零 AI 依赖的工程意义

「大白话翻译」完全由本地词典 + 规则引擎生成，不调用任何在线大模型。这带来三个保证：**离线可用**（在无网环境性能不降级）、**可重现**（同一份代码与词典永远产出同样翻译，适合教学与审计）、**可 owned**（用户可以用自己的 `.dict.json` 完全替换内置词典，翻译风格随人而定）。

## 十八、命运推演空间（FTPE · 行为树命运引擎）

### 18.1 六大面板

| 面板 | 内容 |
|---|---|
| 人格 | 1–3 个主导人格按权重加权混合，带相容/冲突网络 |
| 性格 | 正反极滑块（每个特质标注其对立面） |
| 主义思想 | 高值互斥对触发「内心挣扎」 |
| 事件库 | 7 层分类，种子 100+ 条，可自定义扩展 |
| 随机因素 | 运气/时代/健康…每项独立权重与强度旋钮 |
| 推演参数 | 年数 / 每步分支 1–4 / 混沌强度 / 起始年龄 / **确定性种子** / 增益 |

增益（Buff）系统：对携带特定标签的事件做概率乘法，多个 buff 叠乘后整体钳制在 0.05..4，避免一格 buff「掀桌」。

### 18.2 推演算法（确定性、可重现）

```
最终概率 = 基础概率 × 特质乘子 × 随机因素扰动 × buff 乘数 × 混沌扰动
```

- **mulberry32 PRNG**：同一种子 → 完全相同的命运树；
- 特质乘子走 **SIGMOID 映射**（k(0)=0，k(±100)≈±0.93）：中段灵敏、两端饱和；
- 每个时间步按权重采样分支；终点按路径基调分配 **10 种结局原型**；
- 命运树横向时间轴无限延伸，双击事件节点续分子树；可导出为思维导图。

### 18.3 为什么叫「推演」而不是「预测」

它是基于你设定的特质权重与随机种子的**确定性模拟**：同种子可重现，改一个滑块结果就不同——思想实验工具，不是对现实的预言。无模板哲学在这里体现得最彻底：人格、性格、主义思想全部是抽象自构条目，没有任何真人模板。它适合的场景包括：角色设定验证（小说/剧本人物的行为一致性检查）、人生选择的沙盒推演（「如果我更冒险一点会怎样」）、思想实验（两种主义思想的高值互斥会触发什么内心挣扎）。

## 二十五、兼容性防线

兼容性防线（AI-12 兼容纵深组，域 9 共 16 项）处理「Variable 与真实 Windows 生态共处」的一切边界情况。它的原则是**让位优于强占**。

### 25.1 应用适配等级库

- 每个登记应用带 **A/B/C 适配等级**（matrix.json / matrix.ts 双源）：
  - **A** = 完整支持（嵌入/贴靠/多开全部正常）；

### 25.2 深度兼容能力

- **IME 深度兼容（Z-17）**：中文/日文输入法在虚拟窗口内的组合窗口定位与焦点修正（候选框跟随输入位置）；
- **全屏独占协议（Z-18）**：全屏游戏/视频的独占检测 → 任务栏避让 + 嵌入让位 + 快捷键让渡（F-1 反作弊看门：检测反作弊进程主动停用一切监听）；
- **UWP 识别去重（M-41）**：开始菜单扫描时 UWP 应用与桌面快捷方式的重复项归并；
- **便携路径漂移自愈（M-43）**：U 盘换盘符后，portable 登记按**卷 GUID** 重新绑定路径（而非死盘符）；
- **慢速设备档位（Z-21）**：检测数据目录所在设备速度（HDD/U 盘/SSD），自动切换缩略图/索引/搜索的激进程度；
- **高刷折算**：高刷新率显示器上动效时长按 0.85× 折算，保持观感一致；
- **多实例徽标 / 崩溃善后 / 热插拔退避派发**：同应用多开角标；应用崩溃后的重启建议与登记状态修正；显示器热插拔时的事件退避重放（不雪崩）；
- **提权提示 / 驱动共存扫描**：以管理员运行时的可见提示；与常见安全软件驱动共存性的只读扫描报告；

- **远程与虚拟宿主模式（Z-20）**：远程桌面/VM 环境下的特性自动降档（动效关闭、硬件探针降频）。

### 25.3 接管边界（与 28.4 诚实清单联动）

兼容性防线的原则是**让位优于强占**：全屏独占、反作弊、UAC 安全桌面、系统维护界面四类场景，Variable 主动退让并如实记录，绝不硬接管。

## 二十九、性能工程与长跑稳定性

性能域（域 15 的性能部分 + 域 8 联动）由 AI-13 性能与长跑组交付，覆盖 24 项能力。核心理念：性能不是一次优化，而是**可度量、可门禁、可长跑**的持续工程。

### 29.1 渲染与资源治理

- **安全模式启动（Z-57）**：--safe 以最小功能集启动，排障第一步；

### 36.2 分工总原则（七条铁律）

1. **一组一域、权责闭环**：每个功能项有且只有一个责任组；跨组依赖只允许「上游交付物 → 下游消费」，禁止跨组改他人文件领地；
2. **四大内置应用绝对禁区**：`src/apps/write|mind|code|fate/**` 等四空间相关目录全程零修改；任何 diff 触碰即打回；
3. **共享文件最小触碰**：`dictionaries.ts`、`ipc.ts`、`lib.rs`、`vwm.ts`、`StartMenu.tsx`、`desktop.css`、`tools.css` 等按共享文件协议执行——改前 `rg` 核对、最小 diff、改后跑 `node tools/audit.cjs`、zh i18n 块每批前后双复核；
4. **诚实验收**：未实测不勾 ✅；真机依赖项挂待验清单；
5. **批次闸门**：每批收口必须过各计划实施步骤的验证基线与 DoD，闸门不过不得开下一批；
6. **默认即现状**：所有新行为默认关闭或默认等于现状；拿不准的默认最保守档；
7. **零出站与不越权**：除 M-57（唯一出站，四道闸）与 V-81 winget（逐次显式确认）外零自动出站；不越权杀进程、不改系统设置（写回需显式确认与回滚）。

### 36.3 协作纪律（多智能体工程的经验结晶）

- **单一事实源**：功能全景（355 项原文合并）、AI 分工图、五路进度总览三份文档互为锚点，任何组不得私改他人条目；

## 三十九、常见问题（FAQ）

**Q1: 怎么打开 Variable？**
安装版双击 `Variable_1.0.0_x64-setup.exe` 安装后从开始菜单打开；或直接运行 `src-tauri/target/release/Variable.exe`；开发模式 `npm run tauri dev`。详见第三十一章。

**Q2: 提示缺少 WebView2？**
安装 Evergreen Runtime：https://developer.microsoft.com/microsoft-edge/webview2/

**Q3: 双击 Esc 没反应？**
双 Esc 由 Rust 侧 30ms 轮询识别，与焦点无关；若与某些全屏游戏的 Esc 语义冲突，可稍放慢两次按键间隔（500ms 窗口）。确认 kbdhook 线程已启动可查日志中的 env 切换记录。

**Q4: 第三方软件嵌不进去（提示回退独立窗口）？**
三类原因：UWP/商店应用、管理员权限应用、无标准主窗口的应用。嵌入子系统会等待最长约 30 秒；超时后应用保持独立窗口运行（不会被害），可稍后重试。启动器型软件（如 Wallpaper Engine）已通过进程树捕获支持。也可检查应用的适配等级（兼容性防线，A/B/C）。

**Q5: 嵌入的应用崩溃了会拖垮 Variable 吗？**
不会。嵌入只是窗口层级重父级，应用运行在完全独立的 OS 进程里；崩溃只影响它自己的窗口（虚拟窗口内容失效，手动关闭该虚拟窗口即可），环境与其他窗口不受影响。

**Q6: 通讯软件提醒会不会看我的聊天记录？**
不会，也做不到。Variable 只轮询微信/QQ 等应用的**窗口标题**（标题里带「(3)」这类未读计数），聊天正文在对方进程内存里，Variable 不读取、也无法读取，且全程零网络。

**Q7: Win+E / Win+D 被占用了怎么办？**
默认表已改用 ctrl+alt+\* 变体规避 Win11 保留键；若仍有冲突，被占用的快捷键逐项注册失败并诚实降级——功能仍可从任务栏 / 开始菜单 / 快捷面板 / 命令面板进入，日志里会记录哪一项不可用。

**Q8: Wallpaper Engine 的 scene 壁纸为什么「打不开」？**
scene 类型是 WE 引擎实时渲染的，Variable 无法在 WebView 里复现；点击后走 `wp_engine_open` 在**系统桌面**上应用（官方控制接口），配合壁纸模式「系统桌面」（system 让位）或双击 Esc 临时隐藏环境即可观看。

**Q9: 想彻底离线构建？**
先在联网机器执行一次 `npm install` 与 `cargo fetch`（或完成一次 `build-windows.bat`），之后 `cargo build --offline` + `npm ci --offline` 可复现。

**Q10: 卸载后数据在哪？**
`%APPDATA%\com.variable.app`，重新安装后自动继续使用；便携版在 `data\`。卸载器会询问数据去向（回收站式可反悔），不会静默删除。

**Q11: 命运推演为什么叫「推演」而不是「预测」？**
它是基于你设定的特质权重与随机种子的**确定性模拟**：同种子可重现，改一个滑块结果就不同——思想实验工具，不是对现实的预言。

**Q12: 项目分析的「大白话」是 AI 生成的吗？**
不是。全部由本地七级词典 + 规则引擎生成，零网络、零模型调用。

**Q13: 环境里的动效太多/太少？**
设置 → 氛围 → 密度/几何/字体/焦点环/图标尺寸五档位；设置 → 无障碍 → 动效时长全局缩放（0.5x）；系统讲述人开启时自动叠加 reduce-motion。

**Q14: 开放 IPC 网关安全吗？**
默认关闭、零监听；开启后仅绑定 127.0.0.1 环回，需 token + scope 授权，数据连接器只读 + SELECT 白名单。出站动作另走 netconsent 确认。

**Q15: 便携版换电脑/U 盘换盘符后第三方软件路径失效？**
便携路径漂移自愈按**卷 GUID** 重新绑定 portable 登记路径，而非死盘符——同一只 U 盘换盘符自动恢复。

**Q16: 为什么安装包只有 6.5 MB？**
Tauri 架构复用系统 WebView2，不捆绑 Chromium；音景由 Web Audio 实时合成（零音频资产）；图标以矢量与按需提取为主。

**Q17: 数据库损坏怎么办？**
恢复前自动做 SQLite `quick_check` 校验，损坏即拒绝并提示；日常有备份体系（时间戳备份 + 恢复文件 + 版本时间机）。异常关闭后重启会列出恢复文件供一键恢复。

**Q18: 多显示器支持吗？**
支持。壁纸按显示器设置；跨屏摆渡（M-05）快捷键搬移窗口；多屏混合 DPI 兼容（Z-19）；显示器热插拔事件退避重放。

**Q19: 会被杀毒软件误报吗？**
与常见安全软件驱动共存性的只读扫描报告见 `docs/false-positive.md`（运维观察记录）；嵌入与全局键位属于用户态常规操作，如遇误报可提交白名单。

**Q20: 怎么参与翻译/定制词条？**
多语言中心 2.0 的词条工作台支持 CSV 四列导入导出；`tools/i18n-crowd.cjs` 社区翻译格式工具实测 2529 键回环 0 错误；个人惯用词可用简繁用户词表（500 条上限）。

**Q21: 宏引擎会误点 UAC 弹窗吗？**
不会。UAC 判停是宏引擎的硬边界——检测到提权弹窗自动暂停，绝不代用户点击安全桌面；任何时刻急停键可中止回放。

**Q22: 剪贴板历史会记录我的密码吗？**
敏感名单机制：密码管理器类窗口（标题匹配）复制的内容不记录；历史落盘经 DPAPI 加密（换机不可读）；可配置退出即焚。

**Q23: 为什么有些设置改了没生效？**
设置变更以 `settings://changed` 事件跨窗口广播（携带来源与变更键），正常实时同步；如遇个别页面未刷新，重启该虚拟窗口即可（几何与状态会还原）。

**Q24: 演示/录屏时怎么隐藏个人数据？**
演示模式一键隐藏个人数据（假数据壳），QualityTab 可导出诊断包。

**Q25: 项目分析的写回源文件安全吗？**
写入前二次确认 → 自动备份 `.backups/*.bak` → 原子写盘；Ctrl+Z 两级回滚（先撤会话内改动，再回滚已落盘写入）。永远有反悔通道。

### 41.1 一天的 Variable：晨、午、夜三段场景

**晨间（08:00–09:00）· 暖启动**

1. 开机进入 Windows 桌面，双击 Variable 快捷方式（或等待开机自启，若你在设置中开启了自启）；
2. 启动剧场开场：七层氛围按真实加载进度渐强（0.35→0.55），进度条以 HUD 风格走满，文件滚动条（FileTicker）逐条报出正在加载的模块名——这不是表演，是诚实的加载报告（见第四章）；
3. 进入环境后第一件事：`Win+N`（或对应 ctrl+alt 变体，见第三十五章）打开通知中心，确认昨夜有没有漏掉的提醒；硬件面板看一眼电池/网络状态（第二十二章）；
4. `ctrl+alt+e` 打开写作空间，把昨夜睡前想到的三行灵感补进「晨间速记」——写作空间的记录库设计目标就是「两秒进入、三秒离开」（第十五章）。

**午间（12:30–13:30）· 深度区**

1. 双 Esc 收起环境回系统桌面处理外部事务（第十三章）；办完再双 Esc 切回——状态原地保留，所有虚拟窗口、导图画布、未保存草稿都还在；
2. 午休前 20 分钟：打开思维导图空间，把上午散落在速记里的条目拖成一张周计划图（第十六章）；
3. 若需要查阅一个不熟悉的开源库：PVCCE 空间导入仓库路径，让它把核心文件翻译成大白话步骤（第十七章）。

**夜间（21:00–23:00）· 收束**

1. 打开氛围与个性化引擎，把壁纸切到 living 模式（静态图 + 粒子 + Ken Burns 缓动，见第四章与第十一章），音量调到 30%，声音运行时进入夜间通知静默窗口（第二十一章）；
2. 命运推演空间打开今晚想推演的问题——「下季度要不要换项目组」——跑一遍行为树，看三条分支的推演报告（第十八章）；
3. 睡前：数据安全中心一键备份今日增量（第二十八章），然后 Del+Backspace 彻底退出环境（第十三章），让 Windows 干净过夜。

这一天的剧本里没有出现「保存」这个动作超过两次——因为所有空间的数据都落在本地数据库与数据目录，自动持久化是默认行为（第三十四章）。

### 41.2 写作空间实战：从一句话灵感到 3000 字长文

**场景**：周六上午，你想把本周积累的六七条碎片笔记扩写成一篇 3000 字的技术随笔。

**第一步：碎片归集（5 分钟）**

- 打开写作空间的记录库侧栏，本周的速记按时间线排列；
- 用多选（Shift+点击）把六条相关笔记圈出来，右键「合并为新文档」——记录库支持跨条目合并，原文保留为引用块，不丢失任何字；
- 新文档自动命名为「2026-09-12 随笔草稿」，放入「工作区」目录。

**第二步：搭骨架（10 分钟）**

- 在文档内按 `ctrl+alt+1` 插入一级标题、`ctrl+alt+2` 二级标题，先把三个大节的标题立起来；
- 写作空间的标题层级与左侧大纲面板双向同步——点大纲跳正文，点正文高亮大纲，长文不迷路。

**第三步：填充与打磨（90 分钟）**

- 正文用纯文本流书写，不碰鼠标；需要引用代码时按 `ctrl+alt+k` 插入代码块，语言标注自动高亮；
- 中途想去掉一段又怕后悔：选中后 `ctrl+alt+d` 折叠为「暂存块」，它会在文末的暂存区躺到发布前，随时可拖回；
- 写到卡壳处：按 `ctrl+alt+m` 在当前光标处打一个「留白标记」，继续写后面的——留白标记在大纲面板显示为琥珀色圆点，收尾时按图索骥逐一填平。

**第四步：终稿与导出（15 分钟）**

- 全文朗读一遍（无障碍 2.0 的朗读能力，第二十七章）——耳朵比眼睛更容易抓住拗口的长句；
- 导出：右键文档「导出」，可选 Markdown / 纯文本 / HTML 三种格式，落盘到你指定的任意目录；
- 若这篇随笔来自某个真实项目，顺手在 PVCCE 空间给相关分析档案补一条交叉引用（见 41.4）。

**关键心智**：写作空间刻意不提供「富文本排版」——没有字号字体面板，没有分栏排版。它的立场是：先把字写出来，排版交给导出后的专业工具。这是一个「减法功能」的样本（第二章信条三）。

### 41.3 思维导图实战：把季度规划从混沌拖成一张图

**场景**：季度初，你有一堆互相纠缠的目标：三个项目交付、一次技能认证、一场家庭旅行、若干日常事务。

**第一步：倾倒（10 分钟）**

- 新建导图，中心节点写「Q4」；
- 不假思索把脑子里所有事项敲成一级子节点——此时不要整理，追求「倒空」；快捷键 `Tab` 新建子节点、`Enter` 新建同级节点，双手不离键盘（第十六章）；
- 倒完大概有 14 个一级节点，乱没关系。

**第二步：归类（15 分钟）**

- 拖拽节点开始聚类：项目类、成长类、家庭类、事务类四大枝干浮现；
- 无限画布的缩放手势（滚轮缩放 + 空格拖拽平移）让你能一会儿看全景一会儿看细节——思维导图空间的空间感专为「拉远看结构、拉近抠细节」设计。

**第三步：排程（20 分钟）**

- 给每个项目枝干挂「里程碑」子节点，标注月份；
- 节点支持五种状态色（未开始/进行中/受阻/已完成/已放弃），把「已放弃」大方地用在那些其实做不到的事上——导图的价值一半来自「显式砍掉」；
- 三个项目交付有时间冲突：框选两枝，用「对照视图」并排展开，把里程碑错峰排开。

**第四步：挂接与复用（10 分钟）**

- 把「技能认证」节点直接链接到写作空间里去年写的备考笔记（跨空间引用），点击即在虚拟窗口中打开；
- 导图可导出为 Markdown 大纲（层级转为列表），粘进写作空间就变成规划文档初稿——导图是「想」的容器，文档是「说」的容器，两者之间应当有桥。

**关键心智**：导图空间不支持「美化」类功能（图标贴纸、彩虹配色）。它假设结构本身就是美——层级、状态色、连线，仅此而已。这同样是减法（第二章）。

### 41.4 PVCCE 实战：三小时读懂一个陌生开源项目

**场景**：你接手维护一个没写文档的内部工具仓库，约 8000 行 TypeScript。

**第一步：导入与概览（15 分钟）**

- PVCCE 空间选择「打开本地项目」，指向仓库根目录；
- 引擎先产出「结构概览」：入口文件、模块依赖图的第一层、体积最大的五个文件——这五个文件通常就是理解全局的钥匙（第十七章）。

**第二步：通俗化核心文件（60 分钟）**

- 打开体积最大的核心文件，逐段阅读「代码 → 大白话」对照视图：左侧原始代码，右侧每一段的意图翻译；
- 遇到看不懂的函数：光标移入函数体，`ctrl+alt+i` 触发意图解释，引擎给出这个函数「在整条调用链里的角色」而不是逐行语法复述；
- 八类意图变换（改颜色/加日志/加注释/改数字/重命名/删行/改文字/加异常）在这里首次派上用场：对关键函数点「加日志」，生成一段带标记的日志语句——只写入分析档案，不动你的源文件。

**第三步：验证假设（45 分钟）**

- 你形成了「这个仓库的缓存层有竞态」的假设：在两个疑似竞态的函数上都点「加日志」，把生成的日志语句拷贝进真实源码，跑一次测试；
- 测试输出证明假设成立一半——竞态存在但被上游的串行化挡住了。把这个结论写回 PVCCE 的「结论卡」，挂在对应文件的分析档案上。

**第四步：产出档案（20 分钟）**

- 「生成分析报告」：引擎把本次会话的所有结论卡、意图翻译、你手写的批注汇编成一份结构化档案，存入数据目录的项目档案库；
- 档案可被写作空间与导图空间引用——下季度的重构提案，素材已经在这里了。

**关键心智**：PVCCE 不是 AI 聊天窗，不回答开放性问题。它只做一件事：把「代码在做什么」翻译成「人话」，并让你的验证过程留下痕迹。范围窄，才敢深（第二章信条三的又一实例）。

### 41.5 FTPE 实战：一次职业选择的命运推演

**场景**：你拿到一个新团队的转岗邀请，薪资持平、技术栈更新、但管理风格未知。要不要去？

**第一步：建树（20 分钟）**

- FTPE 空间新建推演树，根节点写「转岗邀请」；
- 第一层分三枝：「接受」「婉拒」「拖三个月再决定」；
- 每枝继续展开：接受 → 团队氛围好/一般/差；婉拒 → 留在原组被重用/被边缘化；拖 → 邀请失效/对方加码；
- 三层之后全树已有 20 余节点，行为树的天然优势在这里显现——你被迫把「模糊的纠结」翻译成「明确的分支」（第十八章）。

**第二步：赋值（15 分钟）**

- 给每个叶子节点赋两个值：发生概率（你的主观估计）与效用（对职业五年发展的打分，-5 到 +5）；
- 赋值过程本身就是推演：当你发现「婉拒后被边缘化」这一枝只能给出 35% 概率却说不清理由时，说明这个担忧其实没有证据——把它下调到 15%，树会诚实地反映你的修正。

**第三步：推演与回看（20 分钟）**

- 触发推演：引擎按你的赋值跑出三主枝的期望值、最坏情形、最好情形；
- 「拖三个月」枝的期望值最高，但方差也最大——报告里明确提示「该选择的不确定性成本」；
- 回看模式：时间旅行到三个月后，把「实际发生了什么」录回树中——FTPE 的价值一半在事前推演，一半在事后校准：你的概率估计准不准，只有回看知道。

**关键心智**：FTPE 不是算命。它不输出「正确答案」，只输出「你的判断如果自洽，会指向哪里」。命运引擎的诚实体现在：所有数字都来自你，引擎只负责乘法与呈现（第十八章、附录 F）。

### 41.6 跨空间组合工作流：三个真实编排

**编排一：周报复读机（写作 + 导图 + 通知中心）**

1. 导图空间打开本周计划图，状态色即完成度；
2. 「导出为 Markdown 大纲」粘进写作空间新文档，补三行总结；
3. 定一个周五 17:00 的提醒（通知中心），下周同一时间自动打开这份文档——周报从「回忆苦差」变成「勾选作业」。

**编排二：开源贡献流水线（PVCCE + 写作 + 命名规范）**

1. PVCCE 分析目标仓库的 issue 相关代码，产出结论卡；
2. 写作空间基于结论卡起草 PR 描述——「这个 PR 改了什么、为什么、影响面」三段式；
3. 走查时用 PVCCE 的意图变换预演 diff，避免「提交后才发现改错文件」。

**编排三：年度决策档案（FTPE + 导图 + 数据安全中心）**

1. 年初的每个重要决定各建一棵推演树；
2. 年末导图空间画一张「决策总图」，链接到各棵树的回看结果；
3. 数据安全中心把整年档案刻一份冷备份——这类「人生数据」值得比代码更高的备份等级（第二十八章）。

**编排四：论文/长报告生产线（写作 + PVCCE + 导图 + 朗读）**

1. PVCCE 分析三篇参考文献的核心代码/数据管线，各产出一张结论卡；
2. 导图空间把三张结论卡挂成「文献综述」枝干，补上自己的论证骨架；
3. 写作空间按骨架开写，每个论点引用对应结论卡（跨空间引用直达）；
4. 终稿用朗读引擎通读两遍（耳朵抓病句，第二十七章），导出 HTML 交稿；
5. 全程零网络——文献在本地、分析在本地、写作在本地，你的选题与观点从没离开过这台机器（第二十八章）。

**编排五：家庭数字资产清点（文件管理器 + 写作 + 备份）**

1. 文件管理器双窗模式，左窗旧硬盘全盘、右窗数据目录资产区（第十章）；
2. 照片/文档/证书分批迁移，迁移清单实时记进写作空间「资产台账」；
3. 台账里给每类资产标注备份等级（三份两媒一离线，第二十八章）；
4. 完工后数据安全中心跑一次全量冷备份——从此「家里有哪些重要数字资产」是一个有答案的问题。

**编排六：外接显示器的一天（VWM + 系统硬件面板）**

1. 到工位插上扩展坞：硬件面板实时报出外接屏与分辨率（第二十二章）；
2. VWM 把环境拖入大屏，召回「演播台 1」布局（43.1 节）——外接屏是舞台编排记忆的一部分，插上即恢复；
3. 下班拔线：布局自动收缩回笔记本屏，窗口按比例落位不叠罗汉；
4. 回家再插家里显示器：另一套「演播台 2」召回——一台笔记本，三个舞台。

这六个编排没有用到任何「隐藏功能」，全部是既有能力的组合——这正是设计哲学的落点：**单点功能克制，组合空间开放**（第二章）。

### 42.1 设置中心总览

| 导图画布惯性 | 中 | 平移/缩放的惯性系数 |
| PVCCE 分析深度 | 标准 | 标准（两层调用链）/ 深入（三层，耗时翻倍）（第十七章） |
| FTPE 回看提醒 | 开 | 推演树到期未回看时通知提醒（第十八章） |
| 回收站保留期 | 30 天 | 到期自动物理删除前一周提醒（第十章） |

### 42.5 隐私与数据分区

本分区大部分入口跳转到数据安全中心（12 面板，第二十八章），设置内直接可调的项：

| 项 | 默认 | 说明 |
|---|---|---|
| 日志级别 | info | debug/info/warn/error；debug 只建议排查期开启 |
| 日志轮转配额 | 50 MB | 超限自动轮转归档（第二十九章） |
| 启动时备份检查 | 开 | 发现超过设定周期未备份时横幅提醒 |
| 匿名崩溃签名 | 关 | 开启后崩溃日志附一段不含内容的签名串（便于你自己比对两次崩溃是否同因），依然完全本地 |
| 数据目录迁移 | — | 按钮项：把整个数据目录迁到新位置（第三十四章） |

### 42.6 无障碍与输入分区

| 项 | 默认 | 说明 |
|---|---|---|
| reduce-motion | 关 | 开启后全部动效停用（优先级最高，覆盖一切氛围设置）（第四/二十七章） |
| 讲述人联动 | 开 | 检测到讲述人运行时自动叠加 reduce-motion（第二十七章） |

| 键位冲突降级策略 | 通知 | 被占用键：仅通知（默认）/ 通知+日志 / 静默降级（第五章） |

### 42.7 推荐配置方案

**方案 A · 默认均衡（出厂态）**

适合大多数机器。全部保持默认：living 壁纸 + 30 帧动态上限 + 启动剧场开。这是所有性能与 soak 测试的基准配置（第二十九章 Bench 2.0 即在此配置下测得）。

**方案 B · 性能优先（低配/HDD/U 盘）**

- 壁纸模式 → static；粒子密度 → 低；动态壁纸帧率 → 24；
- 启动剧场 → 关（或系统会因检测到 HDD 自动切保守渲染档，见第二章信条）；
- 微交互五态 → 关；`--dur-scale` → 0.5x；
- 日志级别 → warn。

**方案 C · 氛围拉满（独显台式/性能富余）**

- 壁纸 → dynamic（Wallpaper Engine 接入）；Ken Burns → 0.7；
- 启动剧场 → 开，胶片颗粒与扫描线按喜好；
- 全部音效 → 开，音量 0.5；
- 其余保持默认——即便「拉满」，动效纪律仍然生效：80ms 降档、reduce-motion 令牌、高刷 0.85× 折算一个都不会少（第二章信条九）。氛围是加载状态的函数，不是恒定的表演。

**方案 D · 无障碍优先**

- reduce-motion → 开（或依赖讲述人联动自动开启）；
- `--dur-scale` → 0.5x；界面缩放按需 125%–175%；
- 键位冲突降级 → 通知+日志（明确知道哪些键没注册上）。

四套方案不存在「谁更正统」——环境在每次启动时读取真实硬件画像自动落到 A/B 之间的合适位置，用户设置永远覆盖自动判定（第二章信条一：诚实第一，含对机器的诚实）。

## 四十三、进阶技巧与组合技

本章收录一批「说明书级功能之外」的用法。它们全部由既有能力组合而来，不引入任何隐藏开关——读完第八至十四章你就能自己发明更多。

### 43.1 窗口编排进阶：把 VWM 当排练场用

**技巧一：三指禅——临时演播台**

需要同时对照四个窗口（比如 PVCCE 对照视图 + 写作 + 导图 + 文件管理器）：

1. 先把四个窗口拖到大致区域；
2. 全部框选（空白处拖出选框），右键「对齐网格」；
3. 用舞台编排的预设（2×2 / 1+2 / 三分栏）一键落位（第九章）；
4. `ctrl+alt+s` 保存为「演播台 1」——下次 `ctrl+alt+1`（舞台槽位键，具体键位以第三十五章为准）直接召回整套布局。

**技巧二：摇一摇的真实用途**

摇一摇（拖住标题栏快速晃动两次还原尺寸，第九章）表面是「撤销最大化」，实际高频用法是**快速腾地方**：画布上正满屏看导图，突然要查一个文件——把导图摇下去，文件管理器拖进来，看完再摇回去。全程 1.5 秒，零鼠标精确操作。

**技巧三：分组标签页做「项目抽屉」**

窗口分组（第八章）按「同类自动成组」工作，但你可以手动把异类窗口拖进同一组：把某项目的 PVCCE 档案窗口、写作文档、导图拖成一组，命名「Q4 重构」。此后该组在任务栏上是一个抽屉图标——项目切换变成抽屉切换，桌面永远只摊开一个项目。

### 43.2 启动器与嵌入子系统的进阶用法

**A/B/C 适配等级的实战意义**（第十二/二十五章）

- **A 级（完美嵌入）**：窗口直接吸附进环境，缩放/截图/快捷键全兼容；
- **B 级（可嵌入有损）**：能嵌入但个别输入法/高 DPI 场景有毛刺——建议固定尺寸使用；
- **C 级（独立运行）**：如实回退为独立窗口，环境只负责启动与切回。

进阶用法：给同一个程序注册两个入口——「嵌入模式」和「独立模式」。写代码用独立模式（编辑器需要完整快捷键链路），看文档用嵌入模式（对照方便）。启动器的每个条目都能标注适配等级徽标，等级由实机验收标定，不是拍脑袋（第二十五章）。

**环境切换的「三明治」工作流**

双 Esc 切出环境处理系统事务时，被嵌入的 B/C 级窗口会跟随环境一起隐藏（第十三章）。如果你需要「环境里的东西」与「系统桌面」并排：

1. 切出环境；
2. 再次双 Esc 切回，但立即把需要的那个虚拟窗口**拖出环境边界**——VWM 允许窗口驻留在边界外的「外廊区」（第五章分层模型）；
3. 于是获得「左半屏系统、右半屏环境内窗口」的并排态。外廊区窗口不计入舞台编排记忆，重启后不恢复——它是为临时并排设计的，不是第二桌面。

### 43.3 键位纪律下的肌肉记忆训练法

键位纪律体系（第十四章）规定了冲突降级与全局表规则，而肌肉记忆靠训练：

**第一周：只练四个键**

双 Esc（切环境）、`ctrl+alt+e`（写作）、`ctrl+alt+g`（导图，g = graph）、`ctrl+alt+f`（文件管理器）。坚持一周不碰开始菜单图标。

**第二周：加入空间内三键**

写作的 `ctrl+alt+1/2`（标题层级）、导图的 Tab/Enter（子级/同级）、PVCCE 的 `ctrl+alt+i`（意图解释）。此时你已覆盖 80% 高频操作。

**检验标准**

关掉显示器（真的），盲操作完成：切到导图 → 新建子节点 → 输入文字 → 切回写作。能 10 秒内完成，肌肉记忆毕业。

**为什么默认表用 ctrl+alt+ 变体**

Win11 保留了大量 Win+* 组合（Win+N、Win+E 等），环境选择 ctrl+alt+* 主表 + 系统键「借用不改写」策略：环境内 Win+E 打开的是环境自己的文件管理器，切出环境后 Win+E 恢复系统行为（第十四章）。被占用时逐项降级并记日志（第二章信条一）。

### 43.4 数据目录的符号链接玩法

数据目录（第三十四章）是一个自包含文件夹，这给了进阶用户合法的玩法空间：

**玩法一：冷热分层**

把 `media/`（媒体附件，最大）移到机械盘，原位置留目录联接（junction）：

```powershell
# 以管理员运行,路径示意
Move-Item D:\VariableData\media E:\VariableMedia
New-Item -ItemType Junction -Path D:\VariableData\media -Target E:\VariableMedia
```

环境按普通路径读写，无感知。注意：便携模式（U 盘）不要这么做——跨盘 junction 在拔盘后是断链。

**玩法二：双机同步（你自己就是同步服务）**

两台机器装同一版本，数据目录放同步盘（你自选的任何同步工具，环境不内置也不推荐云同步——第隐私立场章）。要点：

1. 数据库文件在两台机器**不要同时打开**环境——先关 A 再开 B；
2. 备份子目录建议排除同步，避免备份套备份；
3. 这不是官方支持的场景，出了问题以「文件级拷贝恢复」流程自救（34.1 节）。

**玩法三：版本化你的工作区**

把 `workspace/`（工作区文档）纳入你自己的 git 仓库：

```powershell
git init D:\VariableData\workspace
```

写作空间的自动保存直接变成版本历史，`git log -p` 就是全部草稿演进史。数据库里的记录条目与工作区文件是两套存储（第十五章），版本化文件层即可，不要试图版本化数据库文件。

### 43.5 便携模式高级用法

便携模式（31.2/34.2 节）把「程序 + 数据」整目录搬进 U 盘：

**热插拔纪律**

- 拔盘前 Del+Backspace 退出环境（或至少关闭所有空间）——数据库在写入中途拔盘是唯一可能造成数据损伤的操作；
- 插到新机器首次启动会做「便携路径漂移自愈」：以卷 GUID 为锚点重定位数据目录（附录 F），你不需要手动修路径。

**U 盘选购的三个硬指标**

1. **随机 4K 读写**（不是顺序速度！）——数据库是碎小文件，顺序 1000MB/s 而随机 1MB/s 的盘体验极差；
2. 容量 ≥ 64GB（程序 + 系统 + 你的数据）；
3. 发热控制——环境连续运行时 U 盘持续小写，劣质盘会热降速。

**便携模式下的性能预期**

按方案 B（性能优先）配置使用：static 壁纸、剧场关、`--dur-scale 0.5x`。环境检测到 U 盘宿主时也会自动切保守渲染档（第二章信条），你的显式设置永远优先于自动判定。

### 43.7 壁纸工程进阶：档位联动的底层逻辑

第十一章讲了壁纸域的功能面；这里讲它的档位联动怎么被进阶玩家利用：

| 设置组合 | 效果 | 适用 |
|---|---|---|
| static + 粒子关 | 零合成开销 | 最低配/录屏场景（画面稳定） |
| living + 粒子低 + Ken Burns 0.7 | 缓动明显、粒子省电 | 笔记本电池模式 |
| dynamic + 帧率 24 + 剧场开 | 动态壁纸全体验 | 台式机性能富余档 |
| safeMode 启动 | 一切氛围强制关闭 | 排查个性化层问题（44.2 节） |

**关键认知**：四个档位参数（壁纸模式/粒子/Ken Burns/帧率）彼此独立但共享 reduce-motion 总闸——任何时刻打开 reduce-motion，整张表立即坍缩为第一行。这不是 bug 是纪律：无障碍优先级高于一切氛围选择（第二章信条九、第二十七章）。

**录屏用户特别技巧**：录教程/演示前切 static——动态壁纸与粒子层会让视频编码器疯狂输出帧间差异，同等码率下画质显著劣化。Q24 的演示模式（隐藏个人数据）+ static 壁纸 + 通知静默窗口，是三件套式的录屏准备动作。

### 43.8 一个彩蛋级的严谨：窗口关闭取证日志

第九章提到窗口关闭事件写取证日志，区分「用户请求关闭」与「窗口自行销毁」。进阶排查时这是利器：某第三方嵌入窗口频繁消失？打开 `logs/variable.log`，过滤 `window-close-forensics`，每条记录含：窗口 ID、关闭原因（user-requested / webview-crashed / system）、时间戳。若看到 webview-crashed 连续出现，就该给该程序标 B 级甚至 C 级适配（43.2 节）。

这不是隐藏功能，而是第二章信条一的直接产物：**宁可用日志说真话，不用界面装太平**。

## 四十四、性能调优与故障排查手册

第二十九章讲了工程的性能设计；本章面向使用者：怎么把环境调到你的机器最舒服的状态，出问题时怎么自己排查。

### 44.1 三档硬件画像与调优建议

环境启动时读取硬件画像，自动落到三档之一（你的显式设置永远覆盖自动判定）：

| 档位 | 典型画像 | 自动策略 | 建议叠加 |
|---|---|---|---|
| 性能富余 | 独显 / 32GB+ 内存 / NVMe | 全特效，动态壁纸满帧 | 方案 C，随便开 |
| 均衡主流 | 核显 / 16GB / SSD | living 壁纸，剧场开 | 方案 A（默认即最优） |
| 保守低配 | HDD / U 盘 / 8GB / 老核显 | static 壁纸，剧场关，渲染降档 | 方案 B + 日志 warn |

**核显用户特别提示**：living 模式的粒子层走 WebView 合成，核显驱动老旧时可能触发合成器抖动——若观察到壁纸层偶发撕裂，先更新显卡驱动，无效则粒子密度调低或切 static。这不是环境 bug，是合成器与驱动的交互问题，环境会如实记录而不是掩盖（第二章信条一）。

**内存占用参考**（Bench 2.0，均衡档，第二十九章）：空载环境常驻约 180–260 MB（含 WebView2 运行时）；开满四大空间 + 双动态壁纸约 600–900 MB。8GB 机器可跑，但建议同时驻留的应用别超过环境 + 浏览器两个大户。

### 44.2 常见故障决策树

**症状一：双击图标没反应，进程起了又退**

1. 看 `logs/variable.log` 最后 50 行；
2. 常见原因按概率排序：
   - 上一个实例还在运行且数据目录被锁（任务管理器搜 Variable 结束之；打包脚本同款清理逻辑见 stop-variable.ps1，第三十三章）；
   - 便携模式 U 盘换口后盘符漂移 → 首启自愈流程在跑，等 10 秒；仍失败则按 34.2 节手动指认；
   - WebView2 运行时损坏 → 系统设置里修复 WebView2（Windows 11 自带，不需另装）；
3. 以上都不是 → `safeMode` 启动（31.2 节），safeMode 能起就是个性化层问题：关启动剧场、切 static 壁纸，再正常启动。

**症状二：壁纸黑屏/白屏**

1. 壁纸模式切 static → 恢复？则是动态链路问题（来源帧率协商/解码）；
2. static 也黑 → 检查壁纸文件路径是否被移动；内置图库不会黑；
3. living 模式粒子层卡死但底图正常 → 粒子密度调低一档；仍卡 → 这是已知的个别驱动交互问题，收集日志（44.3 节）后切 static 规避。

**症状三：双 Esc 失灵**

1. 先确认不是「被其他全屏独占应用吞键」——切到普通窗口再试；
2. 环境外按了没反应才叫失灵：环境内正常、环境外失灵 → 检查设置中双 Esc 是否为「Rust 侧轮询」模式（默认，第八章）；若你改过注册方式，恢复默认；
3. 全局失灵 → 日志过滤 `double-Esc`，无记录说明轮询线程未起，重启环境；有记录但窗口没动，收集日志自查（44.3 节）。

**症状四：某第三方程序嵌不进来**

这不是故障——A/B/C 适配等级如实回退（第十二章）。查启动器里该程序的徽标等级；C 级就是「设计如此」，环境不假装成功（第二章信条一）。

**症状五：数据打不开/记录丢失**

1. 先别慌：回收站（第十章）查一眼——30 天保留期内的删除都可恢复；
2. 写作空间的「暂存块」（41.2 节）不会随文档删除而清空，去暂存区翻；
3. 数据库层面：数据安全中心的「完整性体检」面板跑一遍（第二十八章）；
4. 最后手段：34.1 节备份恢复流程。这也是为什么 42.5 节的「启动时备份检查」默认开——备份习惯是数据安全的第一责任，环境只负责提醒与执行。

### 44.3 日志采集与自检

**日志在哪**：数据目录 `logs/variable.log`（含轮转归档，配额 50 MB，第二十九章）。前后端错误共用此文件，窗口关闭取证也在其中（43.6 节）。

**采集一次标准诊断包**

1. 设置 → 日志级别调 debug；
2. 复现问题一次（一次就好，debug 日志量大）；
3. 级别调回 info；
4. 把 `logs/` 整个目录拷出来——这就是诊断包。它只包含本地运行信息，无任何账号/网络标识（第二十八章隐私边界）。

**自检清单**（每月两分钟）

- [ ] 数据安全中心：完整性体检绿、上次备份 < 7 天
- [ ] 硬件面板：电池健康无异常掉电
- [ ] 通知中心：无堆积未读的历史遗留
- [ ] `logs/` 目录大小 < 配额一半
- [ ] 回收站无「本想恢复却忘了」的条目

### 44.4 长跑建议

第二十九章的 soak 测试证明 8 小时档无泄漏，但用户侧长跑仍有三条实用建议：

1. **跨夜挂环境没问题**，但隔天建议 Del+Backspace 完整退出一次——让操作系统回收 WebView2 的渲染进程（环境自身无泄漏不等于 WebView 运行时零碎片）；
2. **大导图（2000+ 节点）长时间平移缩放后若觉迟滞**，`ctrl+alt+r` 重绘画布一次（不丢数据，只重建渲染树）；
3. **便携 U 盘长期使用**，每月跑一次 Windows 磁盘检查（`chkdsk /f`）——U 盘闪存比特翻转是便携数据的头号敌人，比任何软件 bug 都常见。

### 44.6 基准自测：验证你的调优真的生效

调优最忌「感觉变快了」。环境提供两个用户侧可复现的基准动作：

**动作一：冷启动计时**

1. Del+Backspace 彻底退出，等 10 秒让后台进程清空；
2. 秒表（手机即可）掐「双击图标 → 进入桌面可交互」；
3. 均衡档 NVMe 机器参考值约 1.8–2.6 秒（Bench 2.0，第二十九章）；HDD 保守档 4–7 秒；
4. 连测三次取中位数——首次启动含磁盘缓存预热，偏差大属正常。

**动作二：滚动压力测试**

1. 导图空间新建测试图，复制出 500 节点；
2. 空格拖拽画布连续平移 10 秒，观察是否掉帧（体感即可，无需工具）；
3. 均衡档应全程顺滑；保守档允许轻微顿挫但不应卡死；
4. 若顿挫明显：粒子密度降一档再测—— wallpapers 与画布共享合成预算，这是最常见的隐性争用。

**调优前后对比纪律**：每次只改一个参数（42 章的任何一项），测一轮记录一次。一次改五个参数然后「感觉快了」，等于什么都没学到——这也是第二章信条在用户侧的回响：**诚实第一，包括对自己的手速错觉诚实**。

### 44.7 何时该怀疑是系统问题而非 Variable

诚实工程也要求用户侧的诚实归因（附录 F「能力诚实声明」的镜像）。以下情况先查系统：

- **环境整体卡顿且资源管理器也卡** → 系统层问题（驱动/杀软扫描/Windows 更新后台）；
- **声音断续且其他应用也断续** → 音频驱动/独占模式问题；
- **网络面板显示离线但浏览器能上网** → 代理软件劫持了探测端点，硬件面板如实显示探测结果，不是误报（第二十二章）;
- **输入法在环境内异常** → WebView2 与 IME 的已知交互面，先试系统输入法兼容设置。

判断总原则：**跨应用可复现的问题不是单一应用的问题**。环境的日志只对环境自己的行为负责（第二章信条一）。

## 四十五、同类工具对比与选型指南

Variable 不是「更好的桌面」，而是「桌面之上的私人层」。本章把它放进真实工具生态里对比，帮潜在使用者做诚实的选型判断——包括「你不该选它」的情形（附录 F 边界原则的选型版）。

### 45.1 与 Windows 11 原生桌面

| 维度 | Windows 11 原生 | Variable |
|---|---|---|
| 定位 | 操作系统外壳 | 用户会话内的桌面环境层 |
| 窗口管理 | 系统窗口 + Snap Layouts | 虚拟窗口（VWM）+ 系统窗口共存 |
| 多空间 | 虚拟桌面（整屏切换） | 四大功能空间（结构化工具，不是空桌面） |
| 隐私 | 系统级遥测（可部分关闭） | 完全离线、无账号、无遥测 |
| 门槛 | 零 | 需接受「环境进出」概念（双 Esc） |

**结论**：两者不是替代关系——Variable 运行在 Windows 会话内，LogonUI 等系统安全边界它明确不碰（第十四章已知边界）。追求「开机即系统桌面」的用户不需要它；追求「一块结构化私人领地」的用户才需要。

### 45.2 与 PowerToys

| 维度 | PowerToys | Variable |
|---|---|---|
| 形态 | 系统增强工具集（ FancyZones、PowerRename 等） | 完整桌面环境 |
| 窗口 | FancyZones 区域布局（作用于系统窗口） | VWM 自有窗口体系 + 编排记忆 |
| 数据 | 各工具各自存储 | 统一数据目录 + 数据库 + 备份体系 |
| 定位 | 「让 Windows 更顺手」 | 「在 Windows 里再造一个私人房间」 |

**结论**：PowerToys 是「增强件」，Variable 是「整个房间」。你可以在 Variable 环境外继续用 PowerToys——键位纪律体系（第十四章）对系统热键的占用策略是「借用不改写」，与 PowerToys 冲突面很小。若只需要 FancyZones 级别的窗口管理，PowerToys 更轻。

### 45.3 与 Rainmeter / Wallpaper Engine

| 维度 | Rainmeter | Wallpaper Engine | Variable |
|---|---|---|---|
| 主业 | 桌面皮肤/小组件 | 动态壁纸 | 桌面环境（壁纸只是其一域） |
| 壁纸能力 | 有限 | 专业级（编辑器+创意工坊） | 接入 WE 全类型 + living 活化模式 |
| 小组件 | 皮肤生态 | 无 | 通知中心/快捷面板/硬件面板（结构化） |
| 纪律 | 无动效纪律 | 可控 | reduce-motion/80ms 降档/档位联动 |

**结论**：壁纸发烧友应该**同时装 Wallpaper Engine**——Variable 的壁纸域设计就是「接入而非重造」（第十一章）：WE 的创意工坊内容直接可用，Variable 负责在环境内的档位纪律与 living 活化。Rainmeter 用户迁移时注意：Variable 不做自由皮肤，它的面板是结构化组件而非自由摆放的皮肤——自由度换来了无障碍可达性（第二十七章，aria-audit 861/861）。

### 45.4 与 Total Commander / Directory Opus（文件管理方向）

| 维度 | TC / Dopus | Variable 文件管理器 2.0 |
|---|---|---|
| 深度 | 数十年积淀，插件生态，双窗范式 | 2.0：双窗 + 标签 + 回收站 30 天 |
| 定位 | 专业文件操作主力 | 环境内自洽够用 |
| 与空间联动 | 无 | 与四大空间、侧栏数据目录节点组直连 |

**结论**：重cmd 用户请继续用 TC——A/B/C 适配等级下把它作为独立窗口（C 级）挂进环境即可。Variable 文件管理器的目标是「环境内不必出去」，不是「替代你的专业工具」（第二章信条三：范围窄才敢深，但先承认范围）。

### 45.5 与 Notion / Obsidian（写作与知识管理方向）

| 维度 | Notion | Obsidian | Variable 写作+导图 |
|---|---|---|---|
| 网络 | 云端优先 | 本地文件 | 本地数据库+文件，完全离线 |
| 形态 | 文档数据库 | Markdown 文件网络 | 记录库+无限画布+分析+推演四空间 |
| AI/插件 | 云 AI/插件生态 | 社区插件 | 无云依赖；PVCCE 本地分析 |
| 迁移 | 导出受限 | .md 开放 | 导出 Markdown/文本/HTML（第十五章） |

**结论**：需要协作与分享的用户选 Notion——Variable 是单人私人空间，「私人」写在产品定义里（第一章）。重度双链笔记用户选 Obsidian。Variable 的差异化在**四空间一体的工作流**：写作-导图-分析-推演在同一环境内互相引用（41.6 节），这是把「知识工具」当作「桌面域」而非「应用」的路线差异。

### 45.6 选型决策表

| 你的情况 | 建议 |
|---|---|
| 只想整理系统窗口 | PowerToys（FancyZones）够了 |
| 只想要好看壁纸 | Wallpaper Engine 直接装 |
| 需要多人协作文档 | Notion / 飞书 |
| 重度双链笔记 | Obsidian |
| 专业文件操作主力 | TC / Dopus 挂 C 级独立窗口 |
| **想要一块完全离线、结构化、可长期沉淀的私人桌面领地** | **Variable** |
| 电脑常在无网环境，或对遥测零容忍 | **Variable（这正是它的出生理由）** |

最后一行加粗不是营销——项目第一行代码之前，「完全离线·无账号·无云同步·无遥测」就是硬约束（第一章）。如果你不信任何云，你在选型表里的位置应该很清楚。

## 四十六、扩展 FAQ 与进阶问答

第三十九章的 25 问覆盖了高频基础问题；本章的 20 问（E1–E20）面向用过一段时间之后冒出来的进阶疑问。答案遵循同一原则：做不到的直说，做得到的讲清边界。

### 46.1 容量与极限类

**E1：环境最多能同时开多少个虚拟窗口？**

没有硬上限，但有两个软约束：可用内存（每个 A/B 级嵌入窗口吃对应程序自己的开销）与你的注意力。舞台编排记忆保存全部窗口布局，Soak 测试验证过 40+ 窗口长跑（第二十九章）。实际建议：单项目抽屉（43.1 节）控制在 8 个以内，超过说明你该用分组而不是更多窗口。

**E2：写作空间能存多少条记录？**

数据库层面百万条无压力（SQLite 的舒适区）。界面层面：记录库侧栏做了虚拟滚动，十万级条目浏览不卡。真正的瓶颈是「人找得到找不到」——所以导图空间才是组织大量记录的正确工具（41.3 节），记录库自己不承担知识管理职责（第十五章）。

**E3：FTPE 的推演树可以导出分享给别人吗？**

可以导出为自包含的 Markdown（树结构转为缩进列表 + 赋值表），别人用任何文本工具都能读。但「回看模式」的对照数据只在你的环境里——推演的价值一半在事前一半在事后校准（41.5 节），事后那一半无法分享，这是设计属性不是功能缺失。

**E4：PVCCE 支持哪些编程语言？**

以 TypeScript/JavaScript、Python、Rust、Go、C# 为主力语种（意图翻译的语料覆盖最深），其他常见语言基础可用（结构概览、依赖图不分语种）。「加日志」等八类意图变换按语种适配，未覆盖语种会如实提示「该语种暂不支持此变换」而不是硬生成（第二章信条一）。

### 46.2 技术选型类

**E5：为什么用 Tauri 而不是 Electron？**

安装包 6.5 MB vs 动辄百 MB；内存常驻约 200 MB 级 vs Electron 应用常见的 400MB+；Rust 后端可直接调 Win32 API（图标 128px Shell 提取、双 Esc 轮询这类活不需要原生模块桥接）。代价是 WebView2 依赖系统版本——这是 Q2 那个 FAQ 存在的原因（第三十一章环境要求）。

**E6：Rust 后端可以写插件吗？**

v1.x 不开放后端插件接口。开放 IPC 网关（Q14）面向脚本与自动化场景，不是代码级插件。理由：后端 API 的稳定性承诺成本极高，「环境自己的 355 项功能先做到全绿」优先级更高（第三十六章）。插件体系在路线图中（第四十章），但不承诺时间表——未排期的承诺等于谎言。

**E7：支持多用户/多人共用一台电脑吗？**

每个 Windows 用户账户各有一份独立数据目录（数据目录按系统用户路径隔离，第三十四章），互不可见。但「同一个账户内多套人格/工作区切换」不是 v1.x 的功能——环境假设私人空间的主人只有一个，这与产品定义同源（第一章）。

### 46.3 数据与迁移类

**E8：更新版本会覆盖我的数据吗？**

不会。程序与数据物理分离（第三十四章）：更新只动程序目录，数据目录原样。数据库带版本迁移机制（第三章 db/state 层），新版本首次启动自动迁移并留迁移前备份。唯一例外是便携模式手动覆盖整目录的升级姿势——请按 34.2 节流程先备份数据子目录。

**E9：为什么用数据库而不是纯 Markdown 文件？**

记录条目的元数据（时间线、状态、跨空间引用、回收站 30 天）需要事务一致性；Obsidian 式纯文件网络在「删除恢复、引用完整性、十万条性能」上是弱项。折中：**数据库管结构，文件管内容**——工作区文档是真实文件（43.4 节可以 git 版本化），数据库管它们的索引与关联。

**E10：彻底卸载（含注册表残留）怎么做？**

安装版走卸载器后，数据目录默认保留（Q10 的设计——防止误卸载毁数据）。真要删干净：卸载 → 手动删数据目录（位置见 34.1 节）→ 完成。注册表只写了卸载信息与文件关联，卸载器会清；不留遥测类残留——因为从来就没有遥测（第二十八章）。

### 46.4 使用场景类

**E11：快捷键能自定义吗？**

键位纪律体系（第十四章）v1.x 提供的是「冲突降级策略」可调（42.6 节），不是任意改键。原因：默认表是全部门禁（keymap-audit）与文档（第三十五章）的锚点，开放任意改键等于让每个用户的键盘都不再可比。自定义键位映射在路线图（第四十章），态度同 E6：不承诺时间表。

**E12：环境内能玩游戏吗？**

能启动（C 级独立窗口），但没必要：游戏要的是独占全屏与最低输入延迟，环境的价值（编排、对照、沉淀）在游戏场景全部为零。诚实的建议：游戏留在系统桌面玩，双 Esc 秒切（第十三章）。

**E13：截图功能在哪？**

快捷面板（第二十二章）提供区域截图，落盘数据目录媒体子目录并写入索引。不提供长截图/OCR/贴图——那是专业截图工具的领域，环境只保证「环境内所见即可截」这个自洽闭环（第二章信条三）。

**E14：视障用户实际怎么用？**

三层：讲述人联动（检测到即自动 reduce-motion，第二十七章）→ 全量 aria 树（861/861 元素过检）→ 朗读引擎（文档与界面文本）。键盘可达性上，全部核心流程有纯键盘路径（41.3 节的盲操作训练即证明）。真实重度视障使用仍需讲述人/放大镜配合——环境做的是「不成为障碍」，不是「替代辅具」（第二十七章边界）。

### 46.5 项目与参与类

**E15：如何报告 bug？**

仓库 issue，附 44.3 节的标准诊断包。请先跑一遍 44.2 节决策树排除系统侧原因——「跨应用可复现的问题不是单一应用的问题」（44.5 节）。已知边界清单（第十四章、附录 F）里的问题不用报，那是声明过的「不做」。

**E16：项目接受功能建议吗？**

接受，但通过率取决于与信条的契合度而非点赞数（第二章十条信条是宪法）。反例：云同步、账号体系、多人协作——再多人要也不做，因为与「完全离线·私人空间」的定义冲突。正例：更好的键位、更深的分析、更稳的性能——怎么都不嫌多。

**E17：许可证/商用？**

见仓库 LICENSE 文件与本 README 的许可声明。一句话：个人使用完全自由；商用与二次分发遵循许可证条款，不设双重授权陷阱——一个隐私优先的项目在自己的许可上玩套路，是自我否定。

**E18：为什么坚持不做云同步？**

不是技术做不到，是定义不允许：「完全离线·无账号·无云同步·无遥测」是出生约束（第一章）。想要多机同步的用户有 43.4 节的自助方案（文件级同步 + 使用纪律），环境不内置、不推荐、但也不阻止你自己负责（第三十四章）。

**E19：v2 会做什么？**

路线图（第三十八章、四十章）的主轴是便携虚拟系统（A 档免重启 / B 档原生启动的 U 盘系统）与六大件。态度：**只公布已排期的，不画饼**——355 项功能全部交付完毕才写这份 README，就是这个态度的证明（第三十六章）。

**E20：为什么叫 Variable（变量）？**

因为这个名字同时说了三件事：计算机科学里「变量」是「装东西的容器」——它是你的私人容器；「变量」意味着「可变」——从壁纸到键位到空间参数一切可调（第四十二章）；而它跑在 Windows 这个「常量」之上，不改写宿主，只做自己（第十三章环境切换哲学）。一个名字，三重身份，以及一个朴素的愿望：**你的桌面，应该是你的变量。**

这份 README 从第〇章的「三分钟读懂」写到第四十六章的进阶问答，连同六个附录，覆盖了 Variable v1.0.0 的全部交付：五计划 355 项功能、20 个 AI 协作组的代码级实现、六道质量门禁的全绿记录，以及最重要的——每一条「做不到的事」。

2. **不夸大做过的东西**——边界、弱项、已知问题全部成文（第十四章、附录 F、44.7 节）；
3. **不省略难说的东西**——从数据库选型争议（E9）到云同步立场（E18），决策理由尽量透明。

如果你读到这里，无论是否使用 Variable，希望至少带走一个工程判断：**文档的诚实度，就是产品的诚实度。** 一个把「做不到」写成清单的项目，「做到」的部分才值得相信。

2. **白天写作**：桌面双击「Write」→ 星空下的虚拟窗口编辑器。Ctrl+N 新建记录，粘贴截图与视频素材，打上标签 Ctrl+S；在 Mind 画布上把灵感节点「复制为引用」粘回正文，双击即可来回跳。第二个 Write 窗口中键任务栏图标即开，两篇对照着写。觉得背景吵？Ctrl+Alt+P 进纯净模式，音景切到「雨夜」，音量淡变不炸耳。
3. **读别人的代码**：切到项目分析，导入一个开源仓库；对核心函数「查看推理链」，再「逐行解剖」读 6000 行文件；想加功能就放意图节点，「写入源文件」（自动备份 + 原子写盘 + Ctrl+Z 可回滚）。
4. **把游戏关进环境里**：把 WorldBox 拖进启动器 → 双击图标 → 游戏窗口出现在环境内的虚拟窗口里，系统任务栏与 Alt+Tab 里完全没有它；逐应用音量记忆让游戏声与音乐软件互不打架；双击 Esc 瞬间切回真实桌面回个消息，再双击 Esc 回到环境，游戏还在原地。
5. **傍晚整理**：把常用软件拖进桌面文件架，六色标识分好类；文件管理器双栏对照，大文件雷达扫一遍 C 盘；回收站里搜索清掉垃圾，焚毁两个敏感文件；数据安全中心的信任链全绿。
6. **夜晚推演**：命运推演里搭一个角色，种子 20260909，双击关键转折续分子树，导出为思维导图归档。设置里点开 Wallpaper Engine 的场景壁纸 → system 让位模式 → 真实桌面上星河流动，双击 Esc 随时回来。

## 附录 C：批次演进史

Variable 采用小批次演进，每个批次都有明确的验收与教训记录（完整开发日志见 [`project_memory.md`](project_memory.md)）：

- **E-8**：zh-TW 繁体语言包（s2t.ts 字符级转换 + 词汇覆盖）、拼音/首字母搜索、通讯软件提醒（imwatch.rs）、NSIS/MSI 打包与验收清单；
- **E-9**：**VWM 虚拟窗口管理器**落地——四软件改由桌面层内虚拟窗口托管，translateZ 包含块实现多 WebGL 光影随窗口走，display:none 保活最小化；
- **E-10**：用户实测缺陷集中修复——交互宿主补全、explorer/recycle 收进 VWM、红绿灯顺序统一（绿|黄|红）、快捷键默认表改 ctrl+alt+* 规避 Win11 保留键；
- **E-11**：实机自检修三根因——右键子菜单死锁、双快捷键表并存、VWM 红绿灯错排；
- **E-12/13**：Wallpaper Engine 扫描导入（注册表探测 Steam 任意盘）、图标尺寸对齐 Windows、壁纸 1:1 清晰化（去 blur/暗罩）、环境完全覆盖 Windows 任务栏；
- **E-14**：四款功能图标独立视觉语言重设计（AppGlyphs）、VWM 窗口弹簧/关闭/飞行/贴靠全套动效、图标质感；
- **E-15/15b**：Wallpaper Engine 全类型打开（web iframe 内嵌 + wp_engine_open 官方控制接口 + we-open.cmd 包装脚本）、system 让位模式；证伪「透明窗口透出」方案（WebView2 透明与视频渲染冲突）；
- **E-16**：第三方应用嵌入子系统（embed.rs）初版——SetParent、边界/焦点/关闭控制、桌面图标隐藏模式、原生图标提取、双 Esc 退出；
- **E-17/18**：环境切换键位定型——kbdhook.rs 重写为 GetAsyncKeyState 轮询线程（双击 Esc 切环境、Del+Backspace 真退出，实机注入验证）；图标一致性（.lnk 先解析再提取）；
- **v1.x 五计划**：355 项功能由 20 个 AI 协作组代码级全部交付并全仓收口（见第三十六章）；
- **实机反馈修复批次**：动态壁纸活化（living 模式：粒子叠加 + Ken Burns 缓动）、128px Jumbo 高清图标提取（icon_dataurl_hd）、启动氛围七层重铸（BootAtmosphere：双层极光幕/三层尘埃场/流星/暖光/暗角/颗粒/扫描线，强度随真实进度 0.35→0.55）、游戏级胶囊进度条（CapsuleBar：全宽 HUD/右上角百分比/24px 分段刻度/扫光；启动文案全英文化 Consolas 大写字距）、build-windows.bat 打包前自动停掉仓库内运行实例（stop-variable.ps1，防 os error 5 文件锁）。
