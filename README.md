# Variable — Private Space（私人空间）

**完全离线、无账号、无云同步的私人写作 + 思维导图 + 项目分析 + 命运推演 Windows 桌面应用。**

Variable 是一款以「隐私即默认」为第一原则的本地桌面软件：它不注册、不登录、不上传，
所有数据（记录、思维导图、项目分析档案、命运推演树、媒体附件、备份、日志）都只存在于
你自己的电脑上。它同时是一款「审美驱动」的软件——原生 WebGL 星空与极光背景、
低饱和冷调视觉语言、自定义无边框窗口与启动动画，让一个严肃的生产力工具拥有宇宙级的氛围感。

## 一、产品定位与设计理念

### 1.1 这是什么软件

Variable 是一个运行在 Windows 桌面上的单窗口多空间应用，核心由四个彼此独立、
又可以通过「引用」互相跳转的功能空间组成：

1. **写作空间（Library）**：层级文件夹 + 富文本记录 + 标签 + 收藏 + 回收站 + 全文搜索 + 本地媒体。
2. **思维导图空间（Mindmap）**：无限画布、自由节点、丰富的连线样式、小地图、节点绑定记录。
3. **项目分析空间（PVCCE）**：把任意本地代码项目「翻译成大白话」，七级下钻、逐行解剖、推理链、意图生成、写回源文件。
4. **命运推演空间（FTPE）**：基于特质权重与确定性种子的行为树命运模拟引擎，
   人格/性格/主义/事件/随机因素/增益六大面板驱动一棵可无限续写的命运树。

### 1.2 设计理念

- **隐私即默认**：零网络请求、零遥测、零账号。数据库、媒体、备份全部落在本机；
  便携模式甚至可以把整个数据目录放进 U 盘随身携带。
- **启动即写作**：窗口打开的第一眼就是编辑器，键盘可达、快捷键齐全，
  打字时背景自动降级渲染以保证输入零延迟。
- **无模板哲学**：尤其在命运推演里，人格、性格、主义思想全部是抽象自构条目，
  没有任何真人模板——它是一个「思想实验沙盒」，不是算命工具。
- **零 AI 依赖**：项目分析的「大白话翻译」完全由本地词典 + 规则引擎生成，
  不调用任何在线大模型，同样的话术在十年后的离线机器上依然可用。
- **可重现与可追溯**：命运推演同种子完全可重现；源文件写入先备份再原子落盘、
  支持 Ctrl+Z 回滚；数据库写操作有事务与恢复文件兜底。

### 1.3 目标用户

- 需要一个完全私密写作环境的个人作者；
- 用思维导图整理灵感、并希望节点能直接挂接长文记录的人；
- 想快速读懂一个陌生代码库（自己的旧项目、开源项目）的开发者；
- 喜欢做人生推演、角色设定、思想实验的创作者与玩家。

## 二、总体架构

### 2.1 技术栈

| 层 | 技术 |
| --- | --- |
| 桌面壳 | Tauri 2.x（Rust 后端 + 系统 WebView2，无捆绑 Chromium） |
| 前端框架 | React 18 + TypeScript 5（`strict` 严格模式全量通过） |
| 构建工具 | Vite 5（开发端口 1420，`tsc --noEmit` 先行类型检查） |
| 富文本编辑器 | TipTap 2（ProseMirror 生态：starter-kit + 颜色/图片/占位/对齐/下划线扩展） |
| 本地数据库 | rusqlite（SQLite，WAL 模式，版本化迁移 `0001_init.sql` / `0002_frame_extras.sql`） |
| 图标库 | lucide-react |
| 视觉渲染 | 原生 WebGL / WebGL2（星空 worker 管线 + Ray-Marching 极光管线），无三方渲染库 |
| 测试 | Vitest（前端单测）+ cargo test（后端集成测试，含 e2e 命令面测试） |

### 2.2 进程与通信模型

```
┌─────────────────── WebView2（前端）────────────────────┐
│ React 组件树                                           │
│  ├─ App.tsx        空间路由 / 全局交互状态机 / 恢复提示 │
│  ├─ features/*     四大空间实现                        │
│  ├─ lib/ipc.ts     类型化 IPC 封装 + 错误归一化        │
│  └─ lib/saveQueue  同键串行、latest-wins 的保存队列    │
└───────────────△───────────────────────┬───────────────┘
                │ invoke (JSON)         │ Tauri IPC
┌───────────────┴───────────────────────▽───────────────┐
│ Rust 后端（src-tauri）                                 │
│  ├─ system        引导信息 / 打开路径 / 前端日志落盘   │
│  ├─ library       文件夹与记录 CRUD / 搜索 / 回收站    │
│  ├─ mindmap       导图与节点/连线批量存储             │
│  ├─ media         媒体导入 / data-url 落盘 / 附件     │
│  ├─ workspace     内置工作区目录树操作                │
│  ├─ project_scan  项目扫描（噪声目录跳过/越界拒绝）   │
│  ├─ backup        备份与恢复（quick_check 校验）      │
│  ├─ export        记录/导图/工作区 导出与导入         │
│  ├─ settings_cmd  设置 KV / 恢复文件管理             │
│  └─ db/state      连接、迁移、日志、便携模式判定      │
└───────────────────────────────────────────────────────┘
```

前端通过 `lib/ipc.ts` 把全部 60 余个 Tauri command 收敛为带类型的调用面；
`tools/audit.cjs` 静态审计「前端调用的命令都有 Rust 注册、i18n 键完整」，
防止前后端命令面漂移。Rust 侧统一错误类型（`error.rs`）把底层错误翻译成
可展示的中性文案，避免裸 panic 直接击穿 UI。

### 2.3 前端代码结构

```
src/
├─ App.tsx                  空间路由、全局点击捕获、关闭保存流程、恢复提示
├─ main.tsx                 入口 + 浏览器开发模式的 IPC 桩（避免假报错）
├─ components/              TitleBar（无边框自绘标题栏）、Modal、ContextMenu、
│                           ToastHost、WindowControls、ErrorBoundary
├─ features/
│  ├─ folders/Sidebar.tsx   层级文件夹树 + 记录列表 + 回收站 + 工作区面板
│  ├─ editor/               EditorView（主编辑器）、VideoNode、FontSize
│  ├─ mindmap/              MindmapView 与节点/连线/小地图/检查器/泊坞条
│  ├─ projectviz/           ProjectAnalysisView + 词典/解析/叙述/意图/写回引擎
│  ├─ fate/                 FateView + engine/behaviorTree/dictionaries
│  ├─ background/           CosmicBackground + starfield（worker + WebGL）
│  ├─ search/               全局搜索浮层（四类命中）
│  ├─ settings/             SettingsModal
│  └─ startup/              StartupAnimation 启动动画
├─ lib/                     ipc、settings、sanitize（HTML 净化）、pathGuard（路径防穿越）、
│                           saveQueue、mindmapFile（.mindmap/.project/.fatetree 读写）
├─ i18n/                    中英双语文案与运行时切换
└─ state/uiStore.ts         全局 UI 状态（模式/焦点/恢复提示/吐司）
```

### 2.4 全局交互细节（App 层的工程质量）

- **捕获阶段「点击空白即销毁」状态机**：`App.tsx` 在 capture 阶段监听 `pointerdown`，
  任何不属于浮层面板（右键菜单/节点菜单/连线气泡/检查器）与文本框的左键点击，
  都会强制销毁全局激活状态——没有任何浮层能靠 `stopPropagation` 逃避关闭。
- **打字降级渲染**：监听可编辑区域的单字符按键，1.5 秒内标记 `editing`，
  让 WebGL 背景自动降帧/降级，保证输入永远跟手。
- **关闭前保存兜底**：窗口关闭先走保存流程，失败时弹出
  「取消关闭 / 重试保存 / 强制关闭」三选模态，绝不静默丢稿。
- **异常关闭恢复**：崩溃或强杀后，重启时恢复提示宿主会列出恢复文件
  （标题/时间/预览），一键恢复为新记录或删除。

## 三、四大功能空间总览

四个空间通过顶栏按钮与全局状态 `uiStore.mode` 切换：

| 模式 | 入口 | 存档形态 |
| --- | --- | --- |
| 写作 `write` | 默认 | SQLite `variable.db` |
| 思维导图 `mindmap` | 顶栏「思维导图」 | 数据库存储 + `.mindmap` 文件档案 |
| 项目分析 `project` | 顶栏「项目分析」（文件夹+放大镜 · 冰蓝） | `.project` 文件档案 |
| 命运推演 `fate` | 顶栏「✨ 命运推演」 | `.fatetree` 文件档案 |

三种文件档案（`.mindmap` / `.project` / `.fatetree`）与记录库平级，保存在内置工作区里：
侧栏「工作区」面板双击即可直接打开对应空间，也支持从资源管理器拖入。

空间之间唯一的「耦合」是刻意的**双向引用管道**：项目分析中的文件节点可以右键
「引用到思维导图」，在当前导图上生成樱花粉（#f8d4e4）引用节点；双击引用节点又能
跳回该文件的通俗解读卡，「双向引用」面板提供一键互跳。除此之外四个空间数据完全独立、互不污染。

## 四、写作空间（Library · 记录库）

### 4.1 层级文件夹

- 无限层级文件夹树，支持新建、重命名、拖拽/命令移动、排序；
- 删除进入**回收站**（软删除 `deletedAt` 时间戳），可恢复、可彻底清除、可一键清空；
- 重名拦截、跨层级移动的环检测在 Rust 侧 `library.rs` 以事务保证。

### 4.2 富文本记录

- 基于 TipTap 的所见即所得编辑器：标题层级、粗斜下划线、颜色、对齐、列表、引用、
  代码块、占位符提示、图片与**内嵌视频节点**（`VideoNode.ts` 自定义 NodeView），
  字号档位由 `FontSize.ts` 统一管理；
- 内容双列存储：`contentHtml`（渲染）+ `contentText`（全文搜索），保存前经
  `lib/sanitize.ts` 白名单净化——`<script>` 整段剥离、`on*` 事件属性剔除、
  `javascript:` 等危险 URL 拦截（均有 Vitest 用例覆盖）；
- 元数据：收藏星标、多标签（事务写入标签表）、创建/更新时间。

### 4.3 全局搜索

`search_all` 一条命令同时返回四类命中：记录、文件夹、思维导图、导图节点，
带片段（snippet）与更新时间；LIKE 转义在 Rust 侧处理，用户输入 `%`、`_` 不会失控。
`Ctrl+Shift+F` 唤起全局搜索浮层，`Ctrl+F` 为文内查找。

### 4.4 本地媒体

- 图片/视频/音频/任意附件通过对话框或**粘贴/拖拽**导入；
- `media.rs` 把文件复制进数据根 `media/`（按内容特征命名避免重名冲突），
  并在数据库登记媒体与附件两级关系；支持 data-url 直接落盘；
- 删除记录时未被引用的媒体可一并清理；媒体展示走受控的 Tauri asset 协议。

### 4.5 记录与导图的绑定

导图节点可以绑定一条记录（`MindNode.recordId`）：双击节点上的记录角标即可
切回写作空间并定位该记录——「灵感在图上，正文在库里」。

### 4.6 侧栏与工作区面板（Sidebar / WorkspacePanel）

侧栏是写作空间的「总控台」，纵向分为四个区：

- **文件夹树**：层级缩进展示，支持右键菜单（新建子文件夹/重命名/移动/删除）、
  拖拽移动、计数徽标；回收站作为特殊节点出现，进入后条目显示
  「恢复 / 彻底删除」两个动作，清空回收站需二次确认；
- **记录列表**：显示当前文件夹下记录的标题、收藏星、标签胶囊与相对更新时间，
  支持按更新时间/标题/收藏排序与标题内筛选；
- **工作区面板**：列出内置工作区目录中的 `.mindmap` / `.project` / `.fatetree`
  与任意文本文件，双击直接进入对应空间或预览文本；
  支持从系统资源管理器拖入文件复制进工作区（`ws_copy_in`）、
  新建目录（`ws_create_dir`）、重命名与移动（`ws_rename` / `ws_move`）、
  删除进回收站（`ws_delete_trash`）；`ws_default_dir` 提供默认目录定位；
- **标签云/筛选**：点击任意标签快速过滤全库记录。

### 4.7 保存模型（saveQueue）

前端所有持久化写入都经过 `lib/saveQueue.ts`：

- **同键串行**：同一记录/导图的保存请求按序执行，绝不交错；
- **latest-wins**：队列中同键的多个待存项自动合并为最新一次，减少无效 IPC；
- **错误传播**：保存失败会把错误抛给调用方并触发 Toast，同时计入关闭前检查——
  这就是「关闭前保存兜底」的数据来源（有专门单测覆盖三种语义）。

### 4.8 字数统计与专注模式

- 实时字数统计（中英文混合计数规则在 `format.ts`，有单测）；
- F11 专注全屏：隐藏侧栏与顶栏装饰，只留纸面；
- 打字期间背景星野降帧（见 2.4），长文写作不因视觉特效掉帧。

## 五、思维导图空间（Mindmap · 无限画布）

### 5.1 节点系统

- **八种形状**：矩形、圆角、圆、三角、菱形、五边形、六边形、七边形（`NodeShape`）；
- 每个节点独立拥有：位置/尺寸、圆角、边框色、填充色、字号、透明度、旋转、
  层级 `zIndex`、锁定、隐藏、折叠、分组 `groupId`、预设样式（`presets.tsx` 一键套用）；
- 节点文本为富文本（textHtml + textPlain 双列），支持行内样式；
- **批量操作**：框选多选后可统一改样式、对齐、编组，`SelectionOpsBar` 提供浮动操作条；
- 剪贴板：Ctrl+C/V/X/D 复制粘贴剪切复制节点（含样式与相对位置）。

### 5.2 连线系统

- 三种方向（正向/双向/无箭头）、三种线型（实线/虚线/点线）、
  三种路径（曲线/直线/直角正交）、自定义颜色宽度标签、流动动画与辉光；
- 连线几何由 `geometry.ts` 统一计算：**锚点永远位于节点边中点**、
  圆形直径约束、正交与曲线路径生成、命中检测（均有单元测试）；
- 点击连线弹出 `EdgePopover` 就地改样式；删除节点时连线级联清理（后端测试覆盖）。

### 5.3 画布操作

- 左键拖拽平移（工具栏可切框选）、中键平移、空格临时平移；
- 滚轮 / Ctrl+滚轮缩放（指针锚点缩放，不飘移）；
- WASD / 方向键移动视图（编辑文字时自动失效）、Shift 加速、Ctrl 微调；
- `Home` 回中、`F` 适应全部、`Shift+F` 适应所选、`G` 网格开关、`+/-` 缩放；
- `N` 新建文本框、双击节点编辑、三击取消编辑、`Esc` 退出；
- **Minimap 小地图**实时同步视野框；`InspectorPanel` 检查器就地改选中节点全部属性；
- 导图的视口（viewportX/Y/zoom）、网格、吸附设置随图保存，重开还原。

### 5.4 存储与文件

- 节点/连线采用**批量 upsert**（`save_nodes` / `save_edge`），同一次拖动只提交一次；
  后端测试专门验证重复执行两次不再出现
  *cannot start a transaction within a transaction*；
- 「导出为 `.mindmap` 文件」把整图（含视口）写入工作区，双击即开；
  `lib/mindmapFile.ts` 同时承担 `.project` / `.fatetree` 的读写协议
  （`app` 标识 + `formatVersion` 向前兼容）。

## 六、项目分析空间（PVCCE · 代码通俗化引擎）

**PVCCE（Project Visualization & Code Comprehension Engine）是与思维导图平行的
第二大功能空间**：把任意本地代码项目变成一棵「大白话知识树」。
整个空间**没有任何弹窗表单**：导入进度是顶栏微进度条；「大白话 → 代码」是画布工具模式。

### 6.1 布局（三栏沉浸）

- 左侧可折叠文件树：筛选、多选、「固定到画布」、「从分析中移除」；
- 中央无限画布：WASD/方向键平移、指针锚点缩放、流光依赖线；点击空白取消选中；
- 右侧可收起详情舱：文件通俗解读 / 意图结果 / 推理链；
- 底栏轻提示：节点数 / 引用数 / 缩放 / 当前模式。

### 6.2 导入（四种途径）

整个项目文件夹；单个/多个源文件（增量追加，不打断会话）；工作区拖入；
非代码文件（README/配置/设计说明）以「说明书/清单/配置」通俗卡呈现。
Rust 侧 `project_scan.rs` 负责扫描：自动跳过 `node_modules`、`.git`、`target`
等噪音目录，**拒绝符号链接越界**、有界读取，`lib/pathGuard.ts` 在前端再做一层
路径穿越防护（均有测试）。

### 6.3 七级无限下钻

```
根 › 目录 › 文件 › 类/结构块 › 函数 › 逻辑块（if/for/try…可折叠）› 逐行
```

- 文件节点右键「逐行解剖」进入 L2 结构级 → 双击进 L3 段落级 → 再进 L4 逐行级；
- L4 为**双轨制虚拟滚动**：左源码右大白话，无论 619 行还是 6000 行都只渲染可视区约 30 行；
- 函数行可**块级折叠**只看大白话总结；`Esc` 逐级返回；
- 信息卡内嵌**前 10 行真实源码预览** +「逐行解剖（完整源码）」按钮。

### 6.4 深度语义翻译

五维分析（意图/手段/输入/输出/副作用）驱动：

- 文件级：点名明星函数与依赖域；
- 函数级：按参数与调用链组装叙述；
- 行级：按内容模式（赋值/分支/循环/IO…）逐行生成；
- 内置 `dedupeCheck` 品控：任意两条比喻文本词级 Jaccard > 0.9 判退化重写；
- 顶栏可切换 **生活比喻 / 故事叙事 / 工程说明** 三种通俗风格（持久化）。

### 6.5 词典七级体系

L1 通用 / L2 语言 / L3 框架 / L4 领域 / L5 意图变换 / L6 惯用短语 / L7 模式识别，

数据库 / DevOps / 俚语），25+ 旗舰词条带三风格变体；全库经唯一性品控。

## 七、命运推演空间（FTPE · 行为树命运引擎）

**FTPE（Fate Tree Prediction Engine）是第三大独立功能空间**，是一个完全离线的
「人生思想实验沙盒」：无模板哲学——人格/性格/主义思想全部为抽象自构条目，
每个特质是 -100..+100 的无级滑块，并对 19 种语义标签（冒险/社交/事业/感情/健康/
意外/觉醒/冲突/守成/金钱/名望/内心/危险/家庭/学识/机缘/羁绊/传承/欲望）
持有精确影响权重表。

### 7.1 六大独立面板

| 面板 | 内容 |
| --- | --- |
| 人格 | 1–3 个主导人格按权重（0..100）加权混合，带相容/冲突网络 |
| 性格 | 正反极滑块（每个特质标注其对立面 `opposite`） |
| 主义思想 | 高值互斥对触发「内心挣扎」（`ideologyConflicts` 检测两侧 ≥50 的冲突对） |
| 事件库 | 7 层分类（日常琐事 0.8 / 关键转折 0.35 / 命运级 0.15 / 黑天鹅 0.05 / 内心觉醒 0.25 / 人际关系 0.5 / 事业成长 0.45），种子 100+ 条，可自定义扩展 |
| 随机因素 | 运气/时代/健康…每项有基础权重、作用标签、独立强度旋钮 |
| 推演参数 | 年数（步数）/ 每步最大分支 1–4 / 混沌强度 0–100 / 起始年龄 / **确定性种子** / 增益列表 |

另有**模块三：增益（Buff）**系统——启用后对携带特定标签的事件做概率乘法，
多个 buff 叠乘后整体钳制在 0.05..4，避免一格 buff「掀桌」。

### 7.2 推演算法（确定性、可重现）

```
最终概率 = 基础概率 × 特质乘子 × 随机因素扰动 × buff 乘数 × 混沌扰动
```

- **mulberry32 PRNG**：同一种子 → 完全相同的命运树（spec 13.1）；
- **特质乘子走 SIGMOID 映射**（k(0)=0，k(±100)≈±0.93）：中段灵敏、两端平滑饱和，
  「蝴蝶效应」成长自然而非失控；最终乘子同样钳制 0.05..4；
- 每个时间步按权重采样分支生成事件节点；到达终点时按路径基调分配
  **10 种结局原型**；
- `behaviorTree.ts` 负责树的构建、续算与剪枝（`__tests__/behaviorTree.test.ts` 覆盖）。

### 7.3 命运树画布

- 横向时间轴无限延伸，连线亮度 = 概率；节点显示年龄标签（如「27 岁 · 春」）；
- **双击事件节点续分子树**，并反向反馈主干（编号 10.1/10.2 式路径）；
- 结局全览面板列出全部结局印章；版本列表（`versions`）可保存多个推演快照；
- 画布视口（x/y/z）随文件保存，重开精确还原。

### 7.4 存档与导出

`.fatetree` 与 `.mindmap` / `.project` 平级（工作区双击打开），内含：
角色画像、参数、完整树、版本快照、**自定义词典条目随文件携带**、备注。
一键导出为思维导图，把命运树变成可继续编辑的导图。

### 7.5 双语词典

`dictionaries.ts`（中文）与 `dictionaries.en.ts`（英文）完整平行，
跟随 i18n 语言切换；`__tests__` 覆盖引擎概率、增益叠乘与行为树行为。

### 7.6 事件与结局举例（机制示意）

- 一个「冒险 +0.6」的人格在种子固定时，会系统性抬高携带「冒险」标签事件的
  采样权重；同一事件在「守成 +0.6」的角色下几乎不会被采样到；
- 当「理想主义」与「功利主义」的滑块都高于 50 且互为冲突对时，
  引擎登记一对「内心挣扎」，推演期间的对应事件会获得额外的挣扎加成；
- 黑天鹅（L4）基础概率仅 0.05，但混沌强度与随机因素可以把尾部拉长——
  一棵 40 年的树里出现 2–3 次黑天鹅并不罕见；
- 结局原型按路径基调（顺遂/动荡/觉醒/沉沦…）分配，结局印章在「结局全览」
  面板汇总，可一键跳到对应节点。

### 7.7 与导图空间的互通

「导出为思维导图」把命运树逐层映射为导图节点：事件类别映射为语义配色、
概率映射为连线标签、结局映射为终点节点；随后你可以继续在导图上
批注、引用记录、二次加工——推演结果由此进入你的长期知识库。

## 十六、常见问题（FAQ）

**Q: 提示缺少 WebView2？**
安装 Evergreen Runtime：https://developer.microsoft.com/microsoft-edge/webview2/

**Q: 想彻底离线构建？**
先在联网机器执行一次 `npm install` 与 `cargo fetch`（或直接完成一次
`build-windows.bat`），之后 `cargo build --offline` + `npm ci --offline` 可复现。

**Q: 卸载后数据在哪？**
`%APPDATA%\com.variable.app`，重新安装后自动继续使用；便携版在 `data\`。

**Q: 命运推演为什么叫「推演」而不是「预测」？**
它是基于你设定的特质权重与随机种子的**确定性模拟**：同种子可重现，
改一个滑块结果就不同——它是思想实验工具，不是对现实的预言。

**Q: 项目分析的「大白话」是 AI 生成的吗？**
不是。全部由本地七级词典 + 规则引擎生成，零网络、零模型调用；
你可以通过 `.dict.json` 词典包扩展它的表达。

## 附录 A：一次典型使用旅程

1. **清晨写作**：双击图标 → 启动动画 → 星空下的编辑器已经就位。
   Ctrl+N 新建记录，标题写好，正文流淌；粘贴一张截图和一段视频素材进段落；
   写完打上「灵感」「小说」两个标签，Ctrl+S。
2. **整理灵感**：Ctrl+Shift+M 切到导图，N 键撒出几个文本框，
   把刚才的记录绑定到「主角设定」节点上；拉一条流动动画连线标出情节因果；
   F 适应全部后导出 `.mindmap` 到工作区。
3. **读别人的代码**：切到项目分析，导入一个开源仓库；根节点三支四层的
   「是什么/有什么/怎么运行」先把项目讲明白；对核心函数「查看推理链」，
   再「逐行解剖」读到 6000 行文件的 L4 双轨视图；遇到想加的功能，
   灯泡工具在画布上放一个意图节点，「加一个导出 CSV 的按钮」回车，
   预览无误后「写入源文件」（自动备份 + 原子写盘）。
4. **夜晚推演**：✨ 命运推演里搭一个角色：两主一人格混合、
   五六个性格滑块、一对互斥主义；年数 40、分支 3、混沌 35、种子 20260904；
   一棵命运树在横向时间轴上生长；对某个关键转折双击续分子树，
   最后导出为思维导图归档，随手在备注里写下今晚的想法。
