# Variable — Private Space（私人空间）

**完全离线、无账号、无云同步的私人桌面环境 + 写作 + 思维导图 + 项目分析 + 命运推演 Windows 桌面应用。**

Variable 已经不只是一款"应用"——它是一个覆盖在 Windows 桌面之上的**私人桌面环境**：
全屏壁纸层与桌面图标、Win11 风格任务栏与开始菜单、文件管理器与回收站、通知中心与
快捷面板、硬件状态面板、系统托盘、全局快捷键（Win 全家桶）、**虚拟窗口管理器
（VWM）**——四大功能空间与文件管理器全部以「虚拟窗口」的形式在环境内部打开，
支持拖拽、贴靠、最小化、多开；第三方 Windows 软件更可以被**整体嵌入**到环境里的
虚拟窗口中（从系统任务栏与 Alt+Tab 里消失），配合 Wallpaper Engine 全类型壁纸
接入与环境级显隐切换键位，把整个 Windows 改造成一个只属于你的、与真实桌面
「隔离」的第二空间。

同时内嵌四个彼此独立、又可以通过「引用」互相跳转的功能空间：**写作库、无限画布
思维导图、代码通俗化引擎、命运推演沙盒**。

它不注册、不登录、不上传，所有数据（记录、思维导图、项目分析档案、命运推演树、
媒体附件、备份、日志）都只存在于你自己的电脑上；便携模式甚至可以把整个数据目录
放进 U 盘随身携带。它同时是一款「审美驱动」的软件——原生 WebGL 星空与极光背景、
低饱和冷调视觉语言、自定义无边框窗口与启动动画，让一个严肃的生产力工具拥有
宇宙级的氛围感。

> **一句话总结**：Variable = 一个可以把你现有 Windows「关在门外」的私人操作系统
> 皮肤 + 四个彼此互通的生产力空间 + 一个可以把任意第三方软件"关进"自己窗口里的
> 嵌入式窗口管理器。

## 一、产品定位与设计理念

### 1.1 这是什么软件

Variable 是一个运行在 Windows 桌面上的**私人桌面环境 + 单窗口多空间应用**，它由
四个层次叠加而成：

1. **桌面环境层**：全屏壁纸 + 桌面图标网格 + 任务栏 + 开始菜单 + 文件架 +
   通知中心 + 快捷面板 + 系统托盘 + 全局快捷键 + 窗口管理（红绿灯 / Win+Tab /
   分屏贴靠），把 Windows 桌面「接管」成一个属于自己审美与工作流的空间；
   通过双击 Esc 甚至可以在「环境」与「真实 Windows 桌面」之间瞬间切换——
   环境隐藏时看到的是你原本的 Windows 桌面与 Wallpaper Engine 壁纸，
   切回来时一切如初；
2. **虚拟窗口管理器（VWM）**：环境内部的轻量级窗口系统。四大功能空间、
   文件管理器、回收站，以及**被嵌入的第三方软件**，都以虚拟窗口的形式运行，
   拥有独立的 Z 序、聚焦态、拖拽移动、边缘贴靠、最小化飞行动效与多开能力；
3. **四个功能空间**：
   - **写作空间（Library）**：层级文件夹 + 富文本记录 + 标签 + 收藏 + 回收站 +
     全文搜索 + 本地媒体；
   - **思维导图空间（Mindmap）**：无限画布、自由节点、丰富的连线样式、小地图、
     节点绑定记录；
   - **项目分析空间（PVCCE）**：把任意本地代码项目「翻译成大白话」，七级下钻、
     逐行解剖、推理链、意图生成、写回源文件；
   - **命运推演空间（FTPE）**：基于特质权重与确定性种子的行为树命运模拟引擎；
4. **第三方软件子系统**：开始菜单扫描、便携化登记、原生图标提取、进程深度检测、
   Wallpaper Engine 壁纸项目接入，以及把第三方软件窗口**嵌入环境内部**的
   embed 子系统。

### 1.2 设计理念

- **隐私即默认**：零网络请求、零遥测、零账号。数据库、媒体、备份全部落在本机；
  便携模式甚至可以把整个数据目录放进 U 盘随身携带。通讯软件提醒也只读取
  **窗口标题**里的未读计数标记，聊天正文永远不经过 Variable。
- **隔离即安全**：环境与真实 Windows 之间是「软隔离」——第三方应用被启动为
  独立 OS 进程（DETACHED spawn），与 Variable 无 WebView 关系；嵌入只是窗口
  层级的重父级（SetParent），应用崩溃不影响环境，环境关闭也不牵连应用。
  Variable 对系统能力的边界保持诚实：它能做用户态进程管理与窗口集成，
  但绝不假装自己是内核。
- **审美驱动**：原生 WebGL 星空与极光背景、低饱和冷调语义色板、自定义无边框
  窗口、启动仪式动画——桌面环境本身就是作品。四大功能空间的图标各自拥有
  独立的视觉语言（钢笔尖墨迹 / 青色节点星图 / 像素扫描线 / 金色星盘），
  桌面、任务栏、开始菜单三处一致。
- **启动即进入**：窗口打开的第一眼就是启动仪式，落位之后桌面、图标、任务栏
  交错淡入；键盘可达、快捷键齐全，打字时背景自动降级渲染保证输入零延迟。
- **无模板哲学**：尤其在命运推演里，人格、性格、主义思想全部是抽象自构条目，
  没有任何真人模板——它是一个「思想实验沙盒」，不是算命工具。
- **零 AI 依赖**：项目分析的「大白话翻译」完全由本地词典 + 规则引擎生成，
  不调用任何在线大模型，同样的话术在十年后的离线机器上依然可用。
- **可重现与可追溯**：命运推演同种子完全可重现；源文件写入先备份再原子落盘、
  支持 Ctrl+Z 回滚；数据库写操作有事务与恢复文件兜底；窗口关闭事件写取证日志。
- **如实降级**：全局快捷键被系统/他方占用时逐项注册失败并诚实降级为任务栏 /
  开始菜单入口，仅记录日志；硬件能力（Wi-Fi 无线电、蓝牙设备）不可用时面板
  如实显示状态而不是假装成功；不可嵌入的第三方应用（UWP / 管理员权限 /
  无标准窗口）如实回退为独立窗口运行。**不提供假功能**是贯穿始终的纪律。
- **绝不伤害用户进程**：嵌入失败、捕获超时等一切异常路径上，Variable 绝不
  终止第三方进程——应用总是保持运行，用户随时可以手动接管。

### 1.3 目标用户

- 需要一个完全私密写作环境、并想把 Windows 桌面改造成自己审美空间的个人作者；
- 用思维导图整理灵感、并希望节点能直接挂接长文记录的人；
- 想快速读懂一个陌生代码库（自己的旧项目、开源项目）的开发者；
- 喜欢做人生推演、角色设定、思想实验的创作者与玩家；
- 想要一个「工作时与娱乐/通知隔绝」，又能一键回到真实桌面的专注环境使用者。

### 2.1 技术栈

| 层 | 技术 |
| --- | --- |
| 桌面壳 | Tauri 2.x（Rust 后端 + 系统 WebView2，无捆绑 Chromium） |

前端通过 `lib/ipc.ts` 把全部 Tauri command 收敛为带类型的调用面；
`tools/audit.cjs` 静态审计「前端调用的命令都有 Rust 注册、i18n 键完整」，
防止前后端命令面漂移。Rust 侧统一错误类型（`error.rs`）把底层错误翻译成
可展示的中性文案，避免裸 panic 直接击穿 UI。`set_settings` 采用
「事务写入 + 跨窗口事件广播」模型：设置变更以 `settings://changed` 事件
（携带来源窗口与变更键列表）广播给所有 webview，前端按 origin 过滤回声，
保证壁纸、语言等设置在多窗口间实时同步。

### 2.5 全局交互细节（App 层的工程质量）

- **捕获阶段「点击空白即销毁」状态机**：`App.tsx` 在 capture 阶段监听 `pointerdown`，
  任何不属于浮层面板（右键菜单/节点菜单/连线气泡/检查器）与文本框的左键点击，
  都会强制销毁全局激活状态——没有任何浮层能靠 `stopPropagation` 逃避关闭。
- **打字降级渲染**：监听可编辑区域的单字符按键，1.5 秒内标记 `editing`，
  让 WebGL 背景自动降帧/降级，保证输入永远跟手。
- **关闭前保存兜底**：窗口关闭先走保存流程，失败时弹出
  「取消关闭 / 重试保存 / 强制关闭」三选模态，绝不静默丢稿。
- **异常关闭恢复**：崩溃或强杀后，重启时恢复提示宿主会列出恢复文件
  （标题/时间/预览），一键恢复为新记录或删除。
- **宿主齐全性**：桌面分支挂载全部交互宿主（ConfirmHost / ChoiceHost /
  PromptHost / ConfirmBubbleHost / NetConsentHost），所有 `ask*` Promise 都有
  resolve 归宿——历史上曾因漏挂宿主导致「点了没反应」，已根治并有回归意识。

## 三、桌面环境（Desktop Shell）：启动仪式 / 桌面分层 / 窗口管理

### 3.1 启动仪式（BootScreen）

- 启动时**真实加载**：数据库迁移、库统计、媒体索引等真实进度以 `boot://event`
  流式推给前端，全程**没有合成时间线**——进度条走多快取决于机器实际多快；
- 加载完成后进入阶段 4/5 退出编排：字母落位动画 → 任务栏从中央展开 →
  桌面图标交错淡入 → 红绿灯由暗态激活；
- 数据就绪后推送一次「本地数据就绪」通知（数字来自真实 BootStats：工作区
  文件数、记录数、导图数），以及一条「磁盘同步通知」；
- 首次启动（向导未完成）显示**欢迎向导**，引导隐私声明与基础设置，
  点击窗口关闭灯即可跳过并完成向导。

### 3.2 桌面 Shell（DesktopShell）

桌面窗口全屏覆盖 Windows 桌面（默认覆盖系统任务栏，实现环境视觉完全独立；
可在设置→外观切换为「避让任务栏」），纵向分层：

```
壁纸层（静态/轮播/视频/网页壁纸，多显示器，1:1 原样渲染无叠加滤镜）
  └─ VWM 虚拟窗口层（z=15：图标之上、任务栏之下）
      └─ 桌面图标网格（三档大小、多选、框选、拖拽、文件架、抖动编辑模式、
          可整体隐藏）
          └─ 底部 Win11 风格任务栏（小组件区 + 托盘 + 时钟）
              └─ 开始菜单 / 快捷面板 / 通知中心 / 硬件面板
```

壁纸层对桌面壁纸做了「原样渲染」处理：没有应用内文字背景专用的模糊/暗罩/
暗角叠加，壁纸 1:1 清晰锐利；四款软件内部的背景光影不受影响。

### 3.3 窗口红绿灯

Variable 的窗口控制灯统一为三处：桌面壳层、VWM 虚拟窗口、Modal/浮层
（CloseLight 单灯组件），顺序为 **左绿 / 中黄 / 右红**：

- 🟢 **绿灯**：桌面壳层=退出选择框（隐藏到托盘 / 完全退出，未保存先走保存
  冲刷流程）；VWM 窗口=关闭本窗口（170ms 缩小淡出关闭仪式）；
  Modal/浮层=关闭本界面（浮层无最小化/最大化语义，不提供假灯）；
- 🟡 **黄灯**：全屏切换（toggleMaximize），VWM 中为最大化/还原，带平滑滑入动效；
- 🔴 **红灯**：最小化——桌面壳层收起；VWM 窗口播放 200ms「飞向任务栏」动效后
  隐藏（display:none 保活挂载，恢复零重载）。

### 3.4 窗口管理

- **虚拟窗口优先**：四大空间、文件管理器、回收站默认在桌面环境内以 VWM
  虚拟窗口打开（详见第四章）；OS 级独立窗口通道（app-*.html 拆窗入口）完整
  保留为遗留回退——xref 跳转若发生在非桌面窗口、或用户直接运行独立入口，
  仍走旧路径，两条通道互不干扰；
- **Win+Tab 切换器**（可选功能）：后端注册 `super+tab` → `sys://wintab` 事件 →
  唤起自绘切换器，列出全部 Variable 窗口（已并入 VWM 虚拟窗口的 Z 序），
  ↑/↓ 选择、Enter/点击聚焦、Esc 关闭；
- **分屏贴靠**：拖动虚拟窗口到屏幕边缘出现贴靠预览（SnapPreviewHost），
  松手即贴靠左右半屏/四角 1/4；顶部最大化；Win+方向键贴靠、Win+M 最小化；
  双击标题栏切换最大化；Alt+Tab（环境内）轮转窗口；
- **全屏应用避让**：检测到全屏应用运行时，任务栏自动避让，
  不遮挡游戏/视频画面。

### 3.5 覆盖 Windows 行为

- **联网确认弹窗**：任何首次尝试出站请求的动作前弹窗确认（默认无出站）；
- **Win 键全家桶**：Win+E 文件管理器、Win+D 显示桌面、Win+N 通知中心、
  Win+S 开始菜单搜索、Win+Tab 窗口切换（默认表采用 ctrl+alt+* 变体规避
  Win11 系统保留键，详见第二十三章）；
  被系统占用时逐项降级并记日志；
- **托盘常驻**：关闭到托盘后 Variable 继续运行（IM 提醒、快捷键等后台能力
  保持），托盘菜单可随时唤回；
- **桌面图标隐藏模式**：右键「隐藏图标/显示图标」，隐藏时跳过图标与框选
  渲染（`variable:icons:hidden` 持久化），右键菜单仍可用——纯壁纸观影模式。

## 四、VWM 虚拟窗口管理器：环境内的一切窗口

VWM（Virtual Window Manager）是 Variable 桌面环境的「窗口系统」：它把原本
各自弹 OS 窗口的应用全部收进桌面环境内部，以 DOM 层虚拟窗口的方式托管。

### 4.1 核心能力

- **独立 Z 序与聚焦态**：点击置顶、点击外部失焦；Alt+Tab 轮转按 Z 序降序；
- **拖拽移动 / 八向缩放**：标题栏拖拽移动（拖拽半透明 + 抬起阴影），边缘
  八向手柄缩放；
- **边缘贴靠**：拖到屏幕左/右缘=半屏，四角=1/4，顶部=最大化，带实时预览；
  Win+方向键键盘贴靠；贴靠平滑滑入（.snapping 动效）；
- **最小化到任务栏**：200ms「飞向任务栏」动效后隐藏——**display:none 保活
  而非卸载**，恢复零重载（Write 的光标与滚动位置、导图的视口都不丢）；
- **同应用多开**：任务栏图标中键 / forceNew 参数新开实例（例如同时开两个
  Write 看两篇记录、两个 Explorer 看两个目录）；
- **几何持久化**：每个虚拟窗口的位置/尺寸按 `variable:vwm:geom:v2` 存储，
  工作区边界按任务栏四向位置自动推导；重开还原；
- **红绿灯**：左绿（关闭）/中黄（最大化）/右红（最小化），与整体视觉一致。

### 4.2 托管对象

| 虚拟窗口 | 打开方式 | 说明 |
| --- | --- | --- |
| Write / Mind / Code / Fate | 桌面图标、开始菜单、launchIndex | 四空间视图原样挂载，CosmicBackground 置于窗口包含块内，多窗口光影零差异 |
| Explorer 文件管理器 | Win+E / Ctrl+E / 任务栏 / 文件架 | 内嵌模式（无自带标题栏），支持带路径新开实例 |
| Recycle 回收站 | Ctrl+Alt+B / 任务栏 | 单实例 |
| 第三方应用（tp:\<id\>） | 桌面第三方图标 / 开始菜单 | 占位虚拟窗口 + 原生窗口嵌入（见第十章） |

### 4.3 关键实现细节

- **translateZ 包含块技巧**：`.vwm-app` 用 `transform: translateZ(0)` 建立
  包含块，把 `position:fixed` 的 `.bg-root`（WebGL 背景）约束进虚拟窗口——
  这是「每个窗口自带光影、随窗口移动」的关键；同理，内嵌的
  `.ex-window`（Explorer）降级为 `absolute`，避免 fixed 层盖住标题栏；
- **弹簧动画**：打开/恢复用 vwm-in 弹簧动画（scale/translate 使用独立 CSS
  属性而非 transform，避免破坏 translateZ 包含块）；
- **任务栏联动**：任务栏运行态 = VWM 窗口列表；点击 = 开/聚焦/最小化切换；
  中键 = 强制多开；悬停关闭 = 关最上层实例；
- **贴靠与桌面窗口自跳过**：applySnap 对桌面窗口自身跳过，VWM 贴靠与
  遗留 snap 逻辑互不冲突。

## 七、通知中心、快捷面板与硬件面板

### 7.1 通知中心（Win+N 变体 / 点击时钟）

- 监测对象：微信 / QQ / 企业微信 / 钉钉 / 飞书 / Telegram；

  消息正文永远不经过 Variable——只看标题，零网络；

- **勿扰开关**、屏幕亮度等快捷开关。

### 7.4 硬件面板

## 九、壁纸系统与 Wallpaper Engine 全类型接入

### 9.1 Variable 壁纸

- **四类壁纸模式**：静态图片（image）/ 壁纸池轮播 / 视频（video）/
  **网页壁纸（web）**——本地 html 壁纸以 iframe 内嵌渲染（本地 asset 协议、
  允许 autoplay）；另有 **system 让位模式**：把桌面还给系统
  （Wallpaper Engine / Windows 壁纸），Variable 隐藏到托盘，点任务栏
  托盘 V 图标返回；
- **多显示器**：读取系统显示器列表，按显示器设置壁纸；
- **壁纸池目录**（`wallpaperPoolDir`）：放入图片自动轮播；
- 右键「切换壁纸」对 image/video 类型在未选过文件时直接弹文件选择框，
  选完即用；
- 性能档位（`bgTier`）与减少动效（`reduceMotion`）全链路生效。

### 9.2 Wallpaper Engine 扫描与导入（零网络）

- **自动探测安装位置**：注册表 `HKCU\Software\Valve\Steam\SteamPath` 优先，
  补 C 盘默认路径 + `libraryfolders.vdf` 其余 Steam 库——Steam 装在任意盘
  都能找到；
- **扫描范围**：创意工坊 `workshop/content/431960/*` 与
  `common/wallpaper_engine/projects/{myprojects,projects}/*`；
  解析 `project.json`（兼容 utf-8-sig BOM）→ 标题/类型/入口文件/preview.jpg；
- **类型如实标注**：video/image → 可导入（视频壁纸/图片壁纸，一键导入后
  立即生效）；scene/web/application → 标注为不可直接渲染；
- **全类型打开**：
  - video/image → 走 Variable 壁纸链路；
  - web → 网页壁纸 iframe 内嵌；
  - **scene/application** → `wp_engine_open` 命令：前端只传项目目录名 id
    （校验拒绝路径分隔符/`../`/盘符），Rust 在白名单根内解析
    `project.json` 与 `wallpaper64.exe`，生成 `<数据目录>/we-open.cmd`
    包装脚本（`chcp 65001` 兼容中文路径），登记为第三方启动项（幂等）
    后复用既有启动通道独立进程执行
    `wallpaper64.exe -control openWallpaper -file <project.json>`——
    这是 Wallpaper Engine 官方控制接口，壁纸应用在系统桌面；
    配合「system 让位模式」即可完整体验场景壁纸；
- **安全边界**：路径全部服务端白名单解析，前端输入只有项目 id；
  进程启动复用已审查的通道，不在壁纸模块新起炉灶。

## 十、第三方软件启动器与嵌入子系统（embed）

### 10.1 登记与便携性三级

- **登记任意第三方 Windows 软件**（exe/lnk/bat/cmd），登记表仅存本机
  `<数据目录>/apps.json`；
- **便携性三级**：🟢 portable（数据目录内，随 Variable/U 盘整体迁移）/
  🟡 standalone（自包含单文件但绑定本机路径）/ 🔴 shortcut（安装型），
  自动判定 + 用户可覆盖；
- **开始菜单扫描**：递归扫描系统 + 用户开始菜单 `.lnk`（COM IShellLinkW
  解析目标），跳过卸载器/帮助项，目标去重后返回候选，含名称与图标；
- **拖入添加** + **便携化**（把已安装软件整目录复制进数据目录转为 portable，
  复制失败如实报错、登记不变）；
- **原生图标**：登记项无自定义图标时自动提取 Windows 原生图标；
- **深度检测**：进程级检测应用是否正在运行（含运行中标记）；
  软件已卸载时图标置灰并提示，可一键清理残留条目；
- **删除护栏**：仅数据目录内的文件允许彻底删除（防误删系统软件）；
  删除失败（软件运行中/文件被锁）报错并保留登记，绝不半途而废。

### 10.2 启动通道（安全模型）

- **直接启动**：登记 exe 用参数列表方式（`std::process::Command`，无 shell
  拼接）以 DETACHED + 新进程组启动，工作目录设为 exe 所在目录；
- **快捷方式启动**：`.lnk` 经 **ShellExecuteExW**（SEE_MASK_NOASYNC |
  NOCLOSEPROCESS）直接解析启动——不经任何 cmd 字符串拼接，且能取回目标
  进程 pid（供嵌入的进程树捕获使用）；
- **管理员运行**：ShellExecuteW `lpVerb="runas"`，UAC 弹窗由系统展示，
  用户取消（SE_ERR_CANCELLED）如实报错；
- 启动时自动撤销桌面窗口置顶，让第三方窗口浮于桌面之上；回到桌面自动恢复。

### 10.3 嵌入子系统（embed.rs）：第三方软件在环境内打开

第三方应用启动后，其主窗口被 **SetParent** 成 Variable 桌面窗口的子窗口
（WS_CHILD），随虚拟窗口移动/缩放，从系统任务栏与 Alt+Tab 消失——
实现与 Windows 桌面的视觉隔离。

**捕获流程（含启动器型软件的根治方案）**：

1. 启动前记录该应用已有的顶层窗口（避免把旧窗口误嵌）；
2. 通过启动通道取得**根进程 pid**；
3. 以 **Toolhelp32 进程快照展开 pid 树**（根 + 全部后代进程）——启动器型
   软件（如 Wallpaper Engine 的 wallpaper32/64.exe）真正的窗口属于它派生的
   子进程，按 exe 名匹配不到，按进程树就能命中；
4. 轮询 EnumWindows 等待新主窗口，**最长约 30 秒**（200ms 一次，命中即返回，
   慢启动应用不误报）；pid 树为空时按映像名后缀兜底匹配；
5. 命中 → 去标题栏/边框/系统菜单（WS_CAPTION|WS_THICKFRAME|WS_SYSMENU
   剥离 + WS_CHILD），SetParent 到桌面 HWND，先给占位边界，随后由前端
   随虚拟窗口上报精确物理像素边界（embed_bounds）。

**嵌入后的控制**：`embed_bounds`（随虚拟窗口移动缩放）、`embed_visible`
（最小化=SW_HIDE 隐藏，恢复=SW_SHOW）、`embed_close`（投递 WM_CLOSE，
应用自行退出）、`embed_focus`（点击虚拟窗口时移交键盘焦点）。

**失败路径（绝不伤害应用）**：

- 同一时刻只嵌入一个应用；新嵌入前，先前的嵌入先脱离回桌面；
- 捕获超时（30 秒）：应用**保持独立窗口运行，进程绝不终止、登记绝不删除**，
  提示「应用已在系统桌面独立运行，未受影响；稍后重新从环境内打开即可再试」，
  前端关闭占位虚拟窗口；
- 无法嵌入的应用（UWP / 管理员权限 / 无标准窗口）如实回退为独立窗口运行。

**隔离边界（如实说明）**：嵌入是用户态窗口层级操作——第三方应用依然运行在
系统同一会话的独立进程里，与 Variable 无父子进程关系、无沙箱、无内存配额。
Variable 对此保持诚实：它提供的是**视觉与窗口层面的隔离**，不是内核级沙箱
（那需要裸机 OS 项目，超出用户态应用的能力边界）。

## 十一、环境切换：双 Esc 与 Del+Backspace（kbdhook）

Variable 提供两组**全局键盘手势**（`kbdhook.rs`，30ms `GetAsyncKeyState`
轮询线程实现，全局状态与焦点/窗口可见性无关）：

| 手势 | 动作 |
| --- | --- |
| **双击 Esc**（500ms 内两次按下） | 环境 ↔ Windows 切换：环境可见 → 隐藏（露出真实桌面 / Wallpaper Engine 壁纸）；隐藏 → 显示 + 取消最小化 + 置焦 |
| **Delete + Backspace 同按** | 真正退出 Variable：先显示桌面窗口（保证 webview 活跃），再走保存冲刷 + 关闭流程（无确认框，未保存内容已由保存队列兜底） |

**为什么用轮询而不是低级钩子**：WH_KEYBOARD_LL 低级钩子在本环境的宿主进程里
会静默失效，且窗口隐藏后 webview 不再处理事件——「隐藏后再切回」不能依赖
前端监听。所以切换完全在 **Rust 侧**完成：轮询线程读到双 Esc 直接
show()/hide() 窗口，不经过任何事件链路。该方案经实机按键注入验证
（合成 Esc 序列 → 日志 `double-Esc -> toggle environment` → 窗口显隐正确）。

**设计原则**：绝不吞键（钩子/轮询只观察键盘状态，不拦截击键，输入法与
其他应用零影响）；轮询频率 30ms（CPU 占用可忽略）；手势状态机与
焦点/可见性完全解耦。

## 十五、命运推演空间（FTPE · 行为树命运引擎）

### 15.1 六大面板

| 面板 | 内容 |
| --- | --- |
| 人格 | 1–3 个主导人格按权重加权混合，带相容/冲突网络 |
| 性格 | 正反极滑块（每个特质标注其对立面） |
| 主义思想 | 高值互斥对触发「内心挣扎」 |
| 事件库 | 7 层分类，种子 100+ 条，可自定义扩展 |
| 随机因素 | 运气/时代/健康…每项独立权重与强度旋钮 |
| 推演参数 | 年数 / 每步分支 1–4 / 混沌强度 / 起始年龄 / **确定性种子** / 增益 |

增益（Buff）系统：对携带特定标签的事件做概率乘法，多个 buff 叠乘后
整体钳制在 0.05..4，避免一格 buff「掀桌」。

### 15.2 推演算法（确定性、可重现）

```
最终概率 = 基础概率 × 特质乘子 × 随机因素扰动 × buff 乘数 × 混沌扰动
```

- **mulberry32 PRNG**：同一种子 → 完全相同的命运树；
- 特质乘子走 **SIGMOID 映射**（k(0)=0，k(±100)≈±0.93）：中段灵敏、两端饱和；
- 每个时间步按权重采样分支；终点按路径基调分配 **10 种结局原型**；
- 命运树横向时间轴无限延伸，双击事件节点续分子树；可导出为思维导图。

## 二十五、常见问题（FAQ）

**Q: 怎么打开 Variable？**
安装版双击 `Variable_1.0.0_x64-setup.exe` 安装后从开始菜单打开；或直接运行
`src-tauri/target/release/Variable.exe`；开发模式 `npm run tauri dev`。
详见第十九章。

**Q: 提示缺少 WebView2？**
安装 Evergreen Runtime：https://developer.microsoft.com/microsoft-edge/webview2/

**Q: 双击 Esc 没反应？**
双 Esc 由 Rust 侧 30ms 轮询识别，与焦点无关；若与某些全屏游戏的 Esc 语义
冲突，可稍放慢两次按键间隔（500ms 窗口）。确认 kbdhook 线程已启动可查
日志中的 env 切换记录。

**Q: 第三方软件嵌不进去（提示回退独立窗口）？**
三类原因：UWP/商店应用、管理员权限应用、无标准主窗口的应用。嵌入子系统
会等待最长约 30 秒；超时后应用保持独立窗口运行（不会被害），可稍后重试。
启动器型软件（如 Wallpaper Engine）已通过进程树捕获支持。

**Q: 嵌入的应用崩溃了会拖垮 Variable 吗？**
不会。嵌入只是窗口层级重父级，应用运行在完全独立的 OS 进程里；崩溃只影响
它自己的窗口（虚拟窗口内容失效，手动关闭该虚拟窗口即可），环境与其他窗口
不受影响。

**Q: 通讯软件提醒会不会看我的聊天记录？**
不会，也做不到。Variable 只轮询微信/QQ 等应用的**窗口标题**（标题里带
「(3)」这类未读计数），聊天正文在对方进程内存里，Variable 不读取、
也无法读取，且全程零网络。

**Q: Win+E / Win+D 被占用了怎么办？**
默认表已改用 ctrl+alt+\* 变体规避 Win11 保留键；若仍有冲突，被占用的
快捷键逐项注册失败并诚实降级——功能仍可从任务栏 / 开始菜单 / 快捷面板
进入，日志里会记录哪一项不可用。

**Q: Wallpaper Engine 的 scene 壁纸为什么"打不开"？**
scene 类型是 WE 引擎实时渲染的，Variable 无法在 WebView 里复现；点击后
走 `wp_engine_open` 在**系统桌面**上应用（官方控制接口），配合
壁纸模式「系统桌面」（system 让位）或双击 Esc 临时隐藏环境即可观看。

**Q: 想彻底离线构建？**
先在联网机器执行一次 `npm install` 与 `cargo fetch`（或完成一次
`build-windows.bat`），之后 `cargo build --offline` + `npm ci --offline` 可复现。

**Q: 卸载后数据在哪？**
`%APPDATA%\com.variable.app`，重新安装后自动继续使用；便携版在 `data\`。

**Q: 命运推演为什么叫「推演」而不是「预测」？**
它是基于你设定的特质权重与随机种子的**确定性模拟**：同种子可重现，
改一个滑块结果就不同——思想实验工具，不是对现实的预言。

**Q: 项目分析的「大白话」是 AI 生成的吗？**
不是。全部由本地七级词典 + 规则引擎生成，零网络、零模型调用。
