# 2026-10-03 工作日志

## VTaskBoard 壁纸 UI 画质/尺寸适应专项修复

**背景**：Variable 要求 wallpaper UI 打开的所有壁纸尺寸自适应、清晰度达标、画质与原生一致，且不破坏现有功能与定制贴图。

**环境实测基准**（后续任何画质判断都以此为准）：
- 主显示器：1920×1080 物理像素 @144Hz，**DPI 120 = 125% 缩放**，逻辑工作区 1536×864
- 进程 DPI 感知：`SetProcessDpiAwareness(2)` = PER_MONITOR_AWARE，`GetSystemMetrics` 返回**物理像素**
- 渲染宿主：Edge/Chrome `--app` 模式，`--start-fullscreen`（Chromium 栅格化）
- 壁纸层 DOM：`#gwall`（主壁纸层，JS 填充）、`#hudwall`（HTML 里为空，预留样式）

**定位到的真实缺陷**（按影响排序）：

1. **几何错误（最严重）** `_wehd_item` 把 600×600 / 1024×1024 方形官方预览图直接 `resize((sw, sw))` 拉成正方形，再交给浏览器 `object-fit:cover` 裁到 16:9。实测**浪费 44% 纵向像素**，有效放大倍率是修复后的 1.78 倍（600 方图：3.2x vs 1.8x）。
2. **CSS filter 常驻劣化** `#gwall img/video` 与 `#hudwall` 恒挂 `filter:brightness() saturate() blur()`，即使三参数为恒等值。CSS filter 会强制元素脱离普通栅格化路径走独立合成层重采样，破坏本该 1:1 的映射。
3. **`transform:scale(1.02)`** 强制放大 2%，实测左右各裁 18.8px、上下各 10.6px，且本身即二次插值。
4. **`/wallpapers/` 缺 Range** 整文件 `f.read()` 进内存（本地视频 5~7MB、WE 视频最大 841MB），且无缓存头。
5. **`/ui/` 字体 MIME 缺失** `.ttf/.woff2` 落到 `application/octet-stream`，浏览器会拒载 `@font-face` → 定制皮肤字体静默回退系统字体（像素风失效）。

**关键实测结论（推翻了一个预设）**：JPEG q90 4:2:0 → q95 4:4:4 的画质增益**几乎为零**（RMSE 完全一致 2.83/1.98/1.96），体积反增 3%~20%。真正瓶颈是**几何**不是编码。故最终采用 q95+4:4:4（成本低、色度安全）但不夸大其词。

**修复方案**：
- 后端 `_display_px()` 取物理像素；`_cover_to()` 等比 cover 预裁切（与 CSS cover 语义一致，居中）；输出与显示区**同比例**使浏览器端退化为 1:1 映射；仅在确有放大时锐化（缩小/1:1 时锐化只制造振铃白边）；缓存键带尺寸后缀 `<pid>_<w>x<h>.jpg`（换分辨率不命中旧图）
- 前端 `wallStyle()` 统一规格 + `_wallFxOn()`/`applyWallFx()`：三参数恒等时**不挂 filter**，调节光影时才加 `.fx` 类
- `/wallpapers/` 补 Range（206/416）+ ETag + Cache-Control；`/wehd/` 补 ETag/304
- `/ui/` 补字体 MIME

**验证方法（真实浏览器，非静态检查）**：
- Playwright + 已装 `chromium-1243`（**注意：playwright 版本与 ms-playwright 缓存不匹配，必须显式传 `executablePath`，否则报 1247 缺失**）
- `deviceScaleFactor: 1.25` 精确复刻本机缩放
- 结果：6 种视口比例（1536×864 / 1280×800 / 1920×1080 / 900×1400 / 2560×1080 / 1024×1366）全部满幅 PASS；23 张壁纸逐个截图全部加载；无任何 HTTP ≥400
- 定制贴图回归：MC 像素贴图 5 处 `image-rendering:pixelated` 完好、`applySkin` 3 处调用完好、`/ui/` 路由 1 处完好、3 个 `@font-face` 完好

**未处理项及原因**：
- **GIF 壁纸（160×224，需 6.8~12x 放大）保持原样**。服务端无法凭空补出细节，任何重编码只会引入额外劣化，现状已是最优。仅显性记录为素材局限。
- 旧缓存 `_wehd/<pid>.jpg`（5 个，2.3MB）保留未删——属可重建的派生缓存，非用户数据，删除非必要。
- `scene.pkg` 是 `PKGV0002S` 私有归档格式（非 zip），提取原生素材未做——逆向风险高、收益不确定，超出本次范围。

**教训**：测试脚本等待不足会产出假 FAIL（首轮 6 个 FAIL 全部是误报，实际 8/8 PASS）。图像加载判定必须等 `complete && naturalWidth>0` / video `readyState>=2`，不能只 sleep 固定时长。
