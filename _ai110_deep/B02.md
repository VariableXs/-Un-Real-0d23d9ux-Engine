### 批 A110-B02 · 中断与 SMP 地基（A110-021–A110-040）


#### A110-021 x2APIC ICR=MSR 0x830 发包路径单测锚（真机复现链回归）
【功能定位】把 x2APIC 中断命令寄存器（ICR，MSR 0x830）发包路径固化为单测锚，任何中断子系统改动都必跑此锚。
【定制详述】内核戒律明确 x2APIC 下 ICR 必须走 MSR 0x830 单写（目标 ID 与向量合并在一个 64 位写里），这与 legacy xAPIC 的 MMIO 双写完全不同，写错顺序会在真机上表现为中断莫名丢失。单测锚验证三点：发包值为目标 ID 高 32 位+向量低 32 位的正确拼装；写序唯一（一次 64 位写）；Delivery Status 等旧字段在 x2APIC 模式下不被误读。真机复现链（-smp 2 + varix.x2apic）的复现步骤随锚登记为补测项。
【完成与验收】已完成：发包拼装 ×20 断言全过，xAPIC 兼容路径 ×10 回归，复现链留痕。判据号 A110-021-J1。


#### A110-022 SMP AP 启动 EFER=LME|NXE=0x900 序言守卫（缺位即 #PF→#DF 拦截）
【功能定位】守护 SMP 应用处理器启动序言：AP 必须在进入长模式前置 EFER=LME|NXE=0x900，缺位路径在构建期与运行期双重拦截。
【定制详述】血泪戒律：AP 启动跳板若漏设 NXE，AP 一开分页访问数据页立即 #PF，而 AP 尚无 IDT，#PF 双重故障升级 #DF，整机三重故障复位，症状是「加了第二个核就重启」且毫无输出。守卫在启动镜像构建期静态检查跳板汇编序列含 0x900 写入；运行期在 AP 首指令前由 BSP 校验启动页表 NX 位映射齐备。缺位时拒启 AP 并在 BSP 日志三要素报错，宁缺核不死机。
【完成与验收】已完成：序言缺位注入 ×10 拦截；-smp 14 贴实机参数 AP 全启 ×14 核验证。判据号 A110-022-J1。


#### A110-023 IOAPIC legacy 路由全 mask 闸位账（IRQ1 级捕获未开不贸然打开）
【功能定位】登记并看护 IOAPIC legacy 路由的闸位状态：当前全 mask 是既定事实，IRQ1 级捕获未开，任何开闸动作必须走显式审批路径。
【定制详述】F12 逃生门当前依赖 ps2::note_key 在驱动层捕获，未走 IOAPIC IRQ1 直捕——这是有意保守：开 legacy 路由会改变键事件路径，可能让逃生门失效。闸位账记录 24 条 legacy 路由的 mask 实况，任何人想开闸必须在代码评审留下理由与回归计划，账面才放行；直接改寄存器的路径在审计扫描中判红。账面同时登记「开闸后必须回归 F12 全链」的前置条件。
【完成与验收】已完成：mask 实况读取 ×10 与硬件一致；越权开闸注入 ×10 判红。判据号 A110-023-J1。


#### A110-024 ps2::note_key 唯一过闸闸门契约（键事件单一通道）
【功能定位】冻结键事件架构契约：所有按键一律经 ps2::note_key 单点过闸，闸门可布防/关闸/复开，任何绕过通道判红。
【定制详述】F12 逃生门之所以可靠，正因为全内核只有一条键事件通道。契约冻结三点：note_key 是唯一入口，驱动层其他读键路径（直接读 0x60 等）在审计扫描中判红；闸门三态（布防/关闸/复开）有明确时序——bootselect 后布防，菜单期关闸防误触，系统起来后复开；闸门状态变化全埋点。契约同时声明：USB 键盘事件在 xHCI 驱动成型后也必须汇入 note_key，不许另开旁路。
【完成与验收】已完成：旁路注入 ×10 拦截；三态时序 ×10 断言全过。判据号 A110-024-J1。


#### A110-025 内核心跳 47631 端口监听契约（S3 五态状态机联动）
【功能定位】冻结 S3 引擎心跳契约：心跳端口 47631，与 S3 五态状态机（离线/握手/在线/降级/离场）联动，心跳丢失驱动状态迁移。
【定制详述】S3 引擎与内核的存活互证靠 47631 心跳：内核侧每秒发带序号+时间戳的心跳帧，S3 侧连续 3 帧丢失即把会话迁到降级态，恢复后从序号缺口精确续传。契约冻结帧格式与超时阈值，双方任何一方改协议必须 bump 版本号。心跳本身极轻（<100 字节/秒），并为断电安全路径服务——心跳序号与 S3 的 ramcache 零落盘策略对账，保证降级切换不丢已确认数据。
【完成与验收】已完成：心跳 ×1000 帧零丢失；人为断链 ×10 三帧内降级；恢复续传 ×10 零重复。判据号 A110-025-J1。


#### A110-026 中断上下文安全内存分配门（>64KB struct 禁栈禁 Box 断言）
【功能定位】在中断上下文禁用堆分配与超大栈对象：>64KB struct 禁栈禁 Box，必须 static .bss。
【定制详述】戒律来源真实事故：中断处理里放了个大结构在栈上，真机栈溢出表现为随机的 #PF，QEMU 从不复现。分配门两层拦截：构建期用符号体积扫描抓 >64KB 的大对象在栈/堆分配点；运行期中断上下文入口设分配哨兵，此上下文内调用堆分配立即打追踪并拒绝（返回失败而非崩机）。合法出路是 .bss 静态缓冲，账面提供各中断处理器的缓冲登记表防重叠。
【完成与验收】已完成：违例注入 ×10 双层全拦；全内核扫描零现存违例。判据号 A110-026-J1。


#### A110-027 AP 栈与启动参数页传递契约（16 位实模式→长模式跳板完整性）
【功能定位】冻结 AP 启动参数传递契约：启动向量页、参数页、栈三者的物理地址登记与 16 位实模式跳板到长模式的全链完整性。
【定制详述】AP 启动是全内核地址模式最混乱的一段：SIPI 起点在实模式 1MB 内，跳板要手工搭好 GDT/临时页表再开长模式，参数页指针只能塞在约定寄存器/固定地址。契约冻结：参数页 4KB 对齐、含魔数+版本+栈顶+每核编号；跳板每步（实模式→未开分页的保护模式→开分页长模式）有校验点写端口留痕；栈按核编号切分零重叠。任一校验点未到即定位到第几步。
【完成与验收】已完成：跳板 ×14 核全过；参数页损坏注入 ×10 拒启并报错。判据号 A110-027-J1。


#### A110-028 中断风暴熔断器（同源中断超频阈值自动 mask+上报）
【功能定位】同源中断速率超阈值时自动 mask 该源并上报，防止设备失控把 CPU 打满。
【定制详述】坏设备或驱动 bug 会造成中断风暴——线路上 IRQ 每秒数十万次，系统假死。熔断器按源统计速率，超阈值先降采样确认（防误伤突发合法流量），确认后 mask 该 IOAPIC 项并记三要素事件（哪个源、多少速率、已 mask），随后半开探测：周期性放行一个窗口，若风暴停止则恢复，仍在风暴则维持 mask 并继续告警。F12 逃生门所在 IRQ1 列入熔断豁免清单，逃生门永不熔断。
【完成与验收】已完成：风暴注入 ×10 熔断且恢复正确；豁免清单断言通过。判据号 A110-028-J1。


#### A110-029 时钟源标定器（TSC/HPET/PIT 三源一致性与漂移账）
【功能定位】启动期标定 TSC/HPET/PIT 三个时钟源，选主源并建漂移账，为调度与超时提供可信时间。
【定制详述】真机 TSC 可能不变频同步（constant_tsc 缺失）、HPET 可能周期不准，单一时钟源信错了所有超时都会失真。标定器启动期用 PIT 做基准互测三源，一致性通过则主源取 TSC（最快读法）、HPET 兜底；不一致则降级 HPET 主源并登记漂移账供排查。运行期后台低频对账，漂移超阈值告警并自动切源，切换零抖动（单调性保证：新源读数折算到旧时间线）。
【完成与验收】已完成：三源标定 ×10 快照一致；坏源注入 ×10 自动切换且时间单调。判据号 A110-029-J1。


#### A110-030 异常向量表（IDT）全 256 项覆盖自检
【功能定位】IDT 全 256 项必须全部登记处理入口，禁止留空项，空项即自检红。
【定制详述】留空的 IDT 项在异常触发时走默认三重故障，整机无输出复位，排查无从下手。自检断言 256 项每项有合法入口：0–31 CPU 异常各有专属处理器（#PF 带错误码解析、#DF 打全核栈回溯、#GP 打指令字节）；32–255 注册默认打印器（打印向量号+栈快照后按策略恢复或停机），保证任何未知中断至少留下可读痕迹。自检在 AP 全部起来后跑一遍每核 IDT（x2APIC 下每核独立 IDT），防漏配。
【完成与验收】已完成：256 项 ×14 核全过；空项注入 ×10 检出定位。判据号 A110-030-J1。


#### A110-031 上下文切换保存集契约（FXSAVE/XSAVE 特性协商降级）
【功能定位】冻结任务上下文保存集契约：按 CPU 特性协商 FXSAVE/XSAVE/XSAVEOPT，全核一致，切换零丢寄存器。
【定制详述】混合代 CPU（老宿主机）上 BSP 支持 XSAVE 而 AP 不支持的假想场景必须防：协商以全核最老能力为准，一次协商全系统生效。契约定义保存集分层——通用寄存器必存、FPU/SSE 必存、AVX 等扩展按协商位图存，切换时按位图执行，未协商的扩展寄存器若被改动视为内核 bug 判红。同时契约要求 XSAVEOPT 优化区（init/opt 标志）正确使用，避免无谓保存拖慢切换。
【完成与验收】已完成：协商 ×10 降级路径全过；切换 ×1000 寄存器零丢失。判据号 A110-031-J1。


#### A110-032 核间 IPI 顺序门（发送/应答/超时三段协议）
【功能定位】核间中断实行三段协议：发送带序号、目标显式应答、超时重发有上限，杜绝 IPI 悬挂死等。
【定制详述】TLB shootdown、停机命令等 IPI 若目标核在中断层关中断过久，发送方可能永等。顺序门规定：发送方记序号入在途表，目标核处理完写应答序号；超时先重发（至多 3 次），仍无应答则把目标核标记为失联（触发健康检查而非死等），在途表泄漏告警。协议同时防序号回绕混淆新旧帧。失联核的恢复路径由健康检查接管，IPI 层不猜。
【完成与验收】已完成：IPI ×1000 零悬挂；失联注入 ×10 正确标记且恢复后清账。判据号 A110-032-J1。
【落地与回归口径】IPI 顺序门的压测口径补充：在 -smp 14 贴实机参数下构造「半数核同时失联」的极端场景，验证在途表不因失联核无限膨胀（失联核的在途条目转挂起区并计入健康告警，恢复后批量清账）；TLB shootdown 批量场景（一次修改跨多核失效）验证聚合发送优化不破坏应答语义。压测纳入 B02-037 用例集的 full 档位，宿主桩跑逻辑、QEMU 跑时序，双层口径分离留痕。
