#### A110-162 BootNext 临时引导项零残留账（用后即清 NVRAM 契约）
【功能定位】BootNext 是内核唯一允许触碰的 NVRAM 写入（临时一次性引导项），本账契约其用后即清、零残留、不碰 BootOrder。
【定制详述】引导设施红线允许的唯一例外通道就是 BootNext：它是「本次启动后自动失效」的临时项，固件自己消费后清除，不动 BootOrder 顺序。契约三点：内核只写 BootNext 不写任何其他变量；写前读回固件能力（变量大小上限、支持性）；下次启动时若发现 BootNext 残留（固件没消费——如用户拔盘中断），内核读出其值并与本机预期比对，非预期值告警（可能是别的系统写的）。F12 四级阶梯（B01-012）的零 NVRAM 写与此呼应：那是重启路径，本条是引导选择路径。

#### A110-164 SHARED 卷 boot-select.json 双写仲裁（内核 bootcfg 与 dualboot.rs 互斥写）
【功能定位】boot-select.json 的双写方（内核 bootcfg 与 Windows 侧 dualboot.rs）实行互斥写仲裁：文件锁+版本号防交错。
【定制详述】两个世界都会改这份配置：内核写 last_boot，dualboot.rs 写默认项/超时。仲裁机制：写前取文件锁（锁文件同卷原子创建），锁内读-改-写并 bump 版本号；持锁方发现版本号比自己读时新则重读重算（乐观锁语义）。内核侧锁实现为原子提交点写锁文件，Windows 侧走同卷文件锁语义，两端约定超时（3 秒）后放弃并重试上限（3 次），失败走安全默认+日志。死锁场景（一方崩在锁内）由锁文件带时间戳超时自动过期解决。
【完成与验收】已完成：并发 ×10 零竞态；崩溃持锁 ×10 过期恢复。判据号 A110-164-J1。
