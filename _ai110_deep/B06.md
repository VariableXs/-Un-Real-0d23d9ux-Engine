### 批 A110-B06 · AHCI 与 SATA 通道（A110-101–A110-120）


#### A110-101 AHCI 单端口单槽生命周期状态机（空闲/issued/完成三态收口）
【功能定位】AHCI 驱动按「单端口单槽」建模：每端口同时只有一个在飞命令，槽生命周期 空闲→issued→完成 三态严格收口。
【定制详述】S4.6 交付的 AHCI 是精简实现：放弃多命令槽换取状态可推演。三态状态机的价值在悬挂可检测：命令发出后置 issued 并起超时（103 的时序账），超时未完成即定位「槽悬挂」，走复位回收路径（端口 reset，不清 FIS 区避免状态混乱），回收后槽归空闲并记三要素。单槽对吞吐有损，但 AHCI 在本系统是兜底通道（NVMe 为主），正确性优先是明确取舍，账面声明该取舍防后人「优化」破坏。
【完成与验收】已完成：三态 ×1000 迁移全过；悬挂槽 ×10 回收成功且回收后读写正常。判据号 A110-101-J1。


#### A110-102 LBA48 寻址全链校验（48 位扇区号语义与溢出拒）
【功能定位】LBA48 寻址全链校验：扇区号 48 位拆装正确、上界检查、溢出拒绝在 API 层完成。
【定制详述】LBA48 把扇区号拆进六个寄存器字节，拆装错位是老 bug 高发区。校验链：API 入口做 u64 上界检查（超 2^48 拒）、读回校验（命令发出前把拆装值拼回与原始值比对）、容量边界检查（超盘尾拒）。大容量盘（>2TiB，LBA28 覆盖不到）是主要用例。错误全部在发起前拦截，杜绝「发出去了才发现算错」。
【完成与验收】已完成：边界 LBA ×20 全过；溢出 ×10 拒；拆装回读校验断言通过。判据号 A110-102-J1。
【落地与回归口径】LBA48 校验链的桩测补充：构造 48 位边界附近的盘容量桩（恰在 2^48 扇区上下各一格），验证上界检查的严格性；拆装回读校验的实现位置在命令封装出口（发出前最后一步），与 081 队帧清零同点执行（一次遍历两断言，零额外开销）。大容量盘（模拟 4TiB+）的全域随机寻址 fuzz ×10000 无越界。用例入 112 扩容包，用例名含判据号。


#### A110-103 纯轮询驱动时序账（超时上限与让出点插桩）
【功能定位】AHCI 纯轮询驱动的时序纪律：每次轮询带超时上限，长轮询循环内插让出点（f12_checkpoint）。
【定制详述】纯轮询（不用中断）简单可靠但占 CPU，若设备不响应会自旋到天荒地老——F12 都按不动。时序账三纪律：单次轮询超时上限（按 090 基线的 10 倍封顶）、轮询循环每 N 次插 f12_checkpoint（逃生门不断粮）、轮询间隙可调度（其他核不被饿死由调度器保，本核内让出点保证响应）。超时发生后按 101 的悬挂回收走。
【完成与验收】已完成：让出点 ×10 插桩生效；F12 在 AHCI 卡死注入下仍可达。判据号 A110-103-J1。
【落地与回归口径】让出点的度量与调参：让出点间隔 N 的取值经实测标定（过密徒增开销、过疏逃生门迟钝），标定数据入 111 预算账；让出点在 f12_checkpoint 不可用（极早期引导）时退化为纯计数让出（CPU 停顿指令），保证任何阶段都有呼吸口。轮询超时的动态上限（090 基线×10）随基线自动更新——基线账成为驱动参数的活水源，一处更新多处受益。

【定制详述】写回环是验证驱动正确性的金标准，也是最容易伤到真数据的地方。回归账固化执行前置链：061 总闸开→062/063 身份三验→065 dry-run 先行→写回环（原值备份→写图案→读回比对→还原原值→双端 hash 对账）。任何前置不过即拒绝执行。QEMU 战役里此账随 ×5 交替范式跑；真机默认不开。
【完成与验收】已完成：缺开关 ×10 拒；回环 ×10 数据一致含还原校验。判据号 A110-104-J1。
【落地与回归口径】写回环的数据保真升级：图案从固定模式升级为「原值哈希+伪随机图案（种子固定）」双段验证，能抓住「写了个寂寞」（写入被静默丢弃但读回恰好命中缓存）类阴性问题；还原校验后追加一次延迟重读（30 秒后），抓写缓存假提交。回环全程数据入审计账（068）。QEMU ×5 交替范式的回环集成已在战役脚手架，真机默认不开的契约经 109 联动回归确认。


#### A110-105 SATA 端口复用与识别账（PATA 兼容模式拒绝路径）
【功能定位】SATA 控制器识别账：AHCI 模式接管，PATA 兼容/IDE 模式的控制器显式拒绝并给出 BIOS 设置指引。
【定制详述】部分老 BIOS 默认 SATA 跑 IDE 兼容模式，此时寄存器布局完全不同，强行按 AHCI 驱动读写等于对错误端口做 DMA。识别账在初始化时读 PCI 类别码与 ABAR 有效性：标准 AHCI 类别才接管；IDE 模式拒绝并三要素报错（检测到什么模式/为什么不能驱动/去 BIOS 改 AHCI 的指引）。拒绝路径保证系统其他部分继续可用（此盘不出现，系统不死）。
【完成与验收】已完成：IDE 模式注入 ×10 拒+指引；AHCI 正常接管 ×10。判据号 A110-105-J1。


#### A110-106 AHCI 错误寄存器解码器（TFES/STS 人话三要素呈现）
【功能定位】AHCI 错误状态（TFES、端口 STS、任务文件错误寄存器）解码为人话三要素，禁止裸错误码上屏。
【定制详述】0x34 这类裸码对排查毫无意义。解码器把常见错误组合翻译：TFES（任务文件错误）+任务文件 ERR 位+error 寄存器值 → 「盘报告介质错误（扇区 X 读失败），建议检查坏块账/考虑换盘」；PHY 离线 → 「SATA 链路断开，检查线缆/电源」。解码表覆盖寄存器组合 ×20，未覆盖组合输出原始值+通用排查指引（诚实不装懂）。解码结果同时进日志与用户可见通道。
【完成与验收】已完成：解码 ×20 三要素齐备；未知组合 ×10 诚实降级。判据号 A110-106-J1。


#### A110-107 AHCI/NVMe 统一块接口对账（同请求双后端结果一致）
【功能定位】块层统一接口下，AHCI 与 NVMe 双后端对同一逻辑请求产出一致结果，对账机制可验证。
【定制详述】统一接口是「后端可替换」的承诺。对账机制：诊断模式下同一读请求分别派发双后端（若同一物理盘同时可达，QEMU 双盘战役可镜像配置），结果逐字节 diff；写语义对账用干跑清单比对（两后端的提交点行为映射到同一事务序）。对账发现的分歧按最高缺陷（数据正确性）处理，🔴即时修。此机制也是后端重构时的安全网。
【完成与验收】已完成：对账 ×1000 一致率 100%；构造分歧 ×10 检出。判据号 A110-107-J1。
【落地与回归口径】双后端对账的工程化：对账模式的流量配比可调（诊断期 100% 镜像、日常 1% 抽样对账），抽样对账作为常态机制持续给「后端漂移」画像——漂移是渐进的，等全量对账发现就晚了；对账 diff 的自动归因（哪个扇区区间开始分叉）把排障范围直接缩到具体 IO。对账统计入周报。此机制同时是未来新后端（如 NVMe 多队列重构）的安全网预案。


#### A110-108 DMA 边界与 PRDT 项数契约（超限拆分）
【功能定位】PRDT（物理区域描述表）项数上限与 4MB 单描述符边界强制，超限请求在上层拆分，驱动层拒收超限。
【定制详述】AHCI 每命令 PRDT 项数有限（常见 8/16 项），单描述符覆盖最大 4MB；越限直接写寄存器会被控制器忽略或行为未定义。契约在驱动 API 层强制：请求字节数与页分布先算项数，超限返回明确错误码（附「需要拆分」指引），由块层合并器（083）的拆分逻辑负责拆——驱动层拒绝是最后防线不是常规路径。对齐要求（内存 2 字节起、若干场景页对齐）同样在契约内校验。
【完成与验收】已完成：超限 ×10 拆分正确；越限直发 ×10 驱动层拒。判据号 A110-108-J1。
