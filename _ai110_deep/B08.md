### 批 A110-B08 · exFAT 与断电安全文件系统（A110-141–A110-160）



#### A110-141 exFAT 扇区粒度 RMW 契约回归（真卷 128KiB 簇不可物化断言）
【功能定位】exFAT 读写层按「扇区粒度 RMW」建模的契约回归：不允许为小写整簇物化，128KiB 大簇卷上写 512B 只动 1 扇区。
【定制详述】S4.2 的关键设计决策：真卷簇可达 128KiB，若「改一个字节重写整簇」，一次 last_boot 更新就要搬 128KiB 且中间断电风险面扩大 256 倍。契约冻结：所有小写走「读目标扇区→内存改→写回单扇区」的 RMW，簇缓冲只在顺序大 IO 时启用；断言点在块层请求记录（写请求字节数分布），整簇物化注入判红。此契约同时是 142/143 的地基。
【完成与验收】已完成：RMW ×1000 数据一致；单扇区写断言（STREAM 场景 512B）；簇物化尝试 ×10 拦截。判据号 A110-141-J1。



#### A110-142 STREAM Size 单扇区 RMW 提交点账
【功能定位】STREAM 系统卷 Size 字段（文件实际大小）更新的提交点账：单扇区 RMW 且提交点显性，断电后 Size 与数据一致。
【定制详述】exFAT 目录项里的 Size 字段是「文件多大」的唯一真相。改 Size 若与数据写分属不同扇区，断电可能出现「Size 变了数据没写全」。提交点账规定：数据先行、Size 后写、Size 写入即提交点（此前的数据允许丢失重算，此后的数据必在）；对 last_boot 这类定长文件 Size 不变，规避此问题 entirely。账面用断电矩阵验证：Size 提交前后各断一次，恢复后文件要么完整旧态要么完整新态。
【完成与验收】已完成：断电矩阵 ×10 全部一致态恢复；提交点断言在位。判据号 A110-142-J1。



#### A110-143 grow_rewrite 增长改写路径回归（windows7→variable8 增长）
【功能定位】文件增长改写（grow_rewrite）路径回归：内容增长时的簇扩展+索引链更新+Size 提交三步序，断电每一步可恢复。
【定制详述】S4.2 交付的 grow_rewrite 场景：bootselect 记录文件从 windows7 形态增长到 variable8 形态。三步序：新簇分配并写数据（此时 Size 未变，新数据「超出旧 Size」不可见——崩溃即旧文件原样）；目录项簇指针链更新（FAT 链先接好）；Size 提交（新内容可见）。每步之间断电注入 ×10，恢复态全部合法（旧完整态或新完整态）。簇分配走 064 白名单内路径。
【完成与验收】已完成：增长 ×10 路径全过；三步间断电 ×10 零中间态泄漏。判据号 A110-143-J1。



#### A110-144 create_file_root 提交点序契约（目录项/簇链/Size 三段序）
【功能定位】根目录新建文件的提交点序契约：目录项→簇链→Size 三段写入序冻结，任意段间断电零半成品文件。
【定制详述】新建文件最坏的断电是「目录项在、内容悬空」——用户看到一个打不开的鬼文件。契约序：先写数据簇（不可见），再写目录项但带「未提交标志位」（exFAT 保留字段实现），最后清标志+写 Size 一次提交。恢复例程扫描到带标志目录项即回收其簇（孤儿簇回收）。三段序与 143 的三步序共用同一恢复例程，实现单点维护。
【完成与验收】已完成：三段间 ×10 断电注入零半成品；孤儿簇回收 ×10 成功。判据号 A110-144-J1。
【落地与回归口径】提交点序的恢复例程联测：三段序（本条）与增长三步序（143）共用恢复例程的断言升级为「恢复例程单点性」kcheck 不变量（272 族）——扫源码确认目录项回收逻辑只有一个实现，防未来有人复制粘贴出第二套回收（两套回收并发是灾难配方）。孤儿簇回收的压测（10 万孤儿批量回收）验证恢复性能有界（大事故恢复不遥遥无期）。
