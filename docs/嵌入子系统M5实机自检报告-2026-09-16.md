## 本轮发现并修复的缺陷（3 个，全部实机复测）

### 缺陷 1（M2 遗留，实机 v2 验证暴露）：广播/下行坐标系错位 → 7px 漂移

- **现象**：还原后窗口 GDI rect 与收编摆位差 7px（Win11 不可见边框宽），每次「拖动/还原→回写→重同步」循环持续漂移。
- **根因**：`native-geo`/`native-max` 广播用 DWM 扩展框（可见框），而 `embed_bounds` 下行走 SetWindowPos（GDI 语义）——两个语义混用必然互相搬 7px。
- **修复**：`dwf_desktop_phys` 重命名为 `window_rect_desktop_phys`，统一改为 `GetWindowRect`（GDI）语义；MOVESIZEEND 与 LOCATIONCHANGE 广播共用同一换算。
- **验证**：还原广播 (x,y,w,h) 与收编摆位换算后逐字节相等；GDI rect 直比一致。

### 缺陷 2：最小化动画期 iconic 矩形污染 restore 快照

- **现象**：Win11 记事本 SW_MINIMIZE 动画中窗口缩到 185×27 且 `IsZoomed` 瞬间为 false → LOCATIONCHANGE 产生「还原(iconic rect)→最大化」翻转对，iconic 矩形被写进 VWM restore 快照。
- **修复**：后端 LOCATIONCHANGE 分支顶部 `IsIconic` 直接丢弃（最小化语义归 native-min 管）；前端 `nativeMaximizeVwm` 对 `!max && (w<160||h<100)` 兜底丢弃。
- **验证**：修复后最小化周期日志零污染广播；iconic 防御单测通过。

### 缺陷 3：收编通道 TOCTOU 竞态 → 同窗双收编（M5 占位卡双卡根因）

- **现象**：同一 notepad 窗 200ms 内被 launch 兜底与看门狗各收编一次（两个 embed_id、两次 L1 attach），产生 3 张占位卡，tp_final 对账失败。
- **根因**：`embed_adopt` 的查重（注册表）与 `attach_by_tier`（完成时才入注册表）之间存在竞态窗，两通道守卫先后通过。
- **修复**：新增 `ADOPT_IN_FLIGHT` 在途预留集——查重（注册表+在途）与占位在同一临界区原子完成，attach 全路径释放；看门狗派发前加 `adopt_in_flight` 检查。
- **验证**：复跑双窗恰两会话、tp_final=0；`adopt_in_flight_blocks_duplicate_reserve` 单测覆盖预留/拒绝/释放/注册表查重四分支。
