# 无框嵌入模式（Frameless Embed）改造方案

日期：2026-09-15
目标：让嵌入的第三方软件**去掉 Variable 自绘的外框（标题栏 + 圆角边框 + 缩放把手）**，以**自身原生界面与全屏尺寸**铺满显示。
状态：**方案待确认，尚未改动任何代码**

---

## 0. 先回答"要不要重新开始做"

**不要重做。** 理由：

| 维度 | 现状 | 重做的代价 |
|---|---|---|
| L1 嵌入（`SetParent`） | **已经是 Windows 上唯一零延迟/零 CPU 的真原生方案，方向正确** | 重写不可能绕过 Win32 语义，只会丢已有修复 |
| Steam / WE 兼容修复 | 累计 R3-B11、R5、R6、R7 四轮实机定位（`family_images`、`needs_reveal`、`is_adoptable_main_window`、`steam://open/main` 唤起） | 全部作废，需重新踩一遍所有坑 |
| 虚拟窗体系 | 贴靠/多窗/标签组/编组/画中画/布局快照等 40+ 能力已建成 | 全部重建 |

**你要的"无框"是一个渲染层开关，不是架构问题。** 现有代码已经具备全部必要条件：

- 标题栏高度是常量 `VWM_TITLEBAR_H = 38`（`vwm.ts:165`）
- 嵌入窗边界 = 虚拟窗 rect 减去标题栏高度（`VirtualWindowManager.tsx:623-625` 的 `(win.y + 38)` / `(win.h - 38)`）
- 最大化已经用 `workArea` 铺满（`vwm.ts:toggleMaxVwmWin`）

**把标题栏高度设为 0，嵌入区自然铺满整个虚拟窗。** 这是一个约 4 个文件的受控改动，不是重写。

## 1. 改动清单（4 个文件）

### 1.1 新增：每窗口的"无框"标志

**文件**：`src/system/windows/vwm.ts`

`VwmWin` 接口（约第 100–150 行）新增可选字段：

```ts
/** 无框模式：隐藏 Variable 标题栏/边框，第三方软件以原生尺寸铺满内容区。 */
frameless?: boolean;
```

**为什么放在窗口实例而不是全局设置**：你需要的是"某些软件无框"而非"全部无框"。放窗口实例上可以：
- 对 worldbox / Blender / 浏览器这类"有自己完整 UI"的应用开无框
- 对需要 Variable 标题栏拖拽/贴靠的场景保持有框
- 每个窗口独立记忆（配合 `persistGeom` 落地到几何持久化）

### 1.2 标题栏条件渲染

**文件**：`src/system/windows/VirtualWindowFrame.tsx`

| 位置 | 现状 | 改动 |
|---|---|---|
| 第 656–736 行 | `<div className="vwm-titlebar">…红绿灯…</div>` 恒渲染 | `{!frameless && (<div className="vwm-titlebar">…)}` |
| 第 882–888 行 | `{!maximized && (八向缩放把手)}` | `{!maximized && !frameless && (…)}` |

**关键**：无框时必须**保留一个"逃生通道"**，否则窗口无法移动/关闭。方案见 §1.5。

### 1.3 嵌入边界去偏移

**文件**：`src/system/windows/VirtualWindowManager.tsx`（`EmbedBridge`，第 606–643 行）

现状（第 619–626 行）：

```ts
void ipc.embedBounds(
  embedId,
  Math.round(win.x * dpr),
  Math.round((win.y + 38) * dpr),      // ← 固定偏移 38
  Math.round(win.w * dpr),
  Math.round((win.h - 38) * dpr),      // ← 固定减去 38
)
```

改为：

```ts
const tb = win.frameless ? 0 : VWM_TITLEBAR_H;
void ipc.embedBounds(
  embedId,
  Math.round(win.x * dpr),
  Math.round((win.y + tb) * dpr),
  Math.round(win.w * dpr),
  Math.round((win.h - tb) * dpr),
)
```

同时**消除硬编码 38**，改从 `VWM_TITLEBAR_H` 导入（现在这个是魔法数字，与 CSS 里的 `height: 38px` 手工同步，本身是个隐患）。

依赖数组（第 629 行）补 `win.frameless`。

### 1.4 CSS：无框态去装饰

**文件**：`src/styles/vwm.css`

新增（不要改现有 `.vwm-window` 规则，避免影响有框窗口）：

```css
/* 无框模式：去掉圆角/边框/阴影，让嵌入的原生窗口与虚拟窗完全重合 */
.vwm-window.frameless {
  border-radius: 0;
  border-color: transparent;
  box-shadow: none;
  background: transparent;
}
.vwm-window.frameless.focused {
  border-color: transparent;
  box-shadow: none;
}
```

**注意**：`.vwm-window` 有 `overflow: hidden`（第 21 行）+ `transform: translateZ(0)`（第 26 行）。这两个**必须保留** —— 前者约束嵌入区不溢出，后者建立包含块让 `position: fixed` 的背景层不逃逸。

### 1.5 无框下的操作通道（**这是方案的重点，也是最大的设计决策**）

无框后失去标题栏，直接损失 5 项能力：

| 能力 | 原实现位置 | 无框后 |
|---|---|---|
| 拖拽移动 | `onTitlePointerDown`（第 659 行） | ❌ 无拖拽区 |
| 双击最大化 | 第 663 行 | ❌ |
| 右键系统菜单 | 第 664 行 | ❌ |
| 红绿灯关闭/最小化 | 第 689–736 行 | ❌ |
| 边缘缩放 | 第 882–888 行 | ❌ |

**提供三个互补方案，建议同时上 A + C：**

**方案 A（推荐，改动最小）— 「悬浮控制条」**
鼠标移入窗口上缘时，浮现一条**半透明、自动淡出**的窄控制条（高度约 28px，不占布局）：
- 含红绿灯 + 可拖拽区
- 鼠标离开 2 秒后淡出（`opacity: 0; pointer-events: none`）
- 实现：`.vwm-window.frameless .vwm-hoverbar`，`position: absolute; top: 0; z-index: 全窗最高`
- **零布局影响** —— 嵌入区仍是满尺寸（`tb=0`），控制条浮在原生窗口之上

**方案 B — 全局快捷键**
沿用已有的窗口手感快捷键体系（`winfeelMenu.ts`），注册「聚焦窗口切无框/有框」热键。优点：不占任何屏幕空间。缺点：可发现性差。

**方案 C（推荐）— 快捷键 + 保留窗口手势**
- 拖拽：`Alt + 左键拖拽` 触发移动（很多 Linux WM 的约定，`dragBegin` 已存在，只需在无框分支用 `Alt` 作为修饰键判据）
- 缩放：`Alt + 右键拖拽` 或保留 8px 不可见的边缘热区（`position: absolute` 的细条，`cursor` 仍显示缩放光标）
- 关闭：`Ctrl+W`（R4 已实现单窗关闭）
- 最大化：双击 `Alt + 左键` 或热键

**我的建议**：**方案 A + C**。A 保证"能发现、能点"，C 保证"熟练后全键盘/鼠标手势高效"。

## 2. 需要你拍板的 3 个决策点

### 决策 1：无框的**触发范围**

| 选项 | 说明 |
|---|---|
| **A. 按应用开关** | 设置里给每个第三方应用一个「无框显示」开关，`ThirdApp` 登记项加字段（与现有 `dpi_fix` 同层） |
| **B. 按窗口手动切** | 右键菜单/快捷键，对当前窗口临时切无框（不持久化） |
| **C. 两者都要** | 应用级默认 + 窗口级临时覆盖（推荐） |

### 决策 2：无框下**最大化是否真的全屏**

现状 `toggleMaxVwmWin` 用 `workArea`（`snap.tsx:43-46` 从 `currentMonitor()` 取，**已扣除任务栏**）。

| 选项 | 效果 |
|---|---|
| **A. 保持扣任务栏** | 最大化后 Variable 任务栏仍可见，符合现有习惯 |
| **B. 真·全屏（覆盖任务栏）** | 更像"软件原生全屏"，但会盖住 Variable 任务栏，与你 memory 里"一切在 Variable 内"的隔离底线有张力 |

### 决策 3：`worldbox 已退出` 那个占位卡要不要一起处理

你上一轮明确说过（R7 硬约束）：**「已退出」占位框不要**，代码里已经改成 `exited → closeVwmWinSafe` 自动关窗（`VirtualWindowManager.tsx:378-379`）。

但截图里那个卡还在，说明**当时命中的是 `orphaned` 或 `failed` 分支**（这两个分支仍渲染占位卡）。所以：

| 选项 | 说明 |
|---|---|
| **A. 保持现状** | 占位卡只在真失败时出现，属于"如实告知" |
| **B. 全部静默** | `orphaned`/`failed` 也自动关窗或只留一个极小的角标提示（但你就无法知道软件为什么没进来） |
| **C. 折中** | 占位卡保留，但无框模式下渲染得极简（只有一行小字 + 一个按钮） |

## 3. 风险与回归清单

改动虽小，但触及几何链路，必须验这些：

| # | 风险点 | 验证方法 |
|---|---|---|
| R1 | **标签组偏移错算（已确认需处理）** | `EmbedBridge` 的依赖数组（`VirtualWindowManager.tsx:629`）是 `[win.app, win.x, win.y, win.w, win.h, win.minimized, visible, embedId, resync]`。标签组切换成员（`activateVwmTab`）只改 z-order/可见性，**不改 win.x/y/w/h** → 若两个成员 `frameless` 不同，bounds **不会重发**，嵌入窗会停在上一个成员的偏移上。**修法**：把 `win.frameless` 加进依赖数组，并在标签组切换时显式 `bumpEmbedResync` |
| R2 | **贴靠/编组几何** | 已核验 `snapZoneForVwm` 只用 `workArea`，不读标题栏高度 → 预期无影响，仍需实测 |
| R3 | **卷帘态冲突（已确认，必须加守卫）** | `vwm.ts:617` 卷帘把高度压到 `Math.min(x.h, VWM_TITLEBAR_H)`。无框窗口若也走这条，高度会变成 **0**（视觉上彻底消失且无法还原）。**修法**：无框窗口在 `rollUpVwmWin` 里直接 `return` 拒绝卷帘，或在无框时改用最小高度常量（如 28px 控制条高度） |
| R4 | **无框 + 最小化恢复** | `embed_visible(false)` 隐藏原生窗、`force_webview_repaint` 重绘（`embed.rs:1454`）——无框下重绘区域变化，需实测是否白屏 |
| R5 | **视频/游戏类应用** | 真全屏应用（如 worldbox 这类）自己会 `SetWindowPos` 改尺寸，与 `embed_bounds` 抢控制权 → 需实测是否抖动 |
| R6 | **DPI 换算** | 无框后嵌入区高度变化，`monitorDprAt` 的换算需复核（125% 本机必测） |

**门禁要求（改动后必须全绿）**：
- `tsc` 0 错
- `vitest` 基线 2635 passed / 4 skipped（新增 frameless 单测）
- `vite build` 成功
- `cargo test -p variable --lib` 绿（若动到 Rust 侧）
- 实机验证：有框窗口行为**零变化**（这是行为等价红线）

## 5. 备选：一个更激进的方案（供对比）

如果你要的是**"第三方软件完全脱离 Variable 窗口体系，直接以原生窗口浮在桌面层"**（即不用虚拟窗包裹，原生窗口自己就是顶层窗），那与当前架构差异如下：

| | 当前 L1（`SetParent` 子窗） | 激进方案（独立顶层窗） |
|---|---|---|
| 窗口归属 | Variable 桌面窗的子窗 | 独立顶层窗 |
| 剪裁 | 被父窗客户区剪裁（不会超出虚拟窗） | 可自由超出 |
| z-order | 随父窗（天然在桌面之上、任务栏之下） | 需自己管理，易与 Variable 桌面 `always_on_top` 冲突 |
| 贴靠/编组 | 天然跟随虚拟窗 | 需重新实现 |
| 你 memory 里的"隔离"要求 | ✅ 满足 | ❌ 会露出到 Windows 任务栏层级 |

**不推荐**：这会直接破坏你已经确立的隔离底线（R5 的 `reassert_desktop_topmost`），且与"界面分离"症状同源。
