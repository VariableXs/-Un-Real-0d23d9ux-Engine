## 0. 全局工程纪律（每一波次、每一项都必须遵守）

### 0.1 开工前置核查（每项 V 功能动第一行代码前）

1. **去重复核**：`rg` 检索本项关键词在四份既有《功能全景》（NEXT-40 / ASCENT-60 / APEX-70 / SUMMIT-90）中的立项情况，确认无重叠；发现重叠即提请立项仲裁，宁可缓做不可重做。
2. **共享文件核对**：涉及 `src/i18n/dictionaries.ts`、`src/lib/ipc.ts`、`src-tauri/src/lib.rs`、`src/system/windows/vwm.ts`、`src/system/StartMenu.tsx`、`desktop.css`、`tools.css` 的，改前 `rg` 核对当前状态（并行 AI 可能刚改过），只增不改他人段落，改后立即跑 `node tools/audit.cjs`。
3. **键位槽位冻结**：本轮所有新键位（V-25/44/46/51/65 等）一律先查 Z-08 键位注册表；注册表未落地期间只允许 `ctrl+alt+` 空闲槽与裸功能键，且必须实现 Z-09 让位检测（系统组合与第三方全局热键优先）。
4. **四大内置应用零修改**：任何 diff 若触碰 `src/apps/write|mind|code|fate/**`、`src/features/editor|mindmap|project|fate*/**`、`src-tauri/src/library|mindmap|project_scan/**`，一律打回。

### 0.2 每项功能的统一交付流程（DoD）

```
实现（默认关闭或默认=现状）
  → 单测/组件测试（vitest / cargo test 对应模块）
  → i18n zh+en 键补全（audit.cjs 过）
  → tsc 零错误、npm run build 通过
  → cargo check 通过；涉及后端逻辑的项跑 cargo test --no-run（教训：lib check 绿 ≠ test 可编译）
  → 共享文件 diff 复核（只增不删他人段落）
  → 验收条目逐项自测（全景文档「验收」小节）
  → 未实测项不打 ✅（B-30 口径）
```

### 0.3 已知地雷清单（历史教训，逐条规避）

| 地雷 | 规避动作 |
|---|---|
| zh i18n 块被并行进程反复回滚 | 每批修改前后 `rg` 复核新增键；每波次收尾再全量复核一次 |
| Edit 工具剥掉 .ps1 的 UTF-8 BOM | 任何 .ps1 编辑后立即写回 BOM |
| 结构体重构后 `#[cfg(test)]` 字面量漂移 | 后端结构体改动必跑 `cargo test --no-run` |
| match 枚举兜底臂吞语义（L1 嵌入 vs L4 让位教训） | 语义分叉处禁用 `_ =>`，显式分臂 |
| 并行编辑共享文件导致回滚冲突 | 共享文件「一次一批、最小 diff、rg 前后核」 |
| Invalid Cargo feature 阻断 cargo check | 不动 Cargo.toml features；新增依赖走评审 |
| 嵌入窗口（L1）的宿主约束 | 窗口功能对 L1 窗口的不可支持项如实置灰（不硬做） |

### 0.4 并行兼容协议（与 SUMMIT-90 / APEX-70 并行施工）

- 本轮不修改 SUMMIT-90 / APEX-70 已立项项的任何文件领地；需要消费其交付物（如 M-21 校验和、M-24 书签条、N-31 使用洞察）时以**软依赖**接入：未交付时功能如实降级或暂缓，不阻塞本项其他部分。
- 文件领地图以《AI分工图》为准；跨路依赖只允许「上游交付物 → 下游消费」，禁止跨路改文件。
- 波次节奏错开：本轮 P2 波（桌面/文件）与 AI-1 SUMMIT 批次不同周开工，降低 explorer 目录并发。
