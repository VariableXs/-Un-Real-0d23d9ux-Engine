# TRINITY-500 功能全景图（完整版 · 三位一体）

> **TRINITY-500**：围绕 **「内核化 Variable + 三系统隔离共存 + 共享卷」** 的 500 项功能总规划。
> 三系统 = **Windows（宿主）· Variable（Tauri 桌面环境）· Varix（自研裸机内核）**，共处同一 U 盘：
> **独立运行（同一时刻只有一个在运行态）· 系统级隔离（Windows 完全停止/原生启动）· 共享一座桥（单一共享数据卷）**。
> 20 个 AI（AI-01~AI-20）× 25 项 = **500 项**（F001~F500），五波次 W1~W5。
> 状态：⬜ 未开始 / 🔶 半做 / ✅ 完成
> 配套：《TRINITY-500-实施总步骤图》《TRINITY-500-AI分工完成图》

## 〇、总纲与边界

### 0.1 一句话定位

> **把 Variable 装进 Varix 内核里，让它在 U 盘上和 Windows「物理时间互斥」地共存——切换即隔离，共享只经一座刻意留出的桥。**

### 0.2 与既有规划的关系（零重复纪律）

TRINITY-500 是**增量层**，绝不重做已有规划。依赖关系如下：

| 规划 | 它负责什么 | TRINITY 只做什么 |
|---|---|---|
| **VARIX-500**（内核内部） | 引导/CPU/内存/调度/进程/存储命令层/输入协议/图形基础/网络/安全/电源/音频/虚拟化/部署 | 在它的**块设备层之上**做文件系统；在它的**进程/ELF 之上**收口 syscall 入口；在它的**vsem 语义之上**做渲染 |
| **NOVA-500**（桌面下一阶段） | Tauri 版桌面的 500 项增强 | 只做「**内核版**」的实现，语义对齐、不重复设计 |
| **PORTABLE-* / MASTER-PLAN** | 便携虚拟系统、容器、云 AI 矩阵 | 只做「**原生裸机**」路线（B 模式），不做虚拟机路线 |

> 立项前先对照 VARIX-500 / NOVA-500 全文查重；发现重叠即归并到原规划，本图只留增量。

### 0.3 边界先行（如实声明，不写营销话术）

| # | 诚实边界 | 工程含义 |
|---|---|---|
| 1 | **共享即反隔离** | 文件/软件共享是刻意的桥。隔离只覆盖「共享卷之外的每一件事」；共享卷内的数据三系统都可见 |
| 2 | **软件二进制不能共享（ABI 墙）** | Windows `.exe` 永不进 Varix；可共享的是**文档/媒体/配置/数据**与**便携软件的数据目录**，可执行程序各系统一份、共享同一数据 |
| 3 | **全部性能 = 非瞬间切换** | Windows 完全停止靠「休眠到盘」换取，每次切换约 10~60s（由内存量与盘速决定），非秒级 |
| 4 | **React/WebView2 不进内核** | 内核版 Variable 是 framebuffer 重写：**逻辑复用（vsem 语义已移植）、UI 重写**。Tauri 版保留为 Windows 预览形态 |
| 5 | **休眠文件是真实残留** | Windows 休眠 = 全部内存落盘；加密休眠文件 + 不放入共享卷，是防交叉读的底线 |
| 6 | **固件/物理层不可软件防御** | UEFI 固件级木马、硬件键盘记录器、恶意 PCIe DMA 不在防御范围（引导链完整性校验可查、不可根治） |
| 7 | **隔离靠代码正确性** | 隔离 Windows 靠「Windows 已停机」这一架构事实；隔离内核自身进程靠分页+ring3/ring0 的正确性——**必须真机验证，不靠声明** |

### 0.4 质量军规（每项功能全过才算完成）

1. **手感无损**：输入→像素 < 50ms；动效弹簧曲线统一令牌。
2. **画质无损**：合成器禁止降采样；128px 图标管线平移；OKLCH 色彩令牌对齐。
3. **性能预算**：帧预算 60fps、IO 预算（U 盘随机读 < 20ms）、启动预算（秒级进桌面）——全部有仪表且守红线。
4. **可回滚**：驱动/服务/策略独立开关与版本回滚；切换失败自动回退。
5. **降级纪律**：无 GPU→软合成；无 VT-x→纯引导并存；无网络→离线清单；无音频→静默。
6. **崩溃红线**：任何驱动/服务/应用 panic 不拖垮内核；用户态崩溃只回收进程。
7. **零重复**：立项前对照 VARIX-500 / NOVA-500 查重。
8. **完成即自检**：每域 CheckSet 自检 + 域收口自检 + 全系统闭环自检（F475+F500），不写报告、只留可复现验收。

### 3.2 术语速查

| 术语 | 含义 |
|---|---|
| TRINITY | 三位一体：Windows / Variable / Varix 三系统共存 |
| 共享卷 | U 盘上三系统共同读写的 FAT32/exFAT 数据区（那座「刻意留出的桥」） |
| 休眠切换 | Windows 休眠到盘 → 重启进 Varix；反向写唤醒向量 → 重启恢复 Windows |
| 内核版 Variable | vsem 语义 + framebuffer 渲染的原生桌面（逻辑复用、UI 重写） |
| 双形态 | 内核版 Variable ↔ Tauri 版 Variable，同一份数据、两种渲染 |
| CheckSet | 每域自检登记表，逐项 PASS/FAIL，最终全系统闭环 |
| ABI 墙 | 可执行程序二进制边界：.exe 不进 Varix，ELF 不进 Windows |

                  └─ 三宿主验收总表 F497 → 发布
