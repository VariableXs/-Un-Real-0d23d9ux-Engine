# TRINITY-500 AI 分工完成图（完整版 · 三位一体）

> 共 **20 个 AI（AI-01 ~ AI-20）**，围绕「内核化 Variable + 三系统隔离共存 + 共享卷」全域分工，每域 25 项，合计 **500 项功能（F001~F500）**。
> 状态：⬜ 未开始 / 🔶 进行中 / ✅ 完成
> 纪律：
> 1. 每个 AI 只新增/修改 `kernel/varix/src/` 内自己域的模块；确需改 VARIX 既有模块时先登记为「依赖收口」并同步 VARIX-500 文档。
> 2. 共享文件（本图、总步骤图、全景图）编辑前先 `git log` 验 HEAD（并行会话防覆盖）。
> 3. 完成一项：更新本图 → commit（`trinity500(ai-XX): Fxxx <功能名>`）→ 推送 GitHub。
> 4. 质量军规：手感无损、画质无损、性能预算、可回滚、降级纪律、崩溃不扩散、零重复、完成即自检（不写空报告）。
> 5. 编号从 AI-01 起，F 编号从 F001 起，连续无跳号。

## 跨路协作约定（并行会话防冲突）

1. **共享热点文件**：三份 TRINITY MD（本图/总步骤图/全景图）整文件重写会抹掉他路进度——增改保留各自标记段。
2. **内核目录边界**：AI 只写自己域目录；`lib.rs`/`mod.rs` 的模块声明由 AI-20 统一收口，其他 AI 不碰。
3. **VARIX 依赖收口**：确需改 VARIX 模块时，先在 VARIX-500 文档登记「TRINITY 依赖收口」，避免两计划互相覆盖。
4. **commit 规范**：`trinity500(ai-XX): Fxxx <功能名>`；一处一提交，不混批。
5. **完成即自检**：交付 = 代码 + CheckSet 自检 + 更新本图状态，三者缺一不算完成。
