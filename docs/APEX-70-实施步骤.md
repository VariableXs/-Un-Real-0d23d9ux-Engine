## 0. 施工总纪律（全批次共同遵守）

### 0.1 验证基线（每个批次收口前必须全绿）

```powershell
# 前端
npm run build            # tsc + vite 零错误
npm run audit            # audit.cjs AUDIT PASSED（i18n 键 zh/en 同步、术语抽查）
npx vitest run           # 单测全绿

# 后端（涉及时）
cargo check              # lib 绿
cargo test --no-run      # 测试可编译（血泪教训：check 绿 ≠ test 可编译）

# 工具
node tools/keymap-audit.cjs    # PB-0 之后加入：键位零 error 冲突
node tools/theme-validate.cjs  # PB-8 之后加入：示例主题全过
```

### 0.2 共享文件守则（沿承既有血泪教训，全文有效）

1. `src/i18n/dictionaries.ts`、`src/lib/ipc.ts`、`src-tauri/src/lib.rs` 三个共享文件：**改前 `rg` 核对当前状态，改后立即 `rg` 复验未回滚**（zh i18n 块历史上被并发进程反复回滚）。
2. 每次只做最小 diff，不顺手重构、不格式化整文件。
3. 跨路文件冲突：等持有人收口后再动，不抢写。
4. `.ps1` 脚本如经 Edit 工具修改，**必须重新写回 UTF-8 BOM**（已两次翻车）。

### 0.3 批次编号（PB = Peak Batch）与总排布

| 批次 | 内容 | 域 | 关键点 |
|---|---|---|---|

## 1. PB-0：地基层（Z-08、Z-01）

### 阶段 0.1 键位注册表（Z-08）

1. 新建 `src/lib/keymap/types.ts`：`KeyBinding { id, combo, scope: "global"|"window"|"context", priority, source, descKey }`；`Combo` 用规范串（如 `"ctrl+alt+t"`）。
2. 新建 `src/lib/keymap/registry.ts`：`register()/unregister()/snapshot()`；注册时立即做静态冲突检测（同 scope 同 combo = error；跨 scope 同 combo = warn 记录）。
3. 新建 `src/lib/keymap/arbitrate.ts`：作用域栈裁决，输入焦点元素内自动降级（联动 Z-10 机制）。
4. **存量收编**：`rg -n "addEventListener\(['\"]keydown" src/` 全量列出，逐个迁入注册表（预计 30–60 处，分目录小步提交）。
5. `tools/keymap-audit.cjs`：静态扫描源码中的裸 keydown 与注册表 dump 比对，输出冲突报告；进 package.json scripts 与 CI。
6. 单测：注册/注销/冲突检测/作用域裁决各一组；面板卸载后键位释放（snapshot diff 空）。

### 阶段 0.2 图标网格规格（Z-01 基础部分）

1. `docs/ICON-SPEC.md`：16/20/24/32 四档网格、keyline、笔粗档位规格表。
2. 新建 `src/components/AppGlyphs` 旁的 `SystemIcon.tsx`：Segoe Fluent Icons 字体封装（字形名 → codepoint 映射表，仅用系统已装字体，缺失回退 lucide）。
3. 高频 30 图标映射表（回收站、网络、音量、电源、通知、搜索、设置、文件夹…）。
4. 单测：映射表 codepoint 有效性；回退路径触发。

**收口门禁**：keymap-audit 报告零 error；tsc/audit/vitest 全绿；图标映射表评审通过（并排截图对比）。

### 阶段 1.5 文案规范（Z-07）

## 9. PB-8：开放性与拓展（Z-50…Z-56）
