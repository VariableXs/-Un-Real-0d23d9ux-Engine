## 一、定位修正（覆盖主文件"写在前面"）

主文件原文："它不是一个独立的软件，而是嵌入在宿主应用里的一个功能模块。"

**修正为**：

> (Un)Real 0d23d9ux# Engine（Code Analysis）是一个**独立的桌面软件**。
> 它可以单独在 Windows 上运行；也可以被放入 Variable 系统的软件收件箱，
> 由系统自动识别登记、嵌入环境内随时使用；未来还能以只读 viewer 形态
> 接入 VARIX 内核。"嵌入"只是它的运行环境之一，不是它的产品形态。

理由：主文件后续 550+ 项功能（完整窗口体系、三界面系统、动态壁纸、
8 风格 UI、78+ 命令终端）的体量早已超过"模块"，按独立软件设计才不会被
宿主边界卡住；而收件箱机制（已实测存在：`SoftwareInbox` 文件夹自动扫描
登记 exe + 提取 Windows 图标）让"放入系统"零成本。

## 二、统一架构：一个 core，三个壳

```
                    ┌────────────────────────────┐
                    │  core（纯逻辑，零 UI 依赖）  │
                    │  · 多语言解析 → 语义 IR      │
                    │  · 七级下钻模型（项目→行）   │
                    │  · 翻译层：250 概念×9 语言   │
                    │  · 比喻库 + 三层比喻校验     │
                    │  · 检测引擎（6 类开关）      │
                    │  · 命令表（/命令 A-Z 全集）  │
                    └──────────┬─────────────────┘
           ┌──────────────────┼──────────────────┐
           ▼                  ▼                  ▼
   ┌───────────────┐  ┌───────────────┐  ┌───────────────┐
   │ 壳A：Windows   │  │ 壳B：Variable  │  │ 壳C：VARIX     │
   │ 独立完整版     │  │ 收件箱嵌入版   │  │ 内核 viewer    │
   │ （先做，全功能）│  │ （同一 exe     │  │ （远期，只读）  │
   │               │  │   直接投递）    │  │               │
   └───────────────┘  └───────────────┘  └───────────────┘
```

**关键决定：壳B 不单独开发。** 壳A 打包成收件箱友好的绿色软件后，
直接丢进 `SoftwareInbox` 即被 Variable 自动登记，同一份 exe 双栖。
壳C 是远期目标（内核侧只读 viewer，无文件写权限，无拖拽改码）。

### core 的输出契约（三壳共用）

```
open_project(root: Path) -> ProjectIR
ProjectIR {
  meta: { name, lang_stats, loc, file_count },
  tree: 七级节点（项目→模块→子系统→文件→类/结构→函数→行）,
  calls: 调用边表, dataflow: 数据流边表,
  issues: 检测结果（空指针/竞态/泄漏/死代码/热点/安全）,
  plain: 每节点大白话 + 比喻（经三层比喻校验）,
}
```

七种可视化（树根/流程图/3D神经/思维导图/星系/电路/地铁）全部只消费
这一份 IR——这是主文件"七模式共享同一份数据"要求的落点。

## 三、三平台全功能等价原则（550+ 项，三端 100% 可用）

**总原则：一版全功能，三端等价。不做任何"阉割版"。**
三端的差别只允许出现在"由谁提供底层能力"，绝不允许出现在"功能有没有"。
凡看似宿主冲突的能力，一律改为**换实现层**而不是隐藏/禁用：

| 疑似冲突能力 | 实现策略（三端都可用） |
|---|---|
| 动态壁纸（#401–#410） | 实现为**应用内背景层**：壁纸铺在 Code Analysis 自己的画布/窗口底面。独立态=全窗背景；嵌入态=虚拟窗口背景；内核态=应用窗口背景。不碰宿主桌面 → 无冲突，功能完整保留。 |
| 全局 F 键 / 系统级快捷键（#461–#480） | 键位注册表三端同一份；独立态注册系统级，嵌入态由 Variable vwm 把窗口焦点内的按键转发给应用（宿主已具备），内核态走内核键位事件。**用户配置的每个键位在三端都生效**，作用域声明（窗内/全局）只是注册目标不同。 |
| 文件写回 / 拖拽改码（#100–#150、#365–#380） | 走统一的"写回通道"接口：独立态=直接写磁盘；嵌入态=同左（进程身份不受嵌入影响）；内核态=通过内核 VFS 写（用户态应用带 fs.write 能力）。 |
| 命令终端全集（#411–#460，207 条） | 命令表是 core 的数据，三端共用同一张表；端差异只体现在个别命令的执行后端（如 /theme pixel 三端都改自己的主题）。 |
| 多风格 UI（#381–#400） | 8 风格资产全部随应用携带（resources/），不依赖宿主主题；内核态同样渲染应用自带资产（见下"壳C 实现形态"）。 |

### 壳C（VARIX 内核）如何做到全功能

壳C 不做成"只读 viewer"，而是**内核用户态应用**（与仓库现有
`kernel/userspace/<crate>` 约定一致，自带空 `[workspace]`）：

- **进程形态**：entry.elf 用户态进程，经 appfw（aurora/appfw.rs）注册，
  有自己的窗口与事件循环——具备完整的输入接收与画面输出能力；
- **文件访问**：声明 `fs.read`/`fs.write` 能力后经内核 VFS 读写项目文件，
  拖拽改码/一键改进的写回全部走得通；
- **渲染**：7 种可视化 + 8 风格 UI 的资产随应用包携带，用内核 UI 组件
  （ui/widgets、ui/tokens）渲染，不依赖任何宿主主题；
- **输入**：键盘/鼠标事件由内核输入子系统投递给焦点应用，键位管理正常工作；
- **性能预算**：大项目（星系模式几千函数）在内核态按 IR 分页加载，下钻
  到哪层加载哪层——功能不减，只是按需加载。

### 等价性验收（加入每期 Definition of Done）

每个功能完成时必须三端各验一次：
- [ ] Windows 独立运行该功能通过；
- [ ] Variable 收件箱登记后嵌入运行该功能通过；
- [ ] VARIX 内核用户态运行该功能通过（P3 之前内核侧未具备时，标记
  "待内核运行时"挂账，不视为完成）。

## 四、收件箱友好打包规范（壳A 构建必须满足）

投递目标：Variable 的 `<程序目录>\SoftwareInbox`（回退 `<数据目录>\SoftwareInbox`）。
系统行为：开机/拖放自动扫描 → 登记 exe → 提取 128px Windows 图标 →
桌面/开始菜单/任务栏可用 → 启动时窗口嵌入 Variable 环境。

```
CodeAnalysis/                       ← 整个文件夹丢进 SoftwareInbox
├── CodeAnalysis.exe                ← 唯一主 exe（多余 exe 会被收件箱误判）
├── resources/                      ← 前端画布资源（7 种可视化 + 8 风格主题）
└── locales/                        ← i18n 资源
```

四条硬要求：

1. **exe 元数据**：`FileDescription = "Code Analysis 代码透视引擎"`（登记显示名）；
   版本信息、公司名齐全；图标内嵌 exe 资源（收件箱提取用）。
2. **标准 Win32 窗口 + 单实例**：不做 UWP/管理员自提，保证 SetParent 嵌入成功；
   二次启动前置已有窗口并透传新参数。
3. **路径参数**：`CodeAnalysis.exe <项目路径>`——兼容 Variable 文件关联
   （右键项目文件夹 → 打开方式），也是命令行/快捷方式的标准入口。
4. **绿色免安装**：不写注册表、无安装器、解压即用；配置写 `%APPDATA%\CodeAnalysis`
   （嵌入态与独立态共用，保证两种启动方式配置一致）。

验收标准（放入即用）：
- [ ] 文件夹拷入 SoftwareInbox，重启 Variable 后桌面/开始菜单出现图标（自动提取）；
- [ ] 点击启动，窗口嵌入 Variable 虚拟窗口内，任务栏无重复原生窗；
- [ ] 独立双击 exe 一切功能正常（壁纸/全局键等独占功能只在独立态出现）；
- [ ] 右键项目文件夹"打开方式"直达并加载该项目。
