# VARIX 垫片协议规范（任务 22 定版 · S2.01 三体定版 v2 · AI-3）

> 定位：Variable 前端（Tauri 版与内核 Servo 版共用同一份代码）与后端服务之间的统一 IPC 协议。
> 单一事实源：`tools/shim-protocol.source.json`；双侧/三侧类型由 `node tools/gen-shim-protocol.cjs` 同源生成三产物：
> - 前端：`src/lib/shim/protocol.ts`
> - 后端：`src-tauri/src/shim_protocol.rs`
> - 内核：`kernel/varix/src/vport/shim_protocol.rs`（零依赖、无堆分配——vport 域纪律；错误码 u8 序号即线缆编码）
> **禁止手改生成物**；一致性由 `node tools/audit.cjs` 的 SHIM PROTOCOL GATE 段机械化看护（内存再生 vs 磁盘逐字节比对，漂移即红）。
> 当前协议版本：**v2**（2026-09-21，变更记录见 §6）。

## 1. invoke 名命名空间

- 命令名**原文透传**：现有 `snake_case` 命令名（如 `embed_bounds`、`set_settings`）保持不变，垫片不改名、不加前缀。
- 新增命令必须 `snake_case`，且在任务 23 三色映射表（`docs/shim-mapping.json`，数据驱动由 `tools/shim-mapping.cjs` 生成）登记归属后才允许进入 `generate_handler!`。
- 能力位目录见 source.json `capabilities[]`；命令 → 服务归属由映射表数据驱动，**加命令不改垫片代码**。
- 内核侧 dotted API 面（`window.create` 等，vport `tauri_api_map`）是面向嵌入方的另一层命名空间，经 `invoke` → `ipc.shim_invoke` 归一到本协议；两层命名不得混写。

## 2. 参数序列化

- 参数为 JSON 对象，**一次序列化**，禁止二段封装（不得把对象再 stringify 塞进字符串字段）。
- `args` 缺省视为空对象 `{}`。
- 前端 `ipc.ts` 是既有唯一 invoke 出口；垫片出口为 `src/lib/shim/shimInvoke.ts`（传输层注入式：Windows 侧包 Tauri invoke，内核侧经 `embedderTransport.ts` 的 `__VARIX_SHIM__` 桥），零裸 invoke 绕过（audit.cjs 门禁）。

## 3. 错误码三段式

| 段 | 传输形态 | 语义 |
|---|---|---|
| OK | 载荷直达 | 正常返回，无包装 |
| MAPPED_ERR | `{"__shim_error":{"code","message"}}` | 命令存在但执行失败，code ∈ 错误码表 |
| MISSING | `{"__shim_missing":"<cmd>"}` | 命令在映射表无归属 |

错误码表（v2，共 8 码；retryable 同源自 source.json）：

| 码 | 语义 | retryable |
|---|---|---|
| SHIM_INVALID_ARGS | 参数未通过 schema 校验（缺字段/类型不符/超限） | false |
| SHIM_UNSUPPORTED | 命令存在但当前后端能力不支持（capability=false） | false |
| SHIM_TIMEOUT | 内核服务未在预算时间内应答 | true |
| SHIM_BACKEND_DOWN | 后端通道未建立/已断开 | true |
| SHIM_VERSION_MISMATCH | 协议版本协商失败 | false |
| SHIM_PERM_DENIED | 白名单裁决拒绝（默认拒绝面） | false |
| SHIM_KV_FULL | KV 账本/溢出区已满，写被明确拒绝（kv 服务专用，绝不静默覆盖） | false |
| SHIM_INTERNAL | 垫片内部错误（映射表/序列化异常/块设备 IO） | true |

**内核 KvError → 协议码映射**（kvsrv 命令面，见 §7）：

| KvError | 协议码 | 说明 |
|---|---|---|
| BadNamespace / BadKey / TooLarge | SHIM_INVALID_ARGS | 参数约束越限，message 携带具体上限 |
| Full | SHIM_KV_FULL | 明确拒绝写，绝不静默覆盖（总案验收点） |
| Io(_) | SHIM_INTERNAL | 块设备错误，可重试 |

约束：错误文案必带 i18n 词条（audit i18n 门禁扩展到垫片降级文案）；**零裸错误码直出**（体验红线）；MISSING 降级不得产生半改副作用；线缆层未知错误码由前端 `decodeShimOutcome` 兜底为 SHIM_INTERNAL（可重试），不得猜测。

## 4. 事件反向通道

后端→前端 emit，频道名与语义和 Tauri event 同构；**完整枚举以 source.json `events[]` 为准**（20 频道：boot://event、settings://changed、sys://*、embed://*、usb://*、taskbar://state、watch://escape、shim://input、engine://state）。内核发射端用生成物 `vport::shim_protocol::events::is_known` 校验频道名，未知频道拒绝发射、不静默透传。新增频道必须先入 source.json 再生成。

## 5. 版本协商

- 前端启动第一步调 `shim_hello`（`shimInvoke.shimHello()`），应答 `{protocolVersion, backendVersion, capabilities[]}`。
- 判定：`protocolVersion === SHIM_PROTOCOL_VERSION && backendVersion >= SHIM_MIN_BACKEND_VERSION`；不满足抛 `SHIM_VERSION_MISMATCH` 并走降级面。
- 能力位查询 `shimCapability(flag)`；未握手一律 false（调用方按 UNSUPPORTED 降级，不静默）。
- 内核侧是能力位的最终事实源（`vport::shim_protocol::caps` 静态表）；Windows 侧尚未实现 shim_hello 命令（任务22 遗留，S2.05+ 嵌入层落地时对齐）。

## 7. 内核侧命令面契约（kv_* · S2.03）

内核 KV 命令面（`kernel/varix/src/kvsrv.rs` 内嵌 `cmd` 模块）是 `kv_get/kv_set/kv_remove/kv_keys` 四命令的内核半边；嵌入层（S2.05+，AI-4）负责 JSON args ⇄ 线缆帧翻译，本契约即两者边界。

**请求帧**（嵌入层翻译 JSON 后的形态）：

```text
[0]     tag u8      1=KV_GET  2=KV_SET  3=KV_REMOVE  4=KV_KEYS
[1..3]  ns_len u16 LE
[3..5]  key_len u16 LE
[5..9]  val_len u32 LE   仅 KV_SET 携带，其余恒 0
[9..]   ns || key || val（val 仅 KV_SET）
```

**应答帧**：

```text
[0]     status u8   0=OK  1=MAPPED_ERR（本层未知 tag=INVALID_ARGS，不产生 MISSING）
[1..2]  code u8     status=1 时有效，取值 = vport::shim_protocol::err 线缆编码
[2..4]  msg_len u16 LE
[4..8]  payload_len u32 LE
[8..]   msg || payload
```

载荷约定：KV_GET = `[found u8][value…]`（found=0 无值，区分空串）；KV_KEYS = `[count u16 LE][(klen u8)(key)…]*`；KV_SET/KV_REMOVE = 空。

约束：解析对任意输入字节流**零 panic**（fuzz 门禁 ≥1000 组）；坏帧 = MAPPED_ERR(SHIM_INVALID_ARGS)；持久化语义全部继承 kvsrv（fs23_journal 账本，断电 ×10 零丢失、命名空间隔离、满容明确报错）。
