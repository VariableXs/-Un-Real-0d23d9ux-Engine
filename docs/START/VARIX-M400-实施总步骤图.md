## 〇、总纲

### 0.1 为什么是 16 域 400 项

成熟度差距清单（2026-09-12 评估结论）归并为六大缺口，16 个域恰好一一对应并留出打磨纵深：

| 缺口 | 对应域 |
|------|--------|
| 平台底座不牢（引导/SMP/内存隔离） | AI-01、AI-02、AI-03、AI-04 |
| 循环系统缺失（存储/驱动/网络/GPU） | AI-05、AI-06、AI-07、AI-08 |
| 桌面体验未成品化 | AI-09、AI-16 |
| 兼容性欠账（真机矩阵） | AI-10 |
| 看不见的质量（性能/安全/测试） | AI-11、AI-12、AI-14 |
| 交付能力为零（发布/文档/生态） | AI-13、AI-15 |

### 0.2 成熟度军规（每项功能必须全过）

1. **真机优先**：能真机验证的不用 QEMU 代替；QEMU 验证的标注环境版本。
2. **数据说话**：每项性能相关功能必须产出 P95/P99 数字并落盘 `docs/bench/`。
3. **可回滚**：每项功能独立开关，异常一键关闭，不留残留。
4. **断电可活**：凡涉及持久化的改动，必须通过断电一致性测试框架（AI-05 提供）。
5. **安全默认**：默认配置即安全配置；宽松选项必须显式打开。
6. **零回归**：合入前 `cargo ktest --lib` 全绿 + `cargo kbuild` 零告警 + 视觉回归通过。
7. **诚实留痕**：测不了写 `todo`，绝不臆造；每项完成更新分工完成图。
8. **艺术品标准**：像素级走查 + 声音/动效全检——"能跑"不算完，"耐看"才算完。

### 0.3 工程纪律

- 各 AI 只碰自己域内文件；共享文档编辑前先 `git log` 验 HEAD。
- 完成一项：更新分工完成图 → commit（`varixm400(ai-XX): Fxxx <功能名>`）→ 推送 GitHub。
- 不写非功能性报告；文档只维护这 3 个 MD + docs/ 下的证据目录。

## 三、风险与红线

1. **手感红线**：动画/交互改动必须 A/B 对照，手感回退即回滚。
2. **断电红线**：存储相关改动未过断电框架不得合入 W2 之后任何批次。
3. **安全红线**：内核态改动必须过 AI-04 校验框架与 AI-12 审计清单。
4. **性能红线**：任何合入使宏基准 P95 劣化 > 5% 即自动打回。
5. **诚实红线**：验收数据造假=一票否决，无例外。
6. **范围红线**：400 项之外的新想法一律进 backlog 评审，不悄悄加塞。
