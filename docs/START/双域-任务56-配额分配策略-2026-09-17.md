# 任务56 配额分配策略（AI-K · 2026-09-17）

总案验收锚点：步骤1〔完善性=分配策略文档（为什么不这样分）〕＋步骤2〔完善性=回收策略表〕。
代码落点：`kernel/varix/src/quota.rs`（CpuQuota / MemWatermark / GpuChannel）。

## 1. 三方默认矩阵（为什么不这样分）

| Party | min_permil（保底） | weight（超额权重） | 角色与理由 |
|---|---|---|---|
| Front（Variable 前台） | 400‰ | 5 | 人直接看得到的一方：桌面/输入/合成。保底必须最大——前台卡顿=整个系统"卡"；超额权重也最大——空闲算力优先回流交互 |
| Engine（隐形 Windows 引擎） | 350‰ | 3 | 跑 Windows 软件的无缝 VM：吞吐型但有交互性（被打开的软件窗口本身要响应）。保底次之 |
| Wine（兼容层进程） | 150‰ | 1 | 兼容层后台进程为主：保底只防饿死，算力让位前两方 |

- **Σmin = 900‰ < 1000**：留 100‰ 空转余量，任何一方瞬时空闲时其他两方立即可吃，不出现"保底承诺顶满导致空闲也无法加速"的死板。
- **保底求解规则**（比例保底，proportional-with-minimums）：自然份额=w/Σw；低于自身 min 的一方先固化在 min，其余各方在剩余容量内按 weight 再分，迭代至收敛。默认矩阵解得 **500/350/150**（Engine/Wine 自然份额 333/111 低于保底被固化，Front 吃剩余容量 500）。
- **为什么不直接用 class/优先级**：6 调度类是系统级分层（RT/交互/批处理），三方是业务级角色——同一调度类内部的角色配额必须走份额调制（slice），否则会把 Engine/Wine 抬进高优先级类、破坏 RT 语义。
- **为什么不硬划核**：64 槽单核时间片模型下硬划核浪费（一方空闲=核闲置）。份额层 min_permil 是本模型的保底；物理核预留已有现成挂接点 `sched::isolate_for`（Isolated 类），关键线程可叠加使用，两层语义互补。

## 2. 份额→时间片换算（对接方式=只写既有 slice 字段）

- party 总片 = target_permil × SLICE_SCALE / 1000，SLICE_SCALE = 4×基准片（40）；单线程片 = 总片/成员数，clamp [1, 80]。
- 默认解：Front 20 / Engine 14 / Wine 6 tick。粒度 25‰/tick；引擎 on_tick 消费 slice_left、换出按 slice_total 重置、同优先级 RR 每轮份额∝slice_total——**调制走 tick 机制本身，无旁路通道**。
- 覆写入口：`assign_tid(tid, party)`（tid 级≈进程级覆写）/`clear_tid`/`set_default_party`/`set_quota`（运行时重配，校验 Σmin≤1000）。

## 3. 内存水位与回收策略表

| 档位 | 进入条件（free/total） | 退出条件 | 允许动作 |
|---|---|---|---|
| Normal | > 300‰ | —（初始档） | 无回收；有欠账则**逆序归还**（级3→级2→级1） |
| Pressure | ≤ 250‰（即时） | > 300‰（需越过滞回带） | 只级1：ramcache 裁剪，目标拉到 300‰ |
| Critical | ≤ 100‰（即时） | > 300‰ | 级1→级2→级3 顺序回收：ramcache 裁剪 → 引擎页 → Wine 前缀缓存 |

- 滞回带 [250‰, 300‰) 维持原档——升档即时、降档要 margin，防水位抖动反复回收。
- 回收=借走（`owed` 账本记账），归还=压力解除后原路退回；归还量必须等于回收量（探针/用例断言）。
- 危急时用户提示（不闪烁不遮挡）属 UI 侧验收（总案步骤4 设置页/通知），内核侧只出水位档位事件。

## 4. GPU 通道（trait 冻结 + 兜底声明）

- `GpuChannel`：kind/reserve/release/reserved/total_reserved/submit/submitted 七方法冻结，不得增改（扩展走新 trait）。
- 当前唯一实现 `SoftGpuChannel`（kind="soft"）＝**当前软件渲染兜底**（双落点声明：本条 + docs/双域-任务59-GPU-Vulkan立项评估报告-2026-09-17.md）。
