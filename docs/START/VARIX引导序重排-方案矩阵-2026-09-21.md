# VARIX 引导序重排 · 方案矩阵（AI-5 S4.1 缺口一移交件）

> **登记方**：AI-5（kernel-S41-xhci-hid验收记录 §2 缺口一）→ **承接方**：AI-1。
> **定位**：拍板前置件——只列「需要完成什么」与取舍，拍板后才施工。
> **日期**：2026-09-21。

---

## 0. 问题一句话

bootselect 三卡菜单运行在 `mem::init` 之前，而 xHCI 初始化依赖三样菜单期未就绪的东西
（ACPI MCFG→ECAM 扫描、#PF 惰性 MMIO 映射、PMM DMA 帧）——**USB 键盘在菜单阶段物理上
不可达**；且 S4.1 缺口二（DMA 帧落点运气）是独立根因，与顺序无关。

## 1. 约束清单（事实，均有代码/记录证据）

- 菜单输入现状 = PS/2；目标机 Legion 内置键盘即 PS/2，菜单可用（S0.3 已刷盘）。
- USB 键鼠在 **ushell/桌面路径已全通**（feed_key/feed_mouse 汇点零改动接入，AI-5 S4.1）。
- 无 PS/2 口的现代机器：菜单期无法用 USB 键盘选**非默认项**；但「5s 倒计时默认项 +
  拔盘物理兜底」保证不按键也能到达默认系统/回 Windows。
- xHCI「优雅跳过」契约已实测（QEMU 无 MCFG → kwarn 跳过，引导 890ms 不炸——部署预检实证）。
- QEMU 冒烟实证：HEAD 内核 `xhci: no MCFG table - usb hid skipped` 为预期行为。

## 2. 方案清单

### 方案 A · 菜单后置（推荐随缺口二修复落地）

- **做什么**：把菜单段（bootcfg 读取→mouse_init→run_countdown）整体挪到 `mem::init`
  之后；xHCI probe 与 mouse_init 并列、排在菜单前；`boot_next_action` 顺延紧随
  （其延迟执行机制本就存在，语义不变）。
- **前提**：AI-5 缺口二修复（.bss DMA 池+边界翻译）——否则菜单前 xHCI 仍靠运气，
  优雅跳过等于现状。
- **代价**：菜单亮出晚 1-3s（真机估）；菜单绘制须处理 console mirror 时序（先关镜像
  再画，幂等）。
- **收益**：缺口二修复落地后 USB 键盘**立即**进菜单；一次重排永久解决。

### 方案 B · 菜单不挪 + 菜单期最小通道

- **做什么**：菜单期引入最小 DMA 通道 + 早期 MMIO 显式映射（绕过 #PF 惰性机制，
  需在 Limine→内核页表交接窗口内直接编页表）。
- **代价**：引导地基改造，风险高、工作量最大。
- **收益**：菜单时间零回归。
- **定位**：远期备选——仅当「菜单延迟」被证明不可接受时评估。

### 方案 C · 现状收口（推荐立即执行）

- **做什么**：菜单 PS/2-only 如实入档；USB 键鼠从 ushell/桌面起生效（已是现状）；
  本矩阵本身即「缺口一」的登记闭环。
- **代价**：零。
- **收益**：M0/M1 零风险收口；S1.4 走查用内置 PS/2 键鼠即可。
