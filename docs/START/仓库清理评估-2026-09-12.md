### 入库垃圾（git 跟踪中不该在的）
- `tools/*.png` 约 15 张调试截图，单张最大 2.3 MB（`hung_screen.png`、`after_icon_click.png`、`dbg*_wp.png`、`real*.png`）——调试过程产物，应移出历史或至少从 HEAD 移除。
- 根目录散落临时文件（多数已被 `*.log` 规则忽略，但建议归档）：`int.log`、`int2.log`(6.6MB)、`serialD.log`、`qemu-*.log`、`kbuild-out.txt`、`ktest-out.txt`、`push*.txt`、`gitstatus.txt`、`build-windows.bat`、`qscreen*.ppm/png`、`varix.iso`、`app-*.html`。
- `README.md` 高达 211 KB——不像正常 README，疑似生成内容堆积，值得重写。
- `src/i18n/dictionaries.ts` 278 KB 单文件，功能上合理但偏大。

### .git 健康度 ⚠️
`git count-objects` 报 4 个孤儿 `.idx`（对应 `.pack` 已丢失）——正是 2026-09-11 那次 `pull --rebase` 事故的残留。对象库目前可用（size-pack 93 MiB），但建议在远端确认无缺漏后做一次 `git gc` 清掉孤儿索引。

## 二、整体质量评价

**优点（少见地好）**
1. **测试密度极高**：内核 246 个 `.rs` 文件、**2114 个单测**，且每域有 `run_*_checks` 自检闭环 + fuzz。
2. **工程纪律成体系**：CI 三路（frontend/backend/kernel）、逐批验收清单（`docs/acceptance/`）、诚实标注“待真机实测”而非臆造、CHANGELOG 规范、性能预算（bench P95）。
3. **.gitignore 覆盖面已经不错**：构建产物、ISO、QEMU 截图/日志、Limine 工具链都在里面；工作区仅 1 个未跟踪未忽略文件（是 .workbuddy 记忆文件），说明纪律被执行着。
4. **多 AI 并行协作有明确的边界规则**（一域一文件、共享文件重读、提交路径筛选），文档里沉淀了真实踩坑教训。

**问题**
1. **构建缓存失控**：三处 target 合计 35+ GB，`src-tauri` 增量编译产物从未清理过。
2. **调试截图入库**：tools/ 下 ~15 MB PNG 在 git 历史里，拖慢 clone。
3. **根目录杂乱**：日志、push 记录、临时脚本、多个 `app-*.html` 混在根目录，缺一个“只留入口”的整理。
4. **CI 实际没在跑**（GitHub 账号层面 0 job），质量门禁目前只靠本地 `cargo ktest/kbuild`。
5. **真机验收欠账**：大量批次 DoD 停留在“代码级完成、待真机”。

**总评：代码与流程质量 8/10，仓库卫生 5/10。** 核心资产（源码、测试、文档）是健康的，脏的是外围。
