# TRINITY-500 实施总步骤图（完整版 · 三位一体）

> **TRINITY-500**：把 Variable 装进 Varix 内核，让 Windows / Variable / Varix 三系统在同一 U 盘上**独立运行、系统级隔离、共享一座桥**的完整实施计划。
> 本文回答「**现在到哪了、接下来怎么走、每步怎么自检与验收**」。功能清单见姊妹篇《TRINITY-500-功能全景图》，分工见《TRINITY-500-AI分工完成图》。
> 状态：⬜ 未开始 / 🔶 半做 / ✅ 完成

---

## 〇、现状盘点（2026-09-11 实测，非照抄文档）

> 以下结论来自对 `kernel/`、`src-tauri/` 代码的**实测核查**，作为本计划的地基。

| # | 依赖能力 | 实测状态 | 证据 | 对 TRINITY 的影响 |
|---|---|---|---|---|
| 1 | Varix 内核自举 | ✅ 已做 | UEFI/Limine、GDT/TSS/IDT/APIC、分页/PMM/堆、调度、ACPI/SMBIOS、KASLR、完整性校验（VARIX-500 F001~F250 主体） | 地基就绪，可直接在其上施工 |
| 2 | 真实硬件 I/O 原语 | ✅ 已做 | `apic.rs` 真实 `inb/outb` + MMIO volatile；`msr.rs` 真实 `rdmsr/wrmsr` | 中断/寄存器编程能力具备 |
| 3 | ELF 加载器 | ✅ 已做 | `elf.rs` 真解析 PT_LOAD、权限位、entry 用户半区校验 | 四空间可移植的前提具备 |
| 4 | 休眠骨架 | 🔶 半做 | `power.rs` FADT 解析、S3/S4 休眠头、唤醒向量、CRC32、can_hibernate | 缺 BootNext 编排 + 加密 + 实测 |
| 5 | 存储命令层 | 🔶 半做 | `storage.rs` AHCI FIS 往返、NVMe 提交命令编码、队列 phase 翻转 | 缺 HBA/门铃 MMIO 寄存器编程（属 VARIX-500 收口） |
| 6 | 输入协议层 | 🔶 半做 | `input.rs` 扫描码表、xHCI ring、HID 描述符 | 缺端口 0x60/0x64 与 xHCI MMIO 真实 I/O（属 VARIX-500 收口） |
| 7 | Variable 语义移植 | 🔶 半做 | `vsem.rs` F401~F425 全套语义（纯逻辑，零渲染） | 语义已齐，缺渲染后端 |
| 8 | syscall ABI | 🔶 半做 | `syscall.rs` 号表/参数/错误码；`msr.rs` LStar 地址 + EFER_SCE 常量 | 缺硬件入口接线（syscall/sysret） |
| 9 | 图形基础 | 🔶 半做 | `fb.rs` + `font.rs` 背景/Logo/8×8 点阵字 | 缺 2D 合成器/矢量字体/UI 组件 |
| 10 | 渲染/合成器 | ⬜ 未做 | 内核无 webview/chromium/html/dom，无矢量合成 | TRINITY 最大新增量 |
| 11 | 共享卷文件系统 | ⬜ 未做 | 无 FAT32/exFAT | TRINITY 核心新增量 |
| 12 | 双形态一致性 | ⬜ 未做 | 无跨形态对齐协议 | TRINITY 核心新增量 |
| 13 | 真机验证 | ⬜ 未做 | 宿主单测绿 ≠ 真机行为 | 收官必须 |

**结论**：内核「大脑」（CPU/中断/内存/MSR/ELF/设备命令层）是真的；「手脚」（寄存器接线 + 渲染 + 文件系统）和「切换编排」是缺口。**本计划就是把这些缺口填成「艺术品级」的闭环。**

## 三、全局自检体系（CheckSet 闭环）

> 这是「自检查」的落地机制：**每域自检 → 波次自检 → 域收口 → 全系统闭环**，全部走 CheckSet 登记（PASS/FAIL 逐项），不写空报告。

```
┌──────────────────────────────────────────────────────────────┐
│ 全系统终检 F500（AI-20）                                        │
│   ├─ 真机验证矩阵 F475（AI-19）                                 │
│   ├─ 安全域总闭环 F450（AI-18）                                 │
│   ├─ 一致性域收口 F425（AI-17）                                 │
│   ├─ 四空间收口 F325/F350/F375/F400（AI-13~16）                 │
│   ├─ syscall/桌面/VWM 收口 F300/F250/F225（AI-12/10/9）         │
│   ├─ 渲染栈收口 F125/F150/F175/F200（AI-05~08）                 │
│   └─ 切换/电源/文件系统/数据协议收口 F025/F050/F075/F100（AI-01~04）│
└──────────────────────────────────────────────────────────────┘
```

**自检铁律**：每一项功能完成时，必须同时交付**可复现的自检**（host 单测 / QEMU 回归 / 真机点验步骤），不接受「口头完成」。

## 四、风险登记（边界如实）

| 风险 | 等级 | 缓解 | 残留 |
|---|---|---|---|
| 共享即反隔离（共享卷是桥） | 结构 | 共享卷最小权限 + 审计 + 金丝雀 | 共享区数据三系统可见 |
| ABI 墙（.exe 不进 Varix） | 结构 | 可执行程序各系统一份，共享数据 | 软件不能「一份通用」 |
| 休眠切换非瞬间（10~60s） | 结构 | 预算仪表 + 状态机如实显示 | 无法秒级 |
| 休眠文件残留被交叉读 | 高 | 加密休眠文件 + 不放入共享卷 | 密钥若泄露则失效 |
| 内核自身正确性未验证 | 高 | 真机验证矩阵 + 模糊测试 + 闭环自检 | 隔离靠代码正确性 |
| 固件/物理层不可防御 | 中 | 引导链完整性校验 + 边界文档 | 不可根治 |
| 渲染栈从零起（最大新增量） | 中 | 分波递进（渲染→组件→桌面→应用） | 工期最长 |
| 文档漂移（本仓历史顽疾） | 中 | 文档漂移门禁（数字自动生成） | 需持续纪律 |
