## 本轮发现并修复的两个缺陷

### 缺陷 1：多窗应用误判 orphaned → readopt 重复收编（`embed.rs`）

- **现象**：同进程树关闭一扇窗 → 监护循环判 orphaned（树内仍有活进程）→ spawn_readopt_watcher 把**已被兄弟会话收编的窗口**再次收编 → 桌面多出孤儿占位卡（实机复现：hwnd 725630 被双重 adopt）。
- **修复（两道闸）**：
  1. orphaned 判定加同树甄别：hwnd 消失但同 pid 树仍有登记中的存活嵌入窗 → 按正常退出处理，不派 readopt（日志「多窗应用，不派 readopt」）；
  2. readopt 广播前查登记表：目标 hwnd 已被收编 → 跳过重收（防重复收编兜底）。
- **验证（两次实机）**：关双记事本之一 → applog 出现同树甄别日志 + state=exited + 桌面无占位卡 + 幸存窗 rect 不变（r2_after_close_second.png）；瞬时 XAML 窗（1s 自灭）被误收 1 次也被同树甄别兜住，无占位卡残留。

### 缺陷 2：vwm-layer 内浮层鼠标点击穿透（`vwm.css`）

- **现象**：最小化抽屉（Ctrl+Alt+`）能显示、条目也在，但鼠标点击无反应；键盘 Enter 正常。
- **根因（CDP 取证定位）**：`.vwm-layer{pointer-events:none}`（空白处透传桌面图标的设计）下，三个 fixed 浮层 `.wf-drawer-root` / `.wf-switcher-overlay` / `.vwm-sysmenu` 未恢复 `auto` → `elementFromPoint` 命中的是桌面图标层（DIV.desktop-icons），onClick 永不触发；keydown 不走 hit-test，所以键盘正常。
- **修复**：三个浮层各补 `pointer-events:auto`。
- **验证**：重建后抽屉条目鼠标点击恢复实测生效（r5_mouse_restore_final.png）。

### 过程教训（非代码缺陷）：release 构建两步铁律

只跑 `cargo build --release` 不会重打前端——dist 仍是旧产物，复测必失败。前端改动后必须两步：`npm run build` → `cargo build --release --features tauri/custom-protocol`（本轮第一次重建后复测仍失败的根因）。

## 取证方法备忘

- **坐标系**：pyautogui / mouse_event / GetWindowRect 同为物理像素（1920×1080）；Read 渲染截图按宽 1080px 显示，量得坐标 ×1.778 换算。
- **Win11 XAML 记事本**：保存对话框是 XAML ContentDialog 无独立 HWND（不在 EnumWindows、非 #32770），只能按物理坐标点击按钮；KEYEVENTF_UNICODE 注入无效，VK 码路径（pyautogui.typewrite）有效。
- **CDP 调试**：`WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS="--remote-debugging-port=9333"` 启动 → `curl /json` 拿 page id → websocket-client（`suppress_origin=True` 绕 403）→ Runtime.evaluate `elementFromPoint` / getComputedStyle 直接定位命中元素，避免盲修。
