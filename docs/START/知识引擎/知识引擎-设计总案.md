# 第一章 总纲：我们要造的是什么

## 1.1 一句话

**造一个可以住进去的知识世界。**

它不是笔记软件，不是维基百科，不是思维导图工具，也不是一个 3D 演示程序。它是一个把你所理解的——理解本身、物理、数学、哲学、以及它们之间所有交叉的地带——变成一个可以探索、可以居住、可以在里面找到属于自己的语言的地方。

它有三个身体：

1. **独立的 Windows 大型软件**——一个双击即开的 `.exe`，不需要浏览器、不需要安装环境、不依附于任何其他产品。它有自己的图标、自己的窗口、自己的世界。
2. **Variable 系统里的一个原生应用**——和 code、write、mind 平级，有独立图标和独立窗口，与整个桌面共生，数据实时共享。
3. **内核（VARIX）里的一个内建模块**——当整个系统以 U 盘整机形态启动时，知识体系天然随身携带，最核心的结构与检索能力在裸机上也存在。

三个身体共享同一个灵魂：**一份开放格式的知识库，一套纯 Rust 的核心引擎，以及同一种产品哲学。**

## 1.2 为什么是这个工程

这个工程本身就具备独一无二的条件：

- 内核（K 线）是真内核——Limine 引导、内存管理、调度器、文件系统、NVMe 真盘、syscall 表、合成器与窗口系统俱全。知识引擎不是"模拟一个操作系统里的应用"，而是真的能住进一个操作系统的深处。
- Variable 系统（V 线）是完整的桌面生态——Tauri 2 + React 的窗口体系、应用分发机制、存储容器层、嵌入外部程序的子系统，都已经是成熟的现实。
- 分析器（C 线）有 semantic、ir、learn 这些语义模块——知识引擎未来做"潜在关联发现"时，有一个现成的语义分析后端可以握手。

更重要的是这个工程的名字：**Un-Real Engine**。它从一开始就在问一个问题——真实与虚构的边界在哪里，体验的本质是什么。一个"可以住进去的知识世界"，恰恰是这个问题的最好回答之一：知识是真实的，而居住它的方式可以是不真实的、艺术化的、属于你自己的。

## 1.3 挑战性：这个软件为什么难

把它造出来要同时跨过五座山：

1. **体量之山**：设计目标要能容纳 100 亿条知识（10TB 级）甚至更多。这要求从第一行代码起就是外存架构、128 位 ID、邻域有限算法——任何"先做成内存版以后再扩展"的想法在这个项目里都是死路。
2. **帧率之山**：稳定 80 帧，不是平均 80 帧，是稳定。每帧 12.5ms 的预算，渲染量必须与数据总量彻底解耦。
3. **多端之山**：同一份核心要在 Windows 用户态（完整 GPU 渲染）、Tauri 宿主（嵌入桌面生态）、no_std 内核（无堆、无文件系统的裸机环境）三种截然不同的环境里编译、运行、保持行为一致。
4. **哲学之山**：这个软件的灵魂不是技术，是一种克制——不评价、不催促、不定义用户。技术上每一个" helpful "的默认行为，都可能是压在用户语言上的一只手。把"无压力"做成结构性保证而非宣传语，比任何算法都难。
5. **质感之山**：工业级光影、沉浸式 3D 地貌、2D 探索图、视觉与动效的一致性——艺术表现力的上限决定了这个软件是"工具"还是"世界"。

这五座山，就是这个项目的挑战性所在。本总案的每一章，都是在给其中至少一座山打锚点。

## 1.4 什么不是它

划清边界和说明它是什么同样重要：

- **它不是 AI 产品**。没有强制联网，没有云端推理依赖，没有任何"由大模型替你理解"的环节。理解必须发生在你自己的脑子里，软件只负责让这件事发生得更愉快。AI 可以是未来的一个插件，但绝不是地基。
- **它不是社交产品**。没有点赞，没有排行，没有"别人也在学这个"。它是你能找到的离人群最远、离自己最近的地方。
- **它不是效率产品**。没有进度、没有打卡、没有复习提醒。如果你在用它的时候感觉到了 KPI 的气味，那是 bug。
- **它不是内容平台**。预置的知识种子只是示范"可以这样做"，不是权威。它不拥有任何知识，它只拥有一个让知识生长的地方。

## 1.5 成功的度量衡

最后，定义这个软件的成功。不是下载量，不是日活，不是留存。

成功的度量衡只有一句话：

> **这里有多少东西，被你用自己的话重新说过了一遍。**

当有一天你打开自己的知识库，发现里面一半以上的节点都用你自己的语言命名、用你自己的比喻解释、由你亲手织进只属于你的关联网络——这个软件就成功了。哪怕全世界没有第二个人用它。

带着这个度量衡，进入后面所有的技术细节。

# 第二章 产品哲学：无压力、自己的语言、最小定义的无限

## 2.1 压力的解剖学

要在软件里做到"无压力"，先要精确理解压力从哪里来。人在知识面前的压力，来源可以精确枚举为五种：

1. **评价压力**——"你写的不对""定义不准确""这个词用错了"。任何形式的判定，哪怕是最温和的红线提醒。
2. **产出压力**——"要保存""要命名""要归档""要选分类"。仪式感是压力最隐蔽的形态。
3. **进度压力**——"你已掌握 63%""还有 12 条未读""连续学习 7 天"。一切把探索变成任务的东西。
4. **比较压力**——"别人怎么理解这个词""热门笔记是这样写的"。他者的目光。
5. **完备压力**——"这个概念还有三个方面你没记""定义不完整"。追求结构完美的强迫。

这五条，就是本软件的**负面清单**。设计评审时，任何功能先过一遍这五条，沾边的直接毙掉，无论它看起来多有"价值"。

## 2.2 结构性无压力：五条铁律

压力不是靠"界面友好"消解的，是靠数据模型和交互结构消解的。五条铁律，每条都直接落到架构上：

**铁律一：私人语言是主语言，不是批注。**
每个知识节点都有双层文本：官方层（seed definition）与我的层（my language）。我的层在前、字号更大、颜色更亮，是节点的**第一公民**；官方层折叠在次要位置，像词典里的小字注脚。图谱节点悬停、搜索命中、漫游卡片的标题，全部优先显示我的层。视觉层级就是态度层级。

**铁律二：系统永远不评价，只回应。**
你写"熵 = 混乱的账本"，系统的回应不是纠错，而是**织入**——在未来的某次漫游里，把"熵"与"复利""信息论""时间之箭"轻轻连起来给你看。你的隐喻越用越连贯，但全程没有一次打分。实现上：引擎里不存在"正确性"字段，只有"关联度"字段。

**铁律三：没有完成态。**
数据模型里不存在 learned / mastered / done 字段。探索地图上没有"未学习区域"的灰色待办，只有"你去过的地方"在发光。去过一次和去过一百次，在地图上的区别只是光晕的温度，不是勾选框。

**铁律四：记录零仪式。**
在图谱任意位置**双击空白处 = 种下一颗念头**。一个词、半句话都可以，没有文件名、没有分类、没有保存按钮——落笔即保存。念头落在哪个知识区附近，就自动与那片区域建立微弱连接，你可以永远不整理它。存储层的追加式日志就是为这条铁律服务的。

**铁律五：永远属于你。**
开放格式、本地优先、一键导出、无账号、无云强制。人只有确定"这永远是我的、不会被夺走"时，才敢在知识面前裸露自己。信任不是宣传语，是架构决定的事实。

## 2.3 "属于自己的语言"到底是什么

这个软件一切设计围绕的核心概念，值得单独说透。

属于自己的语言，不是"自定义标签"，不是"个性昵称"。它是**你理解世界时自然生成的私人隐喻系统**。一个用户可能会：

- 把熵叫"混乱的账本"，因为在他的理解里，熵就是一笔永远只会越记越乱的账；
- 把极限叫"永远的逼近"，因为他对极限的感受是那种永远在靠近却从不抵达的状态；
- 把递归叫"镜子的镜子"；
- 把自由叫"带着重量的选择"。

这些语言在教科书里是"不严谨"的。但正是这些不严谨的私人隐喻，才是理解的真正载体——认知科学早已证明，人类理解新概念的唯一方式，就是把它锚定在已有经验的隐喻上。**教科书语言是理解的终点，私人隐喻才是理解的起点。**

这个软件做的事情，就是给"起点"正名：让私人隐喻成为知识库的第一层，让官方定义退居为参考，让两者的每一次并置都成为一次"从我的语言出发走向正式语言"的旅程——而不是相反。

## 2.4 最小定义的无限：为什么不"定义一切"

上一轮讨论中确立的原则，这里是它的完整表述。

"没有任何定义和限制"的系统造不出来——连白纸都有边界。真正的自由来自**极少的定义 × 极深的可组合**。围棋的规则一句话说完，却是人类已知最自由的棋。Minecraft 只有一种方块机制，玩家建出了计算机。乐高只有一种咬合方式，所以任何两块积木永远能拼在一起。

因此这个软件的数据模型被压缩到极限：

- 世界上只有一种东西：**节点**。知识条目是节点，你的念头是节点，学科是节点，私人隐喻是节点，将来的视图、面板、插件，统统是节点。
- 节点之间只有一种关系：**连接**。连接有强度、有方向可选、有私人备注，但类型系统被刻意保持单薄——不预置"包含""引用""因果"这些死类型，类型只是连接上的一个可编辑标签，而标签本身也是节点。

不预置"物理卷""哲学分类"这些死结构。学科只是第一批种子节点，和你的念头在结构上完全平等——你可以改名、删除、拆散、重组它们，包括"物理"这两个字本身。

一切默认值都是种子，不是规则。**我们不造一座所有房间都装修好的宫殿，我们造一小袋种子和一把万能钥匙。**种子的基因要足够好，长出来的东西才有艺术感；定义要足够少，长出来的东西才无限。

## 2.5 哲学的可测试性

把哲学写成可执行断言，是这个总案的一个特点。以下断言进入自动化测试，任何 PR 违反即门禁失败：

1. 新建节点后，`definition` 字段为空是合法状态，不触发任何警告路径；
2. 引擎 API 层面不存在任何名为 `validate` / `correct` / `score` 的公开函数；
3. 渲染层的探索地图不实现任何"未访问区域"的可视化（visited 有，unvisited 无）；
4. 保存路径上不存在任何模态对话框（保存是隐式的）；
5. 私有语言字段的导出与主数据在同一文件、同一权限，不存在"备份不包含我的语言"的实现可能。

哲学不是墙上的字，是 CI 里的红线。这是"整体质量极为成熟"的第一层含义。

# 第三章 体验形态：四种打开方式与一次完整的人生使用旅程

## 3.1 为什么是"四种打开方式"

同一个知识库，必须以不同的形态去享受。不是四个功能模块，而是**同一个世界的四种天气**。数据是同一份，连接是同一张网，切换是无缝的。四种方式分别对应人与知识之间的四种关系：查阅、看见、偶遇、对话。

## 3.2 阅读态：像书一样

最古老、也最不会过时的形态。按学科卷册浏览——物理一卷、数学一卷、哲学一卷，交叉领域自成一卷（数学哲学、物理主义、信息哲学作为一等公民存在，而非事后修补的"跨学科专栏"）。

但阅读态有三处刻意的反传统设计：

1. **没有"目录正确性"**。卷册的章节结构由用户随意拖拽重组，系统不认为存在"正确的目录"。教科书目录只是一个可一键套用的种子。
2. **正文中双击任何概念，就地展开为一个"概念浮岛"**——不是跳转链接那种生硬的跳页，而是当前页面上方浮现一张卡片，上面是这个概念的私人语言（你的）与官方定义（折叠），以及它在你图谱里的三度邻域微缩图。读完即合，阅读动线不断。
3. **每卷有"雾页"**——故意留出的空白章节，标注不是"待写"，而是"这里允许什么都不写"。空是合法状态。

## 3.3 图谱态：看见知识的地貌

这是 2D 探索图的主场。一张可无限缩放的力导向大图：学科是大陆，概念是城市，你的念头是散落的灯火，交叉地带是大陆之间互相渗透的海岸线。

交互的核心原则是**触地即生**：

- 悬停节点：浮出私人语言优先的概念浮岛；
- 拖拽节点：布局实时重算（GPU compute），松手时如水面般回弹归位；
- 框选一组节点：浮出"这一束"面板——它们共同的邻居、共同的标签、它们之间的最短路径被高亮成一条金线；
- 双击空白：种下念头，灯火落进图里，自动与最近的知识区发生微弱连接。

缩放是平滑连续的，从"看清一个字的层级"到"俯瞰全部学科大陆"之间没有断层。10 万可见节点在同一画面里 instancing 渲染，远处的聚合成星云光斑。

## 3.4 漫游态：纯粹地逛

这个软件的灵魂形态，也是"不带压力"的终极体现。

打开漫游态，什么都不用填。地图缓缓漂移，从你上次停留的地方，向着邻接的知识区飘去。看到有意思的就停下看两眼，没意思就继续漂。没有搜索框弹出，没有"记录本次探索"，没有"本次漫游你经过了 17 个知识点"的总结页。像散步，不是赶路。

漫游算法的设计原则值得单独记录：

1. **永不全随机**。完全随机是噪音，不是漫游。漫游走的是图谱上的邻接步进，每一步从当前节点的邻居中挑选，挑选权重 = 关联强度 × 新鲜度（久未访问的加成）× 意外度（跨学科连接加成最高——物理跳到哲学的那条边，权重最高）。
2. **漂移有惯性**。下一步的候选里有 20% 概率延续当前方向，模拟散步时"顺着这条路再走走看"的直觉。
3. **可以只是看**。漫游卡片不需要任何交互就会自行飘走，停留时长完全由你决定。系统对"你看了多久"没有任何推断和记录——看了就是看了，走了就是走了。
4. **漫游态没有入口按钮**，它是启动页的一个气氛选项，也是屏保——闲时软件自己进入漫游态，像一幅会呼吸的画。

漫游态存在的意义：它是这个软件里唯一"什么都不要求你"的模式。很多人与知识的破裂关系，就是从"每次打开都要产出"开始的。漫游态是回到关系本身的地方。

## 3.5 书写态：对话的地方

私人语言诞生的地方。一个无压的书写面：

- 不强制格式。想到什么写什么，写到一半关掉也天然保存（自动持久化到追加日志）。
- **书写时的"织入"提示**：当你写下一个与已有节点高度相关的句子时，该节点的灯火会在页面边缘轻轻亮起——不弹窗、不打断、不自动链接，只是亮着。你可以在任何时候把这句话与它正式连接，也可以永远不理会。
- 书写的每一段可以"升格"为正式节点（一键），升格是可逆的，降格回段落也是一键。

书写态与漫游态共享一个设计底线：**它们都不产生任何"待办"**。写下的东西不会变成"以后要整理"的负担。

## 3.6 一次完整的使用旅程（叙事性验收标准）

用一段用户故事来验收全部设计——这是比任何功能清单都严格的验收标准：

> 周日下午，她打开了那个图标是一颗微光种子的软件。
>
> 启动画面只停留了两秒——一颗种子在暗处发芽的粒子动画，然后直接落进她上次停留的地方：图谱态，一张她养了两年的知识地貌。物理的大陆已经延伸出一片新的半岛——那是她最近在读的量子信息。
>
> 她今天不想读什么。她点了漫游。
>
> 地图带着她从"退相干"出发，沿一条她从未走过的边，飘向了信息论的方向。途中经过她自己三个月前种的一颗念头——"测量是不是就是宇宙在打草稿"。灯火还亮着。她停了一下，笑了笑，继续飘。
>
> 飘到"香农熵"时，浮岛亮起。她注意到香农熵和热力学熵的连接边是金色的——那是她某天亲手标亮的"意外发现"。她盯着看了一会儿，双击旁边的空白，种下一句："信息也是物理的，就像重量也是物理的。"
>
> 念头落进图里，微弱地连向了两个她都没想到会连在一起的区域。
>
> 她关掉了软件。没有保存按钮被按过。没有进度条动过。没有任务生成。

> 但她知道，那句"宇宙在打草稿"，有一天会自己长成一片新的半岛。

# 第四章 总体架构：一个核心、三副外壳、一份开放数据

```
│  ┌───────────┐ ┌──────────────────────────────────────┐ │
│  │ 存储抽象   │ │ trait Storage（内存/SSD/内核盘 可换） │ │
│  └───────────┘ └──────────────────────────────────────┘ │

        │                    │                     │
   ┌────┴─────┐       ┌──────┴──────┐       ┌──────┴─────┐

   │ 独立 .exe │       │ Variable 应用│       │ 内核模块     │
   │ egui+wgpu │       │ React + IPC │       │ no_std 只读 │
   │ 全功能     │       │ 画布+原生核  │       │ 结构+检索    │
   └──────────┘       └─────────────┘       └────────────┘
        （另：外壳 D = Unreal 重型沉浸宿主，见第十章）
```

## 4.2 分层纪律：三条边界

架构的成熟度体现在边界的刚性上。三条边界，任何一层不得越界：

1. **core 不渲染、不做 IO、不认识 Windows**。knowledge-core 是纯计算与纯数据结构：节点模型、格式读写、图算法、漫游策略。它通过 `trait Storage` 和 `trait Clock`（用于新鲜度计算）依赖注入环境。no_std 编译目标下，这些 trait 由内核环境实现。
2. **渲染引擎不认识业务**。渲染引擎（第七章）只接受"渲染图"（render graph）：节点位置、半径、颜色、LOD 层级、文字纹理句柄。它不知道"熵"是什么。业务到渲染的唯一通道是每帧构建的渲染图。
3. **外壳是薄壳**。外壳 A/B/C 只做三件事：装配（把 core 接到存储和渲染上）、输入（把用户操作翻译成 core 调用）、呈现（把 core 状态翻译成渲染图）。外壳里不允许出现任何图算法或格式逻辑。

这三条边界的直接收益：任何一层可以单独替换。哪天 egui 换掉，core 分毫不差；哪天出了新的存储介质，只换一个 trait 实现；哪天内核移植到新架构，外壳 C 重写而 core 原样编译。

## 4.3 语言选型决策记录

三个硬性要求：独立 Windows .exe、实时接入 Variable（Tauri 2）、可编译进 no_std 内核。逐语言筛选：

| 方案 | 独立 .exe | 接入 Variable | 进内核 | 沉浸感上限 | 判定 |
|---|---|---|---|---|---|
| Rust + wgpu/egui | ✅ 单文件原生 | ✅ 同语言直接挂 | ✅ no_std | 极高（自写 shader） | 唯一三端通吃 |
| C++ + Qt | ✅ | ⚠️ C ABI 桥 | ⚠️ 内核是 Rust，混语言 | 极高 | 维护两套语言/构建/测试 |
| C# / Unity | ⚠️ 带运行时 | ❌ | ❌ 无 no_std | 高 | 内核无门 |
| JS/TS + Electron | ⚠️ 200MB+ | ✅ | ❌ 不可能 | 中 | 壳快，天花板低 |
| Python | ⚠️ | ❌ | ❌ | 低 | 原型语言 |
| Zig / Go | ✅ | ⚠️ | ⚠️ Zig 可但生态薄 | 要自建一切 | 无优于 Rust 的理由 |

结论：**全 Rust。核心 no_std，渲染 wgpu/egui，Variable 内展示层用现有 React 包 wgpu 画布**——各语言只待在它本来就赢的位置（React 做 UI 布局与桌面集成，Rust 做核心与渲染）。C++ 仅在 Unreal 外壳（第十章）中以插件形式出现。

## 4.5 外壳 A：独立软件的形态

- 单文件 `.exe`，目标体积 15~30MB（wgpu + egui + 核心），无运行时依赖；
- 图标：一颗微光种子（呼应启动动画与产品隐喻）；
- 启动即入图（上次位置），两秒内可交互（冷启动预算，见第十四章）；
- 完整四形态（阅读/图谱/漫游/书写）+ 完整渲染（3D 地貌、光影、后期）；
- 数据目录：默认 `可执行文件旁 /data`，可指定任意路径——**绿色软件语义**，拷走目录即拷走整个知识世界。

## 4.6 外壳 B：Variable 中的形态

在 Variable 桌面注册独立应用（独立图标、独立窗口 label，经 `App.tsx` 分发、`VwmAppContent.tsx` 挂载）。窗口内容 = React 面板（与其他应用一致的桌面观感）+ wgpu 画布（图谱渲染）。核心逻辑全部在 Rust 侧：Tauri command 层直接 `use knowledge-core`，前端零算法。

**"实时"的技术含义**：外壳 A 与外壳 B 读写同一份知识库文件。文件锁用协作式（写入通知 + 自动重载），A 里种下的念头，切到 B 的窗口即见。两壳并存时以"最后写入者胜 + 变更事件广播"保证一致（单机单用户场景下足够工业级）。

## 4.7 外壳 C：内核中的形态

按现有 `apps/mod.rs` 内建应用模式注册。no_std 形态裁剪为：节点结构 + 邻域检索 + 关键字索引。存储走内核文件系统（fs23/NVMe 真盘）。无渲染（内核合成器如需展示，用现有 vwm 的简单文字窗口呈现检索结果）。角色是"保底形态"：U 盘整机即携带完整知识体系，哪怕桌面外壳不在，结构与检索依然可用。

# 第五章 数据模型：从一颗节点到一百亿条知识

## 5.1 一切从两个原语开始

```
Node {
  id:        u128          // 128 位，见 5.3
  my_title:  Option<Text>  // 我的语言（第一公民）
  my_body:   Option<Text>  // 我的理解
  def_title: Option<Text>  // 官方层（种子，可空可改可删）
  def_body:  Option<Text>
  created:   u64           // 时戳（Clock 注入）
  head:      NodeHead      // 常驻索引的轻头（见 6.2）
}

Edge {
  from:    u128
  to:      u128
  weight:  u8              // 0..255 关联强度
  mark:    Option<EdgeMark> // 金线：用户亲手标亮的"意外发现"
  note:    Option<Text>    // 连接上的私人备注
  bidir:   bool
}
```

类型即节点：没有硬编码的"学科""标签"表。一个节点可以通过"标签连接"挂在另一个作为标签的节点上——"物理"就是这样一个普通节点，可改名可删除。连接的语义标记（包含/引用/因果……）同样是普通节点，挂在边上做注解。**模型层零枚举，一切语义皆数据**——这是"最小定义的无限"在数据层的落点。

## 5.2 文本的双层与成长

`my_*` 与 `def_*` 都是可选的、都允许单独存在。一个只有 `my_title` 的节点是完全合法的节点（一颗念头）；一个只有 `def_*` 的节点是种子；两者都有的节点是"成长的节点"。

**升格路径**：段落 → 念头 → 节点，全部可逆。书写态的一段文字升格为节点时，原文位置留下一个轻量引用节点——文本不会因为"整理"而搬家，历史连线永远有效。

## 5.3 为什么是 128 位 ID

100 亿（10^10）只是起步目标。128 位空间 3.4×10^38，配合随机生成（取自硬件熵源），碰撞概率在宇宙尺度下可忽略。更重要的是：**ID 一旦发布永不改变、永不复用**——删除的节点 ID 进入墓碑集，永远不允许新节点占用。这是"你的语言永远属于你"在数据层的又一条保障：哪怕将来做同步与合并，ID 稳定意味着历史永不破碎。

u128 在 no_std 内核与 x86_64 上都是原生友好的（两个 u64）。

## 5.4 邻域有限：性能与总量解耦的核心原则

100 亿节点上任何"全局算法"都是灾难。本模型的对策是把一切算法约束为**邻域有限**：

- 节点的直接连接数上限 512（软上限：超出时引擎建议"束"——把一组概念聚合成一个束节点，束内部连接仍在，对外只呈现一个入口）；
- 漫游、推荐、补全、浮岛的三度邻域图——全部只触及常数规模的邻接；
- 全局操作（全库搜索、统计）永远走索引而不是走图（见第六章）。

由此得到关键性质：**单次交互的计算量是 O(常数)，与库的总量无关**。100 亿还是 1 万亿，点开一个节点的耗时不变。

## 5.5 墓碑、合并与时间线

- **墓碑集**：删除即墓碑（ID + 时戳），物理回收延迟到存储合并期。所有同步/合并协议据此实现"删了就是删了"且可传播。
- **合并规则**：两个知识库副本合并时，节点按 ID 合并、连接按 (from,to) 合并、文本冲突按"较新者胜 + 旧版本保留为历史节点"——历史节点通过"前驱连接"挂在现役节点上，**任何一次修改都可回溯**。这是"书写的每一段永不丢失"的存储层兑现。
- **时间线视图**：由 created 时戳天然支撑——知识库可以按"生长年轮"回看，这是未来视图插件的第一候选。

## 5.6 格式 v1：磁盘上的样子

开放格式是人类可读优先。单库 = 一个目录：

```
my-mind/
├── manifest.json        # 格式版本、库名、统计、种子语言
├── nodes/               # 追加式段文件（6.4 详述）
│   ├── 000001.kseg
│   └── 000002.kseg
├── index/               # 可随时重建的衍生索引（删了也没事）
└── blobs/               # 大附件（图、音频……未来）
```

- `manifest.json` 里一个 `format_version: 1`，配迁移器矩阵——v2 出现后，v1 文件永远可被新版本打开并自动迁移，旧版本软件打开新文件则给出明确版本提示。**格式兼容性进入测试向量**（knowledge-fmt crate 内置跨版本双向用例）。
- `index/` 目录的每一件产物都可由 `nodes/` 全量重建——索引永远可再生，这是存储层最重要的一条鲁棒性设计：**数据只有一份，其他一切皆缓存**。

# 第六章 存储引擎：外存分层、追加式日志与百亿容量

## 6.1 三个数字开始的设计

- 100 亿节点 × ~1KB 平均体量 ≈ 10TB（终局容量目标）；
- 12.5ms 帧预算（渲染，见第七章）；
- <1ms 温层查询预算（任意 ID 精确读取，SSD 上 B+ 树 4~5 层以内）。

由这三个数字推出本存储引擎的全部形态。

## 6.2 热温冷三层

**热层（内存）**：当前交互的邻域 + 常驻轻头索引。每个节点的 `NodeHead` 只含 id、my_title 哈希、连接计数、热度与新鲜度统计，~64B。1 亿节点的轻头索引 ≈ 6.4GB——放不下的部分驻留在温层索引里，热层只保留工作集（LRU + 邻域预取）。**常驻内存量与用户实际活动的知识区域大小相关，与库总量无关。**

**温层（SSD 索引）**：以 ID 为键的 B+ 树（或等价的 LSM 读路径），存储 NodeHead + 正文在冷层的位置指针。100 亿键 × 64B = 640GB 索引——单盘紧张，按 ID 高位分片成多棵子树（128 位 ID 的最高 8 位 = 256 个 shard，天然均衡）。

**冷层（原始数据）**：追加式段文件（kseg，见 6.4），不可变、顺序写、压缩可选。

**预取**：漫游方向预测（第十四章）驱动后台线程把"即将访问的邻域"从冷层捞进热层。预取命中率是漫游丝滑度的决定性指标（目标 >90%，因为邻域有限 + 惯性步进，方向可预测性天然很高）。

## 6.3 追加式日志：为"零仪式写入"而生

一切写入都是追加：

1. 种念头 = 向当前活跃 kseg 追加一条记录（几百字节顺序写 + fsync 可延迟），微秒级，**这就是"双击即存"的底气**；
2. 修改 = 追加新版本记录 + 旧记录标墓碑指针；
3. 合并（compaction）在后台进行：合并墓碑、压缩重复版本、重写碎片段。合并策略照抄 LSM 系数据库几十年的成熟经验（leveled compaction，冷热分层合并频率）。

崩溃安全：每条记录带 CRC32 + 序号；kseg 尾部半条记录在打开时被安全截断；合并过程中断则回退到合并前段集——**任意时刻断电，库都不坏**（本工程内核的 fs23 日志化经验直接复用其设计纪律）。

## 6.4 kseg 段文件格式（骨架）

```
[kseg header]  magic "KNOWSEGV1" / 段号 / 创建时戳 / 记录数
[record]*      len(u32) / crc32 / type(u8: Node|Edge|Tomb|Meta) / body(版本化编码)
[footer]       索引稀疏检查点（每 1024 条一个 offset 样本，加速打开）
```

body 编码：手写二进制（varint + 字符串长度前缀），**不引入 protobuf 等外部依赖**——no_std 内核外壳必须能零依赖解码。同时提供 JSON 双向导出（人类可读、可 diff、可被任何外部程序生成/消费），导出导入纳入 knowledge-fmt 测试向量：**二进制 ↔ JSON 往返字节级一致**。

## 6.5 内核形态的存储

外壳 C 在 no_std 下复用同一格式解码器（零依赖设计在此兑现价值），Storage trait 由内核盘（fs23/NVMe 栈）实现为只读 + 追加两种最小操作。索引在内核里退化为启动时从检查点加载的内存 B+ 树（只读检索场景不需要写路径合并）。容量目标内核端单独定：首批 100 万节点全结构可检索。

## 6.6 容量的诚实边界

10TB 终局容量对单机是成立的（2026 年 24TB SSD 已是消费品），但**单机单库是本设计的边界**而不是分布式全局库。多机协同、跨设备实时同步是未来版本（v2+）的议题，v1 只承诺：格式与 ID 体系为此留好了门（ID 墓碑合并协议天然支持多副本），但不提前实现。**为未来设计，不为未来膨胀。**

# 第七章 渲染引擎：80 帧的哲学与工业级光影

## 7.1 帧预算宪法

80 帧 = 12.5ms/帧。预算分配（目标值，硬件基准为中端集显 + NVMe）：

```
模拟（布局/漫游/预取调度）   ≤ 3.0ms   （GPU compute 为主）
几何与光照                  ≤ 4.5ms
后期链（Bloom/景深/色压）    ≤ 2.5ms
UI（egui）                  ≤ 1.5ms
余量                        ≤ 1.0ms
```

**帧预算哨兵**（budget.rs）：每帧实测各段耗时，滑动窗口统计。任何一段连续超预算 → 自动降级链启动：光影档位 → LOD 密度 → 粒子数量 → 后期半径。降级是静默的、逐级的、可恢复的。**用户永远看到"稳定的 80 帧"，代价被引擎内部悄悄消化。**这是"稳定 80 帧是设计出来的，不是赌出来的"的执行机制。

## 7.2 分层渲染管线

```
┌─ 3D 沉浸层：地貌/星域/雾/体积光/粒子 —— 自定义 shader，艺术主场
├─ 2D 图谱层：节点 instancing + 边批渲染 + 文字纹理图集
├─ 2D UI 层：egui（面板/编辑器/输入），与上两层共享同一 wgpu 设备
└─ 底座：wgpu（DX12/Vulkan/Metal 后端）
```

共享 wgpu 设备是"沉浸感"的技术前提：3D 地貌上可以直接浮 2D UI（悬停"熵"时，浮岛以一致的景深与光照淡入），零缝融合，没有窗口嵌入的接缝感。

## 7.3 LOD：与数据量解耦的渲染

三级细节，缩放连续体上平滑过渡：

- **L0 星云**（极远）：学科大陆聚合为一个光斑 + 名字标签。聚合参数由节点密度场（compute pass 预计算的密度纹理）决定；
- **L1 簇**（中景）：节点为发光点 + 边为半透明曲线，instancing 批渲染，单 draw call 画 10 万级；
- **L2 卡片**（近景）：完整文本排版，文字纹理图集（SDF 字体渲染，任意缩放不糊）。

切换由相机高度（zoom）驱动，LOD 边界用双层交叉淡化（cross-fade）消除突变。**每一帧实际渲染的元素数 ≤ 视锥内的 L2 卡片（千级）+ L1 簇（万级）+ L0 光斑（十级）**——渲染量与 100 亿总量彻底无关。

## 7.4 工业级光影的实现清单

- **PBR 材质**： Cook-Torrance BRDF，金属度/粗糙度工作流；
- **软阴影**：PCSS（百分比渐近软阴影），近景卡片与 3D 地貌投射真实软影；
- **Bloom**：多 mip 高斯链，灯火（念头节点）的微光是它最好的舞台；
- **雾**：高度雾 + 距离雾，哲学的森林在雾里，物理的星空在雾上——雾是"学科地貌"叙事的执行者；
- **体积光**：射线步进（ray-marched）， restrict 到关键镜头（漫游经过时）以保证预算；
- **色调映射**：ACES 近似曲线，整体亮度哲学是"暗夜中的微光"——暗底、微光、克制的高光，这是全软件的情绪基调；
- **动效**：一切位移动效使用弹簧动力学（spring-damper），阻尼系数全局统一——"手感一致"是质感的隐形根基。

以上全部在自研引擎内实现（第十章的 Unreal 外壳则用引擎原生能力达到更高上限）。自研引擎的美术纪律：**少而精**。效果清单每加一项，都要在帧预算表里找到它的位置，找不到就不加。

## 7.5 文字：被低估的质感核心

知识软件的质感一半在排版。SDF 文字渲染 + 分级排版规范（正文/标题/浮岛/标签四级字号阶梯，行距 1.6 基准），暗底上正文用暖白（#E8E4DC 类），永不使用纯白（刺眼）。中文渲染测试字库内置思源系字体的 SDF 预处理管线。**排版规范进入 UI 快照测试**（第十三章）。

# 第八章 UI 与界面设计语言：质感从哪里来

# 第九章 多语言执行模型：让内核接受所有语言的作品

## 9.1 本质与三通道

内核最终只认两样东西：机器码 + 系统调用约定。"接受所有语言"的实现方式是造三个公共通道，任何语言选最合适的一条抵达：

```
①原生通道：编译到 VARIX ABI 的 ELF/PE
   Rust / C / C++ / Zig / Odin / LLVM 系 —— 100% 原生性能
②字节码通道：编译到 WASM
   几十种语言的前端（C#/Go/Python/Swift/Kotlin…）
   AOT 预编译后性能为原生的 80~95%
③脚本通道：内核内置解释器（Lua）
   文本即程序，改完即跑
```

## 9.2 通道①：冻结 ABI（信任基石）

任务 15 已交付 ELF/PE 共用装载原语（SegmentView/UserMapper/页账本），syscall 表带编号与能力位。标准化工作：

1. **syscall 编号表冻结发布**：已发布编号永不改义，只增不改——外部语言编译器后端敢对准它的前提（Linux 30 年不变同此理）；
2. **varix-std 定版为官方运行时库**：Rust `no_std + 自定义 target` 为第一公民路径；C/Zig 走 LLVM 后端产 ELF + 直调 syscall；
3. **能力位即权限**：程序声明所需能力（文件/图形/网络），装载器按位授予——多语言的安全模型统一在能力位上。

## 9.3 通道②：WASM 的两级执行

- **解释级**（wasmi 类纯 Rust 解释器，no_std 可用）：小作品、冷代码；
- **AOT 级**：**离线预编译**——作品安装包发布时即带本机码（类 .NET NGen / Android ART 模型），内核只做加载与签名校验。这样内核不背编译器，性能一分不少，是"所有语言 + 高性能"同时成立的务实正解；
- WASM import 面直接映射能力位：程序要什么权限在模块里声明，沙箱边界即能力边界。

## 9.4 大型多语言作品的聚合架构

工业级大作品（IDE 级、3D 编辑器级）的正确形态不是单进程巨石：

- 重计算组件 → 原生 ELF/PE 进程（渲染器/物理/编译器，Rust/C/C++，零损耗）；
- 界面与胶水 → WASM 模块（任意语言）；
- 通信 → IPC + **共享内存段零拷贝**（10 万节点图谱传给渲染进程 = 传一个句柄）。

**每种语言待在它性能最合适的层级，作品整体跑原生速度。**Chrome/VS Code/Figma 皆此架构，瓶颈永远在计算不在通信。

## 9.5 诚实边界

- Java/Kotlin 等重运行时语言：进通道②（AOT）或将来用户态虚拟机，**内核永不内置这些运行时**——内核接受所有语言，但内核本身不背所有语言的运行时，这正是它扛得住大型作品的底气；
- 三通道施工顺序：冻结 ABI → WASM（覆盖面最大）→ 脚本（锦上添花），不同时开工。

# 第十章 Unreal 集成路线：当重型引擎成为外壳

## 10.1 定位：重壳不进内核

Unreal = 数百 MB 的完整运行时（渲染/物理/音频/资产系统），深绑 Windows/DirectX。**它进不了 VARIX 内核**（内核无 DX、无驱动栈——这也是一切自研内核的共同边界）。但它可以成为三副外壳之外的**第四副外壳：重型沉浸宿主**。

## 10.2 路线 A：嵌入窗口（地基已备，首选）

本工程已有 GWLP_HWNDPARENT 拥有式嵌入子系统（物理像素同语义防漂、exited 自动关占位窗）。Unreal 应用做成独立窗口程序，嵌进 Variable 桌面——**一个 Unreal 制作的沉浸式知识地貌，就是 Variable 里的一个原生窗口**。改动最小、性能零损耗。

## 10.3 路线 B：Pixel Streaming（解耦方案）

Unreal 后台进程渲染，画面编码成流 + 控制信令，前端任意组合。代价一帧延迟与双倍内存。适合远程/多端场景，作后备路线。

## 10.4 路线 C：知识数据打通（让它"属于这个系统"的关键）

格式是开放的——给 Unreal 写一个 C++ 插件直接读写 kseg/JSON 格式（不需要 Rust）。于是：Unreal 的 3D 世界里种下的念头 → 落进同一份知识库 → 回到独立 .exe、Variable、内核，处处可见。**Unreal 只是又一个外壳，与 egui 外壳平级。**

## 10.5 分工哲学

- Windows/Variable 端的顶级艺术层：Unreal（美术管线、光影、粒子的天花板）；
- 核心知识引擎与内核层：Rust 自研，永不动摇；
- 内核端的 3D：把 Unreal 里验证过的美术效果当参考稿，轻量技术重写低保真版——**Unreal 是艺术的设计场，内核是成果的携带场**。这本身也是对本工程名字（Un-Real）的一次呼应。

# 第十二章 开放性与插件体系：极高的开放，极高的拓展

## 12.1 开放的三个层级

1. **数据全开放**：kseg + JSON 双格式，人类可读，任何编辑器/程序/脚本/AI 可直接读写；无账号、无云强制、无加密墙；导出永远一键且完整（含我的语言与连接）；


# 第十四章 性能工程：帧预算的艺术

## 14.1 冷启动 2 秒

预算分解：进程创建与 wgpu 初始化 ≤600ms / 索引检查点加载（热层工作集）≤500ms / 上次场景重建 ≤400ms / 首帧渲染 ≤300ms / 余量 200ms。手段：kseg footer 稀疏检查点（打开不必扫全库）、热层只载工作集、着色器管线缓存（wgpu pipeline cache 落盘）、首帧只渲染 L0+L1（卡片流式跟上）。

## 14.2 漫游的丝滑：预取命中率工程

漫游方向可预测（惯性步进 + 邻域有限），预取策略：维护 3 层预取环（当前邻域 / 一步候选 / 二步候选），后台线程按预测概率排序加载。命中率的敌人是用户突变操作——对策是预取环的 LRU 弹性与"突变后 100ms 内的降级渲染路径"（L1 先行，L2 追平）。

## 14.3 零拷贝链路

冷层读 → 解码 → 热层驻留 → 渲染图 → GPU 上传，全链路审计拷贝次数：解码直写热层页（缓冲区复用池）、渲染图用 SOA 布局（GPU 友好 + 无中间结构）、GPU 上传用 staging 环。大资产（未来 blobs）走共享内存句柄传递。

## 14.4 内存纪律

热层硬上限（默认 2GB，可配），超限按 (距离当前焦点 × 新鲜度) 逐出。逐出的是缓存不是数据——**数据只有一份在盘上**（5.6 的原则让内存管理永远安全）。内核外壳内存预算单独定（首批 100 万节点全结构 ≤64MB）。

## 14.5 规模验证梯度（诚实承诺）

```
M1：100 万条 · 80 稳帧 · 单机 SSD —— 全架构到位
M2：1 亿条 · 索引 P99 <1ms · 预取 >90%
M3：10 亿条 · shard 化索引 · 多盘
终局：100 亿条 = M3 水平扩展，架构不变
```

架构第一天按终局设计（128 位 ID / 外存 / 邻域有限 / 帧预算哨兵），性能承诺逐级兑现。**跳级许诺是不工业的，架构不做未来迁移才是工业的。**

# 附录 A 知识库开放格式 v1 完整规范

## A.0 规范的地位

本规范是知识库格式的**唯一权威定义**。任何实现（Rust 核心、C++ 插件、第三方程序、脚本工具）与本规范冲突时，以本规范为准。规范的每一次修订必须同步更新 knowledge-fmt crate 的测试向量——**规范、实现、测试三位一体，不可单独漂移**。

## A.1 库目录结构（正式版）

```
<库名>/
├── manifest.json          # 库级元数据（见 A.2）
├── nodes/
│   ├── 00000001.kseg      # 段文件，8 位十进制段号
│   ├── 00000002.kseg
│   └── ...
├── index/                 # 衍生索引，全部可重建
│   ├── shard-00.kidx      # ID 高位分片索引（见 A.6）
│   ├── shard-01.kidx
│   └── ...
├── blobs/                 # 大附件（v1.1 起用）
│   └── <sha256>           # 内容寻址
└── journal/               # 存储引擎自身日志（非用户数据）
```

规则：
- `nodes/` 与 `manifest.json` 是数据的全部真相；
- `index/`、`journal/` 任何时刻可删除重建，不丢数据；
- 库目录可以整体拷贝、压缩、放入版本控制——没有隐藏状态。

## A.2 manifest.json

```json
{
  "format_version": 1,
  "library_name": "我的知识世界",
  "created_at": 1789600000,
  "seed_language": "zh-CN",
  "stats": {
    "node_count_approx": 48213,
    "edge_count_approx": 96207,
    "tombstone_count_approx": 309
  },
  "settings": {
    "wander_temperature": 0.7,
    "hot_layer_limit_mb": 2048
  },
  "extensions": {}
}
```

- `format_version` 整数，递增不跳号；
- `stats` 是近似值（缓存），仅供展示，任何实现不得依赖其精确性；
- `extensions` 是开放扩展位——第三方实现可以在此写入自己的元数据，键名必须带命名空间前缀（如 `com.example.xxx`）。**未知的扩展键必须被忽略而不是报错**（前向兼容铁则）。

## A.3 kseg 段文件字节级定义

所有整数小端序。

```
偏移  大小  字段
0     8    magic = "KNOWSEGV1"（ASCII）
8     4    segment_id (u32)
12    8    created_at (u64, Unix 秒)
20    4    record_count (u32) —— 仅在段关闭时回填有效；活跃段此字段为 0xFFFFFFFF
24    4    header_crc32（覆盖偏移 0..23）
28    ...  records...
尾部  8    footer: 每 1024 条一个 {record_index u32, file_offset u64} 稀疏检查点数组，
           后随 checkpoint_count (u32) 与 footer_crc32 (u32)
```

记录结构：

```
偏移  大小  字段
0     4    body_len (u32)
4     4    crc32（覆盖 body 全部）
8     1    type (u8)
           0x01 = NodeRecord
           0x02 = EdgeRecord
           0x03 = TombstoneRecord
           0x04 = MetaRecord（预留）
9     4    seq (u32) —— 库内全局递增序号，崩溃恢复时用于定序
13    ...  body（varint 与长度前缀字符串构成，见 A.4）
```

- 写入顺序：先写 body_len + crc + type + seq，再写 body。**半条记录（写了一半崩溃）以 body_len 与实际剩余字节数不符判定，打开时安全截断**；
- 活跃段末尾允许 `0x00 padding` 对齐到 16 字节——解码器必须跳过全零尾部。

## A.4 记录 body 编码

字符串编码：`varint 字节长 + UTF-8 字节`。可选字符串：先一个 varint，0 表示 None，1 表示 Some（后跟字符串）。

**NodeRecord body：**
```
id            : 16 字节（u128 小端）
flags         : varint 位标志（bit0 有 my_title, bit1 有 my_body,
                bit2 有 def_title, bit3 有 def_body, bit4..保留）
my_title      : 可选字符串
my_body       : 可选字符串
def_title     : 可选字符串
def_body      : 可选字符串
created_at    : varint（Unix 秒）
head_ext      : 可选（预留扩展 TLV：varint tag + varint len + bytes）
```

**EdgeRecord body：**
```
from_id       : 16 字节
to_id         : 16 字节
weight        : 1 字节（u8, 0..255）
flags         : varint（bit0 bidir, bit1 marked/gold, bit2..保留）
note          : 可选字符串
created_at    : varint
```

**TombstoneRecord body：**
```
target_id     : 16 字节
was_node      : 1 字节（1=节点墓碑, 0=边墓碑）
deleted_at    : varint
```

**版本化原则**：body 的解析以"读尽即合法"为准则——未来 v2 在尾部追加字段时，v1 解码器读到 v1 已知长度即可停（由 flags/TLV 承载），未知 TLV 必须跳过不报错。**解析器永远宽容，写入器永远守规**（Postel 法则的存储版）。

## A.5 JSON 双向导出

导出格式（每个 kseg 对应一个 JSON 数组文件）：

```json
[
  {
    "type": "node",
    "id": "a1b2c3d4e5f60718a1b2c3d4e5f60718",
    "my_title": "混乱的账本",
    "def_title": "熵",
    "created_at": 1789600123,
    "links_hint": 3

```

- u128 以 32 位小写十六进制字符串表示；

# 附录 B knowledge-core 关键算法伪码

## B.1 邻域有限三度图（浮岛微缩图用）

```
fn neighborhood3(seed: NodeId, budget: usize = 96) -> SubGraph:
    frontier = [seed]
    visited = {seed}
    result = empty SubGraph
    depth = 0
    while frontier.not_empty() and depth < 3 and result.size < budget:
        next = []
        for node in frontier:
            edges = index.adjacent(node)          # 常数级（≤512 上限）
            edges.sort_by(weight desc)
            for e in edges.take(16):              # 每节点每层最多展开 16 条
                if e.other not in visited:
                    visited.add(e.other)
                    next.push(e.other)
                    result.add(node, e, e.other)
        frontier = next
        depth += 1
    return result                                  # 最坏 O(budget) = O(96)
```

性质断言（进测试）：任意输入规模下，返回图规模 ≤ budget；执行时间上界恒定。

## B.2 漫游步进

```
fn wander_step(current: NodeId, state: WanderState) -> NodeId:
    neighbors = index.adjacent(current)             # ≤512
    if neighbors.is_empty():
        return index.random_hot_node()              # 孤岛跳转：回到活跃区
    candidates = []
    for e in neighbors:
        base    = e.weight as f64 / 255.0
        fresh   = freshness(e.other, state.clock)   # 久未访问 → 高
        novel   = cross_domain_bonus(current, e.other)  # 跨学科边 → 最高
        inert   = 1.2 if direction_matches(state.heading, e.other)
                  else 1.0                          # 惯性：顺路 20% 倾向
        temp    = state.temperature                     # 用户可调 0..1
        score   = (base * 0.4 + fresh * 0.3 + novel * 0.3) * inert
        candidates.push((e.other, score.pow(1.0 / max(temp, 0.05))))
    return sample_softmax(candidates)               # 温度低=确定性高
```

- `cross_domain_bonus`：当前节点与候选的学科标签集（标签也是节点，沿连接上溯 2 度即可得）交集为空时 ×1.8；
- 温度参数即 manifest 里的 `wander_temperature`——温度是漫游唯一的"旋钮"，且它不是任务参数（不是"难度"），是情绪参数（"想不想走远一点"）。

## B.3 隐式保存与恢复

```
写入路径（用户无感知）：
  双击空白 → 内存中创建 Node（仅 my_body 或 my_title）
          → 追加 NodeRecord 到活跃 kseg（无 fsync，依赖 OS 页缓存）
          → 500ms 内合并为事务组，组满或 2s 定时 → fsync
恢复路径（打开时）：
  逐段扫描 footer 检查点 → 从检查点向后重放记录
  → 遇半条记录截断 → 墓碑回放 → 索引重建（后台）
  → 期间 UI 可用（热层先展示检查点时刻的世界）
```

最坏丢失窗口 ≤2 秒的输入——对"种念头"场景足够工业级（同类基准：终端 shell 历史、SQLite 默认 synchronous=NORMAL）。

## B.4 热度与新鲜度

```
freshness(id, now) = 1 / (1 + ln(1 + (now - last_visited[id]) / 86400))
heat[id]           = 指数移动平均(visit 事件, 半衰期 7 天)
逐出排序键         = heat / (1 + graph_distance(current_focus))
```

全部 O(1) 更新，无全局重算—— Again：**邻域有限纪律贯穿一切**。

# 附录 C 渲染管线详解

## C.1 每帧数据流

```
core 状态（上次帧以来变更集 Δ）
   → build_render_graph(Δ)          外壳装配层，增量构建
   → RenderGraph {                  SOA 布局
       nodes:  pos[3], radius, color_idx, lod, flags
       edges:  from_idx, to_idx, weight, gold, alpha
       cards:  transform, text_atlas_slot, style_idx
       ambient: fog_params, light_rig, grade_params
     }
   → passes:
       1. density  (compute)  节点密度场 → L0 星云纹理
       2. simulate (compute)  力导向增量步 + 弹簧动效积分
       3. geo      (graphics) 地貌网格 + 阴影 pass（PCSS）
       4. graph    (graphics) L0 光斑 / L1 instancing / L2 卡片
       5. post     (graphics) Bloom → 雾合成 → 体积光(条件) → ACES → FXAA
       6. ui       (graphics) egui 绘制
   → present (vsync / mailbox)
```

## C.2 instancing 细节

- L1 节点：单 draw call，实例属性走 per-instance storage buffer；10 万实例的 buffer 更新用**环形 staging**（三缓冲轮转，永不同帧读写同一 region）；
- 边：折线 strip 打包成 triangle list（每边 6 顶点），weight 映射 alpha 与宽度，金线走单独高亮 pass（加色混合 + Bloom 强化）；
- 拾取：GPU pick pass（颜色编码离屏渲染，1 像素读回）——万级以上规模不走路 raycast，保证悬停零延迟。

## C.3 文字渲染

- SDF 字体图集：2048² 图集，预烘焙含中文字符集一/二级常用字；字符缺失回退到运行时烘焙队列（异步，期间显示占位光条）；
- 卡片（L2）文本排版在 CPU（egui 风格 glyph run），结果缓存 by (node_id, width_bucket, text_hash)；
- 任何文字在缩放中不重排——重排只发生在"停稳"后的 150ms 静默期，避免缩放过程中的文字跳动。

## C.4 帧预算哨兵实现

```
每帧：各 pass 计时（timestamp query）
滑动 120 帧窗口 P95：
  geo 段超支 → 光影档位 -1（PCSS→硬阴影→无阴影）
  graph 段超支 → L1 密度 -1 档（远处聚合阈值收紧）
  post 段超支 → 体积光关闭 → Bloom mip 减半
恢复条件：连续 300 帧 P95 低于预算的 85% → 逐档恢复
日志：降级/恢复事件写入本地日志（可诊断，不打扰用户）
```

## C.5 美术基准场景

渲染引擎的验收场景固定为三个（进入快照测试）：

1. **星海**：100 万 L1 节点 + 30 万边 + 50 个 L0 光斑，中景镜头，80 帧含全光影；
2. **雾林**：哲学地貌——高度雾 + 体积光 + 200 张 L2 卡片近景，验证文字与光影共存质感；
3. **海岸**：物理/哲学交叉地带的边界过渡——密度场渐变 + 金线高亮 + 念头灯火 Bloom。

```
// 内核内建应用：knowledge（no_std）

    store: KSegReader<'static>,      // 只读段读取器（映射内核 fs）
```

- 无写路径（v1 内核外壳只读；写回走"导出记录文件 + 桌面端合并"，与任务 15 的用户态通道一致）；

## E.2 与 syscall 表的关系

# 附录 G 艺术方向完整设定：一个知识世界的美术圣经

## G.1 世界观的统一隐喻

这个软件的全部美术决策由一个隐喻统领：**暗夜高原上的灯火文明**。

- 世界是一片无边的暗色高原（知识空间本身）；
- 每一条被理解的知识是一盏灯——被点亮过的地方才有光；
- 你的私人语言是灯火中最温暖的那一层光晕；
- 学科是高原上的地貌：物理是高地与星空，数学是水晶山脉（结构清晰、棱角分明），哲学是雾中的森林（边界模糊、深处幽暗），交叉地带是地貌互相渗透的海岸与河谷；
- 念头是散落的萤火——小，但活着，会呼吸；
- 用户是这个世界的唯一居民与唯一制图师。没有他人在场，没有他人的目光。

这个隐喻解决了一切美术分歧的裁决问题：**任何视觉元素，问一句"它在高原灯火的隐喻里是什么"，答案自然浮现。**菜单不是菜单，是营地；搜索不是搜索，是提灯寻路；撤销不是撤销，是时间倒回一步脚步。

## G.2 色彩的完整理论

基础八色（8.2）之上，是色彩的使用法则：

1. **暗底的层次靠"光的距离"而不是"灰度"**。深度感由微光的衰减表达：近处灯火是暖的、清晰的，远处是冷的、弥散的。这是物理直觉（大气透视），比 UI 设计惯常的"灰色阶梯"高级得多；
2. **ember 色是情绪的 monopoly**。暖橙微光是"你的东西"的专属色——你的念头、你的语言、你亲手标亮的金线。系统自带的内容永远不使用 ember。用户看一眼颜色就知道"这处光是我点的"；
3. **雾色是边界的语言**。学科之间不画分割线，用雾的浓度差表达边界——物理的高地雾薄而清朗，哲学的森林雾浓而缓慢。边界处两种雾互相渗透，这正是"交叉知识是天然地带"的视觉宣言；
4. **饱和度纪律**：全软件饱和度峰值出现在两处——金线（意外发现）与种子动画。其余一切颜色都压在低饱和区间。**稀有的高饱和才珍贵**，这是灯火文明的核心视觉经济学。

## G.3 动效的生命感清单

所有动效遵循同一组物理直觉（8.2 的弹簧参数是数学层，这里是语义层）：

- **呼吸**：灯火的亮度以 4~7 秒正弦周期起伏（相位随机错开）。一万个灯火同时呼吸但不同步——像真实的城市夜色，不是 Christmas 灯串；
- **惯性**：一切移动有质量。漫游的漂移是滑冰不是传送；面板出入是水面浮沉不是抽屉开合；
- **生长**：新增元素（念头、节点、连接）以"发芽"动画出现——从一点微光向外伸展，从不"弹出"；
- **消退**：删除不留尸体也不闪烁——灯火缓缓暗下去，化作高原上的一处余温（墓碑在时间线视图里仍可凭吊——**删除也应该是温柔的**）；
- **禁则**：无弹跳（bouncing）、无旋转入场、无闪烁提醒、无进度循环（loading 用"雾聚拢又散开"表达——即使等待也是这个世界的一部分）。

## G.4 声音设计（可选层，默认轻）

世界可以有声音，但声音必须像灯光一样克制：

- 环境层：极低的风声底噪（-48dB 级），漫游移动时有细微的气流声反馈；
- 事件层：种下念头 = 一声极轻的、类似水滴入潭的音（采样自真实水滴，降速 30%）；金线点亮 = 一声温暖的单音泛音；
- **全部声音可一键静默**，且默认音量极低。声音是给"住进去"的人的礼物，不是给"路过"的人的打扰。

## G.5 字体排印的完整规范

- 中文正文：思源宋体（衬线，用于"我的语言"——私人语言值得被郑重排印）；
- 中文界面：思源黑体（无衬线，用于系统 UI 文案——系统退后，用工具字体）；
- **"我的层用衬线、官方层用无衬线"** 是这个软件最有辨识度的排印决策：衬线体的书卷气天然携带"这是有人认真写下的话"的重量；
- 西文与数字：与中文层级一一配对（衬线配宋体系西文，UI 配几何无衬线）；
- 字重纪律：一屏之内字重不超过三种；标题不加粗而是加大（粗体是喊叫，字号是靠近）；
- 行长纪律：正文行长 32~42 字（中文舒适区），浮岛内 28~36 字。

## G.6 Unreal 外壳的美术协议

当沉浸层由 Unreal 承担（第十章），美术协议以"两个世界，一个文明"为约束：

- 色彩系统、ember 专属、雾色语义、饱和度纪律——**逐条照搬本附录**，Unreal 侧做成材质参数集与后处理配置文件，由同一份美术规范文档驱动；
- 渲染图接口（C.1）以 C++ 插件形式对 Unreal 提供同一抽象：Unreal 场景中的灯、雾、金线，直接由知识库的节点、学科、标记驱动——**美术资产可以是 Unreal 的，视觉语义必须是知识引擎的**；
- 两个外壳（wgpu 与 Unreal）交替浏览同一知识库时，观感必须是"同一世界的晴天与雨天"，而不是"两个不同的软件"。

# 附录 H 种子内容计划：出厂的第一袋种子

## H.1 原则：种子是示范，不是教条

出厂库必须足够小（不背内容包袱），又足够好（示范一切可能性）。目标规模：**约 400~600 个节点，全部人工精选**，覆盖：

| 卷册 | 节点数 | 选取标准 |
|---|---|---|
| 物理卷 | ~120 | 大学普通物理骨架，每个概念附一个"好的私人隐喻示范" |
| 数学卷 | ~120 | 从计数到微积分到群论的"观念主干"（不是题型，是观念） |
| 哲学卷 | ~120 | 概念史主干：从泰勒斯到语言哲学的转向节点 |
| 交叉卷 | ~80 | 数学哲学、物理主义、信息哲学、复杂系统——一等公民示范 |
| 元节点 | ~40 | "如何种念头""如何织连接""这世界的一切皆可修改"等自我说明节点 |

## H.2 种子里必须包含的三种"示范语法"

1. **一对双层示范**：至少 30 个节点同时带官方定义与私人语言，让新用户一眼看懂"两层"的用法——示范的私人语言要真诚（"熵——混乱的账本：热量就是那种只会越来越摊平的东西，像打翻的墨水永远收不回来"），不用冷笑话式的假装幽默；
2. **一组金线示范**：5~10 条预先标亮的金线（"意外发现"），告诉用户这条功能存在且值得用——例如"傅里叶变换 ↔ 人耳听声"这条边，备注一句"耳朵是天生的数学家"；
3. **一颗半成品念头**：库中故意保留几颗"未完成的念头节点"（只有半句话）——**出厂状态里就存在未完成**，新用户因此知道：未完成是常态，是被允许的，甚至是被预置的。

## H.3 种子的可卸载性

全部种子节点带 `seed` 标记（MetaRecord 扩展位），提供"一键收起所有种子"——收起后世界完全空白，只剩用户自己的内容。**用户有权让这个世界只属于自己**，包括删除我们出厂时放进去的每一个字。

# 附录 I 开放生态的生长模型

## I.1 生态的三阶段

**第一阶段（自给）**：软件自己就是唯一的作者与读者。开放格式的意义在这个阶段已经兑现——备份、迁移、脚本批处理、被其他工具消费。

**第二阶段（工具环）**：第三方工具围绕格式生长——命令行导入器（从 Anki/Notion/Obsidian 迁移）、静态站点生成器（把知识库发布成网站——格式规范公开使得任何人可以写）、编辑器插件、AI 助手连接器（本地知识库 + 本地模型的组合，数据永不出门）。这个阶段不需要我们做任何事，只需要格式规范 + 测试向量足够好。

**第三阶段（作品环）**：第九章的三通道执行模型让"作品"成为生态主体——WASM 视图插件、原生重型外壳（Unreal 级）、内核小程序。知识库从"一个软件的数据"变成"一个平台的世界"。

## I.2 兼容性承诺（生态的宪法）

1. 格式版本永远向后兼容打开（vN 文件可被 vN+1 及以后打开）；
2. syscall ABI 冻结后永不破坏（内核通道的信任基石）；
3. 渲染图接口大版本间保持语义稳定，破坏性变更走新版本号并行期（≥12 个月）；
4. 开放规范文档随代码同仓发布，永不闭源；
5. 软件本体可以商业化，**但格式与规范永不锁定**——这是"你的语言永远属于你"在生态层面的最终保障。

## I.3 社区形态（远景，不预建）

无账号、无中心服务器的社区想象：知识库片段（子图）可以作为文件流通——"分享一个思考"就是分享一个自包含的节点束文件，接收方一键织入自己的世界（ID 冲突由 128 位随机空间天然解决）。学术讨论、教学课件、读书笔记……皆可以这种"知识胶囊"形态流通。**胶囊格式 = kseg 子集**，无需新发明。

# 附录 J 跨设备与同步远景（v2+ 设计备忘）

今天只定方向，不写实现：

1. **同步单元是事件不是状态**：追加日志天然是事件源——同步 = 合并双方的记录流（按 seq 与时钟定序）+ 墓碑调和。冲突解决规则已在 5.5 定稿（较新者胜 + 历史保留）；
2. **端到端加密是默认项**，不是选项——知识库里的私人语言是最私人的文字，任何同步通道必须默认不可被服务方读取；
3. **内核端的同步边界**：裸机形态只读，不参与同步——U 盘整机的知识库是"快照"，由桌面端定期烧录刷新；
4. 多设备漫游连续性：漫游状态（当前位置、温度）作为普通 MetaRecord 随库走，任何设备打开都从"上次散步的地方"继续。

# 附录 L 反模式清单（宁可提前写下来）

这一份清单来自对同类产品的长期观察，是这个软件"不变成什么"的具体防线：

1. **"复习提醒"陷阱**：任何时候都不引入间隔重复、遗忘曲线、到期复习——那些是好产品，但它们把知识变成债务；
2. **"推荐流"陷阱**：漫游永远基于你自己的图谱，永不注入"热门""推荐"内容——高原上没有别人，也没有算法的Gesture；
3. **"协作"陷阱**：永不添加多人协作编辑——协作必然带来权限、评价与目光，与 2.1 负面清单全面冲突。共享通过"知识胶囊"（I.3）的一次性给予实现，而不是持续在场；
4. **"模板"陷阱**：不提供"读书笔记模板""康奈尔模板"——模板是结构预设，违背"一切默认值都是种子"原则。可以提供示范节点，不提供强制结构；
5. **"AI 概要"陷阱**：永不自动生成"你的知识库摘要""本周思考总结"——替用户总结自己的思想，是剥夺其语言主权的最隐蔽形式。AI 只在被明确召唤时工作，且产物落在用户可逐字审阅的草稿区；
6. **"gamification"陷阱**：无积分、无徽章、无连击、无等级——灯火的温度是唯一的"进度"，而它不可比较、不可展示、不可排行；
7. **"性能焦虑转嫁"陷阱**：任何 UI 元素不得展示"库很大，可能变慢"之类的恐吓文案——性能是工程的责任，不是用户的负担。

# 附录 M 未决问题登记表（诚实的开放项）

设计诚实的一部分是记录尚未想清楚的事：

1. **纯 Rust GUI 的中文输入法（IME）在 egui/wgpu 组合下的成熟度**——Windows IME 与即时模式 GUI 的集成 historically 脆弱。对策：外壳 A 的文本输入先走 egui 原生 IME 支持，不成熟则输入框降级为系统原生控件桥（有先例）。此项列入第 2 步的第一个技术验证点；
2. **wgpu 在老 GPU（DX11 级）上的覆盖**——wgpu 的 DX12 后端要求较新驱动。对策：保留 Vulkan-on-DX12（vkd3d 类方案）评估位；最坏情况为老设备提供 DX11 限制版渲染路径（L0/L1 保留，光影降级）；
3. **10 万级节点文本索引的内存占用极限优化**——当前估算在 2GB 热层预算内，但中文分词索引的膨胀未实测。M1 里程碑用真实数据回测；
4. **Unreal 嵌入窗口的 DPI 与多显示器场景**——嵌入子系统已解决单屏，多屏混合 DPI 的回归范围未验证；
5. **漫游算法的长期新鲜感**——任何确定性算法都会被用户"摸透"。保留一个想法：以用户自己图谱的统计特征做轻量个性化扰动（仍然全部本地），使每一次漫游的"手感"随世界生长而变化。此问题留给实际使用者反馈，不预设答案。

# 附录 N 结语之结语：关于"自由发挥"的自我注解

用户在委托这份文档时说：全部自由发挥，没有任何限制。

写到最后，想诚实地记下这次"自由发挥"里最重要的三个自由判断——它们不是资料整理，而是我替这个软件做出的、未来可以被推翻但必须被记录的立场：

**第一，我决定让"漫游"成为灵魂形态而不是花边功能。**市面上所有知识软件的第一屏都在要求你输入、整理、学习。这个软件的第一屏可以什么都不要求——这个决定违背所有增长指标的常识，但它是对"不带任何压力"最诚实的回答。压力不是被管理的，是被拒绝的。

**第二，我决定把私人语言放在数据模型的第一层而不是界面的第一层。**多数产品会先做一个好看的界面再"支持"自定义。这里反过来：`my_title` 在 Node 结构的第一行，官方定义是可选的附注。界面的一切特权（更亮的颜色、更大的字号、优先显示）只是这个数据层决定的投影。**结构即立场。**

**第三，我决定把哲学写成测试。**"无压力"如果不是 CI 里的一组断言，它就只是 README 里的一行字，会在未来某次"为了用户体验优化"的重构中被无声地磨掉。把价值观变成不可绕过的机器检查，是我所知的、让一个软件在多年演化中不丢失灵魂的唯一办法。

如果未来读这份文档的人只带走一句话，我希望是这一句：

**这个软件的度量衡，不是用户学了多少，而是这里有多少东西被用户用自己的话重新说过了一遍。**

其余一切——128 位的 ID、12.5 毫秒的帧、10TB 的容量、三个通道、四副外壳——都是这句话的注脚。

# 附录 P 第 1 步施工手册：核心引擎（预计 3~5 个工作日）

## P.1 目标

knowledge-core 全功能可用：模型、格式、索引、图算法、漫游、存储抽象，测试覆盖率 ≥85%。

## P.2 任务分解（按依赖序）

1. **model.rs**：Node/Edge 结构 + NodeHead（64B 轻头）+ 128 位 ID 生成（硬件熵源抽象，std 下用 OS 熵，no_std 下由宿主注入）；
2. **format/**：kseg 读写器（写：追加 + 事务组 fsync + 崩溃恢复重放；读：检查点快进 + 顺序扫描）+ manifest 读写 + 迁移器框架（v1→v1 空迁移先立骨架）；
3. **store/**：`trait Storage`（open/append/scan/truncate-tail）+ 内存实现 + std 文件实现（预读缓冲 + 写合并）；
4. **index/**：内存 B+ 树（u128 键）+ 邻接表 + 热度/新鲜度表（B.4 算法）+ shard 分片抽象（v1 只实现 shard-00 单片，接口按 256 片设计）；
5. **graph/**：邻域有限三度图（B.1）+ 束（cluster node）操作 + 墓碑调和 + 合并（5.5 规则）；
6. **wander/**：漫游步进（B.2）+ 温度参数 + 预取候选序列生成（供外壳的预取线程消费）；
7. **fmt 联测**：core 的写入输出喂给 fmt 向量比对；十万节点随机操作序列 + 随机截断崩溃注入测试（附录 F.1-3）；
8. **基准立桩**：criterion 三组（万次写入吞吐 / 百万键查询 P99 / 邻域查询常数性验证——断言任意库规模下邻域查询耗时方差 <10%）。

## P.3 验收标准

- 全部测试绿（含崩溃注入 1000 轮随机序列）；
- no_std 与 std 双特性编译 + 测试通过；
- 基准数据入库并生成首份趋势基线；
- 哲学断言套件（F.2 前三条——模型/API 层面的）成立。

## P.4 坑位预警

- u128 作 B+ 树键时的比较序：直接用数值序，不要用字节序（分片按最高 8 位，数值序与字节序在补码下不一致的坑要避开——ID 恒为正数则两者等价，**在类型上用 non-zero u128 并文档化此前提**）；
- 追加写与 fsync 的组合在 Windows 上与 POSIX 语义有差（FlushFileBuffers 代价高）——事务组策略（B.3）就是为摊薄这个代价，v1 先用 2s 组提交，实测后调参；
- 内核文件（kernel/）与本步骤无接触，但若同 session 有其他 AI 在改内核，遵守盘点与快照纪律。

# 附录 S 第 4 步施工手册：渲染引擎（预计 6~8 个工作日）

## S.1 任务分解

1. **GPU compute 布局**：力导向增量步上 compute shader（万级→十万级）；密度场预计算 pass；
2. **L0 星云**：密度纹理 + 光斑渲染 + 学科标签；

5. **帧预算哨兵**（C.4）：timestamp query + 降级链 + 恢复逻辑 + 事件日志；
6. **LOD 交叉淡化**：zoom 驱动的双层过渡；
7. **三基准场景**（C.5）：星海/雾林/海岸，golden image + 帧剖面基线入库。

## S.2 验收标准

- 星海场景：100 万 L1 节点，中端集显 80 帧稳定（连续 10 分钟，P95 帧时间 ≤12.5ms）；
- 哨兵降级链人工触发测试（制造负载）→ 逐级降级、恢复正确；
- 光影关闭与开启的 golden image 各自稳定（渲染确定性断言——同种子同输出）。

## S.3 坑位预警

- wgpu timestamp query 的驱动差异：部分老驱动不支持，哨兵需回退到 CPU 侧时间测量（精度降但可用）；
- SDF 中文烘焙的图集管理：动态字符集会碎图集，用 shelf packing + 定期整理，烘焙在后台线程，主线程只换纹理句柄；
- 体积光是预算黑洞：先用半分辨率 + 时间重投影，实测仍超支则降为"漫游镜头专属"。

# 附录 X 组件规格全书

## X.1 通用规则（先于一切组件）

1. **浮层堆叠秩序**（z 层语义，非数值）：世界 < 图谱元素 < 浮岛 < 面板 < 搜索 < 光标层。任何浮层出现时，世界继续呼吸（不暂停动画、不变暗压黑——变暗是"打断"的视觉形式，违宪）；
2. **焦点可见性**：焦点元素以 ember 色描边 1.5px 表达，不用系统蓝框；
3. **空态、加载态、错误态三态齐备**才算组件完成——三态缺失的组件不允许合入；
4. **一切列表虚拟化**：任何滚动列表组件必须内建虚拟滚动，无例外（百亿目标的纪律下沉到组件层）；
5. 组件间距用 4 的倍数（4/8/12/16/24/32/48），禁止奇数与非常量间距。

## X.2 种子按钮（主操作按钮的形态）

- 视觉：暗面板色底 + ember 色细描边 + 内部一个小种子图形（16px）；悬停时种子发芽（2 帧微动画）；按下时轻微下沉 1px；
- 文案永远用动词开头："种一个念头""织一条连接""点亮为金线"；
- 一个视图内至多一个种子按钮——**多主操作等于没有主操作**。

## X.3 概念浮岛（D.2 的组件化补充）

- 状态机：`hidden → sprouting(180ms) → open → fading(120ms) → hidden`；
- sprouting 期间再触发同节点 → 忽略（防抖）；open 状态点击外部 → fading；
- 邻域微缩图加载失败 → 该区域显示雾纹占位（不是空白，不是错误图标）；
- 官方定义折叠项的展开箭头仅在悬停浮岛时显现——**系统元素平时隐形，需要时才现身**。

## X.4 念头编辑气泡

- 双击空白后出现：一个 320px 宽的无边框输入区，光标已就位，背景是世界的原样（半透明 8% 压暗）；
- 输入行为：Enter = 落地（灯火生长动画）；Esc = 保留文本为"未完成想法"节点并收起（**Esc 不是丢弃**）；点击别处 = 同 Enter；
- 文本超过一行自动增高（至多 5 行，超出滚动）；
- IME 组合窗口（拼音候选）跟随光标——这是 M.1 验证点的主战场。

## X.5 连接手势的视觉反馈

- 从节点边缘拖出：一条从节点出发的 ember 色光线跟随指针，末端一枚小光点；
- 悬停可连接节点：目标呼吸一次；
- 松手在空白：光线落点生长出一颗"未完成的想法"灯火（D.1 规则），同时光线淡出——**手势的每一种结局都有产出**；
- 松手在节点：两灯火间金线候选出现（先 ember 虚线，用户按 G 确认金线 / Enter 确认普通连接 / Esc 保留为未确认连接——虚线态也是持久状态，不是待办）。

## X.6 Ctrl+K 搜索浮岛

- 居中出现（视口 1/3 高度处），宽 560px，无遮罩变暗；
- 结果分组：我的语言命中（ember 点标记）/ 官方定义命中 / 连接备注命中；
- 每条结果右侧显示三度邻域微缩图的极简版（一条线 + 两个点，示意它连着谁）；
- 无结果时："这里还没有'……'。要么它不存在，要么它正等着你第一次说出它。" + 一键"就地种下这个念头"——**搜索的空态直接转化为生产**；
- 搜索全程走索引（邻域有限纪律），输入节流 80ms。

## X.7 设置三页

**世界页**（≤15 项）：漫游温度 / 灯火密度 / 光影档位（自动·高·中·低）/ 声音开关与音量 / 呼吸节律（标准·缓慢）/ 界面缩放。

**数据页**：库位置（打开/迁移）/ 导出 JSON / 导入 JSON / 收起种子 / 存储用量统计（分段可视化：数据 vs 索引 vs 余量）/ 崩溃恢复自查（"检查我的知识库完整性"按钮 + 结果叙事化呈现）。

**键位页**：D.1 全表可编辑 + 冲突即时提示 + 一键还原默认。

- 每一项都有"跟随默认"状态指示；改动即时生效即时持久化（无"应用/取消"按钮——设置也没有仪式）。

## X.8 书写页

- 版面：居中 680px 文字列，上方留白 ≥120px（给"想法浮现"留出呼吸空间）；
- 工具栏：无。加粗/斜体等格式不支持——**书写态只有文字与念头**，排版是未来升格为节点后阅读态的事；
- 边缘灯火：相关节点在页面左右边缘外 24px 处亮起微光，悬停显示浮岛，可拖入正文成为连接；
- 升格交互：选中一段文字 → 浮出两个选项（"升为节点"/"升为念头"）——节点带标题（取选段首句自动截取，可改），念头只带正文；
- 全页状态持久化粒度：每 500ms 增量落盘（B.3 事务组），光标位置也恢复——**关掉软件再打开，你在写的那句话还在原地等你**。

## X.9 漫游卡片

- 形态：世界中央偏下 1/3 处的浮岛变体，随漂移镜头惯性微摆；
- 内容：当前节点双层文本 + 一条"从这里出发的路"（三度邻域的走向提示，纯视觉不列清单）；
- 交互：无必须交互。点击卡片 = 停留；点击世界中其他灯火 = 转向；空格 = 继续/暂停漂移；
- 卡片永不带按钮（无"收藏""记一笔""跳过"——任何按钮都会把散步变成任务）。

## X.10 图标全家福

| 图标 | 语义 | 造型要点 |
|---|---|---|
| 种子 | 应用本体 | 暗底微光种子，芽尖 ember 点 |
| 灯火 | 节点 | 菱形微光点，中心亮边缘散 |
| 雾页 | 空卷册 | 一页纸的轮廓，下缘化雾 |
| 金线 | 意外发现 | 一条弧线的金色高光 |
| 知识胶囊 | 分享 | 一粒发光的种子封在透明晶格中 |

# 附录 Y 文案风格全书（UX Writing）

## Y.1 语调宪法

像朋友递纸条：简短、具体、平静、留有余地。永远不用感叹号（正文与系统文案中感叹号一律禁用——感叹是情绪强加）。永远不用"请""抱歉给您带来不便"这类客套（客套是距离）。技术细节一律折叠进"详情"。

## Y.2 全场景文案表（直接进字符串资源与测试）

| 场景 | 文案 |
|---|---|
| 首次启动 | "这里是你的世界。从任何一个念头开始都好。" |

## Y.3 命名规范

- 功能命名不用行业黑话："标签"叫"灯火所属"，"收藏"不存在，"导出"叫"带走一份"；

工业级成熟的必备维度：

1. **对比度**：正文 ink 对 bg-deep ≥ 9:1；次要文字 ≥ 4.5:1；任何文字元素进入快照测试时同步做对比度断言；

# 附录 BB 内容设计：三大学科在模型中的正确打开方式

## BB.1 内容设计的总原则：种"观念的骨架"，不种"知识的肉身"

预置内容的失败模式是变成一份压缩版教科书。正确目标是：**种子只搭骨架，肉身由用户长出**。每个种子节点满足三条：

1. 官方定义 ≤120 字（一段话讲清观念本身，不展开）；
2. 至少 2 条预置连接（通向学科内邻居 + 尽可能一条跨学科边）；
3. 至多 1 个私人隐喻示范（真诚的、第一人称的、允许笨拙的）。

跨学科边的密度是种子质量的头号指标：**物理-数学 30 条、数学-哲学 25 条、物理-哲学 20 条**——这三组数字写进种子包的验收标准。

## BB.2 物理卷的编排逻辑

物理卷按"世界观的三次革命"组织，而非教材章节：

- 第一次：从机械到场（伽利略—牛顿—法拉第—麦克斯韦）。种子主脉：惯性、力、场、熵……
- 第二次：从确定到概率（热力学—统计—量子）。这条主脉与哲学卷的"决定论"节点天然金线（预置一条）；
- 第三次：从物质到信息（信息论—计算—量子信息）。这是与交叉卷的接口。

每条主脉终点放一颗"雾页"——物理学的故事没有讲完，最后一章必须是空的。这不是修辞，是诚实。

## BB.3 数学卷的编排逻辑

数学卷不按"分析/代数/几何"分科，按**观念的诞生序**：

- 计数 → 零 → 负数 → 无理数（第一次危机）→ 极限 → 无穷（第二次危机）→ 集合与悖论（第三次危机）→ 形式化与哥德尔。
- 每一次"危机"都是一等节点——**数学的历史就是确定性不断被重新定义的历史**，这条叙事线与哲学卷的认识论骨架互为镜像；
- 公式纪律：种子中公式只出现在 def 层，且必须配一句 def 层的"它在说什么"（自然语言）。my 层永不放公式——私人语言是比喻的地盘。

## BB.4 哲学卷的编排逻辑

哲学卷按"问题的家族"而非"人物年表"：

- 真理家族：符合论—融贯—实用主义—真理的紧缩；
- 存在家族：本体论承诺—共相—物理主义—涌现；
- 心灵家族：意识—意向性—中文房间—延展心灵；
- 语言家族：意义—指称—私人语言论证（与"私人语言"这个产品概念本身形成有趣的互文——**维特根斯坦的"私人语言论证"是这个软件必须诚实面对的哲学对手**，见 BB.6）；
- 自由家族：决定论—相容论—自由意志。

## BB.5 交叉卷：一等公民的编排

交叉卷的种子节点必须成对出现"学科 A 的概念 × 学科 B 的概念"并预置双向金线候选：

- 数学哲学：无穷与神学、柏拉图主义 vs 形式主义、哥德尔与心智；
- 物理主义：随附性、涌现、时间之箭与因果；
- 信息哲学：香农意义 vs 语义信息、观察者问题、熵与意义的边界；
- 复杂系统：涌现、自组织、混沌的哲学。

## BB.6 对"私人语言论证"的正面回应

维特根斯坦论证：一种原则上只有自己能懂的语言不可能成立，因为意义的判定需要公共标准。这个软件的一切理念建立在对该论证的回应之上，必须写清楚：

1. 本软件的"私人语言"不是维特根斯坦意义上的**原则上不可交流**的语言——它随时可以被翻译回公共语言（def 层永远存在且开放）；
2. 私人语言在这里是**翻译前的草稿状态**，不是封闭的终态。理解的轨迹是：公共语言 → 私人隐喻（消化）→ 更深的公共理解（回归）；
3. 图谱的连接结构本身就是私人语言的"公共性容器"——隐喻之间的关系是可检验的（一致性由结构而非词典保证）；
4. 这个回应本身作为一颗元节点种在出厂库里，公开接受用户的反驳——**软件的哲学立场应该和用户的知识一样，是可以被修改的节点**。

# 附录 DD 知识胶囊规范（分享单元）

## DD.1 形态

知识胶囊 = 自包含目录（可打成单文件 zip）：

## DD.2 织入（import）语义

1. ID 冲突：128 位随机空间下概率≈0；真冲突（故意伪造）→ 引入节点保留双方，冲突对进入"待审视"微光状态（不是弹窗任务——是世界里多了一处值得看一眼的地方）；
2. 引入节点自动与现有世界建立"来客连接"（弱权重），指向织入时世界中最相邻的 3 个区域——**客人一进门就认识邻居**；
3. 胶囊可携带"导览线"：作者预设的一条漫游路径（节点序列），接收方可在漫游态选择"沿作者的线走一遍"——**分享的不是知识，是 walk in someone's mind 的体验**。

## DD.3 教学场景

胶囊天然适合教学：教师把一个学科骨架做成胶囊（含导览线），学生织入自己的世界后，在自己的语境里生长它。学生的"作业"是回传一颗子胶囊——**作业从'回答问题'变成'展示你的世界长出了什么'**。

# 附录 EE 基准方法论（性能声明的可验证化）

一切性能声明必须可复现：

1. **基准机分档**：R1 高端独显 / R2 中端集显 + NVMe / R3 老集显 + SATA SSD。对外声明以 R2 为准（80 帧承诺 = R2 档 80 帧）；

5. **公开性**：基准脚本与数据集生成器随仓发布——性能声明的可复现性本身是开放性承诺的一部分。

# 附录 GG 威胁模型

## GG.1 资产清单（保护什么）

| 资产 | 价值 | 最高风险 |
|---|---|---|
| 私人语言文本 | 极高——最私人的思想记录 | 泄露、被云端分析 |
| 知识库整体 | 高——多年积累 | 丢失、损坏、勒索加密 |
| 墓碑与历史 | 高——删除即消失的承诺 | 被恢复/取证 |
| 本地执行环境 | 高 | 恶意胶囊/WASM 插件逃逸 |
| 元数据（浏览轨迹） | 中 | 被遥测搜集（本软件无遥测，风险来自第三方插件） |

## GG.2 对手画像

1. **好奇的服务方**（若引入云同步）：不得存在——v1 无服务，v2 端到端加密使其在密码学上不可能；
2. **恶意胶囊**：从网络收到的知识胶囊可能含超大节点、循环连接（图炸弹）、伪造 ID——织入侧的防御见 GG.4；
3. **恶意 WASM 插件**：沙箱逃逸、资源耗尽——能力位 + 燃料限制双防；
4. **本地物理接触者**：磁盘被直接读取——v1 不做全库加密（本地优先与可用性的权衡，诚实登记），提供可选的"私密库"（独立库目录 + 系统凭据加密，满足日记级隐私需求）；
5. **本软件自己**：最大的隐私风险常常是软件的遥测与"帮助"。对策见隐私宪法。

## GG.3 隐私宪法（产品级，可测试）

1. **零遥测**：软件不发出任何网络请求，除非用户显式触发（导入 URL、未来同步）——网络访问清单进入测试断言（集成测试中挂断网钩子，任何未声明请求即失败）；
2. **零诊断上报**：崩溃转储只落本地 `journal/`，由用户自己决定是否查看/分享；
3. **日志永不包含正文**：任何日志（applog、渲染降级日志、基准日志）只允许 ID、计数、耗时——**私人语言永不出现在日志里**（日志脱敏测试向量）；
4. **无广告、无推荐、无分析**：代码库不引入任何分析 SDK（依赖白名单审查）；
5. **删除是真的**：收起种子/删除节点后，"带走一份"导出物中不含已删内容（导出后校验测试）。

## GG.4 胶囊防御

织入前审计（全部本地，毫秒级）：

- 规模上限：节点数、边数、单体文本长度、总解压体积四重上限（默认 10 万节点/胶囊，可调）；
- 图炸弹检测：连接分布的幂律偏离检测 + 环密度抽样——异常高密度互连的胶囊标记为"致密胶囊"，默认以"束"形态引入（展开需用户显式操作）；
- ID 伪造：胶囊内节点若与本地已有 ID 相同但内容哈希不同 → 双保留 + 待审视状态（DD.2），绝不覆盖；
- 媒体扫描：blobs 按内容寻址校验，类型嗅探与扩展名不符即拒收。

## GG.5 WASM 执行安全

- **能力位最小化**：插件默认零能力，逐一声明（读库/订阅事件/呈现视图），写操作只经 core 公开 API；
- **燃料计量**：每回调配燃料上限，超限即熔断（视图插件卡死不可能拖垮主循环）；
- **内存上限**：每插件线性内存上限 256MB，超限终止；
- **IPC 隔离**：外壳插件（进程级）走共享内存段 + 消息校验，段只读映射给插件侧，写侧属主进程。

# 附录 HH 内核 ABI 冻结规范（知识引擎相关面）

> 全 ABI 属于 VARIX 内核工程本身，此处只冻结知识引擎作为"第一个大型用户态作品"所依赖的最小面。冻结即承诺：以下编号与语义永不改变。

## HH.1 syscall 依赖面（引用现有表 + 新增四项）

既有依赖（编号以内核 syscall/table.rs 现表为准，此处登记用途）：内存映射、文件读写、时钟、能力声明、IPC 注册。

新增（提案编号，随内核 v-next 定案）：

```
SYS_KNOWN_OPEN      打开知识库（能力位：KN_READ / KN_WRITE）
SYS_KNOWN_SEARCH    邻域/关键字检索（走内核 IPC 服务短路路径）
SYS_KNOWN_SUBSCRIBE 订阅变更事件（追加日志的 tail 跟随）
SYS_KNOWN_CAPSULE   胶囊导入导出（写路径唯一入口，保证墓碑/版本不变量）
```

- 四个新增 syscall 都是**薄转发**：真正逻辑在内核 knowledge 模块与 IPC 服务，syscall 层只做能力校验与参数拷贝——ABI 面最小化，未来扩展走 IPC 而不再增 syscall；
- 能力位定义：`KN_READ=1<<0, KN_WRITE=1<<1, KN_EXPORT=1<<2`——WASM import 面直接映射这三 位（9.3 的沙箱映射）。

## HH.2 稳定性纪律

1. 冻结发布物：ABI 文档 + C 头文件 + Rust 绑定 crate（三方同源生成，向量测试保证一致）；
2. 变更流程：只增不改；废弃走"标记 deprecated → 至少两个大版本后移除"；
3. 兼容性测试：冻结向量集（各 syscall 的请求/响应样本）进内核 ktest——**任何内核 PR 破坏冻结向量即门禁失败**。

# 附录 JJ 可选"私密库"加密方案（v1.1）

威胁：本地物理接触。方案要点（设计备案）：

1. 库级加密：整库目录以 XChaCha20-Poly1305 流加密，主密钥由系统凭据（Windows Hello / TPM 包装）+ 用户口令双派生；
2. 追加日志的加密友好性：kseg 顺序加密天然适配追加写（每段独立 nonce 域）——**加密设计不破坏存储引擎**是本方案的成立前提；
3. 热层明文窗口：内存中的明文工作集在锁定时整体丢弃（逐出 + zeroize）；
4. 搜索代价：加密库的索引只在解锁会话内构建（内存态），不落明文索引——解锁耗时换隐私，用户自选；
5. 不承诺对抗：内核级键盘记录、屏幕录制等本机强对抗——诚实边界，文档写明。

# 附录 KK 崩溃与恢复的完整状态机

```
状态：CLEAN ──写入──→ DIRTY ──fsync组──→ CLEAN
        │                 │
      打开时            崩溃
        ↓                 ↓
    正常加载        重放恢复：footer 检查点 → 顺序重放
                         ├─ 半条记录 → 截断（尾部丢失 ≤2s 输入）
                         ├─ CRC 错 → 该记录丢弃 + journal 登记
                         ├─ 段级损坏 → 隔离该段（其余段可用）
                         └─ manifest 损坏 → 从 nodes/ 重建 manifest 骨架
任一恢复路径完成 → 进入只读"自检模式"→ 自查通过 → 恢复可写
自查失败 → 数据页入口提供"带一份导出（可读部分）"逃生门
```

- **恢复永不静默**：用户被告知（Y.2 文案"上次离开得有些突然……"），journal 留痕；
- 恢复路径全覆盖测试：F.1-3 的截断注入扩展到段级损坏与 manifest 损坏两档；
- **最坏结局永远是"可读部分可带走"**——数据全灭在架构上不可达（段独立 + 索引可重建 + 恢复优先保读）。

# 附录 QQ 理解的科学：为什么私人隐喻是理解的载体

## QQ.1 认知科学的三个支点

**支点一：概念的隐喻根基（Lakoff & Johnson）。**《我们赖以生存的隐喻》的核心发现：人类的概念系统本质上是隐喻性的——"时间是金钱"（花时间、省时间）、"理解是抓住"（领会、掌握）、"重要是重"（分量）。抽象概念永远通过具体经验的隐喻被把握。**教科书定义是隐喻的翻译结果，不是理解的发生地。**本软件让用户保留并使用翻译前的原始隐喻，是在顺应认知的本性。

**支点二：生成效应（generation effect）。**记忆与理解的实验心理学结论：自己生成的内容远比被动接收的内容记得牢、懂得深。读十遍"熵增原理"，不如自己写一句"打翻的墨水收不回来"。本软件的双层结构 + 升格路径，是把生成效应做成了产品机制。

**支点三：精细加工（elaborative interrogation）。**对知识提问"为什么是这样、这和我知道的什么像"，显著提升理解。金线（意外发现）与边缘灯火（书写时的相关提示）都是在低摩擦地邀请精细加工——邀请，不是布置作业。

## QQ.2 从这三个支点推出产品特性（回溯验证）

| 认知机制 | 产品机制 | 章节 |
|---|---|---|
| 隐喻性认知 | 私人语言第一公民 | 2.3 |
| 生成效应 | 落笔即存 + 升格路径 | X.4/X.8 |
| 精细加工 | 金线 + 织入提示 | X.5/X.8 |
| 情境依赖记忆 | 知识地貌（空间化） | 7.3 |
| 间隔与随机接触 | 漫游的邻接步进（非刻意复习，而是自然重逢） | 3.4 |
| 双重编码（语言+图像） | 灯火/地貌的可视化与文本并存 | 7.4 |

值得强调最后两行：漫游不是"花哨的随机浏览"，它暗合"间隔接触"与"情境记忆"两条机制——知识在无任务的重逢中被反复加工。这是科学对漫游态的背书。

## QQ.3 对"游戏化学习"的划界

认知科学的另一个结论常被误用：游戏机制（积分、竞争、即时反馈）提升短期参与度，但大量研究显示外在奖励会侵蚀内在动机（overjustification effect）——**一旦学习与奖励挂钩，无奖励时的学习意愿反而下降**。这正是本软件拒绝 gamification（LL 附录的反模式 6）的科学依据：不是保守，是保护内在动机。漫游态的"无任务"是同一保护的光明面。

## QQ.4 理解的层次模型（内容的隐形坐标系）

种子内容与将来的 AI 辅助都遵循同一坐标系（对用户不可见，对设计者可见）：

```
L0 接触   知道它存在（灯火被点亮过一次）
L1 转述   能用自己的话粗略说出（出现 my_body）
L2 联结   与已有知识织出连接（度 ≥2）
L3 隐喻   产生私人隐喻（my_title 出现非术语命名）
L4 迁移   在跨学科处使用它（跨域金线/跨域连接）
```

**这五层不显示、不统计、不提示**——它们只用于设计校准（种子内容检查覆盖 L0~L3；AI 辅助建议只在用户已到 L1 的节点上提供）。度量的存在是为了校准设计，不是为了评价用户——这是"度量衡悖论"（1.5）的内部解法。

# 附录 SS AI 的边界：被召唤的助手，而非在场的管家

把讨论过多次的立场正式化：

1. **默认无 AI**：软件的全部价值在无 AI、无网、无账号时成立——AI 是增强，不是依赖；
2. **召唤制**：AI 只在用户显式召唤时工作（工具栏一个明确的入口），永不在后台观察、建议、补全；
3. **草稿区纪律**：AI 的一切产物落在用户可逐字审阅的草稿区，采纳需逐条确认，产物默认不直接入库（反模式 5）；
4. **本地优先**：支持接入本地模型（用户自己的硬件）；云模型需用户逐次明确授权且会话即焚；
5. **AI 产物的标记**：任何 AI 生成内容入节点后带 `assisted` 元标记（节点级，可清除）——**人与 AI 的边界在世界里可见**；
6. **AI 能做什么的安全清单**：为选中节点建议官方定义草稿 / 为相邻节点提出潜在金线候选（用户确认才织入）/ 帮助把私人隐喻"翻译"成正式语言（方向永远是我的→官方，绝不反向改写用户的语言）。

第 6 条的最后半句值得加粗理解：**AI 永远被禁止"帮"用户把他的语言改得"更规范"**——那是这个软件存在的全部意义所不允许的事。

# 附录 VV 常见问题（写给未来的新成员与好奇者）

**Q：为什么 80 帧而不是 60？**
12.5ms 预算给了光影与动效迭代空间；60 帧裕量不足以支撑"工业级光影"的长期迭代。见 CC-7。

**Q：100 亿条对个人用户有意义吗？**
容量目标是架构的诚实边界（撑得住），不是使用目标（用不满）。个人用户的世界大概率在十万级——但架构不为少数人的例外迁就，也不为多数人的现状妥协。

**Q：为什么不做协作？**
目光即压力（附录 LL 反模式 3）。分享用胶囊（一次性给予），在场协作永不做。

**Q：私人语言会不会让用户越来越偏离正确理解？**
恰恰相反：QQ.1 的三个认知支点说明私人隐喻是理解的入口而非终点；双层结构保证了通往正式语言的路径永远畅通（BB.6 还正面回应了维特根斯坦）。

**Q：为什么文件格式不直接用 JSON 存储？**
追加式日志的性能与崩溃安全需要二进制段；JSON 作为无损双向视图保留（A.5）——机器读段文件，人读 JSON，两者互为镜像。

**Q：内核端真的有人用吗？**
U 盘整机的意义是"世界随身的兜底"——桌面不在、电脑不在，知识体系仍在。它是产品哲学五（永远属于你）的物理极端形态。

**Q：这个软件和本工程的名字有什么关系？**
Un-Real Engine 探索真实与虚构的边界。这个软件让知识（最真实的东西）以虚构的方式（地貌、灯火、雾）被居住——它就是这个命题的最好答案之一。

**Q：如果只能保留一个功能？**
漫游。其余一切都建立在"世界值得被无目的地居住"之上。

# 附录 XX 并发模型：单写者多读者的纪律

## XX.1 并发拓扑

```
唯一写者线程（writer）
   ── 追加记录到活跃 kseg / 推进事务组 fsync
   ── 发布版本号（epoch 递增）
多个读者（渲染装配 / 检索 / 预取 / 漫游）
   ── 读快照（epoch 一致性视图）
   ── 邻接表与轻头索引为 RCU 风格不可变结构（更新时克隆-替换）
```

- **单写者原则**是存储正确性的根：任何时刻至多一个写者，写者之外的一切读者通过 epoch 快照获得一致视图（读时零锁）；
- 跨进程（外壳 A 与 B 共库）：文件锁仲裁写者资格，未持锁进程的写请求排队或转交（II.1 的协作锁）——**进程间也是单写者**，原则跨边界一致；
- 内核外壳只读，天然无冲突。

## XX.2 epoch 快照语义

1. 读者登记当前 epoch → 读索引与热层 → 离开时注销；
2. 写者的合并（compaction）永远不重写"仍有读者驻留的 epoch 之前的段"；
3. 读者最长驻留期设上限（60s）——超限视为泄漏，告警日志（不强制踢出，保护正确性优先于资源回收）；
4. 断言：任意并发读写交错下，读者视图满足"前缀一致性"——只见完整的追加前缀，永无半条记录。

## XX.3 事务组的精确语义

```
组边界：500ms 时间窗 OR 512KB 聚积量，先到者触发
组提交顺序：记录全量写页缓存 → fsync 段 → fsync 目录项（新建段时）→ 发布 epoch
崩溃窗口分析：
  - 组内部分记录落盘 → 重放按 seq 定序，半条截断（B.3）
  - epoch 未发布 → 该组对读者不可见，恢复时照常收编
  - 双段边界崩溃 → 段独立校验，各自按段内完整性收编
```

## XX.4 断言清单（并发测试套件）

1. 双线程并发"读者+写者"1 小时随机操作：读者零半条、零前缀违例；
2. 写者中途 kill -9 × 1000 轮：每次恢复后 node/edge 计数与最后成功 epoch 严格一致；
3. 双进程交替持锁写入：锁交接零丢失（锁文件校验含心跳）；
4. compaction 与读者并发：读者驻留期内旧段零删除（GC 延迟正确）。

# 附录 YY 束（bundle）操作完整语义

5.4 的软上限引出束——超连接节点的聚合形态。束是数据模型里最容易做错的部分，这里给出完整语义。

## YY.1 束的资格与创建

- 资格：节点直接连接数 >512（软上限触发），或用户手动圈选 ≥32 个节点"收拢为一束"；
- 创建：束是**普通节点**（一切皆节点原则——束没有特殊类型），它的 my_title 默认为成员们最高热度的共同标签；成员与束之间自动生成"成员连接"（weight=0 的特殊轻连接，仅表示归属，不参与语义图）；
- 成员的对外连接**不迁移**：束对外呈现的连接是成员连接的聚合投影（束的度 = 成员度之和的对外投影）——成员各自的连接永远完好。

## YY.2 束的展开与呼吸

- 展开即"聚焦进入"：镜头推进束节点，成员灯火散开（动画即含义）——展开是视图操作，不改数据；
- **呼吸重组**：束内成员按热度周期性重新排序投影，活跃成员"浮到束面"——束不是死的文件夹，是活的群落；
- 拆散：一键还原，成员连接原样恢复——**束永远可逆**（与升格/降格同一可逆性家族）。

## YY.3 束与漫游/检索

- 漫游进入束 = 进入束内成员的邻接图（束面对漫游者透明：要么当作一个节点跳过，要么展开深游，由温度决定——低温跳过，高温深入）；
- 检索永远穿透束（束不藏节点——**任何内容任何时刻可达**，束是组织不是容器）。

## YY.4 断言

1. 束操作（建/拆/呼吸）前后，全库节点与连接的集合恒等（投影除外）；
2. 深度嵌套束（束中束 ≤8 层）下邻域查询仍 O(常数)；
3. 束内成员参与全局搜索零遗漏。

# 附录 ZZ 索引页布局示例（kidx 内部，实现参考）

索引虽是"实现自由域"（A.6），此处给出推荐布局供实现者起步（可换，接口不变）：

```
页大小 4KB，与 OS 页对齐
节点页：[页头 16B | (id u128, head_off u64, head_len u16)*n | 增长方向→]
                                      [←增长方向 (溢出槽)]
邻接页：[页头 | (from u128, to u128, w u8, flags u8)*n]
键有序 + 页内二分 + 页间三高层（根/枝/叶）
```

- 溢出策略：页满走兄弟分裂（B+ 树标准），分裂率纳入基准监控；
- 全部页可校验（页尾 CRC）——索引损坏永远只重建不修复（重建便宜于修复，且重建结果必然正确）。

# 附录 AAA 性能与正确性的边界案例十则

实现者最容易踩的十个边界，每则给"必须成立的断言"：

1. **空库全功能**：零节点时四形态可用（漫游退化为呼吸的种子灯）；
2. **单节点自环**：节点连向自己（用户手滑）——合法但默认隐藏，检索/漫游忽略，导出保留（诚实序列化）；
3. **重边**：A→B 十条连接——合并为一条权重取最大 + 其余保留为多版本（合并规则 5.5 的边版）；
4. **超长文本**：单 my_body 512KB 上限（触发时提示"这一句想写成一片海——考虑升格为节点"）；
5. **零字节字符串**：my_title="" 合法但渲染为无名灯火（不显示空引号）；
6. **时钟回拨**：created_at 异常早于既有最早节点 → 标记 clock_skew，合并时该节点时戳让位（时戳从不参与 ID 语义，只影响排序显示）；
7. **UMD 全角/异体字**：检索归一化含 Unicode NFC + 全半角折叠（中文用户日常坑）；
8. **超大胶囊**：GG.4 上限触发时的渐进引入（分批织入，每批带进度微光）；
9. **段号耗尽**：u32 段号在 4G 段后——按设计容量（段均 256MB）远超 10TB 目标，但代码必须显式处理溢出（新库目录继承）而不是静默回绕；
10. **删除一切**：用户删光全部内容——世界合法存在（一颗灯都不剩的暗原），空态文案："这里很安静。灯曾经亮过。"时间线视图保留全部墓碑可凭吊。

# 终章：宣言

写到这里，一百个附录、十七章、十一卷，可以合上了。

合上之前，把散落在全书各处的、构成这个软件灵魂的东西，最后一次并排放在一起——

**我们相信知识不是被管理的对象，而是被居住的世界。**

**我们相信理解始于私人隐喻，而不是终于标准定义。**

**我们相信压力不是被管理的，是被拒绝的。**

**我们相信最少的定义、最深的组合，就是无限。**

**我们相信稳定 80 帧不是优化出来的，是设计出来的。**

**我们相信数据只有一份，其余一切皆缓存；你的语言只有一份，其余一切皆注脚。**

# 附录 OOO 评审问答集（18 问）

**Q1 十万字的方案，最短的不可妥协版本是什么？**
答：五条——私人语言第一公民（2.2-1）/ 系统不评价（2.2-2）/ 一切皆节点（2.4）/ 开放格式（铁律五）/ 帧预算哨兵（7.1）。其余皆是这五条的推论与防护。

**Q2 为什么不先用现成笔记引擎（如 Tauri + SQLite）拼一个？**
答：拼出来的第一天就欠下三笔债：模型债（表格≠节点+连接，2.4 无法成立）、内核债（SQLite 无 no_std 等价物可进 VARIX）、哲学债（评价型字段天然混入 schema）。M1 阶段的自研成本换来的是零迁移（CC-3/CC-8）。

**Q3 128 位 ID 是否过度设计？**
答：64 位的 1.8×10^19 空间在单机随机生成下确实够，但多副本合并 + 墓碑永不复用 + 万亿远期三条件叠加后，碰撞与协调成本出现在最难调试的层面（数据层）。16 字节的代价买永久安心（5.3/CC-2）。

**Q4 追加日志会让库无限膨胀吗？**
答：不会——compaction（6.3）回收墓碑与旧版本；膨胀的是"未合并窗口"，受合并策略约束。100 亿目标的容量核算（6.1）已含合并后稳态。

**Q5 渲染引擎自研的风险是否被低估？**
答：没有。对策有三：基准场景锁验收（C.5）、降级链保下限（7.1）、Unreal 外壳保上限（第十章）。风险被定价且买了三份保险。

**Q6 no_std core 的生态现实吗？**
答：core 的依赖面被白名单压到最小（O.4）；哈希、B+ 树、varint 皆为可控自研量级；最大不确定项是 IME 与 wgpu 老驱动（M.1/M.2），均在外壳层而非 core——**风险被隔离在最容易更换的层**。

**Q7 无协作会让产品失去多少用户？**
答：会有用户因此不来——这是被接受的代价（PP-1）。协作与负面清单的冲突是结构性的（LL 反模式 3），不做是立场不是缺失。

**Q8 私人语言会不会让检索变乱？**
答：检索三路并查（X.6）：我的层/官方层/连接备注各归各组。私人语言增加的是"命中面"而不是噪音面——它让用"自己的话"搜索成为一等体验，这恰是其他产品的空白。

**Q9 帧预算 12.5ms 在低端机上是不是幻觉？**
答：80 帧承诺限定 R2 基准档（EE-1）；R3 老机走降级链到 60 帧稳态。承诺是"档位化稳定"，不是"全硬件 80 帧"——诚实边界（EE）。

**Q10 哲学断言会不会阻碍正常迭代？**
答：会，这正是目的（2.5）。任何被断言挡下的改动，都必须先通过哲学评审改变断言本身——价值观的变更走正门，不走后门。

**Q11 Unreal 插件读 kseg 二进制会不会成为兼容负担？**
答：插件只需实现 NodeRecord/EdgeRecord/Tombstone 三种解码（A.4），且可走 JSON 导入通道（A.5）先跑通——二进制路径作为优化第二步。负担有阶梯（T.5）。

**Q12 100 亿下的全库统计（"我有多少盏灯"）怎么办？**
答：统计永远"约"化（Y.3-3）：manifest 近似值 + 增量维护——全库扫描在架构上就不存在（邻域有限纪律的另一面）。

**Q13 漫游会不会被用户摸透变得可预测？**
答：会部分可预测——但可预测性来自用户自己的图谱（它就是你思想的形状），这正是"熟悉而非重复"。UU-5 的个性化扰动留作实证后的演进项。

**Q14 为什么种子不做成"完整的入门课程"？**
答：课程=进度=压力（2.1-3）。种子只示范语法与地貌（H.1），课程化是.content 平台化的第一步，也是哲学失守的第一步。

**Q15 双层文本会不会让用户永远停在私人层，不接触正式语言？**
答：观测点设为"双层并置"（3.2 浮岛）：官方层永远在同屏折叠区，读与不读都在视野里。生成效应（QQ.1）保证私人层的加工本身在通往理解——路径不是二选一，是坡道。

**Q16 内核端只读，写需求怎么办？**
答：内核端产出以"导出记录文件"暂存，桌面端合并导入（E.1）——U 盘整机的使用画像（查阅/检索）本就以读为主；写路径留给 v2 的 journal 化同步（RR.1）。

**Q17 文档里大量"可测试断言"，测试本身谁测试？**
答：断言基座（philosophy_tests.rs + fmt 向量）自身以"最少代码最大覆盖"为设计（多数是 schema/API 表面断言，逻辑极薄）；测试框架的回归风险由 Rust 类型系统与极简性兜底——**测试的复杂度被刻意压低，压低不了的不引入**。

**Q18 如果整个方向错了，沉没成本多大？**
答：分层边界（4.2）就是止损设计：core 是纯库（任何相似产品可复用）、格式是资产（数据永不作废）、渲染是独立 crate。最坏结局下，留下的是三件可迁移的资产与一份诚实的文档（PP-4）。

# 附录 PPP 设计历程：这些想法是如何长出来的

真实记录（便于未来理解每个决定的"为什么长这样"）：

1. **起点是一句愿望**——"找到属于自己的语言"。最初它只是功能描述（给笔记起别名）；被追问"如何不带压力"后，它长成了产品宪法：压力的五源解剖（2.1）与五条铁律（2.2）。
2. **"无限可能"的转折**——用户说"没有任何定义和限制"。直接照做是不可能的（连白纸都有边界）；围棋/乐高的类比把愿望翻译成了"最小定义×最深组合"——数据模型被压到"节点+连接"两个原语（2.4/5.1）。
3. **".exe 放内核"的澄清**——用户最初想让 .exe 进内核。技术澄清（PE 进不了内核）没有杀死需求，而是催生了"一核三壳"：.exe、Variable、内核三个落点共享一个 no_std 核心（4.1）——错误的理解往往包裹着正确的愿望，拆解它而不是纠正它。
4. **"100 亿"的出现**——体量目标从"很多很多"逐步精确到 10^10。它没有变成一句口号，而是被算术化：10TB→外存分层→128 位 ID→邻域有限（5.4/6.1）——野心的最好归宿是变成约束。
5. **"80 帧"的哲学化**——帧率最初是性能指标；写帧预算表时发现真正的设计是"降级链"（7.1）：稳定不是不超支，是超支时谁先牺牲——性能问题被翻译成了优先级问题。
6. **Unreal 的位置之争**——"用 Unreal 做知识软件"有三个版本（全 Unreal / 嵌入 / 数据打通）；嵌入子系统恰好是本工程现成地基，于是"第四外壳"成为零对抗的合题（第十章）。
7. **哲学测试化**——"无压力"写了三稿都是散文；直到把它写成五条 CI 断言（2.5），它才从愿望变成结构。**本总案最大的方法论收获：所有不能变成断言的理念，都还没想清楚。**

# 附录 TTT 用户视角常见问题（15 问）

**U1 我需要懂技术才能用吗？**
不需要。你会用的动作只有：双击、拖拽、打字、滚轮。其余一切是可选的。

**U2 我的知识库存在哪？我看得见吗？**
在你自己指定的文件夹里，普通文件，双击就能用文本编辑器打开看（导出的 JSON 版本）。

**Q3 换电脑怎么办？**
拷文件夹。完。

**U4 它会连网吗？会看我的内容吗？**
永不连网（除非你主动用分享/未来同步功能）；永不分析你的内容；没有任何遥测——这是写进测试的宪法，不是承诺书。

**U5 我写的"混乱的账本"这种定义会不会误导我？**
恰恰相反——它是理解开始的地方。正式定义永远在同一张卡片上折叠着，你需要时它就在。

**U6 我可以删掉"物理"这个学科吗？**
可以，包括"物理"两个字本身。一切默认内容都是可以修改的种子，不是规则。

**U7 漫游是什么？有什么用？**
没有用。就像散步没有用。它是这个软件里唯一什么都不要求你的地方——很多人和知识的关系，就是从"每次打开都要有产出"开始破裂的。

**U8 进度条在哪？我学到哪了？**
没有进度条。你学到哪了的唯一标志是：多少东西被你用自己的话重新说过了一遍——打开你的世界，那些最亮的光就是答案。

**U9 我能有几个知识库？**
任意多个（每个是一个独立文件夹）。比如一个"世界"一个"工作台"。

**U10 以后不更新了怎么办？**
格式开放、导出一键、无账号无锁定——你的世界可以完整迁往任何工具。优雅的死亡能力是工业级的最后测试。

**U11 它能帮我复习吗？**
它不会提醒你复习（那是把知识变成债务）。但漫游会让你自然地重逢旧知识——在没有任务压力的重逢里，记忆自己发生。

**U12 别人能看到我的世界吗？**
除非你主动导出"知识胶囊"送出去。没有分享按钮的诱导，没有"公开"选项的暗示。

**U13 笔记有字数限制吗？单条知识能有多大？**
单条 512KB（约一部短篇小说），触发上限时它会建议你"把这一片海拆成几盏灯"。

**U14 支持 AI 吗？**
只在你在工具栏明确召唤时。AI 的产物永远落在你可以逐字审阅的草稿区，且永远被禁止"帮"你把你的话改得更规范。

**U15 为什么叫"知识引擎"而不叫"笔记软件"？**
因为它的模型不是"管理知识"而是"居住知识"——你在里面有一个世界，而不只是一个文件柜。

3. **"文档即世界观"**：这份总案写完后，最意外的收获是——它本身已经是一个知识世界的雏形：有术语表、有交叉索引、有观点、有未决问题、有可修改的宣言。**如果造出来的软件读起来像这份文档，它就对了。**

# 附录 XXX 平行宇宙推演：三条被放弃的路

## XXX.1 平行宇宙 A：Electron 路线（"最快见效的宇宙"）

**选择**：TS 全栈 + Electron + WebGL 图谱 + SQLite 存储，三周出 MVP。

**前六个月的模样**：世界上手最快，图谱两万节点流畅，Notion 难民涌入，Star 攀升——所有仪表盘都是绿的。

**第一道裂缝**：十万节点后 WebGL 力导向掉到 30 帧；GPU compute 不可用；力导向回退 CPU——帧预算哨兵（7.1）根本无法成立，因为渲染管线不在自己手里。80 帧目标在 A 宇宙的讣告上写着：**死于借来的渲染器**。

**第二道裂缝**："放进内核"永远不可能——SQLite 无 no_std 等价物，核心逻辑要用 Rust 重写第二遍。三壳愿景退化为一壳。

**结局**：成为一款"不错的笔记软件"，在一个拥挤的赛道上与上百个同类竞争最便宜的维度。**它死于最早实现的那个月。**

## XXX.2 平行宇宙 B：全能结构化路线（"最周到的宇宙"）

**选择**：预设完整的本体类型系统——学科/概念/公式/人物/事件五类节点、八种关系类型（包含/因果/引用/对比…）、内置课程模板、学习进度、复习引擎、协作白板。功能清单长达四十页。

**前三个月的模样**：演示惊艳。每一个需求都能在功能表上指给你看。

**第一道裂缝**：用户开始问"这个该建'概念'还是'事件'？""引用和对比该选哪个？"——**结构的重量落在用户的每一次落笔上**。双击种念头需要先做四个选择题（类型、关系、归属、模板），仪式感杀死零仪式（2.2-4）。

**第二道裂缝**：类型系统成为扩展税——每加一种新内容（比如"我的猜想"），都要改 schema、迁数据、改所有视图。三个月后功能表变成债务表。八种关系里六种没人用，删又不敢删（有用户数据依赖）。

**结局**：它死于"周到"。**定义越多的系统，留给用户的定义越少**——2.4 的围棋论证在 B 宇宙的反面被再次证明。

## XXX.3 平行宇宙 C：云端优先路线（"最性感的宇宙"）

**选择**：云同步实时协作 + AI 全程陪伴 + 社交学习流。增长模型清晰，融资故事完整。

**第一道裂缝**：隐私宪法（GG.3）逐条阵亡——遥测必须上（增长要数据）、云端分析必须上（AI 要语料）、你的语言开始出现"热门说法"的比较压力（2.1-4）。

**第二道裂缝**：无网即无产品。地铁里、飞机上、停电的夜晚——世界一片黑暗。而知识最深的时刻往往恰恰是离线、独处、深夜。

**第三道裂缝**：内核端彻底无意义——U 盘整机、离线世界、裸机检索，这些"不性感"的形态在云架构下连讨论价值都没有。

**结局**：它死于联上网络的那一刻。**云是体验的放大器，但先于体验存在的云是体验的替代品**——C 宇宙用增长换掉了灵魂。

## XXX.4 三个宇宙教会本宇宙的事

- A 教会：**渲染与数据结构必须在第一天就是自己的**（4.2 边界）；
- B 教会：**预置的类型越多，用户的语言越少**（2.4/5.1）；
- C 教会：**本地不是架构选择，是伦理选择**（GG.3）。

本宇宙（本总案）不是三者的折中——它拒绝了三者的前提，才保住了自己的前提。

# 附录 YYY 一页纸总案（浓缩版，传阅用）

> 把 10 万字压进一页。给没时间的人，也给十年后想快速回忆的人。

**它是什么**：一个可以居住的知识世界。独立 Windows 软件 + Variable 系统原生应用 + VARIX 内核内建模块，三副外壳共享一个 no_std Rust 核心与一份开放格式知识库。

**它的信仰**：理解始于私人隐喻；压力被拒绝而非管理；最少的定义、最深的组合；本地优先、永不锁定；你的度量衡是你用自己的话重说了多少东西。

**它的模型**：一切皆节点，节点间唯连接。私人语言是数据第一层。128 位 ID、邻域有限、追加式日志、外存分层——架构从第一天就按 100 亿条设计。

**它的体验**：阅读（书）、图谱（地貌）、漫游（散步，灵魂形态）、书写（零仪式落笔）。暗夜微光的艺术方向，灯火呼吸的世界。

**它的性能**：稳定 80 帧（12.5ms 预算 + 三级 LOD + 帧预算哨兵降级链）；冷启动 2 秒；渲染量与数据总量无关。

**它的开放**：格式人类可读、双向导出、永不锁定；syscall ABI 冻结；WASM 三通道让内核接受所有语言；Unreal 是第四外壳；插件即节点。

**它的成熟**：第四条门禁（哲学断言居首）；崩溃恢复全覆盖；基准趋势入 CI；DoD 十条；dogfood 一票否决。

**它的道路**：第 0 步定稿 → 第 2 步最小可用世界 → 第 4 步渲染引擎 → 第 6 步 Variable → 第 7 步内核 → 第 9 步 Unreal → 第 10 步规模攻坚。可用性先行于完整性。

**它的一句宪法**：这里有多少东西，被你用自己的话重新说过了一遍。
