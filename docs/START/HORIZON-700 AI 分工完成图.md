# HORIZON-700 AI 分工完成图（完整版 · 内核成熟化第四阶段）

> 共 **35 个 AI（AI-01 ~ AI-35）**，围绕 **Varix 内核的终极成熟**全域分工，每域 20 项，合计 **700 项功能（H001~H700，H = Horizon）**。
> **本版已去除**：本地部署 AI（大模型/多模态/RAG/智能体/模型安全/分布式推理/智能编译）、摄像头 ISP、前沿密码学（后量子/零知识/同态/MPC/隐私检索/可验证计算/抗量子迁移）、触觉反馈。
> **界面域（AI-06~AI-21，W2 外观 + W3 交互工具，16 域）按「设计优先」分工**：不是罗列 UI 功能，而是**真正设计这个内核的界面 / UI / 视觉**——设计系统 → 视觉 → 简单操作 → 大量实用自定义，并**去除一切影响操作、手感、视觉的负担**。
> 状态：⬜ 未开始 / 🔶 进行中 / ✅ 完成
> 纪律：
> 1. 每个 AI 只新增/修改 `kernel/varix/src/` 内自己域的模块；确需改 VARIX/PULSAR/QUASAR/TRINITY 既有模块时先登记为「依赖收口」并同步对应文档。
> 2. 共享文件（本图、总步骤图、全景图）编辑前先 `git log` 验 HEAD（并行会话防覆盖）。
> 3. 完成一项：更新本图 → commit（`horizon700(ai-XX): Hxxx <功能名>`）→ 推送 GitHub。
> 4. 十四律军规：不重复、极其实用、高质量、可优化的、有创造力、开放性、艺术性、极具创新性、完善性、可拓展性、完整性、野心性、基础功能、细节优化。
> 5. 编号从 AI-01 起，H 编号从 H001 起，连续无跳号。

## 跨路协作约定（并行会话防冲突）

1. **共享热点文件**：三份 HORIZON MD（本图/总步骤图/全景图）整文件重写会抹掉他路进度——增改保留各自标记段。
2. **内核目录边界**：AI 只写自己域目录；`lib.rs`/`mod.rs` 的模块声明由 AI-35 统一收口，其他 AI 不碰。
3. **VARIX/PULSAR/QUASAR/TRINITY 依赖收口**：确需改其模块时，先在对应文档登记「HORIZON 依赖收口」，避免跨计划互相覆盖。
4. **与 TRINITY 的边界**：渲染栈/桌面壳属 TRINITY，syscall 入口属 TRINITY AI-12，共享卷属 TRINITY AI-03/04——HORIZON 的界面域只做**体验增强层（设计系统/主题/动画/小部件/手势/声音/多显示器/文件管理器/终端等）**，经「依赖收口」登记，不重复实现。
5. **设计优先约定（W2/W3 专属）**：AI-06 的设计令牌是 AI-07~21 的共同地基，先立令牌后做视觉；每域交付必须附「操作步骤数 / 手感帧率 / 视觉一致性」三项自检，去负担清单（全景图 0.5）逐条打勾。
6. **commit 规范**：`horizon700(ai-XX): Hxxx <功能名>`；一处一提交，不混批。
7. **完成即自检**：交付 = 代码 + CheckSet 自检 + 更新本图状态，三者缺一不算完成。
