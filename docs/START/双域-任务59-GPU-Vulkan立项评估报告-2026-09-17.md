# GPU Vulkan 加速立项评估报告（任务59 · AI-K · 2026-09-17）

总案口径：GPU 通道分层阶段归档 Vulkan 后端立项评估（范围/风险/里程碑）；〔完善性="当前软件渲染兜底"双落点声明〕——落点一=本报告，落点二=`kernel/varix/src/quota.rs` 模块注释与 `SoftGpuChannel`。

## 结论

- **分阶段立项可行；当前阶段只启动 M1（显示通路加速），M2 起为长线**——与总案开放改进点"GPU 加速渲染（阶段 7 后长线）"一致。
- **软件渲染兜底不变**：`GpuChannel` trait（任务56 冻结）之下 `SoftGpuChannel` 永久保留为默认后端，Vulkan 后端任何阶段失败都回退软通道，不阻塞引导、不破回归。
- 定位：Vulkan 后端是**渲染加速通道**，不是显示服务替代——displaysrv（任务20）Surface/双缓冲/脏矩形语义不变，加速只发生在" Surface→屏幕"的搬运与合成层。

## 范围（要做什么）

- [ ] **M1 GPU 显示通路**：virtio-gpu 探测（PCI class 0x03/QRexx 走 ECAM 扫描）+ 2D 资源路径（resource create / attach backing / BLIT / FLUSH）→ displaysrv commit 的搬运从 CPU memcpy 换 DMA 加速；软件合成保持
- [ ] **M2 直通渲染评估**：QEMU `virtio-gpu-gl`（venus context）实测——host Vulkan passthrough 可用性、virglrenderer 依赖版本、Guest 侧 context 协议开销；**先出实测数据再决定 M3 是否继续**
- [ ] **M3 GpuChannel::Vulkan 后端**：实现同一 trait（kind="vulkan"）：reserve/submit 映射 GPU 命令缓冲提交；与 SoftGpuChannel 同进程可切换（探针级 A/B）
- [ ] **M4 双后端回归**：软/硬后端切换矩阵 × 帧一致性校验（png_probe 像素对照）；软件渲染路径零改动断言
- [ ] 明确不做：compute/游戏级 3D 管线、GPU 虚拟化多租户、反作弊场景（走纯 Windows 通道）

## 风险与对策

- R1 venus 依赖 host Vulkan + virglrenderer 版本组合 → M2 先实测再立项（本机 QEMU 若不支持，M3 无限期搁置，M1 成果保留）
- R2 内核无 GPU 命令提交栈/无 MSI → virtio-gpu 纯轮询模式（沿 NVMe phase 位范式）；中断虚拟化明确不做
- R3 帧通路回归 → SoftGpuChannel 永久兜底 + M4 像素级对照门禁；任何不一致直接回退软后端
- R4 范围蔓延（3D 管线/compute 诱惑）→ 本报告"明确不做"清单即边界，超界需重新立项
- R5 PMM 压力（backing 大量帧）→ 接内存水位服务（任务56 MemWatermark，回收级1 ramcache 优先让位 GPU backing）
