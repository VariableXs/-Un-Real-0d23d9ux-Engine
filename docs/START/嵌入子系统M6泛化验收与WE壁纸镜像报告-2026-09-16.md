## 本轮发现并修复的缺陷（2 个）+ 环境取证结论

### 缺陷 1：自动收编抢夺键盘焦点（M6 主缺陷，实机复现）

- **现象**：看门狗收编后台窗口（Edge/QQ/微信）后 13~62 秒窗口「无人碰却自己关闭」。
- **取证过程**：3 个假象逐一排除——①EmbedBridge 守卫/收编竞态（无证据）；②应用崩溃（事件日志无崩溃记录）；③收编必死（3 分钟完全静默下 Edge 嵌入存活 170s+）。最终定位：`openVwmTpNew` 无条件设 `focusedId` → `embedFocus` → SetForegroundWindow，**把用户正在打字的前台抢走**，用户后续按键（Ctrl+W/Alt+F4）直接进了被收编窗口。
- **修复**：`openVwmTpNew(app, focus=false)`——watchdog popup/escape 两条自动收编通道不再抢焦点（仅用户显式启动聚焦）。
- **验证**：修复后 3 分钟静默 Edge 嵌入存活 170s+；四应用全生命周期复测无一自灭。

### 缺陷 2：WE 的 `-control openWallpaper` 按 ANSI 解析中文路径（WE 侧限制，已防御）

- **现象**：切换到含中文文件名的壁纸（恋死花海木偶壁纸.mp4）后，WE 把 U+FFFD 乱码路径写进自己的 config.json，Variable 跟随后视频 404（桌面黑+「背景文件缺失」）。
- **修复**：①`we_wallpaper_open` 路径含非 ASCII 时改传同目录 `project.json`（恒 ASCII，WE 自己以 UTF-16 内部传递 → config 写回正确中文）；取不到时回落 8.3 短路径，再不行如实报错；②`we_wallpaper_current` 跳过磁盘上不存在的条目，绝不镜像坏路径。
- **恢复动作**：已用 project.json 通道把用户壁纸恢复为恋死花海（config 码点验证零乱码）。

### 取证结论（非缺陷）

- **「窗口自灭」三假象**：收编竞态（已 M5 修复）、应用崩溃（事件日志无记录）、收编必死（静默实验证伪）——真因是缺陷 1 的焦点抢夺叠加用户正常操作。
- **测试期污染源**：用户双击 Esc（幕帘/维护模式，看门狗暂停 → QA 假「无 attach」）、用户从 Variable 启动 Steam（自愈式窗口重建）、微信/QQ 未登录二维码超时自退。QA 结论：**涉及真实第三方应用的验收必须控制前台输入**。
