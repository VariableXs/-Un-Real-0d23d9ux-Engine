## 宿主用例（8/8 passed）

| 用例 | 验收点 |
|---|---|
| `kv_powercut_x10_zero_loss` | 断电恢复 ×10：每轮 3 键写入 + 上轮 1 键删除 → 收回盘面重开 → 全量逐字节断言零丢失 |
| `kv_torn_journal_head_drops_tail_entries` | 账本槽半写（仅前 16B 到达 → tag/crc 缺失 → Bad）→ torn 语义该点及之后丢弃 → 旧值完好 |
| `kv_torn_overflow_tail_falls_back` | 溢出槽半写（值截断 → fnv 败）→ 该条目忽略 → 回退更早条目（零丢失） |
| `kv_full_capacity_explicit_error` | 账本 64 条满：第 65 次 set/remove → `Err(Full)` 明确报错；既有键仍可读 |
| `kv_overflow_and_journal_full_explicit_error` | 大值路径双资源同步耗尽：第 65 次 → `Err(Full)` |
| `kv_namespace_isolation` | ns 互不可见/互不可删；keys 按命名空间过滤 |
| `kv_semantics_edge_cases` | remove 不存在=no-op；超限/坏名报错；末写生效；0 长值合法；DEL 后重写生效 |
| `kv_large_value_roundtrip` | 60KiB 溢出往返逐字节；覆盖后旧槽垃圾化（差异公示）；边界值=OVERFLOW_MAX；跨重开持久 |

## 实机证据（QEMU q35 双 NVMe，串口日志 `kv24-session{1,2}.log`）

```text
-- 会话1（空盘 init 512MiB）--
[ INFO] kvsrv: session=1 keys=10 remaining=53 verdict=ok
[ INFO] ring3: task15 lifecycle complete — 2 轮 spawn/exit/wait + 压力探针全过 — halting
（驱动脚本 kill QEMU = 断电）
-- 会话2（同一盘面重启）--
[ INFO] kvsrv: powercut-recovered verdict=ok recovered=10     ← 前会话 10 键跨断电零丢失
[ INFO] kvsrv: session=2 keys=20 remaining=42 verdict=ok      ← boot-counter 1→2 累加 + 本会话 10 键
[ INFO] ring3: task15 lifecycle complete — 2 轮 spawn/exit/wait + 压力探针全过 — halting
```

- 异常扫描：两会话 PANIC 计数 0；账本条目数审计（10+1 counter → remaining=53；+11 → 42）与 64 条容量语义精确吻合。
- 排障记录（宿主阶段抓到，实机前消灭）：①初版 `append_entry` 载荷未落盘（DiskJournal::append 只写 24B 头）→ 新增 `append_slot` 载荷与头同块原子写——顺带强化了持久化语义（键值与账本单块原子）；②撕裂注入模型修正为「前缀到达」（清零模型会把槽伪装成 Empty）；③测试盘容量 < 账本区 LBA 越界 InvalidRange。
