# S4.3 · GPU 加速评估报告 —— AI-5 内核基建长线

> **步骤卡**：S4.3 GPU 加速（评估→POC→落地三段；IOMMU 评估为开工前置，无隔离不开工）。
> **状态**：评估完成，**POC 待拍板**。结论先行：**当前内核架构下 GPU 直通加速是高风险高工程量项，短期收益最高的是"软件渲染优化 + 可选硬件光标"这类低风险增量；真正的 GPU 加速必须以 IOMMU 隔离成立为前提，建议排到 S4.2 之后**。

## 1. 现状盘点

| 事实 | 证据 |
|---|---|
| 渲染通路 = Servo/自绘栈直接写 GOP 帧缓冲（Limine framebuffer），软件渲染 | `fb.rs`/`display.rs`/`displaysrv.rs` |
| 分辨率走 Limine 预设（QEMU 1024×768 等），无模式切换驱动 | `limine.rs` framebuffer 响应 |
| 真机目标 Legion Y7000 IRX9：Intel UHD Graphics（iGPU，IOMMU 可开）+ RTX 4060（dGPU） | 实机档案 |

| 帧率瓶颈实际分布：TCG 下 QEMU 走查无法测真机帧率；真机瓶颈未实测 | 无基线数据（诚实声明） |

## 2. 三条路线评估

### 路线 A：Intel iGPU 直通加速（NC/2D blit + 显示控制器）

- **能拿到什么**：iGPU 的显示控制器接管扫描输出（可做modeset 换分辨率）、2D blit（memcpy 级加速）、硬件光标平面；3D（i915 级）工程量不可行。
- **前置硬条件**：**VT-d/IOMMU 隔离成立**——GPU 是全场最大的 DMA 发起者，无 IOMMU 时任何一个错误的 GPU 页表项 = 任意物理内存读写的后门，直接撞"内存不受威胁"红线。IOMMU 成立的定义：DMAR/RTD 表解析 + 每设备页表 + 翻译使能 + 故障注入测试（故意 DMA 越界 → IOMMU 拦截 → 内核活着）。
- **工程量**：IOMMU 栈 ≈ 2-3 周；iGPU KMS 级 modeset/blit ≈ 2-4 周（Intel 显示控制器文档公开但寄存器面巨大）；合计 5-7 周，且真机调试占比高（QEMU 的 igd 模拟 ≠ 真硬件）。
- **风险**：高。GPU 挂掉 = 屏幕黑，恢复路径必须依赖 PS/2 串口救砖范式（串口常驻证据行 + 引导期降级开关）。

### 路线 B：virtio-gpu（QEMU 内完美、真机无用）

- 仅适用于 QEMU 演示形态；真机（Legion 裸机）没有 virtio 设备。**不建议作为主路线**，仅作为 POC 的低成本演练场（协议栈与显示栈解耦工作可先在 QEMU 验证）。

### 路线 C：不加 GPU，优化软件渲染（低风险高确定性）

- 现栈的可做项：脏矩形已设计（display 双缓冲+脏矩形滚动条带已有基础）→ 补全：合成器脏区合并、字体位图缓存、墙纸层独立化（静态墙纸不重绘）、128bpp→32bpp 直拷路径 SIMD（SSE2 手写，no_std 可用）。预期把合成路径带宽降 3-5 倍——**大概率覆盖"桌面流畅"目标而零安全风险**。
- 顺手的低风险硬件增量：**硬件光标**（XGA/VGA 硬件光标平面是 x86 兼容保留项，几行寄存器 + 一个位图，无 DMA）——鼠标体验立竿见影。

## 3. 结论与开工前置

1. **立即做（本批内可并行）**：路线 C 的软件渲染优化 + 硬件光标。零 IOMMU 依赖、零 DMA 风险、QEMU 可验。
2. **IOMMU 栈单独立项**（S4.3-IOMMU）：这是 GPU/网络/任何未来 DMA 设备的共同地基，工程价值独立成立。拍板后 2-3 周交付「DMAR 解析 + 设备页表 + 拦截注入测试」。
3. **GPU POC 在 IOMMU 验收之后**：以「QEMU IGD 2D blit POC」起步（文档公开、寄存器面小子集），真机 POC 需实机安全三问全套走查（SOP 1.8）。
4. **帧率/功耗对比归档**：路线 C 完成后建立 docs/bench/ 基线（合成器帧时间 P95），作为后续 GPU 是否继续投入的判据——**数据先行，不凭感觉上 GPU**。

## 4. 红线对照

- GPU DMA 是「内存不受威胁」红线的最高风险面：**无 IOMMU 不开工**（步骤卡原文），本报告将该闸落为可验证的 IOMMU 验收标准（拦截注入测试 PASS = 闸开）。
- 实机调试遵守 1.8 SOP；GPU 驱动崩 → 引导期 `gfx=off` cmdline 降级开关常备（黑屏救砖路径在步骤卡先写死再动工）。
