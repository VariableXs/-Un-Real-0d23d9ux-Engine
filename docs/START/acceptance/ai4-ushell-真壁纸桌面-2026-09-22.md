# AI-4 · ushell 真壁纸桌面（三世界同源）验收记录

> **定位**：R2 ushell 保底桌面的视觉升位——「进内核桌面看到与 Windows 一样的
> 壁纸」（用户终态验收目标之一）。2026-09-22 交付。

## 1. 交付内容

- **内核 `wallpaper.rs`**：1280×720 RGB565 壁纸常驻（Limine 模块装载进 .bss）、
  最近邻缩放整屏 blit、像素采样（供削角回填）、模块缺席/损坏=回退色带。
- **FRAME 扩展**（`proc/usrshell.rs` sys_frame）：`FRAME_WALLPAPER=7`（整屏）、
  `FRAME_WALLPAPER_PX=8`（采样，a2=x|y → 0xRRGGBB）、`FRAME_FILL_RGB=9`
  （原色填充，a2=xywh、a3=0xRRGGBB）。
- **ushell**：`Ui::wallpaper()` 走真壁纸（回退三段色带）；`cut_corners`
  削角回填从「段色近似」升级为「该处壁纸真色」（逐像素无痕）；浮层/菜单/
  任务栏绘制链零改动。
- **打包**：`make-iso-qemu.py` 可选装入 `wallpaper.rgb565`（缺席=不打包，
  内核回退）；ESP 部署脚本（`esp-deploy-switch.ps1`）新增壁纸部署步骤
  （备份+哈希校验）。

## 2. 壁纸来源（三世界同源）

## 3. 根因取证（两次引导级失败，均已定位并修复）

### 3.1 include_bytes 进 .rodata → fatal #PF
- **现象**：1.8MiB `include_bytes!` 进内核 .rodata 后，引导在 mem 初始化后
  fatal #PF（err=3，写只读页；`_attic/t7-crash-serial.log`）。
- **二分**：同尺寸 `[0; N]` 进 .bss → 引导正常 ⇒ 大初始化资产进 .rodata
  使 RW 段整体后移触发布局敏感缺陷（ Limine 映射与内核自检的交界，
  精确机理待后续取证，规避方案已固化）。
- **修复**：资产走 Limine internal module 通道（.bss 装载实测安全），
  内核映像零膨胀，壁纸可独立替换。

### 3.2 internal module 子目录路径 → 引导黑屏挂死
- **现象**：module 路径 `../boot/wallpaper.rgb565`（子目录）→ SeaBIOS 后
  黑屏、串口零输出（Limine 阶段挂死）。
- **二分**：根级路径 `../wallpaper.rgb565`（同文件、同尺寸）→ 装载成功
  （`wallpaper: loaded 1843200 bytes`）。
- **结论**：Limine internal module 在 ISO9660 上对**子目录路径**存在缺陷
  （或路径解析限制）——资产模块一律放卷根；已在源码注释与本记录双落点登记。

### 3.3 战役脚本引导序（非内核问题，一并记录）
- 共享镜像 VBR 带 0xAA55 签名 → SeaBIOS 将其视为可引导硬盘抢先引导 →
  黑屏空转。战役脚本补 `-boot order=d`（DVD 优先）。
