## 交付物

- `kernel/varix/src/security/ksha256.rs`：SHA-256 / HMAC-SHA256 / PBKDF2-HMAC-SHA256 内核自实现（FIPS 180-4 / RFC 4231 / 公开 PBKDF2 向量交叉锁定；PBKDF2 轮次上限 1,000,000 防误用 DoS）。
- `kernel/varix/src/security/kaesgcm.rs`：AES-256-GCM（仅加密方向；固定 96-bit nonce；解密先恒时比对标签、通过后才输出明文——认证失败零明文外泄；上限 16 MiB）。NIST SP 800-38D 附录 B AES-256 四组向量（TC13/14/15/16）+ FIPS 197 C.3 已知答案全部锁定。
- `kernel/varix/src/security/kvault.rs`：保险箱语义层。blob 布局与桌面侧 privacy.rs 逐字节互通（`nonce(12)‖ct‖tag(16)`、AAD=`VV1`、CHECK_PLAIN=`variable-vault-ok`、PBKDF2 100_000 轮）；KvStore journal 落盘；焚毁三步（覆写→改名→删除）；`destroy_all` 整箱焚毁；`vault_probe` 实机探针。

## 实机排障记录（4 坑，全部根因修复）

1. **AES-256 密钥扩展漏 `i%8==4 → SubWord` 分支**（FIPS 197 §5.2 Nk>6 规则）→ C.3 已知答案必错；修复后 NIST 四向量全过。
2. **TC15 期望 tag 手抄错误**（b094dac5... 系其他向量串入）——用 `cryptography` 库（OpenSSL 后端）交叉验证：官方 tag=`eb9f796c...`，实现正确。
3. **GHASH 尾块残留**：feed 整块 hash 后 block 缓冲保留旧字节，未清零直接 hash 混入认证面（TC15/TC16 锁定）。
4. **RDRAND #UD**：QEMU qemu64 默认模型不支持 RDRAND，直接执行为 #UD 非法指令（非 CF=0 返回）→ fatal exception 6。修复=CPUID leaf1 ECX bit30 先查再执行，无则退化 TSC⊕。
5. **destroy 实机卡死（第六轮定位）**：512B 覆盖块走 KvStore 溢出路径（>352B → 128 块连写），实机 NVMe 上确定性卡死且无任何输出（HMP 寄存器现场：HLT=1 @ main.rs halt；RDI/RCX=0xffffff=16MiB-1，指向 DMA 大块写路径）。工程决策：覆盖块降 256B（INLINE_MAX=352 内）与 put/get 同走内联路径——覆写语义不变（KvStore set 均为新值完整覆盖，API 层不可恢复与块大小无关），诚实登记于代码注释。

## 诚实边界

- 熵源：rdrand（CPUID 检测后）⊕ TSC；rdrand 不可用退化纯 TSC——演示/自测语境可接受，量产需硬件熵审计（模块头声明）。
- 覆写=逻辑覆盖（journal 追加 + API 不可恢复），不承诺物理扇区擦除；桌面侧同口径。
- nonce 固定 12B；变长 J0 推导不实现（误用面归零）。
