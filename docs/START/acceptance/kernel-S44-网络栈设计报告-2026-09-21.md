# S4.4 · 网络栈设计报告（最小协议集 + 防火墙默认拒绝）—— AI-5 内核基建长线

> **步骤卡**：S4.4 网络栈（协议栈最小集；内核侧防火墙默认拒绝先行设计）。
> **状态**：设计完成，**动工待拍板**。定位：给"Steam 客户端通道二"（Wine 路线）与内核 Servo 视图上网提供前置能力的最小栈——**不是**通用网络栈。

---

## 1. 需求边界（从功能全景图倒推）

| 消费方 | 需要什么 | 决定的边界 |
|---|---|---|
| 内核 Servo 视图（日常网页） | TCP + DNS 解析 + TLS 由 Servo 侧rustls 级组件承担 | 内核只做 IP/TCP 传输层 + 网卡驱动 |
| Wine/Steam 客户端（通道二，远期） | 完整 TCP/UDP + 足够的吞吐 | 同上；性能靠 NIC 多队列/中断（远期） |
| 安全承诺 | 内核侧默认拒绝、白名单放行 | 防火墙先行设计（本报告 §4） |
| 明确不做 | WiFi（802.11 全栈）、蓝牙、隧道协议、IPv6（首版） | 真机 Legion 的有线 RJ45 + USB 网卡（随 S4.1 xHCI 生态白送 CDC-ECM 路径） |

## 2. 分层设计（最小集冻结）

```
[网卡驱动]  e1000(e1000e)——QEMU/真机覆盖面最广，寄存器面小，MMIO+DMA 描述符环
            （QEMU: -device e1000e；真机 Legion I219 系 e1000e 兼容）
    ↓
[以太网]    帧收发 + ARP（请求/应答/缓存表，表项老化）
    ↓
[IPv4]      收发 + 校验和 + 分片重组（最小实现：重组仅限 TCP 必需路径）+ ICMP(echo 应答，诊断)
    ↓
[UDP]       无连接最小收发（DNS 客户端走这里）
[TCP]        — M1 连接建立/关闭（三次握手/FIN）+ 停等窗口（window 固定，简单重传）
             — M2 滑动窗口 + 快速重传 + 乱序重组（吞吐到"能用"档）
             — M3 拥塞控制（NewReno 级）——远期
    ↓
[socket 抽象] 内核内 API（bind/connect/send/recv 最小集）+垫片通道预留（S2 命令面挂接点）
```

- **驱动候选评估**：e1000e（首选，文档充分+QEMU 原生）> virtio-net（QEMU-only）> USB CDC-ECM（真机 USB 网卡，依赖 S4.1/S4.2 的 xHCI 框架，可作为无 PCIe 网卡机器的备选）。RTL8168 真机驱动文档差，不做。
- **测试方法论**：与 NVMe/xHCI 同款——宿主"网线对端模拟器"（以太网帧级应答模型）全链用例 + QEMU 两机互 ping/互传（user 网络或 socket 网桥）实证。
- **里程碑**：M1 ARP+ICMP ping 通（≈2 天）→ M2 TCP 停等 + HTTP GET 裸响应（≈3 天）→ M3 滑动窗口吞吐基线（≈4 天）。全宿主可测，QEMU 只做终验，真机接触点仅插网线（零引导风险）。

## 3. 与既有架构的衔接

- **垫片命令面**：网络能力经 S2.02 三色审计登记（初期几乎全 ❌ → M2 后 🔶），前端可见能力随里程碑收敛，绝不静默暴露半成品 socket。
- **Wine 通道**：Wine 侧网络走 Wine 自己的栈转发到内核 socket 抽象（设计预留，不在本件范围）。
- **无 IOMMU 依赖**：NIC DMA 描述符环的缓冲来自内核 PMM（同 NVMe/xHCI 模型），接收环写入由驱动预算的固定缓冲区承接——在 IOMMU 落地前，NIC 的 DMA 面通过"描述符环只指向专用缓冲池"收敛（网卡无法发起任意地址 DMA 的前提 = 驱动只把专用池地址填进描述符环，该约束由代码审计 + 用例看护）。

## 4. 内核侧防火墙——默认拒绝先行设计（本件核心交付）

**设计原则：默认拒绝不是"防火墙功能"，而是"栈的行为"——没有放行规则的包根本进不了协议栈。**

```
                 ┌─────────────────────────────┐
 NIC 收包 ──→ [ L0 入口闸 ] ──拒绝──→ 计数器+审计行，包丢弃
                 │  ① 驱动层：接收环只落专用缓冲池，越界 DMA 物理不可能
                 │  ② 栈层：以太网类型白名单（IPv4/ARP 放行，其余丢弃）
                 │  ③ IP 层：目的地址必须属于本机接口地址；分片上限；
                 │     ICMP 类型白名单（echo/目的不可达）
                 │  ④ TCP/UDP 层：无监听 socket 的包一律 RST/丢弃
                 │  ⑤ socket 层：连接级白名单（默认拒绝，放行=显式规则）
                 └─────────────────────────────┘
 放行规则来源：内核 cmdline 显式声明（net.allow=tcp:443 等）+
              settings:// 总线运行期登记（vfsguard 同款"能力申请式授权"）
 审计：拒绝事件走既有审计账本（vfsguard 审计范式），可回放可出报表
```

- **出站策略**：进程发起的连接同样过白名单（默认拒绝出站连接 = 与"每进程 Job 限额+Seccomp 白名单"同构的安全语义）。
- **可测试性**：L0-L5 每层闸做成纯函数决策器（包描述符进 → ALLOW/DENY 出），宿主注入矩阵用例全覆盖（含畸形包 fuzz：坏校验和/超长分片/端口 0/IP 选项越界）。
- **验收口径**：①默认拒绝矩阵全绿 ②fuzz 1000 组不崩 ③放行规则单条生效验证 ④审计账本可回放 ⑤QEMU 双机 ping/HTTP 实证。

## 5. 风险与依赖

- TCP 拥塞控制远期才做 → 吞吐短期不及格（诚实声明：M2 档"能用但不快"，Steam 通道二至少要 M3）。
- 与 IOMMU 的关系：专用缓冲池约束是 IOMMU 落地前的过渡安全边界；IOMMU（S4.3-IOMMU）落地后自动升级为硬件隔离。
- 本件不阻塞三体主线（Steam 是远期功能）；优先级建议排在 S4.2 MSC 之后、GPU POC 之前。
