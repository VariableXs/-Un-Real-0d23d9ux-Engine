# S4.5 · 内核 VMX 评估报告 —— AI-5 内核基建长线

> **步骤卡**：S4.5 内核 VMX 评估（只评估立项，不冒进；产出评估报告归档，拍板后才施工）。
> **状态**：评估完成。结论先行：**技术上成立、工程上"能做但不该现在做"——建议维持 Hyper-V 过渡形态至 M4 之后，内核 VMX 作为 S5 批的远期立项**。

---

## 1. 问题定义

隐形 Windows 引擎（第 3 批）当前用 **Hyper-V 过渡形态**：VARIX 内核里跑不了 Tauri/WebView2（Windows API 依赖），Windows 引擎以 VM 形态在 Windows 侧运行，画面流进内核。内核 VMX = 由 VARIX 内核自己做 hypervisor，直接在 U 盘引导的内核里启动 Windows 引擎 VM——省掉"先引导 Windows 再跑引擎"的整层。

## 2. 技术可行性（逐项盘点）

| 能力项 | 内核现状 | VMX 需要 | 缺口评估 |
|---|---|---|---|
| CPU 虚拟化入口 | 无 | VMXON 区域、EPT 建立、VMCS 初始化、VMLAUNCH | 3-4 周纯工程，Intel SDM 卷 3C 路径清晰 |
| EPT 二级地址翻译 | 无（页表栈是自研的） | EPT 页表 + EPT violation 处理 + 内存记账 | 2-3 周；与现有 pfh 体系需刻意隔离防纠缠 |
| 多核调度配合 | SMP 已实机（AP 启动/MTTCG 陷阱经验） | vCPU 绑核或轮转调度、VM-exit 成本控制 | 1-2 周 |
| 设备直通 | xHCI/NVMe 自有栈在位 | 引擎 VM 需要 USB/存储透传（DMAR/IR remapping 或软件模拟设备） | **最大缺口**：要么 IOMMU+中断重映射（2-4 周），要么 virtio 模拟设备（Windows 侧装驱动，3 周） |
| Windows 引擎镜像 | Hyper-V 形态已设计（W2 差分链） | 直通形态的镜像需重装/重配（虚拟硬件拓扑全变） | 镜像重制 + 部署链改造 |
| 画面流 | picflow 全链已在位（VM 帧源→显示栈直写） | 直通形态下画面流来源从 Windows 帧通道换成 VM 帧缓冲 | 1 周适配 |

**合计工程量：8-14 周（2-3.5 个月）专职投入**，且真机调试占比高（VMX 只能真机验，QEMU 的 TCG 不执行 VM 指令路径——QEMU 加速态可用但非目标环境）。

## 3. 风险盘点（对着实机安全宪法逐条过）

1. **红线二（内置盘）**：VM 直通内置盘任何控制器 = 红线直接击穿。直通形态下引擎 VM 只能挂 U 盘 WIN_ENGINE——**WIN_ENGINE 分区现在是 Windows 可引导分区（双系统），VM 直通它 = 两套"操作系统视角"同时写同一 NTFS**，日志/卷影/BitLocker 状态机全部冲突。需要引擎镜像迁移到独立 VHDX（差分链 Base 只读 + User 层可写，恰好复用 W2 设计）——架构可行但部署链要重构。
2. **红线一（硬件）**：VMX 本身零固件写入 ✓；但中断重映射（IR）配置错误可能打死 LAPIC——需要引导期 VMX 失败即整体降级回非 VMX 路径的硬闸（`vmx=off` cmdline + 探测失败自动回退，永不卡引导）。
3. **稳定性风险**：hypervisor 是比设备驱动高一个数量级的复杂度（VM-exit 路径 ×100、EPT 一致性、TSC 偏移……）。当前内核 2 万行核心链的体量上叠 8-14 周的 VMX，回滚成本极高——**必须独立成 git 可整批回退的模块**（S2 批"每步打 tag"纪律的放大版）。
4. **收益对照**：Hyper-V 过渡形态已满足"隐形引擎"功能（S3 批验收口径），VMX 的真实收益 = 省掉引擎形态的 Windows 引导依赖 + 更低延迟。在 M4（引擎可用）达成之前，这个收益是"锦上添花"，不是"不可替代"。

## 4. 建议（供拍板）

1. **维持 Hyper-V 过渡形态至 M4 验收完成**——S3 批不受本评估影响，照常施工。
2. **S4.5 不开工 VMX 本体**；唯一建议提前做的子项 = **VMX 硬件能力探测**（CPUID VMX 位/IA32_FEATURE_CONTROL 锁定位读取，纯只读，半天，QEMU 可测）——把"这台机器能不能跑 VMX"从推测变成引导日志里的实测证据行，为后续拍板供数。
3. 若 M4 后拍板立项：按「EPT 先行（纯内存域）→ vCPU 环（无设备 VM）→ virtio 设备 → 直通」四段走，每段独立验收可回退；全程与实机安全宪法三问对表，IOMMU（S4.3-IOMMU）作为直通段硬前置。
4. 终局形态的诚实预期：VMX 落地后仍是"一个 VM 跑 Windows 引擎"，不是"Windows 融进内核"——物理边界（功能全景图 §6）不因 VMX 改变。

## 5. 探测子项的实现锚点（若获准做）

- CPUID leaf 1 ECX bit5（VMX）；IA32_FEATURE_CONTROL（MSR 0x3A）bit0 锁定 + bit2 VMX-in-BIOS-enabled；真机 Legion = 13 代酷睿，VMX 能力必然在位，真正的变量是 BIOS 是否锁 VMX-off——探测行会给出实测答案。
