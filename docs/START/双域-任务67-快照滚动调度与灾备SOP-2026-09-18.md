## 1. 快照滚动调度（P3 三级缓冲兑现）

- [x] 三级缓冲语义冻结：**删到回收站（默认）→ 回收站清空前入快照（保 7 天）→ 快照滚动淘汰**（总案 P3 台阶）。
- [x] 快照区位置：SHARED 盘 SNAPSHOT 目录（任务 18 exFAT 只读挂载侧）；VARIX 侧只读消费，写入由引擎半区/桌面进程发起。
- [x] 滚动调度表（快照区容量水位触发，LRU 淘汰序）：
  - 每次快照写入后检查 SNAPSHOT 占用；
  - 占用 ≥ 80% 容量 → 从**最旧一代**开始逐代淘汰，直到 < 60%；
  - 同代内按创建时间淘汰（最旧优先）；
  - 「7 天保活」优先级高于水位淘汰：未满 7 天的代**不可被水位淘汰**（容量真满时如实拒绝新快照并提示用户，绝不静默清掉保活期内数据）。
- [x] 调度触发点：桌面会话空闲（前台 5 分钟无交互）批量执行；关机序列 FlushDirty 步骤前强制落盘（任务 52 ramcache purge 与本表同序——**先快照落盘、后缓存清空**，顺序不可交换）。

## 4. 「什么救不回来」诚实清单（如实边界，不伪造救援能力）

- [ ] **未入快照的近期写入**：从上次快照到损坏时刻之间的 SHARED/桌面数据增量，不在快照内——能救回的上限=最后一次快照状态。
- [ ] **保险箱（kvault）数据**：密钥仅内存 + 焚毁语义（任务 65）——焚毁过的数据**在任何备份/快照里都不存在**（设计如此，非缺陷）；盘面损坏波及密文块时，口令正确也无法恢复损坏块。
- [ ] **会话级 KV（RamBlk 后端）**：ushell 设置存储是 RAM 后端（任务 27 如实标注"session 级"）——断电即失，**本来就不承诺持久**；盘面 KV（LBA 60000）是另一套持久通道。
- [ ] **未导出的剪贴板/便签等易失工作集**：内存态，无盘面副本。
- [ ] **快照保活期冲突**：容量真满且全部在 7 天保活期内时，新快照被拒绝（不淘汰保活数据）——用户必须手动清理才能继续快照。
- [ ] **引擎半区（Windows/VHDX）内部损坏**：本 SOP 只保证 VARIX 侧与 SHARED 交界的数据；VHDX 内部文件系统损坏属 Windows 域灾备，不在本表承诺内。
