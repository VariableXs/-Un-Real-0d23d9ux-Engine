### 0.4 质量军规（作品化版，每项必须全过）

1. **不重复**：立项即对照 2200 项总清单查重，重复项直接砍。
2. **极其实用**：每个功能回答"用户周二下午会用它做什么"，答不出即砍。
3. **高质量**：每项带 CheckSet 自检断言 + 单测；实现质量对标作品集封面页。
4. **可优化**：每项自带仪表（至少一个计数器/直方图），无仪表不上线。
5. **创造力与艺术性**：视觉/听觉/交互项必须有"标志性瞬间"设计说明，
   说不出标志性瞬间的不算完成。
6. **开放性**：格式、API、数据全部有公开规范文档；可被第三方完整复刻。
7. **创新性**：每域至少 2 项"同类系统没有"的原创设计。
8. **完善性**：边缘情况（无硬件/无网/低电/崩溃中）全部有降级路径。
9. **可拓展性**：每项预留 v2 接口位；API 全部版本化。
10. **完整性**：基础功能 → 细节优化 → 艺术表达三层都要有。
11. **野心性**：每域至少 1 项"超出常规预期"的登月项。
12. **崩溃红线**：任何新功能 panic 不拖垮内核；用户态崩溃只回收进程。
13. **性能红线**：新功能不得使输入延迟、合成帧时、启动耗时回退，CI 预算门守关。
14. **完成即自检**：手感/画质/性能/回滚/崩溃五项自检，只留可复现验收。
15. **作品化门槛（本部新增）**：每个域收口时产出一份"域作品页"——
   截图/录像 + 标志性瞬间描述 + 仪表数据，达不到作品集展示水准的项回炉。

## 三、域模块实现约定（AI-01~AI-24 共用）

- 一域一文件：`kernel/varix/src/<domain>.rs`（用户态域放对应 userspace crate）。
- 每域 25 项功能，按 `// Fxxx 名称` 注释分区，纯逻辑 + 固定容量数组
  （无 Vec/String/Box，no_std 红线）。
- 每域必须导出 `pub fn run_<domain>_checks() -> CheckSet`，
  用 `CheckSet::new("domain")` + `set.add("Fxxx ...", cond, "detail")` 逐项断言，自检项 ≥ 25。
- 单测写在模块内 `#[cfg(test)] mod tests`，命名 `f<编号>_<要点>`。
- 内核自检闭环：`robust::run_kernel_checkup()` 汇总各域 CheckSet（聚合时排除 robust 自身）。

### CheckSet 断言铁律（血泪，违者必返工）

- **禁止"末态读取"**：`set.add` 布尔表达式里对可变对象字段的读取发生在表达式
  求值末尾。凡"操作 → 读状态 → 再操作 → 断言"，每个中间读数必须先存进独立 `let`。
- 登记类接口（register/record/add）必须自带**去重**，否则重复登记静默破坏计数断言。
- 调试手法：临时 `#[cfg(test)] mod tmp_dbg` 把复合断言拆成逐条 `assert!`，
  一次定位到具体子条件，**验证完立刻删掉**。
- 自检失败必须 panic 出 `CheckSet::render` 的内容，否则定位不到具体 F 项。

### Rust 实现红线（VARIABLE-200/M400 实测沉淀）

- `const fn` 里不能用 `Ord::min`，手写 if；`[None; N]` 对非 Copy 类型必须
  `[const { None }; N]`；`Result<&mut T, E>` 不能 `assert_eq`，用 `is_err()`。
- fuzz 必须偏置到有效号段（1/4 野生 + 1/4 原生带 + 1/4 兼容带 + 1/4 低位全谱）。
- 清"未用导入"要连带查 `mod tests`；内层 crate 自带空 `[workspace]` 表。

### 隔离验证法

并行会话把别处源码改坏导致 crate 编不过时：把 `checks.rs` + 待验模块复制到
临时 scratch crate（`/tmp/bcverify`，`[profile.test] panic = "unwind"`）单独
`cargo test --lib`，绕开他人的编译错误。

## 四、多会话并行纪律（M600 版）

1. **共享文件**：本图、全景图、分工完成图编辑前必须先 `git log` / 重读文件，
   只改自己域的段落（`## AI-xx ·` 到下一个 `## AI-x` 之间）。
2. **提交前甄别**：`git log --oneline -1` + `git status --porcelain` 先看自己的文件
   是否已被并行会话卷走，避免重复提交或漏提交；绝不 `git add .` 盲提。
3. **模块注册坑**：新域若与既有单文件模块同名，必须在文件顶部显式 `pub mod`；
   `lib.rs` 的 `pub mod` 列表是共享区，提交前复查自己的行还在。
4. **绝对禁止 `git pull --rebase --autostash`**（历史教训：曾报废整个对象库）。
   对齐远端用 `git fetch origin main` + 显式 SHA `git reset --mixed`。
5. **推送通道**：`git -c credential.helper= -c credential.helper=wincred push origin main`，
   代理间歇 502 需循环重试 2~6 次；api.github.com 始终可用，别被它误导。
6. **提交信息**：`varixm600(ai-XX): Fxxx <功能名>`，一功能一提交或一域一提交。

## 五、构建与验收命令（每域收口必跑）

```bash
# 内核自检（主机，应全绿）
cd kernel && cargo ktest --lib
# 内核构建（应零告警）
cd kernel && cargo kbuild
# 打 ISO（必须 xorriso，不能用 pycdlib 产物）
PATH="/tmp/xorr/root/usr/bin:$PATH" bash scripts/make-iso.sh
# QEMU 冒烟（必须 run_in_background，抓 serial 日志到 boot complete）
qemu-system-x86_64 -cdrom varix.iso -serial file:serialM600.log \
  -monitor tcp:127.0.0.1:5560,server,nowait -no-reboot -no-shutdown \
  -m 512M -M q35 -display none
# 抓状态：python tools/qmon.py 5560 "info status" "info registers"
```

致命异常定位流程：串口最后一行 → `info status` → RIP/CR2/err
（`cpu/idt.rs::isr_dispatch` 会打印）→ ELF 符号表回映射 → 反汇编确认。
中断入口段必须放 `linker.ld` 页对齐 `.stubs` 段并 `harden_stub_mapping()` 清 NX；
任何运行时生成代码的新需求都走这条路径，不能塞进 `.data`。
