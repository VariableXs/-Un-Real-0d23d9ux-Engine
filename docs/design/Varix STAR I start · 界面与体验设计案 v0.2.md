## 卷首 · 总纲（四域共同的第一原则）

**交互词典对齐 Windows，视觉表达完全自研。**

- 用户从 Windows 过来：**零学习成本**——按钮在哪、右键菜单有什么、拖拽怎么行为、快捷键是什么，全部与 Windows 一致（先照抄交互布局，等我们有自己的按钮形状语汇后再统一替换，届时一次全局换装、不动动线）。
- 用户看到的一切：**没有一处像 Windows 克隆**——配色、材质、光影、动画曲线、图标风格、字体层级全部是 VARIX 自己的设计语汇，按 3A 大作级质感做。
- 一句话：**手感和 Windows 一样熟，眼睛看到的是另一个作品。**

**执行纪律**：无软件商店是宪法级决定（MD1 第 20.2 章），一切「获取软件」路径走浏览器下载 + S: 侧载 + vxapp 校验；每项开工前先落 WP 编号与绑定判据。本册与《MD3 第 6 章》互为镜像（此处从体验视角记，MD3 从任务视角记，两处同账不同面）。

## 卷首·甲 防误解写作规范（本册条文如何写成 AI 不会理解错的句子）

本册的读者包括 AI 施工者——AI 不理解失误的前提是**每条条文只有一种解读**。本册全部条文的写作规范七条，施工时发现歧义条文按此修订：

1. **五要素齐备**：每条设计条文必须含「对象 / 数值 / 单位 / 状态 / 验收」——例：「任务栏高度 48px（100% 缩放，1920×1080 基准），偏差 ≤2px，拖动窗口贴底时任务栏不被遮挡（验收）」。「任务栏要好看」不是条文，是愿望。
2. **禁用模糊词表**：适当、美观、尽量、差不多、合理、优化一下、大概——这些词出现在条文中即文档缺陷。想说「适当留白」必须写成「卡片间距 16px」；说不准数值的，写成「随 E1 主题令牌 `--space-md` 取值」，让数值有唯一出处。
3. **状态穷举**：凡控件必有状态清单（常驻/悬停/按下/禁用/选中/焦点），凡流程必有异常分支（取消/失败/断电/中断恢复）——只写正常路径的条文视为未完成。
4. **视觉词配参照物**：颜色用色板令牌（`--accent`）不用「蓝色」；质感用材质样张文件（`design/assets/material-*.png`）不用「毛玻璃感」；动画用时长+曲线（200ms ease-out）不用「流畅地」——AI 拿到条文时，参照物必须已存在于仓库。
5. **对齐 Windows 的条文必须给「对齐到什么」**：写「对齐 Windows」必须同时给出测量基准（本册卷首·乙的规格基线表），基线表是对齐条文的唯一裁判——条文与基线冲突时，以基线表为准并回改条文。
6. **一处一事实**：同一数值只在一处定义、他处引用（引用格式「见 C-9 表第 N 行」）——两处各写一份 48px，将来一处改一处不改就是事故。
7. **判据绑定**：每节末尾列验收判据，格式沿用 B 判据纪律——实测数据 + 复现命令 + 日期三件齐才算绿。

## 卷首·丙 深化设计报告模板（各域报告卷的统一写法）

**卷定位**：F 清单是「做到什么算做到」的一行账，本卷把每一项展开成**完整的设计报告**——按统一七段模板：【功能定义】（这是什么、边界在哪）【用户故事】（谁在什么场景怎么用它）【交互设计】（入口/动线/每个状态的样子，尺寸引用卷首·乙基线表）【数据与存储】（数据长什么样、放哪、怎么保命）【状态与异常】（正常路径之外的全部分支）【验收判据】（实测什么、证据形态）【开源复用】（接哪个现成件、接缝在哪）。**报告式纪律**：每段必须可执行——AI 施工者读完【交互设计】就能画出界面，读完【状态与异常】就知道每个分支怎么弹，读完【验收判据】就知道跑什么命令算绿；凡是写不出的段落，标注「设计缺口」排队补齐，不许用形容词糊过去。

## A-1·补 A5 的落地口径

- **无感标准（验收判据）**：下载 → 双击 → 窗口出现，中间零配置、零终端命令、零「切换域」——用户全程不知道兼容层的存在；错误路径（程序不兼容）用三要素文案诚实提示，不闪退不静默；
- **多语言软件链**：VS Code + 各语言运行时（Python/Node/Java/Go/Rust 等）按 A2 判例工厂逐语言过判例——语言链的兼容目标不是「能装」，是「能装扩展、能跑构建、能调试」（以 VS Code 全绿为标志性判据，承接 MD1 S304）；
- **开源复用纪律**：优先列清单评估现有开源件（借力纪律同 MD1 第 18 章），只接不改、版本锁定；自研只做开源件与 VARIX 内核之间的接缝（垫片/判例/差异表）——兼容面的工程预算花在接缝上，不花在重造上。

## A-2 下载与安装（无应用商店，浏览器为门）

1. **浏览器下载（Variable 2026-09-25 已拍板：Edge 级浏览器下载，不建应用商店——MD1 第 20.2 章同步入宪）**：用户用浏览器正常下载——**不建应用商店**，星图退回其本职（兼容性评级目录），不做商店前端。

## A-5 深化设计报告（F001-F040 报告式全展开）

### G-A-01 F001 无感双击运行 · 完整设计

**【功能定义】**用户在文件资源管理器（或桌面）双击一个 .exe 文件，系统自动完成「识别格式 → peblock 门校验 → 装载进内存 → 建进程 → 显示窗口」全链路，用户全程只做「双击」一个动作。边界：本项只承诺 64 位 PE（32 位见 F004），只承诺 peblock 门规则内的程序（越权见 F037），只承诺窗口级 GUI 与控制台两类子系统。
**【用户故事】**Variable 从浏览器下载了一个开源记事本替代品（Notepad3.exe）到 S:\Downloads，打开资源管理器双击它——3 秒后窗口出现，标题栏是 VARIX 统一装饰，内容区是程序自己的界面；全程没有终端、没有命令行、没有「切到 Windows 域」的提示。Variable 的朋友问「这是 Windows 吗」，Variable 说「不是，这是 VARIX」——这就是无感的定义。
**【交互设计】**双击后 100ms 内指针变忙碌态（Windows 语义保留，C-6 红线）；首帧窗口出现前若超过 500ms，屏幕中央出现占位窗（尺寸按程序 manifest 声明的窗口大小，标题显示程序名，中央三颗点呼吸动画 1.2s 周期）；窗口就位后占位窗无缝替换（无闪烁）。双击过程任何时候 Esc 取消装载（进程回收，资源零残留）。入口共三处：资源管理器双击/桌面双击/开始菜单搜索后 Enter——三条路走同一装载服务，不许有第二条实现。
**【数据与存储】**装载器不落盘任何中间物；peblock 校验结果（哈希+规则命中）写入会话日志；程序自身的写入按 F009/F010 沙盒规则重定向。
**【状态与异常】**①格式不是 PE → 弹「这不是 Windows 可执行文件」三要素对话框；②peblock 拒绝 → 按 F037 给完整解释与越权入口；③装载中崩溃 → 占位窗转为错误卡（「程序未能启动」，展开显示归因五分类 F035），桌面不受影响（F175 隔离）；④双击后立刻断电 → 无任何持久状态损坏（装载零落盘）。
**【验收判据】**「常用 50 件」（F040）中 GUI 类逐件实测：双击到首帧 ≤3s（U 盘实机、二次启动）、占位窗出现率 100%（超过 500ms 的样本）、Esc 取消后进程表零残留（kinfo process self-test 11/11 实测口径）。证据三件套：录屏 + 进程表快照 + 计时数据。
**【开源复用】**装载核心自研（ring3 既有雏形 spawn_pe 族扩面），PE 格式参考文档用 Microsoft PE Spec + 开源 pe-parse 库做格式测试集（只用作对拍样本，不链接进内核）。

【设计细节】装载服务进程独立于合成器与资源管理器（崩溃互不传染）；双击识别走文件签名嗅探（MZ 头加 PE 标记双验证，扩展名不作准）；占位窗动画参数：三颗点 480ms 周期呼吸、透明度 0.4 到 1.0；同一文件 60 秒内重复双击合并为一次装载（防手滑双开）；装载全程 CPU 限额单核 80%——后台装载不抢前台帧率。

### G-A-02 F002 静态 PE 全量支持 · 完整设计

**【功能定义】**无导入表（或仅导入 kernel32 基础面）的静态链接 PE 完整装载：GUI/CUI/Windows CE 三类子系统、任意节数（上限 96 节，Windows 规范值）、非常规 SectionAlignment（含 4KB 以下）、BASE 重定位全类型（HIGHLOW/DIR64）。
**【用户故事】**一位用 Go 写工具的开发者 `go build` 出单文件 exe（静态链接、20MB），拷进 S: 双击——控制台窗口弹出、输出正常、退出码正确。他不知道这背后是 VARIX 自己的装载器，他只知道「能跑」。
**【交互设计】**CUI 子系统自动挂接终端应用（F012）：若从资源管理器双击控制台程序，自动新开一个终端标签页运行（关闭窗口即退出进程，动线对齐 Windows）；GUI 子系统按 F001 流程。装载期无用户可见等待项（20MB 装载目标 ≤800ms，实测线）。
**【数据与存储】**节映射零拷贝（文件页缓存直接映射，写时复制保护）；重定位表不常驻内存（处理完即弃）。
**【状态与异常】**畸形头（e_lfanew 越界/节表溢出）→ 拒绝并归因「文件损坏或非 PE」；地址空间不足 → 提示「内存不足」而非闪退；TLS 回调执行按 Windows 语义先于入口点（顺序差异表登记）。
**【验收判据】**开源静态样本集 20 枚（Go/Rust/Nim 各类）装载成功率 20/20；对抗样本集 30 枚（自造畸形）拒绝率 30/30——两组数字同页呈现，缺一不可。
**【开源复用】**测试集复用 pe-parse 与 Wine 的 conformance 测试样本；装载实现自研（内核零堆纪律不兼容第三方 C 库直入）。

【设计细节】节数上限按 Windows 规范 96 节硬顶；SectionAlignment 小于 4096 时按文件对齐映射（FILE_ALIGN 模式），重定位 HIGHLOW 占 95% 场景优先快路径；BASE 重定位块处理上限 64MB（超限归因「镜像异常」拒绝）；Go/Rust 静态样本的 .text 平均 8-20MB，装载内存按节惰性提交（触碰才分配物理页），20MB 程序实际驻留首启小于 6MB。

### G-A-03 F003 导入绑定加速 · 完整设计

**【功能定义】**IAT 解析的两级缓存体系：进程族缓存（同主程序的 DLL 符号地址表）与会话缓存（系统 DLL 符号表全局只读共享）；delay-load 按首次调用时绑定。目标：二次启动同程序导入解析 ≤ 一次启动的 50%。
**【用户故事】**Variable 每天开机第一件事打开同一个 .exe 记账工具——第一次打开 2.8s，第二次起稳定 1.4s 以内，他感受不到区别也不需要知道，账本里两次数字都在。
**【交互设计】**无直接交互面；数据面在任务管理器（若 C-5 理解 A 拍板）进程详情页显示「导入解析：缓存命中/全量」，给排查者看。
**【数据与存储】**缓存键 = (模块基址哈希 + 符号名哈希表)；缓存文件存 DATA 分区 `cache/pebind.bin`，损坏即弃建（自愈，F189 同族）；上限 64MB，LRU 驱逐。
**【状态与异常】**DLL 版本变化 → 键失配自动全量解析（不报错）；缓存文件损坏 → 静默重建 + 通知中心报备；内存压力下缓存先于文件页被回收。
**【验收判据】**vxbench 装载类基准新增「导入解析耗时」子项：同程序三次启动取后两次均值 ≤ 首次 50%；缓存命中率 >80%（常用 50 件口径）。
**【开源复用】**符号解析参考 Wine 的 PE loader 设计（接缝：仅借鉴算法，代码自研）；缓存格式参考 Microsoft IAT snapshot 思路。

【设计细节】缓存键加系统 DLL 版本戳（内核更新后键全失效重建，防陈旧地址）；delay-load 桩生成按 thunk 表原位改写（Windows 同语义）；会话缓存只读共享以全局映射实现（零拷贝）；命中率统计入诊断面板，低于 60% 自动清缓存重建（自愈）；缓存文件写盘走 WAL 与应用蜂巢同设施。

### G-A-04 F004 Wow64 门（32 位 .exe 前瞻）· 完整设计

**【交互设计】**拒绝卡片样式对齐 F035 兼容性向导（同一卡片体系）：图标+标题+一句归因+两个动作（关闭/查替代）。卡片自动记忆该文件，同文件第二次双击不再重复解释（本地记录，可清）。

**【状态与异常】**带 32 位安装器的混合包（32 位安装器装 64 位主程序）→ 安装器本身被拒时提示完整归因；伪装 32 位的恶意样本照走 peblock 门，先过门再谈位数。
**【验收判据】**32 位样本集 10 枚 100% 触发诚实卡片（零静默失败/零崩溃）；卡片文案三要素齐。
**【开源复用】**机器类型判定逻辑参照 pe-parse 字段表；无运行时依赖。

【设计细节】位数判定读 PE 机器字段 0x014c（I386）与 0x8664（AMD64），ARM64 声明也识别并如实告知；拒绝记录同时上报星卡草稿（F036 联动，匿名）；「查替代品」按钮跳星图搜索并预填程序名关键词；卡片文案经过三要素审计（发生了什么/为什么/下一步），禁用「不支持」裸句。

### G-A-05 F005 Win32 窗口管理兼容层 · 完整设计

**【功能定义】**winsrv 消息泵扩面：常用窗口类七族（按钮/编辑框/列表框/组合框/滚动条/静态文本/通用对话框容器）的 CreateWindowExW/消息路由/绘制请求全通；目标程序是「纯 Win32 写的完整应用」而非 demo 片段。
**【用户故事】**一位只学过 Win32 API 的开发者，把他的开源记事本（3,000 行 C，纯 CreateWindow/DefWindowProc）拷进 VARIX——菜单栏能点、编辑区能打中文（F027 输入法面）、文件对话框能开（F008）、最小化最大化正常——他说「我像在给 Windows 写程序」。
**【交互设计】**窗口装饰由 VARIX 合成器统一供给（标题栏/边框/系统按钮按 C-3 规范），程序自身画的客户区原样呈现；程序自绘标题栏（WM_NCCALCSIZE 处理）则尊重程序——**程序对自己的窗口有主权，VARIX 只管没主权的地方**。非客户区命中测试（WM_NCHITTEST）语义逐消息对齐。

**【状态与异常】**消息死循环检测（同消息 1s 内 10 万次）→ 判定应用卡死，转 F175 隔离处理；未处理消息返回 DefWindowProc 语义（不吞不崩）；窗口类名冲突按 Windows 规则（后注册失败）。
**【验收判据】**标志件：Notepad2 级开源编辑器全功能走查（新建/打开/保存/查找/替换/字体对话框/状态栏）；消息面补全按「常用 50 件」应用的 API 采样频率排序（A2 数据驱动）。
**【开源复用】**消息语义参照 Wine user32 与 ReactOS（语义对拍库），实现自研（winsrv 既有消息泵扩面，非移植）。

【设计细节】七族控件各配消息语义表（WM_ 前缀 40 个高频消息优先），每表附「VARIX 渲染替代」说明——按钮按下态由 winsrv 画还是程序自绘按程序风格位裁定；窗口类原子表进程内上限 16384（Windows 同值）；DefWindowProc 缺省行为逐消息文档化（对拍 ReactOS 用例）；消息泵每窗口独立队列，一窗卡死不堵同进程他窗。

### G-A-09 F009 注册表虚拟化 · 完整设计

**【功能定义】**每应用独立注册表蜂巢（per-app hive）：应用视角的 HKCU/HKLM 读写全部落在自己的蜂巢文件；读操作先查自有蜂巢、未命中回读系统模板（只读）；写操作一律进自有蜂巢。卸载 = 蜂巢文件进回收站（零真删红线）。
**【用户故事】**两款老软件都想往 HKCU\Software 写自己的设置且都写了同名键——在 VARIX 上互不干扰；用户卸载其中一款，另一款的设置纹丝不动——「注册表泥潭」在结构上不存在。
**【交互设计】**设置中心「应用-高级」页显示蜂巢大小与「查看注册表内容」入口（只读十六进制/键树视图）；诊断中心导出蜂巢快照。
**【数据与存储】**蜂巢文件存沙盒目录（F010），格式自定（键值对 B-树，写入走 WAL 保断电一致）；系统模板蜂巢只读内嵌镜像。
**【状态与异常】**蜂巢损坏 → 重建空蜂巢 + 通知（应用设置丢失如实告知，不静默）；蜂巢超 256MB → 告警（正常应用设置 <1MB，超限必有异常写入）；并发写冲突 WAL 串行化。
**【验收判据】**三族安装器（F030）安装-使用-卸载全周期后：全局模板零写入（哈希不变）、蜂巢完整回收；断电注入百次后蜂巢可打开率 100%（WAL 恢复）。
**【开源复用】**蜂巢格式思路参考 Windows regf 格式文档（只读解析用于「从 Windows 迁移设置」前瞻），自有格式自研；WAL 复用存储栈既有设施。

【设计细节】蜂巢 B 树节点 4KB、写放大控制（脏节点合并落盘）；系统模板蜂巢启动时 mmap 只读共享（全进程共用一份）；蜂巢查看器树视图支持键值复制与十六进制值查看；导出快照为 JSON（开放格式 F126）；恢复点（F121）自动纳入蜂巢快照——注册表可回滚。

### G-A-10 F010 文件系统重定向 · 完整设计

### G-A-19 F019 COM 本地接口最小集 · 完整设计

**【用户故事】**程序调用 COM 创建一个 Shell Link 来生成快捷方式——成功；调用某个专业 COM 组件（如语音识别 SAPI）——得到结构化错误「该组件不在 VARIX 兼容面」，引导用户提判例请求——**每个边界都有说法**。
**【交互设计】**无独立 UI；错误经 F035 向导呈现；CLSID 注册内容可在蜂巢查看器（F009 诊断入口）查。
**【数据与存储】**CLSID 注册进应用蜂巢；COM 对象生命周期随进程（引用计数语义按 Windows：AddRef/Release 对拍）。
**【状态与异常】**未注册 CLSID → REGDB_E_CLASSNOTREG 如实返回（不假装成功）；聚合请求不支持 → 明确错误码；引用计数泄漏检测 → 进程退出时告警日志。
**【验收判据】**四族本地对象各一个开源消费者场景全绿；未注册类错误路径文案三要素。
**【开源复用】**语义对照 Wine ole32 本地对象族；实现自研接缝。

【设计细节】CLSID 蜂巢子树路径 Classes 下 CLSID 节点；类对象注册会话级；四族对象接口方法覆盖以「50 件清单实际调用面」为准（A2 数据驱动扩面）；QueryInterface 对未知 IID 返回 E_NOINTERFACE（不假装支持）；聚合按不支持处理（差异表登记）。

### G-A-20 F020 异常与调试面 · 完整设计

**【功能定义】**SEH/VEH 结构化异常翻译：try/except 语义（异常过滤/展开/最终处理）映射到 VARIX 信号与 unwind 层；未处理异常 → minidump（线程栈/寄存器/模块表）落诊断中心，应用按 F175 隔离回收。
**【用户故事】**一个程序段错误崩了——VARIX 弹「程序已停止工作」卡片（可重启/可关闭/可查看详情），详情页就是 minidump 摘要（崩溃地址/模块/异常类型）；开发者拿到 dump 能定位到自己的源码行。崩溃的用户感受是「一个窗口没了」，不是「整个系统没了」。
**【交互设计】**崩溃卡片样式对齐 F035 体系；「重新启动应用」保留原参数重拉；「查看详情」内嵌 dump 摘要只读页。
**【数据与存储】**minidump 存 `diagnostics/dumps/` 上限 20 个 LRU；dump 格式用自定轻量格式（可导出转换 CDB 可读文本）。
**【状态与异常】**异常处理器自身再异常 → 双重故障直接回收进程（不递归）；栈溢出 → 专用栈保护页捕获按栈溢出归因；dump 写入失败 → 静默降级为日志摘要。
**【验收判据】**注入异常样本 6 类（除零/非法访问/栈溢出/未处理 C++ 异常/SEH 吞噬/VEH 链）行为全对；崩溃后桌面帧率实测不跌（F175 联动）。
**【开源复用】**SEH 语义参照 Microsoft 异常文档与 Wine exception 面；minidump 格式参考 MDMP 规范裁剪自定。

【设计细节】异常翻译层内核零堆（定长异常帧栈深 32）；minidump 含：异常码/崩溃地址/线程栈回溯 64 帧/已加载模块表（含校验和）/系统版本指纹；dump 压缩存储（zstd 级评估）；「重新启动应用」保留命令行与工作目录（启动时快照）；同一文件 24 小时内崩溃三次以上自动建议提交 F036 草稿。

### G-A-21 F021 内存语义对齐 · 完整设计

**【功能定义】**VirtualAlloc 族（RESERVE/COMMIT/PROTECT 六保护位/写时复制）、MapViewOfFile 文件映射、VirtualQuery 查询、大页请求（自适应降级）全语义对齐；伙伴分配器供给（WP-104 既有）加大页优先策略。
**【用户故事】**一款内存敏感的开源压缩工具（自管内存池）在 VARIX 上跑基准——吞吐与 Windows 相差 <5%，它的 VirtualAlloc 大块请求拿到对齐良好的物理页。
**【交互设计】**任务管理器（若拍板 A）进程内存三列：工作集/提交/映射——三列语义与 Windows 同名同义；诊断中心内存面板显示整系统分配分布。
**【数据与存储】**提交记账入 MD2 附录 K 内存配额账（F195 配额执行）；文件映射页缓存与存储栈共享（同一份页缓存）。
**【状态与异常】**内存不足 → COMMIT 失败返回 NULL（Windows 语义），程序自处理；保护位违规 → SIGSEGV 类异常进 F020 流程；释放后再访问 → 守卫页捕获（F176）。
**【验收判据】**7-Zip 基准实测无降级（F021 验收原文）；VirtualAlloc 压力脚本（分配-提交-触碰-释放 1 万轮）无泄漏无碎片失控。
**【开源复用】**语义对照 Wine virtual.c 与 MS 文档；实现自研（伙伴/slab 既有面扩展）。

【设计细节】RESERVE 地址空间按 64KB 粒度（Windows 同粒度）；PROTECT 六位全支持（含写时复制位）；WRITECOPY 即写时复制（改页触发复制）；文件映射大小按文件当前大小（扩展后需重映射，语义对齐）；大页请求 2MB 对齐不足自动降 4KB（降级日志）。

### G-A-22 F022 时间与定时器族 · 完整设计

**【功能定义】**时间 API 族：GetTickCount(64)（毫秒 uptime）/QueryPerformanceCounter（TSC 2500MHz 直通，实测 isa-none 已就绪）/GetSystemTime（UTC+时区换算）/timeBeginPeriod（定时器精度请求，尊重但记账）/SetTimer/WaitableTimer。
**【用户故事】**一款开源音乐练习软件依赖高精度计时打拍子——在 VARIX 上节拍稳定（QPC 直通 TSC，无分层纠偏抖动）；长开 24 小时的工具 GetTickCount 不回绕（64 位化）。
**【交互设计】**无独立 UI；定时器精度请求的「谁在要求高精度」进功耗面板（F060 归因数据源之一）。
**【数据与存储】**时区/夏令时规则数据内嵌（tzdata 裁剪版，F130 登记）；uptime 派生自内核打点。
**【状态与异常】**timeBeginPeriod 滥用（多个 1ms 请求）→ 合并执行 + 功耗归因标注；系统休眠唤醒后 QPC 连续性保证（计数不跳变）；时钟被改（F187 NTC 校时）→ GetTickCount 不受影响（uptime 与墙钟分离）。
**【验收判据】**QPC 与外部秒表 24 小时漂移 <50ms；游戏类样本（开 1ms 定时器）帧节奏实测稳定； tzdata 换算 10 时区 round-trip 全对。
**【开源复用】**tzdata 直接复用（IANA 公共数据）；语义对照 Wine kernel32 时间面。

【设计细节】QPC 频率常量等于 TSC 实测频率（启动时校准，2500MHz 基线）；GetTickCount 64 位化且 32 位接口保留 49.7 天回绕语义（对齐 Windows 让程序按预期走）；SetTimer 最小 10ms（请求更短钳制并记账）；timeBeginPeriod 全局最小值生效（多请求取最急）；休眠唤醒后 tick 补齐墙钟差值。

### G-A-23 F023 网络栈 Winsock 面 · 完整设计

**【功能定义】**Winsock2 常用面：socket/connect/bind/listen/accept/send/recv/sendto/recvfrom/select/ioctlsocket/getaddrinfo（DNS 走系统解析器）/WSAAsyncSelect（消息泵模型适配）；阻塞/非阻塞双模式；smoltcp socket 面承接（B-60x 既有）。
**【用户故事】**一款开源 FTP 客户端（Win32 写的）在 VARIX 里连上服务器、浏览目录、传文件——主动/被动模式都通；用户不知道底下是 smoltcp 在替 BSD socket 打工。
**【交互设计】**无独立 UI；网络错误（超时/拒连/DNS 失败）错误码如实翻译（WSAETIMEDOUT 等），程序自己的错误提示自然正确。
**【数据与存储】**socket 缓冲配额按进程（F195）；DNS 缓存 60s TTL（系统级共享）。
**【状态与异常】**句柄泄漏检测（每进程 socket 上限 256）→ 超限告警；网络断开 → 进行中 send/recv 返回 WSAECONNRESET（不悬挂）；WSAAsyncSelect 消息窗口失效 → 静默回收 + 日志。
**【验收判据】**FTP 客户端全流程绿；SSH 交互延迟 ≤30ms（F059 线）；并发 50 socket 压测无饥饿。
**【开源复用】**API 语义对照 Wine ws2_32 与 MS Winsock 文档；传输层全复用 smoltcp（F130 借力件）。

【设计细节】socket 句柄表每进程 256 上限；WSAAsyncSelect 消息映射到窗口消息保留段（与程序自定义消息隔离）；getaddrinfo 支持域名/点分地址/服务名端口；阻塞调用走异步内核等待（不占线程自旋）；UDP 广播/组播基础支持；每 socket 双向缓冲 64KB 默认可调（F195 配额内）。

### G-A-28 F028 高 DPI 感知三态 · 完整设计

**【功能定义】**按程序 manifest（F014）声明执行三态：unaware（合成器位图放大，模糊但比例正确）/ system-aware（按主屏 DPI 虚拟化坐标）/ per-monitor aware（拿真实像素）。VARIX 不越权替程序「变清晰」——尊重声明。
**【用户故事】**用户把缩放调到 150%：老工具（unaware）界面等比放大（略糊可接受，属性页有说明）；新程序（per-monitor）文字锐利如初——两类程序同屏各得其所，用户不困惑。
**【交互设计】**属性「兼容性」页显示程序 DPI 声明 + 用户级覆盖下拉（对齐 Windows 兼容性设置动线）；缩放变更时 aware 程序收 WM_DPICHANGED 实时重排。
**【数据与存储】**用户覆盖存应用蜂巢（F009）；缩放档位全局（E7 联动）。

# 第 2 部分 · B 性能域（目标③）

> 域目标：让系统更快更顺，且所有快都可实测、可复现。

## B-1 提案表

| 编号 | 提案 | 说明 | 量级 |
| --- | --- | --- | --- |
| B1 | vxbench 实机首跑 + 基线账本 | 一切优化的前置——没有基线就没有「极大优化」 | 小 |
| B2 | 启动链优化 | 预读窗口对账 + 二次启动 8 秒判据实机化——用户每天感知最强的性能 | 中 |
| B3 | GPU 加速合成器（R3 摸底后决策） | Ivy Bridge 核显有基本 2D/3D 加速能力（Intel GPU 驱动路线），不一定要换硬件 | 大，需摸底 |
| B4 | U 盘 I/O 深化 | 写合并/预读/缓存策略在真 U 盘上调优——B707 族判据实机化 | 中 |

**铁律**：B1 不绿，B2-B4 不开工——没有基线的优化是凭感觉的优化。

## B-2 性能红线（体验域的性能约束，全域通用）

- 开机动画总时长 ≤8 秒——这是 B2 的验收线，也是第 3 部分开机动画的时长上限，实测几秒就几秒，进度条不骗人；
- **任何点击 100ms 内必有可见反馈**；动画稳定 **80fps**（Variable 2026-09-25 拍板：目标 80 帧，60fps 为最低达标线）、打断不跳变——B3 决定这条 KPI 的天花板（软渲染达标后再谈 GPU 加成）；
- **任意软件打开体验**：窗口出现前的等待全程有反馈（指针忙碌态 → 首帧占位窗 → 内容就位），不允许「点了没反应」——打开耗时随应用如实波动，但**帧率与反馈红线对任意软件一视同仁**（打开慢是诚实标注的事，卡死冻结是事故）；
- 丰盛不以卡顿为代价——P95 与帧率实测是验收硬项（见卷尾验收）。

## B-2·补 性能深度优化方向（Variable 2026-09-25 指定）

80fps 打开任意软件的支撑面按四层推进：① 合成器主循环削减空转与冗余合成（脏区策略深化）；② 应用冷启动优化——ELF/PE 装载预取指纹、BOT 预读窗口对账、二次启动减半；③ 渲染路径 GPU 化（B3 摸底后立项，Intel 核显 2D/3D 加速）；④ U 盘 I/O 深化（B4 写合并/预读调优）。每层先过 B1 基线，逐层实测帧率归因——**80fps 是整链的总验收，不是单层指标**。

## B-3 深化设计报告（F041-F070 报告式全展开）

> 以下 30 份报告为 B 域全部功能项的报告式展开——七段模板见卷首·丙；每项末尾【设计细节】段含参数级、像素级、判据级补深。性能域报告的共同前提：B1 基线账本先行（铁律），一切数字与监视器同源。

### G-B-01 F041 帧率账本 · 完整设计

**【功能定义】**合成器逐帧记账：每帧记录合成耗时、脏区面积、提交耗时、等待时间四项，写入性能账本（与监视器同源，B-2001 纪律）；账本按滚动窗口保留 60 秒逐帧 + 24 小时分钟聚合。
**【用户故事】**用户感觉拖动窗口「偶尔顿了一下」——打开任务管理器性能页，拖动时刻的逐帧图上一眼看到那 300ms 里有五帧超了 12.5ms 红线，归因列写着「输入风暴」——性能问题从玄学变成可回放的录像。
**【交互设计】**监视器性能页帧率图：纵轴帧耗时 0-25ms、横轴最近 60 秒、80fps 线（12.5ms）与 60fps 线（16.6ms）双参考线；悬停任一帧弹出该帧四项数据；「归因」列红黄标注。
**【数据与存储】**逐帧环形缓冲内存 64KB（60s×1000fps 上限）；分钟聚合落账本文件；账本格式对齐 vxbench（F061 回归门直接消费）。
**【状态与异常】**账本写入自身超预算（>0.1% CPU）→ 自动降采样（每 2 帧记 1 帧）并标注；合成器崩溃重启 → 账本标注断点（不伪造连续）。
**【验收判据】**账本打点自身开销 <0.1% CPU 实测；帧率图与实测录屏逐帧对得上（抽 10 帧核对）。
**【开源复用】**聚合口径参照 Travis/Timeline 类性能面板设计；实现自研（合成器既有打点面扩展）。
**【设计细节】**帧耗时测量点三处（输入处理/合成/提交）分段计时——归因的最小粒度是「哪一段慢」；四项数据每项独立阈值（合成 6ms/提交 3ms/输入 1.5ms/等待不做红线）；窗口拖动场景打专项标签（压力测试复现用）；80fps 红线用强调色实线、60fps 用灰虚线——目标线与底线视觉分级。

### G-B-02 F042 帧率归因器 · 完整设计

**【功能定义】**掉帧自动归因：帧超预算时按四类嫌疑（输入风暴/大脏区/IO 阻塞/调度抢占）采集证据并给出排名——「上一秒谁偷了帧」的自动侦探。
**【用户故事】**用户报告「复制大文件时窗口会卡」——开发者打开归因器看历史：卡顿时刻 IO 阻塞类占比 80%，证据链里挂着对应的存储打点——一条可复现的性能缺陷工单 5 分钟建好，以前要靠猜一晚上。
**【交互设计】**监视器「掉帧历史」页：列表（时间/掉帧数/头号归因/证据链接），点开单条看四类嫌疑占比条形图 + 每类的原始证据（哪次 IO/哪个窗口多大脏区）。
**【数据与存储】**归因事件落账本分钟聚合；证据引用账本原始条目（不复制，一处一事实）；保留 7 天。
**【状态与异常】**证据不足（多因并发）→ 如实「混合归因」并按占比排序（不硬编主因）；归因器自身异常 → 静默停用 + 诊断报备（不拖累合成器）。
**【验收判据】**构造四类掉帧样本各一，归器全部命中正确主因；误报率 <10%（正常拖动 100 秒样本零误报）。
**【开源复用】**归因思路参照 Chrome Tracing / ETW 的事件分类法；实现自研（账本数据面直接消费）。
**【设计细节】**四类判定阈值：输入事件 >200/秒 = 输入风暴；单帧脏区 >屏幕 60% = 大脏区；帧内 IO 等待 >2ms = IO 阻塞；帧被高优先线程抢占 >3 次 = 调度抢占；排名算法按「扣除该因素后帧耗时是否回线」的虚拟重放验证——归因要自证不是贴标签。

### G-B-03 F043 冷启动画像 · 完整设计

**【功能定义】**应用启动五段刻度：装载（PE/ELF 解析与映射）/重定位（导入绑定 F003）/首帧（首次合成提交）/可交互（输入事件响应）/稳定（5 秒无超预算帧）；每段耗时建档进星卡与账本。
**【用户故事】**「VS Code 打开慢」到底慢在哪——画像说：装载 1.2s/重定位 0.4s/首帧 6.1s/可交互 8.3s——一眼看出大头在首帧（渲染初始化），优化目标从「让 VS Code 变快」聚焦到「砍首帧前的那段」。
**【交互设计】**星卡详情页「启动画像」五段横向条形图（各段颜色区分、段宽按耗时比例）；对比视图：「首次 vs 二次」并排——预取（F044）的效果一眼可见。
**【数据与存储】**画像按 (应用版本, 启动序号) 记录；保留最近 20 次启动；聚合进星卡取「二次启动中位数」。
**【状态与异常】**应用启动中途崩溃 → 画像标记「中止于第 X 段」（本身就是极有价值的归因数据）；用户取消启动 → 同理记录。
**【验收判据】**五段边界与内核打点一一对应（无重叠无遗漏）；同应用 10 次启动画像方差 <15%（测量自身稳定）。
**【开源复用】**分段口径参照 Android Metrics 的 App Startup 分段；实现自研（装载器/合成器打点扩展）。
**【设计细节】**段边界定义写死在打点常量（一处一事实）：装载止于入口点前、重定位止于 IAT 解析完、首帧止于首次 Present、可交互止于首个窗口过程返回、稳定止于 5 秒观察窗结束；启动序号 1 = 冷（缓存清）、2 起算热；画像收集受隐私总闸（F036 同开关）控制。

### G-B-04 F044 预取指纹 v2 · 完整设计

**【功能定义】**按历史启动记录「哪些文件页真正被摸过」生成指纹，下次启动按指纹预读调序：热页先读、冷页不读；与 BOT 预读窗口对账（存储栈旋钮联动）。
**【用户故事】**VS Code 首次启动读 40MB、二次启动只预读 9MB 热页——用户体感「第二次快一倍」，U 盘也少磨——**预取的聪明在于只预取真的**。
**【交互设计】**无独立 UI；效果在星卡画像对比视图（F043）可见；诊断面板显示当前指纹命中率。
**【数据与存储】**指纹文件按应用存 `cache/prefetch/<hash>.pf`（页位图+访问序），上限 8MB/应用，LRU 驱逐；格式自定开放（F126）。
**【状态与异常】**程序更新（版本变化）→ 指纹失效重建；指纹损坏 → 弃用走无预取路径（正确但慢，不报错）；U 盘换机 → 指纹随 DATA 分区走（天然随身）。
**【验收判据】**「常用 50 件」二次启动均值 ≤ 首次 50%（与 F003/F043 联合对账）；指纹命中率 >70% 实测。
**【开源复用】**思路参照 Windows SuperFetch 与 eBPF prefetch 的页级追踪；实现自研（存储栈预读钩子）。
**【设计细节】**页访问记录在软缺页中断点（内核零堆：定长环形位图）；预读 IO 按指纹序批量 8 页一组（对齐 BOT 顺序读优势）；预读优先级永远低于前台 IO（F057 分级）；指纹生成在应用退出后 30 秒后台完成（不抢退出体验）。

### G-B-05 F045 页缓存水位策略 · 完整设计

**【功能定义】**4GB 内存边界下的页缓存治理：全局水位线三档（高 3.2GB/中 2.4GB/低 1.6GB），到线按 LRU 回收文件页；脏页占比上限 20%（超限强制冲刷，断电窗口受控）。
**【用户故事】**用户连续打开几十张 4K 图后系统依然流畅——水位线在后台悄悄回收了最早的图页；他不会知道有这条策略，只会觉得「这系统不卡也不崩」。
**【交互设计】**监视器内存页三区图（应用/缓存/空闲）实时面积图；水位线档位在诊断面板只读展示（自动策略不暴露旋钮给普通用户——防乱调）。
**【数据与存储】**无持久化（纯运行时策略）；策略决策日志入诊断快照（F174）。
**【状态与异常】**应用内存配额挤压缓存 → 缓存先让（交互优先）；回收导致二次读盘激增 → 记录「回收后悔」指标调参依据；内存耗尽前 200MB 警戒 → 全局冲刷 + 通知后台应用释放（F195 联动）。
**【验收判据】**断电百次中脏页丢失窗口 ≤ 水位规则承诺值（B-703 数据交叉验证）；压测（连续开关大图）无 OOM。
**【开源复用】**水位思路参照 Linux min_free_kbytes 与 dirty_ratio；实现自研（伙伴分配器面扩展）。
**【设计细节】**LRU 按「文件页/匿名页」分列（文件页可弃可重读优先弃）；脏页 20% 上限按分区分别计（SHARED 只读卷不计）；水位判定每 500ms 一次（不逐页检查的功耗账）；三档切换条件文档化（>1GB 空闲=高档……全表在旋钮清单）。

### G-B-06 F046 写合并窗口自适应 · 完整设计

**【功能定义】**写合并窗口按负载动态伸缩：空闲 1s / 正常 5s / 重载 8s 三档自动切换；fsync 硬承诺（应用显式要求时立即冲刷）永不因窗口调整而拖延——自适应只调「惰性写」部分。
**【用户故事】**用户写完文档立刻拔 U 盘走人——空闲档 1 秒内已落盘，数据无损；批量解压时切重载档 8 秒合并，写入量减少 40%，U 盘安静寿命长。
**【交互诊断】**监视器存储页显示当前档位与最近 60 秒实际写入量曲线；档位切换事件入诊断快照。
**【数据与存储】**档位判定依据：每秒写请求数 + 脏页占比（F045 数据源共享）；无持久化配置。
**【状态与异常】**应用 fsync 请求在重载档也立即执行（硬承诺优先级最高）；档位抖动（1s 内反复切换）→ 迟滞保护（切档后至少驻留 5s）；断电一致性判据在任意档位都成立（B-703 分档重跑）。
**【验收判据】**断电百次按三档各跑一遍全绿；写入合并率（合并写/总写）重载档 >40% 实测；fsync 延迟 P99 <10ms 不受档位影响。
**【开源复用】**自适应思路参照 Linux dirty_expire_centisecs 动态化讨论；实现走存储栈旋钮（MD2 附录 K）。
**【设计细节】**三档阈值：请求 <10/s 且脏页 <5% = 空闲；>200/s 或脏页 >15% = 重载；迟滞驻留防抖；档位切换写一行审计；窗口上限 8s 的依据=断电丢失窗口承诺（用户可理解的边界）；B-702 判据在自适应模式下重测重录。

### G-B-07 F047 调度器延迟预算深化 · 完整设计

**【功能定义】**交互线程 p99 唤醒延迟 2000μs 总预算拆为逐类子预算：输入 500μs / 合成 800μs / 音频 300μs / 普通 400μs；每类独立记账，超标逐类归因——预算不是平均值是分布。
**【用户故事】**「系统偶尔卡一下」的追责有了精确到类别的答案：音频类从未超标、合成类每周三次超标且都指向同一场景——性能债有了具体的债务人。
**【交互设计】**监视器调度页四类泳道图（最近 60 秒各类 p99 曲线 + 超标点红标）；点击超标点看当时线程与优先级快照。
**【数据与存储】**延迟采样每类环形 10,000 条（内存 ~160KB）；聚合入账本；调度器打点零堆（定长结构）。
**【状态与异常】**某类长期零样本 → 观察窗说明（不代表无风险）；超预算且归因到自身策略（如优先级饥饿）→ 调度器自修正（优先级老化）并记录修正事件。
**【验收判据】**四类 p99 各自达标（2000μs 总预算内）；压力混载（音频+拖动+构建并发）下输入类 p99 仍达标——交互优先不是口号是曲线。
**【开源复用】**分级思路参照 Linux SCHED_DEADLINE 预算模型；实现自研（既有 rr 调度器扩展）。
**【设计细节】**优先级映射：输入=最高带抢占、音频=高带 deadline、合成=高、普通=rr 老化；energy=balanced 策略（既有实测）在大核可用时保持；预算超标定义 = p99 而非 max（尾部管理）；预算表编译期常量（变更走 ADR）。

### G-B-08 F048 CPU 频率联动 · 完整设计

### G-B-09 F049 空转清零工程 · 完整设计

### G-B-10 F050 中断合并 · 完整设计

**【功能定义】**输入与网络中断按突发窗口合并：2000ns 预算内批量入队处理；input-probe 的 flood_dropped（实测 70）转为「合并处理零丢弃」——把丢弃变成延迟。
**【用户故事】**高速滚动长网页每秒几百个滚轮事件——VARIX 不是丢掉一些（跳变），而是合并成平滑的位置更新（跟手不跳）——用户说不出原理，只觉得「滑起来真顺」。

**【状态与异常】**合并导致延迟 >8ms（体感阈值）→ 动态收缩窗口（流畅优先于省电）；中断风暴（恶意/故障）→ 熔断降频 + 诊断告警。
**【验收判据】**flood 测试（flood-publishes 70 级）零丢弃；滚动场景输入类 p99 延迟 ≤8ms；两数字对账 F041 掉帧归零。
**【开源复用】**合并思路参照 Linux NAPI 与 input coalescing 实践；实现自研（input-probe 既有面扩展）。
**【设计细节】**合并键：同设备同类型事件才合并（键盘不与滚轮混批）；批处理预算 2000ns 超则留队下轮（预算硬，不超卖）；鼠标位置类只保最新（绝对量事件可覆盖）、按键类全保（离散事件不可丢）——「可覆盖与不可丢」的二分是合并的正确性根基。

### G-B-11 F051 大页策略 · 完整设计

**【功能定义】**4MB 大页用于三类静态区：内核代码段、字形图集、合成器帧缓冲池；TLB miss 实测对比入账；R3 GPU 摸底同步评估核显侧大页可行性。
**【用户故事】**长文档连续滚动一小时无 TLB 抖动卡顿——大页让地址翻译的「路牌」少了 512 倍，滚动只烧 CPU 不烧 TLB。
**【交互设计】**无直接 UI；诊断面板内存页显示大页占用与命中率。
**【数据与存储】**大页池启动时预留（物理连续内存分配一次锁定）。
**【状态与异常】**物理连续内存不足 → 部分降级 4KB（按区独立降级并标注）；大页池碎片（长期运行）→ 只增不减策略防碎片。
**【验收判据】**字形图集场景 TLB miss 率实测下降 >50%；大页池启动预留成功率 >95%。
**【开源复用】**策略参照 Linux hugetlbfs 预留池模式；实现自研（WP-104 分页面扩展）。
**【设计细节】**三类区尺寸预算：内核 4MB/图集 8MB/帧缓冲按分辨率（4K 双缓冲 32MB）；预留失败的降级顺序：帧缓冲先降（影响最小）内核最后；TLB miss 测量用性能计数器（Ivy Bridge 支持 mem_load_retired 类事件评估）。

### G-B-12 F052 堆碎片治理 · 完整设计

**【功能定义】**内核堆（56KB 分块实测既有）改尺寸分级池：8/16/32/64/128/256B 六档 + 大块直通；碎片率（空闲块/总块）指标入账本；长期运行碎片率 <15% 达标。
**【用户故事】**系统连续运行一周后内核内存分配依然秒级响应——分级池让「住过很多人的旅馆」依然整洁，不出现「明明有空房却开不出去」的碎片窘境。

**【设计细节】**档位边界按内核实际分配谱定（先采集 1 周分配尺寸直方图再定档——数据先行）；大块直通阈值 512B；每档空闲链用位图（O(1) 分配）；碎片率 = 空闲块数/总块数的分档加权。

**【设计细节】**常用字集预热：启动后台预光栅常用 3500 汉字 + ASCII（用户打字前图集已热）；驱逐保护：当前帧用到的字形禁止驱逐（双缓冲页交换）；灰度 AA 与 hinting 参数冻结进资产版本（换字体版本=图集全重建，显式日志）。

### G-B-16 F056 合成器脏区深化 · 完整设计

**【功能定义】**光标独立层（光标移动不触发窗口重合成）；弹窗/菜单动画只合成自身矩形；全屏重绘从词典删除——所有动画都在「最小矩形集」内发生。
**【用户故事】**用户在文档里打字、光标闪烁、任务栏时钟走秒——三件事同时发生，合成器每帧只碰三小块矩形，CPU 占用依然近乎零——丰盛的界面与安静的系统并存。
**【交互设计】**无直接 UI；效果验收 = F041 账本打字场景的脏区面积曲线（应维持在屏幕 5% 以下）。
**【数据与存储】**脏区跟踪结构定长（每窗口脏矩形 8 个上限，溢出合并为整窗）。
**【状态与异常】**脏区爆炸（程序疯狂自刷）→ 合并限频 30fps + F042 归因；层重叠动画 → 层间脏区求交裁剪；光标层与内容层 z 序冲突 → 光标永远最上（独立层语义保证）。
**【验收判据】**打字场景脏区面积 P95 <5% 屏；光标移动 60fps 恒定且零内容重绘（账本验证）；弹窗动画帧内合成矩形 = 弹窗矩形 + 阴影环带。
**【开源复用】**脏区策略参照 Wayland damage tracking 与游戏引擎 dirty rect 文献；实现自研（既有四步主循环深化）。
**【设计细节】**光标层实现为硬件兼容路径（Ivy Bridge cursor plane 评估）或独立覆盖面（软路径兜底）；阴影按 16px 环带预渲染（不逐帧重算）；动画矩形集在动画注册时声明（合成器预先知道要碰哪里）；脏区合并算法 = 区间树相交合并（O(n log n)）。

### G-B-17 F057 IO 调度分级 · 完整设计

**【功能定义】**IO 队列三级：前台交互（菜单打开/搜索/缩略图）> 后台任务（下载/索引/构建）> 批量（备份/日志轮转）；调度按截止期+权重的混合策略；io-pending 指标（实测 9/9 pass 既有）细化为分级队列视图。
**【用户故事】**后台正在下载 2GB 文件的同时用户打开文件管理器——目录秒开（前台插队），下载匀速继续（后台饿不死）——互不拖累的感觉就是分级在干活。
**【交互设计】**监视器 IO 页三队列实时深度条 + 各队列吞吐曲线；下载类任务自动降级的提示出现在通知中心（透明可查）。
**【数据与存储】**队列结构定长环形；分级事件审计（谁被降级/为什么）入诊断快照。
**【状态与异常】**前台持续满载 60s → 后台完全暂停（防饿死反向保护：前台让出窗口计时）；批量任务超 30 分钟 → 分段让路（每 5 分钟让 1s）；配额（F195）与分级叠加生效。
**【验收判据】**「下载中打开目录」场景目录延迟 ≤ 无下载时的 1.2 倍；后台任务零饥饿（24h 混载测试全部完成）。
**【开源复用】**分级参照 Linux CFQ/BFQ 的 class 思想（极简三 class 版）；实现自研（存储栈既有队列扩展）。
**【设计细节】**class 判定：按发起进程标签（交互面进程=前台）+ 请求特征（读<64KB=交互倾向）；截止期参数：前台 50ms/后台 2s/批量无截止期；分级是调度顺序不改变 fsync 硬承诺（B-7xx 优先于一切）。

### G-B-18 F058 内存压缩前瞻 · 完整设计

**【功能定义】**冷页压缩池评估项：真实工作集超 3.2GB（水位高档 F045 持续一周触发）才立项启用；LZ4 级算法评估；先测后做——不提前上压缩。
**【用户故事】**（立项后）重度用户同时开大程序群——4GB 边界被压缩池悄悄扩到等效 5GB，慢一点但没崩没杀进程——**压缩是边界扩展器，不是常规武器**。
**【交互设计】**触发立项前：设置中心「系统-内存」页显示工作集趋势图（让用户看见「为什么我们建议关掉一个程序」）。
**【数据与存储】**工作集监测数据入账本；压缩池启用后结构：压缩页槽 4KB 框（定长零堆）。
**【状态与异常】**解压延迟超标（P99 >200μs）→ 池缩小；压缩比 <1.5 的页 → 不压缩（白费 CPU）；池满 → 回退 OOM 流程（如实告知用户）。
**【验收判据】**立项判据本身可验证：工作集数据采集脚本先跑一周出报告；启用后（若立项）解压延迟与压缩比双达标。
**【开源复用】**算法评估 zstd/LZ4（zlib 许可核验 F130）；思路参照 zswap/Windows MemCompression 文档。
**【设计细节】**「冷」定义：64 秒未触碰；压缩在空闲 CPU 时段批量做（F048 低频档窗口）；池大小动态 0-512MB；优先压缩文件备份页（重读成本高者）；本项整体是 R3 级评估件——立项文档先行，代码后行（纪律同 S406）。

### G-B-19 F059 网络小包优化 · 完整设计

**【功能定义】**smoltcp 批量收包路径：中断聚合（F050 同窗口）+ 批量轮询处理；每包处理耗时入账；SSH 交互打字延迟 ≤30ms 为体验线。
**【用户故事】**开发者在 VARIX 终端里 SSH 到远程服务器写代码——每个击键回显干脆利落，没有「小包处理不过来」的粘滞感——网络栈对小包的尊重就是交互的尊重。
**【交互设计】**无直接 UI；诊断面板网络页：包处理耗时分布 + 批处理率。
**【数据与存储】**统计入账本分钟聚合；无持久化。
**【状态与异常】**包风暴（>10k pps）→ 熔断限流 + 告警（保交互流优先）；批量路径 bug 兜底 → 单包路径热切换（运行时可切，诊断用）。
**【验收判据】**SSH 打字延迟 P99 ≤30ms 实测；10k pps 小包风暴下交互流延迟劣化 <20%。
**【开源复用】**批处理参照 smoltcp 官方示例与 NAPI 模式；实现自研（F023 面的性能层）。
**【设计细节】**批量窗口 = F050 中断合并窗口（一个窗口两处受益）；轮询 budget 每轮 64 包（超则让 CPU）；TCP ACK 延迟确认 40ms（交互流 5ms——分流参数）；小包定义 ≤512B；延迟测量打点在协议栈入口出口两端。

### G-B-20 F060 电量账本 · 完整设计

**【功能定义】**按应用能耗画像：CPU 时间 × 频率档 + 唤醒次数 + IO 量折算为相对能耗单位；设置中心电池页显示「今天谁在耗电」排行。

### G-B-21 F061 基准回归门 · 完整设计

**【功能定义】**vxbench 六类基准接 CI 夜跑（QEMU 替身）：装载/合成/存储/网络/调度/图像每类 2-4 条基准，基线倒退 >5% 即门禁红——性能资产像代码一样有回归保护。

**【开源复用】**门禁思路参照性能 CI 通用实践（coz/benchkit 类）；vxbench 本体自研（F053/F054 基准共用）。
**【设计细节】**夜跑窗口固定且独占（无其他任务污染）；基准间隔离：每基准独立 QEMU 实例；5% 阈值分基准可调（存储类噪声大放宽到 8%）；趋势图异常点可标注（固件更新/借力件升级等外因）。

**【状态与异常】**journal 恢复失败（极端损坏）→ fsck 路径 + 恢复环境（F198）兜底；journal 空间满 → 强制冲刷（延迟尖峰如实标注）。
**【验收判据】**断电百次（三档窗口 F046 各跑）全部自动恢复零 fsck；顺序写吞吐在 ordered 模式损失 <10%。
**【开源复用】**ext4 与 Google ext4 crate（F130 既有借力件）参数化使用；裁决文档参照 ext4 官方文档。
**【设计细节】**commit 间隔 = F046 窗口（一处一事实，不双参数）；journal 大小 128MB（4GB 内存机型均衡值，旋钮）；元数据 checksum 开启（v1 校验）；恢复后自动触发一次 B-703 子集复测（自证健康）。

### G-B-27 F067 启动 IO 冷热分离 · 完整设计

**【功能定义】**镜像分区布局分离只读区（内核/字体/资产）与可写区：只读区零 journal、零写放大；BOT 顺序读优势最大化（预读全开）。
**【用户故事】**系统更新后首次开机依然快——只读区的内容稳定（不变的文件不重写），U 盘对它们的读取永远走最优顺序路径。
**【交互设计】**无直接 UI；诊断中心启动时间线（F053）中「只读区加载」段耗时应显著优于可写段。
**【数据与存储】**分区布局设计文档化（偏移/对齐/大小三表）；只读区哈希清单用于完整性自查（F191 联动）。
**【状态与异常】**只读区哈希不符 → 启动链自查（F191）拦截进恢复环境；可写区满 → 提前预警（<500MB）。
**【验收判据】**只读区随机读延迟 P99 <2ms（U 盘实测）；启动段 IO 走并行（F053）后只读段耗时占比 <25%。
**【开源复用】**布局思路参照只读 rootfs（squashfs 类）设计经验；实现自研（镜像构建工具链）。
**【设计细节】**只读区对齐 4MB（大页 F051 联动）；资产按访问序物理排布（启动甘特图顺序=盘上顺序）；版本更新 = 只读区整体换槽（双槽 F190 语义）；可写区 journal 只为可写数据服务（职责不混）。

### G-B-28 F068 渲染资产按需装载 · 完整设计

**【功能定义】**壁纸/图标集/音效按当前主题（E1）惰性装载：未选中的主题资产不驻内存；内存占用差值入账本。
**【用户故事】**系统装了 10 套官方主题——用户只用一套时，内存里只有那套的资产（省下 9 套的空间给应用）；切换主题时旧资产卸载新资产流入（300ms 交叉淡入完成换装）。
**【交互设计】**无直接 UI；E1 切换的流畅度即体验面；诊断面板资产页显示当前驻留清单。
**【数据与存储】**资产文件按主题目录组织（4K 管线 C-7 产出）；驻留清单运行时维护。
**【状态与异常】**资产文件损坏 → 回退默认主题 + 诊断报备；切换时新资产解码失败 → 保持旧主题（不白屏）。
**【验收判据】**单主题驻留内存 ≤80MB（4K 全套实测）；主题切换全程无白屏闪烁（录屏帧检）。
**【开源复用】**无外部依赖；装载器复用图像解码面（F054）。
**【设计细节】**引用计数管理资产生命周期（最后一个引用卸载）；解码在后缓冲完成后原子换入（无中间态上屏）；音效文件小（<200KB 全量驻留不按需）；图标集按需粒度=单图标（常用 100 个预驻）。

### G-B-29 F069 性能模式三档 · 完整设计

**【功能定义】**静音/均衡/性能三档一键切换：联动 CPU 频率边界（F048）+ 写合并窗口（F046）+ 音频缓冲档（F064）+ 温度阈值；档位定义全走旋钮清单。
**【用户故事】**会议室里一键切静音档——风扇安静、频率封顶、续航优先；回家插电切性能档——全速释放——**一台机器两种性格，切换只要一秒**。
**【交互设计】**快速设置面板（F076）三档开关（当前档高亮）；切换 toast 显示生效项清单；每档的参数摘要悬浮可见。
**【数据与存储】**当前档持久化（重启保持）；切换事件入账本。
**【状态与异常】**温度强制降档（F197）覆盖手动性能档（安全优先）+ 通知说明；档位参数缺失（旋钮表版本不齐）→ 拒绝切换并诊断报备。
**【验收判据】**三档参数差异实测可辨（频率/写入量/续航三指标分档明显）；切换全程无音频爆音、无 UI 卡顿。
**【开源复用】**档位思路参照 Windows 电源计划；实现全走旋钮清单联动（无新机制）。
**【设计细节】**三档参数表：静音（频率≤中档/窗口 8s/缓冲 20ms）/均衡（自动 F048/窗口 5s/缓冲 10ms）/性能（全频/窗口 5s/缓冲 5ms）；切换动画 200ms（F124 标准曲线）；托盘图标三态区分；自动模式（F048）与手动档的叠加规则文档化（手动=边界，自动=边界内调节）。

### G-B-30 F070 性能域总判据 · 完整设计

**【功能定义】**80fps 整链验收制度：B 域四层（合成/启动/IO/调度）每层独立判据全绿后，整链在「常用 50 件」（F040）真实负载下复测 80fps——单层绿不算数，整链绿才交付。
**【用户故事】**收官那天，账本上 30 项 B 域判据逐条打绿，最后一条整链实测：50 件应用依次打开、拖动、切换——帧率曲线稳稳压在 12.5ms 线下——**这一条曲线是整个性能域的毕业证**。
**【交互设计】**星图/生态季报（F149）公布整链成绩单；诊断中心「性能域状态」页 30 项判据红绿一览（每项可点进证据）。
**【数据与存储】**成绩单版本化（季度快照）；证据链引用各单项判据记录（不复制）。
**【状态与异常】**整链复测中有应用拖垮帧率 → 该应用入「攻坚名单」单独优化（不降低总验收标准）；借力件升级后整链复测重跑（版本漂移防护）。
**【验收判据】**整链场景定义文档化（50 件的打开/操作/退出脚本化）；80fps 达标定义 = P95 帧耗时 ≤12.5ms 且 P99 ≤16.6ms；成绩单两份证据（录屏+账本导出）齐备。
**【开源复用】**负载脚本框架复用 F033 构建链工具；测量本体全自研（F041 账本）。
**【设计细节】**整链测试机锁定 Y7000（可比性）；测试环境温度记录（热节流干扰排除）；每次系统大版本（借力件升级窗）后整链必复测；达标线与红线分离：80fps 目标/60fps 底线——底线破即回炉，目标破即优化不停。

## C-2 开机进入动画（Boot Sequence Experience）

1. **序列设计**（四幕，总时长 ≤8 秒，可跳过——上限即 B 域 B2 验收线）：
   - 幕一「点火」：Limine 选单后的黑场中，一枚 VARIX 星徽从暗到亮（0.8s，缓出）；
   - 幕二「聚合」：星徽周围粒子/光线向中心汇聚，同步真实加载进度（进度条不许骗人——进度与真实 init 里程碑绑定，实测几秒就几秒）；
   - 幕三「点亮」：屏幕整体亮度渐升过渡到桌面（0.6s，桌面先骨架后内容）；
   - 幕四「呼吸」：桌面元素错落淡入（任务栏→图标→组件，错峰 80ms），落定后动画即止——**常驻动画只属于交互反馈，不属于待机**。
2. **技术约束**：动画帧率独立于桌面合成器（不互相拖累）；4K 帧资产预生成、运行时零实时模糊/光追类昂贵效果；跳过键（Esc/回车）第一帧即可用。
3. **断电安全**：动画中断任意帧 → 直接落桌面（动画是装饰不是关卡）。
4. **零代码开机（Variable 2026-09-25 拍板）**：开机全程用户**看不到任何内核自检文字**——现有 kinfo 自检输出（self-test PASS、MMIO、ACPI、xHCI 之类逐行日志）从用户视野移除，转入后台日志文件（开机后可在诊断中心查看）；Limine 选单阶段也换成图形化渲染（星徽背景 + 两枚图形条目 + 倒计时环），不再黑屏白字。开发场景保留快捷通道（按 D 键展开原始日志，仅限开发态镜像，用户镜像无此键）——**用户的开机是动画，工程的开机是日志，两者永不混在同一个屏幕上**。

**F046 写合并窗口自适应**——5 秒窗口按负载动态伸缩（空闲收窄到 1s、重载放宽到 8s，fsync 硬承诺不动）；旋钮联动走 ADR。
**F047 调度器延迟预算深化**——交互线程 p99 唤醒延迟 2000μs 预算拆到逐类（输入/合成/音频/普通），超标即归因报告——预算不是平均值是分布。
**F048 CPU 频率联动**——TSC 2500MHz 实测面之上做负载感知升降档（P-state 表驱动），降档不降交互预算；笔记本电池续航与手感联动的第一块旋钮。
**F049 空转清零工程**——合成器空闲 5% 判据（B-501）细化为「空闲态零定时器唤醒」（帧缓冲无脏区即休眠），待机功耗实测入账本。
**F050 中断合并**——输入/网络中断按突发窗口合并（2000ns 预算内批量处理），input-probe flood 已有 flood_dropped 计数（实测 70）——把丢弃变成合并，计数器归零为目标。
**F051 大页策略**——4MB 页用于内核静态区与字形图集，TLB miss 实测对比入账；R3 GPU 摸底时同步评估核显侧大页。
**F052 堆碎片治理**——内核堆（56KB 分块已实测）增长策略改为尺寸分级池，碎片率指标入账本；零堆纪律之外「堆健康」也要有数。
**F053 启动并行度**——init 里程碑依赖图显式化（ACPI/PCI/USB/存储四链并行），串行等待点逐个消除；开机 8 秒线（B2）的分解攻坚图挂账本。
**F054 图像解码 SIMD**——PPM/PNG/JPEG 解码走 SIMD（SSE4.2 基线，AVX2 探测后启用），解码耗时入 vxbench；壁纸 4K 解码 ≤150ms 为验收线。
**F055 字形光栅缓存**——字形图集按 LRU 热度驻留，冷字形驱逐热字形保位；滚动长文档的光栅耗时实测不抖动。
**F056 合成器脏区深化**——光标移动不触发全屏合成（光标层独立），弹窗动画只合成弹窗矩形——把「全屏重绘」从系统词典里删掉。
**F057 IO 调度分级**——前台交互 IO（打开菜单/搜索）优先级永远高于后台（索引/下载），io-pending 指标（实测 avg 9/9 pass）细化为分优先级队列。
**F058 内存压缩前瞻**——4GB 边界的冷页压缩池（LZ4 级算法评估）立项评估不急于上——先测真实工作集，超 3.2GB 再启用。
**F059 网络小包优化**——smoltcp 描述符混表（B-602）之上的批量收包路径，每包处理耗时入账；终端 SSH 打字延迟 ≤30ms 为体验线。
**F060 电量账本**——按应用的能耗画像（CPU 时间/唤醒次数/IO 量折算），设置中心「电池」页显示「今天谁在耗电」——功耗透明是 U 盘整机的体验面。
**F061 基准回归门**——vxbench 六类基准接入 CI 夜跑（QEMU 替身），基线倒退即门禁红——性能资产和代码资产一样不许悄悄缩水。
**F062 性能自检报告**——开机后 10 分钟静默采样生成「系统健康快照」（帧率 P95/IO 延迟/调度超标次数），异常自动转诊断中心工单——性能问题在用户感知之前先被系统自己看见。
**F063 触控板手势前瞻**——HID 触控板多指手势协议评估（Y7000 触控板实测定级），不承诺但把数据面留好。
**F064 音频低延迟链**——混音器单流延迟 ≤20ms 实测线（音乐类应用的可用性门槛），CORB/RIRB 环形缓冲调优入账。
**F065 唤醒源治理**——USB 键鼠（xHC 已 live）之外的唤醒源白名单化，睡眠态每分钟唤醒次数 ≤1 为达标；待机耗电从查不到变成有账。
**F066 文件系统日志策略**——ext4 journal 模式按分区特性选型（data=ordered 基线），断电百次与性能双达标为准；journal 参数进旋钮清单。
**F067 启动 IO 冷热分离**——镜像内只读区（内核/字体/资产）与可写区物理分离，只读区零 journal 开销；BOT 顺序读优势最大化。
**F068 渲染资产按需装载**——4K 壁纸/图标集按主题加载（当前主题外资产不驻内存），内存占用差值入账本——丰盛与省内存兼得。
**F069 性能模式三档**——静音/均衡/性能三档一键切换（调度预算+频率+写合并窗口联动），任务栏托盘直达；档位定义全走旋钮清单，无隐藏魔法数。
**F070 性能域总判据**——80fps 红线（B-2 补）之下每层都有独立判据与账本页，四层优化逐层绿才整链绿——**总指标是试金石，分层判据是施工图**。

## F-E 个性化域深化（F151-F170）

**F151 主题令牌全集**——颜色/间距/圆角/字号/动效五类令牌全表（JSON Schema 发布，F126 面），E1 换装 = 令牌表热替换；零硬编码纪律（B-1104）是技术地基。
**F152 实时预览编辑器**——设置中心「个性化」页：改令牌即时全屏预览（改圆角立即看效果），「应用/放弃」双按钮——所见即所得。
**F153 主题深浅自动切换**——按时间/日落日出自动在深浅主题对之间切换（跨零点无闪烁，动画 300ms）。
**F154 壁纸每日一换**——本地图片池轮换 + 「每日精选」可选（下载面，无商店原则照走）；切换动画交叉淡入 500ms。
**F155 图标包热更换**——E3 承载：换包不重启、失败回退上一包（E-1 铁律三步验收：改→生效→回退）。
**F156 指针编辑器**——指针热点/尺寸/动效在图形编辑器内调整，4K 双倍率 sprite 自动生成。
**F157 声音混合器**——E5 承载：事件音量独立调节 + 试听按钮 + 「全部静音」总闸。
**F158 开始菜单布局预设**——「效率/简洁/全屏」三官方预设一键切换（E6），用户自定义布局保存为第四套个人预设。
**F159 字体安全档**——E7 换字体前自动兼容性预检（缺字率扫描），缺字率 >5% 给黄色警告——个性化不许破坏可用性。
**F160 动效强度预演**——E8 三档切换前出对比演示动画（同一段动画三档并排预演），选完再应用。
**F161 个性化档案导出**——全部 E 域配置打包 vxtheme（F-E 铁律），含版本号与回滚链；换 U 盘/重装导入即复原。
**F162 每应用主题例外**——个别应用可脱离全局主题（「终端用深色其余浅色」），例外清单上限 10 项——全局一致性优先，例外显式可控。
**F163 桌面小组件开关集**——时钟/天气/系统快照（F062 数据）三枚官方小组件，桌面右键「添加小组件」启用；组件走 4K 管线与 E1 令牌。
**F164 锁屏定制**——锁屏壁纸/时间样式/状态信息（电量/日期）可配置，锁屏动画复用开机四幕语汇的静版。
**F165 开机动画个性化**——四幕动画的配色/粒子密度可调（结构不动），用户壁纸可作幕三「点亮」的过渡底——标准不可改，皮肤可以。
**F166 输入法皮肤**——候选窗配色/字体/透明度随 E1 主题或独立定制，组合期渲染延迟 ≤16ms。
**F167 右键菜单自定义**——用户可隐藏不常用菜单项（白名单恢复），应用注册的菜单项按使用频率自动排序可选。
**F168 任务栏个性化**——图标大小/居中或左对齐/自动隐藏三选项（对齐 Windows 档位），改后即时生效。
**F169 快捷键查看器**——全局快捷键总表页（按应用/按场景分组），冲突检测显式提示——快捷键是契约，契约要可查。
**F170 个性化域总判据**——E-1 三铁律（随时可改/随时可退/预设+微调）对 F151-F169 逐项实测打勾，任何一项「改完要重启」即整项不达标。

## F-G 内核底盘与安全深化（F171-F200）

**F171 图形化引导选单**——Limine 黑底文字选单换成星徽图形渲染（C-2 零代码开机条款的引导面），选单数据不变、渲染层重写。
**F172 引导自检可视化压缩**——kinfo 自检（9/9、11/11 全 PASS 实测面）收敛为一枚进度环 + 四个里程碑图标（内存/进程/存储/输入），文字全入后台日志。
**F173 panic 画面设计**——崩溃画面 ≠ 蓝屏复刻：VARIX 语汇的「星陨」画面（错误码+二维码指向帮助 F119+自动重启倒计时），panic 百次演练（B-2903）同步验证新画面。
**F174 诊断快照键**——任意时刻 Ctrl+Alt+D 静默生成系统快照（账本/日志/调用栈）存诊断中心，全程 UI 零打扰——给问题排查留「案发现场」。
**F175 崩溃隔离强化**——应用崩溃只崩应用（AI2 隔离纪律），崩溃后桌面帧率不跌、其他窗口可交互；崩溃应用的窗口标灰 + 「重新启动应用」按钮。
**F176 内存守卫**——内核堆红线越界检测（guard-host 自检已有）扩面到兼容层沙盒堆，越界即崩应用不崩内核——兼容面是重灾区，守卫先行。
**F177 能力执法可视化**——四个执法点（B-15xx）的拦截事件进通知中心（可关），用户看得见安全系统在工作——安全存在感是信任感。
**F178 签名状态角标**——未签名运行的应用窗口角标 + 任务栏悬停提示（不阻断，如实标注）——「知道自己在跑什么」是用户的权利。
**F179 权限审计页**——设置中心「隐私和安全性」：每应用的权限授予史/越权尝试/网络访问统计，一键收回——权限不是设完就忘。
**F180 断电演练自动化**——QEMU 断电百次脚本化夜跑（替身注入 B-4101），结果分布进周台账——数据红线靠机器守不靠人记得。
**F181 交接预检器**——切 Windows 域前自动预检（目标链存在/哈希/空间），预检不过给修复建议而非放行——防自锁闸门（三条件）的用户可见化。
**F182 双域时钟同步**——交接时 UTC 时间戳互写快照，跨域文件时间戳零漂移——小细节大信任。
**F183 存储健康监测**——U 盘 SMART 等价数据（ext4 错误计数/写入量累计）入设置中心存储页，寿命预估诚实区间显示——耗材也要透明。
**F184 热插拔体验**——U 盘/SHARED 卷插拔通知 + 安全弹出按钮（冲刷完成后才允许弹出，进行中写入则禁止并说明）——数据安全的日常形态。
**F185 只读卷保护提示**——NTFS 只读挂载（B-705）在资源管理器显示「只读」徽标 + 原因解释——限制有说明，不给用户「坏了」的错觉。
**F186 系统分区不可见**——引导/交接分区从资源管理器隐藏（防误写），设置中心「磁盘管理」高级页显式可见（只读）——红线让位给防呆。
**F187 时区与时钟守护**——RTC 漂移校正 + 时区切换向导（跨时区使用 U 盘整机的真实场景），NTP 走网络栈（B-60x）可用时自动校。
**F188 日志三环**——内核环形日志/系统日志轮转/应用日志三环分置，各环上限与覆盖策略在册（B-3802/3803 收尾判据承接），诊断中心可导出合并视图。
**F189 静默自愈集**——图标缓存损坏/主题令牌缺失/缩略图库损坏三类常见损坏自动重建（重建过程通知中心报备）——小病自愈不劳用户。
**F190 更新双槽可视**——A/B 槽当前态在设置中心显示（含上个版本回滚点保留期），更新前强制展示「回滚窗口」——B-1304/B-1305 的透明面。
**F191 安全启动链自查**——每次开机 peblock 门/签名链/W^X 三自查结果进诊断快照（F174），自查失败阻断桌面进入并显示图形化原因——启动链健康是第一公民。
**F192 内核参数白名单**——启动参数仅接受白名单（调试/降级/安全模式三族），未知参数拒绝并记录——引导面不接受自由文本。
**F193 安全模式**——禁用第三方驱动/默认主题/最小服务的救援模式（Limine 菜单图形条目），进入路径与退出路径都文档化——系统永远给自己留一条路。
**F194 审计日志完整性**——安全类日志（越权/门拦截/签名失败）append-only + 序号链（篡改可检测），导出带哈希——审计日志自己先不可抵赖。
**F195 资源配额执行**——每应用内存/IO 配额（MD2 附录 K）超限时降级不终止（后台应用优先降），配额面板可查——失控应用掐流量不掐命。
**F196 电池保护策略**——U 盘整机宿主电池（Y7000）电量 <15% 提示、<5% 主动冲刷+安全关机（B-2902 关机账目照走）——没电也要体面地睡。
**F197 温度感知降档**——宿主温度传感器可读时高温降档（联动 F069 性能三档自动切静音），数据不可读时优雅跳过（graceful 纪律同 NOWE 控制器实测）。
**F198 恢复环境**——镜像内嵌最小恢复环境（引导修复/还原点回滚 F121/日志导出三件），从安全模式（F193）或安装介质可达——最后的救命稻草也做成作品。
**F199 版本与谱系页**——「关于本机」展示系统谱系（STAR I → STAR I start 的版本树/本镜像构建指纹/可复现构建哈希）——每台机器知道自己从哪来。
**F200 全域总检**——F001-F199 的验收锚点汇成总检清单进 20 维度验收脚本，季检滚动复查；**200 项不是终点是基线——每季度审视一次，有现实契机才增补，永远不为功能多而加功能**（MD1 第 20.4 章纪律的全域版）。
