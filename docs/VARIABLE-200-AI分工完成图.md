# VARIABLE-200 AI 分工完成图（完整版 · 内核并入 Variable 系统）

> 共 **8 个 AI**（AI-01 ~ AI-08），围绕 **"Varix 内核并入 Variable 系统"** 全域分工，
> 每域 25 项，合计 **200 项功能**（F001~F200）。
> 状态：⬜ 未开始 / 🔶 进行中 / ✅ 完成
> 纪律：
> 1. 每个 AI 只修改自己域的模块：内核侧在 `kernel/varix/src/`（沿用一域一文件约定），
>    用户态侧在 `kernel/userspace/`（新 workspace），AURORA 移植产物在 `kernel/userspace/aurora/`；
>    **不碰 `src/`、`src-tauri/` 的 Windows 后端**（回滚纪律：只增不删）。
> 2. 共享文件（本图、总步骤图、全景图）编辑前先 `git log` 验 HEAD。
> 3. 完成一项：更新本图 → commit（`var200(ai-XX): Fxxx <功能名>`）→ 推送 GitHub。
> 4. 质量军规：手感无损、画质无损、性能预算、可回滚、降级纪律、崩溃不扩散、零重复、完成即自检（不写报告）。

## 协作与提交纪律

1. 提交信息：`var200(ai-XX): Fxxx <功能名>`，一功能一提交或一域一批。
2. `kernel/varix/src/lib.rs` 的 `pub mod` 列表多方追加，提交前必须复查未被覆盖丢失。
3. 多会话并行：只挑自己域的路径 `git add`，禁止 `git add .`；
   **禁止 `git pull --rebase --autostash`**（血泪纪律，见项目 MEMORY）。
4. 自检接线：每域 25 项 CheckSet 全部汇入 `robust::run_kernel_checkup()`，
   boot 自检清单随域完成逐步扩充，任何一项红即不得提交。
5. 内核命令：`cargo kcheck` / `cargo ktest --lib` / `cargo kbuild` 全绿才提交；
   QEMU 引导冒烟（串口至 boot complete）每域收口必跑。
