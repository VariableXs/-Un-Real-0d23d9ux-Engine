## 第 0 章 终极形态的定义（十条总口径）

终极形态达成 = 在任何一台满足「Windows 10/11 x64 + USB 口」的电脑上，以下十句话**全部**成立：

1. 双击引导器，3 秒内进入我的桌面环境（壁纸是我上次的）；
2. 任务栏 AI Hub 点开，`claude` / `codex` / `zcode` 三张卡全部「已登录」；
3. 左手 VS Code、右手双标签终端（PowerShell + Git Bash），全在环境内；
4. 浏览器两个 profile 同时在线两个不同账号，Cookie 谁也不串；
5. 完成一次真实的「拉仓库 → AI 改代码 → 测试 → 签名提交 → push」；
6. 嵌入一个第三方软件，系统任务栏与 Alt+Tab 里看不到它；
7. 创建一个试验子环境，糟蹋完退回，主环境毫发无损；
8. 1TB 测试卷上完成大文件流式拷贝与冷区归档，GC 无感；
9. 退出时残留扫描输出 0；宿主 `%USERPROFILE%` 与注册表干干净净；
10. 拔盘、换一台电脑、重插——一切如初。
11. **（第二部新增）** 开机即进入 Variable（VM 档登录即桌面；直跑档可选开启），双 Esc 随时可回 Windows，但 Variable 是默认与主要的；
12. **（第二部新增）** 任何软件窗口都出现在 Variable 里：VM 档默认程序 + 回收看门狗兜底，Windows 桌面（若被唤出）上不留一个应用窗口；
13. **（第二部新增）** 基础功能不输 Windows：设置中心/工具集/任务管理器/全局搜索/通知动作/自更新俱全，且整套设计语言经 Design Tokens 统一——精致如艺术品。

**新增的愿景级目标**（超出原 MASTER-PLAN，本计划以新批次号 L-*/W-*/C-*/X-*/S-*/V-*/E-* 标注）：

- L-*：引导器 + 硬件自动探测渲染分级 + Hyper-V 自动化 + 家庭版降级链；
- W-*：VWM 2.0（布局快照/标签页化/多嵌入并发/热切换重排）；
- C-*：四层自动分级兼容引擎（增强重父化/容器包裹/画面捕获输入转发/智能让位）；
- X-*：扩展生态系统（Web 扩展/Tauri 插件/外部进程 + 权限模型 + 商店）；
- S-*：防截屏模式（SetWindowDisplayAffinity）；
- V-*：便携虚拟系统收口（AI3 补齐/差分链/U 盘调优/加密/四阶段交付）；
- E-*：执行档全量化 + 零残留退出集成；
- **F-*（第二部）**：基础功能完备化（设置中心/工具集/任务管理器/全局搜索/自更新/无障碍）；
- **D-*（第二部）**：开机直进 Variable + 全域软件接管（Shell 替换/回收看门狗/幕布切换）；
- **A-*（第二部）**：艺术品级界面精修（Design Tokens/动效体系/视觉审计/声音设计/换装）。

## 第 4 章 阶段 P2：容器与 1TB（B-12…B-17，技术最重）

**总目标**：三档存储后端落地（Dir 兜底 / VHDX 快速档 / Uxv 终态），1TB 分卷、快照、加密、掉电安全；数据目录 → 容器迁移向导。

### 4.1 B-12 ChunkIndex（B+ 树）+ BLAKE3 去重 + 流式读写（1.5 批）

**任务分解**：
1. `container/src/index.rs`：B+ 树实现（阶 64，叶子存 chunk 定位 `[volume_id, offset, len]`），键 = BLAKE3-256 内容哈希；
   - 节点序列化到 mmap 文件（`container/index.bin`），崩溃后可由 journal 重建；
   - 单元测试：10 万键插入/查找/删除，随机序与顺序序两种负载。
2. `container/src/chunk.rs`：定长 64KB chunk + 尾部截断 chunk；写入路径 `put(stream)` → 分块 → 逐块哈希 → 去重查询（命中跳过写）→ 追加到当前 segment（`container/seg-<n>.dat`，64MB 滚动）；
3. 读取路径 `get(key) -> AsyncRead`：按 chunk 定位拼接，实现 `Stream` 接口供大文件边下边读；
4. `DirBackend` 行为等价包装：路径透明映射，老数据无感（`StorageBackend` trait 不变）；
5. 基准：`tools/bench.cjs` 增 `container.put/get`（1GB 混合负载），热 chunk 随机读 < 20ms。

**验收**：[ ] 10 万 chunk 随机读 P99 < 20ms；[ ] 重复写同内容磁盘占用不增长；[ ] cargo test 全绿（含崩溃中断写后索引重建用例）。

**回滚**：DirBackend 永久保留可切换；Uxv 未启用前无迁移。

### 4.2 B-13 Journal 事务 + checkpoint + 掉电注入（1.5 批）

**任务分解**：
1. `container/src/journal.rs`：追加式 WAL（crc32f 帧校验），每个逻辑事务（多 chunk 提交）= journal 里一条 BEGIN/COMMIT 对；
2. checkpoint：segment 满 64MB 或 journal 超 32MB 时把 journal 合并进索引 + segment，截断 journal；
3. 恢复流程：启动时重放 journal 未 checkpoint 事务 → 前滚索引；损坏帧截断到上一好帧；
4. **掉电注入测试**（CI 可跑的模拟层）：`KillUndici` 测试钩子在 put/get 随机点 `abort()` 进程 → 重启 → 断言数据集一致性（100 次循环，cargo test `#[ignore]` 手动跑，CI 抽 10 次）；
5. 快照事务语义：多文件原子可见（读方要么全看到要么全看不到）。

**验收**：[ ] 掉电注入 100 次 0 数据丢失；[ ] journal 重放耗时 < 500ms（1GB 负载）；[ ] 快照原子性用例通过。

**回滚**：journal 可整体禁用（`storage.journal=false`，退化为最终一致模式并横幅声明）。

### 4.3 B-14 压缩 + 加密（1 批）

**任务分解**：
1. `container/src/crypto.rs`：Argon2id（m=64MB,t=3,p=1）从用户口令派生主密钥 → 每 segment 随机 nonce → XChaCha20-Poly1305 每帧加密；主密钥封存 `container/keyring`（可选 TPM 绑定，失败降级口令）；
2. `container/src/codec.rs`：帧级压缩 LZ4（默认）/ Zstd-19（冷区），压缩前加密后（顺序：compress → encrypt）；
3. 已写数据不可逆改密：提供 `rekey` 离线工具（读旧密钥流式重写）；
4. 密钥错误 → 明确错误文案 + 「口令丢失 = 数据不可恢复」双重确认。

**验收**：[ ] 加密开关下吞吐损失 < 30%（NVMe 基准）；[ ] 错误口令打开失败且无 panic；[ ] 压缩比报告（文本代码库 ≥ 2.5:1）。

**回滚**：加密/压缩均为创建容器时的选项，旧容器（明文）继续可读。

### 4.4 B-15 多卷条带 + GC 分代回收（1.5 批）

**任务分解**：
1. `container/src/volumes.rs`：卷表（`volumes.json`：卷 id/路径/容量/健康态）；新 chunk 追加到「当前写卷」，当前写卷满 → 滚动到下一卷（轮转条带，不做 RAID 式并行写——U 盘单卷场景为主）；
2. 跨卷文件：文件 chunk 分布多卷，索引已按 chunk 定位天然支持；
3. **GC 分代**：引用计数（索引反向引用）+ 三代扫描（年轻代每 checkpoint / 中年代每日 / 老年代每周）；垃圾 chunk → segment 碎片率 > 40% 触发 segment 整理（读出活 chunk → 写新 segment → 删旧）；
4. 卷拔除/故障：卷标记 offline，读命中该卷 → 如实报错「数据卷缺失」；不自动删索引；
5. 1TB 盘验收：单盘分卷（数据卷 + 系统卷 + 备份卷三个稀疏测试卷），多卷轮转逻辑不变，为未来更大介质留好扩展。

**验收**：[ ] 跨卷读写与 GC 用例通过；[ ] GC 暂停 < 100ms（后台线程 + 分时切片）；[ ] 拔卷场景 0 panic、UI 如实降级。

**回滚**：单卷模式永远可用（volumes 长度 = 1）。

### 4.5 B-16 VHDX 快速档 + 迁移向导（1 批）

**任务分解**：
1. `container/src/vhdx.rs`：管理员探测（`Mount-VHD` 可用性）→ 挂载/卸载/自动扩展（`Resize-VHD`）；无管理员 → 探测失败如实标注并回落 Dir/Uxv；
2. `VhdxBackend`：挂载点内仍跑 Uxv（VHDX 只是介质，非文件系统方案）；
3. **迁移向导 UI**（设置→存储→迁移）：
   - 步骤 1：扫描现数据目录（`%APPDATA%\com.variable.app` 或便携 `data/`）逐文件清单 + 总量；
   - 步骤 2：目标容器选择（新建 Uxv / 现有容器）；
   - 步骤 3：逐文件复制 → BLAKE3 双端校验 → 失败重试 3 次；
   - 步骤 4：全量校验通过 → 原目录改名 `data.migrated-backup`（保留 30 天，用户确认后「焚毁」）；
   - 任一步失败 → 原目录原样保留 + 明确错误定位（文件/字节偏移）；
4. 迁移过程可取消（断点续传：按文件粒度记录进度）。

**验收**：[ ] 真实数据目录（含 10GB 媒体）迁移后逐文件哈希比对通过；[ ] 中途拔电 → 重跑向导续传成功；[ ] 回滚 = 把 `data.migrated-backup` 改回原名。

### 4.6 B-17 容器仪表 + 冷热分层 + 挂起项目（1 批）

**任务分解**：
1. 任务栏水位线小组件：容器已用/总量/写放大比，点击开「存储」设置标签；
2. 设置→存储：后端切换（Dir/VHDX/Uxv）、加密状态、卷健康、GC 计划、迁移向导入口；
3. 冷热分层：按 atime 老化（默认 90 天）标记冷 chunk → Zstd-19 重压缩；访问命中冷区 → 透明解压并升回热区；
4. 「挂起项目」：文件管理器右键大目录 → 一键冷存（元数据保留、内容移入冷区并可离线卷）；唤回 = 反向。

**验收**：[ ] 水位线数据与实际占用一致（误差 < 1%）；[ ] 冷区命中延迟 < 80ms；[ ] 挂起/唤回往返内容哈希不变。

**回滚**：分层/挂起均为标记操作，可整体关闭。

## 第 5 章 阶段 P3：引导器与硬件自动分级（L-1…L-3，新增）

**总目标**：实现愿景开头那一段——插上 U 盘双击引导器 → 3 秒探测硬件 → 自动配置虚拟化/渲染策略 → 进入自己的桌面。宿主机上零安装。

### 5.1 L-1 SystemLauncher 引导器（1.5 批）

**任务分解**：
1. **形态决策**：引导器为单一 `Variable-Launcher.exe`（Rust，无 Tauri 依赖，约 3MB），放 U 盘根目录；同目录 `launcher.toml` 配置（VHDX 路径、内存/ CPU 配额、引擎 exe 相对路径）；
2. **探测管线**（`launcher/src/probe.rs`，目标 < 3s）：
   - OS 版本/构建号（`RtlGetVersion`）、是否家庭版（注册表 `EditionID`）；
   - Hyper-V 可用性：`Win32_ComputerSystem HypervisorPresent` + `Get-VM` 模块探测（WMI `Msvm_ComputerSystem`）；
   - CPU 核数 / 可用内存（`GlobalMemoryStatusEx`）；
   - GPU：`EnumAdapters`（DXGI）取描述 + 专用显存；
   - 显示器：`EnumDisplayMonitors` 数量 + 每屏分辨率/DPI；
   - 探测结果 JSON 缓存 `probe-cache.json`（同一宿主机二次启动跳过重探测，mtime 失效重探；不做每次启动的介质写测试——伤 U 盘寿命，删减见 25.4）；
3. **VM 编排**（`launcher/src/vmrun.rs`）：PowerShell `Mount-VHD` + `New-VM`（代际 2、关 Secure Boot 模板、动态内存、`Add-VMDvdDrive` 免 ISO 直挂 vhdx）→ `Start-VM` → 等待心跳端口（VM 内 agent 监听 127.0.0.1:47631）→ 全屏窗口化 VMConnect；
4. **VM 内 Agent**（`src-tauri` 新 feature `vm-agent`）：心跳 + 「引擎已就绪」事件 + 退出时通知宿主卸盘；
5. **UI**：极简进度窗（探测/挂载/启动/接管四阶段真实进度，复用启动仪式视觉语言）；
6. **失败路径**：每阶段失败 → 明确文案 + 一键打开诊断包（蓝图附录 F）+ 从不自动删除任何东西。

**验收**：[ ] 支持Hyper-V 的宿主机双击 → 90s 内进 VM 桌面（VM 冷启动占大头，引导器自身 < 5s）；[ ] 二次启动（缓存命中）引导器 < 3s；[ ] 全程宿主零注册表写入、零启动项。

**回滚**：引导器完全独立，删除不影响既有便携目录模式。

### 5.2 L-2 硬件自动分级渲染（1 批）

**任务分解**：
1. `src/system/perf/autoTier.ts`：启动时读引导器/引擎探测结果（无引导器时引擎自查：`navigator.gpu`/WebGL renderer 字符串 + `devicePixelRatio` + 内存）；
2. 分级规则：
   - **S 档**（独显 ≥ 4GB / 集显新架构）：完整 WebGL 星空 + 极光 Ray-Marching + 毛玻璃窗口动效；
   - **A 档**（集显 / 内存 ≤ 8GB）：星空开、极光半分辨率、贴靠动画简化；
   - **B 档**（低配核显 / VM 无 GPU 加速）：静态星空单帧 + 视频壁纸降帧 30fps + 关粒子；
   - **C 档**（检测到 `SafeMode` 或渲染超时）：全静态；
3. 现有 `bgTier` / `reduceMotion` 改为「手动覆盖优先，否则自动」；设置页显示「当前自动档位」及改手动入口；
4. 渲染超时看门狗：首帧 > 3s 自动降档一次并持久记忆该宿主机（key = GPU 描述哈希）。

**验收**：[ ] 三档机器各实测符合预期档位；[ ] 手动覆盖后不再被自动改；[ ] 降档过程无白屏/闪烁。

### 5.3 L-3 Hyper-V 自动化与降级链（1 批）

**任务分解**：
1. Hyper-V 未启用：引导器弹确认 →（用户同意）管理员提权重启流程执行 `Enable-WindowsOptionalFeature -Online -FeatureName Microsoft-Hyper-V -All` → 提示重启 → 重启后续跑（引导器写 `pending-state.json` 于 U 盘，开机自启一次由用户手动双击续跑——**不写宿主启动项**，如实声明）；
2. 家庭版 / Hyper-V 不可用降级链（按序探测，UI 显示当前档）：
   - 档 1：Hyper-V 完整 VM；
   - 档 2：VirtualBox Portable（U 盘自带 `runtime/vbox/`，`VBoxManage` headless + 全屏）；
   - 档 3：**轻量直跑模式**（现便携目录模式：Variable 直接跑宿主机 + 执行档重定向容器，隔离弱但功能全，UI 明示隔离等级差异）；
3. 每档一份能力诚实清单（VM 隔离 ✓/直跑 ✗ 等），切换入口在设置→存储→运行环境。

**验收**：[ ] 三档各在一台真机走通；[ ] 降级全程用户可取消；[ ] 轻量模式下 residue-check 仍 `--expect-clean`（执行档兜底）。

## 第 7 章 阶段 P5：四层自动分级兼容引擎（C-1…C-8，愿景核心）

**总目标**：把「几乎所有软件无感纳入 VWM」做成自动分级系统。四层定义：

| 层 | 名称 | 适用 | 现状 |
| --- | --- | --- | --- |
| L1 | 增强重父化 | 标准窗口应用（约 75%） | 雏形（单次捕获单实例） |
| L2 | 容器包裹 | 自绘/非标框架窗口（约 10%） | 无 |
| L3 | 画面捕获+输入转发 | UWP/沙箱/拒绝重父化（约 10%） | 无 |
| L4 | 智能让位 | 全屏独占/反作弊/专业输出（约 5%） | 全屏避让雏形 |

### 7.1 C-1 L1 增强：常驻窗口监护（1.5 批）

**任务分解**：
1. `embed.rs` 增 `WinEventHook`（`SetWinEventHook EVENT_OBJECT_CREATE/SHOW/LOCATIONCHANGE`，进程内消息泵线程）：过滤目标 pid 树 → 新主窗口自动走捕获链（剥边框→SetParent→bounds 上报）；
2. 窗口消失事件 → W-3 占位卡状态机；窗口重建（应用自重启子窗口）→ 自动重嵌；
3. pid 树动态扩展：Toolhelp32 快照常驻轮询（2s）合并新后代进程（Chrome 类多进程）；
4. 资源护栏：监护线程 CPU < 1%（事件驱动为主，轮询兜底）。

**验收**：[ ] 嵌入 Chrome 后新弹窗（如设置页）自动入 VWM；[ ] 应用内部自杀子窗口重建不脱嵌；[ ] 空闲 CPU 占用 < 1%。

### 7.2 C-2 L1 增强：捕获可靠性工程（1 批）

**任务分解**：
1. 捕获超时分级：30s（现有）→ 快启动应用 < 5s 命中率统计 → 超时自适应延长（登记 `captureTimeout`）；
2. 匹配策略顺序：pid 树新窗口（现）→ 窗口进程映像名 → 窗口标题正则（登记可选）→ 用户手动点选（新增：超时占位卡上「框选窗口」进入 5s 十字准星模式，EnumWindows 高亮命中）；
3. 失败证据包：超时时自动收集 EnumWindows 快照 + 进程树 → `logs/embed-fail-<ts>.json`，供实测矩阵回填；
4. 30 款软件回归清单固化进 `portable/AI5/Data/compat-matrix.json`（复用 Top200 矩阵结构）。

**验收**：[ ] Top30 清单 L1 命中率 ≥ 90%；[ ] 手动框选兜底 100% 可用（有窗口者）。

### 7.3 C-3 L2 容器包裹引擎（2 批）

**任务分解**：
1. 判定条件（探测器输出，见 C-6）：`WS_CAPTION` 缺失 + 无标准非客户区 + `GetWindowLong(GWL_STYLE)` 自绘特征 → 路由 L2；
2. `container_host`：创建 Variable 自己的 WS_OVERLAPPEDWINDOW 宿主窗口（NativeWindow，非 webview）→ 把第三方窗口 `SetParent` 进宿主客户区（不剥其样式）→ 宿主窗口再作为 VWM 嵌入对象；
3. 拖拽/缩放/贴靠全部由宿主代理：宿主 WM_SIZE → `SetWindowPos` 同步第三方窗口到客户区；
4. 键盘焦点：宿主 `WM_SETFOCUS` → `SetFocus(第三方子窗口)`；
5. 主题融合：宿主窗口背景/标题栏走红绿灯自绘（复用 CloseLight 视觉）；
6. 用例：Qt 自绘应用（如 OBS）、游戏启动器壳。

**验收**：[ ] OBS 经 L2 嵌入可拖缩贴靠；[ ] 键盘输入直达第三方；[ ] 宿主关闭 = WM_CLOSE 链路（不杀进程）。

### 7.4 C-4 L3 画面捕获 + 输入转发（2.5 批，难度最高）

**任务分解**：
1. **捕获**：`Windows.Graphics.Capture.GraphicsCaptureItem`（WinRT，Win10 1903+）→ Direct3D11 纹理 → 共享纹理句柄 → 前端经 `SharedTexture` 送 WebView2 合成（或 CPU 回退 `ID3D11StagingAsImage` 30fps）；帧率自适应（变化检测，静止降 5fps）；
2. **窗口隐藏**：真实窗口 `SetWindowPos(-32000,-32000)` 移出屏外 + `WS_EX_TOOLWINDOW`（不出 Alt+Tab）——**不最小化**（避免部分应用暂停渲染）；
3. **输入转发**：VWM 窗口内鼠标/键盘事件 → 归一化坐标（0..1）→ 映射真实窗口客户区物理坐标 → `SendInput`（配合 `SetCursorPos` + `SetForegroundWindow` 抖动保护：转发瞬间抢焦点、移出即还）；
4. **剪贴板/拖拽**：天然系统级共享（同进程会话），无需额外处理，如实文档化；
5. **延迟预算**：目标 1-3 帧（16-50ms）；bench：`tools/bench.cjs` 增 capture 端到端延迟测量（高帧率计时器点击→像素变化）；
6. **失败降级**：WinRT 不可用（旧系统）→ 独立窗口模式 + 横幅。

**验收**：[ ] 一款 UWP 应用（如计算器）经 L3 完整操作；[ ] 端到端延迟 P95 < 50ms；[ ] 输入不泄漏到屏幕上其它区域（屏外真实窗口坐标钳制）。

## 第 22 章 阶段 P17：开机直进 Variable 与全域软件接管（D-1…D-5，新增）

**总目标**：开机 = 进入 Variable；任何软件的窗口永远出现在 Variable 里，而不是 Windows 桌面上；随时可切回 Windows（双 Esc 既有语义），但 Variable 是默认与主要的。三条实现路径按运行档分级：**VM 档**（最彻底——VM 内 Windows 的 Shell 就是 Variable）、**胶囊/直跑档**（用户级 Shell 替换，默认关闭的可选强化）、**普通安装版**（不替换 Shell，仅做关联与回收）。

### 22.1 D-1 VM 档：登录即 Variable（1 批）

**任务分解**：
1. **Shell 替换**：VM 内注册表 `HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Winlogon` 的 `Shell` 值 = `C:\Variable\Variable.exe`（替代 explorer.exe）；
   - Variable 启动时若检测到自身为 Shell（`SM_CXSCREEN` 环境探测 + `GetShellWindow()` 返回非 explorer 窗口）→ 启动仪式进入「Shell 模式」；
   - **依赖兜底**：explorer 相关能力（通用文件对话框、右键 Shell 菜单、拖拽 Shell 集成）在无 explorer 下的行为实测清单（约 20 项）→ 有缺失则 Variable 启动时以隐藏窗口方式拉起一个 `explorer.exe`（`/noautorun` 参数）作为服务进程——窗口层不出现、能力层可用（登记为受管进程，零残留退出时一并处理）；
2. **登录即 Variable**：VM 自动登录（`netplwiz` 配置或 Autologon for Windows，密码进 VM 内 DPAPI）→ Winlogon Shell 直起 Variable → 启动仪式即「开机画面」，从按下电源到桌面全程无 Windows 桌面闪现；
3. **锁屏**：Variable 电源菜单「锁屏」= 调用 `LockWorkStation`，VM 内锁屏后输入密码回到 Variable（Windows 锁屏背景替换为 Variable 壁纸/纯色，消除视觉突兀）；
4. **切换语义**：双 Esc 仍是「Variable ↔ Windows 桌面」——Shell 模式下「Windows 桌面」= 按需启动 explorer shell 会话（首次切换时启动，延迟 2-3s 如实提示；切回 Variable 不关闭 explorer，回收策略见 D-3）；
5. **安全模式兜底**：VM 内 Shell 损坏 → 引导器侧「修复模式」（挂载 VHDX 改回 Shell=explorer.exe 脚本），Runbook 收录。

**验收**：[ ] VM 冷启动到 Variable 桌面全程不见 Windows 桌面（录屏证据）；[ ] 通用文件对话框（如 VS Code 打开文件）正常；[ ] 双 Esc 切 Windows 桌面再切回，状态无损；[ ] 修复模式演练一次成功。

**回滚**：改回 `Shell=explorer.exe`（脚本一键），Variable 退回普通应用模式。

### 22.2 D-2 直跑档：用户级 Shell 替换（可选强化，1 批）

**任务分解**：
1. `HKCU\...\Winlogon` 下 `Shell` 用户级覆盖（只影响当前用户，不动 HKLM、不动其他用户）→ 该用户登录即 Variable；
2. **默认关闭**，Beta 开关藏于 设置→运行环境→「开机进入 Variable（实验性）」，开启前三重警示弹窗（含「如何还原」图文）+ 自动生成一键还原脚本放 U 盘根目录；
3. 安全网：Variable 启动后 60s 心跳自检，Shell 模式下崩溃 > 3 次 → 自动写回 `Shell=explorer.exe`（自我保护，绝不把用户锁在黑屏外）；
4. 多用户隔离：只对开启开关的用户生效；其他用户登录仍是标准 Windows。

**验收**：[ ] 开启后重启 → 登录即 Variable；[ ] 人为破坏 Variable.exe 模拟崩溃 → 自动还原 explorer；[ ] 还原脚本双击生效。

### 22.3 D-3 全域软件接管：所有窗口必须出现在 Variable（1.5 批）

这是「所有软件必须在 Variable 环境运行」的核心机制，分四道防线：

**任务分解**：
1. **第一道：入口接管（预防）**
   - VM 档：VM 内默认程序（浏览器 http/https、邮件 mailto、PDF、图片、文本、终端）全部指向 Variable 关联层（`fileAssociations` + 协议 handler 注册到 VM 注册表 `UserChoice` 由用户确认弹窗完成——不静默劫持，弹「设为默认」向导）；
   - 开始菜单/任务栏：Shell 模式下 Variable 自绘开始菜单为唯一入口（explorer 服务进程不画窗口）；
   - 桌面双击 exe：右键菜单与双击默认 = 「在 Variable 中打开」（VWM 占位 + C-* 四层嵌入）——普通直跑档通过「打开方式」向导引导用户把 exe 关联到 Variable 启动器；
2. **第二道：回收看门狗（兜底）**
   - `shell_watch.rs`：每 500ms 枚举顶层可见窗口 → 不属于 Variable 家族/嵌入登记/系统关键（TaskMgr/输入法/IMM 等 15 类白名单）的新窗口 → 判定「逃逸窗口」；
   - 处置策略（设置可选，默认「询问」）：①**自动邀请**（L1 嵌入收编，复用 C-1 常驻监护，成功则窗口从系统任务栏消失）②询问卡片（「检测到 X 在 Windows 桌面打开——收进 Variable / 保持在桌面（本次）」）③忽略白名单；
   - 逃逸窗口若为全屏独占/反作弊（C-5 特征）→ 不回收，转 L4 让位；
3. **第三道：切回 Windows 桌面时的语义**
   - 双 Esc 切到 Windows 桌面 = 「维护模式」：看门狗进入「标记不回收」状态（此时用户特意要在 Windows 里操作），Variable 收起为薄条/托盘；再双 Esc 回来恢复回收；
   - Shell 模式下 explorer 服务进程若被手动启动出窗口 → 同样被看门狗收编（可选）；
4. **第四道：安装器防护**
   - 在 Variable 内运行安装器（B-27 安装模式执行档）→ 安装完成后其「运行软件」勾选启动的窗口同样被看门狗收编；
   - 安装器自己弹出的 UAC/系统对话框属系统级白名单，不回收（如实声明这类窗口无法收编——它们属于安全桌面）。

**验收**：[ ] VM 档：双击 .txt/.pdf/浏览器链接 → 窗口全部出现在 VWM，系统任务栏（若存在）零图标；[ ] 手动从运行框启动 notepad → 2s 内被收编或弹询问卡；[ ] 全屏游戏不被回收且正常让位；[ ] 看门狗空闲 CPU < 0.5%。

**回滚**：看门狗可整体关闭（设置→接管→关闭，退回「仅手动从 Variable 内启动才嵌入」）。

### 22.4 D-4 切换体验：幕布语义（0.5 批）

### 25.3 性能优化要点（贯穿所有批次的五条军规）

1. **空闲成本预算**：每个常驻组件（看门狗/监护/索引器/代理）空闲 CPU < 1%、内存有上限并在任务管理器可见；
2. **IO 让路**：后台 IO 检测前台交互，让路阈值（队列深度/CPU）写死并在 bench 验证；
3. **启动路径零冗余**：启动仪式期间禁同步网络/大 IO；每批次新增的启动工作必须 `boot://event` 化；
4. **合成层纪律**：动画只动 transform/opacity；每波次结束抽查一次主线程帧耗时 < 4ms；
5. **内存水位**：VWM 保活窗口 > 50 个时自动降级为「快照休眠」（几何+滚动位置持久化，卸载 DOM），恢复 < 300ms。
