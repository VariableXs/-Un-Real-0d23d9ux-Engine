# VARIX + Variable 双域系统施工总案

> 本文件是整场架构讨论的定稿施工文档：目标形态、十大阶段的详细逻辑（数据结构/算法/事件流/决策规则）、每阶段细化的施工步骤（**每步自带六维步骤级验收**）、阶段级六维验收、开放改进点。
> 配套的任务勾选清单见 `docs/VARIX双域系统总施工清单.md`；本文负责"逻辑怎么转 + 质量怎么验"，清单负责"进度怎么勾"。

## 0. 大致步骤总览（先看这张图）

```
阶段0  引导选择页            ← 内核画的第一个界面，无前置依赖，可立即动工
   ↓
阶段1  U盘五分区便携基建      ← 复用 portable/ 现有脚本体系
   ↓
阶段2  内核欠账清零          ← 缺页接线/用户态/真驱动/真盘FS（能跑的前提）
   ↓
阶段3  Variable界面上内核     ← Servo 承载现有 React 前端 + Tauri IPC 垫片
   ↓
阶段4  数据总线与白名单       ← 共享内存/消息通道/共享分区，默认拒绝
   ↓                       ↘
阶段5  Wine兼容层通道         阶段6 隐形Windows引擎通道   ← 二者可并行施工
   ↘                       ↙
阶段7  资源统管与多机打磨（设置页/配额/拔出保护/多机型验收）
   ↓
阶段8  安全加固与隐私（兼容层攻击面/审计/紧急救援通道）
   ↓
阶段9  升级协议与灾备演练（差分升级/失败回滚/快照恢复/长期维护）
   ↓
阶段10 性能基准与生态（bench 门禁/适配数据库/多语言/无障碍）
```

- **并行性**：阶段5 与阶段6 互不依赖，可两条线并行；阶段0/1 可在阶段2 之前先行（不碰内核）；阶段8-10 中不依赖硬件的部分可与 5-7 交错。
- **贯穿线**：「作品级体验专项」二十个专项横切所有阶段——凡涉及用户可见界面的阶段步骤，交付时同步过对应专项的检查项，不留到最后统一补体验。
- **可停性**：任一阶段做完系统都处于"可用的中间态"，随时可停不尴尬。
- **门禁**：每阶段过三线全绿（V: tsc+vitest / C: ca-core / K: ktest+kcheck）+ 六维验收 + 实机验收报告归档 docs/。

### 终局形态一句话

一块 1TB U 盘插任意电脑：开机默认 5 秒进 VARIX+Variable 桌面；日常软件走 Wine 兼容层（Windows 完全没开机）；高兼容软件走隐形 Windows 引擎（实时无缝窗口）；游戏/反作弊重启进纯 Windows（同一块盘上的镜像）；拔盘即走、零残留。

## 六维极高质量验收框架（每个功能/重要步骤通用）

每个阶段、每个重要功能交付时，逐维对照打分，任何一维不达标不算完成：

| 维度 | 检查什么 | 通过标准 |
|---|---|---|
| **视觉** | 截图对照设计稿/既有视觉语言；125% DPI 缩放；多分辨率；暗色一致；动效时长与缓动；焦点环与对比度（无障碍） | 像素级对照无意外偏差；`_attic/tools/png_probe.py` 度量通过；无对比度缺陷 |
| **逻辑** | 状态机全状态可达且可退出；边界条件（空/满/超大/并发）；负向用例（非法输入/越权/断电/拔盘）行为符合"默认拒绝+如实报错" | 状态机图覆盖 100%；每条边界至少 1 个自动化用例；异常路径人工演练通过 |
| **代码** | 三线门禁全绿（tsc 0 错/vitest 全绿/ktest+kcheck 0 告警）；新增代码零 `unwrap`（内核路径）/零裸 invoke（前端）；复用既有原语而非重造；注释说明"为什么" | 门禁脚本全绿；`grep` 复核无违规；模块内聚（单文件不超预算）；关键改动 grep 复核 |
| **开放性** | 扩展点显式存在：配置文件/规则表/插件接口可加不改主逻辑；数据格式带版本号与迁移路径；API 有契约注释 | 新增一类配置/规则不改核心代码即可接入；格式升版演练走通 |
| **简洁性** | 无重复实现（全局 grep 同语义实现）；无死代码；复杂度预算（单函数 ≤80 行、单文件 ≤2000 行、嵌套 ≤4 层）；命名与既有约定一致 | `audit`/lint 无新增告警；重复实现清单为空 |
| **完善性（缺失功能检查）** | 对照本阶段"功能契约清单"逐条核对；缺失能力如实登记三色表（✅可跑/🔶可映射/❌暂缺），❌ 项必须有"为什么缺、谁来补、何时补" | 缺失登记表 100% 覆盖；无未声明的静默缺失；用户可见降级提示均有 i18n 词条 |

> 六维验收分两层：**阶段级**（各阶段末尾的"六维验收"节）与**步骤级**（每个施工步骤自带一行"验收"，写明该步必须过哪几维、怎么验）。步骤级验收全部通过才允许进入下一步骤；产出物统一归档：`docs/acceptance/双域-阶段N-六维验收-YYYY-MM-DD.md`。
>
> **步骤级验收记法**：每步末尾 `〔验收：视觉=…；逻辑=…；代码=…；开放性=…；简洁性=…；完善性=…〕`，只写该步实际涉及的维度（无关维度标 `—`）。任何一步验收不过，退回本步修复，不得带病推进。
>
> **作品级体验加验**：自"作品级体验专项"章节起，面向用户可感知的功能在此六维之上追加五个体验子项——①首用理解（第一次见就会用，无需说明）；②反馈即时（任何操作 ≤100ms 有可见回应，长任务有进度）；③错误可解（每个错误文案回答"发生了什么+我该怎么办"）；④一致性（同语义控件全系统同观感同行为）；⑤记忆点（有一处让人愿意展示给别人的亮点）。涉及用户可见界面的步骤，验收中带 `体验=…` 标注。

## 阶段 0：引导选择页

### 目标
内核引导早期画出系统选择界面；这是 VARIX 画的第一个 UI。

### 前置依赖
无（不依赖其他阶段）。

### 详细逻辑
- **时机**：Limine 移交后、`boot()` 域初始化完成前，在 GOP 帧缓冲上直接绘制（只依赖 framebuffer，不依赖驱动栈）。
- **数据结构**：引导配置文件 `boot-select.json` 放共享分区（两系统都能读写）：
  - `default_entry`: `"variable" | "windows" | "last"`
  - `timeout_sec`: 默认 5
  - `show_menu`: bool（false = 静默走默认项）
  - `last_boot`: 上次实际进入的系统，每次进入时写回
  - `windows_bootnext`: 部署脚本预先探测的 Windows 引导项号
- **交互逻辑**：
  1. 画三行选项 + 倒计时进度条；
  2. 键盘（此阶段只需 PS/2 最小轮询读键）上下选择、Enter 确认；
  3. 倒计时归零 → 执行 default_entry；任何按键立即暂停倒计时进手动态；
  4. 选 variable → 继续域初始化；
  5. 选 windows → UEFI `BootNext` 指向 Windows 引导项，`ResetSystem()` 重启。

### 施工步骤（细化，每步带步骤级验收）

1. **GOP 绘制原语**：fill / rect / 位图字体（8×16 ASCII + 16×16 中文常用子集）＋ 三色自测图案；stride 按 GOP 实际返回值取，不假设等宽。
   〔验收：视觉=三图案 1920×1080/2560×1440 截图无失真，png_probe 度量通过；逻辑=stride 异常/零宽高/越界裁剪负向用例；代码=零 panic 路径（引导期 panic 无处可去），裁剪用饱和运算；开放性=字体/色板常量表参数化；简洁性=独立 `bootui/` 模块；完善性=原语契约清单登记〕
2. **`boot-select.json` 解析器**：手写最小 JSON 子集解析（不引第三方）；容错三层——字段缺失→默认、类型错→默认、整体损坏→内置默认并画"配置已重置"角标。
   〔验收：逻辑=三种脏数据 + timeout=0/负值/超大值域用例各 1；代码=1000 组随机字节 fuzz 不崩溃；开放性=未知字段忽略（前向兼容）；简洁性=单文件 ≤400 行；完善性=全字段默认值表入档〕
3. **选择页状态机**：countdown/manual/confirmed/executing 四态；任意键 countdown→manual；executing 中禁改选（防双触发）；倒计时进度条与状态联动。
   〔验收：逻辑=状态转移图 100% 覆盖 + "倒计时最后一刻按键"竞态 ×100 循环；代码=状态机纯函数化可宿主机单测；简洁性=无隐藏状态变量；完善性=状态机图归档 docs〕
4. **PS/2 键盘最小轮询**：0x60 端口轮询 + 扫描码集 1 翻译（↑↓/Enter/Esc）+ 同键 50ms 去抖。
   〔验收：逻辑=去抖边界、0xE0 扩展前缀忽略不崩；代码=端口等待带上限防死等卡引导；开放性=扫描码表可扩；简洁性=只实现本页 5 键；完善性="USB 键盘引导期不支持"如实写入文档〕
5. **BootNext 写入 + ResetSystem**：`SetVariable(BootNext)` → 回读校验一致 → `ResetSystem()`；写入失败必须留在菜单显示错误行，禁止盲目重启。
   〔验收：逻辑=写入失败/回读不一致/变量不存在三负向路径各 1 用例；代码=UEFI 调用封装独立模块、失败码枚举齐全；完善性=失败提示中英词条登记〕
6. **部署脚本探测引导项号**：`Deploy-To-USB.ps1` 新增探测段：枚举 EFI 启动项 → 匹配 Windows 引导项 → 写入配置；无匹配时明确报错不写默认值。
   〔验收：代码=脚本纯 ASCII+CRLF，`git ls-files --eol` 复核；逻辑=≥3 启动项机器匹配正确、无 Windows 项报错路径；开放性=匹配规则配置化〕
7. **`last_boot` 写回闭环**：VARIX 侧进入前写回；Windows 侧由部署进 VHDX 的开机小脚本写回；`last` 语义 = 读 last_boot。
   〔验收：逻辑=连续交替切换 ×5 次 last_boot 始终正确；完善性=Windows 侧脚本失败模式（只读挂载等）登记〕
8. **负向演练矩阵**：配置损坏 / 键盘中途拔掉 / 倒计时中拔盘 / BootNext 指向失效项 / 双系统引导文件缺一——五场景逐条真机演练。
   〔验收：逻辑=五场景行为全部符合"默认拒绝+如实报错"，演练记录归档；完善性=每场景残余风险声明〕

### 六维验收
- **视觉**：选择页截图与 Variable 视觉语言对照（同色板）；1920×1080/2560×1440 双分辨率绘制正确；125% 高分屏无错位；倒计时进度条动效平滑（帧率抽帧检查）。
- **逻辑**：四态状态机全路径自动化推演（含"倒计时最后一刻按键"竞态）；JSON 损坏/字段缺失/非法值三种脏数据用例；BootNext 写入失败时必须放弃切 Windows 并留在菜单（不得盲目重启）。
- **代码**：绘制原语零 panic 路径（引导期 panic 无处可去）；配置解析 fail-safe 注释齐全；与 Limine 协议代码隔离在独立模块。
- **开放性**：新增第四个引导项（如"维护模式"）只加配置不改状态机；字体/色板参数化。
- **简洁性**：绘制原语与后续内核显示服务不重复实现（本阶段原语后续被阶段2 收编为唯一实现）。
- **完善性**：契约清单=选项绘制/倒计时/键盘/切 Windows/记忆上次/配置容错——逐条核对登记。

### 开放改进点
- 选择页升级为 Variable 风格动画页；多语言（中/英）；USB 键盘引导期支持。

### 验收门禁
- 真机 U 盘引导：5 秒无操作自动走默认项；选 Windows 真机重启进入 VHDX Windows；配置改动下次引导生效。

## 阶段 1：U 盘五分区便携基建

### 目标
一键脚本从零产出可引导 U 盘；复用项目现有便携体系。

### 前置依赖
无（可与阶段 0 并行）。

### 详细逻辑
- **分区布局**（1TB 盘定版）：
  1. `ESP`（1GB）：VARIX 引导器 + Limine + Windows 引导文件（BCD 等）
  2. `VARIX_SYS`（64GB）：内核 ELF + Variable 运行时 + Servo + Wine 前缀模板
  3. `WIN_ENGINE`（300GB，NTFS）：Windows 引擎 VHDX（差分链 Base→Apps→User）
  4. `SHARED`（600GB，exFAT）：唯一互通面
  5. `SNAPSHOT`（余量，NTFS）：快照/回收/恢复
- **SHARED 目录契约**：`apps.json`（软件登记总表：名称/图标/通道 wine|engine|native-only/分级）、`handoff/`（意图接力队列）、`whitelist/`（白名单规则）、`boot-select.json`。
- **脚本改造**：`Deploy-To-USB.ps1` 新增 `Deploy-Varix` 段；`Create-VHDX.ps1` 参数化容量；`Test-VM.ps1` 支持 U 盘整机验收。
- **拔出保护**：复用 `usb.rs`（1s 轮询 + 2s `wal_checkpoint(PASSIVE)` + 卷消失广播），适配五分区。

### 施工步骤（细化，每步带步骤级验收）

1. **分区脚本**：GPT + 五分区（ESP 1GB / VARIX_SYS 64GB / WIN_ENGINE 300GB / SHARED 600GB / SNAPSHOT 余量）+ 4K 对齐校验 + 幂等重跑（已分区时校验布局一致才继续，不一致要求显式确认）。
   〔验收：逻辑=幂等连跑两次结果一致；小盘/已占用盘拒绝并给明确报错；代码=清盘操作二次确认交互；开放性=全部容量参数化（配置驱动）；简洁性=复用 Create-VHDX 既有校验函数；完善性=分区表 ASCII 可视化入部署报告〕
2. **ESP 双引导链组装**：VARIX 引导器（Limine）+ Windows 引导文件（BCD/bootmgfw）同盘共存；两条链互不干扰验证。
   〔验收：逻辑=VM 中两链分别引导成功各 ≥3 次；代码=组装脚本段独立可重入；完善性=两链文件清单与校验和归档〕
3. **VHDX 差分链产出**：Base→Apps→User 三级差分盘创建、挂载、合并、回滚四个动作脚本化。
   〔验收：逻辑=合并/回滚演练各 ×3 数据一致；代码=复用 AI1 脚本只加参数；开放性=链深与容量可配；完善性=每级盘用途与依赖写入文档〕
4. **SHARED 目录契约初始化**：`apps.json`（带 version）/`handoff/`/`whitelist/`/`boot-select.json` 骨架生成 + schema 定版文档。
   〔验收：代码=schema 带版本字段与迁移函数占位；逻辑=损坏 JSON 走默认+角标；开放性=新增目录不改编排骨架；完善性=每个文件用途/写者/读者三方表登记〕
5. **Deploy-To-USB 总编排**：Preflight（盘检测/容量/危险确认）→ Stage（分区+ESP+镜像落盘）→ Verify（校验和+引导 smoke）→ Report（ASCII 报告归档）。
   〔验收：逻辑=零人工干预端到端产盘 ×2 成功率 100%；视觉=报告含分区图与容量核对表；代码=各阶段可单独重跑（断点续作）；完善性=报告样例归档 docs〕
6. **拔出保护适配**：usb.rs 看护扩展到五分区（每分区挂载状态跟踪 + WAL checkpoint 扩展到 SHARED）。
   〔验收：逻辑=五分区各"使用中强拔"演练，数据零损坏（fsck/校验和验证）；代码=轮询间隔与检查点策略参数化；完善性=每分区强拔后果分级表〕
7. **VM 整机验收流水线**：Test-VM.ps1 支持直接挂 U 盘镜像引导到选择页 + 结果自动归档。
   〔验收：逻辑=VM 引导成功率 ≥95%（20 次）；代码=复用 Test-VM 只加盘参数；完善性=失败截图与日志自动收集〕
8. **多 U 盘版本管理（可选成熟步）**：Base 盘 + 差分升级包的分发流程脚本化，为阶段 9 升级协议打地基。
   〔验收：开放性=升级包格式带版本；逻辑=双 U 盘 Base 相同性校验；完善性=版本管理 SOP 入档〕

### 六维验收
- **视觉**：不适用界面项→以"部署报告页"替代：脚本输出含分区表可视化 ASCII 图与容量核对表；报告归档可读。
- **逻辑**：幂等性（连跑两次结果一致）；容量边界（1TB 减五分区余量校验，拒绝小盘时给明确报错）；强拔演练（五分区各占用时拔）数据零损坏；差分链合并/回滚演练。
- **代码**：脚本纯 ASCII + CRLF（`.bat/.ps1` 编码硬约束）；`git ls-files --eol` 复核；危险操作（清盘前）二次确认交互。
- **开放性**：分区容量全部参数化（配置驱动）；apps.json 带版本号与升版迁移函数；新增第六分区不改编排骨架。
- **简洁性**：不重写 Create-VHDX/Deploy 已有逻辑，只加段；部署报告与 Test-VM 报告同一格式。

## 阶段 2：内核欠账清零

### 目标
内核从"引导完就停"变成"能跑程序、能摸硬件、能存数据"。

### 前置依赖
无强制（阶段 0/1 可先行）。

### 详细逻辑
- **2.1 缺页处理接线**（最高优先）：
  - 现状：`paging::decide()` 决策纯函数已完成（guard→Fault / reserved-write→Fault / 栈未触碰→GrowStack / present+write+cow→CopyOnWrite / !present→SwapIn|MapZero），但 `idt::isr_dispatch` 对 vector<32 一律 fatal。
  - 改造：IDT 0x0E 注册专用 handler → CR2 取故障地址 + 错误码 → 组装请求 → `decide()` → 四路动作；仅 Fault 才 fatal。
  - COW：fork 前置——写时复制位 + 页框引用计数；GrowStack 带栈上限。
- **2.2 用户态进程壳**：
  - ring3 切换（段选择子 RPL=3）；syscall/sysret 与 int 0x80 双入口（断言两路一致，沿用 `entry.rs` 既有断言风格）；
  - 号表扩充：spawn/exit/wait/mmap/brk/open/read/write/close/ioctl 骨架；
  - 进程控制块（地址空间/句柄表/父子）+ 复用 64 槽线程调度；
  - init 进程：从 VARIX_SYS 读 ELF 并 spawn。
- **2.3 真驱动**：显示（GOP 封装双缓冲显示服务）；键鼠（PS/2 轮询起步，xHCI 最小栈后补）；存储（NVMe 提交/完成队列最小实现优先，AHCI 兜底，块设备抽象层统一）；文件系统（fs23_journal 换块设备后端；VARIX_SYS 只读简单 FS；SHARED exFAT 读写或先只读过渡）。
- **2.4 掉电安全**：journal 语义不变（torn 丢弃该点及之后全部 + 幂等重放），掉电注入 100 轮沿用。

### 施工步骤（细化，每步带步骤级验收；内核文件禁并行 Edit，串行推进）

1. **#PF handler 接线**：IDT 0x0E 注册专用 handler → CR2 故障地址 + 错误码 → 组装请求 → `decide()` 四路分发；仅 Fault 才 fatal。与既有 `isr_dispatch` 的 vector<32 一律 fatal 路径并存但 0x0E 优先分流。
   〔验收：逻辑=四路各 ≥3 单测（构造非法访问/守卫页/COW 写/栈生长），含并发缺页同一页框用例；代码=handler 零 unwrap、kcheck 0 告警；开放性=decide 决策表可加新动作类型；简洁性=不复制 paging.rs 既有逻辑；完善性=四路行为表入档〕
2. **COW 基建**：写时复制位 + 页框引用计数 + 归零回收；fork 的前置件。
   〔验收：逻辑=计数归零竞态 ×1000 并发用例；COW 断裂后页内容与断裂前逐字节一致；代码=位操作全部封装为函数并注释不变量；完善性="引用计数溢出策略"显式声明〕
3. **GrowStack 栈生长**：栈未触碰页自动扩展 + 栈上限（默认 8MB 可配）+ guard 页保持。
   〔验收：逻辑=超上限返回 Fault 且进程收到明确错误码（非内核 panic）；递归爆栈用例；开放性=上限进程级可配；完善性=栈布局图入档〕
4. **ring3 切换**：GDT 用户段 RPL=3 + syscall/sysret 与 int 0x80 双入口（沿用 entry.rs 双路一致性断言风格）。
   〔验收：逻辑=双入口各发起同一 syscall 结果一致 ×1000；非法 cs/ss 组合被拒；代码=GDT 布局注释齐全；简洁性=复用既有 entry 断言宏；完善性=ring3 切换序列文档化〕
5. **最小 syscall（exit/write）+ 用户态 hello**：串口 write + 干净 exit；用户态 hello.elf 全流程跑通（内核第一次跑上"别人的代码"）。
   〔验收：逻辑=hello 输出逐字节比对；exit 后槽位正确回收（64 槽复用验证）；代码=用户态程序独立 crate 与内核零链接；完善性=此步是里程碑，单独写验收记录〕
6. **进程控制块 + spawn/wait**：PCB（地址空间/句柄表/父子关系）+ spawn/exit/waitpid 语义 + 僵尸进程回收。
   〔验收：逻辑=spawn 压力 64 槽打满/耗尽优雅拒绝；父先死子孤儿被 init 收养；waitpid 循环 1000 次无泄漏；代码=PCB 字段访问全部经核内 API（无裸字段跨模块改）；开放性=句柄表类型可注册扩展；完善性=进程生命周期状态图入档〕
7. **ELF 装载器**：ELF64 解析 + 段映射 + 入口跳转；负向防护（畸形头/越界段/非可执行段执行拒绝）。
   〔验收：逻辑=畸形 ELF ≥10 变体全部拒绝不崩溃；代码=解析器与 Wine 的 PE 装载器共享"映像装载"底层原语（提前统一抽象）；完善性=支持的 ELF 特性清单（PIE？静态？）如实声明〕
8. **块设备抽象 trait**：read/write/flush/容量查询接口冻结——NVMe/AHCI/未来 virtio 同接口。
   〔验收：代码=trait 冻结并写冻结声明（改动需评审）；逻辑=内存模拟盘上全接口单测；开放性=新驱动注册表化接入；简洁性=不引入异步（同步阻塞语义先行）〕
9. **NVMe 最小栈**：提交/完成队列对 + 识别/读写命令；AHCI 兜底驱动。
   〔验收：逻辑=QEMU NVMe 盘读写回环 ×1000 + 数据校验和一致；超时/中断丢失恢复路径；代码=DMA 桶与门铃写序严格注释（memory barrier 语义）；完善性=支持命令集范围如实声明（先不做 admin 全集）〕
10. **fs23_journal 接真盘**：内存 64 槽模型替换为块设备后端；journal 语义不变（torn 丢弃该点及之后全部 + 幂等重放）。
    〔验收：逻辑=掉电注入 100 轮 0 丢失（沿既有测试升级到真盘路径）；顺序写/随机写性能基线归档；代码=既有 journal 单测全部迁移通过不改断言语义；简洁性=分层只换后端不换协议〕
11. **exFAT 读实现 + SHARED 挂载**：只读起步（写走 SNAPSHOT 过渡区），长文件名/簇链/坏簇处理。

12. **PS/2 键盘事件服务化**：阶段 0 的轮询升级为内核输入服务（事件队列 + 订阅者），鼠标 PS/2 协议最小版。
    〔验收：逻辑=队列满时丢最旧并计数（不阻塞中断）；代码=与 bootui 原语同源不复制；完善性=xHCI 立项评估报告归档（范围/工作量/风险）〕

    〔验收：视觉=高速滚动抽帧无撕裂；逻辑=双缓冲交换竞态用例；代码=bootui 与显示服务合并后 grep 无重复实现；完善性=分辨率切换能力声明〕

### 前置依赖
阶段 2（进程/存储）、阶段 3（设置页承载）。

### 详细逻辑
- **三个内核原语**：共享内存块（创建/映射/授权，仅授权进程可见）；消息通道（进程间事件，复用 16 通道等待队列思路扩展）；共享分区访问（一切 SHARED 读写经 VFS 白名单裁决）。
- **白名单规则**：目录级 + 剪贴板 + 拖放三类；规则存 SHARED/whitelist/；设置页增删。
- **审计**：越权尝试全记日志（时间/进程/路径/动作），设置页可查。
- **Uxv 接入**：跨系统大文件交换（BLAKE3 校验 + journal 掉电安全现成）。

### 施工步骤（细化，每步带步骤级验收）

1. **VFS 白名单裁决层**：挂在 SHARED 挂载点的唯一入口——路径规范化（防 `../` 逃逸/符号链接绕过/大小写变体）→ 规则匹配（目录级前缀 + 通配）→ 拒绝默认。
   〔验收：逻辑=路径逃逸用例 ≥15 变体全拒绝；匹配边界（恰好前缀/尾斜杠/Unicode 规范化）用例；代码=裁决层为唯一入口（grep 全库无第二条 SHARED 写路径）；开放性=规则 schema 版本化；完善性=裁决失败原因码表〕
2. **规则引擎与热更新**：规则文件读入内存树 + 版本号比对热更新（改文件不重启生效）+ 规则冲突检测（允许/拒绝叠加时显式定义优先级=拒绝优先）。
   〔验收：逻辑=热更新竞态（更新中请求）用例；冲突组合 ≥10 组断言拒绝优先；开放性=新资源类型可插裁决器 trait；简洁性=规则树 ≤500 行实现〕
3. **越权审计日志**：每次拒绝记录时间/进程/路径/动作/规则命中年；日志走 journal 断电不丢；环形容量上限。
   〔验收：逻辑=断电注入后日志完好；环形覆盖后旧记录明确标记截断；代码=审计写失败不阻塞主流程但降级标记（不静默）；完善性=审计字段与设置页展示字段对照表〕
4. **共享内存块原语**：create/map/revoke 三 syscall；授权模型（句柄不可传递默认、创建者显式授权）；块销毁后映射失效。
   〔验收：逻辑=句柄传递攻击用例被拒；revoke 后访问得明确错误非崩溃；代码=页级权限位封装；开放性=块命名空间可注册；完善性=授权模型语义文档（谁能看到什么）〕
5. **消息通道原语**：订阅/广播/单发三语义 + 通道容量 + 慢消费者策略（丢最旧+计数，与输入服务同策略）。
   〔验收：逻辑=广播顺序保证（同通道 FIFO）×1000；容量边界；代码=与内核 16 通道等待队列复用不重写；开放性=通道名注册表；完善性=与 Windows 侧 emit/on 语义对照表〕
6. **剪贴板/拖放白名单化**：剪贴板读写过白名单 + 格式白名单（文本/图片/文件引用三类起步）；拖放等价为文件读写走同一裁决。
   〔验收：逻辑=未授权进程读剪贴板得空+审计；格式过滤用例（伪装扩展名）；完善性=与 Windows 侧剪贴板行为差异公示〕
7. **Uxv 交换格式接入**：大文件跨域交换用 Uxv 容器（BLAKE3 校验 + journal）；校验失败路径 = 整包拒绝 + 如实报错。
   〔验收：逻辑=掉电注入 ×10 交换文件可恢复或整体回滚；校验失败不产生半文件；代码=复用 container crate 不复制实现；完善性=单文件大小上限声明〕
8. **设置页白名单管理 UI**：目录规则增删改查 + 即时生效 + 变更审计自身也留痕。
   〔验收：视觉=与既有设置页 Win11 风格逐像素对照；逻辑=UI 删除规则后内核侧同步生效延迟 <1s；代码=全部走 settings://changed 既有总线；完善性=空态/错误态设计稿对照〕
9. **审计查看页**：时间线/按进程过滤/按路径过滤/导出。
   〔验收：视觉=与通知中心视觉一致；逻辑=万条记录下滚动流畅（虚拟列表）；开放性=导出格式 JSON+CSV 双选〕
10. **负向演练矩阵**：越权进程 × 目录 × 剪贴板 × 共享内存 全组合自动化矩阵 + 断电全链演练。
    〔验收：逻辑=矩阵 100% 拒绝 + 零崩溃 + 审计全覆盖；完善性=矩阵结果归档，未覆盖组合显式声明〕

### 六维验收
- **视觉**：白名单管理/审计查看页与既有设置页风格逐像素对照；越权提示 toast 与通知中心视觉一致；空态/加载态骨架屏沿用共享组件。
- **逻辑**：越权组合矩阵 100% 拒绝；规则热更新（改白名单不重启生效）；审计日志断电不丢（走 journal）；共享内存句柄传递攻击用例被拒。
- **代码**：裁决层为唯一入口（grep 无绕过路径）；审计写失败不阻塞主流程但不静默（降级标记）。
- **开放性**：规则 schema 版本化；新增资源类型（如网络）可插裁决器。
- **简洁性**：复用 Uxv/privacy.rs 既有加密校验，不新造。
- **完善性**：契约=三原语/三类白名单/审计/设置页/负向矩阵——逐条登记。

### 开放改进点
- 进程级×目录级规则矩阵；审计检索 UI；剪贴板格式过滤。

### 验收门禁
- 负向矩阵全绿；断电零丢失；设置页操作即时生效。

## 阶段 5：Wine 兼容层通道

### 目标
Windows 完全不运行的前提下，.exe 在 VARIX 用户态跑起来。

### 前置依赖
阶段 2（进程/文件系统）、阶段 4（白名单）。

### 详细逻辑
- **三层结构**：PE 装载器（头/节表/导入表 → 映射 + 符号绑定 Wine DLL 实现）；Win32 服务台（Kernel32/User32/GDI 等 VARIX 移植版，底层调内核 syscall）；进程模型（每 exe = 独立内核进程 + Job 级限额，语义同 `isolation.rs` 设计）。
- **图形路径**：GDI → 软件渲染到窗口服务；DirectX → WineD3D→Vulkan（后期）→ 软件兜底。
- **分级登记**（SHARED/apps.json）：✅ 可跑（办公/工具/多数桌面）/ 🔶 逐步补（缺哪个 API 补哪个，登记缺失清单）/ ❌ 不可跑（内核驱动类、反作弊——永远走纯 Windows 通道）。
- **物理隔离语义**：Windows 进程不存在 → 内存零 Windows 代码；地址空间内核隔离；与 Variable 只走白名单。

### 施工步骤（细化，每步带步骤级验收）

1. **Wine 移植评估报告**：NTAPI 对接面（ntdll 核心 syscall 集）→ VARIX syscall 映射清单；逐模块工作量分级（周为单位）；选定 Wine 版本与补丁集管理方式（git patch queue）。
   〔验收：完善性=映射清单逐条标注 ✅/🔶/❌ 及工作量；开放性=Wine 版本升级流程写入报告；代码=评估结论可复核（每条映射对应内核 syscall 号）〕
2. **映像装载抽象统一**：先抽"可执行映像装载"公共原语（阶段 2 的 ELF 装载器与 PE 装载器共用：地址空间预留/段映射/对齐/权限位）。
   〔验收：代码=grep 证明两装载器零重复映射代码；逻辑=ELF 回归测试不破；简洁性=公共原语 ≤300 行；开放性=第三格式（如 Mach-O）可插〕
3. **PE 装载器**：DOS/NT 头、节表、重定位、ASLR（若 exe 支持）；畸形输入全拒绝。
   〔验收：逻辑=畸形 PE ≥20 变体（坏魔数/超界节表/重叠节/超大 SizeOfImage）全部拒绝不崩溃；代码=拒绝原因枚举齐全；完善性=拒绝表样本归档〕
4. **静态链接 exe 闭环**：不含导入解析，先跑通纯静态 MSVC/minlang 类 exe 的加载-执行-退出。
   〔验收：逻辑=退出码传递正确 ×10 样本；代码=与内核 syscall 对接零 unsafe 泄漏到公共层；完善性=可跑样本清单〕
5. **导入表解析 + ntdll/kernel32 绑定**：Wine 核心 DLL 的 VARIX 移植第一层——进程/内存/文件三组 API 优先。
   〔验收：逻辑=GetProcAddress 动态/静态两路一致；API 缺失时返回明确错误码非崩溃；代码=每处映射注释对应内核服务号；开放性=API 实现注册表化（stub→partial→full 三态标记）；完善性=首层 API 覆盖率公示〕
6. **User32/GDI 服务台**：窗口创建/消息循环/文本绘制/基本控件——消息队列接到内核输入总线，绘制接到窗口服务。
   〔验收：视觉=记事本/计算器截图与原生 Windows 对照（字体/菜单/布局）；逻辑=消息循环 100 万次无泄漏；代码=消息结构与 Variable 窗口服务共用定义；完善性=支持的窗口消息集清单（未支持消息显式返回 0 并计数）〕
7. **记事本级闭环**：菜单/文件对话框/编辑/保存——完整的第一个真实 Windows 软件跑通。
   〔验收：视觉=全流程录屏对照；逻辑=打开-编辑-保存-重开内容一致 ×10；完善性=此为里程碑单独归档验收记录〕
8. **进程模型与 Job 限额**：每 exe = 独立内核进程 + Job 级限额（内存/CPU rate/KILL_ON_JOB_CLOSE，语义对齐 isolation.rs）。
   〔验收：逻辑=内存超限优雅终止（子进程树全收）非整机挂；限额边界 ×5 档位；代码=限额语义与 isolation.rs 逐条对照表；简洁性=不复制 Job 实现按语义重写于内核〕
9. **prefix 模板与文件系统视图**：Wine prefix（注册表模拟/C 盘映射）落在 VARIX_SYS 模板 + 每 app 独立 prefix 实例；exe 视野内的 Z: 盘=白名单 SHARED。
   〔验收：逻辑=两 prefix 互不可见；exe 写越界路径被白名单拦截+审计；开放性=prefix 模板可导出导入（版本化）；完善性=注册表模拟覆盖范围声明〕
10. **适配数据库与补齐排期**：每软件记录（版本/所需 API/结论/缺失清单/截图证据）→ apps.json 同步 → 缺失 API 排期看板数据源。
    〔验收：完善性=首批 ≥10 款软件逐款登记；开放性=数据库 schema 公开（社区化潜力）；逻辑=登记流程可自动化脚本采集〕
11. **并发与隔离压力**：10 软件并发启动/退出循环；命名对象（互斥体/事件）命名空间隔离验证。
    〔验收：逻辑=并发循环 ×10 无串扰无死锁；同名互斥体两进程各自独立（或显式共享语义）；代码=对象命名空间实现注释隔离边界；完善性=压力报告归档〕
12. **里程碑整合验收**：Windows 物理断电（拔内存态）实机：记事本 + 办公/工具 ≥5 款闭环可用；限额与隔离全部验证。
    〔验收：逻辑=物理隔离声明验证（内存 dump 无 Windows 内核特征签名）；三线门禁全绿；完善性=✅/🔶/❌ 三色占比公示与补齐计划〕

### 六维验收
- **视觉**：记事本/计算器等目标软件截图与原生 Windows 运行对照（字体渲染/菜单布局）；窗口装饰与 VWM 红绿灯视觉一致；多 DPI 缩放正确。
- **逻辑**：PE 解析负向用例（畸形头/超界节表 → 拒绝加载不崩溃）；限额边界（内存超限优雅终止非整机挂）；10 软件并发启动无串扰（句柄/命名对象隔离）。
- **代码**：移植改动全部落在对接层（上游 Wine 主体不动，补丁集管理）；每处 syscall 映射注释对应内核服务；新增 unsafe 逐一登记。
- **开放性**：适配数据库 schema 公开（社区化潜力）；prefix 模板可导出导入；API 缺失登记驱动补齐排期。
- **简洁性**：不实现与目标软件无关的 API 面（按需渐进）；复用内核文件/窗口服务，不在 Wine 内重复造 FS。
- **完善性**：首批目标软件清单（≥10 款）逐款登记结论；❌ 项明确"走哪个通道替代"。

### 开放改进点
- Wine 版本跟进与补丁集管理；MSVCRT/glibc 运行库打包；字体渲染质量；适配数据库社区化。

### 验收门禁
- Windows 断电状态实机：记事本闭环 + 办公/工具 ≥5 款通过；限额生效验证；适配数据库上线。

## 阶段 6：隐形 Windows 引擎通道

### 目标
需要原生兼容性时，Windows 作为后台引擎被拉起，应用窗口无缝出现在 Variable 桌面。

### 前置依赖
阶段 4（白名单/数据总线）；可跳过（纯 Wine 路线用户可整段禁用）。

### 详细逻辑
- **引擎生命周期**：关闭（默认）→ 拉起中（冷启动 20-40s，UI 如实提示）→ 就绪（常驻近零占用）→ 休眠（内存快照到 WIN_ENGINE 差分盘）。
- **VM 管理**：过渡期 Hyper-V 底座（直接挂 WIN_ENGINE VHDX）；终局评估内核自带 VMX。
- **无缝窗口**：窗口级画面流（RDP RemoteApp / Spice）→ Variable 侧解码为窗口内容；输入反向注入；VWM 接管（`vwm.ts` 状态机复用：贴靠/最小化/Z 序）。
- **ramcache**：热数据缓存进宿主 RAM，**只缓不落盘、关机即清**——不破坏拔盘无痕。
- **拉起协议**：点通道=engine 的软件 → 引擎未就绪则写请求 + 唤醒 + 就绪自动打开；窗口出现前显示占位卡（复用 embed 占位卡视觉语言）。

### 施工步骤（细化，每步带步骤级验收）

1. **VHDX 挂载与 VM 拉起编排**：差分盘挂载 → Hyper-V VM 创建/启动 → 就绪探针（引擎内 agent 心跳，复用 47631 心跳语义）。
   〔验收：逻辑=拉起幂等（重复触发不双开）；心跳超时判定与重启策略；代码=编排状态机五态显式建模；完善性=冷启动耗时实测基线（目标 20-40s 如实公示）〕
2. **保活与休眠**：就绪后常驻近零占用（空闲检测）→ 休眠=内存快照写差分盘 → 恢复秒级。
   〔验收：逻辑=休眠-恢复 ×10 内容一致；休眠中拔盘走异常路径；代码=快照走既有差分链不新造格式；完善性=休眠触发条件（空闲阈值）可配〕
3. **全屏画面流打通**：RDP 全屏会话 → Variable 全屏显示；先跑通端到端再降窗口级。
   〔验收：逻辑=断流重连（网络/引擎重启）自动恢复；延迟实测归档；代码=流协议封装单模块可替换；完善性=画质默认档与实测帧率公示〕
4. **窗口级画面流（RemoteApp）**：单应用窗口抽取 → Variable 侧独立窗口呈现；窗口尺寸/DPI 同步。
   〔验收：视觉=窗口边框/阴影与 VWM 原生窗一致；逻辑=窗口缩放跟随（双向）×20；代码=流协议抽象接口冻结；完善性=多窗口并发数上限声明〕
5. **输入注入通道**：键鼠事件 Variable → 引擎反向注入；IME（中文输入法）路径专项。
   〔验收：逻辑=快速打字 30s 无丢键（字符计数比对）；IME 组合键全流程；代码=输入事件与阶段 3 输入总线同源；完善性=注入延迟实测入基线〕
6. **VWM 接管外来窗口**：引擎窗口注册进 vwmStore（新窗口类型）→ 贴靠/最小化/Z 序/几何持久化全部生效。
   〔验收：逻辑=窗口开关 100 次无句柄泄漏；贴靠后流分辨率同步；代码=复用 vwm.ts 状态机不 fork；完善性=与 embed 收编窗口的能力对照表（哪些 VWM 特性引擎窗不支持，如实列）〕
7. **占位卡与拉起协议**：点通道=engine 的软件 → 未就绪写请求 → 唤醒引擎 → 占位卡（embed 视觉语言）→ 就绪自动打开并撤卡。
   〔验收：视觉=占位卡动画与 embed 一致；逻辑=就绪前用户取消/引擎失败的撤卡路径；代码=拉起协议消息可重放（乱序不坏）；完善性=预期等待时长提示如实〕
8. **ramcache**：SHARED/WIN_ENGINE 热数据 LRU 缓存进宿主 RAM；**只缓不落盘、关机即清**；缓存一致性（盘上文件被另一系统改后失效）。
   〔验收：逻辑=关机后 U 盘字节级零残留校验（整盘 hash 对比）；一致性失效用例；代码=缓存区独立分配器（不碰内核页缓存）；开放性=缓存尺寸随性能档位联动；完善性=命中率统计与公示〕
9. **延迟测量与档位**：端到端延迟拆解（采集/编码/传输/解码/合成）→ 三档画质（流畅/均衡/高清）码率参数化。

## 阶段 9：升级协议与灾备演练

### 目标
U 盘系统可自我更新、可回滚、可救援——长期可用性。

### 详细逻辑
- **差分升级**：Base 不动 + 差分包（VARIX_SYS/WIN_ENGINE/SHARED 契约分通道），SHA-256 校验 + 失败自动回滚（复用 F-6 更新包语义）。
- **快照策略**：SNAPSHOT 区定期快照（每日/每周），保留 3 份滚动。
- **灾备演练**：半损坏（模拟 SuperBlock 撕裂/分区表损坏）→ repair 命令或快照恢复；全损坏 → 重建 U 盘 + 数据从 SHARED/SNAPSHOT 抢救。
- **跨机一致性**：boot-select.json/apps.json/白名单在两系统与引导器间的版本协同（单一事实源=SHARED）。

### 施工步骤（细化，每步带步骤级验收）

1. **升级包格式**：分通道差分包（VARIX_SYS/WIN_ENGINE/SHARED 契约三通道独立）+ 清单（版本/依赖/目标分区/SHA-256）+ 签名（ED25519）。
   〔验收：代码=格式规范文档+参考实现；逻辑=坏签名/清单篡改/分片缺失全拒绝；开放性=通道（stable/beta）与升级源（本地/网络预留）可配；完善性=格式版本号与迁移路径〕
2. **差分应用器**：事务式应用（staging 区先写 → 校验 → 原子切换）+ 任一步失败自动回滚。
   〔验收：逻辑=应用中断电 ×10 演练零变砖（每次重启后版本要么旧要么新，绝不半新）；代码=切换点唯一（单 rename/单指针翻转）；完善性=回滚后配置一致性校验联动〕
3. **快照调度**：SNAPSHOT 区每日/每周快照 + 滚动保留 3 份 + 快照创建避开写高峰（空闲检测）。
   〔验收：逻辑=快照恢复抽检 ×5（复用 F-6 可恢复性自检语义）；容量满时最旧淘汰+明确记录；代码=复用差分链不新造；完善性=快照内容说明（哪些分区进快照）〕
4. **灾备 SOP——半损坏**：SuperBlock 撕裂/分区表损坏/journal 坏尾三类模拟 → repair 命令或快照恢复步骤手册化。
   〔验收：逻辑=三类各 ×3 真机演练走通；恢复后数据完整性校验；完善性=SOP 文档含每步预期输出截图〕
5. **灾备 SOP——全损坏**：重建 U 盘（Deploy-To-USB）→ SHARED/SNAPSHOT 数据抢救流程 → 配置与登记回灌。
   〔验收：逻辑=全损坏演练 ×2 数据抢救率 100%（SHARED+SNAPSHOT 内数据）；完善性=SOP 含"什么救不回来"诚实清单〕
6. **配置一致性校验器**：boot-select.json/apps.json/白名单在引导器/VARIX/Windows 三处的单一事实源（=SHARED）校验 + 冲突时以 SHARED 为准的收敛流程。
   〔验收：逻辑=人为制造三处不一致 ×5 场景全部收敛正确；代码=校验随每次引导执行；完善性=各文件"谁是事实源"表〕
7. **版本协同**：VARIX 内核版本/垫片协议版本/前端版本/Wine 版本兼容矩阵 + 不兼容时的明确拒绝与提示。
   〔验收：逻辑=注入不兼容组合各拒绝并给出升级指引；开放性=矩阵数据驱动；完善性=矩阵表公示〕
8. **升级 UX**：升级进度 UI（bootPhase 视觉语言）/ 失败回滚提示如实 / 升级前自动快照。
   〔验收：视觉=进度页与启动仪式一致；逻辑=升级前快照失败则拒绝升级；完善性=升级耗时预期公示〕
9. **里程碑整合验收**：升级断电零变砖；灾备 SOP 真机走通；一致性校验纳入常规门禁。
   〔验收：逻辑=全部演练记录归档；完善性=长期维护手册（升级节奏/快照策略调优建议）〕

### 六维验收
- **视觉**：升级进度 UI（复用 bootPhase 视觉语言）；回滚提示如实；灾备手册可读排版。

### 验收门禁

## 阶段 10：性能基准与生态

### 目标
性能有基线有门禁；适配生态可持续；国际化与无障碍完整。

### 详细逻辑
- **性能基准**（复用 `tools/bench.cjs` / `Bench-Perf.ps1` 体系）：
  - 引导到选择页时长 / 选择页到桌面首帧 / 桌面交互延迟 P95 / 窗口开关 / 文件索引 / Wine 启动 / 引擎冷启动 / ramcache 命中率；
  - `--check` 回归门禁（>10% 回归 fail）；
  - 归档 `docs/bench/` 按日期（沿用命名纪律避免覆盖）。
- **适配生态**：apps.json 分级数据库 + 每软件缺失 API 清单 → 补齐排期看板。
- **国际化**：三语（简/繁/英）+ 拼音搜索沿用；引导页/新增设置页/降级提示全覆盖（audit i18n 门禁扩展）。
- **无障碍**：高对比度、焦点环、字号 80-150%、reduce-motion（沿 A-1/A-7/F-7 体系全量适用到新界面）。

### 施工步骤（细化，每步带步骤级验收）

1. **基准脚本 U 盘场景适配**：区分内置盘/USB 双模式跑分；采集项=引导到选择页/选择页到桌面首帧/交互延迟 P95/窗口开关/文件索引/Wine 启动/引擎冷启动/ramcache 命中率。
   〔验收：逻辑=同机三次方差 ≤5% 才算有效基线；代码=复用 bench.cjs/Bench-Perf 只加采集项；开放性=新基准项注册制；完善性=USB vs 内置盘对比数据归档〕
2. **性能契约定版**：目标值（引导 <8s 到选择页/首帧 <3s/交互 P95 <100ms 等）逐项登记目标与实测差距。
   〔验收：完善性=未达标项每条写"差距多少/原因/计划"；逻辑=实测值三机归档〕
3. **回归门禁**：`--check` 模式 >10% 回归 fail；注入人为劣化验证门禁真实拦截。

4. **基准数据归档纪律**：docs/bench/ 按日期命名（沿用防覆盖纪律）+ 每份含机型/盘型/档位元数据。
   〔验收：完善性=归档模板定版；简洁性=与既有 docs 归档纪律一致〕
5. **适配看板**：apps.json → 可视化页（三色占比/缺失 API 排期/版本历史）。
   〔验收：视觉=与通知中心风格一致；逻辑=数据源变更自动刷新；开放性=看板数据源可换（未来社区数据库）；完善性=三色占比数字与实际登记一致（交叉校验）〕
6. **i18n 全量补齐**：三语（简/繁/英）覆盖引导页/全部新增设置页/降级提示/救援 CLI 输出；audit i18n 门禁扩展到所有新界面。
   〔验收：逻辑=缺键即 fail 门禁验证（故意删键测试）；视觉=三语下布局不溢出（德语级长词预留）；完善性=词条覆盖率 100% 报表〕
7. **无障碍全量**：高对比度主题/焦点环/字号 80-150%/reduce-motion 四项全量适用到引导页与所有新界面。
   〔验收：视觉=对比度自动化检查零缺陷；逻辑=reduce-motion 下动画全部有静态替代；完善性=沿 A-1/A-7/F-7 体系检查清单逐条打勾〕
8. **生态与社区准备（开放性收口）**：apps.json schema 公开文档/适配数据库导入导出工具/贡献指南草案。
   〔验收：开放性=第三方可按文档产出合法 apps.json 条目（校验器验证）；完善性=schema 版本兼容承诺〕
9. **里程碑整合验收**：基线+门禁上线；i18n/无障碍零缺陷；性能契约实测归档。
   〔验收：三线门禁全绿；完善性=性能契约每项实测值+差距+计划三栏表终版〕

### 六维验收

## 作品级体验专项（贯穿所有阶段的九个专项）

> 定位：阶段 0-10 回答"功能怎么建成"；本部分回答"用户为什么愿意用、愿意留下"。二十个专项各自独立成线，与相关阶段同步施工（对照表见各专项开头）；每步同样带步骤级验收（含体验加验）。

### 专项 A：首次运行向导（First-Run Wizard）

> 关联阶段：3（界面栈就绪后立即做）。目标：新用户从引导页到"第一个软件跑起来"不超过 5 分钟，全程零文档依赖。

- **A1 向导骨架**：全屏向导组件（进度点/上一步下一步/跳过但记录）——复用设置页组件体系。
  〔验收：体验=跳过后下次设置页可重新进入；逻辑=中途断电重进从断点续走；视觉=与桌面启动动画衔接自然；代码=向导步骤注册表驱动（加一步不改骨架）；简洁性=复用 bootPhase 视觉语言〕
- **A2 能力选择页**：三通道（Wine/引擎/纯 Windows）漫画式一图一说明 + 推荐默认（按机型能力探测预选）。
  〔验收：体验=不通技术背景的测试者 3 人各 30 秒内说出三种通道区别（首用理解）；视觉=示意图与真实界面截图一致非概念图；完善性=探测失败时默认保守组合〕
- **A3 白名单初始配置**：向导内完成 SHARED 目录选择（默认建议文档/下载/游戏库三项）+ 明确告知"以后可在设置改"。
  〔验收：体验=单页完成 ≤3 次点击；逻辑=跳过则零白名单（默认拒绝不因向导而放宽）；完善性=每个建议目录有一句"为什么推荐"〕
- **A4 首个软件时刻**：向导收尾引导用户从开始菜单启动第一个软件（Wine 通道记事本或用户自装），成功后庆祝动效 + "你已学会基本操作"。
  〔验收：体验=首次成功启动 ≤5 分钟（实测 3 人计时归档）；视觉=庆祝动效克制（≤1.5s，reduce-motion 有静态版）；逻辑=软件启动失败的向导内兜底引导〕
- **A5 向导数据回灌**：向导选择写入 settings（通道默认/白名单/引擎开关），与设置页双向一致。
  〔验收：逻辑=向导改的项设置页即时反映（settings://changed 验证）；代码=零专用配置通道（全走既有 settings）；完善性=向导可整体重置重跑〕

### 专项 B：引导教程与帮助系统

> 关联阶段：3、4。目标：任何功能 30 秒内能自答"这是什么/怎么用"。

- **B1 情境帮助入口**：每个设置组/管理页右上"?"图标 → 就地气泡说明（不打断当前操作）。
  〔验收：体验=抽查 10 个功能页帮助文案各 ≤80 字且含一个例子；视觉=气泡与 tooltip 体系一致；代码=帮助文案 i18n 词条化管理（缺键 fail 门禁）〕
- **B2 快捷键速查卡**：`Ctrl+/` 全局呼出快捷键面板（分系统级/桌面级/窗口级三组），支持搜索。
  〔验收：体验=面板与实际注册快捷键同源生成（不可能过期）；逻辑=与既有全局键表（winman.rs）数据对接无手抄；开放性=插件可注册新键入卡〕
- **B3 搜索式帮助**：帮助中心单页 + 全文搜索（三语）；命中直接定位到对应设置页或功能入口。
  〔验收：体验=10 个常见问题搜索命中 ≤1 次输入；逻辑=搜索索引随 i18n 词条自动重建；完善性=帮助内容覆盖"三通道选择/白名单/拔盘/升级"四大高频主题〕
- **B4 引导页迷你教程**：选择页首次出现的机器加一行底部提示（"5 秒自动进入，↑↓选择"），看过即记（KV 服务）。
  〔验收：体验=提示只出现一次；逻辑=KV 损坏时提示重新出现（无害）；代码=与 bootui 文本渲染共用字体原语〕

### 专项 C：错误与恢复体验（把报错当产品做）

> 关联阶段：全部。目标：没有任何一个"裸错误码"直接面对用户。

- **C1 错误分级文案规范**：三段式错误卡（发生了什么（人话）/可能原因/现在能做什么按钮）+ 错误码折叠区（给排障者）。
  〔验收：体验=全部用户可见错误走统一组件（grep 无裸 alert/裸错误码直出）；视觉=错误卡三档严重级别（提示/警告/致命）观感分明；开放性=错误码注册表驱动〕
- **C2 一键自检页**：设置页"系统自检"——引导链/存储/白名单/引擎连通性/Wine 前缀健康五项逐项跑并出结论。
  〔验收：体验=每项结论一句话+一个"修复"或"去看"按钮；逻辑=自检只读不改动（修复需显式确认）；代码=自检项注册制；完善性=自检结果可导出（配合 C4）〕
- **C3 恢复向导**：检测到异常退出/强拔痕迹后，下次启动温和地提供"恢复上一次会话/干净启动"二选一。
  〔验收：体验=恢复向导不阻塞正常引导（10 秒无操作走默认）；逻辑=恢复失败回退干净启动且如实说明；代码=复用 boot.rs 备份恢复语义〕
- **C4 脱敏日志导出**：求助场景一键导出脱敏日志包（路径/密钥/白名单内容自动打码）。
  〔验收：逻辑=导出内容抽检零敏感信息（正则+人工双查）；代码=打码规则表驱动；完善性=导出格式含机型/版本元数据〕

### 专项 D：反馈与通知系统

> 关联阶段：3、4、7。目标：系统永远"有回应"，但永远"不打断"。

- **D1 长任务进度统一规范**：引擎拉起/升级/快照/首次 Wine 配置四类长任务统一进度组件（阶段文案+进度条+预计剩余+可取消性声明）。
  〔验收：体验=四类任务全部有阶段化文案（非无限转圈）；逻辑=不可取消任务在开始前明示（如实文化）；代码=进度事件统一协议（接 boot://event 语义扩展）〕
- **D2 toast 规则**：通知分四级（静默记录/角标/条/toast）+ 同类合并 + 顶不遮挡光标热区。
  〔验收：视觉=四级观感逐级递进对照表；逻辑=同类 5 秒内合并计数；代码=接通知中心既有体系〕
- **D3 操作即时反馈**：所有按钮/开关点击 ≤100ms 有可见状态变化（含慢操作立即进 pending 态）。
  〔验收：体验=抽测 20 个控件全部达标（录屏逐帧）；代码=慢操作强制 optimistic UI 模式；完善性=违规清单清零记录〕
- **D4 勿扰与声音**：演示/全屏软件运行时自动静默 toast；声音反馈可选且默认关。
  〔验收：逻辑=引擎窗口全屏时 toast 转角标；开放性=声音方案可替换；完善性=声音版权说明（若引入第三方音效）〕

### 专项 E：加载感知与性能观感（感知性能 ≠ 裸性能）

> 关联阶段：3、5、6。目标：慢可以，但必须"看起来在动、知道还要多久、值得等"。

- **E1 骨架屏统一组件**：文件管理器/设置页/看板三类列表统一骨架屏（形状=真实内容轮廓）。
  〔验收：视觉=骨架形状与加载完成内容逐位对齐（无跳动换位）；代码=单组件三处复用；体验=加载 ≥300ms 才显示骨架（快路径不闪）〕
- **E2 冷启动分阶段叙事**：引擎冷启动 20-40s 拆成命名阶段（挂载镜像→启动引擎→等待就绪→打开应用）逐段推进文案。
  〔验收：体验=测试者看进度能说出"现在卡在哪一步"；逻辑=阶段超时如实报错而非无限等；完善性=各阶段实测耗时公示〕
- **E3 首次 Wine 预期管理**：首次跑某 Wine 软件的 prefix 初始化单独进度 + "首次稍慢，之后秒开"预期文案。
  〔验收：体验=文案实测验证（首跑 vs 二跑对比数据归档）；逻辑=初始化失败清理干净不留半 prefix〕
- **E4 低配模式**：探测到低配机（内存 ≤8GB/无独显）自动建议低配模式（关动效/降 ramcache/骨架屏替代动画）。
  〔验收：体验=低配机交互 P95 改善实测归档；逻辑=模式可手动开关；开放性=档位参数表可调〕
- **E5 ramcache 预热提示**：插盘后后台预热热数据，任务栏角标显示"预热中 n%"，完成后 toast 一次。
  〔验收：逻辑=预热只读不写盘；视觉=角标不打扰（无弹窗打断）；完善性=预热前后启动耗时对比归档〕

### 专项 F：个性化与桌面打磨

> 关联阶段：3、7。目标：用户能把它"变成自己的"，桌面观感达 Windows 侧同水准。

- **F1 主题引擎迁移**：既有四主题（deep-space/paper/minimal-black/high-contrast）在内核显示栈全量适配（任务栏树暗色玻璃语义保留）。
  〔验收：视觉=四主题逐屏截图对照 Windows 侧；逻辑=主题切换热生效不重启；代码=主题 token 单一来源（复用 dictionaries/css 变量体系）；完善性=主题覆盖缺口清单〕
- **F2 壁纸与桌面个性化**：壁纸（含幻灯片轮换接 dailyFeed 思路）/ 图标大小 / 桌面网格吸附。
  〔验收：体验=壁纸切换 ≤1s 且有淡入；逻辑=壁纸文件走白名单路径；完善性=默认壁纸版权说明〕
- **F3 布局记忆**：窗口布局/任务栏设置/开始菜单磁贴全量持久化（KV 服务）+ "布局方案"保存与一键切换。
  〔验收：逻辑=重启后逐像素还原 ×10；开放性=方案可导出导入（跨 U 盘搬家预留）；简洁性=复用 vwmStore 持久化不另造〕
- **F4 配置迁移助手**：从 Windows 侧 Variable（%APPDATA% 或便携目录）一键导入设置/文档/思维导图等既有数据。

### 专项 J：工程级质量基建（让成熟可持续）

- **J3 sanitizer 常态化**：内核宿主机测试与后端测试开启 ASan/UBSan 档；release 门禁不退化。
  〔验收：逻辑=sanitizer 档全测试套件零新增告警；代码=CI 增加 sanitizer job；完善性=已知告警豁免清单（有理由有期限）〕
- **J4 依赖与供应链**：依赖清单冻结评审制（新增依赖需理由）+ npm/cargo lock 完整性校验 + wine/servo 上游版本跟踪表。
  〔验收：代码=lock 校验进门禁；逻辑=上游新版本影响评估流程；完善性=每个关键依赖"为什么用它"一行说明〕
- **J5 实机 QA 资产库**：`_attic/qa/` 脚本基座扩展为正式 QA 库——每阶段验收自动化脚本入库、可参数化复跑、结果归档。
  〔验收：逻辑=阶段 0-2 的验收脚本自动化率 ≥80%；代码=脚本遵循既有基座约定（动态坐标/elementFromPoint 交叉验证）；完善性=脚本清单与覆盖映射表〕
- **J6 混沌演练例行化**：断电/强拔/杀进程/磁盘满/时钟跳变五类故障注入做成可调度演练套件，每阶段验收必跑一轮。
  〔验收：逻辑=五类注入各 ×10 全部按"如实降级"预期；代码=注入框架复用掉电注入实现；完善性=演练报告模板〕

## 全局不变量（任何阶段不得违背）

1. **物理隔离四层**：盘级（Windows 封在 VHDX）/ 机级（宿主机零残留）/ VM 级（引擎边界）/ 进程级（内核独立进程）——任何新功能不得打穿。
2. **默认拒绝**：一切跨域数据访问走白名单，未配置即拒绝。
3. **如实文化**：能力缺失如实降级提示，不伪造成功；todo 与实测分开标注；❌ 项必须有补齐计划。
4. **行为等价**：Variable 既有视觉与操作语义不因迁移而改变。
5. **可停性**：每阶段交付都是可用的中间态。
6. **零残留**：宿主机任何时刻不落任何数据；缓存只入易失内存。
7. **编码纪律**：`.bat/.cmd` 纯 ASCII + CRLF；`.ps1` UTF-8 带 BOM；改后 `git ls-files --eol` 复核。
8. **内核边界**：业务功能不进入"AI 族"登记模块；登记层与启动链零调用关系。
9. **体验红线**：用户可见界面零裸错误码、零无限转圈（长任务必有阶段化进度）、零不可恢复的静默失败；任何界面交付前过"作品级体验加验"五子项。
10. **用户自由度**：任何默认值可配置（设置或配置文件）、任何危险操作可撤销或有缓冲、任何限制有如实解释——默认替用户做主，但永远允许用户做主。
