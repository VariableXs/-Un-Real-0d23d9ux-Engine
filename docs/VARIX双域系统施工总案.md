# VARIX + Variable 双域系统施工总案

> 本文件是整场架构讨论的定稿施工文档：目标形态、十大阶段的详细逻辑（数据结构/算法/事件流/决策规则）、每阶段施工步骤、六维极高质量验收、开放改进点。
> 配套的任务勾选清单见 `docs/VARIX双域系统总施工清单.md`；本文负责"逻辑怎么转 + 质量怎么验"，清单负责"进度怎么勾"。

## 0. 大致步骤总览（先看这张图）

```
阶段0  引导选择页            ← 内核画的第一个界面，无前置依赖，可立即动工
   ↓
阶段1  U盘五分区便携基建      ← 复用 portable/ 现有脚本体系
   ↓
阶段2  内核欠账清零          ← 缺页接线/用户态/真驱动/真盘FS（能跑的前提）
   ↓
阶段3  Variable界面上内核     ← Servo 承载现有 React 前端 + Tauri IPC 垫片
   ↓
阶段4  数据总线与白名单       ← 共享内存/消息通道/共享分区，默认拒绝
   ↓                       ↘
阶段5  Wine兼容层通道         阶段6 隐形Windows引擎通道   ← 二者可并行施工
   ↘                       ↙
阶段7  资源统管与多机打磨（设置页/配额/拔出保护/多机型验收）
   ↓
阶段8  安全加固与隐私（兼容层攻击面/审计/紧急救援通道）
   ↓
阶段9  升级协议与灾备演练（差分升级/失败回滚/快照恢复/长期维护）
   ↓
阶段10 性能基准与生态（bench 门禁/适配数据库/多语言/无障碍）
```

- **并行性**：阶段5 与阶段6 互不依赖，可两条线并行；阶段0/1 可在阶段2 之前先行（不碰内核）；阶段8-10 中不依赖硬件的部分可与 5-7 交错。
- **可停性**：任一阶段做完系统都处于"可用的中间态"，随时可停不尴尬。
- **门禁**：每阶段过三线全绿（V: tsc+vitest / C: ca-core / K: ktest+kcheck）+ 六维验收 + 实机验收报告归档 docs/。

### 终局形态一句话

一块 1TB U 盘插任意电脑：开机默认 5 秒进 VARIX+Variable 桌面；日常软件走 Wine 兼容层（Windows 完全没开机）；高兼容软件走隐形 Windows 引擎（实时无缝窗口）；游戏/反作弊重启进纯 Windows（同一块盘上的镜像）；拔盘即走、零残留。

## 阶段 0：引导选择页

### 目标
内核引导早期画出系统选择界面；这是 VARIX 画的第一个 UI。

### 前置依赖
无（不依赖其他阶段）。

### 详细逻辑
- **时机**：Limine 移交后、`boot()` 域初始化完成前，在 GOP 帧缓冲上直接绘制（只依赖 framebuffer，不依赖驱动栈）。
- **数据结构**：引导配置文件 `boot-select.json` 放共享分区（两系统都能读写）：
  - `default_entry`: `"variable" | "windows" | "last"`
  - `timeout_sec`: 默认 5
  - `show_menu`: bool（false = 静默走默认项）
  - `last_boot`: 上次实际进入的系统，每次进入时写回
  - `windows_bootnext`: 部署脚本预先探测的 Windows 引导项号
- **交互逻辑**：
  1. 画三行选项 + 倒计时进度条；
  2. 键盘（此阶段只需 PS/2 最小轮询读键）上下选择、Enter 确认；
  3. 倒计时归零 → 执行 default_entry；任何按键立即暂停倒计时进手动态；
  4. 选 variable → 继续域初始化；
  5. 选 windows → UEFI `BootNext` 指向 Windows 引导项，`ResetSystem()` 重启。

### 施工步骤（细化）
1. GOP 帧缓冲绘制原语（fill/rect/text 位图字体）＋ 自测图案；
2. `boot-select.json` 解析（容错：字段缺失走默认值，文件损坏走内置默认并标记）；
3. 选择页状态机（倒计时/手动/确认/执行四态）；
4. PS/2 键盘最小轮询 + 去抖；
5. BootNext 写入 + ResetSystem 路径；
6. 部署脚本探测 windows 引导项号并写配置；
7. 负向演练：配置文件损坏/键盘中途拔掉/倒计时中被拔盘。

### 六维验收
- **视觉**：选择页截图与 Variable 视觉语言对照（同色板）；1920×1080/2560×1440 双分辨率绘制正确；125% 高分屏无错位；倒计时进度条动效平滑（帧率抽帧检查）。
- **逻辑**：四态状态机全路径自动化推演（含"倒计时最后一刻按键"竞态）；JSON 损坏/字段缺失/非法值三种脏数据用例；BootNext 写入失败时必须放弃切 Windows 并留在菜单（不得盲目重启）。
- **代码**：绘制原语零 panic 路径（引导期 panic 无处可去）；配置解析 fail-safe 注释齐全；与 Limine 协议代码隔离在独立模块。
- **开放性**：新增第四个引导项（如"维护模式"）只加配置不改状态机；字体/色板参数化。
- **简洁性**：绘制原语与后续内核显示服务不重复实现（本阶段原语后续被阶段2 收编为唯一实现）。
- **完善性**：契约清单=选项绘制/倒计时/键盘/切 Windows/记忆上次/配置容错——逐条核对登记。

### 开放改进点
- 选择页升级为 Variable 风格动画页；多语言（中/英）；USB 键盘引导期支持。

### 验收门禁
- 真机 U 盘引导：5 秒无操作自动走默认项；选 Windows 真机重启进入 VHDX Windows；配置改动下次引导生效。

## 阶段 1：U 盘五分区便携基建

### 目标
一键脚本从零产出可引导 U 盘；复用项目现有便携体系。

### 前置依赖
无（可与阶段 0 并行）。

### 详细逻辑
- **分区布局**（1TB 盘定版）：
  1. `ESP`（1GB）：VARIX 引导器 + Limine + Windows 引导文件（BCD 等）
  2. `VARIX_SYS`（64GB）：内核 ELF + Variable 运行时 + Servo + Wine 前缀模板
  3. `WIN_ENGINE`（300GB，NTFS）：Windows 引擎 VHDX（差分链 Base→Apps→User）
  4. `SHARED`（600GB，exFAT）：唯一互通面
  5. `SNAPSHOT`（余量，NTFS）：快照/回收/恢复
- **SHARED 目录契约**：`apps.json`（软件登记总表：名称/图标/通道 wine|engine|native-only/分级）、`handoff/`（意图接力队列）、`whitelist/`（白名单规则）、`boot-select.json`。
- **脚本改造**：`Deploy-To-USB.ps1` 新增 `Deploy-Varix` 段；`Create-VHDX.ps1` 参数化容量；`Test-VM.ps1` 支持 U 盘整机验收。
- **拔出保护**：复用 `usb.rs`（1s 轮询 + 2s `wal_checkpoint(PASSIVE)` + 卷消失广播），适配五分区。

### 施工步骤（细化）
1. 分区脚本（GPT + 五分区 + 对齐校验）＋ 幂等重跑；
2. ESP 组装（VARIX 引导器 + Windows 引导文件双链）；
3. VHDX 差分链产出与挂载验证；
4. SHARED 目录契约初始化 + apps.json schema 定版（带 `version` 字段）；
5. Deploy-To-USB 总编排（四阶段沿用：Preflight/Stage/Verify）；
6. 拔出保护适配 + 强拔演练；
7. VM 整机验收流水线。

### 六维验收
- **视觉**：不适用界面项→以"部署报告页"替代：脚本输出含分区表可视化 ASCII 图与容量核对表；报告归档可读。
- **逻辑**：幂等性（连跑两次结果一致）；容量边界（1TB 减五分区余量校验，拒绝小盘时给明确报错）；强拔演练（五分区各占用时拔）数据零损坏；差分链合并/回滚演练。
- **代码**：脚本纯 ASCII + CRLF（`.bat/.ps1` 编码硬约束）；`git ls-files --eol` 复核；危险操作（清盘前）二次确认交互。
- **开放性**：分区容量全部参数化（配置驱动）；apps.json 带版本号与升版迁移函数；新增第六分区不改编排骨架。
- **简洁性**：不重写 Create-VHDX/Deploy 已有逻辑，只加段；部署报告与 Test-VM 报告同一格式。
- **完善性**：契约=五分区/双引导链/差分链/SHARED 契约/拔出保护/VM 验收——逐条登记，缺失项标 ❌ 并写明补齐计划。

### 开放改进点
- 容量比例按实际软件规模调参；VARIX_SYS 压缩只读映像；多 U 盘 Base+差分版本管理。

### 验收门禁
- 一键脚本零人工干预产盘；VM 引导到选择页；强拔五场景零损坏。

## 阶段 2：内核欠账清零

### 目标
内核从"引导完就停"变成"能跑程序、能摸硬件、能存数据"。

### 前置依赖
无强制（阶段 0/1 可先行）。

### 详细逻辑
- **2.1 缺页处理接线**（最高优先）：
  - 现状：`paging::decide()` 决策纯函数已完成（guard→Fault / reserved-write→Fault / 栈未触碰→GrowStack / present+write+cow→CopyOnWrite / !present→SwapIn|MapZero），但 `idt::isr_dispatch` 对 vector<32 一律 fatal。
  - 改造：IDT 0x0E 注册专用 handler → CR2 取故障地址 + 错误码 → 组装请求 → `decide()` → 四路动作；仅 Fault 才 fatal。
  - COW：fork 前置——写时复制位 + 页框引用计数；GrowStack 带栈上限。
- **2.2 用户态进程壳**：
  - ring3 切换（段选择子 RPL=3）；syscall/sysret 与 int 0x80 双入口（断言两路一致，沿用 `entry.rs` 既有断言风格）；
  - 号表扩充：spawn/exit/wait/mmap/brk/open/read/write/close/ioctl 骨架；
  - 进程控制块（地址空间/句柄表/父子）+ 复用 64 槽线程调度；
  - init 进程：从 VARIX_SYS 读 ELF 并 spawn。
- **2.3 真驱动**：显示（GOP 封装双缓冲显示服务）；键鼠（PS/2 轮询起步，xHCI 最小栈后补）；存储（NVMe 提交/完成队列最小实现优先，AHCI 兜底，块设备抽象层统一）；文件系统（fs23_journal 换块设备后端；VARIX_SYS 只读简单 FS；SHARED exFAT 读写或先只读过渡）。
- **2.4 掉电安全**：journal 语义不变（torn 丢弃该点及之后全部 + 幂等重放），掉电注入 100 轮沿用。

### 施工步骤（细化）
1. #PF handler + decide 接线 + 故障路径单测（构造非法访问断言四路各走通）；
2. ring3 切换 + 最小 syscall（exit/write 串口）+ 用户态 hello；
3. 进程控制块 + spawn/wait + ELF 装载器；
4. 块设备抽象 + NVMe 最小栈 + 读写回环测试；
5. fs23_journal 后端替换 + 掉电注入回归；
6. exFAT 读实现（写走快照区过渡）+ SHARED 挂载；
7. PS/2 键盘事件服务化 + xHCI 立项评估；
8. 每步一验收，串行推进（内核文件禁并行 Edit 的既有纪律）。

### 六维验收
- **视觉**：本阶段以"内核显示服务自测图案"替代：色条/网格/渐变三图案多分辨率无失真；双缓冲无撕裂（高速滚动抽帧）。
- **逻辑**：decide 四路各 ≥3 用例（含并发缺页同一页框）；COW 引用计数边界（计数归零竞态）；spawn 压力（64 槽打满/耗尽时优雅拒绝）；掉电注入 100 轮 0 丢失。
- **代码**：内核路径新增零 `unwrap`/零 `panic!`（错误统一 Result + kwarn）；不安全块逐一注释不变量；`kcheck` 0 告警；模块不与 AI 族登记层发生调用（架构边界）。
- **开放性**：syscall 号表带版本段（原生 0x4000/兼容 0x4100/vendor 0x4200 既有格局延续）；块设备抽象 trait 冻结（NVMe/AHCI/未来 virtio 同接口）；驱动注册表化。
- **简洁性**：不复活"AI 族"登记模块与启动链的任何调用关系；驱动共用一套 DMA/寄存器访问原语。
- **完善性**：契约=缺页/用户态/进程/ELF/块设备/NVMe/exFAT/掉电安全/串口 console——逐条登记；"SwapIn 通道暂无真交换分区"等暂缺项显式登记。

### 开放改进点
- 调度类权重针对桌面负载调优；xHCI 完成度；virtio 驱动（为 VM 内联调铺路）。

### 验收门禁
- 真机启动到可交互 shell；ELF 程序 spawn/exit；断电重上电数据完好；ktest/kcheck 全绿。

## 阶段 3：Variable 界面上内核

### 目标
U 盘引导默认进入 Variable 桌面；前端代码复用最大化。

### 前置依赖
阶段 2（用户态+显示服务）。

### 详细逻辑
- **架构**：`内核系统服务 ← Tauri IPC 垫片 ← Servo(Variable React 前端) ← GOP 帧缓冲`
- **Servo 集成**：用户态进程；渲染输出走共享帧缓冲；输入事件内核输入服务 → 消息通道 → DOM 事件。
- **Tauri IPC 垫片**（关键复用件）：
  - `lib/ipc.ts` 约 554 方法、全库仅 4 处裸 invoke——垫片实现同一 invoke 协议；
  - 命令三色映射（用 `tools/audit.cjs` IPC 清单）：✅内核原生服务（文件/窗口/输入）/ 🔶可映射（组合多个内核服务）/ ❌暂缺（统一降级错误 + 前端如实提示 + i18n 词条）；
  - 缺失清单驱动补齐顺序。
- **启动链**：选择页选 Variable → 域初始化 → spawn init → spawn Servo(Variable) → 桌面亮起；bootPhase（loading→exit→done）由内核服务进度事件喂 BootScreen，保留启动仪式体验。
- **状态迁移**：vwmStore 几何持久化 localStorage → 内核 KV 存储服务。

### 施工步骤（细化）
1. 垫片协议定版（invoke 名/参数序列化/错误码三段式）；
2. 三色审计：跑 audit.cjs 产出 554 方法映射表（归档 docs）；
3. KV 存储服务 + vwmStore 持久化迁移；
4. 输入事件管道（内核→Servo）+ 焦点模型；
5. 第一批保底命令面：桌面壳/文件管理器/设置页三件套；
6. BootScreen 进度事件对接（bootPhase 语义不变）；
7. 降级提示 i18n（zh/en）全量补齐；
8. 性能采样（首帧时间/交互延迟基线）。

### 六维验收
- **视觉**：Variable 桌面截图与 Windows 侧运行图逐屏对照（任务栏/开始菜单/窗口壳）；动画时长曲线一致（spring 4% 过冲沿用）；125% DPI 与多分辨率；`png_probe.py` 度量；焦点环/对比度无障碍检查。
- **逻辑**：bootPhase 三态与退出路径全覆盖；垫片错误码路径（✅/🔶/❌ 各采样断言）；KV 持久化断电恢复；窗口开关 100 次循环无泄漏（内存水位曲线）。
- **代码**：前端 diff 零语义改动（对照 vitest 全绿证明）；垫片零裸 invoke 绕过；降级错误必带 i18n 词条（audit i18n 门禁扩到垫片）。
- **开放性**：映射表数据驱动（新命令加表不改垫片代码）；Servo 可替换（接口留 BSD 渲染抽象）。

## 阶段 5：Wine 兼容层通道

### 目标
Windows 完全不运行的前提下，.exe 在 VARIX 用户态跑起来。

### 前置依赖
阶段 2（进程/文件系统）、阶段 4（白名单）。

### 详细逻辑
- **三层结构**：PE 装载器（头/节表/导入表 → 映射 + 符号绑定 Wine DLL 实现）；Win32 服务台（Kernel32/User32/GDI 等 VARIX 移植版，底层调内核 syscall）；进程模型（每 exe = 独立内核进程 + Job 级限额，语义同 `isolation.rs` 设计）。
- **图形路径**：GDI → 软件渲染到窗口服务；DirectX → WineD3D→Vulkan（后期）→ 软件兜底。
- **分级登记**（SHARED/apps.json）：✅ 可跑（办公/工具/多数桌面）/ 🔶 逐步补（缺哪个 API 补哪个，登记缺失清单）/ ❌ 不可跑（内核驱动类、反作弊——永远走纯 Windows 通道）。
- **物理隔离语义**：Windows 进程不存在 → 内存零 Windows 代码；地址空间内核隔离；与 Variable 只走白名单。

### 施工步骤（细化）
1. Wine 移植评估报告（NTAPI 对接面 → VARIX syscall 映射清单，工作量分级）；
2. PE 装载器 + 静态链接 exe 加载运行（先不含导入解析）；
3. 导入表解析 + Wine 核心 DLL 绑定；
4. 记事本级闭环（GDI 文本/菜单/文件对话框）；
5. Job 限额接入（内存/CPU rate/KILL_ON_JOB_CLOSE 语义）；
6. 适配数据库（每软件：版本/所需 API/结论/缺失清单）；
7. 分级登记写 apps.json + 桌面图标通道标记。

### 六维验收
- **视觉**：记事本/计算器等目标软件截图与原生 Windows 运行对照（字体渲染/菜单布局）；窗口装饰与 VWM 红绿灯视觉一致；多 DPI 缩放正确。
- **逻辑**：PE 解析负向用例（畸形头/超界节表 → 拒绝加载不崩溃）；限额边界（内存超限优雅终止非整机挂）；10 软件并发启动无串扰（句柄/命名对象隔离）。
- **代码**：移植改动全部落在对接层（上游 Wine 主体不动，补丁集管理）；每处 syscall 映射注释对应内核服务；新增 unsafe 逐一登记。
- **开放性**：适配数据库 schema 公开（社区化潜力）；prefix 模板可导出导入；API 缺失登记驱动补齐排期。
- **简洁性**：不实现与目标软件无关的 API 面（按需渐进）；复用内核文件/窗口服务，不在 Wine 内重复造 FS。
- **完善性**：首批目标软件清单（≥10 款）逐款登记结论；❌ 项明确"走哪个通道替代"。

### 开放改进点
- Wine 版本跟进与补丁集管理；MSVCRT/glibc 运行库打包；字体渲染质量；适配数据库社区化。

### 验收门禁
- Windows 断电状态实机：记事本闭环 + 办公/工具 ≥5 款通过；限额生效验证；适配数据库上线。

## 阶段 6：隐形 Windows 引擎通道

### 目标
需要原生兼容性时，Windows 作为后台引擎被拉起，应用窗口无缝出现在 Variable 桌面。

### 前置依赖
阶段 4（白名单/数据总线）；可跳过（纯 Wine 路线用户可整段禁用）。

### 详细逻辑
- **引擎生命周期**：关闭（默认）→ 拉起中（冷启动 20-40s，UI 如实提示）→ 就绪（常驻近零占用）→ 休眠（内存快照到 WIN_ENGINE 差分盘）。
- **VM 管理**：过渡期 Hyper-V 底座（直接挂 WIN_ENGINE VHDX）；终局评估内核自带 VMX。
- **无缝窗口**：窗口级画面流（RDP RemoteApp / Spice）→ Variable 侧解码为窗口内容；输入反向注入；VWM 接管（`vwm.ts` 状态机复用：贴靠/最小化/Z 序）。
- **ramcache**：热数据缓存进宿主 RAM，**只缓不落盘、关机即清**——不破坏拔盘无痕。
- **拉起协议**：点通道=engine 的软件 → 引擎未就绪则写请求 + 唤醒 + 就绪自动打开；窗口出现前显示占位卡（复用 embed 占位卡视觉语言）。

### 施工步骤（细化）
1. VHDX 挂载 + VM 拉起/保活/休眠编排；
2. 画面流通道打通（先全屏后窗口级）；
3. 输入注入通道；
4. VWM 外来窗口接管（注册/snap/几何持久化）；
5. 占位卡视觉与"引擎拉起中"提示；
6. ramcache（缓存策略/LRU/关机清空断言）；
7. 延迟测量与档位（画质/码率）；
8. 引擎休眠/恢复速度优化。

### 六维验收
- **视觉**：无缝窗口与原生 VWM 窗口混排截图对照（边框/阴影/红绿灯一致）；占位卡动画沿用 embed 视觉语言；流画质档位切换即时生效。
- **逻辑**：生命周期状态机（拉起中强拔盘/VM 崩溃/就绪后拔盘三异常路径）；窗口 100 次开关无句柄泄漏；ramcache 关机后 U 盘零残留字节级校验；延迟实测 ≤50ms（办公场景）归档。
- **代码**：流协议封装单模块（可替换 RDP/Spice）；引擎编排幂等（重复点击不双开）；与 embed.rs 既有语义复用不重写。
- **开放性**：流协议抽象可插；VM 底座可替换（Hyper-V → 内核 VMX）；多引擎实例预留。
- **简洁性**：休眠快照走既有差分链，不新造快照格式。
- **完善性**：契约=生命周期/无缝窗口/输入/ramcache/拉起协议/延迟预算——逐条登记；"内核 VMX 未实现，现用 Hyper-V 底座"显式声明（对齐诚实文化）。

### 开放改进点
- 休眠/恢复速度；码率画质档；多引擎实例；VMX 终局迁移。

### 验收门禁
- 冷启动→窗口出现全流程可用；延迟达标；ramcache 零残留验证；异常路径三场景演练。

### 验收门禁

### 施工步骤（细化）
1. 基准脚本适配 U 盘场景（区分内置盘/USB 跑分）；
2. 基线归档 + 门禁接入阶段验收；
3. 适配看板（apps.json → 可视化）；
4. i18n 全量补齐 + audit 扩展；
5. 无障碍全量检查（对比度/焦点/动效降级）。

### 六维验收
- **视觉**：看板页视觉一致；基准报告排版规范归档；无障碍自动化检查零缺陷。
- **逻辑**：基准可复现（同机三次方差 ≤5%）；回归门禁真实拦截（注入人为劣化验证会 fail）；i18n 缺键即 fail 门禁生效。
- **代码**：基准脚本纯 ASCII 纪律；数据 schema 版本化。
- **开放性**：基准项可扩展注册；看板数据源可换。
- **简洁性**：复用 bench 体系不新造框架。
- **完善性**：性能契约（引导 <8s 到选择页/首帧 <3s/交互 P95 <100ms 等目标值）逐项登记实测值与差距。

### 开放改进点

### 验收门禁

## 全局不变量（任何阶段不得违背）

1. **物理隔离四层**：盘级（Windows 封在 VHDX）/ 机级（宿主机零残留）/ VM 级（引擎边界）/ 进程级（内核独立进程）——任何新功能不得打穿。
2. **默认拒绝**：一切跨域数据访问走白名单，未配置即拒绝。
3. **如实文化**：能力缺失如实降级提示，不伪造成功；todo 与实测分开标注；❌ 项必须有补齐计划。
4. **行为等价**：Variable 既有视觉与操作语义不因迁移而改变。
5. **可停性**：每阶段交付都是可用的中间态。
6. **零残留**：宿主机任何时刻不落任何数据；缓存只入易失内存。
7. **编码纪律**：`.bat/.cmd` 纯 ASCII + CRLF；`.ps1` UTF-8 带 BOM；改后 `git ls-files --eol` 复核。
8. **内核边界**：业务功能不进入"AI 族"登记模块；登记层与启动链零调用关系。
