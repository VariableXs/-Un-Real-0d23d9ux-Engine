# xHCI 立项评估报告（任务19 · AI-K · 2026-09-17）

总案口径：PS/2 事件服务化阶段归档 xHCI 立项评估（范围/工作量/风险）。

## 结论

- **立项可行，建议排在任务21（里程碑整合）之后启动**。
- 定位：xHCI 是**增量键鼠/外设通道**，不替代 PS/2 轮询服务——inputsvc 保持默认输入通道，xHCI 失败不阻塞引导（与"软件渲染兜底不变"同一兜底原则）。

## 范围（要做什么）

- [ ] M1 寄存器层：Capability/Operational 寄存器映射（复用任务18 槽位化 BarMmio）→ USBCMD reset → 端口状态寄存器轮询（CSC/PED 变化识别设备插拔）
- [ ] M2 环形结构：事件环（ERST/ERDP）+ 命令环（CRCR）+ 传输环 TRB ring + 门铃（DBELL）；NoOp 命令回环验收
- [ ] M3 设备枚举：Enable Slot → Address Device（控制传输 BSR/CR）→ GET DESCRIPTOR(DEVICE/CONFIG) → 接口/端点解析
- [ ] M4 数据流：中断端点 IRP 轮询 → HID 报告（boot protocol 键盘 8B/鼠标 3-4B）解析 → 映射 InputEvent 接入 inputsvc（新增 `Hid` 事件种类，扩展 shim://input 契约）
- [ ] QEMU 验收面：`-device qemu-xhci -device usb-kbd -device usb-tablet`，每里程碑实机串口探针（沿任务16/19 风格）

## 可复用基建（零新建）

- ECAM 扫描：pci.rs classify 需加 `xHCI = class 0x0C/0x03/0x30`（scan_nvme_all 模式直接套）
- BAR 映射：BarMmio 每实例槽位窗口（任务18 修复后天然支持多控制器/多设备）
- DMA：DmaBuckets/DmaMem 帧清零规范（任务16 建队帧未清零教训直接迁移到 TRB/ER 环初始化）
- 队列消费：NVMe phase 位轮询+CQE 消费范式 → TRB Cycle bit 同构
- 实机驱动：HMP sendkey/mouse_move（任务19 已验证）+ usb-kbd 注入路径

## 工作量（按里程碑，口径=实现+宿主用例+QEMU 实机+验收归档）

- [ ] M1 约 1 天（寄存器语义简单，参照 NVMe reset/enable）
- [ ] M2 约 2 天（TRB 类型 ~16 种只需 6 种：Link/NoOp/EnableSlot/AddressDevice/Normal/Setup+Status+Data）
- [ ] M3 约 2 天（控制传输三段式 + Endpoint Context/Slot Context 布局核对，需对照 QEMU hw/usb/hcd-xhci.c 源码）
- [ ] M4 约 1–2 天（HID 报告表 + inputsvc 接线 + 契约扩展）

## 风险与对策

- R1 TRB 环 DMA 一致性 / MTTCG 撕裂读 → 沿用任务16 双读一致性快照 + 建环帧清零规范
- R2 QEMU xHCI 事件节流/中断模拟差异 → 纯轮询模式（IMOD=0，ERDP 手动推进），规避 MSI/MSI-X（内核尚无 MSI 栈，明确不做）
- R3 设备状态机复杂（Slot/Endpoint Context 32 字节布局、DCBAAP 索引）→ 只走最小路径：1 控制器 1 设备 1 中断端点；集线器级联/流协议/带宽管理明确不做
- R4 环回绕（TRB ring 4096 项 + Link TRB）→ 宿主环回绕用例 + 实机长跑
- R5 不可达兜底 → PS/2 服务保持默认通道（已任务19 验收），xHCI 探针失败 kwarn 后继续引导

## 验收门禁（立项后）
