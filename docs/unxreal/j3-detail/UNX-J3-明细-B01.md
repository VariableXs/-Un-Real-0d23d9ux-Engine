# UNX-J3 定制明细 · B01（F37601–F37620 · CNG 算法提供者框架与算法注册表）

### UNX-F37601 · BCryptOpenAlgorithmProvider 类入口与算法名解析
**功能**：这是整个 J3 加密服务的第一道大门，对齐 Windows CNG 的 BCryptOpenAlgorithmProvider 语义。调用者传入算法名字符串（AES、RSA、ECDSA P-256、SHA-256 等 12 个算法族全支持）与 flags，入口负责解析名字、查注册表、发放算法句柄。解析层统一做大小写归一、空白裁剪与内码校验，杜绝因字符串差异导致同名算法被当成两个对象。flags 支持 ALG_HANDLE_FLAG 类语义位，未知 flag 精确拒止。
**完成**：30 组黄金打开用例（12 族 × 正常/大小写变体/带空白变体）全部通过；未知算法名返回 STATUS_INVALID_PARAMETER 单一错误码且不残留任何部分初始化对象；句柄发放与关闭构成闭合账，10^3 次开关循环后句柄账余额归零；ktest 断言注册全绿。

### UNX-F37602 · 算法注册表与五槽函数表（init/encrypt/hash/sign/kdf）
**功能**：注册表是 J3 的"算法户口本"：每个算法族一行，挂五槽函数表——初始化槽、加密槽、哈希槽、签名槽、派生槽。哈希族只有哈希槽，AES 族有初始化与加密槽，RSA/ECDSA 族挂签名槽，KDF 族挂派生槽；槽位缺失本身就是一种正确性表达。注册表只读段在启动时构建，运行期查询走无锁读路径，热路径零分配。
**完成**：12 族 × 五槽函数表结构断言通过；对"哈希族查加密槽"这类错配构造 10 格拒止矩阵全部精确拒绝；注册表在 4 线程并发 10^4 次查询下 TSan 零报告；热路径查询 P95 实测入性能账。

### UNX-F37603 · 算法属性查询面（对象长度/块长/支持模式）
**功能**：对齐 BCryptGetProperty 语义：调用者可查询对象长度（放状态结构的缓冲区要多大）、块长、密钥位宽、支持的链模式等属性。实现两段式协议——第一次传 NULL 缓冲区只拿需要的长度，第二次传足额缓冲区拿值；缓冲区不够时返回 STATUS_BUFFER_TOO_SMALL 并回填所需长度，绝不半写。
**完成**：黄金 40 格属性查询（12 族 × 对象长度/块长/位宽/模式四类）全过；两段式协议在"先小后大""先 NULL 后取"两种顺序下结果一致；未知属性名返回 NOT_FOUND 且错误信息含可用属性提示；半写行为用毒化缓冲区（预填 0xAA）检测为零命中。

### UNX-F37604 · 提供者函数表解析与非法注册拒止
**功能**：提供者向注册表登记函数表时，框架负责验表：五槽指针要么合法要么显式标注不支持，禁止悬垂指针与半初始化注册。重复算法名注册一律拒止并告警——这是防"覆盖式劫持"的防线：后到者不能顶掉先到者，防止恶意或失误代码借同名算法偷换实现。每次注册/拒止事件全落审计账。
**完成**：非法函数表 10 格拒止矩阵（空槽指针/悬垂地址/槽位越权）全部拦截；重复注册用例返回明确错误且原注册保持原样（注册表逐字节不变断言）；审计账含全部注册尝试的来源、时间与结果，可检索回放。

### UNX-F37605 · CNG 算法提供者框架与状态机克隆（接管 security.rs 存量哈希纪律）
**功能**：任务书示例锚主条目。本条把 kernel/varix/src/security.rs 里存量的 SHA-256/ChaCha20 存量实现"接管"进新框架：对外接口全部走本框架句柄体系，存量实现作为被托管的后端逐步退役，而不是另起炉灶写第二份。框架层还定义了状态机克隆总纲——任何算法状态对象可被克隆，克隆体与原体状态字节级一致但内存完全独立，为 DuplicateHash 类语义打地基。
**完成**：接管声明落档（存量调用点清单 × 迁移映射表）；框架冒烟用例经克隆后双体各自独立演进且初态逐字节一致；security.rs 存量路径在开关切至框架后回归全绿、无行为漂移；"只此一份实现"审计（全域 grep 无第二份同语义实现）通过。

### UNX-F37606 · FIPS 类模式位（策略开关 · 记账不承诺合规）
**功能**：提供全局策略开关，开启后框架只放行"经过标准向量验证"的算法与参数档（如禁用非标准 tag 长度、禁用弱 KDF 迭代档）。诚实三态：这是"FIPS 类"模式，提供纪律约束与记账，不承诺任何官方合规认证——声明写进文档与错误提示，不虚标。
**完成**：开关开启后 12 族中每个不符合策略的用法都有对应拒止用例；开关状态可查询且随句柄记账（句柄创建时快照策略）；文档与 --help 类输出含"不承诺合规"显式声明；关闭开关行为与旧路径逐字节一致（开关零副作用断言）。

### UNX-F37607 · 句柄表与句柄有效性校验（STATUS_INVALID_HANDLE 面）
**功能**：句柄表是全 J3 的信任锚：所有算法/密钥/哈希状态都以不透明句柄暴露给调用者，句柄表内部存类型标签、代数计数与所属提供者。每次使用先校验——类型对不对、代数是不是最新的（防释放后复用）、有没有越界。校验失败统一返回 STATUS_INVALID_HANDLE，杜绝句柄混淆攻击。
**完成**：句柄表 10^5 次开关循环零泄漏（余额账归零）；释放后复用旧句柄 100% 被代数计数拦截；跨类型误用（哈希句柄当密钥句柄）拒止矩阵 10 格全过；句柄表并发扩容（10^4 并发打开）零竞态，TSan 零报告。

### UNX-F37608 · 对象长度两段式查询协议（BUFFER_TOO_SMALL 语义）
**功能**：把"先问大小、再取数据"的 Windows 惯例做成全框架统一协议：所有返回变长数据的 API 都遵守同一套语义——缓冲区不够不半写、回填所需长度、错误码单一。这样调用者只需学会一次，处处可用；实现层用一个共享的协议函数杜绝各 API 各写一套产生漂移。
**完成**：12 个返回变长数据的 API 逐个过协议断言（小缓冲/精确缓冲/超额缓冲三态）；毒化缓冲区检测零半写；所需长度回填值与后续成功取回的字节数 100% 一致；协议函数单元覆盖 100%，全 API 无旁路实现（grep 验证）。

### UNX-F37609 · 链模式枚举与 CHAINING_MODE 属性面
**功能**：AES 族支持 CBC/ECB/GCM/CTR 等链模式，本条把链模式做成显式枚举 + 字符串属性双面：调用者可用 CHAINING_MODE CBC 字符串设置，也可用枚举 API 直设。非法模式串精确拒止并回显支持清单；模式一经状态机启动不可中途切换，防止半途换模式造成状态错乱。
**完成**：模式串/枚举互转黄金表 20 组全过；非法模式（含大小写陷阱、尾随空白）拒止并回显支持清单；启动后切模式用例被拒且状态机保持原状态逐字节不变；每模式与 Windows CNG 命名对照表入档零漂移。

### UNX-F37610 · 多提供者同名仲裁与优先级账
**功能**：为开放性预留：未来第三方可注册替代实现。框架定义同名仲裁规则——内置提供者优先级最高且不可被覆盖；第三方同名注册只能登记为备选，仲裁结果与优先级全落账可审计。杜绝"谁后注册谁生效"的混乱，也杜绝内置实现被静默顶替。
**完成**：第三方同名注册用例验证"登记为备选、不生效"语义；优先级账含全部仲裁事件可检索；强制切换仲裁顺序的注入用例被拒；内置实现指针完整性断言（注册表构建后内置槽位指针冻结）全绿。

### UNX-F37611 · 提供者生命周期与卸载拒止（在用句柄保护）
**功能**：提供者有完整生命周期：注册→可用→（在用）→卸载。只要还有在用句柄或活动状态对象，卸载请求一律拒止并返回在用计数；引用计数归零才允许真正卸载，卸载时执行资源回收与审计落账。这是防"地毯抽掉还在上面跳舞"的经典生命周期纪律。
**完成**：在用句柄存在时卸载用例 100% 被拒且回报准确在用计数；引用归零后卸载成功且回收完整（内存账归零）；卸载后旧句柄访问全部得到 INVALID_HANDLE 而非崩溃；生命周期事件全落审计账可回放。

### UNX-F37612 · 算法能力探针（AES-NI/SHA 扩展运行时探测·探针结果落账）
**功能**：启动时用 CPUID 类指令探测硬件能力：有无 AES-NI、SHA 扩展、PCLMULQDQ 等，探测结果一次性落账并供各算法选择软件/硬件双路径。探针只读不写、失败不致命（缺能力=走软件路径），结果账供性能归因（"这条慢是因为没硬件加速"有据可查）。
**完成**：探针结果与手工 CPUID 解码一致（三台不同指令集机器实测）；能力缺席时路径选择正确降级且性能账标注原因；探针代码只读寄存器零副作用；同一机器重复探测结果稳定（100 次一致）。

### UNX-F37613 · CAPI 兼容面地基：CryptAcquireContext 供应者语义
**功能**：老式 CryptoAPI（CAPI）的 CryptAcquireContext 语义在本框架的投影：让习惯 CAPI 的调用方能以旧概念（CSP 名、PROV 类型）打开等价能力，内部映射到统一注册表。这是兼容面地基——只做语义映射，不做行为伪造：CAPI 没有的能力不假装有，映射表逐格入档。
**完成**：PROV 类型映射黄金表 15 格全过；CAPI 面不支持的调用精确报错并指引 CNG 等价入口；映射表与 Windows 行为对照零漂移；新旧两面打开同一算法得到的底层实现一致（哈希同文同摘要断言）。

### UNX-F37614 · 提供者注册框架并发安全与热路径开销
**功能**：注册框架的并发面：注册/查询/仲裁都可能被多线程同时触发。写路径（注册）用互斥，读路径（查询）无锁；热路径（已注册算法的打开）不加锁——句柄发放走原子表槽。目标是"注册期安全、运行期零争用"，密码调用不该为框架的并发控制付税。
**完成**：注册期 4 写者 × 8 读者并发压测零竞态（TSan 零报告）；热路径打开 P95 ≤ 2μs 实测入账；读写分离正确性用"注册中查询"交错剧本 10^4 次验证零半态；框架锁不在任何密码操作持锁范围内（锁范围审计断言）。

### UNX-F37615 · E 型注入：非法句柄/非法 flags/未知算法失败矩阵
**功能**：把 B01 全部入口的失败面做成注入矩阵：非法句柄（NULL/越界/已释放/跨类型）、非法 flags（未知位/冲突位组合）、未知算法（空串/超长串/含控制字符）逐格注入，验证每格都得到精确、单一、稳定的错误码，且失败后全局状态零污染（后续正常调用不受影响）。
**完成**：失败矩阵 ≥40 格逐格断言错误码与文档一致；每格失败后接一次正常调用验证零状态污染；控制字符/超长输入（4KB 算法名）不崩溃不越界；矩阵纳入回归总矩阵随波必跑。

### UNX-F37616 · 体验日志埋点：算法打开/属性查询/关闭全事件
**功能**：按体验完整性第十三章，B01 的每个用户可见动作都有埋点：算法打开（谁、哪个算法、耗时、成败）、属性查询（查什么、两段式走了几步）、关闭（是否泄漏前关闭）。埋点只记行为与结果，不记任何密钥材料与业务数据；写入异步批量，零阻塞交互。
**完成**：B01 全 API 埋点覆盖 100%（入口/出口/失败三态）；日志写入延迟 P99 < 100μs 不阻塞调用路径；从日志能回放"打开→查询→关闭"完整生命线；狂开狂关（rage 模式）被识别为挫败事件落账。

### UNX-F37617 · 异常显性化：提供者初始化隐蔽失败捕获
**功能**：初始化链上的隐蔽失败最容易静默：注册表构建半途失败、探针异常、早期日志未起时的错误。本条为 B01 建立启动链探针——初始化每步有检查点，失败即显性化（含发生了什么/为什么/下一步），并在日志系统就绪前用早期缓冲保底，起来后补写。
**完成**：注入初始化各步失败（×8 注入点）均得到三要素呈现而非静默继续；早期缓冲在日志系统就绪后 100% 补写成功；初始化失败后系统进入明确的拒绝服务态而非半可用态；启动链自检报告可一键导出。

### UNX-F37618 · NTSTATUS 错误码对照表 v1（与 D1 域同源联签）
**功能**：J3 全域错误码的"宪法"第一版：每个错误码与 Windows NTSTATUS 语义对照，值与含义双冻结。与 D1 域（内核基础域）同源联签——两边用同一张表，杜绝同码不同义。表是十年不变承诺的一部分：只增不改，废弃走 ADR。
**完成**：对照表 ≥40 格逐格与 Windows 文档对照零漂移；与 D1 域联签单双域签署；错误码稳定性冻结表版本化（v1）；全域 grep 验证无表外裸错误码。
