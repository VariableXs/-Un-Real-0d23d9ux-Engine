# UNX-J3 定制明细 · B02（F37621–F37640 · 句柄式状态机框架与克隆语义）

> AI-48 承办 · 波18 定制化扩写批册：每条「功能/完成」≥300 字。判据在册，红线声明见 batches/UNX-J3-B02.md。

### UNX-F37621 · 多段式状态机框架（分段喂入/收尾/复位三态）
**功能**：加密与哈希的通用骨架：数据可分多段喂入（Update），最后收尾（Finish）出结果，之后可复位（Reset）复用同一对象省去重建开销。框架把三态迁移做成显式状态机，非法迁移（未初始化就收尾、收尾后再喂入）精确拒止。所有算法族共用这一个骨架，写一次处处受益，杜绝每个算法各写一套分段逻辑产生行为漂移。
**完成**：三态迁移图与实现一致性终审通过；非法迁移 12 格矩阵全部精确拒止且错误码单一；分段喂入结果与一次性喂入 100% 等价（黄金 20 组双路对照）；Reset 后对象可复用且行为与新对象逐字节一致（10^3 次复位循环验证）。

### UNX-F37622 · DuplicateHash 克隆语义与状态独立性
**功能**：对齐 Windows DuplicateHash：把一个哈希状态对象原样克隆出一份独立副本——典型用途是"公共前缀只算一次，后续分叉各自续算"。克隆体与原体在克隆瞬间状态字节级一致，此后完全独立：一方喂入、收尾、复位都不影响另一方。克隆走深拷贝，不共享任何可变态（缓冲区、计数器）。
**完成**：克隆瞬间双体摘要中间态逐字节一致（内部快照断言）；克隆后双体各自独立演进 20 组剧本，交叉验证互不干扰；克隆不共享可变态（地址空间断言零重叠）；10^3 次克隆开关循环句柄账闭合零泄漏。

### UNX-F37623 · BCryptCreateHash 族与哈希对象生命周期
**功能**：哈希对象全生命周期管理：创建（绑定算法与可选密钥用于 HMAC）、使用（喂入/收尾）、关闭（资源回收+密钥材料即时清零）。生命周期账贯穿始终——每个对象从生到死都有账，退出时未关闭对象列入泄漏清单。关闭是唯一合法终点，杜绝"用完不管"。
**完成**：10^5 次创建使用关闭循环零泄漏（账面归零）；关闭时密钥材料清零时序断言（清零先于内存释放）；退出哨兵未关闭清单零项；已关闭对象再访问全部得到 INVALID_HANDLE 而非悬垂访问。

### UNX-F37624 · BCryptEncrypt 多段式状态（分块加密语义）
**功能**：加密的多段式语义：调用方可把明文分任意大小的段喂入，框架内部按块长缓冲对齐，分段边界对调用者透明（除 CBC/ECB 最后一块需收尾取填充外，中间任意切分结果一致）。缓冲策略内存有界——不管调用者切多碎，内部缓冲不超过一个块长加余量。
**完成**：同一明文按 1/3/7/64 字节四种切法加密结果完全一致（4 路对照黄金组）；内部缓冲上界断言（喂入 1MB 碎段内存增量 <1KB）；最后一块语义（带填充/无填充 flags）与 Windows 对照零漂移；段边界 fuzz ×10^4 零崩溃。

### UNX-F37625 · BCryptGenerateKeyPair/ImportKeyPair 地基
**功能**：非对称密钥的两条来路：本地生成（GenerateKeyPair，熵取自 CSPRNG）与外部导入（ImportKeyPair，解析标准编码格式）。本条打地基：统一密钥对象结构、参数域校验（模长/曲线名合法性）、导入解析骨架与错误面。具体算法的生成细节归各自批次，这里定的是全族共用的容器与规矩。
**完成**：容器结构断言（密钥对象字段与文档一致）；非法模长/曲线名拒止矩阵 12 格全过；导入畸形 blob（截断/翻转 magic）拒止不崩溃；两条来路产生的密钥对象在后续签名 API 中可互换使用（同构断言）。

### UNX-F37626 · 属性集 BCryptSetProperty/GetProperty 语义
**功能**：状态与算法对象的属性读写面：链模式、填充模式、认证 tag 长度等都经属性 API 设置。语义对齐 Windows：未知属性精确拒止；只读属性拒写；属性类型校验（给块长属性塞字符串拒止）；设置时机约束——状态机启动后关键属性冻结不可改。
**完成**：属性黄金表 30 格（读/写/拒读/拒写/类型错）全过；启动后改关键属性被拒且状态逐字节不变；属性值域校验（如 tag 长度只接受 12–16）断言；与 F37603 查询面共享同一属性表实现（单一事实源 grep 验证）。

### UNX-F37627 · 状态对象并发使用约束（单线程模型强制）
**功能**：与 Windows CNG 一致，单个状态对象不承诺并发安全——本条把这一约束做成强制防线而非注释：状态对象带属主线程标签，跨线程使用在调试构建下断言失败、在正式构建下返回明确错误。多线程的正确用法是每线程独立对象或经克隆分叉，文档与错误提示都说清楚。
**完成**：跨线程共用对象用例被稳定拦截（10^3 次零漏检）；同线程串行使用零误报；错误提示含"如何改对"（指引用克隆）；与 B23 并发批的分工边界写入冻结契约（本条管约束、B23 管共享面）。

### UNX-F37628 · 状态机框架性能基线（每状态操作 P95）
**功能**：框架本身要快到"感觉不到存在"：喂入、收尾、复位、克隆四个状态操作各有 P95 预算（喂入按每字节摊销、其余按每次计）。框架开销与算法本体开销分离计量——性能账能回答"这 1μs 里框架占了多少"，防止框架层吃掉算法层的优化收益。
**完成**：四操作 P95 实测入账且低于预算线（喂入摊销 <50ns/字节、收尾/复位/克隆各 <2μs）；框架开销占比断言 <10%；基线机器/指令集环境钉版入账；回归时基线随波复验防性能倒退。

### UNX-F37629 · E 型注入：状态机错序/半态/悬垂矩阵
**功能**：状态机的失败面注入总阵：错序（未初始化就收尾）、半态（喂一半就关闭）、悬垂（关闭后引用旧指针）、重复收尾、复位后再收尾等乱序组合 ×10^3 全部自动生成遍历，每格验证：不崩溃、错误码精确、状态对象最终可回收、全局账闭合。
**完成**：乱序组合矩阵 10^3 次零崩溃零挂起；每格错误码与语义书一致（对账脚本零漂移）；半态关闭后内存账归零（无半空状态残留）；矩阵收编进 B28 状态机死角批的回归面。

### UNX-F37630 · NCrypt 层地基：KSP 抽象与内存 KSP 骨架
**功能**：NCrypt（密钥存储层）与 BCrypt（算法层）分离的地基：定义 KSP（密钥存储提供者）抽象接口——存、取、删、枚举四件事；第一个实现是内存 KSP（密钥只在内存、进程死则密钥灭），为后续文件 KSP、DPAPI 包裹 KSP 预留插槽。接口设计按"十年不变"标准版本化。
**完成**：KSP 接口 v1 冻结（四操作 + 生命周期回调）；内存 KSP 骨架过冒烟（存取删枚举闭环）；接口插槽注册机制与 B01 提供者框架同构（复用断言）；第三方 KSP 扩展点登记（与 F37670 联动）。

### UNX-F37631 · NCrypt 句柄与 BCrypt 句柄类型隔离
**功能**：两层句柄长得像但绝不能混用：NCrypt 密钥句柄传给 BCrypt 加密 API 必须被拒，反之亦然。句柄表用类型标签强制隔离，错误提示明确告知"拿错了哪类句柄、该去哪个层"。隔离还覆盖派生类型（算法句柄 vs 哈希句柄 vs 密钥句柄三类全分开）。
**完成**：跨层/跨类句柄误用矩阵 12 格全部拒止且错误信息含正确指引；类型标签完整性断言（标签不可经任何公开 API 篡改）；误用注入 ×10^3 零漏检零误报；句柄类型对照表入语义书。

### UNX-F37632 · 密钥存储导出策略位与审计双闸
**功能**：密钥能否导出明文由策略位决定，且导出走"双闸"：策略位允许 + 审计记录落账，两闸齐过才放行。默认策略为不可导出；允许导出的密钥每次导出都有谁、何时、导出长度全记录。双闸设计让"静默掏走密钥"在结构上不可能。
**完成**：默认不可导出密钥的导出用例 100% 被拒；策略允许密钥导出成功且审计账完整（四要素：谁/何时/何钥/长度）；双闸缺一即拒的注入用例（有策略无审计、有审计无策略）全部拦截；审计账只记元数据不记密钥材料（内容红线断言）。

### UNX-F37633 · 密钥文件存储受 J2 DPAPI 类包裹预告位
**功能**：密钥落盘文件必须加密包裹，包裹原语由 J2 DPAPI 供（Schema 先行+fake）：本条先立预告位——定义包裹格式骨架（版本、包裹体、KDF 参数档位）与"未接 J2 前禁落盘"的闸：联签未完成时密钥文件功能显式禁用而非用弱加密顶替。
**完成**：包裹格式 v1 骨架冻结（字段与版本化规则）；未联签状态落盘用例被闸拦截并提示等待联签；fake 包裹后端在测试镜像中闭环（加密→读取→解密往返一致）；与 J2 联签消费接口冻结单在册（R-J3-001 兑现路径）。

### UNX-F37634 · 用户体验日志：状态机误用挫败指纹
**功能**：开发者也是用户。状态机误用（错序、半态、悬垂）自动识别为挫败指纹：同一调用方短时间内反复触发同一错误码、错误后立即重试同参数等模式被标记，聚合出"哪里最难用对"。指纹清单每波出改进建议——改 API 或改错误提示，让误用从源头变少。
**完成**：三类挫败指纹（rage 重试/连环错误/放弃模式）捕获断言；指纹清单前 10 出改进建议表落档；日志只记行为不记密钥（红线断言）；改进项闭环核——首波建议中的错误提示改写已回灌到错误面。

### UNX-F37635 · fuzz：状态操作序列随机注入
**功能**：用随机状态操作序列砸状态机：每轮随机生成 100–1000 步操作（创建/喂入/克隆/收尾/关闭/复位随机排列，参数随机取合法与非法值），验证零崩溃、零挂起、账面始终闭合。语料入库固化，最小复现自动提取，回归时快速集必跑。
**完成**：10^4 轮随机序列零崩溃零挂起；每轮后账面对账（对象数=存活数）断言；发现的最小复现 3 例入库并转 E 型修复；快速 fuzz 集（500 轮）纳入 CI <5min。

### UNX-F37636 · 状态机段锁步回归剧本库
**功能**：把状态机的行为契约写成可重放的锁步剧本：给定操作序列，锁定每步的输出摘要与错误码，回归时逐字对照——任何行为变化（哪怕是"变好"的重排）都必须经 ADR 审批后更新剧本。剧本库是防"顺手改行为"的护栏。
**完成**：剧本库 ≥30 套（覆盖三态全迁移+克隆+复位组合）；回归跑剧本逐字对照零漂移；演示性变更（改一处输出）被剧本红捕获验证；剧本版本化与 ADR 流程在册。
