# UNX-J3 定制明细 · B03（F37641–F37660 · 对称地基 AES 与 GCM 地基）

> AI-48 承办 · 波18 定制化扩写批册：每条「功能/完成」≥300 字。判据在册，红线声明见 batches/UNX-J3-B03.md。

### UNX-F37641 · AES 密钥扩展（128/192/256 三档）
**功能**：AES 的第一步：把 128/192/256 位用户密钥展开成轮密钥序列（10/12/14 轮）。实现严格对照 FIPS-197 原文（禁自造密码红线：轮常数、S 盒逐字节对照标准，不改动任何常量），三档共用同一扩展核，扩展结果有标准向量兜底。扩展过程在锁页内存进行，轮密钥用毕随密钥对象销毁即时清零。
**完成**：FIPS-197 附录密钥扩展向量三档全过；轮密钥缓冲位于锁页且销毁时 secure_zero 清零（内存断言）；三档扩展耗时 P95 入性能账；实现与规范逐节对照审阅留痕（文档号在册）。

### UNX-F37642 · AES 基块加密/解密（位切片路径·常数时间）
**功能**：AES 单块加解密的纯软件路径，选位切片（bitsliced）实现——全程无查表、无数据依赖分支，S 盒用布尔电路展开，从结构上免疫缓存时序侧信道。这是查表禁入红线的主执行件：哪怕性能略低也走常数时间路，安全优先于速度。
**完成**：FIPS-197 标准块向量加解密全过；实现中零查表（grep S 盒表结构零命中）；同输入不同内存地址布局执行时序方差 <2%（量测入常数时间账）；每块吞吐入基线账供双路径对比。

### UNX-F37643 · AES-NI 指令路径与运行时选择
**功能**：有 AES-NI 的机器走硬件指令路径（aesenc/aesdec 系列），吞吐可提升一个数量级。运行时按 F37612 探针结果选择路径：有能力用硬件、缺席自动落回位切片软件路，调用者无感。两条路径输出必须逐字节一致——硬件快不能以行为分叉为代价。
**完成**：双路径在 256 组随机块上输出逐字节一致；路径选择与探针结果一致（三档指令集环境实测）；AES-NI 路径吞吐 ≥软件路 8 倍入账；能力缺席环境自动落软件路无感（降级不告警不静默失败）。

### UNX-F37644 · 查表实现禁入红线（T 表反模式禁令）
**功能**：把"禁查表"写成可执行红线而非口头约定：全域禁用 AES T 表（Te0/Td0 类）与任何以密钥为索引的查表结构——这类实现会把密钥位映射到缓存行，是缓存时序攻击的经典入口。红线配套自动化检查：构建期 grep + 结构断言双闸，违者构建失败。
**完成**：红线检查脚本纳入构建闸（违例样本注入构建必失败）；J3 全域 grep T 表特征零命中；红线条文写入域内宪法与开发者文档（含为什么——缓存侧信原理一段话讲清）；每波回归复验红线持续零命中。

### UNX-F37645 · 缓存时序侧信度量基线（同输入不同地址方差账）
**功能**：常数时间不是声明出来的，是量出来的。本条立量测基线：同一密钥同一明文，散布到 256 个不同地址对齐与缓存状态下执行，采集周期计数器时序，算方差。这条账是 GCM<3%、padding<5% 等全部时序硬门的度量母版——量法统一，各处数字才可比。
**完成**：量测脚本固化（rdtsc 采集/预热协议/离群剔除规则钉版）；AES 位切片路径方差 <2% 基线入账；量测跨次运行可复现（同机 10 次方差波动 <20% 相对值）；基线方法学写入语义书供后续批复用。

### UNX-F37646 · GCM 模式地基：初始化与参数校验（任务书示例锚 F37652 前置）
**功能**：GCM 状态初始化地基：密钥、IV 长度、tag 长度、AAD 预算等参数在初始化时全部校验——tag 长度只收 12–16 字节五档、IV 长度记录在案（12B 走快路、非 12B 走 GHASH 路）、参数组合非法精确拒止。本条是示例锚 F37652 的前置件，把"参数入口干净"做扎实，深水段的复杂度才不失控。
**完成**：参数校验矩阵 25 格（IV 长 ×tag 长 ×密钥档）全过；非法组合错误码单一且含原因；初始化后参数冻结（改参数须重建对象）断言；校验逻辑与 Windows CNG 对照零漂移。

### UNX-F37647 · GHASH 域乘法地基（GF(2^128) 乘法）
**功能**：GCM 认证的核心积木：GF(2^128) 上的域乘法。实现走无查表的移位-规约路径（与红线一致），H 值（认证子密钥）由 AES 在初始化时生成并常驻锁页。域乘法有 NIST 规范向量兜底，是后续 B09 深水与 B16 PCLMULQDQ 硬件路的地基。
**完成**：NIST 规范域乘法向量全过；实现零查表断言；H 值锁页驻留与清零时序断言；单次域乘法耗时基线入账（为 B16 硬件路提速对比留基准）。

### UNX-F37648 · GCM 计数器模式加密面（CTR 块生成）
**功能**：GCM 的加密本体是 CTR：以 IV 派生起始计数器，逐块递增生成密钥流 XOR 明文。本条实现计数器生成与递增纪律——128 位计数器按规范只在低 32 位回卷、回卷即停（防静默计数重叠），J0 派生（12B IV 直拼 + 计数器 1；非 12B 走 GHASH 路径派生）两路都通。
**完成**：J0 派生两路黄金向量全过；计数器回卷停止用例验证（构造 2^32 边界）精确拒止；密钥流块与 NIST 向量逐字节一致；CTR 面与 B11 的独立 AES-CTR 共享块核（单一实现 grep 验证）。

### UNX-F37649 · AAD 关联数据参与认证语义
**功能**：AAD（附加认证数据）是不加密但必须认证的数据——如包头。语义：AAD 只进 GHASH 不进 CTR；AAD 必须在密文喂入之前全部给完（规范要求），顺序错了精确报错；AAD 长度参与最终 tag 计算的长度块编码，长短 AAD（含空 AAD）都正确。
**完成**：AAD 顺序敏感用例（先密文后 AAD）精确拒止；空 AAD/1 字节/跨块/超长 AAD 四档与 NIST 向量一致；AAD 与密文边界在内部记账分离（缓冲不混断言）；AAD 只认证不加密（密文流中零 AAD 痕迹）断言。

### UNX-F37650 · GCM tag 生成与认证路径
**功能**：加密收尾时生成认证 tag：GHASH 累加 AAD、密文与长度块，再与 E(K,J0) 异或得出 tag。tag 按调用者要求的长度（12–16 五档）截断输出——截断规则严格按 NIST（取高位），tag 是十六字节还是十二字节都有明确账目。tag 生成后加密状态终结，复用须复位。
**完成**：五档 tag 长度 ×20 组向量全过；tag 取高位截断语义断言（与全量 tag 前 N 字节一致）；收尾后状态终结语义（再喂入拒止）验证；tag 生成耗时摊销入 GCM 性能账。

### UNX-F37651 · GCM 解密认证与明文释放纪律（先验签后释放）
**功能**：解密方向的铁律：先验 tag、后给明文。tag 不对时一律返回认证失败、不释放任何明文字节——哪怕密文已经解完也锁在内部，验证通过才整体交付。这条纪律封死"明文已到手、错误码随便看"的侧信道，也防调用方拿未认证明文当真。
**完成**：tag 篡改 1bit 用例返回认证失败且明文缓冲区毒化检测零写入（明文确实没出来）；认证成功后明文与 NIST 向量一致；部分块解密中间态不可经任何 API 探及（探针断言）；错误路径内部明文缓冲即时清零断言。

### UNX-F37652 · AES-GCM 与 nonce 单调账（常数时间实现·任务书示例锚）
**功能**：任务书五示例锚之一（720 行保真）。把 GCM 从"能跑"提到"工业级"：nonce 单调账——同一密钥下每个 IV 都记账，重放检测、2^32 计数警戒线、跨重启持久化接口预留。实现整体走常数时间路径（GHASH 无查表 + tag 比较常数时间），缓存时序方差硬门 <3%。
**完成**：nonce 单调账 10^5 次加密零重复 IV（账面唯一性断言）；重放 IV 用例 100% 被拒并落告警；方差量测 <3% 硬门绿；CAVP GCM 向量首批 64 例全过；720 行行数预算在批册对账中兑现登记。

### UNX-F37653 · 随机 nonce 12 字节 API 内部生成（调用者禁传 nonce）
**功能**：把"GCM 最常见的用错方式"从 API 面上消灭：加密方向的 nonce 由 API 内部用 CSPRNG 生成 12 字节并随密文返回给调用方存随行，调用者传入 nonce 的路径在加密侧直接不存在——想传都传不进来。解密侧才收 nonce（验证用）。这是"替用户把每个操作想到"的设计纪律。
**完成**：加密 API 签名中无 nonce 入参（编译期结构断言）；内部 nonce 经 CSPRNG 且入单调账；返回的 nonce 与密文绑定随行（往返用例）；与 B09 单调账并发一致性批的接口分工冻结在册。

### UNX-F37654 · 同 key 加密计数账与 2^32 警戒线
**功能**：NIST 硬约束：同一密钥在 GCM 下加密次数逼近 2^32 时认证风险急剧上升。本条实现同 key 加密计数账：每次加密 +1，达到警戒线（2^32 - 2^20）后拒绝新加密并要求换钥——拒绝是唯一正确行为，绝不为"再凑合一次"放行。
**完成**：计数账并发递增零丢失更新（10^4 并发断言）；构造逼近警戒线用例（计数账可注入）验证拒止与错误三要素；警戒线阈值常量与 NIST 规范对照留痕；换钥指引写入错误提示与文档。

### UNX-F37655 · GCM 并发加密线程安全
**功能**：与状态对象单线程模型不同，本条提供并发友好的加密入口：同一密钥下多线程各自拿独立会话并发加密，共享的只有密钥与单调账——账的并发一致性由本条担保（原子递增 + 无锁读计数）。性能目标是并发加密近线性扩展。
**完成**：8 线程 ×10^4 次并发加密零 IV 冲突（单调账唯一性断言）；并发结果与串行结果逐字节等价（抽样 100 组对照）；TSan 零报告；并发扩展比 ≥6/8 线程入性能账。

### UNX-F37656 · E 型注入：GCM 参数域 fuzz 与畸形输入
**功能**：GCM 的失败面 fuzz 总阵：随机 tag（错位/全零/截断）、畸形密文（截断/翻转/拼接）、非法 AAD 顺序、IV 边界（空/超长）×10^4 轮注入，验证零崩溃、错误码稳定、认证失败路径不泄漏任何信息差异（错误响应时序恒定）。
**完成**：fuzz 10^4 轮零崩溃零挂起；错误码稳定表对账零漂移；认证失败与参数错误的响应时序方差 <5%（不因错误类型泄密）；语料与最小复现入库固化。

### UNX-F37657 · GCM 性能基线（吞吐与 P99 延迟）
**功能**：GCM 性能双指标：大消息吞吐（AES-NI 路径目标 ≥openssl 同机基线 ×0.8，登记真机判据随闸门补测）与小消息 P99 延迟（64B 消息端到端 ≤50μs 预告锚）。性能账区分软件/硬件路径、单线程/并发，每个数字带环境钉版，不给"感觉很快"留位置。
**完成**：吞吐与 P99 实测入账（软件+硬件双路）；×0.8 对照值登记（真机补测判据 R-J3-004 挂账）；小消息 P99 预告锚落档；性能不达标项（如有）带优化计划零挂起。
