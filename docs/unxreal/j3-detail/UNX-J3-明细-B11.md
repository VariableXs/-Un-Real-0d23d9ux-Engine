### UNX-F37801 · AES-CTR 流式模式（并行可·计数器管理）
**功能**：AES-CTR：把块密码变流密码——计数器块加密出的密钥流与明文 XOR。本条实现流式 CTR：计数器状态管理（初始值/递增/回卷拒止）、任意段长喂入（字节级 XOR，无填充）、加密与解密同一核（XOR 对称）。计数器语义与 B03 GCM 的 CTR 核共享（单一实现），但 GCM 绑 J0 派生而独立 CTR 用调用方 IV+计数器拆分。
**完成**：SP800-38A CTR 官方向量全过；计数器回卷精确拒止（构造边界）；流式分段与一次性恒等（十种切分）；与 GCM CTR 核共享断言（grep 单一实现）。

### UNX-F37802 · CTR 并行段加密（无链依赖·并行收益账）
**功能**：CTR 的结构性优势是无链依赖——每块密钥流只依赖计数器，可并行。本条提供并行加密面：大消息按块区间切给多线程（计数器区间互不重叠），并行结果与串行恒等。收益账量化：8 线程加速比、并行调度开销占比，给"该不该并行"以数据。
**完成**：8 线程并行结果与串行 100 组逐字节一致；加速比 ≥6/8 入账；计数器区间不重叠的结构断言（区间分配器审计）；并行调度开销 <10% 计量入账。

### UNX-F37803 · CTR nonce/counter 拆分语义与重放防线
**功能**：CTR 的 IV 需拆成 nonce（会话内固定）+ counter（递增）两域，拆分点调用方声明（如 96/32、64/64）。语义：全零 counter 起步为默认、counter 域回卷即停；同 nonce 跨消息重用是灾难（密钥流重用），防线与 GCM 同思路——同 key 同 nonce 入账检测，重放告警。
**完成**：三种拆分点黄金用例全过；拆分点声明后冻结（中途改拆精确拒止）；同 key+nonce 重用检测告警断言（账目注入）；回卷拒止与指引文案核。

### UNX-F37804 · AES-CBC 加密路径（IV 语义与 PKCS#7 填充）
**功能**：CBC 加密：每块先与前块密文（首块与 IV）XOR 再加密，链式依赖。本条实现加密路径：IV 语义（必须随机、入账随行、禁全零默认——全零 IV 是历史漏洞常客）、PKCS#7 填充（差几补几，整块差补整块）、填充在收尾自动完成。IV 由 API 内部 CSPRNG 生成随密文返回（与 GCM 同纪律）。
**完成**：SP800-38A CBC 向量全过；IV 随机性断言（10^3 次加密 IV 唯一）与全零 IV 拒止；PKCS#7 边界（恰好整块）填充用例；加密分段与一次性恒等。

### UNX-F37805 · CBC 解密与 PKCS#7 验证（常数时间·X3 母版）
**功能**：CBC 解密的深水：PKCS#7 填充验证必须常数时间——填充验证与首块校验（MAC）都不给"填充错在第几字节"的时序或错误码差异。实现按 X3 母版：无论填充对错都完成等量工作，统一错误码，拒绝路径方差 <5% 硬门。这是本批最硬的一条。
**完成**：填充验证常数时间量测方差 <5% 绿（母版方法学）；全部 256 种非法填充单字节注入错误响应恒定（错误码单一+时序均匀）；合法填充全档验证；解密向量全过。

### UNX-F37806 · padding oracle 拒止终账（方差 <5% 硬门）
**功能**：padding oracle 攻击的终账条目：攻击者靠"填充错 vs MAC 错"的响应差异逐字节解密。本条把拒止做成终账：错误分类完全合并（填充错与认证错同码同时序）、量测账固化、攻击剧本复演（模拟 oracle 逐字节试探）验证零信息差。终账是"这条路已封死"的存证。
**完成**：oracle 剧本复演 16 轮（标准攻击流程）零信息差（试探成功率=猜测率）；错误响应全维度恒定断言（码/时序/长度）；终账入常数时间总账供 B15/B39 汇总；拒绝路径文档含攻击原理通俗版。

### UNX-F37807 · CBC 级联与链式依赖（前块密文参与）
**功能**：CBC 链式语义的完整性验证：密文任一块被篡改，只影响该块明文与下一块明文（链式扩散的规范行为）——这个"有限扩散"要写成文档（CBC 不防篡改，认证请用 GCM/HMAC），并做扩散矩阵验证：逐块翻转注入，受影响块范围与规范推导一致。
**完成**：逐块翻转注入矩阵（16 块消息逐块）受影响范围断言与规范一致；"CBC 无认证"的文档警示与 API 命名引导（解密成功≠可信）在位；链式依赖向量兜底；误导使用指纹埋点（CBC 后直接信任明文的调用模式提示）。

### UNX-F37808 · 对称族统一错误码面（三码分离复验）
**功能**：对称三模式（GCM/CTR/CBC）统一错误码面：参数错、状态错、认证错三码正交，模式间同码同义——调用方从一个模式换另一个不用重学错误语义。复验 GCM 三码分离（F37766）在新模式下同样成立，统一面入错误码宪法 v2 附录。
**完成**：三模式错误码对照表 15 格零漂移；跨模式同注入同码断言；统一面入宪法 v2 附录冻结；模式迁移剧本（同业务 GCM↔CBC 切换）错误语义一致验证。

### UNX-F37810 · 对称族流式 API 统一面（三模式同构）
**功能**：三模式共用一套流式 API 形状：init（参数域各异）→update（分段喂入语义相同）→finish（GCM 出 tag、CBC 出填充、CTR 直收）——同构设计让上层加密代码模式无关，切换模式改一个参数。同构面经 B02 框架实现，模式差异全部收进 finish 语义与属性面。
**完成**：三模式同构 API 签名对照断言（差异点清单 ≤2 处且全在 finish）；上层模式无关切换剧本（同业务代码换模式）跑通；同构面文档与交互词典一致；零模式特判散落断言（grep 无 if(mode==CBC) 类散布）。
