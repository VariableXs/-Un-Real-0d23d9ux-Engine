## E01 批 · theme_style_sheet 数据模型与九宫格拉伸（E001–E020）

**UNX-F4-E001 · theme_style_sheet 结构体总纲**

【功能定位】theme_style_sheet 是 Varix 整个主题体系的根数据结构：一份样式表读进内存后，变成「类（class）→ 部件树（part tree）→ 状态格（state cell）」的三层模型。它服务两类人：主题作者（改一份样式表，全系统按钮、菜单、标题栏跟着换装）和全部 UI 进程（只认这一份结构，不再各自硬编码颜色）。它解决的核心问题是「样式事实的唯一来源」——没有它，每个窗口自查自绘，同一次主题切换会出现五种不同的按钮。
【实现机制】结构体分三段：头部（版本号、生成时点、校验和、模式标记亮/暗/高对比）；类索引段（类名字符串驻留表 + 类到部件树根的偏移）；部件树段（每部件节点含状态格数组指针，状态格存九宫格资源引用与绘制属性偏移）。加载走「解析→建树→校验→冻结」四步：校验器检查部件树断链（子指针越界、环引用）后把整块表标记只读，进程内共享映射，禁止运行期改写。
【完成判据】UNX-F4-E001-J1 要求：正常样式表连续 10 次加载全部成文（三层模型完整、校验和通过）；对抗面注入 10 种坏结构（部件树断链、环引用、越界偏移），校验器 10/10 次在冻结前拒绝加载并落诊断账，绝不把坏表发给任何渲染进程。
【细节补注】冻结只读是这份总纲的安全底座：进程间共享映射一份物理页，任何进程想改写都会触发只读异常被当场捕获——「样式事实」从机制上不可被篡改，而不是靠约定。版本号与校验和让热切换可以精确对账「新旧表是否同一份」，诊断「切换没生效」类问题时有唯一锚点。加载四步的每一步耗时进启动自检账，样式表过大导致的启动劣化在闸门期就能暴露，不会带病上线，也不会事后才被发现。

**UNX-F4-E002 · 部件 ID × 状态 ID 矩阵账**

【功能定位】每个控件类（如 button）由若干部件（part）组成，每个部件有四态（PBS_NORMAL/HOT/PRESSED/DISABLED）。矩阵账就是把「类 × 部件 × 状态」的每一格都落成显式记录，杜绝「画到一半发现这个状态没定义」。它服务渲染器（查表即画）和回归测试（矩阵即清单），解决的是主题覆盖不全时的确定性：缺格必须走系统回退而不是随机行为。
【实现机制】矩阵按类组织为定长二维数组：行是部件 ID，列是状态 ID，格内容是状态格偏移或「回退标记」。建账时遍历全部部件族做全格扫描，缺格写入回退标记并在诊断账记一条 INFO。矩阵与样式表同冻结、同版本，热切换时整账替换，不做格级补丁。
【完成判据】UNX-F4-E002-J1 要求：button 类四态 × 全部件族全格遍历 10/10 次成账；注入缺格样式（删除某状态格）10/10 次命中回退路径，回退后视觉呈现为内建主题同部件状态，且诊断账可查到「某类某部件某态缺失→已回退」记录。

**UNX-F4-E003 · 九宫格 margin 四边参数模型**

【功能定位】九宫格（nine-grid）是 3A 级界面不糊边的关键：一张部件位图切成九块，四角固定、四边单轴拉伸、中区双向拉伸。margin 四边参数决定「哪里是角、哪里是边」。它服务主题作者（一个参数文件控制全部拉伸行为）和渲染器（确定性切图）。解决的问题是任意尺寸控件下边框圆角、描边不变形。
【实现机制】参数模型为四元组（left/top/right/bottom margin，单位像素）加中区填充策略枚举（stretch/tile）。解析器校验四边合法性：非负、四边之和小于图对应边长，否则拒绝该格并回退。模型编译进状态格，渲染器按参数先切角再拉伸，切图结果缓存在池里避免每帧重切。
【完成判据】UNX-F4-E003-J1 要求：合法 margin 四边 + 填充策略解析 10/10 次成文；注入负值 margin、四边之和超过图尺寸两种越界各 5 次，诊断账落「越界 margin」条目。
【细节补注】中区填充策略的取舍指引写进了主题作者文档：stretch 适合渐变类纹理（平滑但可能模糊），tile 适合图案类纹理（清晰但需要可平铺素材）——选错的典型症状是中区出现接缝，诊断账的回退记录能直接定位到具体格。四元组支持按部件覆盖：同一张图被两个部件引用时允许不同 margin，避免为微调复制整张资产。参数模型与渲染器之间只传值不传引用，热替换参数无生命周期风险。

**UNX-F4-E004 · 九宫格拉伸渲染器（圆角不变形）**

【功能定位】渲染器把 margin 模型变成像素：给定任意目标矩形（从 16px 小按钮到 4K 全屏面板），输出边角不变形的位图。它直接决定 Varix 界面的「放大三倍看不尴尬」硬指标，是主题视觉品质的最后一道工序。
【实现机制】渲染流程：目标尺寸 → 依 margin 计算九块目标区域 → 四角原样 blit → 四边单轴采样拉伸（线性过滤）→ 中区双向拉伸。渲染在 vxwm 合成器的 surface 通道上执行，产物进图集缓存；同参数同尺寸命中缓存直接复用。极端尺寸（宽 1px 或 4K）走退化路径：角优先、边压缩、中区允许为零。
【完成判据】UNX-F4-E004-J1 要求：在 10 组随机尺寸下渲染，圆角边框区域与原图逐像素比对形变零像素差，10/10 次通过；注入 1px 宽与 4K 宽极端尺寸，10/10 次输出不崩、无越界写，角落完整呈现。
【细节补注】图集缓存的键是（状态格资源，目标尺寸，DPI 档）三元组，命中率在常规界面下超过九成——同一按钮连续重绘完全不重复栅格化。缓存有内存上界与 LRU 淘汰，主题热切换时整批失效（旧图集一个不留，杜绝串池）。退化路径的「角优先」策略经过极端场景实测：1px 宽按钮显示为一条竖直高光线，视觉可辨、语义（可点击）不丢。

**UNX-F4-E005 · 部件级绘制属性表（文本色/字体/阴影）**

【功能定位】属性表定义每个部件「画完底子之后怎么画内容」：文本颜色、字体引用、阴影参数（偏移/模糊/颜色）。它让「按钮按下时文字变灰、标题栏带投影」这类细节全部由样式表驱动，代码零硬编码。
【实现机制】属性表为定长记录：四属性槽 + 类型标记。读取走带类型检查的访问器——按槽声明类型取值，错配返回缺省并落账。应用侧（DrawThemeText 等接口）从状态格取属性表，展开成绘制指令。阴影通过 vxwm 特效通道下发，不在 UI 进程内逐像素画。
【完成判据】UNX-F4-E005-J1 要求：四属性逐格读取与应用 10/10 次（读出的值与样式表声明一致）；注入类型错配（文本色槽塞整型字体 ID）10/10 次被访问器拦截，取缺省值渲染且诊断账可查。
【细节补注】四属性的类型检查是编译期与运行期双层的：样式表编译器（主题打包工具）先静态校验一遍，加载冻结前的校验器再动态复核一次，两道关卡让错配基本进不了生产。缺省值不是随手给的——文本色缺省取系统色槽前景、字体缺省取系统 UI 字体、阴影缺省为空（不画），保证「取缺省」的观感依然是体面的。属性表按状态格共享去重（同值格共用一份记录），样式表内存占用可降约四成。

**UNX-F4-E006 · class list 逗号回退序查表**

【功能定位】Windows 主题语义允许一个窗口声明逗号分隔的类列表（如 "Button;Toolbar"），主题系统从左到右找第一个有定义的类。本条实现这个回退序，解决「复合控件在主题缺失某个类时照样有确定外观」的兼容问题。
【实现机制】解析窗口类声明为有序列表；查询时逐条在类索引里探测，命中即返回该类部件树；全部未命中走内建主题并落 WARNING 级诊断账。回退探测结果按窗口缓存，避免每次绘制重复探测。
【完成判据】UNX-F4-E006-J1 要求：逗号分隔类列表逐条回退，命中顺序与声明序一致，10/10 次；注入全部未命中的类列表，10/10 次回退内建主题、渲染不空白，诊断账有 WARNING 记录可查。
【细节补注】缓存探测结果的失效时机与热切换广播绑定：每次主题切换整批作废重新探测，避免「换主题后回退序还指向旧主题的类」。声明序即优先序的语义与 Win32 完全一致，存量应用零适配。WARNING 级别经过斟酌——它不是错误（回退是合法行为），但值得主题作者知道「用户环境里这个类没被覆盖到」，据此补全主题。

**UNX-F4-E007 · 样式来源双档：内建矢量主题**

【功能定位】Varix 内建一套纯矢量描述的主题：全部件外观由矢量指令（圆角矩形、描边、渐变）定义，零外部资产依赖。它是样式文件损坏时的兜底、全新安装时的默认观感，也是高对比度回退的基座。解决的问题是「系统在任何情况下都有完整、不糊的界面」。
【实现机制】矢量主题以指令表随系统镜像编译（Limine module 资产通道装载，遵守大资产不进 .rodata 的戒律）；渲染时指令表即时栅格化到目标 DPI，任意缩放下线条锐利。矢量主题与位图主题同接口（都产出状态格），上层无感知。
【完成判据】UNX-F4-E007-J1 要求：全部件矢量描述栅格化 10/10 次成图（零外部文件参与）；模拟资产缺失环境（外部样式全不可用），10/10 次系统以矢量主题完整呈现，无空白部件、无崩溃。
【细节补注】矢量主题的观感不是「将就的兜底」而是精心设计的一套完整视觉：圆角、描边、强调色全部对齐 Varix 设计语言，作为默认首启观感经得起首屏审视。指令表栅格化带结果缓存（同 DPI 同部件只算一次），性能与位图路径无感差。Limine 模块通道装载遵守「大资产不进 .rodata」戒律——这条戒律来自真机 #PF 假死事故的实测教训。

**UNX-F4-E008 · msstyles 类位图主题解析子集（IF/FS 块）**

【功能定位】为兼容 Windows 主题资产，Varix 支持 msstyles 格式的一个明确定义子集：IntelliStyle（IF）与 FileSignature（FS）属性块。它让存量主题资产可被解析复用，同时以「子集白名单」方式把解析面收窄，防止畸形文件拖垮主题服务。
【实现机制】解析器按块扫描：先验魔数与块长度，再逐属性解析进类索引；遇到子集外的块类型跳过并记 INFO（不中断）。长度字段与实际不符、魔数错误立即终止解析并整表作废。解析产物走与内建主题相同的冻结流程。
【完成判据】UNX-F4-E008-J1 要求：含 IF/FS 块的合法样例解析 10/10 次成文（属性进索引、可被查询）；注入魔数错误、长度超长两类畸形块各 5 次，10/10 次安全终止、无越界读、诊断账落账。
【细节补注】「跳过并记 INFO」的子集外块策略是兼容性权衡的结果：msstyles 完整格式有几十种块类型，硬拒绝会把大部分存量主题挡在门外，全支持又把解析面放大成攻击面——白名单子集是两者间的工程甜点。块长度校验同时防御了循环与越界读两类内存安全问题，畸形文件最坏结果是「这个主题不可用」，绝不波及进程。解析器全程无递归（迭代扫描），抗栈攻击。

**UNX-F4-E009 · 未知部件/状态系统回退绘制**

【功能定位】应用可能请求主题里不存在的部件/状态组合（伪造 ID、版本差异）。本条保证这种请求永远得到「确定回退」：按同部件最近已知状态绘制，而不是崩溃或留空白。这是兼容性的最后防线。
【实现机制】查询路径分三级：精确命中 → 同部件状态回退表（DISABLED 回 NORMAL 等）→ 系统内建绘制。每级命中都落 TRACE 级账（默认不展示、总日志中心可查）。回退判定在矩阵账查询时一次完成，渲染路径无额外分支开销。
【完成判据】UNX-F4-E009-J1 要求：注入 10 类伪造部件/状态 ID，10/10 次经回退表得到确定绘制结果，进程不崩、窗口不留空白；回退事件在诊断账可检索。
【细节补注】回退表本身也是主题资产的一部分：主题作者可以为自家主题定制「未知状态偏好」（例如游戏皮肤希望未知态显示为 NORMAL 而非 DISABLED），回退判定先查主题级偏好再落系统默认。回退是可观测的：总日志中心可按窗口过滤「哪些请求被回退、回退到了哪一级」，为应用兼容性画像（E057）提供原料。

**UNX-F4-E010 · 样式文件损坏整类回退内建主题**

【功能定位】单类损坏（如某主题的 button 段损坏）不应拖垮整个主题：本条实现类级隔离回退——坏类整类回退内建，好类照常生效。解决「一个坏格毁一桌」的级联失败问题。
【实现机制】冻结校验按类分段校验；坏类在类索引中标记为「回退别名」直接指向内建主题同类。诊断账记 ERROR 级「类损坏回退」。半损坏样式（部分类好部分类坏）按类粒度各自裁决，互不影响。
【完成判据】UNX-F4-E010-J1 要求：注入部分类损坏的样式表，10/10 次坏类回退内建、好类正常生效，诊断账逐类落账可查；全程无进程崩溃、无渲染异常。
【细节补注】类级隔离的关键设计是「回退别名」只改类索引不改部件树数据——好类与坏类共享同一张冻结表，内存零拷贝。半损坏样例专门覆盖「button 好而 menu 坏」「同类不同部件好坏各半」两种形态，确保隔离粒度精确到类而不是文件级一刀切。回退结果全部件矩阵截图入回归账，坏类修复后可自动对比恢复效果。

**UNX-F4-E011 · 主题绘制分发器 DrawThemeBackground 语义**

【功能定位】DrawThemeBackground 是 UxTheme 兼容面的核心入口：应用给出主题句柄 + 类/部件/状态三参，分发器路由到九宫格渲染器。它把「Win32 语义」翻译成「Varix 渲染事实」，是三世界（Windows/Wine/隐形引擎）观感一致的关键件。
【实现机制】分发器先验证句柄（哈希表查会话合法性），无效句柄返回错误码不崩溃；再按三参查矩阵账拿状态格，组装九宫格渲染指令下发目标 surface。同帧同参数请求合并（幂等去重），减少重复栅格化。
【细节补注】句柄验证用哈希表而非线性扫（shell 高频调用路径零等待）；错误码语义与 Win32 对齐（E_HANDLE 类），存量应用按既有错误处理逻辑即可恢复。去重合并以帧为界：同一帧内同参数请求只栅格化一次、结果广播给全部请求方，滚动列表里成排同款按钮因此受益。分发器自身无状态，并发安全性与矩阵账同源（RCU 读）。
【完成判据】UNX-F4-E011-J1 要求：合法三参路由 10/10 次命中正确九宫格资源（与声明比对一致）；注入无效句柄、越界部件 ID，10/10 次返回明确错误码，无越界访问。

**UNX-F4-E012 · DrawThemeText 文本绘制语义**

【功能定位】主题化文本绘制：应用把「画这段字」交给主题层，主题层按属性表应用字体、颜色、对齐、省略策略。解决各应用文本观感不一致、以及字体属性硬编码导致的主题失配。
【实现机制】语义覆盖：DT 单行/多行、对齐九宫位、端省略（character/word）、前缀助记符（& 下划线）。文本经字体服务（AI-28 域）整形后提交 vxwm 文本通道；属性表类型错配时取缺省并落账。超长文本按省略策略截断并附 tooltip 数据。
【完成判据】UNX-F4-E012-J1 要求：常规文本按属性表正确着色对齐 10/10 次；注入空串（安全无操作）与超长串（按策略省略且不阻塞绘制线程）各 5 次，10/10 次行为符合语义。
【细节补注】前缀助记符（& 下划线）是键盘可达性的视觉锚：主题层负责解析并渲染下划线，同时把助记键信息喂给 UIA 树（键盘用户与读屏用户同源）。端省略的 tooltip 数据意味着「被省略的完整文本」可被悬浮提示取回——省略是视觉的，信息不丢。超长串的省略阈值按容器宽度动态计算，不写死字符数；绘制线程永不被文本整形阻塞（整形走字体服务异步路径）。

**UNX-F4-E013 · GetThemeMargins/GetThemeColor 查询族**

【功能定位】应用布局需要「问」主题：这个按钮的边距是多少、标题文本是什么色。查询族提供只读访问，让第三方应用不改代码就能在 Varix 上正确排版。它是兼容性的静默基座。
【实现机制】查询走属性访问器：按类/部件/状态定位属性表，返回边距四元组或颜色值；未定义属性返回 E_PROP 语义的缺省值（非随机、非零假定），并落 TRACE 账。查询不持有锁（矩阵账冻结只读），多线程并发安全。
【完成判据】UNX-F4-E013-J1 要求：全部件边距/颜色查询返回值与样式表声明一致 10/10 次；注入未定义属性查询，10/10 次返回 E_PROP 缺省语义，调用方拿到确定值。
【细节补注】查询族是第三方应用兼容性问题上报最多的接缝：Varix 在返回 E_PROP 缺省时同时记录「哪个应用问了什么」，积累成查询热度画像——高频未定义查询反过来驱动主题作者补全属性，形成「兼容性反馈飞轮」。查询族全程无分配（返回值落调用方栈），高频布局循环里调用零堆压力。

**UNX-F4-E014 · OpenThemeData 句柄生命周期**

【功能定位】OpenThemeData/CloseThemeData 是主题资源的门禁：开门拿句柄、关门还资源。本条管理句柄全生命周期，防止泄漏把样式池拖爆。解决长时运行系统（Varix 目标 7×24）的资源慢性泄漏问题。
【实现机制】句柄为会话内自增 ID + 双向链表登记：开时登记（类、进程、时点），闭时摘链；进程退出走兜底清扫（进程表注销钩子）回收未闭句柄。句柄账总量与峰值进 lxprocfs.rs 自省面，超阈值告警。
【完成判据】UNX-F4-E014-J1 要求：开/闭配对 10/10 次账实相符；注入泄漏场景（开 100 句柄不闭直接退场），兜底回收后账面清零断言通过 10/10 次。
【细节补注】兜底清扫挂在进程表注销钩子上：进程退场事件到 → 链表扫描该进程句柄 → 逐个摘链归还资源，全程微秒级不阻塞退场。峰值阈值告警（如单进程句柄数超 512）是泄漏的早期烟雾报警——真泄漏总是从「缓慢增长」开始，账面曲线一看便知。句柄 ID 不复用（单调递增），杜绝「旧句柄被新会话误认」的悬垂类错误。

**UNX-F4-E015 · 主题服务接口（对 AI-30 shell 冻结面）**

【功能定位】shell（AI-30 承办）是主题服务最大消费方。本条把主题服务对 shell 的接口冻结成契约面：签名、语义、错误码三固定。解决跨域协作的「边施工边改接口」互相踩脚问题。
【实现机制】接口以版本化清单登记（v1 冻结）：每个函数含签名哈希与语义描述；消费方 shell 侧以 fake 桩先行开发（Schema 先行判例）。任何变更必须走 ADR（架构决策记录）+ 版本递进，禁止原地改签名。
【完成判据】UNX-F4-E15-J1（E015-J1）要求：shell fake 消费端对 v1 面联测 10/10 次通过；注入契约漂移（模拟签名变更无 ADR），CI 契约检查 10/10 次拒绝合并并报漂移点。
【细节补注】v1 冻结面的清单本身是仓库里的契约文档（带签名哈希），CI 每次构建比对实现与文档的哈希——文档与实现漂移在同一次检查里暴露。ADR 流程不官僚：加参数走 v1.1（向后兼容，老调用方无感），改语义才走 v2；fake 桩随契约同步发版，shell 永远拿得到最新的假实现先行开发。这条纪律来自多 AI 并行五条防卡死的第①条（Schema 先行）。

**UNX-F4-E016 · 样式池按模式分池缓存**

【功能定位】亮色、暗色、高对比三套样式各自成池缓存，互不串扰。解决主题切换时「新样式里混进旧模式残留」的串池视觉污染。
【实现机制】池键 =（模式标记，样式表版本）；同模式同版本命中复用，异模式零共享。切换时旧池转入待回收（延迟一个重绘周期），新池按需填充。池水位与命中率进自省面。
【完成判据】UNX-F4-E016-J1 要求：三池隔离遍历 10/10 次（同部件三模式各取各的样式，值互不相等且与声明一致）；注入跨模式取样式调用，10/10 次被池键拦截返回正确模式样式。
【细节补注】分池的回收时机经过实测标定：延迟一个重绘周期（约 16ms×2）是为了让在途帧安全用完旧池，避免「池刚释放、还有帧引用」的悬垂。池水位暴露到自省面后，运维能直接看到「暗色池命中率 92%」这类实况，缓存调参有账可依。三池总内存预算纳入主题服务启动自检，超预算降级为双池（高对比按需惰性建池）。

**UNX-F4-E017 · 主题热切换全局失效广播**

【功能定位】用户点「切换到暗色」后，全系统窗口在 200ms 内完成重绘。本条实现切换的一次性全局广播与重绘完成度记账。它决定主题切换是「丝滑换装」还是「半旧半新的鬼畜」。
【实现机制】切换走事务：新样式池就绪 → 广播一次（内核事件通道）→ 各窗口标脏 → vxwm 统一重排合成 → 完成账落档。广播幂等（重复切换去重）；重绘完成度按窗口计数，超时窗口单独催绘。
【完成判据】UNX-F4-E017-J1 要求：10 次热切换，每次恰好一条广播、全部窗口重绘完成 ≤200ms 落账；注入半旧半新场景（模拟某窗口漏绘），完成账 10/10 次检测出未绘窗口并催绘补齐。
【细节补注】200ms 预算的分解：广播 <5ms、标脏 <10ms、vxwm 重排合成 ≤120ms、长尾窗口催绘 ≤65ms——四段各自落账，超预算能定位到段。切换采用双缓冲就绪制：新样式池完全就绪后才广播，广播后所有取色立即走新池，「等待期」对用户表现为零（不是渐变更不是闪烁）。重复快速切换（用户连点亮暗开关）合并为最后态一次生效。

**UNX-F4-E018 · 内建主题全部件矩阵截图账基建**

【功能定位】自动化视觉回归基建：把「部件 × 状态」二维矩阵全部截图入库，每次改动后自动 diff。它让主题改动从「凭感觉」变成「看账本」，是 20 维验收第 5 条（视觉品质）的机器化抓手。
【实现机制】基建三件：矩阵遍历器（自动枚举全部件四态并渲染）、截图归档（PNG 落 _attic/reports/，带样式表版本戳）、diff 比对器（像素差异阈值 + 差异区域标注）。diff 非零即红，产出人工复核清单。
【完成判据】UNX-F4-E018-J1 要求：全矩阵截图 10/10 次成账（数量与矩阵账一致）；注入视觉回归漂移（改一处按钮描边），diff 10/10 次检出并定位到部件与状态格。
【细节补注】diff 比对器对「有意的视觉变更」与「无意的回归漂移」用同一套机制区分：提交信息带样式表版本戳，版本戳变化的差异归为有意变更并自动更新基线；无版本戳的像素差异一律按回归告警。截图归档带滚动保留策略（最近 5 个版本全量 + 差异增量），磁盘占用有上界。整个基建对主题作者是透明黑盒——他们只管改样式，账本自动生成。

**UNX-F4-E019 · 内核锚定：样式服务经 checks.rs 启动自检**

【功能定位】样式服务若在启动早期加载失败（表损坏、池初始化失败），绝不允许静默带病运行。本条把样式服务纳入内核 checks.rs 启动自检链：失败显性化、探针可查。落实「异常零静默」戒律。
【实现机制】自检三步：样式表可加载（校验和过）→ 池可初始化（内存预算内）→ 探针查询一次合法属性（返回值符合声明）。任一步失败，checks.rs 报告FAIL 级启动探针，系统进入内建矢量主题安全模式并留档，绝不停机也不装没事。
【完成判据】UNX-F4-E019-J1 要求：正常启动自检 10/10 次三项全过；注入样式表损坏的早期失败，10/10 次 checks.rs 探针在报告可查、系统降级矢量主题继续运行。
【细节补注】安全模式的降级不是悄悄换皮：诊断账记 ERROR 级事件 + 设置页出现一条非阻断提示卡（三要素齐全），用户知道「当前主题加载失败，已用内建观感」。自检在启动链的时点刻意安排在 shell 起窗之前——早期失败必须在第一扇窗画出之前被捕获，这是「日志系统启动之前的早期失败」戒律的落实。降级态下主题设置页的「重新加载主题」按钮是显式恢复路径。

**UNX-F4-E020 · E01 批收口与批账锁定**

【功能定位】批收口是产线纪律的闸门：本批 20 条逐条对表判据、编号连续性校验、诊断账抽查，全部绿后批账锁定（后续改动必须走新批次而非改历史账）。防止「账面漂亮、实际漂移」。
【实现机制】收口流程：判据对表（20/20 逐条跑）→ 编号连续零重号断言 → 诊断账抽样（每类至少 1 条）→ 批账哈希锁定入库。锁定后任何改动在台账留 diff 痕迹。
【完成判据】UNX-F4-E020-J1 要求：20 条判据对表 20/20 通过、编号 E001–E020 连续零重号，10/10 次运行结果一致；注入短判据（删一条判据），收口检查 10/10 次拒绝锁定并报缺失编号。
【细节补注】批账哈希锁定入总台账后，历史批次即成「只读账本」——发现历史判据有错不原地改，而是开新批登记勘误，账本的可审计性因此完整保留。诊断账抽样每类至少一条的规则确保收口不是只看判据绿、还要看证据在。收口产出的三件套（判据对表、编号断言、抽样记录）归档 _attic/reports/，为后续审计与回溯提供原始凭证。

## E02 批 · UxTheme API 族绘制分发与高对比度回退（E021–E040）

**UNX-F4-E021 · GetSysColor 全色槽语义**

【功能定位】GetSysColor 是 Win32 应用的颜色命脉：32 个系统色槽（窗口背景、按钮面、高亮、灰文等）。本条在 Varix 上完整实现 32 槽语义，并建立高对比度替换表——老应用不改一行代码就能跟随系统配色。这是「存量应用零迁移成本」的兼容承诺。
【实现机制】32 槽定义为常量索引表，每槽存当前模式下的 COLORREF 值；模式（亮/暗/高对比）切换时整表原子替换。高对比替换表独立维护：高对比开启时，读取路径透明替换为高对比值。查询接口无锁只读，越界槽号返回缺省黑并落 TRACE 账。色槽表全量暴露到 lxprocfs.rs 自省节点，运维可实况核对。
【完成判据】UNX-F4-E021-J1 要求：32 槽全量读取值与当前模式色板声明一致，高对比替换表切换后立即生效，10/10 次通过；注入越界槽号（如 0xFFFF），10/10 次返回缺省值不崩溃、诊断账可查。
【细节补注】32 槽的语义对齐 Win32 全集（COLOR_WINDOW 到 COLOR_HOTLIGHT），老应用的每一条 GetSysColor 调用都能拿到语义正确的值。替换表的「透明替换」意味着应用完全无感知——高对比开启前后应用代码路径零变化，变的只是返回值。缺省黑不是随意兜底：越界查询按 Win32 惯例返回 0，行为与 Windows 一致，应用拿到的错误形态也是熟悉的。自省节点同时暴露模式态与槽值，测试脚本一条命令核对全表。

**UNX-F4-E022 · 高对比度模式总开关与状态机**

【功能定位】高对比度是视障用户的生命线功能。本条把「开/关/切换中」建成显式三态状态机：开启时全系统换高对比色板、关位图特效；切换中（过渡态）禁止半新半旧同屏。解决的是无障碍切换的确定性——用户按下开关的瞬间，系统必须给出一致的完整承诺。
【实现机制】状态机三态迁移规则：OFF→TRANSIT→ON，ON→TRANSIT→OFF；TRANSIT 态的进入条件是新色板池就绪 + 广播已发，退出条件是全窗口重绘完成账齐（复用 E017 广播基建）。迁移中的绘制请求一律按目标态取色（不做插值混合），保证同屏色彩同源。状态机当前态进自省面。
【完成判据】UNX-F4-E022-J1 要求：开/关/切换三态迁移 10/10 次账实相符（每态进入退出有账）；注入切换中绘制（TRANSIT 态新请求），10/10 次按目标态取色，无半新半旧像素。
【细节补注】「按目标态取色」消除了插值混合类方案的两大顽疾：过渡期色彩脏（新旧混合出说不清的中间色）与过渡时长不可控。TRANSIT 态时长上限 300ms，超时强制收口到 ON/OFF 并落账——状态机不允许卡在中间态。当前态对外只读暴露（自省面 + UIA 属性），shell 任务栏的高对比指示器直接消费该状态，UI 与内核对「现在是不是高对比」永远一个答案。

**UNX-F4-E023 · 高对比度下九宫格位图禁用**

【功能定位】位图九宫格在高对比度下是负资产：照片式按钮纹理会淹没在纯色背景里，视障用户更难辨认控件边界。本条在高对比开启时逐部件禁用位图、回退纯色描边绘制。解决的是「无障碍模式反而更难用」的常见翻车。
【实现机制】禁用表按部件族枚举：高对比态查询矩阵账时，命中位图资源一律改走纯色绘制表（边框 2px 对比描边 + 实心填充，颜色取高对比色槽）。禁用是查询层行为（不改矩阵账数据），关闭高对比即自动恢复，无残留。
【完成判据】UNX-F4-E023-J1 要求：高对比下逐部件回退纯色绘制表 10/10 次生效（全部件无位图残留）；注入漏回退场景（构造绕行路径直取位图），检测器 10/10 次发现并纠正落账。
【细节补注】纯色绘制表的描边宽度经视障用户实测标定：1px 描边在 200% 缩放下不可辨，2px 是可辨下限，故表级约束最低 2px。回退按部件语义分级——装饰性部件（分隔线）回退单色线，功能性部件（按钮）回退「描边+填充+文本」三件套，保证控件边界在任何高对比配色下可触达。高对比关闭时回退自动撤销，位图路径无状态残留。

**UNX-F4-E024 · 高对比度切换即时生效探针**

【功能定位】「即时」必须被证明而非宣称。本条布设 50 例探针（按钮/菜单/标题栏/滚动条/文本各态），在每次高对比切换后逐例验证是否 ≤1 帧内呈现新色。它把无障碍切换的时效从体感变成账面。
【实现机制】探针为注入式验证件：切换广播后逐部件截图比对目标态色值，超 1 帧未生效记 FAIL。探针结果进诊断账与总日志中心，FAIL 触发催绘与二次验证。探针只在切换窗口期活跃，常时零开销。
【完成判据】UNX-F4-E024-J1 要求：50 例切换探针连续 10 轮全部 ≤1 帧生效；注入延迟生效场景（模拟某窗口挂起重绘），探针 10/10 次捕获 FAIL 并驱动催绘补齐。
【细节补注】50 例探针的选取覆盖了「最容易延迟」的场景：被最小化的窗口恢复、被完全遮挡的窗口、vxwm 合成队列繁忙时刻、跨多显示器各一例。探针判定「生效」的标准是像素级比对而非账面标脏——只有真画出来了才算数，杜绝「账面说切了、屏幕还是旧的」的假绿。探针在切换窗口期以最高优先级调度，常态编译剔除，零运行时代价。

**UNX-F4-E025 · 系统色与主题色优先级仲裁**

**UNX-F4-E029 · 对话框与按钮族状态绘制表**

【功能定位】对话框按钮族有特殊语义：默认按钮（回车触发）要带焦点环强调、按下态要「沉下去」、禁用态灰而不糊。本条补齐按钮族状态表并实现默认钮唯一性约束。解决「两个默认按钮」的语义混乱。

【细节补注】按下态的 1px 内容位移是「按压感」的最小实现：位移发生在内容层而非按钮框层，视觉上按钮沉下去、边框不动，松开回弹带 60ms 缓动。禁用态的 45% 透明度与灰文同时生效，且禁用按钮不参与 Tab 焦点链（无障碍一致性）。焦点环与高对比联动：高对比下焦点环加粗到 3px 并改用高对比强调色。

**UNX-F4-E030 · owner-draw/custom-draw 应用感知挂点**

【功能定位】部分应用自绘控件（owner-draw）。主题不能强改它们，但要「感知」它们：挂点让自绘控件登记进主题账，回归截图与高对比联动把它们纳入视野。解决自绘控件成为主题盲区的问题。
【实现机制】挂点为一对注册接口：应用自绘时登记（窗口句柄、控件类、自绘范围），销毁时注销。登记后：高对比切换会向其发送 WM_THEMECHANGED 类通知、截图账把它纳入扫描（标注「应用自绘」）。不强制、不拦截自绘内容。
【完成判据】UNX-F4-E030-J1 要求：自绘控件登记后 10/10 次收到切换通知且进截图扫描清单；注入绕过挂点的自绘，审计器 10/10 次在截图 diff 中发现未登记自绘区域并提示。
【细节补注】挂点对应用是「自愿登记、换来看护」的契约：登记后高对比切换通知让自绘控件也能响应无障碍模式，这是登记的实际收益——不登记的高对比下自绘控件可能看不清。截图账把自绘区域标为「应用自绘」单独归类，回归 diff 时它们的变化不算主题回归（归属应用），避免误报污染主题基线。审计提示是 INFO 级（不告警不阻断），给主题维护者的视野补全而非执法。

【功能定位】窗口的标题栏/边框/滚动条属于非客户区，传统 Win32 由 WM_NCPAINT 消息驱动绘制。本条实现 NC 区的主题化接管：消息照发（兼容）、绘制走主题服务。解决 NC 区「系统灰框」与主题不搭的历史观感割裂。

【完成判据】UNX-F4-E031-J1 要求：标题栏/边框/滚动条 NC 区主题接管 10/10 次完整（无系统灰残留）；注入 NC 区漏绘场景，完成账 10/10 次检出并补绘。
【细节补注】NC 与客户区同路合成的收益在窗口阴影与圆角上最明显：老式两套路径下 NC 区圆角与客户区内容对不齐，同路后合成器一次性裁切，边角像素级吻合。应用自定义 NC 绘制的「尊重范围」语义保证皮肤类应用（自绘标题栏）不被主题覆盖，只补它没画的空白区——接管是默认、不是强夺。NCPAINT 消息照发兼容了依赖该消息做自制渲染的存量应用。

**UNX-F4-E032 · 主题动画参数（部件过渡时长/缓动）**

【功能定位】按钮悬停渐变、菜单展开滑入——这些微动画的时长与缓动由主题参数化。本条建参数表并与 vxwm 特效通道对接。落实「动画每一帧都该存在」的节奏要求：参数不达标（过快突兀/过慢拖沓）即打回。
【实现机制】参数表：每部件过渡对（时长 ms，缓动曲线枚举），默认 120ms ease-out。下发走 vxwm 特效通道（参数化指令，非逐帧位图）。动画风暴防护：同部件 250ms 内重复触发合并为一次。减弱动效模式（前庭安全）全局覆盖参数表为瞬时切换。
【完成判据】UNX-F4-E032-J1 要求：过渡参数 10/10 次正确下发至合成器（参数账与表一致）；注入高频切换风暴（100 次/秒悬停），节流器 10/10 次合并、帧率无塌陷。
【细节补注】120ms ease-out 默认值来自动效节奏标定：比它快显突兀（人眼捕捉不到过渡）、比它慢显拖沓（操作跟手感受损）。参数表是主题作者的表达面之一——游戏型主题可以全系统加快到 80ms，办公型可以放慢到 160ms，节奏即个性。减弱动效模式（前庭安全）的覆盖优先级最高于主题参数：任何主题都无权在用户声明晕动症时强行放动画，这是无障碍凌驾于个性化的铁律。

**UNX-F4-E037 · 色弱可辨替换色板**

【功能定位】红色高亮对红绿色弱用户不可辨。本条提供三型色弱（红/绿/蓝）替换色板：切换后全系统状态色换为该型可辨组合，且对比度达标 WCAG AA。解决「颜色不只靠色相区分」的验收硬指标。
【实现机制】三套替换板经离线对比度校验（全部语义色对 ≥4.5:1）后冻结入库；切换走色槽表原子替换 + 广播链（同热切换路径）。语义色（错误红/成功绿）同时携带形状冗余（图标/文本），色板替换不牺牲冗余。
【完成判据】UNX-F4-E037-J1 要求：三型色板切换后全槽对比度达标 10/10 次（脚本化 WCAG 断言）；注入不达标板文件，校验器 10/10 次拒绝入库。
【细节补注】三型色弱板的生成不是简单换色相：对每个语义色对（前景/背景）做 Lab 空间距离重排，保证色弱模拟器下依然可分且对比度达标——这是离线校验脚本的工作，入库前全量断言。形状冗余（错误叉号、成功对勾）与色板解耦，任何色板下都保留。切换入口放在无障碍设置一级页，改完即时生效走标准广播链。

**UNX-F4-E038 · 主题回归账扩维：部件×状态×高对比**

【功能定位】在 E018 二维截图账上加第三维「模式」（亮/暗/高对比），矩阵从 N×4 变 N×4×3。解决高对比回退的视觉回归没有系统性看护的问题。
【实现机制】遍历器扩维枚举，截图按三维键归档；diff 按维切片比对（可单独看高对比切片）。容量控制：同版本只留最新一份全量 + 差异增量。三维矩阵规模约数千张，增量 CI 只跑受影响切片。
【完成判据】UNX-F4-E038-J1 要求：三维矩阵截图 diff 连续 10 次零回归（基线稳定）；注入高对比切片漂移，10/10 次按切片检出并定位。
【细节补注】三维矩阵的受影响切片计算依赖样式表依赖图：改了 button 类只跑 button × 状态 × 三模式切片，CI 时间从全量十几分钟压到两分钟内。切片选择策略有保守兜底：依赖图缺失时退化为全量跑，速度慢一些但绝不漏检任何一个回归。矩阵规模与增量策略写入回归基建文档，供后续批次的截图账（E018）统一演进。

**UNX-F4-E039 · 内核锚定：色槽表经 lxprocfs.rs 自省可查**

【功能定位】把色槽实况暴露为内核自省节点（procfs 路径），运维与测试不进 UI 就能核对当前 32 槽值与模式态。落实「总日志中心之外的第二双眼睛」。
【实现机制】lxprocfs.rs 注册节点（/proc/varix/theme/syscolors 等），读时从色槽表快照序列化（只读一致性快照）。节点缺失或读取异常本身成为 checks.rs 的自检项。节点只读，无写路径（杜绝自省面被滥用为控制面）。
【完成判据】UNX-F4-E039-J1 要求：procfs 节点读出值与 UI 实况一致 10/10 次（切换后立即读取反映新态）；注入节点缺失，自检 10/10 次报 FAIL 并留档。
【细节补注】自省节点只读是刻意的安全边界：自省面（读实况）与控制面（改状态）严格分离，procfs 通道永远不成为第二个设置入口——否则诊断工具的一次误写就是一次生产事故。快照一致性靠读时拷贝小结构（32 槽表仅 128 字节，拷贝成本可忽略），不引入读锁。节点缺失进 checks.rs 自检意味着「有人误删了自省注册」这类配置漂移会在下一轮自检现形。

**UNX-F4-E040 · E02 批收口与批账锁定**

【功能定位】E02 批 20 条的批级闸门：判据对表、编号连续、诊断账抽查、与 E01 批的接口无漂移。锁定后进入 E03 批。批收口制度保证「每 20 条一个确凿的完成」。
【实现机制】同 E020 收口流程，追加两项：与上一批的交叉接口冒烟（高对比开关 × 热切换 × 诊断账联动）、批账哈希入总台账。收口记录三件套归档 _attic/reports/，为后续批次收口提供对照基准与审计凭证。
【完成判据】UNX-F4-E040-J1 要求：20 条判据对表 20/20、编号 E021–E040 连续零重号、交叉冒烟全绿，10/10 次可复现；注入缺项，收口 10/10 次拒绝锁定。
【细节补注】交叉冒烟专挑「两批功能交界处」下刀：高对比开关打到一半发起热切换、诊断账滚动中发起矩阵截图——交界处是职责缝隙，单批测试永远照不到。批账哈希入总台账让批次之间形成链式结构：任何一批被改动，后续批次的哈希链即断，篡改无处遁形。收口记录的归档路径遵循台账约定（_attic/ 过程产物），与 docs/ 功能文档分离。

## E03 批 · DPI 三态感知与跨屏重排（E041–E060）

**UNX-F4-E041 · DPI 三态模型（unaware/system/per-monitor）**

【功能定位】应用对 DPI 的感知分三档：unaware（完全不管，系统替它拉伸）、system（只认主屏 DPI）、per-monitor（逐屏感知，最高画质）。本条实现三态模型与 manifest 声明解析，是 Varix 高分屏体验的基石。解决「高分屏上一半清晰一半糊」的混装现实。
【实现机制】三态从应用 manifest 声明解析（缺声明按 unaware 处理并落 INFO），档位随进程登记进会话账；渲染路径按档分派：unaware 走系统位图拉伸（E042）、system 走主屏 DPI 缩放（E043）、per-monitor 走逐屏事件（E044）。档位变化（应用自声明 SetProcessDpiAwareness）允许一次性升级、禁止降级。
【完成判据】UNX-F4-E041-J1 要求：三种 manifest 解析与档位生效 10/10 次正确；注入缺声明应用，10/10 次按 unaware 档处理且自省面档位可查。
【细节补注」三档的档位升级允许、降级禁止是经过权衡的：应用运行中主动声明更高感知（如首窗后才知自己是 per-monitor）是合法的自我修正；降级则会让已按高 DPI 布局的窗口突然错乱，一律拒绝并落账。manifest 解析容错：声明字段拼写错误按缺省处理并 WARN，不因一个坏字段拒绝整个应用。档位信息同时喂给兼容性画像（E057），高分屏体验差的应用画像上一眼可见。

**UNX-F4-E042 · unaware 位图拉伸路径**

【功能定位】unaware 应用认为自己活在 96 DPI 世界，系统按屏比把它的整个窗口位图拉伸放大。本条实现高质量拉伸路径（多桶滤波）并记保真账：拉伸是无奈之举，质量必须做到最好、模糊必须可度量。解决 legacy 应用在 4K 屏的观感底线。
【实现机制】拉伸在 vxwm 合成层做（应用零感知）：GPU 多桶采样（面积平均），文字部分可选锐化补偿。保真账记录：每窗口拉伸比、滤波档、模糊度量值（拉普拉斯方差），低于阈值落 WARN 提示「建议应用升级 per-monitor」。窗口移动不改位图（应用坐标系恒定）。
【完成判据】UNX-F4-E042-J1 要求：典型 DPI 比（125%/150%/200%）拉伸保真账 10/10 次在质量阈值上；注入极端比（50% 缩小），10/10 次输出不崩且账面标注质量降级。
【细节补注】多桶滤波选型基于实测：双线性在 >150% 放大时边缘发糊，Lanczos 锐但计算贵且偶发振铃，面积平均桶滤波在位图整窗放大场景兼顾质量与成本。文字锐化补偿可开关（部分应用自渲染文字，二次锐化反而脏），默认开、画像账里按应用记忆偏好。WARN 级「建议升级」只进画像不弹窗——糊是应用的错，不该打扰用户。

**UNX-F4-E043 · system 档主屏 DPI 缩放**

【功能定位】system 档应用按主屏 DPI 一次性缩放布局：几何、字体、图标全按比系数（如 150%）。本条实现该档的缩放语义。解决「次屏 DPI 不同但应用只认主屏」档的确定性——行为明确、结果可预期。
【实现机制】系统在应用首窗创建时下发主屏 DPI，应用内部坐标系按该值运转；窗口被移到异 DPI 屏时整窗位图拉伸（同 E042 路径，账面标注 system 档跨屏拉伸）。字体经字体服务按 DPI 选点阵/矢量档，避免整数化发虚。
【完成判据】UNX-F4-E043-J1 要求：主屏 100%/150% 两档下几何与字体等比正确 10/10 次（截图尺寸比例断言）；注入错缩放（伪造 DPI 值），校验 10/10 次发现账实不符。
【细节补注】「首窗创建时锁定主屏 DPI」的语义明确到场景：应用启动后用户改了主屏缩放，system 档应用不跟随（保持启动时档），跨屏移动走位图拉伸——行为可预期是这一档的全部价值。字体点阵/矢量分档的阈值按字号划线：小字号（<14px 等效）用带 hinting 的矢量保清晰，不退点阵；点阵仅用于极小尺寸兜底。截图尺寸比例断言是像素级验收：150% 档按钮位宽必须精确等于 100% 档的 1.5 倍（四舍五入规则统一在主题层）。

**UNX-F4-E044 · per-monitor WM_DPICHANGED 通知语义**

【功能定位】per-monitor 应用在跨屏或屏 DPI 变化时收到 WM_DPICHANGED：带新 DPI 与建议矩形。本条实现通知的产生、投递、与漏投检测。它是高分屏多屏体验的核心事件，漏一条通知就有一个错位窗口。
【实现机制】事件源两路：跨屏移动（几何跨过屏边界）与屏 DPI 热变（分辨率/缩放变更）。事件按窗口逐个投递（含建议矩形），投递账逐条登记；应用处理后回执（采纳/拒绝）。投递超时（应用无回执）不重发但记账，供诊断。
【完成判据】UNX-F4-E044-J1 要求：逐屏 DPI 变更事件 10/10 次全部投递（账面无漏）；注入漏通知场景（模拟投递丢失），对账器 10/10 次发现缺口并补投。
【细节补注】建议矩形的生成考虑了窗口链（owned windows）：主窗重排时附属窗口（对话框、工具窗）联动出各自建议矩形，一次事件全家搬——只搬主窗留附属窗是最常见的错位事故源。投递账按窗口粒度记录（不止按事件），对账器能精确指出「哪个窗口漏了哪条」。事件源去重：跨屏移动与热切换同时发生时合并为一次事务（共用事务 ID），应用只收一条通知。

**UNX-F4-E045 · 建议矩形采纳/拒绝双路径**

【功能定位】WM_DPICHANGED 附带建议矩形（系统按相对位置算的新几何），应用可采纳（自动重排）或拒绝（保持旧矩形自管）。本条实现双路径与双落账——两条路都合法，但都必须留下确定性痕迹。解决「应用不理建议、窗口悬空」的追踪难题。
【实现机制】回执双态：采纳（应用 MoveWindow 至建议矩形，账记「采纳+新几何」）或拒绝（系统按旧矩形保留，账记「拒绝+旧几何」）。半采纳（改了尺寸没改位置）按拒绝语义归类并单独计数，供应用质量画像。
【完成判据】UNX-F4-E045-J1 要求：双路径 10/10 次落账正确（采纳/拒绝各自几何与账一致）；注入半采纳，10/10 次归类拒绝语义并计数可查。
【细节补注】建议矩形的计算遵循「屏幕相对位置不变」原则：窗口在旧屏的相对位置映射到新屏同位置，用户的心智模型（窗口在右边屏幕靠上）不因重排而打破。拒绝不是错误——有些应用（专业绘图工具）需要自己管理多屏几何，账面把高频拒绝应用标进画像（E057），但绝不强制干预。回执超时窗口设 2 秒，超时不重发（避免打扰自管型应用）只记账。

**UNX-F4-E046 · 跨 DPI 拖屏窗口重排**

【功能定位】用户拖窗口从 150% 屏到 100% 屏的瞬间，窗口必须平滑重排（per-monitor 应用重布局、其他档拉伸），光标抓手点不漂移。本条实现拖屏重排的完整链路，这是多屏体验的「体感分水岭」功能。
【实现机制】拖动中按光标所在屏判定目标 DPI：过界瞬间触发重排事务——冻结用户输入几何（抓手点屏幕坐标不变）、应用重布局或合成层拉伸、完成后解冻。重排动画 ≤1 帧（无跳变观感），失败回退拉伸路径保底（绝不出现窗口消失）。
【完成判据】UNX-F4-E046-J1 要求：100 次拖屏演练几何重算零错位（抓手点漂移 ≤1px）10/10 轮；注入重排失败，10/10 次回退拉伸保底，窗口不丢。
【细节补注】抓手点不漂移的诀窍是「屏幕坐标锚定」：重排期间以光标的屏幕坐标为锚反推窗口新几何，而不是以窗口旧几何推新几何——用户的视觉锚点（手下的那一点）全程不动。重排事务与 DPI 热切换共用事务基建（同一状态机），拖屏是其中「单窗子集」。100 次演练覆盖双向跨屏、三屏链式跨越、拖动中松手于边界上等刁钻时序。

**UNX-F4-E047 · DPI 与字体渲染联动**

【功能定位】字号随 DPI 等比、字形在高倍屏上必须锐利不发虚。本条打通 DPI 档到字体服务的参数链（像素字号、微调 hinting 档、亚像素渲染开关）。落实「放大三倍看不尴尬」在文字维度的承诺。
【实现机制】字号换算统一在主题层（pt→px 按 DPI），应用拿到的已是像素值；hinting 档按 DPI 分级（低 DPI 全 hinting、高 DPI 轻量）；矢量字体高倍直接光栅化。文本测量与绘制同源（同 DPI 参数），杜绝「量的时候一套、画的时候另一套」的截断错位。
【完成判据】UNX-F4-E047-J1 要求：125%/150%/200% 三档字号等比、字形锐利度阈值达标 10/10 次；注入发虚（hinting 档错配），探针 10/10 次按锐利度量检出并纠正参数。
【细节补注】「测量与绘制同源」防住的是排版最阴险的 bug：文本量出来 100px、画出来 103px，按钮里最后一个字被挤裁——同源参数让两类调用拿同一份整形结果，物理上不可能分歧。亚像素渲染按屏类型自适应：高分屏 PPI 高时关闭亚像素（RGB 条纹间距小于可辨阈值），省电且避免彩色边纹。锐利度探针用拉普拉斯方差量化「发虚」，阈值经多种字重实测标定，不凭肉眼。

**UNX-F4-E048 · 光标与系统图标的 DPI 缩放**

【功能定位】4K 屏上一个 96 DPI 的小光标是灾难。本条实现光标与系统图标按屏 DPI 选档（多尺寸资产或矢量生成），边缘无锯齿。解决「界面清晰了、光标还是锯齿小点」的违和。
【实现机制】光标资产多档（1x/1.5x/2x）+ 矢量兜底（无对应档时矢量光栅化到目标尺寸）；按光标所在屏实时切档（跨屏瞬间切换，缓存目标档避免抖动）。系统图标（ shell/对话框）同路走主题图标账按 DPI 取图。
【完成判据】UNX-F4-E048-J1 要求：各 DPI 档光标尺寸正确且边缘锐利 10/10 次（截图量尺断言）；注入低质放大（只有 1x 资产强行放大），矢量兜底 10/10 次接管、无锯齿。
【细节补注】光标跨屏切档的时序要求 <1 帧：缓存策略是「预取目标屏档位」（光标接近屏边界时提前装载），过界瞬间零等待。矢量兜底光栅化带描边修正（细箭头在放大后线宽补偿），避免高倍屏光标「细得看不见」。文本 I 型光标与手型光标分别实测热点偏移，热点在缩放后仍指在像素级正确位置——这是「看起来对」与「真的对」的区别。

**UNX-F4-E049 · 多屏异 DPI 并存会话**

【功能定位】150% 与 100% 双屏并存是主流真机形态。本条保证并存会话的隔离性：每窗口绑定所在屏 DPI，串屏即纠正。解决「两屏窗口互相污染 DPI」的串屏 bug 族。
【实现机制】会话账维护「窗口→屏→DPI」三元组，几何操作（移动/缩放）后重验绑定；串屏检测器周期扫描（或在几何事件后即时扫描）发现绑定与实况不符即按 E044/E046 链路纠正。自省面暴露全表供诊断，多屏问题的一线排查从这里起步。
【完成判据】UNX-F4-E049-J1 要求：150%+100% 双屏各窗口渲染 DPI 与所在屏一致 10/10 次；注入串屏（伪造绑定），检测器 10/10 次发现并自动纠正落账。
【细节补注】串屏检测的时机分两路：几何事件后即时扫描（窗口移动/缩放完成钩子）是主路，周期兜底扫描（10 秒）防「几何事件丢失」类边角。纠正动作尊重窗口 DPI 档：per-monitor 窗口走完整重排链，unaware/system 窗口只更新拉伸参数（不打扰应用）。三元组全表在自省面按屏分组展示，多屏问题的一线诊断从这里开始。

**UNX-F4-E050 · DPI 热切换（分辨率变更）**

【功能定位】用户在显示设置改缩放比/分辨率的瞬间，全系统窗口重排。本条实现热切换事务：变更事件 → 全窗重排 → 完成账。解决「改完缩放后窗口残旧几何」的经典事故。
【实现机制】切换事务复用主题热切换骨架（E017）：显示服务发出变更 → 按屏更新 DPI 账 → 全窗按档分发（per-monitor 重布局/unaware 拉伸参数更新）→ vxwm 全量重排 → 完成度记账超时催办。切换期间输入短暂合并（不丢事件）。
【完成判据】UNX-F4-E050-J1 要求：分辨率变更后全部窗口重排完成账 10/10 次齐（无残旧几何窗口）；注入重排挂起窗口，催办 10/10 次驱动完成或显式降级拉伸。
【细节补注】切换期间输入合并策略经过场景推演：用户在改缩放的同时在打字，键入事件不丢（进队列合并），鼠标点击类事件在重排完成前延迟派发（防点错位）。完成账按屏分组——多屏不同缩放档同时改的场景各屏独立记账，任一屏未完成整事务不算完。残旧几何的判定以「窗口实绘矩形 vs 账面应有矩形」像素级比对为准，不是应用自报。

**UNX-F4-E051 · 文本缩放因子与 AI-28 字体服务联动**

【功能定位】系统级文本缩放（125%/150%）独立于屏幕 DPI：用户可能只想字大一点而不改布局密度。本条把文本缩放因子接到 AI-28 字体服务，专管「字」不动「框」。解决视力低下用户与高密度布局的两难。
【实现机制】缩放因子作为字体服务全局参数：字号请求经因子放大后再选字重/字距（自动防截断：容器按新字号重新测量，控件按需增高）。因子变更走轻量广播（只标脏文本 surface）。因子与 DPI 正交记录，账面分开。
【完成判据】UNX-F4-E051-J1 要求：125%/150% 因子下文本放大、容器自适应无截断 10/10 次（截图断言）；注入截断场景（容器拒不增高），检测 10/10 次报出截断部件清单。
【细节补注】因子与 DPI 的正交性是设计底线：150% 因子 + 100% DPI = 字大框不变；100% 因子 + 150% DPI = 全等比。两参数组合矩阵 2×2 全场景进探针。防截断的自适应增高有安全上限（单控件最多增高 2 倍），超限走省略策略并落账——绝不允许一个超大字号把整窗布局撑爆。因子偏好持久化与 E056 同库同迁移链。

**UNX-F4-E052 · DPI 感知探针集 30 例**

【功能定位】把 DPI 行为固化为 30 例探针（三档 × 跨屏/热切/字体/光标/串屏各场景），任何主题/DPI 改动后一键全跑。解决 DPI 回归「改一处坏三处」的隐性扩散。
【实现机制】探针集为声明式清单（场景输入、期望输出、断言函数），宿主侧替身跑（无头渲染比对），QEMU 面随闸门补测。探针结果四态（PASS/FAIL/SKIP/WARN）全落账，假绿防护：探针自身带自检（期望值与断言联动校验）。
【完成判据】UNX-F4-E052-J1 要求：30 例全 PASS 账 10/10 轮稳定；注入假绿探针（断言被改弱），自检 10/10 次识破并标红该探针。
【细节补注】30 例的分布：三档各 6 例基础场景（首窗、跨屏、热切），再加串屏、字体、光标、建议矩形、unaware 拉伸、多屏并存等专项。假绿防护是探针集的灵魂：每例探针的断言函数与期望值绑定为对（改期望必改断言，单改一边自检即红），防「为过而改断言」的纪律腐蚀。探针清单在仓库登记为契约文件，新增场景必须带例入册，清单只增不减不删除。

**UNX-F4-E053 · 跨 DPI 拖屏重排账零缺陷断言**

【功能定位】E046 的账面固化：拖屏重排的每次事务都落账（时点、起止屏、重排路径、结果），并对账断言「账上零未闭合事务」。解决重排失败被静默吞掉的风险。
【实现机制】事务账状态机：BEGIN→PATH(路径)→COMMIT/ROLLBACK；对账器周期扫描未闭合事务（超时 BEGIN 无终态）即报缺陷。账与探针集联动：E046 演练的 100 次事务必须在账内全闭合。
【完成判据】UNX-F4-E053-J1 要求：100 次拖屏演练账内全闭合零缺陷 10/10 轮；注入缺陷漏记（模拟账写入丢失），对账器 10/10 次以「计数差」发现缺口。
【细节补注】计数差检测是防漏记的最后防线：BEGIN 计数与 COMMIT+ROLLBACK 计数的差值即未闭合事务数，即使单条账被丢，差值暴露缺口。ROLLBACK 是一等公民：重排失败回退拉伸保底时显式落 ROLLBACK 账（含失败原因），回退本身也是确定性路径而非静默吞错。账本与 E058 性能账共用同一事务 ID，性能问题与正确性问题可以交叉定位，排查链路完整闭合。

**UNX-F4-E054 · 主题资源 DPI 多档资产账**

【功能定位】位图类主题资产（图标、插画）需要多 DPI 档（1x/1.5x/2x）。本条建资产账：每资产登记可用档、缺档回退策略（就近档缩放并标注）。解决主题作者只给一张图时的确定性行为。
【实现机制】资产账键 =（资产 ID，档），值 = 资源引用；请求按屏 DPI 匹配最近可用档，缩放走高质量滤波并在账标「非原生档」。缺档信息回馈主题健康评分（卷六 E81 联动），促使作者补档。
【完成判据】UNX-F4-E054-J1 要求：多档资产按屏正确取档 10/10 次；注入仅 1x 资产场景，10/10 次就近缩放成功且账面标注非原生。
【细节补注】「就近档」的选取规则：向上取档优于向下（放大 1.5x 图优于缩小 2x 图——下采样保真度高于上采样）。非原生档标注会累积进主题健康评分，主题市场页可见「此主题 2x 屏清晰度不足」提示，倒逼作者补档。资产账与九宫格渲染器解耦：账管取材、渲染器管拉伸，二者可独立演进。资产档位缺失清单可导出给主题作者作为补全工单。

**UNX-F4-E055 · DPI 变更与 UIA 树重投影联动**

【功能定位】DPI 变更后窗口几何变了，UIA（无障碍树）的屏幕坐标必须重投影，否则读屏软件点错位置。本条打通 DPI 事务到 UIA 树的失效-重投影链。落实无障碍与显示变更的同步。
【实现机制】DPI 事务完成段广播 UIA 失效（复用内核事件通道），UIA 侧按新几何重建投影缓存；重投影期间读屏请求按旧缓存应答并标记「迁移中」。完成账与 DPI 完成账对齐（同一事务 ID）。
【完成判据】UNX-F4-E055-J1 要求：DPI 变更后 UIA 坐标重投影 10/10 次与实况一致（探针点击命中）；注入重投影遗漏，对账器 10/10 次发现事务 ID 缺失并补投影。
【细节补注】「迁移中」标记保护读屏用户在重投影窗口期不被错误坐标误导：读屏请求在此期间拿到旧坐标 + 「正在更新」语义标记，读屏软件可选择等待或播报状态。重投影按窗口粒度流水执行（先完成先可用），不做全树一次性阻塞式重建。事务 ID 对齐让「DPI 变了但无障碍树没跟上」这类事故在对账时无处遁形。

**UNX-F4-E056 · DPI 用户设置持久化与迁移**

【功能定位】用户的缩放档选择要持久化（重启不丢），且跨 Varix 版本升级可迁移。本条实现 DPI 偏好存储与版本迁移。落实「升级不破坏旧数据」的信任承诺。
【实现机制】偏好存 KV 存储（SHARED 卷 boot-select.json 同款机制），含 schema 版本；读取时按版本迁移函数链升级到当前 schema（旧字段映射、新字段缺省）。写入原子（临时文件+改名）。损坏时回退系统默认并落账，绝不拒启。
【完成判据】UNX-F4-E056-J1 要求：写入→重启回读一致 10/10 次；注入旧版本偏好文件，迁移链 10/10 次升级成功且语义保留（档位不变）。
【细节补注】迁移函数链按版本号顺序执行（v1→v2→v3 逐级），每级迁移是纯函数且带单测——升级路径本身是被测试覆盖的代码而非一次性脚本。原子写的实现是「同目录临时文件 + 改名提交」，断电时旧文件完好（fs23 日志机制兜底）。损坏检测用双校验和（文件级 + 记录级），可定位到记录粒度，能救一条是一条，绝不整文件作废。

**UNX-F4-E057 · 应用 DPI 兼容性画像账**

【功能定位】按应用聚合 DPI 行为数据（档位、拒绝建议次数、拉伸时长占比），产出兼容性画像。它给用户的设置页提示「哪些应用建议开启高 DPI 支持」，也给开发者反馈改进方向。解决「哪个应用糊」需要用户肉眼排查的问题。
【实现机制】画像账按进程聚合 E042/E045 数据：拉伸时长比、建议拒绝率、模糊告警数。画像经总日志中心可导出；设置页消费画像出提示卡（低侵扰、可关闭、不再弹）。画像不上传（隐私红线），仅本机。
【完成判据】UNX-F4-E057-J1 要求：画像按进程正确聚合 10/10 次（与明细账合计一致）；注入画像与明细不符，对账 10/10 次报差值并重算。
【细节补注】提示卡的措辞遵循体验第九章三要素：现象（「此应用在高分屏下偏糊」）、原因（「应用未声明高分屏支持」）、下一步（「已用兼容方式显示；如常用，建议向开发者反馈」）。画像聚合是增量的（明细账变动只更新受影响进程），不是周期全量重算——百进程规模下聚合开销近零。画像数据生命周期跟随进程，进程退场画像归档 30 天后清理。

**UNX-F4-E058 · DPI 性能账（重排时延预算）**

【功能定位】热切换与拖屏重排必须在预算内（全窗重排 ≤300ms、拖屏单窗 ≤1 帧）。本条建性能账：每事务记录各阶段耗时，超预算落账定位瓶颈段。落实「性能是体感不是指标」的度量化。
【实现机制】事务打点五段：事件→分发→布局→合成→完成，段耗时入性能账（环形，含 P50/P95 滚动统计）；预算线按事务类型配置。超线自动附瓶颈段诊断（最慢段 + 该段窗口数）。
【完成判据】UNX-F4-E058-J1 要求：10 轮热切换 P95 在预算内；注入慢布局（模拟卡顿应用），账面 10/10 次定位到布局段并给出窗口清单。
【细节补注】P50/P95 滚动统计窗口取最近 1000 事务，既能反映近期体感又不被单次离群值带偏。预算线按事务类型分级配置：拖屏单窗 1 帧（16ms）最严、全窗热切换 300ms、DPI 热切换 300ms——不同场景用户耐 心不同，一刀切预算必有一头失真。瓶颈诊断「附窗口清单」直接把问题归到应用：主题团队收到告警第一眼就知道该找哪个应用联调，省掉排查环节。

**UNX-F4-E059 · DPI 异常路径三要素呈现**

【功能定位】DPI 失败必须按三要素呈现给用户：发生了什么（「窗口未能跟随新缩放」）、为什么（应用不支持）、下一步（「已用兼容方式显示，可在应用官网寻求更新」）。禁止裸抛 DPI 错误码。落实体验第九章。
【实现机制】错误映射表：内部错误码 → 三要素文案（人话 + 原因 + 动作），技术细节收「详情」折叠。呈现通道按场景分流：通知气泡（非阻断）/ 设置页卡片 / 诊断账（静默类）。文案走 i18n 词典（en=dict-en.ts）。
【完成判据】UNX-F4-E059-J1 要求：10 类 DPI 错误全部映射三要素文案 10/10 次（无裸码出现）；注入未登记错误码，10/10 次走通用模板兜底仍含三要素。
【细节补注】通用模板兜底保证「再陌生的错误也不会裸奔」：未登记码映射为「发生了显示适配问题/原因未知/已记录详情，可在日志中心查看」——三要素一个不少，技术码只出现在详情折叠里。文案改走 i18n 词典意味着词典缺失键会在 CI 文案走查（验收第 13 维）被抓，不会等到用户面前。呈现频率有节流：同类错误 5 分钟内不重复弹，避免骚扰。

**UNX-F4-E060 · E03 批收口与批账锁定**

【功能定位】E03 批闸门：20 条判据对表、编号连续、与 E01/E02 交叉接口冒烟（主题热切换 × DPI 热切换叠加场景）、性能账预算复核。三批连跑作为 F4 增补第一册的阶段性里程碑。
【实现机制】收口流程同前批并加叠场景：主题切换与 DPI 切换并发（用户边换主题边改缩放），验证两事务账互不污染（事务 ID 独立、完成账各自齐）。收口三件套归档并哈希锁定。
【完成判据】UNX-F4-E060-J1 要求：20/20 对表、E041–E060 连续零重号、叠加场景两账独立完整 10/10 次；注入账交叉污染（伪造同事务 ID），检查 10/10 次拒绝锁定。
【细节补注】叠加场景是本批最刁钻的验收面：主题切换改「颜色从哪来」、DPI 切换改「几何怎么算」，两者并发时最怕共享状态被互相覆写——事务 ID 独立命名空间 + 各自完成账的隔离设计在此受验。批收口的「拒绝锁定」产出有出口：缺失/污染项生成结构化工单（现象/位置/建议修法），走缺陷账本流程而非卡死产线。三批连跑里程碑达成后，第一册（E01–E03 批）即具备整合进总汇编册的资格。
