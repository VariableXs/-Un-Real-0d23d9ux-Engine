- **语义边界**：轮询式看门狗（依赖日志/状态推进点喂狗），中断式归 F0128 NMI 兜底；时限表编译期固化 + cmdline 可放大（只许放大不许缩小）。
- **依赖与嫁接源**：F0106 TSC 时间、F0121 状态机；嫁接 Linux `lockup_detector` 的软狗思想与 `hung_task` 超时语义。
- **风险与回退**：时限误判（慢机器真在干活）会误杀正常引导——时限默认值 × 3 余量、cmdline `boot.wd_scale=2` 放大一倍；误杀事件落账供调参。
- 正文：实现路径分三步。第一时限表：每阶段（交接/ACPI/内存/加载/页表/多核...）一条时限记录（默认值 ms、来源：骨架估算 ×3），cmdline 只能整体放大倍率；表 CRC 盖章。第二检查器：每次阶段内日志推进点喂狗（更新阶段起始 TSC 或进度戳），轮询检查器在日志写路径与显式 `wd_poll()` 调用点触发，超时判定 `(now - last_progress) > limit` 毫秒换算走 F0106。第三捕获动作：超时即组装"卡死证据"（阶段名、最后日志序号、卡死时长）→ 进诊断模式（F0114）而非直接 panic（可现场查 `logs` 命令）；连续 3 阶段超时则直接恢复流程（F0129）。与现存内核衔接点：喂狗点嵌在各阶段出口（A1 全部批次零改动则由日志宏隐式喂）；诊断入口与 F0136 统一。与 Windows 对照：Windows 引导无阶段看门狗（蓝屏即终态），服务侧有 SCM 超时；Linux softlockup 是运行期。本工程把看门狗前移到引导期是"可自愈引导"的关键。判据 UNX-F0122-J1 的复测方式：ktest 注入阶段卡死（停止喂狗）断言毫秒级超时捕获、捕获后进诊断（状态 = 诊断态）、时限放大参数生效、误杀演练（慢速但活着）不误报。
