### UNX-F7321 · raid target 注册与几何参数

- **语义边界**：只做注册与参数解析校验；不做 RAID 算法本体（B09–B12 防重声明）、不做成员 IO 路径（F7322 绑定后由算法批接管）、不做重建（B08 起）。
- **依赖与嫁接源**：注册进 F7203 注册表；嫁接源为 Linux dm-raid 参数语义（raid1/raid10/raid456 三家族）与 mdadm 参数惯例，只跟随。
- **风险与回退**：参数组合爆炸（级别×成员数×条带全组合）——几何约束表静态声明（级别→成员数域+条带域），约束表穷举覆盖，表外组合默认拒绝（保守）。

### UNX-F7323 · raid target 超级块驻留格式
- 域/批：B5/B07｜判据：UNX-F7323-J1（保护判据先行）超级块写盘前双副本+校验和（单副本损坏可恢复断言）；格式版本字段冻结（变更走 ADR）；成员盘身份指纹入块（防插错盘 100% 拦截）｜纯功能行数：300 行（超级块格式 100 + 双副本协议 100 + 指纹校验 100；测试段不计）｜状态：[已深化]
- **定位**：RAID 超级块是阵列的持久身份卡：每个成员盘上驻留（阵列 UUID/角色槽号/成员指纹/格式版本/世代号）——重启后按超级块重组阵列（哪些盘是一伙的、谁是谁），**成员指纹入块**是防插错盘的物理级防线：盘上的超级块声明"我是阵列 X 的 3 号数据盘，我的指纹是 Y"，实际盘指纹≠Y=盘被插错/被替换，100% 拦截。
- **语义边界**：只做超级块格式与协议；不做重组编排（B08 起）、不做指纹算法（F7228）、不做写盘执行本体（B4，本条定义格式与校验，写入动作走 F7228 闸门）。
- **依赖与嫁接源**：复用 F7228 指纹与 F7258 双副本思想；嫁接源为 Linux md 超级块（v1.x 格式，1.0/1.1/1.2 三驻留位）语义，只跟随。
- **风险与回退**：超级块写坏（写到一半断电）——双副本+校验和（F7258 同构：主备各带 CRC），单副本损坏按存续副本恢复，双损坏按无超级块处理（盘不可识别入阵，保守拒绝）。
- 正文：实现路径分三步。第一步超级块格式：固定 4KB 块，字段表（魔数/版本/阵列 UUID/槽号/角色/成员指纹/世代/创建时间/CRC），版本字段冻结声明（格式变更走 ADR——超级块是盘上的持久格式，变更=兼容性断层，必须最高级别慎重）；第二步双副本协议：主副本驻盘尾、备副本驻盘头后 1MB（md 1.2 风格双驻留位），写入=双副本各带 CRC 顺序写（经 F7228 闸门），读取=双读双验，单损恢复断言；第三步指纹校验：入阵时盘指纹与超级块声明比对，不符拒绝入阵（"wrong-member"码）留账，防插错盘注入 10/10 拦截。与现存内核衔接点：`dm/raid_sb.rs` 新建，写盘动作过 F7228 闸门。与 Windows 对照：Windows Spaces 的池元数据驻留（每物理盘头部）+成员身份校验同构。判据 UNX-F7323-J1 的复测方式：单副本损坏恢复 20/20、版本字段冻结声明在册、插错盘注入 10/10 拦截留账。

- **语义边界**：只做句柄消费与校验；不做密钥本体（J3 判例二）、不做句柄生成（K5/J3）、不做内存扫描器本体（A5 安全扫描工具复用）。

- **风险与回退**：句柄在加密路径的缓存泄漏（加密上下文缓存句柄派生物）——句柄派生物（session key 引用）同样以句柄形态存在（J3 保证），dm 侧只见引用；扫描断言覆盖派生物区。
- 正文：实现路径分三步。第一步句柄协议：crypt 上下文持句柄（opaque），加解密调用传句柄给 J3（J3 内部取材料），句柄类型系统隔离（Handle 类型非字节数组——误用编译期拦截）；第二步扫描断言：测试密钥注入 J3 后全链（注册/激活/读写 IO），dm 侧内存扫描明文模式零命中（ktest 常驻断言）；第三步校验：句柄长度语义（J3 返回句柄元数据含密钥长度）与 cipher 声明比对，不一致拒绝激活（"keysize-mismatch"码），失效路径（J3 报句柄失效）显式失败不静默。与现存内核衔接点：`dm/crypt_key.rs` 新建，J3 冻结接口签字面。与 Windows 对照：Windows CNG 的密钥句柄（BCRYPT_KEY_HANDLE，密钥不落应用层）同构。判据 UNX-F7325-J1 的复测方式：全链扫描零明文、句柄失效 10/10 显式失败、长度不一致 20/20 拒绝。

### UNX-F7326 · crypt IV 生成框架（plain/essiv/sector 模式分派）
- 域/批：B5/B07｜判据：UNX-F7326-J1 三种 IV 模式逐扇区生成值与规范向量一致（测试向量表全过）；模式字段非法值拒绝｜纯功能行数：320 行（IV 框架 110 + 三模式实现 120 + 向量表 90；测试段不计）｜状态：[已深化]
- **定位**：IV（初始向量）是加密模式的随机性来源：plain（扇区号直用，简单但有水印泄露）、essiv（盐化哈希，防水印攻击——LUKS2 默认）、sector（偏移组合）三模式是 dm-crypt 事实标准。IV 生成是确定性的（同扇区同 IV——解密必须可重现），**规范向量表**（dm-crypt 官方测试向量的等价物）逐扇区对拍是 IV 正确性的验收线——IV 错一个扇区=那个扇区永远解不开。
- **语义边界**：只做 IV 生成框架；不做加密模式本体（XTS 等归 J3）、不做盐的密钥派生（J3/K5）、不做 IV 格式扩展（三模式起步，扩展走 ADR）。
- **依赖与嫁接源**：嫁接源为 dm-crypt IV 生成语义（crypto API iv generators）与 LUKS 规范 IV 章节，只跟随。
- **风险与回退**：IV 碰撞（不同扇区同 IV 的病态组合）——三模式在合法参数域内无碰撞（数学保证+参数域守卫），模式参数越出域即拒绝（F7324 矩阵）。
- 正文：实现路径分三步。第一步 IV 框架：IV 生成器接口（模式枚举+扇区号→IV 字节），模式分派器按声明选择，生成纯函数化（可对拍）；第二步三模式实现：plain（IV=扇区号 little-endian 定宽）、essiv（IV=E_salt(扇区号)，盐=密钥哈希，哈希调用 J3 允许的摘要接口）、sector（IV=扇区号+偏移组合），各模式按规范向量表逐扇区对拍（向量表静态 512 项起步）；第三步断言：向量表全过断言（512/512）、非法模式值 20/20 拒绝、跨扇区 IV 单调性抽验（essiv 模式同扇区重生成一致）。与现存内核衔接点：`dm/crypt_iv.rs` 新建，摘要接口消费 J3 允许面。与 Windows 对照：Windows BitLocker 的 IV 策略（-sectorize 语义）同域，BitLocker 用 ECC 生成 IV 的思想与 essiv 同属抗水印家族。判据 UNX-F7326-J1 的复测方式：向量表 512/512 全过、非法值 20/20 拒、确定性断言（同输入同输出 1000 轮）。

### UNX-F7327 · crypt per-bio 加解密路径挂点
- 域/批：B5/B07｜判据：UNX-F7327-J1（保护判据先行）写路径先加密后下发、读路径先解密后上交的顺序断言；加密失败写请求 100% 失败不落明文；AES-NI 路径标记可观测｜纯功能行数：340 行（路径挂点 110 + 顺序断言 110 + 失败守卫 120；测试段不计）｜状态：[已深化]
