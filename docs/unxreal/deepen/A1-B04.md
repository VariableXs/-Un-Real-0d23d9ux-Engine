### UNX-F0061 · 三源冲突仲裁策略器
- 域/批：A1/B04｜判据：UNX-F0061-J1 构造 100 组合成冲突样本，仲裁结果与设计优先级矩阵 100% 一致，冲突有账｜纯功能行数：320 行（优先级矩阵与比较器 90 + 归并算法 130 + 冲突记账 60 + 版本化接口 40；测试段不计）｜状态：[已深化]
- **定位**：三源内存描述不一致时的唯一裁决入口，输出一份带冲突账的权威合并图。
- **语义边界**：只做"区间重叠/类型不一致/边界不齐"三类冲突的裁决与记账；不做区间归并后的分类（F0063）、不做对齐（F0067）。
- **依赖与嫁接源**：消费 F0008 三源合并框架产出的原始三源列表；嫁接 Linux `e820__update_range` 的区间插入-覆盖语义。
- **风险与回退**：优先级矩阵误判会静默吞内存——任何冲突必须落账并可导出；矩阵不可解释时回退"取最保守（可用变保留）"策略。
- 正文：实现路径分三步。第一步定义冲突模型：把每个源产出规范化为 `(base, len, type, source_id, confidence)` 五元组，重叠检测用扫描线，两两相交即生成冲突记录。第二步建优先级矩阵：UEFI GetMemoryMap > ACPI 表 > E820，同源内以 confidence 排序；对"一边可用一边保留"的冲突取保守侧，对"类型同为可用但范围不同"取交集并记账。第三步归并输出：按地址排序做区间合并，同类型相邻合并，输出区间列表 + 冲突账双产物，冲突账含冲突双方完整五元组与裁决理由编号。与现存内核衔接点：合并图即 F0066 快照、F0071 早年分配器、F0072 页账本初始化的共同输入，接口以版本化结构体传递。与 Windows 对照：WinNT 的 `MmGetPhysicalMemoryBlocks` 只取 BIOS 传递结果、无多源仲裁；本条对应其 Job 环节前 `KiMemoryInitialize` 的物理图固化步骤，但本工程显式化冲突账是超出 Windows 的设计。判据 UNX-F0061-J1 的复测方式：构造 100 组人工标注的冲突样本（含 E820 旧式脏数据、UEFI 重复映射、ACPI SRAT 缺失三类），断言裁决输出与矩阵推演逐条一致，冲突账条数与注入冲突数一致。

### UNX-F0062 · 保留区白名单与守护
- 域/批：A1/B04｜判据：UNX-F0062-J1 SMM/ACPI NVS/TPM/TSEG 等保留区入白名单，分配器申请越界 10 万次全部拒绝｜纯功能行数：300 行（白名单构建 110 + 守护钩子 90 + 越界审计 60 + 接口 40；测试段不计）｜状态：[已深化]
- **定位**：把固件声明与体系结构规定的保留区固化为白名单，对一切物理分配做准入拦截。
- **语义边界**：白名单只覆盖"分配拦截"视角；Reclaim 可回收语义归 F0063，热插拔隔离归 F0069。
- **依赖与嫁接源**：输入为 F0061 合并图；嫁接 Linux `memblock_reserve` 与 `reserve_mem_type` 语义。
- **风险与回退**：白名单过宽浪费内存、过窄引发 SMI 风暴——构建时对每条记录标注来源与置信级；守护失效时以全局只读兜底并告警。
- 正文：实现路径分三步。第一步白名单构建：从合并图筛出 Reserved/ACPI NVS/MMIO/Unusable 类型区间，再叠加体系结构硬保留（SMM TSEG 需经 MCFG 与 PCI 配置空间交叉核对、EBDA、VGA VRAM），每条记录附来源编号。第二步守护钩子：在 F0071 早年分配器的分配入口前置白名单重叠检查，`overlap(alloc, whitelist)` 非空即拒绝，拒绝事件入越界审计账（地址、长度、调用方标签）。第三步审计与演练：审计账支持按调用方聚合统计，提供白名单转储命令供 ktest 断言。与现存内核衔接点：守护钩子以函数指针注入 F0071 分配器，使内核后续任何子系统复用同一拦截；白名单同时供 F0073 空洞检测做参照系。与 Windows 对照：对应 NT 的 `MmIsAddressValid` 体系之下的物理层 `MmPhysicalMemoryBlock` 排除逻辑与 SMM TSEG 处理（Windows 由 BIOS 经 e820/EFI 保留，内核不二次核验）；本工程显式 TSEG 交叉核对是加固项。判据 UNX-F0062-J1 的复测方式：ktest 注入 10 万次随机区间申请（坐标故意覆盖白名单边界两侧），断言拒绝率 100%、审计账条数等于拒绝次数、放行的申请与白名单交集为空。

### UNX-F0063 · ACPI Reclaim/NVS 区分类账
- 域/批：A1/B04｜判据：UNX-F0063-J1 Reclaim 区在 ACPI 初始化后可回收进 PMM，NVS 区永不可用，两类零混用｜纯功能行数：240 行（分类账构建 80 + 生命周期状态机 70 + 回收通道 60 + 断言 30；测试段不计）｜状态：[已深化]
- **定位**：给 ACPI 两类特殊内存一个显式生命周期账：Reclaim 可在 AML 解释器成年后回收，NVS 终身不可碰。
- **语义边界**：只管 ACPI 专属两类型；普通 Reserved 由 F0062 管，回收动作只面向 PMM 账本不改变页表。
- **依赖与嫁接源**：输入合并图 + F0002 ACPI 表解析的 FACP 版本号；嫁接 Linux `acpi_ex_enter_interpreter` 后 `acpi_os_map_memory` 生命周期语义。
- **风险与回退**：过早回收 Reclaim 会让 AML 方法崩溃——回收触发点绑定"ACPI 初始化完成事件"而非时间；误回收时提供冻结开关（cmdline `acpi.no_reclaim`）。
- 正文：实现路径分三步。第一步建账：扫描合并图所有 `ACPI Reclaimable` 与 `ACPI NVS` 区间，登记为两条独立分类链表，每条含物理区间、AML 引用计数占位、状态（held/released）。第二步状态机：初始全 held；当 F0001 链路上 ACPI 初始化宣告完成（所有表已解析、AML 命名空间 F0044 树构建完毕、\_GPE/\_SB 方法已加载），状态机发出 reclaim 许可事件，Reclaim 链表逐区转 released 并调用 PMM 登记接口把区间还给可用池；NVS 链表无 release 转移，永固白名单。第三步回收通道与断言：回收按区间粒度进行、逐区记账，任何对 NVS 的分配请求被 F0062 拦截；ktest 提供两类零混用断言。与现存内核衔接点：reclaim 事件由 ACPI 初始化完成回调触发（B03 F0044 树构建收口点），回收页直接进入 F0072 页账本的可用池。与 Windows 对照：NT 的 `ACPI.sys` 在 `ACPIInitialize` 完成后同样释放 Reclaim 区，NVS 交由固件保留；Windows 语义在 ACPI 规范 14.2 有明文，本条是规范语义的内核侧显式实现。判据 UNX-F0063-J1 的复测方式：ktest 模拟 ACPI 初始化完成事件前后分别尝试分配 Reclaim/NVS 区，断言事件前两类均拒绝、事件后 Reclaim 可分配且 NVS 仍拒绝、分类账状态转移与事件序列一致。

### UNX-F0064 · 低 1MB 遗留区布局图
- 域/批：A1/B04｜判据：UNX-F0064-J1 EBDA/VGA/BIOS 区间标记落账，遗留驱动借用申请可查可拒｜纯功能行数：240 行（布局表 80 + 借用登记 80 + 断言 80；测试段不计）｜状态：[已深化]
- **定位**：给实模式遗物（IVT/BDA/EBDA/VGA VRAM/BIOS ROM）绘制权威布局图，管理其短暂借用窗口。
- **语义边界**：只管 <1MB 区间；1MB 以上 BIOS 保留归 F0062；VGA 字体拷贝动作归 B06 显示通道。
- **依赖与嫁接源**：BDA 0x400 起读 EBDA 段基址；嫁接 Linux `legacy_reserve` 与 `video-bios` 保留语义。
- **风险与回退**：EBDA 大小字段可能撒谎——上限钳位并落账；借用未释放时以超时强制回收并告警。
- 正文：实现路径分三步。第一步绘制布局：硬编码体系结构布局（0x000–0x3FF IVT、0x400–0x4FF BDA、0xA0000–0xBFFFF VGA、0xC0000–0xFFFFF 适配器/BIOS ROM），运行期读 BDA 0x40E 得 EBDA 段、读 0x413 得常规内存顶并钳位校验，全部条目入布局表。第二步借用登记：提供 `legacy_borrow(range, tag)` 接口给 VGA 字体拷贝、SMP trampoline（B17）、BIOS 调用残段等短暂借用者，登记窗口与用途标签，`legacy_release` 注销；借用区临时从可用池摘除。第三步断言：布局表落账可导出，借用-注销配对核验，超窗强制回收写审计。与现存内核衔接点：trampoline 起步（B17 F0341+）是最大借用方，低 1MB 布局图为其实模式页与 reboot 残段提供锚点；reboot 路径（A1 后期批）也依赖此图恢复实模式所需映射。与 Windows 对照：NT 对低 1MB 由 `hal!HalpMapPhysicalMemory` 按需映射并全生命周期保留，无借用窗口概念；本工程显式借用-注销是资源更紧凑的设计。判据 UNX-F0064-J1 的复测方式：ktest 读布局表断言六类区间边界与规范一致；注入 100 次借用/注销序列，断言窗口外分配被拒、配对注销后区间回到可用池、泄漏借用被超时回收。

### UNX-F0065 · E820 桥接层（BIOS 兼容路径）
- 域/批：A1/B04｜判据：UNX-F0065-J1 无 EFI 环境走 E820 时三源合并降级可跑，类型映射与 Linux 语义对照一致｜纯功能行数：260 行（E820 采集 90 + 类型映射 70 + 降级融合 60 + 断言 40；测试段不计）｜状态：[已深化]
- **定位**：为 CSM/Legacy BIOS 引导路径采集 E820 并翻译为统一内存图语汇，保证三源合并框架在无 EFI 时降级可用。
- **语义边界**：仅当引导源为 BIOS 时激活；UEFI 路径永不进入本条；翻译不做任何纠偏（原始性优先），纠偏归 F0061 仲裁。
- **依赖与嫁接源**：int 15h ax=E820 三次调用协议（ Continuation ebx）；嫁接 Linux `arch/x86/boot/memory.c` 的 `detect_memory_e820` 逐条重试语义。
- **风险与回退**：不同 BIOS 返回脏数据（零长/乱序/overlap）是常态——逐条校验、脏条目记账不中断；采集彻底失败回退 int 88h/0x413 老路径并告警降级。
- 正文：实现路径分三步。第一步采集循环：实模式残段或引导器转交的 E820 表遍历，逐条做 `(base,len)` 溢出与零长校验，脏条目入降级账；支持 ebx 续读直到 CF=1。第二步类型映射：E820 type 1→Usable、2→Reserved、3→ACPI Reclaim、4→ACPI NVS、5→Bad、其余→Reserved，映射表与 Linux `e820_type` 逐项对照写注释，双向断言。第三步融合：把翻译后的区间以 source_id=E820 注入 F0061 仲裁器，本条自身不做合并；ktest 用固定 BIOS 模拟表断言全链输出。与现存内核衔接点：BIOS 路径是 F0001 双路固件交接（EFI/BIOS 双路）中 BIOS 支路的内存采集终点，产出与 UEFI 路径同构的五元组序列。与 Windows 对照：NT 5.x 时代 `ntoskrnl!KiRosFilterRam` 类似逻辑由 `ntldr` 的 `BlMemoryInitialize` 完成 E820 解析；本工程把解析从 boot 阶段挪到内核早年，保持两路固件汇合点一致。判据 UNX-F0065-J1 的复测方式：ktest 注入 5 组典型 BIOS 表（干净/含 overlap/含零长/乱序/脏 type），断言类型映射逐条正确、脏条目入账不中断、融合后仲裁输出与手推一致。

### UNX-F0066 · 内存图快照落盘与序列化
- 域/批：A1/B04｜判据：UNX-F0066-J1 合并后内存图序列化落盘，重启后可导出与上次引导 diff｜纯功能行数：260 行（TLV 序列化 100 + 快照区读写 80 + diff 引擎 80；测试段不计）｜状态：[已深化]
- **定位**：把合并图固化为带版本 TLV 快照，跨引导可 diff，为"三机 50 次引导零差异"主判据提供数据底座。
- **语义边界**：只序列化合并图本体 + 冲突账摘要；页账本运行期快照归 F0077；落盘介质为保留内存区（非磁盘），磁盘持久化属存储域。
- **依赖与嫁接源**：TLV 编码自研（tag 1 字节/len 2 字节/value）；嫁接 Linux `kexec` 的 crash_notes 固定区思想。
- **风险与回退**：快照区被下游误用会毁证据——白名单入册；序列化版本不匹配时拒绝 diff 并告警，不猜测解析。
- 正文：实现路径分三步。第一步编码：合并图逐区间编码 TLV（base/len/type/source/confidence），头部含魔数、版本、区间数、冲突账摘要哈希；编码器零分配、静态缓冲。第二步落盘：在物理图高位划一块 64KB 快照保留区（白名单入册），写入前校验旧快照魔数以决定覆盖或滚动双缓冲，写后 CRC32 校验。第三步 diff：下次引导读到同版本快照即逐区间比对，产出"新增/消失/类型变/边界移"四类差异报告；版本不符则只存不比。与现存内核衔接点：快照供 F0095 随机化指纹、F0088 BootManifest 引用，也供 B13 早传十二步携带。与 Windows 对照：Windows 无原生跨引导物理图 diff（调试靠 windbg 手工）；本条对标 WinDbg `!physmem` 的数据但自动化为引导行为判据，是"50 次引导零差异"主轴的物理面证据链。判据 UNX-F0066-J1 的复测方式：ktest 模拟两次引导（第一次写快照、第二次读回 diff），断言 CRC 通过、人工注入一处类型变更被 diff 捕获、版本不符走拒绝路径。

### UNX-F0067 · 可用区边界对齐器
- 域/批：A1/B04｜判据：UNX-F0067-J1 4K/2M/1G 三档对齐后的可用区零跨界，边界统计落账｜纯功能行数：240 行（三档对齐 100 + 损耗统计 70 + 断言 70；测试段不计）｜状态：[已深化]
- **定位**：把可用区间按 4K/2M/1G 三档向上/向下取整，产出三套对齐视图与损耗账。
- **语义边界**：只做边界几何对齐；大页"值不值得映射"的决策归 F0068；对齐不改变类型。
- **依赖与嫁接源**：嫁接 Linux `memblock_align_up/down` 与 `find_memory_block` 边界语义。
- **风险与回退**：对齐把可用区间切碎可能产生 <4K 碎片区——碎片区并入损耗账不丢弃；全区间小于一页时告警。
- 正文：实现路径分三步。第一步三档扫描：对合并图 Usable 区间分别做 `align_up(base, 2^n)` 与 `align_down(end, 2^n)`，得到 4K/2M/1G 三档视图，逐档断言 `aligned_base % 2^n == 0` 且 `aligned_end % 2^n == 0`。第二步损耗统计：每档记录"被切掉的头部/尾部字节数"与"整区间小于档位颗粒而整条弃用"的区间数，损耗账按档位聚合落盘，供 F0068 计算大页覆盖率分母。第三步一致性核验：4K 视图必须包含 2M/1G 视图（子集关系断言），防对齐方向写反。与现存内核衔接点：2M/1G 视图直接供 B16 初始页表族选粒度，4K 视图是 F0072 页账本初始化的区间来源。与 Windows 对照：NT 的 `MiGetPhysicalAddress` 体系按需 4K 映射、大页仅用于 PTE 模板与特殊池（`MiLargePage` 专用路径）；本工程在物理图阶段就备齐三档视图让页表构建零猜测，优于 Windows 的运行期试探。判据 UNX-F0067-J1 的复测方式：ktest 构造含奇数边界（0x123456789 级）区间组，断言三档视图边界模零、4K⊇2M⊇1G 子集关系、损耗账与手推差值一致、总可用量守恒（对齐前 = 对齐后 + 损耗）。

### UNX-F0068 · 大页可用性预判
- 域/批：A1/B04｜判据：UNX-F0068-J1 2M/1G 大页可覆盖区比例落账，预判结果与后续实际映射抽样一致｜纯功能行数：260 行（覆盖计算 100 + 预判账 80 + 抽样断言 80；测试段不计）｜状态：[已深化]
- **定位**：统计各内存区能被 2M/1G 大页覆盖的比例与候选清单，让 B16 页表构建"先知先觉"。
- **语义边界**：只做覆盖预判，不做页表写；CPU 大页能力位（PSE/1G-cap）核对以输入参数传入，能力位读取属 CPU 域。
