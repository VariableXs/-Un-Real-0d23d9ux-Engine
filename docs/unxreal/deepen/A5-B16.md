## F3501 跟踪点总设计（TP 注册表/编译期埋点/运行时开关）

**定位**：静态跟踪点（tracepoint/TP）总纲：编译期埋点 + 运行时开关 + 结构化事件流——观测面第二块基建，为 B17 动态探针与 B18 剖析提供事件源底座。
**语义边界**：本条冻结语义与分工；注册协议 F3502、编解码 F3503、过滤 F3505、会话 F3507。TP 与日志分工：日志=文本流（人读、过程叙述）、TP=结构化事件流（机读、字段化）——两流不合并（F3516 划界）；TP 埋点**绝不改变被观测代码语义**（观测不扰动红线——禁用态零行为差异）。
**判据**：
- J1：M-259 TP 全链路：埋点 → 开关启用 → 负载编码 → 消费端解码 → 字段逐项可读——全链零失真。
- J2：分工声明落判据（禁用态零开销 ≤5 拍——F3509 对账锚；文本流与事件流的可读性对照用例）。
**纯功能行数**：320（总纲矩阵 ~110 + 全链用例 ~110 + 分工红线 ~100）
**依赖与嫁接源**：F3481 日志五级（分工对端）；F3482 三维过滤（谓词过滤断代源——TP 用字段谓词不用位图）；F3406 域标识（事件归属）；F3450 预算三线（启用态预算对账）。
**风险与回退**：埋点滥用（处处埋点→热路径税）——回退：埋点规约 F3510 执法（密度上限）+ 禁用态 5 拍预算实测（超限即违例）；事件语义漂移（字段悄悄改义）——回退：负载布局版本化（F3517）+ 布局表单一真源。
**正文**：TP 三层结构（判据行内嵌）：①**埋点层**——被观测代码处的宏调用 `tp!(sched.switch, prev, next)`，编译期展开为"开关位测 + 事件提交调用"两段——开关关闭时只有位测（F3509 的 5 拍）；②**注册层**——每个 TP 一条描述符入注册表（F3502），启动期链接收集；③**消费层**——reader 订阅（F3506）从 TP ring（F3516）取事件。与日志的分工论证（判据行展开）：日志回答"发生了什么事"（人读、含叙述、级别驱动），TP 回答"系统状态机怎么走的"（机读、纯字段、会话驱动）——同一现场两种出口（锁争用现场：日志说"锁 L 争用加剧"，TP 给 `{lock=L, waiter=t3, wait_us=12}` 结构化三元组供 B21 压力机直接聚合）——文本流可以被截断折叠（流可丢），事件流必须可聚合（字段不可含糊）——两者共享转储后端（Runner）但语义分层。为什么静态埋点先行、动态探针殿后（判据行论证）：静态埋点零风险（位置编译期定死、语义评审期冻结）、动态探针有安全面（F3524 不可探针区）——观测面建设次序与风险等级一致；且静态 TP 是 B21 锁压力机/F3513 锁事件的直接数据源，检测器联证链（F3356→TP→压力机复现）由此起步。Windows 对照：ETW 的 provider/event 模型同构（provider≈域、event≈TP、keyword≈域组开关）——我们学它的 manifest 模式（布局先于事件），弃它的运行时注册复杂度。M-259 复测：全链路五步逐项断言 + 分工对照用例 + 禁用态拍数。

## F3502 跟踪点注册协议（TP 描述符/域内唯一名/注册期校验）

**定位**：TP 注册协议：描述符结构冻结 + 注册期三维校验（重名/跨域撞名/布局合法）——注册表是 TP 全系统的唯一真源。
**语义边界**：只做注册与校验（事件提交路径 F3503/F3504）；注册**只在启动期**（运行期动态注册是探针的事——F3522——静态 TP 注册期冻结是"语义评审期冻结"红线的结构保障）。
**判据**：
- J1：描述符字段冻结（`{name, dom, payload_layout, default_state}` 四字段——判据行内嵌）；M-260 注册拒绝三例（域内重名/跨域同名/布局越界）。
- J2：注册表容量与序（TP 总数上限 256/域内序号连续无空洞——自检 F3519 的前置）。
**纯功能行数**：320（描述符结构 ~110 + 校验逻辑 ~110 + 用例 ~100）
**依赖与嫁接源**：F3501 总纲（三层结构）；F3406 域标识（dom 字段编码）；F3517 命名规约（name 合法性判据源）；F3519 自检（注册表完整性后置复核）。
**风险与回退**：注册表溢出（256 上限被埋点狂潮击穿）——回退：注册期容量断言（第 257 个注册直接失败——失败显性化，绝不静默截断）+ 规约 F3510 密度上限双层扼流；描述符手写错（布局字节数与字段总和不符）——回退：布局合法性校验（字段偏移自洽断言——错一个 bit 都进不了注册表）。
**正文**：描述符（判据行内嵌）：`TpDesc { name: &str(三段式), dom: u8, layout: &LayoutDesc, default_state: bool }`——layout 指向 F3503 布局表（单一真源——描述符不复制字段，只引用）；default_state 决定启动时开关初值（绝大多数 TP 默认关——默认开的只有 sched 与 irq 两族调度关键事件，供 B17 度量启动即用）。三维校验（判据行原文）：①域内唯一（name 在 dom 内查重——线性 256 上限，启动期一次性成本可忍）；②跨域撞名拒绝（TP 名含域前缀，跨域同名=前缀冲突=命名规约破坏——直接拒绝，防"别人域的语义挂进我域"的观测污染）；③布局自洽（字段偏移累加=布局总长、对齐合法、封顶 64B——三项断言）。为什么启动期冻结、拒绝运行期注册（判据行论证）：静态 TP 的价值在"语义可评审"——编译期埋点+启动期注册=每次构建的 TP 全集可 diff（上次构建 214 个 TP、本次 216 个、新增两个是谁——接入表 F3518 的 diff 视图直接回答）；运行期注册让 TP 集合不可审计（观测面自己变成动态面=观测不可信）——动态需求全部导向 B17 探针（有安全边界管理）。注册序与域内序号：注册按链接序、域内按注册序编号（稳定序——同构建内可复现；跨构建不承诺——TP 引用一律经名字不经序号）。Windows 对照：ETW manifest 注册同样是部署期冻结。M-260 复测：三拒绝例逐项 + 容量断言 + 序号稳定。

## F3503 跟踪点负载编解码（payload 布局/类型分派/定长封顶）

**定位**：TP 负载编解码：布局表驱动的类型分派编解码器（四类封闭类型 + 64B 封顶 + 截断可辨认）——事件流的字段化基石。
**语义边界**：类型集**封闭**（整数/指针/短串/枚举四类——开放类型是堆与间接调用的温床，与 B15 log! 宏的封闭格式符同律）；只做编码与解码（过滤 F3505 在编码前）。
**判据**：
- J1：编解码往返：布局表 → 编码 → 解码 → 字段逐项相等（四类型全覆盖）；M-261 四类各 2 变体往返全绿。
- J2：封顶语义（>64B 负载：截断 + TRUNC 标记——与 B12 截断可辨认同律，解码端可辨"截过"）。
**纯功能行数**：340（布局表结构 ~120 + 编解码器 ~120 + 往返用例 ~100）
**依赖与嫁接源**：F3502 描述符（layout 引用）；B15 F3485 封闭格式符（同律源）；B12 截断可辨认（TRUNC 标记先例）；F3517 版本化（布局表版本号挂点）。
**风险与回退**：布局漂移（同 TP 两个构建的布局不同→解码错位读脏数据）——回退：布局表带版本号，事件头内嵌版本（解码器版本不匹配→拒读+显性报错，绝不猜）；短串超长（32B 上限被超）——回退：编码期截断+TRUNC（与封顶同协议——截断永远是"标记过的截断"）。
**正文**：布局表（判据行内嵌）：`LayoutDesc { ver: u8, size: u8, fields: &[FieldDesc] }`，`FieldDesc { name, off: u8, kind: FieldType }`——kind 四类（判据行原文）：`U64`（整数统一 8B——u8/u32 编码期零扩展到 u64，解码端按原宽读——编码统一简化分派）、`PTR`（指针 8B，仅记值不解引用——解引用是隐私与安全双重风险点，TP 负载里只有地址没有内容）、`STR32`（短串 ≤32B 定长槽，剩余填零，TRUNC 位在头）、`ENUM`（枚举 u16+封闭词表索引——词表随布局表版本化）。编码路径（判据行原文）：按 fields 序逐字段拷入 64B 栈缓冲（零堆——负载缓冲是栈上固定槽，写满即截断）→ 整体提交 F3516 ring（带 8B 记录头：tp_id/seq/ts_lo/len）。解码对称：同一布局表反向逐字段读——编码解码共享 LayoutDesc（两套实现一个真源——漂移在结构上不可能）。为什么 64B 封顶（判据行论证）：TP ring 8KB/CPU、64B 上限=每环 ≥126 事件——事件密度与缓冲寿命的平衡点；>64B 的现场需求（大结构体快照）正确出口是"TP 记指针+快照走 dump 通道"（B23 转储）——TP 是指针化的轻事件不是全量快照器（职责边界判据行内嵌）。枚举词表版本化的红利：ENUM 解码总是词表查名（人读友好），词表只增不改（版本化规则 F3517——旧事件的词表索引永远有效）。Windows 对照：ETW 的 TDH 类型系统同类封闭思路。M-261 复测：四类往返 + 截断标记 + 版本不匹配拒读 + 零堆断言（栈缓冲尺寸编译期断言）。

## F3504 跟踪点开关位图（每 TP 独立 enable/域组开关）

**定位**：TP 开关双层模型：每 TP 独立位 + 域组位（`enabled = indep | domain_group`）——运行时可变（原子单字改写），控制观测面开度。
**语义边界**：开关**只控制"是否提交事件"**（谓词过滤 F3505 是提交后的二次筛选——开关拒的连编码都不做，谓词拒的已编码）；ERROR 快照联动（F3508）**绕过独立位**（快照是保真语义——但域组位仍生效）。
**判据**：
- J1：双层语义矩阵（独立×组四种组合的启停行为与手算一致）；M-262 矩阵验证（含运行期改写后行为即时生效断言）。
- J2：改写原子性（位图 ≤32 位单字——AtomicU32——与 B15 Filter3D 同律）。
**纯功能行数**：300（位图结构 ~100 + 判定逻辑 ~100 + 矩阵用例 ~100）
**依赖与嫁接源**：F3502 注册表（位下标=域内序号）；B15 F3482 Filter3D（原子位图同律）；F3508 快照旁路（独立位豁免的例外声明）。
**风险与回退**：开关竞态（热路径读×控制路径写）——回退：单字原子读写（撕裂不可能——32 位单字）；误开风暴（域组位全开→事件洪峰）——回退：域组开启用**警告式 API**（`enable_group` 返回该组 TP 数与预估事件率——调用方确认后生效）+ F3516 缓冲覆盖兜底。
**正文**：位图布局（判据行原文）：`TpSwitch { indep: AtomicU32, group: AtomicU32 }`——indep 每 TP 一位（域内序号下标）、group 每域一位（域标识 F3406 下标——32 域容量，与 B15 模块位图同容量声明）；启用判定 `enabled = (1<<tp_idx) & indep | (1<<dom) & group`（一次位测一次或——禁用态预算 5 拍的构成：位测 2 + 或 1 + 分支 1 + 调用序 1）。双层设计的理由（判据行论证）：独立位是"精查单点"（排查某一条事件）、域组位是"面扫整域"（观察一个子系统的全貌）——两层正交组合避免"开 40 个独立位"的手工灾难；与 B15 Filter3D 的同构与差异：日志过滤是三维（级别×域×模块）、TP 开关是双层（独立×域组）——差异的原因是 TP 没有"级别"维（事件不等价于日志级别——事件是事实不是判断），域组位承担了日志域位的角色。ERROR 快照的独立位豁免（判据行细辨）：F3508 的 ERROR 现场快照即使该 TP 独立位关闭也触发——因为快照服务的是"事后无法复现的现场"（保真语义高于采样语义）；但域组位**不豁免**（域被整体静音=运维明确表态不要该域数据——静音动作本身有操作日志留痕，B15 MUTE 同律）。运行期改写接口：`set_tp/set_group` 双入口，控制平面收口于 F3507 会话（会话持有目标位图快照，退出会话恢复原状——观测会话不留下永久开关状态污染）。M-262 复测：四组合矩阵 + 改写即时生效 + 快照豁免边界 + 会话恢复。

## F3505 跟踪点谓词过滤（字段比较式 filter）

**定位**：TP 谓词过滤器：字段比较式（==/!=/>/</范围五式封闭）——编码前筛选（拒绝不付序列化税），会话级挂载。
**语义边界**：谓词五式**封闭**（开放表达式求值=解释器=热路径不可承受）；字段引用经布局表偏移（无反射无名字查表——挂载期解析一次）；谓词在**编码前**判定（先谓词后编码——被拒事件连 64B 编码都不发生）。
**判据**：
- J1：五式语义与边界（含边界值：相等边界/范围开闭端）；M-263 命中/拒绝双向验证（拒绝路径拍数实测——无编码开销证据）。
- J2：谓词挂载解析（字段名→偏移在挂载期一次解析——热路径零查表）。
**纯功能行数**：320（谓词结构 ~110 + 求值器 ~110 + 用例 ~100）
**依赖与嫁接源**：F3503 布局表（偏移真源）；F3507 会话（谓词生命周期挂靠）；F3504 开关（先开关后谓词的次序声明）。
**风险与回退**：谓词复杂度失控（谓词链长→求值税）——回退：单 TP 谓词上限 4 条（挂载期拒绝第 5 条——显性化）；类型不匹配谓词（拿 STR 字段做 > 比较）——回退：挂载期类型检查拒绝（不求值期才发现）。
**正文**：谓词结构（判据行原文）：`Predicate { field_off: u8, kind: FieldKind, op: PredOp, val: u64 }`——op 五式封闭（`EQ/NE/GT/LT/RANGE`——RANGE 带 lo/hi 两值槽，开闭端显式标记）；挂载期流程：字段名查布局表 → 偏移与类型冻结 → 类型-操作匹配校验（GT/LT/RANGE 仅 U64/PTR——序语义只在有序类型上有定义；EQ/NE 全类型）→ 编译为求值闭包（定长结构——无堆）。求值路径（判据行原文）：读字段（按 off 从 64B 原始负载读）→ 单比较 → 布尔——全程无查表无分配（热路径三拍级）；**先谓词后编码**的次序（判据行论证）：谓词的目的是"减量"（高频率 TP 只看特定值——如 lock_contend 只看 wait_us>1000 的重争用）——若先编码后过滤，被拒事件已付 64B 拷贝税（过滤反而加了总开销）；编码前判定使拒绝路径只剩"开关位测+谓词三拍"——减量才真的减。为什么五式封闭不做表达式（判据行论证）：`wait_us>1000 && lock==L2` 这类复合需求，正确姿势是挂两条谓词（AND 语义）而非内嵌表达式语言——表达式语言需要解析器/优先级/短路求值（热路径解释器，与零分配零查表誓不两立）；AND 语义覆盖 95% 实战（OR 需求=两个 TP 各挂一条）。谓词与 F3504 的次序：开关位测（5 拍）→ 谓词求值（~3 拍/条 × ≤4）→ 编码——三层递进的漏斗各司其职。M-263 复测：五式×边界值矩阵 + 拒绝路径拍数 + 类型不匹配挂载拒绝 + AND 链。

## F3506 跟踪点消费端协议（reader 订阅/缓冲移交）

**定位**：TP 消费端四步协议：订阅→移交→确认→回收——reader 与 ring 的握手契约，移交批零丢失零重复（序号校验）。
**语义边界**：v1 **单会话单 reader**（多 reader 是会话隔离问题——F3507 多会话各带 reader）；reader 是**消费者不是过滤器**（谓词在生产端已筛——reader 全收）；确认前移交批**只读**（ring 不覆盖待确认区——待确认区是覆盖禁区）。
**判据**：
- J1：四步握手全流程；M-264 移交往返（N=1000 事件分 10 批 → reader 逐批确认 → 全程序号连续无重无缺）。
- J2：覆盖禁区语义（待确认区被写者推进越过的计数恒为 0——禁区协议有效性断言）。
**纯功能行数**：300（协议状态机 ~100 + 移交实现 ~100 + 用例 ~100）
**依赖与嫁接源**：F3516 TP ring（缓冲本体——禁区实现的物理基础）；B15 F3483 seq 代际（序号校验同律）；F3507 会话（reader 生命周期归会话）。
**风险与回退**：reader 卡死（确认迟迟不来→待确认区无限增长→ring 被禁区锁死）——回退：确认超时（1 个水位周期未确认→会话转 PAUSED+待确认区强制释放+GAP 标记——卡死降级为断流，绝不拖死生产端）；移交批过大（单批内存峰值）——回退：批上限 128 事件。
**正文**：四步协议（判据行原文）：①**订阅**——reader 向会话注册（回调指针+批上限）；②**移交**——ring 攒满一批（或水位周期到）→ 把 `[rd_base, wr)` 可读窗口切成批（每批 ≤128 事件）移交 reader，同时 rd_base 推进到窗口尾**但进入"待确认"状态**（推进分两级：移交线/确认线——判据行给双线设计）；③**确认**——reader 处理完批→`ack(batch_end_seq)`→确认线推进→该区解锁可覆盖；④**回收**——确认线之前的缓冲区归还写者循环使用。零丢失零重复的证明（判据行论证）：移交批携带 `(start_seq, end_seq)`，reader 校验连续性（本批 start==上批 end+1——不等即缺口→GAP 上报——流可丢红线下的诚实缺口标记，绝不静默补齐）；不重复由单 reader+序号单调保证（v1 无重传——丢的标 GAP 不补发，补发是协议复杂度黑洞）。覆盖禁区（判据行论证）：待确认区（移交线与确认线之间）禁止覆盖——写者推进 wr 遇禁区时的行为是**丢弃新事件+DROPPED 计数**（不覆盖旧数据——reader 正在读的物理页不能被踩）而非阻塞写者（阻塞=观测拖垮被观测——红线）；禁区大小上限 2KB（ring 8KB 的 1/4——禁区满即强制释放最老待确认批+GAP——确认超时的兜底兄弟）。为什么双线推进（判据行论证）：单线（移交即确认）省协议但 reader 慢时数据被覆盖（读到的页被踩=撕裂读）；双线的代价仅是 1/4 缓冲换"reader 视野内数据物理稳定"——观测可信性优先。Windows 对照：ETW real-time 消费 vs 缓冲文件模式，双线≈缓冲模式的 flush-ack。M-264 复测：10 批往返连续性 + 禁区零越界 + 超时降级 + DROPPED 计数对账。

## F3512 中断跟踪点（irq enter/exit 与潜伏期原始事件）

**定位**：中断 TP 成对事件：irq_enter(irq)/irq_exit(irq)——中断潜伏期度量的原始事件，成对记账（per-CPU 深度计数）保证流可验。
