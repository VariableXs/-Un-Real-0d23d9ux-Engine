### UNX-F2421 · order-0 页快速路径
- 域/批：A4/B02｜判据：UNX-F2421-J1 单页分配 p99 时延落账且与高阶路径比值 ≤0.5，10^6 次分配释放对账零泄漏｜纯功能行数：280 行（快路径判定 100 + 直出直还 90 + 时延账 90；测试段不计）｜状态：[已深化]
- **定位**：order-0（4KB 单页）是分配谱里频次最高的一档，快路径让单页分配绕过阶遍历直出直还——它是后续每 CPU 池（B03）的"无池形态基线"。
- **语义边界**：只做 order-0 直出直还；不做每 CPU 池（F2441 起）、不做零化（F2416 覆盖）。
- **依赖与嫁接源**：依赖 F2409/F2410 拆合原语；嫁接源为 Linux 单页快路径（`rmqueue` 的 order==0 分支）语义，实现自研。
- **风险与回退**：快路径绕过统计导致直方图失真——快路径同样计数（F2427 消费），统计闸在出口单点，绕路不绕账。
- 正文：实现路径分三步。第一步快路径判定：请求 order 为 0 时直接取本区 order-0 链首，链空才落通用路径，判定为一次分支比较；第二步直出直还：释放 order-0 时先走合并探测（F2410），合并不成即回挂链首（LIFO 提高缓存局部性），直还路径与通用路径账同源；第三步时延账：p99 时延打点（时间基用 A2 计时账），与通用路径 p99 比值落账，比值是快路径有效性的直接证据。与现存内核衔接点：`pmm::alloc_page` 现存单页语义收编为快路径入口，签名不变。与 Windows 对照：Windows 的单页分配走 lookaside 形态快路径，本条无池基线的快路径是其前置形态。判据 UNX-F2421-J1 的复测方式：真机 10^6 次对账零泄漏，p99 比值 ≤0.5，直还计数账与释放账配平。

### UNX-F2422 · order-1–4 中阶分配行为
- 域/批：A4/B02｜判据：UNX-F2422-J1 四档中阶各 10^4 次分配释放对账零偏差，中阶降级率账可导出｜纯功能行数：300 行（中阶行为矩阵 120 + 降级率账 90 + 对账面 90；测试段不计）｜状态：[已深化]
- **定位**：order-1–4（8KB–64KB）是内核 slab 大对象与 IO 缓冲的主消耗档，本条把四档行为建成矩阵账（命中/拆分/降级三态计数），中阶的健康度可量化。
- **语义边界**：只做中阶行为账与矩阵；不做分配策略改动（路由归 F2428）、不做 slab 对接（heap 域防重）。
- **依赖与嫁接源**：依赖 F2409/F2411；嫁接源为域内 buddy 语义，无外部上游。
- **风险与回退**：中阶被高阶请求反复拆薄——拆分来源账记录高阶拆分去向，供 F2430 策略评估。
- 正文：实现路径分三步。第一步行为矩阵：order-1–4 各建（命中数/拆分数/降级数）三列账，分配完成时按实际路径计数；第二步降级率账：降级率 = 降级数 / 请求数，按阶分列可导出，连续窗口滑动平均防抖；第三步对账面：每档 10^4 次分配释放循环后，该阶 free 计数回基线（守恒），偏差即泄漏或双计。与现存内核衔接点：`pmm.rs` 分配出口插桩计数，路径不变。与 Windows 对照：Windows 池分档统计（`poolused`）同粒度呈现各档用量，本条多出路径三态维度。矩阵三列账与 F2427 直方图同源勾稽（每笔分配必落命中/拆分/降级三态之一，三态合计=请求数逐窗口核对恒等），滑动平均窗宽与采样点距参数入 F2513 参数册（默认 64 次一窗、逐千次采样点），跨机型对比按同窗宽对齐，窗宽差异在导出 JSON 显式携带防误读。判据 UNX-F2422-J1 的复测方式：四档各 10^4 次对账零偏差，降级率账三机型齐全可导出。

### UNX-F2423 · order-5–10 高阶分配与 2M 块
- 域/批：A4/B02｜判据：UNX-F2423-J1 order 9/10 分配 10^3 次成功率与降级账落档，2M 块对齐断言（2MB 对齐零例外）｜纯功能行数：320 行（高阶路径 110 + 对齐断言闸 110 + 成功率账 100；测试段不计）｜状态：[已深化]
- **定位**：高阶块（128KB–4MB）服务大缓冲与 2MB 大页（F2518），高阶的健康度是碎片风险（风险三）的敏感指标，本条给高阶路径立成功率与对齐两道账。
- **语义边界**：只做高阶分配行为与对齐闸；不做大页映射（B10/B12 段）、不做预留池策略（F2483）。
- **依赖与嫁接源**：依赖 F2409/F2413；对 `m700vm.rs` 大页阶梯建模是接管声明（现存为 CheckSet 建模，本条落地机制）；嫁接源同前。
- **风险与回退**：高阶枯竭连锁（一次 order-10 失败触发风暴式降级）——降级幅度账限幅（单次 ≤3 阶），超限转 ENOMEM 并告警。
- 正文：实现路径分三步。第一步高阶路径：order 5–10 走通用降级序（F2411），成功率按阶分列（成功数/请求数）；第二步对齐闸：order≥9 的块基址必须 2MB 对齐，闸在分配出口单点断言，例外即实现事故 panic；第三步成功率账：10^3 次压测的成功率、降级幅度分布、碎片告警触发数三账齐全，供 B29 压力矩阵复用。与现存内核衔接点：`pmm.rs` 高阶请求入口加闸，无签名变化。与 Windows 对照：Windows 的连续内存分配（`MmAllocateContiguousMemorySpecifyCache`）有对齐参数与失败语义，本条对齐其对齐刚性。判据 UNX-F2423-J1 的复测方式：order 9/10 各 10^3 次成功率账在档，2MB 对齐零例外，限幅用例 10/10 次按预期转 ENOMEM。

### UNX-F2425 · 阶位图与 nr_free 总账

- **定位**：nr_free（空闲帧总数）是水线（F2461）与 OOM（后段）的判据源，总账与阶位图的恒等关系是 buddy 完整性的机器证明，本条把恒等做成抽核制度。
- **语义边界**：只做总账维护与抽核；不做水线判定（F2461）、不做账导出格式（F2436）。

- 正文：实现路径分三步。第一步总账维护器：nr_free 在分配/释放出口单点增减，禁止旁路改账（出口审计清单）；第二步抽核器：按采样策略全阶求和与总账比对，漂移即冻结分配（fail-stop）并打印阶差表定位引入点；第三步漂移检测账：每次抽核结果（含差值）落环形账，供长稳分析。与现存内核衔接点：`MemDomainState.free_frames` 改由总账单点供给（F2419 聚合器消费）。与 Windows 对照：Windows 的 available pages 计数由 PFN 数据库单点维护，双账恒等抽核是本工程加固。判据 UNX-F2425-J1 的复测方式：10^5 次操作后恒等保持，注入漂移用例 20/20 次捕获，环形账长度与采样率一致。

### UNX-F2426 · 伙伴互算与配对验证原语
- 域/批：A4/B02｜判据：UNX-F2426-J1 互算原语 10^7 次往返零误差，非法对（跨区/越阶）10/10 次拒绝｜纯功能行数：240 行（互算原语 90 + 非法对判定 80 + 验证账 70；测试段不计）｜状态：[已深化]

### UNX-F2429 · 页迁移原语（物理页搬家）
- 域/批：A4/B02｜判据：UNX-F2429-J1 迁移后旧页内容逐字节一致、新页可达旧映射，10^3 次迁移零内容损失｜纯功能行数：380 行（迁移编排器 140 + 内容搬运 100 + 映射重定向 140；测试段不计）｜状态：[已深化]

- **语义边界**：只做单页迁移原语；不做批量整理策略（F2524/F2525）、不做跨节点策略（F2513）。映射重定向只做"同地址空间内 PTE 指向更换"，TLB 批失效挂 A3 接口账。
