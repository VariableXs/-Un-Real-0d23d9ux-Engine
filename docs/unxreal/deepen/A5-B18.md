## F3541 采样剖析器总设计（周期中断采样——桩化 tick）

**定位**：采样剖析器：周期 tick 中断→采当前栈→按栈计数——观测面第四块（谁在吃 CPU 的时间机器），为 F3450 预算对账提供实测引擎。
**语义边界**：剖析**纯观测**（采样路径不改代码不改调度——与探针的 ABORT 权利相比剖析连"标记"都不做——最纯的观测者）；采样式选型冻结（与插桩式对比判据行内嵌）；开发期 tick 全走桩（B27 fake 时钟——零 QEMU）；剖析结果=概率估计不是精确计时（采样语义的认识论声明——精确计时用双账 F3526）。
**判据**：
- J1：剖析语义冻结（tick 周期/采样点/计数结构三件——判据行内嵌）；M-299 采样全链（注入 tick 100 次→样本 100→聚合→导出全通）。
- J2：选型声明落判据（零插桩税断言——被剖析函数二进制与剖析开关无关）。
**纯功能行数**：340（总纲 ~120 + 全链用例 ~120 + 选型论证 ~100）
**依赖与嫁接源**：F3530 时钟（tick 源）；F3542 回溯（样本内容）；F3543 记账（样本去向）；F3550 会话（生命周期）；B27 fake 时钟（注入源——前向声明）。
**风险与回退**：采样 ISR 太重（剖析 ISR 自身成负载）——回退：ISR 预算 50 拍（F3557——剖析 ISR 是全内核最高频 ISR 之一，超预算=剖析拖垮系统=观测自毁）；tick 周期不适（太疏漏热点/太密税重）——回退：周期档位（10ms/5ms/1ms 三档——会话选——判据行给档位依据：1ms 档 1s 出 1000 样本/CPU（统计够）、税 0.4%（50 拍/1250 拍周期——可忍上限））。
**正文**：剖析语义（判据行原文）：周期 tick（默认 5ms 档）→ISR 采样当前 CPU 栈（F3542 回溯）→样本入 per-CPU 环（F3543）→会话结束聚合（F3544）→导出（F3545/F3546）。采样式的选型论证（判据行展开）：与插桩式（函数进出口埋点）对比——插桩精确但**每函数加税**（全覆盖插桩=全员 15 拍税——万断言系统里再叠插桩=L1 线爆表）；采样**零代码改动**（被剖析函数不知道自己在被剖析——J2 的二进制不变断言即此）——精度换自由的取舍：剖析回答"热点在哪"（TopN 需求——10% 精度够用）、不回答"这函数跑了多少 µs"（精确需求走双账——两机器两问题不互代——判据行把"剖析与双账的分工"点透：剖析给分布、双账给精确、火焰图给直觉）；采样式的固有风险（盲区：短函数在两 tick 之间进出=零样本——偏差声明 F3549 承接——剖析结论带"采样视角"水印）。tick 档位（判据行论证）：10ms 档（常态巡检——税 0.04%）/5ms 档（默认——税 0.1% 统计密度均衡）/1ms 档（深度剖析——税 0.4% 短会话专用）——三档全会话预算约束（F3550 时长 ≤60s——1ms 档 60s=6 万样本/CPU——聚合账容量核对）。桩化声明：开发期 tick=B27 fake 时钟编程注入（tick 时刻可控——M-299 注入 100 次全链可复现）；真机 tick=硬件定时器随闸门（F3499：真机 tick 精度与 ISR 拍数实测——真机专属登记）。与 F3529 分发器的关系：剖析样本不入四路（样本环独立——剖析数据量大走独立环+会话内聚——分发器四路是事件流的、样本是采样流的——两流分离（判据行声明：事件流（低频高信息）与采样流（高频低信息）物理分离——各自缓冲各自协议）。M-299 复测：注入全链+二进制不变+三档税核算+双流分离。

## F3542 采样栈回溯采集（帧指针回溯——OTP 回溯降级）

**定位**：栈回溯采集：帧指针（fp）链逐帧上溯×帧界校验（烂帧即断）×OTP 降级（一次性回溯深度上限 32）——采样样本的"内容"生成器。
**语义边界**：只支持 **fp 链回溯**（v1 不做 DWARF/OTP 全量展开——fp 链的编译约定在 Varix 内核构建全量生效——判据行声明 fp 全量是内核自有代码的前提：外部位码不经 fp 约定则回溯断于其帧——诚实断帧优于错误展开）；**烂帧即断**（帧界校验失败停止回溯——校验三条件判据行内嵌）；回溯深度上限 OTP=32（超深即断+TRUNC）。
**判据**：
- J1：回溯语义（fp 链步进+三校验——判据行内嵌）；M-300 回溯正确性（十层已知调用树→回溯逐帧与调用树一致）。
- J2：烂帧即断（注入伪造 fp→回溯在校验点断+断点标记——不猜断言）。
**纯功能行数**：340（回溯引擎 ~130 + 校验逻辑 ~100 + 用例 ~110）
**依赖与嫁接源**：B24 符号化（帧地址→函数名的消费端——前向声明）；F3556 自检（回溯失败计数）；F3519/F3539 自检（fp 编译约定完整性——构建期检查项）。
**风险与回退**：fp 链断（叶函数无帧——优化尾调）——回退：构建约定（Varix 内核构建禁尾调用优化于可剖析函数——编译选项冻结——判据行给"回溯质量是构建质量问题"的定位：剖析精度的一半在编译选项）；校验误判（好帧被拒）——回退：三校验的全确定参数（栈界/对齐/序——零启发式——误拒率随约定完整性趋零）。
**正文**：fp 链步进（判据行原文）：`while (fp 在栈界内) { ret_addr = fp[1]; 记帧; fp = fp[0]; }`——每步三校验（判据行内嵌）：①**栈界**——fp 指针落在本任务栈区间（越界=烂帧立即断）；②**对齐**——fp 8B 对齐（不对齐=踩了数据当帧）；③**单调**——新 fp > 旧 fp（fp 链向高地址生长——倒退=循环或垃圾）——三校验全过才记帧继续——**任一失败立即停**（断点标 BREAK——样本带"回溯到第 k 层断"的诚实标记——断帧样本仍入账（部分栈也有价值——TopN 里显"≤k 层"桶——判据行给断帧的记账语义：不完美数据诚实记账好过丢弃）。OTP=32（判据行论证）：Varix 内核调用深度 P99 <20（构建期栈深分析——F3519 自检家族的编译期伙伴——深度分布入构建账）——32=P99×1.6 裕度；深递归（>32 层）在剖析里显 TRUNC 桶（递归热点照样可见——只是看不到底——"能看到递归在烧 CPU"已满足热点需求）。为什么不做 DWARF 展开（判据行论证）：DWARF 表=二进制体积+2（内核镜像翻倍不可忍）+展开逻辑复杂（ISR 50 拍装不下）；fp 链=每函数 2 条指令的约定税（fp 维护 prologue/epilogue——L1 预算内的常态）+回溯 3 拍/帧（32 层=96 拍——略超 50 拍 ISR 预算→OTP 常态截在 16 层（48 拍）——P99 深度 20 的截断损失 <5% 样本——判据行把这个拍数算账亮出来：ISR 预算逼出的 OTP=16 实际值、32 是断言上限——两值并存各有用途）；"烂帧即断不猜"的哲学（判据行展开）：猜帧（启发式栈扫描——找像返回地址的值）是剖析界的经典邪路（猜对的概率高但错的样本混入分布=假热点——假热点比没热点毒——B17 F3537 宁缺毋错同律二践）——Varix 剖析的每个帧都是 fp 链真实节点（证据纯度优先）。M-300 复测：十层树逐帧+三校验逐项+断帧记账+OTP 截断+编译约定检查。

## F3543 采样记账（per-CPU 样本桶/计数饱和）

**定位**：采样记账：per-CPU 样本环形（原始样本暂存）+折叠计数账（聚合前置账）×饱和语义（计数到顶停增+SAT 标记）——样本的落账与完整性对账。
**语义边界**：两层账分工（样本环=暂存（ISR 写）——折叠账=ISR 内快速折叠（同栈键+1——免后端聚合的内存换算力）；饱和语义：计数 u16 封顶 65535——到顶后不再加但 SAT 位亮（丢失的是**计数精度**不是**样本存在**——判据行给饱和的诚实语义）；记账对账式：样本数==tick 数−丢样数（ISR 预算内丢单样本优先于拖长 ISR——判据行给丢样优先级：剖析 ISR 宁可丢样本不可超时——观测不扰动红线的量化执行）。
**判据**：
- J1：记账结构（环+折叠账+饱和三件——判据行内嵌）；M-301 记账对账（注入 tick 1000——对账式成立）。
- J2：饱和行为（注入 7 万同栈样本→计数 65535+SAT——不溢出不静默）。
**纯功能行数**：320（结构 ~110 + 对账 ~110 + 用例 ~100）
**依赖与嫁接源**：B15 F3483 ring（环形同律）；F3544 折叠（键一致）；F3556 自检（对账复跑）；F3557 预算（丢样决策的预算锚）。
**风险与回退**：折叠账内存（每 CPU 千级栈键——键表涨）——回退：键表上限 1024/会话/CPU（超限新键并入"其他"桶——TopN 精度保住、"长尾合并"显式——判据行给长尾合并的语义：报表诚实（其他桶可见））；ISR 内折叠慢（键查找）——回退：样本环直写模式（ISR 只入环、折叠在会话结束时批做——两模式会话可选——默认折叠式（税均摊）、深剖析用直写式）。
**正文**：记账结构（判据行原文）：`SampleBook { ring: [Sample; 256], folds: FoldTable }`——Sample=(栈键 h64, ts_lo, 层数)（16B——回溯产物 F3542 的压缩：完整栈在折叠账里、样本环只带键）；FoldTable=开链哈希（栈键→计数 u16+SAT 位）——ISR 路径：回溯→算键（帧序号序列的滚动哈希——F3544 键函数）→fold[h]++（命中路径 ~15 拍——ISR 50 拍预算的构成：tick 5+回溯 ~30+记账 15——判据行把预算拆到条目）。饱和语义（判据行论证）：u16 顶格=65535——单栈 6.5 万样本意味着"这函数占了会话的一半以上"（1ms 档 60s=6 万样本总量——单栈饱和=它是绝对霸主）——饱和后 SAT 位亮+继续丢该栈样本（不再加计数）——报表显示 `65535+`（不是 65535——加号是饱和的诚实标记；把饱和值当精确值=把地板当天花板——判据行把饱和数据的读法冻结进报表格式 F3545）。对账式（判据行论证）：`样本数 == tick 计数 − 丢样计数`——三数全有来源（tick=F3530 计数/丢样=ISR 自报——ISR 超时风险点前置检查：回溯已 40 拍未完→丢弃记账直接出 ISR（丢一样本保一时限——丢样决策在 ISR 内部机械执行——不靠自觉靠预算检查代码）；对账式每会话终了跑（F3556 复跑）——数字对不上=ISR 或账有 bug=ERROR——记账的自洽是剖析可信的底线（账都不自洽的剖析无人敢信）。折叠式 vs 直写式（判据行论证）：折叠式 ISR 内 +15 拍换后端零聚合（会话结束直接出报表——快）；直写式 ISR −15 拍但后端要聚 6 万样本（会话结束慢 100ms）——默认折叠（常态剖析重"快出"）、直写可选（深度剖析重"ISR 轻"——1ms 档常配直写——模式与档位的推荐配对入 F3550 会话契约）。长尾合并（判据行展开）：键表 1024 上限——超限新键并入"其他"桶（计数合并+OTHER 标记）——TopN 看头部长尾看"其他"的大小（其他占 >20%=键表不够=会话该换直写式——报表给出这个提示——账面不仅报数还给建议）。M-301 复测：对账式+饱和 SAT+丢样注入+两模式对比+长尾合并提示。

## F3544 折叠栈聚合（stack→count 折叠账）

**定位**：折叠聚合：同栈同计数（栈键=帧序号序列的滚动哈希+全序列存证）——火焰图数据的聚合核心（键纯度是聚合正确性的全部）。
**语义边界**：键**双部件**（哈希索引+全帧序列存证——哈希撞了比全序列（撞键不可能——判据行给键纯度论证：哈希只做索引加速、键的相等性由全序列逐帧比对裁决——哈希碰巧同、序列不同→不同栈（键=序列不是哈希——哈希是索引不是身份）；折叠**确定性**（同输入账必得同聚合——M-302 纯度断言）。
**判据**：
- J1：折叠语义+键双部件（判据行内嵌）；M-302 折叠一致性（10 万随机栈→同栈必同键（纯度）+异栈必异键（判别）——双断言）。
- J2：折叠确定性（同输入两次聚合→账逐项相等）。
**纯功能行数**：320（键结构 ~110 + 聚合逻辑 ~110 + 用例 ~100）
**依赖与嫁接源**：F3543 记账（折叠账本体在记账条——本条是键函数与聚合语义）；F3545 导出（聚合账的出口）；F3542 回溯（帧序号来源）。
**风险与回退**：帧序号不稳定（同一栈两次回溯序号不同——地址布局变化）——回退：键用**符号序号**（帧地址经 B24 符号化→函数 ID 序列——函数 ID 稳定（符号表静态）——判据行给键稳定性的机制：剖析与符号化联姻（采样时符号化？太贵（ISR 内查表 30 拍）——折中：ISR 记帧地址、会话终了批符号化转 ID 键——两阶段键转换（ISR 快、后端稳——键的最终形态=函数 ID 序列）；哈希碰撞风暴（理论 64 位撞——回退：全序列裁决使碰撞只损索引效率不损正确性——碰撞无损正确性的结构声明）。
**正文**：键结构（判据行原文）：`StackKey { frames: &[FnId] }`（FnId=u32 符号 ID——B24 符号表的稳定编号）+索引哈希 `h64`（frames 的滚动哈希——SipHash 族无种子固定——确定性哈希（同输入同哈希——随机种子哈希会破确定性——判据行声明固定种子的理由：键哈希不需要防碰撞攻击（输入是自己的栈）只需要确定性）。聚合逻辑（判据行原文）：`fold(key) -> cnt`：查索引（h64 桶）→链上逐项**全序列比对**（帧数同+逐帧 ID 同）→命中 cnt++/未命中新键入表——比对裁决使哈希碰撞无害（撞了走链慢一点、不会错——判据行把"索引可错、裁决不错"作为聚合正确性的分层保障）。M-302 双断言设计（判据行给方法）：①纯度——10 万样本按"逻辑栈"分组（注入负载的已知调用树组合）→每组聚合后必须单条目（同逻辑栈全序列必然同——函数 ID 转换的确定性保证）；②判别——任意两条目全序列不同（同条目=判别失败=键函数 bug）——双断言机械执行。两阶段键转换（判据行论证）：ISR 内帧地址键（快——免查表）+会话终了批量符号化转 FnId 键（稳——符号表静态）——两阶段的存在理由是 ISR 预算（50 拍装不下符号查找——B24 符号查找是二分 ~30 拍/帧×16 帧=480 拍——超预算 10 倍）；转换的完整性对账：转换前地址帧数==转换后 ID 帧数（逐样本——断帧样本的"≤k 层"标记随转（部分帧的 ID 序列也是合法键——断帧桶照折叠）；转换失败的帧（地址查不到符号——外部位码）→帧标记 UNK（未知帧入键（UNK 也是稳定 ID——分配静态段——判据行给 UNK 的键语义：未知帧是"一类身份"不是"无身份"——含 UNK 的栈照样折叠可查（热点在未知区照样现身——只是名字是 UNK——诚实命名）。确定性声明（判据行论证）：J2 同输入双聚合逐项相等——聚合无时钟无随机无遍历序依赖（哈希表遍历序不影响账内容——输出按键排序后恒定——判据行把输出序也冻结（报表序稳定=两次报表可 diff——火焰图对比 A/B 会话的元需求）。M-302 复测：纯度+判别+确定性+UNK 键+断帧转+输出序稳定。

## F3545 火焰图数据导出（folded 格式 v1）

**定位**：folded 格式 v1：`frame;frame;...;frame count` 行式（分号分隔栈+尾缀计数）——聚合账的文本出口（工具生态的通用接口——Brendan Gregg folded 标准）。

**判据**：
- J1：格式冻结（行文法判据行内嵌：`[≤k ]frame1;frame2;...;frameN count[+]`）；M-303 导出往返（聚合账→folded→F3559 解析回账——逐条目一致）。
- J2：转义完整性（符号名含分号/空白的转义规则——解析无损）。
**纯功能行数**：300（文法 ~100 + 导出器 ~100 + 往返用例 ~100）

**正文**：文法（判据行原文）：每行 `[≤k ]root;...;leaf count[+]`——≤k=断帧样本前缀（k=实际回溯深度——`≤16 foo;bar 128` 表示 128 个样本回溯到 16 层断）；分号=帧分隔（帧名转义：符号名内分号→`\;`、反斜杠→`\\`——最小转义集（J2 往返验证含转义名用例）；count=十进制计数+饱和加号。选 folded 而非自造树格式的论证（判据行展开）：folded 是火焰图生态的 lingua franca（Brendan Gregg flamegraph.pl/速度栈工具全认——**自造格式=自绝于工具生态**（A5 域的开放性判例（十四·开放性）在观测面的落点：数据用开放格式存储可导出可迁移——判据行引 Variable 体验判例第十四章原文精神：用户的数据用开放格式、不给用户上锁——剖析数据是 Variable 的数据不是剖析器的数据）；folded 的文本性红利：diff 友好（两会话 folded diff=热点漂移的一手证据）、grep 友好（`grep malloc` 秒查）、体积小（聚合后千行级）。导出时序（判据行声明）：会话 CLOSED→聚合冻结→符号化转换（F3544 两阶段的后半）→folded 生成→RunDigest 摘要（F3555）+文件导出双出口——导出是会话收尾的必经步骤（不出 folded 的会话=数据困在账里=白采——判据行把"会话必须出账"定为收尾纪律（F3550 状态机的 CLOSED 转移条件含"folded 已生成"）。计数语义再冻结：folded 的 count=样本数（不是 µs 不是 %——百分比由解析器算（count/freq×周期换算——换算系数在 F3559 接口契约里——数据层不给百分比（同一数据不同 tick 档百分比不同——换算是解读层的事——数据与解读分离）。M-303 复测：往返逐条目+转义用例+版本头+双键排序+65535+/≤k 前缀。

## F3546 热点榜（TopN 自占/累计双序）

**定位**：热点榜：TopN=20 的双序榜（自占榜=本帧样本数排序/累计榜=含子帧样本数排序）——剖析结果的终极人读面（一眼看谁在烧 CPU）。
**语义边界**：双序定义（判据行内嵌：自占=样本栈的叶帧计数/累计=样本栈中含该帧的计数——两榜数字不同用途不同：自占找"烧 CPU 的本体"、累计找"调用路径的源"）；榜只**呈现**不解释（榜上函数→什么原因→人的工作——榜不诊断）；N=20 冻结（一屏两列——榜的容量与可读性平衡）。
**判据**：
- J1：双序定义+修正式（Σ自占==Σ累计−共享帧计数和——账面自洽式）；M-304 双榜一致性（注入已知负载→双榜各自正确+自洽式成立）。
- J2：零样本函数不上榜（最小样本 ≥100——F3549 最小样本数联动）。
**纯功能行数**：300（双序计算 ~100 + 自洽式 ~100 + 用例 ~100）
**依赖与嫁接源**：F3544 聚合账（数据源）；F3549 最小样本（上榜门槛）；F3551 断言热点（断言帧的榜外账——断言税单列）。
**风险与回退**：双榜数字矛盾（自洽式破=聚合 bug）——回退：自洽式是榜的完整性校验（每次出榜必算——破=ERROR 不出榜）；累计榜被大入口霸屏（main 累计 100%）——回退：累计榜滤独占 >90% 的"管道帧"（main/start_thread 类——滤除规则显式+滤除清单可关——判据行给滤除的透明性）。
**正文**：双序语义（判据行原文）：自占=self——样本栈叶帧的归属（`foo;bar` 样本计入 bar 的自占）——自占榜回答"CPU 此刻正在执行的函数是谁"（烧 CPU 本体）；累计=total——栈中**每帧**都 +1（`foo;bar` 计 foo 和 bar 各 1 累计）——累计榜回答"谁调用了烧 CPU 的路径"（调用源）——两榜互补（自占找凶手、累计找同谋链——判据行给两榜的侦探学比喻：榜是推理起点不是结论）。自洽式（判据行论证）：`Σ自占 == Σ累计 − Σ(非叶帧累计)`——展开：每个样本恰好给叶帧 1 自占（自占总和=样本数）、给沿途每帧各 1 累计（累计总和=Σ各样本帧数）——差值=非叶帧的累计和——恒等式机械可算（M-304 实测）——自洽式破=聚合或榜计算 bug（数字游戏玩不转的账本没有资格出榜）。滤除管道帧（判据行论证）：`main/start_thread` 类帧累计≈100%（所有路径的必经点——累计榜被它们霸屏则榜失信息量）——滤除规则：累计占比 >90% 且子调用 >50 个的帧进"管道嫌疑"→滤出榜+滤除清单（可关——滤除是呈现策略不是数据修改——folded 原始数据不受影响——判据行强调滤除只作用于榜不作用于账——原始数据永远完整可查（呈现层滤镜与数据层的分离）。断言帧特记（判据行展开）：断言位（kassert）在榜上单列"断言税"段（F3551 热点账联动——断言执行占 CPU 的份额一目了然——万断言系统的断言税可视化——预算对账 F3450 的呈现层入口）；断言税榜外单列的理由：断言税是**已知的固定支出**（预算内的——与热点混排会污染"寻找意外热点"的榜语义——已知支出与未知热点分栏（榜的导航语义）。N=20（判据行论证）：一屏 40 行（双榜各 20）——人类视觉扫榜的容量上限（>20 靠滚动=扫榜变翻账——榜的交互性让位于一览性——N 可扩（会话参数 topN ≤100——扩是显式选择）。M-304 复测：双榜正确+自洽式+滤除透明+断言税分栏+门槛。
