### UNX-F9261 · 权限错误面总纲（EPERM vs EACCES 判定域）
- 域/批：C2/B24｜判据：UNX-F9261-J1 两错误码判定域判据过，EPERM（操作特权缺失）与 EACCES（对象权限不足）分界逐格落账，与 Linux 语义逐例一致格过｜纯功能行数：420 行（两码判定域伪代码 150 + 分界逐格落账 140 + Linux 逐例一致 130）｜状态：[已深化]

- **定位**：本条是 B24 权限族错误矩阵批（F9262–F9279 各专条）总纲：EPERM（操作特权缺失）与 EACCES（对象权限不足）两错误码判定域分界——判定伪代码、典型格落账与 Linux 逐例一致核，全批错误码语义地基。
- **语义边界**：只管两码判定域与分界；rwx 位面格归 F9262/F9264；CAP 能力面归 F9268；判序格（EROFS 卷面/路径段序）归 F9269/F9266；对象权限正判据面归 B01–B15 已深化册（零重铺）。
- **依赖与嫁接源**：嫁接 credentials(7)/path_resolution(7) man-pages 与各调用 ERRORS 段 EPERM/EACCES 行；锚定 B05 三身份档、B02 inode 权限位、guard.rs CAP 位、B13 矩阵总装体例。
- **风险与回退**：风险一为两码混判（对象操作失败一律 EACCES 的简化倾向）——回退为判定伪代码冻结：特权面检查先行且单独出口（EPERM 语义），逐例格断言码唯一；风险二为优先级争议格（特权缺失+权限不足双触发时码漂移）——回退为双触发构造格显式断言（按冻结判序输出唯一码），判序伪代码落账。
- **正文**：实现路径分三步：第一步立两码判定域伪代码——判定路径伪代码冻结：进入对象操作→若操作要求特权（CAP_* 位或 uid==0 面）且调用者缺失 → EPERM（先判，操作特权面）；否则对象权限校验（inode 九位 vs 调用者身份）失败 → EACCES（后判，对象权限面）；两域互斥出口断言（同一次调用单码出口）；第二步立分界逐格落账——典型格落账：chmod 非属主（EPERM）、open 缺 r（EACCES）、kill 他人进程（EPERM）、目录缺 x（EACCES）、setuid 非特权（EPERM）、搜索路径中段缺 x（EACCES）等，逐例带操作/身份/对象三要素与预期码四列；第三步立 Linux 逐例一致——逐例与 man-pages 各调用 ERRORS 段比对表落账（码名/触发条件/优先级三列），零分歧断言，与 F9269 判序格（EROFS 先于两码）预留接口。与现存内核衔接点：身份面与 B05 三身份档单源；权限位与 B02 inode 位单源。与 Windows 对照：Windows 无两码分立（ERROR_ACCESS_DENIED 覆盖两域+ERROR_PRIVILEGE_NOT_HELD 特权面），对照随 F9276 落账。判据 UNX-F9261-J1 的复测方式：ktest 三断言——伪代码路径判定一致、逐例格表四列齐、比对表零分歧。

### UNX-F9262 · open EACCES 矩阵（rwx 三位逐格）
- 域/批：C2/B24｜判据：UNX-F9262-J1 rwx 三位逐格注入判据过，缺 r 读全 EACCES 格过，缺 w 写全 EACCES 格过，缺 x 执行全 EACCES 格过｜纯功能行数：360 行（rwx 三位注入矩阵 130 + 三格 EACCES 检出 120 + 正判据对照 110）｜状态：[已深化]

- **定位**：本条立 open EACCES 三位逐格矩阵：文件 rwx 三位对 open 读/写与 execve 执行三操作的逐格拒绝面——对象权限域最基础矩阵，属主位/他位双面扩展格。
- **语义边界**：只管文件对象 rwx 拒绝面；目录段搜索权限归 F9266；属主变更/chmod 特权面归 F9263；九位模型本体归 F9264（本条消费位值）；O_EXCL 冲突域归 F9270。
- **依赖与嫁接源**：嫁接 open(2)/execve(2) man-pages EACCES 行（"write permission is denied"/"execute permission is denied"原文语义）；锚定 B02 open 语义档、B04 execve 母体、F9264 九位矩阵。
- **风险与回退**：风险一为写拒绝判定歧义（O_RDWR 含读位部分通过）——回退为访问模式逐位匹配格：open 要求的每位（读/写）均须位面授权，任一缺位全拒（不部分授权）断言；风险二为截断副作用于拒绝路径（O_TRUNC 在权限检查前执行致数据丢失）——回退为时序格：拒绝路径文件内容零变化快照断言（校验先于任何变更）。
- **正文**：实现路径分三步：第一步立 rwx 三位注入矩阵——测试文件三组权限（0400 仅 r/0200 仅 w/0100 仅 x）×三操作（O_RDONLY/O_WRONLY/execve）=9 格矩阵；第二步立三格 EACCES 检出——缺 r 读（0200/0100 × O_RDONLY）全 -EACCES、缺 w 写（0400/0100 × O_WRONLY）全 -EACCES、缺 x 执行（0400/0200 × execve）全 -EACCES 逐格断言 errno 单一，拒绝路径文件内容零变化（O_TRUNC 时序承诺断言）；第三步立正判据对照——0400×O_RDONLY/0200×O_WRONLY/0100×execve 三格全成功（夹逼证明拒绝在位面非路径面），属主位/他位双面扩展：u=--- o=rwx 属主读仍 EACCES（属主位优先命中，上游语义格），O_RDWR 双位匹配格（缺任一位全拒）断言。与现存内核衔接点：open 权限校验与 B02 open 语义档单源；execve 校验与 B04 母体联动。与 Windows 对照：ACL 拒绝 ACE 近似位面，ERROR_ACCESS_DENIED 单码；对照注记随 F9276。判据 UNX-F9262-J1 的复测方式：ktest 三断言——9 格矩阵、三格检出+三格正判据夹逼、属主优先与 O_RDWR 双位匹配表。

### UNX-F9263 · chmod/chown EPERM 矩阵（非属主）
- 域/批：C2/B24｜判据：UNX-F9263-J1 非属主注入判据过，全 EPERM 格过，特权路径正判据格过，与 B05 三身份档对账格过｜纯功能行数：340 行（非属主注入 110 + EPERM 格与特权正判据 120 + B05 对账 110）｜状态：[已深化]

- **定位**：本条立 chmod/chown EPERM 矩阵：非属主注入全 EPERM（euid 不匹配属主且无 CAP_FOWNER）与特权路径正判据（属主/CAP_FOWNER 双路径）——操作特权域的文件元数据格。
- **语义边界**：只管 chmod/fchmod/chown/fchown/lchown 错误面；权限位值本体与九位模型归 F9264；身份三元组语义归 B05（本条消费）；提限操作域归 F9271；组变更特权细节随 B05 对账。
- **依赖与嫁接源**：嫁接 chmod(2)/chown(2) man-pages EPERM 行（"The effective UID does not match the owner of the file"原文语义）；锚定 B05 三身份档（euid 判定基准）、guard.rs CAP_FOWNER 位、B02 inode 属主位。
- **风险与回退**：风险一为判定用错身份面（real uid 误判致 setuid 翻转后属主格漂移）——回退为 euid 基准格：判定逐例断言用 effective uid（与 B05 对账），real 面格单独标注对照；风险二为 CAP_FOWNER 与属主双路径行为分岔（能力路径残缺元数据变更）——回退为双路径同结果断言：两路径成功后 st_mode/st_uid 终态逐字段一致。
- **正文**：实现路径分三步：第一步立非属主注入——测试进程（euid 与文件属主不同）注入 chmod(file,0644)/fchown(fd,uid,gid)/lchown 全 -EPERM（上游：euid 不匹配属主且无 CAP_FOWNER），失败后 st_mode/st_uid 快照零变化断言（拒绝路径零副作用）；第二步立特权路径正判据——属主进程 chmod/chown 成功正判据（返回零、st_mode/st_uid 变更可观测），CAP_FOWNER 置位进程（能力位注入格）同操作成功（能力面正判据），特权与属主双路径终态逐字段一致（夹逼+一致性双断言）；第三步立 B05 对账——与 B05 三身份档（real/effective/saved 三身份）对账：判定用 effective uid（非 real）格断言（setuid 翻转后仍可 chmod 自有文件格），三身份语义零冲突声明落账。与现存内核衔接点：属主判定与 B05 身份面单源；CAP_FOWNER 与 guard.rs 能力位单源。与 Windows 对照：属主变更 SeTakeOwnershipPrivilege 面，域近似形态异；注记随 F9276。判据 UNX-F9263-J1 的复测方式：ktest 三断言——非属主注入零副作用表、双路径正判据终态一致、B05 euid 判定对账。

### UNX-F9264 · 权限位模型（st_mode 九位逐格矩阵）
- 域/批：C2/B24｜判据：UNX-F9264-J1 九位逐格矩阵判据过，ugo×rwx 逐格可观测，S_IFMT 类型位掩码格过，与 stat 结构单源格过｜纯功能行数：380 行（九位矩阵铺设 140 + ugo×rwx 可观测格 130 + S_IFMT 与 stat 单源 110）｜状态：[已深化]

- **定位**：本条立权限位模型矩阵：st_mode 低九位 ugo×rwx 全枚举可观测格与 S_IFMT 类型位掩码格——全批位面操作的模型地基，stat 结构单源核。
- **语义边界**：只管九位模型与类型位；位面拒绝行为格归 F9262/F9266；s 位（setuid/setgid）语义挂点归 F9265（本条只核位可置可读）；stat 结构本体归 B02/B05（单源复测）。
- **依赖与嫁接源**：嫁接 inode(7)/stat(2) man-pages st_mode 位布局（S_IFMT 0170000 掩码与低九位段）；锚定 B02 stat 语义档（结构单源）、B05 身份档（ugo 归属判定）、chmod(2) 语义。
- **风险与回退**：风险一为枚举回环拖垮套件（512 值全跑时延长）——回退为双轨：批级套件跑抽样式三十二值，512 全枚举随闸门补测登记（双轨条款）；风险二为类型位与权限位互扰（chmod 意外清类型位或 stat 解码串位）——回退为正交断言：chmod 只动低十二位、S_IFMT 高段回环零变化。
- **正文**：实现路径分三步：第一步立九位矩阵铺设——st_mode 低九位 u/rwx·g/rwx·o/rwx 网格 512 值全枚举铺设（chmod 逐一置位→stat 回读逐位断言），回环零漂移（512 值双轨：批级三十二抽样+闸门全量）；第二步立 ugo×rwx 可观测格——九位各自独立翻转（chmod 001→004→010→040→100→400 等十态）stat 回读逐位正确，umask 过滤面联动（open 时 mode&~umask，与 B02 单源）断言，ugo 归属判定与 B05 身份面对账（属主/组/他三面取位正确）；第三步立 S_IFMT 与 stat 单源——S_IFMT 掩码（0170000）类型位四值（REG/DIR/LNK/CHR 桩）解码断言（S_ISREG/S_ISDIR 宏判定与九位正交互不污染），stat 结构布局与 B02 stat 语义档单源复测（字段偏移零漂移）。与现存内核衔接点：inode 权限位与 B02 单源；stat 结构与 B05 stat 档单源。与 Windows 对照：无九位模型（ACL 体系），ATTR_READONLY 单位近似；对照账注记随 F9276。判据 UNX-F9264-J1 的复测方式：ktest 三断言——枚举回环零漂移、十态独立翻转、S_IFMT 正交与 stat 偏移复测。

### UNX-F9265 · setuid/setgid 文件位与执行路径矩阵
- 域/批：C2/B24｜判据：UNX-F9265-J1 s 位语义挂点判据过，目录 setgid 位继承挂点格过，实装归 C1/B1 联签声明格过｜纯功能行数：340 行（s 位挂点 120 + 目录 setgid 继承挂点 110 + 联签声明 110）｜状态：[已深化]

- **定位**：本条立 setuid/setgid 文件位与目录 setgid 继承的语义挂点矩阵：位面可置可读+执行翻转/组继承语义冻结声明，实装归 C1/B1 联签——安全敏感面的协议先行格。
- **语义边界**：只管 s 位挂点协议与目录继承声明；执行翻转实装（euid 切换机制）归 C1/B1 联签（本域零触及）；s 位本身置位/回读归 F9264 位模型；提限拒绝面归 F9271。
- **依赖与嫁接源**：嫁接 inode(7)/execve(2) man-pages setuid/setgid 位语义与目录 setgid 继承段；锚定 C1 域联签对账面、B1 VFS 冻结接口、F9271 提限矩阵。
- **风险与回退**：风险一为挂点协议被当实装（缺席态产生翻转假象）——回退为缺席格：无联签期 execve s 位文件按普通执行零翻转（行为显式声明+断言），杜绝默认翻转移语义；风险二为目录 setgid 继承越界（未声明语义混入）——回退为继承面白名单：只声明组继承一格，其余语义零进入。
- **正文**：实现路径分三步：第一步立 s 位语义挂点——setuid(04000)/setgid(02000) 文件位挂点：位可置（属主 chmod 成功）可读（stat 回读 S_ISUID/S_ISGID 位），执行路径翻转语义（euid→文件属主）声明为挂点协议（语义冻结格），实装归 C1/B1 联签（本域零触及实装，协议签名冻结）；第二步立目录 setgid 继承挂点——目录 g+s 位声明：新建子项继承目录组（语义挂点冻结），注入格：置位目录 mkdir 后 stat 子目录 st_gid==目录组（桩态断言），清位对照格不继承（夹逼）；第三步立联签声明——C1/B1 联签编号登记（执行翻转实装边界+测试用例移交清单），缺席格：无联签期间 execve 对 s 位文件按普通执行（不翻转）且注记落账（行为显式声明非默认），与 F9271 提限矩阵互认（翻转触发面归联签、提限拒绝面归 F9271）。与现存内核衔接点：位存储与 B02 inode 单源；联签协议与 C1 域 handoff 单源。与 Windows 对照：无 setuid 等价（服务账户模型替代）；注记随 F9276。判据 UNX-F9265-J1 的复测方式：ktest 三断言——s 位置/读回环、目录继承桩断言夹逼、联签编号与缺席声明在案。

### UNX-F9266 · 目录搜索权限 EACCES 矩阵（路径逐段）
- 域/批：C2/B24｜判据：UNX-F9266-J1 路径逐段缺 x 注入判据过，全 EACCES 格过，错误点（首段缺失优先）判序格过｜纯功能行数：360 行（逐段缺 x 注入 130 + EACCES 检出 110 + 判序格 120）｜状态：[已深化]

- **定位**：本条立目录搜索权限 EACCES 矩阵：路径逐段 x 位注入（任一段缺 x 断链）、错误点判序（首段缺失优先/ENOENT→ENOTDIR→EACCES 优先级链）——path_resolution(7) 的注入面落点。
- **语义边界**：只管路径段 x 位拒绝面与判序；文件本体 rwx 面归 F9262；路径解析机制本体（walk/挂点跳跃）归 B01 母体（本条消费）；open 正判据归 B02。
