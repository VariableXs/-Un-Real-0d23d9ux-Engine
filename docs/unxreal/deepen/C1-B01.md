### UNX-F8001 · ELF interpreter 标签装载
- 域/批：C1/B01｜判据：UNX-F8001-J1 带 interpreter 的 glibc 动态程序在 Varix 装载运行输出正确，PT_INTERP 三路径全解析；UNX-F8001-J2 解释器缺失/损坏时错误码与 Linux 一致（ENOENT/ELIBBAD），同码双跑 10/10｜纯功能行数：420 行（解释器定位与三路径 130 + 递归装载与交接 120 + 错误路径两档 90 + 账本与判据件 80；测试段不计）｜状态：[已深化]
- **定位**：interpreter 装载是 Linux 人格动态世界的第一道门——glibc 世界一切可执行物（除静态链接外）都要先装载 /lib64/ld-linux-x86-64.so.2 再由它接管，本条把"能跑静态程序"升级为"能进门接 ld.so"，是 C5 嫁接域 glibc 全跑通判据的物理前提。
- **语义边界**：只做解释器定位、装载与控制权交接；不做动态链接本体（重定位执行/符号解析归 C5）；不做 ELF32（D2 WOW64 判据面）；路径解析消费 B1 冻结接口不自带解析器。承接非重复：proc/elf.rs F105 只留"共享对象解释器"占位语义，本条实装完整三路径与交接协议，接管差异登记 F8150 协议。
- **依赖与嫁接源**：依赖 F8005 五要素校验链、F8007 段映射落位器、F8064 递归装载算法；消费 B1 VFS 读接口与 F8039 冻结清单；嫁接源为 Linux fs/binfmt_elf.c load_elf_binary 的 interpreter 分支（版本 6.x，来源注记）与 LSB core 解释器路径约定。
- **风险与回退**：解释器自身装载失败会留下主程序半建状态——回退路径为"解释器镜像先全量校验再触碰主程序映射"，失败即整体回滚（F8073 保证）；封闭树场景解释器路径被改指树外——白名单校验失败返 EACCES 显性化（F8078 联动），绝不静默回退到树内任意文件。
- 正文：实现路径分三步。第一步解释器定位：PT_LOAD 遍历完成后扫 PT_INTERP 段取得路径串，按三路径分派——绝对路径直读、相对路径相对进程 cwd（cwd 消费 B1 接口）、$ORIGIN 前缀交给 F8062 展开器以可执行文件自身目录为基准替换；路径串 NUL 终止与长度上限先行校验（F8077）。第二步递归装载：解释器镜像走与主程序完全相同的五要素校验与段映射管线（F8064 保证同一算法），装载基址独立选择（F8065）并与主程序区间做重叠断言，装载完成产出解释器的入口地址与基址账。第三步控制权交接：入口上下文（F8169 构造）的 rip 指向解释器入口而非主程序，auxv 携带 AT_PHDR/AT_ENTRY/AT_BASE 三元组把主程序信息交给 ld.so，交接点写入 F8075 三账。与现存内核衔接点：proc/elf.rs 的 PT_INTERP 检测常量与 loader.rs 的 SegmentView 消费面全部保留复用，新增的 InterpreterLoader 结构落在 proc/ 模块树内，旧 F105 占位语义升级后行为面由回归样例集（F8270）锁定。与 Linux 对照：Linux load_elf_binary 在 PT_INTERP 存在时以解释器 ELF 替换入口并保留原映像供 ld.so 查询——本条逐行为点对齐，ENOENT（解释器文件不存在）与 ELIBBAD（解释器镜像坏）两码与 Linux 同码双跑验证。与 Windows 对照：Windows 无解释器装载概念（PE 由加载器内建），本条是 Linux 人格专属语义，D2 对照表（F8285）中该行标注"POSIX 专属"。判据 UNX-F8001-J1 的复测方式：钉版 glibc 动态 hello 样本装载运行输出正确、三路径样本各 10/10；J2 复测：删除解释器与注入坏解释器各 10 次错误码与 Linux 基准机逐码一致（真机面随闸门补测登记）。

### UNX-F8002 · ELF 重定位语义实装
- 域/批：C1/B01｜判据：UNX-F8002-J1 GLOB_DAT/JUMP_SLOT/RELATIVE 三族在 ET_DYN 上逐类型应用正确，DT_RELA/DT_JMPREL 遍历无遗漏，GOT 逐项与 Linux 一致｜纯功能行数：380 行（三族应用器 150 + 遍历器 90 + GOT 对照判据件 80 + 错误矩阵 60；测试段不计）｜状态：[已深化]
- **定位**：重定位是 ET_DYN 程序"地址相关项换算"的物理动作——内核侧只需把三族基础重定位应用到位，让 ld.so 接手时 GOT/PLT 处于 Linux 同构状态；本条是 C5 符号解析域的地基，也是 F8001 装载链在动态世界 runnable 的第二道工序。
- **语义边界**：只做三族基础重定位（GLOB_DAT/JUMP_SLOT/RELATIVE）与遍历账；不做符号解析/版本化/IFUNC（C5 主权）；不做 .so 文件的装载（本域只处理主程序自身段）；错误路径只覆盖内核侧可判定的未知类型与越界偏移（F8097 细化）。
- **依赖与嫁接源**：依赖 F8084 遍历器与 F8085 动态段转录账；消费 F8003 vdso 基址账（RELATIVE 条目可能落 vdso 区间的防御）；嫁接源为 ELF64 规范重定位类型表（SHT_RELA 章）与 Linux arch/x86/kernel/module 侧 R_X86_64 处理语义。
- **风险与回退**：重定位目标越界（偏移指向段外）会造成静默内存破坏——防御为"逐项目标地址先验后写"（F8097 断言），越界即整批拒绝装载并全量回收；重复应用（同一偏移两次进表）以幂等性保证（RELATIVE 加数语义允许、GLOB_DAT 拒绝并登记）。
- 正文：实现路径分三步。第一步遍历建账：DT_RELA 与 DT_JMPREL 两表按 DT_RELASZ/DT_SYMENT 与 DT_PLTRELSZ 展开为条目视图，条目总数与转录账（F8085）对账，越界表直接拒绝；每条目按 r_info 拆 type/sym 两字段并按类型分派。第二步三族应用：RELATIVE 型按"基址+加数"直写（批量路径，逐项计时可测）；GLOB_DAT 型写 GOT 槽（初值=加数+基址，符号修正留给 ld.so）；JUMP_SLOT 型写 PLT 关联 GOT 槽（内核只写初始值，延迟绑定语义由 ld.so 主导）——三族应用后 GOT 区逐项与 Linux 基准机同镜像装载结果比对（F8002-J1 判据件）。第三步错误矩阵：未知类型、目标越界、表内自引用三类样本显性拒绝，错误码经 lxerrno 单源出口（F8275 对接），拒绝时全量回收。与现存内核衔接点：proc/elf.rs 现存 RELA 遍历的常量与结构体（Elf64_Rela 尺寸 24 字节等）保留，应用器新增于 C1 装载管线，旧静态链接"无重定位直通"路径行为不变（回归样例锁定）。与 Linux 对照：Linux 内核对 ET_DYN 只做 load 段映射、重定位全权交 ld.so，但 PIE 的 RELATIVE 型在部分内核路径（如 vdso 自身）内核直接应用——本条以"内核应用三族基础型"为对齐点，与 glibc 装载结果逐项比对作终判。与 Windows 对照：PE 重定位（.reloc 基址重定位块）语义与 ELF RELATIVE 族同构，D2 对照表互引该行。判据 UNX-F8002-J1 的复测方式：三族各 10 个真实动态样本应用后 GOT/PLT 区逐项 diff 与 Linux 一致；遍历计数与 DT_ 声明逐项相等（ktest 宿主面全绿，真机随闸门补测）。

### UNX-F8003 · vdso/vvar 映射语义
- 域/批：C1/B01｜判据：UNX-F8003-J1 clock_gettime 走 vdso 路径 syscall 计数为零，AT_SYSINFO_EHDR 与映射基址一致，1,000 次读零偏差｜纯功能行数：260 行（两页映射器 90 + 基址账与 AT 注入 80 + 零陷入判据件 90；测试段不计）｜状态：[已深化]
- **定位**：vdso/vvar 是 ELF 装载链的内核侧特例——每进程地址空间里预置的两页"内核发给用户态的礼盒"，glibc 的 clock_gettime/gettimeofday 走它直读 vvar 数据免陷入；本条把"有 vdso"从口号变成可计数的物理事实（零陷入判据），是 B05 三函数挂点与 F8095 计数判据件的地基。
- **语义边界**：只做 vdso 代码页与 vvar 数据页的映射、权限与基址账、AT_SYSINFO_EHDR 注入；不做三函数符号语义本体（B05）；不做 sigreturn stub（F8093 挂点级）；时钟数据源对接 timesrv 现存账（不重做时钟源）。
- **依赖与嫁接源**：依赖 F8094 嵌入段构建与 F8091 vvar 布局；消费 mem.rs 现存映射原语与 A4 地址空间接口（冻结申请单）；嫁接源为 Linux arch/x86/entry/vdso 布局与 vclock_mode 结构语义。
- **风险与回退**：vdso 缺席（构建裁剪）时 AT_SYSINFO_EHDR 必须按 Linux 语义缺席而非填零——否则 glibc 走死路；回退路径为"配置开关三态（开/关/自动）"，关档下判据件自动跳过并显性登记；vvar 序列锁数据错会导致 glibc 读到撕裂时钟——布局逐字段校验（F8091）前置。
- 正文：实现路径分三步。第一步嵌入段与映射：vdso 镜像（代码页+符号表）以 const 段编入内核构建产物，装载期在每进程地址空间选择固定槽位映射两页——代码页 R+X、vvar 页只读，权限与 Linux 一致（F8094）；映射区间进 F8134 三列账（来源=vdso）。第二步基址账与 AT 注入：两页基址入 F8096 基址账，AT_SYSINFO_EHDR 取 vdso 基址写入 auxv（F8050 交叉核对），glibc 由此定位快速路径。第三步零陷入判据件：提供陷入计数器（消费 C2 现存 int 0x80 面（升级接管）或未来 syscall 面计数挂点），clock_gettime 走 vdso 成功路径时计数增量恒零，连续 1,000 次读数与慢路径交叉校验偏差在阈值内。与现存内核衔接点：timesrv.rs 时钟数据为 vvar 数据页的数据源（只读快照同步），gmem.rs 映射原语复用；lxrun.rs 现存建模无 vdso 语义，本条为纯新增（差异表登记"新增语义"行）。与 Linux 对照：Linux vvar 布局含 tsc/mult/shift/序列锁四要素，本条逐字段对齐；Linux 在 rseq/vDSO 特性缺失时 glibc 自动回退 syscall——缺席行为语义一致。与 Windows 对照：Windows 无用户态时钟直读面（KUSER_SHARED_DATA 是对位物），D2 对照表标注"对位差异、机制不同"。判据 UNX-F8003-J1 的复测方式：ktest 宿主面跑映射器与判据件（1,000 次零陷入+交叉校验）；真机上 clock_gettime 直读路径以样本程序计数验证（随闸门补测登记）。

### UNX-F8004 · wait/waitpid 收割语义
- 域/批：C1/B01｜判据：UNX-F8004-J1 状态编码逐位与 Linux 基准一致，WNOHANG 语义正确，zombie 收割后 pid 不复用｜纯功能行数：310 行（waitpid 主路径 110 + 状态编码器 80 + 收割与 pid 不复用 70 + 阻塞/唤醒挂点 50；测试段不计）｜状态：[已深化]
- **定位**：wait/waitpid 是进程生命周期的终点站——exit 造出的 zombie 只有被 wait 收割才真正消失，pid 才可复用；本条作为四样板中的进程原语样板，为 B02 整批进程模型提供"终点先行"的语义锚（先钉收割契约，再铺 fork/exec 起点）。
- **语义边界**：只做 waitpid 的阻塞/非阻塞/状态解析/收割四段；不做信号投递（SIGCHLD 挂点归 C4，本条只留唤醒槽位）；不做 wait4 的 rusage 返回（F8109 计数挂点供数，语义在 C2 号面）；WUNTRACED/ WCONTINUED 档位依赖组/会话与信号语义的部分在 B12 联签后复测。
- **依赖与嫁接源**：依赖 F8026 pid 分配器（不复用窗口）、F8027 zombie 账、F8024 状态编码器；嫁接源为 Linux kernel/exit.c do_wait 路径与 wait 状态编码宏族（WEXITSTATUS=（status&0xff00)>>8 等）。
- **风险与回退**：多等待者竞态（两进程同时 wait 同一子）会造成双收割——防御为"收割原子性"（收割动作单次生效，第二等待者得 ECHILD），竞态注入 10/10 显性；遗忘收割的 zombie 积压由 reparent（F8028）兜底到 init 类守护收割。
- 正文：实现路径分三步。第一步等待选择器：按 pid 参数语义分派——正数等指定子、0 等同组、负数等 |pgid| 组（组语义消费 B12 账）、-1 等全部子；在子链表上做状态扫描（zombie/退出事件槽），无匹配且 WNOHANG 立即返 0，否则挂入等待队列（SIGCHLD 唤醒槽位，C4 联签前用内核事件量模拟）。第二步状态编码器：退出状态按 Linux 位布局逐位构造——正常退出（WIFEXITED+低 8 位码）、信号终止（WIFSIGNALED+WTERMSIG+WCEXCORED）、停止/继续档位，六宏语义单源实现供判据与号面共用（F8024 细化）。第三步收割与不复用：收割动作原子清账（zombie 计数减、退出状态搬出、描述符释放、pid 进"不可复用窗口"直到收割完成边界），收割后 pid 才回分配池（F8026 断言）。与现存内核衔接点：lxrun.rs 现存建模无 wait 语义（纯新增，差异表登记）；proc.rs AI-05 F101–F125 的退出约定面为消费底座，收割器挂其退出事件槽。与 Linux 对照：do_wait 的 ECHILD（无等待子）与 EINTR（被信号打断，可重启性登记）两码逐码对齐；收割次序（先到先收）语义一致。与 Windows 对照：Windows WaitForSingleObject 句柄模型与 POSIX wait 族机制不同，对照表标注"语义对位、机制各表"。判据 UNX-F8004-J1 的复测方式：ktest 双面跑状态编码 30 用例（与 Linux 逐位比对）、WNOHANG 立返、双收割竞态注入、pid 不复用窗口断言（真机随闸门补测）。

### UNX-F8005 · ELF 头五要素校验链
- 域/批：C1/B01｜判据：UNX-F8005-J1 五要素逐项机检，20 种畸形头 20/20 拒绝且错误码与 Linux 同码，合法样本 30/30 放行｜纯功能行数：280 行（五要素逐检 100 + 畸形样本矩阵 90 + 错误码映射 90；测试段不计）｜状态：[已深化]
- **定位**：五要素校验是装载器"拒绝的勇气"的第一关——magic/class/data/machine/type 任一不符即拒绝装载，把坏镜像挡在第一字节；本条实装逐项校验与错误码映射，与 proc/elf.rs 现存常量族（ELF_MAGIC/ELFCLASS64/EM_X86_64）同源升级。
- **语义边界**：只做 ELF64 头五要素与版本字段校验；不做 Phdr 语义（F8006）；不做 EI_OSABI 强校验（OSABI 记账不做拒绝依据，人格路由在 F8071）；不做 ENDIAN 转换（只接受小端，大端按 ENOEXEC 拒绝）。
