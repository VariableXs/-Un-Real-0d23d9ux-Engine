## F3781 域中期收口总设计（B20 前向声明的兑现面）

**定位**：域中期收口的总纲：三总轧（批账/域账/凭证）+三宣告（断言大关/移交就绪/风险清单）——B16–B30 十五批的总验收架构。
**语义边界**：收口是核验不是施工（本批不新增框架行为——F3782–F3799 全部是核验与凭证面）；收口范围钉死 B16–B30（B01–B15 的 89,900 行是已冻结历史账，不重轧——历史账冻结是收口纪律的第一句）。
**判据**：
- J1：收口架构三总轧三宣告齐备（判据行内嵌）；M-539 收口预跑（三总轧空转→流程通→正式总轧前演练）。
- J2：收口纪律（收口只核不改——发现的偏差走修正流程+留痕，收口不涂改历史账）。
**纯功能行数**：320（架构图 ~110 + 预跑用例 ~110 + 纪律声明 ~100）
**依赖与嫁接源**：B20 前向声明 F3781（期票源——本批即兑付面）；F1382/F1400 段断言大关（B11/B12 双层判据）；F1399 五条件移交宣告（B12 立的条件）；F3557 守恒哲学（域账总轧的总律）。
**风险与回退**：收口演成"走过场"（三总轧跑成三句口号）——回退：每项总轧都必须出示机械证据（awk 输出/grep 输出/计数清单——无证据的总轧无效，判据行给"证据或无效"的二元判据）；收口与施工混台（核验中发现"顺手改进"）——回退：发现即登记不即改（改进走后续批次的正常流程——收口的纯净性）。
**正文**：收口架构（判据行内嵌）：三总轧 = 批账总轧（F3787 十五批逐批守恒核）+域账总轧（F3791 求和==90,040）+凭证总轧（F3788–F3790 四要件签发）；三宣告 = 断言大关（F3783 机器核 ≥80）+移交就绪（F3784/F3786 五条件与守卫位）+风险清单（F3795 未决风险上账）。预跑的设计（判据行原文）：正式总轧前先空转一遍全流程（M-539）——空转的价值在暴露流程自身的断点（脚本路径错误/文件位错/口径引用错），让这些错误落在演练轮而非正式轮（正式轮的红是事故、演练轮的红是发现——**把红提前是收口设计的全部智慧**）；B20 期票的兑付仪式（判据行论证）：B20 收口条写"域中期收口 F3781–F3800 的阶段铺垫"时本批尚未存在——跨十批的前向声明要求收口条与兑付条双向登记（grep 互见——B26 的滑号教训之后，跨批接线一律双端记账），本条的兑付登记即第三链的兑付端（F3789 要件三核它的闭链）。与 B15 域收口的分层（判据行论证）：B15 F3500 收的是"前 300 条"的域级账、本批收的是"续领 300 条"的域级账——两个收口点互不覆盖（收口范围各自钉死），合成 A5 域 600 条的中期全景；域终收口在 B40（收官批——本轮不越位预告其形态，只登记"域账余 60,000 行/200 条待领"的滚动边界）。Windows 对比：Windows 的 release gate（winqual/系统级 sign-off 清单）同"三总轧三宣告"的收口形态——gate 不是仪式是清单执法。M-539 复测：三总轧空转 + 三宣告演练 + 期票兑付登记 + 范围边界声明。

## F3782 段断言计数口径（F1382/F1400 双层）

**定位**：断言大关的计量口径：F1382 段层（每批段的断言计数——批级里程碑）+F1400 域层（全段断言累计——域级大关）的双层结构定义。
**语义边界**：只定口径不执行核验（核验归 F3783）；断言的计数对象 = ktest 库 assert 调用计数（F3745 同口径——口径漂 = 大关失义，判据行钉死"数字的来源单一"）。
**判据**：
- J1：双层对账（段层求和==域层计数——双层的守恒）；M-540 双层对账执法。
- J2：口径冻结（大关核验前口径锁定——核验中途改口径=作弊）。
**纯功能行数**：320（双层结构 ~120 + 对账用例 ~100 + 冻结纪律 ~100）
**依赖与嫁接源**：F1382/F1400（B11/B12 立的双层判据——本条是它们的域级计口径）；F3745 计数口径（ktest 库直取——同源）；F3783 大关核验（执法位）。
**风险与回退**：段与域的计数打架（某段数字进了域累计又在本段重复计）——回退：求和式执法（域层计数 = Σ段层——不是两本账是一本账的两级视图，判据行给"两级视图一本账"的口径声明）；口径在中途漂移（核验时把 CheckSet 计入/assert 不计入）——回退：口径 const + 核验前 hash（口径快照入凭证——核验用的口径与快照一致才有效）。
**正文**：双层结构的语义（判据行原文）：段层是砖、域层是墙——F1382 的段层口径回答"这一批的断言里程碑过没过"（≥80/批——B11/B12 立的批级判据），F1400 的域层口径回答"续领波的断言总量到哪了"（十五批累计——万断言承诺的段级里程碑）；两层的守恒关系（判据行论证）：域层计数不是独立统计而是段层求和——**没有第二本账**（如果域层另数一遍，两数迟早打架且无法定位谁错——单源求和让"墙塌"必能定位到"哪块砖"）；计数来源的单一性（判据行原文）：断言计数从 ktest 库直取（F3745 的口径——assert 调用点计数，建模层不算、注释不算、重复注册不算）——大关不是宣布是出示（F3783 执法时出示逐段计数清单+求和式）；口径冻结的操作（判据行原文）：核验脚本启动前先出"口径快照"（口径三要素：计数对象/计数范围/排除项——快照 hash 入 F3796 域中期报告），核验中途任何口径变更都使核验结果作废重跑（**改口径=换考卷=作废重考**——与铁律 4 诚实三态同律：口径漂移按灌水处置）。与 B26 修正事件的呼应（判据行论证）：B26 的 M 号滑号教训（行的守恒核了、号的连续没核）在本条的一般化为"两核缺一不可"——段层核每批的 ≥80、域层核求和守恒——**只核一层就等于没核全**。现有内核接入：ktest 库计数接口（既有）。Windows 对比：WLK 的作业计数与 rollup 报告（子作业求和==总作业——同两级视图一本账）。M-540 复测：双层对账 + 口径快照 hash + 求和式出示。

## F3783 断言大关核验（≥80 的机器核）

**定位**：段断言大关的执法位：十五批逐段核 + 域层汇总核——双层全过才算过大关。
**语义边界**：核验只读（计数直取 ktest 库——不重跑用例、不重算建模——大关核的是"断言在库"的事实不是"断言通过"的运行态，运行态由 Runner 侧账（B12）与 CI 门禁（B28）持续保证）；红段点名（不足段逐一批号列出——不抹不并）。
**判据**：
- J1：大关契约（十五批逐段核+域层汇总核——双层全过才算过大关）；M-541 大关执法（正常段绿/构造不足段红——红段点名）。
- J2：大关的真实性（计数从 ktest 库直取——非人工填报，F3745 门同源）。
**纯功能行数**：300（执法脚本 ~110 + 红段点名 ~90 + 用例 ~100）
**依赖与嫁接源**：F3782 口径（双层与冻结）；F1382/F1400（判据母源）；F3745 计数门（同源口径）。
**风险与回退**：红段被"解释掉"（"这段框架性条目断言少是合理的"）——回退：红段一律点名留痕，豁免必须走显式豁免单（豁免理由+批准位——豁免是显式的、有账的，默认豁免即灌水——与 C3 域豁免清单纪律同构）；计数虚高（把 CheckSet 重复计数）——回退：口径快照（F3782）+抽 3 段人工回溯计数（脚本与库的数字对得上才算核过）。
**正文**：执法的形状（判据行原文）：核验脚本逐批输出"批号/断言计数/≥80 判定"三列清单——十五行清单+求和行就是大关的物证（**大关不是一句"过了"，是一张可复算的表**）；域层汇总核（判据行原文）：Σ段计数 == F1400 域层计数（F3782 的守恒在执法位复验——两层各核一遍是防"单层自洽但双层矛盾"的冗余设计）；红段执法（判据行论证）：构造一个断言不足的段（注入用——演练面）验证红路径：判定红→段号点名→大关整体不宣告→点名进入域风险账（F3795）——**红的价值不在拦截本身在点名的坐标**（知道哪批不足才知道补哪里）；豁免单的形态（判据行论证）：框架性条目（如 F3796 报告条本身）断言计数天然偏低——豁免单三字段（条目号/理由/批准位）逐条显式，豁免率本身入报告（豁免不是免检是另一种账——豁免率异常上升就是大关失守的先兆信号，判据行给这个"豁免率是体温计"的哨兵语义）；真实性执法（判据行原文）：脚本数字与 ktest 库直读数字逐段 diff（三段抽查——非全量但随机段轮换——抽查的威慑在"随时可能被抽"）。现有内核接入：ktest 库（计数源）。Windows 对比：WLK 的 rollup 里 fail/exempt 分列（豁免显式同构）。M-541 复测：双层执法 + 红段点名 + 豁免单形态 + 三段抽查。

## F3785 移交面清单（接口/语义/判据三面）

**语义边界**：清单是索引不是全文（全文在深化册——清单给"文件+条目号"的精确引用，不允许"参见"式模糊引用——域收口凭证的精确引用纪律在移交面同样生效）；清单覆盖面 = B16–B30 产出面（B01–B15 的移交面在 F3499——历史账不重列）。

- J2：清单版本锚（清单带版本——消费域领的版本显式，版本不明=移交糊涂账）。
**纯功能行数**：320（三清单生成器 ~130 + 三角对账 ~90 + 用例 ~100）
