### UNX-F0041 · DSDT 采集与校验链
- 域/批：A1/B03｜判据：UNX-F0041-J1 真机引导后定位 DSDT 指针、校验和与 OEM ID 提取落账，坏表时引导报告列出诊断项且不阻塞引导｜纯功能行数：300 行（双代指针选择器 80 + 校验链与头部清洗 90 + 坏表分档诊断 70 + DSDT 账与快照落账 60；测试段不计）｜状态：[已深化]
- **定位**：DSDT 是 AML 世界的正本（差异化系统描述表，全部设备命名空间与方法体的主载体），本条把"表索引里有一行 DSDT"升级为"DSDT 采集链可信"——FADT 双代指针选择、长度先行防越界、头部五项清洗、OEM 三元组提取、坏表分档诊断五环一次建齐，为 F0042/F0043/F0044 及后续全部 AML 深化条目供载荷指针与可信账。
- **语义边界**：只做 DSDT 定位、校验与账本登记；不做 SSDT 枚举（F0042）、不做 AML 词法扫描（F0043）、不做命名空间树构建（F0044）；AML 内容不解释不执行（解析归 A1，执行语义后续波次 ADR 立项）。
- **依赖与嫁接源**：依赖 F0003 `Facp` 结构取 X_DSDT/DSDT 双代字段（承接非重复——F0003 解码 FADT 特征位，本条消费其中的 DSDT 指针字段做专项链）、F0002 `checksum_ok`/`table_at` 与表索引、F0008 合并内存图交叉核对指针落点、F0012 高半区映射原语做只读映射；嫁接源为 ACPI 6.5 规范 FADT 章节第 5.2.11 节，只跟随。
- **风险与回退**：固件双代字段自相矛盾（X_DSDT 与 32 位 DSDT 指向不同）——以 X_DSDT 优先为原则、差异落冲突账可人工复核，极端冲突进 F0017 诊断模式；DSDT 坏表按降级档处置（引导报告列诊断项、引导继续、"ACPI 命名空间缺失"显式记账），致命档按 F0017 诊断路径处置，绝不静默吞错。
- 正文：实现路径分三步。第一步双代指针选择器：FADT 版本 ≥2.0 且 X_DSDT 非零时取 64 位指针，否则回退 32 位 DSDT 字段，两代选择结果与依据落账；指针经 F0012 高半区映射原语只读映射，映射前与 F0008 合并内存图交叉核对——指针落点必须是保留或 ACPI NVS 区，落进可用区即红账（固件撒谎的典型现场）。第二步校验链：长度字段与映射跨度一致性校验先行（坏长度表直接进诊断，不再做全表求和防越界读），随后表头五项清洗——签名 "DSDT"、校验和求和为零、修订版本、OEM ID 六字节可打印、OEM Table ID 与 OEM Revision 提取，三元组进 DSDT 专账。第三步坏表分档诊断：致命档（指针为零/长度越界/映射失败）与降级档（校验和失败/OEM 字段异常）分列，引导报告逐项列出表签名、物理地址、字段名、期望/实际值，降级档引导不阻塞；表头前 64 字节快照进 F0018 引导记账供事后比对。与现存内核衔接点：`acpi.rs` 新增 `Dsdt` 结构与 `dsdt()` 取用函数，全部逻辑落在 F0002/F0003 既有函数之上扩展。与 Windows 对照：Intel `acpidump.exe` 可导出 DSDT 并附校验状态，WDK 的 `asl.exe /tab=dsdt` 与 iasl 均以 DSDT 可解析为前提——固件坏 DSDT 在 Windows 侧的表现即 ACPI_BIOS_ERROR 停止码或设备管理器批量异常，本内核以"诊断不阻塞"为体验对齐点。判据 UNX-F0041-J1 的复测方式：三机型真机引导后 DSDT 指针/校验和/OEM ID 账与 acpidump 同机输出一致；人为注入坏校验和 DSDT 10/10 次引导报告列出诊断项且引导到达 F0019 检查面（随闸门补测登记）。

### UNX-F0042 · SSDT 多表枚举与版本登记
- 域/批：A1/B03｜判据：UNX-F0042-J1 全部 SSDT 枚举数与 XSDT 声明一致，逐表校验和通过，清单可导出比对｜纯功能行数：260 行（多实例迭代器 90 + 逐表校验与版本登记 90 + 清单导出比对 80；测试段不计）｜状态：[已深化]
- **定位**：SSDT 是 DSDT 的补丁包，一台真机挂 2–8 张是常态，本条把"按签名取表只拿到首张"升级为"多实例全枚举可信"——XSDT 声明序全收集、逐表校验、五元组版本登记、可导出清单四件一次建齐，枚举完整性（声明数与实收数一致）是 F0044 命名空间树不缺枝的前置保证。
- **语义边界**：只做 SSDT 枚举、校验与版本清单；不做 DSDT 采集链（F0041）、不做 AML 词法（F0043）、不做跨表 AML 引用解析（F0044 命名空间层防重）；清单登记不改表内容，全程只读。
- **依赖与嫁接源**：依赖 F0002 表索引（承接非重复——F0002 每表通用四元组登记，本条补同签名多实例迭代与声明数核对）、F0041 校验链体例复用；嫁接源为 ACPI 6.5 规范 XSDT 章节第 5.2.4 节，只跟随。
- **风险与回退**：同签名 SSDT 的 OEM 私有重复条目（真机实况非异常）——按（OEM ID，OEM Table ID，OEM Revision）三元组去重合并并留合并账；枚举数与声明数不一致时逐项列差异入诊断账，引导不阻塞；校验失败的表标记"不可用"但保留在清单内（缺席即失真，宁记坏不静默删）。
- 正文：实现路径分三步。第一步多实例迭代器：现存 `table_at` 按签名取表只返回首实例，本条扩展表索引为按签名向量并交付 `tables_by_sig("SSDT")` 迭代器——XSDT 条目区按序扫描全部收集，顺序严格保持 XSDT 声明序（AML 加载语义依赖表序，顺序账不可重排），`table_at` 首实例语义向后兼容。第二步逐表校验与版本登记：每张 SSDT 复用 F0041 校验链体例（长度先行、表头清洗、`checksum_ok` 求和），版本登记五元组（OEM ID/OEM Table ID/OEM Revision/创建修订/校验态）按声明序入清单。第三步清单导出比对：SSDT 清单（枚举数 + 逐表五元组）序列化进 F0018 引导记账，可经 F0011 引导日志通道导出，导出格式对齐 acpidump 输出风格（签名/长度/OEM ID/修订逐列），供同机 diff 审计。与现存内核衔接点：`acpi.rs` 表索引新增签名向量与迭代器，签名表扩容不改既有解析函数。与 Windows 对照：`acpidump.exe` 逐张列出全部 SSDT，iasl 可对每张独立反汇编，Windows 侧固件表异常时事件日志报 ACPI 驱动加载失败。判据 UNX-F0042-J1 的复测方式：三机型（含单 SSDT 与多 SSDT 机型）枚举数与 XSDT 声明一致、逐表校验和通过、导出清单与 acpidump 同机输出逐列 diff 一致；注入校验和坏表 10/10 次标记"不可用"且清单完整保留（随闸门补测登记）。

### UNX-F0043 · AML 只读反汇编基础（词法层）
- 域/批：A1/B03｜判据：UNX-F0043-J1 对 DSDT 前 64KB 做词法扫描，Opcode 识别覆盖率对照 iasl 抽样表 ≥99%，未知码有账｜纯功能行数：340 行（操作码静态表 110 + 流式词法扫描器 130 + 覆盖率账与未知码登记 100；测试段不计）｜状态：[已深化]
- **定位**：AML 词法层是 ACPI 反汇编工具链的第一块砖，本条交付纯只读的流式词法扫描器——把 DSDT 载荷字节流分类为 token 流（操作码/NameSeg/整数/字符串/包），产出覆盖率账与未知码账，是 F0044 命名空间树构建的直接供给端；全程零解释零执行，纯审计工具定位。
- **语义边界**：只做词法扫描与分类统计；不做命名空间树（F0044）、不做 _SB/_PRT 语义提取（F0045/F0046）、不解释不执行任何控制方法（执行语义不在本域本批，ADR 候选提交 AI-93）；反汇编输出仅服务诊断与审计，不作为运行期数据结构。
- **依赖与嫁接源**：依赖 F0041 `Dsdt` 账的载荷指针与长度（承接链：F0002 索引 → F0041 采集 → F0043 词法）；嫁接源为 ACPI 6.5 规范第 20 章 AML 规范与 ACPICA iasl 实现参照，只跟随。
- **风险与回退**：OEM 私有操作码与畸形 AML（校验和通过但内容坏）——未知字节登记三账（偏移 + 上下文 16 字节十六进制 + 重同步位置），重同步启发式（跳到下一合理 ExtOpPrefix 或 NameOp 边界）可配置开关，扫描不中断不崩溃；64KB 窗口截断处显式记"未扫余量"账（DSDT 常大于 64KB，判据窗口外部分不在本条范围）。
- 正文：实现路径分三步。第一步操作码静态表：按 ACPI 6.5 AML 文法建 const 表——单字节操作码族（NameOp 0x08/ScopeOp 0x10/MethodOp 0x14/PackageOp 0x12 等）、双字节 ExtOpPrefix 族（0x5B 前缀：DeviceOp 0x5B82/ProcessorOp 0x5B83 全族）、数据前缀族（0x0A–0x0E 整数编码与 0x0D 字符串前缀）、NameSeg（四字符可打印）与 Local/Arg 引用族，每项登记编码/长度语义/后随参数形态三列。第二步流式词法扫描器：游标式逐字节分类产出 token 流统计账（按操作码类计数）、NameSeg 可打印校验、字符串终止符校验、整数编码边界校验，零堆依赖（早年静态缓冲），token 统计进 F0018 引导记账。第三步覆盖率账与未知码登记：覆盖率 = 已识别 token 字节数 / 扫描总字节数，未知码 100% 有账（偏移+上下文+重同步三要素），扫描全程只读。与现存内核衔接点：`acpi.rs` 子系统新增 `aml_lex` 只读模块，消费 F0041 账，不触碰 `table_at`/`checksum_ok` 既有语义。与 Windows 对照：判据点名 iasl 抽样表——ACPICA iasl 反汇编同机 DSDT 提取操作码直方图为比对基准，WDK `asl.exe /tab=dsdt` 二次交叉（Windows 侧无内核态对应工具，故以双编译器采样替代对照）。判据 UNX-F0043-J1 的复测方式：三机型 DSDT 前 64KB 词法扫描覆盖率对照 iasl 抽样表 ≥99%、未知码 100% 三要素齐备、坏 AML 注入 10/10 次扫描不崩溃不中断（随闸门补测登记）。
