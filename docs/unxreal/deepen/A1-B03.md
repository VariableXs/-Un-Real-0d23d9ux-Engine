### UNX-F0041 · DSDT 采集与校验链
- 域/批：A1/B03｜判据：UNX-F0041-J1 真机引导后定位 DSDT 指针、校验和与 OEM ID 提取落账，坏表时引导报告列出诊断项且不阻塞引导｜纯功能行数：300 行（双代指针选择器 80 + 校验链与头部清洗 90 + 坏表分档诊断 70 + DSDT 账与快照落账 60；测试段不计）｜状态：[已深化]
- **定位**：DSDT 是 AML 世界的正本（差异化系统描述表，全部设备命名空间与方法体的主载体），本条把"表索引里有一行 DSDT"升级为"DSDT 采集链可信"——FADT 双代指针选择、长度先行防越界、头部五项清洗、OEM 三元组提取、坏表分档诊断五环一次建齐，为 F0042/F0043/F0044 及后续全部 AML 深化条目供载荷指针与可信账。
- **语义边界**：只做 DSDT 定位、校验与账本登记；不做 SSDT 枚举（F0042）、不做 AML 词法扫描（F0043）、不做命名空间树构建（F0044）；AML 内容不解释不执行（解析归 A1，执行语义后续波次 ADR 立项）。
- **依赖与嫁接源**：依赖 F0003 `Facp` 结构取 X_DSDT/DSDT 双代字段（承接非重复——F0003 解码 FADT 特征位，本条消费其中的 DSDT 指针字段做专项链）、F0002 `checksum_ok`/`table_at` 与表索引、F0008 合并内存图交叉核对指针落点、F0012 高半区映射原语做只读映射；嫁接源为 ACPI 6.5 规范 FADT 章节第 5.2.11 节，只跟随。
- **风险与回退**：固件双代字段自相矛盾（X_DSDT 与 32 位 DSDT 指向不同）——以 X_DSDT 优先为原则、差异落冲突账可人工复核，极端冲突进 F0017 诊断模式；DSDT 坏表按降级档处置（引导报告列诊断项、引导继续、"ACPI 命名空间缺失"显式记账），致命档按 F0017 诊断路径处置，绝不静默吞错。
- 正文：实现路径分三步。第一步双代指针选择器：FADT 版本 ≥2.0 且 X_DSDT 非零时取 64 位指针，否则回退 32 位 DSDT 字段，两代选择结果与依据落账；指针经 F0012 高半区映射原语只读映射，映射前与 F0008 合并内存图交叉核对——指针落点必须是保留或 ACPI NVS 区，落进可用区即红账（固件撒谎的典型现场）。第二步校验链：长度字段与映射跨度一致性校验先行（坏长度表直接进诊断，不再做全表求和防越界读），随后表头五项清洗——签名 "DSDT"、校验和求和为零、修订版本、OEM ID 六字节可打印、OEM Table ID 与 OEM Revision 提取，三元组进 DSDT 专账。第三步坏表分档诊断：致命档（指针为零/长度越界/映射失败）与降级档（校验和失败/OEM 字段异常）分列，引导报告逐项列出表签名、物理地址、字段名、期望/实际值，降级档引导不阻塞；表头前 64 字节快照进 F0018 引导记账供事后比对。与现存内核衔接点：`acpi.rs` 新增 `Dsdt` 结构与 `dsdt()` 取用函数，全部逻辑落在 F0002/F0003 既有函数之上扩展。与 Windows 对照：Intel `acpidump.exe` 可导出 DSDT 并附校验状态，WDK 的 `asl.exe /tab=dsdt` 与 iasl 均以 DSDT 可解析为前提——固件坏 DSDT 在 Windows 侧的表现即 ACPI_BIOS_ERROR 停止码或设备管理器批量异常，本内核以"诊断不阻塞"为体验对齐点。判据 UNX-F0041-J1 的复测方式：三机型真机引导后 DSDT 指针/校验和/OEM ID 账与 acpidump 同机输出一致；人为注入坏校验和 DSDT 10/10 次引导报告列出诊断项且引导到达 F0019 检查面（随闸门补测登记）。

### UNX-F0042 · SSDT 多表枚举与版本登记
- 域/批：A1/B03｜判据：UNX-F0042-J1 全部 SSDT 枚举数与 XSDT 声明一致，逐表校验和通过，清单可导出比对｜纯功能行数：260 行（多实例迭代器 90 + 逐表校验与版本登记 90 + 清单导出比对 80；测试段不计）｜状态：[已深化]
- **定位**：SSDT 是 DSDT 的补丁包，一台真机挂 2–8 张是常态，本条把"按签名取表只拿到首张"升级为"多实例全枚举可信"——XSDT 声明序全收集、逐表校验、五元组版本登记、可导出清单四件一次建齐，枚举完整性（声明数与实收数一致）是 F0044 命名空间树不缺枝的前置保证。
- **语义边界**：只做 SSDT 枚举、校验与版本清单；不做 DSDT 采集链（F0041）、不做 AML 词法（F0043）、不做跨表 AML 引用解析（F0044 命名空间层防重）；清单登记不改表内容，全程只读。
- **依赖与嫁接源**：依赖 F0002 表索引（承接非重复——F0002 每表通用四元组登记，本条补同签名多实例迭代与声明数核对）、F0041 校验链体例复用；嫁接源为 ACPI 6.5 规范 XSDT 章节第 5.2.4 节，只跟随。
- **风险与回退**：同签名 SSDT 的 OEM 私有重复条目（真机实况非异常）——按（OEM ID，OEM Table ID，OEM Revision）三元组去重合并并留合并账；枚举数与声明数不一致时逐项列差异入诊断账，引导不阻塞；校验失败的表标记"不可用"但保留在清单内（缺席即失真，宁记坏不静默删）。
- 正文：实现路径分三步。第一步多实例迭代器：现存 `table_at` 按签名取表只返回首实例，本条扩展表索引为按签名向量并交付 `tables_by_sig("SSDT")` 迭代器——XSDT 条目区按序扫描全部收集，顺序严格保持 XSDT 声明序（AML 加载语义依赖表序，顺序账不可重排），`table_at` 首实例语义向后兼容。第二步逐表校验与版本登记：每张 SSDT 复用 F0041 校验链体例（长度先行、表头清洗、`checksum_ok` 求和），版本登记五元组（OEM ID/OEM Table ID/OEM Revision/创建修订/校验态）按声明序入清单。第三步清单导出比对：SSDT 清单（枚举数 + 逐表五元组）序列化进 F0018 引导记账，可经 F0011 引导日志通道导出，导出格式对齐 acpidump 输出风格（签名/长度/OEM ID/修订逐列），供同机 diff 审计。与现存内核衔接点：`acpi.rs` 表索引新增签名向量与迭代器，签名表扩容不改既有解析函数。与 Windows 对照：`acpidump.exe` 逐张列出全部 SSDT，iasl 可对每张独立反汇编，Windows 侧固件表异常时事件日志报 ACPI 驱动加载失败。判据 UNX-F0042-J1 的复测方式：三机型（含单 SSDT 与多 SSDT 机型）枚举数与 XSDT 声明一致、逐表校验和通过、导出清单与 acpidump 同机输出逐列 diff 一致；注入校验和坏表 10/10 次标记"不可用"且清单完整保留（随闸门补测登记）。

### UNX-F0043 · AML 只读反汇编基础（词法层）
- 域/批：A1/B03｜判据：UNX-F0043-J1 对 DSDT 前 64KB 做词法扫描，Opcode 识别覆盖率对照 iasl 抽样表 ≥99%，未知码有账｜纯功能行数：340 行（操作码静态表 110 + 流式词法扫描器 130 + 覆盖率账与未知码登记 100；测试段不计）｜状态：[已深化]
- **定位**：AML 词法层是 ACPI 反汇编工具链的第一块砖，本条交付纯只读的流式词法扫描器——把 DSDT 载荷字节流分类为 token 流（操作码/NameSeg/整数/字符串/包），产出覆盖率账与未知码账，是 F0044 命名空间树构建的直接供给端；全程零解释零执行，纯审计工具定位。
- **语义边界**：只做词法扫描与分类统计；不做命名空间树（F0044）、不做 _SB/_PRT 语义提取（F0045/F0046）、不解释不执行任何控制方法（执行语义不在本域本批，ADR 候选提交 AI-93）；反汇编输出仅服务诊断与审计，不作为运行期数据结构。
- **依赖与嫁接源**：依赖 F0041 `Dsdt` 账的载荷指针与长度（承接链：F0002 索引 → F0041 采集 → F0043 词法）；嫁接源为 ACPI 6.5 规范第 20 章 AML 规范与 ACPICA iasl 实现参照，只跟随。
- **风险与回退**：OEM 私有操作码与畸形 AML（校验和通过但内容坏）——未知字节登记三账（偏移 + 上下文 16 字节十六进制 + 重同步位置），重同步启发式（跳到下一合理 ExtOpPrefix 或 NameOp 边界）可配置开关，扫描不中断不崩溃；64KB 窗口截断处显式记"未扫余量"账（DSDT 常大于 64KB，判据窗口外部分不在本条范围）。
- 正文：实现路径分三步。第一步操作码静态表：按 ACPI 6.5 AML 文法建 const 表——单字节操作码族（NameOp 0x08/ScopeOp 0x10/MethodOp 0x14/PackageOp 0x12 等）、双字节 ExtOpPrefix 族（0x5B 前缀：DeviceOp 0x5B82/ProcessorOp 0x5B83 全族）、数据前缀族（0x0A–0x0E 整数编码与 0x0D 字符串前缀）、NameSeg（四字符可打印）与 Local/Arg 引用族，每项登记编码/长度语义/后随参数形态三列。第二步流式词法扫描器：游标式逐字节分类产出 token 流统计账（按操作码类计数）、NameSeg 可打印校验、字符串终止符校验、整数编码边界校验，零堆依赖（早年静态缓冲），token 统计进 F0018 引导记账。第三步覆盖率账与未知码登记：覆盖率 = 已识别 token 字节数 / 扫描总字节数，未知码 100% 有账（偏移+上下文+重同步三要素），扫描全程只读。与现存内核衔接点：`acpi.rs` 子系统新增 `aml_lex` 只读模块，消费 F0041 账，不触碰 `table_at`/`checksum_ok` 既有语义。与 Windows 对照：判据点名 iasl 抽样表——ACPICA iasl 反汇编同机 DSDT 提取操作码直方图为比对基准，WDK `asl.exe /tab=dsdt` 二次交叉（Windows 侧无内核态对应工具，故以双编译器采样替代对照）。判据 UNX-F0043-J1 的复测方式：三机型 DSDT 前 64KB 词法扫描覆盖率对照 iasl 抽样表 ≥99%、未知码 100% 三要素齐备、坏 AML 注入 10/10 次扫描不崩溃不中断（随闸门补测登记）。

### UNX-F0044 · AML 命名空间树构建（只读）
- 域/批：A1/B03｜判据：UNX-F0044-J1 构建的 \_SB/\_GPE/\_PR 树节点数与 iasl 反汇编结果抽样一致（抽 3 机型各 100 节点）｜纯功能行数：360 行（节点池与树构建 140 + 多表增量合并 100 + 冲突账与深度保护 60 + 快照导出 60；测试段不计）｜状态：[已深化]
- **定位**：命名空间树是 AML 世界的"文件系统树"——\_SB（系统总线）、\_GPE（事件）、\_PR（处理器）、\_TZ（温区）等预定义根域下的 Device/Scope/Method/Processor/ThermalZone 层级结构。本条把 F0043 的线性 token 流升级为可导航的树结构，是 F0045 设备拓扑提取与 F0046 _PRT 路由提取的共同供给端，也是后续全部 AML 消费类条目的地基。
- **语义边界**：只读构建树结构并登记节点元数据（类型/名段/起始偏移/长度）；不做方法体解释与执行（执行语义不在本域本批，ADR 候选提交 AI-93）、不做 _SB 设备属性专项提取（F0045）、不做 _PRT 提取（F0046）；树中 Method 节点只登记体量与偏移，不解析内容。
- **依赖与嫁接源**：依赖 F0043 词法 token 流（承接链：F0002 索引 → F0041 采集 → F0043 词法 → F0044 树）、F0042 SSDT 清单（多表加载序）、F0041 DSDT 载荷指针；嫁接源为 ACPI 6.5 规范第 20 章 AML 规范（NameOp/ScopeOp/ExtOpPrefix 建树语义）与 ACPICA namespace 实现参照，只跟随。
- **风险与回退**：SSDT 对 DSDT 已有路径的二次定义（真机常态非异常）——按 ACPI 加载序（DSDT 先、SSDT 按声明序后）增量合并，二次定义记冲突账并保留双版本节点，合并结果树以"最终态"呈现、历史态入账可查；畸形嵌套（Scope 未闭合/包长度越界）——树深度上限 64 层与包长度边界双保护，越界即停扫描、已建子树保留、诊断账登记偏移，绝不越界读写。
- 正文：实现路径分三步。第一步节点池与树构建：早年静态节点池（零堆依赖，容量按 DSDT+SSDT 合计 64KB 窗口预估上限），消费 F0043 token 流——ScopeOp/DeviceOp/ProcessorOp/ThermalZoneOp/PowerResOp 入树为容器节点，NameOp 为叶子登记，MethodOp 登记体量与偏移不解析体；每个节点五元组（类型/名段四字符/父指针/AML 偏移/子节点链）入池，\ 根节点为锚，相对路径（\_SB.PCI0 类）按 ACPI 路径语法逐段下探。第二步多表增量合并：按 F0042 清单序先 DSDT 后 SSDT 逐表建树合并，二次定义路径按加载序后者覆盖、前者入冲突账（保留双版本偏移供审计）。第三步冲突账与快照导出：冲突账（路径/双版本偏移/来源表五元组）与树统计账（各根域节点数/总节点数/最大深度）序列化进 F0018 引导记账，快照可经 F0011 通道导出供同机 diff。与现存内核衔接点：`acpi.rs` 新增 `aml_ns` 只读模块，消费 `aml_lex` 输出，不触碰表索引既有语义。与 Windows 对照：iasl 反汇编输出的 Scope/Device 层级即对照真值——本树节点数与层级对照 iasl -d 抽样一致；Windows 侧对应物是设备管理器与 `wmic namespace` 视角的 ACPI 节点呈现，坏命名空间在 Windows 表现为 ACPI.sys 加载失败事件。判据 UNX-F0044-J1 的复测方式：抽 3 机型各取 \_SB/\_GPE/\_PR 三域前 100 节点与 iasl 反汇编逐节点比对（类型+名段）一致（随闸门补测登记）。

### UNX-F0045 · \_SB 设备拓扑提取
- 域/批：A1/B03｜判据：UNX-F0045-J1 提取的设备 HID/_ADR 列表与 Windows 设备管理器同机快照抽样一致（≥10 台设备）｜纯功能行数：280 行（设备节点遍历 100 + EISAID 解码 60 + _ADR/_UID/_STA 静态位登记 60 + 快照与对照账 60；测试段不计）｜状态：[已深化]
- **定位**：\_SB 域的 Device 节点携带 _HID（硬件 ID）/ _ADR（总线地址）/ _UID（唯一实例）/ _STA（静态使能位）四类静态属性，构成"引导期就能看见的设备地图"。本条把命名空间树里的设备节点提取为拓扑清单，供后续波次设备枚举域与 B4 域交叉核对，也是引导报告"设备面摘要"的数据源。
- **语义边界**：只做静态属性提取与登记；_STA 动态求值（方法执行返回运行期状态）不做——只登记 _STA 存在性与 AML 偏移，动态语义归执行层 ADR；不做 _PRT 提取（F0046）、不做 _CRS 资源解析（执行语义同理）；电源类对象（\_PR0/\_PR3）只登记存在性。
- **依赖与嫁接源**：依赖 F0044 命名空间树（承接非重复——F0044 建树，本条做 \_SB 域专项遍历与属性解码）；嫁接源为 ACPI 6.5 规范第 6 章（设备配置：_HID/_ADR/_UID/_STA 定义）与 EISAID 编码规范（PNP ID 压缩 32 位编码），只跟随。
- **风险与回退**：_HID 为 EISAID 压缩整数（如 0x0103D041 即 PNP0A03 的压缩形态）与字符串两种形态并存——解码器双形态兼容，解码失败记"不可解码"账不中断；无 _HID 只有 _ADR 的总线子设备——双键登记（_ADR 为主键）；_HID 值异常（空串/全零）——登记异常账并保留节点，绝不丢弃设备。
- 正文：实现路径分三步。第一步设备节点遍历：从 F0044 树的 \_SB 根出发深度优先遍历全部 Device 子树，逐节点登记路径、父路径、AML 偏移；遍历深度与节点数受 F0044 深度保护约束。第二步 EISAID 解码：_HID 的 32 位压缩编码按 EISAID 规范逐段展开（3 字符厂商码 + 4 位十六进制产品码），字符串形态直取，解码结果双形态统一为 "PNP####" 规范式登记。第三步静态属性登记与对照账：_ADR（总线地址高位 device/低位 function）、_UID、_STA 静态位（present/enabled/show 三位摘录）逐项入设备拓扑清单；清单含"可打印摘要"（设备路径 + HID + ADR 三列）进 F0018 引导记账。与现存内核衔接点：`aml_ns` 模块新增 `sb_devices()` 遍历接口，消费树不修改树。与 Windows 对照：设备管理器"按连接查看设备"树即对照面——HID 列表与同机 Windows 快照（`pnputil /enum-devices` 可脚本化导出）比对；Windows 侧固件拓扑坏行表现为设备幽灵项或重复项（设备管理器黄色叹号群），本内核以"清单如实呈现 + 异常记账"对齐。判据 UNX-F0045-J1 的复测方式：同机导出 Windows 设备清单与本拓扑清单按 HID+ADR 双键比对，抽 ≥10 台设备一致（随闸门补测登记）。

### UNX-F0046 · _PRT PCI 中断路由表提取
- 域/批：A1/B03｜判据：UNX-F0046-J1 _PRT 路由项提取后与 lspci 同机中断号对照一致，供 B4 域消费｜纯功能行数：300 行（_PRT 包解析 120 + 两类路由项账 90 + 与 F0004 Override 表交叉核对 90；测试段不计）｜状态：[已深化]
- **定位**：_PRT（PCI Routing Table）是 PCIe 设备 INTx 引脚到 GSI 全局中断号映射的唯一真相源——每个 PCI 设备的四引脚（INTA–INTD）路由项以 Package 数组形式挂在 PCI 桥的 _PRT 对象下。本条把路由项提取为结构化账本，是 B4 域块设备中断接线的上游供给，与 F0004 的 Interrupt Source Override 表（ISA 侧）共同构成中断路由初值的完整来源。
- **语义边界**：只做 _PRT 包的解析、两类路由项（静态 GSI 项与动态 Link 设备引用项）登记与交叉核对；Link 设备的 _CRS/_PRS/_SRS 动态求值不做（方法执行语义）；路由决策与 RTE 编程归 AI-02（分界判例"初值归 A1，路由归 A2"）。
- **依赖与嫁接源**：依赖 F0044 命名空间树定位 _PRT 对象、F0045 设备拓扑（桥节点路径）、F0004 Override 表（GSI 语义交叉）；嫁接源为 ACPI 6.5 规范第 6.2.12 节（_PRT 定义）与第 19.6.x 节（Package 编码），只跟随。
- **风险与回退**：动态 Link 引用项（Source 为设备名而非 0）在方法执行缺席时不可解出最终 GSI——登记"待解析"账（路径 + 引用设备名），GSI 字段置显式无效值 0xFFFFFFFF 并在账中标"Link-pending"，绝不编造静态值；_PRT 覆盖不全（某桥缺 _PRT）——按 PCI 规范缺省路由假设有账声明（假设值与实际偏差进诊断），不静默；重复路由项（同 Address+Pin 双条目）——冲突账登记后者，绝不覆盖前者且不中断。
- 正文：实现路径分三步。第一步 _PRT 包解析：遍历 F0044 树定位全部 _PRT 对象（挂在 PCI Root Bridge 与 PCIe 桥 Device 节点下），逐包按五元组解码（Address 64 位高 device 低 function、Pin 0–3、Source、SourceIndex）；F0043 词法层已把 Package 编码为 token，本条做语义装配。第二步两类路由项账：静态项（Source=0，GSI 直接给出）登记 GSI + 触发模式推断位；动态项登记 Link 设备路径与 SourceIndex，标 Link-pending 待执行层解析；两类项统一入"_PRT 路由账"（桥路径/Address/Pin/Source/GSI 或 pending 五列）。第三步交叉核对：静态项 GSI 与 F0004 Override 表的 GSI 空间交叉核对——GSI 落在 ISA 0–15 区且 Override 有映射的，登记映射关系；GSI 超出平台声明的，异常账。与现存内核衔接点：`aml_ns` 模块新增 `prt_table()` 提取接口，产出结构体数组供 B4 域消费（冻结接口候选，波 01 Q3 冻结申报）。与 Windows 对照：`lspci -vv` 的中断引脚/路由显示与 Windows 设备管理器"资源"页的 IRQ 分配同源——本路由账是 Varix 侧对应物，Windows 侧 _PRT 坏行表现为 PCI 设备资源冲突黄色叹号群与 PCI 中断路由失败事件日志。判据 UNX-F0046-J1 的复测方式：同机 lspci 对照静态项中断号一致、Link-pending 项 100% 有账（随闸门补测登记）。

### UNX-F0047 · MCFG 表与 PCIe ECAM 基址固化
- 域/批：A1/B03｜判据：UNX-F0047-J1 ECAM 基址/段号/总线范围与真机一致，配置空间首字节读取判据通过｜纯功能行数：240 行（表解析与段登记 100 + 内存图交叉核对 70 + 降级声明 70；测试段不计）｜状态：[已深化]
- **定位**：MCFG（PCIe Memory Mapped Configuration）表声明 ECAM 窗口——每总线段（Segment）的 MMIO 配置空间基址与总线范围。本条把"表里有一行 MCFG"升级为"ECAM 基址可信可用"：解析、与内存图交叉核对、段-总线三元组登记三环，是后续波次 PCIe 枚举域（B 部）读写配置空间的唯一合法窗口声明。
- **语义边界**：只做 MCFG 解析、ECAM 基址登记与只读验证（读配置空间首字节 Vendor ID 断言非全 F）；不做 PCIe 设备枚举（归 B 部）、不做配置空间写入；MCFG 缺席时的传统 PCI CAM 探测不在本条（降级声明即止）。
- **依赖与嫁接源**：依赖 F0002 表索引取 MCFG、F0008 合并内存图交叉核对（ECAM 窗口必须是保留/MMIO 区）、F0012 高半区映射原语做窗口映射；嫁接源为 PCIe 规范 ECAM 章节（基址对齐 256MB/段、偏移 = bus×1MB+dev×32KB+fn×4KB+reg）与 ACPI 6.5 规范 MCFG 章节第 5.2.1.6 节，只跟随。
- **风险与回退**：MCFG 声明窗口与内存图矛盾（基址落在 usable 区）——固件撒谎红账，进 F0017 诊断模式而非继续使用；总线范围超声明（end_bus > start_bus+255）——越界账截断；ECAM 缺席（BIOS 老机）——降级声明"legacy CAM 模式"入引导报告，枚举域后续按 legacy 语义接线，绝不假装 ECAM 存在。
- 正文：实现路径分三步。第一步表解析与段登记：MCFG 头后为段描述符数组（基址 64 位/PCI 段号/起始总线/结束总线/保留），逐段校验（基址 256MB 对齐、段号递增、总线范围自洽），登记为 ECAM 段账。第二步内存图交叉核对：每段 ECAM 窗口（基址起 256MB×总线数）与 F0008 合并内存图求交——窗口必须整体落在保留或 MMIO 类型区，与可用区相交即红账进诊断；核对通过后经 F0012 映射原语只读映射窗口首 4KB。第三步只读验证与降级声明：读总线 0 设备 0 功能 0 配置空间首双字（Vendor ID/Device ID），全 F（0xFFFFFFFF）即视为窗口无效进降级；MCFG 整表缺席时打印降级声明（含签名"ECAM absent, legacy CAM pending"）入引导报告。与现存内核衔接点：`acpi.rs` 新增 `Mcfg` 结构与 `ecam_segments()` 取用函数，映射走 F0012 既有原语。与 Windows 对照：`lspci` 无需 ECAM 也能经 legacy CAM 工作，但现代 Windows 全部走 ECAM（设备管理器资源页可见大段 MMIO 配置窗口）；ECAM 配置错误在 Windows 表现为开机即 0xA0 类 ACPI 错误或 PCI 枚举失败。判据 UNX-F0047-J1 的复测方式：真机读段 0 总线 0 设备 0 功能 0 的 Vendor ID 与 lspci 同机输出一致，段登记三元组与 MCFG 表逐项一致（随闸门补测登记）。

### UNX-F0048 · SRAT/SLIT NUMA 拓扑解析
- 域/批：A1/B03｜判据：UNX-F0048-J1 节点数/CPU 归属/内存区间与真机拓扑一致（单路机退化单节点有账）｜纯功能行数：260 行（SRAT 解析 100 + SLIT 矩阵 60 + 退化与联签账 100；测试段不计）｜状态：[已深化]
- **定位**：SRAT（System Resource Affinity Table）声明"哪个 CPU 属于哪个 NUMA 节点、哪段内存属于哪个节点"，SLIT（System Locality Distance Information Table）声明节点间访问距离矩阵。本条把双表解析为拓扑账本，供 A3（调度亲和提示）与 A4（节点优先分配）远期消费——本域只交付"图纸"，施工（策略）归下游，分界判例"图纸归 A1，施工归 A4"在本条的实例。
- **语义边界**：只做 SRAT/SLIT 解析、归属账本与距离矩阵登记；不做调度/内存分配策略（A3/A4）、不做节点在线判定（AP 到齐账归 B17 段条目）；SRAT 的内存Affinity与 X2APIC Affinity 两种结构都解析。
- **依赖与嫁接源**：依赖 F0002 表索引取 SRAT/SLIT、F0004 LAPIC 列表（APIC ID 联签核对——SRAT 声明的 APIC UID 必须能在 F0004 处理器列表找到）；嫁接源为 ACPI 6.5 规范第 5.2.16/5.2.17 节，只跟随。
- **风险与回退**：单路机无 SRAT/SLIT——退化单节点账（全部 CPU/内存归节点 0，距离矩阵单值 10），账中显式标注"退化态"防下游误读；SRAT 声明的 APIC UID 与 F0004 不相交——孤儿条目账（不进拓扑、引导报告列诊断），不静默丢弃；内存区间重叠（双节点声明同区间）——冲突账首表优先。
- 正文：实现路径分三步。第一步 SRAT 解析：表头后逐结构扫描——Processor Local APIC/X2APIC Affinity（APIC UID/节点号/标志位）、Memory Affinity（基址/长度/节点号/标志位含 hot-pluggable 位）两类逐条登记；标志位逐位校验（enabled 位为零的条目登记但不计入有效拓扑）。第二步 SLIT 矩阵：N×N 距离字节阵登记，对角线自检（diag 必须为 10，异常记账）、对称性抽检（对称破缺记账不修正——如实呈现固件声明）。第三步退化与联签账：无 SRAT 时构建退化单节点账并显式标注；APIC UID 与 F0004 处理器列表求交，孤儿条目账列全；产出"NUMA 拓扑账"（节点数/逐节点 CPU 列表/逐节点内存区间/距离矩阵摘要）进 F0018 引导记账。与现存内核衔接点：`acpi.rs` 新增 `Srat`/`Slit` 结构与 `numa_topology()` 汇总函数，消费方接口留 A3/A4 冻结位。与 Windows 对照：Windows 侧 `coreinfo`（Sysinternals）可视化 NUMA 拓扑即对照面——节点数与 CPU 归属同源同真值；SRAT 坏行在 Windows 表现为 NUMA 节点缺失或内存归属异常（性能骤降类故障）。判据 UNX-F0048-J1 的复测方式：多路真机节点数/CPU 归属与 coreinfo 一致、单路真机退化单节点账显式（随闸门补测登记）。

### UNX-F0049 · UEFI SystemTable 只读快照
- 域/批：A1/B03｜判据：UNX-F0049-J1 引导期对 SystemTable 各指针快照落 BootManifest，退出后不再访问（越界访问断言为零）｜纯功能行数：280 行（快照结构 100 + 置毒与断言 90 + Manifest 落账 90；测试段不计）｜状态：[已深化]
- **定位**：UEFI SystemTable 是固件交接的总枢纽——HDR、固件厂商串、BootServices/RuntimeServices/ConfigTable 等指针全在其中。任务书专题三已裁决：本域**弃用 Runtime Services**（时钟走 HPET/TSC、重启走 ACPI RESET_REG 与 0xFE 双路、关机走 FACP SLP_TYP）。本条把该裁决工程化：引导期对 SystemTable 全指针做一次性只读快照入 BootManifest，随后把原始指针"置毒"，运行期任何越界访问都被断言当场抓住——这是"弃用运行时服务"候选 ADR 的执行面。

- **风险与回退**：Limine 响应缺 EFI 系统表（BIOS 路）——快照账显式标"BIOS path, no EFI snapshot"，判据走 BIOS 路矩阵；快照时指针为空——逐指针可空性校验（空指针登记"absent"而非置毒崩溃）；置毒值的误读（把毒值当真指针）——毒值选非规范对齐魔数（0xDEADBEEF 类不可映射值）并在类型系统上用枚举包装防混淆。

### UNX-F0050 · UEFI 变量只读枚举
- 域/批：A1/B03｜判据：UNX-F0050-J1 引导期枚举全部变量名/GUID/属性，与 efibootmgr 同机对照一致，全程只读零写入｜纯功能行数：300 行（枚举协议 120 + 三元组账 90 + 对照导出 90；测试段不计）｜状态：[已深化]
- **定位**：UEFI 变量是固件世界的"注册表"——启动项（Boot####）、引导顺序（BootOrder）、SecureBoot 配置全在其中。本条在 EBS 前的最后窗口对变量区做**全量只读枚举**（GetNextVariableName 协议遍历），产出变量名/GUID/属性三元组账本，为 F0051（SecureBoot 态）供给数据、为 L1 域安装器（远期写启动项）提供态势快照。全程零写入——变量区写入归 L 部且触发红线复核，本条宁读不写。

### UNX-F0053 · ExitBootServices 时序协议
- 域/批：A1/B03｜判据：UNX-F0053-J1 两次调用语义（首调后 MapKey 失效重取）真机按协议执行，GetMemoryMap 重取零遗漏｜纯功能行数：320 行（时序状态机 120 + MapKey 重取协议 100 + 失败路径 100；测试段不计）｜状态：[已深化]
- **定位**：ExitBootServices（EBS）是固件世界与内核世界的"边境检查站"——首调后 Boot Services 全部失效，但固件可能在此刻最后修改内存图，因此规范要求：首调后必须重取 GetMemoryMap 检查图是否变更，变更则重取 MapKey 再次调用。这是 UEFI 移植的第一经典陷阱区（内核社区无数引导失败的根因）。本条把 EBS 时序做成显式状态机，含 F0049/F0050 两个消费方的调用时序约束。
- **语义边界**：只做 EBS 时序状态机与失败路径；不做 EBS 后的内存重整（F0008 合并已在 EBS 前完成初版、EBS 后做终版合并——时序账标注）；Boot Services 封装不做（EBS 后即弃用）；EBS 前最后窗口的调用清单（F0049 快照、F0050 枚举）由本状态机排程。
- **依赖与嫁接源**：依赖 F0008 内存图（EBS 前后两版对比）、F0049/F0050（时序约束消费者）；嫁接源为 UEFI 2.10 规范第 7.3 节（ExitBootServices 语义与 GetMemoryMap/MapKey 重取协议），只跟随。
- **风险与回退**：EBS 失败（EFI_INVALID_PARAMETER——MapKey 过期竞态）——重试上限 3 次（重取 MapKey→再调），超限进诊断模式（F0017）并打印失败码；EBS 后仍访问 Boot Services——状态机置"post-exit"位，debug 断言网（复用 F0049 置毒机制）当场 panic；首调后内存图变更未检出——两版图 diff 断言，变更未反映即红账。
- 正文：实现路径分三步。第一步时序状态机：四态显式机——`PreExit`（最后窗口：F0049 快照 → F0050 枚举 → 终版 GetMemoryMap）、`FirstCall`（持 MapKey 首调 EBS）、`Revalidate`（重取 GetMemoryMap 与首版 diff）、`PostExit`（固件服务置毒、进入内核自治）；每态迁移带边界断言。第二步 MapKey 重取协议：Revalidate 态检出内存图变更（条目数或任一描述符差异）时重取 MapKey 再调 EBS——循环上限 3 次；变更检出但无变更时直通 PostExit；diff 结果（变更条目清单）入 F0018 引导记账。第三步失败路径：EFI_INVALID_PARAMETER/EFI_NOT_FOUND 等失败码分档登记，重试耗尽即进 F0017 诊断模式（串口输出失败码与 MapKey 序号）——绝不静默重启循环；PostExit 位挂接全局断言网（任何 Boot Services 函数指针解引用即 panic）。与现存内核衔接点：`boot` 模块新增 `exit_timing()` 状态机模块，`main` 入口序第 0 位调用。与 Windows 对照：Windows bootmgr 的 EBS 处理同样实现重取协议（引擎级同构），固件 EBS 坏行在 Windows 表现为卡 Logo 或 INACCESSIBLE_BOOT_DEVICE 类启动失败——本内核以"三态显式账 + 诊断退路"提供超越 Windows 的可观测性。判据 UNX-F0053-J1 的复测方式：三机型真机引导时序账完整（PreExit→PostExit 无跳态）、注入 MapKey 竞态模拟重取 3/3 成功（随闸门补测登记）。

- 正文：实现路径分三步。第一步断言聚合器：定义 B03 组断言注册表——19 条条目各一条主断言（判据 J1 的 ktest 化：可观测动作 + 阈值 + 账本输入）与派生断言（如 F0044 树深度 ≤64、F0053 状态机无跳态、F0052 矛盾账可空性）；注册表静态 const，断言函数纯消费账本结构。第二步逐条接线：各功能条目的账本结构挂接断言输入（账本零值即断言失败——"没采到"与"采到但错"分列报告）；失败隔离（单条失败不中断组，继续跑完全组）。第三步报告输出：B03 组报告（总断言数/通过/失败/跳过四态计数 + 逐条结果 + 实机判据待测清单）进 ktest 总报告，一次命令全跑。与现存内核衔接点：`ktest` 引导面新增 `b03_group()` 注册单元，消费 `acpi.rs`/`boot` 模块既有账本，不改其语义。与 Windows 对照：Windows 无公开对等的引导期断言面（WLK/HCK 是离线认证体系）——本内核的 ktest 面是体验完整性的自有创新：把"引导做对了"变成每次引导可复验的机械事实。判据 UNX-F0060-J1 的复测方式：ktest 引导面一次命令全跑通过率 100%（逻辑面）、实机判据清单单列随闸门补测（登记双轨口径）。
