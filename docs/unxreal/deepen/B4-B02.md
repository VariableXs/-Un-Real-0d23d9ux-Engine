### UNX-F6421 · Request 结构体与请求状态机
- 域/批：B4/B02｜判据：UNX-F6421-J1 请求五态（allocated→queued→in-flight→completed→freed）迁移全可观测，非法迁移注入 100% 拒绝；状态机与设计图逐边一致｜纯功能行数：383 行（Request 结构体 140 + 五态状态机 130 + 迁移可观测账 113；测试段不计）｜状态：[已深化]
- **定位**：request 是块层多队列化的核心对象：bio 在队列里排队、合并、派发、完成的载体。本条立 Request 结构体（bio 引用/标签/LBA 范围/状态/计时戳五要素）与五态状态机——五态全可观测是"每请求必有终态"铁律在请求层的表达，也是合并器、超时派发器、重试策略的公共地基。
- **语义边界**：只做请求对象与状态机；不做分配器（F6422 防重）、不做合并本体（F6423/F6424 防重）、不做派发路径（B03 防重）；状态迁移唯一执行点在状态机内。
- **依赖与嫁接源**：依赖 F6402 bio 与 F6415 断言面；嫁接源为 Linux blk-mq request 生命周期（MQ_RQ_* 态）语义与 Windows SRB 状态域（SRB_STATUS 族）语义坐标，只跟随。
- **风险与回退**：状态机竞态（多核同时迁移同一请求）——迁移原子化（CAS 单点），同请求迁移串行化断言；非法迁移注入即红账并冻结请求（不再派发）。
- 正文：实现路径分三步。第一步结构体：Request 含 tag（F6422 分配）、bio 引用链（拆分聚合头）、LBA 范围（首+扇区数，合并器判定域）、op/flags、状态域（五态枚举+迁移时间戳）、错误域与重试计数；全部字段与设计图逐字段对照落账。第二步五态机：allocated→queued（入队）→in-flight（派发）→completed/error（终态）→freed（回收）单向迁移，error 分支可入 queued（重试，F6432 消费），每边原子 CAS 迁移+时间戳记录，非法边（如 freed→in-flight）100% 拒绝并冻结请求。第三步可观测账：迁移边计数账（每边累计次数）+在态时长采样，注入测试（乱序完成/重复完成/跳态）全检出；与 F6430 全态审计联动。与现存内核衔接点：现存"单请求直通"（无请求对象）语义由本条注销——薄层路径同样构造请求对象（1 请求 1 bio），旧调用方零感知。与 Windows 对照：Windows storport 对 SRB 维护状态域且 SRB_STATUS 在 WPA 可观测（微软跟踪文档化），本内核五态+逐边账面化对齐且更细，判据 UNX-F6421-J1 的复测方式：五态迁移边覆盖率 100% 机检、非法迁移注入 10 型全拒、迁移账与设计图逐边一致。

### UNX-F6422 · 请求分配器（tag→request 映射）
- 域/批：B4/B02｜判据：UNX-F6422-J1 tag 分配/回收 10^6 次零重复零泄漏；tag 唯一性断言（并发分配压力下无双占）｜纯功能行数：343 行（分配器结构与位图 110 + tag→request 映射表 120 + 并发分配账 113；测试段不计）｜状态：[已深化]
- **定位**：tag 是请求的"排队号"：设备命令与请求以 tag 对账（NVMe cmdid 对接 B10 F6585），tag 分配器是请求层的号码机。本条立 tag 分配/回收与 tag→request 映射表，10^6 次零重复零泄漏与并发无双占是硬判据——号码错乱等于命令错乱。
- **语义边界**：只做 tag 分配与映射；不做标签池容量策略（F6433 防重，本条消费池）、不做 cmdid 语义（B10 防重，cmdid 与 tag 的绑定关系在 B10 声明）；分配 O(1)（位图扫描+缓存尾指）。
- **依赖与嫁接源**：依赖 F6421 请求结构与 F6433 标签池；嫁接源为 Linux blk-mq tag 分配（sbitmap 语义）与 Windows SRB 序号惯例，只跟随。
- **风险与回退**：回收竞态（完成路径与超时路径同时回收）——回收以状态机终态为门（非 freed 不可回收），双回收注入 100% 捕获；泄漏候选周期扫描。
- 正文：实现路径分三步。第一步分配器：每队列位图分配器（空闲位扫描起步位+缓存上次分配位），分配即置位并绑 request，回收清位；分配路径无锁（per-CPU 位图分域）。第二步映射表：tag→request 指针表（池内数组直索引），映射唯一性断言（同 tag 双绑不可能），解析 O(1)；表与位图逐位一致周期自检。第三步并发账：8 核并发分配/回收压测 10^6 次零重复零泄漏；双占注入（模拟分配竞态）检出即红账；泄漏候选（长期未回收 tag）账面暴露。与现存内核衔接点：现存无 tag 概念，纯增量；薄层提交自动分配/回收 tag。与 Windows 对照：Windows storport 以请求序号对账端口驱动与微型驱动（SRB 序号语义，WDK 文档化），本内核 tag 分配账面化且并发机检，判据 UNX-F6422-J1 的复测方式：10^6 次压测零重复零泄漏、双占注入检出、映射表与位图逐位一致。

### UNX-F6423 · back-merge 合并（相邻 LBA 向后）
- 域/批：B4/B02｜判据：UNX-F6423-J1 相邻 LBA 顺序写请求向后合并正确，合并不改变完成语义（数据校验和不变）；不可合并边界注入全过｜纯功能行数：303 行（合并判定器 110 + 后合并执行器 100 + 完成语义等价对账 93；测试段不计）｜状态：[已深化]
- **定位**：顺序写是合并器的最大红利：后发请求的 LBA 恰接在队首请求之后时，两请求并成一请求——设备命令数减半、寻址更连续。back-merge 是主合并路径（顺序流负载合并率可达 50%+），本条立判定与执行器，合并语义等价（数据与完成时序不破坏）是红线级判据。
- **语义边界**：只做请求级 LBA 相邻合并；不做段级缝合（F6413 防重）、不做 front 向（F6424 防重）；合并上限（扇区数/段数设备 limits）约束生效，超限不合并。
- **依赖与嫁接源**：依赖 F6421 请求结构与 F6413 段缝合器；嫁接源为 Linux blk-mq 合并（elv_merge BACK 语义）与 Windows 类驱动相邻写合并惯例，只跟随。
- **风险与回退**：合并破坏保序（flush 请求在中间）——合并判定器遇 flush/FUA 请求即墙（不跨越屏障合并，B05 契约消费），保序在合并风暴下依然成立。
- 正文：实现路径分三步。第一步判定器：队内查找 LBA 邻接请求（红黑树 LBA 索引，后继=本请求首 LBA 的请求），邻接且操作位同向（读并读/写并写）、无屏障墙、合并后扇区数≤limits——四条件全过才合并，判定 O(log n)。第二步执行器：后请求的段链挂到前请求尾（bio 引用链化），LBA 范围扩写，tag 保留前者回收后者（回收走 freed 正常态）；合并动作账（前后 tag 对）记录可追溯。第三步等价对账：合并开关双跑（m700blk 顺序写 10^5 扇区），数据校验和与完成序恒等断言；不可合并边界（屏障墙/跨操作/超 limits/不邻接四型）注入全拒。与现存内核衔接点：现存单请求直通无合并，纯增量；薄层路径合并器开启后自动受益。与 Windows 对照：Windows 存储栈的相邻写合并效果在 WPR 存储视图可见（传输合并统计），本内核合并率显式账面化（F6425），判据 UNX-F6423-J1 的复测方式：顺序写合并正确率 100%、屏障墙注入不跨越、开关双跑校验和恒等。

### UNX-F6424 · front-merge 合并（向前）
- 域/批：B4/B02｜判据：UNX-F6424-J1 前向合并正确性断言（LBA 前沿衔接），与 back-merge 互斥选择可判定；合并上限约束生效｜纯功能行数：283 行（前合并判定器 100 + 互斥选择器 90 + 上限约束执行 93；测试段不计）｜状态：[已深化]
- **定位**：front-merge 处理"新请求的尾 LBA 恰接队内请求之首"的场景（写时序回跳负载出现）。它比 back-merge 少见但语义对称，本条与 F6423 共享判定框架、只换方向，并立"前后互斥选择器"——同一新请求对同一目标请求只允许一个方向判定生效，防双重合并毁账。
- **语义边界**：只做前向合并；判定框架复用 F6423（不重复立账），本条新增仅方向性语义与互斥选择器；上限约束与屏障墙语义同 F6423。
- **依赖与嫁接源**：依赖 F6423 框架与 F6421 结构；嫁接源为 Linux elv_merge FRONT 语义，只跟随。
- **风险与回退**：前合并后 tag 归属歧义（被并者与合并者身份反转）——执行器规定"保留队内请求 tag、回收新请求"与 back 一致，身份账（合并事件记录主从 tag）显式。
- 正文：实现路径分三步。第一步判定器：LBA 索引查前驱（前驱请求尾 LBA+1==新请求首 LBA），条件框架同 back（同向/无墙/上限），判定 O(log n)。第二步互斥选择器：新请求入队判定序"先 back 后 front"，一请求一合并（合并成功即出循环），选择器对"back 可行且 front 也可行"的病态对（理论不可达）注入检测留账——互斥是账目守恒的前提。第三步执行与上限：段链前插、LBA 范围扩写、上限约束（超 limits 拒绝）执行；合并事件账与 back 共表分向记录；等价对账同 F6423 双跑口径。与现存内核衔接点：同 F6423 纯增量。与 Windows 对照：Windows 无显式前后向合并区分（端口驱动内部优化不外显），本内核显式分向且互斥可判定，判据 UNX-F6424-J1 的复测方式：前向合并正确率 100%、互斥注入检测零双合并、上限注入全拒。

### UNX-F6425 · 合并率账本（可导出判据）
- 域/批：B4/B02｜判据：UNX-F6425-J1 合并率（合并请求数/总请求数）实时账可导出，与手工核算一致；按负载类型分列｜纯功能行数：263 行（合并事件账 90 + 率计算器 90 + 导出与手工核算对账 83；测试段不计）｜状态：[已深化]
- **定位**：合并率是调度与合并有效性的总指标（B02 判据主轴的账面载体，B04 对照基线 F6448 的伙伴指标）。本条立合并率账本：合并事件计数、总请求计数、实时比率与按负载类型（顺序流/随机流/混合）分列——数字不漂亮可以改策略，账不清就是失明。
- **语义边界**：只做账本与导出；不做合并策略调整（各调度器自管）；口径定义钉死（分母=新入队请求数，分子=被合并回收的请求数，前后向都算）。
- **依赖与嫁接源**：依赖 F6423/F6424 合并事件；嫁接源为 Linux blktrace 合并统计（Q/G/M 事件对账）语义，只跟随。
- **风险与回退**：口径漂移（统计点变动导致率失真）——统计点在状态机迁移边固定挂接（queued 边与合并回收边），口径注记写入导出头，变更走 ADR。
- 正文：实现路径分三步。第一步事件账：合并事件（主 tag/从 tag/方向/扇区数）与入队事件双计数账，原子累加，事件账与请求账守恒（合并回收数+独立完成数=入队总数恒等式周期自检）。第二步率计算器：实时合并率=分子/分母（浮点仅导出侧计算，账内为整型对），按负载类型分列（负载分类由 F6446 消费）；滑动窗率（近 1s/10s/60s 三窗）预留。第三步导出与对账：导出行（总请求/合并数/合并率/分向拆解），与手工核算（事件流离线重放）比对一致断言；导出面供 F6524（B07 三维导出）复用。与现存内核衔接点：账挂接状态机迁移边，零侵入；O1 对标消费面 stub 验证。与 Windows 对照：Windows 无内核级合并率导出面（WPR 需离线分析），本内核实时账+手工核算对账双保险，判据 UNX-F6425-J1 的复测方式：率与手工重放一致、分列账与事件账守恒、导出格式消费方齐备。

### UNX-F6426 · 请求超时派发器
- 域/批：B4/B02｜判据：UNX-F6426-J1 滞留超阈值的 in-flight 请求被强制派发并记错误账，超时注入 10/10 次捕获；无请求被静默悬挂｜纯功能行数：323 行（超时扫描器 110 + 强制派发路径 110 + 错误账与悬挂检测 103；测试段不计）｜状态：[已深化]
- **定位**：请求在队列里滞留超阈值（派发器罢工、调度器漏调）意味着延迟雪崩前兆。本条立超时扫描器：周期扫描 in-flight 与 queued 超龄请求，queued 超龄强制派发、in-flight 超龄转错误账（重试或上抛）——"无请求被静默悬挂"是 B4 域"每请求必有终态"铁律的队列侧执法点。
- **语义边界**：只做滞留扫描与强制处置；不做设备级超时（F6571 admin 超时、B12 复位链防重）；强制派发不越过队列暂停/静默态（F6449/F6450 语义尊重）。
- **依赖与嫁接源**：依赖 F6421 状态机时间戳与 F6453 中断协作契约；嫁接源为 Linux blk-mq 超时（timeout work）语义与 Windows storport 超时处理惯例，只跟随。
- **风险与回退**：误杀长耗时合法请求（重负载下正常排队）——阈值按设备类分档且只对"异常滞留"（队列活性正常但单请求超龄）执法，活性判定以派发进度账为准；误杀事件可审计可调参。
- 正文：实现路径分三步。第一步扫描器：周期任务（F0033 tick 消费）扫描双龄账——queued 龄（入队至今）与 in-flight 龄（派发至今），阈值可配（缺省按设备类），扫描 O(在途数)。第二步强制处置：queued 超龄→强制派发（越过调度器排队直插 hwq，插队事件留痕）；in-flight 超龄→错误账（TIMEOUT 类，F6410 消费）→重试或上抛（F6432 策略）；处置全程请求不消失（终态必达）。第三步悬挂检测：悬挂探测账（终态缺失候选）与"静默悬挂=0"机检断言——任意注入序列下悬挂计数恒零；超时注入 10/10 次捕获。与现存内核衔接点：薄层同步路径不走本条（同步等待自带超时档）；异步路径全量覆盖。与 Windows 对照：Windows storport 有 SRB 超时机制（WDF/STORPORT 超时文档化），本内核双龄扫描+悬挂零机检对齐，判据 UNX-F6426-J1 的复测方式：超时注入全捕获、强制派发插队账可查、悬挂计数恒零机检。

### UNX-F6427 · plug/unplug 批量派发
- 域/批：B4/B02｜判据：UNX-F6427-J1 plug 窗口内请求批量聚合并一次 unplug 派发，派发顺序语义保持；plug 深度与窗口参数可配｜纯功能行数：303 行（plug 状态与窗口 100 + 批量聚合执行 100 + 顺序保持断言 103；测试段不计）｜状态：[已深化]
- **定位**：plug（塞子）是合并的最后机会：突发提交时先"塞住"派发、攒一批、再"拔塞"批量放行——让合并器见到完整突发而非逐个放走。本条立 plug 窗口状态机与批量派发，深度与窗口双参可配；派发顺序语义（同请求序）在批内保持是保序底线。
- **语义边界**：只做批量聚合窗口；不做调度排序（B03/B04 防重）；plug 不掩盖请求——排队计数照常（上层不可感知延迟积累破阈值，超时派发器 F6426 兜底）。
