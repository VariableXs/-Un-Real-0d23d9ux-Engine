### UNX-F1101 · C 分发表数据结构本体（256 槽向量索引表）
- 域/批：A2/B16｜判据：UNX-F1101-J1 分发表 256 槽全量落位与五区规划逐区一致断言 ≥20 条全绿，表结构大小与对齐编译期断言常绿｜纯功能行数：300 行（表结构 100 + 五区一致性断言 100 + 导出打印 100；测试段不计）｜状态：[已深化]
- **定位**：B08 的 F0942 立了"IDT→向量分型→handler 主通道"，通道是路径；本条立通道脚下的**数据结构本体**——按 vector 索引的 256 槽 C 分发表，每槽登记（handler 指针/flags/领主/分型/计数）五元组，表是分发热路径唯一数据源，结构固化后 B17–B29 全部条目在表上作业，防"分发路径各查各的表"的结构性散乱。
- **语义边界**：只做分发表数据结构与一致性断言；不做注册协议语义（B17 主场）、不做并发无锁算法（F1105 主场，本条是它的地基）；与 F0942 分层：F0942 立路径，本条立表体。
- **依赖与嫁接源**：消费 F0817 分发表管理器与 F0801 五区规划表常量；嫁接源为 Linux `irq_desc` 数组组织与 `handle_irq` 查表惯例，只跟随。
- **风险与回退**：表槽与五区规划漂移（新增区后表未同步）——表结构内置五区边界常量静态断言，编译期拦截漂移；运行期一致性断言随引导报告复核，不一致即红账不静默。
- 正文：实现路径分三步。第一步表结构本体：以静态数组定义 256 槽 C 分发表，每槽五元组（handler 指针/flags 位集/领主标识/向量分型/分发计数），槽零 = 空 handler（未注册向量记账 handler，F0801 联动），表大小与 cache line 对齐做 const 断言；第二步五区一致性断言族：表内每槽分型字段与 F0801 五区表逐区比对（异常区 0x00–0x1F 槽分型=异常、设备池槽分型=IRQ 等），≥20 条断言全绿进 ktest 中断面，断言随引导报告可打印；第三步导出打印：整表 256 槽状态一键导出（按区分段打印占用/handler 名/计数），供 O1 对标域与排障消费。与现存内核衔接点：`idt.rs` 的 stub 公共入口查表消费本表，`IdtEntry` 结构零改动。与 Windows 对照：Windows 的 ISR 分发表可经 WinDbg `!idt` 逐向量观察 handler 归属，本内核整表导出以同等颗粒对齐，判据 UNX-F1101-J1 的复测方式：引导报告五区一致性 ≥20 条全绿一次命令完成、编译期断言常绿、256 槽导出与 `!idt` 同机对照逐区一致。

### UNX-F1102 · 公共 stub 到 C 入口的全路径审计账
- 域/批：A2/B16｜判据：UNX-F1102-J1 stub→C 入口全路径 10 万次注入路径账零断链，每级栈帧偏移与 F0807 契约一致断言全绿｜纯功能行数：280 行（路径探针 100 + 审计账 90 + 断言族 90；测试段不计）｜状态：[已深化]
- **定位**：分发链路（汇编 stub 压栈→公共入口→查表→C handler）是中断子系统最热的路径，任何一级断链（栈帧错位/寄存器丢失/错误码未抹平）都是全线事故；本条给全路径装"探针+审计账"——每级入口登记到达时刻与栈帧指纹，形成可审计的完整到达链，B16 之后的全部分发深化在"路径已被审计"的前提下展开。
- **语义边界**：只做路径探针与审计账；不做查表算法（F1103）、不做性能优化（B29 主场）；与 F0942 分层：F0942 立路径定义，本条立路径审计。
- **依赖与嫁接源**：消费 F0807 TrapFrame 契约偏移常量与 F0942 入口；嫁接源为 Linux entry code 审计惯例（enter_from_user_mode 探针）与 x86-64 ABI 栈帧规范，只跟随。
- **风险与回退**：探针自身开销污染热路径——探针分常开/采样两档（默认采样 1/1024，审计模式常开），开销账随健康报告可见，采样档 P95 开销 ≤2% 断言，超限自动降频。
- 正文：实现路径分三步。第一步路径探针：在汇编 stub 尾部、公共入口首部、查表前、handler 首指令四处埋探针点，探针登记（到达时刻/栈帧指纹/核 id/向量号）四元组入环形审计缓冲；第二步审计账：审计缓冲按全局事件序号串成完整到达链，链完整性断言（四级探针逐级时序单调、栈帧指纹与 F0807 契约偏移一致）随注入测试复核，断链即红账并冻结现场快照；第三步开销账：探针两档（常开/采样）实测开销差异，采样档 10 万次注入 P95 额外开销 ≤2% 断言进 ktest。与现存内核衔接点：`idt.rs` stub 公共入口尾部插探针点，`build_stubs` 零改动。与 Windows 对照：Windows 的中断到达链可经 ETW 中断事件与 `!idt` 交叉观察，本内核审计账以事件链形式对齐可观测性，判据 UNX-F1102-J1 的复测方式：10 万次注入到达链零断链、栈帧指纹断言全绿、采样开销账 P95 ≤2% 实测打印。

### UNX-F1103 · 分发表查找账与 O(1) 索引验证
- 域/批：A2/B16｜判据：UNX-F1103-J1 全向量随机查找 10^7 次零失配，单次查找周期数实测账 P99 ≤50 cycles 且分布可导出｜纯功能行数：280 行（查找封装 90 + 周期数测量 100 + 断言族 90；测试段不计）｜状态：[已深化]
- **定位**：分发热路径每一步都在查表——查找必须 O(1) 且可证：本条把"按 vector 直接索引"的事实做成**可测量的账**（周期数实测+分布导出），把"应该是 O(1)"变成"实测就是 O(1)"，为 B29 性能深化与 B31 延迟账本段提供分发环节的实测底数。
- **语义边界**：只做查找封装与测量；不做查找优化改造（B29 主场）、不做延迟账本本体（B31–B40 主场，本条是挂点）；与 F0942 分层：F0942 立路径，本条立查找实测。
- **依赖与嫁接源**：消费 F1101 表结构与 rdtsc/HPET 计时原语；嫁接源为 Linux `generic_handle_irq` 直索路径与性能测量惯例（perf stat cycles），只跟随。
- **风险与回退**：编译器对查表代码的意外优化（边界检查插入/数组越界钳制）破坏 O(1)——查找函数用 `get_unchecked` 语义 + 调用点范围断言（vector ≤0xFF 常量证明），汇编清单复核无边界指令，破坏即编译期红账。
- 正文：实现路径分三步。第一步查找封装：`dispatch_lookup(vector)` 单函数封装表索引访问，函数标注 `#[inline(always)]` 并以编译期断言证明 vector 范围（五区表起终界包夹），汇编清单复核生成代码无边界检查分支；第二步周期数测量：测量原语用 rdtsc 前后差（串行化 `lfence` 防乱序污染），10^7 次随机向量查找逐次登记周期数，分布账（P50/P95/P99/max）计算落档；第三步断言与导出：P99 ≤50 cycles 硬断言进 ktest（超限红账并导出分布供分析），全量分布随性能账 JSON 可导出。与现存内核衔接点：`idt.rs` 公共入口改走本封装，行为零变化。与 Windows 对照：Windows 无公开的单次查找周期账但可用 `!idt` 与性能分析器间接核验分发开销档位，本内核以实测分布账对齐可验证性，判据 UNX-F1103-J1 的复测方式：10^7 次零失配、P99 ≤50 cycles 断言全绿一次命令完成、分布 JSON 可导出复查。

### UNX-F1104 · per-CPU 分发统计面（每核每向量双维计数）
- 域/批：A2/B16｜判据：UNX-F1104-J1 8 核并发分发统计 10^7 次零丢失（对账恒等），per-CPU 缓存行无伪共享断言（地址间隔 ≥64B）全绿｜纯功能行数：300 行（per-CPU 结构 100 + 汇总对账 100 + 伪共享断言 100；测试段不计）｜状态：[已深化]
- **定位**：分发统计是可观测性的血液——但多核共用一份计数器会产生缓存行乒乓（伪共享），统计本身拖慢分发；本条把统计做成 per-CPU 双维（每核×每向量）布局，读侧汇总对账，写侧零争用，统计面"看得全、跑得快"两全。
- **语义边界**：只做统计布局与对账；不做统计的业务消费（F0997 健康账主场）、不做延迟测量（B29/B31 主场）；与 F0877 审计账分层：审计账记事件流水，本条记聚合计数。
- **依赖与嫁接源**：消费 F1101 表内计数槽位与 A5 per-CPU 原语；嫁接源为 Linux per-CPU irq stats 与 `PerfCount` 布局惯例（cache line 对齐防伪共享），只跟随。
- **风险与回退**：per-CPU 槽位随核数扩展越界——结构按 MAX_CPUS 编译期上限分配 + 运行期核数校验（F0004 核数账），越界配置引导期红账拒绝，不运行期越界写。
- 正文：实现路径分三步。第一步 per-CPU 结构：每核一份 256 向量×u64 计数矩阵，行按 cache line（64B）对齐隔离，矩阵基址 per-CPU 区注册，结构总大小与对齐编译期断言；第二步写路径挂接：分发路径对命中向量 per-CPU 计数自增（无锁裸加——单核单写者语义），未注册向量入空 handler 同步计数；第三步读侧对账：汇总器遍历各核矩阵求和，与全局事件序号增量做恒等对账（10^7 次注入零丢失），对账账本随健康报告可打印，伪共享断言（相邻行地址间隔 ≥64B）进 ktest。与现存内核衔接点：`apic.rs` 现存计数（若有）收编进矩阵并保留原符号别名。与 Windows 对照：Windows 的每中断计数可经 `!pic`/性能计数器分核观察，本内核双维矩阵以同等颗粒对齐且对账可证，判据 UNX-F1104-J1 的复测方式：8 核 10^7 次对账恒等零丢失、伪共享断言全绿一次命令完成、汇总账随引导报告打印。

### UNX-F1105 · 分发表并发注册-分发安全（读侧无锁纪律）
- 域/批：A2/B16｜判据：UNX-F1105-J1 注册并发分发 10^7 次零撕裂零野指针（对拍账恒等），读侧临界区指令数 ≤5 条实测留痕｜纯功能行数：320 行（RCU 式读侧 110 + 写侧发布 110 + 并发对拍 100；测试段不计）｜状态：[已深化]
- **定位**：注册（写侧）与分发（读侧）并发是分发表最深的坑——运行中换 handler 时读侧可能读到半初始化槽或悬空指针；本条立"读侧无锁、写侧发布"纪律：读侧只做原子指针装载，写侧构造新槽后原子替换发布，旧槽宽限期回收，把并发正确性做成可对拍的账。
- **语义边界**：只做表槽级并发安全；不做注册协议语义（B17 主场）、不做 A5 RCU 本体（消费其原语）；与 F0817 分层：F0817 立管理器单线程面，本条立并发面。
- **依赖与嫁接源**：消费 A5 RCU 原语（GP 宽限期）与 F1101 表结构；嫁接源为 Linux RCU 保护 `irq_desc` action 链的惯例与指针发布纪律（rcu_assign_pointer），只跟随。
- **风险与回退**：宽限期实现缺陷导致旧槽过早回收（use-after-free）——回收延迟三重保险（GP 宽限期 + 引用计数兜底 + 回收延迟队列），三道闸任一未过不回收；回收泄漏红账常驻，泄漏即告警不静默。
- 正文：实现路径分三步。第一步读侧纪律：分发路径对槽内 handler 指针只做一次原子 acquire 装载，临界区内禁再入禁阻塞（指令数 ≤5 条实测留痕进账本），装载后 handler 调用与槽状态解耦；第二步写侧发布：注册/注销路径构造完整新槽（handler/flags/领主全量就绪）后以原子 release 替换槽指针，旧槽进入宽限期清单，GP 过后经引用计数兜底与延迟队列三道闸回收；第三步并发对拍：注册线程与 8 核分发线程并发 10^7 次，对拍账（每次分发命中 handler 版本号连续、零撕裂零野指针）恒等断言进 ktest，宽限期泄漏账常驻零容忍。与现存内核衔接点：`idt.rs` 现存注册路径（若有单线程假设）收编为写侧消费者，行为面保持。与 Windows 对照：Windows 的中断对象连接（KeConnectInterrupt）有内部锁纪律但不公开并发细节，本内核以对拍账把并发正确性显式化，判据 UNX-F1105-J1 的复测方式：10^7 次并发对拍恒等零撕裂、读侧指令数 ≤5 条实测打印、宽限期泄漏账零。

### UNX-F1106 · 分发热路径固化（入口到 handler 的指令预算）
- 域/批：A2/B16｜判据：UNX-F1106-J1 热路径全段汇编清单审计零意外分支，空载分发延迟 P99.9 ≤10µs（对齐任务书主轴）实测留痕｜纯功能行数：280 行（热路径清单 90 + 汇编审计 90 + 延迟实测 100；测试段不计）｜状态：[已深化]
- **定位**：任务书主轴"微秒级中断延迟"的第一段就是分发路径——本条把入口到 handler 的热路径段固化为"清单化+汇编审计+实测"三重：路径上每条指令有清单席位、生成汇编逐条审计无意外分支、端到端延迟实测对齐 ≤10µs 主轴，热路径从"默认快"变成"证明快"。
- **语义边界**：只做入口到 handler 首指令段；不做 handler 本体（设备域）、不做 BH 段（B19）；与 F0949（B08 延迟分解账）分层：F0949 立分解框架，本条立热路径段的清单与实测。
- **依赖与嫁接源**：消费 F1102 探针与 F1103 查找封装；嫁接源为 Linux 热路径 noinline/inline 纪律与 Windows HAL 快速分发路径设计惯例，只跟随。
- **风险与回退**：未来改动无意插入慢操作（日志/锁/分配）污染热路径——清单席位制：路径上每个函数席位登记"允许的指令类别"，CI 审计脚本对新席位强制复核，越席即编译期红账，杜绝无意污染。
- 正文：实现路径分三步。第一步清单固化：热路径段（stub 尾→公共入口→分型→查表→handler 首）逐函数席位登记，席位注记允许指令类别（原子装载/间接调用/计数自增）与禁入类别（日志/锁/堆分配/浮点）；第二步汇编审计：生成汇编逐席审计（无意外分支/无边界检查/无调用泄漏），审计脚本进 CI 每次构建复核，越席红账编译期拦截；第三步延迟实测：空载注入 10^6 次，入口到 handler 首指令段延迟实测分布（rdtsc+HPET 双计时交叉验证），P99.9 ≤10µs 对齐任务书主轴断言进 ktest，分布 JSON 可导出。与现存内核衔接点：`idt.rs` stub 链路按清单席位复核，现存指令全部登记无删除。与 Windows 对照：Windows 的 HAL 快速路径不可汇编级审计但中断延迟可经性能分析器分档观察，本内核以清单+汇编审计+实测三重对齐可验证性，判据 UNX-F1106-J1 的复测方式：汇编审计零越席、P99.9 ≤10µs 实测全绿、分布 JSON 可导出复查。

### UNX-F1107 · 未注册向量记账 handler 全量化（空槽审计升级）
- 域/批：A2/B16｜判据：UNX-F1107-J1 未注册向量触发 10^5 次全入账不 panic，入账项与 F0801 规划账逐区对账一致率 100%｜纯功能行数：260 行（记账 handler 升级 90 + 对账 90 + 断言族 80；测试段不计）｜状态：[已深化]
