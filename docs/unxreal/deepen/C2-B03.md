### UNX-F8841 · brk 语义档与探顶行为（glibc 探测关键）
- 域/批：C2/B03｜判据：UNX-F8841-J1 brk(0) 返回当前断点、增减与对齐行为与 Linux 逐项一致，glibc 探顶序列（渐进探测）10/10 次正确响应｜纯功能行数：280 行（断点账 110 + 探顶序列 90 + 对齐语义 80；测试段不计）｜状态：[已深化]
- **定位**：brk 是 glibc malloc 小块分配的探路石，本条把断点账与探顶行为建成逐项事实——brk(0) 返回当前断点、增减断点页对齐语义、glibc 渐进探测序列（试探性抬升）10/10 次正确响应，malloc 初始化失败即全线崩溃的命门号。
- **语义边界**：只做 brk 号面语义；不做堆 VMA 管理（A4 防重）、不做 mmap 大块路径（F8851/F8853 防重）、不做 sbrk 库层（glibc 侧）。
- **依赖与嫁接源**：消费 MmapRequest 通道与 A4 挂点（F8857）；嫁接源为 Linux man-pages brk(2)/sbrk(3) 语义，只跟随。
- **风险与回退**：A4 未收口期断点账无真实 VMA 支撑——以 MmapState 最小栈模拟断点区先行全过判据，A4 收口后回归闭账，缺口入 open_risks。
- 正文：实现路径分三步。第一步断点账：进程断点（program break）登记于任务内存账，brk(0) 返回当前断点值、brk(addr) 请求抬升/回落断点，成功返回新断点、失败返回旧断点且 errno=ENOMEM（Linux 语义：失败不清零），断点账随每次调用更新可审计；第二步对齐语义：请求地址按页对齐抬升（未对齐地址向上取页），回落允许页内收缩（Linux 允许未对齐回落），对齐行为逐项断言；第三步探顶序列：glibc malloc 初始化时渐进探测（brk 小步抬升试水），模拟序列 10/10 次正确响应（抬升成功/失败边界与 Linux 一致），探测失败不崩内核。与现存内核衔接点：MmapState 扩展断点槽，brk 入口新增。与 Windows 对照：Windows 堆管理（HeapAlloc）无 brk 概念，glibc 在 Windows 侧用 VirtualAlloc 模拟 sbrk，本内核原生对齐 Linux。判据 UNX-F8841-J1 的复测方式：ktest 断点账与探顶序列用例批跑全过，对齐边界 10 组零差。

### UNX-F8842 · mremap 扩缩与搬移语义
- 域/批：C2/B03｜判据：UNX-F8842-J1 MREMAP_MAYMOVE 允许搬移判据过，不允许搬移时扩容失败返 ENOMEM，搬移后旧地址失效访问收 SIGSEGV｜纯功能行数：300 行（扩缩通路 110 + 搬移语义 100 + 失效断言 90；测试段不计）｜状态：[已深化]
- **定位**：mremap 是 glibc realloc 大块路径的引擎（mremap 搬移免拷贝），本条把扩缩与搬移两语义建成事实源——MREMAP_MAYMOVE 允许内核搬迁映射（返回新地址）、不带标志时原位扩容失败返 ENOMEM、搬移后旧地址访问收 SIGSEGV，realloc 免拷贝扩容的命门。
- **语义边界**：只做 mremap 号面；不做 VMA 本体（A4 防重）、不做 SIGSEGV 投递本体（C4 防重，联测挂点声明）。
- **依赖与嫁接源**：消费 MmapRequest 通道；嫁接源为 Linux man-pages mremap(2)，只跟随。
- **风险与回退**：搬移需要页表批量重映射（A4 未收口）——搬移判据以最小栈先行（模拟重映射），A4 收口后真映射回归，挂点登记。
- 正文：实现路径分三步。第一步扩缩通路：mremap(old_addr, old_size, new_size, flags) 对既有映射扩容/收缩，收缩原位完成（尾部解除）、扩容尝试邻接空闲区原位扩展；第二步搬移语义：MREMAP_MAYMOVE 置位时允许整体搬迁到新虚拟区间（页表映射批量转移，物理页不拷贝），成功返回新地址；不带标志扩容失败返 ENOMEM 且原映射完好，两分支各 100 次断言；第三步失效断言：搬移成功后旧地址解除映射，访问触发 #PF → SIGSEGV（与 C4 联测挂点，就地先以页表事实断言"旧地址无映射"），新地址内容与原内容逐页一致。与现存内核衔接点：MmapRequest 扩展 mremap 通道。与 Windows 对照：Windows VirtualAlloc 无原子重映射（需手工拷贝），mremap 是 Linux 独有优势语义，对照声明入档。判据 UNX-F8842-J1 的复测方式：ktest 扩缩/搬移/失效三类用例批跑全过。

### UNX-F8847 · mlockall/munlockall 与 RLIMIT_MLOCK
- 域/批：C2/B03｜判据：UNX-F8847-J1 MCL_CURRENT/MCL_FUTURE 两标志语义正确，FUTURE 对后续 mmap 自动锁定的行为留账，非特权限额触发 ENOMEM｜纯功能行数：200 行（两标志 90 + FUTURE 联动 60 + 限额档 50；测试段不计）｜状态：[已深化]

- **语义边界**：只做 mlockall 号面；不做 mmap 挂点锁定本体（F8851 消费）、不做特权判定（guard 侧防重）。

- 正文：实现路径分三步。第一步两标志：MCL_CURRENT 对当前全部映射逐区上钉（总量入限额账），MCL_FUTURE 置进程标志位（后续 mmap/mremap/brk 增量自动上钉），两标志可或设，munlockall 全解；第二步 FUTURE 联动：置位后新建映射自动上钉行为留账（映射事件与锁定事件关联记录），限额触达返 EAGAIN 分档；第三步限额档：非特权进程（无 CAP_IPC_LOCK）受 RLIMIT_MLOCK 约束（默认 0 或低限），触达 ENOMEM/EAGAIN 显式。与现存内核衔接点：进程标志槽与锁通路复用。与 Windows 对照：Windows 进程工作集上限（SetProcessWorkingSetSize）近似同角色，对照入档。判据 UNX-F8847-J1 的复测方式：ktest 两标志与联动账批跑全过。
