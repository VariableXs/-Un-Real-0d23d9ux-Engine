### UNX-F8801 · syscall 分发表骨架与注册协议
- 域/批：C2/B01｜判据：UNX-F8801-J1 300+ 表项注册唯一性断言全过（重复注册构建失败即捕获），未知号返回 -ENOSYS 与 Linux 基准一致，抽查 50 号逐号断言零混码｜纯功能行数：350 行（SyscallDesc 表扩容 140 + 注册协议宏 120 + 唯一性构建检查 90；测试段不计）｜状态：[已深化]
- **定位**：分发表是全系统调用面的唯一事实源，本条把现存 `table.rs` 的 18 号存量表升级为 300+ 号可注册骨架——每号五元组 {nr, handler, nargs, flags, persona} 注册制，注册协议冻结后 B02–B40 全部承办方按协议增表，杜绝号面私有实现。
- **语义边界**：只做表结构与注册协议；不做具体号的处理函数本体（各批防重）、不做路由判定（F8806 防重）、不做快路径优化（F8814 防重）。
- **依赖与嫁接源**：对现存 `SyscallDesc`/`SYSCALLS`/`SyscallInfo` 是承接扩容（补注册宏与唯一性检查，保留 18 号存量行为逐号不变）；嫁接源为 Linux man-pages syscalls(2) 号面清单与 Intel SDM Vol.2，只跟随。
- **风险与回退**：300 号一次入表导致表常量膨胀编译变慢——分批增量注册，构建期唯一性断言先行；回退路径：协议冻结前发现字段缺陷则本轮走 mini-ADR 修订，绝不静默换义。
- 正文：实现路径分三步。第一步把现存 `SyscallDesc { nr, name, nargs, flags, persona }` 升级为注册宏 `register_syscall!(nr, handler, ...)`，宏在编译期展开为表项并自动登记唯一性校验条目，现存 18 号全部经宏改写、行为逐号回归不变；第二步构建期唯一性检查：`build.rs` 阶段对全表 nr 排序断言严格递增，重复号直接编译失败并报出冲突对（防重 grep 第四范围联动），表容量扩至 F9600 全区间；第三步抽查断言框架：随机 50 号经 `SyscallInfo::lookup` 取回五元组与注册值逐项比对，未知号统一走 `NrVerdict::Unknown` 返 -ENOSYS，与 Linux 对未注册号的基准行为一致。与现存内核衔接点：全部落在 `table.rs` 既有类型之上，`route_incoming()` 与 `abi_negotiate()` 签名不动。与 Windows 对照：Windows 的系统服务描述符表（KeServiceDescriptorTable）同为此角色，本表以源码级注册宏替代 SSDT 的运行时打桩，判据 UNX-F8801-J1 的复测方式：ktest 注册唯一性用例批跑全过，抽查 50 号零混码，人为在测试分支注入重复号 10/10 次编译期捕获。

### UNX-F8802 · syscall 入口上下文保存与参数提取
- 域/批：C2/B01｜判据：UNX-F8802-J1 6 参 syscall 寄存器逐位传递正确（rdi/rsi/rdx/r10/r8/r9），r10 槽位约定专项断言通过，EFAULT 探针注入不崩内核 10/10 次｜纯功能行数：280 行（TrapFrame 提取器 100 + r10 槽位适配 90 + 探针防护 90；测试段不计）｜状态：[已深化]
- **定位**：入口上下文是双门（SYSCALL/int 0x80）并轨的公共底座，本条把现存 `entry.rs` 的入口保存路径升级为标准 6 参提取器——重点锁 r10 槽位（x86-64 ABI 中 syscall 第 4 参走 r10 而非 rcx），这是 glibc 兼容的头号命门，任务书验收要求 r10/上下文 ABI 100% 断言。
- **语义边界**：只做寄存器提取与上下文约定；不做返回路径恢复（F8817 防重）、不做内核栈切换（F8816 防重）、不做信号栈帧（B11 F9005 防重）。
- **依赖与嫁接源**：对现存 `entry.rs` 的 SYSCALL 入口段与 TrapFrame 布局是承接扩容（补提取器函数与 r10 专项断言）；嫁接源为 x86-64 System V ABI 第 3.2.3 节参数传递表与 Intel SDM SYSCALL 语义，只跟随。
- **风险与回退**：int 0x80 遗留门参数全走 ebx 系（32 位遗留约定）与 64 位门不同——双门各自维护参数映射表，映射差异入 RouteNote 账；探针注入坏寄存器值时提取器只读不写，天然免疫。
- 正文：实现路径分三步。第一步固化 6 参提取器 `SyscallArgs::from_frame()`：按 ABI 顺序 rdi/rsi/rdx/r10/r8/r9 逐位提取为 `usize` 六元组，int 0x80 遗留门单独维护 ebx/ecx/edx/esi/edi/ebp 映射表，双门输出统一为同构六元组供分发表无差别消费；第二步 r10 槽位专项断言：构造第 4 参携带 r10 特征值（0xDEADBEEF 位型）的调用序列，断言 r10 直达而 rcx（被 SYSCALL 指令占用存返回地址）不参与传参，双门各跑 1,000 对取值一致；第三步探针防护：ktest 注入参数寄存器全 1/全 0/用户指针三种极端值，提取器只读寄存器不解引用，坏指针交由 uaccess 探针（F8812）在 handler 内拦截，入口层 10/10 次不崩内核。与现存内核衔接点：`entry.rs` 的 push 段保持字节级不动，新增提取函数挂在 TrapFrame 之上。与 Windows 对照：Windows x64 调用约定同样以 rcx 存返回地址而第 4 参走 r9，内核侧系统服务分派寄存器约定与 SysV 的 r10 差异是两大阵营 ABI 分水岭，本条以映射表消化差异。判据 UNX-F8802-J1 的复测方式：ktest 双门参数回显用例（每门 6 参逐一回读比对）批跑零差，r10 特征值断言 1,000 对全过。

### UNX-F8803 · write/read 循环语义与错误矩阵
- 域/批：C2/B01｜判据：UNX-F8803-J1 EBADF/EFAULT/短写/零长四路径行为与 Linux 逐码一致，O_APPEND 追加位生效可观测，短写返回值计数准确｜纯功能行数：320 行（write/read 本体接通 140 + 短写循环 100 + 错误矩阵 80；测试段不计）｜状态：[已深化]
- **定位**：write/read 是 glibc printf 的第一消费号，本条把 FdTable 的 fd→文件对象通道接通为完整读写循环——重点消化"短写"（fd 缓冲满/磁盘限速时部分完成）与"零长"（count=0）两大 Linux 语义细节，错误矩阵四路径逐码对齐。
- **语义边界**：只做普通文件与已接通 fd 的读写；不做管道（B12 F9023 防重）、不做 socket（B12 F9025 防重）、不做 O_APPEND 本体（B02 F8831 扩容）。
- **依赖与嫁接源**：消费 F8801 表注册与 F8812 uaccess 探针；对现存 `calls.rs` 的 FdTable 是承接扩容（补读写循环与错误分档）；嫁接源为 Linux man-pages read(2)/write(2) 返回值章节，只跟随。
- **风险与回退**：短写在跨域依赖（B1 VFS 写路径）未全量就位时触发频次不可控——错误矩阵以注入式复测锁定行为，依赖缺口登记 open_risks 移交，不做阻塞式等待。
- 正文：实现路径分三步。第一步接通本体：fd 经 FdTable 解析出文件对象，write 走对象写路径、read 走读路径，返回值语义对齐 Linux（write 返回写入字节数、read 返回读到字节数、fd 关闭返 -EBADF）；第二步短写循环消化：写路径遇目标缓冲限流时返回已完成字节数而非自旋重试，glibc stdio 据返回值自行续写，零长调用直接返 0 不触碰文件对象（Linux read(2) 明文约定），O_APPEND 位追加生效以文件偏移后移可观测；第三步错误矩阵四路径：EBADF（坏 fd）/EFAULT（用户缓冲不可写，uaccess 拦截）/短写（注入限流）/零长（count=0）逐码断言与 Linux 基准一致，矩阵入 F8939 错误注入账本。与现存内核衔接点：`calls.rs` 的 FdTable 增补读写方法，uaccess 三原语直接消费。与 Windows 对照：Windows WriteFile 部分完成以 lpNumberOfBytesWrite 报告且需调用方循环，Linux write 返回值即循环协议本身，本内核取 Linux 语义。判据 UNX-F8803-J1 的复测方式：ktest 四路径用例批跑逐码全过，限流注入下短写计数 10/10 次准确。

### UNX-F8804 · mmap/munmap/mprotect 三联语义
- 域/批：C2/B01｜判据：UNX-F8804-J1 对齐/越界/权限翻转错误码矩阵全对齐 Linux 基准，mprotect 翻只读后写触发 #PF 且进程收 SIGSEGV（与 C4 联测）｜纯功能行数：380 行（三联入口接通 160 + 错误矩阵 110 + #PF 联测挂点 110；测试段不计）｜状态：[已深化]
- **定位**：mmap 三联是 glibc malloc 与 ELF 装载的命脉，本条把 MmapRequest 的号面入口接通为完整三联语义——对齐/越界/权限三错误矩阵逐码对齐 Linux，mprotect→#PF→SIGSEGV 链与 C4 缺页域联测，是 B03 扩容（F8841 起）的母版。
- **语义边界**：只做三联号面入口与错误矩阵；不做 VMA 管理本体（A4 域防重）、不做缺页处理本体（C4 域防重）、不做 MAP_FIXED_NOREPLACE 语义（B03 F8847 扩容）。
- **依赖与嫁接源**：消费 F8801 注册与 F8812 探针；对现存 `calls.rs` 的 MmapRequest 是承接扩容（补入口语义与错误分档）；嫁接源为 Linux man-pages mmap(2)/mprotect(2) ERRORS 章节与 Intel SDM 分页章节，只跟随。
- **风险与回退**：C4 缺页域未完成时 SIGSEGV 投递链无法联测——联测挂点先行注册，依赖缺口登记 open_risks（C2 依赖 C4），复测方式声明"联测随 C4 验收补测"，就地可测部分先行全过。
- 正文：实现路径分三步。第一步三联入口接通：mmap 经 MmapRequest 携带 addr/len/prot/flags/fd/off 六参入 VMA 请求通道，munmap 携带区间卸载请求，mprotect 携带区间权限翻转请求，三入口参数经 uaccess 探针校验后交 A4 接口层；第二步错误矩阵：页不对齐 addr/off 返 EINVAL、区间越进程地址空间返 ENOMEM、mprotect 对未映射区间返 ENOMEM、prot 携带非法位返 EINVAL、文件映射 fd 无读权返 EACCES，五格逐码对齐 Linux ERRORS 章节；第三步 #PF 联测挂点：mprotect 翻只读后注入写访问，A4/C4 链路触发 #PF 时进程收 SIGSEGV 的投递挂点在号面侧预注册，联测用例随 C4 验收补测，就地先用注入断言验证"只读页写必缺页"的页表事实。与现存内核衔接点：MmapRequest 结构扩容 prot/flags 字段，VMA 请求经 A4 冻结协议（B03 F8857）交接。与 Windows 对照：Windows VirtualAlloc/VirtualProtect 与 mmap/mprotect 同角色，VirtualProtect 对未提交页返 ERROR_NOT_COMMITED 而 mprotect 返 ENOMEM，语义对照表入档。判据 UNX-F8804-J1 的复测方式：ktest 错误矩阵五格批跑全过，#PF 就地断言过、联测挂点登记随 C4 补测。

### UNX-F8805 · -ENOSYS 与保留号段行为
- 域/批：C2/B01｜判据：UNX-F8805-J1 全部未实现号返回 -ENOSYS，抽查 50 号逐号断言无混码，保留带（Reserved/Out）与未注册带（NotYet）分档留痕｜纯功能行数：150 行（ENOSYS 兜底 60 + 分档账 50 + 抽查断言 40；测试段不计）｜状态：[已深化]
- **定位**：未实现号的行为是号面诚信的底线——本条把"查无此号"与"查有未做"统一收敛到 -ENOSYS 兜底单点，同时把保留带与未注册带分档留痕，杜绝兜底路径的静默混码（如误返 EINVAL 或 0）。
- **语义边界**：只做兜底返回与分档账；不做分发表结构（F8801 防重）、不做路由判定本体（F8806 防重）、不做 ENOSYS 语义档扩容（B07 F8925 扩容）。
- **依赖与嫁接源**：消费 F8801 的 `NrVerdict` 三态；对现存 `table.rs` 的 NrVerdict{Implemented/NotYet/Unknown} 是承接消费；嫁接源为 Linux 对未注册号统一返 -ENOSYS 的基准行为，只跟随。
- **风险与回退**：抽查 50 号可能漏掉边角混码——配合 F8818 manifest 全量导出做交叉核验，导出账与兜底账逐号比对兜住全量。
- 正文：实现路径分三步。第一步兜底单点：`route_incoming()` 判定 NotYet/Unknown 两态时统一经 errno 编码器返 -ENOSYS，兜底路径在 SyscallMeter 记 not_yet 计数，与成功路径账分离；第二步分档留痕：保留带（Reserved 带，未来扩展预留）与越界带（超 SYS_NR_BASE+NR_SPAN）与未注册带（区间内查无表项）三档各记独立计数，分档依据落 NRGuard 账本，审计时可见每笔兜底的档位归属；第三步抽查断言框架：从 0x4000 至 0x4400 区间随机抽 50 号断言返回值全为 -ENOSYS 且档位账一致，另抽 10 个表内已注册号断言不落入兜底路径（反向断言防兜底误吞合法号）。与现存内核衔接点：全部消费 `table.rs` 存量三态，不改动路由判定逻辑本身。与 Windows 对照：Windows 对未实现系统服务返 STATUS_NOT_IMPLEMENTED，与 Linux -ENOSYS 同档，对照表入档。判据 UNX-F8805-J1 的复测方式：ktest 抽查用例（60 号）批跑逐号全过，分档账三档计数与断言集合账一致，兜底路径 meter 计数可导出。

### UNX-F8806 · 号段治理四带路由升级接管
- 域/批：C2/B01｜判据：UNX-F8806-J1 band_of 四带判定（Reserved/Native/Compat/Vendor）与 Linux 号面路由回归 1,000 号零误判，band miss 与垃圾号分档入账｜纯功能行数：260 行（band_of 回归框架 110 + 分档账 80 + miss 治理 70；测试段不计）｜状态：[已深化]
- **定位**：四带（Reserved/Native/Compat/Vendor）是号段治理的宪法，本条把现存 `band_of()` 判定升级为千号回归框架——1,000 号逐号断言带归属零误判，band miss（号在带内但表外）与垃圾号（区间外）分档入账，为 B02–B40 承办方提供带判定的事实源。
- **语义边界**：只做带判定与回归框架；不做兼容转接本体（F8807 防重）、不做 ENOSYS 兜底（F8805 防重）、不做路由四带语义档扩容（B07 F8925 联动声明）。
- **依赖与嫁接源**：对现存 `table.rs` 的 SYS_NR_BASE/SYS_NR_END/NR_SPAN/band_of 是承接扩容（补回归框架）；嫁接源为 Linux 号面（0–400 常用段）与任务书 §2.2 区间定义，只跟随。
- **风险与回退**：1,000 号回归样本可能不及未来扩号——回归框架按"区间边界 + 带边界 + 随机内点"三层抽样设计，扩号后重跑成本 O(毫秒)。
- 正文：实现路径分三步。第一步带判定固化：band_of 对 [SYS_NR_BASE, SYS_NR_BASE+NR_SPAN) 区间按任务书 §2.2 定义分四带——保留带（首尾各 0x20）、原生带（Linux 常用号映射）、兼容带（COMPAT_TABLE 覆盖段）、厂商带（0x4380 起自有号），带边界常量单一事实源化，任何分发表消费方只读 band_of 不自算；第二步千号回归框架：生成 1,000 号抽样（四带边界各 10 号 + 区间随机 960 号），逐号断言带归属与常量推导值一致，零误判才绿；第三步 miss 分档：号在带内但无表项（band miss）与号完全越界（垃圾号）分两档计数入 NRGuard 账，垃圾号直接 -ENOSYS，band miss 按"NotYet 待注册"档留痕供承办方认领时消费。与现存内核衔接点：`band_of()` 签名不变，新增回归与账本函数。与 Windows 对照：Windows 号面以 SSDT 索引治理无带概念，四带是本内核对兼容/自有号面的治理发明，对照声明入 ADR。判据 UNX-F8806-J1 的复测方式：ktest 千号回归批跑零误判，miss/垃圾号两档账与断言集合账一致。

### UNX-F8807 · Linux 兼容号面转接器扩容
- 域/批：C2/B01｜判据：UNX-F8807-J1 COMPAT_TABLE 15 号存量 + 扩容新号转接路由 300 号全通，RouteNote 四态（Exact/Permuted/ExtraArgsIgnored/ReturnDiffers）逐号核对一致｜纯功能行数：300 行（转接器扩容 130 + RouteNote 核对框架 100 + 300 号路由 70；测试段不计）｜状态：[已深化]
- **定位**：COMPAT_TABLE 是 Linux 二进制兼容的翻译词典，本条把现存 15 号存量扩容为覆盖 C2 域 300 号的转接路由——RouteNote 四态逐号登记语义差异（参数换位/多余参数忽略/返回值不同），glibc 与 busybox 的每一号消费都有明确的转接档案。
