### UNX-F0081 · KASLR 熵源采集器
- 域/批：A1/B05｜判据：UNX-F0081-J1 RDRAND/TSC/内存图自由度三源混合熵估计落账，熵低于阈值时降级固定基址并告警｜纯功能行数：280 行（三源采集 120 + 混合与估计 90 + 降级门 70；测试段不计）｜状态：[已深化]
- **定位**：为内核基址随机化提供可信熵：RDRAND、TSC 抖动、内存图自由度三源混合，并给出熵估计与降级决策。
- **语义边界**：只服务引导期一次性基址抽取；运行期 CSPRNG 属 A9 随机域；不做熵源健康自检连续监测（仅引导期单次）。
- **依赖与嫁接源**：RDRAND 指令封装、RDTSC、F0067 对齐视图自由度；嫁接 Linux `kaslr_get_random_long` 的三源混合思想与 `CONFIG_RANDOMIZE_BASE` 阈值语义。
- **风险与回退**：RDRAND 单源可被固件退化（Intel erratum 史实）——三源异构混合、RDRAND 失败连续 5 次即弃用该源；总熵低于 8 bit 阈值时降级固定基址并告警（确定性优于伪随机）。
- 正文：实现路径分三步。第一步三源采集：RDRAND 循环取 64bit 并做连续失败计数；RDTSC 取引导期两次测量差值（跑一小段校准循环放大抖动）；自由度 = F0067 对齐视图中满足对齐约束的可用槽位数，取 log2。第二步混合与估计：三源 SHA-256 级联压缩为 256bit 种子，熵估计取三源中最小可用位数（保守），估计值与各源原始值落账。第三步降级门：估计 < 阈值（默认 8 bit）→ 拒绝随机化、选固定基址、日志告警打"fallback"标签；≥ 阈值 → 种子交给 F0082 槽位抽取。与现存内核衔接点：种子消费方为 F0082/F0089，摘要入 F0088 BootManifest 与 F0095 指纹；cmdline `nokaslr` 直接短路本条。与 Windows 对照：Windows 的 KASLR 熵来自 `KiInitialProcessorsStart` 期 RDTSC 与 ACPI 表指纹混合（`MiEntropyForKaslr`），微软未公开详细估计模型；本工程显式熵估计与降级门是对标 Linux `kaslr_check` 的更严设计。判据 UNX-F0081-J1 的复测方式：ktest 采集 1000 次混合结果做频率检验（卡方近似），断言估计落账数值合理、人为屏蔽 RDRAND/TSC 各源后降级门触发且告警有账。

### UNX-F0082 · 随机化范围与槽位计算
- 域/批：A1/B05｜判据：UNX-F0082-J1 槽位数与物理映射窗口计算正确，1 万次模拟零越界零重叠｜纯功能行数：260 行（窗口计算 90 + 槽位枚举 90 + 抽取器 80；测试段不计）｜状态：[已深化]
- **定位**：把物理内存图转成合法基址槽位清单（对齐、避开禁区、互不重叠），从熵种子里等概率抽一个。
- **语义边界**：只算物理侧槽位；高半区虚拟侧归 F0089；槽位粒度固定 2M（大页友好）。
- **依赖与嫁接源**：输入 F0067 2M 档视图 + F0075 cap + F0062 白名单；嫁接 Linux `process_efi_entries`/`find_random_mem` 的槽位枚举语义。
- **风险与回退**：槽位过少（小内存机）会退化——槽位数 < 4 时降级固定基址并告警；抽取越界是 P0，抽取后双重断言落位。
- 正文：实现路径分三步。第一步窗口计算：遍历 2M 对齐视图 Usable 区间，区间内以 2M 粒度切槽位，剔除与白名单/内核保留区重叠的槽位，剔除低于 1M 与超 cap 部分。第二步槽位枚举：全部合法槽位入数组（最多 4096 槽防溢出），记录总槽位数与每槽所属区间；对槽位做相邻去重合并校验。第三步抽取器：用 F0081 种子做拒绝采样（`seed % n` 后 slot 合法性复验，非法重抽，最多 8 轮），返回槽位基址并落账槽位号；两次抽取接口支持互斥避让（供多镜像未来用）。与现存内核衔接点：产出基址交 F0096 段加载器，槽位表入 F0088 BootManifest。与 Windows 对照：Windows 的 `MiSelectKaslrAddress` 同样按物理图枚举候选（PXE 槽 2MB 对齐），但候选窗口固定在低 16TB 虚拟段；本工程物理/虚拟两侧独立枚举，物理侧与 Linux 同构。判据 UNX-F0082-J1 的复测方式：ktest 用三张典型内存图（1G/8G/128G）断言槽位数与手推一致；1 万次模拟抽取全落合法槽、零越界零重叠、槽位覆盖均匀性（卡方）通过。

### UNX-F0083 · ELF PT_LOAD 段解析器
- 域/批：A1/B05｜判据：UNX-F0083-J1 解析结果与 readelf 同内核镜像对照逐段一致，畸形段拒绝并落账｜纯功能行数：320 行（头解析 100 + PT_LOAD 遍历 110 + 校验拒绝 110；测试段不计）｜状态：[已深化]
- **定位**：解析内核 ELF64 的 ELF header 与 Program Header 表，产出 PT_LOAD 段清单供加载器消费。
- **语义边界**：只解析内核自镜像（Limine 已装但需自读布局信息）；动态段/符号重定位细节归 F0084；DWARF 调试节忽略。
- **依赖与嫁接源**：ELF64 规范（System V ABI）结构定义；嫁接 Linux `elf_info`/`kexec` 段遍历与 Linux boot 的 `parse_elf` 校验风格。
- **风险与回退**：畸形镜像（假 e_phoff/巨型段数）是攻击面——所有字段钳位校验、表项数上限 64；解析失败拒绝继续并落账，绝不越界读。
- 正文：实现路径分三步。第一步头解析：校验 magic `\x7fELF`、class=64、data=LSB、type=EXEC、machine=EM_X86_64；读 `e_phoff/e_phnum/e_phentsize` 并对三值做上界钳位（镜像长度内）。第二步 PT_LOAD 遍历：逐项 Program Header 校验 p_type==PT_LOAD，取 `p_offset/p_vaddr/p_filesz/p_memsz/p_flags` 五元组，要求 `p_filesz <= p_memsz`、offset+filesz 在镜像内、vaddr 2M 对齐；产出段清单数组。第三步校验拒绝：畸形项（超界、乱序重叠、对齐不符）逐项记账拒绝；全部段通过才输出，否则整体失败模式（拒绝加载路径 F0097 接手）。与现存内核衔接点：段清单是 F0096 加载器与 F0084 重定位器的共同输入；解析器同时被 F0097 畸形拒载路径复用。与 Windows 对照：Windows PE 格式由 `winload!BlImgLoadPEImage` 解析，Section headers 对应 ELF PT_LOAD；Linux 同类为 `extract_kernel.c` 的 `parse_elf`。本工程因 Limine 直接交付 ELF，解析在内核内做、证据链更完整。判据 UNX-F0083-J1 的复测方式：ktest 对构建产物真实内核镜像断言段清单与 `readelf -l` 输出逐段一致（地址/长度/权限三轴）；注入 20 组畸形段逐组被拒且落账。

### UNX-F0084 · 段重定位项修复器
- 域/批：A1/B05｜判据：UNX-F0084-J1 R_X86_64 系列重定位全类型支持，重定位后符号引用抽样比对零错｜纯功能行数：340 行（Rela 遍历 90 + 全类型处理器 160 + 抽样比对 90；测试段不计）｜状态：[已深化]
- **定位**：对 PT_REL/PT_RELA 段执行 R_X86_64 系列全类型重定位修复，使内核在随机基址上自洽运行。
- **语义边界**：只处理静态链接内核镜像的 SHT_RELA；动态链接（.so）语义不支持；RC 相关（R_X86_64_GLOB_DAT 等）在静态内核不存在，遇即记账跳过。
- **依赖与嫁接源**：System V ABI x86-64 重定位类型表（R_X86_64_64/PC32/PLT32/32S 等）；嫁接 Linux `apply_relocations` 与 kpatch 的类型分发器思想。
- **风险与回退**：漏一个类型 = 运行期随机崩溃——类型分发表穷举规范 38 型，未知类型落账拒绝；重定位加法和校验溢出用 u64 环绕并断言。
- 正文：实现路径分三步。第一步 Rela 遍历：定位 SHT_RELA 节区，逐项取 `r_offset/r_info/r_addend`，解出符号索引与类型号，r_offset 落点必须在某 PT_LOAD 段内（否则记账拒绝）。第二步类型分发：按 R_X86_64_* 类型号分发处理器——绝对型 `S+A`、PC 相对型 `S+A-P`、size 型等；每型独立小函数，规范公式注释原文；与基址解耦（S 为已重定位后的符号地址）。第三步抽样比对：重定位完成后，对每类型抽样 16 个点位手工反推目标值，与内存实际 8 字节比对；汇总"类型覆盖表 + 抽样比对账"落盘。与现存内核衔接点：运行在 F0096 段载入后、符号表保留（F0086）前；重定位基址即 F0082 抽取槽位。与 Windows 对照：PE 的基址重定位由 `.reloc` 节 + `LdrProcessRelocationBlock` 完成，类型集远小于 ELF；本工程 ELF 全类型支持是移植 Wine（阶段 2）的前置能力，也是 A1 对 ELK 生态的关键嫁接点。判据 UNX-F0084-J1 的复测方式：ktest 用构建系统导出的符号表（nm）对重定位后镜像抽样比对；构造含全部 38 型的合成 Rela 段断言逐型正确；未知类型注入被记账拒绝。

### UNX-F0085 · BSS 清零与校验
- 域/批：A1/B05｜判据：UNX-F0085-J1 BSS 段载入后逐页读断言为零，遗漏检出 100%｜纯功能行数：200 行（清零执行 70 + 逐页校验 70 + 记账 60；测试段不计）｜状态：[已深化]
- **定位**：对 `p_filesz < p_memsz` 的段补零区执行清零并逐页校验，保证 C 静态零初始化语义。
- **语义边界**：只清 BSS 补零区；内核自映像的 .bss 若已由 Limine 零化仍强制复清（幂等）；非 PT_LOAD 段不管。
- **依赖与嫁接源**：ELF 规范 p_memsz-p_filesz 语义；嫁接 Linux `extract_kernel` 的 `memset(bss)` 与 assert 风格。
- **风险与回退**：漏清一页 = 未定义行为潜伏（最难查的 bug 类）——清零后立即逐页读回断言，失败即停机报页号；大段清零耗时入 F0099 记账。
- 正文：实现路径分三步。第一步识别补零区：对每 PT_LOAD 段计算 `zero_begin = vaddr+filesz`、`zero_len = memsz-filesz`，为 0 跳过并记账"无补零"。第二步清零执行：对补零区按页循环 memset 0（页内残余按字节），大段用 `rep stosq` 路径；清零区段边界值（首尾 8 字节）单独置 0 并记快照。第三步逐页校验：清零后再次按页读回，逐 8 字节断言为零，任何非零即停机打印页号与实际值；全过则"清零+校验"双戳落账（页数、耗时）。与现存内核衔接点：紧跟 F0096 段载入执行；清零页自动进入 F0072 账本 allocated-内核 tag 集。与 Windows 对照：PE 没有 BSS 概念（.bss 是 `.data` 的虚拟尺寸扩展），`winload!BlImgAllocateImageSections` 同样做 memsz-filesz 零填充但不逐页校验；本工程校验步是防 Limine 未来版本行为漂移的护栏。判据 UNX-F0085-J1 的复测方式：ktest 对含 .bss 的测试镜像断言逐页零、注入"跳过一页"的故障注入版清零器检出率 100%、双戳落账。

### UNX-F0086 · 符号表保留与 panic 符号化
- 域/批：A1/B05｜判据：UNX-F0086-J1 panic 栈回溯符号名解析与 nm 输出一致，无符号区段显示原始地址｜纯功能行数：300 行（symtab 摘取 90 + 排序索引 90 + 符号化查询 120；测试段不计）｜状态：[已深化]
- **定位**：从内核镜像摘取 SHT_SYMTAB/SHT_STRTAB 建常驻符号索引，供 panic 栈回溯把地址翻译成 `symbol+offset`。
- **语义边界**：只保留 FUNC/NOTYPE/OBJECT 全局+局部符号；STRNAME 全量字符串表可裁剪（只保留被引用项）；栈回溯帧遍历本身归 A1 后期 panic 批。
- **依赖与嫁接源**：ELF symtab 布局；嫁接 Linux `kallsyms` 的地址排序 + 二分查找思想（引导期建索引替代编译期生成）。
- **风险与回退**：符号表体积（可数 MB）驻留保留区并白名单登记；无 symtab 的 stripped 镜像降级"原始地址模式"并告警，不崩溃。
- 正文：实现路径分三步。第一步摘取：F0083 解析时顺带定位 SHT_SYMTAB 与其链接的 STRTAB，把 `Elf64_Sym` 数组（去 SHN_UNDEF）拷贝至保留区，记录符号数。第二步建索引：按 `st_value` 升序排序（基址重定位后值），建区间索引表 `(addr_start, addr_end, sym_idx)`，相邻符号重叠即记账（编译器不该产生）；索引 CRC 盖章。第三步符号化查询：`sym_resolve(addr)` 二分命中区间返回 `name+offset`，未命中返回原始地址十六进制；panic 面板调用同一 API，输出与 `nm --numeric-sort` 交叉可对。与现存内核衔接点：panic 路径（A1 后期批）与 F0094 审计报告都消费本索引；BootManifest 记录符号表位置供调试工具离线解析。与 Windows 对照：Windows 用 PDB 外置符号（`DbgHelp` 按需加载）内核态只有 KPCR 级摘要；Linux kallsyms 常驻内核。本工程取 kallsyms 路线但引导期建索引，调试无需外置文件。判据 UNX-F0086-J1 的复测方式：ktest 对 1000 个随机地址调用 sym_resolve 与 nm 输出比对一致；无符号镜像降级路径正确显示原始地址；索引 CRC 校验入账。

- **语义边界**：关闭 KASLR 不关闭重定位（固定基址仍需重定位修复）；关闭态也是"引导零差异"判据的一部分。
- **依赖与嫁接源**：链接脚本 `varix.ld` 的 `KERNEL_BASE` 常量；嫁接 Linux `nokaslr` 参数语义（保留空闲页等差异不再复刻）。
- **风险与回退**：链接脚本基址与运行时窗口冲突会导致加载失败——构建期断言脚本基址 ∈ F0082 合法槽集合；冲突时构建失败（fail fast）。
- 正文：实现路径分三步。第一步开关解析：cmdline 识别 `nokaslr`（与 F0016 白名单一致），置引导参数 `randomize=0`；参数块落账。第二步固定路径：F0082 抽取器读到关闭态直接返回链接脚本基址（跳过熵与槽位），F0081 熵采集跳过，全程打"diagnostic-fixed"标签。第三步断言：加载完成后断言实际基址 == 链接脚本常量，相等性入 BootManifest；两次引导该标签下基址必须逐字节相同（零差异断言直接复用 F0066 快照 diff）。与现存内核衔接点：开关状态入 B13 早传十二步参数链；F0093 脱敏断言对固定基址豁免（诊断态本就明文）。与 Windows 对照：Windows 的 `/NOLOWMEM`、BCD `nointegritychecks` 均非 KASLR 专用关闭（Win8+ KASLR 不可关）；Linux `nokaslr` 是同义对照。本工程保留关闭态是为"50 次引导零差异"主判据提供确定性基线。判据 UNX-F0087-J1 的复测方式：ktest 两次带 `nokaslr` 模拟引导断言基址恒等且等于链接常量；与开启态对比确认两条路径互不污染。

### UNX-F0097 · 畸形内核镜像拒载路径
