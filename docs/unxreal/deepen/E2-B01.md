### UNX-F16801 · crt_version_matrix 裁决器首版（版本矩阵与四级裁决总纲）
- 域/批：E2/B01｜判据：UNX-F16801-J1 裁决器对 50 个导入面样本（manifest 声明/无声明/侧载/系统级四类混合）产出裁决结果与预置账本逐例一致，四级裁决优先序断言齐备，兜底命中 100% 记诊断账｜纯功能行数：320 行（矩阵总纲 120 + 裁决管道 110 + 样本断言 90；测试段不计）｜状态：[已深化]
- **定位**：本条是 E2 域的锚位条目（320 行为全批最大单条）——crt_version_matrix 裁决器首版总纲：Windows 世界运行库不是单一物，真实 PE 导入表里的 msvcrt/msvcr80~140/ucrtbase/vcruntime 并存且同名函数跨版本行为有差（printf 格式串扩展、swprintf 签名变更、locale 漂移是三大经典事故源），裁决器以 (DLL 名， 导入方 PE 的 manifest 声明) 为键裁决"这个 PE 该吃到哪个 CRT 模块实例"。首版立四级裁决优先序的骨架：PE 内嵌 manifest 声明 → SxS 策略 → 系统默认 → 兜底。
- **语义边界**：只立裁决总纲与优先序骨架，manifest 解析细则归 F16805/F16806（B02）、SxS 策略读取细则归 B04（与 AI-18 会签面）、具体版本档差异表归 F16811–F16814；裁决器不实现 CRT 函数语义本体（那是 Wine 本体与语义校验的事——本域管"给对版本"不管"版本内部每一函数"，防重分界判据行内嵌）。Windows 对照锚：Windows loader 的 assembly 版本绑定公开行为。
- **依赖与嫁接源**：嫁接源为 AI-21 上栈的 Wine 运行库本体（版本实例的提供方，Schema 先行：E1 未收口期以冻结接口+fake 模块收口，登记 R-E2-001）。上游依赖：AI-17 导入表解析（import_desc 输入源，resolve_crt 挂接点 B03 冻结）、AI-18 注册表 SxS 策略读取（冻结 API 消费方）。下游消费：B02–B05 裁决器细化条目群、AI-25 缺口清单（兜底诊断账供给）、B16 消费 D2 冻结的 F13098 WOW64 分档协议（32 位档 CRT 裁决共用本矩阵）。现存内核衔接点：裁决器实现挂 E2 域新立模块 `compat/crtver/`，经 resolve_crt 冻结接口被导入解析调用。
- **风险与回退**：风险是四级优先序实现序错——把"系统默认"提前于 manifest 声明，侧载应用吃到错误版本且能启动（比崩溃更难排查的"行为错"态）。对策：优先序以断言矩阵冻结（判据口径 50 例四类混合逐例断言），任何重排必须走域内 ADR；回退为裁决器降级"仅 manifest 声明+系统默认"两态（砍 SxS 中间层），零错误裁决回退仅覆盖率取舍注记。
- 正文：实现路径分三步。第一步立矩阵总纲：crt_version_matrix 数据骨架（键=DLL 名+manifest 声明二元组，值=crt_module 描述符）与四级优先序声明（manifest→SxS→系统默认→兜底）。第二步写裁决管道：resolve_crt(import_desc) 入口（冻结接口 B03 细化）按优先序逐级查询，每级命中即短路，兜底命中强制写诊断账（模块/原因/导入方三元组，供 AI-25 收集）。第三步写样本断言：50 个导入面样本四类混合逐例断言裁决结果与预置账本一致，优先序反例（人为调序）必须被断言抓出。与现存内核衔接点：模块挂 compat/crtver/，resolve_crt 导出符号由导入解析在符号表注册。与 Windows 对照：四级绑定优先序与 Windows loader 公开行为一致（真机随闸门补测）。复测方式：J1 复测＝50 例裁决一致断言＋优先序反例抓出＋兜底诊断账计数核。

- **依赖与嫁接源**：嫁接源为纯自研（提取骨架）。上游依赖：AI-17 资源目录遍历（被复用基础件，D2 收口面）、F16803 契约（binding_ref 回填源）。下游消费：F16806（XML 细节解析）、F16818（裁决缓存失效源——manifest 内容指纹）。现存内核衔接点：提取函数挂 compat/crtver/，经 AI-17 冻结的资源遍历接口调用。

### UNX-F16806 · assemblyIdentity 版本字段语义（name/version/architecture 三元）
