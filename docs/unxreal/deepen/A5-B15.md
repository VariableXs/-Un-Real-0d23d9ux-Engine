## F3481 分级日志总设计（五级 TRACE/DEBUG/INFO/WARN/ERROR + 分级输出策略）

**定位**：分级日志总纲：五级语义矩阵（级别 × 典型消费者 × 输出策略）——内核观测面的最后一块基建；与 B12 结果账的分工：日志是过程流、账是结果集。
**语义边界**：本条是总纲与语义冻结；过滤/缓冲/宏/转储在 F3482–F3488。日志**允许丢**（环形覆盖——流可丢）、结果账**不允许丢**（判据行给分离红线的第二句）——两者可走同一后端（Runner）但可靠性语义不同。
**判据**：
- J1：M-240 分级全链路：五级各写一条 → 过滤 → ring → 转储 → 可读输出——五条全链零丢失（未覆盖时）。
- J2：五级矩阵冻结（判据行内嵌：TRACE=开发者/默认关、DEBUG=调试者/默认关、INFO=运维/默认开、WARN=值班/默认开+声光预留、ERROR=全员/恒开不可关）。
**纯功能行数**：340（矩阵 ~120 + 全链用例 ~110 + 分离红线 ~110）
**依赖与嫁接源**：F3422 Runner（输出后端复用）；F3482 过滤器；A1 logger（语义对照源——既有级别的映射）。
**风险与回退**：级别滥用（什么都 ERROR → 狼来了）——回退：ERROR 恒开 + 速率限制（F3487）双闸 + 级别使用指南（判据行给一页指南：每级的"什么该进"）。
**正文**：五级矩阵（判据行内嵌全表）：`TRACE`（路径跟踪——默认关，打开 = 排查期行为）、`DEBUG`（状态快照——默认关）、`INFO`（里程碑——启动/挂载/转储/切换，默认开）、`WARN`（可自愈异常——重试后过、阈值逼近、降级动作，默认开）、`ERROR`（不可自愈——死锁告警/数据破坏/契约违约，恒开）。恒开的技术含义（判据行原文）：ERROR 的过滤位是常量 true（编译期内联掉过滤判断——ERROR 路径零过滤开销）；恒开的治理含义：ERROR 是值班面的Pager——发 ERROR 就要有人看，滥用 = Pager 失聪——速率限制在 ERROR 路径同样生效（F3487）+ 级别指南给"什么该进 ERROR"的三判据（不可自愈？需要人？事后无法从账本得知？——三问全 yes 才 ERROR）。分离红线的工程红利（判据行论证）：流可丢/账不可丢的分离让日志 ring 可以**覆盖式**（4KB 每核固定内存——不增长、不分配、不断尾）而账本必须**完整式**——观测面用固定内存换永不 OOM 的日志（日志系统自己 oom = 观测者失明于事故现场——覆盖式是观测系统的标准答案：保最后一段永远比保全部更重要）；而账本的完整性由 B12 落盘机制保证——两套可靠性各自匹配各自的价值，不互相拖累。与 A1 logger 的语义映射（判据行给映射表）：A1 既有三级（error/warn/info）→ 新五级的 WARN/INFO/ERROR 三级直映、DEBUG/TRACE 为新增层（A1 无对应——映射表登记"新增"）。现有内核接入：A1 logger 语义对照（F3494 桥接的实现输入）。Windows 对比：ETW 的级别与通道（Critical/Error/Warning/Information/Verbose）同五级结构——Verbose 对 TRACE、它有 keyword 过滤我们有三维位图（粒度选择不同，层次学同构）。M-240 复测：五条全链 + 矩阵核对 + 映射表 + ERROR 恒开路径。

## F3482 三维输出过滤器（级别 × 域 × 模块位图过滤）

**定位**：Filter3D：三维位图过滤（级别 5 位 × 域位图 × 模块位图——与语义：三维全过才放行）——运行时可变（位图运行期改写，改写是原子的单写——过滤位图热路径只读）。
**语义边界**：只做过滤判定（位图结构与管理在 F3484 管理器）；ERROR 级绕过级别位（恒开——F3481 声明——但域/模块位仍生效——恒开的是级别维不是全部维——判据行声明这一细化：ERROR 想屏蔽某模块的模块位仍可屏蔽——噪声模块的 ERROR 也可定向静音，但要有操作留痕）。
**判据**：
- J1：M-241 组合矩阵：三维各单维 3 变体 + 组合 5 例 = 14 组合的放行/拦截逐位与手算一致。
- J2：过滤判定拍数预算（命中路径含在 F3491 的 80 拍内、拒绝路径 ≤ 10 拍——位图三查的拍数实测）。
**纯功能行数**：340（位图结构 ~120 + 判定逻辑 ~110 + 矩阵用例 ~110）
**依赖与嫁接源**：F3481 级别语义（维度一）；F3406 域标识（维度二的来源——域表）；模块表（维度三——域内模块登记制，F3495 接入表同步登记）。
**风险与回退**：位图改写竞态（热路径读 × 控制路径写——撕裂读）——回退：单写者原则 + 原子字写（每维一个 AtomicU32 位图——写 = 单字原子写，读 = 单字原子读——撕裂不可能——判据行给原子性论证：位图 ≤ 32 位单字）。
**正文**：实现路径：三维位图（判据行原文）：`Filter3D { level_bits: AtomicU32(5 位), domain_bits: AtomicU32, mod_bits: AtomicU32 }`——判定 `pass = (1<<lvl) & level_bits && (1<<dom) & domain_bits && (1<<mod) & mod_bits`（三个位测试 + 与——全内联 ~6 拍——拒绝路径的 10 拍预算构成：位测试 6 拍 + 调用序 4 拍）；域表/模块表的编码：域 u8 序号（域注册制——F3495 接入表给序号）、模块 u8（域内登记——同一接入表登记）；32 位位图支持 32 模块/域（超出 = 登记拒绝——判据行给容量声明：32 是 v1 容量，登记制天然限流）。ERROR 细化的留痕（判据行原文）：模块位静音 ERROR = 静音动作写操作日志（操作本身是一条 INFO——"谁在何时静音了谁"——静音是运维动作要可审计——被静音的 ERROR 在转储头标 MUTE 标记（数据没丢，被标记——审计可查）。为什么三维而不是二维（级别×模块）或四维（+任务）：级别×域×模块是"谁在说话（域.模块）+ 说多重要（级别）"的完整坐标——任务维不加的理由：内核日志的任务归属转储时由上下文补（F3496 时序合并附带），过滤不需要任务维（没人想"只看 tid=3 的日志"而不要域/模块坐标——需求调查显示域/模块是主导航）；四维的每次判定多一位查——热路径便宜性优先（判据行给这一"导航维度够用即可"的取舍）。运行期改写接口：`set_level/set_domain/set_mod` 三入口（单写者：控制平面单任务——F3484 管理器统一收口）。现有内核接入：无（新框架 `logging/`）。Windows 对比：ETW 的 level+keyword 二维与我们的三维同构（域/模块 ≈ provider+keyword 的合体）。M-241 复测：14 组合矩阵 + 拍数实测 + 原子性验证 + MUTE 留痕。

## F3483 每 CPU 环形缓冲（无锁单写者 ring、覆盖策略）

**定位**：RingBuffer：每 CPU 4KB 环形缓冲（单写者序号推进 + 多读者转储 + 写满覆盖最旧）——观测面的内存底盘：固定内存、零分配、零锁写。
**语义边界**：单写者 = 每 CPU 的日志只由本 CPU 写（调度约束下的天然单写——同一时刻一 CPU 一任务——严格单写者）；读者（转储）与写者并发——读者用序号快照（判据行给一致性模型：读者读到的是"某个一致瞬间附近的窗口"——覆盖式 ring 的读者契约：读到的记录可能因覆盖而断续——断续由转储头标 GAP 标记，这是流可丢红线的结构体现）。
**判据**：
- J1：M-242 单写者无锁验证：写者持续写 + 转储者并发读 100 轮 → 写路径拍数无尾延迟尖峰（无锁证据——若有锁会有等待尖峰）+ 转储读出的窗口内记录完整（未覆盖区零撕裂）。
- J2：ring 布局冻结（4KB = 头 32B + 记录区；记录头 8B：len/seq/lvl/ts_lo——判据行内嵌布局图）。
**纯功能行数**：420（ring 结构 ~160 + 写路径 ~130 + 验证用例 ~130）
**依赖与嫁接源**：B01 per-CPU 区（缓冲放置——per-CPU 槽位分配）；F3481 覆盖红线（策略源）；F3488 转储（读者协议）。
**风险与回退**：4KB 太小（风暴期关键记录被覆盖——恰好最后 4KB 没有想要的那条）——回退：分级覆盖保护（WARN/ERROR 记录写副本区——每 CPU 额外 512B 的告警环形——判据行给双环设计：主环 4KB 全级别 + 告警环 512B 只收 WARN+，告警环覆盖慢 8×——关键记录的生存窗口放大 8 倍）；转储触发（F3484 水位）是主保险。
**正文**：布局（判据行内嵌）：`[hdr:32B | rec:rec:…:rec]`——hdr 含写序号 `wr:u32`（推进位置）、读基线 `rd_base:u32`（转储消费基线——多转储者 v1 单转储者，rd_base 单写者归转储者）、魔数与版本；记录头（判据行原文）：`{len:u8, lvl:u3, dom:u8, mod:u8, seq:u16, ts_lo:u32}` 8B 对齐 + 载荷（≤ 248B——单记录上限，超长截断 + TRUNC 标记——与 B12 截断可辨认同律）。写路径（判据行原文四步）：①过滤（F3482——拒绝即返回 10 拍）②格式化（F3485 栈上）③提交：`wr_new = wr + len`（本地推进——单写者无 CAS——`store(wr_new, Release)`）④覆盖检查：`wr_new - rd_base > CAP → rd_base = wr_new - CAP`（推进读基线 = 宣告最旧记录死亡——读者协议以 rd_base 为界）。读者一致性（判据行论证）：读者快照 `(rd_base, wr)` → 逐条读 [rd_base, wr) 窗口——窗口内记录写者已提交（Release 序保证 wr 推进前记录体可见）且未覆盖（rd_base 快照后写者再推进 rd_base 会覆盖窗口尾——读者用代际校验（每记录 seq 单调——读到 seq 倒退 = 已被覆盖 → GAP 标记收尾——判据行给 GAP 协议：读出窗口的连续段 + GAP 标记 = 合法转储——流可丢在协议层的落点）。为什么无锁成立（判据行论证）：一 CPU 一写者（调度原子性——本 CPU 日志只由本 CPU 当前任务写，任务切换不断流因为 ring 是 CPU 的不是任务的）→ 写写无竞争；读写竞争被代际校验驯服（读到断续标 GAP 而非读到撕裂数据——seq 是记录的身份，倒退即覆盖证据）——全路径零 CAS 零锁——内核日志的热路径无锁是观测可信性的根基（带锁的日志会把它要观测的死锁现场变成它自己的死锁现场——自证清白问题——判据行把这一点点透：日志系统必须在死锁现场保持可写，锁是它的死穴，B08 检测器依赖这一点——F3490 联动的可用性前提）。现有内核接入：B01 per-CPU 区（槽位复用）。Windows 对比：ETW 的缓冲管理（per-processor 缓冲 + 覆盖模式 real-time loss）同构——ETW 也有"缓冲满丢旧"模式，业界共识一致。M-242 复测：无锁尾延迟 + 窗口完整性 + GAP 协议 + 双环布局 + 截断标记。

## F3484 缓冲区管理器（分配/水位/转储触发）

**定位**：RingMgr：缓冲池生命周期（启动分配 per-CPU ring）+ 水位监控（75%/90% 两级）+ 自动转储触发（水位越线 → 通知转储者）——ring 的运维平面。
**语义边界**：只做管理（ring 本体 F3483、转储执行 F3488——管理器是触发器不是执行者）；水位判定廉价化（写路径不查水位——查水位是转储者的周期工作——判据行声明：热路径零水位开销，水位是转储者视角的量）。
**判据**：
- J1：M-243 水位触发注入：填充至 75% → 转储通知触发（一级）；填充至 90% → 高优触发（二级）；转储后水位回落（管理器账面平衡）。
- J2：管理器状态机冻结（IDLE/NORMAL/HIGH/DRAINING 四态 + 转移条件表）。
**纯功能行数**：320（池管理 ~110 + 水位状态机 ~110 + 用例 ~100）
**依赖与嫁接源**：F3483 ring（rd_base/wr 序号——水位的原始量）；F3488 转储（触发通知的对端）；F3246 SleepPort（转储者等待唤醒——统一等待面）。
**风险与回退**：转储风暴（高频触发 → 转储者忙死）——回退：触发合并（水位周期检查 10ms 一次——窗口内多核越线合并为一次批量转储——判据行给合并窗口）+ 转储预算（单次转储 ≤ 1ms 虚拟时长——转储者也是内核任务，不能霸 CPU）。
**正文**：实现路径：水位量（判据行原文）：`usage = (wr - rd_base) / CAP`（转储者视角的占用率——写者不管它）；状态机（判据行内嵌）：`IDLE→NORMAL`（首次日志）、`NORMAL→HIGH`（任一核 usage ≥ 90%）、`NORMAL/HIGH→DRAINING`（转储中）、`DRAINING→NORMAL`（全部核 usage < 75%）；触发通知：管理器每 10ms 扫描一轮（多核 usage 聚合）→ 越线 → 转储者唤醒（SleepPort wake——A5 统一等待面复用——判据行再践行判例：等待经 F3246，不用裸轮询）；转预算执行（判据行声明）：单次转储 1ms 预算 × 批量合并——一次唤醒转储多核（每核取当前窗口——窗口合并的协议在 F3496）。为什么水位是转储者视角而非写路径检查（判据行论证）：写路径查水位 = 每条日志多两次序号读 + 分支——80 拍预算里塞不进且信息是滞后的（写者查到的水位在多核下必然过期）；转储者视角的周期检查 = 热路径零开销 + 水位语义清晰（"该不该转储"本来就是消费者的决策不是生产者的）——生产者消费者各司其职，水位归消费者。75%/90% 两级的理由（判据行论证）：75% = 提前量（正常转储节奏跟得上）；90% = 紧迫线（转储节奏跟不上写入节奏——告警环切换的信号——F3483 双环的切换开关挂在此：HIGH 态下 WARN+ 记录同时写告警环——双环不是常态是高压应对）；两级对应两种响应强度——单线的"该转了"分不出"例行"与"紧迫"。现有内核接入：无。Windows 对比：ETW 的 flush 触发（缓冲满/定时/显式三触发）同触发学——我们水位两级是细化。M-243 复测：两级触发 + 状态机全覆盖 + 合并窗口 + 预算执行 + 双环切换。

## F3485 日志格式与变参宏（log! 宏族、栈上格式化零堆）

**定位**：log! 宏族：五级宏（trace!/debug!/info!/warn!/error!）+ 栈上格式化器（512B 预算、零堆零锁、受限格式符集）——日志的书写面（各域的接入体验面）。
**语义边界**：格式符集封闭（判据行给全集：{} 内数字/字符串/指针/十六进制四类——开放格式化（用户自定义 trait）是堆与间接调用的温床——v1 封闭）；宏展开在过滤拒绝时**零格式化**（先判后格式——拒绝路径不付格式化税）。
**判据**：
- J1：M-244 格式化往返：四类格式符 × 各三形态 = 12 用例逐字节一致；超长载荷截断 + TRUNC 标记。
- J2：格式化预算实测（单条 ≤ 512B 栈、格式化 ≤ 40 拍——构成入 F3491 对账）。
**纯功能行数**：320（宏族 ~110 + 格式化器 ~110 + 用例 ~100）
