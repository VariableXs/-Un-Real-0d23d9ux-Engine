### UNX-F4061 · inode 缓存结构（sb 分桶哈希）
- 域/批：B1/B04｜判据：UNX-F4061-J1 缓存按（sb,i_ino）双键分桶，64 桶 × 万次插入桶分布极值有账，跨 sb 同号 inode 分属不同桶（隔离断言通过）｜纯功能行数：320 行（分桶结构 110 + 分布账 100 + 隔离断言 110；测试段不计）｜状态：[已深化]

- **语义边界**：只做桶结构与分布账；不做查找路径（F4062）；不做哈希函数本体（F4063）；64 桶常量起步（扩展再平衡随 F4063 碰撞账演进，登记注记）。
- **依赖与嫁接源**：依赖 F4041 ino 体系/F4054 静态池（节点供给）/F4017 RCU 读侧（桶读保护）；被 F4062/F4069/F4070 消费；嫁接源为 Linux inode_hashtable 语义，只跟随。
- **风险与回退**：桶分布退化（恶意聚集号全落一桶）——分布极值账+F4063 再平衡联动，退化可观测不静默；桶内线性扫退化——碰撞链长账兜底（F4063 承接），本条只保证结构可计数。
- 正文：实现路径分三步。第一步分桶结构：64 桶定长数组，桶内单链（RCU 读友好形态），键=（sb 槽号,ino）二元组哈希取桶；第二步分布账：万次插入逐桶计数，导出极值（max/min/方差），隔离断言：两个 sb 各插入同号 inode 后分属不同桶且互不可见；第三步结构完整性：出入桶配对账（插入/摘除各一次），账面零差。数据结构：桶数组 + 分布计数器 + 配对账。与现存内核衔接点：`m700vfs.rs` F204 现存 inode 记录数组升级为消费本分桶缓存（接管注记：现存全量数组扫在 8,192 上限内可容，分桶为万次级负载服务）；`m700vfs.rs` F207 路径缓存考古的消费面迁移注记。与 Windows 对照：NT 无公开 inode 缓存结构——FCB 查找经文件系统驱动内部哈希（NTFS 的 FCB 表 per-volume）与对象管理器名字空间；per-volume 分桶与 per-sb 同构，Windows 侧结构不可观测（内部实现），本域显式账为自研口径（对照登记）。判据 UNX-F4061-J1 的复测方式：ktest 万次插入分布账 + 跨 sb 隔离断言 + 配对账零差，宿主侧全跑。

### UNX-F4062 · iget 查找-插入-命中路径
- 域/批：B1/B04｜判据：UNX-F4062-J1 iget 三路径（命中/未命中新建/并发竞争合并）各 1,000 次行为正确，路径判定账与理论分布一致｜纯功能行数：300 行（三路径状态机 110 + 行为账 100 + 分布断言 90；测试段不计）｜状态：[已深化]
- **定位**：iget 的三分岔路网——命中（缓存有：kref+1 返回）/未命中（缓存无：走池新建+插桶）/并发竞争合并（两路同时 iget 同号：合并为单实例）。三路径各 1,000 次行为正确且判定账与理论分布一致——路径账是"缓存有没有在干活"的直接证据。
- **语义边界**：只做三路径行为账；不做哈希结构（F4061）；不做并发协议本体（F4070 RCU 消费）；未命中新建依赖 fs 侧回填（fake fs 起步：回填即时完成）。
- **依赖与嫁接源**：依赖 F4061 结构/F4054 池/F4064 引用纪律；被 B09 walk 与 F4071 回归消费；嫁接源为 Linux iget_locked 三态语义，只跟随。
- **风险与回退**：竞争双建（两路都走新建）——插入去重守卫（第二次插入发现已有即转为合并路径），双建注入被账检出；路径账漂移（账面与实际路径不符）——路径判定在入口单点落账，账与分支绑定。
- 正文：实现路径分三步。第一步 iget(sb,ino) 状态机：查桶→命中（kref+1/账"hit"）→未命中（池取+初始化+插桶/账"miss-new"）→插入竞争（发现已存在转合并/账"merge"）；第二步行为账：三路径各 1,000 次（确定性负载），账面分布与负载构造的理论比例核对；第三步合并正确性：竞争注入（双线程模拟交错）后实例计数==1。数据结构：路径账三计数器 + 行为账。与现存内核衔接点：`m700vfs.rs` F204 现存查找切换为消费 iget（接管注记）；`fs23` 系列按号取 inode 语义对齐（对照账）。与 Windows 对照：NT 等价物是 FCB 查找路径（NTFS Vcb 内 FCB 表查/建），"竞争合并"在 NT 由每卷 FCB 表锁串行化表达（先到建、后到等或合并）；本域 RCU 化（F4070）与 NT 锁化是两种并发形态，对照登记演进注记。判据 UNX-F4062-J1 的复测方式：ktest 三路径各 1,000 次 + 分布核对 + 竞争合并断言，宿主侧全跑。

- **语义边界**：只做哈希与再平衡；不做桶结构（F4061）；再平衡是"链长超限触发重哈希扩桶"的保守形态（64→128 桶单次演进），不做动态无界扩容（静态配额纪律延续）。

- **风险与回退**：再平衡期间读者不可见（迁移撕裂）——再平衡在写锁内完成（F4037 锁序），读侧 RCU 宽限期后切新表（F4017 消费）；哈希质量未知（自选函数无凭证）——三类输入分布账即凭证（极差入账）。
- 正文：实现路径分三步。第一步哈希函数：乘法哈希（黄金比例常数）对（sb,ino）二元组；第二步三类分布账：连续号/随机号/聚集号（ino≡0 mod 64 恶意构造）各 1 万次分布极差入账，聚集注入的退化可观测（极差报告）；第三步再平衡：链长上限 16 触发重哈希（64→128 桶），迁移账逐条核对（新旧表条目数恒等）。数据结构：哈希常量 + 分布账 + 再平衡账。与现存内核衔接点：`m700vfs.rs` F207 现存缓存哈希（若有）对齐本函数（对照账）；F4061 结构为直接宿主（消费关系）。与 Windows 对照：NT 内部哈希（对象管理器名字树、FCB 表）不公开函数与分布账；"分布可观测+再平衡"是自研工程纪律增强（对照登记：Windows 侧对应机制内化不可见）。判据 UNX-F4063-J1 的复测方式：ktest 三类分布账 + 聚集注入退化报告 + 再平衡迁移恒等断言，宿主侧全跑。

### UNX-F4064 · inode 引用计数与 i_count 纪律
- 域/批：B1/B04｜判据：UNX-F4064-J1 i_count 增减与持有者账（walk/file/挂载三类持有源）逐笔对应，万次往返零偏差，负值注入即红｜纯功能行数：300 行（引用纪律 100 + 持有者账 100 + 负值守卫 100；测试段不计）｜状态：[已深化]
- **定位**：i_count 的纪律与来源账——引用增减与持有者账（walk/file/挂载三类持有源）逐笔对应，万次往返零偏差，负值注入即红。F4015 kref 立了原语，本条立 inode 侧纪律："每一笔引用都有名字"——泄漏时能回答"谁持着不放"。
- **语义边界**：只做 inode 引用纪律；不做 dentry/file 引用（F4011/F4012 自带 kref 各自记账）；持有者三类起步（新源类型注册扩展）；负值守卫即 F4015 underflow 的 inode 侧实例。
- **依赖与嫁接源**：依赖 F4015 kref 原语；被 F4065/F4071 消费；嫁接源为 Linux i_count/igrab 语义，只跟随。
- **风险与回退**：匿名引用（没过持有者账的 get）——get 接口强制带源参数（缺参编译期拒绝），匿名注入被账检出；账开销（逐笔历史大）——逐笔账 ktest 面全开、生产面计数器式（三源计数器），口径注记。
- 正文：实现路径分三步。第一步引用接口：ihold(inode,source)/iput_ref(inode,source) 带 source 枚举（walk/file/mount），缺参即编译错；第二步持有者账：逐笔（ktest 全量环形账）+三源计数器（生产口径），万次 get/put 往返残差断言=0；第三步负值守卫：put 过量注入即红（F4015 underflow 联动），泄漏注入（只 get 不 put 万次）账面三源计数定位到源。数据结构：源枚举 + 逐笔账 + 三源计数器。与现存内核衔接点：`m700vfs.rs` F204 现存引用处理切换为带源纪律（接管注记）；F4015 原语为直接地基（消费关系）。与 Windows 对照：NT 对象引用（ObReferenceObject）无强制来源参数——泄漏定位靠外置工具（Driver Verifier 引用追踪，开销巨大）；本域"引用必有名"为内核内置轻量纪律（对照登记：Windows 侧等价能力在验证工具态）。判据 UNX-F4064-J1 的复测方式：ktest 万次往返残差=0 + 三源账核对 + 负值注入即红，宿主侧全跑。

### UNX-F4065 · iput 归零路径与回收队列
- 域/批：B1/B04｜判据：UNX-F4065-J1 iput 归零触发回收队列入队恰好一次（重复入队注入零命中），脏 inode 归零先写回后回收（写回完成标志先行断言通过）｜纯功能行数：300 行（归零路径 100 + 回收队列 100 + 写回先行 100；测试段不计）｜状态：[已深化]
- **定位**：引用归零的终局裁决——iput 归零触发回收队列入队恰好一次（重复入队注入零命中）；脏 inode 归零先写回后回收（写回完成标志先行断言）。"恰好一次"与"先写回"是回收安全双闸：前者防重复回收（use-after-free 源头），后者防数据丢失（脏 inode 直接丢弃）。
- **语义边界**：只做归零裁决与队列；不做队列消费（回收执行随 B15 总回归联动，队列消费接口预留）；写回依赖 fake A4 完成回调（F4055 脏位协议消费）；已在孤儿账的 inode（F4035）走孤儿路径不入本队列（两账联动注记）。
- **依赖与嫁接源**：依赖 F4064 纪律/F4055 脏位/F4015 归零回调；嫁接源为 Linux iput_final/evict 语义，只跟随。
- **风险与回退**：重复入队（回调重入）——队列成员标志位（在队即不再入），重入注入零命中；写回失败仍回收（数据丢失）——写回完成标志必须置位才放行回收，失败注入停在队列（重试语义注记）。
- 正文：实现路径分三步。第一步归零裁决：iput 减到 0 时检查脏位——脏则触发写回请求、等完成标志（fake 回调）、再入队；净则直接入队；第二步恰好一次：入队前查成员标志，重复入队注入 100 次零命中；第三步先行断言：写回完成事件与入队事件的时序账单调（完成先于入队）。数据结构：回收队列 + 成员标志 + 时序账。与现存内核衔接点：`m700vfs.rs` F204 现存归零处理切为消费本裁决（接管注记）；F4035 孤儿账与队列联动（注记）。与 Windows 对照：NT 对象归零回调（ObDereferenceObject 触发 DeleteProcedure）语义同构；脏数据先行写回在 NT 由缓存管理器 flush（CcFlushCache）在最后句柄关闭路径承担；"先 flush 再删"与"删挂起等引用"两语义在 Windows 合并于句柄语义（FILE_DISPOSITION+SHARE_DELETE），口径差异对照登记。判据 UNX-F4065-J1 的复测方式：ktest 重复入队注入零命中 + 脏归零时序断言 + 失败注入停队列，宿主侧全跑。

### UNX-F4066 · 未引用 inode 淘汰（LRU 尾部）
- 域/批：B1/B04｜判据：UNX-F4066-J1 淘汰只从 LRU 尾取（头部注入被拒），淘汰后 iget 重建路径与首次创建路径行为一致（重建账零差）｜纯功能行数：260 行（LRU 结构 90 + 淘汰协议 90 + 重建对账 80；测试段不计）｜状态：[已深化]
- **定位**：缓存收缩的秩序——未引用（i_count=0）inode 挂 LRU，淘汰只从尾部取（头部注入被拒——最近使用的绝不被先扔），淘汰后 iget 走重建路径且与首次创建行为一致（重建账零差）。F4054 裸池的"策略层"就是本条 LRU。
- **语义边界**：只做 LRU 与淘汰协议；不做脏 inode 淘汰（F4067 不变式拒绝）；不做水位触发（F4074）；"未引用才可挂 LRU"是入队纪律（带引用的入队注入被拒）。
- **依赖与嫁接源**：依赖 F4064 引用/F4061 结构；被 F4074 压力消费；嫁接源为 Linux inode_lru 语义，只跟随。
- **风险与回退**：LRU 与缓存双链漂移（在缓存不在 LRU 的幽灵节点）——出入双链配对账，漂移注入检出；淘汰热头（策略 bug 把新节点放尾）——分布账（淘汰节点年龄分布）可观测。
- 正文：实现路径分三步。第一步 LRU 结构：双向链+入队纪律（i_count==0 且非脏才入队）；第二步淘汰协议：shrink 取尾、头部注入拒绝、淘汰节点出缓存+回池（账配对）；第三步重建对账：淘汰后 iget 同号→走 miss-new 路径→与首次创建的行为账逐项比对零差。数据结构：双向 LRU 链 + 配对账。与现存内核衔接点：`m700vfs.rs` F204 现存记录无淘汰策略，接管后消费本 LRU（注记）；F4054 池为直接地基。与 Windows 对照：NT 内存管理器工作集裁剪与缓存管理器按需清退承担等价职能（对象级 LRU 内化在 FCB 生命周期）；"LRU 尾取"纪律为 Unix icache 语义（对照登记）。判据 UNX-F4066-J1 的复测方式：ktest 头部注入拒绝 + 尾部淘汰账 + 重建零差断言，宿主侧全跑。

### UNX-F4067 · 脏 inode 不淘汰不变式
- 域/批：B1/B04｜判据：UNX-F4067-J1 脏位存活期间淘汰注入 1,000 次零命中，脏位清零后立即回到可淘汰集（状态迁移账可见）｜纯功能行数：280 行（不变式守卫 100 + 迁移账 90 + 注入检测 90；测试段不计）｜状态：[已深化]
- **定位**：脏数据的保护伞——脏位（F4055）存活期间 inode 绝不被淘汰（1,000 次注入零命中），脏位清零后立即回到可淘汰集（迁移账可见）。"脏了不能扔"是数据安全的缓存侧红线：淘汰=丢弃内存态，脏 inode 淘汰即丢数据。
- **语义边界**：只做不变式守卫与迁移账；不做写回触发（脏 inode 在 LRU 外挂着等写回——谁触发写回是 A4 调度职责，本条只保证"脏期不可淘汰"）；清零瞬间回集的时序账口径在 F4055 确认事件。
