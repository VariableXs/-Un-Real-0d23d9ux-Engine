### UNX-F4002 · VFS 错误码全集与 errno 投影基座
- 域/批：B1/B01｜判据：UNX-F4002-J1 VFS 全域 32 类错误码枚举与 errno 数值投影表逐项比对一致（32/32），投影函数对枚举外值返回 EINVAL｜纯功能行数：260 行（错误码枚举与常量表 80 + 投影函数 90 + 反向投影与守卫 90；测试段不计）｜状态：[已深化]
- **定位**：VFS 全域错误语言的宪法页——32 类错误码（ENOENT/ENOTDIR/EISDIR/EBUSY/ELOOP/EXDEV/EROFS/ENAMETOOLONG/ENOSPC/ENOMEM/EMFILE/ENFILE/EACCES/EPERM/EINVAL/EEXIST/ENODEV/ENOTTY/EOVERFLOW/ESTALE/EIO/EFSCORRUPTED 等）一个枚举、一张 errno 投影表、一条投影函数，B1 域 40 批与下游 B2–B5/C2/D3 全部说同一种错误语言。
- **语义边界**：只做错误码定义与数值投影；不做错误呈现三要素文案（呈现归各调用面与日志域）；不做 fs 嫁接层错误码的语义改写（透传契约归 F4155）；errno 数值对齐 POSIX 权威表不改一个数。
- **依赖与嫁接源**：依赖 F4001 初始化序；被全域 40 批消费（首批消费者 F4022/F4091）；嫁接源为 POSIX.1-2017 errno 权威数值表与 Linux asm-generic/errno.h 对照，只跟随。
- **风险与回退**：枚举与投影表漂移（加码不同步）——用编译期断言（枚举计数=表长度）+ 运行期全表比对用例双保险；投影函数被绕过（直接裸传数值）——审计面以"域内禁止裸 errno 字面量"为 grep 红线，违例入缺陷账。
- 正文：实现路径分三步。第一步权威枚举：32 值按 POSIX 数值锚定（非连续，保留真实 errno 数值），每值附语义一句话注释；第二步投影表：`static const` 数组做枚举→errno 数值，编译期断言锁长度；第三步投影函数：正向投影（枚举→数值）、反向投影（数值→枚举，供诊断显示）、守卫（非法值→EINVAL 并计数落账）。数据结构：枚举 + 常量投影表 + 单计数器（守卫命中数），全静态。与现存内核衔接点：`lxerrno.rs` 已有 Unix 错误码投影雏形（lxrun 消费面），本条与之对齐数值表并声明为 VFS 域权威入口，`vfsguard.rs` 现存错误路径逐步切到本入口（切换映射账归 F4216 同型处理）。与 Windows 对照：Win32 错误以 Win32 Error Code 命名空间表达，NT 内核层用 STATUS_ 值（NTSTATUS），两套数值经 Win32→NTSTATUS 投影互转——Windows 文件系统驱动返回 STATUS_OBJECT_NAME_NOT_FOUND 而 POSIX 层见 ENOENT，正是双人格内核需要投影层的原因；本条即 Unix 人格侧的投影起点，D3/D1 侧的 NTSTATUS 投影由该域自建，两表在对照账中互查。判据 UNX-F4002-J1 的复测方式：ktest 用例逐表项比对（32/32）+ 非法值注入（枚举外 ±1、极大值、零）四类各跑断言守卫返回 EINVAL，宿主侧一条命令全跑，无实机依赖。

- **定位**：一切文件对象的身份身份证——常规文件/目录/符号链接/字符设备/块设备/FIFO/socket 七类的枚举与 S_IFMT 位段编码。路径解析（B09）按类型分派行为、权限检查（B03）按类型走不同通路、挂载（B12）只认目录，全部依赖本条的类型事实。
- **语义边界**：只做类型定义与编码；不做类型行为差异（分属各条目）；不做 DT_* 目录项编码（d_type 归 B05 lookup 返回面）；socket 类型只立枚举占位，socket 文件语义归 I2 域（边界联签）。
- **依赖与嫁接源**：依赖 F4002 错误码（非法类型注入报错）、F4004 权限位（i_mode 复合编码的另一半）；嫁接源为 POSIX.1-2017 `<sys/stat.h>` S_IFMT 编码权威表（S_IFREG 0100000/S_IFDIR 0040000/S_IFLNK 0120000 等），只跟随。
- **风险与回退**：编码位段与权限位串位——S_IFMT 高四位与低九位权限+三特殊位掩码独立，编解码函数各自掩码后拼装，串位注入被往返测试捕获；第七类 SOCK 在 Unix 域 socket 落地前被误用——枚举保留但构造入口断言拦截（占位纪律）。
- 正文：实现路径分三步。第一步编码表：七类 × S_IFMT 权威值的常量表，附 POSIX 章节出处注释；第二步编解码函数：type_of(mode)（掩码提取→查表）与 encode(type)（查表→位段），非法输入返回错误码；第三步往返账：随机 mode 值 10,000 次往返，不一致计数必须为零。数据结构：枚举 + 常量表 + 两个纯函数，零状态。与现存内核衔接点：`m700vfs.rs` 现存类型判定（F201 操作码旁路）切换为消费本条编码表（映射注记）；`fs/fs23_abstract.rs` 的文件类型描述与本表对齐（对照账）。与 Windows 对照：Windows 文件属性以 FILE_ATTRIBUTE_* 位表达（DIRECTORY/REPARSE_POINT/NORMAL 等），无"七类"正交枚举——设备在 NT 是带 DeviceType 的对象而非文件类型位，FIFO 对应命名管道（\\.\pipe\）独立命名空间；D3 转换层把 NT 属性投影到本七类（DIRECTORY→DIR、REPARSE_POINT→LNK 优先判、其余→REG），投影规则登记为 D3 联签边界（F4096 同源）。判据 UNX-F4003-J1 的复测方式：ktest 表逐位比对 + 10,000 次往返账 + 串位注入（构造高位污染 mode 断言提取正确），宿主侧全跑。

### UNX-F4004 · 权限位模型（rwx 九位与 setuid/setgid/sticky）
- 域/批：B1/B01｜判据：UNX-F4004-J1 权限位编解码与 chmod 八进制字面量全部 4,096 组合往返一致；setuid/setgid/sticky 单独置位后 i_mode 对应位可观测为 1｜纯功能行数：280 行（权限位编码与解析 90 + 特殊位三件 90 + 4,096 组合账 100；测试段不计）｜状态：[已深化]
- **定位**：i_mode 低 12 位的权威编解码——九位 rwx（三类属主）+ setuid/setgid/sticky 三特殊位。chmod 八进制字面量（0644/1777 级）到 i_mode 的映射是权限检查（F4043）、setattr 管道（F4151）与 C2 chmod 族 syscall 的共同语言。
- **语义边界**：只做位编解码与可观测性；不做权限判定逻辑（属主/组/其他三路判定归 F4043）；不做 ACL 扩展（POSIX ACL 与 NT DACL 投影是 J1/B3 联签件，本域不越权）；sticky 对目录的独占语义注记归 F4043 判定矩阵。
- **依赖与嫁接源**：依赖 F4003 类型位（i_mode 复合编码高位段）；嫁接源为 POSIX.1-2017 `<sys/stat.h>` 权限位宏（S_ISUID 04000/S_ISGID 02000/S_ISVTX 01000），只跟随。
- **风险与回退**：八进制字面量歧义（chmod 777 与 0777）——解析函数统一按无符号八进制处理并落账输入形式；特殊位在不支持文件类型上的静默丢弃——构造入口对 REG+sticky 类组合保留位值不解释（由 fs 嫁接层决定支持度），VFS 层零丢弃（透传纪律）。
- 正文：实现路径分三步。第一步位段编解码：九位+三位的提取/置位/清除纯函数；第二步 chmod 字面量解析：1–4 位八进制全接受（1 位视为补零前缀），越界（>07777）返回 EINVAL；第三步组合账：0–07777 全量 4,096 组合往返比对，不一致零容忍。数据结构：纯函数 + 组合账计数器。与现存内核衔接点：`fs/fs23_acl.rs` 现存权限位描述对齐本编码（对照账），`m700vfs.rs` F206 权限裁决台消费本条编解码（映射注记）。与 Windows 对照：NT 无 rwx 九位——DACL 以 ACE（允许/拒绝×特定权限）表达，读/写/执行对应 FILE_GENERIC_READ/WRITE/EXECUTE 复合权限；D3 投影方向（NT→POSIX）按属主/组/其他三元近似折叠是经典有损映射（POSIX 无 Deny 优先语义），投影规则与损失登记为 B31/J1 联签件（对照账占位）；sticky 在 Windows 无对应（目录仅 TEMP 类语义近似），投影显式丢弃并落账。判据 UNX-F4004-J1 的复测方式：ktest 4,096 组合全量往返 + 三特殊位逐一置位可观测断言 + 越界字面量注入，宿主侧全跑。

### UNX-F4005 · uid/gid 属主模型与凭据传递接口
- 域/批：B1/B01｜判据：UNX-F4005-J1 属主三元组（uid/gid/mode）在 inode 创建链三段传递保真，凭据缺省值（0/0）落账，传递链中途抹除注入在第三段被检出｜纯功能行数：240 行（凭据结构 70 + 传递接口 80 + 保真账 90；测试段不计）｜状态：[已深化]
- **定位**：属主身份的传递管道——uid/gid 从调用凭据经 VFS 层到 fs 嫁接层的三段保真。chown（F4152）、权限判定（F4043）、挂载旗（F4250 nosuid）都以此为身份事实源；凭据抹除（中间层丢身份）是安全红线级缺陷，本条把"传递保真"变成可注入验证的账。
- **语义边界**：只做传递结构与保真账；不做凭据的来源认证（登录/令牌归 J2 域）；不做属主修改语义（chown 行为归 F4052）；单用户态起步（uid=0 全权）是事实口径，多用户矩阵待 J 域收口后回归补测。
- **依赖与嫁接源**：依赖 F4004 mode 编码；嫁接源为 POSIX.1-2017 `<sys/types.h>` uid_t/gid_t 语义，只跟随。
- **风险与回退**：凭据在跨层调用中被默认值覆盖（0/0 即 root——提权事故）——传递接口禁用缺省参数（显式必传），抹除注入第三段校验拦截；fake 凭据泄漏到真实路径——结构标注 fake 标志位，真实接线（A3/J 域收口）时强制清除。
- 正文：实现路径分三步。第一步凭据结构：`Cred{uid,gid,flags}` 定长结构，uid=0/gid=0 为显式缺省（构造时落账"使用缺省凭据"事件）；第二步三段传递接口：`cred_at(seg)` 三段（入口/VFS/嫁接）只读视图，任何一段拿到的三元组与其他段逐字段可比；第三步保真账：每次创建链传递落一条账（三段指纹），抹除注入在第三段比对时命中并报告段位。数据结构：Cred 结构 + 段指纹账（环形账 32 条，溢出滚动）。与现存内核衔接点：`m700vfs.rs` F206 权限裁决台现存 uid 处理消费本结构（映射注记）；`vfsguard.rs` 白名单裁决（SHARED 挂载面）暂以单一信任域运行，多凭据接线随 J 域（注记在案）。与 Windows 对照：NT 属主以 SID 表达（域化身份），令牌（Token）承载凭据随线程/进程走——POSIX 的 fsuid/fsgid 线程级覆盖在 Windows 无直接对应（impersonation 是等价物）；D3 投影把本地 SID 简化映射 uid/gid 数值（S-1-5-21 域内 RID），投影损失（域外 SID 不可映射）显式落账。判据 UNX-F4005-J1 的复测方式：ktest 三段保真注入（每段抹除各 10 次，第三段检出率必须 10/10）+ 缺省凭据落账断言，宿主侧全跑。

### UNX-F4006 · 时间戳四件套（atime/mtime/ctime）语义锚
- 域/批：B1/B01｜判据：UNX-F4006-J1 三时间戳纳秒级分辨率编码落账，mtime/ctime 触发矩阵（读/写/截断/属性改四操作）按 POSIX 行为表逐格断言通过｜纯功能行数：260 行（时间戳结构 70 + 触发矩阵 100 + 编码账 90；测试段不计）｜状态：[已深化]
- **定位**：文件时间语义的锚——atime/mtime/ctime 三件套（Windows 的 btime 创建时间作为第四件登记但不进 POSIX 判定）的编码与触发矩阵。备份工具、rsync 类同步、make 类构建系统全部以时间戳为决策输入，语义错一格下游全错，故逐格判据化。
- **语义边界**：只做编码与触发矩阵；不做时间源（时钟读取归 A2 域，本条消费接口）；不做 relatime 策略（F4046 深化）；btime 只登记不参与 POSIX 判定（对照面）。
