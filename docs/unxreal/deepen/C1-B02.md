### UNX-F8038 · fork 失败路径与资源回滚
- 域/批：C1/B02｜判据：UNX-F8038-J1 页预算耗尽/描述符配额耗尽时 fork 返回 EAGAIN 且已分配资源 100% 回滚，失败注入 10/10 零泄漏｜纯功能行数：240 行（失败点矩阵 70 + 回滚例程 90 + 注入判据件 80；测试段不计）｜状态：[已深化]
- **定位**：失败回滚是 fork 的"安全气囊"——fork 是资源申请大户（描述符+fd 表+地址空间），半途失败必须净身而退；本条把失败点矩阵与回滚序钉死，是零泄漏纪律在 fork 路径的专属防线。
- **语义边界**：只做 fork 失败矩阵与回滚；不做 execve 失败回滚（F8011/B09 域自有，语义对齐同款纪律）；不做 OOM killer 策略（域外登记）；EAGAIN 是唯一用户可见错误码（EINVAL 参数错除外）。
- **依赖与嫁接源**：依赖 F8022 构造序、F8031/F8032 复制挂点、A4 冻结接口错误码；嫁接源为 Linux copy_process 的错误清理路径（bad_fork_free 系列标签语义）。
- **风险与回退**：回滚序错（先回收描述符再回滚 fd 计数）会造成悬垂——回滚序为构造序的严格逆序（配额→描述符→fd 表→地址空间），逆序纪律机检；注入器 10 失败点全覆盖。
- 正文：实现路径分三步。第一步失败点矩阵：fork 构造序逐点枚举失败位——配额检查（进程数上限）、pid 发号（F8026 耗尽）、fd 表复制（B1 失败）、COW 空间构造（A4 fake/真实现失败）、统计挂点（不失败位登记）；矩阵七位各配注入开关（ktest 用）。第二步回滚例程：任一点失败按构造逆序逐项回收——已复制的 fd 表逐项计数-1、A4 空间整体归还（冻结签名）、描述符回池、发号器游标回退（窗口账不产生残留）；回收账与申请账逐项对账（零泄漏判据）。第三步错误出口：失败统一 EAGAIN（Linux 同码）经 lxerrno 单源；回滚完成事件入诊断账（失败点/回收项数两列）。与现存内核衔接点：lxerrno.rs errno_of 单源出口消费（EAGAIN 映射在册）；A4 冻结接口的失败错误码矩阵在本条随冻结申请单联合登记（双方同文）。与 Linux 对照：copy_process 的 EAGAIN 语义（进程/线程上限）与失败清理路径逐行为对齐；Linux 的 vm 空间失败码族（ENOMEM 在 mmap 语义中）在 fork 路径统一 EAGAIN 的策略与 Linux 一致。与 Windows 对照：CreateProcess 失败码族（ERROR_NOT_ENOUGH_MEMORY 等）对位——对照表互引码映射。判据 UNX-F8038-J1 的复测方式：ktest 跑七失败点注入 10/10（每点回滚后对账零泄漏+EAGAIN 断言），真机随闸门补测。
