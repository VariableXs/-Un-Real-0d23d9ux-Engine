### UNX-F10461 · rt_sigframe 布局与 ABI 注出处
- 域/批：C4/B04｜判据：UNX-F10461-J1 帧内 pretcode/uc/siginfo 偏移与 System V ABI 注出布局逐字段一致，offsetof 断言全过｜纯功能行数：320 行（帧结构定义 120 + 偏移断言 100 + 布局账 100；测试段不计）｜状态：[已深化]
- **定位**：rt_sigframe 是内核递给 handler 的"案件卷宗"——返回地址、上下文、信号信息三件套按 ABI 精确落位。本条建帧布局事实源：以 System V AMD64 ABI 与 Linux UAPI 为源逐字段誊录，offsetof 断言构建期锁定，杜绝记忆误差。
- **语义边界**：只做帧布局与偏移账；不做构造时序（F10462）、不做回位（F10463）。SA_RESTORER 桩字段按 Linux UAPI 保留（glibc 依赖其存在）。
- **依赖与嫁接源**：ABI 注出处：System V AMD64 ABI 信号帧图示与 Linux arch/x86/.../sigframe.h 结构（出处入账），只跟随。
- **风险与回退**：ABI 文档与内核实现字段的差异（内核私有扩展字段）——布局账按"ABI 承诺字段 + 内核私有字段"两节登记，用户可见面只依 ABI 节。
- 正文：实现路径分三步。第一步帧结构：`RtSigFrame { pretcode, siginfo, ucontext, retcode[] }` 按注出布局落定义——pretcode 指向 sigreturn 调用桩、ucontext 持寄存器现场与掩码、siginfo 按 F10447 布局内嵌；第二步偏移断言：offsetof/sizeof 逐字段断言表（pretcode=0、siginfo=8、uc=176 级精度以 ABI 文档为准）构建期全跑；第三步布局账：字段表注出处逐行登记（源文档章节号），账面即防幻觉证据链——后续任何帧改动必须先改账再改码。与现存内核衔接点：帧定义置 signal.rs，构造器消费 `proc/ring3.rs` 寄存器现场快照。与 Linux 对照：glibc sigreturn 桩直跑 Varix 帧，判据 UNX-F10461-J1 的复测方式：offsetof 断言全过、账面出处 31 信号源齐备、三件套内容抽查 10/10 次一致。

### UNX-F10462 · 用户 handler 栈帧构造与对齐
- 域/批：C4/B04｜判据：UNX-F10462-J1 帧落用户栈按 16 字节对齐，寄存器现场快照与故障时点一致（10/10 次），栈溢出有红账｜纯功能行数：300 行（栈下探 100 + 现场快照 100 + 对齐与红账 100；测试段不计）｜状态：[已深化]
- **定位**：递送是"在用户栈上给 handler 开间临时办公室"——办公室落位要 16 字节对齐（ABI 要求）、办公室家具（寄存器现场）要与故障时点分毫不差。本条实现构造器：对齐下探、现场快照、溢出红账三件事。
- **语义边界**：只做帧构造；altstack 路径（F10464）与溢出兜底（F10477）分条；现场快照的来源是中断/异常时的寄存器保存区（ring3 侧已有），构造器只读不造。
- **依赖与嫁接源**：消费 F10461 布局与 ring3 保存区；嫁接源为 Linux setup_rt_frame 构造顺序与 ABI 对齐要求，只跟随。
- **风险与回退**：用户栈指针被用户程序改到非法区（栈上构造帧本身引爆页错误）——构造前对帧区间做 uaccess 预检，不可写即走 F10477 兜底，零内核递归异常。
- 正文：实现路径分三步。第一步对齐下探：sp 按 16 字节向下对齐后再让出帧空间，对齐值落账可查——对齐错一档，glibc 级代码即崩，判据含对齐值断言；第二步现场快照：中断/异常保存区的 GP 寄存器、RIP、RFLAGS 逐个快照入 ucontext，快照与保存区逐值比对（构造正确性旁证）；第三步溢出红账：预检失败（栈空间不足/不可写）记红账（进程、信号、sp 值），走兜底路径——红账即排疑线索，静默降级被禁。与现存内核衔接点：保存区与 `proc/ring3.rs` 现有现场结构联签。与 Linux 对照：handler 内回读 ucontext 与 gdb 所见一致，判据 UNX-F10462-J1 的复测方式：对齐断言 10/10 次、现场一致 10/10 次、溢出红账 10/10 次落账。

### UNX-F10463 · rt_sigreturn 回位与栈指针校验
- 域/批：C4/B04｜判据：UNX-F10463-J1 sigreturn 恢复寄存器现场与构造时快照逐寄存器一致，伪造帧（坏魔数）拒收 SIGSEGV｜纯功能行数：300 行（回位恢复 110 + 魔数校验 90 + 伪造拒收 100；测试段不计）｜状态：[已深化]
- **定位**：sigreturn 是信号世界的"会议结束签字离场"——把 ucontext 里的现场原样恢复回寄存器。它同时是最危险的syscall：现场全由用户栈提供，伪造帧等于挟持内核。本条建魔数校验与逐寄存器恢复对账，伪造必拒。
- **语义边界**：只做回位与校验；帧构造（F10462）与恢复语义的完整闭环在本条对勾。特权位恢复（RFLAGS 的 IOPL 等）按现行保护模式白名单恢复，越权位拒绝并红账。
- **依赖与嫁接源**：消费 F10461 帧布局；嫁接源为 Linux sys_rt_sigreturn 与魔数（uc_flags/帧魔数）校验思路，只跟随。
- **风险与回退**：恢复点 sp 被用户改写后的定位（从栈上哪找帧）——按 Linux 语义以 sigreturn 入口时 sp 为帧锚，锚被改走校验失败路径（SIGSEGV），不做栈内扫描（扫描即漏洞）。
- 正文：实现路径分三步。第一步回位恢复：sigreturn 以入口 sp 锚帧，逐寄存器恢复（GP 全组 + RIP + RFLAGS 白名单位），恢复前与 ucontext 快照对账——"恢复的 == 构造存的"逐值断言；第二步魔数校验：帧头魔数与 ucontext 尺寸字段双重校验，不符即拒收——拒收动作统一 SIGSEGV 并红账（进程、sp、魔数实值）；第三步伪造用例：构造坏魔数/越界帧/特权位攻击三类伪造帧各 10 次，全数拒收零放行。与现存内核衔接点：sigreturn 号面挂号，恢复写 ring3 现场区。与 Linux 对照：`sigreturn` 后寄存器与 gdb 快照一致，判据 UNX-F10463-J1 的复测方式：逐寄存器一致 10/10 次、伪造拒收 30/30 次、特权位拒绝 10/10 次。

### UNX-F10464 · SA_ONSTACK 替换信号栈（sigaltstack）
- 域/批：C4/B04｜判据：UNX-F10464-J1 altstack 注册/查询/切换三态正确，栈内再触发同信号按 POSIX 判核终止（栈耗尽路径）｜纯功能行数：280 行（altstack 注册 100 + 切换判定 90 + 栈耗尽 90；测试段不计）｜状态：[已深化]
- **定位**：SA_ONSTACK 是栈溢出自救的生路——主栈炸了，handler 在备用栈上还有地方站。本条实现 sigaltstack 注册/查询与 ONSTACK 切换判定，栈内再触发同信号的"栈耗尽"路径按 POSIX 判核终止。
- **语义边界**：只做 altstack 三态与切换；栈本体由用户分配（内核只登记区间）；SS_ONSTACK 状态查询语义（在 alt 栈上时禁改注册）按 POSIX。
- **依赖与嫁接源**：消费 F10462 构造器（栈选择分支）；嫁接源为 sigaltstack(2) 语义与 POSIX 栈耗尽条文，只跟随。
- **风险与回退**：altstack 区间非法（用户给坏指针）——注册时 uaccess 预检区间可写性，非法即 EINVAL，防递送时才发现的晚爆。
- 正文：实现路径分三步。第一步注册：sigaltstack 登记（基址、大小、旗标）三态账——禁用/启用/当前使用中，注册时区间预检；第二步切换判定：递送时 handler 旗标含 SA_ONSTACK 且当前不在 alt 栈上→帧落 alt 栈；已在 alt 栈→不重复切换（按 POSIX 用主栈语义的豁免分支需谨慎，Varix 按同信号判耗尽、异信号允许同栈嵌套）；第三步栈耗尽：alt 栈上同信号再触发→DFL 判核终止（POSIX 裁定），崩溃账注"altstack 耗尽"。与现存内核衔接点：栈选择并入构造器，耗尽路径复用 DFL 执行器。与 Linux 对照：`sigaltstack` 自救模式同源，判据 UNX-F10464-J1 的复测方式：三态 10/10 次、切换判定 10/10 次、耗尽终止 10/10 次账面有因。

- **定位**：SIGCHLD 是父进程的育儿警报——退出/停止/继续三类事件各带 CLD_* 码。本条从 C1 退出路径挂接警报源，事件分类进 siginfo，与 waitpid 收割链联签成环：警报响→掩码过→handler 或 wait 收割，链条每段可观测。
- **语义边界**：waitpid 收割本体归 C1（僵尸账/退出码提取），本域立警报面与联签；SA_NOCLDWAIT 的不产僵尸语义与 F10448 旗标账联签消费。

- **风险与回退**：警报与收割的竞态（wait 与 handler 同时收尸）——收割原子化（C1 僵尸账锁），谁先拿到谁收、后者得 ECHILD，竞态结果落账。
- 正文：实现路径分三步。第一步挂接：C1 退出/停止/继续三事件点调警报源，挂位（SA_NOCLDSTOP 对停止事件抑制，退出/继续照常）与 siginfo 填充（CLD_EXITED/CLD_STOPPED/CLD_CONTINUED + 子 pid）同步完成；第二步事件分类：三事件 × CLD 码映射逐项判据，码错即红；第三步收割联签：全链观测账（事件时点、挂位、递送、收割）四拍可导——handler 收割用例与 waitpid 收割用例双路验证，竞态用例（handler+wait 并发）100 轮零双收零漏收。与现存内核衔接点：C1 exit/sched 事件钩子联签，收割对账消费 C1 僵尸账。与 Linux 对照：`waitpid` + handler 并存行为同源，判据 UNX-F10465-J1 的复测方式：全链四拍 10/10 次、NOCLDSTOP 抑制 10/10 次、竞态 100 轮零异常。

### UNX-F10468 · 实时信号 32–64 排队（RTSIG 区间）
- 域/批：C4/B04｜判据：UNX-F10468-J1 32–64 号逐投逐递（排队不合并），FIFO 同号序保持，受 F10457 quota 约束超限 EAGAIN｜纯功能行数：300 行（实时队列 120 + FIFO 序 90 + quota 消费 90；测试段不计）｜状态：[已深化]
- **定位**：实时信号与标准信号的分野就一句话：排队不合并。SIGRTMIN=32 到 64 号每投必挂、按序递送——事件型库（epoll 服务器）的可靠事件通道。本条建实时队列：逐投逐递、同号 FIFO、quota 准入。
- **语义边界**：只做 32–64 号队列；标准信号位图（F10442）不动；队列深度受 F10457 判定函数管制。SIGRTMIN 值按 POSIX 无 glibc 扩展口径钉 32（差异声明：glibc 的 NSIG 扩展不引入）。
- **依赖与嫁接源**：消费 F10457 quota 与 F10442 位图（实时位图并存）；嫁接源为 POSIX "real-time signals are queued" 条文，只跟随。
- **风险与回退**：队列与位图双轨的递送顺序（标准与实时同 pending 时谁先）——POSIX 未强制跨族顺序，Varix 钉"实时优先"并落账（差异声明），防实现漂移。
- 正文：实现路径分三步。第一步队列结构：每（进程，信号号）一 FIFO 队列，节点持 siginfo 全量，挂位即入队——同号连投 N 次挂 N 个节点；第二步递送：检查点按号序消费队列，出队即递、递完即摘，FIFO 序断言（同号先投先递）；第三步 quota：入队前过 F10457 判定，超限返 EAGAIN 且账面计数，压测"灌满-消费-再灌"循环零泄漏零错序。与现存内核衔接点：队列与位图并挂进程对象，递送统一出口。与 Linux 对照：`sigqueue` 连发百次全收同源，判据 UNX-F10468-J1 的复测方式：百投百递 3/3 轮、FIFO 序 100%、quota 超限 10/10 次 EAGAIN。
