### UNX-F7261 · 堆叠映射框架（dm 设备作为下层 target）
- 域/批：B5/B04｜判据：UNX-F7261-J1 dm 设备注册为下层 target 后上层 IO 正确穿透（逐扇区校验）；堆叠注册的合法性校验（物理盘不可作上层）全账｜纯功能行数：320 行（堆叠注册协议 120 + 穿透路径 100 + 合法性校验 100；测试段不计）｜状态：[已深化]
- **定位**：堆叠（dm-on-dm）是 B5 域的架构力量之源：LUKS 卷=dm-crypt 挂在 dm-linear 之上、LVM 快照=快照 target 挂在 origin 之上、RAID 卷可直接被 crypt 覆盖。本条把"dm 设备作为下层 target"的注册协议立起来——上层 dm 的成员不再是物理盘而是另一个 dm 设备，IO 穿透（上层请求经映射到下层 dm 再到物理盘）逐扇区正确是堆叠全部价值的验收线。
- **语义边界**：只做堆叠注册与穿透；不做环检测（F7262）、不做堆叠错误归因（F7265）、不做 crypt 语义（J3 判例二）。
- **依赖与嫁接源**：消费 F7203 target 注册表（dm 设备以 target 形态注册）与 F7209 块层注册；嫁接源为 Linux dm 堆叠（table 里 target 参数引用 dm 设备）惯例，只跟随。
- **风险与回退**：穿透路径的完成回调层数混乱（三层回调序号错位）——F7205 完成对应账的"层数"字段随下传递增，完成回溯按层数逐层剥离，层号断言常驻（完成层号=下传层号），错位在账目显形。
- 正文：实现路径分三步。第一步堆叠注册协议：dm 设备注册为下层 target 的形态=新 target 类型 `dm-attached`（注册进 F7203 表），参数串为下层 dm 设备名+偏移，注册时合法性校验——被引用设备必须是 dm 设备且处于 active 态（物理盘不可作堆叠上层 target 的反向校验：dm target 只接受 dm 设备参数），引用建立时下层设备引用计数 +1（F7206 协议）；第二步穿透路径：上层请求换算到下层 dm 设备后经 F7205 正常下传，下层作为独立 dm 完成自己的映射再下传物理盘——穿透=两层各自完整的映射路径串联，无捷径无缓存旁路；第三步合法性账：注册校验的全部拒绝（非 dm 设备/非 active/自引用预备）分档留账，注册成功账含（上层/下层/偏移）三元组。与现存内核衔接点：`dm/stack_reg.rs` 新建，`dm-attached` target 注册走 F7203 标准通道。与 Windows 对照：Windows 存储栈天然多层（卷管理器→分区→磁盘类驱动），层间经设备对象栈穿透，本内核堆叠对齐多层语义并以显式注册协议替代隐式栈叠放。判据 UNX-F7261-J1 的复测方式：两层堆叠 1 万扇区逐扇区校验全过、非法注册（物理盘/非 active）注入各 20 次全拒留账。

### UNX-F7262 · 堆叠深度上限与环检测
- 域/批：B5/B04｜判据：UNX-F7262-J1 环引用（A→B→A）100% 检出拒绝；深度超上限（默认 8 层）拒绝留账｜纯功能行数：260 行（环检测器 100 + 深度闸门 80 + 检测账 80；测试段不计）｜状态：[已深化]
- **定位**：堆叠的自由要配护栏：A 引用 B、B 引用 A 的环引用会让 IO 在两层之间无限循环（栈溢出或活锁），深度失控的堆叠（100 层）会让每次 IO 的延迟与内存开销线性放大。环检测在**注册时**做（建环前拦截），深度上限 8 层（Unxreal 生产拓扑最深层：crypt→linear→raid→物理=4 层，留余量）。
- **语义边界**：只做环检测与深度闸门；不做深度上限的自适应（常量+ADR 变更）、不做环的运行期检测（注册时拦截后运行期不可能成环——成员关系只增不改，reload 换表重新过检测）。
- **依赖与嫁接源**：消费 F7261 注册协议；嫁接源为 Linux dm 环防护惯例与有向无环图（DAG）校验惯例，只跟随。
- **风险与回退**：环检测的并发窗口（两个注册同时进行互相引用）——注册互斥（全局注册锁，注册是低频管理动作锁开销可忽略），检测与引用建立原子完成。
- 正文：实现路径分三步。第一步环检测器：注册时沿"被引用设备→它的成员→成员的成员"遍历，起点出现在路径中即环（A→B→A 检出），遍历深度即堆叠深度，超 8 层拒绝；检测算法为简单 DFS（设备数有限，性能无忧），检测结果与路径留账（环路径打印：A→B→A 看得见）；第二步深度闸门：深度=DFS 最大层数，上限常量集中声明（F7251 同族纪律），超限拒绝账含实际深度与上限值；第三步检测账：环拒绝/深度拒绝分账分列，reload 换表时新表成员关系重跑检测（换表可能引入环），检测失败整表拒绝（F7242 预校验链路）。与现存内核衔接点：`dm/cycle.rs` 新建，检测挂 F7261 注册与 F7242 预校验两处。与 Windows 对照：Windows 文件系统挂载环（subst 循环）与存储栈层叠深度由 PnP 栈深限制，环场景由加载器拒绝。判据 UNX-F7262-J1 的复测方式：环注入（2 环/3 环/自环）各 20 次 100% 检出拒绝、深度 9 层注入拒绝留账、reload 引环拦截 20 轮通过。

### UNX-F7264 · 堆叠请求传播的偏移累积换算
- 域/批：B5/B04｜判据：UNX-F7264-J1 两层偏移叠加换算与手算表一致（含边界）；换算溢出（超 64 位扇区空间）拒绝｜纯功能行数：300 行（累积换算 110 + 边界对拍 90 + 溢出守卫 100；测试段不计）｜状态：[已深化]
- **定位**：堆叠的偏移是**累积**的：上层偏移 + 下层偏移 = 物理落点，两层各算各的（穿透路径天然分层计算）本无溢出风险，但**验证换算正确性**需要把累积结果与手算表对拍；溢出守卫防的是"两层偏移相加超过 u64 扇区空间"的病态表（数学上可能，物理上无意义）——溢出即拒绝，拒绝优于回绕（回绕=写到盘头=数据错乱）。
- **语义边界**：只做换算验证与溢出守卫；不做单层换算（F7205）、不做堆叠注册（F7261）。
- **依赖与嫁接源**：复用 F7205 换算核心；嫁接源为算术溢出检查惯例（Rust checked_add），只跟随。
- **风险与回退**：checked 算术的性能开销（每 IO 一次检查）——checked_add 开销纳秒级（一次进位判断），对比 IO 本身可忽略，安全换性能的选择无需权衡。
- 正文：实现路径分三步。第一步累积换算验证：两层堆叠（linear+linear）的端到端换算=上层逻辑扇区 L → 上层表映射（L+off1 进下层）→ 下层表映射（+off2 到物理）——理论落点=L+off1+off2，手算表穷举边界组合（2000 例含段边界/叠层边界）对拍穿透结果；第二步边界对拍：边界扇区（上层段尾+下层段首的组合）逐扇区对拍，off1+off2 在段边界处的进位行为与手算一致；第三步溢出守卫：两层偏移相加用 checked_add，溢出（理论落点超 u64）注册时即拒绝（F7261 注册校验链新增溢出项）——运行期单请求换算不再需要溢出检查（注册时已保证表内区间不溢出），双层防御。与现存内核衔接点：`dm/stack_math.rs` 新建，对拍工具挂 F7280 断言族。与 Windows 对照：Windows 卷管理器多层偏移换算（跨区卷+分区偏移叠加）同构，溢出场景在卷大小上限（GPT 64bit 扇区）内由格式约束排除。判据 UNX-F7264-J1 的复测方式：手算表 2000 例对拍全过、边界扇区逐扇区一致、溢出表注入注册时 20/20 拒绝。

### UNX-F7265 · 堆叠错误归因（哪一层失败）
- 域/批：B5/B04｜判据：UNX-F7265-J1 注入各层错误 10/10 次归因正确（错误事件标注失败层与失败 target）；归因不改变错误语义｜纯功能行数：280 行（归因协议 100 + 层标注传递 90 + 注入验证 90；测试段不计）｜状态：[已深化]
- **定位**：三层堆叠报错时"哪一层坏了"直接决定运维动作：物理层坏=换盘、linear 层坏=表错了、crypt 层坏=密钥或算法问题。归因协议=错误事件携带失败层标注（层号+target 类型+设备名），标注随错误上抛逐层附加（不覆盖底层已标信息）。归因不改语义（F7215 协议）——归因是附加信息，错误码本体原样透传。
- **语义边界**：只做归因标注协议；不做错误码语义（F7215）、不做归因驱动的自动处置（F7274 降级行为另立）、不做诊断报告生成（F7259 同族复用）。
- **依赖与嫁接源**：消费 F7215 错误传播与 F7261 层数标记；嫁接源为 Windows 过滤驱动栈错误归因（IoStatus 附驱动对象）思想，只跟随。
- **风险与回退**：归因标注的内存开销（每层错误附一段标注）——标注为定长小结构（层号 u8+target 枚举+设备 ID 索引，16 字节），错误路径低频，开销无忧。
- 正文：实现路径分三步。第一步归因协议：错误发生层在自己的错误事件附首段标注，上抛路径各层**追加**自己的标注（不覆盖）——最终上层看到的错误携带完整层链（物理层→linear 层→crypt 层各段标注），链上第一段=失败源头层；第二步层标注传递：标注结构随完成回调上溯（F7222 聚合协议扩展），子请求错误聚合到父请求时层链合并（取首个失败的层链）；第三步注入验证：ktest 在三层各设错误注入点（各层可独立注入 EIO），每层注入 10 轮断言归因层链首段=注入层、错误码语义不变（透传断言）。与现存内核衔接点：`dm/stack_attr.rs` 新建，标注结构并入 F7215 错误来源账。与 Windows 对照：Windows 存储栈错误事件的栈轨迹（Which driver failed）同构，Event Log 的存储错误带失败组件。判据 UNX-F7265-J1 的复测方式：三层注入各 10/10 归因正确、层链完整性验证、错误码透传断言（归因前后语义一致）。

### UNX-F7266 · 堆叠 flush 屏障传播
- 域/批：B5/B04｜判据：UNX-F7266-J1（保护判据先行）顶层 flush 传播至全部下层成员并全确认后返回（漏层即断言红）；屏障顺序跨层保持｜纯功能行数：300 行（跨层 flush 协议 110 + 传播断言 100 + 顺序保持 90；测试段不计）｜状态：[已深化]
- **定位**：堆叠下的 flush 语义是红线级：顶层 flush 必须**传播到全部下层成员直到物理盘**——漏一层=该层缓存的写没落盘=断电丢数据的位置精确确定。三层堆叠的顶层 flush→中层 flush→底层 flush→物理盘 flush，全链确认后才返回。屏障顺序跨层保持：顶层屏障前的写在所有层都先于屏障后的写落盘。
- **语义边界**：只做跨层 flush 传播与屏障顺序；不做单层 flush 转发（F7235）、不做物理 flush 执行（B4 判例一）、不做跨层 flush 优化合并（禁——每层独立确认才可信）。
- **依赖与嫁接源**：复用 F7235 flush 转发协议（堆叠递归化）；嫁接源为 Linux dm 堆叠 flush 传播（flush 递归到最底层盘）语义，只跟随。
- **风险与回退**：递归 flush 的层间死锁（下层 flush 等待上层释放队列锁）——flush 传播路径零持锁设计（每层 flush 转发独立提交），传播为纯递归 IO 无共享锁，死锁结构性排除。
