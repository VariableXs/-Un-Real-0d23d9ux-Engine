### UNX-F9001 · rt_sigaction 语义档
- 域/批：C2/B11｜判据：UNX-F9001-J1 sigaction 结构布局（handler/mask/flags）ABI 冻结判据过，旧 action 读回判据过，SA_* 五旗标（RESTART/NOCLDSTOP/NODEFER/ONSTACK/SIGINFO）逐位判据过｜纯功能行数：260 行（结构布局冻结器 90 + 旧值读回通道 80 + 五旗标逐位矩阵 90）｜状态：[已深化]

- **定位**：本条是 B11 信号挂点族的头号语义档，为 `rt_sigaction` 号立三件套语义：sigaction 结构在用户/内核两侧的字段布局、旧处置（oldact）读回通道、SA_ 五旗标逐位语义。所有后续信号条目（F9003 投递、F9005 返回、F9013 重启）都以本条冻结的布局为引用基准，是信号面其余 19 条的锚点。
- **语义边界**：只管 sigaction 号本身的语义档与结构 ABI；handler 真正执行时的栈帧布局归 F9005，掩码三操作归 F9002，投递路由归 F9003。SA_RESTART 的 EINTR 联动语义归 F9013 单点，本条只登记旗标位存在性与置位校验，不做判定逻辑。
- **依赖与嫁接源**：嫁接 Linux man-pages sigaction(2) 章节的结构定义与 SA_ 旗标表；锚定现存 `syscall::calls` 分发表中 F9001 号槽位与 `SyscallDesc` 描述符、`syscall::guard` 的 CAP_KILL 门校验、`copy_from_user`/`copy_to_user` 做 oldact/newact 双向搬运；`Errno::EINVAL` 格由 F8923 编码器单点产出。
- **风险与回退**：风险一为结构布局与 glibc 期望不一致导致 oldact 读回乱码——回退为对照 SysV ABI 逐字段偏移表自检，差异格以冻结单登记；风险二为五旗标语义越界（本条做了判定逻辑挤占 F9013 单点）——回退为本条只做置位合法性校验，越位旗标清零登记。
- **正文**：实现路径分三步：第一步在 `syscall::calls` 下新建 sigaction 语义模块，定义内核侧 `SigAction { handler: SignalHandler, mask: SigSet, flags: SaFlags, restorer: usize }` 四字段，按 x86-64 SysV ABI 冻结用户态布局偏移（handler@0/restorer@8/mask@16/flags@128），并用编译期 `const` 断言锁定尺寸；第二步实现 oldact 读回通道——调用方传非空 oldact 指针时，先经 `copy_to_user` 把旧处置原样写回，再以 `copy_from_user` 装入新处置，顺序保证半途 EFAULT 时语义等同"未变更"；第三步铺 SA_ 五旗标逐位矩阵：SA_NOCLDSTOP/SA_NODEFER 的具体消费语义不在本条展开、SA_RESTART 交给 F9013，本条矩阵覆盖五位的"置位/清零/保留位拒绝"三态共 15 格，保留位非零返 EINVAL。与现存内核衔接点：挂在 `route_incoming` 分发后的 C2 段调用门，入参经 F8920 access_ok 预检，错误路径统一走 F8923 编码器；oldact 读回复用 `UserRegion` 边界检查。与 Windows 对照：Windows 以 `SetUnhandledExceptionFilter` 与 SEH 链承载类似语义，无逐号 handler 表；Varix 取 Linux 逐号语义因 glibc 消费面（B14 F9073）以 sigaction 为单源。判据 UNX-F9001-J1 的复测方式：ktest 三断言——(1) 布局冻结：sizeof/offset 逐字段对照常量表零差；(2) 旧值读回：注册 handler A→读回得 A→注册 B→读回得 B；(3) 五旗标 15 格矩阵批跑全过，保留位格期望码为 -22。

### UNX-F9002 · rt_sigprocmask 掩码语义
- 域/批：C2/B11｜判据：UNX-F9002-J1 SIG_BLOCK/UNBLOCK/SETMASK 三操作判据过，旧掩码读回判据过，SIGKILL/SIGSTOP 掩蔽请求被忽略判据过｜纯功能行数：240 行（三操作执行器 100 + 旧掩码读回 70 + KILL/STOP 忽略格 70）｜状态：[已深化]

- **定位**：本条立信号掩码（blocked set）的三操作语义档：SIG_BLOCK 求并、SIG_UNBLOCK 求差、SIG_SETMASK 整体替换，外加旧掩码读回与两个不可掩蔽号的忽略格。掩码是投递（F9003）与挂起（F9011）的分流依据，本条冻结"掩码运算在哪、怎么算、什么不可挡"三问。
- **语义边界**：只管掩码运算与读回；pending 集的读取归 F9011，掩码在信号 handler 进入/退出时的自动保存恢复归 F9005 栈帧协议，掩码原子切换防丢信号的多路复用协议归 F9018。本条不触碰 per-thread 掩码与线程组掩码的共享关系（归 F9012）。
- **依赖与嫁接源**：嫁接 sigprocmask(2) 三 how 常量语义；锚定 F9001 的 `SigSet` 类型（同源复用，不另立类型）、`copy_from_user` 装入请求掩码、`copy_to_user` 读回旧掩码；KILL/STOP 忽略格对照 signal(7) "SIGKILL/SIGSTOP cannot be blocked" 原文；错误格经 F8923 编码器单点。
- **风险与回退**：风险一为三操作作用域越界——glibc 语义为 per-thread 掩码，若误做线程组广播将污染他线程；回退为作用域显式限定"当前线程"，组共享语义留 F9012 扩容格。风险二为 KILL/STOP 被意外掩蔽导致进程不可杀——回退为执行器尾端硬过滤，两号在并集后强制清位，ktest 以"掩蔽请求后 kill 仍可达"复测。
- **正文**：实现路径分三步：第一步定义掩码运算器——`SigSet` 以 64 位双字承载 64 号，SIG_BLOCK 做按位或、SIG_UNBLOCK 做与反、SIG_SETMASK 直接装载，三种操作均为单次原子写，避免拆写窗口；第二步实现旧掩码读回通道——先读旧值存局部、再运算落新值、最后 `copy_to_user` 写回旧值，若写回失败则掩码回滚，保证操作可逆；第三步铺 KILL/STOP 忽略格：结果掩码在落盘前强制执行 `set &= !((1<<9)|(1<<19))`，并在 meter 计数器记一次"掩蔽被拒"事件供 F9020 断言读取。与现存内核衔接点：掩码本体存于线程控制块的 `blocked` 字段（C1 域对象），本条只提供运算入口 `sigprocmask_impl(how, set, oldset)`；与 F9001 共用 `SigSet` 类型防类型漂移；错误路径（how 非法值、set 指针 EFAULT）走 F8923 编码器。与 Windows 对照：Windows 无 per-thread 可编程信号掩码，SuspendThread/ResumeThread 是粗粒度挂起；Varix 的掩码+pending 两集模型严格对齐 POSIX，是 glibc pthread_cancel/条件变量中断语义的必要底座。判据 UNX-F9002-J1 的复测方式：ktest 五断言——BLOCK 后 pending 不投递、UNBLOCK 后立即投递、SETMASK 整体替换读回一致、旧掩码读回通道往返零差、掩蔽 KILL 请求后 kill 自投递仍送达。

### UNX-F9003 · kill/tgkill/tkill 投递
- 域/批：C2/B11｜判据：UNX-F9003-J1 三投递号目标解析（pid/tgid/tid）判据过，信号 0 探活语义判据过，跨进程投递权限 EPERM 格过｜纯功能行数：220 行（三号目标解析器 90 + 信号 0 探活格 60 + 权限门 70）｜状态：[已深化]

- **定位**：本条立信号投递三入口的号面语义档：kill（按 pid 投递，命中整个线程组）、tgkill（按 tgid+tid 定向单线程）、tkill（仅按 tid，遗留号）。三条共用同一个投递引擎，本条冻结"目标怎么解析、信号 0 为什么合法、跨进程凭什么拒"三件事。
- **语义边界**：只管投递入口的目标解析与权限门；投递后进入 pending 还是直接送达、排队与否归 F9008，KILL 号的组播 exit_group 联动归 F9009，pidfd 化投递归 F9004 挂点。signalfd 消费端在 B10 F8989，本条不重复。
- **依赖与嫁接源**：嫁接 kill(2)/tgkill(2) man-pages 目标解析规则；锚定 C1 域进程对象表（pid→线程组映射、tgid→主线程）、`syscall::guard` CAP_KILL 门、`Errno::ESRCH`（目标不存在）与 `Errno::EPERM`（无权投递）双格经 F8923 编码器；信号 0 探活语义嫁接 signal(7) "if sig is 0, then no signal is sent, but error checking is still performed" 原文。
- **风险与回退**：风险一为 tkill/tgkill 混淆——tkill 在多线程组下语义不足，Linux 自身已建议弃用；回退为 tkill 实现为 tgkill(当前tgid, tid) 转接并登记 RouteNote::Permuted。风险二为信号 0 被误当错误——回退为引擎入口特判 sig==0：只跑目标解析与权限检查，不落 pending，返回 0。
- **正文**：实现路径分三步：第一步立目标解析器三路——kill(pid) 经 C1 进程表查 tgid 组、tgkill(tgid,tid) 双键校验 tid 确属该组、tkill(tid) 单键查线程再回填其组；三路产出一个统一的 `DeliveryTarget`（组播或单线程定向），解析失败返 ESRCH；第二步铺信号 0 探活格：sig==0 时跳过入队，只执行解析与权限两阶段，成功返 0、失败返 ESRCH/EPERM，这正是 ps/killall 类工具的探活命门；第三步立权限门：发起者 euid 与目标 real/saved uid 匹配或持 CAP_KILL 方放行，否则 EPERM；root 恒过。与现存内核衔接点：投递引擎尾端调 F9008 的入队函数（标准号合并、实时号排队），KILL/STOP 特号走 F9009 特判链；`syscall::meter` 记 delivery 计数；三号共用同一引擎实现单源防漂移。与 Windows 对照：Windows 无跨进程信号，TerminateProcess 是唯一硬手段且不可被目标协作处理；Varix 的 kill 语义保留"目标可捕获可清理"的协作面，是 glibc system()/shell 作业控制的底座。判据 UNX-F9003-J1 的复测方式：ktest 六断言——kill 组播命中组内任一线程的 handler、tgkill 定向命中指定 tid、tkill 转接一致性、sig==0 对存在 pid 返 0 对不存在 pid 返 -3、跨进程非特权投递返 -1、meter 计数与投递次数对账。

### UNX-F9004 · raise/pidfd_send_signal 挂点
- 域/批：C2/B11｜判据：UNX-F9004-J1 raise 自投递判据过，pidfd 号面挂点注册判据过（fd 化投递本体档待 M 型后续批次落），未实现路径返 -ENOSYS 判据过｜纯功能行数：200 行（raise 转接器 80 + pidfd 挂点登记 60 + ENOSYS 收口 60）｜状态：[已深化]

- **定位**：本条立两个投递侧号的挂点档：raise（向自身线程组投递）与 pidfd_send_signal（按 pidfd 投递）。raise 是 F9003 引擎的自投递转接；pidfd_send_signal 本会话只立号面挂点与 -ENOSYS 收口，fd 化进程句柄本体待 M 型后续批次，挂点先行占位防号面漂移。
- **语义边界**：raise 只做转接不做新语义（语义全在 F9003）；pidfd_send_signal 只做挂点注册、参数形状登记与 ENOSYS 收口，不实现 pidfd 的获取（getfdv P_PIDFD 属 waitid 族扩容，非本会话认领段）。fd 化本体与 pidfd 打开/轮询协议归后续 M 型批次，本条声明不重铺。
- **依赖与嫁接源**：raise 嫁接 raise(3) glibc 语义（等价 tgkill(gettid 组, 自 tid)）；锚定 F9003 `DeliveryTarget` 引擎、F9001 handler 表；pidfd_send_signal 嫁接 pidfd_send_signal(2) 参数形状（pidfd/sig/info），挂点登记入 `SYSCALLS` 表并挂 `NrVerdict::NotYet`；ENOSYS 编码经 F8923 单点。
- **风险与回退**：风险一为 raise 转接错线程——POSIX 要求 raise 等价 kill 到自身进程组，glibc 内部走 tgkill；回退为 raise 固定转 tgkill(自 tgid, 0 组播位) 并以"同组 handler 命中一次"复测。风险二为 pidfd 挂点被误当已实现——回退为挂点档显式 `NrVerdict::NotYet` 且 COMPAT_TABLE 登 RouteNote，ktest 断言该号恒返 -38。
- **正文**：实现路径分三步：第一步立 raise 转接器——`raise_impl(sig)` 内部构造 `DeliveryTarget::Group(self_tgid)` 后直调 F9003 引擎，signal 0 同样探活，成功返 0；它与 F9003 的关系是"薄壳调厚核"，杜绝第二套投递逻辑；第二步立 pidfd_send_signal 挂点——号面登记三参数形状与 EBADF/EINVAL 期望码表，`SYSCALLS` 表置 `NrVerdict::NotYet`，入口统一收口返 -ENOSYS，为后续 fd 化批次预留零改动接位；第三步铺 ktest 双断言：raise 后 handler 命中计数 +1 且掩码按 F9002 规则生效；pidfd_send_signal 恒返 -ENOSYS 且 RouteNote 登记"本体档待 M 型批次"。与现存内核衔接点：raise 转接器与 F9003 共用 `syscall::calls::dispatch` 分发表槽位；pidfd 挂点与 F8928 COMPAT 扩容机制对齐，`AbiInfo` 标注 5.1+ 引入版本供 F8921 协商器读取。与 Windows 对照：raise 对应 Windows 无原生等价（内部 RaiseException 语义不同类）；pidfd 是 Linux 独有的防 pid 复用竞态设计，Windows 无对应物，Varix 登记挂点是为未来用户态（B6 域）回收工具链铺路。判据 UNX-F9004-J1 的复测方式：ktest 三断言——raise 自投递命中、raise(sig==0) 探活返 0、pidfd_send_signal 参数非法与合法两路均返 -38 且 RouteNote::NotYet 登记在册。

### UNX-F9005 · sigreturn 返回路径（信号栈帧 ABI）
- 域/批：C2/B11｜判据：UNX-F9005-J1 rt_sigframe 布局（uc_flags/uc_link/uc_mcontext/uc_sigmask）对照 SysV ABI 冻结判据过，寄存器组（含 r10 槽位）恢复零差判据过，坏栈帧返 EFAULT 判据格｜纯功能行数：260 行（栈帧布局冻结器 100 + 寄存器恢复器 100 + 坏帧 EFAULT 格 60）｜状态：[已深化]

- **定位**：本条立信号 handler 执行完毕后的返回路径语义档：rt_sigreturn 号消费内核投递时压入用户栈的 rt_sigframe，恢复中断现场。栈帧布局是 ABI 命门——glibc 的 restore 垫片按固定偏移取数，任何字段错位都是用户态崩溃。本条冻结布局与寄存器组恢复零差两件事。
- **语义边界**：只管返回路径与栈帧恢复；handler 进入时的帧构造与 trampoline 搬运是投递侧（F9003 尾端）职责，SA_ONSTACK 换栈归 F9010，r10 第 4 参槽位约定的通用 ABI 归 F8802（本条只在恢复面引用同一约定）。
- **依赖与嫁接源**：嫁接 x86-64 SysV ABI 的 rt_sigframe 标准布局与 ucontext_t 定义（uc_flags@0/uc_link@8/uc_mcontext@40/uc_sigmask@176 一类偏移表）；锚定 `TrapFrame` 结构（A1 域现场对象）做全寄存器组（GP×15+rflags+rip+rsp）零差恢复；r10 槽位与 F8802 提取器同源对照；坏帧检测复用 `copy_from_user` 边界检查与 F8923 EFAULT 格。
- **风险与回退**：风险一为栈帧偏移与 glibc restore 垫片不齐——垫片硬编码偏移，错位即段错误；回退为布局冻结单登记每字段偏移，ktest 以"glibc 垫片字节码反汇编逐字段对照"复测。风险二为恢复器漏恢复 r10/r11 等 SysV 易忘位——回退为恢复器按 17 位清单逐位打勾，缺位即编译期断言失败。
- **正文**：实现路径分三步：第一步冻结栈帧布局——内核侧 `RtSigFrame { pretcode: [u8;8], uc: UContext, fpstate: usize, siginfo: SigInfo }`，UContext 内 uc_flags/uc_link/uc_mcontext（=TrapFrame 17 位镜像）/uc_sigmask 四件按 glibc bits/ucontext.h 偏移冻结，编译期断言 sizeof；第二步实现恢复器——sigreturn 入口从当前 rsp 取 frame 指针，`copy_from_user` 整帧读入后，把 uc_mcontext 逐位写回 `TrapFrame`（GP、rip、rsp、rflags、fs_base/gs_base 全 17 位），掩码按 F9002 规则装载回 blocked，随后调度器恢复被中断线程；第三步铺坏帧格：帧指针非用户态可读、magic/pretcode 校验失败任一命中即返 EFAULT，进程按 SIGSEGV 默认处置走 F9006 表，绝不让坏帧静默通过。与现存内核衔接点：恢复器尾端直接复用 A1 域的上下文切换原语；投递侧（F9003）构帧与本恢复器共享同一 `RtSigFrame` 类型定义实现"构帧-解帧"同源；掩码恢复复用 F9002 运算器。与 Windows 对照：Windows 信号等价物（CRT signal/SEH）由运行时自己保存现场，内核不参与栈帧 ABI；Varix 按 Linux 惯例内核构帧，保证 glibc 无感知兼容。判据 UNX-F9005-J1 的复测方式：ktest 三断言——(1) 构帧后立即 sigreturn 恒等往返，TrapFrame 17 位逐位零差；(2) r10 携带非常量值穿越 handler 后保真（专测第 4 参槽位）；(3) 栈底坏帧返 EFAULT 且进程收 SIGSEGV 默认处置。

### UNX-F9006 · 默认处置表（SIG_DFL/SIG_IGN/SIG_ERR 全集）
- 域/批：C2/B11｜判据：UNX-F9006-J1 1–31 号默认处置（Term/Ign/Core/Stop）逐号对照 signal(7) 表判据过，处置切换生效时点判据过｜纯功能行数：220 行（默认表常量集 110 + 处置类型判别器 60 + 切换生效时点格 50）｜状态：[已深化]

- **定位**：本条立 1–31 号标准信号默认处置常量表：每号四类之一（Term 终止/Ign 忽略/Core 终止转储/Stop 暂停），逐号对照 signal(7) 标准表。handler 未注册或显式 SIG_DFL 时走此表；本条同时冻结处置切换的生效时点语义。SIG_ERR 是 glibc 侧哨兵值（返回值），登记在档用于 F9073 消费核对。

### UNX-F9008 · 信号队列与排队语义（rt 信号排队）
- 域/批：C2/B11｜判据：UNX-F9008-J1 实时信号多次投递多次送达判据过，队列上限 RLIMIT_SIGPENDING 触达 EAGAIN 格过，标准信号合并投递判据过｜纯功能行数：220 行（双类队列引擎 100 + RLIMIT 上限格 70 + 合并语义格 50）｜状态：[已深化]

- **语义边界**：只管入队/出队/上限；投递目标解析归 F9003、出队后的处置执行（查 F9006 表或调 handler 构帧）在引擎尾端但构帧本体归 F9005 协议、signalfd 消费出队归 B10 F8989（引擎提供 `dequeue_for_fd` 接口单点）。si_value 携带字段本会话登记不实现。

- **风险与回退**：风险一为 RT 队列无上限被恶意投递打爆内存——回退为两级上限（任务级 rlimit + 全局水位）双闸，全局水位触达同样 EAGAIN 且 meter 记溢出事件；风险二为合并语义误伤 RT 号——回退为分流按登记簿字段单源判断，ktest 以同号连投断言两分档行为。

### UNX-F9009 · SIGKILL/SIGSTOP 不可捕获单点
- 域/批：C2/B11｜判据：UNX-F9009-J1 捕获/掩蔽/忽略三路径对 KILL/STOP 均无效判据过，KILL 组播 exit_group 联动判据过｜纯功能行数：180 行（三路径拦截器 90 + 组播 exit 链 90）｜状态：[已深化]

- **定位**：本条立两个不可抵抗号的单点强制档：SIGKILL（9）与 SIGSTOP（19）无论 handler 如何注册、掩码如何设置、SIG_IGN 如何置位，处置一律按默认表强制执行。这是进程管理工具（kill -9）的语义根基，也是 F9002 掩码过滤与 F9006 表引用的强制收口。
- **语义边界**：只管 KILL/STOP 两号的强制路径；SIGCONT 恢复语义随 Stop 系处置联动（表内登记），Term 类的退出状态字与 exit_group 组播在 KILL 格内实现，其余号的默认处置执行归 F9006 判别器。特权投递权限门归 F9003（root 才能杀他进程组）。
- **依赖与嫁接源**：嫁接 signal(7) "SIGKILL and SIGSTOP are special signals which cannot be caught, blocked, or ignored" 原文；锚定 F9006 默认表、C1 域 exit_group 组播原语、`ExitStatus` 状态字（KILL 置 signal 位）、F9002 掩码运算器的硬过滤钩子。
- **风险与回退**：风险一为 handler 注册表未拦 KILL（用户注册 handler(9) 成功后投递时仍进 handler）——回退为两道闸：注册时 F9001 拒绝（EINVAL）+投递时本条强制走默认，双闸防"注册漏拦"；风险二为组播 exit 与 wait 竞态——回退为 exit_group 先置 zombie 态再唤醒 wait 端（C1 收尸协议）。
- **正文**：实现路径分三步：第一步立三路径拦截——引擎处置决策点前置特判：sig==9 或 sig==19 时无视 handler/mask/dispo 三路，直取默认表 Term（KILL）/Stop（STOP）类执行；ktest 分别以"注册 handler 后投 KILL 进程仍退出""掩蔽 KILL 后投递仍送达""SIG_IGN 后投 STOP 仍停等"三格验证；第二步立组播 exit 链——KILL 送达时调 C1 exit_group 原语，全组线程逐一置 ExitStatus::Signaled(9)，wait 端（F8868）读回状态字 signal 位=9；第三步铺 STOP 联动——STOP 送达置任务停等态并从调度就绪摘除，SIGCONT 送达（F9003 投递）置回就绪，两态转换经 A3 调度器原语，绝不自行改队列。与现存内核衔接点：本条挂在 F9003 引擎与 F9008 出队单点之间的处置决策位；掩码硬过滤复用 F9002 尾端钩子；C1 僵尸告警（B04 深化档）与本条 exit 链联动监控。与 Windows 对照：TerminateProcess 不可被目标拦截与 Varix KILL 语义同神，但 Windows 无 STOP/CONT 挂起恢复对（DebugBreak 需调试器），Varix 的 Stop 系是 shell 作业控制（Ctrl+Z）的内核底座。判据 UNX-F9009-J1 的复测方式：ktest 四断言——KILL 三路抵抗全无效、KILL 后 wait 读回信号位 9、STOP 后任务停等且 SIGCONT 后恢复运行、组播 exit 触发全组线程状态字一致。

### UNX-F9010 · sigaltstack 与 SA_ONSTACK
- 域/批：C2/B11｜判据：UNX-F9010-J1 备用栈注册与切换判据过，栈溢出防护（stack_t 尺寸校验）判据过，禁用后 ONSTACK 忽略判据过｜纯功能行数：200 行（备用栈注册器 80 + 切换恢复器 70 + 尺寸校验格 50）｜状态：[已深化]

- **定位**：本条立信号备用栈语义档：sigaltstack 注册一块用户栈空间，投递时若 handler 带 SA_ONSTACK 旗标则切到备用栈执行，返回时恢复。核心场景是 SIGSEGV 级栈溢出——原栈已不可用，必须在备用栈上运行 handler 才有自救机会。这是 SSA (stack-protector 之外的) 健壮性底座。
- **语义边界**：只管备用栈的注册/查询/切换；handler 执行栈帧本体归 F9005、SIGSEGV 投递源（缺页路径→信号转换）归 A4 缺页回调（F9095 跨域协议登记），备用栈上的 SEGV 不再换栈（Linux 语义：已在 altstack 上则忽略 ONSTACK）。
- **依赖与嫁接源**：嫁接 sigaltstack(2) 与 SA_ONSTACK 旗标语义（sigaltstack man-pages "notes" 节）；锚定 F9001 `SigAction.flags` 的 ONSTACK 位、F9003 构帧点的栈选择逻辑、`stack_t { ss_sp, ss_flags, ss_size }` 结构与 `copy_from_user` 装载；禁用（SS_DISABLE）态登记。
- **风险与回退**：风险一为备用栈尺寸过小导致 handler 执行中再溢出——回退为注册时校验 ss_size ≥ MINSIGSTKSZ（对照 Linux 2048 字节体例），低于返 ENOMEM；风险二为嵌套信号换栈递归——回退为"已在 altstack 执行中"状态位，置位时投递忽略 ONSTACK 走原栈或直接挂起。
- **正文**：实现路径分三步：第一步立注册器——`sigaltstack_impl(new, old)` 接受 stack_t，校验 ss_flags 仅 SS_DISABLE/SS_ONSTACK 两合法值、ss_size 下限，通过后存入线程控制块 `altstack` 槽位；old 非空时 `copy_to_user` 读回当前态（含 SS_ONSTACK 运行中标记）；第二步立切换器——F9003 构帧点查 handler 旗标：ONSTACK 置位且 altstack 非禁用则构帧用 altstack 栈顶（向下生长方向预留），sigreturn 恢复时判定"本次执行用了 altstack"则切回原 rsp（该原 rsp 已存于帧内）；第三步铺防护格：尺寸校验返格（ENOMEM）、SS_DISABLE 注册生效后 ONSTACK 投递忽略（走原栈）、嵌套防护状态位三格断言。与现存内核衔接点：切换器挂在 F9003 构帧单点与 F9005 恢复单点之间，是两单点的共用小协议；SS_ONSTACK 运行标记与 F9011 查询联动。与 Windows 对照：Windows 无信号备用栈，SEH 链展开在原栈；Varix 备用栈是 Rust panic runtime（用户态）与 glibc 崩溃处理器的自救前提。判据 UNX-F9010-J1 的复测方式：ktest 四断言——注册后查询读回一致、ONSTACK handler 执行时 rsp 落于 altstack 区间、sigreturn 后 rsp 复原、ss_size 过小返 -12 且 SS_DISABLE 后 ONSTACK 走原栈。

### UNX-F9011 · sigpending/sigtimedwait/sigwaitinfo
- 域/批：C2/B11｜判据：UNX-F9011-J1 pending 集读回判据过，同步等待未决信号三号（timedwait 超时 EAGAIN 格）判据过｜纯功能行数：200 行（pending 读回器 70 + 同步等待三号 90 + 超时格 40）｜状态：[已深化]

- **定位**：本条立信号同步消费三号语义档：sigpending（读 pending 集）、sigwaitinfo/sigtimedwait（同步等待指定信号并同步出队）。同步等待把"异步 handler 回调"翻转为"同步取信号"，是纯轮询消费（如事件循环内嵌信号处理）的 POSIX 正路，也是 F9008 出队单点的第三个消费者。
- **语义边界**：只管 pending 读回与同步等待；异步消费（handler 回调）归 F9003/F9005 链、signalfd 消费归 B10 F8989（与 sigwaitinfo 语义同族但接口不同，本条与之共享出队单点防双读）、等待期间掩码自动替换语义（等待集临时 unblock）在本条内实现并登记。

### UNX-F9016 · alarm 兼容挂点
- 域/批：C2/B11｜判据：UNX-F9016-J1 alarm 返回剩余秒判据过，seconds=0 取消语义判据过，与 setitimer(ITIMER_REAL) 互斥语义判据过｜纯功能行数：180 行（alarm 转接器 100 + 取消格 40 + 互斥格 40）｜状态：[已深化]

- **语义边界**：只管 alarm 转接；REAL 槽位本体全在 F9015、到期投递走 F9014、本条无独立数据结构（这是防重关键——不立第二张定时器表）。秒粒度截断语义（value 向上取整到秒）登记在档。

### UNX-F9018 · 信号与多路复用竞态防护（signalfd/ppoll 联动档）
