### UNX-F6401 · BlockDevice trait 升级接管声明与 bio 面抽象基座
- 域/批：B4/B01｜判据：UNX-F6401-J1 接管三字段（接管对象=blk.rs BlockDevice trait 全部调用点；新增语义=bio 向量提交面；退役范围=旧单缓冲读写接口降级为兼容薄层）登记入台账并经 AI-84 复核留痕；旧接口兼容薄层回归全过｜纯功能行数：360 行（接管三字段登记与台账结构 110 + bio 面抽象基座类型定义 140 + 兼容薄层适配器 110；测试段不计）｜状态：[已深化]
- **定位**：块层地基的第一钉子。本条把现存 BlockDevice trait 的"单缓冲读写直通"语义显式升级为 bio 向量提交面，并以三字段口径把接管边界钉进台账——这是 UNX-B4 全域"升级不重复、新增不越界"总纪律的开山条目；同时立起 bio 面公共类型基座（操作/标志/状态三类定义点），后续 19 条与 B02 起的全部批次的公共类型均从此处引用。
- **语义边界**：只做接管声明登记、公共类型基座与兼容薄层；不做 bio 结构体本体（F6402 防重）、不做提交入口路由（F6404 防重）、不改动 nvme.rs/ahci.rs/m700blk.rs 三个现存实现的内部代码。
- **依赖与嫁接源**：依赖现存 `drivers/blk.rs`（290 行）与其三个实现方（nvme.rs/ahci.rs/m700blk.rs）的调用点清单；嫁接源为 Windows storport 面从旧块请求到统一存储请求块的演进语义与 Linux block layer 的 bio 概念坐标，只跟随。
- **风险与回退**：兼容薄层语义漂移——旧调用方在升级后拿到与历史不同的行为即违约。硬判据"旧语义逐字节等价"兜底：薄层内部转 bio 提交，回归不过不许收口；AI-84 复核若判非重复口径不成立，本条回炉重写声明。
- 正文：实现路径分三步。第一步接管三字段登记：接管对象=blk.rs BlockDevice trait 的全部调用点与三实现方调用面；新增语义=bio 向量提交面（scatter-gather 段数组 IO，替代单缓冲）；退役范围=旧 read_block/write_block 单缓冲接口降级为兼容薄层——签名不变、内部转 bio、保留不删除，登记表入台账并触发 AI-84 非重复复核留痕。第二步抽象基座：BioOp（读/写/flush/reqop 四枚举）、BioFlags（位标志集）、BioStatus（成功/错误二态回传域）三类型与段描述原语先行定义，全部常量命名化零魔法数，类型间互斥可判定性在本层以类型系统钉死。第三步兼容薄层：旧接口在 blk.rs 内构造等价单段 bio 提交，结果翻译回旧返回码；m700blk 模拟设备上 10^4 次旧调用回归，写入内容回读逐字节比对恒等才放行收口。与现存内核衔接点：blk.rs 内部重构、三个实现方零改动，调用方（现存的测试与引导代码）零感知。与 Windows 对照：Windows 存储栈同样经历"类驱动旧请求→storport 统一 SRB"的接管式演进且旧路径以兼容垫片保留（微软 WDK 迁移文档明示该口径），本内核把同等纪律以三字段台账制度化，判据 UNX-F6401-J1 的复测方式：台账三字段查询接口返回完整、AI-84 复核留痕可检索、薄层回归 10^4 次逐字节等价报告落账。

### UNX-F6402 · Bio 结构体与向量段数组
- 域/批：B4/B01｜判据：UNX-F6402-J1 bio 携带 1–32 个向量段构造/遍历/回收零泄漏（10^5 次构造回收对账恒等）；段合计长度与数据总量一致断言｜纯功能行数：380 行（Bio 结构体与段数组 150 + 构造器与段装载 120 + 回收对账钩子 110；测试段不计）｜状态：[已深化]
- **定位**：bio 是块层的"一票 IO 请求"本体：目标 LBA、操作类型、一到三十二个（地址，长度）向量段。向量段（scatter-gather）是多队列性能的前提——让一次提交覆盖物理不连续的多个缓冲，合并器与 PRP 多页扩展（F6592）都吃这个红利。本条立结构、构造器与回收对账三件套，是 B01 批被引用最多的类型条目。
- **语义边界**：只做 bio 结构与段数组本体；不做提交路径（F6404 防重）、不做合并语义（B02 防重）、不负责段内存的分配策略（F6408 池防重，本条只持有引用）。
- **依赖与嫁接源**：依赖 F6401 基座类型与 F6408 bio 池（回收路径对账）；嫁接源为 Linux bio 的 bi_io_vec 语义与 Windows MDL（Memory Descriptor List）链描述散列缓冲的语义坐标，只跟随。
- **风险与回退**：段长度合计与实际数据量漂移（构造器入参错漏）——构造器内部强制"合计校验"门槛，不一致即拒绝构造并红账定位；上限 32 段溢出交给 F6405 拆分器，本条不做静默截断。
- 正文：实现路径分三步。第一步结构定义：Bio 含 lba（u64 扇区寻址）、op/flags（F6403 编码）、段数组（固定容量 32 的 VecSlot 布局，段=物理地址+长度+偏移三元组）、status 回传域与完成回调槽；全部字段注释化语义，段数组容量常量命名暴露。第二步构造器：从（缓冲地址列表，长度列表）装载段，逐段校验长度非零与合计一致性，合计不符即构造失败返回明确错误而非吞掉；构造成功即挂入引用计数域（F6407 接管计数语义）。第三步回收对账：回收路径清零段数组并递减对账账本，账本以"构造计数−回收计数=在途计数"恒等式自检，10^5 次构造回收对账恒等才收口；泄漏候选（回收超期）计数显式暴露给 F6407 泄漏检测。与现存内核衔接点：现存单缓冲调用经 F6401 薄层转"1 段 bio"，旧路径数据面零改动；m700blk.rs 作为构造回归宿主。与 Windows 对照：Windows 内核以 MDL 链描述一次传输的散列缓冲（WDK 文档化行为），本内核段数组同语义且上限显式、对账显式，判据 UNX-F6402-J1 的复测方式：10^5 次构造回收对账恒等报告、合计校验注入 10/10 次拒绝定位、1–32 段全档构造遍历正确。

### UNX-F6403 · Bio 操作标志编码（读/写/flush/reqop）
- 域/批：B4/B01｜判据：UNX-F6403-J1 全操作类型编码互斥可判定，非法组合注入 100% 拒绝；编码值与设计表逐位一致｜纯功能行数：320 行（位编码定义表 100 + 互斥判定器 110 + 设计表逐位核对器 110；测试段不计）｜状态：[已深化]
- **定位**：一次 bio 到底是读、写、刷盘还是管理请求，必须由一套唯一且互斥的位编码判定——编码歧义是块层最难查的病灶（错把 flush 当写会毁数据）。本条立全操作位编码表与互斥判定器，B05 flush/FUA 族的语义就从这里挂位。
- **语义边界**：只做编码定义与判定器；不做 flush 业务语义（B05 防重）、不做请求对象（B02 防重）；编码值一经冻结接口 v1 即不可变（变更走 ADR）。
- **依赖与嫁接源**：依赖 F6401 BioFlags 基座；嫁接源为 Linux bio 操作标志（REQ_OP 族与 REQ_* 标志位）语义与 Windows IRP MajorFunction/Flags 编码族的语义坐标，只跟随。
- **风险与回退**：未来操作类型扩容撞位——预留高位段（reqop 空间 8 位 + 标志空间 24 位）并在设计表登记占位，扩容走设计表追加不改既有位。
- 正文：实现路径分三步。第一步编码表：操作位（Read/Write/Flush/Discard/WriteZeroes/Passthrough 六操作起步）与属性标志（FUA/Prio/Agg 可合并标记等）分段定义，每值与设计表逐位核对并落账，位含义注释到单 bit。第二步互斥判定器：`classify(flags)` 函数对操作位做"恰好一位"断言（多操作位/零操作位均非法），属性位按兼容矩阵校验（如 Discard 与 FUA 互斥），非法组合 100% 拒绝并返回设计表指明的错误码。第三步逐位核对器：构建期静态断言编码值与设计表逐位相等（编译期防止手滑改值），运行期抽验接口供 ktest 反复验证。与现存内核衔接点：现存薄层（F6401）把旧读/写调用映射到 Read/Write 操作位，映射表静态可查。与 Windows 对照：Windows 用 IRP 主功能码+设备栈 Flags 区分操作（WDK 明示），Linux 用 REQ_OP 位图，本内核取位图式并把互斥判定做成一等公民，判据 UNX-F6403-J1 的复测方式：全操作编码逐位比对设计表零差异、非法组合注入 100 例全拒、判定器复杂度 O(1) 断言。

### UNX-F6404 · submit_bio 提交入口与队列路由
- 域/批：B4/B01｜判据：UNX-F6404-J1 提交入口按目标 gendisk 路由到正确请求队列（多设备并发路由 10^4 次零错队）；无设备 bio 拒绝路径留痕｜纯功能行数：360 行（入口函数与参数校验 120 + gendisk→queue 路由表 130 + 并发路由断言账 110；测试段不计）｜状态：[已深化]
- **定位**：submit_bio 是块层的总闸门：上层（文件系统、缓冲层、诊断工具）一切 IO 都从这里进。本条实现提交入口（参数校验+引用挂账）与 gendisk→请求队列的路由表——多设备并发时零错队是硬判据，NVMe 与 AHCI 双盘同写走错队列即灾难。
- **语义边界**：只做入口与路由；不做队列内合并与派发（B02 防重）、不做 gendisk 注册本体（B06 防重，本条消费其路由表）；提交成功即返回句柄，完成走异步回调（同步等待语义归 F6412）。
- **依赖与嫁接源**：依赖 F6402 Bio 结构与 B06 gendisk 表（以 B06 接口契约先立占位结构）；嫁接源为 Linux submit_bio 总入口语义与 Windows 设备栈 IoCallDriver 自顶向下分发语义，只跟随。
- **风险与回退**：设备热移除后路由表悬空——路由命中前做存活检查，失活即拒绝并留痕，绝不把 bio 派向幽灵队列。
- 正文：实现路径分三步。第一步入口：submit_bio(bio, dev) 做四道校验（bio 段合法/操作位互斥/对齐校验联动 F6418/目标设备存在），任一道失败即拒绝并留痕（拒绝理由入事件账），通过后递增在途挂账。第二步路由表：主设备号→gendisk→请求队列的两级路由结构，查询 O(1)，多设备并发压测（NVMe/AHCI/模拟三盘交错提交 10^4 次）零错队；路由表与 B06 注册/注销事件联动（F6506 通知链消费），设备注销时该路由项冻结拒绝新提交。第三步断言账：路由正确性账（提交设备 ID 与完成设备 ID 比对）、错队检测（完成回调发现非提交目标队列即红账）双账常开。与现存内核衔接点：现存薄层调用走本入口（1 段 bio 直通），与旧路径行为等价；多队列派发面留给 B02/B03。与 Windows 对照：Windows 以卷设备栈逐层分发（I/O 管理器按设备对象路由），本内核以路由表显式化同语义并附零错队断言账，判据 UNX-F6404-J1 的复测方式：三设备交错 10^4 次零错队、无设备提交注入 100 例全拒留痕、入口校验四道逐道单测通过。

### UNX-F6405 · Bio 拆分器（段数超限/越界 LBA）
- 域/批：B4/B01｜判据：UNX-F6405-J1 超 32 段/越设备容量边界的 bio 被正确拆分或拒绝，拆分后各段 LBA 连续无重叠（边界值注入 1,000 组全过）｜纯功能行数：320 行（拆分决策器 110 + 越界校验与拒绝 100 + 拆分重挂与关联账 110；测试段不计）｜状态：[已深化]
- **定位**：上层不保证一次请求都合法：段数可能超 32、LBA 可能越过设备容量。拆分器把"超限但可服务"的请求切成合法序列，把"越界不可服务"的显式拒绝——它是 F6402 的 32 段上限与设备几何（F6409）的执法者，也是后面 NVMe PRP 单页限制升级（B10）前的块层兜底。
- **语义边界**：只做块层拆分与拒绝；不做设备层传输分页（PRP/SGL 归 B10/B11）、不做读改写跨扇区对齐修补（对齐由 F6418 拒绝语义承担）；拆分产生的子 bio 与父 bio 的完成聚合由 F6406 回调语义承担。
- **依赖与嫁接源**：依赖 F6402 段结构、F6409 几何三元组与 F6401 拆分后重提交入口；嫁接源为 Linux blk_queue_max_segments 拆分语义与 Windows 类驱动 split request 惯例，只跟随。
- **风险与回退**：拆分风暴（病态负载构造大量临界请求）——拆分次数账与告警阈值联动，风暴时显式记账不静默；拆分中途分配失败即整体回滚拒绝，不留半提交态。
- 正文：实现路径分三步。第一步决策器：`split_if_needed(bio, limits)` 判段数上限（>32）与容量边界（lba+len > 总扇区数），可服务的超段请求按段边界切开（LBA 连续推进），越界的按越界位置区分"部分合法"（截断到容量并拒绝越界余段，管理面可配）与"完全越界"（整体拒绝）；决策树全部落设计文档。第二步越界校验：容量检查用 saturating 运算防溢出，边界值注入 1,000 组（首扇区/末扇区/恰越一扇区/u64 溢出临界）全过。第三步拆分重挂：子 bio 携带父关联 ID 入提交链，完成聚合账保证父 bio 恰在全部子项终态后回调一次，子项失败父项错误（部分完成语义显式）；关联账与 F6406 挂起计数联动归零断言。与现存内核衔接点：现存薄层单段 bio 天然合法，拆分器对其零干预；NVMe 单页 PRP 现状下段长上限由 limits 表注入（后续 B10 放宽）。与 Windows 对照：Windows storport 对超限 SRB 由类驱动/端口驱动分层拆分（WDK 分层模型），本内核把拆分集中在块层单点显式账面化，判据 UNX-F6405-J1 的复测方式：边界注入 1,000 组全过、拆分后 LBA 连续无重叠断言、拆分风暴告警账可见。

### UNX-F6406 · Bio 完成回调与状态码回传
- 域/批：B4/B01｜判据：UNX-F6406-J1 每个提交的 bio 必有终态回调（成功/错误二态），挂起计数账归零断言（10^4 次提交回收对账）；错误状态码与 BLK_STS 族一致｜纯功能行数：320 行（回调注册与触发器 110 + 挂起计数账 100 + 状态码翻译层 110；测试段不计）｜状态：[已深化]
- **定位**："每请求必有终态"是 B4 域两条设计铁律之一（另一条在 B12 复位链兑现）。本条立 bio 完成回调的注册/触发/去重三件套与挂起计数账——任何提交的 bio 最终必然收到恰好一次终态回调（成功或错误二态，无第三态无零次无多次），这是 soak 压测与断电演练能对账的根基。
- **语义边界**：只做完成机制与账；不做错误分类学本体（F6410 防重，本条只回传其类型）、不做请求级完成（B02 request 回调防重，本条管 bio 层）；回调上下文（中断/线程）由提交方声明并校验。
