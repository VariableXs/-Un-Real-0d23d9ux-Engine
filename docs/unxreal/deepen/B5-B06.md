### UNX-F7301 · flush 转发契约总纲（→B2/B3 联签三方断电链）
- 域/批：B5/B06｜判据：UNX-F7301-J1（保护判据先行）契约断言：dm 设备上任何 flush 返回成功时，其下全部成员设备的 flush 均已确认（全确认语义）；UNX-F7301-J2 契约与 B2/B3 联签文档落纸（三方断电链：应用 fsync→fs 层 journal→dm 转发→B4 执行），接口变更必须 AI-86 复核（冻结级别全域最高）｜纯功能行数：340 行（契约断言器 120 + 全确认协议 120 + 联签文档结构 100；测试段不计）｜状态：[已深化]

- **语义边界**：只做契约断言与联签文档；不做 flush 物理执行（B4 判例一）、不做 fsync 应用语义（fsyncp.rs 承接）、不做 journal 提交逻辑（B2/B3 域）、不做性能优化（F7313 合并等条目在契约约束内做）。

### UNX-F7302 · flush 全成员扇出与确认聚合
- 域/批：B5/B06｜判据：UNX-F7302-J1 单 flush 扇出至 N 成员（RAID 型）后聚合确认（缺一不返）；扇出数与成员数一致断言｜纯功能行数：300 行（扇出协议 110 + 聚合确认 100 + 一致断言 90；测试段不计）｜状态：[已深化]
- **定位**：扇出与聚合是契约（F7301）的执行机制：RAID 型 dm 设备一个 flush 要扇出到 N 个成员盘（RAID5 的 4 盘=4 个成员 flush），N 个确认全回才聚合成功——缺一不返。扇出数与成员数一致断言防"漏发"（N 盘只发 N-1 次=漏的那盘数据没落盘），F7235 已立转发协议，本条在契约语境下强化一致断言与聚合的工程细节（确认码防伪、确认超时）。
- **语义边界**：只做扇出与聚合机制；不做契约语义（F7301）、不做 RAID 成员管理（B09–B11）、不做物理 flush（B4）。
- **依赖与嫁接源**：复用 F7235 转发协议与 F7222 聚合计数法；嫁接源为 Linux dm flush 扇出（`__flush` 遍历 target）语义，只跟随。
- **风险与回退**：确认超时（某成员 flush 永不回）——确认等待带超时（缺省 10s，cmdline 可配），超时=整体失败（不是放弃等待）+失败成员标注（F7303 流程），超时不破坏契约（超时=未确认=失败，语义一致）。
- 正文：实现路径分三步。第一步扇出协议：flush 到达取表快照成员集，逐成员发 flush（B4 原语），扇出计数=成员数（计数即断言基准），扇出清单落账（成员/时戳）；第二步聚合确认：每成员确认（确认码=B4 返回的唯一完成码，防伪比对）登记进确认账，账满（计数=扇出数）聚合成功，确认码不匹配=无效确认（红账+重发），确认等待超时转 F7303；第三步一致断言：ktest N 成员（2/3/4/6 盘 RAID 型）各 1000 轮 flush，断言扇出数=成员数、聚合确认数=扇出数、确认码全匹配。与现存内核衔接点：`dm/flush_fanout.rs` 新建，确认账并入 F7235 协议。与 Windows 对照：Windows 软件 RAID（LDM raid5 卷）的 flush 扇出到全部成员盘同构。判据 UNX-F7302-J1 的复测方式：四档成员数 ×1000 轮扇出/聚合/确认码断言全过、确认超时转失败路径验证、确认码伪注入 10/10 拦截。

### UNX-F7303 · flush 失败语义（部分成员失败）
- 域/批：B5/B06｜判据：UNX-F7303-J1（保护判据先行）任一成员 flush 失败则整体失败并标注失败成员（不静默吞）；失败成员进入降级评估流程（与 F7273 联动）；失败后重试策略可配且默认保守｜纯功能行数：320 行（失败聚合 100 + 标注协议 100 + 重试与联动 120；测试段不计）｜状态：[已深化]
- **定位**：flush 部分失败的处置是契约的另一半：任一成员失败→整体失败（绝不静默吞——吞掉=上层以为落盘了实际那盘没落，断电后数据丢失且无人知晓）+失败成员标注（哪盘失败精确到设备号）+失败成员进降级评估（F7273 离线检测联动——flush 失败往往是离线前兆）。重试策略默认保守（不自动重试 flush——重试语义含混，人工评估后显式重试）。
- **语义边界**：只做失败聚合与联动触发；不做降级评估本体（F7273）、不做物理重试（B4）、不做契约变更（F7301 不动）。
- **依赖与嫁接源**：消费 F7273 离线检测与 F7215 错误传播；嫁接源为 Linux dm flush 失败传播惯例，只跟随。
- **风险与回退**：失败风暴（介质坏时每秒百次 flush 失败）——失败聚合进事件节流（F7275 风暴节流复用），整体失败对上层的返回不节流（上层语义必须每次真实），内部事件限频。
- 正文：实现路径分三步。第一步失败聚合：确认账出现失败成员（确认码=错误）即停止等待其余（已确认的不回滚——flush 幂等无害），整体失败返回，失败成员清单（1 个或多个）随错误上抛；第二步标注协议：失败标注（设备号/成员槽位/底层错误码）三段结构随失败事件（F7275 格式）上报，标注可定位到设备号（判据要求），上层与运维从标注直接定位坏盘；第三步重试与联动：重试策略三档（不重试【默认】/显式命令重试/自动重试 N 次【显式开启】），默认保守档文档声明；失败成员同步进 F7273 评估流（离线检测计数+1），联动事件留账。与现存内核衔接点：`dm/flush_fail.rs` 新建。与 Windows 对照：Windows 卷 flush 部分成员失败的整卷失败返回（STATUS_DEVICE_DATA_ERROR）同构。判据 UNX-F7303-J1 的复测方式：单成员失败注入 50 轮整体失败+标注 100%、多成员失败（2/3 盘）标注完整、默认不重试验证、联动评估触发 10/10。
- **红线注记**：保护判据载体条目（flush 失败不静默）——已列 AI-86 双人复核清单。

### UNX-F7304 · flush 顺序与屏障合成
- 域/批：B5/B06｜判据：UNX-F7304-J1 连续 flush 的完成顺序与其间写的顺序一致（顺序断言）；屏障与 flush 合成不改变承诺强度｜纯功能行数：280 行（顺序协议 100 + 合成规则 90 + 断言 90；测试段不计）｜状态：[已深化]
- **定位**：flush 的顺序承诺：连续 flush（flush A→写→flush B）的完成顺序必须与提交顺序一致——journal 场景里 flush A 是事务 1 提交、flush B 是事务 2 提交，B 先完成 A 后完成=事务顺序颠倒=断电后日志恢复出错误顺序。屏障与 flush 的合成（F7233 屏障协议与 flush 的组合）不许改变承诺强度——合成是执行优化，承诺不打折。
- **语义边界**：只做顺序协议与合成规则；不做屏障本体（F7233）、不做合并优化（F7313，合并须过本条顺序断言）、不做物理顺序保证（B4）。
- **依赖与嫁接源**：复用 F7233 屏障协议与 F7213 保序账；嫁接源为 Linux blk 层 flush 顺序（`REQ_OP_FLUSH` 排队序）语义，只跟随。
- **风险与回退**：顺序保证与并行的矛盾（多线程各自 flush 想并行）——跨线程 flush 的顺序以到达序为准（每 flush 带到达序号，完成序=到达序），同设备 flush 串行化（flush 本来就该串行——并行 flush 无语义收益只有成本）。
- 正文：实现路径分三步。第一步顺序协议：每 flush 带到达序号，dm 层 flush 队列按序提交（同设备 flush 串行），完成序号与提交序号单调一致断言（完成序回退=顺序违约红账）；第二步合成规则：屏障到达时若队列头是未完成 flush→屏障合并进 flush（一次下传，承诺=flush 全确认+屏障前写终态，强度不降），合成规则表静态声明（flush+barrier→单次强操作/flush+flush→F7313 折叠域），合成前后承诺等价断言；第三步顺序断言：ktest 写-flush 交错流 1000 组，断言完成顺序=提交顺序、断电模拟恢复序=提交序（对拍恢复语义）。与现存内核衔接点：`dm/flush_order.rs` 新建。与 Windows 对照：Windows NTFS 日志的 flush 顺序（LCI 序）依赖卷栈顺序保证同构。判据 UNX-F7304-J1 的复测方式：交错流顺序断言 1000 组零违例、合成承诺等价断言通过、恢复序对拍一致。

### UNX-F7305 · cache 模式协商（write-back/write-through 切换）
- 域/批：B5/B06｜判据：UNX-F7305-J1 双档切换生效且切换瞬间在途写有终态（零丢失断言）；模式状态可查询（所见即所是）｜纯功能行数：300 行（模式协议 100 + 切换原语 100 + 查询面 100；测试段不计）｜状态：[已深化]
- **定位**：write-back（写回：写先落 dm 缓存即确认，后台回写盘）/write-through（写穿：写直接落盘才确认）双档是性能与安全的模式选择：write-back 快（写延迟=缓存写入）但断电窗口大（缓存里的数据随断电消失），write-through 慢但每个确认写都是真落盘。切换原语的纪律：切换瞬间在途写有终态（零丢失）——切到 write-through 时缓存脏段先全落盘再切，切到 write-back 时在途直写先终态再切。
- **语义边界**：只做模式协商与切换；不做缓存本体（F7307）、不做回写策略（F7308）、不做模式的自动选择（O 部域）。
- **依赖与嫁接源**：消费 F7307 脏段账（切换前排空）；嫁接源为 Linux dm-cache writeback/writethrough 模式与 Windows 写缓存策略（disk 属性）惯例，只跟随。
- **风险与回退**：切换期性能塌陷（排空脏段的大批量写）——排空走回写批量路径（限速），切换完成时间落账（切换是管理动作，秒级完成可接受）。
- 正文：实现路径分三步。第一步模式协议：设备级模式位（write-back/write-through），模式命令（F7281 消息命令扩展）切换，模式状态查询面（枚举面扩展字段）——所见即所是（查询返回的模式=真实生效模式，无过渡态谎报）；第二步切换原语：wb→wt 切换=脏段全量回写（F7308 批量路径）→在途写终态→切位；wt→wb 切换=在途直写终态→切位，两向切换均先排空后切（切换瞬间零丢失断言）；第三步零丢失断言：切换风暴（10 轮双向切换×在途 IO 压力）每请求有终态、断电模拟（切换中途断电注入）恢复后已确认写零丢失。与现存内核衔接点：`dm/cache_mode.rs` 新建。与 Windows 对照：Windows 磁盘写缓存启用/禁用（设备管理器策略）切换前刷缓存同构。判据 UNX-F7305-J1 的复测方式：双向切换各 50 轮零丢失、切换中断电注入 10/10 恢复一致、查询面所见即所是验证。

### UNX-F7313 · flush 请求合并（连续 flush 折叠）
- 域/批：B5/B06｜判据：UNX-F7313-J1 无写间隙的连续 flush 折叠为单次（性能）且有写插入时不折叠（正确性）；折叠账可观测｜纯功能行数：260 行（折叠器 90 + 间隙守卫 90 + 折叠账 80；测试段不计）｜状态：[已深化]
