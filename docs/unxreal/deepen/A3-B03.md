- **正文**：每核 runqueue 是调度器的心脏肌肉，B01-F1610 已定下"每核一队列、调度类分组"的骨架，本条目负责把骨架上的第一根神经——锁——接对。选择每核自旋锁而非全局锁的理由在多核语义上是不容谈判的：全局锁让 N 个核在调度路径上退化为串行， SMP 压测的吞吐曲线会随核数不升反降。锁域清单是本条目的治理件：枚举每一个可能触碰队列的路径（入队、出队、选中、统计快照、迁移暂存、自检扫描），逐条登记"持什么锁、持多久、在什么中断层级"，清单入册可审计。跨队列访问禁区是第二条纪律：任何核不得直接读改他核队列，唯一合法通道是 B07 迁移原语——这条禁区用断言守护，注入测试以十种越锁形态（直读他核队长、他核入队、他核改 vruntime 等）验证断言 10/10 捕获。持锁窗口账把"锁很快"从承诺变成账目：每次持锁登记窗口长度，ktest 汇总分布，超上限即失败。

## UNX-F1642 · 入队路径 enqueue 全序语义（300 行）

- **定位**：定义入队全序语义：先按线程优先级定桶，桶内按 vruntime 定插位，入队动作在全序账中可回放、可闭合。
- **语义边界**：管：入队步骤序、插位确定性、全序账格式与回放、并发入队闭合。不管：桶序定义（F1648）、vruntime 值的生成（F1644）、唤醒特例（F1649）。
- **判据**：UNX-F1642-J1 入队序确定性可回放，10 核×10^4 并发入队零丢失，全序账闭合。
- **行数**：300 行（入队步骤 90 + 插位与全序账 80 + 并发注入测试 70 + 文档 60）。
- **依赖与嫁接源**：上游 F1641（锁前提）、F1648（桶序）；下游 F1650（入队即判抢占挂接点）、F1656（不变量断言）。
- **风险与回退**：风险为并发入队在同一插位竞争导致序账与实序漂移。回退：插位竞争以锁内重验（持锁后重算插位）消化，全序账以锁内顺序为准；漂移注入覆盖重验窗口。
- **正文**：入队的核心要求是"同序结果确定"：给定同一组线程状态，任何一次入队重放都必须产生同一队列序——这是调度可复现性的根基，也是延迟抖动定位的前提。全序账为此而生：每次入队登记（线程号、优先级桶、插位比较路径、锁内时刻戳）四元组，账目按核归档，ktest 回放时以账目重演插位过程，与实际队列序逐位比对，任何一位不符即确定性破坏。并发闭合是第二层账：10 核各发起 10^4 次并发入队后，全队计数等于 Σ各核入队数，队内无重复无遗漏——这一闭合检验的是锁内重验与链表接续的原子性。桶内插位算法取"从队首线性扫描至第一个 vruntime 更大者"的形态，在每核队列深度可控（≤数百）的前提下线性扫描的缓存友好性优于平衡树，且避免树结构的重平衡开销进入锁内窗口；深度上限与扫描退化由 F1659 边界注入守护。

## UNX-F1644 · vruntime 账目与睡眠补偿语义（340 行）

- **定位**：落位 vruntime 账目语义：累加=权重倒数×运行时长、min_vruntime 锚定、睡眠补偿与唤醒锚定，账目回放偏差为零。
- **语义边界**：管：vruntime 累加公式、min_vruntime 维护、睡眠补偿规则、账目回放。不管：权重表定义（F1648 放置桶职责）、tick 推进时刻源（A2/F1630）、迁移时 vruntime 归一化（B07 迁移原语职责）。
- **判据**：UNX-F1644-J1 vruntime 累加=权重倒数×运行时长，睡眠补偿 min_vruntime 锚定语义落位，账目回放偏差为零。
- **行数**：340 行（累加与权重 100 + min_vruntime 与补偿 100 + 回放账 80 + 文档 60）。
- **依赖与嫁接源**：嫁接 CFS vruntime 思想（只取语义，不引入外部实现）；上游 F1643（运行时长来源）、F1630（tick 时刻源）；下游 B07（迁移归一化消费）。
- **风险与回退**：风险为长睡眠线程唤醒后 vruntime 严重落后导致饿死其他线程（反向补偿过冲）。回退：唤醒锚定取 min_vruntime（非补偿外推），补偿上限封顶一个窗口周期；过冲注入覆盖封顶边界。
- **正文**：vruntime 是公平性的度量衡：运行越多欠账越多，权重越高欠账越慢——累加公式"权重倒数×运行时长"把这两条直觉变成可回放的账。本条目把公式做成账目而非代码注释：每次从 tick 推进到线程让出，登记（线程号、起止时刻戳、权重、本次增量、累加后值），账目可在 ktest 中重演累加过程，重演结果与实际值逐位一致为通过，偏差非零即判据失败——这把"公式写对"变成"公式被验证过"。min_vruntime 是队列的公平锚点：取队首 vruntime 与当前运行者 vruntime 的最小值慢速推进，新入队线程以锚点起步，长睡眠线程唤醒后锚定锚点而非携带陈旧值，防止"睡一觉回来把别人全饿一遍"的补偿过冲。补偿上限封顶一个窗口周期是过冲的最后一道闸，封顶边界由注入测试覆盖。迁移归一化（跨队列带 vruntime）的语义在本条目只登记签名，执行归 B07 迁移原语——边界划清，联签一致。

- **依赖与嫁接源**：上游 F1644（权重语义承接）、B07 迁移原语（转移执行点）；下游 B07（均衡决策主输入）、B29（负载倾斜观测轴）。
- **风险与回退**：风险为迁移的负载转移与线程实际摘挂非原子，闭合被窗口竞争打破。回退：转移绑定 B07 迁移原语的同一临界区（登记宏内联，与 F1627 同纪律），闭合断言保留差异窗口日志。

- **正文**：双链表是 runqueue 的物理骨架，骨架的断裂是最恶性的故障：断链让线程从账目上消失，环化让扫描永动——两者都不崩溃系统，只是慢慢腐蚀调度正确性，等到症状浮现（某线程永远不被调度）时，现场早已被几百万次队列操作冲刷干净。周期自检把骨架健康变成持续观测的账目：扫描算法双向走链（正向数计数、反向数计数、比对相等），同时以 Floyd 判圈检测环化，两项合计 O(n) 单遍。自检挂接三类周期位点：ktest 显式触发、72h 账例每小时、每万次入出队抽样一次，三类位点保证短时回归与长时压测都被覆盖。注入测试构造断链（单侧指针置空）与环化（尾指回中部）各五形态，验证自检 10/10 捕获并报告断点位置（第几个节点、正向还是反向断裂）——报告精度决定修复速度，只说"链坏了"与说出"第 37 个节点后向断链"是两种修复体验。扫描持锁窗口计入 F1641 持锁账，自检的观测成本自身也被观测。
