### UNX-F2441 · 每 CPU 页池结构（32 页批量）
- 域/批：A4/B03｜判据：UNX-F2441-J1 池容量 32 页/核/区三机型配置账一致，池内页与 buddy 账恒等（抽核零漂移）｜纯功能行数：340 行（池结构 140 + 批量粒度协议账 110 + 三机型配置 90；测试段不计）｜状态：[已深化]
- **定位**：每 CPU 页池是分配谱最高频档（order-0）的本地缓存层——F2421 无池快路径证明"单页直出"已是最快形态，池再快一档：本核本链零锁命中。它是 F2480 样板总账条目"buddy 分配器与每 CPU 页池"的池侧实体，32 页批量是池-buddy 交接的粒度单位。
- **语义边界**：只做池结构与批量粒度；不做 refill 语义（F2442）、不做 drain（F2443）、不做核间均衡（F2445）。高阶页不进池（池是 order-0 专池），高阶快路径归 F2421–F2423。
- **依赖与嫁接源**：依赖 F2408 阶结构、F2433 分区锁、F2444 交接协议；嫁接源为 Linux per-CPU pageset（pcp）双链形态，实现自研。
- **风险与回退**：池页在 buddy 账上呈"已分配但闲置"，可用量感知失真——池页单列账（F2450 三计数），水线判定用池+buddy 合计口径（F2461 消费），失真被口径设计吸收。
- 正文：实现路径分三步。第一步池结构：每核双链（热端供常规分配、冷端供 DMA 类低局部性请求），每链上限 32 页，池项仅含帧号与迁移区标记（高四位编码），池头带代际计数——跨代际页不混用，为 F2451 失效语义铺底；第二步 32 页批量：池与 buddy 的所有交接以 32 页为一批（F2444 协议），批内页同迁移区同阶，批边界账落档，批内页数不足时半批入池但逐页配平；第三步三机型配置：8GB/16GB/32GB 机分别配 32/32/64 页上限，配置档位表编码在 F2454，开机自检（F2452）核对配置账并写入 MemDomainState 池段。与现存内核衔接点：`pmm.rs` 现存 `alloc_page` 单页直出路径收编为"池未命中→buddy 直出"降级序的末端，签名不变，调用方零感知。与 Windows 对照：Windows 的 per-processor lookaside list（PP_LOOKASIDE）同形态且深度自动调节，本条以账可审计性对齐工业口径——池的每一页进出都有批记录可查。判据 UNX-F2441-J1 的复测方式：三机型配置账一致（自检账），池内页与 buddy 已分配账恒等抽核（每 64 次分配抽核一次 + 水线跨越前强制）零漂移，漂移注入用例 20/20 次被抽核捕获。

### UNX-F2442 · refill 批量补给语义
- 域/批：A4/B03｜判据：UNX-F2442-J1 池空触发批量补给 32 页 10/10 次一次到位，补给时延账落档｜纯功能行数：300 行（触发判定 90 + 批量拉取 120 + 时延账 90；测试段不计）｜状态：[已深化]
- **定位**：refill 是池-buddy 交接的主要正向流——池空时一次补给拉一批而非逐页拉，把 buddy 锁与区锁的开销摊薄到 32 页上，这是池存在的经济学理由。
- **语义边界**：只做 refill 触发与批量拉取；不做 drain（F2443）、不做池干涸直接回收触发（F2459）、不做核间借池（F2445）。
- **依赖与嫁接源**：依赖 F2441 池结构、F2444 交接协议、F2428 迁移路由；嫁接源为 Linux pcp refill 语义，实现自研。
- **风险与回退**：补给中途 buddy 只凑出部分页（区内 order-0 枯竭）——半批入池允许但逐页配平，凑不满部分记"补给不足"计数，连续补给不足是 F2459 直接回收触发的评估输入。
- 正文：实现路径分三步。第一步触发判定：池空或低于单页阈值即触发 refill，判定在分配路径单点（池命中检查后立即判定），判定本身零额外锁；第二步批量拉取：按 F2444 协议从 buddy 拉一批——优先本迁移区 order-0 链，区内不足按 F2428 许可矩阵跨区降级，拉到的页逐页入池账并保持区标记，批意图预写（WAL 形态）保证中断可恢复；第三步时延账：补给时延（触发点到池可用点）打点落账，"一次到位"的判定口径为一次 refill 操作完成且池计数到位，分次凑批的每次都单独记账。与现存内核衔接点：`pmm.rs` 新增 refill 路径，插在池未命中降级序之前，buddy 接口消费 F2421/F2422 出口。与 Windows 对照：Windows 的 MDL 批量页分配与 paged pool 块补给同思想，本条补足批记录与半批配平两个账面细节。判据 UNX-F2442-J1 的复测方式：池空触发补给 32 页 10/10 次一次到位（计数账），补给时延账三机型落档，半批用例（buddy 只剩 11 页）逐页配平通过且"补给不足"计数正确。

### UNX-F2443 · drain 回收语义与水线联动
- 域/批：A4/B03｜判据：UNX-F2443-J1 drain 后池余页与策略值一致 10/10 次，联动触发与 F2461 水线账时序一致｜纯功能行数：300 行（drain 判定 100 + 归还语义 100 + 联动账 100；测试段不计）｜状态：[已深化]
- **定位**：drain 是池的反向流——buddy 低于 low 水线时，各核池把闲置页按比例归还 buddy，让"沉睡在池里的页"回到全局供给；池与 buddy 的水线联动是两层水线体系（池水线 F2448 / buddy 水线 F2461）的耦合件。
- **语义边界**：只做 drain 判定与归还；不做 buddy 水线本体（F2461）、不做池水线告警（F2448）、不做干涸直接回收（F2459）。
- **依赖与嫁接源**：依赖 F2441/F2444/F2461（前向声明）；嫁接源为 Linux pcp drain on high watermark 语义，实现自研。
- **风险与回退**：drain 风暴——水线临界抖动引发反复 drain/refill 对冲，滞回带（drain 触发后需 buddy 回升至 high 才解除）+ 时间窗节流双闸，风暴计数落账。
- 正文：实现路径分三步。第一步 drain 判定：buddy free 低于 low 时触发全核 drain（跨核经 F2451 失效 IPI 通道或本核自触发），单次 drain 比例为池量一半（显式常量），drain 后池余页可复算；第二步归还语义：drain 页按 F2444 协议逐批归还 buddy，归还页按池项区标记回到原迁移区链（禁止跨区归还——区标记错位即结构事故 panic），归还批与 buddy 账配平；第三步联动账：drain 事件时序与 F2461 水线跨越事件对账——drain 必发生在水线跨越后的时间窗内，滞回解除点（buddy 回升到 high）记录在档，drain/refill 对冲计数为零才认定滞回有效。与现存内核衔接点：`mm.rs` 现存 Watermarks 判定消费对齐 F2461 口径，drain 编排挂在 `mm.rs` 回收入口前置位。与 Windows 对照：Windows 的 working set trim 与池回收分属不同层，池 drain 是 buddy 形态专属语义，对照 Linux 的滞回参数可审计性对齐。判据 UNX-F2443-J1 的复测方式：drain 后池余页与策略值（池量一半）一致 10/10 次，联动时序账与水线账逐笔一致，风暴注入用例（水线临界抖动 10 分钟）零对冲计数。

### UNX-F2444 · 池-buddy 批量交接协议
- 域/批：A4/B03｜判据：UNX-F2444-J1 交接（入池/出池）批记录与双方账逐笔配平，交接中断恢复 10/10 次无半批态｜纯功能行数：320 行（批记录 110 + 配平 110 + 恢复 100；测试段不计）｜状态：[已深化]
- **定位**：refill、drain、核间均衡三条流共用一个交接协议——批记录、逐笔配平、中断恢复三件套，这是池账完整性的契约件；没有协议，三条流各自记账必然漂移。
- **语义边界**：只做交接协议；不做三条流的触发策略本体（F2442/F2443/F2445）、不做恢复扫描时机（F2452 自检消费）。
- **依赖与嫁接源**：依赖 F2441；嫁接源为域内账配平方法论（F2431 配对账同源思想），批意图预写为 WAL 思想简化版，实现自研。
- **风险与回退**：交接中断（核在 refill 中途被夺走/异常）——批记录预写：先写批意图，再动页，后写批完成；恢复扫描发现"有意图无完成"即按批意图回收页（幂等回滚），回滚账留痕。
- 正文：实现路径分三步。第一步批记录：每次交接必写批记录（方向/批次页清单/发起核/代际/时戳五字段），批记录与页动账同事务序（意图→动页→完成），批记录本身入环形账防膨胀；第二步配平：入池批 buddy 减池加、出池批池减 buddy 加，逐批对账——批记录页清单与双方账增量逐页配平，任何差值即冻结分配并打印批号（fail-stop），配平逻辑单点实现供三条流共用；第三步恢复：bring-up 与接管扫描批记录，发现未完成批按意图回滚（页归还原属方），回滚批计入恢复账，回滚后配平复查必须通过。与现存内核衔接点：`pmm.rs` 交接函数单点收编（refill/drain/均衡共用），现存无等价物为新增件。与 Windows 对照：Windows 无公开等价批协议形态，本条属 buddy 池化形态的结构加固项，对照 Linux 的 pageset 批处理（无恢复语义）本条多出中断恢复一档。判据 UNX-F2444-J1 的复测方式：三条流交接批记录与双方账逐笔配平（长稳 10^6 交接零差值），中断注入（批中 abort 模拟）10/10 次恢复无半批态，恢复账与配平复查账齐全。

### UNX-F2445 · 核间池均衡
- 域/批：A4/B03｜判据：UNX-F2445-J1 均衡触发后池间差收敛到阈值内 10/10 次，均衡搬运页数账落档｜纯功能行数：280 行（均衡判定 90 + 搬运 90 + 账 100；测试段不计）｜状态：[已深化]
- **定位**：负载不均时有的池满有的池空——均衡把富余池的页显式搬到稀缺池，避免"富余核 drain 同时稀缺核 refill"的对冲浪费；它是池层的核间协调动作，与调度层的核间负载均衡（A2 域）解耦但账面可关联。
- **语义边界**：只做均衡判定与搬运；不做调度迁移（A2 域防重）、不做 drain/refill 本体（F2443/F2442）、不做借出方下限策略细节（F2449）。
- **依赖与嫁接源**：依赖 F2441/F2444/F2449；嫁接源为 Linux 本地优先 + steal 思想的显式均衡版，实现自研。
- **风险与回退**：均衡乒乓（两池互相搬）——均衡单向化（只从富余向稀缺搬）+ 冷却窗（同两池间均衡最短间隔），乒乓计数落账且必须为零。
- 正文：实现路径分三步。第一步均衡判定：周期扫描（A3 时钟 tick 驱动，接口前向声明）池间差，最大池与最小池比值超阈值（如 2 倍）即触发，触发源与判定值落账；第二步搬运：从最富余池按 F2444 协议取批（借出方下限保护由 F2449 闸校验），跨核搬运到最稀缺池，搬运页保持区标记与代际（跨代际页拒绝搬运入账），搬运是纯池间动作不动 buddy；第三步账：搬运页数、触发源、收敛结果三账齐全，收敛判定为池间差进入阈值带内，连续两轮观测确认（防单点波动误判收敛）。与现存内核衔接点：新增 `pool_balance()` 编排，由 A3 时钟事件驱动，挂点接口前向声明。与 Windows 对照：Windows 的 per-CPU lookaside 无显式均衡（靠自然回流），本条显式均衡是多核压力场景（8 核机）的结构性加固。判据 UNX-F2445-J1 的复测方式：负载倾斜用例触发均衡后池间差收敛 10/10 次，搬运页数账与批记录逐笔配平，乒乓监测计数恒零，冷却窗参数在档。

### UNX-F2446 · 中断上下文原子分配路径
- 域/批：A4/B03｜判据：UNX-F2446-J1 中断态分配 10^6 次零睡眠零自旋长持，池空即原子失败留账｜纯功能行数：300 行（上下文判定 100 + 原子失败 90 + 静态审计 110；测试段不计）｜状态：[已深化]
- **定位**：中断上下文不能睡眠、不能长持锁——池命中路径天然满足（本核数据、无锁），池空时必须原子失败（立即返回）而非下探 buddy 锁；这条纪律是中断路径延迟确定性的底线。
- **语义边界**：只做中断态判定与原子失败；不做中断处理本体（A2 域防重）、不做紧急保留池策略（F2458 授权闸消费本条的失败路径）、不做静断注入制度（F2455）。
- **依赖与嫁接源**：依赖 F2441；嫁接源为 Linux GFP_ATOMIC 语义，实现自研。
- **风险与回退**：中断态池空率上升导致分配失败率上升影响功能——失败率账单列（按中断向量分组），F2458 紧急池是关键路径兜底，失败率异常上升报 AI-83 域经。
- 正文：实现路径分三步。第一步上下文判定：进入分配路径先判上下文（中断态标志位一次读），中断态请求只允许池命中路径，判定与池查找合并为一次原子读序；第二步原子失败：池空即返回结构化失败（错误码 + 失败计数），绝不取分区锁、绝不触发 refill——调用方（中断处理例程）决策推迟重试或放弃，失败逐笔计数（按向量/调用点 F2431 site 体系聚合）；第三步静态审计：中断态路径静态断言编译期生效（可睡眠调用清单黑名单），运行期抽查断言双闸，审计清单（grep 中断态调用点）随批归档。与现存内核衔接点：`pmm.rs` alloc 入口加上下文分支，现存中断态调用点审计后逐点收编。与 Windows 对照：Windows 的 DISPATCH_LEVEL ≤ NonPagedPool 约束同思想，本条失败率按向量分组账面更细，可定位到具体中断源。判据 UNX-F2446-J1 的复测方式：中断态（定时器+软中断双源）分配 10^6 次零睡眠零长持（F2455 静断制度背书），池空即失败留账，失败率账按向量分组可导出，零"中断态下探 buddy 锁"审计命中。

### UNX-F2447 · 分配 CPU 亲和与 NUMA 本地命中
- 域/批：A4/B03｜判据：UNX-F2447-J1 NUMA 本地命中率 ≥90%（样板判据承载），远端命中逐笔留账｜纯功能行数：300 行（亲和判定 100 + 命中账 100 + 远端账 100；测试段不计）｜状态：[已深化]
- **定位**：NUMA 机上跨节点取页延迟数倍于本地——分配请求尽量在发起核本地节点完成，本地命中率 ≥90% 是 F2480 样板判据第三分句的承载分解条目（B03 骨架批注已声明）；本条把"亲和"从愿望变成账面可验的指标。
- **语义边界**：只做亲和判定与命中账；不做 NUMA 拓扑发现（F2402 已建）、不做页迁移搬运策略（F2429/F2430 归 B02 语义）、不做跨节点进程绑核（A2 域调度语义）。
