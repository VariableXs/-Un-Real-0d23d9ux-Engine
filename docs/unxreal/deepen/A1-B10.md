### UNX-F0181 · 初始化顺序编排器（依赖图驱动）
- 域/批：A1/B10｜判据：UNX-F0181-J1 各 init 单元依赖图声明后执行序与拓扑序一致，环依赖检出 100%｜纯功能行数：320 行（单元注册与依赖声明 100 + 拓扑排序 120 + 环检出 100；测试段不计）｜状态：[已深化]
- **定位**：早年初始化的编排核心：init 单元显式声明依赖，编排器按拓扑序驱动执行，环依赖编译期+运行期双检。
- **语义边界**：只编排"引导阶段内"的 init 单元（ACPI/内存/控制台/页表等）；阶段间顺序由 F0014 状态机管（分工声明）；单元粒度 = 单条 UNX 功能的实现入口（每条一个 init 函数注册）。
- **依赖与嫁接源**：F0014 状态机、F0126 阶段进度账；嫁接 Linux `initcall` 分层（early/core/postcore/arch/subsys/fs/device/late）与 Kbuild 链接序思想。
- **风险与回退**：链接序隐式依赖是 Linux 历史包袱——本工程显式依赖表（init_register(name, deps[], fn)），禁止用链接顺序表达依赖；依赖名打错（未注册名）编译期静态断言拒绝。
- 正文：实现路径分三步。第一注册表：init 单元静态注册（名称/依赖名单/入口函数/所属阶段），编译期宏 `init_unit!(name => deps: [a, b], fn)` 展开为数组节；未注册依赖名（拼错）在编译期以符号存在性断言拒绝。第二拓扑排序：Kahn 算法对注册表排序（稳定序：同层按注册序），输出执行序表；排序失败（有环）即停机三要素报告（环路径打印）。第三执行与账：按序执行每单元入口，计时入 F0198 时间线；执行序与拓扑序一致性断言（ktest 重算拓扑序比对）；环注入检出 100%。与现存内核衔接点：B03–B09 已深化条目的入口函数全部改由本编排器驱动（一次性重构登记）；F0126 阶段徽标按单元序推进。与 Windows 对照：Windows 的 `KiInitSystem` 硬编码顺序（无依赖图）；Linux initcall 是分层近似。本工程显式 DAG 是 30 年工程的可维护性基石。判据 UNX-F0181-J1 的复测方式：ktest 断言执行序 == 拓扑序、环注入（A→B→A）检出 100% 且环路径打印、依赖名错误编译拒绝演练、执行账齐。

### UNX-F0182 · 阶段产物交接协议（init 契约）
- 域/批：A1/B10｜判据：UNX-F0182-J1 单元间交接结构体版本化校验，缺字段拒绝启动并落账｜纯功能行数：280 行（契约结构 90 + 版本校验 100 + 缺字段拒绝 90；测试段不计）｜状态：[已深化]
- **定位**：init 单元间交接数据（如 ACPI 解析产物 → 内存合并、CPU 特征表 → 页表族）的契约协议：版本化结构体 + 齐备性校验，缺字段拒绝启动。
- **语义边界**：契约覆盖"单元→单元"交接（跨域交接另有 F0079/F0113/F0139 三件——本条是其单元级同族）；字段只增不改语义（版本轴）；契约定义与消费双端单源（一个 .rs 定义两处引用）。
- **依赖与嫁接源**：F0079 交接协议（域级先例）、F0181 编排器（交接点插入）；嫁接 Linux `x86_init` 平台操作表与 `boot_params` 传递思想。
- **风险与回退**：契约漂移（生产者改字段消费者未跟上）是最常见重构坑——版本双向校验（生产者写版本、消费者断言支持版本）；降级策略缺字段即拒（宁可不引导不可带病——与 F0079 同纪律）。
- 正文：实现路径分三步。第一契约结构：每交接点一个结构体（如 `AcpiProduct { version, madt_ptr, facp_ptr, ... }`），`#[repr(C)]` + magic + version + size 头；定义单源（一处 mod 两端 include）。第二校验：生产者填充后写 CRC；消费者 `contract_verify()` 断言 magic/version（受支持集）/size/CRC 四项，任一失败拒绝启动（三要素 panic：哪个契约/缺什么/怎么修）。第三缺字段演练：ktest 注入缺字段（版本降级模拟）、CRC 坏、版本超前三类断言全拒并落账；正常链全过。与现存内核衔接点：编排器在单元执行间插入校验点；跨域三交接件（F0079/F0113/F0139）复用同一校验函数。与 Windows 对照：Windows 的 `LOADER_PARAMETER_BLOCK` 字段演进无版本断言（靠 NTDDI 版本）；本工程运行期断言更严。判据 UNX-F0182-J1 的复测方式：ktest 三类异常注入全拒、正常链零误拒、CRC 校验过、版本受支持集断言。

### UNX-F0183 · 单元失败隔离（失败不阻断无依赖单元）
- 域/批：A1/B10｜判据：UNX-F0183-J1 注入单元失败，无关单元照常完成，失败单元状态显性化（零静默）｜纯功能行数：260 行（失败分类 80 + 隔离执行器 90 + 显性化账 90；测试段不计）｜状态：[已深化]
- **定位**：init 单元失败的隔离语义：失败单元显性化记账，无依赖的下游单元照常执行，有依赖的下游跳过（级联 skip 显性化）。
- **语义边界**：失败三分类——soft（可继续，如可选特性探测失败）、hard（本单元功能不可用）、fatal（系统不可继续，立即 panic）；级联 skip 只传播一层标记（下游看依赖状态自行决策，编排器不猜）。
- **依赖与嫁接源**：F0181 编排器、F0182 契约、F0197 健康门禁；嫁接 systemd 的 `After=` 失败传播与 `Requires=`/`Wants=` 两级依赖语义。
- **风险与回退**：soft/hard 误分类会让"该死的没死"或"能活的死了"——分类必须由单元作者显式声明（返回 Err3(Soft/Hard)），编排器不推断；fatal 立即停（不隔离）。
- 正文：实现路径分三步。第一失败分类：单元返回三态（Ok/Err(Soft, reason)/Err(Hard, reason)/fatal 由 panic 表达）；reason 走三要素模板。第二隔离执行器：单元失败 → 状态表标 failed(soft|hard) → 依赖图中未依赖它的单元继续按序执行；直接依赖 hard 单元的下游标 skipped（级联标记），soft 依赖由下游自决（消费接口带 canary 查询）。第三显性化账：失败/skip 事件全落账（单元名/原因/影响面：受影响下游列表自动算出）；零静默断言（任何 failed/skip 必有日志行）；汇总入 F0197 门禁。与现存内核衔接点：F0197 门禁聚合本状态表；F0121 状态机接收 fatal。与 Windows 对照：Windows 驱动加载失败不阻断其他驱动（类似 soft），核心服务失败蓝屏（fatal）——语义同族但本工程显式声明。判据 UNX-F0183-J1 的复测方式：ktest 注入 hard 失败断言无关单元完成 + 下游 skip 显性、soft 失败下游自决、fatal 立停、零静默断言。

### UNX-F0184 · init 串行性显式声明
- 域/批：A1/B10｜判据：UNX-F0184-J1 串行假设以断言固化，越序调用检出 100%（并行化留 A3 后按 ADR）｜纯功能行数：180 行（串行断言器 90 + 越序检出 90；测试段不计）｜状态：[已深化]
- **定位**：把"早年 init 全串行"假设显式固化为运行期断言：单元外越序调用 init 接口即检出——为 A3 并行化留下显式 ADR（架构决策记录）入口。
- **语义边界**：串行断言 = "编排器执行中"标志位 + 非法并发调用检测（早年单核下主要防中断上下文误调 init 接口）；并行化决策不在本条做（ADR 占位：A3 SMP 成年后评审）。
- **依赖与嫁接源**：F0181 编排器、A3 未来 ADR；嫁接 Linux `might_sleep()`/`lockdep` 的"假设即断言"思想。
- **风险与回退**：断言误伤（合法的延迟调用模式）会假红——断言范围限定 init 注册表入口函数（编排器调用的那批）；延迟调用须走单元内注册的 deferred 队列（显式豁免）。
- 正文：实现路径分三步。第一断言器：全局 `init_in_progress` 标志（编排器进入置位/退出清零）+ 每单元 `current_unit` 名；init 接口入口断言"必须在编排器上下文"（标志位 && 上下文名匹配），违例即 panic（越序单元名打印）。第二越序检出：中断上下文调用（中断框架 A2 未成年前用栈探测近似：栈指针范围判断）、deferred 队列外的异步路径两类注入断言检出。第三 ADR 占位：`docs/adr/ADR-001-init-parallelism.md` 占位文档（本条产出），记录"串行假设 + 并行化前置条件清单（A3 SMP 交接 + 锁原语 + 决策评审）"；ADR 编号与协作总台账修订记录对齐。与现存内核衔接点：F0181 编排器是唯一合法调用方；A3 并行化时按 ADR 评审改造。与 Windows 对照：Windows 早年 init 也是串行（`KiInitSystem` 单线程）；假设隐式。本工程显式断言 + ADR 是演进友好设计。判据 UNX-F0184-J1 的复测方式：ktest 越序注入 100% 检出、中断上下文注入检出、deferred 豁免路径不误伤、ADR 文档占位齐。

### UNX-F0185 · CPU 特征统一特征表（CPUID 汇总）
- 域/批：A1/B10｜判据：UNX-F0185-J1 特征位表与 CPUID 原始输出逐位一致，消费方查询 API 冻结｜纯功能行数：320 行（CPUID 采集 120 + 特征表构建 100 + 查询 API 100；测试段不计）｜状态：[已深化]
- **定位**：CPUID 全叶采集（0x0–0x1F + 扩展 0x80000000 系）汇总为统一特征表（feature bitmap + 原始叶缓存），消费方查询 API 冻结。
- **语义边界**：只做"采集与表"（SMP 归 A3、性能计数归 A2）；特征位语义注释规范出处（Intel SDM / AMD APM 双源注记）；未知叶（未来 CPU）保留原始值不猜语义。
- **依赖与嫁接源**：F0090 禁区（大页能力位交叉）、B16 页表族（1G 大页位消费）；嫁接 Linux `cpu_feature_enabled` 与 `cpuid_leaf_data` 缓存思想。
- **风险与回退**：CPUID 序列化问题（低叶需要 CPUID 0 清理序列化副作用）——采集顺序固定并注释；RDTSCP 不存在（老 CPU）时序列化用 CPUID 0x80000003 替代并记账。
- 正文：实现路径分三步。第一采集：叶 0x0 起按 max_leaf 遍历基本叶（0x1/0x7/0x6/0xA...）与扩展叶（0x80000001/0x80000007/0x80000008），每叶四寄存器原始值入缓存数组；采集前 CPUID 0 序列化、闭关中断（窗口计量入 F0196）。第二特征表构建：把散在 ECX/EDX/EBX 的特征位汇总为命名位图（SSE4.2/AVX2/PCID/SMAP/UMIP/1G-page/INVPCID 等 64+ 位），每位注释"叶.寄存器.位 + SDM 条款"；原始叶缓存保留（消费方需全值时取）。第三查询 API：`cpu_has(feat)` 位图查询 + `cpu_leaf(leaf, sub)` 原始查询双入口；API 签名冻结（A2/A3/B16 消费）；ktest 逐位对照（表位 vs 原始叶位重提取比对）。与现存内核衔接点：B16 大页能力、F0193 控制寄存器基线、A2 中断（APIC 位）全消费本表。与 Windows 对照：Windows 的 `SharedUserData->ProcessorFeatures`（KF_* 位）是同位物；本工程带原始叶缓存更全。判据 UNX-F0185-J1 的复测方式：ktest 逐位对照全一致、查询 API 冻结签名断言、未知叶保留断言、序列化顺序注释齐。

### UNX-F0186 · MSR 访问白名单
- 域/批：A1/B10｜判据：UNX-F0186-J1 白名单外 MSR 读写被拦截并记缺陷账，红线（防裸写硬件）｜纯功能行数：260 行（白名单表 90 + 拦截门 90 + 缺陷账 80；测试段不计）｜状态：[已深化]
- **定位**：MSR 访问白名单：A1 域允许的 MSR 集显式列表（EFER/IA32_PAT/MTRR 等），白名单外读写一律拦截记缺陷账——红线"防裸写硬件"。
- **语义边界**：白名单按域划分（A1 只放行本域需要的）；rdmsr/wrmsr 的封装层强制（裸汇编 `rdmsr` 指令在 A1 域代码内被 CI 符号扫描拒绝）；A2/A3 未来扩白名单走评审（白名单版本化 + 修订记录）。
- **依赖与嫁接源**：F0185 特征表（EFER 能力前置）、F0194 PAT/MTRR；红线出处：任务书 §9 硬件数据安全红线；嫁接 Linux `msr_safe` 驱动的白名单思想（科研安全 MSR 访问先例）。
- **风险与回退**：白名单漏项会让正常功能被误拦——每次误拦即缺陷账（缺项候选），修复流程 = 评审 → 白名单版本 +1 → 修订记录；误拦率是白名单质量指标。
- 正文：实现路径分三步。第一白名单表：A1 集合——IA32_EFER（NX 位）、IA32_PAT、MTRR 系（0x200–0x20F + deftype）、IA32_APIC_BASE（只读）、TSC 系列（只读）；每项注释用途与所属条目；表 CRC 封、版本 v1。第二拦截门：`msr_read/msr_write(addr, &val)` 封装——白名单二分查（r/w 分权），越界拒绝并记缺陷账（地址/方向/调用方标签/栈顶符号）；拒绝计数入健康位。第三守门：CI 符号扫描断言 A1 源码零裸 `rdmsr/wrmsr` 汇编（宏展开除外——宏内部才允许）；ktest 越界注入 100% 拦截。与现存内核衔接点：F0193/F0194 全走封装；A2/A3 扩表流程冻结。与 Windows 对照：Windows 驱动 MSR 访问无内核级白名单（驱动即特权）；msr_safe 是 Linux 社区对同类风险的方案。判据 UNX-F0186-J1 的复测方式：ktest 越界注入全拦、白名单内放行、缺陷账齐、CI 裸指令扫描零命中、只读项写拒绝断言。

### UNX-F0187 · 微码加载状态检测（只读）
- 域/批：A1/B10｜判据：UNX-F0187-J1 微码修订号读取与 OS 侧（Windows registry/cpuinfo）对照一致；加载动作不做（归固件，防重复）｜纯功能行数：240 行（修订号读取 80 + 微码能力位 70 + 对照账 90；测试段不计）｜状态：[已深化]
- **定位**：只读检测 CPU 微码状态：修订号（MSR 0x8B Intel / 0x8B AMD 变体语义）、微码加载能力位；**加载动作不做**（归 BIOS/固件，防双载冲突）。
- **语义边界**：**分工声明：内核不做微码加载**（Linux 有 `microcode` 驱动做后期加载；本工程 30 年计划内由固件负责，内核只检测——防重复加载语义冲突，注释规范出处：Intel SDM Vol3 §9.11 微码更新约束）；修订号是"检测面"不是"更新面"。
- **依赖与嫁接源**：F0186 MSR 白名单（0x8B 只读）、F0185 特征表；嫁接 Linux `microcode/intel.c` 的修订号读取口径。
- **风险与回退**：修订号读取在 AMD 平台语义不同（0x8B 是 P-state 相关）——按 vendor 分支（CPUID 0x1 vendor 字段判定）；读数异常（全 0/全 F）记"疑似无微码"账。
- 正文：实现路径分三步。第一修订号读取：Intel 路径——写 0 到 0x8B 再读（标准探测序）；AMD 路径——CPUID 0x80000001 后 MSR 0x8B 读（patch level）；vendor 分支注释规范出处；读数落账（修订号/时间戳字段）。第二能力位：微码更新支持位（CPUID 0x1 EDX bit 不存在——从特征表取 MTRR/EFER 相关间接位）与 BIOS 微码加载证据（SMBIOS Type0 BIOS Version 与已知名单对照）辅助判定；输出"微码状态摘要"（修订号/供应商/疑似固件已载）。第三对照账：ktest 对照判据——修订号读取两次一致（稳定性）+ 与构建环境模拟值（QEMU 固定修订号）对照；真机对照（Windows registry HKLM\HARDWARE\DESCRIPTION\System\CentralProcessor 的 Update Revision）随闸门补测登记。与现存内核衔接点：微码状态入 BootManifest 环境节；F0132 健康位（固件区）。与 Windows 对照：Windows 的微码修订在 `HKLM\...\Update Revision` 可读；Linux /proc/cpuinfo microcode 字段同源。判据 UNX-F0187-J1 的复测方式：ktest 双读一致、vendor 分支正确、异常读数记账、加载动作零存在（符号扫描）、真机对照登记补测。

- 正文：实现路径分三步。第一行大小采集：clflush size 与 L2 行取 max 为 CACHELINE（典型 64）；常量导出全内核。第二对齐声明：共享写清单（per-CPU self_ptr/看门狗戳/EFI 锁状态/时间戳生成器状态）逐项 `#[repr(align(64))]` 断言（编译期）；清单内结构 sizeof 断言不跨界。第三伪共享框架：检测接口（两变量地址差 < CACHELINE 且分属不同逻辑域 → 热点标记）+ 计数账（早年单核基本零命中——框架自检用合成样例验证检出能力）；账落 BootManifest 性能节。与现存内核衔接点：A3 多核的性能基础；F0192 per-CPU 区对齐消费。与 Windows 对照：Windows 的 `DECLSPEC_CACHEALIGN` 同思想；Linux cachealign 惯例同源。判据 UNX-F0195-J1 的复测方式：ktest 清单结构对齐断言全过、伪共享合成样例检出、CACHELINE 常量与 CPUID 一致、清单范围断言。
