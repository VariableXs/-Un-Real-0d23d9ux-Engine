### UNX-F1001 · TSC 跨核同步校验（不变量与残差账）
- 域/批：A2/B11｜判据：UNX-F1001-J1 跨核残差 ≤1µs（QEMU 多核档实测落账），残差账可修正（F0893/F0936 延迟账消费修正值 10/10 次），漂移趋势账（长跑残差趋势可析）｜纯功能行数：360 行（校验器 140 + 残差账 120 + 修正 100；测试段不计）｜状态：[已深化]
- **定位**：TSC 是全核共享计数器但各核读取有采样偏差（跨核读差=核间通信测量误差的底噪）——本条做跨核同步校验：主从校验序列（ BSP 读主值→广播从核读→差值即残差，多轮取分布），残差账（per 核残差/分布/趋势），修正值导出（延迟账（F0893/F0936）消费的修正常量——残差代入修正使跨核测量可信），漂移趋势（残差随温度/负载的长期趋势——随闸门长跑档）。
- **语义边界**：只做校验与修正值；不做同步重写（TSC 不可写——架构只读，同步靠启动期写 TSC（`wrmsr` 同步在 `smp.rs` 启动序——收编不改时序纪律））；修正值是测量校准非硬件修复。
- **依赖与嫁接源**：依赖 `read_tsc`（现存）与 `smp.rs` 启动同步；嫁接源为 Intel SDM §17.15（TSC 同步语义）与 Linux tsc_sync 惯例，只跟随。
- **风险与回退**：残差过大（>10µs——虚拟化 TSC 缺陷/硬件异常）——残差超标红账（跨核测量声明不可信档），延迟账降精度声明（测量精度诚实原则），超标探测（F1007 联动）。
- 正文：实现路径分三步。第一步校验序列：主从式（BSP 发校验 IPI（F0931 notify 面）——各核读 TSC 回报），多轮（100 轮）分布统计（per 核残差直方图），校验时机（启动后+周期低频）；第二步残差账：per 核残差/全核最大/趋势三账，修正值导出（最大残差常量——延迟账修正接口），超标红账（>10µs 降精度声明）；第三步验证：QEMU 四核残差 ≤1µs 实测、修正消费断言（F0893 延迟账代入后精度提升可测）、超标注入 10/10 次降档、趋势账落盘、启动期校验进 F1010 序列断言。与现存内核衔接点：`clock.rs` `read_tsc`/`TscCalibration` 收编挂接、`smp.rs` 校验 IPI。与 Windows 对照：Windows TSC 同步校验（KeQueryPerformanceCounter 底层同面），判据 UNX-F1001-J1 的复测方式：≤1µs、修正 10/10 次、降档 10/10 次、趋势落账。
