### UNX-F5641 · $AttrDef 元文件装载与解析
- 域/批：B3/B03｜判据：UNX-F5641-J1 $AttrDef 条目（类型码/标签/min/max 尺寸四字段）逐条解析与 ntfsinfo 类工具对照一致，样本卷 0 差异｜纯功能行数：270 行（条目结构 100 + 表装载 90 + 对照账 80；测试段不计）｜状态：[已深化]
- **定位**：$AttrDef（MFT 记录 4）是 NTFS 的"属性字典"：每个条目 160 字节，含 Unicode 属性名、类型码、显示偏移/标志、最小与最大尺寸。本条把它从元文件层装载成内存中的属性定义表，是 F5642 校验引擎与 F5643 合法性判定的数据源。
- **语义边界**：只做装载与解析；不做规则校验（F5642）、不做逐属性判定（F5643）、不做 runlist 读取（B04 专属，$AttrDef 的 $DATA 读经 B04 管线）。
- **依赖与嫁接源**：依赖 B01 F5610 自定位链与 B02 F5625 属性遍历器；嫁接源为 NTFS 属性定义表公开语义，只跟随。
- **风险与回退**：$AttrDef 缺失或魔数损坏——按 F5715 元文件缺失分档，装载失败时以"内置 26 常用类型只读字典"降级运行并在装载摘要账（F5615）标注降级原因。
- 正文：实现路径分三步。第一步条目结构解码：160 字节条目按 Unicode 名（64 字节 UTF-16LE）、类型码（4）、显示偏移/字段（8）、标志（8）、最小尺寸（8）、最大尺寸（8）逐字段解析，字段原始值与解析值双记，条目数以遍历终止标记为准并登记入账。第二步表装载：解析结果聚合为 `AttrDefTable`（类型码→定义的只读映射），装载时机挂在 B01 装载状态机 F5608 的"元文件就绪"阶段之后，装载结果（条目数/总字节/是否降级）写入装载摘要账。第三步对照与账：样本卷 $AttrDef 与 ntfsinfo 类工具属性定义视图逐条对照（类型码/min/max 三项），差异即缺陷。与现存内核衔接点：`AttrDefTable` 纯结构新增于 B3 模块族，读取经 `fs23_disk` 通道与 B02 遍历器。判据 UNX-F5641-J1 复测方式：三卷样本对照一致率 100%、降级路径 10/10 次正确标注、解析零 panic。

- **语义边界**：只做 resident 内容尺寸校验；不做 non-resident 尺寸语义（归 B04 F5667）、不做属性内容语义（各型条目自管）、不做修复建议落盘（只出建议账）。

- 正文：实现路径分三步。第一步规则表构建：把 F5641 定义表的 min/max 变成查表函数 `size_rule(type_code) -> (min,max)`，无定义类型返回"无规则"。第二步引擎执行：B02 遍历器每解析出一个 resident 属性，引擎即时校验内容长度（不含属性头），越界（<min 或 >max）属性进分档账：轻微（±字段对齐误差）与严重（结构性越界）两档，轻微放行并记录、严重截断读取并标注。第三步账与复测：校验结果按卷聚合成"规则命中账"（总数/通过/轻微/严重四数），样本卷十类属性注入越界变异各 1 次，10/10 正确分档。与现存内核衔接点：引擎为纯函数族，挂在 B2 `CheckSet` 校验通道，结果进 `timeline.rs` 事件流。判据 UNX-F5642-J1 复测方式：全部样本属性判定与定义表一致、10/10 变异正确分档、引擎零误杀记录在案。

### UNX-F5643 · 属性类型合法性判定（读/写两侧）

- **定位**：属性类型码空间分三区：已定义型（$AttrDef 登记）、保留型（0xFFFFFFFF 结束标记、$LOGGED_UTILITY_STREAM 等系统型）、未知型。本条建立"读侧判定"：遍历中遇到的每个类型码给出三分判定（已知/系统保留/未知），并声明写侧（B12 契约层）将引用同一判定表。
- **语义边界**：只做类型码三分判定与未知型处置策略；不做属性内容解析（各型自管）、不做写侧实现（B12 只引用本表）、不做 $AttrDef 增删（只读）。
- **依赖与嫁接源**：依赖 F5641/F5642；嫁接源为公开类型码表（0x10–0x100 主型 + 0x1000 LOGGED_UTILITY）与 B2 ntfsro 白名单语义，只跟随。
- **风险与回退**：未知型可能是新版 Windows 新增属性——处置策略为"安全跳过 + 事件登记"，绝不因未知型中断整记录解析；事件经 `SecEvent` 通道进 F5694。
- 正文：实现路径分三步。第一步判定函数：`classify_attr(type_code)` 三分返回（Known/SysReserved/Unknown），Known 以 F5641 表为准，SysReserved 硬编码 0xFFFFFFFF（结束标记）与 0x100（$LOGGED_UTILITY_STREAM）。第二步未知型处置：安全跳过——按属性头长度跳到下一属性（B02 F5625 遍历器回调），跳过事件（类型码/位置/记录号三参）入事件账，同一记录未知型计数上限 8，超限按 F5634 损坏分档。第三步两侧账与声明：读侧判定账（三分计数）逐卷聚合；写侧契约（B12 F5822）引用本判定表的声明写进条目账，保证读/写两侧对"什么类型合法"永远同一张表。与现存内核衔接点：判定函数与 ntfsro `WriteOp` 白名单同层对齐（读侧三分为写侧白名单的镜像输入），事件经 `SecEvent` 进 `timeline.rs`。判据 UNX-F5643-J1 复测方式：样本卷含 1 个人工未知型，10/10 跳过正确且记录解析继续、ntfsro 白名单零冲突、三分计数账与实际一致。

- 正文：实现路径分三步。第一步解码：12 字节内容取标志字段（偏移 12 处的 flags，resident 头后），逐位布尔化为四布尔量 + 保留位原值，全部入账。第二步账目联动：dirty 位联动 B01 F5604 装载摘要（同一来源双消费核对）；modify/resize_log/upgrade 三位仅入账并写"需人工关注"建议（不动手）；标志账随 F5615 摘要输出。第三步复测：三样本卷标志读取与 Windows fsutil dirty 查询语义对照（dirty 一致）；变异注入——手工置位四个标志各 1 次跑只读装载，10/10 正确置位且零写盘。与现存内核衔接点：标志账挂在 `self_heal` 通道的只读核对面，事件进 `timeline.rs`。判据 UNX-F5644-J1 复测方式：fsutil 对照 dirty 一致、四标志变异 10/10 正确、保留位原值零丢失。

- 域/批：B3/B03｜判据：UNX-F5657-J1 全卷属性类型码与定义表核对账产出，未登记类型零误判（走 F5643 通道）｜纯功能行数：270 行（核对账 110 + 分界 80 + 复测 80；测试段不计）｜状态：[已深化]
- **定位**：卷上实际出现的属性类型码集合与 $AttrDef 登记集合的差集有三类：实际有而未登记（Windows 运行期动态登记型/第三方型）、登记而无实际（正常）、双向都有但 min/max 与实际尺寸分布矛盾（定义漂移）。本条做差集核对账，与 F5643 逐属性判定分界：那条管单属性，这条管卷级集合。
- **语义边界**：只做集合级核对账；不做逐属性校验（F5642/F5643 已管）、不做定义表修改、不做动态型学习（只识别不登记）。

- 正文：实现路径分三步。第一步集合采集：复用 F5647 扫描通道的属性回调，按卷聚合计数表（type_code→出现次数），零额外 IO。第二步差集核对：三差集产出——未登记集（实际∩¬定义）逐型计数与样本名；登记未现集仅计数；漂移检测对登记型做 min/max 与实际尺寸分布的粗核（min>实际最小即漂移嫌疑，进轻微账）。第三步复测：样本卷构造 1 个未登记型（自定义 0xE0 段），10/10 进未登记集且零误判为 Unknown 中断；正常卷未登记集为空。与现存内核衔接点：核对账挂 `run_b3_format_checks`，F5641 降级联动在案。判据 UNX-F5657-J1 复测方式：未登记型 10/10 正确归类、正常卷零误报、漂移检测对已知型零误报。
