### UNX-F6581 · 每核队列对架构（sq/cq per-CPU）

- **定位**：本批地基条目：把 NVMe 从"单队列对"升级为"每核一对"——8 核模型建 8 对 SQ/CQ，每核的 IO 提交全程只触碰本核队列对（提交路径全本地化），彻底消除跨核共享可变态（锁争用/缓存行弹跳/门铃竞争）。队列对与 A3 的 per-CPU 基建对账（复用其核枚举与亲和机制，不重复建轮子）。
- **语义边界**：只做每核队列对架构与核亲和绑定；不做队列深度协商（F6582 防重）；不做中断向量与队列对的绑定细节（F6567 已立 admin 侧、本条只注记 IO 侧指针）；A3 per-CPU 基建为消费方不重立。
- **依赖与嫁接源**：依赖 F6575 队列协商（Create I/O SQ/CQ 命令底座）与 A3 per-CPU 核枚举基建；嫁接源为 Linux nvme 驱动每核 blk-mq hctx→SQ 映射语义与 Windows stornvme 每核队列组语义，只跟随。
- **风险与回退**：核数与队列对数不匹配（核数超模拟器 QID 上限）——QID 分配器裁断（超限核共享队列对降级档+红账注记），不匹配注入检出；提交路径隐性跨核（伪本地化）——跨核触碰检测探针（队列对结构带 owner 核标记，非 owner 触碰即断言红）。
- 正文：实现路径分三步。第一步架构：每核队列对结构体（SqPair：SQ 基址/SQ tail/CQ 基址/CQ head/P 位影子/QID/CQID/owner 核号八字段）与分配器（QID/CQID 从 F6564 清单后的空闲池分配，admin 对占 QID 0/CQID 0 永久保留），8 核模型分配器产出 8 对全落账。第二步核亲和：每对绑定 owner 核（A3 per-CPU 句柄挂接），提交 API 入口按当核号路由（本地化路由：`sq_pair_of(cpu_id)`），绑定账与 A3 核枚举对账（核号一致断言）；每对独立命令环与独立 cmdid 子空间（F6585 联动）。第三步本地化断言：提交路径逐段标注触碰面（SQ 内存/tail 变量/doorbell 寄存器三类），owner 标记探针断言全本地（无跨核共享可变态）；8 对并发冒烟（每核独立提交千次）零串扰预验；跨核触碰注入（人为从他核提交）必红验证。与现存内核衔接点：现存 nvme.rs 单队列对（QUEUE_ENTRIES=64）保留为对照工具，新架构旁路建立不动旧代码。与 Windows 对照：Windows stornvme 为每核建队列组（GroupAffinity 语义），本内核每核一对+owner 探针更严，判据 UNX-F6581-J1 的复测方式：8 对建立账、亲和对账断言、本地化探针全绿。

- **定位**：任务书样板条目（NVMe I/O 队列对与 doorbell 时序）的三条细化之一：门铃是全内核最脆弱的写点——写早了设备读到空 SQ、写晚了命令滞留、写乱了顺序全毁。本条立门铃写入单点封装：全内核唯一写入口（DoorbellWriter 类型），写序 fence 契约双向强化（提交侧 SQE 可见→Release→写 SQ tail；完成侧 CQE 读全→Acquire→推进 CQ head），绕过封装编译期拒绝（寄存器写入面类型化封死）。
- **语义边界**：只做门铃写入单点与 fence 契约；不做 CQE P 位语义（F6584 防重）；不做竞态注入样本（F6595 防重，本条为机制、那条为攻击面）；admin 队列门铃同样走本封装（单点无例外）。
- **依赖与嫁接源**：依赖 F6581 队列对结构与 A2 的 fence 原语（Acquire/Release 语义）；嫁接源为 Linux nvme 驱动 doorbell write 与 write_combine 语义、C11 内存模型 fence 惯例，只跟随。

- 正文：实现路径分三步。第一步单点封装：DoorbellWriter 类型（每队列对一个实例，内嵌寄存器偏移与上次写入值影子），写入口唯一（`ring_sq_tail(pair, new_tail)` / `ring_cq_head(pair, new_head)` 两个方法，全内核 grep 唯一写点），影子账记录每次写入值与时序序号（可观测账本）。第二步 fence 契约：提交侧——SQE 全字段写完→Release fence→写门铃（契约单测：SQE 未完成即写门铃的注入必红）；完成侧——CQE 读全（数据+P 位+status）→处理毕→Acquire fence→推 head（契约单测：CQE 读一半推 head 注入必红）；fence 契约文档化（契约页：两条时序图+错误示例各一），页归档可检索。第三步编译期拒绝：MMIO 门铃地址只存在于 DoorbellWriter 内部（裸地址类型私有化），绕过封装的裸写无类型入口（编译失败即证）；绕过注入尝试清单（三种典型绕法）逐一编译拒绝验证留痕。与现存内核衔接点：现存 nvme.rs 内联写门铃（unsafe 直写）全部改走封装（行为等价替换，影子账上线）。与 Windows 对照：Windows WDMA 层对寄存器写入有类型化封装（WRITE_REGISTER_* 宏族），本内核类型化单点+fence 契约更严，判据 UNX-F6583-J1 的复测方式：唯一写点 grep、契约注入必红、绕过编译拒绝三证。

### UNX-F6585 · 命令标签分配（cmdid 唯一性）

- **语义边界**：只做 IO 队列 cmdid 分配器；不做块层 tag 池（F6433 防重——tag 与 cmdid 两级标签的关系在本条注记映射契约，本体不重立）；admin 队列 cmdid 复用 F6577 语义不重立。
- **依赖与嫁接源**：依赖 F6581 队列对（子空间挂点）与 F6422 tag 分配器（上层映射参照）；嫁接源为 NVMe 1.4 CID 字段唯一性要求与 Linux nvme command_id 惯例，只跟随。
- **风险与回退**：分配回收不对称（异常路径回收缺失）——回收配对账（F6591 泄漏检测思想下沉），不对称注入检出；映射唯一性被破坏（同 cmdid 双请求并发挂账）——分配器互斥域本地化（每核队列对内分配天然无竞争+调试模式全量探针）。
- 正文：实现路径分三步。第一步分配器：每队列对独立 cmdid 空间（位图分配器，容量=队列深度），分配/回收 API（alloc/free 对称接口），分配账（当前在用数/峰值/累计分配数/累计回收数四计数器）。第二步映射唯一性：cmdid→请求指针哈希表（每队列对一张，容量与深度同），挂账/查账/摘账三操作，挂账时唯一性断言（同 cmdid 二次挂账即 panic——调试模式；生产模式红账+拒绝），摘账时存在性断言（不存在即红账）。第三步压力验证：10^6 次分配/回收循环（模拟器批量档：分配→提交→完成→回收全链），结束后计数器对账（在用数=0 即零泄漏；累计分配=累计回收即对称），零重复探针（全量位图回扫无残留置位）；并发压力档（8 核各自队列对独立跑 10^6，cmdid 子空间隔离零干扰）。与现存内核衔接点：现存固定 cmdid 计数器（wrap 式）升级为位图分配器（行为兼容）。与 Windows 对照：Windows stornvme 以 SrbExtension 生命周期管理命令唯一性（WDF 文档化语义），本内核位图+哈希+探针三重，判据 UNX-F6585-J1 的复测方式：10^6 压力对账、零重复零泄漏探针、并发隔离断言。

### UNX-F6586 · SQ tail 环绕语义（wrap 断言）
