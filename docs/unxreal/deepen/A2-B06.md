### UNX-F0901 · 设备中断统一注册协议（register_irq 契约面）
- 域/批：A2/B06｜判据：UNX-F0901-J1 协议契约冻结（签名+语义文档+消费样例三件齐备），注册全链 10/10 次成功（QEMU NVMe 档端到端），契约违例注入 10/10 次拦截｜纯功能行数：320 行（协议 130 + 全链 110 + 拦截 80；测试段不计）｜状态：[已深化]
- **定位**：设备域（B4）拿中断的唯一入口——本条把"注册一个设备中断"的全链固化为一纸协议：`register_irq(dev_id, trigger, mode)` 返回句柄，内部串联向量分配（F0874 或 MSI-X 槽位 F0872）→绑定（F0867）→handler 挂接（F0903）→能力使能（F0908 MSI-X 时序或 RTE 配置 F0866），协议文档四节（参数语义/返回语义/失败语义/生命周期义务——注册者必须保证 handler 生命周期）；是本域与设备域的第一冻结接口。
- **语义边界**：只做协议与全链编排；不做设备侧实现（B4）；注册内部各步已在本域前批立账，本条是编排器与契约面（组合复用，不重写内部逻辑——单源纪律）。
- **依赖与嫁接源**：依赖 F0874/F0872/F0867/F0903/F0866/F0908 全链；嫁接源为 Linux request_irq 契约（flags 语义/释放义务）与 Windows IoConnectInterrupt 契约语义，只跟随。
- **风险与回退**：注册失败中途残留（分配成功但绑定失败——半注册态）——失败补偿链（逆序回退：已挂 handler 摘除→已绑解绑→已分配释放），补偿链断言（半注册态不可存续——注册表扫描断言），补偿动作账。
- 正文：实现路径分三步。第一步协议面：`register_irq` 签名冻结（dev_id/trigger/mode 三参+flags 预留位），返回句柄结构（中断标识/类/向量或槽位），契约文档四节落档（冻结接口登记表），消费样例（桩设备注册示例）随文档；第二步全链编排：内部五步序（分配→绑定→挂接→使能→确认），每步失败即入补偿链（逆序回退），全链账（步序/耗时/结果）；第三步验证：QEMU NVMe 档注册全链 10/10 次端到端成功（中断真实到达 handler）、契约违例注入（非法 trigger 组合/生命周期违规句柄使用）10/10 次拦截、半注册补偿 10/10 次回退干净（注册表扫描断言通过）、协议文档字段完整性校验。与现存内核衔接点：`apic.rs`/`pci_msi.rs` 编排挂接，接口文件 `irq_api.rs`。与 Windows 对照：Windows IoConnectInterruptEx 同统一入口（内部分线中断/MSI 路径），判据 UNX-F0901-J1 的复测方式：契约三件齐、全链 10/10 次、拦截 10/10 次、补偿 10/10 次。

### UNX-F0902 · MSI-X 多向量设备支持（per 设备多中断队列）
- 域/批：A2/B06｜判据：UNX-F0902-J1 多向量注册正确（NVMe 4 队列 4 向量各到各 handler 10/10 次），向量间无串扰（10 万事件零错队），配额纪律（per 设备上限超限拦截 10/10 次）｜纯功能行数：320 行（多向量 130 + 配额 100 + 验证 90；测试段不计）｜状态：[已深化]
- **定位**：MSI-X 的核心价值是多队列设备每队列独立向量（NVMe IO 队列/网卡收发分列）——本条做 per 设备多向量注册支持（F0901 协议的多槽位扩展：一次注册声明向量数 N，逐槽位分配+逐向量 handler），配额纪律（per 设备向量数上限默认 32，超限拒绝留账——防单设备吃光池），向量-队列映射账（设备声明自己的队列语义，本域只管"第 k 个向量"与 handler 对位）。
- **语义边界**：只做多向量注册面；不做队列业务（设备域）；配额上限可配（cmdline）但默认值是纪律线（修改需红账留痕）。
- **依赖与嫁接源**：依赖 F0872/F0901/F0903；嫁接源为 PCIe Spec §6.1.4（多消息能力）与 Linux pci_alloc_irq_vectors 惯例，只跟随。
- **风险与回退**：设备声明向量数超过其 MSI-X 表大小（谎报）——表大小双重校验（F0871 能力解析值上界），声明越界注册失败红账，防表外写。
- 正文：实现路径分三步。第一步多向量注册：`register_irq_multi(dev, n, handlers[])` 扩展（n ≤ 表大小校验），逐槽位序（分配→绑定→挂接→使能循环），任一槽位失败入补偿链（F0901 链复用逆序清全部），句柄数组返回；第二步配额：per 设备计数账（当前占用/上限/峰值），超限拒绝（Err+账面），配额修改入口（cmdline）红账留痕；第三步验证：NVMe 4 队列注册 10/10 次各向量到各 handler（队列标识断言）、10 万事件零串扰（向量-队列对位账平）、配额超限注入 10/10 次拒绝、谎报注入（n>表大小）10/10 次拦截、补偿链多槽位回退 10/10 次干净。与现存内核衔接点：`irq_api.rs` 扩展。与 Windows 对照：Windows 多消息中断（MsiX 多向量连接同理念），判据 UNX-F0902-J1 的复测方式：多向量 10/10 次、零串扰、配额 10/10 次、谎报 10/10 次。
