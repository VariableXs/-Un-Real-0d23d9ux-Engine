### UNX-F3201 · 原子操作底座与内存序封装
- 域/批：A5/B01｜判据：UNX-F3201-J1 四类内存序（Relaxed/Acquire/Release/SeqCst）各 10^7 次操作落账零异常，序语义对照表与 Rust 参考一致｜纯功能行数：320 行（AtomicU32/U64/usize 语义封装 110 + 内存序注释化语义表与选择指南 90 + fetch 族/compare_exchange 全套包装 80 + 序违规注入检测账 40；测试段不计）｜状态：[已深化]
- **定位**：锁族一切正确性踩在原子操作与内存序上，本条把 core::sync::atomic 的裸接口收敛为全内核唯一原子底座——四种内存序各配语义表与使用判例，fetch_add/sub/or/and/xor 与 compare_exchange 全套带账本包装，是 F3202–F3219 全部锁条目的地基。
- **语义边界**：只做原子封装与内存序语义表；不做锁实现（F3202 起）、不做双宽度原子（DWCAS 属 F3207 依赖面，在本条边界外）、不做用户态原子（varix-std 自带，域外）。
- **判据**：UNX-F3201-J1（见首行）。扩展判据：UNX-F3201-J2 注入"该用 Acquire 处用 Relaxed"样例 20 个，序违规检测账 20/20 标记可疑。
- **依赖与嫁接源**：依赖 core::sync::atomic（no_std 自带）；无上游嫁接；下游被 F3202/F3205/F3207/F3213 全量消费。
- **风险与回退**：内存序误用是最隐蔽的并发缺陷——语义表逐条给出"何时不该用"判例，序违规检测账在调试模式对 acquire/release 配对做静态扫描；某平台原子指令异常时按操作回退到关中断+普通读写序列（性能降级、正确性不降），降级事件入账。
- 正文：实现路径分三步。第一步原子类型封装：为 AtomicU32/AtomicU64/AtomicUsize 提供统一 `Atom` trait，load/store/fetch 族/compare_exchange 全套带默认内存序参数，调用点必须显式写序（禁止隐式默认，防顺手写错）。第二步内存序语义表：Relaxed（计数器、统计）、Acquire/Release（锁握手、发布数据）、SeqCst（跨变量序）四类各配三个正确判例与两个误用判例，注释化语义表落盘为冻结文档（F3217 消费）。第三步序违规检测账：调试模式下扫描 acquire 载荷与 release 载荷的配对关系，发现"只 release 不 acquire"或"SeqCst 与 Acquire 混用同一变量"登记可疑账。与现存内核衔接：`cpu/sync.rs` 现存 AtomicU32 直用点经 F3219 桥改道本底座；与 Windows 对照：Windows `InterlockedIncrement/Exchange` 族即本条的裸形态，WDK 文档明示其 acquire/release 语义变体（InterlockedExchangeAcquire 等），本条语义表与之逐条对齐。判据 UNX-F3201-J1 的复测方式：ktest 原子面四序各 10^7 次（QEMU 批跑）零异常，语义对照表与 Rust 参考逐条 diff 一致。

### UNX-F3202 · 自旋锁基础类型与 RAII 锁守卫
- 域/批：A5/B01｜判据：UNX-F3202-J1 加锁/解锁配对断言 10^6 次零失配，守卫析构强制解锁路径编译期成立（drop 语义验证）｜纯功能行数：280 行（SpinLock<T> 泛型容器 100 + SpinGuard RAII 析构解锁 80 + 释放后数据访问编译期隔离 60 + 解锁状态原子账 40；测试段不计）｜状态：[已深化]
- **定位**：把"锁与它保护的数据"绑成一个类型——`SpinLock<T>` 容器 + `SpinGuard<'a, T>` 守卫，解锁只能经守卫析构，数据只能在持守卫期间访问。这一条类型纪律消灭了"忘了解锁"与"绕过锁摸数据"两大事故类，是全域锁族的类型学基石。
- **语义边界**：只做类型容器与守卫；不做公平排队（F3203）、不做 irqsave 变体（F3207）、不做 per-CPU 优化（F3213）。泛型 T 无内嵌锁要求（嵌套锁由层次表 F3421 管）。
- **判据**：UNX-F3202-J1（见首行）。扩展判据：UNX-F3202-J2 试图在无守卫处访问 T 的样例集编译期 20/20 拒绝（类型系统验证）。
- **依赖与嫁接源**：依赖 F3201 原子底座；现存 `cpu/sync.rs` SpinLock 是升级对象（承接非重复：旧型无泛型数据绑定，本条重构为容器型）；无上游嫁接。
- **风险与回退**：守卫在解锁前被 `forget`（泄漏守卫不解锁）——提供 `ManuallyDrop` 场景审计账，调试模式对泄漏守卫计数告警；中断上下文误用（持守卫期间开中断）由 F3208 类型标注拦截。极端情形回退：容器型可降级为旧裸锁接口（F3219 桥保留双向路径），降级入账。
- 正文：实现路径分三步。第一步容器型：`SpinLock<T>` 内嵌 F3201 原子标志与 `UnsafeCell<T>`，`lock()` 返回守卫，`try_lock()` 非阻塞语义，全部方法 const fn 可静态构造。第二步守卫：`SpinGuard` 实现 Deref/DerefMut 与 Drop——Drop 中原子交换解锁并记账，数据引用生命周期与守卫绑定，守卫死后编译期即无法再摸数据。第三步状态账：locked 标志、持有者核号、持有起始 TSC 三元组原子维护，解锁时校验"解锁者=加锁者"（核号比对），失配即调试账留痕。与现存内核衔接：现存 `cpu/sync.rs` 的 SpinLock（非泛型、无守卫）经 F3219 桥逐调用点迁移到本容器型，旧路径保留。与 Windows 对照：Windows KSPIN_LOCK 是裸字锁、靠 KeAcquireSpinLock/KeReleaseSpinLock 手工配对，配对失误即蓝屏级缺陷；本条把配对义务压进类型系统——对照 Driver Verifier 的"Force pending I/O requests/锁检查"理念，VARIX 用类型与析构在编译期做到 Verifier 在运行期才查的事。判据 UNX-F3202-J1 的复测方式：ktest 锁面配对断言 10^6 次（QEMU 批跑）零失配；J2 样例集编译验证入 CI 断言面。

### UNX-F3203 · ticket lock 队列公平性语义（升级接管现存）
- 域/批：A5/B01｜判据：UNX-F3203-J1 8 核压测下最长等待有界（等待票据差 ≤ 核数上限），FIFO 到达序与获锁序一致率 100%｜纯功能行数：340 行（next/owner 双票据状态机 100 + 公平性断言账 90 + 到达序记账 80 + 溢出回绕处理 70；测试段不计）｜状态：[已深化]
- **定位**：ticket lock 是"先来先服务"的公平锁——到达者领票、owner 票据依序推进，任何等待者都有界等待。本条把现存 `cpu/sync.rs` 的 ticket 语义升级为带公平性账本与有界断言的正式实现，是全域锁公平性的基线参照（qspinlock 的对照物，F3327 公平性账与它对账）。
- **语义边界**：只做 ticket 公平语义与账本；不做排队节点内存分配（qspinlock 归 F3321）、不做自适应后端选择（F3324）。"锁归 A5，醒归 A3"：持锁者释放后不负责唤醒，spin 者自旋观察到 owner 推进即前进。
- **判据**：UNX-F3203-J1（见首行）。扩展判据：UNX-F3203-J2 票据 32 位回绕注入测试（next 与 owner 相差 2^31 时序判定正确）10/10 过。
- **依赖与嫁接源**：依赖 F3201/F3202；承接现存 `cpu/sync.rs` ticket 实现（承接非重复：旧实现无公平性账与回绕验证，本条补齐并接管）；无上游嫁接。
- **风险与回退**：票据回绕边界（2^32 次加锁后）——按无符号减法序比较（(next-owner) as i32 > 0 判定），J2 注入验证；8 核以上压测若公平性失界，回退 F3321 qspinlock 并行实现的对比账定位（两实现并存可切换，参照 F0039 双模开关体例）。
- 正文：实现路径分三步。第一步双票据状态机：next（发票号）与 owner（服务号）两个 AtomicU32，lock 时 fetch_add 领票并自旋等待 owner==自己，unlock 时 owner.fetch_add(1)——全程 F3201 Acquire/Release 序。第二步公平性账本：每次获锁记录"到达票据-获锁票据-等待 TSC 周期"三元组入环形账，压测后聚合出最长等待与 FIFO 一致率。第三步回绕处理：按模 2^32 比较语义实现序判定，注入 next/owner 距 2^31±k 的边界样本验证。与现存内核衔接：现存 `cpu/sync.rs::SpinLock` 即 ticket 雏形（next/owner/contentions/longest_hold 四字段），本条保留四字段语义并补公平性账与回绕验证，`contentions`/`longest_hold` 账面口径与 F3204/F3205 对齐。与 Windows 对照：Windows 未内置公平自旋锁（KSPIN_LOCK 是非公平的），其排队公平由 QueuedSpinLock（内核排队转锁）提供——本条与 F3321 构成同样的两级形态，公平性判据对齐 Windows 排队转锁的 FIFO 语义。判据 UNX-F3203-J1 的复测方式：ktest SMP 面 8 核 10^6 次并发获锁（QEMU 批跑），最长等待票据差 ≤8、FIFO 一致率 100% 落账；J2 回绕样本 10/10 过。

### UNX-F3204 · 锁持有时长账本（TSC 采样）
- 域/批：A5/B01｜判据：UNX-F3204-J1 每锁 longest_hold 以 TSC 周期落账，账面值与注入式已知持有时长偏差 ≤1%｜纯功能行数：240 行（TSC 采样包装 70 + 每锁 longest_hold 原子维护 80 + 持有时长分布分桶 60 + 账本导出接口 30；测试段不计）｜状态：[已深化]
- **定位**："锁被拿了多久"从感觉变数字——每锁记录最长持有 TSC 周期数并按对数分桶落分布，供 O1 性能对标（锁持有是临界区延迟的第一因）与 F3214 粒度审计消费。承接现存 `contentions`/`longest_hold` 字段语义并账本化。
- **语义边界**：只做持有时长采样与账本；不做等待时长（F3212）、不做联合持有（F3216）。采样开销预算：单次 lock/unlock 路径新增 ≤20 TSC 周期（账面留证）。
- **判据**：UNX-F3204-J1（见首行）。扩展判据：UNX-F3204-J2 采样开销断言：带账 lock/unlock 对比裸锁路径开销增量 ≤20 TSC 周期（10^5 次均值）。
- **依赖与嫁接源**：依赖 F3201（原子维护）、`cpu/clock.rs::read_tsc`（现存承接）；无上游嫁接。
- **风险与回退**：TSC 跨核不同步导致的负时长——按无符号回绕比较并记"跨核样本"标记位，可疑样本单独分桶不混入主账；采样开销超标时降级为抽样采样（1/16 采样率），降级开关入账。
- 正文：实现路径分三步。第一步采样包装：lock 入口读 TSC 起始、unlock 出口读结束，差值经回绕安全的减法包装，规避跨核 TSC 漂移的负值陷阱。第二步账本：每锁 AtomicU64 fetch_max 维护 longest_hold，另设十六桶对数分布（复用 F3212 直方图桶界，两账同尺），持有时长事件带核号入每 CPU 环形账。第三步导出：账本快照接口输出（锁名/longest_hold/分布）JSON 行，供 F3214 与 O1 消费。与现存内核衔接：现存 SpinLock 已有 longest_hold 字段与 TSC 采样（`cpu/sync.rs`），本条保留语义、补分布分桶与导出，`read_tsc` 直用不重复封装。与 Windows 对照：Windows 侧锁持有时长的官方观测面是 ETW（Microsoft-Windows-Kernel) 的 Contention 事件与 WPA 的锁分析视图，本条账本以"随时可导出的 TSC 周期数"对齐其可观测性目标。判据 UNX-F3204-J1 的复测方式：ktest 锁面注入已知持有时长（100/1,000/10,000 周期）各 1,000 次，账面 longest_hold 与注入值偏差 ≤1%（QEMU 批跑）；J2 开销断言同面验证。

### UNX-F3205 · 争用计数与缓存行对齐
- 域/批：A5/B01｜判据：UNX-F3205-J1 锁结构体按 64 字节缓存行对齐（align 断言），contentions 计数与压测注入争用次数一致｜纯功能行数：260 行（repr(align=64) 布局定义 60 + 争用计数语义（ticket 差>0 即争用）80 + 缓存行内布局账 60 + 伪共享检测账 60；测试段不计）｜状态：[已深化]
- **定位**：争用计数回答"这把锁有多热"，缓存行对齐回答"这把锁有没有拖累邻居"——两者合成本条：锁结构强制 64 字节对齐杜绝伪共享，争用计数（到达时 owner≠next 即 +1）落账供 F3214 审计与负载分析。承接现存 contentions 字段并补齐对齐纪律。
- **语义边界**：只做对齐与争用计数；不做争用的根因分析（F3214 审计层）、不做迁移（F3330）。
- **判据**：UNX-F3205-J1（见首行）。扩展判据：UNX-F3205-J2 伪共享检测：两锁相邻布置时性能对比（对齐前后吞吐差 ≥10% 可观测）落对照账。
- **依赖与嫁接源**：依赖 F3201/F3203（争用判定复用 ticket 差语义，承接非重复——旧字段无对齐纪律与对照账）；无上游嫁接。
- **风险与回退**：对齐要求导致锁数组内存膨胀（64B×N）——提供紧凑模式（对齐关闭+伪共享接受）开关，默认开对齐，膨胀量入域内存预算账；争用计数在 try_lock 失败路径的口径（计不计入）统一为"计入"，口径写进冻结表。
- 正文：实现路径分三步。第一步布局：`#[repr(align(64))]` 包裹锁结构，编译期 const 断言 size_of ≤64 且 align==64；next/owner/账本字段分列布局表，保证票据对与统计字段不同缓存行。第二步争用计数：lock 到达时若 ticket≠owner 判为争用，contentions.fetch_add(1)——承接现存 `cpu/sync.rs` 判定式零改动（承接非重复，仅补口径冻结与对照账）。第三步伪共享检测账：提供"两锁相邻/隔行布置"的吞吐对照样板（ktest 场景），对照数据入账作为对齐纪律的证据链。与现存内核衔接：现存字段语义保留，迁移经 F3219 桥。与 Windows 对照：Windows 内核的 KSPIN_LOCK 按 processor 缓存行对齐是文档化的最佳实践（LOCK_OPERATIONS 缓存行弹跳分析），WDK 性能指南明示伪共享危害；本条把实践升格为编译期断言。判据 UNX-F3205-J1 的复测方式：ktest 锁面 align 断言 + 8 核争用压测 contentions 与注入次数比对（QEMU 批跑）；J2 对照账同面产出。

### UNX-F3206 · 自旋等待提示与暂停指令策略
- 域/批：A5/B01｜判据：UNX-F3206-J1 等待循环含 spin_loop 提示与 pause 指令档位，三档策略切换落账可导出｜纯功能行数：180 行（pause 指令封装 50 + 三档策略状态机（紧/中/松）70 + 切换账本 30 + 每核偏好配置 30；测试段不计）｜状态：[已深化]
- **定位**：自旋等待的能耗与总线压力由等待方式决定——本条封装 x86 `pause` 指令并交付三档等待策略（紧：纯 spin_loop；中：间歇 pause；松：长 pause 链），等待档位可按核数与争用面配置，切换事件落账。
- **语义边界**：只做等待策略；不做等待时长统计（F3212）、不做后端选择（F3324）。策略只影响自旋节奏，不改获锁语义。
- **判据**：UNX-F3206-J1（见首行）。扩展判据：UNX-F3206-J2 三档策略下 8 核压测吞吐对照账（三档各跑 10^6 次）落盘。
- **依赖与嫁接源**：依赖 core::hint::spin_loop 与 x86 pause（0xF3 0x90）内联；无上游嫁接。
- **风险与回退**：pause 在极老 CPU（不支持 SSE2 前的管线）上行为退化——启动时 CPUID 探测（承接 A1 CPUID 采集账），无 pause 时回退纯 spin_loop 并记档位降级账。
- 正文：实现路径分三步。第一步指令封装：pause 内联汇编包装 + spin_loop 提示统一入口 `wait_hint(level)`，CPUID 探测 pause 可用性（承接现存 cpuinfo 采集）。第二步三档策略：紧档（spin_loop 纯提示，最低延迟）、中档（每 16 次 spin_loop 一次 pause）、松档（连续 pause 链，最低功耗），档位由每核偏好配置与锁类型模板参数两路指定。第三步切换账本：档位切换与生效面（哪些锁用了哪档）落账导出。与现存内核衔接：现存自旋点为裸 `spin_loop()`（`cpu/sync.rs`），迁移经 F3219。与 Windows 对照：Windows 内核自旋等待同样使用 pause（KeStallExecutionProcessor 与自旋路径），其策略不外置；VARIX 把策略做成可配置可观测的三档——对照其"可配置性"增强而非行为分歧。判据 UNX-F3206-J1 的复测方式：ktest 锁面三档各 10^6 次获锁（QEMU 批跑），策略账导出与配置一致；J2 吞吐对照账同面产出。

### UNX-F3207 · 中断保存/恢复型自旋锁（irqsave）
