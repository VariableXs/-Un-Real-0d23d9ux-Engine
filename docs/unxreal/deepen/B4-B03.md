### UNX-F6441 · 调度器注册框架（elevator 抽象）
- 域/批：B4/B03｜判据：UNX-F6441-J1 调度器类型注册/注销/枚举 API 闭合，注册冲突（重名）100% 拒绝；框架零调度器时回退 none 可用｜纯功能行数：361 行（elevator trait 抽象 130 + 注册表与冲突检测 120 + 回退与枚举 111；测试段不计）｜状态：[已深化]
- **定位**：调度器框架是块层的"排班表系统"：定义调度器类型接口（入队/派发/合并钩子/参数面），支持注册/注销/枚举——B04 deadline 与后段 bfq 类调度器都从这里挂入。注销旧语义声明：现存栈无任何调度器分层（直通即行为），框架建立即把"直通"注册为首个调度器类型（none），旧无分层语义正式收编。
- **语义边界**：只做框架与注册表；不做具体调度器策略（F6442 none 本体防重）；框架接口版本化（F6444 契约消费），钩子集合冻结后追加走 ADR。
- **依赖与嫁接源**：依赖 F6437 排序接口与 F6434 ctx 抽象；嫁接源为 Linux elevator 框架（elevator_ops 语义）与 Windows storport 队列策略抽象坐标，只跟随。
- **风险与回退**：钩子集膨胀（每个新调度器加钩子）——钩子全集按"最小完备"立法（入队/派发/合并/超时/参数五钩起步），膨胀走 ADR 审查；注册冲突（重名/重复实现）100% 拒绝。
- 正文：实现路径分三步。第一步 trait：elevator trait 五钩（add_req 入队/dispatch_request 派发/merge 可合并查询/timeout 超时策略/params 参数面）+生命周期对（init/exit），钩子语义逐条注释；trait 对象经 F6437 排序接口操作队列（不越 ctx/hwq 抽象）。第二步注册表：类型注册/注销/枚举三 API，重名注册 100% 拒绝（冲突红账），注销时在用调度器先切换（F6443 协议）；注册表与 B06 设备注册表同构风格。第三步回退：框架零调度器（或注册失败）时强制回退 none 直通可用——"永远有调度器"不变量断言（100 次异常注入回退成功）。与现存内核衔接点：现存直通路径收编为 none 类型默认实现；薄层提交经框架入口（行为等价）。与 Windows 对照：Windows storport 以队列策略抽象支持不同调度行为（WDK 队列语义），本内核显式注册框架+不变量断言，判据 UNX-F6441-J1 的复测方式：注册/注销/枚举三 API 全过、重名注入全拒、零调度器回退 10/10 次成功。

### UNX-F6442 · none 调度器（直通语义）
- 域/批：B4/B03｜判据：UNX-F6442-J1 none 直通零排序零延迟累积，提交即派发；直通路径开销 ≤2% 基线断言｜纯功能行数：321 行（none 实现 110 + 直通路径与统计 110 + 开销断言 101；测试段不计）｜状态：[已深化]
- **定位**：none 调度器是"不调度"的调度器：请求入队即派发、零排序零延迟累积——NVMe 设备自带深度并行（每核队列对），内核少干预即快。none 是多队列时代的主流缺省（Linux 默认 none for NVMe），也是一切性能对照的基线锚。本条以框架 trait 实现直通语义并断言开销 ≤2%。
- **语义边界**：只做 none 直通；不做排序（语义上无）、不做请求重组；直通不绕过保序墙（flush/FUA 与 plug 语义照常）。
- **依赖与嫁接源**：依赖 F6441 trait 与 F6438 快速路径；嫁接源为 Linux none 调度器（mq-noop 语义）惯例，只跟随。
- **风险与回退**：直通风暴（无限流控）——none 本职即不限流（设备 MQES 为天然上限，F6565 仲裁），QD 顶格由标签池兜底；直通计数与排队计数账分列可对。
- 正文：实现路径分三步。第一步实现：none 类型实现五钩——add_req 即派发（移交 hwq）、dispatch 返回下一请求（队列序）、merge 恒否（none 不合并，账面显式）、timeout 默认策略（上抛）、params 空参数面；实现体零堆分配。第二步直通统计：直通路径计数（提交→派发时延采样）账，延迟累积为零断言（排队时长恒零抽样验证）。第三步开销断言：直通路径开销 ≤2% 基线（与 F6438 快速路径同负载对照实测），断言报告落账；none 与框架组合后单请求延迟与裸快速路径一致。与现存内核衔接点：现存直通行为语义等价迁移（旧路径=none 路径），旧调用方零感知。与 Windows 对照：Windows 对 SSD 类设备默认最小队列干预（ storport 直通惯例），本内核以显式调度器类型承载该语义，判据 UNX-F6442-J1 的复测方式：排队时长恒零抽样、开销 ≤2% 断言、merge 恒否注入验证。

### UNX-F6443 · 调度器选择与切换协议
- 域/批：B4/B03｜判据：UNX-F6443-J1 运行期切换协议（排空旧队列→挂新调度器→恢复派发）在途请求零丢失，切换 100 次回归全过｜纯功能行数：321 行（切换协议状态机 110 + 在途排空与迁移 110 + 回归账 101；测试段不计）｜状态：[已深化]
- **定位**：调度器是运行期可换的：NVMe 盘挂 none、机械盘挂 deadline，负载变了还能热切。本条立切换协议三步（排空→挂新→恢复），在途请求零丢失是硬判据——切换不是重建，排队中的请求要完整迁移给新调度器。
- **语义边界**：只做切换协议；不做调度器本体迁移逻辑（各调度器导出迁移钩子实现）；切换期间队列静默语义复用 F6450；设备级切换持久化（重启后保持）留 ADR 后段。
- **依赖与嫁接源**：依赖 F6441 注册表与 F6449 排空原语；嫁接源为 Linux 调度器切换（elevator_switch 语义）惯例，只跟随。
- **风险与回退**：切换途中新请求路由歧义——切换以队列级原子标志推进，新请求在标志未落前按旧调度器入队（队列静止期），标志落定后按新调度器；双态并存不可能断言。
- 正文：实现路径分三步。第一步协议状态机：idle→draining（排空旧队列）→switching（挂新）→running 四态，每态迁移断言；排空=旧调度器队列全请求导出（含 deadline 树内请求的导出钩子）。第二步迁移与挂载：导出请求批量移交新调度器（迁移账守恒：导出数==移交数），新调度器 init 钩子执行（失败即回退旧调度器——切换可回退断言）。第三步恢复与回归：恢复派发（F6449 run），切换全程请求零丢失机检（迁移账+终态账闭合）；切换 100 次回归（none↔deadline 预演档）全过。与现存内核衔接点：现存单调度器（收编 none）无切换路径，纯增量；B04 热迁移（F6469）为本协议的 deadline 专项。与 Windows 对照：Windows 无公开运行期调度器切换面（策略编译期定），本内核热切+零丢失机检为增量能力，判据 UNX-F6443-J1 的复测方式：切换 100 次零丢失、init 失败回退注入 10/10 次、双态并存不可能断言。

### UNX-F6445 · 请求派发预算（dispatch quantum）
- 域/批：B4/B03｜判据：UNX-F6445-J1 单次派发批量上限生效，超预算请求留存下轮；预算参数可调且调整即时生效｜纯功能行数：281 行（预算参数与执行 100 + 轮转续派 90 + 参数热调 91；测试段不计）｜状态：[已深化]

- **语义边界**：只做批量预算；不做时间预算（µs 级时间片留 B04 deadline 参数域）；预算与 plug 解耦（plug 是合并窗口、预算是派发节流）。

- 正文：实现路径分三步。第一步预算执行：派发循环计数到 quantum 即停（留存请求在队列原位），下轮续派（轮转指针不重头）；预算执行账（批大小分布）落账。第二步轮转续派：多 hwq 场景预算按 hwq 轮转均分（防单 hwq 独占一轮）；预算耗尽即返回（中断上下文限时纪律）。第三步参数热调：quantum 运行期可调（cmdline 白名单+运行接口），调整即时生效断言（调整后首批即按新值）；非法值拒绝路径全过。与现存内核衔接点：单 hwq 起步预算单列，扩容后轮转生效。与 Windows 对照：Windows storport 有每 DPC 派发批量限制惯例（中断上下文纪律），本内核参数化+热调+账面化，判据 UNX-F6445-J1 的复测方式：预算上限注入生效、续派不重头断言、热调 100 次即时生效。
