### UNX-F7224 · dm 请求合并窗口（相邻扇区）
- 域/批：B5/B02｜判据：UNX-F7224-J1 相邻扇区读写合并后数据完整性逐扇区校验通过；跨 target 边界请求永不合并（正确性优先于性能）｜纯功能行数：280 行（合并窗口 110 + 边界守卫 80 + 完整性校验 90；测试段不计）｜状态：[已深化]
- **定位**：相邻扇区请求合并是块层经典优化（4 个相邻 4KB 写合成 1 个 16KB 写，减少底层命令数），dm 层的合并窗口只在**同 target 段内**生效——跨 target 边界合并会把两个不同物理去向的请求揉成一个，正确性立即破产。本条立"正确性优先于性能"的合并铁律：边界守卫是硬的，合并且无守卫的路径在代码里不存在。
- **语义边界**：只做同段相邻请求合并；不做底层物理请求合并（B4 域，判例一分层）、不做条带对齐切分（B09）、不做合并排序重排（保持到达序）。
- **依赖与嫁接源**：消费 F7205 换算核心与 F7212 拆分器；嫁接源为 Linux `dm_merge_bvec`/blk merge 窗口语义，只跟随。
- **风险与回退**：合并窗口把保序语义弄乱（后到相邻写与先到不相邻写交错）——合并只接受"窗口内已到达且序号连续"的请求对，序号断开的相邻扇区不合并不等待，保序账（F7213）在合并前后各自守恒断言。
- 正文：实现路径分三步。第一步合并窗口：同 target 段内，到达序连续且扇区相邻（后请求起点=前请求终点）的请求对合并为一个，合并方向必须一致（读写不混），窗口上限 128 扇区（防巨型请求拆分反噬），窗口参数 cmdline 白名单可调；第二步边界守卫：合并候选对先过"同 target 段"断言（换算结果 target 上下文指针相等），不等即放弃合并直传——守卫在合并函数首行，无任何绕过路径；第三步完整性校验：ktest 以扇区号签名模式写入相邻序列，合并开启前后数据逐扇区比对（合并是传输优化不是数据变换），比对工具随 F7220 常驻。与现存内核衔接点：`dm/merge.rs` 新建，合并发生在 per-target 队列入队前，与 F7213 保序账共用序号空间。与 Windows 对照：Windows Storport 的 SRB 合并（SRB_FLAGS_ 相邻请求聚合）与文件系统 FsRtl 的相邻写聚合同源，Windows 合并同样受边界约束（卷成员边界不跨）。判据 UNX-F7224-J1 的复测方式：相邻写合并后逐扇区签名校验 10 万扇区零错、边界跨越注入 1000 对全部不合并、合并率统计账与预期窗口参数一致。

### UNX-F7225 · dm 错误重试策略（可重试错误分类）
- 域/批：B5/B02｜判据：UNX-F7225-J1 可重试类（暂态介质忙）与不可重试类（介质损坏/表无效）分类断言 100% 正确；重试仅对可重试类生效｜纯功能行数：280 行（错误分类表 90 + 重试引擎 100 + 分类断言 90；测试段不计）｜状态：[已深化]
- **定位**：错误重试是"粘性"与"无害"的平衡术：暂态错误（介质忙、队列满）重试无害且提高成功率，永久错误（介质损坏、表无效）重试是浪费甚至放大损害（对坏块反复写可能加速介质退化）。分类表是重试引擎的宪法——分类错一档，行为错一世界。
- **语义边界**：只做 dm 层错误分类与重试；不做底层盘自身重试（B4 域）、不做上层文件系统重试（A 部域）、不做错误上报策略（F7215 传播协议）。
- **依赖与嫁接源**：消费 F7215 错误码协议与 F7222 聚合账；嫁接源为 Linux dm 重试惯例（`DM_ENDIO_REMAP` 与 blk 域 REQUEUE）与 SCSI/ATA 错误分类惯例，只跟随。
- **风险与回退**：分类表漏项（新错误码未归类）——分类表以白名单双列（可重试/不可重试）封闭枚举，表外错误码默认不可重试并落"未分类"红账催补表，默认保守是原则。
- 正文：实现路径分三步。第一步分类表：错误码双列封闭分类——可重试列（介质忙/队列满/资源暂缺三类）、不可重试列（介质损坏/表无效/只读拒绝/白名单拒绝等全部其余），静态 const 表实现，编译期穷举 dm 错误码空间（F7215 前缀位两类各自穷举）；第二步重试引擎：仅可重试类进重试引擎——退避间隔（指数退避，起 1ms 封顶 128ms）、重试计数挂请求体、重试请求走完整下传路径（不绕 F7228 写闸门——重试的写也是写）；第三步分类断言：ktest 对全部错误码逐个注入，断言分类结果与声明表一致、重试引擎对不可重试类零触发。与现存内核衔接点：`dm/retry.rs` 新建，退避计时复用内核定时器原语。与 Windows 对照：Windows 存储栈 Storport 的总线复位重试（SRB_STATUS_BUS_RESET 可重试）与介质错误（SCSI sense key MEDIUM ERROR 不重试）分类同源，ClassPnP 的 SenseData 解码即分类表。判据 UNX-F7225-J1 的复测方式：全部错误码注入分类断言 100% 与表一致、可重试类重试生效（重试计数递增）、不可重试类零重试。

### UNX-F7226 · dm 重试上限与永久失败标注
- 域/批：B5/B02｜判据：UNX-F7226-J1 达到重试上限后请求按永久失败标注并上抛（不静默吞）；上限值可配置且越界配置被拒｜纯功能行数：240 行（上限协议 80 + 永久失败账 80 + 配置校验 80；测试段不计）｜状态：[已深化]
- **定位**：重试上限是"粘性兜底"的止损线：没有上限的重试=请求永远不完成=上层挂死。达到上限的请求必须以"永久失败"身份上抛——永久失败与普通失败的差别在标注：永久失败触发上层（fsync 承诺、备份校验链）的严重错误处置，普通失败可能只是慢。上限可配置但配置本身要被校验（0 或负值即"禁重试"必须显式声明，越界值拒绝）。
- **语义边界**：只做上限与永久失败标注；不做上层对永久失败的处置策略（各消费域自管）、不做重试分类（F7225）。
- **依赖与嫁接源**：消费 F7225 分类表与重试引擎；嫁接源为 Linux dm 重试上限惯例与 Windows 类驱动重试上限（ClassPnP MaximumRetryCount）语义，只跟随。
- **风险与回退**：上限配置过小（正常暂态抖动也被判死）——缺省值 8 次按经验值设定，配置变更走 cmdline 白名单并落配置审计账，越界值（>100 或 <0）拒绝并留账。
- 正文：实现路径分三步。第一步上限协议：请求体重试计数达上限即转"永久失败"态（请求体标注位），引擎不再排队、请求按 F7215 协议带 DM_ERR 前缀"retry-exhausted"码上抛，重试史（每次错误码+时间戳）随请求归档；第二步永久失败账：永久失败请求进入专门失败账（与普通失败分列），账目条目含（请求签名/重试次数/错误史摘要），供 B25 断电链与备份校验链消费，账目只增；第三步配置校验：上限值经 cmdline 白名单解析（F0016 同族纪律——B5 域的 dm.retry_max 键），越界拒绝并留账，拒绝动作可审计。与现存内核衔接点：`dm/retry_cap.rs` 新建，cmdline 键注册走 F0016 白名单协议。与 Windows 对照：Windows 磁盘类驱动对 SRB 重试有隐式上限（超过即报 STATUS_IO_DEVICE_ERROR），事件日志记 disk 错误（Event ID 7/51），本内核把上限显式化并可审计。判据 UNX-F7226-J1 的复测方式：注入持续暂态错误达上限 100 轮全部按永久失败上抛、错误史归档完整、上限配置 5 组合法值生效/5 组越界值全拒留账。

### UNX-F7231 · dm 超时请求取消与排空
- 域/批：B5/B02｜判据：UNX-F7231-J1 超时请求取消后其全部子请求有终态（取消/已完成二选一，零悬挂）；排空期间新请求按明确错误拒绝｜纯功能行数：300 行（取消协议 110 + 子请求排空 100 + 终态断言 90；测试段不计）｜状态：[已深化]
- **定位**：取消是块层最危险的动词——取消一个可能已在底层执行的写请求，语义上"不知道写没写进去"，上层必须按不确定处理。本条的纪律：取消只对超时请求生效（F7230 两道闸之后）、取消后全部子请求必须有终态（零悬挂）、排空期间新请求明确拒绝——"零悬挂"是 fsync 承诺（B2 域）能建立在 dm 之上的前提：任何请求任何时刻都有确定状态。
- **语义边界**：只做取消与排空协议；不做底层介质级中止（B4 域接口能力决定，dm 只发取消意图）、不做取消后的数据恢复（上层域）。
- **依赖与嫁接源**：消费 F7222 父子账与 F7214 quiesce；嫁接源为 Linux blk-mq timeout 的 abort 语义与 Windows SRB abort 流程，只跟随。
- **风险与回退**：取消与完成赛跑（取消发出瞬间请求完成了）——终态裁决唯一化：完成回调与取消路径竞争同一终态标记（CAS 先到先得），败者路径空转，绝不双终态；取消后写请求的数据不确定性由上层协议处置（fsync 承诺把不确定写视为未确认写）。
- 正文：实现路径分三步。第一步取消协议：观察标请求二次超时触发取消——取消意图下传 B4（B4 能力范围内尽力中止），dm 层不等介质确认，直接把请求终态定为"取消"（与"完成""失败"并列第三终态），终态 CAS 保证唯一；第二步子请求排空：取消父请求时沿 F7222 父子账遍历全部子请求，未完成子请求逐个取消（同协议），断言"全部子有终态"后父终态才可落——排空是父取消的前置；第三步排空期拒绝：取消排空进行中，同设备新请求按 DM_ERR 前缀"draining"码明确拒绝（不是排队不是挂死），排空完成自动恢复放行。与现存内核衔接点：`dm/cancel.rs` 新建，终态标记并入 F7205 终态账枚举（终态从两态扩三态，全链断言同步）。与 Windows 对照：Windows SRB abort 后 SRB 以 SRB_STATUS_TIMEOUT 完成，请求不会无限悬挂（类驱动保证终态），排空期新请求在队列暂停（WDF queue stop）返回状态码。判据 UNX-F7231-J1 的复测方式：超时取消 100 轮全部子请求有终态零悬挂、取消/完成赛跑注入 1000 轮终态唯一、排空期新请求 100% 明确错误即时返回。

- **定位**：bio 资源池是 dm 请求的内存来源：no_std 内核无堆依赖的 IO 路径必须池化（静态分配的请求槽位环）。池耗尽路径的纪律是数据安全域的格言级要求：**明确错误优于静默挂死**——挂死的请求让上层 fsync 永不返回（系统假死），明确错误让上层立即重试或降级。
- **语义边界**：只做池与 OOM 协议；不做物理页分配（AI-04 域）、不做池容量的自适应扩容（静态容量是安全属性——扩容可能吃光系统内存，扩容走 ADR）、不做请求池与克隆池的合并（分池分账，防互相挤兑）。
- **依赖与嫁接源**：消费 F7205 请求结构与 F7221 克隆；嫁接源为 Linux mempool 语义（保证最小并发的预留池）与 Windows NP 池配额惯例，只跟随。
- **风险与回退**：池被某一高频路径独占（拆分风暴吃光池）——预留池思想：主池+预留池（预留池仅服务"在途请求的子请求拆分"这一必需路径），主池耗尽走 OOM 错误时预留池仍有拆分能力，在途请求永不因池耗尽而悬挂。
- 正文：实现路径分三步。第一步池结构：请求槽位静态数组+空闲位图（位图 O(1) 分配），主池 4096 槽、预留池 512 槽，分池分账（各自占用计数/高水位/耗尽计数），槽位归还带指纹校验（归还非本池槽位即红账——内存安全断言）；第二步 OOM 协议：池耗尽按 DM_ERR 前缀"pool-exhausted"码明确失败（请求快速失败，不等待不重试不静默），耗尽计数落账，耗尽率随 F7229 账可查（耗尽频繁=池容量配置问题的信号）；第三步泄漏断言：池归还 10 万次后占用计数精确归零、高水位记录与峰值断言一致、归还指纹校验注入错池用例 10/10 次红账捕获。与现存内核衔接点：`dm/pool.rs` 新建，静态内存在 dm 模块初始化期一次性分配（F0013 早年堆之后、块设备注册之前）。与 Windows 对照：Windows 内核 NP 池耗尽返回 STATUS_INSUFFICIENT_RESOURCES（明确失败），mempool 的预留思想在内核池 lookaside list 同构。判据 UNX-F7238-J1 的复测方式：池耗尽注入 100 轮全部明确错误即时返回、预留池在主池耗尽时保持拆分能力验证、10 万次归还真零泄漏。
