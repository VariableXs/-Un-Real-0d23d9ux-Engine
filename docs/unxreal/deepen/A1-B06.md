### UNX-F0101 · VGA 文本模式后备通道
- 域/批：A1/B06｜判据：UNX-F0101-J1 帧簿不可用时自动落 VGA 文本通道输出，切换零丢行｜纯功能行数：280 行（文本缓冲写 90 + 滚动与光标 90 + 通道注册 100；测试段不计）｜状态：[已深化]
- **定位**：实装 VGA 文本模式 0xB8000 通道，作为帧簿（fbcon）不可用时的硬后备输出。
- **语义边界**：只支持 80x25 标准文本模式与属性字节；图形化显示归帧簿通道（F0103）；本通道无色彩语义细分（属性字节直写由 F0110 映射）。
- **依赖与嫁接源**：F0010 双通道抽象注册表；嫁接 Linux `vt.c` 的 console 写路径与 `vgacon` 滚动语义。
- **风险与回退**：VGA 内存窗口在某些 UEFI 机器上不可用（无 CSM）——探测 0xB8000 响应（写读回比较）失败即标记通道 dead 并跳过；dead 通道仍占注册位保序。
- 正文：实现路径分三步。第一通道实装：`vgacon_write(str, len)` 直写 0xB8000 偶字节字符/奇字节属性，光标硬件端口 0x3D4/0x3D5 同步；探测函数启动时写-读回 0xB8000 首格验证窗口存活。第二滚动：写满 25 行触发整屏 memcpy 上滚（硬件无平滑滚动），顶行内容压入历史缓冲（供 F0111 回看）；光标越界钳位。第三注册与切换：向 F0010 注册为"fallback 级"通道，帧簿探测失败（fb tag 缺失或映射失败）时仲裁器（F0104）自动切本通道；切换时重放最近 8 行（零丢行判据），重放计数落账。与现存内核衔接点：是 F0010 抽象的第一个实装通道；F0119 早期探针的最简输出口。与 Windows 对照：Windows 早年蓝屏文本输出走 `HalDisplayString`（VGA 文本模式 80x50/25），现代 Win10+ 改用图形蓝屏；本通道同语义，是"黑屏诊断"的兜底。判据 UNX-F0101-J1 的复测方式：ktest 模拟帧簿不可用场景断言自动切换、切换前后逐行比对零丢行、VGA 窗口探测失败时通道标记 dead 且不阻塞引导。

### UNX-F0102 · 16550 串口全速通道
- 域/批：A1/B06｜判据：UNX-F0102-J1 波特率 115200 下 1MB 输出零错位零丢字符（环回/对端计数核验）｜纯功能行数：300 行（UART 驱动 130 + FIFO 流控 90 + 计数核验 80；测试段不计）｜状态：[已深化]
- **定位**：实装 16550 UART 串口通道（115200-8N1，FIFO 启用），作为最可靠的引导诊断出口。
- **语义边界**：只做轮询模式（无中断，早年中断系统未建）；LSR 超时（THRE 永空）即判定端口死并记账；参数定制归 F0109。
- **依赖与嫁接源**：16550 数据手册寄存器语义（THR/RBR/LSR/FCR）；嫁接 Linux `early_serial8250` 轮询驱动。
- **风险与回退**：输出阻塞会冻死引导——LSR THRE 等待带超时（时钟 TSC 计 10ms），超时丢本字节记账继续（丢字节计数显性化优于冻死）；FIFO 未启用老旧芯片退化为逐字节模式。
- 正文：实现路径分三步。第一驱动实装：初始化序列（LCR DLAB→DLL/DLH 波特率除数 1→LCR 8N1→FCR FIFO 使能→MCR DTR/RTS），`serial_putc` 轮询 LSR bit5（THRE）后写 THR；探测时读 LSR 确认端口存在（0xFF 是死口特征）。第二流控：发送循环内检查超时与 FIFO 标志，换行 `\n` 自动补 `\r`（终端兼容）；输入路径（诊断模式 F0114 用）轮询 LSR bit0 读 RBR。第三计数核验：发送计数器/丢字节计数器落账，ktest 提供环回模式（MCR loopback 位）自发自收 1MB 数据逐字节比对；对端核验依赖串口对端 echo（实机随闸门补测）。与现存内核衔接点：F0119 早期探针首选出口；F0108 panic 快照吐出口；F0117 远程镜像源。与 Windows 对照：Windows 内核调试走 `KdSerial`（1394/USB3/NET 时代前的 COM 基础），`bcdedit /debug` 配置与 `KDNET` 演进；本通道等价 KdSerial 的 COM 模式。判据 UNX-F0102-J1 的复测方式：ktest 环回模式发送 1MB 伪随机流断言零错位零丢、超时注入（FIFO 禁用）时丢字节计数显性、波特率寄存器值 115200 对应除数 1 复核。

### UNX-F0103 · 帧簿控制台字体渲染
- 域/批：A1/B06｜判据：UNX-F0103-J1 8x16 位图字体全字符集渲染，可变分辨率下行列自适应无破版｜纯功能行数：320 行（帧簿写 90 + 字体引擎 110 + 自适应布局 120；测试段不计）｜状态：[已深化]
- **定位**：实装帧簿（Limine framebuffer tag）8x16 位图字体控制台，按分辨率自适应行列数。
- **语义边界**：只支持内嵌 8x16 ASCII+Latin-1 位图字体；中文等宽字形属图形栈（阶段 3）；色彩像素格式（RGB/BGR）按帧簿 tag 参数适配。
- **依赖与嫁接源**：Limine framebuffer tag（bpp/pitch/内存地址）；内嵌字体取自 Public Domain VGA ROM 字体；嫁接 Linux `fbcon` 的 `ops->putcs` 分层。
- **风险与回退**：非标准 bpp（24bpp）路径易错——渲染层以像素尺寸参数化，bpp 分支全覆盖测试；帧簿 tag 缺失回退 VGA 通道（F0101）。
- 正文：实现路径分三步。第一帧簿层：读 tag 得 `address/width/height/pitch/bpp`，映射后建"屏幕像素画布"句柄；清屏函数按 bpp 分支填充背景色。第二字体引擎：8x16 字形表按 ASCII 索引，`putchar(x,y,ch,fg,bg)` 逐位展开写像素，bpp 分支（32/24）内联展开；换行/退格/回车控制符处理。第三自适应布局：行列数 = `width/8`、`height/16` 取整，边缘残像素留黑；分辨率变化（多显示器未来）时重算并重绘最近内容；渲染输出计数与行列尺寸落账。与现存内核衔接点：是 F0010 抽象的主通道实装；F0104 仲裁器选它的条件是 tag 有效；F0110 色彩语义经它渲染。与 Windows 对照：Windows 图形控制台在 `RdpI386InitializeDisplay` 后由 `Boot Vid` 通道画字符（winload 的 `BlDisplayString`），同为本工程"图形可用即用图形"路线；Linux `fbcon` 的 `bitblit` 是字形展开同源。判据 UNX-F0103-J1 的复测方式：ktest 对三种模拟分辨率（1920x1080/1280x720/640x480）断言行列自适应正确、全 ASCII 字形渲染后像素哈希与预期一致、边缘无破版（出界写零次）。

### UNX-F0104 · 双通道仲裁与降级策略
- 域/批：A1/B06｜判据：UNX-F0104-J1 通道优先级仲裁可配置，主通道故障 100ms 内降级零丢失｜纯功能行数：240 行（仲裁器 90 + 健康探测 70 + 降级重放 80；测试段不计）｜状态：[已深化]
- **定位**：对串口/帧簿/VGA 三通道做优先级仲裁与健康探测，主通道故障时自动降级并重放未确认日志。
- **语义边界**：仲裁粒度"通道级"（非单条日志）；探测周期 50ms 固定；重放只到"存活的次级通道"。
- **依赖与嫁接源**：F0010 抽象注册表；嫁接 Linux `console_drivers` 的 unregister/re-register 降级链思想。
- **风险与回退**：降级风暴（反复切通道抖动）——降级后需健康连续 3 次探测通过才允许回升；仲裁配置 cmdline 可覆盖（`console=` 序），非法配置走 F0016 白名单拒绝。
- 正文：实现路径分三步。第一仲裁器：注册表按优先级排序（默认串口>帧簿>VGA，cmdline 可改），写日志先投递主通道；仲裁器持锁保证多核早年（B17 后）串行写。第二健康探测：每通道带 `is_alive` 探针（串口 LSR 超时计数、帧簿 tag 有效性、VGA 窗口响应）；主通道连续 2 次探针失败即判死，100ms 内完成切换（判据阈值）。第三降级重放：切换时把"当前未确认行缓冲"（最近 8 行）重放到新主通道，重放计数与切换事件落账；全部通道死亡时静默挂起（无通道可写，引导继续但日志丢弃计数显性化）。与现存内核衔接点：是 F0010 框架的运行时大脑；F0107 环形缓冲与仲裁器解耦（缓冲先落，通道后投）。与 Windows 对照：Windows 蓝屏输出在 `KdDebuggerEnabled` 失败时落 VGA 蓝屏，无多通道重放语义；Linux `printk` 的 console switch 重放（`console_trylock` 后 replay）是同源思想。判据 UNX-F0104-J1 的复测方式：ktest 模拟主通道探针失败断言 100ms 内切换、重放零丢行、回升需 3 次健康、配置非法走拒绝账。

### UNX-F0105 · 日志级别体系（debug–fatal）
- 域/批：A1/B06｜判据：UNX-F0105-J1 五级过滤编译期+运行期双控，级别错误路由检出 100%｜纯功能行数：220 行（级别常量与宏 70 + 运行期过滤 80 + 编译期裁剪 70；测试段不计）｜状态：[已深化]
- **定位**：建立 debug/info/warn/error/fatal 五级日志体系，编译期与运行期双控过滤。
- **语义边界**：只管级别路由与过滤；格式规范归 F0118；级别与色彩映射归 F0110。
- **依赖与嫁接源**：嫁接 Linux `KERN_DEBUG..KERN_EMERG` 语义与 `pr_debug` 编译期裁剪、`loglevel` 运行期语义。
- **风险与回退**：fatal 级被过滤掉是最危险错误——fatal 无条件输出（编译期裁剪不含 fatal）；运行期过滤下界钳位（不允许过滤到 fatal 之下）。
- 正文：实现路径分三步。第一常量与宏：五级数值 0–4（fatal 最高），宏 `klog(level, tag, fmt, ...)` 展开为先查编译期裁剪表（`CONFIG_LOG_LEVEL` 之下的 debug 全剔除、fatal 永留）、再调运行期过滤器。第二运行期过滤：全局级别变量（cmdline `loglevel=` 设置）+ 子系统覆盖表（F0113 扩展），级别 < 全局下界的直接丢弃并计数；级别错误（fatal 走 info 宏）由 lint 式断言在 ktest 中检出。第三双控验证：ktest 构造"编译期裁剪+运行期过滤"正交矩阵（3 编译档 × 5 运行档）逐一验证路由正确、fatal 穿透全档。与现存内核衔接点：全部 A1 条目日志经本宏；F0106 时间戳、F0118 格式在本宏下游。与 Windows 对照：Windows 的 `DbgPrintEx` 有 DPFLTR 级别与组件过滤（注册表可调），编译期裁剪无；Linux 组合更接近本设计。判据 UNX-F0105-J1 的复测方式：ktest 正交矩阵 15 组合全验证、错误级别路由注入 100% 检出、fatal 过滤尝试被钳位拒绝。

### UNX-F0106 · 日志时间戳（TSC 换算）
- 域/批：A1/B06｜判据：UNX-F0106-J1 时间戳微秒级单调递增，与 TSC 频率校准偏差 <1%｜纯功能行数：220 行（TSC 读取 60 + 频率校准 100 + 单调保证 60；测试段不计）｜状态：[已深化]
- **定位**：为日志提供微秒级单调时间戳：TSC 读数 × 校准频率，并完成早期 TSC 频率标定。
- **语义边界**：只服务日志与性能记账（F0099）；墙钟时间归 RTC/PIT 域（A1 后期）；TSC 不变式（invariant）缺失时降级 PIT 估频并标注。
- **依赖与嫁接源**：RDTSC/RDTSCP 指令；Calibrate 用 PIT Channel 2 或 ACPI PM Timer 双法；嫁接 Linux `tsc_init` 的 `calibrate_tsc` 双源交叉思想。
- **风险与回退**：频率错 1% 会让"引导耗时"数据全偏——双源校准互差 >1% 时取 PIT 并告警；虚拟化环境 TSC 变速（TSC scaling）时读 MSR 检测并标注"unstable"。
- 正文：实现路径分三步。第一校准（PIT 法）：PIT 通道 2 设 50ms 定时，TSC 起止读数差 ÷ 50ms 得频率；交叉法（ACPI PM Timer，若 FACP PM_TMR 可用）独立测一遍，两值互差落账。第二换算：`us = (tsc - boot_tsc) * 10^6 / freq`，用 u64 全精度除法（避免浮点）；换算函数纯函数化可测。第三单调保证：读数用 RDTSCP（多核序列化），时间戳生成器持最近值，新值 < 旧值即记"回退"账并输出钳位值（单调性优先于真实值）；boot_tsc 基准点在 F0119 探针就绪后固化。与现存内核衔接点：F0099 性能记账消费频率值；B17 多核后时间戳仍单点生成（不引入多钟）。与 Windows 对照：Windows 的 `KeQueryPerformanceCounter` 早期由 HAL 用 PM Timer，TSC invariant 就绪后切 TSC；本工程同路线但引导期即标定。判据 UNX-F0106-J1 的复测方式：ktest 断言双源互差 <1%、1 万次采样单调、注入时钟回退场景钳位有账、校准值与模拟 PIT 频率偏差 <1%。

### UNX-F0107 · 日志环形缓冲持久化
- 域/批：A1/B06｜判据：UNX-F0107-J1 缓冲满覆盖策略生效，重启后最近 N 条可从保留区找回｜纯功能行数：280 行（环形缓冲 110 + 持久保留区 90 + 找回通道 80；测试段不计）｜状态：[已深化]
- **定位**：日志写入 1MB 环形缓冲并镜像到持久保留区，重启后最近日志可找回（跨引导取证）。
- **语义边界**：只缓存日志行；二进制 dump 归 panic 批；保留区与 F0066 内存图快照区相邻但独立。
- **依赖与嫁接源**：F0011 环形缓冲框架实装；嫁接 Linux `printk` 的 `log_buf` 环形结构与 pstore 的 RAM backend 思想。
- **风险与回退**：并发写竞争（B17 后）——写指针原子递增（x86 `lock xadd`），行封装带序号与长度；保留区 CRC 逐条校验，坏条跳过不中断。
- 正文：实现路径分三步。第一环形缓冲：1MB 缓冲按"序号 + 长度 + 正文"三元组存行，写指针原子递增，满则覆盖最老行（覆盖计数落账）；读侧按序号遍历（跳过撕裂行）。第二持久镜像：每写 16 行或 fatal 级立即把缓冲尾窗刷入持久保留区（64KB 窗滚动），刷前 CRC 逐条、刷后写"落盘水位"指针；下次引导启动时读到旧窗即挂"上次引导"账。第三找回通道：`klog_dump_prev()` 按水位导出上次引导最近 N 行（默认 256），供 F0108 与 ktest 消费；导出内容与主日志格式一致（F0118 解析器可直接读）。与现存内核衔接点：F0108 panic 快照取自本缓冲；B13 早传把"上次引导日志摘要"纳入早传内容。与 Windows 对照：Windows 蓝屏后日志经 crash dump 落盘（页文件通道），无 RAM 环形跨引导；Linux pstore/ramoops 是同构先例。判据 UNX-F0107-J1 的复测方式：ktest 写 2MB 触发覆盖断言覆盖计数、模拟重启找回最近 256 条逐条 CRC 过、撕裂行注入被跳过有账。

### UNX-F0108 · panic 前日志快照
- 域/批：A1/B06｜判据：UNX-F0108-J1 panic 时最后 256 条日志经串口完整吐出，抓取成功率 10/10｜纯功能行数：260 行（快照组装 80 + 串口倾泻 100 + 成功率账 80；测试段不计）｜状态：[已深化]
- **定位**：panic 触发时立即组装最近 256 条日志快照并经串口全速倾泻，是事故现场的第一证据。
- **语义边界**：只吐日志（文本）；寄存器/栈快照归 panic 批本体；倾泻是 fire-and-forget（不等对端确认）。
- **依赖与嫁接源**：F0107 环形缓冲 + F0102 串口通道；嫁接 Linux `dump_stack` 前的 `console_flush_on_panic` 语义。

- **风险与回退**：格式串与参数不匹配是 classic CVE 源——编译期 `__attribute__((format(printf)))` 检查 + 运行期格式符白名单双门；异常格式串按字面输出并记账。
- 正文：实现路径分三步。第一格式化器：状态机解析格式串，支持集 {%%,%s,%d,%i,%u,%x,%p,%c,%lld,%llu,%llx}，参数寄存（x86-64 SysV 传参序）按类型取值；输出缓冲硬上限 512 字节，截断记"truncated"标记。第二安全门：`%n` 遇到即整串按字面输出并记账（安全事件）；`%s` 参数空指针输出 `(null)`；浮点不支持（字面输出并计数）。第三 fuzz 框架：ktest 内置固定种子 LCG 生成随机格式串（含嵌套 %%、截断 %、超长 %s）与随机参数 1 万组，断言无越界（哨兵页检测）、无崩溃、输出缓冲 CRC 完好。与现存内核衔接点：全部日志宏的格式化出口；诊断 UI 的字符串拼装复用。与 Windows 对照：Windows 的 `RtlStringCbVPrintfA`（Safe CRT）同题；Linux vsnprintf 是内核事实标准。本工程子集实现换 no_std 可控性。判据 UNX-F0116-J1 的复测方式：ktest fuzz 1 万次哨兵页零越界、%n 注入被禁绝有账、合法格式输出与参考实现逐字节一致（对照 1000 例）。

- 域/批：A1/B06｜判据：UNX-F0117-J1 第二串口镜像主日志，镜像流与主通道 diff 一致（开发机双口验证）｜纯功能行数：240 行（镜像挂接 80 + 流量整形 80 + diff 工具 80；测试段不计）｜状态：[已深化]

### UNX-F0118 · 日志格式规范与解析器
- 域/批：A1/B06｜判据：UNX-F0118-J1 统一格式（时间/级别/子系统/正文）机器可解析，解析器回读 100% 还原｜纯功能行数：220 行（格式规范 70 + 解析器 80 + 回读断言 70；测试段不计）｜状态：[已深化]

- **语义边界**：规范只覆盖行级结构；多行消息（栈回溯）用续行前缀 `|`；二进制 payload 不入行格式。

- 正文：实现路径分三步。第一规范固化：行格式 `[%012llu][%c][%-4s] %s`（微秒、级别单字符 D/I/W/E/F、标签、正文），续行 `[%012llu][|][%-4s] %s`；规范文档写入本册（格式即契约）。第二解析器：`log_parse_line(buf) -> (us, level, tag, msg)` 严格解析（字段校验：us 全数字、level ∈ DIFWE、tag ≤4 字符），失败返回 raw；解析器零分配（输出指针引用原文）。第三回读断言：ktest 把 1000 条生成日志解析后与原始字段比对，100% 还原；多行消息续行合并还原断言；解析器对截断行/坏行正确落 raw 桶。与现存内核衔接点：F0107 找回、F0108 快照、F0113 断面、F0117 镜像全部走同一格式；外部工具链（脚本）按本规范解析。与 Windows 对照：Windows 事件日志是 XML 二进制混合（EVTX），引导期不可用；Linux dmesg 文本即本规范同族。本工程选择"文本即接口"，零工具依赖。判据 UNX-F0118-J1 的复测方式：ktest 1000 条回读 100% 还原、续行合并正确、截断行 raw 落账、解析器 fuzz 不崩溃。
