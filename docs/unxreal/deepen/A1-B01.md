### UNX-F0002 · ACPI RSDP/XSDP 深度解析与表校验链
- 域/批：A1/B01｜判据：UNX-F0002-J1 真机上 RSDP 定位、XSDT 遍历、每表校验和验证结果落账，坏表有明确诊断｜纯功能行数：300 行（RSDP 双代校验器 90 + 表索引缓存 80 + 坏表分档账 60 + 诊断报告 70；测试段不计）｜状态：[已深化]
- **定位**：ACPI 是早年平台枚举的正源，本条把"拿到 rsdp 指针"升级为"全表校验链可信"——RSDP 双代（RSDT/XSDT）遍历、逐表头校验和验证、表索引缓存三账一次建齐，供 F0003–F0005 与 B03 全部 ACPI 深化条目消费。
- **语义边界**：只做 RSDP/RSDT/XSDT 定位校验与表索引建立；不做 MADT 结构解析（F0004）、不做 FADT 特征位解读（F0003）、不做 AML 词法（F0043）。
- **依赖与嫁接源**：消费 F0001 固化的 rsdp 指针；对现存 `acpi.rs` 的 `Rsdp::parse`/`root_table_entries`/`table_at`/`checksum_ok` 是承接深化（补双代遍历分档账，非重复实现）；嫁接源为 ACPI 6.5 规范第 5.2 节，只跟随。
- **风险与回退**：固件只给 32 位 RSDT 而无 XSDT（老 BIOS 机）——双代遍历按 XSDT 优先、RSDT 兜底，代际选择落账；RSDP 扩展校验和失败时按 F0017 诊断路径处理。
- 正文：实现路径分三步。第一步在现存 `acpi::init()` 的表定位段之后插入双代遍历器：XSDT 存在时按 64 位条目遍历，否则回退 RSDT 32 位条目，两代选择结果与依据写入表索引；第二步建立表索引缓存——每表登记 OEM ID、表签名、长度、校验态四元组，`table_at` 取表时先查索引避免重复校验，索引本身只增不改供全程审计；第三步坏表分档账：校验和失败表按"致命签名（MADT/FACP）/可选签名"两档处置，致命档走 panic（文案含表签名与偏移），可选档降级记账引导不失败。与现存内核衔接点：全部落在 `acpi.rs` 既有函数之上扩展，`sig_str` 的签名表同步扩容，不改动 `Rsdp::parse` 已真机通过的字节级逻辑。与 Windows 对照：Windows 平台的 Intel `acpidump.exe` 可导出全部 ACPI 表并附校验状态，本内核的引导报告以同等颗粒度逐表列出签名/OEM ID/校验态，判据 UNX-F0002-J1 的复测方式：真机引导后导出表索引账与 acpidump 同机输出逐表比对一致率 100%，人为注入坏表 10/10 次给出分档正确的诊断项。

### UNX-F0003 · ACPI FADT 硬件特征位提取
- 域/批：A1/B01｜判据：UNX-F0003-J1 FADT 特征位（PM 时钟源/Century 位/遗留影响位）与 Windows 所见一致｜纯功能行数：260 行（特征位解码表 100 + PM1a/b 块地址账 70 + 版本分支 90；测试段不计）｜状态：[已深化]
- **定位**：FADT 是 ACPI 硬件特征的总开关面板，本条把现存 `facp_addr()` 拿到的 FACP 物理地址升级为逐特征位事实源——PM 时钟源选择位决定 A2 域 HPET/PIT 兜底序，Century 位决定 RTC 世纪寄存器语义，PM1a/b 控制块地址供 K4 电源域远期消费。
- **语义边界**：只做 FADT 字段解码与特征位账本登记；不做电源状态实际切换（K4 域防重）、不做 PM 计时器编程（A2 域 F0029 防重）。
- **依赖与嫁接源**：依赖 F0002 表索引定位 FACP；对现存 `acpi::facp_addr()` 是承接深化；嫁接源为 ACPI 6.5 规范 FADT 章节与 IA-PC 遗留硬件规范，只跟随。
- **风险与回退**：OEM FADT 版本混乱（长度 128/132/244 混杂）——按表长度分支解码，未知长度按最新保守子集解读并打降级账，不阻塞引导。
- 正文：实现路径分三步。第一步按 FADT 长度字段建立版本分支表（ACPI 1.0 至 6.5 的字段增补逐版本登记），同名字段在不同版本取不同偏移，解码前先定版本；第二步逐位解码特征账本：BOOT_ARCH 特征（PM 时钟源选择位、CMOS RTC 未存在位）、CENTURY 寄存器索引位、遗留影响位、PM1a/b 事件块与控制块物理地址、RESET_REG，全部落结构化账本并附原始字节快照；第三步交叉校验——PM1a 与 PM1b 地址相同时合并记账，X_PM 前缀 64 位字段优先于 32 位旧字段，冲突以 64 位为准并留差异账。与现存内核衔接点：扩展 `acpi.rs` 新增 `Facp` 结构与 `facp()` 取用函数，`facp_addr()` 保持兼容返回。与 Windows 对照：Windows `powercfg /a` 报告的睡眠能力与 msinfo32 的 ACPI 设置源自 FADT 同源字段，本内核账本与同机 Windows 所见逐位对照，判据 UNX-F0003-J1 的复测方式：三台不同代机型上特征位账本与 Windows 观测（powercfg /a、msinfo32）一致率 100%，CMOS RTC 未存在位机型 10/10 次正确降级。

### UNX-F0004 · MADT 解析与 LAPIC 列表构建
- 域/批：A1/B01｜判据：UNX-F0004-J1 LAPIC/IOAPIC/x2APIC 项解析数与真实 CPU 拓扑一致｜纯功能行数：280 行（五类条目解码 120 + 拓扑三账 90 + x2APIC 条目 70；测试段不计）｜状态：[已深化]
- **定位**：MADT 是多核世界的出生证明，本条把现存 `parse_madt` 的四类条目解析补全为五类（增 x2APIC 条目）并构建 A2/A3 两域的拓扑事实源：核数账、LAPIC 基址账、GSI 空间账一次建齐，经 F0001 BootManifest 对外冻结交付。
- **语义边界**：只做 MADT 条目解码与拓扑账本构建；不做 LAPIC 寄存器操作与 EOI 语义（AI-02 域防重，判例一"解析归 A1，操作归 A2"）、不做 SMP 启动序列（A3 域防重）。
- **依赖与嫁接源**：依赖 F0002 表索引；对现存 `acpi.rs` 的 `MadtInfo`/`CpuEntry`/`IoApicEntry`/`IsoEntry` 是承接深化（补 x2APIC 条目与拓扑三账聚合）；嫁接源为 ACPI 6.5 MADT 章节与 Intel SDM Vol.3 第 8 章，只跟随。
- **风险与回退**：OEM MADT 遗漏 enabled 标志或 NMI 源缺失——缺失项按"显式缺账"登记而非默认值填充，F0015 CPUID 交叉校验兜底发现不一致即打诊断。
- 正文：实现路径分三步。第一步补全第五类条目 x2APIC（类型 9）：32 位处理器 UID 与 ACPI UID 全宽解码，与类型 0 条目去重合并（同一核两种条目并存时以 x2APIC 为准并留合并账）；第二步构建拓扑三账：核数账（enabled 计数与全量计数分列）、LAPIC 基址账（MADT 全局地址 + F0003 FACP 交叉）、GSI 空间账（每 IOAPIC 的 GSI 基址与中断源数求和），三账固化进 F0001 BootManifest 固定槽位对 AI-02/AI-03 冻结交付；第三步 ISA Override 表进 IRQ 路由初值：每条 Override 的 legacy IRQ→GSI 映射、极性、触发模式三项落结构化初值表，AI-02 建立中断路由时逐项消费。与现存内核衔接点：`MadtInfo` 增加 `x2apic_entries` 与 `topology()` 方法，`enabled_cpus()` 语义不变。与 Windows 对照：Windows 设备管理器"查看-按连接排序资源"与 msinfo32 的处理器计数同源于 MADT，本内核拓扑账与同机 Windows 处理器数、逻辑核数对照，判据 UNX-F0004-J1 的复测方式：4/8/16 核真机各引导后核数账与 msinfo32 一致，Override 表逐项与 Windows `!apic`（WinDbg）路由观测一致，缺席 0。

### UNX-F0005 · HPET 表解析与基地址捕获
- 域/批：A1/B01｜判据：UNX-F0005-J1 HPET 基址与最小 tick 可读，读写判据通过｜纯功能行数：240 行（表签名解析 70 + 最小可读验证 90 + 能力账 80；测试段不计）｜状态：[已深化]
- **定位**：HPET 表是 A2 域时钟源金字塔的门票，本条在 ACPI 表索引上新增 HPET 签名解析，把"表存在"验证为"硬件可读"——基址、最小 tick 周期、比较器数量、页保护标志四项能力账一次捕获，"表存在但硬件不响应"的真机怪病挡在早年。
- **语义边界**：只做 HPET ACPI 表解析与基址最小可读验证；不做 HPET 计数器使能与比较器编程（A2 域 F0029 防重）、不做时钟源仲裁（F0032 防重）。
- **依赖与嫁接源**：依赖 F0002 表索引按 HPET 签名取表；嫁接源为 ACPI 6.5 HPET 章节与 IA-PC HPET 规范 1.0a，只跟随。
- **风险与回退**：无 HPET 表（部分老机）——空账显式登记，A2 域时钟源仲裁走 PIT 兜底（F0031），引导不失败；最小可读验证失败（基址可读但计数器不走）按"表真硬件假"入缺陷账并降级。
- 正文：实现路径分三步。第一步在 `acpi.rs` 表分发器注册 HPET 签名解析器：事件定时器块基址（32 位地址字段与 64 位地址扩展按表版本取舍）、HPET 编号、最小 tick（纳秒）、页保护标志四字段解码入账；第二步最小可读验证序列：经 F0012 高半区映射读主计数器两次，断言差值非零且方向单调、GENERAL_CAPABILITIES 寄存器厂商 ID 与周期字段自洽，两次读数相同的"死计数器"判为硬件不响应；第三步能力账固化：比较器数量从 CAPS 寄存器 NUM_TC 位读出，连同基址与最小 tick 落 BootManifest 槽位供 AI-02 消费，全部验证动作与结果进 F0018 引导记账。与现存内核衔接点：`acpi.rs` 新增 `HpetTable` 结构与 `hpet()` 取用函数，验证序列依赖 F0012 页表映射与 `timeline::read_tsc` 计时。与 Windows 对照：Windows 设备管理器"系统设备-高精度事件计时器"节点存在性同源于 HPET 表，本内核能力账与同机 Windows 该节点可见性对照，判据 UNX-F0005-J1 的复测方式：三机型引导后基址与比较器数与 Windows 所见一致，人为拔除 HPET 表的退化路径 10/10 次显式空账不阻塞。

### UNX-F0006 · SMBIOS 采集与 DMI 字符串表
- 域/批：A1/B01｜判据：UNX-F0006-J1 主板/厂商/版本字符串与 Windows msinfo32 所见一致｜纯功能行数：260 行（64/32 位入口双路 70 + 五类结构遍历 110 + 字符串表提取 80；测试段不计）｜状态：[已深化]
- **定位**：SMBIOS 是机型世界的身份证，本条把现存 `smbios.rs` 的入口解析深化为五类结构全遍历与 DMI 字符串表提取——Type 0 BIOS/Type 1 系统/Type 2 板/Type 4 处理器/Type 17 内存设备五类优先，供 sysinfo 面、O4 崩溃归因（机型分档）、L1 安装器（机型白名单）三处消费。
- **语义边界**：只做 SMBIOS 结构遍历与字符串提取；不做机型白名单策略（L1 域防重）、不做内存设备容量进物理内存账（F0008 防重）。
- **依赖与嫁接源**：依赖 F0001 BootManifest 的 smbios 响应（EFI 档）与 0xF0000–0xFFFFF 扫描（BIOS 档）；对现存 `smbios.rs` 的 `parse_entry`/`struct_at`/`string_at` 是承接深化；嫁接源为 SMBIOS 3.x 规范，只跟随。
- **风险与回退**：OEM 私有结构类型未知——未知类型按"长度守恒跳过"处理并留未知类型账，字符串索引越界以空串记账不崩溃。
- 正文：实现路径分三步。第一步双路入口定位统一：EFI 档直接取 Limine SMBIOS 响应的 64 位入口，BIOS 档按 `parse_entry` 既有 32 位入口兼容，两路产出统一 `Entry` 账并登记来源档位；第二步五类结构遍历器：按结构类型白名单逐条解析，每结构登记句柄、长度、字符串表偏移，Type 4 取处理器插槽与版本串、Type 17 取内存设备定位与速度串，字符串经 `string_at` 提取后做长度上限与可打印字符双重清洗；第三步 DMI 账导出：五类关键字段组装成系统摘要（厂商/产品/版本/序列号/BIOS 版本/处理器标识），与 F0001 BootManifest 合流，供运行期 sysinfo 查询面按需取用。与现存内核衔接点：`smbios.rs` 新增 `DmiSummary` 结构与 `collect_summary()` 函数，遍历复用 `struct_at`/`next_struct_offset`。与 Windows 对照：Windows msinfo32"系统摘要"的 OEM 信息与系统型号同源 SMBIOS Type 1/Type 0，判据 UNX-F0006-J1 的复测方式：三机型引导后 DMI 摘要与同机 msinfo32 逐字段一致，未知结构类型注入 10/10 次跳过有账不崩溃。

### UNX-F0007 · EFI 运行时服务桩面
- 域/批：A1/B01｜判据：UNX-F0007-J1 GetTime/SetTime/ResetSystem 三服务在真机 EFI 环境可用｜纯功能行数：300 行（三服务桩 150 + VA 映射分界账 80 + 降级记账 70；测试段不计）｜状态：[已深化]
- **定位**：ExitBootServices 之后 EFI 运行时是"半弃用"地带，本条建立三服务桩面（GetTime/SetTime/ResetSystem）与虚拟地址映射分界账——引导期可用性、运行期可用性、弃用声明三段留痕，为 K4 电源域时钟基准与重启关机提供 EFI 档互补路径（ACPI S5 档之外的另一条路）。
- **语义边界**：只做服务桩封装与可用性分界账；不做 RTC 世纪的业务语义（F0003 Century 位防重）、不做电源管理策略（K4 域防重）。
- **依赖与嫁接源**：依赖 F0001 的 efi-system-table 响应指针；嫁接源为 UEFI Spec 2.10 运行时服务章节，只跟随；弃用决策（本域选弃用运行时服务、时钟走 HPET/TSC）作为候选 ADR 提交 AI-93 形档。
- **风险与回退**：固件运行时区被 ExitBootServices 后内存使用破坏——三服务调用前做签名自检，失败即降级记账改走 ACPI 路（RESET_REG/键盘控制器 0xFE/SLP_TYP），不 panic。
- 正文：实现路径分三步。第一步桩封装层：GetTime/SetTime/ResetSystem 三服务经现存 `limine::efi_system_table()` 取运行时服务表指针，按 UEFI 调用约定封箱为三个 no_std 包装函数，调用前后签名自检（表 CRC 比对引导期快照）；第二步分界账：ExitBootServices 前后各做一次服务探活（GetTime 探针），两探活结果与时间戳落账，构成"引导期可用/运行期可用/全弃用"三段状态机，弃用声明落 F0011 引导日志可打印；第三步互补路径对接：ResetSystem 桩与 ACPI RESET_REG/键盘控制器 0xFE 双路并列注册进 power 模块的复位指令表，EFI 档失败自动降级 ACPI 路，降级动作显式记账。与现存内核衔接点：`limine.rs` 既有 `efi_system_table()` 供指针，power 模块消费复位指令表；不改动 `efi_memmap()` 语义（F0008 消费）。与 Windows 对照：Windows `shutdown /r /fw` 与系统时间同步（w32tm）背后是同组 EFI 运行时服务，判据 UNX-F0007-J1 的复测方式：EFI 真机引导后三服务探活通过、复位指令双路各触发 5/5 次成功，BIOS 老机 10/10 次显式降级记账不 panic。

### UNX-F0008 · 内存映射三源合并与一致性校验
- 域/批：A1/B01｜判据：UNX-F0008-J1 Limine/EFI/BIOS 三源合并冲突检测器跑真机内存图并出具合并账｜纯功能行数：320 行（类型归一表 80 + 冲突裁决器 130 + 合并账输出 110；测试段不计）｜状态：[已深化]
- **定位**：内存图是物理页管理的唯一真值输入，本条把现存 `memmap.rs` 的 Limine 单源消费升级为三源合并器——Limine mmap、EFI GetMemoryMap、BIOS e820 按优先级裁决合并，冲突检测与合并账（每源贡献区间数/冲突数/裁决结果）全程留痕，F0013 物理页账本只信合并后的唯一图。
- **语义边界**：只做内存图源间合并与冲突裁决；不做物理页分配器（F0013/AI-04 域防重，判例三"图纸归 A1，施工归 A4"）、不做预留区策略实现（`Reservations` 语义保留）。
- **依赖与嫁接源**：依赖 F0001 mmap 响应与 `limine::efi_memmap()`，BIOS 档 e820 从引导器兼容层取；对现存 `memmap.rs` 的 `Kind::from_limine`/`Region`/`validate` 是承接深化；嫁接源为 UEFI GetMemoryMap 类型表与 e820 类型约定，只跟随。
- **风险与回退**：三源冲突无解（同区间三种类型）——按"EFI 最宽、Limine 次之、e820 最窄"可配置优先级裁决，裁决全部落账可人工复核，极端冲突进 F0017 诊断模式。
