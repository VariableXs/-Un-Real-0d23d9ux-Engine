### UNX-F12801 · PE 头解析与映像布局校验器
- 域/批：D2/B01｜判据：UNX-F12801-J1 100 个真实 PE 样本头解析逐字段与工具输出一致（L1 级），非 MZ/坏节表/对齐非法三类拒载逐码对齐｜纯功能行数：400 行（头部视图入口分发器 120 + 三类拒载判定链 140 + 解析账本导出 80 + 工具对照差分器 60；测试段不计）｜状态：[已深化]
- **定位**：本条是 D2 域装载链的总入口与第 0 关——把"拿到文件视图"升级为"可信的头部事实源"，向 B02 节表、B04 重定位、B05 导入、B06 导出、B07 TLS 全部消费方输出同一份解析账本，是 B09 全映像校验器的单层前置。
- **语义边界**：只做头解析与单层布局判定；不做节映射执行（B02）、不做逐目录越界校验体系（B08）、不做全映像三层联合校验（B09 防重分层）。
- **依赖与嫁接源**：对现存 `proc/pe.rs` 的 DOS 头/e_lfanew/SizeOfImage 上限逻辑是升级接管（保留其 PeError 码族作回归基线）；嫁接源为 PE/COFF 规范 §Timer（MS-PE）与 pefile 工具输出口径，只跟随。
- **风险与回退**：非 MZ 样本前缀含 MZ 伪签（打包器）——定位链按 e_lfanew 复核二次签名，复核失败按拒载码落账；解析账本导出失败不阻塞装载判定，降级只记账。
- 正文：实现路径分三步。第一步在现存 `pe.rs` 的 `parse` 之前立头部视图分发器：文件视图零拷贝进入，先 e_magic 复核、再 e_lfanew 区间校验（落在 0x40–0x400 且不越文件尾）、后 PE 签名复核，三判定任一失败走三类拒载码族（与现存 `PeError` 逐码回归对齐）；第二步解析账本：DOS 头 19 字段、COFF 20 字段、OPTIONAL 双档全字段以只读视图登记，账本带样本哈希与解析时间戳可导出比对；第三步差分器：与 pefile 同样本输出逐字段 diff，差异项落工具差异账不得静默。与现存内核衔接点：`pe.rs` 现存 `PeError` 枚举扩容不改既有变体（下游 B25 畸形防御消费），`parse` 重构为消费本条账本。与 Windows 对照：`dumpbin /headers` 的头区输出为本条对照锚，判据 UNX-F12801-J1 复测方式：100 样本（来源+哈希落 AI-94 账）逐字段一致率 100%，三类拒载构造样本逐码复测 30/30 对齐。

### UNX-F12802 · DOS header e_magic/e_lfanew 定位与 MZ 存根语义
- 域/批：D2/B01｜判据：UNX-F12802-J1 e_lfanew 定位链在 100 样本全通，e_lfanew 越界/悬空 DOS 头内两族畸形拒载且错误码与现存 proc/pe.rs PeError::BadPeOffset 回归一致｜纯功能行数：260 行（e_lfanew 定位链 90 + 两族畸形判定 90 + 存根只读快照 80；测试段不计）｜状态：[已深化]
- **定位**：e_lfanew 是 DOS 世界通往 PE 世界的独木桥，本条把现存 `pe.rs` 的单点偏移检查升级为完整定位链——含 DOS 存根只读快照（供 F12816 Rich header 与打包器指纹消费），是 B01 解析链的第二判定级。
- **语义边界**：只做 DOS 头定位链与存根快照；不做 DOS 存根执行（永不执行，Windows 亦然，行为对照落账）、不做 Rich header 解码（F12816 防重）。
- **依赖与嫁接源**：对现存 `PeError::BadPeOffset` 是承接深化（两族畸形细化归入该码族）；嫁接源为 MS-PE 规范 DOS header 章节与真实打包器产物行为，只跟随。
- **风险与回退**：e_lfanew 悬空（指向头区外但文件仍大）——按区间上界判拒；e_lfanew=0 与极小值区分账面口径，避免把合法微头误伤。
- 正文：实现路径分三步。第一步定位链四判定：e_magic=='MZ'、e_lfanew≥0x40、e_lfanew+4≤文件尾、e_lfanew+4≤SizeOfHeaders（后者只警告不拒载，Windows 同口径），每判定独立记账可单独关闭做对照实验；第二步两族畸形判定：越界族（e_lfanew>文件尾）与悬空族（落在 DOS 头与 PE 签名之间无签名）分别产出拒载码，两码均回归到现存 `BadPeOffset` 语义（升级接管保证旧判据不破）；第三步存根快照：DOS 存根区间（0x40–e_lfanew）做只读快照与长度登记，供打包器指纹（UPX/ASPack 特征串）与 Rich header 条目消费，快照零拷贝引用不复制。与现存内核衔接点：`pe.rs` 定位段替换为本条链式实现，旧单点检查逻辑保留为回归对照开关。与 Windows 对照：Windows LoadLibrary 对坏 e_lfanew 的失败不外显码值，本内核以 `dumpbin` 能否出头为接受/拒载对照锚，判据 UNX-F12802-J1 复测方式：100 样本定位链全通，两族畸形构造样本 40/40 拒载码与现存面回归一致。

### UNX-F12803 · PE 签名与 COFF 头逐字段解析（IMAGE_FILE_HEADER）
- 域/批：D2/B01｜判据：UNX-F12803-J1 20 字段（Machine/NumberOfSections/TimeDateStamp/PointerToSymbolTable 等）解析值与 pefile 工具输出逐字段一致，TimeDateStamp 零值/伪造值有账｜纯功能行数：340 行（COFF 20 字段解码 140 + TimeDateStamp 真伪账 100 + 签名复核 100；测试段不计）｜状态：[已深化]
- **定位**：COFF 头是 PE 结构的目录页——Machine 定架构路由（F12804）、NumberOfSections 定节表规模（F12809）、TimeDateStamp 定构建真伪（供 B15 双向对照与 AI-94 样本账），本条把 20 字段一次解码入账成为全部下游的事实源。
- **语义边界**：只做 COFF 字段解码与时间戳账；不做符号表解析（COFF 符号表为遗留格式，Windows 加载器亦不消费，行为对照落账）、不做架构路由执行（F12804）。
- **依赖与嫁接源**：依赖 F12802 定位链给出的 PE 签名位置；嫁接源为 MS-PE 规范 IMAGE_FILE_HEADER 章节与 pefile `PE.FILE_HEADER` 输出口径，只跟随。
- **风险与回退**：TimeDateStamp 为 hash 值（ reproducible build 产物）——按" reproducible 标志位"识别登记不判伪造；伪造值（未来时间）只记账不拒载，与 Windows 接受行为一致。
- 正文：实现路径分三步。第一步 20 字段解码器：按偏移 4 起 20 字段逐一定长读取，字段表（名称/偏移/宽度/语义）以 const 表交付，与 pefile 输出逐字段 diff 零差异为出厂门槛；第二步 TimeDateStamp 真伪账：零值、超 2100 年未来值、reproducible hash 值（高于阈值且配套 TimeDateStamp 辅助调试目录存在）三态分类登记，真伪判定只入账不拒载；第三步签名复核深化：PE\0\0 签名读出后与 F12802 定位值交叉复核，签名位置与 e_lfanew 不符即报内部一致性错误（此为解析器自身 bug 探测位）。与现存内核衔接点：`pe.rs` 现存 COFF 读取段（若有）替换为字段表驱动实现，账本结构 `CoffHeader` 对 B02–B08 全消费方导出。与 Windows 对照：Windows 加载器对 COFF 逐字段只有"是否可装载"二值，本内核账本更细但接受/拒载判定必须同向，判据 UNX-F12803-J1 复测方式：100 样本 20 字段与 pefile 一致率 100%，时间戳三态构造样本 30/30 分类正确。

### UNX-F12804 · Machine 双档识别与架构分档路由（0x8664/0x014c）
- 域/批：D2/B01｜判据：UNX-F12804-J1 64/32 位样本各 ≥20 个识别分档全对，未知 Machine 码拒载落账，与 compatstar/wow64.rs gate_machine 行为回归对照一致｜纯功能行数：300 行（Machine 码识别表 80 + 分档路由器 110 + gate_machine 回归对照 110；测试段不计）｜状态：[已深化]
- **定位**：Machine 字段是整个 D2 装载链的分岔口——本条立双档路由器（x64/IA32），下游全部批次按档位走 64/32 位解析分支，与现存 `compatstar/wow64.rs` 的 `gate_machine` 位数门是升级接管关系：门语义保留，路由能力扩展为全链档位事实源。
- **语义边界**：只做 Machine 识别与档位路由；不做 32 位装载执行（B15 分档本体）、不做位数门缓存策略改造（现存 `gate_machine` 零改动，仅对照）。
- **依赖与嫁接源**：依赖 F12803 的 Machine 字段值；对现存 `wow64.rs::gate_machine` 是升级接管（其接受/拒绝结果成为本条回归基线）；嫁接源为 MS-PE Machine Types 全表，只跟随。
- **风险与回退**：ARM64/ARMNT 等未支持 Machine 码样本——显式拒载落账（与 Windows 在 x64 机拒载行为一致），码值与拒绝理由入样本账供 B15 扩档评估。
- 正文：实现路径分三步。第一步识别表：0x8664（AMD64）与 0x014c（I386）两支持档、其余全表登记为"已知名单/未支持"两列，识别表版本化；第二步路由器：档位枚举（X64/X86/UNSUPPORTED）写入解析账本头部，全 D2 链经账本取档，禁止下游二次读 Machine 字段（单点事实原则）；第三步回归对照：对现存 `gate_machine` 全量样本跑双实现 diff，接受/拒绝两态必须逐样本一致，不一致即缺陷入账（接管基线漂移视为回归）。与现存内核衔接点：`compatstar/wow64.rs` 零改动，`gate_machine` 结果与本条路由结果做运行期对拍。与 Windows 对照：Windows x64 加载器对 0x014c 走 WOW64 路径（B15 承接）、对未知码拒载，判据 UNX-F12804-J1 复测方式：64/32 位真实样本各 30 个分档全对，未知码构造样本 20/20 拒载码与 gate_machine 行为一致。

### UNX-F12805 · IMAGE_OPTIONAL_HEADER64 解析（Magic/AddressOfEntryPoint/ImageBase）
- 域/批：D2/B01｜判据：UNX-F12805-J1 0x20B Magic 样本 100 个全字段解析一致，入口 RVA 越出 SizeOfImage 拒载（对齐现存 PeError::EntryOutsideImage 回归）｜纯功能行数：380 行（64 位 30 字段解码 150 + 入口越界判定 90 + ImageBase 区间账 140；测试段不计）｜状态：[已深化]
- **定位**：OPTIONAL_HEADER64 是 64 位装载链的参数总表——入口点（E1 入口调度消费）、ImageBase（B04 重定位 delta 基准）、SizeOfImage（B02 映射规模）、栈参数（B12 消费）、DataDirectory（B08 消费）全在本条出账，是 PE32+ 档的唯一字段源。
- **语义边界**：只做 PE32+ 字段解码与三项单点判定（入口越界/ImageBase 区间/Magic 复核）；不做 DataDirectory 逐目录校验（B08）、不做栈参数语义执行（B12）。
- **依赖与嫁接源**：依赖 F12804 档位路由（仅 X64 档进入）；对现存 `pe.rs` 的 SizeOfImage 上限与 `EntryOutsideImage` 是承接深化；嫁接源为 MS-PE 规范 OPTIONAL Header（PE32+）章节，只跟随。
- **风险与回退**：ImageBase 落高熵区但 DllCharacteristics 未开 HIGHENTROPYVA——一致性警告账（不拒载，Windows 同容忍）；Magic 值既非 0x20B 又非 0x10B 按损坏档走 F12819 错误码。
- 正文：实现路径分三步。第一步 30 字段解码表：PE32+ 从 Magic 到 NumberOfRvaAndSizes 逐字段定长读取，字段宽度全部 64 位口径，const 字段表与 pefile `PE.OPTIONAL_HEADER` diff 零差异；第二步入口判定：AddressOfEntryPoint+4≤SizeOfImage 断言，越界走现存 `EntryOutsideImage` 回归码（升级接管），入口=0 合法（NATIVE 映像），零入口样本单列特例账；第三步 ImageBase 区间账：按 DllCharacteristics 组合登记基址策略初值（高熵/常规/固定），账面值供 B04/B12 消费，本条只登记不执行随机化。与现存内核衔接点：`pe.rs` 现存 optional 段重构为本条解码表，`PeError` 语义不变。与 Windows 对照：`dumpbin /headers` 的 OPTIONAL 段数值逐字段对照，判据 UNX-F12805-J1 复测方式：100 样本全字段一致率 100%，入口越界构造样本 20/20 拒载码回归一致。

### UNX-F12806 · IMAGE_OPTIONAL_HEADER32 双轨差异解析（PE32 vs PE32+）
- 域/批：D2/B01｜判据：UNX-F12806-J1 0x10B Magic 样本 ≥30 个字段宽度差异（BaseOfData/32 位 ImageBase/AddressOfEntryPoint）逐字段对照一致，双轨混读零误判｜纯功能行数：360 行（32 位 31 字段解码 150 + 双轨差异表 100 + 混读防护 110；测试段不计）｜状态：[已深化]
- **定位**：PE32 与 PE32+ 双轨并存是 Windows 生态的现实（32 位应用存量巨大），本条立 31 字段 PE32 解码与双轨差异表——BaseOfData 仅 32 位有、ImageBase 32 位宽、指针宽字段全档差异，保证 B15 WOW64 档拿到与 64 位档同粒度的事实源。
- **语义边界**：只做 PE32 档字段解码与双轨差异表；不做 32 位装载执行（B15）、不做 WOW64 系统调用转发（B15/F13087 防重）。
- **依赖与嫁接源**：依赖 F12804 档位路由（X86 档进入）；嫁接源为 MS-PE 规范 OPTIONAL Header（PE32）章节与真实 32 位产物 ≥30 例，只跟随。
- **风险与回退**：伪装 Magic（64 位体配 0x10B）——按 Magic 声明档位解码并做长度自洽复核（OPTIONAL 头尺寸字段 vs 档位预期尺寸），不符走损坏档拒载，与 Windows 行为对照。
- 正文：实现路径分三步。第一步 31 字段解码表：PE32 档独立 const 表（BaseOfData 4 字节、ImageBase 4 字节、其余指针宽字段 32 位口径），输出账本结构与 64 位档同构（消费方无感双轨）；第二步双轨差异表：逐字段登记宽度/偏移/有无三差异列，差异表本身版本化供 B15 与 fuzz 语料生成器消费；第三步混读防护：账本头部带档位印章，任何消费方跨档取字段（X64 档账本取 32 位字段）即断言失败——防升级期误用，防护断言零容忍。与现存内核衔接点：`pe.rs` 档位分支处接入本条，双档账本统一 `OptionalHeader` 枚举类型。与 Windows 对照：`dumpbin /headers` 32 位样本输出逐字段对照，判据 UNX-F12806-J1 复测方式：32 位真实样本 40 个全字段一致率 100%，伪装 Magic 构造样本 20/20 拒载行为与 Windows 同向。

### UNX-F12807 · SectionAlignment/FileAlignment 合法性矩阵校验
- 域/批：D2/B01｜判据：UNX-F12807-J1 SectionAlignment<PageSize 且≠FileAlignment 拒载矩阵 16 组合全过，2^k 对齐边界样本逐组落账｜纯功能行数：300 行（对齐矩阵判定器 130 + 2^k 边界账 90 + 拒载/容忍口径表 80；测试段不计）｜状态：[已深化]
- **定位**：双对齐字段是节映射（B02）的几何前提，本条立合法性矩阵——SectionAlignment 必须 ≥PageSize 且为 2 的幂、FileAlignment 须为 2 的幂且落在 512–64K 口径，矩阵判定结论直接决定 B02 散布映射走哪条路径。
- **语义边界**：只做对齐合法性判定与口径表；不做映射几何执行（B02/F12823 防重）、不做对齐修复建议输出（只判定不改造）。
- **依赖与嫁接源**：依赖 F12805/F12806 双档对齐字段；嫁接源为 MS-PE 规范对齐约束条款与 Windows 加载器容忍行为观测，只跟随。
