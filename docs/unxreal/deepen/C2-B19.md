### UNX-F9161 · setrlimit/getrlimit 语义档总纲（rlimit 结构四元组）
- 域/批：C2/B19｜判据：UNX-F9161-J1 软硬限读写回环判据过，结构四元组探针格过，RLIM_INFINITY 编码格过｜纯功能行数：420 行（结构四元组与读写回环 150 + RLIM_INFINITY 编码格 140 + 探针格与对象布局 130）｜状态：[已深化]

- **定位**：本条是 rlimit 限额族（F9162–F9168 各专条）的总纲：getrlimit/setrlimit 以 struct rlimit{rlim_cur, rlim_max} 二字段结构对 16 个资源号逐一读写，RLIM_INFINITY 全 1 位码表无穷限——shell ulimit 与 POSIX spawn 限额继承的地基结构。
- **语义边界**：只管读写回环与结构编码；各资源号专项语义归 F9162–F9165；错误矩阵归 F9167；翻转协议归 F9168；prlimit64 双轨归 F9166；fd 表本体与分配器归 B08（NOFILE 联动消费不重铺）。
- **依赖与嫁接源**：嫁接 getrlimit(2)/setrlimit(2) man-pages（RLIM_INFINITY 语义、RLIM_NLIMITS=16 资源集）；锚定 C1 进程对象（rlimits 数组挂点）、F8921 参数拷贝探针、B08 fd 分配器（NOFILE 联动）、B15 F9092 prlimit64 档。
- **风险与回退**：风险一为资源号越界索引出界读写——回退为入口判据 resource∈[0,15] 硬校验先行，越界一律 -EINVAL 后才允许数组索引；风险二为 RLIM_INFINITY 与大限值混淆（~0ULL 与 0xFFFFFFFFFFFFFFFE 差一位）——回退为编码格用相邻值对照断言（INFINITY 与 INFINITY-1 行为分岔：前者放行后者按限值拒绝）。
- **正文**：实现路径分三步：第一步立结构四元组与读写回环——内核侧 struct unx_rlimit{u64 rlim_cur; u64 rlim_max;}，每任务 rlimits[RLIM_NLIMITS=16] 数组，四元组=（资源号, cur, max, 有效位图）；getrlimit(resource,&rl) 回读 cur/max 逐字段断言，setrlimit 写入后回环一致，16 资源号全扫 0–15、越界号全 -EINVAL；第二步立 RLIM_INFINITY 编码格——无穷限以全 1 位码 ~0ULL 落账：cur=INFINITY 写入回读同码、与上限值 0xFFFFFFFFFFFFFFFE 相邻不混淆（前者 ftruncate 路径放行、后者按限值拒绝的分岔断言）、INFINITY 作 max 时软限升到 max 放行三断言；第三步立探针格与对象布局——结构 ABI 与 glibc struct rlimit 布局单源（两 u64 字段序固定），坏指针（NULL/内核态地址/只读页写目标）全 -EFAULT。与现存内核衔接点：rlimits 数组挂 C1 进程对象（F9193 消费协议同源）；参数拷贝走 F8921 探针。与 Windows 对照：Windows 限额在 Job Object（SetInformationJobObject）而非每进程结构，无软硬限对偶；本条按 Linux 上游语义冻结。判据 UNX-F9161-J1 的复测方式：ktest 三断言——16 号读写回环全过、INFINITY 编码三断言、四元组探针与坏指针 EFAULT。

### UNX-F9162 · RLIMIT_NOFILE/CORE/STACK 三限额逐格
- 域/批：C2/B19｜判据：UNX-F9162-J1 三限额逐格判据过，NOFILE 与 fd 分配器联动可观测，CORE 零值禁转储格过｜纯功能行数：360 行（NOFILE 与 fd 分配联动 130 + STACK 限额格 120 + CORE 零值禁转储 110）｜状态：[已深化]

- **定位**：三最高频限额的逐格语义：RLIMIT_NOFILE（fd 数上限，与 B08 分配器联动 EMFILE）、RLIMIT_STACK（栈上限）、RLIMIT_CORE（转储上限，0=禁转储）——shell ulimit -n/-s/-c 三开关的内核侧判定格。
- **语义边界**：只管三限额判定挂点；fd 分配器本体归 B08；栈自动增长与 guard page 归 B03 内存族；core 转储器实装缺席（限值为语义预留）；SIGSEGV 投递归 B11。
- **依赖与嫁接源**：嫁接 getrlimit(2) man-pages NOFILE/STACK/CORE 段；锚定 B08 fd 分配器（EMFILE 出口）、B03 栈映射、B11 信号挂点、F9102 EMFILE 上限格对账。
- **风险与回退**：风险一为 NOFILE 判定与分配器时点错位（先分配后校验漏网一个 fd）——回退为分配器入口单点校验（计数值在分配事务内递增），并发复测随闸门登记；风险二为 STACK 触限一刀切（触限即杀）——回退为触限路径先尝试栈扩展、失败才 SIGSEGV 的上游行为分岔，探针断言双路径。
- **正文**：实现路径分三步：第一步立 NOFILE 联动——cur=64 预置后分配第 65 个 fd → -EMFILE（B08 分配器入口消费 rlimits[NOFILE].cur，计数器 meter 可观测），调升 cur=128 后同分配成功，dup/F_DUPFD 同判据路径抽查；第二步立 STACK 限额格——mmap 栈扩展请求超 cur → -ENOMEM（映射路径拒绝不投递），执行栈触限且扩展失败 → SIGSEGV（与 B11 投递联动桩断言），双路径分岔表落账；第三步立 CORE 零值禁转储——cur=0 时致命信号路径检查 rlimits[CORE].cur==0 直接跳过转储挂点（本内核转储桩只记 meter 计数），cur>0 时挂点被调（预留格），零值/非零值对照断言。与现存内核衔接点：fd 计数与 B08 分配器单源；信号投递与 B11 单源。与 Windows 对照：Windows 无 per-process fd 上限（句柄配额进程级近似）、栈保留/提交两段制（STACK 限对齐 reserve 段）、转储受 WER LocalDumps 配置；对照表落账。判据 UNX-F9162-J1 的复测方式：ktest 三断言——EMFILE 联动断言、栈双路径分岔、CORE 零值跳过断言。

### UNX-F9163 · RLIMIT_AS/DATA/RSS 内存限额族
- 域/批：C2/B19｜判据：UNX-F9163-J1 三限额判据过，AS 与 mmap 分配联动可观测，RSS 提示性语义声明格过｜纯功能行数：340 行（AS 与 mmap 分配联动 120 + DATA brk 联动 110 + RSS 提示性语义 110）｜状态：[已深化]

- **定位**：内存三限额：RLIMIT_AS（地址空间总量，mmap/brk 出口 -ENOMEM）、RLIMIT_DATA（数据段+brk 总量）、RLIMIT_RSS（驻留集，Linux 上游为提示性无强制）——ulimit -v/-d 的内核侧与历史 RSS 语义澄清格。
- **语义边界**：只管三限额判定挂点；mmap/brk 分配器本体归 B03 内存族（消费不重铺）；页表与回收归 B03；RSS 统计器实装缺席（提示性语义声明即本格主产物）；shm 归 B07。
- **依赖与嫁接源**：嫁接 getrlimit(2) man-pages AS/DATA/RSS 段（"RSS is advisory"原文语义）；锚定 B03 brk/mmap 语义档（出口挂点）、B07 shm、F9161 四元组、B02 tmpfs。
- **风险与回退**：风险一为 AS 统计漂移（munmap 后计数未回收致假满）——回退为计数器与映射表同事务更新（映射增删单段原子），泄漏探针：随机 mmap/munmap 100 轮后计数回归基线；风险二为 DATA 误计共享映射致误伤（上游只计 brk+数据段）——回退为计数范围声明：只计私有匿名+数据段，文件映射不计，断言核。
- **正文**：实现路径分三步：第一步立 AS 联动——cur=8MiB 预置，mmap(16MiB) → -ENOMEM（分配出口消费 rlimits[AS].cur，VMA 计数器与映射表同事务），调升后成功，边界值双断言（8MiB 请求恰好过、8MiB+1 页拒）；第二步立 DATA 联动——brk 增长超 cur → -ENOMEM，AS 与 DATA 两计数独立对照（AS 计全部 VMA、DATA 只计 brk+数据段：大文件映射撑爆 AS 不动 DATA 的对照断言）；第三步立 RSS 提示性语义——声明格：本内核无页回收器，RSS 限值登记不强制（写入成功、读取回环、运行期零判定），与上游 "advisory" 行为一致，声明落账 handoff。与现存内核衔接点：出口挂点与 B03 mmap/brk 单源（判定函数在分配事务内联调用）。与 Windows 对照：Windows 对应 Job Object ProcessMemoryLimit/JobMemoryLimit（提交内存而非地址空间，语义族不同源）、工作集 SetProcessWorkingSetSize（可调非强制）；对照表落账。判据 UNX-F9163-J1 的复测方式：ktest 三断言——AS 边界值双断言、DATA/AS 独立对照、RSS 提示性声明格在案。

### UNX-F9164 · RLIMIT_CPU/NPROC/SIGPENDING 调度限额族
- 域/批：C2/B19｜判据：UNX-F9164-J1 三限额判据过，CPU 超限 SIGXCPU 投递挂点格过，NPROC 与 fork EAGAIN 联动格过｜纯功能行数：340 行（CPU 超限 SIGXCPU 挂点 130 + NPROC 与 fork EAGAIN 110 + SIGPENDING 限额 100）｜状态：[已深化]

- **定位**：调度侧三限额：RLIMIT_CPU（CPU 秒软限触发 SIGXCPU、硬限 SIGKILL）、RLIMIT_NPROC（用户进程数上限，fork 出口 -EAGAIN）、RLIMIT_SIGPENDING（挂起信号队列上限）——防跑飞与防 fork 炸弹双保险格。
- **语义边界**：只管三限额判定挂点；CPU 计时归 A2 计时基座（tick 消费）；SIGXCPU/SIGKILL 投递归 B11；fork 本体归 B04（出口联动）；信号队列本体归 B11（限额消费点）；NPROC 计数按 uid 聚合（与 B03 身份对齐）。
- **依赖与嫁接源**：嫁接 getrlimit(2) man-pages CPU/NPROC/SIGPENDING 段与 signal(7) SIGXCPU 语义；锚定 A2 计时基座（F8911 tick 源）、B04 fork 语义档（EAGAIN 出口）、B11 信号族、B25 fork EAGAIN 格联动声明。
- **风险与回退**：风险一为 SIGXCPU 重投递节拍漂移（软限超后连投 vs 周期投）——回退为上游语义冻结：软限超后每消耗 1 秒重投一次 SIGXCPU、硬限触达 SIGKILL，节拍与 A2 tick 单源夹逼复测；风险二为 NPROC 计数泄漏（子进程退出未减计）——回退为计数与任务生命周期钩子绑定（fork 加/wait 收减单段原子），100 轮 fork-exit 后计数回归断言。
- **正文**：实现路径分三步：第一步立 CPU 挂点——cur=2s：任务 CPU 时越 2s 投 SIGXCPU（B11 投递联动 meter 可观测，每秒重投节拍声明），max=4s 触达投 SIGKILL；SIGXCPU 处置为忽略时仍不可豁免硬限（上游行为注记），软限重投/硬限收口三拍状态断言；第二步立 NPROC 联动——uid 计数表（哈希按 uid 聚合活任务数），fork 出口消费 rlimits[NPROC].cur 超限 -EAGAIN（与 B25 格同码同路径对账），收割子进程后计数减一可再 fork 回环断言；第三步立 SIGPENDING——挂起信号计数超 cur 时队列类投递 → -EAGAIN（队列满拒收），标准信号不计数（上游语义注记），计数器与 B11 队列单源对账。与现存内核衔接点：tick 与 F8911 单源；EAGAIN 与 B25 同出口。与 Windows 对照：Windows Job Object 的 JOBOBJECT_END_OF_JOB_TIME_INFORMATION（超时动作 terminate/suspend）与 ActiveProcessLimit（超限 CreateProcess 失败）；无挂起信号配额（信号模型缺席）；对照表落账。判据 UNX-F9164-J1 的复测方式：ktest 三断言——SIGXCPU 三拍断言、NPROC EAGAIN 联动、SIGPENDING 满队列拒绝。

### UNX-F9165 · RLIMIT_FSIZE/LOCKS/MSGQUEUE/RTPRIO 补位族

- **语义边界**：只管四限额判定与挂点；FSIZE 写路径归 B02/B1（出口联动）；锁实装归 B1 联签（F9103）；POSIX mq 未实装（预留声明）；RTPRIO 调度实装归 A1（联签面）。

- **风险与回退**：风险一为 FSIZE 超限双路径混淆（既投 SIGXFSZ 又返 EFBIG）——回退为上游语义冻结：默认处置下信号终止（不返回）、处置为忽略/阻塞时才返回 -EFBIG，双路径判定表；风险二为未实装限额静默假装生效（写入回环过但运行期不查）——回退为零静默声明：LOCKS/MSGQUEUE 登记为预留（回环过、运行期无判定点、判定挂点位置冻结），声明落账。

### UNX-F9166 · prlimit64 与 setrlimit 协同（新旧 ABI 双轨）
- 域/批：C2/B19｜判据：UNX-F9166-J1 双轨协同判据过，新旧 ABI 行为一致可观测，与 B15 prlimit64 档对账一致｜纯功能行数：340 行（新旧 ABI 双轨路由 120 + 行为一致对账 110 + B15 prlimit64 对账 110）｜状态：[已深化]

- **定位**：新旧入口双轨协同：setrlimit/getrlimit（旧口两参）与 prlimit64（新口四参：pid+resource+new+old，可跨进程读写）在内核侧同走一套限额表（单源存储），行为逐格一致——B15 F9092 prlimit64 档的协同收口格。
- **语义边界**：只管双轨路由与一致性；prlimit64 主体语义归 B15 F9092（本条对账不重铺）；跨进程权限判定归 B03（ptrace 同源规则复用）；旧口 32 位 rlim_t 截断语义（INFINITY=0xFFFFFFFF 特判）注记落账本格。
