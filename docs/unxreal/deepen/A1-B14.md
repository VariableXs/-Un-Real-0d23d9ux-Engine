### UNX-F0263 · 串口 XModem-CRC 接收器（镜像导入只读通道）
- 域/批：A1/B14｜判据：UNX-F0263-J1 1MB 接收零丢包（CRC 过），数据只入内存审计区零执行（安全边界）｜纯功能行数：300 行（XModem 状态机 130 + CRC 校验 80 + 安全边界 90；测试段不计）｜状态：[已深化]
- **定位**：串口镜像导入接收器：XModem-CRC 协议（SOH/STX 块、块号、CRC16 校验、ACK/NAK/EOF）最小实现，接收目标镜像到内存"审计区"，用于诊断环境导入样本/补丁包——只入区、零执行，1MB 接收零丢包。
- **语义边界**：**安全边界红线：接收数据仅写入 F0061 登记的审计区（W^X 下不可执行页，F0306 权限矩阵覆盖），任何执行尝试在权限面直接 #PF**；协议范围 = 标准XModem-CRC（不做 1k-XModem/YModem 扩展）；块重传上限 10 次（超限断连落账）；审计区容量 1MB（上限即拒）。
- **依赖与嫁接源**：F0105 串口驱动字节层、F0061 审计区登记、F0306 W^X 矩阵；嫁接经典 XModem-CRC 规范（Ward Christensen 块协议）与 Windows 内核调试器 KDTO 协议的"调试数据面零执行"同位思想。
- **风险与回退**：协议状态机死锁（对端半途静默）——块级超时（3s）+ 总超时（60s）双层兜底断连；CRC 碰撞放过坏块——CRC16-CCITT 捕错能力工程声明 + 接收后整体 SHA-256 落账（构建侧复核）；审计区被误执行——权限位断言（区首 PTE NX 置位检查）。
- 正文：实现路径分三步。第一状态机：idle→wait_start→recv_block（块号/CRC 验证）→ack/nak→eof 终态；NAK 触发同块重传（≤10）；超时双层；状态迁移表驱动。第二 CRC 校验：CRC16-CCITT 块级校验 + 全文 SHA-256 终校验（接收完落账哈希）；坏块计数与重传计数入接收账。第三安全边界：审计区 PTE NX 断言（接收前后各查一次）、容量上限拒收演练、非审计区写入防护（接收器地址硬绑定审计区基址，无指针注入面）；ktest 1MB 传输（构建侧发送脚本）零丢包断言、注入坏块（翻转 1 字节）断言 NAK 重传后终收一致、超时断连演练、执行尝试演练（QEMU 下跳转审计区断言 #PF 被处理非跑飞）。与现存内核衔接点：F0105 字节层复用；F0272 会话状态机的传输会话态消费本器。与 Windows 对照：KD 协议调试通道同位思想；本工程 XModem 更简单但零执行红线更硬。判据 UNX-F0263-J1 的复测方式：ktest 1MB 零丢包、坏块重传一致、NX 断言、上限拒收、超时断连、执行尝试被拦。
