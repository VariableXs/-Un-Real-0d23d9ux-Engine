### UNX-F0821 · LAPIC 基址检测与 MMIO 映射管理
- 域/批：A2/B02｜判据：UNX-F0821-J1 基址三源（MSR/MADT/ACPI 默认）交叉一致，映射只读校验位生效（写入拦截）｜纯功能行数：260 行（三源检测 100 + 映射管理 90 + 校验 70；测试段不计）｜状态：[已深化]
- **定位**：LAPIC MMIO 基址是本域一切寄存器操作的地基（默认 0xFEE00000 但 MSR 可改），本条做三源交叉检测——IA32_APIC_BASE MSR 的基址字段、F0004 MADT 全局地址、ACPI 默认值，三源不一致红账（固件异常信号）；映射页带只读校验（基址页映射后写探测，写成功即映射错误红账）。
- **语义边界**：只做基址检测与映射；不做寄存器操作（F0822 起）、不做 x2APIC 迁移（F0839 分层——本条只管 xAPIC MMIO 档基址）。
- **依赖与嫁接源**：消费 F0004 MADT 账与现存 `msr.rs`；嫁接源为 Intel SDM §10.4.3（IA32_APIC_BASE）与 §10.4.1（默认基址），只跟随。
- **风险与回退**：MSR 基址与 MADT 不一致（极端固件）——按 MSR 优先裁决并红账，MADT 值留差异账，裁决依据随引导账可查。
- 正文：实现路径分三步。第一步三源检测：MSR 0x1B 读基址字段（bit12–35）+ MADT 全局地址（F0004 交付）+ 默认 0xFEE00000 三源并列，一致性裁决（MSR 优先 > MADT > 默认），不一致红账留差异；第二步映射管理：基址 4KB 页经 F0012 高半区映射（缓存禁用属性 PCD=1——MMIO 页禁缓存是硬要求），映射后回读 SVR 寄存器验证可读；第三步只读校验：写探测用"读-算-读"三步（读 SVR→计算写值→读回比对），只读页写探测发现"写成功"即映射属性错误红账（写探测本身用无害值）。与现存内核衔接点：`apic.rs` 现存 `Lapic` 结构的基址字段收编为本条产出，`lapic()` 零改动。与 Windows 对照：Windows 的 HAL 同样三源校验 LAPIC 基址（WinDbg `!pcr` 可见），本内核差异账对齐可观测性，判据 UNX-F0821-J1 的复测方式：三机基址一致率 100%、写探测拦截 10/10 次、映射属性 PCD 位断言通过。

### UNX-F0822 · SVR 寄存器全位语义与使能序列
- 域/批：A2/B02｜判据：UNX-F0822-J1 SVR 四位（使能/焦点重定向/EOI 广播抑制/spurious 向量）逐位断言，使能序列时序正确率 100%｜纯功能行数：240 行（SVR 管理 90 + 使能序列 80 + 位断言 70；测试段不计）｜状态：[已深化]
- **定位**：SVR（Spurious Interrupt Vector Register）是 LAPIC 的总开关+伪中断配置面，四位语义各管一摊：bit8 使能、bit9 焦点处理器重定向抑制、bit12 EOI 广播抑制（x2APIC 才有，xAPIC 保留）、bit0–7 spurious 向量号；本条做全位语义管理与使能序列固化——使能前必须先设 spurious 向量（F0805 识别集联动），序列颠倒会丢伪中断配置。
- **语义边界**：只做 SVR 管理；不做 spurious 处置（F0805）、不做 EOI 抑制的路由联动（F0872 IO-APIC 侧）；与 F0021 分层：F0021 立 SVR 使能位断言，本条立全位语义与序列。
- **依赖与嫁接源**：依赖 F0805 识别集与现存 `apic.rs::LAPIC_SVR`；嫁接源为 Intel SDM §10.9（SVR 全位表）与 §10.4.4（使能序列），只跟随。
- **风险与回退**：固件预使能（BIOS 阶段已开 LAPIC）——检测 SVR 当前态再写（先读后写保位），预使能态登记入账不做重复使能动作，避免"二次使能清配置"事故。
- 正文：实现路径分三步。第一步 SVR 管理：读-改-写三段式封装（禁裸写——会清其他位），四位逐位 getter/setter（每 setter 独立事务），位写入回读验证；第二步使能序列：序列固化三步——①写 spurious 向量（0xFF，F0805 识别集同步）②焦点重定向位按策略置位（默认抑制=bit9=1）③置 bit8 使能，序列前检测预使能态（bit8=1 时跳过①②保留原配置），序列时序账落 F0018；第三位断言族：四位逐位断言（写 1 读 1、写 0 读 0、保留位写 0 读 0）进 ktest。与现存内核衔接点：现存 `SVR_ENABLE` 常量消费，`Lapic` 结构增 SVR 管理方法。与 Windows 对照：Windows 对 SVR 的配置不可直接观测但 spurious 统计纯净（同 F0805 对照），本内核位断言把配置事实显式化，判据 UNX-F0822-J1 的复测方式：四位断言全绿、使能序列 10/10 次时序正确、预使能检测 10/10 次正确跳过。

### UNX-F0823 · EOI 调用点断言与五类向量分账
- 域/批：A2/B02｜判据：UNX-F0823-J1 EOI 全部经单点封装发出（直写拦截率 100%），五类向量（IRQ/MSI/IPI/spurious/NMI）分账独立且断言全绿｜纯功能行数：300 行（单点封装 100 + 五类分账 110 + 直写拦截 90；测试段不计）｜状态：[已深化]
- **定位**：任务书专题一把"丢 EOI"列为本域第一大陷阱，防线是"EOI 全部经由单点封装函数发出并附调用点断言"；本条实现单点封装（`eoi()` 全域唯一出口）+ 调用点断言（封装内验证调用上下文合法性）+ 五类向量独立分账（各类 EOI 次数/延迟/异常分列），直写拦截靠 EOI 地址页写保护（映射只读，封装经别名映射写）——物理级防直写。
- **语义边界**：只做 EOI 出口与分账；不做 eoi_pending 账本本体（F0021 已立，本条消费）、不做五类向量 EOI 行为矩阵（F0859 测试资产）、不做各类语义细分（B03 批）。
- **依赖与嫁接源**：依赖现存 `EoiAudit` 与 F0021 eoi_pending 账本；嫁接源为 Intel SDM §10.8.5（EOI 寄存器）与 Linux apic_eoi 单点惯例，只跟随。
- **风险与回退**：写保护影响性能（别名映射写多一次 TLB 查找）——EOI 是高频路径，性能账（F0954 分发基线）纳入写保护开销测量，超预算（>0.5µs 额外开销）走 ADR 裁决降级为"封装纪律+静态扫描"档。
- 正文：实现路径分三步。第一步单点封装：`eoi(vector_class)` 全域唯一 EOI 出口，封装内三查——调用上下文（中断态内合法）、vector_class 合法性（五类枚举）、eoi_pending 账本对账（有 pending 才许发 EOI），三查任一失败红账；第二步五类分账：五类向量各建独立账（次数/最后一次延迟/异常计数），账本结构对齐 F0854 导出 schema；第三步直写拦截：EOI 地址（LAPIC_BASE+0xB0）页映射只读，封装经 MMIO 别名映射（同物理页另一 VA，写使能）写，直写尝试触发 #PF 被 F0813 底座识别为"EOI 直写事故"红账——物理级拦截。与现存内核衔接点：现存 `EoiAudit` 收编进分账，`lapic()` EOI 写点替换为封装调用。与 Windows 对照：Windows EOI 经 HAL 单点（HalpEoiIoApic 类），本内核物理拦截对齐"结构性防错"，判据 UNX-F0823-J1 的复测方式：直写注入 10/10 次触发 #PF 红账、五类分账独立可查、三查断言全绿。

### UNX-F0824 · TPR/PPR 任务优先级寄存器与中断屏蔽语义
- 域/批：A2/B02｜判据：UNX-F0824-J1 TPR 置 N 屏蔽 0–N 优先级中断 10/10 次生效，PPR 反映与规格一致（Class/Subclass 全宽）｜纯功能行数：260 行（TPR 管理 100 + PPR 对账 80 + 屏蔽验证 80；测试段不计）｜状态：[已深化]
- **定位**：TPR（Task Priority Register）是中断的优先级闸门——TPR 置 N 后优先级 ≤N 的中断被暂扣（不是丢弃，是等待 TPR 下降），这是内核临界区"屏蔽低优中断"的硬件原语；PPR（Processor Priority Register）是硬件根据 TPR+ISR 状态算出的实际生效闸门；本条做 TPR 管理原语与 PPR 对账（软件预期 vs 硬件实态），屏蔽语义注入验证。
- **语义边界**：只做 TPR/PPR；不做 CR8 联动（F0825）、不做优先级策略（F0913 分组策略）；与 F0021 分层：F0021 不涉 TPR，本条独立。
- **依赖与嫁接源**：依赖现存 `LAPIC_TPR` 常量；嫁接源为 Intel SDM §10.8.6.1（TPR/PPR 语义与 PPR 计算规则），只跟随。
- **风险与回退**：TPR 忘复位（临界区退出漏写）——TPR 复位纪律与 A5 锁层次联动（临界区标记强制带 TPR 恢复），超时检测（TPR>0 持续超 1ms 且无临界区标记）红账告警，防"中断永扣"静默事故。
- 正文：实现路径分三步。第一步 TPR 管理：`tpr_set(class, subclass)`/`tpr_clear()` 原语（Class 4 位+Subclass 4 位全宽），写后回读验证，读写经封装（与 F0823 同纪律）；第二步 PPR 对账：PPR 只读寄存器定期采样（每 tick 一次采样点），与软件 TPR+ISR 状态推算的预期值比对，连续 3 次不一致红账（固件/虚拟化异常信号）；第三步屏蔽验证：注入用例——TPR 置 4 后向本核投递优先级 2/5/7 三档测试中断，验证 2 被暂扣（IRR 置位 ISR 不置）、5/7 正常投递，TPR 清零后 2 立即补投，时序账记录暂扣时长。与现存内核衔接点：`apic.rs` 增 TPR 方法族，临界区入口挂点预留 A5 联动。与 Windows 对照：Windows 的 IRQL 机制就是 TPR 的软件抽象（KeRaiseIrql→TPR 写），WinDbg `!irql` 可查，本内核 TPR 账对齐 IRQL 可观测性，判据 UNX-F0824-J1 的复测方式：三档屏蔽 10/10 次正确、暂扣补投时序账完整、PPR 对账不一致检测 10/10 次红账。

### UNX-F0825 · CR8 与 TPR 联动快路径
- 域/批：A2/B02｜判据：UNX-F0825-J1 CR8 写与 TPR Class 字段同步 10/10 次一致，快路径开销实测低于 MMIO 路径 50%｜纯功能行数：220 行（CR8 封装 80 + 联动验证 70 + 性能账 70；测试段不计）｜状态：[已深化]
- **定位**：CR8 是 TPR 的 Class 字段快捷视图（x2APIC 时代的性能遗产——MMIO 读 TPR 慢，CR8 一次寄存器读写），本条做 CR8 封装与双写一致性（CR8 写必须同步 TPR Subclass=0，读时以 TPR 为准源）、快路径性能账（同 TPR 写 MMIO vs CR8 耗时对比落账），为高频临界区（A5 自旋锁 irqsave 档）提供硬件快路径。
- **语义边界**：只做 CR8 封装与联动；不做 TPR 策略（F0824）、不做锁原语（A5 域）；xAPIC/x2APIC 双模式下 CR8 行为一致性是判据核心。
- **依赖与嫁接源**：依赖 F0824 TPR 管理；嫁接源为 Intel SDM §10.8.6.2（CR8 与 TPR 关系：CR8 访问=TPR Class 字段访问，Subclass 恒 0），只跟随。
- **风险与回退**：CR8 写清零 Subclass（硬件语义如此）导致精细优先级丢失——封装纪律：需要 Subclass 精度的场景禁用 CR8 快路径（白名单控制），精度需求与性能需求的裁决规则显式化。
- 正文：实现路径分三步。第一步 CR8 封装：`cr8_read()/cr8_write(class)` 封装，write 内同步写 TPR（Class 同值+Subclass=0，双写原子性靠中断关闭窗口保护），read 返回 TPR 实态（准源是 TPR）；第二步联动验证：CR8 写后 TPR 回读（Class 一致/Subclass=0 断言）、TPR 直接写后 CR8 读（Class 一致），双向 10/10 次；第三步性能账：两路径各 10 万次写实测均值/p99 落账（预期 CR8 快 ≥50%），性能账供 A5 锁路径选型消费，不达预期如实记档（性能不虚报）。与现存内核衔接点：`msr.rs`/`cpuinfo.rs` 消费 CR8 支持位（CPUID.01H:ECX[13] x2APIC 与 CR8 语义捆绑检测）。与 Windows 对照：Windows IRQL 快路径同样利用 CR8（`!irql` 与 CR8 值一致可观测），本内核性能账对齐优化透明性，判据 UNX-F0825-J1 的复测方式：双写一致 10/10 次、性能账开销达标、精度场景白名单拦截 10/10 次正确。

### UNX-F0826 · ISR/IRR/TMR 位图查询与状态机
- 域/批：A2/B02｜判据：UNX-F0826-J1 三位图读回与注入投递一致率 100%（256 向量 × 10 万次），查询原语零副作用｜纯功能行数：260 行（位图查询 110 + 状态机建模 80 + 验证 70；测试段不计）｜状态：[已深化]
- **定位**：ISR（In-Service，已接手未 EOI）/IRR（Received，已接收未接手）/TMR（Trigger Mode，边沿/电平）三张 256 位硬件位图是 LAPIC 的内部状态机账本；查询协议特殊——写寄存器号再读数据（两次 MMIO，非原子），本条做查询原语封装（含窗口期竞态说明）与状态机软件建模（ISR/IRR 软件镜像，与硬件位图对账），"中断在途审计"（F0850）的地基。
- **语义边界**：只做位图查询与镜像建模；不做 EOI 残留审计（F0850 消费本条）、不做 TMR 写入（硬件自动维护，只读语义）。
- **依赖与嫁接源**：依赖现存 `LAPIC_ISR_BASE/TMR_BASE/IRR_BASE` 常量；嫁接源为 Intel SDM §10.8.3（三寄存器族与读协议）、§10.5.4（TMR 语义），只跟随。
- **风险与回退**：读窗口期状态变化（读 IRR 时新中断到达）——镜像对账容忍窗口期差异（差异 <阈值=正常竞态，连续超阈=异常红账），对账纪律显式化不苛求原子（硬件本就不原子）。
- 正文：实现路径分三步。第一步查询原语：`isr_read()/irr_read()/tmr_read()` 三原语，256 位逐 32 位段读（8 段），段读序固定（低段→高段，保证快照单调性），原语零副作用（纯读）；第二步软件镜像：三张软件位图镜像（静态数组），投递/接手/EOI 事件驱动更新，与硬件位图周期对账（差异按窗口期容忍度裁决）；第三步状态机验证：注入用例——投递 N 个不同优先级向量，逐步读回 ISR/IRR 验证状态迁移（IRR 置位→最高优先级进 ISR→EOI 后清除），256 向量 × 10 万次注入一致率 100%。与现存内核衔接点：`apic.rs` 增位图查询族，现存 EOI 审计消费镜像。与 Windows 对照：Windows `!idt`/`!apic` 扩展可 dump ISR/IRR 位图，本内核镜像+对账把同一能力常驻化，判据 UNX-F0826-J1 的复测方式：10 万次注入一致率 100%、对账窗口期容忍裁决正确、查询零副作用断言（读前后状态不变）。

### UNX-F0827 · ESR 错误状态寄存器两次读语义与错误分账
- 域/批：A2/B02｜判据：UNX-F0827-J1 两次读语义正确（首读锁定次读清零，注入 10/10 次符合），错误位七类分账独立｜纯功能行数：260 行（ESR 协议 100 + 分账 90 + 注入验证 70；测试段不计）｜状态：[已深化]
- **定位**：ESR（Error Status Register）记录 LAPIC 内部错误（非法寄存器访问/接收校验错/发送校验错/重定向 IPI 非法/送达失败/送达非法/接收非法七位），读协议特殊——先写一次清旧值再读新值（"两次读"语义，SDM 明文），单读会丢错误；本条做协议封装（write-then-read 固定序）与七位错误分账，错误位是 LAPIC 健康的体温计（F0997 健康总账消费）。
- **语义边界**：只做 ESR 协议与分账；不做 LVT 错误中断挂接（F0830 错误 LVT 条目联动 ESR）；xAPIC/x2APIC 差异（x2APIC 读即清）按模式分档封装。
