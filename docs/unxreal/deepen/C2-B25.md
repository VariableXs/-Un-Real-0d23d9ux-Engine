### UNX-F9281 · 进程族 E 型总纲（进程空间错误面）
- 域/批：C2/B25｜判据：UNX-F9281-J1 进程空间错误面判据过，四类错误域（pid 不存在/权限/资源耗尽/参数坏值）逐格落账，判序协议声明格过｜纯功能行数：400 行（四错误域逐格落账 140 + 判序协议声明 130 + 批内归域总编排 130）｜状态：[已深化]

- **定位**：本条是进程族 E 型错误矩阵（F9282–F9299 各专条）的总纲：以 pid 不存在→ESRCH、权限不足→EPERM、资源耗尽→EAGAIN/ENOMEM、参数坏值→EINVAL/EFAULT 四类错误域为骨架，立进程空间错误面的判域全景与判序协议基线，B25 批全部注入格的总装配图。
- **语义边界**：只管判域划分与判序协议声明；kill 三码矩阵归 F9282、fork 双耗尽归 F9284/F9285、execve 四码归 F9288、判序协议专条归 F9293；进程正判据（fork/execve/wait 正路径语义）归 B04/B08/B18 母体深化册（本批只铺错误面不重铺正面）。
- **依赖与嫁接源**：嫁接 kill(2)/fork(2)/execve(2)/setpgid(2) man-pages ERRORS 段四域错误清单；锚定 B21–B28 E 型正反双判据体例、B13 错误矩阵总装（B01–B15 轮）、B18 进程族地基母体、F9293 判序专条。
- **风险与回退**：风险一为四判域重叠漏判（同一注入既缺 pid 又坏参数时判域歧义）——回退为判序协议硬规则：pid 存在性→权限→资源→参数四级瀑布判定，每级判定函数签名冻结，注入格按判序落点归域；风险二为错误面与正判据面混铺（错误注入误触正路径语义）——回退为域账分层声明：本批号段只含错误注入断言，正路径断言零条（逐条扫描声明落账）。
- **正文**：实现路径分三步：第一步立四错误域逐格落账——pid 不存在域（kill/wait/setpgid 的 ESRCH 面）、权限域（kill pid=1 EPERM/setsid 会话首 EPERM 面）、资源耗尽域（fork RLIMIT_NPROC EAGAIN/地址空间 ENOMEM 面）、参数坏值域（非法 sig EINVAL/坏指针 EFAULT 面）四域判定表落账，每域列出触发 syscall 集与典型注入构造；第二步立判序协议声明——四级瀑布（存在性→权限→资源→参数）声明格冻结：判序即错误码优先级，前级命中即短路返回，后级不再评估，该协议是全批注入格的公共前置（F9293 专条逐例展开）；第三步立错误面总编排——批内 19 条专条按四域挂载归位（每条标注所属域与注入格数），总纲断言批内每条恰属一域、跨域注记条单列。与现存内核衔接点：进程查找与 B18 pid 表单源；错误码出口与 B01 分发表 errno 通道单源。与 Windows 对照：Windows 进程错误族以 NTSTATUS/Win32 ERROR 为主（ERROR_INVALID_PARAMETER/ERROR_ACCESS_DENIED），无 POSIX errno 直映，映射对账归 F9296；本条按 Linux 上游语义冻结。判据 UNX-F9281-J1 的复测方式：ktest 三断言——四域判定表逐域命中、判序瀑布短路序断言、19 条归域扫描零漏挂。

### UNX-F9282 · kill 坏 pid 矩阵（ESRCH/EPERM/EINVAL）
- 域/批：C2/B25｜判据：UNX-F9282-J1 三错误码注入矩阵判据过，pid=1 EPERM 特例格过，非法 sig 全 EINVAL 格过，不存在 pid 全 ESRCH 格过｜纯功能行数：360 行（三错误码注入矩阵 140 + pid=1 EPERM 特例格 90 + 非法 sig EINVAL 格 70 + 坏 pid ESRCH 格 60）｜状态：[已深化]

- **定位**：本条立 kill(pid, sig) 三错误码注入矩阵：ESRCH（pid 不存在）、EPERM（无权投递，含 pid=1 特例）、EINVAL（非法 sig 值）三格逐格注入构造与判定路径，进程族 E 型矩阵最常用条，shell kill 命令与进程管理的错误底座。
- **语义边界**：只管 kill 注入面三码；SIGKILL 信号本体语义归 B11（红线注记：零强杀路径，矩阵只验投递拒绝）；判序细节（ESRCH 先于 EPERM）归 F9293 专条；wait ECHILD 归 F9283。
- **依赖与嫁接源**：嫁接 kill(2) man-pages ERRORS 段三行原文语义（'No process can be found'/'do not have permission'/'invalid signal'）；锚定 B11 信号投递挂点（权限校验单源）、B03 身份族（uid 校验）、F9293 判序协议。
- **风险与回退**：风险一为 EPERM 判定泄漏存在性信息（对不存在 pid 先查权限致逐 pid 探测可行）——回退为判序格：存在性查找先行（F9293 协议），查无即 ESRCH 短路，权限只在 pid 命中后评估；风险二为 sig=0 探测语义误判（sig 0 用于存在性探测不投递，误报 EINVAL 或误投真信号）——回退为 sig=0 专项格：sig=0 合法且不投递（仅做存在性+权限空检），与 Linux 上游逐例一致。
- **正文**：实现路径分三步：第一步立三码注入矩阵——ESRCH 组：pid=不存在大值/pid=未分配空洞值/pid=已终结重命名值等 5 值全 -ESRCH；EPERM 组：pid=1（init，非特权投递必拒绝，本内核单用户域简化为 pid=1 一律拒绝真信号冻结）×3 注入；EINVAL 组：sig=64/sig=-1/sig=33（超出 0–31 合法集）×5 值全 -EINVAL，三组逐格 errno 断言表落账；第二步立 pid=1 特例格——pid=1 存在性成立前提下的 EPERM 判定链三拍断言（存在→权限→拒绝），与 ESRCH 组对照断言（pid=1 必非 ESRCH，错误码互斥扫描）；第三步立非法 sig 格——sig 值域校验函数与 B11 投递路径共用单源（值域表 grep 核），注入非法 sig 断言零混 ESRCH/EPERM（EINVAL 单一出口），sig=0 探测格并列：对存在 pid 成功、对不存在 pid ESRCH，投递计数恒零。与现存内核衔接点：pid 查找与 B18 进程表单源；权限校验与 B03/B11 单源。与 Windows 对照：Windows TerminateProcess 无权时 ERROR_ACCESS_DENIED、句柄无效 ERROR_INVALID_HANDLE，kill 的信号投递模型无直映（映射差异账归 F9296）；本条按 POSIX 冻结。判据 UNX-F9282-J1 的复测方式：ktest 三断言——三码注入矩阵逐格 errno、pid=1 特例三拍链与互斥扫描、sig 值域扫描表含 sig=0 探测格。

### UNX-F9283 · wait 坏 pid ECHILD 矩阵（联 B18 对账）
- 域/批：C2/B25｜判据：UNX-F9283-J1 无子进程注入判据过，全 ECHILD 格过，与 B18 wait 矩阵零重复分层格过｜纯功能行数：320 行（无子进程注入 130 + ECHILD 全格 90 + B18 分层对账 100）｜状态：[已深化]

- **定位**：本条立 wait 族（wait/waitpid）无子进程态的 ECHILD 注入矩阵：调用方零子进程（从未 fork/子已收割尽）时全部 wait 形态统一 -ECHILD——shell 作业控制与 init 收割循环的错误前提格，与 B18 wait 正判据矩阵零重复分层。
- **语义边界**：只管 ECHILD 注入面（无子/无此子两态）；waitpid 正路径状态机归 B18 母体（对账不重铺）；EINTR（waitpid 阻塞中被信号打断）归 B12 判定器消费；僵尸收割竞态归 F9291（本条静态注入无竞态）。
- **依赖与嫁接源**：嫁接 wait(2) man-pages ECHILD 行原文语义（'the calling process has no existing unwaited-for children'）；锚定 B18 wait 矩阵母体格（正路径对账单源）、B04 fork 档（子进程计数来源）、B12 EINTR 判定器。
- **风险与回退**：风险一为 ECHILD 与阻塞语义混淆（无子进程时误挂起等待而非立即返错）——回退为立即返错格：零子进程态不等待（时钟夹逼 <1ms 返回 -ECHILD），挂起断言为零；风险二为 waitpid(pid) 的"无任何子"与"有子但非此 pid"两态判错（存活非己子被误判或误伤）——回退为两态对照格：两注入分别断言均 -ECHILD 但判定路径不同（子表空查 vs 子表扫描未命中），路径观测点落账。
- **正文**：实现路径分三步：第一步立无子注入——新起任务（零 fork 历史）直接 wait/waitpid(-1,0)/waitpid(9999,0) 三形态注入，全 -ECHILD 且不挂起（耗时夹逼），子进程计数值 0 断言；第二步立 ECHILD 全格——收割后态：fork 一子、wait 成功一次后再 wait → -ECHILD（子已收割清空），双子收光后第三次 wait → -ECHILD，三格逐步计数观测（子计数 1→0 后置 ECHILD）落账；第三步立 B18 对账——与 B18 wait 矩阵分层声明：B18 铺正路径状态机（running→zombie→reaped），本条只铺无子可收注入面，两册断言零重叠扫描（断言文本 diff 落账），判定函数与 B18 同源（同一 wait_core 入口，注入面只是其错误分支），对账表两行（入口函数/分层边界）登记。与现存内核衔接点：子表遍历与 B18 单源。与 Windows 对照：Windows WaitForSingleObject 无子概念，句柄无效 WAIT_FAILED+ERROR_INVALID_HANDLE，ECHILD 的收割完成语义无直映（CloseHandle 后句柄失活近似）；对账注记落账。判据 UNX-F9283-J1 的复测方式：ktest 三断言——三形态注入全 ECHILD 不挂起、收割后计数三格、B18 分层 diff 零重叠。

### UNX-F9284 · fork/clone EAGAIN 矩阵（RLIMIT_NPROC 联动）
- 域/批：C2/B25｜判据：UNX-F9284-J1 进程数触顶注入判据过，全 EAGAIN 格过，与 B19 NPROC 联动格过，释放后恢复正判据格过｜纯功能行数：380 行（进程数触顶注入 140 + 全 EAGAIN 格 80 + B19 NPROC 联动 90 + 释放后恢复正判据 70）｜状态：[已深化]

- **定位**：本条立 fork/clone 资源耗尽第一源 EAGAIN 注入矩阵：任务数触顶 RLIMIT_NPROC 时 fork/clone 全量返回 -EAGAIN——fork 炸弹防护与进程配额治理的错误面，fork 失败双源矩阵（EAGAIN/ENOMEM）的进程数侧。
- **语义边界**：只管 NPROC 触顶注入面；地址空间耗尽 ENOMEM 归 F9285（双源分界对账）；RLIMIT_NPROC 限额本体与 getrlimit/setrlimit 语义归 B19 资源限制族（联动对账不重铺）；clone 线程上限（CLONE_VM 侧共池计数）同格覆盖不另铺。
- **依赖与嫁接源**：嫁接 fork(2) man-pages EAGAIN 行原文（'RLIMIT_NPROC was reached'）；锚定 B19 限额族深化册（NPROC 值读写联动）、B04 fork 档（进程创建计数挂点）、B18 进程表（容量上限常量）。
- **风险与回退**：风险一为触顶边界 off-by-one 反向（NPROC=8 时第 8 个误拒或第 9 个误放行）——回退为边界值格：预起 NPROC-1 任务后 fork 必成功、再 fork 必 -EAGAIN，计数=上限前后两断言夹逼；风险二为限额释放后不复原（子退出后配额泄漏致后续 fork 永久 EAGAIN）——回退为恢复正判据：触顶后收割一个子再 fork 必成功（配额回还观测），泄漏即 fail。
- **正文**：实现路径分三步：第一步立触顶注入——经 B19 联动置 RLIMIT_NPROC=8，连续 fork：第 1 至第 8 子成功（进程计数逐次递增断言）、第 9 次 fork 返回 -EAGAIN，注入循环带计数器形成 8 成功+1 拒绝精确序列断言；第二步立全 EAGAIN 格——clone（CLONE_VM|CLONE_FS 线程态）同触顶同拒绝（线程与进程共池计数声明落账），fork+clone 混合注入 10 组全 -EAGAIN 且 errno 单一（零混 ENOMEM 互斥扫描）；第三步立联动与恢复——与 B19 对账两项：限额值变更实时生效（NPROC 8→16 后 fork 立即可行，getrlimit 回读同源）、触顶后收割一子配额回还（fork 再成功+计数回位断言），恢复正判据收口。与现存内核衔接点：进程计数与 B18 进程表容量单源；限额读取与 B19 单源。与 Windows 对照：Windows 无 RLIMIT_NPROC（配额走 Job Object 的 active process limit），满额 ERROR_NOT_ENOUGH_QUOTA；映射注记归 F9296。判据 UNX-F9284-J1 的复测方式：ktest 三断言——8+1 精确序列、clone 混注全 EAGAIN 互斥扫描、释放后 fork 成功与限额实时生效。

### UNX-F9285 · fork/clone ENOMEM 矩阵（地址空间耗尽）
- 域/批：C2/B25｜判据：UNX-F9285-J1 地址空间耗尽注入判据过，全 ENOMEM 格过，COW 挂点依赖声明格过｜纯功能行数：340 行（地址空间耗尽注入 140 + 全 ENOMEM 格 90 + COW 挂点依赖声明 110）｜状态：[已深化]

- **定位**：本条立 fork/clone 资源耗尽第二源 ENOMEM 注入矩阵：父进程地址空间复制所需内存不可得（页池余量不足/VMA 表满）时返回 -ENOMEM——fork 失败双源（EAGAIN 进程数侧 F9284/ENOMEM 内存侧本条）矩阵的收口条。
- **语义边界**：只管内存耗尽注入面；页池分配器本体与回收策略归内存域母体（本条只构造耗尽态消费其返回）；COW 页复制挂点实装归 B04 fork 档联签（依赖声明格）；EAGAIN 进程数源归 F9284（双源分立）。
- **依赖与嫁接源**：嫁接 fork(2) man-pages ENOMEM 行原文（'failed to allocate the necessary kernel structures'）；锚定 B04 fork 档 COW 挂点（页复制路径声明）、内存池冻结接口（容量常量）、F9284 EAGAIN 源（双源分界对账）。
- **风险与回退**：风险一为双源混淆（内存耗尽误触 EAGAIN 或配额触顶误报 ENOMEM）——回退为双源分立格：进程数未触顶+仅页池耗尽的注入必返 ENOMEM，errno 与触因一一对应（触因探针：预压页池至余量低于父进程页数再 fork），两源互斥断言；风险二为半程失败残留（复制半途失败后父进程页表被污染或页池泄漏）——回退为失败原子性格：ENOMEM 后父地址空间完整（页表校验和前后一致），半程资源全回收（页池余量回还断言）。
- **正文**：实现路径分三步：第一步立耗尽注入——构造父进程大 VMA（预写脏页抬高复制成本），压页池余量至低于复制需求，fork → -ENOMEM，触因探针（分配请求计数在失败点中断）可观测，与 F9284 触顶态（页池充裕仅配额满）对照构造同跑断言两源互斥；第二步立全 ENOMEM 格——同耗尽态 clone（CLONE_VM 轻量路径仍需内核结构）注入亦 -ENOMEM、VMA 表满态注入（父进程 VMA 拉满表容量）fork → -ENOMEM，三构造逐格 errno 断言并互斥扫描（零混 EAGAIN 零混 EFAULT）；第三步立 COW 依赖声明——本条注入面依赖 B04 fork 档 COW 挂点（页复制路径失败点的回滚协议），联签声明：失败时已复制页全回收、未复制页零触及，父态校验和不变，声明与 B04 冻结接口互认落账。与现存内核衔接点：页池与内存域容量常量单源；VMA 表与 B03 地址空间母体单源。与 Windows 对照：Windows CreateProcess 内存不足 ERROR_COMMITMENT_LIMIT/ERROR_NOT_ENOUGH_MEMORY，fork 的 COW 复制语义无直映；差异账归 F9296。判据 UNX-F9285-J1 的复测方式：ktest 三断言——压池注入 ENOMEM 与两源互斥、三构造 errno 表、失败后父页表校验和与页池回还。

### UNX-F9286 · setpgid 坏 pid ESRCH 矩阵
- 域/批：C2/B25｜判据：UNX-F9286-J1 坏 pid 注入判据过，全 ESRCH 格过，跨会话 EPERM 格过，与 B18 对账格过｜纯功能行数：320 行（坏 pid 注入 120 + 全 ESRCH 格 70 + 跨会话 EPERM 格 70 + B18 对账 60）｜状态：[已深化]

- **定位**：本条立 setpgid(pid, pgid) 的错误注入矩阵：pid 不存在全 -ESRCH 主格、跨会话移动 -EPERM 次格、exec 后禁改 -EACCES 注记格——作业控制（shell 前后台进程组管理）的错误底座，进程组语义的注入面。
