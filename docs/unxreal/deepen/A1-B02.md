### UNX-F0022 · IDT 全量重排与异常栈切换（IST）
- 域/批：A1/B02｜判据：UNX-F0022-J1 256 向量全挂接；Double Fault 走 IST 独立栈真机可验（构造栈溢出触发 DF 且现场完整）｜纯功能行数：340 行（256 向量挂接器 120 + IST 三栈 100 + 现场保存宏 120；测试段不计）｜状态：[已深化]
- **定位**：IDT 是 CPU 异常与外部中断的总接线板，本条把现存零散向量处理收敛为 256 向量全挂接 + IST 独立栈三张（Double Fault/NMI/机器检查）——栈溢出引发的 Double Fault 必须走独立栈才能被接住，这是"接住接不住的异常"的关键设计。
- **语义边界**：只做 IDT 布线与异常栈切换；不做具体异常的业务处置（panic 归 F0037、页错误语义归 AI-04）、不做中断控制器投递（F0023/F0024 防重）。
- **依赖与嫁接源**：依赖 F0021 LAPIC 底座与 F0012 高半区布局（IST 栈选址）；嫁接源为 Intel SDM Vol.3 第 6 章（IDT/IST/TSS）与 WinDbg `!idt` 可观测语义，只跟随。
- **风险与回退**：IST 栈选址与 F0012 布局表冲突——三栈从保留区划出并在布局表登记，选址冲突引导期红账拒绝继续；向量挂接遗漏在引导自检用"空向量计数器"显式记账。
- 正文：实现路径分三步。第一步向量挂接器：256 项 IDT 表静态构建，异常 0–31 全挂专用处理、IRQ 32 起挂通用分发、系统调用向量留位注释，每项经宏生成入口（寄存器现场全量保存、有错误码与无错误码分型、现场结构体地址入参），引导自检遍历 IDT 计"非空向量数"落账；第二步 IST 三栈：Double Fault/NMI/机器检查三张独立栈各 16KB，从 F0008 保留区划出、F0012 布局表登记，TSS 的 IST 索引逐项配置并与 IDT 项的 IST 位交叉校验；第三步验证路径：ktest 构造栈溢出触发 Double Fault——溢出栈（正常栈已毁）的现场必须完整保存于 IST 栈并转 F0037 panic 路径，现场寄存器与 RSP 快照落账可查。与现存内核衔接点：`main.rs` 异常入口与 F0037 panic 路径对接，TSS/GDT 初始化收编本条管理。与 Windows 对照：Windows x64 的 Double Fault 走 KiDoubleFaultStack 独立栈（WinDbg `!idt` 可见 DF 向量挂接），本内核把同等保护以"三栈+交叉校验"制度化，判据 UNX-F0022-J1 的复测方式：空向量计数为零、栈溢出注入 10/10 次现场完整、IST 栈选址与布局表交叉校验 50/50 次通过。

### UNX-F0023 · IOAPIC 重定向表管理（GSI 映射）
- 域/批：A1/B02｜判据：UNX-F0023-J1 GSI→向量映射真机可配置、可屏蔽、可查询｜纯功能行数：300 行（多实例管理 90 + GSI 两级映射 100 + RTE 配置语义 110；测试段不计）｜状态：[已深化]
- **定位**：IOAPIC 是外部中断的总调度台，本条实现多 IOAPIC 实例管理与 GSI→（实例，重定向表项）两级映射——RTE 配置语义（向量/投递模式/极性/触发模式/屏蔽位）全量落地，ISA Override 条目的极性与电平继承自 F0004 初值表，屏蔽/解屏蔽/查询三原语齐备。
- **语义边界**：只做 IOAPIC RTE 管理面；不做设备中断使能策略（设备域自管）、不做 ACPI PCI 路由 _PRT（A5 类驱动模型阶段接入，本条先立 GSI 管理面）。
- **依赖与嫁接源**：依赖 F0004 IOAPIC 条目与 Override 初值表、F0021 LAPIC 投递；嫁接源为 Intel SDM Vol.3 第 8 章 IOAPIC 章节与 Windows msinfo32 硬件资源-IRQ 可观测语义，只跟随。
- **风险与回退**：RTE 写入后回读不符（虚拟化环境或怪芯片组）——回读校验失败即打红账并降级该 GSI 为屏蔽态，绝不带"以为配好了"的状态运行。
- 正文：实现路径分三步。第一步多实例管理：从 F0004 账取每 IOAPIC 的 MMIO 基址与 GSI 基址，建立实例表，IOAPICVER/IOAPICID 寄存器逐一探活并落账；第二步 GSI 两级映射：GSI 号→（实例索引，RTE 索引）的静态函数，`route(gsi, vector, flags)` 配置语义逐位落地（目的模式、投递模式、极性、触发模式、屏蔽位），F0004 Override 初值逐条灌入 RTE 并回读比对；第三步三原语与查询账：mask/unmask/status 三原语带回读断言，全表可导出（GSI/向量/极性/触发/屏蔽态五行账）供 F0027 亲和迁移与运行期查询，RTE 回读不符降级屏蔽并记缺陷账。与现存内核衔接点：消费 `acpi::madt()` 的 `ioapics()`/`isos()`，MMIO 访问经 F0012 高半区直映射。与 Windows 对照：Windows msinfo32"硬件资源-IRQ"呈现设备中断占用与路由结果，本内核全表导出以同颗粒度可查，判据 UNX-F0023-J1 的复测方式：真机全 GSI 配置回读 100% 一致、屏蔽/解屏蔽/查询三原语各 100 次零异常、Override 继承项与 F0004 初值逐条相等。

### UNX-F0024 · MSI-X 分配器与消息编码
- 域/批：A1/B02｜判据：UNX-F0024-J1 NVMe 挂 MSI-X 多队列中断真机可用（现存轮询升级接管）｜纯功能行数：320 行（能力结构解析 90 + 向量分配器 110 + 消息编码与使能协议 120；测试段不计）｜状态：[已深化]
- **定位**：MSI-X 是现代设备中断的正道，本条实现 MSI-X 能力结构解析（表 BAR 偏移/表大小）、向量分配器（每设备多向量、per-CPU 亲和预留给 F0027）、消息地址/数据编码（remappable 与非 remappable 两档）、使能/禁用协议——首个消费者是 NVMe：现存轮询 NVMe 挂 MSI-X 多队列中断，"全轮询内核"第一次被打穿的标志条目。
- **语义边界**：只做 MSI-X 能力面与向量分配；不做 NVMe 队列业务（B4 域防重）、不做 MSI/MSI-X 之外的传统 INTx 路由（F0023 防重）。
- **依赖与嫁接源**：依赖 F0021 LAPIC（MSI 投递目标）、F0023 GSI 面；嫁接源为 PCIe 规范 MSI-X 能力章节与 Intel SDM 消息中断地址/数据格式，只跟随。
- **风险与回退**：设备 MSI-X 能力畸形（表大小为零或 BAR 映射失败）——能力探活失败显式记账并回落轮询（F0039 双模开关兜底），绝不带病挂中断。
- 正文：实现路径分三步。第一步能力结构解析：PCI 配置空间扫描 MSI-X 能力链（能力 ID 0x11），解析表偏移/BIR、PBA 偏移/BIR、表大小三组字段，BAR 映射经 F0012 布局校验后取用，解析结果逐字段落账；第二步向量分配器：全局向量池按设备请求切分连续段（NVMe 队列数即请求段长），段内 per-CPU 亲和位预留给 F0027，分配/回收带泄漏检测（引用计数账）；第三步消息编码与协议：消息地址（0xFEE00000 基 + 目标 LAPIC 编码）与消息数据（向量号）按 IA32 格式写入 MSI-X 表逐项，remappable 档位按平台中断重映射能力选择并落账，使能协议（先表后使能位）带状态机防中间态，NVMe 接入走 F0039 切换协议。与现存内核衔接点：现存 NVMe 轮询路径经 `IrqBackend` trait（F0039）挂接，`bootchain.rs` 探活链新增 MSI-X 探活点。与 Windows 对照：Windows 设备管理器设备"资源"页显示 MSI/MSI-X 中断类型与向量，本内核分配账以同颗粒度可导出，判据 UNX-F0024-J1 的复测方式：NVMe 多队列中断真机触发、1,000 次模式往返零丢事件（随闸门补测）、能力畸形注入 10/10 次回落轮询留账。

### UNX-F0025 · x2APIC 模式支持与迁移
- 域/批：A1/B02｜判据：UNX-F0025-J1 x2APIC 真机启用且与 xAPIC 路径行为一致｜纯功能行数：280 行（特性检测 60 + 两步迁移序 90 + MSR 双寻址统一 130；测试段不计）｜状态：[已深化]
- **定位**：x2APIC 是 LAPIC 的现代寻址模式（MSR 取代 MMIO），本条实现特性检测、xAPIC→x2APIC 两步迁移序（先 EXTD 后 ENABLE，避免中间态）、MSR 寻址全语义，与 F0021 的 mmio 路径统一封装——同一中断在两模式下的时序与语义等价是硬判据。
- **语义边界**：只做模式迁移与双寻址封装；不做 IPI 广播业务（F0026 防重）、不做 x2APIC 物理簇模式（物理目的模式起步，簇模式留 A3 SMP 深化）。
- **依赖与嫁接源**：依赖 F0015 CPUID x2APIC 特征位与 F0021 LAPIC 底座；嫁接源为 Intel SDM Vol.3 第 8 章 x2APIC 扩展，只跟随。
- **风险与回退**：迁移序列中途异常（EXTD 置位后 ENABLE 失败）——按 SDM 规定回退路径退回 xAPIC 并记缺陷账，模式选择结果落 BootManifest 供 AI-03 消费。
- 正文：实现路径分三步。第一步特性检测：F0015 账取 CPUID 叶 1 ECX bit21（x2APIC）与 IA32_APIC_BASE 的 EXT 位状态，三态判定（不支持/xAPIC 可迁/x2APIC 已启）落账；第二步两步迁移序：IA32_APIC_BASE 先置 EXTD（bit14）再置 ENABLE（bit11），两步间读回确认，任一步失败按 SDM 回退序退回并显式记账，迁移全程 TSC 计时落 F0018 账；第三步双寻址统一：MMIO 读写与 MSR 读写封装为同一 `ApicReg` 接口（偏移表双列映射），F0021 的 EOI/LVT/SVR 语义在上层零改动，两模式行为一致性以"同序列双跑比对"判据验证（同一中断序列在两模式各跑一遍，事件账逐项相等）。与现存内核衔接点：`acpi.rs` MADT 的 LAPIC 基址在 x2APIC 模式下不再消费 MMIO（改 MSR），`limine.rs` 无感知。与 Windows 对照：Windows 8+ 在支持的平台上默认启用 x2APIC（设备管理器中断控制器节点可见），本内核模式选择落账可查，判据 UNX-F0025-J1 的复测方式：支持机迁移 10/10 次成功、双模式行为一致性双跑比对逐项相等、不支持机 10/10 次显式降级 xAPIC。

### UNX-F0026 · IPI 广播与 TLB shootdown 批处理
- 域/批：A1/B02｜判据：UNX-F0026-J1 多核 shootdown 批合并率可测，误杀为零｜纯功能行数：300 行（IPI 原语 100 + 批处理协议 110 + 应答账 90；测试段不计）｜状态：[已深化]
- **定位**：IPI 是核间的"叫人铃"，TLB shootdown 是多核页表一致性的核心协议，本条实现 IPI 发送原语三模式（单播/广播/掩码组播，目的简写与目的掩码两式）与 shootdown 批处理协议——同页表核的待刷项聚合、批合并窗口、应答计数账，A4 域每进程 CR3 的多核配合面由此立起，批合并率可测且误杀为零。
- **语义边界**：只做 IPI 原语与 shootdown 协议层；不做页表失效的业务决策（AI-04 防重）、不做核间调度（A3 防重）。
- **依赖与嫁接源**：依赖 F0021/F0025 双寻址接口与 F0004 拓扑账；嫁接源为 Intel SDM IPI 投递语义与 Windows KiFlushTargetListAll 类核间 TLB 操作语义，只跟随。
- **风险与回退**：应答超时（某核失联）——等待侧按超时档转单核降级（触发核自刷+缺席核登记），绝不无限等待死锁，超时事件进缺席核账供 A3 消费。
- 正文：实现路径分三步。第一步 IPI 原语：ICR 寄存器封装三模式发送（单播/全含自广播/掩码组播），目的简写与目的掩码两式统一接口，投递状态寄存器轮询完成，发送计数账逐模式分列；第二步批处理协议：per-页表待刷队列（虚拟地址段聚合），发送前聚合窗口（默认 50µs）内同页表请求合并，IPI 携带批量项，应答计数账（期待数/已答数）原子推进，全部到齐才返回，未到齐按超时档降级；第三步判据账：批合并率 =（合并后 IPI 数 / 逻辑请求数）逐窗口落账，误杀检测=刷了不属于目标页表的项计数（恒为零要求），两项账随 F0018 段账落盘。与现存内核衔接点：现存单核无 shootdown 路径，本条为纯增量，AP 到齐后（A3 拉起）自动启用多核路径。与 Windows 对照：Windows 的核间 TLB 失效开销在 xperf 上下文切换视图可见（DPC/ISR 与 TLB 抖动联动），本内核以"批合并率+误杀率"两项可数账对齐并超越观测粒度，判据 UNX-F0026-J1 的复测方式：并发 mmap/munmap 压测下合并率 ≥30% 落账、误杀计数 10^7 次操作恒零、超时降级注入 10/10 次不死锁不丢刷。

### UNX-F0027 · 中断亲和性掩码与负载分布
- 域/批：A1/B02｜判据：UNX-F0027-J1 亲和掩码生效、每核中断计数分布可导出｜纯功能行数：300 行（两路掩码实现 120 + 默认分布策略 80 + 每核计数账 100；测试段不计）｜状态：[已深化]
- **定位**：中断亲和决定每条中断落在哪一核，本条实现 per-IRQ 亲和掩码两路实现（IOAPIC RTE 目标字段改写/MSI-X 消息地址改写）、默认分布策略（round-robin 起步）、每核中断计数账（`/proc/interrupts` 类视图的内核侧数据源，K3 域任务管理器语义与 sysinfo 消费面），迁移在线生效（先屏蔽→改向→解屏协议，不丢在途中断）。
- **语义边界**：只做亲和设置与计数账；不做负载均衡策略（A3 调度器防重）、不做设备驱动的中断注册策略（各设备域自管）。
- **依赖与嫁接源**：依赖 F0023 RTE 三原语与 F0024 向量分配账；嫁接源为 Windows 中断关联策略（设备管理器"中断关联"设置）与 `Get-Counter 'Processor: Interrupts/sec'` 可观测语义，只跟随。
- **风险与回退**：在线迁移途中设备中断恰达（屏蔽窗口竞态）——迁移协议先屏后改再解屏，解屏后回读在途计数确认归零，竞态窗口事件由 F0028 风暴检测兜底观察。
- 正文：实现路径分三步。第一步两路实现：IOAPIC 路（RTE 目标字段写 LAPIC 编码掩码）与 MSI-X 路（消息地址目标字段改写）统一 `set_affinity(irq, mask)` 接口，两路语义一致性以双路同配置比对判据验证；第二步默认分布：round-robin 起步策略按 F0004 拓扑账逐 IRQ 轮转分配，策略可被 cmdline 白名单键覆盖（F0016 消费），每 IRQ 当前亲和落查询账；第三步每核计数账：LAPIC EOI 路径累加每核每向量计数（原子加），账面按核×矩阵可导出（`/proc/interrupts` 同构格式），K3 域与 sysinfo 直取，迁移协议三步（屏→改→解）带回读确认。与现存内核衔接点：F0023 的 `route`/`mask` 原语消费，计数钩子挂 F0021 EOI 路径。与 Windows 对照：Windows 设备管理器可对每设备设中断亲和并即时生效，`Get-Counter` 可见每核中断分布，本内核两能力等价且账面更细（向量级），判据 UNX-F0027-J1 的复测方式：掩码设置回读 100% 生效、每核计数账与 LAPIC 实测分布一致（抽 3 核比对）、在线迁移 1,000 次零丢中断。

### UNX-F0028 · 中断风暴检测与节流
- 域/批：A1/B02｜判据：UNX-F0028-J1 人为制造风暴被检测并节流，系统存活｜纯功能行数：260 行（滑动窗检测 90 + 两档节流 80 + 风暴源诊断账 90；测试段不计）｜状态：[已深化]
