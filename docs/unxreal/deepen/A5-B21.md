## F3601 锁压力机总设计（场景编排/指标采集/裁决门）

**定位**：并发压力机的总架构：场景层（压力剧本的注册与参数化）/执行层（N 工作者按冻结交错序驱动）/度量层（争用账的挂钩采集）三层——把锁的争用行为变成可重放、可度量、可裁决的实验。

**判据**：
- J1：压力机三层（场景/执行/度量职责表——判据行内嵌）；M-359 全链首跑（单锁场景注册→执行→度量→裁决四段走通+报告产出）。
- J2：零侵断言（压力机关闭时锁 acquire/release 路径拍数与基线逐位一致——度量可关）。
**纯功能行数**：340（三层架构 ~120 + 全链用例 ~120 + 裁决门 ~100）
**依赖与嫁接源**：A2/A3 锁 API（被驱动对象）；F3530 时钟 trait（计时唯一入口）；F3602 度量账（度量层核心）；F3614 确定性（执行层纪律）；F3595 报告同族（产出）。
**风险与回退**：三层耦合蔓延（场景层偷偷做裁决/度量层干预时序——层界腐蚀）——回退：层间类型隔离（指令账与度量账是仅有的跨层类型——API 签名即层界——编译期执法）；度量税超标（J2 实测超 2 拍）——回退：度量降档（全量账→抽样账（seq%N 下采样——F3539 同构——账永不抽样除外——降档只降分布账）；场景注册泛滥（人人可加场景——场景质量失控）——回退：场景注册判据门槛（每场景 ≥2 断言+手法不重复——F3574 同律——注册即审查）。
**正文**：三层的结构（判据行原文）：场景层 `Scenario {name, params, gen(seed) -> Vec<Instr>}`——gen 纯函数产指令账；执行层 `fn run(instrs, workers: N) -> RunTrace`——按冻结交错序消费指令账（F3614 的账上并发时上串行在执行层落实——RunTrace 是"谁在哪拍执行了哪条指令"的轨迹）；度量层 `fn observe(trace) -> ContentionBook`——从轨迹与锁路径挂钩点采集等待/持有样本。层间数据流：`seed → 指令账 → RunTrace → 度量账 → 裁决 → 报告`——单向管道（无回授——度量不反馈到执行（反馈=被测行为被观测改变——海森堡红线在并发域的投影）。M-359 首跑剧本：注册单锁场景（N=4/临界区 100 拍/轮次 1K）→跑四段→产出首份争用报告→四判（走通/互斥/守恒/零误报）全绿→PASS。裁决门的意义（判据行论证）：压力机不做"跑完就算"——四判是每次跑的门槛——互斥不变量（F3603 J2）与守恒式（F3611 J1）是**不变量族**、零误报（F3617 J2）是**质量族**——不变量族保证"压力下系统仍守规矩"、质量族保证"观测系统自身可信"——两类判据缺一不可（只测不变量=系统对但观测瞎；只测质量=观测清但系统乱）。J2 零侵的实测：度量挂钩点（acquire 前/release 后）在关闭态是编译期消除的空操作（cfg 特性+内联——空操作不占拍——关闭态拍数 diff==0 实测）。M-359 复测：四段+报告+四判+零侵实测+层界类型核查。

## F3602 争用度量账（等待时间/持有时间分布）

**定位**：锁争用的核心观测账：per-lock 的等待时间分布（acquire 发起到获得）与持有时间分布（获得到 release）各一张 2 的幂桶直方图——争用的"体检报告"（等待长=锁是瓶颈、持有长=临界区是瓶颈——两种病的化验单分开开。
**语义边界**：双分布**口径**（判据行内嵌：等待=从 acquire 调用到 lock 返回（含自旋与睡眠全程）；持有=lock 返回到 release 调用（临界区净长——不含调度延迟——判据行给口径的精确化：持有时间的时钟起点是"锁到手"不是"开始尝试"）；桶结构（2 的幂桶：1/2/4/…/65536 拍+溢出桶——F3526 中断潜伏期直方图同构——桶是常量结构、直方图计数 u32 饱和）；per-lock 键（lock_id——锁实例级不是锁类型级（同类型两把锁的争用画像不同——实例化观测）；账**环形有限**（桶计数是定长数组——无累积膨胀——F3616 J2 的前提）。
**判据**：
- J1：双分布账（等待/持有口径+2 幂桶+per-lock——判据行内嵌）；M-360 分布正确（构造已知等待序列（可控延迟桩）→桶计数与手算一致）。
- J2：账开销预算（每对 acquire/release 的度量税 ≤2 拍——实测核账）。
**纯功能行数**：320（账结构 ~110 + 用例 ~110 + 口径论证 ~100）
**依赖与嫁接源**：F3526 直方图先例（桶结构同构）；F3530 时钟（时间戳）；F3601 度量层（宿主）；F3615 报告（P50/P99 消费口）。
**风险与回退**：时间戳对偶误差（acquire 起点与获得点两次取时——时钟读数税本身计入等待）——回退：起点时戳在挂钩点一次取得、获得点复用锁内部既有时间点（不新增取时——税控制的一部分）；桶粒度不足（亚拍级等待全落桶 1——精度声明（等待 <1 拍的事件计数单列 sub-tick 桶——诚实标注测量下限）；P99 抖动（小样本 P99 不稳）——回退：样本量门槛（P99 报告附样本数——<100 样本标 LOWDATA——F3547 同律）。
**正文**：账结构（判据行原文）：`ContentionBook {wait: [u32; 17], hold: [u32; 17], sub_tick: u32, n_wait: u64, n_hold: u64}`——17 桶=16 个 2 幂桶+溢出桶；挂钩：`acquire_enter(t0)`/`acquire_ok(t1)`→wait 样本 t1−t0；`release(t2)`→hold 样本 t2−t1。M-360 剧本：可控延迟桩（锁的测试实现——acquire 前注入固定延迟 d）→构造等待序列 [3, 5, 9, 300, 70000 拍]→断言桶：3→桶 1（4 拍桶）、5→桶 2、9→桶 3、300→桶 8（256 桶）、70000→溢出桶——逐桶手算对表（边界值入测：恰为 2^k 的样本落哪桶——边界语义=落入上边界桶（值 4 落"1~4 拍"桶——闭区间右闭——判据行把边界写死）。口径分离的价值（判据行论证）：等待与持有是两种病灶的指标——等待 P99 高+持有 P50 低=锁本身竞争激烈（热点锁——要拆锁/缩临界区）；持有 P99 高=有人的临界区太长（要找长持有者——F3609 热点图联动）——合并成单一"锁时间"指标则两种病混为一谈——开药就错——判据行给"双分布"的处方学比喻。J2 税实测：空载锁（无争用）acquire/release 全程拍数：基线（无度量）vs 开度量——diff ≤2 拍断言（税的构成：两枚时戳+两次桶自增——设计上 2 拍内可控——实测背书）。u32 饱和语义：桶计数溢出饱和于 u32::MAX+SAT 标记（F3540 同构——长稳跑不溢出假零）。M-360 复测：五值桶表+边界值+双口径分离+税实测+饱和标记。

## F3603 单锁压力场景（N 工作者争一把锁）

**定位**：最基础的争用场景：N 个工作者循环 acquire/临界区/release 同一把锁——N 梯度（1/2/4/8）下的等待分布与互斥验证——争用的"基准音"（一切复杂场景的对照组）。
**语义边界**：场景参数三元组（判据行内嵌：N（工作者数）/临界区长度（拍）/轮次（每工作者 acquire 次数）——三元组定义一个具体实验；N=1 的**退化语义**（无争用基线——等待应近零、用于校准度量税——场景族的零点校准器）；互斥不变量（判据行原文：临界区内工作者计数（原子计数器 acquire 后 +1/release 前 −1）全程 ≤1——违反即互斥破——**硬断言即崩**）；"账上并发、时上串行"的执行（F3614——交错序冻结但逻辑并发保持——互斥断言在逻辑并发语义下依然有意义（同时=交错序中的重叠区间））。
**判据**：
- J1：场景契约（三元组+N 梯度清单）；M-361 争用梯度（N=1→8 四档各跑——等待均值随 N 单调升+无跳变（平滑恶化——突变=隐藏 bug 信号））。
- J2：互斥不变量（全程计数 ≤1 断言——四档全绿）。
**纯功能行数**：320（场景实现 ~110 + 梯度用例 ~110 + 不变量论证 ~100）
**依赖与嫁接源**：A2/A3 互斥锁（被压对象）；F3602 度量账（等待样本源）；F3614 确定性（交错序）；F3611 守恒式（配套判据）。
**风险与回退**：交错序不真（串行执行使争用失真——串行下永不重叠）——回退：交错序的**重叠注入**（冻结交错序里显式安排"工作者 A 未释放时 B 尝试"的重叠点——争用在账面上真实发生——串行执行测的是"重叠区间内的行为"不是"全程并行"——判据行把"账上并发"的操作性定义讲透：逻辑同时=交错序可比较区间）；临界区内容虚（空临界区——编译器/执行器优化掉）——回退：临界区强制副作用（写一字节到隔离缓冲——不可优化——volatile 语义）；N 上限选择武断（8 够吗）——回退：N 梯度来自 A3 调度域的真实并发上限（CPU 数账——压力场景的 N 与系统能力对齐——不压不存在的并发度）。
**正文**：场景执行器（判据行原文）：`for i in 0..rounds { worker(i % N) { lock.acquire(); critical(len); lock.release(); } }`——交错序由 F3614 的冻结序给定（seed→交错排列——M-361 的四档用四 seed 或同 seed 不同 N）。M-361 梯度剧本：N=1 跑→等待均值 e1≈度量税（零点校准——e1 即 J2 税的旁证）；N=2/4/8 各跑→等待均值序列 e1<e2<e4<e8（单调）且相邻比值平滑（e4/e2 与 e8/e4 都 <4——排队论直觉：等待 ~O(N)——超线性跳变=调度异常或锁退化——判据行给跳变的诊断价值：单调+平滑是"健康争用"的形状，跳变是"病态争用"的形状——形状即体检）。互斥不变量的实现（判据行展开）：`in_counter.fetch_add(1) after acquire_ok`/`fetch_sub(1) before release`——断言点在 add 后立即（`assert!(in_counter.load() <= 1)`——违反即 panic+现场 dump（B23 通道——互斥破是🔴级——不可续跑）；J2 在账上并发语义下的成立性论证：计数器的加减发生在交错序的确定点——"同时"=两个 add 之间无 sub——冻结序里可静态验证+运行期断言双保险——静态验证（交错序回放检查重叠区间）+动态断言（跑时计数）——双通道一致才算绿（单通道绿可能是断言点写错）。等待样本的去处：每档跑毕争用账快照→F3615 报告的梯度段（四档并排——报告读者一眼看形状）。临界区副作用的清理：隔离缓冲每跑重置（不污染下一档）。M-361 复测：四档梯度+单调平滑断言+互斥双通道+零点校准+缓冲重置。

## F3604 多锁压力场景（锁层级竞争/序获取）

**定位**：多锁场景：M 把锁×N 工作者+获取序参数化（升序/降序/随机三档）——锁序纪律在压力下的实证（升序=守纪律的正例、降序=故意违反的负例——正例防误报、负例防漏报的双缰绳。

**判据**：

**依赖与嫁接源**：B08 死锁检测器（suspect/confirm 消费方）；F3356/F3368 字段直传（事件通道）；F3602 度量（争用画像）；F3614 确定性。
**风险与回退**：降序不成环（M=1 退化——单锁无环）——回退：降序场景 M≥2 强制（参数校验——M<2 拒绝注册——退化的场景是不合法的实验）；随机档的环概率低（随机序偶尔无害——suspect 不触发——预期管理）——回退：随机档的期望是**频率**不是必然（M-362 随机档断言"suspect 频率 ≥0 且与理论环率同量级"——不设下限断言（随机实验的诚实预期）——判据行：三档的断言强度不同（升序=零容忍/降序=必达/随机=统计——断言强度匹配场景语义）；检测器时延掩盖（T_detect 太松——死锁已实际挂死才报）——回退：T_detect 判据内嵌数值（suspect ≤T1 拍/confirm ≤T2 拍——T1/T2 与 B08 判据同源——压力域复检）。
