### UNX-F7241 · table reload 总控协议
- 域/批：B5/B03｜判据：UNX-F7241-J1 reload 四阶段（挂起/排空/切换/退役）顺序断言与状态留痕全账；跳阶段 100% 被拒｜纯功能行数：340 行（总控状态机 130 + 四阶段钩子 100 + 顺序账 110；测试段不计）｜状态：[已深化]
- **定位**：reload 总控是"在线换图纸"的总指挥：四阶段（挂起→排空→切换→退役）顺序不可乱——没挂起就排空是空排、没排空就切换是在途请求跨表（数据混乱）、没切换就退役是把现役表丢了。总控状态机把四阶段做成穷举迁移表，跳阶段在结构上不可达（F7216 同族纪律）。
- **语义边界**：只做四阶段总控顺序协议；不做新表校验内容（F7242）、不做排空细节（F7243）、不做切换点原子实现（F7244）、不做退役回收（F7245）。
- **依赖与嫁接源**：消费 F7210 reload 框架协议与 F7214 quiesce；嫁接源为 Linux `dm_swap_table` 路径（`__bind` 四步）语义，只跟随。
- **风险与回退**：四阶段中途卡死（排空永不完成）——每阶段带超时观察（超时转 F7246 回滚路径，不静默悬挂），阶段超时值可配并落配置账。
- 正文：实现路径分三步。第一步总控状态机：reload 会话对象（会话 ID/当前阶段/新表句柄/旧表句柄/发起者）承载四态迁移，迁移表穷举（idle→suspending→draining→switching→retiring 五态含 idle 起点），表外迁移编译期不可表达，同设备同时只允许一个 reload 会话（F7248 并发控制在此互锁）；第二步四阶段钩子：每阶段进入/退出钩子登记动作与时间戳，阶段账只增不改（append-only），会话结束（成功或回滚）全账归档；第三步顺序断言：ktest 对四阶段顺序插桩断言（后阶段入口断言前阶段退出戳存在），跳阶段注入（人为调用阶段函数乱序）100% 被迁移表拒绝。与现存内核衔接点：`dm/reload_ctrl.rs` 新建，会话对象复用 F7210 reload 结构扩容。与 Windows 对照：Windows Storage Spaces 的池布局调整（Add-PhysicalDisk 后 retune）在后台分阶段推进（规划/迁移/收尾三阶段事件可见），本内核四阶段账对齐可观测性。判据 UNX-F7241-J1 的复测方式：四阶段顺序断言 200 轮 reload 全账完整、跳阶段注入 10/10 被拒、阶段超时转回滚路径验证。

### UNX-F7242 · reload 新表预校验（切换前合法性）
- 域/批：B5/B03｜判据：UNX-F7242-J1（保护判据先行）新表全量校验（对齐/越界/target 参数）通过才进入挂起；预校验失败 10/10 次旧表无扰动续用｜纯功能行数：300 行（预校验编排 100 + target 参数验 100 + 失败无扰断言 100；测试段不计）｜状态：[已深化]
- **定位**：预校验是 reload 的第一道保护判据：新表在**挂起设备之前**就要全部验完——带病新表挂起设备=服务中断了才发现换不了=最差的运维体验；预校验失败时设备根本没被打扰（旧表无扰动续用），这是"先验后动"纪律的直接体现。
- **语义边界**：只做预校验编排与 target 参数验证；不做静态校验器本体（F7207 复用）、不做参数串词法（F7211 复用）、不做切换（F7244）。
- **依赖与嫁接源**：复用 F7207 三类校验器与 F7203 target 构造函数的参数验证路径；嫁接源为 Linux `dm_table_load` 的校验先行惯例，只跟随。
- **风险与回退**：预校验与切换时环境漂移（校验时盘在、切换时盘没了）——预校验通过戳带环境指纹（成员盘集合+容量快照），切换前二次指纹比对，漂移即回滚（F7246），两次校验夹一个切换窗口，漂移无处遁形。
- 正文：实现路径分三步。第一步预校验编排：新表走完整 F7207 校验器（对齐/越界/重叠三类）+ 全部 target 构造函数干跑（构造成功即销毁，验证参数可解析可建上下文），两步全过签发"预校验通过戳"（含环境指纹），总控状态机只接受带戳新表进入挂起阶段；第二步 target 参数验：干跑深度到 target 上下文构建（linear 的盘存在性与偏移、crypt 的密钥槽可用性——B14 接管后此验激活），干跑失败报告定位到表行号与字段名；第三步失败无扰断言：ktest 注入各型坏表 100 轮，断言预校验失败路径设备零挂起（挂起计数不变）、旧表 IO 持续成功（注入期间在跑的读写全过）——"验失败不打扰"是可断言的运维承诺。与现存内核衔接点：`dm/reload_validate.rs` 新建，干跑复用 F7203 构造函数。与 Windows 对照：Windows 存储池布局变更前 Validate 操作（StoragePool 验证 API）先行，验证不过布局不动。判据 UNX-F7242-J1 的复测方式：坏表注入 100 轮全部预校验拦截且设备零扰动（挂起计数与 IO 成功率断言）、环境指纹漂移注入 10/10 回滚。

### UNX-F7243 · reload 在途 IO 排空语义
- 域/批：B5/B03｜判据：UNX-F7243-J1 排空完成断言：切表点前提交的全部请求均达终态（F7214 计数归零）；UNX-F7243-J2 排空超时路径显式报错不静默继续｜纯功能行数：300 行（排空编排 100 + 归零断言 100 + 超时路径 100；测试段不计）｜状态：[已深化]
- **定位**：排空（drain）是 reload 的安全阀：切表点之前，旧表的所有在途请求必须全部到达终态——在途请求跨表（一半按旧表一半按新表映射）是数据错乱的精确形态。排空复用 F7214 quiesce 原语，但 reload 排空有独立判据：排空完成=切表点的唯一前置。
- **语义边界**：只做 reload 场景的排空编排；不做 quiesce 原语本体（F7214）、不做挂起期间排队（F7247 策略）、不做底层盘排空（B4 域，判例一）。
- **依赖与嫁接源**：复用 F7214 quiesce 与 F7205 终态账；嫁接源为 Linux `dm_suspend` 排空（`__hold` 计数等待）语义，只跟随。
- **风险与回退**：在途请求悬挂（超时请求取消路径恰好也在这时跑）——排空前先完成取消排空（F7231 排空先行），两排空串行化，取消路径未清零时不进入 reload 排空；排空超时显式报错转回滚，绝不"超时也算排空了"。
- 正文：实现路径分三步。第一步排空编排：挂起阶段完成后进入排空——调用 F7214 quiesce（reload 语义：拒绝新请求），等待在途计数归零（F7205 终态账与 F7214 计数双账互证，差额非零即红账）；第二步归零断言：归零判定=双账一致归零+终态账全部终态（无一挂起态），断言通过签发"排空完成戳"（时间戳+在途峰值记录），切表点（F7244）只接受带戳状态；第三步超时路径：排空等待带超时（缺省 10s，cmdline 可配），超时显式报错——报告含未决请求清单（F7214 诊断格式），reload 会话转 F7246 回滚，"超时继续切换"路径在代码中不存在。与现存内核衔接点：`dm/reload_drain.rs` 新建，双账互证复用 F7214 计数与 F7205 账。与 Windows 对照：Windows 卷布局调整前排空（IO 排队至切换点）同域，卷影子拷贝前的排空（VSS flush-and-hold）同构。判据 UNX-F7243-J1 的复测方式：在途 1000 请求中 reload 200 轮排空归零断言全过、双账互证零违例；J2 排空超时注入 10/10 显式报错+回滚、未决清单完整。

### UNX-F7244 · reload 原子切换点与切换瞬间零丢失
- 域/批：B5/B03｜判据：UNX-F7244-J1（保护判据先行）切表点原子性断言：任意时刻提交的请求要么走旧表要么走新表，不存在混合映射（注入式验证 ×1000）；UNX-F7244-J2 切换瞬间在途请求零丢失（每请求有终态）｜纯功能行数：360 行（切表点实现 130 + 原子性注入验证 130 + 零丢失断言 100；测试段不计）｜状态：[已深化]
- **定位**：本条是 B03 批的红线核心：切表点的原子性。排空后设备零在途，切换动作=表指针原子替换+版本号递增（F7208 协议）——一个 CAS 完成切换窗口。"任意时刻的请求要么走旧表要么走新表、绝无混合映射"的判据用注入式验证 ×1000 坐实：这是表一致性对数据安全的最终承诺。
- **语义边界**：只做切表点原子实现与验证；不做排空（F7243）、不做切换后可见性（F7256）、不做堆叠传播（F7257）。
- **依赖与嫁接源**：消费 F7208 版本号协议与 F7243 排空完成戳；嫁接源为 Linux `dm_swap_table` 的指针替换（RCU 等价物）语义，只跟随。
- **风险与回退**：切表点后新表 IO 立即失败（新表成员盘刚好失效）——切换后首批 IO 的探针（构造探测读写走一遍新表路径），失败即自动回滚（切回旧表，旧表退役阶段未开始时可用），自动回滚留账并告警。
- 正文：实现路径分三步。第一步切表点实现：排空完成戳在手→新表指针与旧表指针双指针就绪→单 CAS 原子替换（新表接管 IO 路径）→版本号递增（F7208 协议）→切换完成戳落账，切表点耗时预算 ≤1ms（F7255 账目验证）；第二步原子性注入验证：ktest 以多线程在切表点前后高速提交探针请求（每请求带表版本断言——换算结果与请求开始时快照版本一致），1000 轮注入断言"混合映射"零命中——探针请求的映射结果与它拿到的表快照永远自洽；第三步零丢失断言：切换瞬间在途清单（排空后应为空）与切换后首批请求终态账全量断言，"每请求有终态"的守恒在切表点前后无缝衔接。与现存内核衔接点：`dm/swap_point.rs` 新建，CAS 原语用 `core::sync::atomic`，切表点为唯一写表指针位置（架构上单点）。与 Windows 对照：Windows Storage Spaces 布局切换为原子呈现（卷属性一次更新，无中间布局可观测），本内核切表点单 CAS 对齐原子性并加注入验证。判据 UNX-F7244-J1 的复测方式：原子性注入 1000 轮混合映射零命中；J2 切换 200 轮在途零丢失、探针首验失败自动回滚 10/10 生效。
- **红线注记**：红线核心条目（切表点原子性）——动工前清单：单 CAS 切换点架构确认、注入验证用例 AI-86 会签；已提交 AI-86 双人复核流程。

### UNX-F7245 · reload 旧表退役与引用回收
- 域/批：B5/B03｜判据：UNX-F7245-J1 旧表在最后引用归零后释放（引用计数断言）；退役表快照归档可查（审计需求）｜纯功能行数：260 行（退役协议 90 + 引用回收 90 + 快照归档 80；测试段不计）｜状态：[已深化]

- **语义边界**：只做旧表退役与归档；不做引用计数原语（F7206 复用）、不做快照机制（F7208 复用）、不做归档持久化（内存档案，落盘走 ADR）。
- **依赖与嫁接源**：复用 F7206 引用协议与 F7208 快照；嫁接源为 Linux dm `old_table` 延迟释放语义，只跟随。
- **风险与回退**：旧表被永久持有（快照读者泄漏）——退役等待带观察账（持有者清单可打印），长期持有（>60s）落诊断告警但不强制回收（强制回收=use-after-free 重现，绝不做）。

### UNX-F7246 · reload 失败回滚（新表不生效旧表续用）
- 域/批：B5/B03｜判据：UNX-F7246-J1 注入排空超时/切换失败用例 10/10 次回滚成功且旧表续用零扰动；回滚动作留审计账｜纯功能行数：300 行（回滚状态机 100 + 分阶段回滚 110 + 零扰动断言 90；测试段不计）｜状态：[已深化]
- **定位**：reload 的每一步都可能失败（排空超时/校验漂移/切换后探针失败），回滚协议保证"失败的 reload 等于没发生"——旧表续用零扰动。回滚按阶段分档：排空前回滚=直接放弃（设备没动过）、排空后回滚=resume 恢复放行（设备在排队）、切换后回滚=切回旧表（旧表未退役时可用）。分档回滚让"回滚"本身也是确定性的。
- **语义边界**：只做回滚状态机与分阶段处置；不做失败原因诊断（F7259）、不做自动重试 reload（运维决策域）、不做回滚后的新表清理（退役协议复用）。
- **依赖与嫁接源**：消费 F7241 四阶段账与 F7244 切换点；嫁接源为 Linux dm bind 失败回滚（`__bind` 失败路径）语义，只跟随。

### UNX-F7248 · reload 并发控制（双 reload 竞争拒绝）

### UNX-F7249 · reload 与挂起状态机交互
