### UNX-F2401 · 物理内存图消费与四态归一
- 域/批：A4/B01｜判据：UNX-F2401-J1 真机引导后消费 A1 合并内存图，四态归一（可用/保留/可回收/坏页）区间数与 A1 合并账一致，逐态字节和与总 RAM 偏差 ≤4KB｜纯功能行数：300 行（图结构消费器 110 + 四态归一表 80 + 对账输出 110；测试段不计）｜状态：[已深化]
- **定位**：把 A1 域 F0008 产出的合并内存图从"图纸"变成"施工输入"——A4 全域一切分配语义的唯一真值源在本条固化，四态归一表是 buddy 初始化的第一口粮食。
- **语义边界**：只做内存图消费、四态归一与对账输出；不做三源合并与冲突裁决（A1 F0008 防重，判例三）、不做分配器本体（F2407 起）。
- **依赖与嫁接源**：上游冻结件 F0079 内存图交接结构体（handoff cross_domain_freeze 在案）；对现存 `memmap.rs` 合并产物的消费是承接深化；嫁接源为 e820/UEFI 类型约定，只跟随。
- **风险与回退**：A1 图结构若波 02 内变更——冻结件变更走 §16.2 通知链，本条消费者回归清单随行，回退为仅消费 Limine 单源并打降级账。
- 正文：实现路径分三步。第一步定义图消费器：以 F0079 冻结结构体为唯一入参，逐区间读出基址/长度/类型三元组，读入即校验（基址按 4KB 对齐、长度非零、区间不重叠），违规区间拒绝并记坏账；第二步四态归一：把 A1 合并类型映射为可用/保留/可回收/坏页四态，归一表为 const 静态表，未知类型按保留态兜底并打未知类型账，绝不猜；第三步对账输出：逐态区间数与字节和落 F0018 引导记账，与 A1 合并账并排打印，偏差超 4KB 即引导期自检失败（F2418 消费）。与现存内核衔接点：`memmap.rs` 的 `Region`/`Kind` 结构保留为兼容读取面，新增 `MemoryMapIngestor` 消费器不动旧路径。与 Windows 对照：Windows 管理器启动时同样以固件内存图为唯一真值（`!memusage` 可观测），本条对账账本与该形态同粒度。判据 UNX-F2401-J1 的复测方式：三机型真机引导后四态字节和与 A1 合并账差 ≤4KB，人为注入重叠区间用例 10/10 次拒绝留账。

### UNX-F2402 · 可用区间位图初始化与对齐裁边
- 域/批：A4/B01｜判据：UNX-F2402-J1 位图置位总数 ×4KB 等于可用区间字节和，页对齐裁边裁失字节逐区间落账，三机型偏差为零｜纯功能行数：300 行（区间对齐裁边器 120 + 位图置位器 100 + 裁边账 80；测试段不计）｜状态：[已深化]
- **定位**：把"连续可用区间"翻译成"页粒度位图"——页对齐裁边是物理管理的第一道精度账，裁掉多少、为什么裁，逐字节可查。
- **语义边界**：只做可用区间的页对齐与位图置位；不做预留区登记（F2403）、不做分配（F2407 起）。
- **依赖与嫁接源**：依赖 F2401 四态归一后的可用区间清单；对现存 `pmm.rs::FrameBitmap` 的 `reset`/`set` 是承接深化（补区间级对齐裁边与裁边账，位图原语零改动）；嫁接源为 x86-64 4KB 页基线，只跟随。
- **风险与回退**：极小可用区间（<4KB）裁边后为零页——区间按"零页可用"显式登记而非静默丢弃，账本可见。
- 正文：实现路径分三步。第一步对齐裁边器：每可用区间计算向上对齐基址与向下对齐终址，裁失头尾字节按区间登记（起点/终点/裁失量三账），全部裁失总和落引导记账；第二步位图置位：按对齐后区间逐页置 `FrameBitmap`，置位计数与区间页数实时比对，不一致即中止初始化（早年失败早暴露）；第三步口径闭环：位图置位总数 ×4KB 与可用字节和比对，差异只允许来自裁边账且逐笔可对，对账结果写入 F2418 自检链输入。与现存内核衔接点：复用 `FrameBitmap::set/count_set` 原语，新增 `ingest_range()` 包层；`first_clear` 语义不变。与 Windows 对照：Windows 资源监视器"硬件保留内存"与可用内存的分界同源于页粒度裁边，本条裁边账把该分界做成逐字节可审计。判据 UNX-F2402-J1 的复测方式：三机型位图口径与可用字节和差等于裁边账总和（零隐损），构造 3KB 尾区间用例 10/10 次显式零页登记。

### UNX-F2403 · 预留区登记账（内核映像/引导器/保留页）
- 域/批：A4/B01｜判据：UNX-F2403-J1 内核映像/引导器/诊断保留页三类预留区间与 Limine 响应逐条一致，预留区间被分配计数恒为零｜纯功能行数：280 行（三类预留登记器 120 + 永不分配闸 90 + 一致性核对账 70；测试段不计）｜状态：[已深化]
- **定位**：预留区是分配器的禁飞区——内核映像、引导器驻留、诊断保留页（F0017/F0011 快照区）一旦被分配即是引导级事故，本条把禁飞区做成带闸门的账。
- **语义边界**：只做预留区登记与禁分闸；不做内核段权限重排（A1 F0009 防重）、不做诊断页策略（F0017 防重）。
- **依赖与嫁接源**：依赖 F2401 图消费器与 F0001 kernel-address/帧簿等响应；对现存 `memmap.rs` 的 `Reservations` 语义是承接深化（补三类分账与禁分闸）；嫁接源为 Limine 引导协议响应集，只跟随。
- **风险与回退**：固件未申报某预留（怪机型）——按"未申报但实占"检测兜底：对内核映像区做标记比对，发现缺登记者补登并打固件缺陷账。
- 正文：实现路径分三步。第一步三类登记器：内核映像（kernel-address 响应区间）、引导器（bootloader 可回收区之外的固驻段）、保留页（F0017 诊断/F0011 快照共享预算）逐类登记基址与长度，来源响应字段逐条留痕；第二步禁分闸：分配入口（F2407 起）对预留区做前缀检查，命中即 panic（文案含区间类别与调用点），闸门自检在 F2418 链中常驻；第三步一致性核对：三类登记与 Limine 响应逐条比对，缺登/多登/交叠三种异常各给独立错误码。与现存内核衔接点：`Reservations` 结构扩容为三类分账，现有 `contains` 判定收编为闸门底层。与 Windows 对照：Windows 的 `MmGetPhysicalMemoryRanges` 与页帧数库（PFN database）初始化同样先固化固件预留，本条对齐该语义形态。判据 UNX-F2403-J1 的复测方式：三机型登记账与 Limine 响应一致率 100%，注入"分配命中预留区"用例 10/10 次 panic 文案可读。

### UNX-F2404 · 页帧序号与物理地址互转原语
- 域/批：A4/B01｜判据：UNX-F2404-J1 互转原语 10^7 次宿主随机往返零误差，边界值（0/最高帧/未对齐入参）按契约拒绝｜纯功能行数：260 行（互转函数族 90 + 边界契约 90 + 账面断言 80；测试段不计）｜状态：[已深化]
- **定位**：帧号与物理地址的互转是内存域出现频率最高的算术，本条把它单点化并钉死边界契约——全域禁止散写 `>> 12` 式私算，杜绝口径漂移。
- **语义边界**：只做互转原语与边界契约；不做 HHDM 偏移语义（`paging::phys_to_virt` 承接不动）、不做位图操作。
- **依赖与嫁接源**：依赖 F2402 位图长度定最高帧号；对现存 `pmm.rs::PAGE_SIZE` 常量体系是承接深化；嫁接源为 x86-64 物理地址宽度判定（CPUID PA 位），只跟随。
- **风险与回退**：PAE/5 级页表类地址宽度扩展——原语按 `PhysAddrBits` 参数化预留，本波按 48 位物理基线交付，扩展位显式待账不入码。
- 正文：实现路径分三步。第一步原语族：`frame_of(phys)`/`addr_of(frame)` 双向函数，入参出参全用新类型 `FrameNo`（非裸 usize）承载，类型层面禁混用；第二步边界契约：未对齐地址、越界帧号、0 号帧的保留语义（保留给 NULL 判定）逐条定义错误返回，契约表随原语同文件交付；第三步全域替换审计：grep 全内核 `>> 12`/`<< 12` 裸算点，逐点判定归属——属于本域语义的改调原语并留清单，属于他域（如页表索引算术）的显式豁免记账。与现存内核衔接点：`pmm::alloc_page` 返回值换帧号处改走原语，行为零变化。与 Windows 对照：Windows PFN 与物理地址换算同样集中于 `MmGetPhysicalAddress` 族单点，散算即审计项。判据 UNX-F2404-J1 的复测方式：宿主 10^7 次随机往返零误差，三类非法入参 10/10 次按契约拒绝，裸算点审计清单随批归档。

### UNX-F2405 · PCID/ASID 分配与 INVPCID 语义
- 域/批：A4/B01｜判据：UNX-F2405-J1 支持平台 ASID 轮转账零复用冲突；INVPCID 三类型逐型可观测；不支持平台退全 flush 基线等价断言｜纯功能行数：320 行（PCID 能力判定与状态机 100 + ASID 轮转分配器 110 + INVPCID 三型封装 110；测试段不计）｜状态：[已深化]
- **定位**：本条是域经 DJ-UNX-0001 的承载条目——"改页表前必须查 F2405 PCID 状态"的纪律由本条提供唯一查询 API；PCID 决定全域 TLB 策略形态，必须在 B01 地基批立账。
- **语义边界**：只做能力判定、ASID 轮转与 INVPCID 封装；不做 TLB 失效列表构造（F2629，本域后段）、不做 shootdown 广播（A3 防重）。
- **依赖与嫁接源**：依赖 F2406 CPUID 能力账；嫁接源为 Intel SDM Vol.3 §4.10.1（PCID）与 §4.10.4（INVPCID 三类型：individual-address/single-context/all-context），只跟随；不支持平台退 CR3 全 flush 基线为显式回退路径。
- **风险与回退**：个别真机 PCID 位报支持但 INVPCID 缺位（杂凑平台）——能力账按"PCID 与 INVPCID 双位与"裁断，半支持按不支持处置并打平台缺陷账。
- 正文：实现路径分三步。第一步状态机：`PcidState` 三态（Supported/Disabled/Unsupported），由 F2406 能力账与引导参数共同裁断，状态只读单点查询 API `pcid_state()` 即域经纪律承载点，全域改页表路径调用前必查（AI-82 抽查项）；第二步 ASID 轮转分配器：12 位空间中 0 号留内核、用户进程从 1 轮转分配，世代（generation）计数器在轮转回绕时递增，世代不符即失效——轮转账零复用冲突由账本断言（分配-回收配平账）；第三步 INVPCID 三型封装：type0（单地址失效）/type1（单上下文失效）/type2（全上下文失效）三个包装函数，逐型调用计数落账，不支持的类型调用按 panic 拒绝（能力裁断前置）。与现存内核衔接点：现存 `cpu/smp.rs` 中 pcid 字样仅为字段占位，本条首次给出可运行状态机与分配器，属接管新建。与 Windows 对照：Windows 进程地址空间切换同用 PCID 减少 TLB 全清（`MiSwitchProcess` 形态），本条 ASID 轮转对齐该体验。判据 UNX-F2405-J1 的复测方式：支持平台轮转 10^6 次分配回收配平零冲突，三型逐型计数可观测递增，不支持平台 10/10 次走全 flush 基线且行为等价断言通过。

### UNX-F2406 · CPUID 平台内存能力判定账
- 域/批：A4/B01｜判据：UNX-F2406-J1 PCID/1G 页/NX/PGE 四能力位与真机 CPUID 原始值逐位一致，能力账跨引导可复现｜纯功能行数：280 行（能力探测器 110 + 四位账本 90 + 可复现校验 80；测试段不计）｜状态：[已深化]
- **定位**：内存域的平台分岔点全部由 CPUID 决定（PCID、1GB 大页、NX、PGE），本条在最早时点把四能力位读成结构化账本，供 F2405/F2586/F2594 消费，杜绝各路径重复裸读 CPUID。
- **语义边界**：只做内存相关四能力位探测与账本；不做 CPU 拓扑枚举（A1/A3 域防重）、不做能力使能（使能归各使用条目）。
- **依赖与嫁接源**：依赖引导期 CPUID 可用性（现存 `cpu` 模块）；嫁接源为 Intel SDM Vol.2 CPUID 指令参考（leaf 0x01 EDX NX/PGE、leaf 0x80000001 EDX 1G 页、ECX PCID），只跟随。
- **风险与回退**：跨厂商 leaf 差异（AMD 与 Intel 布局同但有保留位）——按 leaf 号+位号双锚定读取，保留位读数记原文不解读，避免误判。
- 正文：实现路径分三步。第一步探测器：引导早年一次性读取 leaf 0x01 与 0x80000001 原始寄存器值，原始值整体快照入账（审计可回放）；第二步四位账本：PCID（leaf1 ECX bit17）、PGE（leaf1 EDX bit13）、NX（leaf1 EDX bit20）、1G 页（leaf 0x80000001 EDX bit26）逐位解码，每位登记原始位值/解码结论/裁断依据三字段；第三步可复现校验：能力账摘要（四位的十六进制组合）写引导日志，跨两次引导比对一致——不一致即平台异常入缺陷账。与现存内核衔接点：现存 `cpu` 模块已有 CPUID 基础封装，新增 `memcap` 子账不动既有探测。与 Windows 对照：Windows 的内核调试器 `!cpuinfo` 展示同组能力位，本条账本与其逐位可比。判据 UNX-F2406-J1 的复测方式：三机型四位账与 CPUID 原始值逐位一致，跨引导摘要 10/10 次一致，虚拟化环境位裁撤用例降级路径留账。

### UNX-F2407 · buddy 元数据区自举分配
- 域/批：A4/B01｜判据：UNX-F2407-J1 元数据区字节数按最大帧数闭式计算并与实占一致，自举后 buddy 可用帧数与位图口径差为零｜纯功能行数：320 行（元数据尺寸闭式计算 100 + 自举 carving 120 + 口径对账 100；测试段不计）｜状态：[已深化]
- **定位**：buddy 的 free_area 数组与阶链表本身需要内存——"谁来分配分配器"的自举问题在本条以闭式计算 + 从可用区 carving 解决，是 buddy 一切结构的出生地。
- **语义边界**：只做元数据区尺寸计算与自举占用；不做阶结构填充（F2408）、不做预留区登记（F2403）。
- **依赖与嫁接源**：依赖 F2402 位图与 F2403 预留账；对现存 `pmm.rs` buddy 起步实现是承接深化（现存为单阶位图态，本条补元数据自举账）；嫁接源为 Linux MM buddy 初始化次序（`memblock`→`buddy` 接力形态），语义参照实现自研。
- **风险与回退**：大内存机型元数据区超预算——闭式计算先行报数（16GB 机约百 KB 级，远低于最小区间），超预算按降容档裁断并打告警，不静默。
- 正文：实现路径分三步。第一步闭式计算：`meta_bytes(max_frame) = free_area 结构 × 11 阶 + 链表节点 × 帧数`，公式连同代入实数落账，禁止"拍脑袋定容量"；第二步自举 carving：从最大可用区间头部切出元数据区，切出区间转保留态（复用 F2403 登记器），carving 偏移与字节账落引导记账；第三步口径对账：自举后 buddy 可用帧数 = 位图可用帧数 − 元数据占用帧数，两口径差必须为零，差值即自举事故。与现存内核衔接点：`pmm.rs` 新增 `BuddyMeta::bootstrap()`，`FrameBitmap` 消费点不变。与 Windows 对照：Windows 的 MM 元数据（PFN database）同样从物理内存中预留且尺寸可由 RAM 推算，本条闭式计算对齐该形态的可审计性。判据 UNX-F2407-J1 的复测方式：三机型闭式数与实占一致，口径差为零，8GB/16GB/32GB 三档计算账随批归档。

### UNX-F2408 · free_area 阶结构与块登记

### UNX-F2409 · 高阶块拆分（split）语义
- 域/批：A4/B01｜判据：UNX-F2409-J1 split 后兄弟块两两配对账零孤儿，10^5 次拆分对账零偏差｜纯功能行数：340 行（递归拆分器 130 + 兄弟账 110 + 配对验证 100；测试段不计）｜状态：[已深化]
- **定位**：split 是 buddy 把大块变成小块的唯一通道——从目标阶向下逐级对半，兄弟块账是合并（F2410）正确性的前提，孤儿块即碎片事故的种子。
- **语义边界**：只做阶间拆分与兄弟登记；不做分配出口语义（F2411/F2415）、不做迁移约束（F2413）。

- **风险与回退**：拆分中途 ENOMEM（元数据节点耗尽）——节点预算在 F2407 按最大帧数闭式给足，中途耗尽按实现缺陷 panic（账本可证），不做半拆状态。
- 正文：实现路径分三步。第一步递归拆分器：从 order 高处向下逐级对半，每级把右半块挂入该阶空闲链、左半块继续下探，抵达目标阶时返回；第二步兄弟账：每块登记其 order 与兄弟基址（XOR 互算），拆分产生的兄弟对全量入配对账，链上任意块可从账本反查其兄弟；第三步配对验证：split 完成后对涉及阶做配对扫描，孤儿块（账有链无/链有账无）计数必须为零。与现存内核衔接点：`pmm.rs` 的 `find_run`（连续位搜索）退役为对账工具，拆分走阶链。与 Windows 对照：Windows 分配器按页数分档（`MiAllocatePagesForMdl` 形态）无显式兄弟账，本条兄弟账是 buddy 形态的固有资产，对账能力强于分档形态。判据 UNX-F2409-J1 的复测方式：宿主 10^5 次随机 order 拆分，兄弟配对账零孤儿零偏差，单次拆分级数上限断言（≤10 级）通过。

- **依赖与嫁接源**：依赖 F2407 起的分配出口；对现存 `mm.rs::is_zero_page` 检测函数是承接复用；嫁接源为 Linux `alloc_pages(GFP_ZERO)` 与 `clear_page` 路径语义，实现自研。
- **风险与回退**：大页零化时延长（2MB 清扫）——大页零化走非缓存写合并策略优化，时延账分档记录，超预算档位告警不阻塞。
- 正文：实现路径分三步。第一步零化分配器：分配出口提供 `alloc_zeroed` 族，分配后立即按页粒度零写，零写策略按页大小分档（4K 直写、2M 分块）；第二步全零校验：校验器对零化结果按字长抽查（首尾 + 随机 16 点），宿主测试全量校验、真机抽查（开销平衡显式声明），校验失败即实现缺陷 panic；第三步时延账：零页供给时延与普通分配时延并排落账，差值是安全税的量化，供 O1 性能对标取数。与现存内核衔接点：`pmm.rs` 分配出口扩展，`is_zero_page` 收编为校验器底层。与 Windows 对照：Windows 用户态页供给同样要求零化（`MiZeroPageThread` 专用零页线程形态），本条时延账与其零页线程预算同量纲。判据 UNX-F2416-J1 的复测方式：真机 10^4 次全零校验零失败，时延差账三机型齐全，2MB 大页零化分档账在册。
