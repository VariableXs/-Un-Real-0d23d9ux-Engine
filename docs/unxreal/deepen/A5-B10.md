## F3381 样本库总设计（可复现死锁样本注入框架）

**定位**：样本库的语义宪法：样本 = 参数化场景函数（四参数：锁数 n / 持有时长 d / 注入时机 t / 期望结果 e），框架 = 注册-生成-执行-对账四段流水线——检出率与误报率的可测量化装置。
**语义边界**：本条是框架定义；九样本（F3382–F3389）是其首批住户、引擎（F3390）是其参数化扩展。样本安全红线（批级声明细化）：样本的等待全部可被桩 CANCEL 解除——真死锁在开发环境永不真实发生（真死锁只在闸口真机允许由人工触发，判据行声明）。
**判据**：
- J1：M-140 框架空转：注册 0 样本 → 生成 0 → 执行 0 → 账本空表——四段流水线各段接口存在且空转不崩。
- J2：框架文档四节：样本定义/四段流水线/安全红线/与 D 族（F3359）的演进关系。
**纯功能行数**：400（样本 trait ~130 + 四段流水线 ~150 + 安全机制 ~80 + 判据行 ~40）
**依赖与嫁接源**：F3359 D 族（种子）；B08/B09 检测面 API（F3358/F3376）；F3246 桩（CANCEL 注入）。
**风险与回退**：样本把开发环境真卡死（安全红线失效）——回退：样本执行全程带超时看门狗（B12 F3432 预对齐——样本超时 = 强制 CANCEL 全部等待者 + 样本判失败 + 记账 SAMPLE_TIMEOUT）——三重保险：桩 CANCEL / 看门狗 / 样本自限。
**正文**：框架定义（判据行原文）：`trait Sample { fn name(&self) -> &str; fn params(&self) -> SampleParams; fn setup(&mut self, env); fn run(&mut self, env) -> SampleOutcome; fn teardown(&mut self, env); fn expect(&self) -> Expectation; }`——四参数（n/d/t/e）中 n·d·t 是生成参数、e 是期望断言（Expectation 枚举：Detect(环长)/SelfLock/Silent/CriticalAlert/GraphExternalCount）。四段流水线：注册段（样本表）、生成段（参数 → 场景资源：锁实例数组/桩任务）、执行段（跑 + 超时看门狗）、对账段（实际 vs 期望 → 检出率账本 F3391）。安全红线三重保险（判据行原文）：①每个等待者的桩都登记 CANCEL 句柄——teardown 逐一解除；②看门狗超时（默认 2×样本预算）强制全 CANCEL；③样本自限（run 内最多等待 X 窗）——三层任何一层兜住都不卡死。与 D 族演进：D 族 = 手写用例（B08 交付），样本库 = D 族的参数化与账本化（B10）——D-001..D-010 的对应样本关系在 F3391 账本中显式映射。现有内核接入：无（新框架 `sync/dlsamples.rs`）。Windows 对比：Windows 无内建样本库（Verifier 的测试场景散于 HLK 套件）；我们库化 + 参数化 = 检测能力的可复测资产——1 万+ 断言运动里，样本库是"断言的工厂"。M-140 复测：四段空转 + 红线三保险的存在性断言（CANCEL 句柄/看门狗/自限各一检查）。

## F3382 样本 S-AB 两锁互等

**定位**：样本 #1：两锁 AB-BA 互等（期望 Detect(2)）——最经典死锁形态的参数化样本（D-001 的样本化）。
**语义边界**：单一样本条目；参数默认值判据行固化，可被引擎（F3390）改写。
**判据**：
- J1：M-141：默认参数执行 → 检出报告环长 2、路径 [A→B→A]、参与锁身份正确；账本记 Detect 命中。
**纯功能行数**：280（样本函数 ~120 + 期望与桩 ~90 + 用例 ~70）
**依赖与嫁接源**：F3381 框架；F3345 环检测。
**风险与回退**：双核互等的到达序不确定（谁先持锁）——回退：期望不依赖到达序（环长 2 是序不变量），路径方向按实际等待边还原——非确定性下判据稳定（F3302 同哲学）。
**正文**：实现路径：`setup`：建 2 锁（A、B，class 同层次相邻）+ 2 桩任务（核 0/核 1）；`run`：核 0 拿 A 后请求 B（桩阻塞入等待图）、核 1 拿 B 后请求 A——等待图形成 2 环；检测器首扫/次扫确认（F3354 窗口）→ DL_RING；`teardown`：CANCEL 双任务 → 摘边 → 环解 → 账本对账（expected=Detect(2), actual=Detect(2)）。默认参数（判据行）：n=2, d=hold=∞（桩持锁不放）, t=同时注入, e=Detect(2)。路径方向的序不变量论证：无论谁先拿到，环结构（两节点互指）不变——报告路径可能是 [A→B→A] 或 [B→A→B]，判据用"环长 2 + 节点集 {A,B}"不含方向序（判据行给序不敏感断言的写法）。现有内核接入：无。Windows 对比：Verifier 的经典测试场景（两线程互持）同构；我们的桩任务环境是"无真任务模型"下的等价构造（A3 实装后样本可切真任务——判据行给切换预告）。M-141 复测：10 轮执行全命中 + 方向不敏感断言 + CANCEL 后图零残留。

**判据**：
