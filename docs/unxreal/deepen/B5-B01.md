### UNX-F7201 · dm 设备对象与生命周期
- 域/批：B5/B01｜判据：UNX-F7201-J1 dm 设备创建/激活/挂起/销毁四态迁移全路径断言，销毁时在途 IO 零残留（每请求有终态）；UNX-F7201-J2 非法迁移（未激活先挂起等）100% 拒绝留账｜纯功能行数：280 行（设备对象结构 90 + 四态状态机 100 + 在途终态账 90；测试段不计）｜状态：[已深化]
- **定位**：dm 设备对象是整个 B5 域的原子单位——RAID 卷、LVM 逻辑卷、LUKS 明文面全部以 dm 设备形态存在，本条先把"一个 dm 设备是什么、能处于哪些状态、何时可以消失"钉死。四态（created/active/suspended/destroyed）生命周期与在途 IO 终态账是后续全部批次的地基：B03 的 table reload、B04 的三层堆叠、B06 的 flush 转发契约都以本条状态机为前提。
- **语义边界**：只做 dm 设备对象本体与四态迁移；不做表内容解析（F7202）、不做块层注册细节（F7209）、不做挂起期间 IO 排队语义（F7217）。
- **依赖与嫁接源**：消费 B4 冻结的块层请求提交与完成回调接口；嫁接源为 Linux drivers/md/dm.c 的 mapped_device 生命周期语义与 mddev 状态位惯例，只跟随。
- **风险与回退**：销毁与在途 IO 竞争导致悬空完成回调——销毁路径强制先 quiesce（F7214 原语）再等待在途计数归零，等待期间销毁请求标记 pending 而非失败；状态机迁移表用穷举静态表实现，任何表外迁移在编译期即不可表达。
- 正文：实现路径分三步。第一步设备对象建模：`DmDevice` 结构承载唯一 ID、名称、当前态、映射表句柄、在途计数五要素，对象本身经 B4 块层冻结名空间分配，杜绝裸指针跨域传递；第二步四态状态机：created→active（表校验通过才可迁移）、active↔suspended（对称迁移）、任意态→destroyed（仅允许引用归零后），迁移函数以穷举匹配实现，非法迁移直接拒绝并落拒绝账（原态/目标态/调用栈摘要），绝不静默降级；第三步在途终态账：每个进入 dm 层的请求登记序号，完成路径无论成败必达终态账，销毁前置断言"终态账无未决项"，账目随设备销毁归档供 AI-86 审计。与现存内核衔接点：新建 `kernel/varix/src/dm/` 模块目录，`device.rs` 为首个文件，消费 B4 冻结接口的提交/完成原语，不触碰 B4 内部实现。与 Windows 对照：Windows 存储栈中卷设备由 volmgr 挂载、device 对象生命周期由引用计数与 IO 管理器裁决，禁删在用卷与 dm 销毁协议同义，本内核把"在途零残留"升级为显式终态账可审计。判据 UNX-F7201-J1 的复测方式：ktest 注入四态全路径迁移各 100 次断言通过，销毁并发在途 IO 用例 1000 次每请求有终态；J2 非法迁移穷举用例 100% 拒绝留账。

### UNX-F7202 · dm 映射表三段式结构与解析器
- 域/批：B5/B01｜判据：UNX-F7202-J1 映射表（起始扇区+扇区数+target 类型+参数串三段式）解析后与声明逐字段一致；UNX-F7202-J2 畸形表行（缺段/超长参数/非数扇区）全拒并逐条留诊断账｜纯功能行数：300 行（表行结构 70 + 逐行解析器 130 + 诊断账 100；测试段不计）｜状态：[已深化]
- **定位**：dm 映射表是"逻辑扇区 → 物理去向"的翻译说明书，三段式（起始扇区+扇区数+target 类型与参数串）是 Linux dm 表格式的事实标准，本条把它建为 B5 的对外冻结接口之一（冻结接口第一项"dm 表格式"）——B07 的 raid/crypt target 接入、L1 安装器的卷描述、ktest 的表注入全部消费同一格式，一次冻结处处受益。
- **语义边界**：只做表行结构与文本解析；不做参数串 target 专用词法（F7211）、不做表校验对齐越界（F7207）、不做表激活（F7216）。
- **依赖与嫁接源**：嫁接源为 Linux Documentation/admin-guide/device-mapper 与 dmsetup table 输出格式，只跟随；消费 F7201 设备对象的表挂载槽位。
- **风险与回退**：表行数巨大（RAID 多段）导致解析内存压力——逐行流式解析，解析一行校验一行入账一行，失败行立即终止并报行号，不做全表缓冲；参数串原样透传给 target 词法层，本层不做语义解释。
- 正文：实现路径分三步。第一步表行结构：`TableLine { sector_start, sector_count, target_type, args }` 四字段，扇区以 u64 承载（防 2TB 盘溢出），target 类型以受限枚举预留给 F7203 注册表，args 保序保空格；第二步逐行解析器：以行为单位分词——行号跟踪、扇区数字段严格十进制（拒绝十六进制与负数）、长度非零断言、类型字段白名单预查、参数串原样截取，任何一段失败即以"行号+字段名+原始行"三元组落诊断账并终止整表加载；第三步一致性回读：解析完成的表以规范化格式重新序列化并与原始声明逐字段 diff，保证"解析结果=声明"无隐藏改写，diff 账随表归档。与现存内核衔接点：`dm/table.rs` 新建，扇区算术复用 B4 冻结的扇区常量与块大小定义，无堆分配路径支持静态表构建（F7219 消费）。与 Windows 对照：Windows 存储栈无直接对等物（LDM 数据库为私有二进制格式），Windows 磁盘管理 GUI 的"跨区卷布局"展示的段列表与三段式表行语义同源，本内核选择公开文本格式换取可审计性。判据 UNX-F7202-J1 的复测方式：30 组声明表解析后规范化回读逐字段一致；J2 三类畸形各注入 20 变体全拒且诊断账行号定位 100% 准确。

### UNX-F7203 · dm target 注册表与类型分派
- 域/批：B5/B01｜判据：UNX-F7203-J1 linear/raid/crypt 三 target 注册后按表类型正确分派，未注册类型拒绝路径 100% 覆盖；重复注册拒绝有账｜纯功能行数：260 行（注册表本体 90 + 分派器 80 + 重复与未注册账 90；测试段不计）｜状态：[已深化]
- **定位**：target 注册表是 dm 框架的插件总线——linear（本批）、raid（B08–B11）、crypt（B14–B15）三类 target 依次注册进场，框架层不感知任何 target 内部语义，只负责"按名字找到构造函数"。这一间接层使 B5 域后 39 批的扩展全部发生在 target 侧而框架零改动，是架构上最重要的一条。
- **语义边界**：只做注册、查找与分派；不做任何 target 的映射语义（各 target 条目自管）、不做表解析（F7202 已产出类型名）。
- **依赖与嫁接源**：嫁接源为 Linux `dm_target_type`/`dm_register_target` 语义与 CLOS 插件分派惯例，只跟随；消费 F7202 的 target 类型字段。
- **风险与回退**：target 构造函数 panic 污染框架——分派器要求构造函数返回 Result，框架层捕获不了 panic 就在判据层规定构造函数禁 panic（静态审计条目随 F7220 断言集登记）；注册表容量静态上限 16 类型，超限编译期报错。
- 正文：实现路径分三步。第一步注册表本体：静态数组承载 `TargetOps`（名字/构造函数/析构函数/map 函数/权限位四元组），注册动作只能在内核初始化早期（表加载之前）进行，运行期注册入口不存在——把动态插件的攻击面在架构上删除；第二步分派器：表加载时按类型名查注册表，命中则调用构造函数把参数串交给 target 自行解析（返回 target 私有上下文），未命中返回"未注册类型"错误并落账（类型名+表行号）；第三步重复注册防御：注册时线性查重，重名注册拒绝并落账（两处注册来源），保证一个名字永远只有一个语义。与现存内核衔接点：`dm/target.rs` 新建，linear target 在本批 F7204 实装并作为注册表第一个消费者，raid/crypt 槽位以 `unimplemented!` 占位但判据规定占位不可达（B08/B14 接管时替换）。与 Windows 对照：Windows 存储过滤驱动栈（disk.sys→partmgr→volmgr）以驱动对象栈叠放实现分派，PnP 管理器按设备名装载驱动，本内核以静态注册表对齐"按名分派"体验并显式拒绝热注册。判据 UNX-F7203-J1 的复测方式：三 target 注册后按表分派各 50 次构造上下文正确、未注册类型 20 变体全拒留账；重复注册用例 10/10 次拒绝有账。

### UNX-F7204 · linear target 线性映射实装
- 域/批：B5/B01｜判据：UNX-F7204-J1 线性映射 IO 正确性：dm 设备扇区 N 读写与物理盘偏移 N+base 逐扇区一致（1 万扇区抽样）；UNX-F7204-J2 映射区间外请求按 EIO 拒绝｜纯功能行数：280 行（参数解析 60 + 偏移映射 90 + 区间外拒绝 70 + 抽样校验工具 60；测试段不计）｜状态：[已深化]
- **定位**：linear target 是 dm 世界的"Hello World"，也是最常用的真实语义——LVM 线性卷、多盘拼接的每一段都是 linear。本条把它完整实装并作为框架层（F7201–F7203、F7205）正确性的试金石：框架若有偏移换算缺陷，linear 的逐扇区抽样断言第一个暴露。
- **语义边界**：只做线性偏移映射与区间守卫；不做多段拼接设备语义（F7218）、不做 bio 拆分（F7212）、不做底层盘选择策略（B4 域）。
- **依赖与嫁接源**：注册进 F7203 注册表；消费 B4 冻结的底层盘提交接口；嫁接源为 Linux dm-linear.c（约 200 行）语义，只跟随。
- **风险与回退**：底层盘在 dm 生命周期内被移除（B4 热插拔语义）——linear 上下文持有底层盘的引用计数（F7206 协议），移除路径必须先降引用，映射时发现引用失效立即返回明确错误而非悬空访问。
- 正文：实现路径分三步。第一步参数解析：linear 参数串为"底层盘名 起始偏移"二元组，解析后立即做存在性校验与偏移+长度≤盘容量校验（复用 F7207 校验器的 linear 分支），上下文结构存（盘引用，偏移）二元组；第二步映射实现：map 函数把 bio 的逻辑扇区加上偏移生成新扇区后直传 B4 提交原语，零拷贝零缓冲——linear 是纯地址翻译，任何缓冲引入都是过度设计；完成回调反向剥掉 dm 层标记后上抛，保证上层看到的错误语义与直连物理盘一致（F7215 语义在此首验）；第三步抽样校验工具：向 dm 设备写 1 万个抽样扇区的标记模式（扇区号哈希），再直读底层盘 N+base 位置验证标记一致，双向各做一次，工具随 ktest 固化。与现存内核衔接点：`dm/target_linear.rs` 新建，提交走 B4 冻结接口 `blk_submit`，不触碰 B4 队列内部。与 Windows 对照：Windows 的"简单卷"（diskpart `create volume simple`）即线性映射，IO 管理器把卷内偏移加基址后下发卷设备栈，语义同源；本内核抽样断言对应 Windows 文件系统一致性校验（chkdks 的扇区验证段）的前移。判据 UNX-F7204-J1 的复测方式：1 万扇区抽样双向一致率 100%；J2 区间外请求 20 变体全 EIO 拒绝。

### UNX-F7205 · bio 重映射核心：偏移换算与逐级下传
- 域/批：B5/B01｜判据：UNX-F7205-J1 偏移换算断言：任意（逻辑扇区, 长度）组合换算结果与手算表一致（含边界扇区）；UNX-F7205-J2 逐级下传后上层 bio 完成回调与底层完成一一对应（零丢失零重复）｜纯功能行数：360 行（换算核心 100 + 下传协议 120 + 完成对应账 140；测试段不计）｜状态：[已深化]
- **定位**：bio 重映射是 dm 框架的心脏：每个 IO 请求进入 dm 设备后经历"查表→定位 target→偏移换算→生成子请求→下传→完成回调回溯"全链路，本条把这条链路做成框架级公共设施而非各 target 各写一遍——B03 堆叠、B07 crypt/raid 接入、B12 快照全部复用同一心脏，心脏错一处全域皆错，因此判据最重。
- **语义边界**：只做换算、下传与完成对应协议；不做跨边界拆分（F7212）、不做错误语义改装（F7215）、不做 flush 特殊语义（B06）。
- **依赖与嫁接源**：消费 F7201 设备对象与 F7203 分派器；嫁接源为 Linux `__map_bio`/`clone_bio` 路径与 `bio_endio` 回溯语义，只跟随。
- **风险与回退**：完成回调重复触发（底层驱动缺陷）——完成对应账以请求序号做一次性标记，二次完成直接拒收并落"重复完成"红账，防一个请求唤醒两次上层等待者；下传层零分配（复用请求池），分配失败路径显式拒绝而非排队等待。
- 正文：实现路径分三步。第一步换算核心：给定（逻辑扇区，长度）在映射表二分定位所属 target 段，输出（target 上下文，物理扇区，段内余量）三元组，换算函数纯函数化（无副作用），使其可以用手算表穷举对拍——边界扇区（段首/段尾/跨段前一个）全数入对拍表；第二步下传协议：换算结果生成子请求并携带父请求序号与剩余段信息，按 target 的 map 函数分派下传，下传失败（底层拒收）立即反向完成父请求，绝不滞留；第三步完成对应账：每请求登记"父序号→子序号"边，完成回调沿边上溯，账目断言全链"一边一完成"，请求终态时边删除，账空断言随设备销毁执行。与现存内核衔接点：`dm/map.rs` 新建，请求池复用 B4 冻结的请求分配接口，完成回调注册走 B4 完成原语。与 Windows 对照：Windows 卷管理器（volmgr）对 IRP 的重映射与完成传播同构——下层完成例程经 IoCallDriver 逐层回溯，本内核的父序号边账把该过程显式化为可断言结构。判据 UNX-F7205-J1 的复测方式：穷举边界组合 2000 例与手算表 100% 一致；J2 压测 10 万请求完成账零丢失零重复、重复完成注入 10/10 次拒收有红账。

### UNX-F7210 · dm target 表与请求重映射
- 域/批：B5/B01｜判据：UNX-F7210-J1 三层堆叠（crypt→linear→物理）IO 正确性断言；UNX-F7210-J2 reload 在途零丢失（每请求有终态）；UNX-F7210-J3 非法表参数拒绝路径全账｜纯功能行数：400 行（堆叠下传 130 + reload 协议 140 + 参数守卫 130；测试段不计）｜状态：[已深化]
- **定位**：本条是任务书示例条目（深化保真落位），把 dm 的两大高级能力前置到 B01 收口验证：三层堆叠证明框架支持 target 输出再进 dm（crypt 在 B14 才有真实现，此处以直通桩验证堆叠协议），table reload 证明映射表可以不拆设备热替换——这两点是 LVM 快照（B12–B13）与在线扩容（B12）的直接前提。
- **语义边界**：只做堆叠协议验证与 reload 框架协议；不做 crypt 算法本体（J3 域，判例二）、不做 reload 的 target 专用迁移语义（快照合并归 B13）、不做表内容校验（F7207）。
- **依赖与嫁接源**：消费 F7201 状态机（reload 仅允许 active 态）、F7205 下传协议；嫁接源为 Linux `dm_swap_table`/`__bind` 路径与 dm-restore-in-place 语义，只跟随。
- **风险与回退**：reload 新旧表对同扇区语义冲突（旧表 linear 盘 A 新表盘 B 而请求在途）——reload 强制先 quiesce（F7214）清空在途再换表，绝不允许"在途请求跨表"，协议层面把数据混乱可能性归零；quiesce 失败 reload 整体回滚旧表。

### UNX-F7214 · dm 在途 IO 计数与 quiesce 原语
- 域/批：B5/B01｜判据：UNX-F7214-J1 quiesce 调用后新请求全拒、在途请求全部到达终态后返回（计数归零断言）；UNX-F7214-J2 quiesce 期间提交请求返回明确错误非挂死｜纯功能行数：290 行（在途计数 70 + quiesce 协议 120 + 明确错误账 100；测试段不计）｜状态：[已深化]
- **定位**：quiesce（静止）是 dm 的"暂停世界"原语——reload 换表、挂起（F7217）、断电演练前置（B25 批）都需要"此刻零在途"的保证。它是数据安全域的核心工具：断电演练如果在途不清零，"零损失"结论无效。本条把 quiesce 做成可断言、可重入、无死锁的框架原语。
- **语义边界**：只做在途计数与 quiesce 协议；不做挂起期间排队语义（F7217 挂起排队、本条 quiesce 拒绝）、不做底层盘 quiesce（B4 域）。
- **依赖与嫁接源**：消费 F7201 设备对象与 F7205 完成对应账；嫁接源为 Linux `dm_suspend`/`__dm_internal_suspend` 的静默语义与 blk-mq quiesce，只跟随。
- **风险与回退**：quiesce 与并发 quiesce 死锁（互相等待）——quiesce 带状态位（quiescing/quiesced 双态 CAS），并发调用合并为一次等待（引用化），退出时最后持有者负责放行；quiesce 超时（在途请求悬挂）按 F7215 错误传播诊断，不无限等待。
- 正文：实现路径分三步。第一步在途计数：每设备原子在途计数，请求进入 +1、终态 -1，计数与 F7205 终态账双账互证（计数>0 而终态账空即红账）；第二步 quiesce 协议：置 quiescing 位→新请求立即拒绝（返回明确错误码 + 落拒绝账）→等待在途归零（带超时与阻塞者诊断）→置 quiesced 态，协议全程可重入（多次 quiesce 计数化，resume 对称），quiesce 期间提交请求的行为是"明确错误"而非排队——与挂起（F7217 排队）语义严格区分；第三步超时诊断：在途归零等待超时后打印每在途请求的（序号/进入时间/当前阶段）清单，把"谁卡住了"变成可直接读的账，超时值 cmdline 白名单可调。与现存内核衔接点：`dm/quiesce.rs` 新建，计数原语与 F7206 引用计数同族但语义独立（在途≠引用）。与 Windows 对照：Windows 卷冻结（IOCTL_VOLUME_OFFLINE/fltmc detach 前的排空）与 VSS 快照前的卷静默同语义，文件系统检查（chkdsk /f 独占）前系统对卷执行等效静止。判据 UNX-F7214-J1 的复测方式：在途 1000 请求中 quiesce 100 轮全部归零后返回、计数互证断言零违例；J2 quiesce 期间提交 1000 次 100% 明确错误即时返回。

### UNX-F7216 · dm 表激活状态机
- 域/批：B5/B01｜判据：UNX-F7216-J1 inactive→active→suspended 三态迁移全路径断言；非法迁移（未校验先激活）100% 拒绝；每次迁移留审计账｜纯功能行数：280 行（表级状态机 110 + 审计账 80 + 迁移闸门 90；测试段不计）｜状态：[已深化]

- **语义边界**：只做表级状态机与审计；不做设备级生命周期（F7201）、不做挂起语义实现（F7217）、不做校验内容（F7207）。
- **依赖与嫁接源**：消费 F7201/F7207/F7208；嫁接源为 Linux `dm_table` bind/bind 失败回滚语义，只跟随。

### UNX-F7217 · dm 设备挂起/恢复协议
- 域/批：B5/B01｜判据：UNX-F7217-J1 挂起期间新 IO 排队不丢失，恢复后按序提交（顺序断言）；UNX-F7217-J2 挂起中再挂起幂等（不叠加不泄漏）｜纯功能行数：270 行（挂起协议 100 + 排队簿 90 + 幂等断言 80；测试段不计）｜状态：[已深化]
- **定位**：挂起（suspend）与 quiesce（F7214）的语义分野：quiesce 拒绝新请求（维护窗口），挂起排队新请求（快照拍摄前的静默——B12 快照、B15 LUKS 解锁全部依赖）。挂起期间请求在排队簿等候、恢复后按到达序放行，"按序"是挂起语义的灵魂——乱序放行等于把挂起前后的写顺序打乱，文件系统日志无法容忍。
- **语义边界**：只做挂起/恢复与排队簿；不做 quiesce（F7214 拒绝语义）、不做快照内容冻结（B12 target 语义）、不做挂起时长限制策略（运维域远期）。
- **依赖与嫁接源**：消费 F7201 挂起态与 F7213 队列；嫁接源为 Linux `dm_suspend` 的 deferred 排队语义，只跟随。
- **风险与回退**：排队簿溢出（挂起太久积压）——排队簿容量上限（默认 4096 请求）触顶后转明确错误（拒绝而非丢失，错误带"挂起积压"前缀码），上限与触发计数落账；恢复时排队簿非空但设备已销毁——排队请求全部按明确错误完成，绝不静默丢弃。
- 正文：实现路径分三步。第一步挂起协议：active→suspended 迁移时置排队位，新请求入排队簿（带到达序号）不提交；第二步排队簿：到达序号即放行顺序，恢复（resume）时按序重放提交（重放走 F7213 队列正常路径），重放完成前 resume 不返回——恢复返回时排队请求全部已提交（提交≠完成，语义边界明确：resume 返回=全部进入提交通道）；第三步幂等断言：挂起中再挂起直接成功（状态不变、排队簿不动、无第二本簿），恢复中再恢复同样幂等，两向幂等各有断言（状态位 CAS 验证 + 排队簿引用计数不变量）。与现存内核衔接点：`dm/suspend.rs` 新建，排队簿复用 F7213 队列节点池，到达序号与 F7205 请求序号独立（两套账各管各的）。与 Windows 对照：Windows 卷影子拷贝（VSS）拍摄前对卷执行挂起排空（volsnap 冻结写流），快照期间写请求短暂排队后放行，语义同源；本内核把"排队不丢失"升级为可断言的守恒账。判据 UNX-F7217-J1 的复测方式：挂起期间注入 1000 请求恢复后按序提交（序号单调断言）、零丢失；J2 双重挂起 500 轮幂等且排队簿无泄漏。
