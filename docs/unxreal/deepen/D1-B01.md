### UNX-F12001 · Windows 人格进程对象与内核写路径
- 域/批：D1/B01｜判据：UNX-F12001-J1 进程对象创建/销毁全链可观测，PEB/TEB 由内核侧唯一写者填充，双人格并存隔离判据绿（与 C1 专题六联动）｜纯功能行数：360 行（进程对象结构 110 + 内核写路径分发表 90 + 生命周期钩子 90 + 审计账 70；测试段不计）｜状态：[已深化]
- **定位**：D1 域第一根桩——把"Windows 人格的进程"从 C1 的通用进程模型里独立成 NT 语义对象，内核侧是 PEB/TEB 全部可变字段的唯一写者，这条唯一写者纪律是后续全部偏移对照可信的前提。
- **语义边界**：只做进程对象结构与内核写路径协议；不做进程创建完整系统调用（F12003 承接）、不做句柄表实现（D3 域，本域只做句柄抽象 F12009）。
- **依赖与嫁接源**：上游消费 AI-11（C1）冻结接口"进程对象人格路由"与 A4 每进程地址空间；纯自研无嫁接，语义锚为 Windows Internals 7th Part1 ch.4 进程章（版本锚 ADR-UNX-008）。
- **风险与回退**：C1 接口若在波 06 前调整——写路径分发表以 trait 隔离，路由变更只改编译单元适配层；人格路由错误注入走域守卫拦截。
- 正文：实现路径分三步。第一步建立 NT 进程对象结构：在 C1 通用进程对象之上以组合层挂接 NT 语义扩展块（退出状态、优先级类、配额账、PEB 指针、TEB 链表头），扩展块归 NT 人格子树所有，C1 字段零改动，两人格并存时互不可见。第二步立内核写路径分发表：PEB/TEB 每个可变字段登记唯一写入口（being_debugged、参数块、映像基址、堆指针族），写入口校验调用方上下文（必须是内核线程上下文+持有对象写锁），用户态任何直写由只读快照页映射挡住（F12010 承接），白名单外写入一律红账并拒止。第三步建生命周期审计账：创建、就绪、运行、退出、拆除五态迁移逐笔落账，账条目含时间戳与写入口标识，判据 J1 的复测方式为创建/销毁全链日志回放与账对平、双人格并存进程各 25 个交叉观测 PEB 可见性互斥 50/50 绿。与 Windows 对照：WinDbg `!process 0 0` 列出的进程字段集即本对象语义档的对照面，双机同码逐字段读回一致为复测硬线；与现存内核衔接点为 C1 进程模型 trait 与 A4 地址空间原语，全部经冻结接口消费不越界。
### UNX-F12002 · EPROCESS 语义模型与进程控制块字段账
- 域/批：D1/B01｜判据：UNX-F12002-J1 字段账逐项注出处（版本锚章节号），核心字段语义档双机对照零差异，查无资料字段显式标"待基准机实测"非零条｜纯功能行数：340 行（字段账表 120 + 语义档生成 80 + 出处校验器 80 + 对照面 60；测试段不计）｜状态：[已深化]
- **定位**：EPROCESS 是 Windows 进程的"户口本"，本条不照抄 Windows 私有布局（那是不可复验的），而是建立"语义字段账"——每个 NT 进程语义必须承载的信息项逐条登记：字段名、语义、出处、Varix 承载位置，作为 D2–D5 与 E1 的查询事实源。
- **语义边界**：只做字段语义账与承载映射；不做 Windows 私有偏移复刻（查无公开资料的私有偏移一律不编）、不做对象头通用结构（D3 域）。
- **依赖与嫁接源**：消费 F12001 对象扩展块；出处锚=Windows Internals ch.4 公开论述与 MSDN SYSTEM_PROCESS_INFORMATION 公开结构，逐项注章节号。
- **风险与回退**：部分字段（如私有调试口）公开资料薄——显式标"待基准机实测"进 O1 排期，禁编造（§40 幻觉红线），账面诚实优先。
- 正文：实现路径分三步。第一步建字段账静态表：以 Rust const 表登记 UniqueProcessId、ActiveProcessLinks、StartAddress、 Peb、ProcessQuotaUsage、ProcessQuotaPeak、CommitCharge、CreateExitTime、ImageFileName、PriorityClass 等 ≥25 个公开语义字段，每行五列（字段/语义/出处章节/Varix 承载位/判据 ID），出处列空即编译失败——把防幻觉做成静态断言。第二步语义档生成：每字段从账表派生语义档（正常值域/异常值/边界），供 F12018 查询底座与 O1 对标账取用。第三步对照面：抽取公开结构（SYSTEM_PROCESS_INFORMATION）可见子集与 Windows 真机读回对照。与现存内核衔接点：账表落在 NT 人格子树静态区，消费 F12001 扩展块字段。与 Windows 对照：双机同码跑同组进程，Process Explorer 与本域账读回字段逐项一致为复测硬线；判据 J1 复测方式：30 字段抽样一致性 100%，"待实测"条数显式在账非零即合规。
### UNX-F12003 · NT 进程创建内核路径语义（NtCreateUserProcess 底座）
- 域/批：D1/B01｜判据：UNX-F12003-J1 创建路径 10 步序列（参数校验→对象建→PEB 填→TEB 填→线程挂→句柄回）真机逐步日志可回放，失败注入 10/10 次按错误矩阵落正确 NTSTATUS｜纯功能行数：380 行（创建序列器 130 + 失败回滚器 90 + 错误矩阵 90 + 步骤日志 70；测试段不计）｜状态：[已深化]
- **定位**：进程创建是 NT 人格的"出生序列"，本条把创建路径钉成 10 步不可乱序的状态序列器——每步有前置断言、失败回滚点与独立日志，D2 装载器联签时以同一序列表对表。
- **语义边界**：只做创建内核路径序列与失败矩阵；不做 PE 映像装载（D2 防重）、不做句柄表数据结构（D3 防重，本条只到"句柄回填"协议位）。
- **依赖与嫁接源**：消费 F12001/F12002 对象与字段账、F12005/F12006 PEB/TEB 实装件；语义锚=Windows Internals ch.4 创建流程论述（CreateUserProcess 路径）。
- **风险与回退**：上游 C1 线程底座接口变动——序列器步骤 7"线程挂"以适配 trait 隔离；失败回滚保证半成品进程不残留（句柄/内存账归零）。
- 正文：实现路径分三步。第一步序列器建模：创建路径固化为 10 步枚举（参数校验、映像节消费占位、进程对象建、地址空间绑定、PEB 填充、进程参数块填、初始线程建、TEB 填充、线程就绪、双句柄回传），每步注册前置断言与回滚函数，任一步失败按逆序回滚已步。第二步错误矩阵：每步登记可失败集（参数错→INVALID_PARAMETER、资源尽→INSUFFICIENT_RESOURCES、人格路由错→访问拒），注入用例逐码验证。第三步步骤日志：每步进出打带时间戳与对象 ID 的日志行，支持离线回放比对。与 Windows 对照：双机创建同参数进程，步骤序列在语义层面逐段对应（Windows 无公开逐步日志，对照面取"最终态一致+错误码一致"两硬线）。与现存内核衔接点：序列器挂 NT 人格子树，步骤 5/6/8 分别调 F12010 写路径、F12008 参数块、F12006 TEB 填充；判据 J1 复测方式为 20 次创建日志回放零缺步、10 类失败注入逐码对矩阵。
### UNX-F12004 · 进程终止语义与退出状态传播链
- 域/批：D1/B01｜判据：UNX-F12004-J1 NtTerminateProcess 退出码传播全链可观测，等待方取回的 ExitStatus 与终止方写入值逐字节一致 50/50 次｜纯功能行数：320 行（终止序列器 100 + 退出码账 80 + 等待方交付 80 + 特例处置 60；测试段不计）｜状态：[已深化]
- **定位**：终止比创建更易出隐患——本条把退出码从"终止方写入"到"等待方读回"的完整传播链做成守恒账：一个退出码，全程零改写，沿途每笔交付留痕。
- **语义边界**：只做退出码传播与终止序列语义；不做拆除的内存回收细节（F12016 承接）、不做 Job 终止传播（D2 域）。
- **依赖与嫁接源**：消费 F12001 生命周期钩子与 F12016 拆除次序协议；语义锚=MSDN NtTerminateProcess/TerminateProcess 语义与 ExitProcess 链公开论述。
- **风险与回退**：多线程进程"先杀他线程再自杀"次序歧义——按版本锚语义固定：Terminate 面向全进程，先逐线程终告再回收，次序写死在序列器；异常退出（未捕获）走 STATUS 码链路同账。
- 正文：实现路径分三步。第一步终止序列器：NtTerminateProcess 语义固化为三段（标记者置退出码与状态、全线程终告、移交拆除协议），段间屏障可观测。第二步退出码账：写入一次记账，此后每笔读出（等待方 GetExitCode 语义、父进程回收语义）只读不改，账尾与账头逐字节比对即守恒判据。第三步特例处置：自身终止 vs 被他人终止、初始化失败快速退出、双终争用三个特例场景显式建模，落"谁赢谁记账"裁决规则。与现存内核衔接点：终止序列器挂 F12001 五态机"退出"态入口，等待方交付复用 C1 等待底座。与 Windows 对照：双机同码跑"子进程退出码 X→父进程等待读回"链路 50 次，读回值与写入值逐字节一致率 100%（判据 J1）；对照工具链为 PowerShell `$LASTEXITCODE` 与 Win32 GetExitCodeProcess 双通道互证。

### UNX-F12006 · TEB 与 NT_TIB 语义实装
- 域/批：D1/B01｜判据：UNX-F12006-J1 gs:[0x30] Self 指针自指正确，TLS 槽数组挂点可寻址，LastErrorCode 读写语义与版本锚一致｜纯功能行数：300 行（TEB 布局表 90 + NT_TIB 语义 70 + gs 挂点 80 + TLS 槽 60；测试段不计）｜状态：[已深化]
- **定位**：TEB 是线程的自述书——应用代码用 gs 段直取，本条立 x64 TEB 布局表与 NT_TIB 三锚（Self/StackBase/StackLimit），保证"gs:[0x30] 取 TEB 自身"这一自指恒等式成立。
- **语义边界**：只做 TEB 结构与 gs 挂点；不做逐字段深化（B04 批承接）、不做线程切换本体（A3 域，本域只挂 gs 基址写点）。
- **依赖与嫁接源**：消费 F12001 线程扩展块；布局锚=公开 TEB x64 布局资料（NT_TIB 在 0x0、Self 在 0x30 档），逐项注出处。
- **风险与回退**：gs 基址写点与 A3 调度切换竞态——写点收敛为单入口并在切换屏障内执行，联签 A3 锁序账。
- 正文：实现路径分三步。第一步布局表：TEB 从 NT_TIB（0x0）起登记 EnvironmentPointer、ClientId（0x40 档）、ActiveRpcHandle、ThreadLocalStoragePointer、ProcessEnvironmentBlock（0x60 档）、LastErrorValue 等公开字段，编译期断言锁偏移。第二步 NT_TIB 语义：ExceptionList（x64 弃用链式但结构位保留）、StackBase/StackLimit 与线程栈范围对账、Self 自指（写入 TEB 自身地址，读回校验）三锚立判据。第三步 gs 挂点：线程创建时分配 TEB 页→填 Self→写 gs 基址（经 A3 切换屏障单入口），TLS 槽数组（TlsSlots[64]）挂点可寻址，LastErrorCode 读写语义立档。与 Windows 对照：双机用户态同码 `mov rax, gs:[0x30]` 取 Self 与 `NtCurrentTeb()` 对照，再以 WinDbg `dt nt!_TEB` 校偏移；判据 J1 复测方式为 50 线程 Self 自指 50/50、TLS 槽写读回 10^4 次一致、LastError 槽位注入链路读回一致。
