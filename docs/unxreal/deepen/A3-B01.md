### UNX-F1601 · SMP 前置数据包消费与 A1 联签确认
- 域/批：A3/B01｜判据：UNX-F1601-J1 宿主侧消费 A1 F0188 前置数据包全字段（核列表/LAPIC 基址/缺席核账/trampoline 预留区）逐字段校验落账，字段缺失或版本不符时启动序列拒绝开跑并列出缺失清单，联签确认记录入 handoff｜纯功能行数：320 行（数据包结构体映射 100 + 逐字段校验账 120 + 联签记录与拒绝路径 100；测试段不计）｜状态：[已深化]
- **定位**：F0188 是 A1 递给本域的开工钥匙，本条把"数据包在册"验证为"逐字段可信可消费"——核列表、LAPIC 基址、缺席核账、trampoline 预留区四组字段全部过校验后，多核启动序列才有开跑资格；联签动作同时解除 handoff `cross_domain_freeze` 中"待 A3 联签"的冻结项。
- **语义边界**：只做数据包消费校验与联签；不做 MADT 重新解析（A1-F0004 防重）、不做启动序列本体（F1604）、不改 A1 冻结数据结构（只读消费）。
- **依赖与嫁接源**：依赖 A1-F0188 前置数据包（承接非重复——A1 建包，本条验包）、A1-F0004 拓扑账交叉核对核数；嫁接源为 Intel SDM Vol.3 §8.4 与 ACPI 6.5 MADT 章节，只跟随。
- **风险与回退**：A1 数据包字段版本升级（新增字段）——按"消费已知字段 + 未知字段登记不拒绝"的向前兼容策略，版本号不匹配时显式降级并告警；关键字段缺失（核列表为空）按致命档处置进 F0017 诊断路径。
- 正文：实现路径分三步。第一步数据包映射：按 A1 冻结的 F0188 结构体定义本域侧只读视图（零拷贝引用），核列表向量、LAPIC 基址、缺席核位图、trampoline 预留区基址四组字段逐一定位；第二步逐字段校验：核列表非空且 ≤MAX_CPUS=64、LAPIC 基址与 F0004 拓扑账一致、缺席核与 enabled 核互斥、trampoline 预留区落在 A1 三源合并内存图的保留区——四组校验各出独立结论账，任一致命档失败即拒绝开跑并打印缺失清单进诊断模式（F0017 路径），降级档（字段可选缺失）记告警不阻塞；第三步联签落账：校验全过后在本域账本写联签确认记录（数据包版本/校验时间/字段结论四元组），同步更新 handoff 冻结项状态。与现存内核衔接点：消费 `cpu/smp.rs` 既有 `register()` 注册原语，校验逻辑新增于 `smp.rs` 扩展模块，不触碰 A1 侧任何写入路径。与 Windows 对照：Windows 启动期内核以 `KeQueryActiveProcessorCount` 等原语消费固件拓扑，固件拓扑坏数据在其侧表现为启动蓝屏 INACCESSIBLE_BOOT_DEVICE 族，本内核以"拒绝开跑 + 可读缺失清单"为体验对齐点。判据 UNX-F1601-J1 的复测方式：宿主侧以三机型快照数据包注入 10/10 次逐字段校验落账一致；缺失注入（删字段/改版本/坏基址）10/10 次拒绝开跑并列全清单；联签记录与 handoff 状态同步可查（实机核数一致性判据随闸门补测登记）。

### UNX-F1602 · CPU 拓扑表消费与每核坐标账
- 域/批：A3/B01｜判据：UNX-F1602-J1 消费 A1 拓扑账构建（包/核/线程）四元组坐标表，坐标数与 MADT enabled 核数一致，SMT 兄弟线程对映射账零遗漏可导出｜纯功能行数：300 行（坐标表构建 120 + SMT 兄弟对映射 100 + 一致性校验 80；测试段不计）｜状态：[已深化]
- **定位**：拓扑坐标是负载均衡与核亲和的地基坐标系，本条把 A1 的线性核列表升级为带结构坐标的每核档案——哪两个线程共享物理核、哪个包挂哪条内存节点（NUMA 项预留），调度器后续一切"就近调度"的判断都从这里取数。
- **语义边界**：只做坐标表构建与兄弟对映射；不做负载均衡决策（B09 防重）、不做 NUMA 距离仲裁（消费 SLIT 属后续条目）、不改 A1 拓扑账本体。
- **依赖与嫁接源**：依赖 A1-F0004 拓扑账与 A1-F0015 CPUID 拓扑叶（承接非重复——A1 建账，本条建坐标视图）；嫁接源为 Intel SDM Vol.3 §8.9 与 CPUID 叶 0x1F 语义，只跟随。
- **风险与回退**：OEM 拓扑叶缺失或 MADT 与 CPUID 拓扑矛盾——矛盾核按保守档（每线程独立核坐标）降级并打诊断账，兄弟对映射缺席时均衡器自动退化为无缓存亲和模式。
- 正文：实现路径分三步。第一步坐标表构建：从 A1 拓扑账逐核展开（包 ID/核 ID/线程 ID/全局核号）四元组，核号连续分配与 MADT enabled 序一致，表容量按 MAX_CPUS 静态布局零堆分配；第二步 SMT 兄弟对映射：同包同核双线程建立互指关系账（线程 A 的兄弟是 B，反之亦然），兄弟对是 B09 缓存亲和与 F1764 cache-hot 判定的直接输入，单线程核兄弟位登记为空；第三步一致性校验：坐标总数对 MADT enabled 核数、对 F0015 CPUID 拓扑逻辑核数双向核对，不一致打诊断账并按保守档运行。与现存内核衔接点：`cpu/cpuinfo.rs` 既有 CPUID 解析零改动，坐标表新增于 `smp.rs` 扩展模块，供 B09/F1770 与 F1692 隔离集消费。与 Windows 对照：SysInternals Coreinfo 以矩阵图呈现 P/S 共享拓扑，本内核坐标账导出格式与其逐核可比对；Windows 处理器亲和 API 的"逻辑处理器编号"即本表全局核号。判据 UNX-F1602-J1 的复测方式：宿主侧三机型拓扑快照注入后坐标数与 enabled 数一致、SMT 机型兄弟对 100% 建账可导出、Coreinfo 同机对照一致；矛盾注入 10/10 次诊断捕获并保守降级（真机拓扑核对随闸门补测登记）。

### UNX-F1603 · 缺席核账消费与在线核位图建立
- 域/批：A3/B01｜判据：UNX-F1603-J1 缺席核账逐核登记后建立在线核位图，位图人口与注册核数一致，缺席核位永远为零且有账可查｜纯功能行数：260 行（位图容器与置位原语 100 + 缺席核登记 80 + 一致性账 80；测试段不计）｜状态：[已深化]
- **定位**：在线核位图是全系统"谁活着"的唯一速查表——IPI 广播、负载均衡、热插拔协议全部以它为过滤面，本条在启动早期把 A1 缺席核账转化为本域的在线位图，缺席核从第一天起就永不进入广播名单，防"向幽灵核喊话"类事故。
- **语义边界**：只做位图建立与缺席登记；不做位图运行期热更新（F1613）、不做缺席核复活（F1849 上线协议）。
- **依赖与嫁接源**：依赖 A1-F0188 缺席核账与 F1601 数据包校验；现存 `cpu/smp.rs` PerCpu::is_online 承接扩展；嫁接源为 Linux `cpu_online_mask` 语义与 Intel SDM Vol.3 §8.4，只跟随。
- **风险与回退**：A1 缺席账与 MADT enabled 账冲突（账面缺席但固件声称可用）——以缺席账为准并在启动报告双列登记差异，运行期探测到"缺席核自启"按异常事件入账。
- 正文：实现路径分三步。第一步位图容器：64 位整型位图按 MAX_CPUS=64 满容量静态布局，置位/清位/查询三原语全部原子操作，BSP 核启动即置位；第二步缺席核登记：消费 A1 缺席核账逐核核对，缺席核位保持零并写入缺席账（核号/缺席来源/登记时间），F1609 超时降级的核在运行期追加进缺席账同一位图纪律；第三步一致性账：位图人口（置位数）对 `cpu_count()` 注册数逐次核对，启动报告输出"应到/实到/缺席"三数对照——这个三数对照是 F1614 时间线账与后续 72h 长稳账的口径基准。与现存内核衔接点：`PerCpu::is_online` 与 `register()` 零改动，位图为新增静态结构，B09 均衡与 F1807 IPI 选路全部消费本位图。与 Windows 对照：Windows 的 KeQueryActiveProcessors 返回 KAFFINITY 掩码即同构在线位图，本内核位图导出与其逐位可比对。判据 UNX-F1603-J1 的复测方式：宿主侧注入缺席核 1/2/8 核快照各 10/10 次位图人口与缺席账一致；"应到/实到/缺席"三数对照在启动报告可查；缺席核位永零断言全过（真机缺席核场景随闸门补测登记）。

### UNX-F1604 · AP 启动序列总控状态机（INIT-SIPI-SIPI）
- 域/批：A3/B01｜判据：UNX-F1604-J1 INIT→SIPI→SIPI 序列按 Intel SDM 时序逐核发出，每核状态机六态（待启/INIT 已发/SIPI 一发/SIPI 二发/到齐/超时）迁移全落账，序列重放账可审计｜纯功能行数：380 行（六态状态机 160 + 10ms 等待节拍与双 SIPI 时序 120 + 重放账 100；测试段不计）｜状态：[已深化]
- **定位**：INIT-SIPI-SIPI 是 x86 多核启动的法定三拍，本条把散落的 ICR 写入收拢为一台逐核总控状态机——每核独立六态迁移、每拍发出时刻落账、双 SIPI 间隔（SDM 建议 10ms 级节拍）由 TSC 计时保障，状态机本身可重放可审计，是三十年 SMP 面的第一块承重墙。
- **语义边界**：只做启动序列总控与状态机；不做 trampoline 页内容（F1605）、不做 AP 侧初始化（F1608）、不做 IPI 运行期语义（B11 防重）。
- **依赖与嫁接源**：依赖 F1601 数据包核列表、F1602 坐标表、现存 `cpu/smp.rs` 的 `icr_low()`/`DM_INIT=0b101`/`DM_STARTUP=0b110`/`send()` 原语（承接非重复——原语已真机可写，本条建总控层）；嫁接源为 Intel SDM Vol.3 §8.4.4 MP Initialization 与 §8.4.5「INIT-SIPI-SIPI」时序表，只跟随。
- **风险与回退**：个别固件要求 INIT 后延时才能收 SIPI（虚拟化与老平台差异）——延时参数进 F1738 参数注册表可配置，缺省按 SDM 保守值；双 SIPI 之间发现核已到齐即短路跳过第二发（幂等保护），乱序到齐不崩溃。
- 正文：实现路径分三步。第一步六态状态机：每核独立 `ApBootState`（待启/INIT 已发/SIPI 一发/SIPI 二发/到齐/超时），迁移函数单一入口、迁移即记账（前后态+TSC 时刻），禁止跨态跳转；第二步时序节拍：INIT 经 `icr_low(0, DM_INIT, true, target)` 级目标发出，TSC 计时等待后第一发 SIPI（vector=TRAMPOLINE_PAGE>>8 语义对齐现存 TRAMPOLINE_VECTOR=0x08 约定），间隔节拍后第二发，逐拍时刻进重放账；第三步重放账与幂等：全部 ICR 写入按序登记（核号/类型/向量/TSC），支持宿主侧按账重放比对；已到齐核的 SIPI 自动跳过并记账"跳发"，到齐判定消费 F1612 握手完成位。与现存内核衔接点：`send()`/`icr_low()` 零改动，状态机新增于 `smp.rs` 扩展模块，BSP 侧驱动、AP 侧消费 F1605 布局。与 Windows 对照：Windows 的 NTOSKRNL 多核启动路径在 WinDbg `!apic` 可观测 ICR 历史行为，双 SIPI 是其兼容性结论的行业共识，本内核以时序账逐拍对齐。判据 UNX-F1604-J1 的复测方式：宿主侧状态机单测六态迁移矩阵全过；时序账毫秒级可导出；跳发/乱序注入 10/10 次幂等不崩（真机 INIT-SIPI-SIPI 发射成功判据随闸门补测登记）。

### UNX-F1605 · trampoline 页布局与 16 位实模式入口协议
- 域/批：A3/B01｜判据：UNX-F1605-J1 trampoline 页（消费 A1 预留低 1MB 保留区与 TRAMPOLINE_PAGE=0x08 向量约定）布局五段（实模式入口/GDT 载荷/临时 IDT 摘要/保护模式跳板/到齐旗标）逐段偏移账固化，字节布局与向量号约定一致可重放构建｜纯功能行数：380 行（五段布局生成器 150 + 向量号与页基址协议 110 + 可重放校验 120；测试段不计）｜状态：[已深化]
- **定位**：trampoline 页是 AP 醒来后读到的第一页内存，本条把 A1 预留的低 1MB 保留区固化为五段布局的字节级契约——SIPI 向量号 0x08 即页基址 0x8000 段约定、实模式入口偏移、五段各自的偏移与长度全部静态可验证，BSP 写入端与 AP 读取端共享同一份布局常量，杜绝"两端各想各的"经典串页事故。
- **语义边界**：只做布局契约与构建校验；不做 AP 侧 16 位代码语义（F1608 路径）、不做临时页表内容（F1607）、不改 A1 预留区边界。
- **依赖与嫁接源**：依赖 A1-F0188 trampoline 预留区、A1-F0008 内存图保留区交叉核对、现存 `cpu/smp.rs` TRAMPOLINE_PAGE/TRAMPOLINE_VECTOR 常量（承接非重复——常量已立，本条建布局层）；嫁接源为 Intel SDM Vol.3 §8.4.4 SIPI 向量-页基址换算规则，只跟随。
- **风险与回退**：低 1MB 保留区被固件 SMM 或遗留设备侵占——布局构建前对目标页做签名写读校验，侵占即换备用页（A1 预留区含双候选）并落账；备用页也失守则该核走缺席账降级。
- 正文：实现路径分三步。第一步五段布局：页内偏移 0x00 实模式入口（jmp 到初始化头）、0x10 GDT 载荷（基址/界限二元组）、0x20 临时 IDT 摘要（早期异常兜底）、0x40 保护模式跳板（置 PE/PG 的 far jump 序列）、0xE0 到齐旗标（原子字），每段偏移为 const 常量且 BSP/AP 共享同一常量表；第二步向量协议：SIPI 向量 0x08 → 段基址 0x8000（向量<<12），与现存 TRAMPOLINE_PAGE=0x08 逐字对齐，布局生成器按常量表产出自检（段重叠/越界/对齐三断言），布局字节图可导出；第三步可重放校验：构建完成后对页做签名写读回验，字节图哈希入 F1614 时间线账，宿主侧可用同一哈希核对真机页内容。与现存内核衔接点：`TRAMPOLINE_PAGE`/`TRAMPOLINE_VECTOR` 常量零改动消费，布局生成器新增于 `smp.rs` 扩展模块，A1 内存图只读消费。与 Windows 对照：Windows AP 启动同样依赖低 1MB 实模式跳板页，HalPrivateData 路径在 WinDbg 可观测其页内容，本内核以字节级布局账对齐其兼容性实践。判据 UNX-F1605-J1 的复测方式：布局自检三断言 10/10 次通过；侵占注入（目标页预写脏数据）10/10 次签名校验拦截并切换备用页；字节图哈希重放一致（真机 SIPI 后 AP 首指令命中判据随闸门补测登记）。

### UNX-F1606 · AP 临时栈分配与栈顶约定
- 域/批：A3/B01｜判据：UNX-F1606-J1 每 AP 临时栈按核序从预留区顺序切分，栈顶指针写入 trampoline 约定槽位，双核栈区零重叠断言｜纯功能行数：240 行（切分器 100 + 槽位协议 70 + 重叠断言 70；测试段不计）｜状态：[已深化]
- **定位**：AP 醒来时没有堆没有分配器，唯一的内存安全来自一份预先切好的临时栈，本条按核序从 trampoline 预留区切分每核 4KB 临时栈，栈顶写入约定槽位——trampoline 跳板加载该值进 SP，这是"AP 不踩 BSP、AP 不踩 AP"的边界保证。
- **语义边界**：只做临时栈切分与槽位写入；不做内核栈独立化（F1624 防重）、不做栈内容约定（F1608 七步路径）。
- **依赖与嫁接源**：依赖 F1605 五段布局的槽位约定与 A1 预留区；嫁接源为 Intel SDM Vol.3 §8.4.4 启动栈要求与 Linux trampoline 栈惯例，只跟随。
- **风险与回退**：预留区容量不足（核数超预期）——切分器按容量上限硬断言，超限核直接缺席账降级；栈顶对齐 16 字节强制（SSE 对齐需求）。
- 正文：实现路径分三步。第一步切分器：预留区按核序线性切 4KB，区间 [base+i*4K, base+(i+1)*4K)，BSP 核为零号不入切分；第二步槽位协议：栈顶（高地址端，16 字节对齐）写 trampoline 页约定槽位（F1605 布局 0x30 偏移），写入即记账（核号/栈顶值/TSC）；第三步重叠断言：任意两核栈区间闭开交叠检测为零，切分表与 F1605 字节图合并导出。与现存内核衔接点：`cpu/smp.rs` 扩展模块新增切分器，消费 A1 内存图只读。与 Windows 对照：Windows AP 临时栈由内核初始化路径预置，规模同量级（4KB 档），本内核切分账与其实践对齐。判据 UNX-F1606-J1 的复测方式：64 核满载切分 10/10 次零重叠；对齐断言全过；槽位值与切分表逐核一致（真机栈可用性判据随闸门补测登记）。

- **语义边界**：只做临时页表与挂接路径；不做母版页表本体（A1-F0012 防重）、不做每进程 CR3（A4 域防重）、不做 PCID（A4 域 F2405 防重）。

- **风险与回退**：临时表与母版布局漂移（A1 侧改动未同步）——构建期对两表做逐项 diff 断言，漂移即拒绝上线；CR3 预期值账为唯一真值，AP 实际写入值不符按上线失败处置。

- **定位**：AP 从实模式醒来到能被调度器调度，七步缺一不可且顺序不可乱——本条是七步的推进器与监督者，每步完成置独立标志位，账面可查每核走到第几步；判例"拉起归 A1，落座归 A3"在本条完成落座侧定义：A1 负责把核拉进 trampoline，A3 从 trampoline 起全权接管七步。
- **语义边界**：只做七步推进与监督；不做 GDT/TSS 内容构建（F1615）、不做 LAPIC 使能细节（F1617）、不做 idle 循环语义（F1618）。

- **风险与回退**：某步失败（如 LAPIC 使能异常）——推进器在该步挂起该核并落账（步号/错误码/TSC），已上线核不受影响；挂起核可由 F1609 重试路径重启七步。

- 域/批：A3/B01｜判据：UNX-F1609-J1 AP_READY_TIMEOUT_10MS=200（2 秒）超时后单次重试，再超时该核标记离线落缺席账，系统降级单核继续引导不阻塞，全路径 10/10 次注入按账处置｜纯功能行数：280 行（超时监视器 110 + 重试序列 80 + 降级处置 90；测试段不计）｜状态：[已深化]
