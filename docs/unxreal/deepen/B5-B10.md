### UNX-F7385 · RAID5 双故障检测与缺席声明
- 域/批：B5/B10｜判据：UNX-F7385-J1（保护判据先行）双盘故障立即拒绝服务并显式声明（数据不可恢复警告，禁止静默半可用）；双故障检测延迟账 ≤1 个 IO 错误内｜纯功能行数：300 行（双故障检测 100 + 拒服态 100 + 显式声明 100；测试段不计）｜状态：[已深化]
- **定位**：双故障=RAID5 数据不可恢复的悬崖：两盘同时失效时部分条带（两盘同带）数据永久丢失——此时绝不能"静默半可用"（把丢数据的区段悄悄返回垃圾），必须立即拒绝服务并显式声明（阵列挂起+数据不可恢复警告+哪些条带受影响可查）。保护判据先行：双故障检测延迟 ≤1 个 IO 错误内（第二个故障确认的那一刻阵列就挂起，不给任何错误数据流出的窗口）。这是"显式缺席"哲学的最强执行点：宁可全停，不可半骗。
- **语义边界**：只做双故障检测与拒服；不做单故障处理（F7381 降级态）、不做拒服后的数据抢救面（管理域扩展，本条提供受影响条带清单接口）、不做 RAID1 双故障（RAID1 双镜像无此悬崖——单盘剩一块=零冗余档 F7366）。
- **依赖与嫁接源**：承接 F7386 检测源与 F7381 状态机；嫁接源为 md failed 阈值语义，只跟随。
- **风险与回退**：误判双故障（瞬时 IO 风暴被误计为第二盘故障）——故障判据沿用 F7386 三源确认口径（确认级事件才计数），瞬时错误重试不计数；拒服瞬间的在途 IO（半完成的写）——在途 IO 按完成序裁定（未确认=未发生），拒服前 flush 收尾（F7301 契约语义）。
- 正文：实现路径分三步。第一步双故障检测：故障成员计数器（确认级故障事件累计），计数达 2 即触发拒服（检测延迟账：从第二故障确认到拒服生效，≤1 个 IO 错误内断言——注入第二故障后首个到达的 IO 必得拒服码）；第二步拒服态：阵列挂起（新 IO 全拒 EROFS 语义+错误码细分"双故障拒服"），在途收尾（flush+未确认写裁定），拒服状态落元数据（重启后保持拒服——不自动复活）；第三步显式声明：数据不可恢复警告全通道（F7366 三通道复用），受影响条带清单（两故障盘同条带交集计算，清单接口可查），声明含自救指引（两盘均不可用时的恢复途径说明——文字声明落档）。与现存内核衔接点：`dm/raid5/refuse.rs` 新建。与 Windows 对照：Windows RAID-5 失败卷（failed redundancy → failed volume）同构。判据 UNX-F7385-J1 的复测方式：双故障注入 ×20 全部拒服（延迟 ≤1 IO 断言逐次落账）、静默半可用审计（拒服后注入读请求全拒零垃圾返回）、受影响条带清单与理论交集一致、重启保持拒服断言。
