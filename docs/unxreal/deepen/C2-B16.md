### UNX-F9101 · fcntl 语义档总纲（F_GETFD/F_SETFD/F_GETFL/F_SETFL 四命令）
- 域/批：C2/B16｜判据：UNX-F9101-J1 四命令读写回环判据过，FD_CLOEXEC 位 execve 后生效可观测，坏 fd 注入全 EBADF 逐格核对｜纯功能行数：400 行（四命令读写回环 150 + FD_CLOEXEC 生效格 130 + 坏 fd 注入 120）｜状态：[已深化]

- **定位**：本条是 fcntl 命令面（F9102–F9115 各专条）的总纲与四基础命令语义档：F_GETFD/F_SETFD 管描述符旗标（FD_CLOEXEC 单位）、F_GETFL/F_SETFL 管文件状态旗标（O_RDONLY/O_NONBLOCK/O_APPEND 等），四命令构成 fcntl 的地基命令集，glibc FILE* 与 shell 重定向的底层依赖。
- **语义边界**：只管四命令语义与回环；复制命令归 F9102、记录锁归 F9103、信号属主归 F9110；fd 表本体分配策略归 B08 dup 族母体（本条消费不重铺）；execve 清理时点语义归 B04 fork/exececve 母体格。
- **依赖与嫁接源**：嫁接 fcntl(2) man-pages 四命令段（FD_CLOEXEC 值 1、F_GETFL 返回位掩码语义）；锚定 B08 dup 族 fd 表格、F8921 参数拷贝探针（arg 寄存器取参）、B1 VFS fd 表消费协议、B12 EINTR 判定器（回环重试面）。
- **风险与回退**：风险一为 F_GETFL 回读与置位不对称（置 O_NONBLOCK 回读丢位）——回退为回环判据硬规则：F_SETFL 置位后 F_GETFL 回读逐位与期望集一致，差一位即 fail；风险二为 FD_CLOEXEC 在 execve 路径清理时点错误（清理过早致父进程 fd 失效）——回退为生效格只在 execve 成功落点清理、失败路径 fd 保持原态的探针断言。
- **正文**：实现路径分三步：第一步立四命令读写回环——F_GETFD/F_SETFD 以 FD_CLOEXEC 单位位回环（置 1 读 1、置 0 读 0），F_GETFL/F_SETFL 以 O_NONBLOCK/O_APPEND 双位回环，回环在 tmpfs 常规 fd 与管道 fd 双对象上各跑一遍（对象无关性）；第二步立 FD_CLOEXEC 生效格——置位后 fork+execve 子进程侧 fd 关闭断言（关闭前 open 计数、execve 后计数减一）、execve 失败（坏路径）时 fd 存活对照断言，双路径可观测；第三步立坏 fd 注入——fd=-1/9999/已 close 三态注入四命令，全部 -EBADF 且 errno 单一，逐格核对表落账。与现存内核衔接点：fd 表与 B08 分配器单源；arg 取参经 F8921 探针。与 Windows 对照：Windows 无 fcntl 等价（_setmode/HandleFlags 部分覆盖），HANDLE 无继承位语义对齐 HANDLE_FLAG_INHERIT；本条按 Linux 上游语义冻结。判据 UNX-F9101-J1 的复测方式：ktest 三断言——四命令回环 2 对象×4 命令全过、CLOEXEC 双路径计数断言、坏 fd 三态注入表。

### UNX-F9102 · fcntl F_DUPFD/F_DUPFD_CLOEXEC 复制命令
- 域/批：C2/B16｜判据：UNX-F9102-J1 最小可用 fd ≥ arg 分配判据过，CLOEXEC 变体位翻转可观测，与 dup 族分配器单源对账｜纯功能行数：320 行（最小 fd 分配格 120 + CLOEXEC 变体翻转 100 + dup 族对账 100）｜状态：[已深化]

- **定位**：本条立 fcntl 复制双命令语义档：F_DUPFD 分配 ≥arg 的最小可用 fd（共享文件描述）、F_DUPFD_CLOEXEC 同分配并置 FD_CLOEXEC——shell 与运行库扩展 fd 表的主力路径，与 dup/dup2/dup3 构成复制命令全家族。
- **语义边界**：只管两命令分配与旗标语义；dup/dup2/dup3 本体归 B08 母体（本条对账不重铺）；分配策略（最低可用位扫描）归 fd 表本体；F_GETFD 回读归 F9101。
- **依赖与嫁接源**：嫁接 fcntl(2) man-pages F_DUPFD 段（"least available file descriptor ≥ arg"原文语义）；锚定 B08 dup 族分配器单源协议、F9101 FD_CLOEXEC 单位、B12 EMFILE 上限格。
- **风险与回退**：风险一为 arg 边界（arg 大于上限）语义漂移——回退为 arg>上限时返回 -EINVAL 的探针格与 Linux 一致，arg=0 最小值合法断言；风险二为 CLOEXEC 变体与 dup3 O_CLOEXEC 双路径旗标不一致——回退为分配后 F_GETFD 回读单源断言（两路径回读同一单位）。
- **正文**：实现路径分三步：第一步立最小 fd 分配格——预占 fd 0–5，F_DUPFD(arg=3) 分配 6（跳过占用位），F_DUPFD(arg=100) 在稀疏表分配 100，"最小可用 ≥arg"规则用三组预占布局各断言一次；第二步立 CLOEXEC 变体翻转——F_DUPFD_CLOEXEC 分配后 F_GETFD 回读 FD_CLOEXEC=1，普通 F_DUPFD 回读=0，成对断言；第三步立 dup 族对账——与 dup（最小可用）与 dup3（显式 newfd）在"分配结果与共享偏移"两点对账：复制后 lseek 移动共享偏移双 fd 可见，与 B08 母体行为逐格一致。与现存内核衔接点：fd 表扫描与 B08 分配器同函数；共享文件对象与 B02 open 语义档单源。与 Windows 对照：Windows 等价 DuplicateHandle（伪句柄与继承标志参数化），fd≥arg 最小分配是 POSIX 特有约定；本条按上游语义冻结。判据 UNX-F9102-J1 的复测方式：ktest 三断言——三组布局分配值断言、CLOEXEC 成对回读、dup 族共享偏移对账。

### UNX-F9103 · fcntl 记录锁挂点（F_GETLK/F_SETLK/F_SETLKW 三命令协议）
- 域/批：C2/B16｜判据：UNX-F9103-J1 三命令协议落账判据过，l_type/l_whence/l_start/l_len 四字段探针格过，实装归 B1 联签声明格过｜纯功能行数：340 行（三命令协议落账 130 + 四字段探针格 110 + B1 联签声明 100）｜状态：[已深化]

- **定位**：本条立 fcntl 记录锁三命令的挂点协议：F_GETLK 探测锁冲突、F_SETLK 非阻塞置锁、F_SETLKW 阻塞置锁——以 flock 结构四字段（l_type/l_whence/l_start/l_len）为参数面，本内核按挂点协议落账（协议与字段校验在本域，锁表实装归 B1 VFS 联签）。
- **语义边界**：只管三命令协议与字段探针；锁表数据结构与冲突仲裁实装归 B1（联签面）；flock(2) 独立锁体系归 F9112 差异账；EDEADLK 检测归 F9105 矩阵登记。
- **依赖与嫁接源**：嫁接 fcntl(2) man-pages 记录锁段（F_RDLCK/F_WRLCK/F_UNLCK 三型、SEEK_SET/CUR/END 三基准）；锚定 B1 VFS 冻结读路径（锁挂点路由落点）、F9105 错误矩阵、B12 四输入判定器（F_SETLKW 阻塞面）。
- **风险与回退**：风险一为挂点协议与实装边界模糊（本域越界写锁表）——回退为联签声明格硬规则：本域只做参数校验与协议路由，锁操作经挂点转发 B1，转发函数签名冻结；风险二为 l_len 负值/零值语义（零=到文件尾自动扩展）丢失——回退为四字段探针对 l_len=0（到 EOF）与负值（EINVAL）双格显式断言。
- **正文**：实现路径分三步：第一步立三命令协议落账——F_GETLK 冲突探测（无冲突返回 F_UNLCK 占用、有冲突返回冲突锁描述）、F_SETLK 非阻塞（冲突即 -EAGAIN）、F_SETLKW 阻塞（冲突挂起待解锁唤醒）三态判定规则以伪代码冻结，命令分发表落账；第二步立四字段探针格——l_type 非法值 -EINVAL、l_whence 三基准换算（l_start 相对基准折算绝对偏移）、l_start/l_len 区间合法性、l_len=0 自动扩展语义四格逐格断言；第三步立 B1 联签声明——挂点转发签名（fd, flock*）与返回码约定冻结，"实装归 B1"声明与 B1 冻结接口登记互认，联签编号落账。与现存内核衔接点：挂点路由经 B1 VFS 操作表；探针格与 F8921 参数拷贝单源。与 Windows 对照：Windows 对应 LockFileEx（区间锁+ OVERLAPPED 偏移），语义族等价但参数面不同；本条按 POSIX 冻结协议、实装对账归联签。判据 UNX-F9103-J1 的复测方式：ktest 三断言——三命令伪代码判定一致、四字段探针表全过、联签声明与转发签名冻结在案。

### UNX-F9104 · fcntl F_SETFL O_NONBLOCK/O_APPEND 位语义
- 域/批：C2/B16｜判据：UNX-F9104-J1 O_NONBLOCK 置位后非阻塞路径可观测判据过，O_APPEND 追加位生效判据过，F_GETFL 回读逐位一致｜纯功能行数：340 行（O_NONBLOCK 非阻塞路径 130 + O_APPEND 追加位 110 + F_GETFL 回读 100）｜状态：[已深化]

- **定位**：本条立文件状态旗标两位的运行期语义档：O_NONBLOCK 置位后读写在无数据/无空间时立即 -EAGAIN 而非挂起、O_APPEND 置位后每次 write 强制落到文件当前尾——多路复用（B09 epoll/B15 select 面）与 shell 追加重定向的语义底座。
- **语义边界**：只管两位运行期行为；F_SETFL 可置旗标集的掩码校验归 F9101 回环；管道容量与 EAGAIN 归 F8966 管道容量账对账；epoll ET 模式联动归 B09/B33 联测面。
- **依赖与嫁接源**：嫁接 fcntl(2) man-pages O_NONBLOCK/O_APPEND 描述与 open(2) 同名旗标语义（F_SETFL 与 open 旗标同源不同时点：open 时置 vs 运行期改）；锚定 B02 open 语义档、F8966 管道容量账、B12 EINTR/EAGAIN 判定器。
- **风险与回退**：风险一为 O_APPEND 原子性弱化（位置计算与写入非原子致并发覆盖）——回退为追加位写入路径"尾偏移取值与写入"单段原子声明落账（本域语义档声明，压力并发实测随闸门补测登记）；风险二为 O_NONBLOCK 对常规文件无效被误当 bug——回退为语义档显式注记"常规文件 O_NONBLOCK 无效果（Linux 上游行为）"，管道/终端/套接字才生效，注入矩阵按对象分类。
- **正文**：实现路径分三步：第一步立 O_NONBLOCK 非阻塞路径——管道读端无数据时置位前阻塞、置位后立即 -EAGAIN（时钟夹逼：耗时 <1ms），管道写端满时同构断言，双端可观测；第二步立 O_APPEND 追加位——三段写入（无 O_APPEND 独立偏移、置位后绕过偏移强制落尾、与显式 lseek 并存时 lseek 无效）逐段断言落点偏移，与 shell `>>` 语义等价；第三步立 F_GETFL 回读——两位分别置/清后回读逐位一致，与 O_RDONLY 等访问模式位并存不互扰。与现存内核衔接点：非阻塞路径与 B12 EINTR 判定器共用"可立即完成"判定；追加位与 B02 open 时旗标单源（同一 flags 位）。与 Windows 对照：Windows 无 O_APPEND 运行期翻转等价（FILE_APPEND_DATA 在 CreateFile 时定），无 O_NONBLOCK（WSA 非阻塞在套接字面）；本条按 POSIX 冻结。判据 UNX-F9104-J1 的复测方式：ktest 三断言——双端 EAGAIN 夹逼、三段追加落点断言、回读逐位一致。

### UNX-F9105 · fcntl 错误矩阵（EBADF/EINVAL/EINTR/EDEADLK/EMFILE）
- 域/批：C2/B16｜判据：UNX-F9105-J1 五错误码注入矩阵判据过，逐码与 Linux 语义一致，非法命令全 EINVAL 格过｜纯功能行数：320 行（五错误码注入矩阵 140 + 逐码语义一致 90 + 非法命令 EINVAL 90）｜状态：[已深化]

- **定位**：本条立 fcntl 命令面错误注入矩阵：EBADF（坏 fd）、EINVAL（非法命令/非法 arg）、EINTR（F_SETLKW 阻塞中被信号打断）、EDEADLK（F_SETLKW 自锁死锁检测）、EMFILE（F_DUPFD 超上限）五码逐格注入，是 E 型错误矩阵体例在 fcntl 命令面的落点（与 B21–B28 矩阵域判定一致）。
- **语义边界**：只管 fcntl 命令面五码；全命令面错误矩阵总装归 B13（B01–B15 轮）与 B21–B28 扩展域；EINTR 重启协议本体归 B12 母体格（本条对账）；EDEADLK 检测算法归 A5 死锁检测器联签面。
- **依赖与嫁接源**：嫁接 fcntl(2) man-pages ERRORS 段五码定义原文；锚定 B13 错误矩阵正反双判据总装体例、B12 EINTR 四输入判定器、F9102 EMFILE 上限格、A5 死锁检测器（EDEADLK 联签）。
- **风险与回退**：风险一为 EDEADLK 误报（跨进程正常等待误判死锁）——回退为 EDEADLK 只在"同任务已持同区间写锁再请求阻塞"自锁态触发（保守判定），跨进程等待归阻塞语义；风险二为 EINTR 与重启 SA_RESTART 交互遗漏——回退为 EINTR 格与 B12 判定器四输入对账（信号 SA_RESTART 置/清两态各一断言）。
- **正文**：实现路径分三步：第一步立五码注入矩阵——逐码构造：坏 fd（-1/9999/已闭）×四命令全 EBADF；非法命令号（未注册值）全 EINVAL；F_SETLKW 阻塞中投递信号 → EINTR 且 flock 参数不被破坏（重试可复用）；自锁场景（同任务重入 F_SETLKW 写锁）→ EDEADLK；fd 表满态（预占至上限）F_DUPFD → EMFILE，五格各带构造步骤与预期 errno；第二步立逐码一致核——与 man-pages ERRORS 段逐码比对表落账（码名/触发条件/优先级三列），与 B13 总装矩阵判定域逐格一致（零分歧声明）；第三步立非法命令格——命令号扫描未注册区间 100 值全 EINVAL（不误返回 ENOTTY——fcntl 与 ioctl 错误码差异点，单列注记）。与现存内核衔接点：EINTR 与 B12 单源；EDEADLK 与 A5 检测器联签。与 Windows 对照：Windows 错误码族 ERROR_NOT_LOCKED 等，映射表随深化落账（对账注记不重铺）。判据 UNX-F9105-J1 的复测方式：ktest 三断言——五码注入表全过、比对表三列齐、非法命令 100 值扫描。

### UNX-F9106 · ioctl 语义档总纲（第三参数装箱协议与方向位）
- 域/批：C2/B16｜判据：UNX-F9106-J1 IO/IOR/IOW/IOWR 四方向位解码判据过，参数装箱协议落账，未知命令路由格过｜纯功能行数：380 行（四方向位解码 140 + 参数装箱协议 130 + 未知命令路由 110）｜状态：[已深化]

- **定位**：本条是 ioctl 命令面（F9107–F9109/F9116 各专条）的总纲：ioctl 第三参数装箱协议（无参/整型/指针三态）与命令字方向位解码（_IO 无方向/_IOR 读内核/_IOW 写内核/_IOWR 双向）——ioctl 万象命令的路由地基。
- **语义边界**：只管总纲协议与方向位解码；终端族命令归 F9107、网络族预留归 F9108、ENOTTY 矩阵归 F9109、结构拷贝归 F9116；具体设备命令实装归各设备域（B4 块层等），本条只立路由面。
