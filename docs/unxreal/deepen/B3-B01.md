### UNX-F5601 · NTFS Boot 扇区 BPB 全字段解析
- 域/批：B3/B01｜判据：UNX-F5601-J1 三卷样本（NTFS 3.1）逐字段解析值与 Windows `fsutil fsinfo ntfsinfo` 同机输出一致率 100%，坏 OEM ID 卷 10/10 次拒载留账｜纯功能行数：360 行（BPB 字段解码表 120 + 校验和验证 80 + 双扇区长读取 60 + 对照账 100；测试段不计）｜状态：[已深化]
- **定位**：Boot 扇区是 NTFS 卷的第 0 句话，本条把 0 号扇区 512 字节里的 BPB（BIOS Parameter Block）扩展区全字段解码为结构化账——OEM ID（"NTFS    "）、每扇区字节数、每簇扇区数、保留扇区（NTFS 恒 0）、总扇区数、$MFT 起始簇、$MFTMirr 起始簇、MFT 记录大小描述、索引块大小描述、卷序列号、校验和，十一字段一次建齐，是 F5610 自定位链与全部后续条目的字节级地基。
- **语义边界**：只做 Boot 扇区字段解码与校验；不做 $MFT 记录解析（F5610）、不做簇位图语义（F5703）、不做 GPT/MBR 分区表（B4 域防重）。
- **依赖与嫁接源**：消费 B4 块读通道冻结接口（扇区读）；对现存 `fs/mod.rs` 的 `VolumeGuid` 是对照深化（卷序列号来源）；嫁接源为 NTFS 磁盘布局公开文档与 fsutil 行为对照，只跟随。
- **风险与回退**：OEM ID 非标准串（第三方格式化器）——不硬编码"NTFS    "单值白名单，按字段结构合法性（保留扇区=0、簇大小为 2 的幂）双判据放行，OEM ID 异常记降级账不阻塞。
- 正文：实现路径分三步。第一步字段解码表：按偏移 0x00–0x200 建立全字段解码器，OEM ID 8 字节、每扇区字节数（0x0B）、每簇扇区数（0x0D）、保留扇区 16 位（NTFS 必为 0，非零即红账）、总扇区 64 位（0x28）、$MFT/$MFTMirr 起始簇双 64 位（0x30/0x38）、MFT 记录大小与索引块大小的簇数描述字段（0x3C/0x40，负值表示字节数的 2 的幂取反，-10 即 1024 字节、正值表示簇数，双语义分支解码）、卷序列号（0x48）与校验和（0x50），每字段解码时保存原始字节快照供审计。第二步合法性三判据：扇区大小 ∈ {512,1024,2048,4096}、簇大小为扇区大小的 2 的幂且 ≤2MB、总扇区 × 扇区大小与 B4 上报容量偏差 ≤1 簇，三判据任一失败按坏卷分档进 F5609 注入矩阵处置。第三步对照账：解析结果组装为键值账，与同机 Windows `fsutil fsinfo ntfsinfo` 的对应字段逐项比对（Bytes Per Sector/Bytes Per Cluster/Total Sectors/Mft Start Lba/Mft2 Start Lba/FileRecord Segment/Serial Number），不一致即缺陷。与现存内核衔接点：`fs/mod.rs` 的 `VolumeGuid::from_serial` 消费本条卷序列号，块读经 `fs23_disk` 通道。判据 UNX-F5601-J1 复测方式：三卷样本逐字段比对一致率 100%，注入 OEM ID 篡改/簇大小非幂/保留扇区非零三类坏卷各 10/10 次被三判据拦截并分档留账。

### UNX-F5602 · 卷几何三元组与合法域校验
- 域/批：B3/B01｜判据：UNX-F5602-J1 簇/扇区/总簇三元组换算全卷合法簇号区间，越界簇号访问 10/10 次被拒并留账｜纯功能行数：300 行（三元组结构 70 + 越界判定器 90 + 换算函数族 80 + 账目 60；测试段不计）｜状态：[已深化]
- **定位**：卷几何三元组（扇区大小、簇大小、总簇数）是全部 VCN/LCN 算术的量纲系统，本条把 F5601 解码出的三元组固化为 `VolumeGeometry` 只读结构，提供簇号合法域 [0, total_clusters)、字节偏移换算、簇号↔字节偏移双向换算三函数族，任何后续读路径都必须经它换算——量纲错误（扇区与簇混用）在这一层被结构性拦截。
- **语义边界**：只做几何换算与越界判定；不做 runlist 级 VCN 映射（F5666）、不做块层扇区分发（B4 防重）。
- **依赖与嫁接源**：依赖 F5601 解码结果；对现存 `fs23_disk` 扇区读通道是消费声明；嫁接源为 NTFS 卷几何公开语义，只跟随。
- **风险与回退**：4K 原生盘（扇区 4096）与模拟盘（扇区 512）混装——三元组自带扇区大小字段，全部换算函数以结构字段为准，不使用全局常量，混装机 10/10 次正确分道。
- 正文：实现路径分三步。第一步结构固化：`VolumeGeometry { sector_size: u32, cluster_size: u32, total_clusters: u64 }`，由 F5601 解码账构造，构造时内联重验三判据（与 F5601 双保险），验证不过拒绝构造并返回分档错误。第二步换算函数族：`cluster_to_lba(c)` = c × cluster_size / sector_size（除法前断言 cluster_size ≥ sector_size，不满足即程序性缺陷）、`cluster_to_byte(c)` = c × cluster_size（64 位溢出检查，溢出即返回 None 并留账）、`byte_to_cluster(b)` 向下取整并附带簇内偏移，三函数全部纯函数、无全局态、ktest 逐个穷举边界值（0、total-1、total、u64::MAX/cluster_size 附近）。第三步越界判定器：`in_range(c)` 判定簇号合法域，越界访问统一返回 `Err(OutOfBounds)` 并向安全事件账（复用 `ntfsro.rs` 的 `SecEvent` 载体，事件类型扩展"几何越界"）追加一条，绝不静默截断或回绕。与现存内核衔接点：`fs23_disk` 通道保持扇区读原语不变，几何换算层新增于其上，`fs/mod.rs` 挂载表不变。判据 UNX-F5602-J1 复测方式：三卷样本换算值与 fsutil 几何字段一致，边界簇号（0/total-1）读取成功、total 与 total+1 越界 10/10 次被拒并留账，4K/512 两种扇区混装机换算分道零错。

### UNX-F5603 · NTFS 版本判定与能力门
- 域/批：B3/B01｜判据：UNX-F5603-J1 $Volume 主次版本读出 3.1，非 3.x 卷拒载留账，版本门判定 10/10 次正确｜纯功能行数：240 行（版本读出 80 + 能力门 80 + 降级账 80；测试段不计）｜状态：[已深化]
- **定位**：NTFS 3.0（Windows 2000）与 3.1（XP 起）在 $LogFile 客户区与目录索引细节有差异，本工程锚定 3.1（样本卷矩阵的唯一版本基线，Windows 10 21H2/Windows 11 22H2 双样本机 ADR-UNX-008 版本锚）。本条在装载早期读 $Volume 元文件的 $VOLUME_INFORMATION 主/次版本号，版本不符即走能力门：拒绝装载并留诊断账，不做"大概能读"的静默降级。
- **语义边界**：只做版本判定与门禁；不做 $VOLUME_INFORMATION 的脏位语义（F5604）、不做版本差异行为分档表（B16+ 版本锚条目）。
- **依赖与嫁接源**：依赖 F5610 自定位链对 $Volume 的定位（依赖声明：本条在 B01 批内与 F5610 同批联测，F5610 提供元文件定位）；嫁接源为 NTFS 版本演进公开语义，只跟随。
- **风险与回退**：$Volume 自身损坏读不出版本——按"版本未知"档拒载（宁可拒载不可错读），诊断账列出损坏位置与建议（Windows 侧 chkdsk 修复后重试）。
- 正文：实现路径分三步。第一步版本读出：经 F5610 元文件遍历器定位 $Volume（序号 3），解析其 $VOLUME_INFORMATION 属性的 Major/Minor 版本字节与 flags 字段，版本号与 flags 原始值落装载账。第二步能力门：主版本 ≥3 且次版本 =1 判"完全支持"，主版本 <3 或次版本异常判"不支持"，版本未知（$Volume 损坏）判"版本未知"档——三档中仅第一档放行后续装载步骤，后两档拒载并在诊断账列出"版本证据字节 + 建议"。第三步降级账与对照：拒载时输出人话三要素（发生了什么/为什么/下一步），"版本未知"档给出"在 Windows 上运行 chkdsk X: 后重试"的操作指引；支持档把版本号写入 F5615 装载摘要账供全程审计。与现存内核衔接点：`ntfsro.rs` 挂载路径收编为能力门的消费者——能力门不过则 `NtfsMount` 不建立，`MOUNT_POINT` 语义不变。判据 UNX-F5603-J1 复测方式：三卷 3.1 样本 10/10 次判"完全支持"并放行，注入 3.0 版本字节样本 10/10 次拒载留账，$Volume 损坏样本 10/10 次进"版本未知"档给出 chkdsk 指引。

### UNX-F5604 · 卷脏位解析与装载策略
- 域/批：B3/B01｜判据：UNX-F5604-J1 脏位样本卷装载进"脏卷只读档"，干净卷全档放行，判定 10/10 次正确｜纯功能行数：260 行（脏位读出 80 + 装载策略状态机 100 + 联动账 80；测试段不计）｜状态：[已深化]
- **定位**：$Volume 的 flags bit 15 是卷脏标志（dirty bit）——Windows 非正常卸载时置位、干净卸载清零。本条读脏位并执行装载策略：脏位=1 时强制进"脏卷只读档"（拒绝任何写意图，读路径加"可能不一致"标记），脏位=0 时按 F5605 只读最小闭环正常装载。脏位是与 Windows 语义对齐的第一道数据安全阀：Windows 也在脏位卷上自动调度 chkdsk，本内核以只读档对齐"不冒险"原则。
- **语义边界**：只做脏位读出与装载档位决策；不做脏位置位/清零（写侧，B12 红线复核后）、不做 chkdsk 类检查（F5885 起）。
- **依赖与嫁接源**：依赖 F5603 版本门与 $Volume 定位；对 `ntfsro.rs` 只读强制是策略级承接（脏卷档比常规只读档更严——读路径附加不一致标记）；嫁接源为 Windows dirty bit 公开语义与 autochk 行为，只跟随。
- **风险与回退**：flags 字段其它保留位非零（OEM 私有标志）——只解析 bit 15，保留位原值入账不解读，避免把 OEM 标志误判为脏。
- 正文：实现路径分三步。第一步脏位读出：解析 $VOLUME_INFORMATION 的 16 位 flags，bit 0x8000（dirty）单独提取，其余位原值快照入账并标注"保留位未解读"，提取动作本身落装载账。第二步装载策略状态机：脏位=0 → 正常只读档；脏位=1 → 脏卷只读档（`NtfsMount` 增加 dirty 标记，读路径每次返回前校验标记并给返回数据附"可能不一致"档位注记）；状态迁移只允许单向（脏→干净需 Windows 侧确认修复，本内核不清零）。第三步联动账：脏卷档建立时诊断账输出三要素（检测到脏卷/上一次非正常卸载可能造成元数据不一致/已进入只读保护，如需修复请在 Windows 上运行 chkdsk），联动事件写体验日志（对接现存 `logger.rs` 分级账）。与现存内核衔接点：`ntfsro.rs` 的 `NtfsMount` 结构扩展 `dirty` 字段，`allow_read` 语义不变，`deny_write` 对脏卷档无差别拒绝（本来就拒绝）。判据 UNX-F5604-J1 复测方式：Windows 侧强拔样本盘制造脏位 10/10 次被检测并进脏卷档、干净卷 10/10 次正常档，两档读行为差异（档位注记）在账本可查。

### UNX-F5605 · 只读装载最小闭环（ntfsro 承接深化）
- 域/批：B3/B01｜判据：UNX-F5605-J1 样本卷挂 /windows 后枚举根目录成功，写句柄拒绝率 100% 回归通过｜纯功能行数：380 行（装载编排器 140 + 根目录首读 100 + 挂载表登记 70 + 闭环自检 70；测试段不计）｜状态：[已深化]
- **定位**：本条是 B3 域第一条端到端闭环：F5601–F5604 的全部构件（BPB、几何、版本门、脏位）组装成一次完整装载——读 Boot 扇区 → 建几何 → 过版本门 → 查脏位 → 定位 $MFT（F5610）→ 首读根目录 → 挂载表登记 → 闭环自检。现存 `ntfsro.rs` 的"挂载即只读定型"（API 面上不存在写模式）是本条的结构性宪法：装载器从第一行起就没有写路径可选。
- **语义边界**：只做装载编排与根目录首读闭环；不做目录枚举语义（F5726）、不做文件读内容路径（F5673）、不做写路径（B12）。
- **依赖与嫁接源**：依赖 F5601–F5604 与 F5610；对现存 `ntfsro.rs` 的 `NtfsMount`/`deny_write`/`run_ntfsro_checks` 是承接深化（挂载结构升级为真装载产物，判据函数保留回归）；嫁接源为 Windows 挂载时序（mountmgr → fs → volmgr）公开语义，只跟随。
- **风险与回退**：装配链某一步失败——编排器按步骤号失败定位（第 N 步失败 + 原因 + 已完成步骤快照），失败卷不登记进挂载表，绝不留半挂载态。
- 正文：实现路径分三步。第一步装载编排器：`mount_volume(disk, slot) -> Result<NtfsMount, MountError>` 按固定序调用八步（Boot/几何/版本/脏位/自定位/根目录首读/挂载登记/自检），每步进入退出打点（耗时与结果），任何一步失败返回 `MountError{step, cause}`，错误文案三要素齐全。第二步根目录首读：经 F5610 遍历器取根目录 MFT 记录（记录号 5），确认 $INDEX_ROOT 或 $INDEX_ALLOCATION 存在即认为卷结构自洽可继续（目录内容解析归 F5726），首读结果（索引类型、记录校验态）落账。第三步挂载登记与自检：`NtfsMount` 以装载产物（几何/版本/脏位/自定位结果）填充实例，登记进 `fs/mod.rs` 挂载表（slot 复用 `MountTable`），随后跑闭环自检——复用 `run_ntfsro_checks` 全量回归 + 新增装载八步结果账核对，自检绿才挂出 `/windows`。与现存内核衔接点：`ntfsro.rs` 的挂载面从"建模挂载"升级为"真装载挂载"，`WriteOp::ALL` 穷举表与拒绝率判据原样保留。判据 UNX-F5605-J1 复测方式：三卷样本各装载 10/10 次成功并挂出、根目录首读账齐、对挂出卷穷举 11 类 WriteOp 各 100 次拒绝率 100% 且事件账条目齐。

### UNX-F5606 · 挂载点 /windows 语义与 MountTable 对接
- 域/批：B3/B01｜判据：UNX-F5606-J1 多卷并发挂载槽位分配唯一，卸载后槽位可复用，路径解析 10/10 次正确｜纯功能行数：300 行（挂载点登记 90 + 槽位生命周期 100 + 路径前缀解析 70 + 冲突账 40；测试段不计）｜状态：[已深化]
- **定位**：MD2 篇 7.4 宪法钉死 NTFS 挂载点为 `/windows`（VARIX 侧命名）。本条把挂载点语义工程化：单 NTFS 卷挂 `/windows`、多 NTFS 卷时第二卷起挂 `/windows2`、`/windows3`（序号递增），槽位经 `MountTable` 分配与回收，路径前缀解析把 `/windows/...` 请求路由到对应卷。归属与隔离原则的文件系统版：NTFS 世界完整地活在 `/windows` 子树里，不越界。
- **语义边界**：只做挂载点命名与路由；不做 Windows 盘符（C:/D:）语义映射（D3 域防重）、不做 B1 全局 mount 命名空间（B1 冻结接口消费）。
