### UNX-F0881 · 中断亲和性策略引擎（策略表驱动）

- **语义边界**：只做策略裁决；不做迁移执行（F0882）、不做均衡算法（F0885 消费策略引擎输出）；默认策略 = 核池内均衡（策略表首项显式，无隐式默认）。

### UNX-F0882 · RTE 目的地重编程与 mask-move-unmask 迁移序列
- 域/批：A2/B05｜判据：UNX-F0882-J1 迁移序列正确率 100%（注入乱序 10/10 次拦截），迁移后投递落新核断言 10/10 次，序列时长实测 <50µs｜纯功能行数：340 行（迁移序列 140 + 拦截 110 + 验证 90；测试段不计）｜状态：[已深化]
- **定位**：亲和性从策略到硬件的执行面——RTE 目的地字段重编程三步序（掩引脚→改目的地→解掩），跳步或乱序的典型事故是"半配置 RTE 投递"（目的地已改掩未挂，中断飞向旧核的窗口）；本条做迁移序列固化（三步序+每步硬件读回确认，复用 F0866 状态机 Masking 态）与乱序拦截（状态机非法迁移硬拦）。
- **语义边界**：只做 IRQ 类迁移；MSI-X 类走 F0884（表项重写不同时序）；不做均衡决策（F0885）；序列是同步操作（调用方阻塞至完成，异步化是后续域权限）。
- **依赖与嫁接源**：依赖 F0866 状态机与 F0881 策略；嫁接源为 Linux irq_set_affinity（masked-move-unmask 惯例）与 Windows 中断重定向时序语义，只跟随。
- **风险与回退**：迁移期间中断丢失（掩窗内设备触发）——水平触发设备解掩后自动重投递（电平语义自带补偿），边沿触发设备掩窗事件入 F0883 在途账核对，丢事件断言覆盖两类触发模式。
- 正文：实现路径分三步。第一步序列：`irq_migrate(gsi, new_dest)` ——状态机入 Masking（掩位写+读回确认）→目的地字段写（编码器重组）→实况读回比对→解掩（目标态裁决），五步账逐步落，单序列时长 TSC 采样；第二步拦截与核对：乱序注入（跳掩直接改目的地）10/10 次状态机拦截，迁移后投递落新核断言（测试向量从新核 handler 记账验证）10/10 次；第三步验证：序列时长 <50µs 断言（QEMU 档）、电平设备掩窗事件解掩后重投递 10/10 次、边沿设备掩窗事件账平（F0883 消费）10/10 次、迁移 1000 次状态机账零异常。与现存内核衔接点：`apic.rs` 迁移路径收编。与 Windows 对照：Windows 中断重定向同三步序（HAL 内部），本内核乱序拦截与账本显式化，判据 UNX-F0882-J1 的复测方式：序列 100%、拦截 10/10 次、落新核 10/10 次、<50µs。

### UNX-F0883 · 迁移在途事件不丢账（迁移窗口语义）

- **定位**：F0882 迁移序列的掩窗是丢失风险窗——本条把窗口语义做成账：迁移开始记录窗口开启（gsi/旧核/新核/时刻），窗内到达事件（IRR 镜像观测）逐笔入在途账，窗口关闭（解掩完成）时对账（在途事件=窗内投递数+解掩后补投递数），边沿设备账平断言（F0882 第三步消费），水平设备自动重投递计数独立分账，账平即"迁移零丢失"断言成立。
- **语义边界**：只做窗口账与对账；不做补偿重投递（补偿动作是 F0841 延迟 EOI 机制同型，本条只记账）；账的观测源是 IRR 镜像（F0826）与投递计数（F0842 三计数）交叉。
