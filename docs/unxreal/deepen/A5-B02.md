### UNX-F3221 · qspinlock 队列节点结构与 MCS 排队语义
- 域/批：A5/B02｜判据：UNX-F3221-J1 队列节点成链/断链配对 10^6 次零悬挂引用，FIFO 交接序与到达序一致率 100%｜纯功能行数：420 行（McsNode 结构（next/locked 状态）100 + 入队 CAS 协议（尾指针交换）110 + 出队交接（前驱释放后继）100 + 悬挂引用检测账 60 + 节点复用池接口 50；测试段不计）｜状态：[已深化]
- **定位**：MCS 队列是 qspinlock 的心脏——每个争用者在自己的缓存行上自旋（等前驱的 locked 标志），获锁权像接力棒沿队列传递，彻底消除 ticket 锁全员盯同一字的缓存行弹跳。本条交付节点结构、入队 CAS 协议、出队交接三件核心与悬挂引用检测账，是 F3222 位域编码字的直接供体。
- **语义边界**：只做 MCS 队列语义；不做位域压缩编码（F3222）、不做后端选择（F3224）。节点内存来自预分配池（栈上节点禁入——栈帧退出即悬挂）。
- **判据**：UNX-F3221-J1（见首行）。扩展判据：UNX-F3221-J2 节点复用池耗尽注入 10/10 回退（联动 F3236）。
- **依赖与嫁接源**：依赖 F3201/F3202、F3205（节点 64B 对齐）；无上游嫁接。
- **风险与回退**：出队交接竞态（前驱 unlock 与后继入队同时发生）——交接协议三步（前驱置后继 locked/后继自旋观察到/前驱清队列尾指针），竞态窗口用版本序号账检测；悬挂引用（持节点者先退）由节点池生命周期约束+悬挂检测账兜底。
- 正文：实现路径分三步。第一步节点结构：`McsNode { next: AtomicPtr<McsNode>, locked: AtomicBool }`，64 字节对齐独占缓存行，从预留池取用（池归 F3236 边界）。第二步入队协议：尾指针 fetch_swap 原子交换——旧尾是我的前驱，交换结果决定我是队首还是队尾；非队首则把前驱的 next 指向我（前驱交接点）。第三步交接与检测：自旋等前驱 locked 置位获锁；解锁时把锁权交给自己 next（若有），无 next 则 CAS 清尾指针（此窗口即 finally 竞态，版本账检测悬挂）。悬挂检测账：节点归还池前校验无人引用（next 置空+账本核对）。与现存内核衔接：现存无排队锁体例（F043 是 ticket），本条为新增语义，桥经 F3231 开关并轨。与 Windows 对照：Windows 内核排队转锁（queued spin lock）正是 MCS 思想的产品化——本条对照其 FIFO 语义与"在自身缓存行等待"的性能要点。判据 UNX-F3221-J1 的复测方式：ktest 锁面 8 核 10^6 次并发入队出队（QEMU 批跑）零悬挂、FIFO 一致率 100%；J2 注入同面。

### UNX-F3222 · qspinlock 编码字压缩状态机（locked/pending/queue 位域）
- 域/批：A5/B02｜判据：UNX-F3222-J1 四态位域迁移（00 unlocked/01 pending/10 locked/11 queue）全路径覆盖断言 64 迁移边 64/64 走到｜纯功能行数：400 行（u32 编码字位域定义（locked/pending/idx/queue 段）100 + CAS 状态迁移表（16 迁移边）110 + 迁移覆盖断言账 90 + 尾指针折叠编码（CPU 号入字）60 + 状态解码辅助 40；测试段不计）｜状态：[已深化]
- **定位**：qspinlock 的精髓是把"锁字+队列尾指针"压缩进一个 32 位字——locked/pending 位、队列尾 CPU 号与位索引折叠编码，一次 CAS 完成状态迁移，缓存行流量最小化。本条交付编码字定义、迁移表与覆盖断言账。
- **语义边界**：只做编码字与迁移表；不做队列节点本体（F3221）。CPU 号位宽按最大核数（8 位/256 核）参数化。
- **判据**：UNX-F3222-J1（见首行）。扩展判据：UNX-F3222-J2 编码字溢出（核号超位宽）编译期拒绝断言。
- **依赖与嫁接源**：依赖 F3221/F3201；无上游嫁接。
- **风险与回退**：折叠编码与真实队列不一致（编码说有队/实际无人）——一致性断言账：编码字 queue 段非零必须能在节点池找到对应活跃节点，违例即调试账；位域布局改动是 ADR 事项（冻结表 F3239 管）。
- 正文：实现路径分三步。第一步位域：编码字 [pending:1][locked:1][idx:2][cpu:28]（或按核数裁剪），const 断言位宽合法。第二步迁移表：unlocked→locked（快路径 CAS）、unlocked→pending→locked（单等待者优化）、unlocked→queue（挂 MCS 队列）、queue→locked（交接）等 16 条边全列，每边一个 CAS 操作序列定义。第三步覆盖断言账：ktest 注入各边触发场景（单核/双核/高争用编排），64 条组合路径（含非法边拒绝）走账。与现存内核衔接：新语义，经 F3231 并轨。与 Windows 对照：Windows 排队转锁同样是单字编码（锁字内嵌等待位与队列信息），本条对照其"单字完成全部协调"的设计要点。判据 UNX-F3222-J1 的复测方式：ktest 锁面迁移覆盖 64/64（QEMU 批跑）+ J2 编译断言。

### UNX-F3223 · qspinlock 快路径与慢路径升级序
- 域/批：A5/B02｜判据：UNX-F3223-J1 无争用快路径单 CAS 命中率 ≥99%（10^6 次账），升级序（fast→pending→queue）注入验证 20/20｜纯功能行数：360 行（快路径单 CAS 获取 80 + pending 缓冲态（单等待者免入队）110 + 慢路径升级判定序 90 + 命中率账 40 + 升级路径注入器 40；测试段不计）｜状态：[已深化]
- **定位**：好锁要让无争用路径近乎免费——qspinlock 快路径一次 CAS 完成（对比 ticket 锁两次原子操作），单等待者走 pending 位不建队列，争用升级才挂 MCS 队列。本条交付三级升级序与命中率账，是"性能轴"在锁上的第一兑现点。
- **语义边界**：只做升级序；不做队列本体（F3221/F3222）；命中率口径：成功走单 CAS 边的获取占比。
- **判据**：UNX-F3223-J1（见首行）。扩展判据：UNX-F3223-J2 pending 态超时降级（等待者卡 pending 过久转 queue）10/10 触发。
- **依赖与嫁接源**：依赖 F3221/F3222/F3206（退避）；无上游嫁接。
- **风险与回退**：pending 态饿死第三者（两个等待者间新到者无法判断）——pending 位语义冻结为"至多一个缓冲"，第三者直接入队；升级序倒置（已入队又回 pending）编译期不可表达（状态机约束）。
- 正文：实现路径分三步。第一步快路径：CAS 0→locked 单指令获取，失败读出竞争态。第二步 pending 缓冲：第二者 CAS 0→pending 后自旋等 locked 清零再抢；第三者发现 pending 占用直接入队（queue 态）。第三步升级序账：fast→pending→queue 三级判定的注入器（人为制造 1/2/3+ 等待者），每级命中率与迁移次数落账。与现存内核衔接：经 F3231 并轨。与 Windows 对照：Windows 排队转锁同样含"单等待者快道"（单 CPU 争用不建队列）——本条对照其分级思想并以命中率账量化。判据 UNX-F3223-J1 的复测方式：ktest 锁面 10^6 次命中率 ≥99%（QEMU 批跑）+ 升级注入 20/20；J2 同面。

### UNX-F3224 · 按核数自适应裁断后端
- 域/批：A5/B02｜判据：UNX-F3224-J1 核数阈值（≤2 ticket/≥3 qspinlock）裁断落账，两后端切换点行为等价断言过｜纯功能行数：280 行（CPUID 核数读取（承接 A1 采集）50 + 阈值裁断器（编译期模板+运行期确认）90 + 裁断账（每锁后端归属）60 + 切换点等价断言 80；测试段不计）｜状态：[已深化]
- **定位**：单核/双核机上 qspinlock 的队列维护是纯开销——ticket 足矣；三核起排队优势显现。本条按"编译期最大核数模板+运行期实际核数确认"两段裁断，每锁后端归属入账，阈值 3 可按机型调优（调优走 ADR）。
- **语义边界**：只做后端裁断；不做运行期热切换（那是 F3231 的 Draining→Arming 协议）；裁断是启动期一次决定。
- **判据**：UNX-F3224-J1（见首行）。扩展判据：UNX-F3224-J2 阈值边界机（2 核/3 核 QEMU 机型）各 10^5 次行为等价对照。
- **依赖与嫁接源**：依赖 F3203/F3221 两实现、A1 CPUID 账（核数真值承接）；无上游嫁接。
- **风险与回退**：CPUID 账缺失（引导面降级）——回退保守默认（qspinlock，多核时代主形态）；裁断与 F3231 手工开关冲突时手工优先（开关覆盖裁断，覆盖事件入账）。
- 正文：实现路径分三步。第一步核数真值：从 A1 CPUID/SMP 采集账读实际核数（承接非重复——只消费不采集）。第二步裁断器：锁类型经泛型后端参数编译期定形，启动期按实际核数给运行期确认位；阈值常量 3 入冻结表。第三步裁断账：每锁记录选定后端与理由（核数/手工覆盖），切换点（阈值边界机型）等价断言——两后端在同场景吞吐差 <5% 且 FIFO 一致率均 100%。与现存内核衔接：现存 ticket（F043 体例）在单/双核机继续服役即本条裁断结果。与 Windows 对照：Windows 排队转锁按核数启用（单核机退化为普通转锁）——本条对照其分核启用策略并账本化。判据 UNX-F3224-J1 的复测方式：ktest SMP 面 2/3/8 核三机型（QEMU 批跑）裁断账核对+等价断言；J2 同面。

### UNX-F3225 · 排队等待者唤醒与尾节点交接协议
- 域/批：A5/B02｜判据：UNX-F3225-J1 交接协议（尾节点 next 交接/finally 竞态窗口）注入 10^5 次零丢失唤醒｜纯功能行数：340 行（finally 竞态窗口协议（无后继交接）120 + 有后继交接（前驱→后继 locked 置位）100 + 丢失唤醒检测账 70 + 交接时序账 50；测试段不计）｜状态：[已深化]
- **定位**：qspinlock 最微妙的窗口是"解锁者看见空队、新到者正要入队"——finally 竞态。本条把交接协议（有后继：置后继 locked；无后继：CAS 清尾）与丢失唤醒检测账写成独立条目，10^5 次竞态注入零丢失是本域"零静默"纪律的锁面表达。
- **语义边界**：只做交接协议；不做队列结构（F3221）；检测账只针对交接窗口，不重复 F3232 重入检测。
- **判据**：UNX-F3225-J1（见首行）。扩展判据：UNX-F3225-J2 交接延迟账：交接成功到后继开跑的 TSC 差分布落账（P99 可读）。
- **依赖与嫁接源**：依赖 F3221/F3222/F3201；无上游嫁接。
- **风险与回退**：检测账自身时序误差掩盖丢失——丢失判定以"有界等待超时"为锚（等待者超时未获锁且队列账显示有前驱），不依赖亚纳秒时序；协议 bug 修复前回退 ticket 后端（F3231 开关）。
- 正文：实现路径分三步。第一步有后继交接：解锁者读自己节点 next，非空则置后继 locked=1（Release 序），后继自旋观察到即获锁——全程无锁字写，缓存行流量最小。第二步无后继交接：CAS 队列尾指针从自己换成空闲编码；若 CAS 失败（恰好新到者入队）转入有后继路径——两次读取间的窗口就是 finally 竞态，协议保证任一结局可达。第三步丢失唤醒账：等待者侧记录入队时刻与获锁时刻，超时锚（100ms）触发即记丢失事件并 panic（异常显性化）；注入器在解锁-入队间插入随机延迟 10^5 次。与现存内核衔接：新语义经 F3231 并轨。与 Windows 对照：Windows 排队转锁的交接窗口由 HAL 汇编实现，竞态正确性靠形式化设计；本条同构协议+运行期丢失检测账双保险。判据 UNX-F3225-J1 的复测方式：ktest 锁面竞态注入 10^5 次（QEMU 批跑）零丢失；J2 延迟分布同面。

### UNX-F3226 · 缓存行弹跳测量账（争用下降账本）
- 域/批：A5/B02｜判据：UNX-F3226-J1 8 核高争用下 qspinlock 对 ticket 吞吐提升 ≥20%（对照账落盘）｜纯功能行数：340 行（弹跳计数（跨核缓存行失效事件估算）100 + 吞吐对照场景器（ticket vs qspinlock 同负载）120 + 对照账落盘格式 60 + 弹跳-吞吐相关分析 60；测试段不计）｜状态：[已深化]
- **定位**：任务书判据"queued lock 缓存行争用下降账"的执行条目——量化证明排队锁的引入动机：同负载下 ticket 锁的锁字缓存行在核间弹跳，qspinlock 弹跳集中在各自节点。本条交付弹跳估算账与吞吐对照账，≥20% 提升是硬判据。
- **语义边界**：只做测量与对照；不做弹跳根因剖析（perf 面 O 域协作）；弹跳估算用"锁字写次数×核数权重"模型（无硬件 PMI 依赖，QEMU 可跑）。
- **判据**：UNX-F3226-J1（见首行）。扩展判据：UNX-F3226-J2 低争用场景对照：吞吐差 <5%（排队锁无开销惩罚的证据面）。
- **依赖与嫁接源**：依赖 F3203/F3221/F3235（场景编排）；无上游嫁接。
- **风险与回退**：估算模型失真（负载形态偏置）——三负载形态（短临界区/长临界区/混合）各跑对照，报告三组数据不选优呈现；≥20% 判据只对高争用短临界区场景声明（口径写进判据句成立范围）。
- 正文：实现路径分三步。第一步弹跳模型：锁字被不同核写的次数序列落账（F3211 事件账扩展），跨核写交替次数即弹跳估算值。第二步对照场景器：同参数（核数/迭代/临界区长）两后端各跑一遍，吞吐（完成次数/秒）与弹跳双指标对照。第三步分析：弹跳下降率与吞吐提升率相关表落盘，三负载形态分别成账。与现存内核衔接：对照基线是 F3203 ticket（升级对象），数据同时供 O1 对标账。与 Windows 对照：Windows 排队转锁引入的动机即缓存行争用（KB 文档与 WDK 性能指南明示）；本条以自家账本复现该动机的证据链。判据 UNX-F3226-J1 的复测方式：ktest SMP 面 8 核高争用三形态对照（QEMU 批跑），吞吐提升 ≥20% 落账；J2 低争用无惩罚同面。
