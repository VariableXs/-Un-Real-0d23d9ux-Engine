- 域/批：A1/B11｜判据：UNX-F0205-J1 命令触发全报告串口导出，传输 1MB 零丢包（CRC 校验）｜纯功能行数：220 行（导出协议 90 + 分帧传输 70 + 校验对账 60；测试段不计）｜状态：[已深化]

- **语义边界**：协议 = 头帧（报告元数据）+ 数据帧（4KB 分块）+ 尾帧（总 CRC）三段式；对端确认可选（无确认 = 尽力而为 + 计数，有确认 = 逐帧 ACK 重传）；协议版本 v1。
- **依赖与嫁接源**：F0102 串口驱动、F0204 槽带读取；嫁接 SLIP/kermit 的分帧思想与 Intel XMODEM-CRC 校验口径。

- 正文：实现路径分三步。第一协议帧：头帧（magic/version/报告序号/总长/总 CRC）→ 数据帧（seq/len/payload/frame_crc）→ 尾帧（END + 导出统计）；帧间 10ms 呼吸间隔（对端缓冲友好）。第二传输器：F0102 全速写，帧 CRC 生成；中止监听（ESC 字节）与超时（对端 ACK 等待 500ms ×3 重传）；导出统计（帧数/重传数/耗时）入账。第三校验对账：ktest 环回断言 1MB 随机数据导出零丢包（总 CRC 过）、注入帧损坏重传恢复、中止半包作废、统计账齐。与现存内核衔接点：诊断 UI `report export` 命令入口；F0203 真机补测时的数据搬运通道。与 Windows 对照：Windows 无引导期串口导出协议（windbg 是调试非报告）；kermit/xmodem 是传统口径。判据 UNX-F0205-J1 的复测方式：ktest 环回 1MB 零丢包、损坏注入重传恢复、中止作废、统计账齐、协议版本断言。
