### UNX-F0801 · IDT 全量初始化与向量空间五区规划
- 域/批：A2/B01｜判据：UNX-F0801-J1 真机 256 项 IDT 全量填充且 lidt 生效，异常/IRQ/MSI/IPI/spurious 五区规划断言 ≥20 条全绿，五区边界值逐区可打印｜纯功能行数：320 行（五区规划表 90 + 全量填充器 110 + 边界断言族 70 + 导出打印 50；测试段不计）｜状态：[已深化]
- **定位**：向量空间是中断子系统的土地规划图，本条把现存 `idt.rs::init()` 的"填表可用"升级为"五区规划固化"——异常区 0x00–0x1F、设备本地池、全局 MSI-X 池、IPI 区、spurious 0xFF 槽位五区边界常量化、注册表化、可审计化，后续 B02–B10 全部条目在五区框架内领地向，防"向量乱占"这类随批数增长必然出现的失序。
- **语义边界**：只做 IDT 表体填充与向量空间规划账；不做具体异常的处置语义（F0802 起逐条）、不做向量分配算法（F0901 分配器主场）；与 F0022 分层：F0022 立全量重排与 IST 纲领，本条立五区规划与规划账。
- **依赖与嫁接源**：消费现存 `cpu/idt.rs` 的 `Idt`/`IdtEntry`/`init()`；上游消费 F0004 MADT 账（核数定 IPI 区宽度）；嫁接源为 Intel SDM Vol.3 §6.3（中断向量表组织）与 Linux 向量空间布局惯例（x86 vector layout），只跟随。
- **风险与回退**：规划区与现存硬编码向量冲突（现存代码用固定向量做 tick）——冲突项按"现存优先、规划表登记豁免"处理，豁免账随批次推进逐条收编，收编完成前规划表带豁免标记，不静默覆盖。
- 正文：实现路径分三步。第一步五区规划表：以 const 静态表定义五区（异常 0x00–0x1F / 设备本地池 0x20–0x8F / 全局 MSI-X 池 0x90–0xDF / IPI 区 0xE0–0xFE / spurious 0xFF），每区登记（起界/终界/用途/领主域/容量）五元组，区表作为全域唯一向量化分事实源导出常量接口；第二步全量填充器：现存 `init()` 逐项写 256 条目的基础上，按区表批量填充默认 handler（未注册向量进"未知向量记账 handler"，入账不 panic），IDT 基址经 lidt 装载后回读验证（limit 与基址双回读）；第三步边界断言族：五区边界值逐区断言（区不重叠、不留洞、spurious 单槽），≥20 条断言全部注册进 ktest 中断面（F0040 聚合面），规划账随引导报告可打印。与现存内核衔接点：`idt.rs::init()` 内插入规划表校验步骤，`IdtEntry` 结构零改动；与 F0022 衔接：IST 栈槽位在本条表内预留三席（F0806 消费）。与 Windows 对照：Windows 的 IDT 可经 WinDbg `!idt` 全表导出，逐向量显示 handler 与所属驱动，本内核规划账以同等颗粒度导出五区占用，判据 UNX-F0801-J1 的复测方式：真机引导后 IDT 全量 256 项非零、五区边界断言 ≥20 条全绿一次命令完成、`!idt` 同机对照未注册向量行为一致（皆入账不崩）。

### UNX-F0802 · 异常区向量 0x00–0x1F 全挂接与分型分发
- 域/批：A2/B01｜判据：UNX-F0802-J1 三类异常（Fault/Trap/Abort）32 项逐项分型落账，注入 10 种异常全部走正确分型路径且现场完整｜纯功能行数：300 行（分型表 80 + 分发器 120 + 注入记账 100；测试段不计）｜状态：[已深化]
- **定位**：异常区 32 项不是 32 个同质入口——Fault（#PF/#GP 可恢复重启指令）、Trap（#DB/#BP 穿透返回）、Abort（#MC/#DF 不可续）三类语义分型决定后续路径走向（返回/移交/panic），本条把分型做成静态分型表，异常入口按表分发，杜绝"所有异常一律 panic"的粗暴口径。
- **语义边界**：只做异常分型与分发路由；不做各异常的具体处置（#PF 移交 F0813、#GP 三联判 F0814、DF 现场保全 F0811、MC 采集 F0812）；与 F0022 分层：F0022 立挂接完备性，本条立分型语义。
- **依赖与嫁接源**：消费现存 `idt.rs::exception_name`/`explain` 的人话化底座；嫁接源为 Intel SDM Vol.3 表 6-1（异常分类）与 §6.15（异常引用），只跟随。
- **风险与回退**：分型表与 CPU 实际行为偏差（保留异常触发）——保留号（1F 之前未定义号）按 Abort 原型处置并登记"保留号触发"红账，触发即进诊断模式，不猜语义。
- 正文：实现路径分三步。第一步分型表：32 项异常逐项登记（向量号/助记/类属 Fault-Trap-Abort/错误码有无/处置域归属）五元组，const 静态表与 SDM 表 6-1 逐行对齐；第二步分型分发器：异常公共入口查表路由——Fault 走"处置域回调，成功则重启指令 iret 返回"，Trap 走"回调后直接返回（下一条指令）"，Abort 走"现场快照 + panic（带表内助记与类属）"；分发器对"表声明无错误码但硬件压码"的不一致做运行期检测（栈帧特征校验），不一致即红账；第三步注入记账：十种代表性异常（除零/调试/断点/溢出/越界/非法指令/协处理器错/对齐/保护/缺页）经 ktest 注入触发，逐项断言分型正确、现场完整、类属路由正确，结果落异常分型账。与现存内核衔接点：`idt.rs` 的 `read_trap_frame`/`dump_frame` 零改动消费，分发器挂接现存 stub 公共入口之后。与 Windows 对照：Windows 蓝屏 stop code 与异常号同源（如 0x1E KMODE_EXCEPTION_NOT_HANDLED 对应未处置异常），本内核 panic 文案携带表内助记与类属，判据 UNX-F0802-J1 的复测方式：ktest 注入 10/10 次分型正确、Abort 类现场快照含全部寄存器、Fault 类成功处置路径 10/10 次重启指令无状态残留。

### UNX-F0803 · 设备 IRQ 向量区 0x20–0x8F 池化与首配分配
- 域/批：A2/B01｜判据：UNX-F0803-J1 设备池向量申请-归还状态机一致（万次操作零悬空），越界申请被拒并留账｜纯功能行数：300 行（池描述块 90 + 首配分配器 110 + 状态账 100；测试段不计）｜状态：[已深化]
- **定位**：设备本地池是 IO-APIC/MSI（非 X 档）路由的向量来源，本条把 0x20–0x8F 建为带状态机的向量池（Free/Used/Reserved 三态），首配分配起步（B05/B06 升级为位图+配对审计），池账与 F0801 五区表联动——池内占用情况随规划账可查。
- **语义边界**：只做设备池的池化与状态机；不做 MSI-X 全局池（F0804 主场）、不做分配器完整算法与冻结接口（F0901/F0902 主场，本条是其地基）；与 F0021 分层：F0021 立使能与 EOI，本条立向量供给侧。
- **依赖与嫁接源**：依赖 F0801 区表边界常量；嫁接源为 Linux IRQ 向量分配域（vector domain）语义与 Intel SDM §6.3.2，只跟随。
- **风险与回退**：现存代码固定向量占用池内槽位（tick 等早年向量）——Reserved 态登记现存占用，收编路径随 F0039 接管清单推进，收编前 Reserved 槽不参与分配。
- 正文：实现路径分三步。第一步池描述块：0x20–0x8F 112 槽逐槽三态标记，Reserved 态登记现存占用者（引用符号名），Free/Used 态带分配时间戳与领主标识，池块与 F0801 区表边界常量做一致性断言（池起界=区起界）；第二步首配分配器：`pool_alloc()` 从低到高取首个 Free 槽，`pool_free()` 归还并清领主，两原语零堆依赖（静态表驱动），申请时带领主字符串供审计，归还时不匹配领主即红账拒绝；第三步状态账：池占用率、各领主持有数、Reserved 收编进度三项随规划账导出，越界申请（非池区间向量号）与重复归还两类非法操作注入测试 10/10 次被拒留账。与现存内核衔接点：现存硬编码向量号（如 PIC 转发路径）逐处登记 Reserved，不改现存行为；与 F0901 衔接：本条池块结构被分配器直接复用。与 Windows 对照：Windows `!msiext` 类扩展可查中断资源分配，本内核池账以"领主-向量-时刻"三元组对齐可观测性，判据 UNX-F0803-J1 的复测方式：ktest 万次申请归还后占用率归零、Reserved 槽全程未泄漏、越界/重复归还注入 10/10 次被拒。

### UNX-F0804 · 全局 MSI-X 向量池与 IPI 向量区隔离
- 域/批：A2/B01｜判据：UNX-F0804-J1 MSI-X 池 0x90–0xDF 与 IPI 区 0xE0–0xFE 双向越界为零，IPI 区预留宽度与 F0004 核数账匹配｜纯功能行数：320 行（双区描述块 110 + 隔离断言 100 + 宽度核算 110；测试段不计）｜状态：[已深化]
- **定位**：MSI-X 池与 IPI 区是向量空间里两类"高价值地产"——MSI-X 池服务多队列设备（NVMe 32 队列级需求），IPI 区服务核间通信（宽度随核数），两者相邻（0xE0 界碑）最易被越界踩踏，本条把两区做成独立描述块 + 双向越界断言 + 宽度核算账，为 B05/B06 分配器与 B07 IPI 族划清产权。
- **语义边界**：只做两区规划与隔离保障；不做 MSI-X 分配算法（F0901）、不做 IPI 发送语义（F0922）；与 F0803 分层：F0803 是设备本地池，本条是全局池与 IPI 区。
- **依赖与嫁接源**：依赖 F0801 区表与 F0004 核数账（enabled_cpus）；嫁接源为 Intel SDM §10.6（IPI 向量惯例）与 PCIe Spec MSI-X 能力章节，只跟随。
- **风险与回退**：核数账超 IPI 区容量（理论核数 >31 时区不够）——宽度核算失败时红账告警并进"紧凑 IPI 模式"（IPI 复用设备池高位），告警不静默；现役机型核数 ≤16，容量余量充足。
- 正文：实现路径分三步。第一步双区描述块：MSI-X 池 80 槽与 IPI 区 31 槽各自建块（起界/容量/领主/水位四字段），两块与 F0801 区表逐界对齐断言；第二步双向越界断言：MSI-X 分配不得越过 0xDF、IPI 编号不得低于 0xE0，两条断言常驻分配路径（越界即 panic——越界是规划损坏不是运行错误，宁可停机不可踩踏），断言触发率账常驻；第三步宽度核算账：IPI 区容量按 F0004 enabled_cpus 核算（每核预留 RESCHEDULE/INVALIDATE/CALL_FUNCTION 三类 + 余量），核算结果随规划账打印，超容走紧凑模式红账。与现存内核衔接点：现存 IPI 若有硬编码向量（`smp.rs` 检查后收编进区表）；与 B05/B07 衔接：两描述块成为分配器与 IPI 族的领地产权凭证。与 Windows 对照：Windows 的 IPI 向量分配对用户不透明但可经 WinDbg `!idt` 观察高频 IPI 向量段，本内核以区表+核算账把同一事实显式化，判据 UNX-F0804-J1 的复测方式：双区越界断言注入 10/10 次触发、IPI 区宽度与 msinfo32 逻辑处理器数匹配、MSI-X 池水位账随分配增长可查。

### UNX-F0805 · spurious 向量 0xFF 槽位与伪中断过滤
- 域/批：A2/B01｜判据：UNX-F0805-J1 spurious 触发全程入账不误 EOI（10 万次注入零误 EOI），伪中断识别率 100%｜纯功能行数：240 行（0xFF 入口 70 + 伪中断过滤器 90 + 计数账 80；测试段不计）｜状态：[已深化]
- **定位**：spurious（伪）中断是 LAPIC 竞态窗口的固有产物——IF 清零瞬间撤回的投递以 0xFF 槽位抵达，它是"最合法的垃圾"，处置纪律是入账不 EOI 不传播；本条把 0xFF 槽位做成独立入口 + 伪中断过滤器 + 计数账，与 F0845 五态处置账分层（本条立入口与过滤，F0845 立处置分档）。
- **语义边界**：只做 0xFF 槽位入口与过滤计数；不做 spurious 率统计告警（F0852）、不做 SVR 重编程迁移（F0846）；与 F0021 分层：F0021 立 SVR 使能位，本条立伪中断的运行期过滤。
- **依赖与嫁接源**：依赖 F0801 五区表 spurious 槽位与现存 `apic.rs` SVR 常量；嫁接源为 Intel SDM §10.9（Spurious Interrupt）与 Linux apic spurious 处置惯例，只跟随。
- **风险与回退**：固件把 SVR spurious 向量配成非 0xFF 值——初始化时按 SVR 寄存器实际值建立"伪中断识别集"（默认 0xFF + 实配值双成员），识别集随引导账打印，两值都能被过滤。
- 正文：实现路径分三步。第一步 0xFF 独立入口：五区表 spurious 槽位挂独立 stub，入口只做三件事——伪中断计数加一、ISR 位状态快照（供竞态分析）、iret 返回，全程不触碰设备 handler、不写 EOI（含 EOI-disable 位分支语义随 F0021 SVR 语义走）；第二步伪中断过滤器：识别集（默认 0xFF + SVR 实配值）成员命中即走过滤路径，非成员但无 handler 的向量进"未知向量记账 handler"（F0801 规划账联动），两路严格分开——伪中断是已知无害，未知向量是需要诊断的异常；第三步计数账：伪中断计数、按核分布、伴随向量（同一时刻在途的真中断号）三项落账，供 F0852 率统计与竞态分析消费。与现存内核衔接点：现存 `apic.rs` SVR 常量与 `lapic()` 零改动，入口挂接走 F0801 填充器。与 Windows 对照：Windows 对 spurious 的处置不可直接观测但中断计数器（`!pic`/性能计数）不含 spurious 污染，本内核计数账单独分列保证真中断统计纯净，判据 UNX-F0805-J1 的复测方式：10 万次 IF 竞态注入伪中断全入账、EOI 写零次、真中断计数不受污染。

### UNX-F0806 · IST 三栈布局与 DF/NMI/MC 挂接
- 域/批：A2/B01｜判据：UNX-F0806-J1 三张 IST 栈独立可用（构造 DF 触发走 IST 且现场完整），栈溢出防护触发率 100%｜纯功能行数：320 行（IST 栈分配 100 + TSS 槽位编程 110 + 挂接断言 110；测试段不计）｜状态：[已深化]
- **定位**：Double Fault/NMI/Machine Check 三者必须在"未知状态"下被接住——普通中断栈可能正是故障源，IST 独立栈是"接住接不住的异常"的唯一手段；本条把三张 IST 栈（每张独立预留页）布局固化、TSS 槽位编程、三条异常挂接一次建齐，与 F0022 纲领分层：F0022 立 IST 概念，本条立三栈实物与防护验证。
- **语义边界**：只做 IST 栈分配、TSS 编程与挂接；不做 DF 处置语义（F0811）、不做 NMI panic 硬化（F0037 已立/本域 F0987 风暴联动）；栈体零修改现存 GDT/TSS 主结构（槽位填入而已）。
- **依赖与嫁接源**：依赖现存 `cpu/gdt.rs` 的 TSS 结构与 F0801 IDT 填充器；嫁接源为 Intel SDM Vol.3 §6.14.5（Interrupt Stack Table）与 x86-64 ABI 栈对齐要求，只跟随。
