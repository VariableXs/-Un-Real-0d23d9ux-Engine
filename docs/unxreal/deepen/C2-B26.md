### UNX-F9301 · EINTR 语义总纲（慢系统调用中断面）
- 域/批：C2/B26｜判据：UNX-F9301-J1 慢系统调用中断面判据过，EINTR 触发三条件（信号到达/无 SA_RESTART/阻塞中）逐格落账，与 Linux 语义一致格过｜纯功能行数：420 行（慢调用中断面 150 + 触发三条件逐格 140 + Linux 一致 130）｜状态：[已深化]

- **定位**：本条是 EINTR 竞态注入批（F9302–F9319 各专条）的总纲：立慢系统调用（阻塞于管道/终端/等待队列/休眠的调用面）被信号中断的语义全景——EINTR 触发三条件合同、可重启/不可重启分面基线，glibc TEMP_FAILURE_RETRY 与信号驱动模型的地基格。
- **语义边界**：只管 EINTR 语义总纲与三条件合同；逐 syscall 重启面矩阵归 F9302、部分完成语义归 F9311、判定次序归 F9313、信号发生器归 F9312；信号本体语义归 B11/B12 母体（本批消费不重铺）。
- **依赖与嫁接源**：嫁接 signal-safety(7)/signal(7) 中断面语义（'slow' device 定义、EINTR 触发条件原文）与 sigaction(2) SA_RESTART 字段；锚定 B11 信号挂点族（投递单源）、B12 四输入判定器（重启旗标输入）、B09 四件套（多路复用消费面）。
- **风险与回退**：风险一为三条件缺一误触发（信号已到达但任务非阻塞态时误返 EINTR——快速路径调用被误中断）——回退为三条件与格：触发必须三条件同时成立（信号到达/无 SA_RESTART/处于可中断阻塞），单条件注入（如信号到达但无阻塞）断言零 EINTR；风险二为慢调用面定义漂移（常规文件读写被当慢调用可中断）——回退为慢调用面冻结表：管道/终端桩/等待队列/休眠面四类列入，常规文件 I/O 零中断声明落账（与 Linux 上游一致）。
- **正文**：实现路径分三步：第一步立慢调用中断面——慢调用面冻结表落账（管道空读阻塞/终端桩读/等待队列挂起/nanosleep 休眠四类），每类标注阻塞点位置与可中断睡眠标志位，常规文件读写/非阻塞快路径零中断声明格；第二步立触发三条件逐格——条件一信号到达（目标信号处于未屏蔽且 pending 置位）、条件二无 SA_RESTART（sigaction 默认态）、条件三阻塞中（任务处于 TASK_INTERRUPTIBLE 态），三条件真值表 2^3 组合注入（仅三真才 EINTR，其余七组合全部正常完成或无中断），逐格 errno 断言；第三步立 Linux 一致核——与 signal(7) 中断面语义逐例比对（三条件合同/慢调用范围/快速路径豁免三列），与 B12 四输入判定器的"信号处置/重启旗标"两输入对账一致，比对表落账。与现存内核衔接点：可中断睡眠标志与 A1/B18 任务态单源；信号 pending 与 B11 单源。与 Windows 对照：Windows 无 SA_RESTART 等价（等待由调用方循环重入），APC/IO completion 中断模型差异归 F9317 差异账；本条按 Linux 上游语义冻结。判据 UNX-F9301-J1 的复测方式：ktest 三断言——慢调用面冻结表、三条件真值表 8 组合注入、比对表三列一致。

### UNX-F9302 · SA_RESTART 重启语义矩阵（逐 syscall 重启面）
- 域/批：C2/B26｜判据：UNX-F9302-J1 SA_RESTART 逐 syscall 重启面矩阵判据过，可重启族逐格重启可观测，不可重启族逐格 EINTR 格过｜纯功能行数：420 行（可重启族重启可观测 150 + 不可重启族 EINTR 140 + 逐 syscall 分面表 130）｜状态：[已深化]

- **定位**：本条立 SA_RESTART 置态下的逐 syscall 重启面矩阵：可重启族（read/write/wait/flock 等慢调用）自动重启可观测、不可重启族（poll/epoll_wait/nanosleep/sigsuspend 等）SA_RESTART 置态仍 EINTR——两族边界是 EINTR 语义最易错分面，逐格落账。
- **语义边界**：只管 SA_RESTART 置态的重启/不重启分面；SA_RESTART 清态（全族 EINTR 基线）归 F9301 三条件合同；部分完成后的重启语义归 F9311；判定器本体归 B12（消费对账）。
- **依赖与嫁接源**：嫁接 signal(7) 'Interruption of system calls' 两清单原文（SA_RESTART 条件重启清单/never-restarted 清单）；锚定 B12 四输入判定器（重启旗标输入单源）、B11 sigaction 挂点（旗标存储）、B09 poll/epoll 面（不可重启族源）。
- **风险与回退**：风险一为两族边界漂移（poll 被误可重启或 read 被误不重启，上游语义逐例不同）——回退为分面冻结表：可重启族（read/write/ioctl 慢设备/wait 族/flock/open 阻塞）与不可重启族（poll/ppoll/select/epoll_wait/nanosleep/sigsuspend/sigwait）逐 syscall 两列清单冻结，逐格对照断言，任一格漂移即 fail；风险二为重启次数不可观测（自动重启对用户态不可见，断言无锚点）——回退为内核侧观测点：重启计数探针（重启路径命中计数器），置 SA_RESTART 注入一次信号后计数=1 且调用最终成功返回，清态对照计数=0 且返回 EINTR。
- **正文**：实现路径分三步：第一步立可重启族矩阵——read（管道空读阻塞中注入）×SA_RESTART 置态：内核重启后读到数据正常返回（重启计数探针=1），write/flock 阻塞/wait 子退出/阻塞 open 同构注入五格，逐格"重启计数+最终成功"双断言；第二步立不可重启族矩阵——poll/epoll_wait/nanosleep/sigsuspend 四格 SA_RESTART 置态注入：仍返回 -EINTR（never-restarted 上游语义），nanosleep 附 remaining 回写（F9304 联动）、poll 附重入正确性（F9306 联动），逐格 errno 断言；第三步立分面表收口——两族清单冻结表落账（每 syscall 一行：族别/置态行为/清态行为三列），与 signal(7) 原文清单逐例比对一致（零差异断言），边界抽查：wait 族（可重启）与 poll（不可重启）相邻对照格锁定边界。与现存内核衔接点：重启路径与 B12 判定器单源；sigaction 旗标与 B11 单源。与 Windows 对照：Windows 无重启旗标（APC 完成后调用方决定重试），无族别语义；差异账归 F9317。判据 UNX-F9302-J1 的复测方式：ktest 三断言——可重启族五格重启计数断言、不可重启族四格置态 EINTR、分面冻结表比对零差异。

### UNX-F9303 · read/write EINTR 矩阵（部分读写残留量）
- 域/批：C2/B26｜判据：UNX-F9303-J1 部分读写后中断注入判据过，已传字节数返回正判据格过，零字节残留 EINTR 格过，与 B03/B04 对账格过｜纯功能行数：400 行（部分读写后中断注入 140 + 已传字节正判据 130 + 零字节残留 EINTR 70 + B03/B04 对账 60）｜状态：[已深化]

- **定位**：本条立 read/write 的 EINTR 竞态矩阵核心：中断落在部分读写之后时返回已传字节数（正值）而非 -EINTR、中断落在零字节起点时返回 -EINTR——部分完成优先语义（先完成后中断 F9313 的 I/O 侧），与 B03 读写语义档/B04 装载链对账。
- **语义边界**：只管 read/write 中断面；部分完成语义通则归 F9311（本条 I/O 侧落点）；write 半程回滚归 F9311 对账；缓冲 I/O（FILE* 层）重试归 F9318 glibc 消费核；非中断态读写正语义归 B03 母体（零重铺）。
- **依赖与嫁接源**：嫁接 read(2)/write(2) man-pages 返回值段（'it may return less than count'/EINTR 行）与 signal-safety(7) 部分传输注记；锚定 B03 读写语义档（计数路径单源）、B04 装载链（copy 探针消费）、F9313 判序协议。
- **风险与回退**：风险一为部分完成被误报 EINTR（已传 4096 字节后中断，误返 -EINTR 致数据重复或丢失）——回退为正判据硬格：已传字节>0 时中断注入必返回正字节数（零 EINTR 出口），注入构造用管道小缓冲强制半程（buf 大于管道容量），返回值与管道实际到达量逐字节一致断言；风险二为半程中断后内核缓冲状态不一致（用户缓冲已写入部分但计数错报）——回退为计数探针格：用户缓冲内容逐字节校验（前 N 字节与源一致），内核侧拷贝游标与返回值一致断言。
- **正文**：实现路径分三步：第一步立部分读写注入——管道容量 64KiB 预写 32KiB，read(buf,128KiB) 阻塞于半程（已拷 32KiB 后无数据可拷）注入信号（无 SA_RESTART），断言返回 32768（正值非 -EINTR），write 侧构造大 buf 半程写入（管道满后阻塞）注入信号返回已写字节数；第二步立已传字节正判据——返回值与管道对端实际到达字节量逐字节比对（计数探针），用户缓冲前 N 字节内容校验和一致，两构造各一断言；第三步立零字节残留格与对账——零字节起点中断（管道空 read 阻塞起点注入）→ -EINTR；与 B03/B04 对账：计数路径与 B03 读写档同函数（grep 单源核）、装载链 copy 探针（B04）对同语义消费一致，对账表两行落账。与现存内核衔接点：读写计数路径与 B03 单源；拷贝探针与 F8921 链单源。与 Windows 对照：Windows ReadFile 半程被 APC 打断返回已传字节数+TRUE/FALSE 语义、GetLastError()==ERROR_IO_INCOMPLETE，无 EINTR 正值惯例；差异注记归 F9317。判据 UNX-F9303-J1 的复测方式：ktest 三断言——半程注入返回正值逐字节核、零字节起点 EINTR、B03/B04 单源对账表。

### UNX-F9304 · nanosleep EINTR remaining 回写矩阵（联 B20）
- 域/批：C2/B26｜判据：UNX-F9304-J1 中断注入 remaining 回写判据过，剩余量逐 ns 可观测格过，与 B20 休眠族对账一致格过｜纯功能行数：380 行（中断注入 remaining 回写 140 + 剩余量逐 ns 观测 120 + B20 休眠族对账 120）｜状态：[已深化]

- **定位**：本条立 nanosleep 的 EINTR 专格：中断注入时 remaining 回写（第二参数 timespec 回写剩余休眠量，供调用方重入续睡）——不可重启族的代表格，sleep 循环重试模型（sleep(3) 语义）的内核侧底座，与 B20 休眠族母体对账。
- **语义边界**：只管 nanosleep 中断面与 remaining 回写；nanosleep 正路径精度与定时器本体归 B20 休眠族（对账不重铺）；clock_nanosleep 旗标变体归 B20；重试循环用户态惯例归 F9318 消费核注记。
- **依赖与嫁接源**：嫁接 nanosleep(2) man-pages（'rem' if interrupted... remaining time'原文与 never-restarted 注记）；锚定 B20 休眠族母体（定时器挂点单源）、F9302 不可重启族（族别对账）、F9313 判序（完成优先：到期后才到的信号零 EINTR）。
- **风险与回退**：风险一为 remaining 回写缺省（中断后 rem 未写或写全零，调用方重入造成长睡或忙转）——回退为回写硬格：中断注入后 rem 必为正且 ≤ 请求量（rem>0 断言），rem 全零注入（临近到期注入）单列边界格（上游允许 0，断言容差窗口）；风险二为剩余量精度失真（rem 与定时器内部余量漂移，累计睡眠偏差）——回退为逐 ns 观测格：rem 与内核定时器过期时刻-当前时刻差值逐 ns 比对（时钟源探针），续睡后总睡眠 ≥ 请求量的夹逼断言。
- **正文**：实现路径分三步：第一步立中断注入回写——nanosleep(500ms) 阻塞中 100ms 注入信号（无 SA_RESTART），断言返回 -EINTR 且 rem 写回约 400ms（逐 ns 观测：rem 与定时器探针差值 <1ms 抖动阈值），rem>0 且 rem≤请求量双断言；第二步立逐 ns 可观测与边界——rem 与内核过期时刻差逐 ns 比对落账；边界三格：注入恰在到期后（完成优先 → 正常返回 0 零 EINTR）、注入临近期到（rem 小值 ≥0）、重入续睡（rem 回填再 nanosleep，总睡眠夹逼 ≥500ms）；第三步立 B20 对账——remaining 回写路径与 B20 定时器余量读取同函数（grep 单源核）、到期完成语义与 B20 精度格对账一致，对账表两行落账（never-restarted 族别与 F9302 分面表一致）。与现存内核衔接点：定时器挂点与 B20 单源；任务态与 A1 调度让出协议单源。与 Windows 对照：Windows Sleep 无中断与 remaining（SleepEx+APC 可警醒但无剩余量回写），调用方自算重试；差异账归 F9317。判据 UNX-F9304-J1 的复测方式：ktest 三断言——注入回写 rem 双断言、逐 ns 观测与边界三格、B20 单源对账表。

### UNX-F9305 · wait EINTR 矩阵（联 B18）
- 域/批：C2/B26｜判据：UNX-F9305-J1 阻塞 wait 中断注入判据过，全 EINTR 格过，WNOHANG 零中断正判据格过｜纯功能行数：320 行（阻塞 wait 中断注入 120 + 全 EINTR 格 90 + WNOHANG 零中断正判据 110）｜状态：[已深化]

- **定位**：本条立 wait 族的 EINTR 注入格：阻塞 wait/waitpid 在子未退出时被信号中断返回 -EINTR（SA_RESTART 清态）、WNOHANG 非阻塞态零中断（立即返回 0 正判据）——作业控制（shell 等待子进程+信号驱动）的竞态底座，与 B18 wait 母体对账。
- **语义边界**：只管 wait 中断面；wait 正路径状态机与 ECHILD 面归 B18/F9283（对账不重铺）；SA_RESTART 置态下 wait 的重启行为归 F9302 可重启族（对账格）；SIGCHLD 投递竞态归 F9292/F9309（本条只管 wait 侧中断）。
- **依赖与嫁接源**：嫁接 wait(2) man-pages EINTR 行（'interrupted by a signal'原文）与 signal(7) wait 可重启注记；锚定 B18 wait 母体（阻塞点单源）、B12 判定器（重启旗标输入）、B11 信号挂点（注入源）。
- **风险与回退**：风险一为中断注入破坏等待状态（EINTR 后子进程信息或等待队列残留脏态）——回退为状态零破坏格：EINTR 返回后子表计数不变、等待队列已出队（复入可再阻塞），两断言；风险二为 WNOHANG 误中断（非阻塞立即返回路径被注入打断）——回退为零中断格：WNOHANG 态注入信号后仍立即返回 0（无子退出态），时钟夹逼 <1ms，EINTR 零出现断言。
- **正文**：实现路径分三步：第一步立阻塞注入——fork 子后父 waitpid(-1,0) 阻塞，100ms 注入信号（SA_RESTART 清态）：返回 -EINTR，且 EINTR 后复入 waitpid 再次阻塞（队列出队/复入两断言），子收割后第二次注入对照（有子可收时 wait 立即返回状态值非 EINTR——完成优先对账）；第二步立全 EINTR 格——wait/waitpid(-1)/waitpid(pid) 三形态阻塞注入全 -EINTR（SA_RESTART 清态），零状态破坏（子表计数/队列空表）断言，SA_RESTART 置态对照（重启后收到子退出正常返回，F9302 对账）；第三步立 WNOHANG 正判据——WNOHANG 态注入信号：立即返回 0（无子退出）夹逼断言、有子已退出态立即取状态（零中断），两态正判据收口。与现存内核衔接点：阻塞点与 B18 wait_core 单源；注入与 B11 发生器（F9312）单源。与 Windows 对照：Windows WaitForSingleObject 可被 APC 警醒（WAIT_IO_COMPLETION）无信号重启语义；注记。判据 UNX-F9305-J1 的复测方式：ktest 三断言——阻塞注入 EINTR 与复入、三形态全 EINTR 零脏态、WNOHANG 双态夹逼。

### UNX-F9306 · poll/epoll EINTR 矩阵（就绪前中断）
- 域/批：C2/B26｜判据：UNX-F9306-J1 就绪前中断注入判据过，全 EINTR 格过，重启后重入正确格过，与 B09 四件套对账格过｜纯功能行数：380 行（就绪前中断注入 140 + 全 EINTR 格 100 + 重启后重入正确 80 + B09 对账 60）｜状态：[已深化]

- **定位**：本条立 poll/epoll_wait 的 EINTR 注入格：fd 就绪前被信号中断返回 -EINTR（SA_RESTART 置态亦然——never-restarted 族）、EINTR 后重入正确性（重入后原监听集与超时语义不失效）——事件循环（Reactor 模型）竞态底座，与 B09 四件套对账。

- **定位**：本条立 EINTR 面的用户态消费核：glibc TEMP_FAILURE_RETRY 宏（EINTR 即重试循环）对慢 syscall 的消费链——read/nanosleep 续睡（rem 回填）/poll 重入三条典型重试路径的内核侧验证，B14 消费清单体例的续登记。
- **语义边界**：只管 glibc 重试消费链；glibc 全量清单归 B14 母体（对账引用）；stdio 缓冲层内部重试归 libc 本体（消费核只核 syscall 侧）；重试语义正确性的内核前提（remaining/重入正确）归 F9304/F9306（单源消费）。
- **依赖与嫁接源**：嫁接 unistd.h TEMP_FAILURE_RETRY 宏定义（'operate again until success or non-EINTR failure'）与 glibc sleep/nanosleep 重试惯例；锚定 B14 消费清单四列体例、F9304 rem 回写（续睡前提）、F9306 重入正确（重入前提）。
- **风险与回退**：风险一为重试后语义漂移（宏重试后内核侧状态与首次调用态不一致——如 poll 超时未重算致长阻塞）——回退为语义正确格：重试后最终结果与零中断等价对照（注入重试路径结果 vs 无注入直接调用结果一致断言），nanosleep 续睡总时长夹逼；风险二为消费号空登记（声称消费无证据）——回退为登记格：每条路径附发生器触号证据（F9312 注入号），空登记即 fail。
- **正文**：实现路径分三步：第一步立重试宏消费链——三条典型路径构造：read 重试（EINTR 后重读到数据）、nanosleep 续睡（EINTR 后 rem 回填重睡至满额）、poll 重入（EINTR 后重入得就绪），发生器注入断点可控（F9312 单源）；第二步立重试后语义正确——三路径各自与零中断对照等价断言（结果一致）、nanosleep 总睡眠 ≥ 请求量夹逼、read 最终读到完整数据逐字节核；第三步立消费号登记——三条消费号四列登记（消费号/glibc 路径/触号/断言态）入 B14 清单续表，meter 证据逐条附，随 B34 消费面回归联测复核。与现存内核衔接点：与 B14 清单单源续表；rem/重入与 F9304/F9306 单源。与 Windows 对照：Windows 无 TEMP_FAILURE_RETRY（循环重试为应用惯例），注记。判据 UNX-F9318-J1 的复测方式：ktest 三断言——三路径注入重试链、零中断对照等价与夹逼、三条消费号四列齐。

### UNX-F9319 · E 型竞态参数探针总成
- 域/批：C2/B26｜判据：UNX-F9319-J1 nargs 逐位提取判据过，坏指针全 EFAULT 格过，与参数拷贝探针单源格过｜纯功能行数：300 行（nargs 逐位提取 120 + 坏指针 EFAULT 90 + 探针单源 90）｜状态：[已深化]

- **定位**：本条立 EINTR 批参数探针总成：nanosleep(timespec*)/poll(fds*,nfds,timeout)/waitpid(pid,status*,options)/sigsuspend(mask*) 等注入面的参数逐位提取与坏指针 EFAULT 出口——F8921 探针总成在竞态批的落点消费核。
- **语义边界**：只管本批参数提取与指针校验；探针总成本体归 F8921/F9117/F9294（单源复用）；timespec/epoll_event 结构拷贝面归 F9116 结构探针（联动）；各 syscall 语义归各专条。
- **依赖与嫁接源**：嫁接 syscall ABI 与各 man-pages 参数签名（timespec*/pollfd*/sigset_t* 指针面）；锚定 F8921 探针总成、F9294 进程族探针（姊妹格体例）、F9116 结构拷贝探针（结构面联动）、B01 分发表（nargs 元数据）。
- **风险与回退**：风险一为 timespec 坏指针被延迟解引用（中断注入后才发现坏指针，状态已破坏）——回退为前置校验格：timespec/结构指针在入口全量预检（access_ok 谓词与 F8921 同源），坏指针零定时器副作用（定时器未注册断言），EFAULT 先于一切；风险二为 options 位域污染（waitpid options 高位垃圾位被误读为 WNOHANG）——回退为逐位截取格：options 按合法位掩码过滤（高位垃圾注入后判定不变），掩码表落账。
- **正文**：实现路径分三步：第一步立逐位提取——四入口注入已知值组（nanosleep(0.5s)/poll(nfds=2,timeout=-1)/waitpid(-1,&st,WNOHANG)/sigsuspend(空屏蔽)）经探针回读内核侧参数区逐位一致，nargs 元数据（nanosleep=2/poll=3/waitpid=3/sigsuspend=1）与 B01 表对账；第二步立坏指针 EFAULT 格——timespec 野指针/pollfds 野指针/status 野指针/mask 野指针×3 值（0/0xFFFFFFFF/只读页写目标）共 12 格，全 -EFAULT 且零副作用（定时器未注册/监听集未建/子表零变更观测）；第三步立单源核——取参与 F8921 同路径（grep 核）、access_ok 谓词与 F8921/F9294 同源、结构拷贝与 F9116 联动对账，对账表三行落账。与现存内核衔接点：与 F8921/F9116/F9294 四方单源链。与 Windows 对照：Windows 坏参数 STATUS_ACCESS_VIOLATION；注记。判据 UNX-F9319-J1 的复测方式：ktest 三断言——四入口逐位回读、12 格 EFAULT 零副作用、三行单源对账表。
