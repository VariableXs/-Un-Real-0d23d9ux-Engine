## F3281 RCU 语义边界声明（宽限周期概念与不做的事）

**定位**：RCU 族的根声明条目：定义读侧零锁语义、宽限周期（Grace Period，GP）概念模型、"不做的事"清单——B05 后续 19 条与 B06 RCU 二批的语义宪法。
**语义边界**：本条是语义宪法：v1 范围 = 非抢占式 RCU（读临界区不可睡眠）；显式不做：preemptible RCU（读侧可睡眠的变体）、NMI 上下文读侧、用户态 RCU、多级树形 GP（8 核规模用扁平位图足够，判据行给规模论证）。
**判据**：
- J1：M-040 概念验证用例：发布-订阅场景（写者换指针、读者无锁读旧值）在三原语（rcu_read_lock/dereference/unlock）下全链路安全，可重复。
- J2：声明文档四节齐：语义定义 / 概念模型 / 不做清单 / 与 B04 的边界（F3274 三前置的兑现对照）。
**纯功能行数**：380（语义定义与概念模型 ~140 + 不做清单与规模论证 ~120 + 前置兑现对照 ~70 + 判据行 ~50）
**依赖与嫁接源**：F3274 前置清单（承接依据）；F3201 原子底座。
**风险与回退**：GP 概念被误用为"任意延迟释放"——回退：声明文档用一句话钉死：GP 保证的是"临界区内的指针在 GP 结束前有效"，不是"任意对象保活"。
**正文**：语义定义（文档核心三句）：①读侧：`rcu_read_lock` 进入只标记 per-CPU 计数（F3282），零共享写、零原子竞争；②写侧：更新者复制-修改-替换（发布），旧对象经 `call_rcu` 延迟释放，释放条件 = 所有读者已离开旧值读取（GP 完成）；③宽限周期：从"写侧发布替换"到"所有 CPU 都经历一次静默点"的区间，GP 完成即旧值无人再引用。概念模型给验收者的心智图：把 GP 想成"全系统的一次集体眨眼"——每只眼（CPU）都眨过（静默点），旧世界的影子就消失了。不做清单的理由逐条给：preemptible RCU 需要任务级读标记（依赖 A3 任务模型深化），v1 用 CPU 级标记（8 核固定拓扑，任务不跨核迁移的窗口内语义成立——该前提写入判据行，A3 实装任务迁移后复核）；NMI 读侧需要无中断读标记方案（预算外）；树形 GP 是百核级优化（8 核扁平位图 O(1)）。与 B04 边界：F3274 三前置逐条兑现映射（GP→F3284、回调→F3287、内存序→F3291），兑现表入 J2。Windows 对比：Windows 无内核通用 RCU（前述 F3274 已析），本声明文档的价值是给"为什么 A5 比 Windows 主线驱动多这层"一个正式答辩——动机：读侧 7×24 观测负载 + ktest 1 万+ 断言的运行底座需要零锁读。M-040 复测：发布-订阅用例含"读者读到旧值→读中间值禁止（Release/Acquire 配对保证）→读新值"三段断言。

## F3282 每 CPU 静态读取侧标记（rcu_read_lock/unlock 计数）

**定位**：读侧标记本体：per-CPU 嵌套计数器，进 +1 出 -1，GP 上报条件 = 计数为 0 经历静默点。零共享写是设计红线。
**语义边界**：只做标记计数；静默点定义在 F3285、上报在 F3285、断言在 F3283。计数器内存布局与伪共享防护在本条。
**判据**：
- J1：M-041：8 核并发进出 10,000 轮，每 CPU 计数最终归零、中途峰值 = 嵌套深度；无共享缓存行写（伪共享检查用例）。
- J2：进出路径指令预算 ≤ 3 条（load/add/store 本地内存），判据行给预算依据。
**纯功能行数**：400（计数器结构与布局 ~120 + 进出路径 ~100 + 嵌套语义 ~90 + 判据行 ~90）
**依赖与嫁接源**：F3213 per-CPU 快路体例；F3295 嵌套深度（本条定义嵌套计数，深度账本在 F3295 消费）。
**风险与回退**：per-CPU 变量的 CPU 编号读取在 NMI/中断内可能不稳——回退：v1 明确禁用中断内 RCU 读（与不做清单的 NMI 条一致），读路径断言上下文。
**正文**：实现路径：`#[repr(align(64))] struct RcuCpuState { nest: Cell<u32>, last_quiet_seq: AtomicU64, stall_max: Cell<u64> }`，`RCU_STATES: [RcuCpuState; 8]` 静态数组（8 核编译期定长——判据行声明：核数泛化是 B27+ 跨域批的扩展项，v1 按目标硬件定长）。进：`nest += 1`（本地普通写，无原子——单核内 Cell 足够，这是"零共享写"的关键：连原子指令都不用）；出：`nest -= 1`。GP 上报侧（F3285）读 nest==0 判静默。数据结构要点：nest 用 Cell 非 AtomicU32 的理由——本核独占，原子性无意义，普通写更快且省 fence；last_quiet_seq 用 AtomicU64 因 GP 驱动核要跨核读它（这是唯一的跨核可见点，Acquire/Release 配对在 F3285 定义）。现有内核接入：per-CPU 区域机制对齐 F3213 的每 CPU 快路径基建（GS base 相对寻址），不新建 per-CPU 框架。Windows 对比：Windows 的 per-CPU 语义由 KeGetCurrentProcessorNumber + 数组实现（与 KPRCB 结构），其每 CPU 字段访问即本条模式；RCU 读标记无 Windows 对应物——对照物是 Linux 的 `__this_cpu_inc(rcu_read_lock_nesting)`，本条的 Cell 优化等价其 per-CPU 变体的本核语义。J2 预算依据：进出各 1 load + 1 add + 1 store（x86 本地内存操作），无 fence 无原子 RMW——比 F3262 的读锁 CAS 还轻，这正是 F3274 说的"质的边界"。M-041 复测：伪共享检查 = 各 CPU 计数器地址差 ≥ 64 且压测吞吐无核间相关。

## F3283 读侧临界区不可睡眠断言

**定位**：非抢占式 RCU 的纪律执行：RCU 临界区内禁止睡眠（任何走 F3246 sleep_on 的路径），调试档下断言 + 记账。
**语义边界**：只做检测；不做 preemptible 变体（F3281 不做清单）。检测机制复用 F3254 的 NoSleepMask（新增 RCU tag）。
**判据**：
- J1：M-042：桩环境 RCU 临界区内调用睡眠路径 → RCU_NOSLEEP 违例记账 + 断言；正常锁操作（自旋）不触发。
**纯功能行数**：260（tag 接入 ~80 + 违例路径 ~90 + 判据行 ~90）
**依赖与嫁接源**：F3254 标记机制；F3246 协议（sleep_on 是唯一睡眠入口，检测点天然收敛）。
**风险与回退**：检测点遗漏（绕过 sleep_on 的睡眠）——回退：v1 契约"sleep_on 是唯一睡眠入口"（协议 v1 冻结保证），若有第二入口即 ADR 级议题。
**正文**：实现路径：F3246 的 sleep_on 入口加检测钩子：`if rcu_nesting(current_cpu) > 0 { 记账 RCU_NOSLEEP + debug_assert }`——检测点选在协议层而非 rcu_read_lock 层的理由：睡眠入口只有一个（协议冻结），一处钩子全覆盖；rcu 层标记反而要在锁族所有慢路径布点。数据结构：违例账本同 F3254 格式（tag=RCU_NOSLEEP）。现有内核接入：NoSleepMask 的 tag 枚举扩一位（枚举空间在 F3254 定义时预留，判据行引用预留说明）。Windows 对比：Windows 的等价纪律是"DISPATCH_LEVEL 以上不可页错误/等待"（前述 F3254 已对照），RCU 读临界区在 Linux 是 `might_sleep()` 检查（CONFIG_DEBUG_ATOMIC_SLEEP）——我们的钩子位即 might_sleep 的协议层收口版，覆盖面相同、布点更少。M-042 复测：正例（临界区睡 → 触发）+ 反例（临界区内自旋锁失败重试——自旋不是睡眠，不得触发）——这条反例是 v1 语义的关键：RCU 临界区内可以拿自旋锁（Linux 惯例一致），判据行写明。

## F3284 宽限周期状态机（GP 序号推进）

**定位**：GP 核心：`gp_seq: AtomicU64` 全局序号，GP 驱动推进"开 GP→等全 CPU 静默→收 GP"，序号奇偶标记 GP 进行中/已完成。
**语义边界**：只做状态机与序号语义；驱动循环在 F3286、静默判定在 F3285/F3282。多 GP 并发不做（v1 单 GP 串行——8 核规模单 GP 足够，判据行给吞吐论证）。
**判据**：
- J1：M-043：单轮 GP：开 → 8 CPU 各上报 → 完成序号 +1 且奇偶翻转；多轮：连续 10 轮序号单调 +10。
- J2：状态机三态（IDLE/OPEN/收尾）迁移完备，桩注入各态可达。
**纯功能行数**：420（序号语义与奇偶协议 ~130 + 三态机迁移 ~120 + 完成判定 ~100 + 判据行 ~70）
**依赖与嫁接源**：F3282 标记；F3285 上报；F3246 协议（驱动等待）。
**风险与回退**：GP 序号与 per-CPU 上报序的配对错误导致假完成——回退：完成判定 = "GP 开始序号 s 已被所有 CPU 的 last_quiet_seq ≥ s 覆盖"，序号比较单向，判据行给反例证明（旧静默不能抵新 GP）。
**正文**：实现路径：全局 `gp_seq` 偶=IDLE/完成态、奇=OPEN；开 GP：`gp_seq.fetch_add(1, AcqRel)`（变奇）+ 记录 `gp_start_seq`；收 GP：全 CPU 满足 `last_quiet_seq >= gp_start_seq`（各 CPU 在静默点把 last_quiet_seq 置为当前 gp_seq——F3285 定义写点）后 `fetch_add(1)`（变偶）+ 触发回调执行（F3288）。反例证明（判据行核心论证）：CPU 在 GP 开始前的静默（last_quiet_seq = 旧偶数 s-2 < s）不满足 ≥ 条件——旧静默不能抵新 GP，因为该静默发生在旧值发布之前，旧值读者可能还活着。三态迁移：IDLE→OPEN（有回调待处理时由驱动开）、OPEN→收尾判定（周期检查）、收尾→IDLE（完成 + 回调派发）。单 GP 串行的吞吐论证：8 核下 GP 典型时长 = 最慢 CPU 的静默间隔（tick 级，毫秒量级），回调批量执行微秒级——串行 GP 的回调解锁速率远超 8 核的发布速率，瓶颈不存在。现有内核接入：无接管物（新能力），桥点归 F3299。Windows 对比：Windows 无 GP 对应物；概念对照物是 Linux 的 `rcu_gp_kthread` 状态机（我们裁剪树形与加速投票）。J2 复测：桩注入"CPU 永不上报"（离线场景归 F3296，此处用可恢复悬挂）验证收尾判定不假完成——GP 的"宁可慢不可假"是判据宪法级原则，判据行原文记之。

## F3285 每 CPU GP 完成上报

**定位**：静默点与上报：per-CPU 在固定静态点（tick 处理、调度切换点）检查 nest==0，满足则把 last_quiet_seq 更新为当前 gp_seq——GP 完成判定的数据供给。
**语义边界**：只做静默判定与上报写点；静态点挂接位置清单归 F3299 桥；上报的触发频率策略在本条（每 tick 检查，判据行给开销分析）。
**判据**：
- J1：M-044：模拟 tick 注入 N 次，nest==0 的 CPU 的 last_quiet_seq 跟进 gp_seq；nest>0 的 CPU 不上报——逐 tick 对账。
- J2：上报写点唯一（last_quiet_seq 只有一个写者 = 本 CPU），数据竞争自由证明。
**纯功能行数**：380（静默判定 ~110 + 上报写点与序配对 ~120 + tick 注入用例 ~90 + 判据行 ~60）
**依赖与嫁接源**：F3282 标记；F3284 序号语义；tick 路径（A4 桩先行）。
**风险与回退**：tick 未到导致 GP 迟滞（CPU 长期不进 tick）——回退：GP 迟滞观测归 F3293；v1 不做"强制 resched 打断"（依赖 A3 调度联动，列 ADR 记录位）。
**正文**：实现路径：上报点伪码：`on_tick(cpu) { if rcu_states[cpu].nest == 0 { let s = gp_seq.load(Acquire); if s != last { rcu_states[cpu].last_quiet_seq.store(s, Release); } } }`——读 gp_seq 用 Acquire、写 last_quiet_seq 用 Release，与 F3284 完成判定的读侧（Acquire 读 last_quiet_seq）构成跨核配对：CPU 写"我已静默至 s"对驱动核可见时，其静默事实先行可见。写点唯一性证明：last_quiet_seq 的写者只有本 CPU 的 tick 路径（F3296 离线处置写"跳过位"不是本字段），单写者 + 跨核读者 = Release/Acquire 充分，无 RMW 竞争。tick 开销分析（判据行）：nest==0 时每 tick 1 次 Acquire load + 可能 1 次 Release store——正常路径（无 GP 进行）gp_seq 未变则 store 省略，稳态开销 = 1 条 load/tick。现有内核接入：tick 处理函数的挂接点登记归 F3299（A4 tick 路径，桩先行）。Windows 对比：无对应物；Linux 的 `rcu_check_callbacks` 即本条，我们裁剪其用户态/紧急度分级。J2 复测：静态分析断言（grep last_quiet_seq 的写点唯一）+ 运行时单写者注入检测（两核同写用例，断言框架报警——负例验证唯一性有牙齿）。

## F3286 宽限周期驱动器（GP kthread 边界协议）

**定位**：GP 驱动循环：检查待处理回调 → 开 GP → 周期检查完成判定 → 完成后派发回调执行——驱动自身等待/唤醒经 F3246 协议（醒归 A3 边界在 GP 侧的落地）。
**语义边界**：只做驱动循环与节拍策略；回调执行体在 F3288；驱动寄宿形式 v1 = tick 驱动的协作循环（不开真线程，A3 线程就位后切换，判据行声明切换计划）。
**判据**：
- J1：M-045：桩调度器注入下，注册回调 → GP 开 → 上报齐 → GP 收 → 回调执行，全链路在桩环境走通；驱动的每次等待/唤醒均经 SleepPort（事件账本验证无旁路）。
- J2：驱动节拍可配置（poll 间隔），默认与 tick 同频。
**纯功能行数**：360（驱动循环 ~130 + 协议等待/唤醒衔接 ~110 + 节拍与切换计划 ~70 + 判据行 ~50）
**依赖与嫁接源**：F3246 SleepPort；F3284 状态机；F3287 回调队列（待处理信号）。
**风险与回退**：tick 驱动的协作循环在"没人 tick"（全核忙）时饿死——回退：v1 契约"tick 必然存在"（A4 tick 是系统心跳前提），若 A3/A4 联动后出现无 tick 场景即 ADR。
**正文**：实现路径：驱动入口 `rcu_gp_poll()` 挂 tick（每 tick 一次）：①有待处理回调且 gp_seq 偶 → 开 GP；②GP 开着 → 检查完成判定（F3284）；③完成 → gp_seq 变偶 + 摘回调队列派发（F3288）。等待语义：v1 协作循环无阻塞（poll 模式），`SleepPort` 的使用保留在两个点——synchronize_rcu 的等待者（F3289）与未来真线程版驱动的睡眠；M-045 的事件账本验证即检查这两点的协议使用合规。切换计划（判据行）：A3 线程模型实装后，驱动改寄宿为 `rcu_gp_kthread`（睡眠等待"有待处理回调"信号 + "GP 完成信号"两条件），切换 diff 预估 ~80 行，接口不变。现有内核接入：tick 挂接点归 F3299 清单。Windows 对比：Windows 的延迟释放类机制（ExFreeWithDeferredCleanup 类内部设施）无公开 GP；Linux 的 rcu_gp_kthread 是对照物——我们的"先协作后线程"路线是双轨制的直接应用（开发期不依赖线程设施，真机闸口前完成切换验证）。J1 复测的旁路检查：grep 协议面之外的唤醒调用（wake 原语直接调用点应为零）。

## F3287 回调注册与每 CPU 回调队列

**定位**：`call_rcu` 的回调挂载：per-CPU 回调队列按 GP 代际分段（当前代 / 下一待完成代 / 待执行代），注册 O(1) 挂本核队列尾。
**语义边界**：只做队列与代际挂载；批量执行在 F3288；回调函数契约（上下文约束）在本条判据行定义。
**判据**：
- J1：M-046：注册 100 回调跨 3 轮 GP，代际归属正确（第 i 轮注册的回调在第 i+1 轮 GP 完成后才可执行——两代间隔原则）。
- J2：注册零阻塞零分配（节点从 per-CPU 池取）；池耗尽回退路径有界（对齐 F3236 体例）。
**纯功能行数**：360（节点与池 ~110 + 代际分段 ~120 + 注册路径 ~80 + 判据行 ~50）
**依赖与嫁接源**：F3284 GP 序号（代际依据）；F3236 池耗尽回退体例。
**风险与回退**：回调注册在回调执行中（递归注册）——回退：契约允许递归注册（挂队不执行，下轮处理），M-046 附递归用例。
**正文**：实现路径：`RcuCpuState.cbs: [CbList; 3]`——`cbs[0]` 当前代（新注册都进这）、`cbs[1]` 上一代等待中、`cbs[2]` 待执行；GP 收尾时轮转：`cbs[2]=cbs[1]; cbs[1]=cbs[0]; cbs[0]=空`——两代间隔原则的队列实现：注册进 cbs[0]，至少经历一次完整 GP 轮转（进 cbs[1] → GP 完成进 cbs[2]）才执行，保证"注册时仍可能有读者，执行时必然 GP 已过"。轮转原子性：轮转在 GP 收尾处单点执行（驱动核），per-CPU 队列的本核注册与驱动核的轮转竞争——v1 契约：轮转时该 CPU 必然已上报静默（nest==0）且注册只发生在 RCU 临界区外（读侧才在临界区，call_rcu 在临界区内注册是 Linux 允许的但 v1 禁止，判据行声明差异及理由：8 核规模简化轮转锁协议）。回调契约：回调在 GP 完成上下文执行（v1 = 驱动核轮转点），回调内禁止睡眠（RCU_NOSLEEP 同款钩子覆盖）、允许 call_rcu 递归。现有内核接入：无。Windows 对比：无 GP 回调对应物；Linux `call_rcu` 的 nxt/tail 分代队列即本条结构（我们三段简化其四段）。J1 复测：递归注册用例 = 回调 A 执行时注册回调 B，断言 B 挂 cbs[0] 且下下轮才执行。

## F3288 回调在 GP 完成后的批量执行

**定位**：GP 完成后 cbs[2] 的批量派发与执行：执行序 = 注册序、批量预算（单轮最多执行 N 个防饿驱动）、执行失败隔离。
**语义边界**：只做派发执行；回调内的违规由 F3283 钩子抓。批量执行时新完成 GP 的处理（执行中 GP 又收）延后处理——单 GP 串行语义（F3284）保证此窗口不存在，判据行引用串行契约。
**判据**：
- J1：M-047：200 回调跨代注册，执行序与注册序全序一致（逐 token 核对）；批量预算触发时余量顺延下轮。
- J2：单个回调 panic 被隔离记账，后续回调继续执行（回调隔离契约）。
**纯功能行数**：340（派发循环 ~110 + 预算控制 ~80 + 隔离与记账 ~90 + 判据行 ~60）
**依赖与嫁接源**：F3287 队列；panic 隔离参照 panicseq.rs 的批处理骨架（嫁接源）。
**风险与回退**：回调执行时间不可控拖死驱动核——回退：批量预算 N=64/轮 + 执行超时观测（不做强杀——强杀需任务模型，ADR 记录位）。
**正文**：实现路径：GP 收尾派发：`for cb in cbs[2].take() { 执行; 记账; }`，预算：`if executed == 64 { 余量留 cbs[2]（重新挂回），下轮继续 }`——留队不丢失（队列所有权转移原子）。执行序保证：链表 FIFO 天然保序，M-047 逐 token 核对即验证链表完整性。隔离：回调体以 catch 风格包装（Rust panic = abort 语义在内核 v1 为记账 + 断言路径，对齐 panicseq.rs 的批处理骨架——内核 panic 策略的正式定义归 A5 日志批 B15，本条引用其预留接口），隔离记录 panic_token 供验收追溯。现有内核接入：panicseq.rs 骨架复用登记（F3299 桥）。Windows 对比：Windows 的工作项执行（IoQueueWorkItem）有队列深度与并发度控制，其"执行失败不拖垮队列"由工作线程模型承载；我们单核协作执行 + 预算顺延是 8 核 v1 的等价简化，判据行注明 B06 workqueue（F3309–F3312）交付后回调执行可迁移至工作项（迁移计划入契约）。J2 复测：注入 panic 回调（第 3 个），断言 1/2/4…200 除 3 外全执行且隔离账目 = 1。

## F3289 synchronize_rcu 同步等待接口

**定位**：同步等待当前注册点 GP 完成：阻塞语义（经 F3246 协议睡眠等待 GP 完成信号），供"必须确保旧值无人再读"的同步路径使用。
**语义边界**：只做同步等待；等待者的唤醒信号在 GP 收尾处发（F3284 完成点 + 本条的等待者登记表）。超时变体不做（协议 TIMEOUT 态可用但 v1 不暴露参数，判据行声明）。
**判据**：
- J1：M-048：3 等待者并发 synchronize，GP 完成后三者全部收敛且不早于 GP 完成序号翻转。
- J2：等待者在 RCU 临界区内调用 synchronize → 断言拒绝（自等待死锁预防）。
**纯功能行数**：300（等待者登记表 ~110 + 收敛与唤醒衔接 ~90 + 自等待拒绝 ~60 + 判据行 ~40）
**依赖与嫁接源**：F3246 协议；F3284 完成点。
**风险与回退**：等待者登记表自身竞争（等待者注册 vs GP 收尾发信号）——回退：登记表自旋锁保护（B01 F3202），登记与检查的两步序（先登记后查 GP 状态）防丢信号，判据行给次序证明。
**正文**：实现路径：`fn synchronize_rcu() { assert_not_in_rcu_read(); waiters.lock(); if gp 已过注册点 { unlock; return; } 挂登记表; sleep_on(...); }`——GP 收尾：`摘登记表逐个 wake_protocol`。丢信号防证明：登记（加锁）→ 查 gp_seq（加锁内）→ 睡眠（解锁后）：若查时已完成则直接返回不睡；若未完成，收尾的摘表必持同锁，睡前登记已可见——锁序（waiters 锁 → 睡眠）与收尾序（waiters 锁 → 唤醒）构成标准无丢信号模式。自等待拒绝的理由：临界区内 synchronize 要等"自己退出"才能完成 = 自死锁，断言必须在睡前置位（睡后无人能醒它）。现有内核接入：无。Windows 对比：Windows 等价语义 = ExWaitForRundownProtection 类栅栏（rundown protection 的 WaitForRundownRelease 与 synchronize 的"等读者清零"同构）；我们的 GP 版更强（全系统读者而非单对象引用计数）。J2 复测：临界区内调用 → 记账 SYNCHRONIZE_IN_READSIDE + 断言，不睡不挂。

## F3291 rcu_dereference/rcu_assign_pointer 内存序包装

- J2：配对表交付：assign 的每处使用必须有 deref 对端（静态清单核对）。

## F3296 CPU 离线时 GP 推进处理（quiescent 替补上报）

**定位**：离线 CPU 不阻塞 GP：离线标记位使完成判定跳过该 CPU——"不响应也不拖死"的 GP 健壮性条款。
**语义边界**：只做离线跳过；CPU 热插拔的全生命周期管理归 A4/A3（本条只消费"离线状态位"），上线恢复上报的自然性验证在本条。
**判据**：
- J1：M-055：桩注入 CPU 离线（停止其 tick 与上报）→ GP 照常完成；上线后恢复参与，下一 GP 覆盖它。
- J2：跳过位读点唯一（完成判定处），写点 = A4 状态变更钩子（v1 桩）。
**纯功能行数**：300（跳过位语义 ~90 + 完成判定改造 ~100 + 恢复验证 ~70 + 判据行 ~40）
**依赖与嫁接源**：F3284 完成判定；A4 离线状态（桩先行）。
**风险与回退**：离线瞬间竞态（离线标记与最后上报交错）——回退：跳过判定用"离线位或已静默"的或语义（离线即满足，无需上报）——或语义天然消除交错窗口，判据行给证明。
**正文**：实现路径：完成判定条件从"全 CPU last_quiet_seq ≥ s"改为"全 CPU（offline 位 || last_quiet_seq ≥ s）"——离线 CPU 视为天然静默（无读者在其上，读者随离线流程退出——该前提依赖 A4 的离线协议"离线前清 RCU 临界区"，契约写入判据行并登记 A3/A4 联签需求）。或语义证明：离线位在 GP 进行中置位 → 判定通过（其历史上报作废也无妨——离线即无新读者）；恢复上线 → 位清除 → 下轮 GP 正常等它。竞态证明：位与 last_quiet_seq 独立字段，或逻辑下任何交错序结果一致。现有内核接入：A4 离线钩子桩先行（同 F3267 模式），联签需求登记（B14 迁移批的接口面）。Windows 对比：Windows 处理器离线的同步语义 = KeProcessorAdd/Stop 的 rundown 序列（PrcbOffline 状态机）；我们的"离线即静默"是其 RCU 侧投影，契约依赖写明（离线协议的 RCU 清点）。M-055 复测：离线注入 3 轮 GP + 恢复 1 轮，完成序号单调且恢复后该 CPU 的迟滞（F3293）从大值回落。
