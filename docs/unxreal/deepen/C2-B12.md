### UNX-F9021 · EINTR/SA_RESTART 判定器单点本体（自 F8948 深化）
- 域/批：C2/B12｜判据：UNX-F9021-J1 判定器四输入（handler 置位/信号掩码/慢调用类别/重启白名单）全组合矩阵判据过，白名单外号不重启判据过，单点唯一性（全号面仅此一处分流）判据过｜纯功能行数：280 行（四输入判定器 130 + 全组合矩阵 80 + 单点唯一性审计 70）｜状态：[已深化]

- **定位**：本条是全号面 EINTR 分流的唯一单点本体：信号中断慢调用后，判定器收四输入——SA_RESTART 是否置位（F9013 查询）、信号是否被掩蔽（F9022）、慢调用类别（可重启/不可重启）、号是否在重启白名单——四输入决定"自动重启"或"返 EINTR"。F8948（B07 锚点）在本条升级为完整判定器，全号面仅此一处分流。
- **语义边界**：只管判定器本体与白名单；SA_RESTART 旗标读取协议归 F9013（本条消费其查询函数）、restart_syscall 显式重启号归 F9022、各慢调用自身的中断点检查在调用实现内（本条只定义判定接口）。F8948 锚点格保留为回归对照，不再承载新逻辑。
- **依赖与嫁接源**：嫁接 signal(7) "Interruption of system calls" 节与 restart_syscall(2) 背景说明（白名单体例对齐 Linux kernel `syscall_restart` 机制）；锚定 F9013 `read_restart_flag`、F9002 掩码集、F9005 TrapFrame 改写原语、F8948 锚点格回归；`SyscallMeter` 记 restart/eintr 双计数。
- **风险与回退**：风险一为判定器被绕行（某慢调用自行返 EINTR 不经单点）——回退为单点唯一性审计：grep 全慢调用实现的中断分支，返 EINTR 出口必须经本判定器函数，审计脚本断言零绕行；风险二为白名单遗漏导致 read 被无谓报错——回退为白名单以 Linux 语义为准（read/write/wait4/poll/epoll_wait/futex/accept 等），ktest 逐号断言。
- **正文**：实现路径分三步：第一步立四输入判定器——`eintr_decide(frame, sig, call_class) -> Restart|Eintr`：输入一 SA_RESTART 位（F9013 查询）、输入二投递时掩码态（掩蔽信号在出 handler 后自动恢复掩蔽，不触发重启判定——登记边界格）、输入三慢调用类别（慢调用清单在册：IO/等待/IPC 三类）、输入四白名单成员判定；四输入 AND 语义：全可重启才 Restart；第二步铺全组合矩阵——四输入理论上 16 组合，有效组合 8 组（掩蔽格独立单测），每组登记期望行为，ktest 以注入式逐组断言；第三步立单点唯一性审计——全号面 grep `EINTR` 出口：除本判定器外仅 signalfd/timerfd 等登记特例（对齐 Linux），审计清单落账，漂移格零容忍。与现存内核衔接点：判定器挂在 F9005 sigreturn 恢复路径之后（handler 返回→判定→改帧重启或返 EINTR）；重启实现调 F9005 TrapFrame.rip 回退原语；meter 双计数与 F9020/F9040 断言对账。与 Windows 对照：Windows 同步 IO 无信号中断概念，取消走 CancelIoEx 显式接口；Varix 单点判定把 POSIX 历史发散行为（BSD/SYSV 两大流派）收敛为一处可审计逻辑。判据 UNX-F9021-J1 的复测方式：ktest 四断言——8 组合矩阵逐组断言、白名单外号（如 getpid 类快调用概念不存在中断）不重启、grep 审计零绕行、meter restart+eintr 计数=中断总数。

### UNX-F9022 · restart_syscall 挂点
- 域/批：C2/B12｜判据：UNX-F9022-J1 重启号面挂点注册判据过，重启上下文（原号+参数快照）保存恢复判据过，无上下文调用返 EINVAL 格过｜纯功能行数：180 行（挂点注册 60 + 上下文快照器 70 + EINVAL 格 50）｜状态：[已深化]

- **定位**：本条立 restart_syscall 号的挂点档：SIGSTOP→SIGCONT 周期后部分系统调用（如 nanosleep）需"带剩余参数重启"，内核把原号+参数快照存于任务，用户态 handler 返回后经 restart_syscall 显式重放。它是 F9021 判定器的特殊重启路径（信号场景特例：普通重启改帧重入，本号走显式号面）。
- **语义边界**：只管 restart_syscall 号面挂点与上下文协议；判定器主体归 F9021（本条是其"快照重启"分支的号面出口）、nanosleep 的 rem 回填归 B06 F8903（EINTR rem 格）、白名单内号的重启参数构造归各调用自身登记。
- **依赖与嫁接源**：嫁接 restart_syscall(2) man-pages（"restart a system call interrupted by a stop signal"）；锚定 F9021 判定器分支、C1 任务控制块上下文槽位、F8923 EINVAL 编码；快照结构对齐 Linux `restart_block` 体例（原号/参数/剩余时间三件）。
- **风险与回退**：风险一为快照悬垂（保存的参数指针指向已释放用户内存）——回退为快照只存值参，指针参数一律不可快照重启（降级返 EINTR）并登记约束；风险二为无上下文调用被误放行——回退为挂点入口先查上下文槽位，空则 EINVAL，ktest 断言。
- **正文**：实现路径分三步：第一步立挂点注册——`SYSCALLS` 表登记 restart_syscall 号，`NrVerdict::Implemented`，入口 `restart_syscall_impl` 直查任务上下文槽位；第二步立上下文快照器——F9021 判定器走"快照重启"分支时（nanosleep 类需剩余时间的调用），把原号/值参/剩余时间三件存入 `RestartBlock`，挂点入口解包后按原号转接对应实现（当前支持 nanosleep 转接，余号登记待扩）；恢复即重放，重放失败按普通错误路径走 F8923；第三步铺 EINVAL 格——上下文槽位空（用户态直接调 restart_syscall 或快照已消费）时返 EINVAL，ktest 断言。与现存内核衔接点：挂点与 F9021 单点共享 `RestartBlock` 类型（单源定义）；nanosleep 转接复用 B06 实现与 rem 回填格。与 Windows 对照：Windows 无等价机制（可等待对象超时由系统管理）；restart_syscall 是 Linux 对"睡眠类调用必须可恢复"语义的补丁形态，Varix 号面兼容必须登记。判据 UNX-F9022-J1 的复测方式：ktest 四断言——nanosleep 被 STOP/CONT 打断后经 restart_syscall 重放且 rem 保真、无上下文直接调用返 -22、快照消费后二次调用返 -22、指针参数调用降级返 EINTR 登记。

### UNX-F9023 · pipe/pipe2 本体档（PipeTable 对齐）
- 域/批：C2/B12｜判据：UNX-F9023-J1 双 fd（读/写端）分配判据过，O_NONBLOCK/O_CLOEXEC 旗标矩阵判据过，读写端闭环 10^3 次零失真判据过｜纯功能行数：280 行（双端分配器 100 + 旗标矩阵 90 + 闭环压测 90）｜状态：[已深化]

- **定位**：本条是 IPC 挂点族的本体头档：pipe/pipe2 创建匿名管道，`PipeTable` 存量档升级接管——分配读/写两个 fd（读端只读、写端只写）、pipe2 带旗标装载（O_NONBLOCK/O_CLOEXEC）。管道是 shell 管道线（busybox `|`）与 self-pipe 技巧的消费基座，B10 管道消费档（F8995）与本条对接。
- **语义边界**：只管 pipe/pipe2 创建与双端 fd 分配；容量与阻塞语义归 F9024、epoll 联动归 F9037、F_SETPIPE_SZ 联动格归 F9024（fcntl 侧归 B08 F8944）；fork 继承管道 fd 归 B04 fd 表继承语义（引用本条）。
- **依赖与嫁接源**：锚定现存 `syscall::calls::PipeTable` 存量档升级接管、`FdTable`/`FdEntry`/`FdKind`（B07 F8916 族）、`copy_to_user` 写回双 fd、F8923 EFAULT 编码；pipe2 嫁接 pipe2(2) 旗标语义；F8919 FdTable 断言借力。
- **风险与回退**：风险一为双 fd 分配原子性破缺（读端分配成功写端 EMFILE）——回退为 fd 表预占两槽位再落账，失败全回滚，杜绝半管道；风险二为旗标矩阵漏格（O_CLOEXEC 未登记 exec 扫描）——回退为旗标装载直通 F8916 CLOEXEC 扫描链，ktest 双格断言。
- **正文**：实现路径分三步：第一步立双端分配器——`pipe2_impl(filedes, flags)`：校验 flags 合法位（O_NONBLOCK|O_CLOEXEC，越位 EINVAL），`PipeTable` 建环形缓冲对象，`FdTable` 预占两槽位（读端 FdKind::PipeRead/写端 FdKind::PipeWrite，方向权限在 fd 层强制——写读端返 EBADF 格登记），成功后 `copy_to_user` 写回双 fd；第二步铺旗标矩阵——O_NONBLOCK 置位→两端非阻塞（读写满/空即 EAGAIN）、清零→阻塞；O_CLOEXEC 置位→execve 扫描链关闭，四组合矩阵 ktest 断言；第三步立闭环压测——写端写→读端读 10^3 次随机长度字节流，逐字节比对零失真，meter 记管道 IO 计数。与现存内核衔接点：`PipeTable` 单源升级（防重：不立第二张管道表）；双 fd 回收与 B08 close 引用计数链对接；B10 F8995 消费档经本条的 fd 句柄读数。与 Windows 对照：Windows 匿名管道 CreatePipe 单向双句柄同神，但句柄非 fd 空间；Varix 管道入 fd 表统一 epoll 消费，是 busybox 管道线的直接底座。判据 UNX-F9023-J1 的复测方式：ktest 四断言——双 fd 分配且方向权限正确、四旗标组合矩阵全过、10^3 闭环零失真、写读端返 EBADF 格登记。

### UNX-F9024 · 管道读写阻塞语义与容量（F_SETPIPE_SZ 联动）
- 域/批：C2/B12｜判据：UNX-F9024-J1 默认 64KiB 容量判据过，写满阻塞/NONBLOCK EAGAIN 双路径判据过，原子写边界（≤PIPE_BUF 4KiB 不撕裂）判据过｜纯功能行数：260 行（容量引擎 90 + 阻塞双路径 90 + 原子边界格 80）｜状态：[已深化]

- **定位**：本条立管道的容量与阻塞语义本体：默认 64KiB 环形缓冲、写满阻塞（或 NONBLOCK 返 EAGAIN）、PIPE_BUF（4KiB）原子写边界——≤4KiB 的写要么整体可写入要么不写不撕裂。这是多写者管道（shell 多进程同写）不串字的命门语义。
- **语义边界**：只管容量/阻塞/原子边界；创建与双端分配归 F9023、epoll 就绪联动归 F9037、F_SETPIPE_SZ 改容的 fcntl 侧指令归 B08 F8944（本条消费其改容回调改环形缓冲容量，登记单源协议）；读端 EOF 语义（写端全关→read 返 0）在本条登记。
- **依赖与嫁接源**：嫁接 pipe(7) 手册页（默认容量 65536 字节、PIPE_BUF 4096 原子写、最小容量页大小体例）；锚定 F9023 `PipeTable` 对象、F8923 EAGAIN 编码、A3 `WaitQueue`（读/写等待队列两根）、B08 F8944 改容回调接口。
- **风险与回退**：风险一为改容与并发读写竞态（缩容截断在途数据）——回退为改容回调持管道互斥、缩容仅在空管道时生效否则 EBUSY（对齐 Linux），登记约束；风险二为原子写在大缓冲下的撕裂窗口——回退为写路径前置判定：len≤PIPE_BUF 且缓冲剩余<len 时整写挂起（阻塞/返 EAGAIN），绝不部分写入。
- **正文**：实现路径分三步：第一步立容量引擎——环形缓冲默认 64KiB，容量可变区间 [4KiB, 1MiB]，改容走 B08 F8944 回调（单源）；读路径空时挂读等待队列（阻塞模式）或返 EAGAIN（NONBLOCK）；第二步铺阻塞双路径——写满时：阻塞模式挂写等待队列、读者消费唤醒；NONBLOCK 直接 EAGAIN；读端全关时写返 EPIPE 并投递 SIGPIPE（F9003 引擎，B02 锚点格联动）；写端全关时读返 0（EOF）——两 EOF/EPIPE 格是管道语义收尾件；第三步立原子边界格——len≤PIPE_BUF 的写为原子：判定"剩余容量≥len 或缓冲空且 len≤容量"才启动拷贝，一次 `copy_from_user` 进缓冲；len>PIPE_BUF 允许部分写（返回写入数），ktest 以"多写者并发各写 512B×10^3 次，读端按块解析零串字"复测。与现存内核衔接点：等待唤醒走 F9037 epoll 联动与 A3 `WaitQueue` 双通；SIGPIPE 投递经 F9003 单引擎。与 Windows 对照：Windows 匿名管道默认缓冲 4KiB 且无 PIPE_BUF 原子承诺文档化；Varix 4KiB 原子边界是 POSIX 并发 shell 脚本正确性的内核保证。判据 UNX-F9024-J1 的复测方式：ktest 五断言——默认容量读回 65536、写满阻塞后读者消费唤醒、NONBLOCK 写满返 EAGAIN、≤4KiB 并发写零撕裂、读端全关写返 EPIPE 且 meter 记 SIGPIPE 投递一次。

### UNX-F9025 · socket 基座挂点（socket/bind/listen 登记档）
- 域/批：C2/B12｜判据：UNX-F9025-J1 三号挂点注册判据过，AF_UNIX/AF_INET 域校验判据过，防重：协议栈本体归 B2（AI-07）不重铺声明落账｜纯功能行数：260 行（三号挂点注册 90 + 域校验器 80 + 防重声明格 90）｜状态：[已深化]

- **定位**：本条立 socket 基座三号挂点登记档：socket（创建）/bind（命名）/listen（监听）三号在本域只立"号面挂点 + 参数形状 + 域校验"，协议栈本体（网络栈、AF_UNIX 传输）归 B2 网络域（AI-07）不重铺。挂点的作用是让号面协议（参数/错误码/ABI）先行冻结，B2 本体落位时零号面改动。
- **语义边界**：只管三号挂点与域校验；connect/accept/send/recv 四 IO 挂点归 F9026、sendmsg/recvmsg ABI 归 F9027、AF_UNIX 命名空间细节挂点归 F9028；协议栈数据面/控制面全部归 B2（防重核心声明）。
- **依赖与嫁接源**：嫁接 socket(2)/bind(2)/listen(2) 参数语义与地址族表；锚定 `SYSCALLS` 表挂点注册机制、F8921 abi_negotiate 协商面、F8923 错误编码（EAFNOSUPPORT/EINVAL/EADDRINUSE 期望码登记）、`FdEntry`（socket fd 归 FdKind::Socket 登记）。
- **风险与回退**：风险一为挂点与 B2 本体接口漂移（参数形状两套）——回退为挂点档即接口契约：B2 落位必须实现挂点定义的 `SocketOps` trait，号面零改动；风险二为域校验误放未知族——回退为 AF 白名单（UNIX/INET/INET6 登记），未知族返 EAFNOSUPPORT。
- **正文**：实现路径分三步：第一步立三号挂点——socket(domain,type,protocol) 挂点校验参数形状并登记 `FdKind::Socket`、bind/listen 挂点登记地址与积压参数形状，三号入口当前收口返 -ENOSYS（B2 未落）或转接 B2 已落接口（占位判断），`SYSCALLS` 表挂 `NrVerdict::NotYet` 与 RouteNote::Delegated 双态登记；第二步立域校验器——AF_UNIX（1）/AF_INET（2）/AF_INET6（10）白名单，SOCK_STREAM/SOCK_DGRAM/SOCK_SEQPACKET 三型登记，protocol 语义（AF_UNIX 恒 0、INET 的 IPPROTO_TCP/UDP）登记到挂点档；第三步落防重声明格——协议栈本体（IP/TCP/UDP/UNIX 传输实现）归 B2 域 AI-07，本条号面档案移交 B2 承办方消费，声明落账入 COMPAT_TABLE 注记与 F9095 跨域协议。与现存内核衔接点：挂点经 `route_incoming` C2 段分发、fd 登记复用 F8916 `FdEntry`；错误码表与 B2 共用 F8923 单点。与 Windows 对照：Winsock 内核态 AFD 驱动承载 socket；Varix 挂点先行的协议与 B2 分工是 40 域并行开发的接缝标准件。判据 UNX-F9025-J1 的复测方式：ktest 四断言——三号挂点在 `SYSCALLS` 表登记查得、AF 未知值返 EAFNOSUPPORT 期望格、socket fd 归 FdKind::Socket、防重声明在 COMPAT 注记可 grep。

### UNX-F9026 · socket connect/accept/send/recv 挂点
- 域/批：C2/B12｜判据：UNX-F9026-J1 四 IO 挂点注册判据过，慢调用 EINTR 联动（F9021 判定器消费）判据过，未连接 fd 操作返 ENOTCONN 格过｜纯功能行数：260 行（四挂点注册 100 + EINTR 联动格 80 + ENOTCONN 格 80）｜状态：[已深化]

- **定位**：本条立 socket 数据面四 IO 挂点档：connect（主动连接）/accept（接受连接）/send（发送）/recv（接收）四号挂点登记，重点冻结两件：四 IO 全部是慢调用（必须经 F9021 EINTR 判定器联动）、未连接状态下操作的 ENOTCONN 格。数据面本体仍归 B2（F9025 防重声明延续）。

### UNX-F9033 · IPC 键空间与 ftok 语义
- 域/批：C2/B12｜判据：UNX-F9033-J1 ftok 派生键（st_ino/st_dev 混合）判据过，IPC_PRIVATE 特殊键判据过，键冲突查询挂点判据过｜纯功能行数：160 行（ftok 派生器 70 + PRIVATE 键格 40 + 冲突查询格 50）｜状态：[已深化]

- **依赖与嫁接源**：嫁接 ftok(3) 派生算法原文（"the low-order 8 bits of st_dev, the low-order 16 bits of st_ino, the low-order 8 bits of proj_id"）；锚定 B1 stat 通路（ino/dev 两字段）、F8923 ENOENT（路径不存在）编码、三族挂点消费接口。
