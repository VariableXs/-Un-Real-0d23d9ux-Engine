### UNX-F10401 · pipe2 环形缓冲区对象与回绕语义
- 域/批：C4/B01｜判据：UNX-F10401-J1 环形回绕读写 100 万次零错位，写端全关后 read 返 0（EOF），读端全关后 write 触发 SIGPIPE（SIG_IGN 设置下返 EPIPE）｜纯功能行数：340 行（环形缓冲体 120 + 回绕游标 90 + EOF/SIGPIPE 判定 70 + 统计账 60；测试段不计）｜状态：[已深化]
- **定位**：环形缓冲是 C4 域一切字节流通路的地基——管道、pty 主从通路、行规程输入缓冲共用同一缓冲内核。本条把"pipe 有个缓冲"升级为"回绕语义可证"：读写游标在缓冲尾部的回绕推进、已用字节数的不变式、EOF 与 EPIPE 两个终态判定一次建齐。
- **语义边界**：只做环形缓冲体与回绕游标及两个终态判定；不做 fd 分发（F10403）、不做等待队列（F10408）、不做容量设置（F10404）。缓冲体默认 64KB 单块连续分配，不切页池（页池化是 splice 条目 F10427 的边界）。
- **依赖与嫁接源**：分配消费 mem/heap.rs 内核堆；嫁接源为 Linux pipe_buffer 环形组织语义与 POSIX pipe(2) 返回值约定，只跟随；EOF/SIGPIPE 判定与 C1 信号投递面（F10406）接口对齐。
- **风险与回退**：回绕边界 off-by-one 是本条头号风险——以"先推进后写、先读后推进"的单一游标约定消除歧义，不变式（used == wr - rd 模长）每千次断言一次，破坏即 panic 带双方游标快照。
- 正文：实现路径分三步。第一步缓冲体与游标：`PipeRing` 结构持有 64KB 连续缓冲、`rd`/`wr` 两游标与 `used` 计数，读路径先拷贝后推进、写路径先写入后推进，两游标只增取模，禁止原地回退；第二步回绕正确性：写跨越缓冲尾时拆成两段拷贝（尾段+头段），读同理，任何一次操作后断言 used 与两游标差值取模相等，不变式破坏即 panic 并附游标快照；第三步终态判定：`writer_alive`/`reader_alive` 双标志分别由端点关闭路径清除，写侧发现 reader_alive 为假走 SIGPIPE/EPIPE 分支（F10406），读侧发现 writer_alive 为假且 used 为零返 0，used 非零仍继续供数。与现存内核衔接点：分配走 `mem::heap`，结构置于新模块 `proc/ipc/pipe.rs`（与既有 `proc/ipc.rs` 端口总线并列注册，不改动其语义），统计字段供 F10412 账本消费。与 Linux 对照：Linux pipe 的环形 buffer 数组在 fcntl(F_GETPIPE_SZ) 下可见容量语义一致，判据 UNX-F10401-J1 的复测方式：ktest 回绕压测 100 万次读写校验和比对零错位、EOF/EPIPE 双终态各注入 10/10 次按语义返回。

### UNX-F10402 · 管道对象生命周期与读写端引用计数
- 域/批：C4/B01｜判据：UNX-F10402-J1 最后一个端点关闭时对象回收，回收前读写端计数与 fd 表引用数三方一致，计数差非零即红账｜纯功能行数：320 行（引用计数器 90 + 释放时序状态机 120 + 三方对账钩子 110；测试段不计）｜状态：[已深化]
- **定位**：管道对象横跨多个进程的 fd 表——fork、dup、exec 每一步都在改变"还有谁握着这根管子"。本条建立读写两端各自独立的引用计数与释放时序状态机，把"最后一端关闭"从约定变成可审计事实，泄漏与 use-after-free 在结构上排除。
- **语义边界**：只做对象级引用计数与释放时序；不做 fd 表本体（C1 域）、不做端点级 O_NONBLOCK（F10410）。读写端计数彼此独立：读端归零即走 reader 释放分支，写端归零即走 writer 分支，两侧都归零才回收缓冲体。
- **依赖与嫁接源**：消费 C1 fd 表的关闭回调挂点（与 F10407 fork 继承同点）；嫁接源为 Linux pipe_inode_info 引用模型与 POSIX "全部写端关闭"措辞，只跟随。
- **风险与回退**：释放与唤醒的时序竞态（关端点的同一瞬间对端阻塞中）——释放状态机先摘等待队列再清标志，摘除动作持队列自旋锁，阻塞者醒来即见终态标志，不存在"醒来读已释放对象"的窗口。
- 正文：实现路径分三步。第一步双端引用计数：`PipeEnd` 各持 `refs` 原子计数，fd 表安装、dup、fork 继承各 +1，close/dup2 覆盖各 −1，减到零触发该端释放；第二步释放时序状态机：端释放分四拍——摘等待队列、清 alive 标志、唤醒对端、最后归还缓冲份额，任何一拍失败显式记账不静默，全拍完成才允许对象析构；第三方三方对账：析构前对账钩子比对 fd 表侧引用快照、双端计数、缓冲持有标志三项，差值非零打红账并拒绝析构（对象保留至差账清零，防 use-after-free）。与现存内核衔接点：fd 关闭回调走 `proc/ring3.rs` 进程退出清扫路径注册的钩子位，管道模块提供 `on_fd_close` 单入口。与 Linux 对照：lsof 类工具对同一管道多进程持有的引用呈现与计数账一致，判据 UNX-F10402-J1 的复测方式：ktest 构造 fork/dup/close 混合序列 1 万轮，末态回收守恒 10/10 次、注入计数错位用例 10/10 次红账拦截。

### UNX-F10403 · pipe2 fd 端点分发与 flag 组合
- 域/批：C4/B01｜判据：UNX-F10403-J1 pipe2(fds, O_NONBLOCK|O_CLOEXEC) 后 F_GETFD 含 CLOEXEC 位、F_GETFL 含 O_NONBLOCK 位，两端标志独立可查｜纯功能行数：300 行（fd 安装 100 + flag 通路 100 + 双端独立账 100；测试段不计）｜状态：[已深化]
- **定位**：pipe2 是管道世界的唯一入口 syscall，fd 与标志的第一次分发决定后续全部行为。本条把"拿到两个 fd"细化为"CLOEXEC 在 fd 层、O_NONBLOCK 在文件层、两端口径严格分离"，shell 与 daemon 化程序对标志的每一条假设在此兑现。
- **语义边界**：只做 pipe2 入口分发与两级标志挂接；不做 exec 时 CLOEXEC 关闭动作本体（C1 exec 路径，本条只保证标志位在 fd 表上正确登记）、不做 O_NONBLOCK 行为差异（F10418）。
- **依赖与嫁接源**：fd 安装消费 C1 fd 表接口；号面注册消费 C2 `syscall/table.rs` 兼容段（Linux compat band 0x4100）；嫁接源为 pipe(2) 手册 flags 语义与 fcntl(2) F_GETFD/F_GETFL 分层，只跟随。
- **风险与回退**：两级标志混挂是经典错法（把 NONBLOCK 写进 fd 标志）——分发器以类型化结构传递两级标志，编译期禁止互灌，混挂用例进 ktest 常驻。
- 正文：实现路径分三步。第一步端点构造：pipe2 内部先建管道对象（F10401/F10402）与读写两 `PipeEnd`，再向 C1 fd 表连续安装两个描述字，安装顺序固定读端在前写端在后，失败路径成对回滚不留半装态；第二步两级标志：O_CLOEXEC 落 fd 表条目的 close-on-exec 位（F_GETFD 视角），O_NONBLOCK 落端点文件状态字（F_GETFL 视角），两级各自独立读写；第三步双端独立账：每端标志独立存取，读端设 NONBLOCK 不影响写端，反之亦然，标志快照可经 F10412 账本导出。与现存内核衔接点：号面走 `syscall/table.rs` 兼容段注册（表驱动而非散布），错误编码走 `syscall/errno.rs`，参数校验复用 `syscall/uaccess.rs` 用户指针判界。与 Linux 对照：busybox sh 的 daemon 化路径以 pipe2(O_CLOEXEC) 起手，行为完全同源，判据 UNX-F10403-J1 的复测方式：ktest 四组 flag 组合（none/NB/CE/both）各 100 次，F_GETFD/F_GETFL 位断言 100% 一致，exec 后 fd 关闭行为随 C1 联测确认。

### UNX-F10404 · 管道容量与 F_SETPIPE_SZ/F_GETPIPE_SZ
- 域/批：C4/B01｜判据：UNX-F10404-J1 默认 64KB 档，设置 1KB–1MB 内 2 次幂容量生效，非 2 次幂向上取整落账，越界 EINVAL｜纯功能行数：300 行（容量查询 70 + 设置与取整 120 + 越界拒绝 110；测试段不计）｜状态：[已深化]
- **定位**：管道容量决定吞吐与回压行为的物理上限——splice 与高频 IPC 都要按容量调优。本条实现 fcntl 两号对容量的查询与设置，把"64KB 默认"从常量升级为可调、可查、有边界的账面事实。
- **语义边界**：只做容量账与设置语义；不做容量变化时的数据搬迁保证（已存数据超新容量的拒绝语义照 Linux：设置值小于已用字节返 EBUSY）；不做 splice 页池（F10427）。
- **依赖与嫁接源**：消费 F10401 缓冲体；嫁接源为 Linux fcntl(2) F_SETPIPE_SZ 语义（含上限 pipe-max-size 特权判断），只跟随。
- **风险与回退**：非 2 次幂取整造成实际容量与请求值偏差——偏差向上取整并落账，查询返回实际容量而非请求值，与 Linux 对齐，杜绝"设了 3KB 当 3KB 用"的假象。
- 正文：实现路径分三步。第一步查询：F_GETPIPE_SZ 返回当前容量字节数，默认档 64KB，随对象账（F10412）可导出；第二步设置：F_SETPIPE_SZ 校验请求值落在 1KB–1MB 区间（区间可由引导参数调宽，走 C2 cmdline 白名单），非 2 次幂向上取整，取整结果落账并生效——生效路径按"新容量 ≥ used 直接改容量；新容量 < used 返 EBUSY"两分支，改容量动作持管道锁原子完成；第三步越界拒绝：低于 1KB 或高于上限返 EINVAL/EPERM 分码（上限越权 EPERM，格式非法 EINVAL），拒绝行为与理由入账。与现存内核衔接点：fcntl 号面经 C2 分发表挂号（本批 F10415 协议），容量字段并入 F10401 `PipeRing`。与 Linux 对照：`fcntl(fd, F_GETPIPE_SZ)` 在基准机与 Varix 同值同态，判据 UNX-F10404-J1 的复测方式：2 次幂设置 10 档全生效、非 2 次幂取整 10/10 次落账正确、used 超新容量用例 10/10 次 EBUSY、越界用例 10/10 次分码正确。

### UNX-F10405 · 写端全关 EOF 语义链
- 域/批：C4/B01｜判据：UNX-F10405-J1 写端计数归零后未读完数据仍可读尽，读尽后 read 恒返 0，poll 同步报 POLLHUP｜纯功能行数：260 行（EOF 判定 90 + 余量读尽 80 + POLLHUP 挂点 90；测试段不计）｜状态：[已深化]
- **定位**：EOF 是 Unix 字节流世界的"说完了吗"——shell 关闭写端等待子进程输出的每一条流水线都踩在这条语义上。本条钉死"写端归零 ≠ 立即断流"的时序：余量优先、读尽才 EOF、poll 同步可见。
- **语义边界**：只做 EOF 判定链；不做写端关闭动作本体（F10402 释放状态机）、不做 SIGPIPE（F10406，那是读端方向）。
- **依赖与嫁接源**：消费 F10401 终态标志与 F10402 写端计数；嫁接源为 read(2) 返回 0 的 POSIX 定义与 poll(2) POLLHUP 语义，只跟随。
- **风险与回退**："先到 EOF 还是先到 EAGAIN"的歧义（非阻塞 + 余量 + 写端已关）——判定顺序钉死为"余量优先于 EOF、EOF 优先于 EAGAIN"，顺序写进判据防止实现漂移。
- 正文：实现路径分三步。第一步判定链：read 入口按三段判定——used > 0 时无论写端死活都供数（余量优先）；used == 0 且 writer_alive 为假返 0；used == 0 且写端活着按阻塞/非阻塞分路（F10408/F10418）；第二步读尽同步：最后一次供数的同时检查写端已死，本次即返短读，下次返 0，两次返回之间不存在"数据消失"窗口，供数与标志检查持同一把管道锁；第三步 poll 挂点同步：POLLHUP 的上报条件钉死为"写端死且 used == 0"，余量期间 poll 只报 POLLIN 不报 HUP，与 read 视角完全一致，防止"读得到数据 poll 却说挂断"的精神分裂态。与现存内核衔接点：判定链置于 `proc/ipc/pipe.rs` 读路径头部，poll 挂点与 F10409 共用 poll 表。与 Linux 对照：`cat file | head -c 10` 场景中 head 退出后 cat 的写端行为与余量读取时序同源，判据 UNX-F10405-J1 的复测方式：写端关后余量 100/100 次可读尽、读尽后 read 恒 0 连续 1 千次、POLLHUP 与 read 视角 100 次零矛盾。

### UNX-F10406 · 读端全关 SIGPIPE 触发链
- 域/批：C4/B01｜判据：UNX-F10406-J1 读端计数归零后 write 返 EPIPE 并投递 SIGPIPE，SIG_IGN 下不投递仅返 EPIPE，死亡判据落账｜纯功能行数：300 行（死亡判定 90 + 投递链 110 + SIG_IGN 分支 100；测试段不计）｜状态：[已深化]
- **定位**：SIGPIPE 是管道的"断线枪声"——`head` 提前退出后 `yes` 被一枪毙命，全靠这条链。本条实现读端死亡→write 时点判死→投递/返错的完整链，与信号域（B03/B04）接口对齐。
- **语义边界**：只做管道侧判死与投递请求；不做信号投递机制本体（B03 域 F10444）、不做 SIG_IGN 的处置表登记（信号域条目）。死亡时点语义按 Linux：判死发生在 write 尝试写入之前。
- **依赖与嫁接源**：投递请求走 B03 信号投递入口（kill 类路径）；嫁接源为 write(2) EPIPE/SIGPIPE 联动语义与 Linux pipe_write 判死位置，只跟随。
- **风险与回退**：判死与投递之间的竞态（write 检查时读端活着、写入瞬间关闭）——判死持管道锁，判死后才动缓冲，读端关闭路径也持同一把锁摘队列，两侧在锁上串行化，竞态窗归零。
- 正文：实现路径分三步。第一步判死：write 入口持锁检查 reader_alive，为假即进入 EPIPE 分支，判死点在一切缓冲写入之前——保证"读端死后半字节都不进缓冲"；第二步投递链：判死后向当前进程发 SIGPIPE 投递请求（默认处置为终止进程），投递请求与 EPIPE 返回值同拍产出，进程若已设置 SIG_IGN 则跳过投递仅返 EPIPE，SIG_DFL/SIG_IGN 两分支判据分立；第三步死亡判据落账：每次判死事件写入管道账本（时间戳、写端 fd、SIGPIPE 处置档位），账本随 F10412 可导出——排疑手册"程序莫名消失"类问题从此有账可查。与现存内核衔接点：投递请求调 B03 信号域注册的 `signal::deliver_request` 接口（F10415 挂号协议的一部分），判死逻辑置于 pipe 写路径头部。与 Linux 对照：`yes | head -1` 在基准机上 yes 死于 SIGPIPE，Varix 同场景同死法，判据 UNX-F10406-J1 的复测方式：DFL 档 10/10 次进程终止、IGN 档 10/10 次返 EPIPE 存活、判死事件账 10/10 次与进程终态对上。

### UNX-F10407 · fork 继承管道端点与共享对象语义
- 域/批：C4/B01｜判据：UNX-F10407-J1 fork 后父子跨进程读写同一缓冲 10 万次零错序，对象不复制，引用计数 +1 留账｜纯功能行数：320 行（继承挂点 100 + 共享断言 110 + 计数留账 110；测试段不计）｜状态：[已深化]
- **定位**：管道的使命就是跨进程——fork 继承是它的成年礼。本条钉死"fork 不复制管道对象、只复制 fd 指向"的共享语义，父子进程从此读写字节流如同同一进程的两根手指。
- **语义边界**：只做 fork 继承挂接与共享语义断言；不做 fd 表复制本体（C1 fork 路径）、不做 exec 后端点关闭策略（F10403 CLOEXEC 位与 C1 联动）。
- **依赖与嫁接源**：继承挂点消费 C1 fork 的 fd 表复制回调；嫁接源为 fork(2) "副本共享打开文件描述"语义与 POSIX pipe 继承约定，只跟随。
- **风险与回退**：继承后引用计数与 fd 表三方漂移（F10402 对账钩子）——对账钩子在 fork 完成点强制跑一次，漂移即红账拒绝 fork 返回，把问题挡在出生时而非收尸时。

### UNX-F10415 · pipe2 与 C2 挂号注册协议联签
- 域/批：C4/B01｜判据：UNX-F10415-J1 pipe2 经 syscall/table.rs 号段注册分发，错误码统一走 errno.rs 编码器，表内可查号可查名可查能力位｜纯功能行数：280 行（号面注册 100 + 分发挂接 90 + 能力位对账 90；测试段不计）｜状态：[已深化]
- **定位**：C2 的挂号注册协议是 C4 全域的"过闸手续"——每个对外 syscall 都要在分发表里有名有号有能力位。本条以 pipe2 为第一个过闸件，把注册协议、错误编码器、能力位对账三件事一次联签落地，为后续 14 批立样板。
- **语义边界**：只做 pipe2 的注册与联签；不做分发表本体改造（C2 域设施零改动，本条是消费方）、不做其他入口（各批自带联签条目）。
- **依赖与嫁接源**：上游 C2 `syscall/table.rs` 号段（Linux compat band 0x4100）、`syscall/guard.rs` 能力位（CAP_FS）、`syscall/errno.rs` 编码器；嫁接源为 C2 冻结接口"挂号注册协议"条文，只跟随。
- **风险与回退**：号段冲突（兼容段满或撞号）——注册动作先查号后落表，撞号显式失败并拒绝引导，绝不静默改号；能力位选错降级路径：CAP_FS 缺失时返 EPERM 不返 ENOSYS，语义可辨。
- 正文：实现路径分三步。第一步注册：pipe2 以（号、名、arity、CAP_FS、无锁快速路径标志）五元组落 `syscall/table.rs` 兼容段，落表即自检——号在段内、名唯一、arity 与实现签名一致；第二步分发挂接：表项 handler 指向管道模块入口，入口内部只做参数判界与业务分发，错误一律经 `errno.rs` 编码器原样上抛，私造码在代码评审断言中拒绝；第三步能力位对账：注册后跑一遍表级自洽断言（号段区间、能力位白名单、handler 非空三查），结果落账——C4 域后续每一批的联签条目复用本条的注册样板。与现存内核衔接点：`table.rs` 的注册接口零改动消费，`guard.rs` 能力位按 C2 冻结语义取用。与 Linux 对照：`ausyscall --dump` 类号表可见性与本表同构，判据 UNX-F10415-J1 的复测方式：表内查 pipe2 号/名/能力位 10/10 次一致、错误码经编码器 10/10 次正确、撞号注入用例 10/10 次显式失败。

### UNX-F10416 · 管道小写原子保证（<PIPE_BUF 单写者视角）
- 域/批：C4/B01｜判据：UNX-F10416-J1 单写者 <4KB 写入在读侧呈现为连续字节序列，阻塞写被打断后不产生半条交错｜纯功能行数：280 行（原子写判定 100 + 交错检查器 90 + 打断恢复 90；测试段不计）｜状态：[已深化]
- **定位**：POSIX 承诺：不超过 PIPE_BUF 的写是原子的——日志行、消息帧、协议头全押在这条承诺上。本条把"原子"落实为"持锁单段入缓冲"，半条交错在结构上不可能。
- **语义边界**：只做小写原子路径；不做多写者大块交错规则（F10417）；不做 PIPE_BUF 边界精确值压测（B02 F10421 专批）。原子域：单次 write 调用 ≤ PIPE_BUF。
- **依赖与嫁接源**：消费 F10401 缓冲与管道锁；嫁接源为 POSIX "writes of {PIPE_BUF} bytes or less shall not be interleaved" 条文，只跟随。
- **风险与回退**：容量不足以容纳整块（空管容量 1KB < 请求 2KB）——按 POSIX：阻塞档等待至整块可容，非阻塞档返 EAGAIN，绝不写半块，两种分路都进判据。
- 正文：实现路径分三步。第一步原子写路径：len ≤ PIPE_BUF 的 write 持管道锁一次性入缓冲——锁内完成容量检查、两段拷贝（回绕拆段）、游标推进，出锁时数据完整可见，读侧在锁外观察永远看到整块；第二步交错检查器：读侧校验器以"帧长+帧校验和"协议识别写入块，压测中每块与写入方注册的内容逐字节比对，块内撕裂检出即红；第三步打断恢复：阻塞档容量不足时入睡（F10408 队列），信号打断返 EINTR 且缓冲零触碰——"打断不留半条"由写前占位检查保证：占位不成功就不动缓冲。与现存内核衔接点：PIPE_BUF 常量 4096 与 F10404 容量档解耦（容量可小于 PIPE_BUF，此时原子域收缩为容量值——POSIX 允许的最小保证）。与 Linux 对照：基准机 `printf | cat` 帧完整性同语义，判据 UNX-F10416-J1 的复测方式：单写者 1 万帧零撕裂、打断用例 10/10 次零半条、容量不足两分路 10/10 次语义正确。

### UNX-F10417 · 管道多写者交错记账
- 域/批：C4/B01｜判据：UNX-F10417-J1 4 写者并发大块写入允许交错但每块内部完整，块边界标记 100 万次零撕裂｜纯功能行数：280 行（并发写路径 100 + 块校验协议 90 + 交错账 90；测试段不计）｜状态：[已深化]
- **定位**：POSIX 对超过 PIPE_BUF 的写明说"不保证原子、数据交错"——但"允许交错"不等于"允许撕裂"。本条验证多写者并发下每块内部完整、块间交错可辨，把"乱而有界"钉成判据。
- **语义边界**：只做多写者 >PIPE_BUF 场景；不做小写原子（F10416）；不做写者优先级仲裁（内核不做调度偏好，交错顺序由锁竞争自然产生）。
- **依赖与嫁接源**：消费 F10401 锁与缓冲；嫁接源为 POSIX "> PIPE_BUF bytes ... may be interleaved" 条文，只跟随。
- **风险与回退**：块内撕裂的检测盲区（校验协议本身太弱）——块协议用"长度前缀 + 内容指纹"双验，指纹碰撞概率工程上归零，检出即红账。
- 正文：实现路径分三步。第一步并发写路径：>PIPE_BUF 的 write 允许在容量不足时部分写入（POSIX 允许写部分并返回短计数），短写行为落账——每次 write 的请求长度与实写长度成对入账；第二步块校验协议：压测写方为每块加长度前缀与内容指纹，读方按前缀取块、按指纹验块，指纹不符即块内撕裂，检出率判据为零容忍；第三步交错账：账本记录每块的写入者 ID、入缓冲时刻、读出时刻，交错图谱可导出——判据不要求任何特定交错顺序，只要求"每块完整 + 账与实况一致"。与现存内核衔接点：短写路径复用 F10401 回绕拷贝的段处理，账本并入 F10412。与 Linux 对照：基准机多写者大块压测同样"交错但块完整"，判据 UNX-F10417-J1 的复测方式：4 写者 100 万块零撕裂、短写对账 100% 匹配、交错图谱导出 10/10 次可辨。

### UNX-F10418 · 管道 EAGAIN 非阻塞空读/写满矩阵
- 域/批：C4/B01｜判据：UNX-F10418-J1 非阻塞空读返 EAGAIN、写满返 EAGAIN，与 EOF（返 0）严格区分，4 象限矩阵全对｜纯功能行数：240 行（四象限判定 100 + 区分断言 70 + 矩阵判据 70；测试段不计）｜状态：[已深化]
- **定位**：EAGAIN 与 EOF 的混淆是事件循环程序的噩梦根源——epoll 说可读、read 返 0，到底是真 EOF 还是假警报。本条把四象限（空/满 × 阻塞/非阻塞）判据钉死，EAGAIN 与 0 永不混淆。
- **语义边界**：只做非阻塞行为判定矩阵；不做阻塞等待（F10408）、不做 poll 上报（F10409 与本矩阵交叉验证）。判定顺序沿用 F10405：余量 → EOF → EAGAIN。
- **依赖与嫁接源**：消费 F10405 判定链与 F10410 状态字；嫁接源为 read(2)/write(2) 的 EAGAIN 语义与 Linux 实现顺序，只跟随。
- **风险与回退**：判定顺序漂移（先查 EOF 后查余量导致末块丢失）——顺序以判据固化，任何实现重排必须先过本矩阵，防"看似等价"的重构偷换语义。
- 正文：实现路径分三步。第一步四象限：读侧两态——空+非阻塞返 EAGAIN、空+阻塞入睡（F10408）；写侧两态——满+非阻塞返 EAGAIN、满+阻塞入睡；第二步区分断言：EOF（写端死且余量尽）在任何标志下都返 0 不返 EAGAIN，EPIPE（读端死）在任何标志下都走 F10406 分支——EAGAIN 只属于"活着但暂时不行"这一种状态；第三步矩阵判据：4 象限 × 与 EOF/EPIPE 交叉共 8 格，逐格用例、逐格断言，与 F10409 的 revents 矩阵交叉验证（poll 报可读时 read 绝不 EAGAIN）。与现存内核衔接点：判定顺序并入 pipe 读/写路径头部，与 poll 回调共享实态快照。与 Linux 对照：事件循环库（libuv 类）对 EAGAIN/EOF 的区分测试同源，判据 UNX-F10418-J1 的复测方式：8 格矩阵 100 轮全对、与 poll 一致性 100/100 次、状态翻转边沿 1000 次零误判。

### UNX-F10419 · 管道 dup/dup2/dup3 端点别名语义
- 域/批：C4/B01｜判据：UNX-F10419-J1 dup 后两端引用计数同步增长，dup2 覆盖目标 fd 时原对象正确释放，别名写与原写等效｜纯功能行数：280 行（dup 族挂接 100 + 覆盖释放 90 + 别名等效断言 90；测试段不计）｜状态：[已深化]
- **定位**：dup2 把管道接上 stdout 是 shell 重定向的心脏手术——`ls > file`、`cmd 2>&1` 全靠它。本条把 dup 三兄弟在管道端点上的语义钉死：别名共享、覆盖释放、计数同步。
- **语义边界**：只做 dup 族在管道端点上的挂接与语义断言；不做 dup 系统调用本体（C2/C1 fd 层设施）、不做 CLOEXEC 版 dup3 的标志位（F10403 两级标志结构直接消费）。
- **依赖与嫁接源**：消费 C1 fd 表 dup 接口与 F10402 引用计数；嫁接源为 dup(2)/dup2(2)/dup3(2) 语义与 "copies of a file descriptor share one file description" 条文，只跟随。
- **风险与回退**：dup2 覆盖正在使用的 fd（目标 fd 是另一管道端点）——覆盖路径先走被覆盖对象的引用减计与 F10402 释放状态机，再做指向切换，顺序不可颠倒，颠倒用例进 ktest。
- 正文：实现路径分三步。第一步挂接：dup 族命中管道端点时调用端点的 `on_fd_dup` 回调——计数 +1、账本登记别名关系，新 fd 与旧 fd 指向同一端点对象、共享同一状态字（NONBLOCK 翻转对别名同时可见）；第二步覆盖释放：dup2/dup3 的目标位若已有占用，先对占用者走 close 语义（含 EPIPE/SIGPIPE 可能引发的连锁——被覆盖的是写端且读端已死时同样判死落账），后做切换；第三步别名等效：别名写与原写经 F10416 原子路径同权竞争，压测断言"别名 fd 写入的字节在原 fd 读出"零差异，共享状态字翻转即时可见。与现存内核衔接点：`proc/ring3.rs` fd 层 dup 入口回调管道模块，端点对象持有别名清单供 F10402 对账。与 Linux 对照：`cmd 2>&1` 在 bash 的实现路径即 dup2 语义，判据 UNX-F10419-J1 的复测方式：别名等效 1 万次零差异、覆盖释放 10/10 次计数正确、共享状态字 100/100 次即时可见。

### UNX-F10420 · 管道与 shell 重定向联测地基（C5 预埋）
- 域/批：C4/B01｜判据：UNX-F10420-J1 fork+dup2 构造 cmd1|cmd2 双子进程流水线，64KB 数据经双管道往返零丢失｜纯功能行数：300 行（流水线构造器 110 + 往返校验 100 + 用例集 90；测试段不计）｜状态：[已深化]
- **定位**：管道的一切单点判据，最终都要经得起"真流水线"的检验。本条以内核侧行车试验场构造 fork+pipe+dup2+exec 形态的最小流水线，为 C5 域 shell 生态嫁接提前把裁判台搭好——shell 还没来，考场先开。
- **语义边界**：只做内核侧联测地基与用例集；不做 shell 本体（C5 域）、不做 exec 装载语义（C1 域，本条按黑盒调用）。构造器在内核测试面运行，不依赖用户态 shell。
- **依赖与嫁接源**：消费 F10407 继承与 F10419 dup2 语义；嫁接源为 POSIX sh 的流水线语义（`|` 即管道 + 双 fork + dup2 接线），只跟随。
- **风险与回退**：联测对 C1/C2 未收口部分的依赖——用例分层：P0 级（pipe+dup2+fork）仅依赖本批已收口面；P1 级（含 exec）登记"随闸门补测"，C1 收口后自动升级跑通。
- 正文：实现路径分三步。第一步构造器：测试面提供 `make_pipeline(cmd1, cmd2)` 原语——pipe2 两根、fork 两次、子进程各自 dup2 接线（cmd1 写端接管道 A 写口、读端接管道 B 读口，cmd2 反之）、CLOEXEC 标志按 POSIX 惯例挂接；第二步往返校验：64KB 伪随机数据块从 cmd1 经管道 A 到 cmd2、cmd2 加工后经管道 B 回流 cmd1，全量校验和比对——零丢失、零错序、零重复；第三步用例集：单管道直通、双管道往返、三进程链（cmd1|cmd2|cmd3）、中途终止（cmd2 死于 SIGPIPE 后 cmd1 的 EPIPE 感知）四用例入 ktest，P1 级 exec 相关标注随闸门补测。与现存内核衔接点：fork/exec 经 `proc/ring3.rs` 与 `proc/loader.rs` 既有面调用。与 Linux 对照：`sh -c 'a | b'` 行为同构，判据 UNX-F10420-J1 的复测方式：64KB 往返 100/100 次零丢失、三进程链 10/10 次通、SIGPIPE 中途死 10/10 次上游 EPIPE 感知。
