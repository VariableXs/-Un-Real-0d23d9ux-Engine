## F3521 动态探针总设计（桩点式注入——编译期预留 probe 槽）

**定位**：动态探针总纲：probe 槽=编译期预留的空操作调用点 × 运行时挂载处理器——"临时观测"的机制化（与静态 TP 构成观测面的完整光谱）。
**语义边界**：本条冻结总纲；槽协议 F3522、捕获 F3523、禁区 F3524。与 TP 的分工：TP=**预定义事件**（语义冻结、注册期审、全集可 diff）、探针=**临时观测**（点位运行时选、处理器运行时挂、会话结束即卸）——探针**永不转正**为 TP（转正=写新条目过评审——判据行给转正禁令的理由：临时观测绕过评审是治理漏洞，长期挂着的探针=匿名 TP=观测面账外资产）。
**判据**：
- J1：探针语义冻结（槽结构/处理器签名/生命周期三件）；M-279 挂载全链（激活→执行→数据正确→卸载→槽复位零残留）。
- J2：转正禁令落判据（探针连续挂载超 24h 虚拟时长→告警环 WARN——临时观测的临时性有账面监督）。
**纯功能行数**：320（总纲结构 ~110 + 全链用例 ~110 + 分工红线 ~100）
**依赖与嫁接源**：F3501 TP 总纲（分工对端）；F3507 会话（探针挂载归会话管理——控制面唯一入口复践）；F3524 禁区（安全面）；F3538 预算（拍数锚）。
**风险与回退**：探针滥用（处处挂探针=变相全量插桩）——回退：槽容量上限（每函数 ≤1 槽+全系统 64 槽——编译期预留的槽位本身是配额：探针配额稀缺性逼着选点如规约 F3510 逼着选点同律）；处理器坏（探针处理器 panic）——回退：处理器隔离（探针调用包 try 边界语义——开发期桩环境处理器异常→槽自动去激活+ERROR 账——观测件故障降级不传染）。
**正文**：probe 槽结构（判据行原文）：`ProbeSlot { id, site: &SiteDesc(函数+偏移), params: &[ParamDesc; ≤4], handler: Option<fn>, act_cnt: AtomicU32 }`——槽在编译期由 `probe_slot!(site, params...)` 宏生成（展开为：参数快照代码+空操作调用点——未激活时调用点直接返回 3 拍内 F3538）；运行时挂载=向槽写 handler（激活协议 F3522）。为什么桩点式而非断点式（判据行论证）：断点式动态探针（int3 重写指令流）需要指令级补丁与原子改写（风险与复杂度的双高峰），且与"开发期零 QEMU/双轨产线"的节奏冲突（补丁语义真机才可全验）；桩点式把动态性限制在"预先同意的位置"（编译期槽=评审过的可观测点）——动态的是**时机**不是**位置**（观测自由度让渡 5%、安全自由度全保——判据行给这个取舍的比例化表述）；槽位预留的代价是二进制 +N×8B 空槽（64 槽=512B——可忽略）。处理器签名（判据行内嵌）：`fn(&ProbeCtx) -> ProbeVerdict`——ctx 含参数快照（F3523）+时间戳+任务上下文；verdict 三态（CONTINUE 正常/PASSTHROUGH 跳过本槽后续/ABORT 观测器认为现场异常——ABORT 只记事件**绝不改变控制流**（观测不扰动红线三践——探针没有"阻止函数执行"的权力——它不是过滤器是观察者）。重入防护（判据行内嵌红线实现）：per-CPU 重入位——处理器执行期间置位，同 CPU 再入槽直接跳过（防处理器自身调用了带槽函数的无限递归——递归的观测器是最经典的观测自毁）；重入跳过计数入账（大量重入跳过=处理器设计问题信号）。转正禁令的治理面（判据行展开）：24h WARN 监督+接入表 F3518 只认 TP 不认探针（探针不进域接入账——账外状态本身是"临时"的账面表达）——想长期观测？写 TP 条目进评审（观测面的正门永远开着）。M-279 复测：全链四步 + 零残留 + 重入防护 + 24h WARN + ABORT 不扰动。

## F3522 探针槽注册与激活协议（槽表/激活计数/独占挂载）

**定位**：探针槽协议：注册→激活→执行→去激活四态 + 激活计数器 + 独占挂载（v1 一槽一处理器）——槽的状态机与并发契约。
**语义边界**：v1 **独占挂载**（一槽同时只挂一个处理器——多路需求由 F3529 分发器承担）；激活**原子且幂等**（重复激活同处理器计数不变——幂等性防控制面重试风暴）；去激活与挂载竞争（读侧在跑、写侧卸载）——RCU 式两阶段（判据行给卸载安全协议）。
**判据**：
- J1：四态状态机+转移条件表（判据行内嵌）；M-280 激活/去激活往返（全转移路径+双挂载拒绝+幂等重激活）。
- J2：卸载安全（去激活后处理器不再被调用——两阶段宽限期验证）。
**纯功能行数**：320（状态机 ~110 + 并发协议 ~110 + 用例 ~100）
**依赖与嫁接源**：F3521 槽结构；F3507 会话（激活请求归会话）；F3529 分发器（独占的补充面）；B01 per-CPU（重入位载体）。
**风险与回退**：卸载竞态（handler 指针置空瞬间执行中调用→跳空指针）——回退：两阶段卸载（stage1 置"退役"标记——新调用全拒；stage2 宽限期（一轮调度周期）后清指针——宽限期语义=所有在途调用已离开——判据行给宽限期的充分性论证）；激活风暴（控制面故障疯狂激活）——回退：幂等+激活配额（每会话 ≤16 激活——配额显性拒绝）。
**正文**：状态机（判据行内嵌）：`REGISTERED→ACTIVE`（挂 handler+计数 1）、`ACTIVE→ACTIVE`（重激活同 handler——幂等，计数不变）、`ACTIVE→RETIRED`（去激活 stage1——拒新调用）、`RETIRED→REGISTERED`（stage2 宽限期满——清 handler 槽复位）。激活语义细节（判据行原文）：激活=`compare_exchange(handler: null→h)`（单 CAS——独占的原子实现：两个挂载者竞争，赢家成功输家收到"已持"显性错——双挂载拒绝的机制是 CAS 而非锁（槽是热路径住客——锁是它的死穴，B15 F3483 同律四践）；幂等重激活=`compare_exchange(handler: h→h)` 成功即幂等（不同 handler 的重激活失败——"换处理器"必须先卸后挂——换处理不是原子操作是两步协议，防半旧半新）。两阶段卸载的充分性论证（判据行论证）：stage1 置退役标记后，新调用在槽入口判标记直接走空路径（3 拍内）；在途调用（已过入口正在处理器里的）最迟在"一轮调度周期"内离开（处理器执行 ≤80 拍——远短于调度周期——宽限期上界有数）；stage2 清指针时在途为零——跳空指针不可能；宽限期不是"等一等"是"等一个可证明的空档"（调度周期作为最坏情况的界——工程上保守、语义上充分）。为什么独占不搞多播（判据行论证）：一槽多处理器=调用链变长=热路径税随处理器数线性涨（观测税失控）；多路需求收口 F3529 分发器（分发器本身是一个处理器——内部扇出到 N 路消费者——扇出的税在分发器内账、不在槽的热路径上）——独占槽+内部分发=热路径固定税+消费面自由扩。会话联动：会话 CLOSED 时自动去激活本会话挂的所有槽（泄漏防线 F3531 的机制保障——控制面唯一入口的自愈）。M-280 复测：全转移+双挂拒绝+幂等+两阶段宽限+会话自愈卸载。

## F3523 探针参数捕获（现场快照语义——开发期桩化）

**定位**：探针参数捕获：槽声明参数表（≤4 项）×按值捕获×指针只记值不解引用——观测现场的最小忠实快照。
**语义边界**：捕获发生在**槽入口**（参数寄存器尚未被 callee 破坏——位置即忠实）；**只按值**（结构体大参数只捕获首 8B+长度声明——不解引用不深拷贝——判据行给"指针陷阱"条款）；捕获表编译期生成（槽宏展开——运行时零反射）。
**判据**：
- J1：捕获语义冻结（≤4 项/按值/指针陷阱条款——判据行内嵌）；M-281 捕获正确性（四参数函数各参数值与实参逐项一致——含指针值一致断言）。
- J2：捕获拍数（≤10 拍——热路径预算 F3538 的子项）。
**纯功能行数**：320（快照结构 ~110 + 捕获逻辑 ~110 + 用例 ~100）
**依赖与嫁接源**：F3521 槽宏（捕获代码生成点）；F3503 类型封闭（参数类型四类同律——探针参数复用 TP 类型系统）；F3524 禁区（捕获不允许绕禁区）。
**风险与回退**：捕获误差（槽位置在参数被改之后→快照失真）——回退：槽位置纪律（槽宏必须贴函数头——注册期校验偏移 ≤8B——位置纪律代码化）；误解引用（指针参数被处理器解引用→读到已释放内存）——回退：指针陷阱条款执法（处理器框架层不提供解引用 API——想看内容走 dump 通道 B23——能力不给则误用不存在）。
**正文**：快照结构（判据行原文）：`ProbeCtx { ts: u64, tid: u32, slot_id: u16, args: [ArgVal; 4] }`——`ArgVal { kind: FieldType, val: u64 }`（复用 F3503 四类型——整数/指针/短串/枚举：短串参数捕获栈上 ≤32B 定长槽——捕获面与 TP 负载同律）。按值捕获的忠实性论证（判据行论证）：槽入口=被观测函数第一行后（位置纪律）——此刻参数寄存器是调用者传入的原值（callee 尚未覆盖）——快照=实参的忠实镜像；"忠实"的边界诚实声明：指针参数捕获的是**地址值**不是所指内容（内容可能在被观测函数执行中变化——捕获内容=快照一个移动靶=假忠实；地址不变性对栈参数成立、堆参数不保证——判据行把"捕获的语义是值不是所指"定为探针观测的认识论边界——观测数据的使用者必须知道这一点（数据字典里写明——规约 F3510 的姐妹条款）。指针陷阱条款（判据行展开）：处理器框架 API 只暴露 `ctx.arg_as::<u64>(i)` 取值——不存在 `ctx.arg_deref(i)`——解引用能力在 API 层面不存在（误用不存在=最彻底的防误用——与 B15 封闭格式符"开放是温床"同律五践）；要看内容？`ProbeVerdict::ABORT+事件`→B23 dump 通道全量快照（通道分离：轻观测走探针、重快照走 dump——两通道成本差 100 倍不该混用）。开发期桩化声明：M-281 的捕获正确性在桩环境验证（HostRunner 定参调用——实参已知可断言）；真机寄存器级的捕获正确性随闸门（F3499：真机调用约定的参数寄存器映射实测——真机专属登记）。捕获税：4 参数快照=4 次读+16B 拷贝 ≤10 拍（预算子项——F3538 对账）。M-281 复测：逐参数一致 + 指针陷阱 API 缺席断言 + 拍数 + 槽位置偏移校验。

## F3524 探针安全边界（不可探针区清单）

**定位**：探针禁区三级清单：panic 路径/调度器提交点/中断入口——探针处理器在这些位置执行会递归、死锁或放大中断税——禁区=注册期拒绝。
**语义边界**：禁区是**硬禁区**（无豁免列——F3495 豁免机制在探针面不适用——安全面不让步）；清单**封闭**（新增禁区=改本条=评审可见——运行时不可加禁区）；禁区与重入防护（F3521）的关系：重入防同槽递归、禁区防结构性递归（不同机制不同风险）。
**判据**：
- J1：三级清单冻结（判据行内嵌：panic 链全函数/调度器提交点（state 写入→上下文切换指令间）/中断入口（enter 到 handler 转发段））；M-282 禁区挂载三例逐拦（注册期拒绝+报错三要素）。
- J2：禁区判定的机械性（按符号表段标记判——非启发式——零误判）。
**纯功能行数**：300（清单结构 ~100 + 拒绝逻辑 ~100 + 用例 ~100）
**依赖与嫁接源**：B12 F3438 panicseq（panic 链范围真源）；F3512 中断埋点（中断入口相邻语义——禁区边界与中断 TP 埋点位置协调：TP 在 enter 内、探针禁区在 enter 之前）；F3519 自检（禁区清单完整性自检项）。
**风险与回退**：清单遗漏（新代码路径落进危险区而清单没跟）——回退：段标记制（危险函数编译期打段标记 `#[no_probe]`——禁区判定读标记不读清单——标记跟代码走、清单会忘跟——判据行把"清单会忘、标记不会"作为机制选型的理由）；误禁（可观测的安全函数被标记）——回退：标记评审（no_probe 标记进 code review 检查单——标记本身可审计）。
**正文**：三级禁区（判据行内嵌全文）：①**panic 路径全链**——panic 从触发到 halt 的调用链全部禁探针（理由：探针处理器若在 panic 链执行，处理器自身异常→递归 panic→观测器制造了它要观测的灾难；且 panic 路径是 B15 F3489 保真协议的专管领域——三禁保真（禁锁禁堆禁等待）与探针处理器的常规执行环境（可分配可等待）不兼容——双重理由）；②**调度器提交点**——`state 写入到上下文切换指令之间`的窗口禁探针（此窗口的任务状态半旧半新（state 已改、上下文未存）——探针处理器此刻读任务上下文读到撕裂状态——观测数据假+处理器若再调度=状态机破坏）；③**中断入口段**——`irq.enter 到 handler 转发`之间禁探针（中断税放大器——F3512 论证过中断路径每一拍×两个放大器；且此段在栈切换中——探针处理器用栈快照会读到未切完的栈）。段标记制（判据行论证）：`#[no_probe]` 编译期属性→符号表标记→注册期按标记拒绝（M-282 三例：panic 链函数/提交点函数/中断入口函数各挂探针→逐例"NO_PROBE_REGION"拒绝）——标记跟代码走的优势：函数改名/搬文件标记不动（清单制的失败模式恰恰是"函数搬了清单忘了"）；标记的可见性：符号表里 no_probe 函数全集可 dump（禁区地图随时可查——禁区的透明性让"为什么这里不能挂"有据可查）。机械判定声明（判据行重申）：拒绝判定=符号表查找=确定性操作（零启发式零误判——误禁合法观测与漏禁危险观测同罪，机械判定两个都不犯）。与中断 TP 的边界协调：`irq.enter` TP 埋点在禁区段**之后**（enter 提交点）——事件照发、探针禁挂——同一区域"可观测（TP）不可探（探针）"的精确分层（TP 的空操作提交 5 拍可忍、探针处理器任意代码不可忍——分层的技术根据）。M-282 复测：三例逐拦+报错三要素+段标记 dump+机械判定+分层边界。

## F3525 上下文切换事件流（sched_switch 语义冻结→事件流度量）

**定位**：调度事件流消费端：B16 F3511 三事件的流式消费契约——字段不改、度量加层、流连续性保证——"消费者无权改生产者契约"的样板条。
**语义边界**：本条只做**流组织**（订阅/序校验/连续性账——度量在 F3526/F3527/F3528）；流连续性=序号连续账（缺口计 GAP 不静默补）；契约纪律：本条发现 F3511 字段不敷使用→走新条目改 F3511（消费者不改生产者——判据行把协作纪律点透）。
**判据**：

## F3526 切换延迟度量（运行/等待时长账——per-task 时间账）

**定位**：切换延迟双账：运行账（sched_in→sched_out 的 CPU 占有时长）/等待账（switch(prev) 让出到本任务 sched_in 的排队时长）——per-task 时间账，账实守恒（任务时间总和==CPU 时长）。
**语义边界**：账在**事件提交点同步记**（读流只做对账——F3525 分工）；守恒式冻结：Σ(task 运行时长)==Σ(CPU busy 时长)——多核各账各的（per-CPU 账不合并——合并序问题归聚合层）；空闲语义：CPU 无任务时记 idle 段（idle 也是"时间去处"——守恒式的第 N+1 个任务）。
**判据**：
- J1：双账定义+守恒式（判据行内嵌）；M-284 账实对账（桩环境 10s 虚拟时长——Σ任务时长+idle==10s——零漂移）。
- J2：账的拍数预算（事件提交点记账 ≤8 拍——L1 线内）。
**纯功能行数**：320（账结构 ~110 + 记账逻辑 ~110 + 用例 ~100）
**依赖与嫁接源**：F3525 连续流（数据源）；F3530 时钟抽象（ts 来源）；F3450 预算（记账拍数对账）；F3453 SlowLedger（时长分布的直方图同律）。
**风险与回退**：时钟精度不足（时长小于一拍——细分失真）——回退：精度声明（账的分辨率=时钟拍——桩环境定拍下最短任务 1 拍、真机 TSC ns 级——账面带分辨率标记，度量结论不超分辨率）；记账遗漏（事件丢→账缺段→守恒破）——回退：账与流分离（账不丢——守恒式本身就是账完整性的自检——守恒破=账有 bug=ERROR）。
**正文**：双账结构（判据行原文）：per-CPU 两槽——`run_start`（当前任务上台时刻）/`wait_since[tid]`（等待起点——switch 让出时刻按任务记）——记账三动作：①`sched_in(t)`：`run_len = now - run_start` 记给**上一个任务**（运行账结账）+`wait_len = now - wait_since[t]` 记给 t（等待账结账）+`run_start = now`；②`sched_out(t)`：`wait_since[t] = now`（排队开始）；③`idle 进出`：同①②对 idle 槽。守恒式（判据行论证）：任何时刻 CPU 时间去向三类（运行某任务/等待中的任务不占 CPU（等待账是"排队时长"非 CPU 时长——两个账的语义差异点透：运行账=CPU 时间账（守恒）、等待账=调度延迟账（不守恒——它度量的是体验））——真正的守恒式是"Σ运行账（含 idle）==墙钟时长"——M-284 实测 10s 虚拟时长逐 CPU 对账零漂移（漂移即记账 bug——守恒式是账的完整性自检器，比任何单点校验都根本）；等待账不守恒但可统计（分布 P50/P99——F3453 直方图同律——调度延迟的分布比均值诚实：均值掩盖长尾、P99 暴露长尾——度量语义的哲学声明）。为什么双账不合并（判据行论证）：运行账服务性能分析（谁吃了 CPU——火焰图的对账数据源 F3547）、等待账服务体验分析（谁被亏待——优先级反常的原始数据 F3533 消费它）——两个问题两种受众，账合一则查询互相污染。为什么同步记账不读流（判据行论证）：流可丢账不可丢——度量账在提交点同步写（8 拍内——预算实测），流只是事后对账的副本；若先记流再异步算账，流缺口=账缺口=守恒式破——账的可靠性等级决定它必须在最可靠的路径上（事件提交点）生成。M-284 复测：守恒零漂移+双账语义区分+P50/P99 分布+记账拍数+idle 归位。

## F3527 中断潜伏期跟踪（irq latency 账——消费 F3512 成对账）

**语义边界**：潜伏期定义=**外层** enter→exit（嵌套取最外层——内层处理计入外层时长——判据行给嵌套语义：总时长含子中断，"自身时长"=外层减内层和——两口径都记）；消费 F3512 **成对账**（不依赖事件流——账对账——流可丢账不可丢三践）；慢中断登记（超 256 拍入 SlowLedger——与慢断言同账不同段）。
**判据**：
- J1：直方图定义（桶界 2 的幂：4/8/…/8192 拍——判据行内嵌桶表）；M-285 分布账（注入已知时长的中断序列→桶计数与注入逐桶一致）。
- J2：嵌套双口径（总时长/自身时长分列——两口径和差一致）。
**纯功能行数**：320（直方图 ~110 + 成对消费 ~110 + 用例 ~100）
**依赖与嫁接源**：B16 F3512 成对账（数据源）；F3453 SlowLedger（慢账同律）；F3530 时钟（时长测量）；F3450 预算（中断路径预算的对账数据——本账是预算执行情况的体检表）。
**风险与回退**：时长测量误差（嵌套时钟读数开销计入自身）——回退：测量开销声明（读钟 3 拍×2+账 8 拍=14 拍常数——账面带"含 14 拍测量税"标记——度量含税声明是诚实的度量）；桶溢出（超 8192 拍的中断——极端）——回退：溢出桶（>8192 全入顶桶+SlowLedger 登记——分布不失真）。

## F3528 唤醒延迟跟踪（wakeup→sched_in 全链）

**定位**：唤醒延迟账：wake 事件→目标任务 sched_in 的全链时长分布——"叫醒了多久才上台"的体验账，经 F3246 SleepPort 唤醒路径全程埋账。
**语义边界**：全链=两段（唤醒处理段：wake→入就绪队列/就绪等待段：入队→sched_in——两段分记——唤醒延迟的归因需要分段：处理慢是 wake 路径问题、排队慢是调度器问题）；目标语义：wake(tid) 唤醒的任务 t 的延迟**记给 t**（不是记给唤醒者——延迟的归属是受害者——判据行给归属纪律）；丢失唤醒防护：wake 时任务非睡眠态→事件标 NOSLEEP（唤醒竞争的可观测化）。
**判据**：
- J1：分段定义+归属纪律（判据行内嵌）；M-286 延迟账（受控唤醒注入→两段延迟与注入一致——P50/P99）。
- J2：NOSLEEP 语义（竞争唤醒计数账——非延迟账污染）。
**纯功能行数**：300（分段账 ~100 + 归属逻辑 ~100 + 用例 ~100）
**依赖与嫁接源**：F3246 SleepPort（唤醒路径——账的埋点对端）；F3526 等待账（就绪段与等待账的衔接：就绪等待是等待账的子段——两账对得上）；B16 F3511 sched TP（sched_in 时刻源）。
**风险与回退**：wake 与 sched_in 配对错乱（同任务多次 wake→账张冠李戴）——回退：pending 唤醒槽（per-task 单槽——新 wake 覆盖旧 pending+覆盖计数——最新唤醒是有效唤醒——语义声明）；假唤醒（spurious）——回退：NOSLEEP 分账（假唤醒不入延迟分布——只入竞争计数——分布的纯度保障）。
**正文**：两段账（判据行原文）：①**唤醒处理段**——`wake 事件 ts → 任务入就绪队列 ts`（wake 路径自身开销——含 SleepPort 队列操作；这段长=唤醒路径本身慢（锁争用/队列长））；②**就绪等待段**——`入队 ts → sched_in ts`（调度延迟——这段长=调度器没及时给 CPU（优先级/其他任务占用））——两段和=全链延迟（体验数字）、两段差=归因（慢在 wake 还是慢在调度——归因是延迟账的存在理由：单一数字只报忧不指路）。归属纪律（判据行论证）：延迟记给被唤醒任务 t——理由：延迟的承受者是 t（t 的所有者/体验方），记给唤醒者会产生"唤醒者选择"的误导归因（谁 wake 不重要、等多久才重要）；归属纪律的实现：pending 槽在 t 的任务控制块（不在唤醒者侧——数据结构跟着归属走）。NOSLEEP 语义（判据行论证）：wake 时 t 不在睡眠态（已在运行/已就绪）——这次 wake 是竞争性冗余——不产生延迟对（没有 sleep 就没有"被唤醒"）→NOSLEEP 计数+1（竞争唤醒率本身是健康指标：高竞争率=唤醒风暴或协议误用信号——可观测化让竞争从"偶发怪象"变"有账可查"）。与 F3526 等待账的衔接（判据行论证）：就绪等待段 ⊆ F3526 等待账时段（等待账从 switch 让出记到 sched_in——就绪段从入队记到 sched_in——让出与入队之间是"睡眠"（不算等待））——两账的时段语义显式区分（等待=让出后可运行未上台/睡眠=不可运行——唤醒延迟只覆盖睡眠→就绪→上台链；两账对账：就绪段长==等待账中"已就绪部分"——对得上则两账互证）。M-286 复测：两段注入一致+归属断言+NOSLEEP 分账+两账互证+P50/P99。

## F3529 跟踪流多路分发（事件扇出——TP/log 双通道）

**定位**：事件多路分发器：一事件扇出到 N 路消费者（度量账/探针流/联动快照/回放缓冲）——路间独立（一路堵不拖另两路）+扇出对账。
**语义边界**：分发器本身是**一个处理器**（F3522 独占槽的"内部分发"实现——热路径只见分发器一跳）；路间**无共享状态**（每路独立缓冲独立预算）；扇出**固定四路 v1**（新增路=改本条——扇出面是治理面不是插件面——判据行给不开放的理由）。
**判据**：
- J1：四路契约表（路名/消费者/缓冲/预算四列——判据行内嵌）；M-287 扇出对账（四路计数独立且源事件数==四路受理数之和（含路内丢弃计数））。
- J2：隔离性（一路缓冲满→该路丢弃计数+1、其余三路零影响——实测）。
**纯功能行数**：300（分发逻辑 ~100 + 对账器 ~100 + 用例 ~100）
