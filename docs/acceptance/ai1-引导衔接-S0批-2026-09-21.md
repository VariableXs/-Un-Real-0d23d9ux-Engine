## 2. S0.2 L0 配置桥（方案 A）✅

### 2.1 机制决策记录（与清单原案的偏差与依据）

S0.2 清单原文为「limine.conf 增 module_path」。实现改用**内核声明的 Limine internal module**
（`MODULE_REQUEST` rev1 + `internal_modules: "../boot-select.json"`，flags=0），依据为 Limine
官方协议与源码逐字核实：

1. 协议：internal module 路径**相对内核可执行文件位置**解析（内核在 /kernel/varix →
   `../boot-select.json` = 引导卷根）；`limine_file.path` 为「卷内带前导斜杠路径」，与
   `bootcfg::read_via_limine("/boot-select.json")` 匹配语义一致。
2. 源码（common/protos/limine.c）：conf `module_path` 指向缺失文件 → `module_required=true`
   → **panic，引导失败**；internal module flags=0 缺失 → verbose 警告+跳过。
3. 结论：conf module_path 会把「副本缺失→回退内置默认（契约不破）」的验收条款直接砸掉
   （缺失即 panic），internal module 是唯一同时满足全部 S0.2 验收条款的机制。
   limine.conf 因此**保持不动**（timeout:0/serial:yes 语义不变）。
