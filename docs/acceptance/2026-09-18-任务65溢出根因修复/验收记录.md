# NVMe/KvStore 溢出路径实机卡死：根因攻坚与修复（AI-B，2026-09-18）

> 对应任务65 验收记录中登记的开放项："destroy 512B 覆盖块走溢出路径 128 块连写
> 实机确定性卡死（HMP 寄存器现场 HLT=1@halt, RDI=0xffffff=16MiB-1 指向 DMA
> 大块写）"。本记录为根因的完整闭环：假设验证 → 复现 → 取证 → 修复 → 实机确认。

## 1. 假设排除

| 假设 | 验证手段 | 结论 |
|---|---|---|
| LBA 越界（盘尾边界） | 复查 nvme.rs `check_range`：`lba.checked_add(n).filter(end<=nblocks)` 防护完备；探针盘 512MiB、VLT_DATA_BASE=100000+64×128 块 << 盘尾 | **证伪** |
| io 等待无超时 | io_submit_and_wait 有 deadline 超时，Err 上抛 | 已排除（任务65 时已证） |
| destroy 复杂度 | 最小化复现探针：单次 `put(512B)` 即停摆 | **卡点 = 单次溢出槽写** |

## 2. 最小复现

kvault.rs vault_probe 增设溢出路径专项段（pre-overflow → overflow put/get →
overflow destroy）。实机（512MiB 探针盘）：`pre-overflow` 后无任何输出、无
Err、无 fatal，确定性停摆——复现率 100%（多轮一致）。

## 3. 取证（HMP 寄存器 + 内核栈回溯）

- 现场寄存器：RIP=0xffffffff80001251、**HLT=1**、RCX=RDI=0xffffff、
  RAX=RBX=0xffffffff807cbd98、RSP=0xffff80001ff99df0
- 关键突破：HMP `xp` 直读内核栈（RSP 物理区）发现
  **`/rustc/8bab26f4…/library/alloc/src/alloc.rs:573`** panic location 字符串
- 结论：**alloc 分配失败 panic**（alloc.rs:573 = handle_alloc_error 路径）。
  单核内核探针运行中 CPU 却在 HLT——panic 打印路径自身再触分配失败 →
  panic-in-panic → `cli + hlt` 静默停机。这完整解释"无输出、无 Err、无 fatal"
  的反常形态（fatal handler 会打 `fatal exception` 行，栈上从未出现）。

## 4. 根因定性

`kvsrv.rs write_overflow/read_overflow` 的 `vec![0u8; 65536]`——溢出槽
64KiB 整槽堆物化；而内核堆（mem/heap.rs）ARENA_BYTES=256KiB slab，
注释明示"Larger requests go to the page allocator (F051/F052)"，该 fallback
对本次请求路径失效 → alloc 失败 → panic。宿主 MemDisk 因 std 分配器
不复现——正是"宿主全过、实机独有"的分野。

与任务56 戒律（>64KB 结构禁堆/栈物化，ImportTable 41KB 击穿内核栈）同族：
**KvStore 溢出路径是 kheap 256KiB 现实下的第二个物化越界点**。

## 5. 修复（kernel/varix/src/kvsrv.rs + security/kvault.rs）

1. **KV_SLOT_BLOCKS 128 → 64**（槽 64KiB → 32KiB；`OVERFLOW_MAX`=32744）——
   溢出区预算 64 槽 × 32KiB = 2MiB（原 4MiB），登记于语义差异清单
2. **write_overflow 分片直写**：512B 栈片逐块写，全槽覆盖（零填充尾块），
   残留防泄露语义不变；单次堆分配归零
3. **read_overflow 分片读**：头片 488B + 512B 栈片续读，仅物化 val 本身
   （≤32KiB，1/8 kheap 预算内）
4. **MAX_ITEM 262144 → 32716**（kvault.rs）：明文 M → ct=M+28 ≤ OVERFLOW_MAX
   边界推导；原 256KB 声明照抄桌面侧堆语义，与内核 kheap 现实冲突，如实修正
5. 探针溢出专项段保留为常态化复现器

## 6. 验证

- 宿主：kvsrv 8 用例（30KiB 分片直写往返/覆盖/边界值/跨重开）+ kvault 15 用例
  （含新 MAX_ITEM 的 limits_enforced）全绿；ktest **2961 passed / 0 failed**；
  kcheck 0 告警
- 实机（512MiB 探针盘 QEMU）：
  ```
  vault: ok - pre-overflow
  vault: ok - overflow put/get PASS
  vault: ok - overflow destroy PASS
  vault: PROBE PASS (全链: init/unlock/put/get/密文核验/焚毁/零化)
  RESULT: PASS
  ```
  修复前同探针 100% 停摆于 pre-overflow；修复后多轮全链 PASS
- 证据：_attic/vault65-serial.log（修复后 PASS 轮）、
  _attic/vault65-hang-regs.txt / vault65-hang-regs2.txt（修复前现场）、
  _attic/stack-walk.py / panic-forensics.py（栈取证脚本）

## 7. 遗产

- 探针溢出专项段常驻：任何回归（如未来 kheap/分配器改动）实机即复现
- `MAX_ITEM`/`OVERFLOW_MAX` 的 kheap 边界推导已内嵌常量注释，防止后续
  "照抄桌面语义"再次引入超预算物化
