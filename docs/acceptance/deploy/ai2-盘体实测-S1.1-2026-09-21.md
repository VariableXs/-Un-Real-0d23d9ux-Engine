## 2. 方法（严格只读 + 绕缓存）

- **零写入**：X:（WIN_ENGINE）为空且 CrystalDiskMark 类工具需先写测试文件，违反 S1.1"纯只读"安全闸 → 全部改用**盘上既有文件**的读路径测速。全盘唯一 ≥16MiB 文件 = `S:\variable.exe`（31MiB）。
- **绕 Windows 文件缓存**：`CreateFileW(FILE_FLAG_NO_BUFFERING)` + `VirtualAlloc` 页对齐缓冲，读的每一字节都来自设备而非内存缓存。
- **顺序**：1MiB 对齐块，同一文件循环直读凑满每轮 1GiB（重复直读在 NO_BUFFERING 下仍是真实设备路径）；**3 轮独立测量**。
- **4K 随机**：4K 对齐随机偏移 ×8000 ops，热身后**复测一轮**；`FILE_FLAG_RANDOM_ACCESS`。
- 探针：`_attic/ai2-s111-perf.py`（原始 JSON：`_attic/ai2-s111-perf-result.json`）。

## 4. 如实解读

1. **390MB/s 是 USB 3.2 Gen1（5Gbps）链路的典型饱和值**（Gen1 实测天花板一般 380-450MB/s；若为 Gen2 10Gbps 应见 ~900MB/s）。瓶颈大概率在**链路代际**，不在盘体本身（SSD 盒 + NVMe 盘 4K 都有 21MB/s 的 SSD 级表现）。
2. **对 S1.2 体验的含义**：Windows To Go 在 Gen1 链路上可用但系统盘顺序吞吐打折（大文件拷贝 ~390MB/s 封顶）；4K 达标意味着系统响应粒度（随机小 IO）不受罪。编译/游戏等重负载按方案既定走内置盘。
3. **局限声明**：①写路径未测（写测试必写盘，违反本步只读闸）；②测源是 31MiB 单文件循环（SSD 内部读缓存可能参与，读数只会偏高不会偏低——即真实冷读 ≤391.9 的风险存在）；③X:/W:/V: 为空无既有数据可测，物理同盘同链路，以 S: 读路径代表。

## 5. 判定与处置

- **判定：FAIL（顺序门）**。依据 S1.1 纪律"不达标 = 如实告知体验预期并停下问询，不硬上"——**S1.2 暂停，待用户拍板**。
- 选项（供拍板）：
  1. **接受 Gen1 级体验继续**：391.9MB/s 顺序 + 21MB/s 4K 对 WTG 系统盘是可用档，随后用 AS SSD/CrystalDiskMark（写测试档，需用户授权写入）复测交叉验证；
  2. **换口/换盒重测**：插 USB 3.2 Gen2 口或换 Gen2 盒再跑本探针（只读，零风险）；
  3. **推迟 S1.2**，先推进无依赖线。
- 无任一选项时本线后续任务（S3.1 real 模式 ×10、S3.3-S3.10 实测）按"依赖 S1.2"继续挂起。
