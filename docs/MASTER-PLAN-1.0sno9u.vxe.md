## 1. 版本定义

- **版本号**：`1.0sno9u.vxe`（本计划的代号版本；应用 semantic version 沿用 Tauri 配置独立演进）。
- **本版本目标画像**：插上 8TB 移动 SSD → 任意 Win10/11 电脑双击 → 3 秒内进入独立桌面环境 → 左手 VS Code、右手多标签终端，`claude` / `codex` / `zcode` 等 CLI 就绪且账号封存容器 → 任意浏览器多 profile 即开 → 任意壁纸（含 Wallpaper Engine / 着色器）→ 任意第三方软件携原生图标嵌入环境 → 可创建/嵌套子环境套娃 → 退出刷盘拔走，宿主零残留。
- **明确不含**（承接蓝图第 9 节）：本地大模型推理、内核驱动、攻击性安全工具、对抗宿主监控。

## 4. 里程碑详细步骤与验收

> 每个里程碑给出：目标 / 任务分解（含涉及文件）/ 验收标准（可执行命令或可手测步骤）/ 回滚策略。批次纪律见第 6 节。

### M0 工程底盘（预计 2 个批次）

**目标**：把本计划接入仓库工作流，建立性能基准与文档基线。

**任务**：
1. 新建 `docs/` 文档基线（本蓝图 + 本计划入库）；
2. `tools/bench.cjs`：冷启动计时、万文件索引、VWM 打开延迟、内存水位四项基准，输出 Markdown 报告；
3. `tools/audit.cjs` 扩展：执行档模板与 netconsent 域名一致性校验占位；
4. Cargo workspace 内新增 `container` crate 骨架（空 trait + 测试桩）。

**验收**：`npm run typecheck && npm test && cd src-tauri && cargo test` 全绿；`node tools/bench.cjs` 输出首份基线报告入库 `docs/bench/`。
**回滚**：纯增量，无需回滚。

### M1 隔离执行档与凭据封存（预计 3 个批次）★最高优先

**目标**：任何受管进程的落盘与凭据 100% 进容器；「零残留」从口号变为可验证。

**任务**：
1. `ThirdApp` 登记模型扩展为 `PortableProfile`（蓝图 7.2）：`env_redirect` / `env_set` / `net_allow` / `sensitive`；登记表迁移逻辑（旧 apps.json 平滑升级）；
2. Rust `exec.rs` 新模块：`spawn_profiled()` —— 启动子进程前展开 `{container}` 占位符、注入环境表；`tp_launch` 改为经由执行档；
3. 内置模板库 v1：Claude Code / Codex CLI / ZCode / Git / Node（`CLAUDE_CONFIG_DIR`、`HOME`、`USERPROFILE`、`npm_config_cache`、`GIT_CONFIG_GLOBAL`…）；
4. 残留扫描器：`ipc.residueScan()` 对 `%USERPROFILE%` 顶层 + Recent 做会话前后差集（快照在环境启动时建立）；
5. 设置页新增「执行档」标签：模板查看、编辑、按应用覆写。

**验收**：
- 登记一个 Claude Code CLI → 运行 → `%USERPROFILE%\.claude` **不存在**，容器 `home/.claude` 出现；
- `node tools/residue-check`（包装 residueScan）输出 0 残留；
- 旧登记项（apps.json v1）升级后 `tp_launch` 回归通过（cargo test）。
**回滚**：登记表保留 v1 字段兼容读取；`spawn_profiled` 失败自动降级旧通道并横幅提示。

### M2 容器与 8TB（预计 6 个批次，可与 M3 并行后半段）

**目标**：三档存储后端落地；8TB 多卷、快照、加密、掉电安全。

**任务**：
1. `container` crate：`StorageBackend` trait（蓝图 7.1）+ `DirBackend`（现状目录包装，行为等价迁移）；
2. `VhdxBackend`：`Mount-VHD`/`DISM` API 挂载（管理员档）+ 无管理员降级探测；
3. `UxvBackend` 分四个子批：chunk 索引（B+ 树 + BLAKE3 去重）→ journal 事务 → 压缩加密（LZ4/Zstd + XChaCha20）→ 多卷 + GC；
4. 掉电注入测试：测试钩子下 `kill -9` / 句柄拔除，journal 重放恢复校验（CI 可跑的模拟层）；
5. 容器仪表 UI：任务栏水位线 + 设置页「存储」标签（迁移向导：数据目录 → 容器，逐文件校验）；
6. 冷热分层与「挂起项目」（大目录一键冷存）。

**验收**：
- 迁移向导把真实数据目录（含 10GB 媒体）转入 Uxv，逐文件哈希比对通过；
- 8TB 卷表用稀疏测试卷（4×2TB 虚拟卷）通过跨卷读写与 GC；
- 掉电注入 100 次，0 数据丢失（journal 重放断言）；
- 基准：热 chunk 随机读 < 20ms；GC 暂停 < 100ms。
**回滚**：DirBackend 永久保留为可切换后端；迁移向导提供反向导出。

### M3 终端与云端 AI 矩阵（预计 4 个批次）★本版本灵魂

**目标**：环境内 `claude` / `codex` / `zcode` 即开即用，账号封存，AI Hub 统一管理。

**任务**：
1. **ConPTY 终端**（`terminal.rs` + 前端终端虚拟窗口）：V1 嵌入 Windows Terminal Portable（embed 通道复用）；每子环境独立 shell 配置；窗口关闭会话保活；
2. 容器内 Node 运行时接入（`runtime/node`）；AI 工具安装器：`ai install <tool>` 在容器内 npm 全局装，进度回传（事件流）；
3. **AI Hub 面板**：任务栏入口 + 卡片列表（蓝图 3.6）；登录态推断、用量本地计数、一键唤起；
4. **账号身份**：Vault 2.0 —— 身份条目模型 + Token 注入执行档环境变量 + 多账号 profile 切换（`CLAUDE_CONFIG_DIR@work`）；
5. Web 模型收藏夹（环境内浏览器 profile 直开，依赖 M4）。

**验收**：
- 全新宿主：M1 执行档 + M3 终端 → 打开终端输入 `claude` → 登录 → 会话落容器 `home/.claude` → 退出 → 宿主 `%USERPROFILE%` 残留扫描为 0；
- Codex / ZCode 各登记并跑通一次真实代码修改（终端内完成）；
- AI Hub 一键在「工作/个人」两账号间切换且互串为 0（目录隔离断言）。
**回滚**：终端与会话保活纯增量；Hub 数据独立键空间。

### M4 浏览器矩阵与账号（预计 3 个批次）

**目标**：任意浏览器、任意多 profile，Cookie/扩展/登录态全在容器。

**任务**：
1. 浏览器便携模板（Chrome 系 `--user-data-dir` / Firefox `--profile`）+ 安装探测（注册表 App Paths / 开始菜单）；
2. Profile 管理器 UI：列表 / 新建 / 克隆 / 删除（删 profile 前确认 + 可焚毁）；
3. 任务栏窗口组按 profile 分组显示；
4. 首次导入向导：宿主浏览器导出文件（书签 HTML / 密码 CSV）本地导入，明确文案「绝不读取宿主浏览器运行数据」。

**验收**：Chrome 与 Firefox 各双 profile 同时登录不同账号，重启环境后登录态完好、宿主无任何浏览器痕迹。
**回滚**：模板失败时按普通第三方软件登记（已有通道）。

### M5 大型编码体系（预计 4 个批次）

**目标**：8 小时高强度开发工作流全程在环境内完成。

**任务**：
1. VS Code Portable 一键部署 + 执行档 + VWM 嵌入实测（Electron 窗口嵌入回归）；
2. 工具链模板：Node/Python/Rust/Go/Git 便携部署脚本（容器 `runtime/`），终端 PATH 注入；
3. Git 深度面板：状态/暂存/提交/分支/差异（复用文件总线与终端能力，不自研 git 引擎——`git2-rs` 只读 + 终端写操作混合）；
4. SSH key 金库代理（`git credential` + ssh-agent 转发到内存）；
5. 大文件与索引：ripgrep 式并行全库搜索（容器流式读）；100MB 文件分块查看器；
6. PVCCE ↔ VS Code 双向跳转（`xref:` 扩展行级锚点）。

**验收**：
- 克隆真实开源仓库（万文件级）→ 索引 < 3s → 全库搜索冷缓存 < 8s；
- 在环境内完成一次「改代码 → 跑测试 → 提交（SSH 签名）→ push」全流程，凭据零落宿主；
- 100MB 单文件打开 < 1.5s，内存峰值 < 400MB。
**回滚**：各工具链独立目录，删目录即卸载；Git 面板降级为纯终端流。

### M6 子环境系统（套娃）（预计 5 个批次，依赖 M2）

**目标**：多环境档切换 + 最多 3 层嵌套 + 秒级克隆。

**任务**：
1. 环境档模型与存储剖面（容器子卷隔离：`envs/<id>/` 各自的 home/apps/db 视图）；
2. 切换编排器：确认保存 → 卸剖面 → 挂新剖面 → Shell 状态重载（启动仪式短版）；
3. 嵌套实例：子环境 = 新 Variable 进程（独立数据根参数），经 embed 嵌入父 VWM；深度 3 上限；白名单子集继承（只减不增）；
4. 快照克隆：`envSnapshot` → 零拷贝 COW；「平行世界」UI（克隆前后对比进入）；
5. 子环境崩溃占位卡与重开（复用嵌入失败路径的哲学：不杀进程、给重试）。

**验收**：
- 创建「试验档」子环境 → 在其中装软件/改壁纸 → 退回主环境，主环境零变化；
- 三层嵌套全功能可用（键盘/壁纸/窗口），父层关闭时子层按栈保存；
- 克隆 10GB 环境档 < 2s（COW 验证：克隆后立读哈希一致，写入不膨胀）。
**回滚**：环境档机制可整体停用（单环境模式回退）。

### M7 应用生态 2.0（预计 3 个批次）

**任务**：可移植性评估向导（注册表/服务依赖扫描 → 绿黄红评估卡）+ 搬迁执行器（含 `portable.reg` 快照）+ 256px Jumbo 图标 + 自研软件「收入环境」一键登记。
**验收**：搬迁一个真实安装软件（如 7-Zip）→ 评估卡绿 → 容器内独立运行 → 图标与宿主一致；评估不通过案例（依赖服务的软件）如实列出缺失项。
**回滚**：向导产物即普通便携档，删除登记即清退。

### M8 网络层（预计 4 个批次，依赖 M1）

**任务**：环回代理（环境自管 HTTP/HTTPS 代理，白名单执行点）+ 域名确认卡升级（显示发起执行档）+ 托盘 kill-switch + 流量仪表 + 代理配置（HTTP/SOCKS5、远端 DNS）+ 直连逃逸告警（如实边界文案）。
**验收**：未授权域名在代理层被拒且弹确认卡；授权后云 AI 正常工作；kill-switch 一键全断后所有受管工具断网、浏览器环境内 profile 同断；直连型工具触发告警横幅。
**回滚**：代理层可关（回退 netconsent 单次确认模式）。

### M9 安全分析工作台（预计 4 个批次，依赖 M2/M6）

**任务**：PE 静态解析器（纯 Rust：哈希/熵/导入表/签名链）+ 字符串/混淆度量面板 + capstone 反汇编只读查看器 + Windows Sandbox 编排（探测可用性，不可用如实标注）+ 安全子环境预设（白名单清空 + 快照预建 + 红色警示）+ 分析报告导出。
**验收**：对一个自有测试样本完成「情报卡 → 反汇编浏览 → 断网沙盒执行（如可用）→ 报告导出」全流程；主环境与常规子环境**不存在**任何危险执行入口。
**回滚**：工作台为独立面板，整体可禁用。

## 5. 迁移与兼容

1. **数据目录 → 容器**（M2）：迁移向导逐文件复制 + BLAKE3 校验 + 完成后原目录自动改名 `data.migrated-backup`（保留 30 天，用户确认后焚毁）；任一步失败原目录原样保留。
2. **apps.json v1 → v2**（M1）：新增字段全部 `#[serde(default)]`，旧文件可读可写；登记项首次运行时惰性补模板。
3. **快捷键**：双 Esc / Del+Backspace 语义不变；新增 Ctrl+K 命令面板、Ctrl+J 终端，冲突检测走既有 `shortcuts.ts`。
4. **打包**：`build-windows.bat` 增加 `container` 目标（产出引导器 + 空容器模板）；NSIS 安装版与便携版继续并存。

## 6. 批次纪律（开发规范，延续 project_memory 传统）

1. 每批次：单一主题、可独立验收、留一条「教训」记录进 `project_memory.md`；
2. 合并门槛：`tsc --noEmit` 0 错、`cargo test` 全绿、`npm test` 全绿、bench 无 >10% 回归；
3. 涉及「启动进程 / 网络出站 / 删除文件」的批次必须：a) 无 shell 字符串拼接；b) 失败路径不杀进程不删文件；c) UI 文案如实降级；
4. 契约变更（蓝图第 7 节）必须在同批次更新两文档并 `git commit` 于同一提交。

## 8. 验收总口径（v1.0sno9u.vxe 达成定义）

> 以下十句话全部成立时，本版本收官——在任何一台满足「Windows 10/11 x64 + USB 口」的电脑上：

1. 双击引导器，3 秒内进入我的桌面环境（壁纸是我上次的）；

4. 浏览器两个 profile 同时在线两个不同账号，Cookie 谁也不串；

6. 嵌入一个第三方软件，系统任务栏与 Alt+Tab 里看不到它；
7. 创建一个试验子环境，糟蹋完退回，主环境毫发无损；

9. 退出时残留扫描输出 0；宿主 `%USERPROFILE%` 与注册表干干净净；
10. 拔盘、换一台电脑、重插——一切如初。

| 凭据疑似泄露演练 | 公用机登入→登出→残留扫描+吊销清单走查 | 扫描 0；吊销清单列出全部已登录服务且链接可达 |
| 杀软误报演练 | 三杀软提交引导器样本 | 白名单流程记录在案，误报处理 ≤ 48h 闭环 |
| 黑屏演练 | 强制 GPU 上下文丢失 | `--force-raster` 降级进入，用户数据无损 |
| 空间耗尽 | 稀疏卷写满 | 冷冻/GC 引导可用，写路径返回明确错误而非静默截断 |

## 21. 明确不做的事（本轮评审后继续排除）

- **多人共享一只胶囊**：口令体系与快照语义都是单人假设，多用户意味着权限系统——那是另一个产品。共享场景的正解是「每人一只胶囊 + 项目级导出互换」；
- **移动端 / Web 宿主形态**：只在 Windows 桌面形态兑现；
- **容器内运行 Windows 图形子系统级兼容层**（如 Wine 类）：嵌入通道已覆盖 Win32 软件，不引入兼容层复杂度；
- **自动云备份默认开启**：提供导出与冷区网盘同步的**手动**通道，默认零出站原则不因便利性破例。

## 22. 程序与功能自检体系（Self-Check）

> 「功能是否可以正常运行」不能靠感觉，靠一套**每批次必跑、发版必归档**的自检栈。本节是执行规范；历次结果归档在 [`docs/selfcheck/`](selfcheck/)。

### 22.1 自动验证栈（五层，全部本地、零网络）

| 层 | 命令 | 防什么 |
| --- | --- | --- |
| L1 类型 | `npm run typecheck` | 前后端契约漂移（strict 全量） |
| L2 前端单测 | `npm test`（Vitest 218+） | 净化/几何/引擎/保存队列/拼音/快捷键逻辑回归 |
| L3 后端测试 | `cd src-tauri && cargo test`（36+） | DB 事务、命令面、级联删除、upsert 幂等 |
| L4 静态审计 | `node tools/audit.cjs` | **IPC 面一致性**（前端 invoke ↔ Rust 注册一一对应）+ **i18n 键完整性**（used-keys ⊆ 各语言词典） |
| L5 构建 | `npm run build` | 生产可构建（chunk 体积告警人工复核） |

**合并门禁**：L1–L5 全绿 + bench 无 >10% 回归（M0 起）。任一层红 → 该批次不得提交。

### 22.2 功能冒烟清单（5 分钟手测，实机发版前必过）

1. 双击启动 → 启动仪式真实进度 → 桌面图标交错淡入；
2. 双击 Esc 环境隐/显各一次；Del+Backspace 弹出退出前保存冲刷（取消）；
3. 桌面双击 Write → VWM 窗口打开 → Ctrl+N 新建 → 输入 → Ctrl+S → 关窗重开内容在；
4. 开始菜单搜 `swdt`（拼音首字母）→ 命中思维导图；
5. 登记一个第三方软件 → 环境内打开 → 系统任务栏无新窗口 → 关闭虚拟窗口 → 应用退出；
6. 右键桌面切换壁纸 → 立即生效；设置 → 关于 → 版本号正确；
7. 切换语言 zh ↔ en → 无 key 名裸露（若出现 = i18n 缺键，回到 L4 审计排查）。

### 22.3 自检发现问题的处理纪律（本轮实例）

- **工具缺陷也算缺陷**：本轮 audit.cjs 的三处解析 bug（子目录漏扫 / cfg 属性断行 / 同行双键漏检）曾让"审计全绿"长期不可信——修复后立即暴露 90 个真实 i18n 缺键。**自检工具自身必须有怀疑精神**：数字突变（74→161 命令数）要追问原因，不能当作修好了；
- 修复顺序：先修验证工具 → 重建基线 → 再修应用问题 → 全栈复跑归档。

### 22.4 归档规范

- 每次发版 / 每里程碑收口：跑完整栈 + 冒烟清单，结果写入 `docs/selfcheck/<YYYY-MM-DD>.md`（表格 + 发现 + 边界声明，格式见 [2026-09-05 首份报告](selfcheck/2026-09-05.md)）；
- 报告必须包含"已知边界"小节——如实声明本轮**没有**验证什么（如 GUI 实操路径依赖三宿主矩阵手测）；
- `git commit` 与发版提交同批入库，保证"报告说绿的"可回溯到具体提交。

## 23. CI/CD 与实时闭环（GitHub Actions）

> 「实时更新到 GitHub」的完整含义：**推送即验证**。本节随本次更新直接落地（`.github/workflows/ci.yml` 已创建）——不再是计划，而是已运行的闭环。

### 23.1 流水线规格

| 项 | 配置 |
| --- | --- |
| 触发 | push 到 main + 全部 PR |
| Runner | `windows-latest`（Win32 依赖决定，不拆双系统矩阵） |
| L1 类型 | `npm ci && npm run typecheck` |
| L2 前端 | `npm test -- --run`（218+，CI 模式） |
| L3 后端 | `cargo test --manifest-path src-tauri/Cargo.toml`（Swatinem/rust-cache 加速） |
| L4 审计 | `node tools/audit.cjs`（IPC 面 + i18n 完整性，失败即红） |
| L5 构建 | `npm run build`（Vite 产物上传 artifact 7 天） |
| 时长预算 | ≤ 12 分钟（超时视为红，防任务腐化） |

### 23.2 闭环规则

- **PR 必须绿才能合**（仓库设置 Required checks）；
- **main 上红 = 最高优先级修复**（ revert 优先于 hotfix——历史线性纪律）；
- CI 红 + 本地绿 → 优先怀疑环境差异（Node/Rust 版本锁在 `engines`/`rust-toolchain.toml`，缺失则补）；
- 发版额外手跑三宿主矩阵（第 14 节），CI 不替代实机验收——只守住"每个提交都是绿的"这条底线。

### 23.3 与自检体系的关系

CI = 自检栈 22.1 的 L1–L5 的**无人值守形态**；冒烟清单（22.2）与三宿主矩阵（第 14 节）仍为人肉环节。三层合起来构成完整验证金字塔：CI（每次推送）→ 冒烟（每次发版）→ 实机矩阵（每个里程碑）。
