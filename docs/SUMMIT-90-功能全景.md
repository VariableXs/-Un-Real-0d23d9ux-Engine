### 0.2 本轮五条立项铁律（每项 M 功能必须全部满足）

1. **实用优先**：每项必须回答「一个真实用户在什么场景下会用到它」，答不上来的不立项。
2. **零退化**：任何改动不得让现有观感、操作、性能产生哪怕一点回退；所有新行为**默认关闭或默认等于现状**，用户显式开启才生效。
3. **零键位冲突**：所有新键位一律走 Z-08 键位注册表仲裁（该注册表落地前，本轮新键位只允许 `ctrl+alt+` 空闲槽与裸 F 键）；不确定的组合一律不占用。
4. **不弄巧成拙**：不做任何「演示很惊艳、日常是干扰」的花活；动效克制、文案诚实、降级如实。
5. **四大内置应用绝对隔离**：写作空间（Library）、思维导图（Mindmap）、项目分析（PVCCE）、命运推演（FTPE）四个内置软件的**任何文件不修改**；本轮所有功能只作用于桌面壳层、VWM、任务栏、文件管理器、设置与后端 shell 模块。

## 域 W：窗口手感新维度（M-01…M-09）

> 目标：把「老 Windows 用户肌肉记忆」里被系统放弃的好手感找回来，全部默认关闭、可逐项开启。

### M-01 摇一摇最小化（Aero Shake）

- **定位**：拖住某个 VWM 虚拟窗口标题栏左右晃两下，其余虚拟窗口全部最小化。
- **动机**：Windows 11 删掉了 Aero Shake；很多老用户的肌肉记忆还在，且它确实是最快的「只留这一个」操作。
- **具体内容**：① 在 `VirtualWindowFrame` 拖拽路径上检测横向速度峰值与来回次数（≥2 次换向即触发）；② 触发后其余窗口走既有 200ms 飞行动画最小化；③ 设置项 `winShake.enabled` 默认 false；④ 触发时轻微 toast 提示「已最小化其他窗口（Ctrl+Alt+D 恢复）」，可关。
- **不做清单**：不做二次晃动恢复（易误触）；不做可调灵敏度滑杆（固定阈值，宁缺勿滥）。
- **验收**：正常拖拽（含贴靠拖拽）100 次零误触；开启后故意晃动 10 次全部命中；`cargo test` / vitest 全绿。

### M-02 窗口卷帘（Roll-Up）

- **定位**：双击 VWM 窗口标题栏左侧空白区或右键菜单「卷起」，窗口收缩为只剩标题栏的一条，再双击展开还原。
- **动机**：挂着的参考窗口（聊天、监控、终端）占地太大时，卷帘是最克制的收纳方式，比最小化「找得回来」。
- **具体内容**：① 右键标题栏菜单新增「卷起/展开」项 + 可选双击热区（默认关闭）；② 实现 = 高度动画至 40px 标题栏，窗口内部 `display:none` 保内容不卸载（与最小化同一保活策略）；③ 卷起状态在任务栏图标上以小图标角标区分；④ 卷起窗口仍可拖动、贴靠（贴靠时自动展开）。
- **不做清单**：不做卷起高度自定义；不给嵌入 L1 窗口提供卷帘（第三方窗口重父级后高度受宿主约束，强行卷会破坏其渲染，如实不支持）。
- **验收**：卷起/展开各 50 次内容零重载；嵌入窗口右键菜单中该项置灰并显示「该窗口类型不支持」。

### M-03 最小化窗口抽屉（Minimized Drawer）

- **定位**：任务栏右下角「收纳抽屉」：所有已最小化的 VWM 窗口按时间序列出（标题+应用图标+最小化时刻），点击即还原。
- **动机**：窗口多了以后，最小化的窗口在任务栏里和运行中的混在一起；「刚最小化那个去哪了」是高频疑问。
- **具体内容**：① 新组件 `MinimizedDrawer`，入口为任务栏一枚抽屉图标 + 徽标计数；② 列表项含应用图标、窗口标题、相对时间（「3 分钟前」）；③ 支持 Ctrl+Alt+`（反引号，空闲槽）呼出、Esc 关闭、↑↓ 选择、Enter 还原；④ 空抽屉时图标自动隐藏（不占位）。
- **不做清单**：不做最小化历史记录（只列当前会话仍存活的窗口，环境退出即清空）。
- **验收**：最小化 20 个窗口后抽屉排序正确；还原后条目消失、计数-1；键盘全链路可达。

### M-04 窗口体检与无响应标记（Window Health）

- **定位**：VWM 对嵌入窗口与运行中第三方窗口做轻量体检：无响应（5s 消息泵停滞）时标题栏出现琥珀色「未响应」徽标，环境自身绝不动它，只提供「再等等 / 结束进程」两个选项。
- **动机**：用户分不清「卡了」还是「在算」；现在只能切出去开任务管理器。
- **具体内容**：① 后端 `winman.rs` 每 3s 轮询 `IsHungAppWindow`（仅对已登记窗口，开销极低）；② 前端标题栏徽标 + 悬停说明（「窗口 5 秒未响应，这是应用自身问题，Variable 不会替它做任何决定」）；③ 「结束进程」按钮走确认模态，明确提示会丢失未保存数据；④ 恢复响应后徽标自动消失。
- **不做清单**：绝不自动杀进程；不做 CPU/内存数值面板（那是性能 HUD 的地盘）。
- **验收**：用 `Sleep` 测试程序注入 6s 停滞，3~6s 内徽标出现；恢复后 ≤3s 消失；不误报正常窗口。

### M-05 跨屏摆渡走廊（Monitor Ferry）

- **定位**：把 VWM 窗口拖到屏幕边缘并停留 600ms，出现「摆渡预览」把窗口送进另一台显示器；全程有连续的位置动画，不闪、不跳。
- **动机**：目前多显示器下窗口跨屏移动是「瞬移」，坐标换算在混合 DPI 下还会错位；用户需要的是「看得见地过去」。
- **具体内容**：① 拖拽悬停边缘 600ms 后目标屏显示半透明落点预览；② 松手后窗口以 260ms 位移动画滑入目标屏（DPI 换算后按比例缩放几何）；③ 键盘版：Ctrl+Alt+Shift+←/→ 把聚焦窗口送邻屏（空闲槽，经注册表仲裁）；④ 摆渡中窗口渲染不中断。
- **不做清单**：不做循环摆渡动画的花活（一条直线位移动画即止）；不做超过 2 屏的路径规划（直接到目标屏）。
- **验收**：双屏 100%/150% 混合 DPI 下 20 次摆渡零错位；动画期间无白屏/黑屏帧。

### M-06 窗口挂起与恢复（Suspend / Resume）

- **定位**：VWM 窗口右键「挂起」：对应进程 `NtSuspendProcess` 冻结（0% CPU），窗口打上「已挂起」冰蓝徽标；「恢复」一键解冻，一切如常。
- **动机**：编译/渲染这类吃满 CPU 的后台任务，用户想临时让路给别的事，但不想取消重来。
- **具体内容**：① 仅对**嵌入登记的第三方进程**开放（四空间等环境内窗口不提供——它们本就可最小化零占用）；② 徽标 + 任务栏图标角标；③ 环境退出前自动恢复全部挂起进程（绝不带着挂起退出）；④ 挂起进程在系统任务管理器中显示「已挂起」，与系统语义一致。
- **不做清单**：不提供定时自动挂起规则（规则引擎 N-03 已覆盖该场景，本项只做手动开关）。
- **验收**：挂起期间进程 CPU 采样为 0；恢复后网络连接/窗口内容无损；环境退出时 `rg` 验证无残留挂起。

### M-07 对齐参考线（Alignment Guides）

- **定位**：拖拽 VWM 窗口时，与其他窗口边缘/中心线接近对齐时出现细参考线并吸附；可 Alt 临时禁用。
- **动机**：现在的贴靠只有「半屏/四角」档位；用户想两个窗口各占 1/3、或窗口边缘整齐排成一列时只能目测。
- **具体内容**：① 检测被拖窗口边缘与其他可见窗口边缘、屏幕中线/三分线的距离 <8px 时显示 1px 参考线并轻吸附；② 参考线颜色用 `--accent`（尊重主题与高对比度模式）；③ 设置项默认关闭；④ Alt 按住时本次拖拽禁用吸附（与 Figma/PowerPoint 同语义）。
- **不做清单**：不做「记住上次布局」；不做显示像素数值标尺（克制，避免变成设计工具）。
- **验收**：三窗口手动 1/3 排列 10 次，边缘间隙目测为 0 且几何值误差 ≤1px；Alt 禁用路径无吸附。

### M-08 精炼 Alt+Tab（Alt+Tab Refinement）

- **定位**：给环境内 Alt+Tab 轮转加两个可选过滤模式：按「当前显示器」过滤、按「当前应用」过滤；`Ctrl+Alt+Tab`（空闲槽）打开设置过的过滤模式，`Alt+Tab` 保持默认全局。
- **动机**：双屏用户 Alt+Tab 一半概率切到另一屏的窗口；同应用多开时想只在几个窗口间轮转。
- **具体内容**：① 复用现有 WintabSwitcher 的 Z 序数据，仅加过滤谓词；② 过滤结果为空时如实提示「当前过滤器下无其他窗口」并回退一次全局轮转（诚实降级，不静默改变行为）；③ 过滤模式记忆到 settings，勿扰状态不受影响。
- **不做清单**：不改变 Alt+Tab 默认行为（默认过滤=关）。
- **验收**：双屏各 5 窗口，显示器过滤下轮转集合正确；空集合提示文案 zh/en 齐全。

### M-09 悬停聚焦（X-Mouse，可选）

- **定位**：Windows 的「悬停时激活窗口」选项的 Variable 版：鼠标悬停 300ms 后窗口自动聚焦（仅前置，不抢键盘焦点到输入框），默认关闭。
- **动机**：一部分老 Unix/Windows PowerToys 用户重度依赖 X-Mouse；但默认开启对多数人是灾难，所以必须「默认关 + 三档可调（关/仅聚焦/聚焦并置顶）」。
- **具体内容**：① `VirtualWindowManager` 指针移动节流监听；② 仅聚焦档不改变 Z 序（只给焦点环/标题栏激活态）；③ 在全屏应用、拖拽中、模态打开时自动暂停；④ 设置项带一句诚实提示「该模式可能让部分用户不适，不确定请保持关闭」。
- **不做清单**：不做 0ms 即时聚焦（必误触）。
- **验收**：300ms 档在正常操作（滑过任务栏、扫过窗口）下误聚焦率 <2%（人工走查 50 次）。

## 域 T：任务栏与托盘进阶（M-10…M-18）

> 目标：任务栏从「显示状态」进化到「替你干活」。全部克制、默认值等于现状。

### M-10 跳转列表（Jump Lists）

- **定位**：任务栏固定图标右键弹出上下文任务单：最近打开的文件（本应用）、常用动作（新开窗口/进入设置）、最近 VWM 窗口。
- **动机**：Windows 任务栏最被低估的能力；用户期望「右键浏览器图标 → 最近项目」在 Variable 里也成立。
- **具体内容**：① 数据源：recent.ts 已有最近使用记录 + launcher 登记信息；② 每项图标支持 pin/unpin（钉住的置顶）；③ 对被嵌入应用，列出其最近实例窗口（点击聚焦）；④ 列表 ≤10 项，超过折叠「查看全部」。
- **不做清单**：不接管 Windows 系统任务栏的跳转列表（系统壳是系统的领地）。
- **验收**：10 个高频应用右键走查，最近文件真实可打开；pin 持久化重启不丢。

### M-11 托盘收纳抽屉（Tray Overflow Drawer）

- **定位**：Variable 托盘区的「溢出抽屉」：托盘图标超出阈值后收纳进二级抽屉，抽屉内可搜索、可拖动排序、可「置顶常驻」。
- **动机**：长跑一天后系统托盘图标 20+ 个，系统自带的 `^` 溢出是「藏起来就找不到」；需要一个能搜索的收纳处。
- **具体内容**：① 托盘枚举沿用 `tray.rs` 既有能力，新增溢出阈值设置（默认 8）；② 抽屉内拼音/首字母搜索（复用 pinyin.ts）；③ 图标 tooltip 显示完整名称（系统托盘 tooltip 截断问题的补偿）；④ 新图标出现时抽屉入口徽标 +1，点开后清零。
- **不做清单**：不修改系统托盘本身（只读取并镜像展示）；不提供系统托盘图标隐藏注入（越权且危险）。
- **验收**：注入 15 个测试图标，溢出后抽屉搜索「微信/wx/WeChat」三种输入均命中；置顶常驻重启保留。

### M-12 时钟多时区与细节（Clock Details）

- **定位**：任务栏时钟悬停卡片显示：多时区时间（用户配置 ≤3 个）、周数、今日已完成/待办计数（只读消费通知中心数据）。
- **动机**：跨时区协作用户每次都要换算；「今天第几周」是项目管理刚需。与 Z-22 时钟中心的区别：Z-22 是「时钟应用面板」，本项是**任务栏悬停卡**这一个小切面。
- **具体内容**：① 时区列表设置（城市名 + IANA 时区）；② 悬停卡在既有日期卡之上增量渲染，无新窗口；③ 周数用 ISO 8601 口径；④ 24h/12h、秒显开关沿用系统区域设置。
- **不做清单**：不做世界时钟地图、不做会议时间换算器（换算是 Z-26 的事）。
- **验收**：配置「上海/伦敦/纽约」三时区，夏令时切换日自动正确；zh/en/繁三语完整。

### M-13 任务栏等待态规范（Launch Pending State）

- **定位**：从开始菜单/快捷键启动应用到图标出现在任务栏之间，统一显示「占位呼吸图标」；超过 8s 未出现则占位转为「仍在启动（点击查看详情）」。
- **动机**：启动重软件（IDE、浏览器冷启动）有 3~10s 空窗，用户不知道点没点上，常常重复点击开出多实例。
- **具体内容**：① 占位图标用既有 `.skeleton` shimmer 样式（不新增视觉语言）；② 重复点击占位图标不重复启动（拦截 800ms 内的重复 ShellExecute）；③ 8s 后状态如实变文案，点击显示启动详情（进程 pid、已启动毫秒数）。
- **不做清单**：不做启动失败自动重试（自愈中心 N-25 的地盘）。
- **验收**：启动 10GB 级 IDE 时占位出现 ≤300ms；800ms 内连点 5 次仅 1 个实例。

### M-14 托盘 IM 未读聚合（IM Unread Aggregate）

- **定位**：imwatch 检测到的多个 IM（微信/Telegram/Discord…）未读数聚合成任务栏一枚总徽标，悬停分应用列出明细。
- **动机**：现在每个 IM 一个提醒源，多开时通知轰炸；聚合徽标让「有没有人找我」一眼可知，明细悬停才展开。
- **具体内容**：① 复用 imwatch.rs 的标题解析（只读窗口标题的红线不破）；② 总徽标数字 = 各 IM 之和，上限 99+；③ 悬停列出「微信 3 · Telegram 12」；④ 点击任一明细聚焦/启动对应 IM。
- **不做清单**：不读聊天内容、不解析窗口内容（只读标题既有边界）；不提供回复功能。
- **验收**：双 IM 各有未读时聚合与明细一致；某 IM 关闭后计数即时清零。

### M-15 任务栏空区菜单定制（Taskbar Blank Menu）

- **定位**：任务栏空白处右键菜单支持用户自选可见项与排序（任务管理器/设置/显示桌面/最小化抽屉/切换性能模式…），默认项集与现状一致。
- **动机**：右键任务栏空白是高频入口；现在项目固定，用户想把自己最常用的三项放前面。
- **具体内容**：① 菜单项注册表（id + i18n + 动作）；② 设置页「任务栏」区新增菜单编辑器（拖动排序 + 勾选显隐）；③ 与 Windows 11 任务栏右键菜单的项目语义对齐（任务管理器、任务栏设置入口）。
- **不做清单**：不支持任意命令注入（只有注册表内的安全项，防误配）。
- **验收**：自定义排序持久化；未勾选项不再渲染；默认状态与改动前逐像素一致。

### M-16 任务栏时钟的媒体呼吸（Media Breathing，可选）

- **定位**：音乐播放时时钟旁的媒体控件图标做 2% 幅度的呼吸缩放（4s 周期），暂停即静止；默认关闭。
- **动机**：播放状态「一眼可感知」且不打扰；幅度刻意压到接近阈值，属「感觉得到但说不出」的档位。这是本轮唯一的新动效，立项理由是媒体区已存在但状态不显眼。
- **具体内容**：① 复用 MediaControl 的播放态；② CSS 动画走 `prefers-reduced-motion` / `data-reduce-motion` 既有令牌，降级为静态；③ 幅度 2%、周期 4s，写死不可调（防调出怪东西）。
- **不做清单**：不做频谱可视化、不做随音量变色（花活红线）。
- **验收**：reduce-motion 用户永不看到呼吸；开启用户 30 分钟使用无「闪烁感」投诉口径（自测）。

### M-17 任务栏便签速贴（Quick Sticky）

- **定位**：Ctrl+Alt+S（空闲槽）或任务栏菜单唤出单行输入框，回车后生成一张桌面角便签（纯文本、无格式），自动 10 分钟淡隐，点击可钉住。
- **动机**：跨过「打开写作空间 → 新建记录」的重量级路径，接一个电话时只想记 10 个字。
- **具体内容**：① 便签是桌面 shell 层轻组件（与四大空间无关，不是写作空间的入口）；② 数据进 settings KV（轻量，不上 SQLite）；③ 桌面四角堆叠、可拖动、可一键全部清除；④ 环境重启后钉住的便签恢复，未钉住的如实消失。
- **不做清单**：不做富文本、不做提醒时间（提醒是 Z-49 的事）、不与写作空间打通（避免误导用户以为记进了记录库）。
- **验收**：输入→显示 ≤100ms；10 分钟淡隐动画 500ms；重启后钉住便签完整恢复。

### M-18 外设音量滚轮规范（Volume Wheel Etiquette）

- **定位**：键盘音量滚轮/多媒体键（VK_VOLUME_UP/DOWN/MUTE）在环境内被尊重：调节时显示与 QuickPanel 同款的音量浮标，且在 DND 下静音键照常生效。
- **动机**：多媒体键目前直达系统、环境无感知，浮标不出现、与 QuickPanel 的音量显示脱节。
- **具体内容**：① 前端捕获多媒体键（不抢占系统行为，仅监听渲染浮标）；② 浮标 1s 淡出；③ 与逐应用音量记忆（Z-43）联动显示当前应用档位。
- **不做清单**：不拦截/改写多媒体键的系统效果（系统音量该变就变，我们只做显示与联动）。
- **验收**：滚轮/静音键三种设备走查浮标正确；DND 下浮标照常（音量操作不是打扰）。

## 域 F：文件操作务实增强（M-19…M-27）

> 目标：只做「每天都在发生」的文件操作增量，全部只增不删、默认值等于现状。

### M-19 右键菜单自定义编辑器（Context Menu Editor）

- **定位**：设置页可视化编辑文件管理器右键菜单：显隐、排序、分组分隔线；只提供注册表内安全动作（打开/复制/剪切/重命名/删除/属性/发送到/压 None…）。
- **动机**：右键菜单 15+ 项后高频项沉底；每个人高频动作不同。
- **具体内容**：① 菜单项注册表（复用 ContextMenu 组件结构）；② 拖动排序 + 勾选显隐持久化；③ 「恢复默认」一键还原；④ 二级菜单支持折叠/展开默认态。
- **不做清单**：不支持注册任意 shell 命令（安全红线）；不改系统右键菜单。
- **验收**：自定义后 50 次右键走查顺序与设置一致；恢复默认与出厂逐项相同。

### M-20 同名操作选择记忆（Conflict Choice Memory）

- **定位**：文件复制/移动遇到同名时的对话框增加「对剩余全部应用此选择」的勾选记忆（仅本次批量会话内有效，不跨会话）。
- **动机**：批量拷 200 个文件弹 47 次同名框是最真实的痛；但「永久记住替换」又太危险，所以记忆只活在本次批量操作内。
- **具体内容**：① 冲突对话框（已有）+ 会话级选择传播；② 批量结束时 toast 汇总「替换 40 · 跳过 7 · 保留两者 0」；③ 「保留两者」自动重命名规则展示预览。
- **不做清单**：不做跨会话/可配置的默认策略（危险面太大）。
- **验收**：200 文件含 47 同名的合成批量，弹窗 1 次 + 汇总正确；Esc 中断批量不产生半拷文件（走既有事务路径）。

### M-21 校验和工具（Checksum Utility）

- **定位**：文件右键「校验和」：计算 MD5/SHA-1/SHA-256/BLAKE3（BLAKE3 复用容器既有实现），支持「输入期望值比对」与「复制」。
- **动机**：下载镜像/校验发布包是极高频动作；开 PowerShell 输命令太重。
- **具体内容**：① 后端流式分块哈希（1GB 文件不进内存，进度事件流式回传）；② 大文件计算显示进度 + 可取消；③ 期望值粘贴框，一致显示绿勾、不一致红叉并高亮差异字符。
- **不做清单**：不做哈希数据库/在线查询（离线红线）。
- **验收**：1GB 随机文件四算法结果与 certutil 一致；取消后无临时文件残留。

### M-22 空格快速预览（Quick Look）

- **定位**：文件管理器选中文件按空格，弹出居中浮窗快速预览（图/文/音/视/PDF/代码着色）；再按空格或 Esc 关闭；方向键切换相邻文件预览。
- **动机**：macOS Quick Look 是「翻找文件」效率的代名词；与 Z-29（预览格式扩展）的区别：Z-29 扩的是**格式支持**，本项做的是**空格浮窗这一交互形态**与连续浏览。
- **具体内容**：① 预览渲染复用 explorer 既有预览组件，浮窗化封装；② 支持格式白名单诚实降级（不支持格式显示图标 + 类型说明，不装能看）；③ ←/→ 连续切换、↑/↓ 上下层级、空格开关；④ 浮窗不抢焦点到内容（视频/音频例外，需要控制条）。
- **不做清单**：不做预览内编辑；不做缩略图瀑布流（那是 Explorer 2.0 的视图问题）。
- **验收**：20 种常见格式走查，支持列表内全正确、不支持的全部如实降级；键盘闭环无鼠标依赖。

### M-23 压缩包目录浏览（Zip Browse-Only）

- **定位**：zip/7z/tar 在文件管理器中显示为可进入的「只读目录」，浏览内部结构、双击单个文件直接解压到临时目录并打开。
- **动机**：取压缩包里 1 个文件却要整包解压，是最普遍的浪费。
- **具体内容**：① 后端用 zip/ta-rs 等纯 Rust 解析（只读，不落盘整包）；② 双击单文件 → 解到缓存目录 → 系统默认程序打开，关闭后缓存清理；③ 压缩包损坏时如实报错（不尝试修复）；④ 包内搜索（文件名）。
- **不做清单**：不做压缩/创建压缩包（传输指挥台的归档语义已由 Z-29/存档柜覆盖）；不支持加密包写操作。
- **验收**：3GB zip 浏览首屏 ≤1s；单文件解压打开正确；损坏包错误文案 zh/en 齐。

### M-24 目录置顶书签条（Places Pins）

- **定位**：文件管理器地址栏旁的「书签条」：当前目录一键置顶/取消，置顶目录按使用频率排序（LRU 上限 12 个）。
- **动机**：与 Z-31（位置侧栏，系统级预设位置）的区别：本项是**用户自己钉的**高频目录，自动按真实使用频率进化。
- **具体内容**：① 目录访问计数进 settings KV；② 书签右键 → 在新标签打开/资源管理器打开/取消置顶；③ 拖拽文件夹到书签条即置顶（与拖放总线手势一致）。
- **不做清单**：不做层级书签树（克制，一条横排）。
- **验收**：钉 12 个后第 13 个自动淘汰最久未用；重启排序保留。

### M-25 文件锁定侦探（File Lock Detective）

- **定位**：删除/移动失败提示「文件被占用」时，一键展开占用侦探：列出占用该文件的进程名、pid、窗口标题（如系统可查），并提供「跳转到任务管理器对应进程」。
- **动机**：「操作无法完成，因为文件已在 X 中打开」——X 有时根本不告诉你是谁；用户被迫注销重登。
- **具体内容**：① 后端用 Restart Manager API 枚举占用者（Windows 官方姿势，无驱动）；② 查不到占用者时如实显示「系统未披露占用者（可能是系统服务）」；③ 只提供跳转与刷新，**不提供强拆句柄**（危险操作红线）。
- **不做清单**：绝不提供「强制解锁/删除被锁文件」按钮。
- **验收**：用 Word 打开 docx 后删除，侦探正确列出 WINWORD；系统页面文件等无窗口占用显示诚实降级文案。

### M-26 环境回收站安全网（Delete Safety Net）

- **定位**：文件管理器删除行为可配置为「先进 Variable 回收站 2.0（Z-27），Shift+Delete 才真删」；默认等于现状（进系统回收站）。
- **动机**：误删是数据安全第一大敌；给「想把删除全部留在自己环境里审计」的用户一个选择。
- **具体内容**：① 设置项三档：系统回收站（默认）/环境回收站/直接询问；② 环境回收站路径在便携模式自动跟随数据卷；③ 清空前的确认模态显示可恢复的最近 10 项（劝退式确认）。
- **不做清单**：不做覆写式删除（极端化红线，已被用户明令禁止）。
- **验收**：三档行为各走查 10 次；便携模式拔盘保护（usb.rs）联动正常。

### M-27 目录监控哨兵（Folder Sentinel）

- **定位**：用户给任意目录挂「哨兵」：新文件/删除/改名事件推送到通知中心（可配声音）；与宏引擎（N-18）互补——宏引擎做「触发后动作」，本项做**事件源与通知**这一最轻层。
- **动机**：盯一个共享目录/下载目录/构建输出目录，是自动化需求里最朴素的一种，不需要宏的重量。
- **具体内容**：① 后端 ReadDirectoryChangesW（每个哨兵一条线程，上限 5 个目录）；② 事件合并节流（1s 窗口内同目录合并成一条「新增 12 个文件」）；③ 每哨兵独立开关 + 免打扰期；④ 环境隐藏时事件照常记录，唤回后通知中心可查。
- **不做清单**：不做触发后执行动作（那是宏引擎）；不做网络目录监控（SMB 抖动大，如实不支持）。
- **验收**：下载目录连收 50 文件合并为 1 条通知；5 哨兵上限第 6 个被拒并提示。

## 域 K：键位与输入手感（M-28…M-36）

> 目标：键鼠输入的「细水长流」。全部走 Z-08 注册表（未落地前只占 `ctrl+alt+` 空闲槽）。

### M-28 键位使用统计（Keymap Telemetry，本地）

- **定位**：本地统计每个快捷键的触发次数与「被占用降级率」，设置页快捷键中心显示冷热榜；**纯本地**，绝不上传。
- **动机**：哪个键没人用、哪个默认键总被系统占用，数据说了算；冷键槽位可以释放给新功能。
- **具体内容**：① dispatch_action 处埋点计数（内存 + 定期落 settings KV）；② 快捷键中心列表加「近 30 天使用 N 次」列；③ 降级失败的键位单独成「占用榜」，并给一键换绑建议（挑空闲槽）。
- **不做清单**：不做按键间隔/输入内容记录（只记动作 id + 次数）。
- **验收**：触发 100 次散布 5 个动作，计数准确；数据文件 <10KB/月。

### M-29 长按加速曲线（Key Repeat Profiling）

- **定位**：Win+方向键移动窗口、方向键在窗口网格中导航时，长按 500ms 后进入加速（1.5x→2.5x→4x 三段曲线），与系统光标移动手感一致。
- **动机**：按 20 次方向键才能把窗口挪半屏；系统文本光标有加速，窗口没有。
- **具体内容**：① 只作用于「窗口移动/网格导航」两类重复语义键；② 曲线常数写死（防调坏）；③ reduce-motion 不影响（这是效率不是动效）。
- **不做清单**：不做用户可调曲线（过度配置）。
- **验收**：长按 2s 的移动距离 ≈ 单击 12 次的距离（±15%）；短按无加速。

### M-30 鼠标侧键可编程（XButton Programming）

- **定位**：鼠标第 4/5 键（XButton1/2）在环境内可映射为：后退/前进（默认，等于现状）、呼出命令面板、切换窗口、贴靠左右。
- **动机**：五键鼠标用户的两颗侧键在环境内目前只对 explorer 生效；这是最便宜的「获得两个新快捷键」的方式。
- **具体内容**：① kbdhook 路径识别 XButton（全局钩子内白名单转发）；② 默认映射=系统语义（零退化）；③ 全屏应用/游戏内自动让位回系统。
- **不做清单**：不做全键盘任意键映射（Z-14 方案的地盘）。
- **验收**：五键鼠标浏览器前进后退默认不变；映射切换面板后全屏游戏内自动恢复系统语义。

### M-31 启动槽可视化分配（Launch Slots Editor）

- **定位**：设置页把 Ctrl+Alt+1…9 九个启动槽做成可视化托架：从开始菜单/桌面拖应用图标进槽即绑定，槽位显示应用图标。
- **动机**：launch1-9 现在只能在下拉框里选名字；拖拽分配所见即所得，且槽位直接展示图标更像「系统的固定栏」。
- **具体内容**：① 复用桌面图标拖拽手势与 Droppable 逻辑；② 槽位冲突（同应用多槽）允许但提示；③ 空槽显示虚线框 + 键位标签。
- **不做清单**：不扩展槽位数量（9 个封顶，防键位通胀）。
- **验收**：拖拽绑定后按键启动正确；删除应用后槽位自动清空并提示。

### M-32 每窗口输入法状态（Per-Window IME State）

- **定位**：环境为每个 VWM 窗口记忆「上次聚焦时的 IME 中英状态」，切回该窗口时自动恢复。
- **动机**：在终端敲命令（英文）→ 切去聊天（中文）→ 切回终端又打了一屏中文，是中文用户每天 20 次的痛。与 Z-17（IME 深度兼容）的区别：Z-17 解决「IME 在环境内不坏事」，本项做「IME 状态跟随窗口」的体验层。
- **具体内容**：① 前端监听 VWM 焦点切换 + 读取 IME 转换模式（ImmGetConversionStatus 不可用则降级为不干预）；② 状态条托盘显示当前窗口记忆态；③ 四大空间窗口同样适用（只读 IME 状态，不改其代码）。
- **不做清单**：不强行切换系统 IME（只在可查询/可设置的 API 范围内动作，失败则如实不动）。
- **验收**：终端↔聊天 50 次往返，状态恢复正确率 ≥95%；API 不可用环境零副作用。

### M-33 按键回显（Key Cast Overlay）

- **定位**：可选的「演示模式」：屏幕角落浮层回显当前按下的修饰键组合与功能名（如 `Ctrl+Alt+V → 剪贴板历史`），用于教学/录屏/截图。
- **动机**：写教程、教家人用电脑、录操作演示时的刚需；平时一键关闭。
- **定位细节**：① 入口在设置→辅助功能，默认关；② 浮层 2s 淡出，位置四角可选；③ 只回显**功能键组合**，不回显打字内容（隐私红线：绝不显示普通字符输入）。
- **验收**：开启后 20 组快捷键回显正确；打字时浮层零出现。

### M-34 Esc 层级语义规范（Esc Semantics）

- **定位**：全环境统一 Esc 关闭层级：模态 > 浮层面板 > 右键菜单 > 搜索框清空 > 无操作；每层只关一层，连续 Esc 逐层退出到桌面。
- **动机**：不同面板对 Esc 的处理不一致（有的全关、有的没反应），连续 Esc 的肌肉记忆没有稳定预期。
- **具体内容**：① Esc 处理收编为 uiStore 的「浮层栈」模型（栈顶消费、逐层弹出）；② 现有 12 类浮层逐一走查归类入栈；③ 文档化层级表进帮助中心。
- **不做清单**：不改「双击 Esc 切环境」的 kbdhook 语义（那是既有全局契约）。
- **验收**：开 5 层浮层连按 5 次 Esc 逐层关闭无跳层；双击 Esc 语义不受影响。

### M-35 滚轮语义全局规范（Wheel Semantics）

- **定位**：Shift+滚轮=横向滚动、Ctrl+滚轮=缩放（支持处）、悬停任务栏滚轮=音量（可选），三条规则全局统一并文档化。
- **动机**：滚轮行为现在各组件各自为政；用户在列表里 Shift+滚轮有效、在导图里无效（导图属四空间，不改动——本项只统一**壳层**组件）。
- **具体内容**：① 壳层 15 个滚动容器逐一走查补齐；② 任务栏滚轮音量默认关（防误触，与 M-18 联动显示浮标）；③ 行为表文档化。
- **不做清单**：不碰四大空间内部画布（隔离红线）。
- **验收**：壳层全部滚动容器三规则一致；默认行为与现状相同（任务栏滚轮音量默认关）。

### M-36 键位变更影响预览（Keymap Change Preview）

- **定位**：改键保存前显示「此键位当前还被 X 使用 / 系统占用风险 高」的影响预览卡，一键「查看冲突」跳到占用者。
- **动机**：改键后才发现撞了系统 Win+X 或自家功能，用户只能瞎试；冲突要在保存前看见。与 Z-08（注册表与仲裁机制）互补：注册表是地基，本项是**改键 UI 的预览体验**。
- **具体内容**：① 保存前 diff 当前绑定 → 列出被挤占项；② 系统保留键库内置（Win+E/D/M/N/I/V/数字/方向/Tab…）风险标注；③ 提供「自动挑一个空闲槽」按钮。
- **不做清单**：不做一键交换两个键位（少见且易错）。
- **验收**：把 Ctrl+Alt+E 改到已占用组合，预览正确列出双占用；空闲槽建议可用。

## 域 C：兼容性纵深（M-37…M-45）

> 目标：什么软件、什么机器、什么外设都相安无事。原则：只观察、只提示、只降级，绝不越权干预。

### M-37 图标缓存校验与自愈（Icon Cache Integrity）

- **定位**：launcher 图标缓存加校验和与 mtime；启动时快扫失效项后台重建，扫描不打断开始菜单渲染（先显示占位）。
- **动机**：软件升级/卸载后开始菜单出现白图标，用户无从下手。
- **具体内容**：① 缓存条目记录源 .lnk 的 mtime + hash；② 失效条目进后台重建队列（并发 ≤2）；③ 重建完成事件通知前端替换，替换时无闪烁（沿用 Z-66 图标零闪策略）。
- **不做清单**：不做全量重建按钮以外的任何主动清理（保守）。
- **验收**：升级/卸载某软件后重启，开始菜单 10s 内自愈；未自愈前占位不空白。

### M-38 UWP 应用识别增强（UWP Awareness）

- **定位**：开始菜单正确识别 UWP/MSIX 应用：官方图标、显示名、发布者、启动（独立窗口，如实标注「不可嵌入」）。
- **动机**：UWP 应用现在常显示为灰色通用图标或英文名，体验割裂；嵌入不支持没关系，但「认识它」是底线。
- **具体内容**：① 通过 GetStartApps + 包管理 API 枚举；② 与 .lnk 扫描结果去重合并；③ compat 矩阵标记 tier=L4（让位）。
- **不做清单**：不尝试嵌入 UWP（技术边界如实）。
- **验收**：Store 常见 20 个 UWP 应用名/图标正确；启动正常；嵌入按钮置灰有说明。

### M-39 提权应用协作提示（Elevation Etiquette）

- **定位**：启动需要管理员权限的应用时：检测 manifest 的 requireAdministrator → 先弹一张说明卡「该应用需要管理员权限，将以独立窗口运行、退出后环境仍在」，再 ShellExecute runas。
- **动机**：提权应用不能嵌入；现在的体验是「点了没嵌入，是不是坏了」。诚实预告比事后解释好十倍。
- **具体内容**：① 读取 PE manifest 提权标记（安全工作台已有 PE 解析能力，复用）；② 说明卡每应用只显示一次（记住选择）；③ UAC 弹出失败（拒绝）如实回执。
- **不做清单**：不替用户绕过 UAC（红线）。
- **验收**：10 个常见提权工具走查说明卡正确；拒绝 UAC 后 toast 如实。

### M-40 高刷自适应时长（High-Refresh Timing）

- **定位**：检测显示器刷新率 ≥120Hz 时，动效时长按 0.85x 折算（动作更利落），60Hz 保持现状；全局一个开关（默认开）。
- **动机**：同一 240ms 动效在 144Hz 屏上显得拖；高刷用户对「跟手」的预期更高。做法克制：只调时长，不加速度曲线。
- **具体内容**：① 后端 QueryDisplayConfig 取刷新率；② 前端 `--dur-*` 令牌乘系数（令牌化的收益兑现点）；③ 混合刷新率多屏按主屏。
- **不做清单**：不做逐动效自定义时长（Z 域编排的事）。
- **验收**：144Hz 屏 170ms 贴靠动效折算为 ~145ms 且无跳帧；60Hz 屏零变化。

### M-41 外设驱动软件共存协议（Peripheral Driver Coexistence）

- **定位**：检测 Logitech G Hub / Razer Synapse / 雷蛇等键鼠驱动在运行时，环境弹一次性提示卡「检测到 X 在运行，侧键/宏可能由其接管；若键位异常，可在其内排除 Variable」，并提供「不再提示」。
- **动机**：驱动软件的宏层与全局钩子打架时，用户第一反应是「Variable 坏了」；提前告知归属能省一次误报工单。
- **具体内容**：① 进程名快照匹配已知驱动清单（内置 10 个主流，可更新）；② 提示卡只出现一次（settings 记忆）；③ 帮助中心收录「与驱动软件共存」条目。
- **不做清单**：不干预、不屏蔽驱动进程（红线）。
- **验收**：运行 G Hub 时提示卡出现一次；勾选不再提示后不再出现。

### M-42 多实例应用任务栏区分（Instance Badging）

- **定位**：同一 exe 多开（如两个 Chrome profile、双 IDE）在任务栏图标上显示实例角标（1/2/3），悬停 tooltip 显示区分性窗口标题。
- **动机**：三个同图标窗口在任务栏排排坐，点错率 30%；角标是最便宜的区分。
- **具体内容**：① 按 exe path 聚合计数；② 角标样式沿用 IM 未读徽标组件（视觉一致）；③ ≤3 显示数字，>3 显示 `3+`。
- **不做清单**：不做按窗口标题自动分组重命名（规则引擎的地盘）。
- **验收**：双开 5 组应用角标正确；关闭一个实例后角标即时收敛。

### M-43 便携路径漂移自愈（Portable Path Healing）

- **定位**：便携模式下 U 盘盘符变化（E:→F:）后，launcher 登记路径、壁纸池、数据卷引用自动按「卷 GUID + 相对路径」重定位。
- **动机**：换一台电脑插 U 盘盘符几乎必变；现在需要用户手动重登记，便携体验的核心断点。
- **具体内容**：① 登记时同时记录卷 GUID；② 启动时数据卷定位失败 → 枚举卷 GUID 匹配 → 命中即批量改写登记路径并 toast 告知；③ 未命中走既有应急包流程。
- **不做清单**：不做跨盘符内容同步（那是接力 N-36）。
- **验收**：U 盘 E:→F: 模拟 10 次，全部自动恢复；拔盘保护不误触发。

### M-44 嵌入应用崩溃善后（Embed Crash Aftercare）

- **定位**：被嵌入应用崩溃时：虚拟窗口 300ms 优雅摘除（不残留黑框）、弹一张「应用 X 已停止运行」卡片带「重新打开」按钮、环境零感知继续运行。
- **动机**：嵌入应用的崩溃残留（黑底窗口、失焦死区）是「环境坏了吗」恐慌的最大来源；崩溃归应用，善后归环境。
- **具体内容**：① 监听嵌入进程退出事件（已有 embed 会话状态机扩展）；② 摘除动画复用关闭仪式样式；③ 重开按钮沿用上次启动参数；④ 取证日志记录崩溃时间/pid/退出码（本地）。
- **不做清单**：不自动重启（用户决定）；不弹多个重复卡片（同应用 60s 内合并）。
- **验收**：注入 crash 测试 20 次，黑框残留 0 次；重开按钮可用；环境内存无泄漏。

### M-45 输入设备热插拔稳定（Input Hot-Plug Stability）

- **定位**：键盘/鼠标热插拔（蓝牙键鼠休眠唤醒、USB 重插）后：全局快捷键自动重注册、钩子自动重挂、期间输入不堆积不丢失。
- **动机**：蓝牙键盘休眠唤醒后 RegisterHotKey 失效是 Windows 老问题；用户以为「快捷键坏了」。
- **具体内容**：① 监听 WM_DEVICECHANGE；② 触发快捷键重注册（指数退避，5 次）；③ 重挂期间队列缓存 dispatch 动作 ≤1s；④ 全程 toast 一次「输入设备已重连，快捷键已恢复」。
- **不做清单**：不锁定设备布局（系统的职责）。
- **验收**：蓝牙键鼠休眠/唤醒 30 次，快捷键恢复率 100%；重挂期 ≤2s。

## 域 S：长跑稳定性（M-46…M-54）

> 目标：挂机一周不出事的工程底座。全部后台静默，用户无感即成功。

### M-46 日志轮转与配额（Log Rotation Quota）

- **定位**：后端日志按天 + 5MB 双阈值轮转，保留最近 7 份；总配额 50MB 超限删最旧。
- **动机**：取证日志与调试日志现在无限增长；挂机一个月能把 U 盘便携模式写穿。
- **具体内容**：① log 写入统一走 append + 轮转检查（每 N 条一次）；② 压缩归档（旧份 .gz）；③ 设置页显示当前日志占用与「立即清理」。
- **不做清单**：不做日志上传（离线红线）。
- **验收**：注入日志洪峰 100MB 后目录稳定在配额内；轮转期间写入不丢条目。

### M-47 设置迁移预检（Settings Migration Preflight）

- **定位**：升级安装前对 settings KV 做 schema 预检：未知键列举、损坏值检测、迁移演练（dry-run），失败则出「保守升级」建议（备份后清未知键）。
- **动机**：升级后设置丢失/错乱是最伤信任的事故；预检把事故拦在安装前。
- **具体内容**：① settings schema 版本化（现已版本化迁移，补 dry-run 层）；② 演练输出 diff 报告；③ 与既有自更新回滚（sysmaint）联动：预检不过 → 自动备份先行。
- **验收**：构造 5 种损坏 settings 样本，预检全部拦截且给出正确建议；正常升级零感知。

### M-48 数据库紧凑会话（DB Compaction Session）

- **定位**：sysmaint 计划任务新增「数据库紧凑」：空闲（无输入 ≥15min）且非电池供电时执行 incremental_vacuum + WAL checkpoint，进度走既有维护面板。
- **动机**：SQLite 长跑膨胀 3~5 倍是常态；便携模式 U 盘空间金贵。
- **具体内容**：① PRAGMA auto_vacuum=incremental 一次性迁移（首次升级后执行一次）；② 触发条件四要素（空闲/接电/非备份中/距上次 ≥7 天）；③ 执行前强制快照（走备份通道）。
- **不做清单**：不做定时硬compact（条件不满足就不做，绝不打扰）。
- **验收**：删 10 万条记录后紧凑回收 ≥80% 空间；紧凑期间写入请求排队 ≤200ms。

### M-49 图标缓存 LRU 治理（Icon Cache LRU）

- **定位**：图标位图缓存引入 LRU 上限（默认 256MB，可调 64~512MB），超限淘汰最久未用；缓存命中率达到 95%+。
- **动机**：图标缓存现在只增不减；重度用户（500+ 应用）内存悄悄吃掉半个 GB。
- **具体内容**：① 缓存条目带 last_used；② 淘汰分批（每批 ≤32 张）避免卡顿；③ 设置页显示缓存占用/命中率。
- **不做清单**：不做跨会话持久化缓存（重启冷启动可接受，换复杂度不值）。
- **验收**：500 应用滚动开始菜单 3 遍，第三遍命中率 ≥98%；内存峰值 ≤ 上限 + 10%。

### M-50 事件风暴削峰（Event Storm Shedding）

- **定位**：高频事件（窗口枚举、进程快照、设置广播）统一走「合并窗口 + 背压丢弃策略」框架：同频道 50ms 内合并、UI 忙时丢中间保最新。
- **动机**：打开 60 窗口的项目时窗口事件风暴让 UI 掉帧；各模块自造轮子节流，行为不一致。
- **具体内容**：① 新 lib 层 `eventShed.ts`（纯前端，不碰后端模块归属）；② 三档策略（合并/最新/排队）声明式配置；③ 5 个风暴源（winman 轮询、imwatch、设置广播、硬件面板、VWM 状态）迁移接入。
- **不做清单**：不做跨进程事件总线（开放事件流 O-52 的地盘）。
- **验收**：注入 1000 事件/秒的合成风暴，UI 帧率降幅 <5%；行为「最新必达」100%。

### M-51 长跑浸泡测试基建（Soak Test Harness）

- **定位**：nightly soak：无头模式跑 8 小时合成负载（开/关窗口、启停应用、设置读写、事件风暴），每小时快照内存/句柄/句柄数增长曲线，超阈值报警。
- **动机**：「不崩溃」的证明只能靠时间； soak 是长跑稳定性的唯一证据源。
- **具体内容**：① 复用 bench 工具链加 `--soak` 模式；② 泄漏判定：8h 内存增长 <100MB、句柄增长 <500；③ 报告归档 docs/bench（沿用现有归档纪律）。
- **不做清单**：不做 CI 强制门禁（先观察一个月，稳定后再升级为门禁）。
- **验收**：连续 7 晚 soak 通过率 ≥6/7；报告含趋势曲线。

### M-52 冷启动 A/B 对照（Boot A/B Comparator）

- **定位**：每次发版自动与上一版做冷启动对照：总耗时 + boot 各阶段分项耗时，回归 >10% 的阶段标红并归因建议。
- **动机**：启动速度是体验第一印象；无对照的「感觉变慢了」无法归因。
- **具体内容**：① boot 事件流已有分阶段时间戳，补「分项耗时快照 JSON」落盘；② 对照工具输出 diff 报告进发版清单；③ 机器口径固定（同机、空载、5 次取中位）。
- **不做清单**：不做线上遥测（离线红线）。
- **验收**：连续 3 个版本对照报告稳定产出；人为注入 200ms 延迟能被定位到具体阶段。

### M-53 崩溃转储收集与符号化（Crash Dump Pipeline）

- **定位**：Rust 侧 panic / WebView 崩溃时写 minidump（本地 `crashes/` 目录），保留最近 10 份；提供离线符号化脚本（发版包带符号表时自动解析栈）。
- **动机**：「崩溃了但没有任何线索」是修复的起点困境；minidump 是 Windows 原生标准答案。
- **具体内容**：① SetUnhandledExceptionFilter + MiniDumpWriteDump；② 崩溃后下次启动检测并提示「可导出诊断包」（联动 Z-42 诊断导出）；③ 符号化工具脚本 tools/symbolize.ps1。
- **不做清单**：不上传崩溃转储（离线红线）。
- **验收**：注入崩溃 5 次，dump 100% 落盘且可符号化出主栈；crashes 目录轮转正常。

### M-54 资源公平调度（Resource Fairness）

- **定位**：对被嵌入的第三方进程提供可选 CPU 配额（Job Object 限额，三档：不限制/50%/25%），配额生效时窗口徽标提示。
- **动机**：后台挂着的一个失控网页标签能把整机 CPU 吃满，拖垮整个环境；用户需要温和的「限流」而不是「杀死」。
- **具体内容**：① JobObjectSetInformationJobObject CPU_RATE 限额；② 每应用独立设置（登记信息扩展）；③ 配额进程在硬件面板标黄。
- **不做清单**：不做内存限额（易触发进程崩溃，副作用大）；不做自动配额（仅手动）。
- **验收**：50% 配额下 Cinebench 类负载被限制在半核口径；取消配额即时恢复满速。

## 域 O：开放性与生态健康（M-55…M-63）

> 目标：让别人能安全地给你写东西、给你反馈、给你翻译。开放是信任的放大器。

### M-55 路由注册公开表（Route Registry Spec）

- **定位**：variable:// 深链路由的公开注册表：全部路由、参数 schema、版本、所有者，随版本自动生成 markdown 文档 `docs/ROUTES.md`。
- **动机**：深链（Z-37 协议中枢）落了 20+ 路由后，外部（插件/浏览器伴侣/脚本）需要一份可编程对照的权威清单，手工维护必漂移。
- **具体内容**：① 路由声明处加结构化注解（id/params/owner/since）；② 生成脚本 tools/gen-routes.cjs 进发版流程；③ 文档带可复制示例链接。
- **不做清单**：不做路由在线 playground（离线红线）。
- **验收**：`rg` 校验文档与代码路由 100% 同步（audit.cjs 检查项）；示例链接全部可点开。

### M-56 设置项自动文档（Settings Auto-Doc）

- **定位**：从设置 schema 自动生成《设置手册》：每项的键名、类型、默认值、取值范围、since 版本、i18n 描述。
- **动机**：设置项 100+ 后，「到底有哪些设置」连开发者都说不全；用户自配置/迁移/求助都需要一份手册，手工写必过期。
- **具体内容**：① settings 定义处集中元数据（现有 sanitize 层已有雏形）；② 生成 `docs/SETTINGS.md`；③ 与导出格式（Z-51）字段一一对应。
- **验收**：新增一个设置项不改文档，下次发版自动出现在手册里；默认值与代码实测一致。

### M-57 本地出站桥（Local Webhook Bridge，opt-in）

- **定位**：用户可配置「事件 → 本地 URL」的转发规则（如「窗口嵌入成功 → POST http://127.0.0.1:9000/hook」），严格复用联网确认弹窗与域名白名单体系，默认关闭。
- **动机**：进阶用户想把环境事件接进自己的 Home Assistant/n8n/日志管道；这是插件之外最轻的自动化出口。与 N-28（IPC 网关，进程内）的区别：本项是 **HTTP 出站**这一形态。
- **具体内容**：① 规则表（事件源复用 O-52 事件流白名单子集）；② 出站前逐次走 netconsent（或会话级白名单+开关）；③ 失败重试 1 次，结果本地日志；④ URL 仅允许内网/环回段（公网地址需要二次确认）。
- **不做清单**：不做云端转发；不做未经确认的任何出站。
- **验收**：指向本地 echo server 的规则 10/10 送达；未确认时 0 出站（抓包验证）。

### M-58 插件开发热重载（Plugin Dev Reload）

- **定位**：插件开发模式：`variable plugin dev <dir>` 监听插件目录变更，改动即热重载（无需重启环境），控制台输出结构化日志。
- **动机**：插件开发「改一行重启一次」的循环杀死热情；热重载是生态繁荣的第一基建。
- **具体内容**：① 插件运行时 2.0（N-26）之上的 dev 通道；② 文件 watch + 沙箱重建；③ dev 模式插件带明显 DEV 角标（防混淆生产）。
- **不做清单**：不做插件商店上架流程（市场的事）。
- **验收**：改插件 manifest/代码 20 次，热重载成功率 ≥95%；坏插件隔离失败不影响环境。

### M-59 第三方嵌入声明协议（Embed Manifest Protocol）

- **定位**：公开一个 `variable-embed.json` 声明格式：第三方软件可在自身目录放置该文件，声明「我希望被嵌入时的窗口标题匹配、最小尺寸、多实例策略、检测等待毫秒」；环境据此优化嵌入体验。
- **动机**：现在嵌入参数（捕获等待、标题匹配）全靠环境侧猜测与人工登记；给应用作者一个主动声明的通道，是「开放生态」的深层含义。与 Z-15（适配等级库，环境侧记录）互补：一个环境记、一个应用自己说。
- **具体内容**：① schema 定义 + 校验器；② launcher 扫描时读取并合并（应用声明优先级低于用户登记）；③ 声明样例进文档。
- **不做清单**：不做声明签名强制（v1 阶段先跑通格式，签名留给信任链中心）。
- **验收**：带声明的测试应用嵌入等待时间按声明生效；非法声明被忽略且日志记录。

### M-60 测试钩子规范（Test Hooks Standard）

- **定位**：全环境 data-testid 命名规范（`{组件}-{语义}`）+ e2e 辅助命令（`variable test ready` 等待环境就绪），让社区也能写 e2e。
- **动机**：现在测试选择器靠 class 名凑合，重构即碎；规范化的钩子让 UI 自动化与视觉回归都稳。
- **具体内容**：① 规范文档 + 现有 15 条主路径补齐钩子；② audit.cjs 检查重复 testid；③ e2e 就绪哨兵（boot 完成事件）。
- **验收**：15 条主路径 e2e 脚本在钩子重构后零修改通过。

### M-61 变更日志自动化（Changelog Automation）

- **定位**：发版时从 conventional commits 自动生成 CHANGELOG 增量草稿（分 feat/fix/docs/perf），维护者只做删改不做录入。
- **动机**：CHANGELOG 手写必滞后；自动草稿把成本降到「审阅」级。
- **具体内容**：① tools/gen-changelog.cjs（git log 解析）；② 与发版演练（M-87）串成流水；③ 输出中文模板（项目语言）。
- **验收**：对最近 50 条 commit 生成草稿，归类准确率 ≥90%（人工抽检）。

### M-62 社区翻译工作台格式（i18n Crowd Format）

- **定位**：i18n 词典支持 CSV 导入导出（键、zh、zh-Hant、en 四列），社区用表格软件即可贡献翻译；导入时走键校验 + 简繁转换器预检。
- **动机**：想帮忙翻译的人被 JSON 挡在门外；CSV 是最低门槛。与 U-41（多语言中心 2.0，运行时管理）的区别：本项是**贡献工作流**。
- **具体内容**：① 导出全部键/导入仅允许更新既有键（新增键走代码评审）；② 循环引用与占位符（{n}）校验；③ audit.cjs 保持四语一致性检查。
- **验收**：导出→改 20 条→导入，20 条生效且零副作用；坏占位符被拒绝并定位行号。

### M-63 资源包安全扫描（Pack Safety Scan）

- **定位**：导入 .vxs 资源包（主题/壁纸/图标包）前的静态安全扫描：体积、文件类型白名单、路径穿越检查、超大图与可执行文件拦截；报告随导入确认展示。
- **动机**：开放生态 = 攻击面扩张；导入前的自动检查是生态可信度的守门员。
- **具体内容**：① 白名单（图片/CSS/JSON/字体）；② zip slip 路径穿越防护（pathGuard 前置）；③ 扫描报告（文件数/类型分布/可疑项）在确认模态里如实展示。
- **不做清单**：不做病毒云查杀（离线红线；提示用户自行 VirusTotal）。
- **验收**：构造恶意包（含 exe、`../` 路径、500MB 假图）全部拦截；正常包 10 个零误报。

## 域 A：沉浸与氛围·克制版（M-64…M-72）

> 目标：氛围是减法不是加法。本域每一项都先问「一年后还会喜欢它吗」。

### M-64 壁纸主色主题采样（Wallpaper Accent Sampling）

- **定位**：一键从当前壁纸采样主色生成 accent 色板（候选 3 色可预览切换），生成结果存为主题；不自动生效。
- **动机**：Windows 11 的「从壁纸取色」是被验证过的喜爱功能；Variable 的 OKLCH 令牌体系做这事天然合适。与 U-46（色彩与时辰，按时间调色）的区别：本项是**用户主动采样**。
- **具体内容**：① 后端缩小图 + OKLCH 聚类取主色；② 预览卡显示三候选对全环境关键界面的影响（迷你预览）；③ 采样 → 预览 → 应用三步分离，绝不偷跑。
- **不做清单**：不做自动跟随壁纸换色（静默改变主题色 = 弄巧成拙）。
- **验收**：10 张不同风格壁纸采样主色人工评价 ≥8 张「和谐」；应用后高对比度模式不受影响。

### M-65 昼夜壁纸组（Day-Around Wallpaper Set）

- **定位**：壁纸轮播升级为「时段组」：为早/日/暮/夜各配一组壁纸，按系统时间在时段边界切换，切换用 300ms 交叉淡入。
- **动机**：现有轮播是均匀随机；「白天亮堂、入夜深沉」符合直觉且对夜间用眼友好。
- **具体内容**① 时段边界默认 6/12/18/21 点，可调；② 组内沿用现有轮播间隔；③ 淡入复用主题零闪白（Z-68）的交叉技术。
- **不做清单**：不做地理位置/日出计算（离线 + 克制）。
- **验收**：手动改系统时间跨 4 边界，切换正确且无黑帧；视频壁纸在组间切换走直接替换（不强交叉）。

### M-66 音量淡变防爆音（Volume Fade Guard）

- **定位**：系统音量/逐应用音量调节与静音切换时，后端 30ms 线性淡变到目标值（防耳机爆音），仅对环境内发起的调节生效。
- **动机**：半夜调音量「咔」一声的爆音是物理不适级体验；30ms 淡变听感无延迟、无爆音。
- **具体内容**：① IAudioEndpointVolume 回调路径加淡变；② 30ms 常数写死；③ 系统侧调节（音量键直达系统）不拦截不改写。
- **验收**：示波器口径下阶跃噪声消除（人工听测 20 次零爆音）；拖动音量滑杆跟手感无延迟感。

### M-67 桌面纯净模式（Pure Mode）

- **定位**：Ctrl+Alt+P（空闲槽）一键进入「纯净模式」：桌面图标、任务栏、通知横幅全部隐藏（通知仍入中心不打扰），只剩壁纸与当前聚焦窗口；再按恢复。
- **动机**：现有「隐藏图标」只藏图标；用户要的是完整的长文阅读/视频/演示净化。与焦点舱（U-50）的区别：焦点舱管「干扰源治理」，本项只是**一个键的视觉净空**。
- **具体内容**：① 三层（图标/任务栏/横幅）独立记忆，退出恢复原状；② 进入/退出 200ms 淡出淡入；③ 通知中心角标在任务栏隐藏期间移到屏幕边缘一枚小点（不丢失存在感）。
- **不做清单**：不自动屏蔽任何功能（纯净≠禁用，只是不显示）。
- **验收**：进入后播放视频 30 分钟零 UI 侵入；退出后各层状态精确还原。

### M-68 屏保时钟（Screensaver Clock）

- **定位**：环境空闲（无输入 ≥N 分钟，默认 10）时进入极简时钟屏保（大字号时间+日期，暗色低亮度），任意输入退出；可在设置关闭或改纯黑。
- **动机**：CRT 时代的屏保是防烧屏，OLED 时代是防久视 + 「这台机器还活着」的安心感；极简时钟是所有屏保里最不花哨的。
- **具体内容**：① 空闲检测复用打字降级的输入监听；② 时钟分钟级跳动（不渲染秒针，省电省眼）；③ 视频壁纸播放中不触发。
- **不做清单**：不做粒子/星空/翻页钟等花活屏保（红线）。
- **验收**：空闲 10 分钟进入、输入 ≤100ms 退出；连续 2 小时 CPU 占用 <1%。

### M-69 今日简报卡（Daily Briefing Card）

- **定位**：每天首次进入环境时桌面右下角浮出一张简报卡：日期周数、昨日使用摘要（本地统计 Z-62 的只读摘要）、一条快捷键小贴士、「关闭/今日不再显示」。
- **动机**：环境每天给你「开机问候」，是私人环境区别于工具的温度；同时是快捷键可发现性的最好载体。
- **具体内容**：① 触发条件 = 每日首启（跨午夜会话 M-90 联动）；② 小贴士池 30 条轮换（含新功能引导）；③ 全部数据本地只读，卡片 8s 自动收起。
- **不做清单**：不做天气/新闻（那是 Z-23 与联网边界的事）。
- **验收**：连续 7 天每天首启出现且贴士不重复；跨午夜会话不重复弹。

### M-70 壁纸快捷操作（Wallpaper Context Actions）

- **定位**：桌面壁纸空白处右键菜单新增壁纸区：收藏当前壁纸 / 下一张 / 壁纸详细信息（分辨率/文件路径/加入轮播组）；收藏夹在壁纸工坊里成一个特殊组。
- **动机**：看到喜欢的壁纸想收藏，现在要开设置翻半天；右键直达。
- **具体内容**：① 复用壁纸池数据结构加 favorite 标记；② 「详细信息」如实显示（含文件路径可复制）；③ 菜单项遵守 M-19 菜单编辑器。
- **不做清单**：不做壁纸在线下载（离线红线）。
- **验收**：收藏→壁纸工坊收藏组出现；重启持久。

### M-71 悬停延迟全局面板（Hover Latency Controls）

- **定位**：任务栏预览、tooltip、跳转列表的悬停出现/消失延迟统一为可调三档（快 200ms / 标准 400ms / 慢 600ms），一处设置全局生效。
- **动机**：高手嫌 tooltip 挡视线、新手嫌菜单出现太快；一个三档开关解决两类抱怨，比每处单独调克制。
- **具体内容**：① 延迟值进 tokens.css `--hover-delay-*`；② 6 处悬停浮层统一走令牌；③ 默认 = 现状（标准档）。
- **验收**：三档走查 6 处浮层一致；默认档与改动前逐像素行为一致。

### M-72 环境氛围会话恢复（Ambient Session Restore）

- **定位**：环境退出（隐藏到托盘或正常退出）前自动保存「氛围快照」：壁纸状态、音量、DND、开着的窗口集合与几何；下次进入时提示「恢复上次的样子？」一键回到离开时的全部状态。
- **动机**：与布局快照（Z-40，用户主动存档）的区别：本项是**自动的、氛围级的**——用户什么都不做，回来就是昨天的样子。与工作区场景（N-05）的区别：场景是抽象配置，本项恢复真实窗口集合。
- **具体内容**：① 快照存 settings KV（窗口集合只记登记应用 + 几何，环境内四空间窗口记路由参数）；② 恢复是提示而非自动（绝不偷跑）；③ 快照可关（隐私偏好用户可能不想留痕迹）。
- **验收**：开 8 窗口退出重进，一键恢复窗口集合+几何+音量+DND 全部一致；关闭快照后零残留。

## 域 U：无障碍与本地化（M-73…M-78）

### M-73 系统辅助功能桥（Accessibility Bridge）

- **定位**：感知系统的粘滞键/筛选键/讲述人启用状态：环境内等效行为对齐或如实提示「该功能由系统提供」；讲述人运行时环境降级动效（讲述人对动画敏感）。
- **动机**：开了系统粘滞键的用户在环境内按组合键，环境自己的快捷键系统不认识粘滞序列；这类「少数用户的完全不可用」必须修。
- **具体内容**：① SystemParametersInfo 读取粘滞/筛选键标志；② 键位解析层支持「分步修饰键」输入；③ 讲述人进程检测 → 自动套用 reduce-motion。
- **不做清单**：不实现自家屏幕阅读器（系统的职责，如实提示）。
- **验收**：开粘滞键后逐个按 Ctrl→Alt→E 成功触发；讲述人运行时动效自动降级。

### M-74 系统高对比度跟随（HC System Follow）

- **定位**：环境高对比度主题增加「跟随系统」档：系统切换高对比度时环境在 300ms 内切换到自家 HC 主题并广播给全部窗口。
- **动机**：视力受损用户按 Win+Alt+PrtScn 切系统高对比，环境却还是原来的样子——割裂即不可用。
- **具体内容**：① 监听 WM_THEMECHANGED / HighContrastInProgress；② HC 主题已有（F-7），本项做「跟随」联动；③ 联动事件写日志可查。
- **验收**：系统三档 HC 切换，环境 300ms 内跟随；切回标准主题同样跟随。

### M-75 动效时长缩放（Motion Duration Scale）

- **定位**：设置新增动效时长全局缩放三档（0.5x / 1x / 与 reduce-motion 二进制互补），1x 为默认现状。
- **动机**：reduce-motion 是全或无；一部分用户要「快一点但不全关」。三档封顶防过度配置。
- **具体内容**：① `--dur-scale` 令牌乘入全部 `--dur-*`；② 与 M-40 高刷系数叠加（乘法）；③ 缩放只影响时长，不影响缓动曲线。
- **验收**：0.5x 下 20 处动效时长全部减半；reduce-motion 优先级最高不受影响。

### M-76 屏幕阅读器标注审计（ARIA Audit）

- **定位**：环境主路径 15 条的全部交互元素补齐 aria-label / role / aria-keyshortcuts；audit.cjs 增加无头 DOM 检查（纯静态可查项）；每发版出一份 ARIA 覆盖率报告。
- **动机**：讲述人/NVDA 用户现在的可访问率接近零；标注是最低成本的巨大改善。
- **具体内容**：① 图标按钮必须 aria-label（审计强制）；② 状态变化用 aria-live=polite 通知；③ 键盘操作元素补 aria-keyshortcuts。
- **验收**：15 条主路径 aria-label 覆盖率 100%；NVDA 朗读走查 3 条主路径可完成基本任务。

### M-77 简繁转换用户词表（S2T User Lexicon）

- **定位**：s2t 转换器支持用户自定义词覆盖表（如「内存→記憶體」的个性化偏好、专有名词不转换），settings KV 存储，转换管线最后一级应用。
- **动机**：简繁转换的「术语不合口味」是繁体用户持续流失的原因；机器无法完美，用户自 fixes 最有效。
- **具体内容**：① 词表上限 500 条（防性能退化）；② 导入导出 CSV（联动 M-62 格式）；③ 冲突词（同简异繁）提示选择。
- **验收**：自定义 10 词后 UI 全量转换生效；转换耗时增量 <5%。

### M-78 区域格式跟随（Locale Format Follow）

- **定位**：日期/时间/数字/容量单位显示跟随系统区域设置（12/24h、日期序、千分位、KB/MB 口径），而非硬编码。
- **动机**：`2026/9/8` 与 `8/9/2026` 的歧义是国际化产品的经典事故；系统区域设置是用户已表达的偏好，环境应该尊重。
- **具体内容**：① Intl API 按系统 locale 渲染；② 容量单位二进制口径（MiB）与十进制（MB）设置项（默认系统口径）；③ 全环境 30 处日期容量显示点走查统一。
- **验收**：切系统区域为 en-US/zh-CN/de-DE 三组走查，日期数字格式全部正确跟随。

## 域 Q：工程质量基建（M-79…M-87）

> 目标：每一次发版都比上一版更可信。全部工具链，用户无感。

### M-79 前端错误聚合看板（FE Error Board）

- **定位**：ErrorBoundary 捕获的前端错误在设置→诊断里聚合展示：近 7 天错误 Top10（组件、消息、次数、首末时间），支持一键复制诊断文本。
- **动机**：前端错误现在吞进 ErrorBoundary 用户看不见；「偶现白屏」无法自助报告。与 Z-56（错误叙事 2.0，展示层）的区别：本项是**错误数据的本地聚合与自助导出**。
- **具体内容**：① 错误环形缓冲（500 条）进内存 + 退出落盘；② PII 清洗（不含用户输入内容）后展示；③ 一键复制为 markdown 报告。
- **验收**：注入 3 类组件错误 100 次，看板聚合正确；报告文本可直接贴 issue。

### M-80 IPC 调用追踪（IPC Trace View）

- **定位**：dev 构建下 Ctrl+Alt+F12（仅 dev 生效）打开 IPC 追踪面板：最近 500 次 invoke 的命令名、耗时、成功/失败瀑布图。
- **动机**：定位「哪里慢了」靠猜；追踪面板把前后端边界透明化，也是开放 API（O-53）的行为对照。
- **具体内容**：① ipc.ts 统一埋点（仅 `import.meta.env.DEV`）；② 瀑布图 + 慢调用（>100ms）标红；③ 支持按命令名过滤。
- **不做清单**：不进 release 构建（零运行时开销承诺，编译期剔除）。
- **验收**：dev 面板瀑布与真实调用一致；release 包 `rg` 验证埋点代码被剔除。

### M-81 设置漂移测试基建（Settings Drift Tests）

- **定位**：settings 迁移函数的版本矩阵测试：每个历史版本快照 → 逐级迁移到当前 → 断言结果；新版本必须补「上一版→新版」用例才能合入。
- **动机**：迁移代码是「改动最少、事故最多」的区域；矩阵测试把每个历史用户的升级路径全部锁死。
- **具体内容**：① 快照 fixtures 目录（每版一份匿名化样例）；② cargo test + vitest 双侧覆盖；③ CI 缺失用例即红。
- **验收**：构造 v1.0→当前全链迁移用例通过；人为破坏迁移函数被测试拦截。

### M-82 视觉回归多主题矩阵（Visual Matrix Regression）

- **定位**：visual-audit.cjs 的截图基线从单主题扩展为 dark/light/HC 三主题 × 3 缩放（100/125/150）矩阵，diff 阈值按主题分别标定。
- **动机**：亮色主题上线后没有任何截图基线；回归靠人肉。矩阵一次投入长期回报。
- **具体内容**：① 基线存储结构升级（主题/缩放两维）；② 基线更新流程文档化（PR 里必须含基线 diff 截图）；③ 矩阵跑批 15 条主路由。
- **验收**：三主题×三缩放 135 张基线产出；注入一处样式破坏被对应主题捕获。

### M-83 键位审计 CI 门禁（Keymap CI Gate）

- **定位**：tools/keymap-audit.cjs（Z-08 交付物）接入 pre-commit + CI 双层：error 级冲突阻断合入，warn 级（如与系统保留键重叠）允许但要求 PR 说明。
- **动机**：注册表没有门禁 = 早晚回到散装键位时代；门禁是纪律的制度化。
- **验收**：注入冲突 keymap 提交被 CI 拒绝；正常提交零误报。

### M-84 性能影响声明（Perf Impact Statement）

- **定位**：PR 模板新增「性能影响」必填段：无影响/影响主线程 <1ms/影响 >1ms 三选一，选后者必须附 bench 对照数据。
- **动机**：性能回归都是「无意间」合入的；声明制度逼出意识，数据逼出证据。
- **具体内容**：① .github/PULL_REQUEST_TEMPLATE.md 更新；② bench 工具输出标准化片段（可直接粘贴）。
- **验收**：模板上线后新 PR 100% 含声明段；>1ms 段全部附数据。

### M-85 依赖审计自动化（Dependency Audit Automation）

- **定位**：每周本地跑 npm audit + cargo audit（计划任务），高危项生成报告进 docs/selfcheck，不自动升级（升级由维护者决策）。
- **动机**：依赖漏洞是信任的慢性毒药；「知道」是最低要求。
- **具体内容**：① tools/dep-audit.cjs 双生态聚合；② 报告含修复建议版本；③ 与 sysmaint 计划任务调度集成。
- **不做清单**：不自动升级依赖（供应链安全红线：升级必须人审）。
- **验收**：连续 4 周报告产出；注入已知漏洞测试依赖能被报出。

### M-86 文档链接检查（Doc Link Checker）

- **定位**：tools/link-check.cjs 扫描 docs/ 与 README 全部 markdown 内链（相对路径 + 锚点），断链即 CI 红。
- **动机**：文档重构后断链是常态；「点开是 404」损耗专业感。
- **验收**：当前全库扫描清零断链；CI 注入断链被拦截。

### M-87 发版演练脚本（Release Rehearsal）

- **定位**：tools/release.ps1 一键演练发版全流程：版本号检查 → 全量测试 → 构建 → NSIS 产物校验 → CHANGELOG 草稿（M-61）→ 路由/设置文档再生成（M-55/M-56）→ 检查清单输出。
- **动机**：发版步骤 12+ 步靠记忆，漏一步就是事故；演练脚本 = 可执行的发版手册。
- **验收**：空跑一次全流程输出完整清单；人为引入版本号不一致被拦截。

## 域 X：收尾三针（M-88…M-90）

### M-88 全局 Tooltip 规范（Tooltip Standard）

- **定位**：全环境 tooltip 统一：样式（令牌化）、出现延迟（M-71 联动）、快捷键提示后缀格式（`复制 (Ctrl+C)` 圆括号式）、超长截断 + 完整内容 alt。
- **动机**：tooltip 现在有三种样式三种延迟；统一后「细节感」立刻不同。这是典型的「最后一毫米」。
- **验收**：30 处 tooltip 走查样式延迟一致；快捷键后缀格式 100% 统一。

### M-89 单位与数字规范（Units & Numbers Standard）

- **定位**：全环境速度/容量/时间显示统一：容量按 M-78 口径、速度显示「XX MB/s」保留 1 位小数、时间显示相对时间（「3 分钟前」）与绝对时间切换规则文档化。
- **动机**：「1.5GB」与「1536MB」与「1.53G」混排是廉价感的最快来源。
- **验收**：30 处数字显示点走查零混排；工具函数单测覆盖 20 个边界值。

### M-90 跨午夜会话正确性（Midnight Rollover Correctness）

- **定位**：环境跨午夜运行时时钟、日历、今日简报（M-69）、DND 日程（Z-44）、每日统计的「日界」全部在 00:00 正确翻页，无需重启或聚焦触发。
- **动机**：挂机过夜的环境第二天日期不翻页是隐蔽但致命的细节事故；所有「今日」类功能都需要统一的日界事件。
- **具体内容**：① uiStore 日界事件（`day://rollover`）统一定时器（含系统时间手动调整的监听）；② 5 个消费方全部迁移到统一事件；③ 测试注入虚拟时钟用例。
- **验收**：虚拟时钟跨午夜 50 次翻页全正确；手动改系统时间 ±1 天各 10 次事件正确。
