## 二、五项实际处置（均已实证归因后才动手）

### 2.1 清除源码树内 356 项递归副本污染 ★最高危

**现象**：`kernel/varix/src/svstar2/` 下有 343 个 `zz_*` 文件 + 13 个 `zz_*` 目录。

**归因**：有人用 `cp -r` 把**整个仓库根**复制进了源码树并加 `zz_` 前缀：

```
zz_varix/  zz_docs/  zz_src-tauri/  zz_code-analysis/  zz_launcher/
zz_user/  zz_memory/  zz_reports/  zz_VarixAutoPilot2/  zz_VarixTaskOps/
zz_boot-select.json   zz_limine.conf   ← boot 关键文件的副本进了源码树
```

**零风险论证**（三条独立证据）：

1. **零引用** —— `grep -rnE '(mod|use|include_str!|include_bytes!|path)\s*[!("=]*.*\bzz_'` 命中数 **0**；`svstar2/mod.rs` 未声明任何 `zz_` 模块。
2. **全为正本副本** —— 207 个 `.deep_*.json` 与根目录正本 `cmp` 逐字节相同；`zz_boot-select.json`/`zz_limine.conf`/`zz_varix/src/unxstar/*` 8 文件 `cmp` 全部 SAME；同名但内容不同 = **0**。
3. **先备份后删** —— 全量快照存 `attic/hygiene_2026-10-12/svstar2_zz_prefixed_snapshot/`（166M / 3840 文件）。

**结果**：`svstar2` 从 981 个 `.rs` 回到 **736 个纯源码**（与总案基线记录一致）。

### 2.2 入库 852 个已注册但未在册的活代码 ★最高价值

**现象**：857 个 `.rs` 在本地存在、`git status` 显示 `??`（未跟踪）。

**关键判别**——按「是否被 `mod.rs` 以 `pub mod <stem>;` 声明」二分：

| 类别 | 数量 | 性质 | 处置 |
|------|------|------|------|
| **已被 mod.rs 注册** | **852** | 参与编译的**活代码**，误删即编译失败 | **已入库** |
| 未被任何 mod.rs 声明 | 5 | 半成品/死文件 | 留清单待裁决 |

**这就是 4153 事故的完整机制**：

```
mod.rs 声明模块 ⇒ 编译依赖它 ⇒ 必须留在工作区
⇒ 开发不敢 git add（怕混入构建产物）⇒ 一次清理/切分支/换机即永久丢失
```

git 历史里没有副本，所以**恢复是不可能的**——这正是当年事故的性质。

**结果**：87.25 万行 / 852 文件入库，`kernel/varix/src` 在册率 3433/4150 → **4283/4150**。

## 三、制度性修复：`.gitignore` 的 7.1G 泄漏

**根因**：原规则只有精确名 `target/` 与 `**/target/`，于是 15 个变体
（`_target_iso` / `target-a4` / `target-wb5` / `_target_wb23` …）**全部漏网**。

**修法用前缀族而非逐个点名**——点名式清单下次新增变体又会漏，
这与 `.gitignore` 开头「源码保护红线」段是同一个教训：**靠人记的清单不算清单**。

```gitignore
*target/       # _target_iso / _target_wb23 / target_wb
*target-*/     # target-a4 / target-wb / target-wb5
*target_*/     # 下划线变体
*target[0-9]*/ # target2 / target3 数字后缀变体
```

**实测**（造 5 个探针目录）：5/5 命中产物；`boot-select.json`、`limine.conf`、
`kernel/varix/src/lib.rs`、`kernel/Cargo.toml` **零误伤**。

## 八、给下一任 AI-7 的三条纪律

1. **删之前先证明零风险**，三条独立证据缺一不可：零引用（`mod`/`use`/`include_*`）、
   全为正本副本（`cmp` 逐字节）、先备份再删。单靠目录名推断会误删
   ——`_attic/wb20probe` 名字像产物，实际含 3 个探针 crate 源码。

2. **检查器自身也要被证伪**。本席写的体检器第一版就有假阴性
   （`check-ignore` 跳过已跟踪文件）和一处自身崩溃（`count()` 遇到字符串条目）。
   工具写完必须用**已知反例**测它，否则它给出的「绿」不可信。

3. **gitignore 用前缀族，不用点名清单**。原规则 `target/` 漏掉 15 个变体累计 7.1G，
   补了 15 条点名规则也救不了下一次。**凡是需要人来维护的清单，就是没维护的清单。**
