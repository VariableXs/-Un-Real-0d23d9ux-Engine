### UNX-F36801 · 登录会话结构总模型与 LogonSession 数据结构

**功能**：登录会话是 J2 域一切凭据与隔离语义的根对象。LogonSession 采用单一结构体承载九类字段：LUID 唯一标识、认证包 ID、用户名、域、令牌引用（指向 J1 Token::build 冻结接口产出的令牌对象）、会话 ID（指向 B03 Session 对象）、引用计数、状态位（Active/Expired）、创建与最后访问时间戳。结构体本身不可被 ring3 直接触碰，只能通过域内 API 以句柄方式访问，句柄表挂在 J1 的对象命名空间里，走统一的 AccessCheck。设计上刻意让"登录会话"与"窗口站会话（Session）"解耦：一个登录会话可以在注销前经历窗口站重建，因此两者是引用关系不是包含关系。所有字段的写入只允许认证包路径与注销路径两处，其余一律只读，从结构上消灭竞态写入点。

**完成**：结构黄金样本 20 组逐字段对账全对；九字段 ×20 断言注册 ktest fast 档；令牌引用字段在 J1 冻结接口未交付前以 fake 桩验证引用/解引用语义（R-J2-001）；字段账与 F36817 双账对齐条目零偏差；三类登录路径（F36802–F36804）产出对象与本模型一致性 ×60 复验。完成标志：ktest 一条命令全绿，批册 740 行落账与深化正文互为表里，无占位符、无 TODO。

### UNX-F36802 · Interactive 交互登录全路径（建会话+桌面）

**功能**：交互登录是用户可见的主路径，共七步：①凭证提交→认证包常数时间验证（J3 模板复用）；②通过后从 LUID 池取号建 LogonSession；③按会话 ID 挂 B03 Session 对象并绑 WinSta0/Default 桌面；④构建主令牌并挂接会话；⑤加载用户配置与凭据命名空间初始化；⑥触发桌面初始化事件；⑦落审计事件（AI-50 四类必录）。每一步都设计失败出口：第②步池耗尽返回明确错误码，第③步隔离对象缺失为不可恢复错误并三要素呈现，第④步令牌构建失败回滚会话对象。全程引用计数保护，任何一步失败都不留半初始化会话——这是"会话无半空状态"红线在本路径的落点。

**完成**：Interactive 路径 ×20 用例全对（正常/口令错/锁定态/池耗尽/桌面缺失）；失败注入 ×10 每步一次，回收零泄漏断言；端到端 P95 <500ms（不含用户输入）；与 F36805 锁定策略联动 ×10 触发正确；审计事件 ×20 全落且不含明文口令。ktest 注册 20 判据全绿。

### UNX-F36803 · Service 服务登录路径（挂 Session 0 无桌面）

**功能**：服务登录与交互登录共享认证与建会话前段，分叉点在桌面挂接：服务会话固定挂 Session 0，且禁止创建窗口站与桌面（B24 深水的前置语义）。设计要点有四：一是服务会话的 LogonSession 标记 Service 类型，枚举接口（F36809）对其有专属过滤；二是服务会话生命周期可以远长于用户会话，因此引用计数采用"服务管理器持主引用"模型，避免服务自持导致泄漏；三是服务登录不允许携带交互式凭据 UI，凭证来源只有账户库与 B28 服务账户模型；四是服务崩溃时会话回收走独立看门狗路径，不拖累用户会话。该条目同时为 B24 的 Session 0 无 UI 强制语义预埋判据接口。

**完成**：Service 路径 ×20 用例全对；挂 Session 0 断言 ×20；尝试创建桌面 ×10 全拒且错误分类明确；服务崩溃回收 ×10 零孤儿会话；与 B28 服务账户联签 ×20 零二写；审计 ×20 落账。ktest 全绿，300 行落账与深化一致。

### UNX-F36804 · Network 网络登录路径（无会话只凭据）

**功能**：网络登录（远程类连接、命名管道鉴权等场景）只建立凭据上下文，不建 LogonSession 也不占 LUID——这是它与其他两类路径的本质区别。设计为"三无"对象：无会话、无窗口站、无桌面，仅持验证结果与派生令牌的凭据句柄，句柄有效期默认 10 分钟且可被显式关闭。这一设计直接杜绝了"网络登录残留僵尸会话"这一类 Windows 历史上反复出现的问题。凭据句柄与 B25 远程会话判据联动：若后续该凭据被用于真正建立远程会话，则在建立时点转为完整登录路径，凭据句柄随之注销，绝不复用旧句柄。

**完成**：Network 路径 ×20 用例全对；"三无"断言 ×20（枚举接口不可见、LUID 池无占位、对象树无挂点）；句柄过期回收 ×10 零泄漏；转完整登录时旧句柄注销 ×10 断言；与 B25 联签 ×10 零二写。ktest 全绿。

### UNX-F36805 · 登录失败锁定策略：连续失败 N 次延迟 M 秒（任务书示例锚·B01 区间承载位）

**功能**：失败锁定是暴力破解的第一道闸。策略参数 N（默认 5 次）与 M（基础延迟 3 秒）可配，退避采用指数序列：第 N 次失败后延迟 M，此后每次再失败延迟翻倍，上限 10×M 封顶——封顶而不是无限增长，是为了让合法用户在可预期时间内能重试，也让攻击者的成本曲线可被审计量化。锁定状态挂在账户维度而非会话维度，因此无会话的 Network 路径同样能触发锁定。每次锁定触发与解除都产生审计事件（含触发时的源上下文摘要，不含口令内容）。策略变更走 L2 配置域冻结接口并落审计，防止运行时被静默放宽。

**完成**：默认参数 ×10 触发与退避序列精确断言（3s→6s→…→30s 封顶）；N/M 双参数可配 ×10 生效；锁定事件 ×10 全落审计且字段齐；成功登录后计数清零 ×10；与 B26 锁屏解锁链一致性 ×10（同一策略零二写）。ktest 全绿。

### UNX-F36806 · 会话引用计数器：令牌/窗口站/凭据三方放手

**功能**：LogonSession 被令牌、窗口站、凭据上下文三方引用，销毁条件是三方引用全部释放——任何一方残留都会造成会话僵尸。引用计数采用无锁读/原子写模型：AddRef 在取引用时进行，Release 在归还时进行，计数归零即时触发销毁回调。设计上的关键防御是"放手顺序无关"：三方以任意顺序释放都正确，销毁回调以幂等方式执行且只执行一次（用状态位 CAS 保证）。为捕获泄漏，附带泄漏看门狗：周期扫描计数大于零但三方均已失活的异常会话，5 秒内告警并三要素呈现。计数溢出防护：AddRef 前检查上限（10^9），触顶拒绝并告警。

**完成**：AddRef/Release 10^4 次零漂移；三方任意顺序放手 ×6 全排列销毁正确；双线程并发放手 ×100 销毁仅一次；泄漏注入 ×20 看门狗检出率 100% 且 <5s；溢出防护 ×10 拒绝正确。ktest 全绿。

### UNX-F36807 · LUID 唯一登录 ID 分配语义地基

**功能**：LUID 是登录会话的全局唯一短标识，本条目只立"分配语义"的地基，池化管理归 B02 深水。地基语义三条：一是全局唯一性——任何两个存活会话的 LUID 不可能相同，由 64 位单调计数器加启动随机偏移保证，重启后不重放旧值；二是不透明性——LUID 仅作比较与索引用，不编码任何语义（不含会话类型、不含用户信息），杜绝下游从 LUID 反推敏感信息的攻击面；三是零值与保留值拒分配——LUID 0 与系统保留段（高 32 位全 F）永不分配给登录会话。本条目同时定义 LUID 与会话 ID（B03 Session 编号）的双账字段对齐规则，排疑手册对表随条目落档。

**完成**：唯一性 ×10^3 并发分配零重复；重启不重放 ×5（模拟重启后新值大于历史最大值）；保留值拒分配 ×10；不透明性由代码评审确认无语义编码并登记；与 F36817 对账表零偏差。ktest 全绿。

### UNX-F36808 · 登录会话状态机（Active/Expired 两态+非法转移全拒）

**功能**：会话状态机刻意保持两态极简：Active 与 Expired。所有终结路径（注销、Kill 币、崩溃回收、超时）都汇入单一 Expired 态，从结构上排除"半注销""僵尸活跃"等中间态。状态转移只有一条合法边：Active→Expired；任何其他转移（Expired→Active、自转移）全部拒绝并落异常事件。转移由状态位 CAS 原子完成，竞争转移（注销与注销并发）只有一方成功，另一方收到"已过期"而非错误——这个语义选择让上层调用方无需处理注销竞态的特殊分支。Expired 是终态，过期会话对象在引用归零后被回收，Expired 状态本身保留于审计快照供追溯。

**完成**：合法转移 ×20 全对；非法转移 ×20 全拒且事件落审计；并发注销竞态 ×100 仅一方成功语义验证；过期后访问拒止 ×20 错误分类明确；两态枚举与 F36809 对账一致。ktest 全绿。

### UNX-F36809 · 会话枚举接口最小面（WTSEnumerateSessions 类语义）

**功能**：提供会话枚举的最小 API 面：全量枚举、按类型过滤（Interactive/Service）、按状态过滤（Active/Expired 不外显，Expired 仅审计视图可见）。对外语义与 Windows WTSEnumerateSessions 对齐（L1 API 级）：返回句柄数组、调用方负责释放、枚举结果是调用时刻的快照而非活视图——快照语义从根上消除"枚举中会话注销导致悬挂引用"。Network 类型不出现在枚举结果（对齐 F36804 三无语义）。接口线程安全，支持并发枚举；结果集内存上界 10MB，超限走分页。最小面原则：不做排序承诺、不做模糊过滤、不做跨域聚合——这些归上层工具，本 API 保持可十年不变的窄面。

**完成**：枚举 ×100 与内部状态对账一致；类型过滤 ×20 精确；快照一致性（枚举中注销）×20 无悬挂；并发枚举 ×10^3 零竞态；句柄释放 ×10 零泄漏；10MB 上界 ×10 分页正确。ktest 全绿。

### UNX-F36810 · 登录类型白名单与非法类型拒止

**功能**：登录类型是枚举值而非自由整数。白名单只含三个合法值：Interactive(1)、Service(2)、Network(3)，与公开文档锚逐一对账。任何白名单外的类型值——包括看起来"合理"的扩展值、零、负数、超大值——在认证包入口即拒绝，错误分类为"非法登录类型"而非笼统参数错，让调用方一眼定位。拒止动作同时落审计事件（含被拒值原文），为攻击面监测提供信号。白名单本身编译期冻结，运行时不可扩展；若未来需要新类型（如 RemoteInteractive 对应 B25），走 ADR 变更流程修改白名单并全量回归，而不是留运行时开关——这个选择牺牲灵活性换确定性，是本域的立场。

**完成**：合法值 ×3 全过；非法值 ×50（0/负/4/2^31/2^64-1 等）全拒且分类正确；拒止事件 ×10 落审计；白名单冻结由代码评审登记；未来扩展路径 ADR 模板落档。ktest 全绿。

### UNX-F36812 · 登录会话与 J1 令牌交付接口冻结对账（Schema 先行）

**功能**：认证包验证成功后要把构建好的令牌交付给登录会话，这个交付接口是 J2 与 J1 的最高频接缝。Schema 先行：接口签名（TokenHandle 语义、引用转移规则、错误码空间）以冻结文档先行定义，J2 侧以 fake 令牌开发全链，J1 真身就绪后零改动接入。对账三原则：一是引用转移单边性——令牌引用从认证包转移到会话是移动不是复制，转移后认证包侧置空，杜绝双持；二是失败原子性——交付失败时引用归还认证包路径，会话不得持半效令牌；三是错误码空间不重叠——J1 域错误码与 J2 域错误码分段，交付接口翻译器（F36818）统一处理。对账记录落档，冻结签哈希登记。

**完成**：Schema 冻结签哈希落档；fake 链 ×20 全对；交付/失败归还 ×20 原子性断言；双持探测（引用计数账）×10 零双持；错误码分段无重叠由清单核对 ×32 项。ktest 全绿。

### UNX-F36813 · 登录全链体验日志埋点地基（十三）

**功能**：按十三章体验完整性标准，登录全链从第一天起就把体验日志当需求做：每个关键步骤埋点记录"在哪一步、对哪个对象、什么时刻、触发了什么、反馈是什么、耗时多少"，事件按统一时间轴串联成可回放的操作故事线。埋点主动捕获挫败信号：连续失败提交（rage submit）、提交后长时间无反馈（dead wait）、锁定触发后的原地徘徊——这些信号自动标记为体验事件并带结论字段（顺畅/卡顿/被打断/报错）。隐私红线严格执行：只记交互行为与结果，永不记口令内容与凭据明文；日志写入异步批量，绝不阻塞登录主路径；日志系统启动之前的早期失败由启动探针兜底捕获（衔接 F36814）。

**完成**：埋点覆盖 7 步全路径 ×20 故事线可回放；挫败信号注入 ×10 捕获率 100%；隐私红线抽查 ×10 零敏感内容；异步写入不阻塞断言（登录 P95 不因日志劣化 >5%）；总日志中心可见 ×5 抽查。ktest 全绿。

**完成**：隐蔽点清单 12 处逐处捕获验证；fail-closed ×10 断言；早期事件回灌 ×10 零丢失；未处理异常钩子注入 ×5 全显性；三要素呈现抽查 ×10 人话合格。ktest 全绿。
