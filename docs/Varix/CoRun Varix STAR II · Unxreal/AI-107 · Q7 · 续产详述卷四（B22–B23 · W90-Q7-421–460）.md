### W90-Q7-421 SDK 面适配总纲（用户态适配工作法）（行数 300｜骨架→详述收口）

**功能**：B22 承接 B21 内核面适配的成果，转向用户态 SDK 面（60 接口）与环境标识（ac_env_id）的厂商适配工作，本条立适配总纲。用户态适配与内核面适配的三点本质差异决定工作法不同：一、适配主体不同——内核面适配由 Varix 侧实现（厂商只消费），SDK 面适配多为「厂商在 Varix 上集成其组件」场景，Varix 的角色是提供高质量 SDK 语义与集成支持，适配单从「我改什么」变成「厂商怎么接」——适配单模型七节相应调整为：集成场景定义、SDK 消费面（厂商会用哪些接口组）、语义对齐点（Varix 语义与厂商预期的对齐清单）、集成陷阱预警（常见误用与防御）、支持材料清单、验证协作建议、风险与兜底；二、语义对齐是核心战场——厂商组件按 Windows SDK 语义开发，Varix SDK 的对拍零偏差是信任基础（B09 已保），本批的对齐点登记聚焦「文档未言明的隐性预期」（如回调线程模型的隐含假设）；三、环境标识集成是本批独有重点——ac_env_id 的集成单独立成节系列（与内核适配单并行）。总纲经双人复核冻结，批内产出按「集成场景单＋标识集成单」双轨组织。

**完成**：SDK 适配总纲已冻结：适配单七节新模型定义（与 B21 模型的差异显式对照表）；「厂商怎么接」的角色定位声明入纲（角色漂移即越权——Varix 不代厂商写组件代码，边界声明落规约）；隐性预期对齐方法论成节（对齐点来源：Windows SDK 公开语义＋社区已知惯例，臆测标签纪律延续）；双轨组织结构排定；双人复核冻结（双签在册）。判据 `W90-Q7-421-J1`（M-Q7-421）以「七节新模型＋角色边界＋复核冻结」收口，kcheck 0 违例。诚实三态：总纲为方法框架，各集成单的实际对齐点随厂商真实组件暴露（当前基于公开口径预研）；「集成支持」的深度以文档与对拍宿主为限，远程调试类支持属商务协议范畴零预支。
