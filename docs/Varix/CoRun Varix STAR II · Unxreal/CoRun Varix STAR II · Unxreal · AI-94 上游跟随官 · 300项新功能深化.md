## 第一组 · 16 项嫁接件版本台账核心（UP-001～UP-020）

- **UP-001｜KB-UPSTREAM 主台账结构 v2**：每嫁接件一条主记录：钉定版本、上游仓库 URL、跟随策略（只跟随）、准入 ADR 号、许可复核号（AI-95 联签栏）、最近评估日期。判据：16 项主件记录齐全且字段非空，缺失即告警。
- **UP-002｜钉版快照哈希**：每项钉定版本同时钉 tarball/commit 的 sha256，评估与构建单可对哈希。判据：构建单哈希与台账哈希一致率 100%。
- **UP-003｜版本变更历史子账**：每次钉版变更记录旧版→新版、变更原因、回归计划编号、批准 ADR。判据：历史链不可篡改（append-only），抽验任一条可回溯。
- **UP-004｜跟随策略枚举固化**：策略枚举只有三种——钉版坚守/评估后升级/退役替换；禁止出现"跟随最新"非法值。判据：schema 校验拒绝非法枚举。
- **UP-005｜上游发布源自动订阅**：16 项嫁接件的 GitHub Release/tags 订阅清单，逐项登记订阅方式（webhook/轮询）与轮询周期。判据：任一上游发布后 24h 内台账"上游事件"列出现记录。
- **UP-006｜嫁接件分级（A/B/C）**：A=内核直连（Limine/openssl/wpa_supplicant）、B=用户态关键（glibc/musl/Wine）、C=工具链与生态。A 级评估 SLA 压缩到 T+3。判据：分级清单经 AI-100 备案。
- **UP-007｜台账唯一事实源申明**：KB-UPSTREAM 是版本唯一事实源；判据/构建单/文档引用版本一律以台账为准，出现第二事实源即 P0。判据：grep 全库版本引用与台账比对，不一致清单为零容忍。
- **UP-008｜无上游自研域登记面**：自研域（如 AI-36 KMS 类）按"参照版本"口径登记 RFC/规范文档版本，与嫁接件同账管理。判据：自研域登记字段齐全，抽查 3 域可核。
- **UP-009｜版本号幻觉拦截**：台账写入前校验版本号真实存在（上游 tags 查询），查不到即拒收并记幻觉告警。判据：注入伪造版本号被拒的自动化测试通过。
- **UP-010｜嫁接件负责人映射**：16 项逐项登记消费域列表（哪个域用哪个版本），版本变更时可精确圈定受影响面。判据：消费映射覆盖全部 16 项，抽查任一嫁接件可列出全部消费批次。
- **UP-011｜钉版例外账**：确需偏离钉版的（如安全紧急修补），入例外账并 72h 内补 ADR。判据：例外账无"已用未记"条目（与 AI-84 防重联动抽检）。
- **UP-012｜台账季度抽验器**：自动比对台账钉定版、构建单版本、镜像内实际二进制指纹三方一致。判据：GOV-94-J4 抽验脚本一命令出报告，不一致即红。
- **UP-013｜退役嫁接件档案**：被替换/停用的嫁接件转档案区，保留版本、许可义务存续期、替换去向。判据：档案条目不可删除只可归档。
- **UP-014｜多版本并存登记**：同一嫁接件因域隔离需要并存多版本时（如 glibc 兼容旧样本），逐版本独立记录与许可复核。判据：并存版本各自有独立评估单。
- **UP-015｜台账 API 只读接口**：对域线提供只读查询接口（按嫁接件/按域/按批次三种视图），域线判据可直接引用。判据：接口冻结，变更走 mini-ADR + REGRESS 通知。
- **UP-016｜事件去重窗口**：同一上游短时间多次发布（连续 patch）合并为一次评估事件，窗口 72h。判据：合并事件保留全部版本子条目，不丢任何一版。
- **UP-017｜台账完整性自检心跳**：每日自检 16 项记录字段完整性、订阅活性、最近评估时限，异常入日巡检报告。判据：心跳连续 30 天无缺日。
- **UP-018｜嫁接件依赖树快照**：每项登记直接依赖与其许可证（供 AI-95 传递性污染审查取数）。判据：依赖树深度 ≥2 的项全部展开到叶。
- **UP-019｜版本别名归一**：上游命名风格不一（v1.2.3/1.2.3/release-1.2.3）统一归一化规则，避免同版异名重复评估。判据：归一化规则文档化，抽 20 条别名无误。
- **UP-020｜台账导出与镜像件**：台账随年度镜像发布（十四件之外的 AI-94 附件件），格式为纯 Markdown+JSON 双形态。判据：镜像构建时自动带出当日快照，双形态内容一致。
