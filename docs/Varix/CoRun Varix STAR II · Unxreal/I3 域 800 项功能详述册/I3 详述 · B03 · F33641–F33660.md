# I3 域功能详述册 · B03 批（F33641–F33660 · 接口账·地址管理·邻居账（ARP/NDP）与 MTU/计数器）

> 承骨架批册 UNX-I3-B03 逐条定制详述；每条 ≥300 字。

### UNX-F33641 · 接口账结构：up/down/地址/MTU/计数器总账

接口账是网络世界的户口簿。本条目定义接口总账结构：标识（索引/名称/类型）、状态、地址族、MTU、计数器五域合计二十字段，黄金样本逐一验证。状态机为 up/down/dormant 三态，迁移路径 ×100 验证只走合法边（如 dormant→up 合法、down→dormant 非法），非法迁移一律拒止并落错误账。设计上接口账是单一事实源：B19 状态总账的接口视图、网管 CLI 的 ip link 输出、DHCP/路由的依赖判断全部读这里，账实一致的探针常驻。判据含：字段完整性断言、三态迁移黄金剧本、账本变更事件（类型/时间戳齐备）必发。该账本与 I1 的接口事件源对账挂 ktest，两端漂移即告警——户口簿错一个字，下游全错，这是本批其余十九条的地基。

### UNX-F33642 · 接口 up/down 事件与依赖联动（路由/DHCP）

接口拔了，依赖它的东西必须干净退场。本条目规定联动语义：接口 down → 其依赖路由自动撤销零残留（×10 注入验证）、DHCP 客户端停止租约维护、邻居账该接口条目冻结；重新 up → DHCP 重启 DORA、路由按持久化/重学两路恢复。判据核心是事件顺序全序：down 事件必先于依赖撤销，恢复序反之，乱序即账目失真——幽灵网检测器（B14）就靠这个顺序。设计上依赖关系在插入时登记（路由记录"我因接口 X 而生"），撤销时按账索骥而非全表扫描，O(依赖数) 而非 O(n)；联动事件进 F33610 通道与 B20 总线双发（口径与 AI-50 联签一致）。判据含：拔插 100 次循环后零泄漏（路由/租约/邻居三账对账）、联动期间查询不崩溃。这是"出现必有完整消失路径"纪律在接口面的执行条。

### UNX-F33643 · IPv4 地址添加/删除与别名地址语义

一个接口多个地址是常态（主地址+别名）。本条目规定地址增删语义：增删 ×100 次引用账闭合零泄漏；同网段多地址区分主/别名——主地址参与源地址选择，别名只作应答；删除主地址触发次地址提升（ eldest 优先），提升事件必发。设计上地址条目含生命周期状态（active/deprecated）与持有者标签（static/dhcp/apipa/slaac 四来源互斥，与路由表协议来源同构但独立枚举）；源地址选择按 RFC6724 思路的最小面实现（预告位，实装在后续批次）。判据含：同地址重添加拒止、删除不存在地址精确错误码、地址变更事件（含前后值）进 B20 事件总线。该条目是 B12 DHCP 落址与 B13 APIPA/SLAAC 的共同落点，三来源对同一接口的竞争由本条目的持有者账仲裁。

### UNX-F33644 · 子网掩码与广播地址推导语义

掩码推导是最不容出错的简单逻辑。本条目实现：掩码→网络地址/广播地址推导，10^3 随机样本零差；/31（点对点）与 /32（主机路由）特例按语义处理——/31 无广播地址、/32 全主机位；非法掩码（主机位非零如 255.0.255.0）入库前拒止，错误码单一精确。设计上推导是纯函数（同输入必同输出、无全局状态），放公共库供 DHCP（offer 校验）、APIPA（自选网段）、网管 CLI（addr 显示）三处复用——一份实现三处消费，杜绝各自推导各自错。判据含：边界样本全集（/0 /1 /31 /32 及各字节边界）、推导结果与黄金表逐位对照、纯函数属性由 fuzz 随机输入断言。该条目虽小，是"简单逻辑也要有判据"的示范位：幽灵网事故里最不起眼的推手往往就是掩码算错一位。

### UNX-F33645 · ARP 邻居账：解析/缓存/老化全状态机

邻居账是二层世界的通讯录。本条目实现 ARP 全状态机：INCOMPLETE（解析中）→REACHABLE（可达，30s 刷新）→STALE（过期待验，60s）→PROBE（探测中）→FAILED（失败）五态，迁移 ×100 全对；老化时间表逐值断言；并发解析合并——同目标多请求只发一次探测，结果广播给所有等待者。设计上状态机是显式迁移表（非法迁移编译期不可表达），不是散落的 if；每次迁移落事件账（含原因），B19 邻居视图与诊断 CLI 直接消费。判据含：五态黄金剧本、老化扫描 O(1) 摊销（轮转桶）、解析风暴限速。该状态机与 NDP（F33647）同构——一份状态定义两族协议共用，v4/v6 行为一致是全域交互词典纪律在协议层的体现，差异只在报文构造层。

### UNX-F33646 · ARP 冲突检测与随机恢复

IP 冲突是局域网里的撞车事故。本条目实现检测与防御：收到与自身冲突的 ARP（他人冒用本机 IP）→ 告警事件必发 + 防御响应（gratuitous ARP 重申所有权）；冲突源清除后自动恢复 ×10；防御风暴限速 ≤1 次/秒——防御本身不能变成新的攻击面。判据：冲突注入 ×10 检出率 100%、防御报文内容与黄金样本一致、恢复后账目干净（冲突标记清除）。设计上冲突检测被动侦听为主（不主动扫描，避免扰动网络），防御响应节流由令牌桶控制；冲突事件带对端 MAC，供 B21 安全场域关联（同一 MAC 反复冲突=疑似恶意）。该条目与 B13 APIPA 的 DAD 探测同族不同用——那是自己上线前查重，这是上线后被打抢的应对，两处判据独立不混。

### UNX-F33647 · NDP 邻居账与 I1 NDP 面对接（v6 侧地基）

v6 邻居发现复用 ARP 的状态机骨架（F33645 五态 ×100 同构验证），差异在报文族（NS/NA）与路由器发现扩展。本条目职责有二：本地 NDP 邻居账全功能；与 I1 的 NDP 面逐方法对账 20 格——对接收发谁负责、状态谁主沉浮，边界双向声明，未收口项显性登记（R-I3-001 同源风险）不静默。判据：五态迁移与 ARP 同构一致、对账账逐格留痕、跨界报文（本域收到的 RA/NS）正确分流到 I1 或本地。设计上"同构不同实现"是刻意的——v4/v6 报文差异大，强行抽象公共基类会造成伪共享，保持两份代码一份状态定义才是清晰结构；一致性由差分测试保证而非由继承保证。该条目是 B13 SLAAC（RA 学习）的邻居侧依赖，也是 B29 I1 联签"邻居账跨域一致性"的实体。

### UNX-F33648 · 邻居不可达探测与路由 FAILED 联动

邻居死了，路由必须知道。本条目把邻居账 FAILED 态与路由表 FAILED 标记（F33628）联动：邻居 FAILED → 其依赖路由全部标记不可达 ×10 全过；探测恢复 → 路由自动复活 ×10；联动事件零丢失（序号账）。设计上依赖关系由路由表项持有"下一跳邻居键"，联动是按键索引的定向操作，O(1) 而非全表扫；探测节奏（PROBE 态单播探测 ×3）复用状态机既有预算，不为联动另起定时器。判据含：联动顺序全序（邻居先于路由）、ECMP 场景（一个成员死不冤枉其他成员）、风暴场景（邻居抖动致路由反复 FAILED/复活）限速与账目不乱。该条目是 B02 ECMP 健康联动（F33623）的底层事件源，三条构成"邻居-路由-ECMP"完整传导链，链条任一环断账在 B29 跨域对账现形。

### UNX-F33649 · MTU 语义：协商/变更/PTBUD 处理地基

MTU 是隐形而易碎的契约。本条目实现：MTU 变更事件必发 ×10（下游 TCP/PMTU 缓存依赖它）；低于最小值 68（IPv4）拒止；PMTU（路径 MTU 发现收到的 ICMP too big）缓存与老化账落档——PMTU 按目标前缀缓存，10 分钟老化重探。判据：变更传播全序（接口账→事件→PMTU 缓存失效）、/32 与隧道场景的 PMTU 下限保护、畸形 too big（声称 MTU <68）拒止计数。设计上 MTU 变更是 rare 事件，处理路径要简单可审计——不做增量协商的花活，变更即生效即广播；PMTU 缓存有界（1k 目标上限，LRU 淘汰），防表洪水。该条目是 I1 分片决策的上游输入，边界声明：分片本身归 I1，本域只提供准确的 MTU 事实。

### UNX-F33650 · 接口计数器账：rx/tx/err/drop 全维度

计数器是网管的眼睛。本条目建 16 维计数器（收发字节/包、错误、丢弃、广播、组播等）：黄金流量对账零差——喂已知包数与字节数的合成流量，16 维读数逐位吻合；64 位计数器溢出回绕处理正确（回绕不是清零，差值算法正确）；计数器清零操作是审计事件（谁在什么时候抹了账）。设计上计数器更新在数据面热路径，用每 CPU 计数+读取时合并避免缓存行争用——但内核域无多核调度时退化为原子加，两种实现同一判据；计数器只增不减（除显式清零），读数是快照语义。判据含：计数器与 B19 接口视图、CLI 输出三方一致（同源零漂移）。这是 J6 判据（CLI ×40 与状态账一致）里 ifconfig 类子命令的数据地基，数字对不上，网管就会用脚投票。

### UNX-F33651 · 接口枚举与稳定命名（网管 CLI 数据源）

"eth0 到底是谁"必须是确定性的。本条目实现接口枚举与稳定命名：枚举顺序按注册序，10^3 次全对；热插拔场景命名不漂移（×10 拔插，名字与实体映射恒定）；别名冲突拒止（两个接口不许叫一个名）。设计上稳定命名的锚是固件/驱动提供的稳定标识（MAC 或槽位路径），注册名是它的确定性函数而非先到先得——先到先得是竞态温床；枚举接口是有序快照语义（中途插拔不影响本次枚举一致性）。判据含：命名规则黄金样本（同硬件两次注册同名）、枚举与接口账一致性、名称长度/字符集校验。该条目是 B38 CLI ×40 回归里 link/addr 系命令的输出稳定性根基：用户脚本按名字找接口，名字漂移=脚本全崩，这不是小事是事故。

### UNX-F33652 · 无线接口类型标记与以太网区分（I3/I1 边界）

接口类型字段（ether/wifi/loop 三值互斥）是 I3 域接管 WiFi 的开关信号。本条目规定：类型标记入库断言三值互斥；wifi 类型触发本域接管路径（驱动接口注册、漫游决策挂载）探针验证；类型误标注入（wifi 报成 ether）检出率 100%——误标意味着 WiFi 接口没人管，是静默故障的典型。判据含：类型与能力表（B04 驱动协商结果）交叉验证一致性、类型变更（理论不发生）事件必发并告警、与 I1 的边界划账双向声明（转发归 I1，无线管理归 I3）。设计上类型判定一次性完成（注册时），运行期不翻转——翻转是状态机噩梦；判定依据（驱动声明+能力位）落档可查。该条目是 F 型地基段（路由/接口）与 WiFi 段（B04–B18）的接界碑，跨界对流在此交接。

### UNX-F33653 · 地址生命周期事件流（DHCP 消费位）

地址的生老病死都要有讣告。本条目定义地址三事件：add/del/expire，字段完整（地址/接口/持有者/时间戳）×100 验证；同因合并去重——同一地址同一原因的重复事件合并为一件（防抖），不同原因不合并；消费端 fake 订阅 10^3 件零丢失。设计上事件流是 B12 DHCP、B13 SLAAC、静态配置三源的合流总线（B13 的"地址生命周期事件流总装"条目是它的终装版，本条目是地基）；事件顺序按地址账实际变更序全序；订阅走 B20 事件总线多播机制，本条目只定义事件 schema 与发布纪律。判据含：expire 事件与租约账（B12）联动时序、事件风暴（批量配置导入）背压正确。下游消费者名单：B19 地址视图、I4 DNS 交付、B26 并发对账，schema 一经冻结不改。

### UNX-F33654 · 邻居账持久化与重启恢复预告

重启不该忘掉整个通讯录。本条目做两件事：现有能力——邻居账导出/导入往返 10^3 条零差（格式开放，含状态/老化剩余/MAC/接口全字段，损坏文件拒止三要素呈现）；预告位——重启恢复接口编译期冻结（恢复时 STALE 态批量重建、REACHABLE 不恢复需重探的语义声明），实装归 B23 恢复全路径批。判据：导出快照一致性（导出中途的变更不影响本次快照）、导入校验全通过才切换、预告接口冻结断言。设计上"持久化现在做、恢复以后做"的拆分是双轨纪律的体现：文件格式先冻结，恢复剧本后实装，二者经接口解耦互不等待；预告位登记进总纲 §7.3-I3 与 handoff，防"预留变烂尾"。该条目与 F33613 路由表持久化同构，共享原子写与事务导入原语。

### UNX-F33655 · 接口面 fuzz：畸形 ioctl/事件注入

接口面是配置洪水的入海口，fuzz 必须先行。本条目对两个入口注入：ioctl 面（畸形命令/越界参数/非法状态迁移请求）10^5 组零崩溃；事件面（伪造 up/down/地址变更事件，模拟驱动层错乱）10^4 组账目不乱。判据：越权操作（非 root 改接口）全拒 ×20 且审计落账；所有畸形输入走显性拒绝路径，错误账完整；崩溃样本归档转最小复现入 B25 样本库。设计上 fuzz 语料包含真实驱动 bug 库的畸形化样本（历史事故是最好的语料）；注入器幂等可复现（种子落档）。该条目与 F33632 路由面 fuzz 同模式不同面，样本统一进 B25 全域样本库治理——fuzz 不是一次性动作是常驻纪律，每次协议面改动都要回跑对应面语料，回归零报告才算过。

### UNX-F33656 · 接口账与网管 CLI 对账（ip link/addr 数据源）

CLI 说的和账本记的必须是同一套真话。本条目做双向对账：CLI 输出（link/addr 系）与接口账逐字段一致 ×40 子命令面（J6 判据首批范围），一致性断言自动化挂 ktest——不是抽检是全量；本地化文案词典一致（错误提示/字段名全局唯一）。判据：三方对账（账本↔视图↔CLI）零漂移、输出格式稳定基线（格式变更视为破坏性变更走版本流程）、一致性断言误报 ≤1%。设计上 CLI 是账本的纯投影（无独立状态），"投影说谎"只可能是投影代码 bug，对账断言直接定位；对账跑法分快档（日常）与全档（闸门）。该条目是 J6 判据的先行兑现面，B38 收官批做 ×40 全量终验时按本条目的对账框架执行，届时零新增机制只做全量复演。

### UNX-F33657 · 接口面体验日志埋点

接口面的每一次状态迁移都值得被记住。本条目把状态迁移、地址变更、计数器异常（突增的 err/drop）三类事件接入统一时间轴：异步批量写入 P95 <1ms 零阻塞；敏感脱敏——MAC 只记后 4 位、不记完整地址。判据：事件字段完整率 100%（抽样 10^3 件逐字段核）、时间轴连续性（无断档无乱序）、计数器异常事件带阈值上下文（超过多少触发）。设计上"计数器异常"是体验信号不是技术信号：用户上网卡顿往往先表现为 drop 计数爬升，把它标记为挫败信号指纹（第十三章纪律），体验改进清单可从日志直接生成；埋点开关三级（全开/只错误/全关），默认全开，关闭走配置审计。该条目数据是 B39 域级体验日志完整性总终验的接口面分册。

### UNX-F33658 · 异常显性化：接口面隐蔽失败捕获

接口面三处最易吞错的位置布防：事件丢失（up/down 事件被队列吞掉致账实分裂）、计数器竞态（多源并发更新丢计数）、老化竞态（地址过期与续租并发误判）。判据：三处各 10^3 次故障注入捕获率 100% 零静默；每处捕获带独立计数器与告警；自检探针过；总日志中心可检索。设计上捕获点实现为账本写路径的前后哨兵（写前记意图、写后验结果，不合即响），比"事后对账发现"早一个量级发现问题；误报由灵敏度必红三条约束在 ≤1%。该条目与 F33618（路由面）、F33617 系列构成全域异常显性化网络：40 批 × 每批一条，任何一处失守都在 B28/B39 的全域零静默终验现形——异常零静默是明令，本网络是执行机构。

### UNX-F33659 · B03 段 ktest 断言面扩表
