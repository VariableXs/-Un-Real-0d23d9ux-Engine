# I3 域功能详述册 · B02 批（F33621–F33640 · ECMP 等价多路径、策略路由最小面与 ICMP 重定向）

> 承骨架批册 UNX-I3-B02 逐条定制详述；每条 ≥300 字。示例锚 F33633（wpa_supplicant 适配层）ID 于本批 #13 区间恒等承载，语义锚落 B05 末条 F33700。

### UNX-F33621 · ECMP 等价多路径组与五元组哈希选路

等价多路径是带宽与冗余的合流点。本条目把 metric 相等的同前缀路由组织成 ECMP 组，选路用五元组（源目地址/源目端口/协议）哈希在组内成员间分流。判据三条：四路成员的哈希分布过 χ² 检验（P>0.05，均匀性不是感觉）；同一五元组 10^3 次选路结果恒定，流内一致是硬承诺；组内单成员摘除时，该成员承载的流零中断迁移到幸存成员。设计上哈希种子可配置，变更必发事件（因为变更会重排所有流，消费方有权知晓）；哈希函数复用 I1 转发面同一实现，两端一致才能保证转发表与控制面判断不背离。该条目与 F33608 仲裁器衔接：metric 相等不仲裁而是建组，组生命周期事件进 F33610 通道供 B19 视图呈现。

### UNX-F33622 · ECMP 流内一致与逐包轮转禁令

逐包轮转是流内乱序与 TCP 重传风暴的经典根源，本条目把它钉死在禁止清单上。功能约束：100 条流 × 每流 10^3 包的验证集里，每条流全生命周期下一跳恒定；代码层面 grep 防重登记——任何轮转计数器模式的代码路径零存在，违反即构建期红线。判据另含：哈希种子变更时事件必发且新种子下流内一致复验；流表（五元组→成员映射）缓存有界，淘汰后同流重哈希结果必须与首次一致（哈希是纯函数）。设计考量：流内一致与 F33621 的均匀分布是一对张力——成员摘除会强制部分流迁移，这是唯一允许的流迁移时机，迁移本身也要零中断（先在新成员上建好再切）。J4 判据的 ECMP 部分以此条为执行面。

### UNX-F33623 · ECMP 成员健康联动：下一跳不可达摘除

成员死了组要能自愈。本条目把下一跳 ARP 状态与 ECMP 成员资格联动：成员 ARP 进入 FAILED 态 ×10 次注入，全部自动摘除并向受影响前缀发 ICMP host unreachable；恢复后自动回组 ×10 全过，回组即重新参与哈希分流；全组失效时回退到默认路由兜底。设计上摘除与回组都走 F33605 的删除/插入物理路径，保证事件流形态一致；摘除期间成员表项标记 FAILED 而非删除（承 B02 骨架语义），恢复探测由邻居账驱动，不另设定时器。判据含：摘除/回组事件顺序全序（摘除先于流量迁移）、风暴场景（成员反复抖动）限速处理、联动账逐次可查。该条目是 B03 邻居账 FAILED 联动（F33668）的第一个消费方，二者对账挂 ktest。

### UNX-F33624 · 策略路由规则表：源前缀→指定表最小面

策略路由按"最小面"实现：规则表只做一件事——按源前缀把流量指到指定路由表，不多做端口匹配、不做时间窗、不做用户态钩子，面铺大就是维护债。功能上支持 16 条规则上限内插入、匹配、优先级仲裁，黄金剧本 30 组全过；超限拒绝返回单一错误码；规则变更事件必发。设计上规则表是有序数组而非树——16 条的规模线性扫描快过任何花哨结构，简单即正确；每条规则含源前缀/目标表 ID/优先级三元组，优先级相同按插入序。判据含：规则匹配确定性（同包同结果）、规则环检测前置（指向自身的表拒绝）。该条目是 L5 容器/VPN 多表命名空间（F33629）的入口消费方，也是 netxp.rs 接管账（F33635）的边界声明对象。

### UNX-F33625 · 策略路由命中与查表次序语义

命中语义要像法律条文一样无歧义。本条目规定查表次序：先扫规则表，命中即查指定表并跳过主表——10^3 次验证零例外；规则表全未命中则回落主表正常最长匹配；命中表之后再触发一次最长匹配（策略表内部仍按前缀语义查），但不再递归策略规则，循环引用（表指向自身）在配置期即拒止。判据含：命中/回落两路各 10^3 样本零差、次序账逐次可查（每个查询命中哪条规则落审计）、性能账——策略扫描给热路径增加的开销 P99 ≤0.5μs。设计上热路径先查"规则表为空"的快速位，无规则时零开销直通主表，保住 F33606 的 2μs 红线；有规则时代价可见且有账。该语义与 I1 转发面对账（B29）时双向声明，避免两端各查一套。

### UNX-F33626 · ICMP 重定向接受与来源标签老化（10 分钟）

ICMP 重定向是网关的善意提示，接受它 but 带怀疑。本条目规定：合法重定向注入 ×10，表项落账并带"重定向"来源标签；按 600 秒老化精确移除 ×10，到期事件必发；重定向环（A 网关与 B 网关互指）检测后拒止不入表。设计上重定向路由是四类来源中寿命最短的一类（F33609 策略表），因为它是优化建议而非拓扑事实，过期即弃；老化复用增量轮转桶，与 RA 路由同桶不同 TTL。判据含：接受后查询命中验证（下一跳已切换）、老化后回落原网关验证、环检测的三种构造（自指/互指/三环）全部拒止。该条目与 F33627 安全闸构成两道关：先验合法（闸），再落账老化（本条），顺序不可倒置。

### UNX-F33627 · 重定向安全闸：只接受同接口来源且网关合法

重定向是经典攻击面（伪造重定向可劫流）。本条目设双条件闸门：报文必须来自当前表项的同接口网关，且重定向后的新网关与旧网关同网段，两条同时成立才放行。判据：跨接口伪造重定向 ×20 零入表；新网关不在同网段 ×20 全拒；接受率账与白名单策略逐条一致，拒绝事件进审计通道（含伪造源地址，供 B21 安全面关联分析）。设计上闸门在解析层实现，非法报文不进入路由逻辑就被丢弃，攻击面止步于边界；白名单是显式配置而非隐式默认，"默认全拒"是安全底线。该条目响应十六章安全纪律：外部输入全清洗，重定向报文正是最典型的外部输入。审计事件与 J5 联签位（F33636）对账，攻击尝试可回溯。

### UNX-F33628 · 路由不可达标记语义（FAILED 态而非删除）

下一跳失联时，删路由是懒办法，坏处是恢复时要重新学习且事件流里"失联"与"真删除"混账。本条目规定：下一跳 ARP FAILED ×10 注入，路由保留但标记不可达；查询命中 FAILED 项时上抛 unreachable 错误而非转发；恢复探测（由邻居账驱动）×10 自动复活，复活事件必发。设计上 FAILED 是路由的状态位而非独立态机，与 F33623 的 ECMP 摘除共享同一探测源；标记期间该前缀的 metric 仲裁冻结，防止失联期间的 metric 抖动引发仲裁震荡。判据含：FAILED 态查询行为 10^3 次一致、复活后行为与失联前逐位一致（快照对照）、FAILED 老化兜底（长期 FAILED 且确认死路由才真删，条件落档）。该语义是 B14 租约降级链"幽灵网零发生"判定的路由侧参照。

### UNX-F33629 · 多表路由命名空间预留（L5 容器/VPN 消费位）

多表是未来，接口现在就位。本条目把路由表 ID 从单例改为命名空间参数：现有主表占 ID 0，其余 ID 段编译期冻结预留；查询接口带表 ID 参数，分发探针验证查询正确路由到对应表。判据：预留接口编译期冻结断言；主表行为零回归（回归账 30 例全过——加参数不能让老路径变慢或变味）；跨表查询分发探针正确。设计上明确"预留不实装"边界：表创建/隔离/规则引用属于 L5 容器域，本条目只保证策略路由（F33624）的"指定表"有合法命名空间可指；越界实装被预告位登记拦下。该条目与 F33612 双栈预留同属"接口先手棋"判例：让未来功能有稳定落点，防止届时回头改冻结面。

### UNX-F33630 · 路由面与 I1 转发面钩子对账（route_lookup 消费位）

I1 转发面每包调用的 route_lookup(dst)→next_hop_if 是本域最重的上游契约。本条目做消费对账：冻结接口逐方法核对 30 格全过；fake 端（Schema 先行阶段的替身）10 剧本全链验证；未收口项显性登记 R-I3-001 风险，绝不静默——上游 AI-41 波 16 Q3 冻结日前，本域全链按 fake 落账，冻结日后走 B29 的 fake→真身切换剧本。判据含：对账账逐格留痕、fake 与真身行为差分（切换剧本里零改消费侧）。设计上消费侧只依赖接口签名不依赖实现，切换风险被压缩到零。该条目是跨域协作纪律的样板：依赖方拿冻结接口+fake 开发，不等上游做完；风险登记在 open_risks，闸门日闭环销号。

### UNX-F33631 · 路由面压测：混合读写 10^6 次稳定性

真实流量是读写混合的，单测纯读纯写都会漏。本条目构建 8 写 24 读混合压测：写侧随机插入/删除/更新，读侧并发查询，持续 10^6 次操作。判据：零崩溃零撕裂（TSan 全程零报告）；延迟 P99 ≤5μs 实测落档（写风暴下的读劣化有上界）；压测后结构不变量校验零违规——树还是那棵树，只是经历了风雨。设计上压测是确定性回放友好的：操作序列种子落档，失败可复现（承 B26 竞态复现器模式）；压测 profiles（读写比 1:3 / 1:1 / 3:1）三档落档，覆盖真实分布。该条目数据进 B39 域级性能总终账，是"流畅不是指标是体感"在路由面的量化锚点：任何新功能合并前跑一遍压测档，劣化即拦截。

### UNX-F33632 · 路由面 fuzz：恶意前缀/掩码/事件注入

外部输入不可信，内部输入也不可全信。本条目对路由面三个入口做 fuzz：配置注入（畸形前缀/掩码/metric）、事件注入（伪造协议来源事件）、接口注入（畸形 ioctl 参数），随机畸形输入 10^5 组，要求零崩溃零越界（ASan 零报告）。判据：畸形输入全拒且错误账落档（拒绝也是被记录的行为，不是静默）；崩溃样本（如有）归档零残留并转最小复现（B25 样本库模式前置）。设计上 fuzz 用语料库+变异混合策略，语料含真实互联网路由表样本的畸形化版本；fuzz 与 CI 集成分 fast/full 两档，fast 档日常跑、full 档闸门跑。该条目是 B25 全域 fuzz 汇总的路由面样本源，所有 fuzz 纪律（样本库、分级、工单联动）以 B25 为总章，本条目供料。

### UNX-F33633 · F33633 语义承载预告位与接口翻译预告（恒等归位登记）

本条目是任务书示例锚 F33633 的 ID 恒等承载位，本体语义（wpa_supplicant 适配层与驱动接口翻译）因 20 条/批的 ID 连续性约束落于 B05 末条 F33700 语义承载——这是区间恒等归位判例（承 C2/D2/G4）的第三次执行：ID 不变不重编，语义锚落批内承载位，跨批引用链零断点。本条目自身承载三件事：预告位登记（F33633→语义见 F33700 的映射落档）；ID 恒等核对断言（任何对账工具读到 F33633 都能找到归宿）；引用链完整性校验（任务书→总纲 §7.3-I3→批册→本条目四级锚链全通）。设计上恒等归位是全域纪律而非本域发明，B04 的 F33672、B06 的 F33720 同判例执行，B39 域级 ID 终验时 800 条连续唯一与锚链完整性一并核销。

### UNX-F33634 · 路由面压测与延迟账归档（性能补强位）

本条目是压测的归档化收口：把 F33631 的三档 profiles 压测结果、F33616 基线账、F33606 热路径账合并为路由面延迟总账，按操作类型（查/插/删/事件）分列，P50/P95/P99 三档齐备。判据：总账与三源账逐项一致（零漂移）；总账版本号与构建版本绑定；回归剧本一键复演（基线偏离 >10% 必红）。设计上账目是机器可读格式（JSON 落档），B39 六判据汇兑直接读取不人工转抄——人工转抄是账目漂移的温床。判据另含：账目敏感字段审计（无凭据/无内部路径泄漏）；账目对网管 CLI 可见（route perf 子命令数据源）。该条目体现域级纪律：性能数字要能从单条判据一路追到域级终表，中间不允许断链。

### UNX-F33635 · 策略路由与 QoS 面衔接预留（netxp 接管预告）

netxp.rs 存量 QoS/流量画像语义的移交/接管双账（联 AI-98）在本条目落位：衔接接口预告编译期冻结（策略路由命中后向 QoS 面传递命中表 ID 的钩子签名）；存量语义零实装撞号核对——本域不实现 QoS 逻辑，只留钩子，防止与接管账"两边都管"或"两边都不管"。判据：预告位冻结断言；与 netxp 接管账的边界划账双向声明落档；钩子空实现时行为零回归。设计上这是 B31 移交账执行的预告件：届时 netxp.rs DNS 缓存/代理/信任库退役、无缝切换/热点/Wi-Fi/QoS 归本域真身化，钩子就是真身化的第一个落点。判据含：钩子调用开销账（空钩子 P99 ≤0.1μs）、钩子事件进时间轴。移交即退役的纪律在预告期就已生效。

### UNX-F33636 · 路由表事件流与 J5 审计通道联签位

审计是事件的最后一站，也是不可删改的一站。本条目做联签位登记：路由变更事件（F33610 四类）进 J5 审计通道的映射声明落档；审计通道不可删改属性探针过（写入后尝试篡改必拒）；与 AI-50 的边界划账双向声明——本域负责发事件，审计面负责存证，谁都不越界。判据：联签声明版本化落档；事件端到端（路由变更→审计存证）延迟 ≤100ms 抽测；联签对账 10 格全过。设计上审计事件与体验日志（F33617）双轨分流：审计走 J5 通道重不可变，体验走时间轴重还原，两轨互不阻塞（B34 双轨分流语义的前置对齐）。该条目是全域"事件一经发出不可撤回"纪律的路由面锚点，B34 终验时按联签表回销。

### UNX-F33637 · 路由面资源账：内存/CPU 常驻上限

资源账是域级 ≤64MB 承诺的分项。本条目立路由面的分账：10 万条目常驻 ≤24MB 实测；查询 CPU 空闲态零残留（空闲时无轮询线程、无定时唤醒）；资源超限告警三要素呈现。判据：分账挂 CI 门禁（每次构建实测，越限即红）；内存构成细分（节点池/镜像/事件队列）逐项可查；CPU 账含空闲/峰值两态。设计上资源守卫复用 B24 域级配额表条目，路由面配额是表中的一行而非独立机制——全域一个配额体系，杜绝各面私设小金库；告警一次性不刷屏（同水位档去重）。该条目数据是 B39 域级资源总终账（合计 ≤64MB）的直接输入，B24 的域级合计终验按分批占比账回溯到本条目核销。

### UNX-F33638 · 双表一致性：主表与镜像对照自检

镜像机制的信任必须被验证而非假设。本条目实现主表/镜像逐条对照自检：10^3 轮后台低优先级扫描，逐条比对前缀/下一跳/metric/状态位，零漂移为绿。判据：漂移注入检出率 100%（灵敏度自检——人为改镜像一条必被抓）；自检开销 P99 <100μs/轮（不干扰业务）；漂移检出即告警并触发镜像重建（重建期间查询回落主表加锁模式，短暂降速但正确）。设计上自检是机会主义的（系统空闲时跑，忙时让路），与帧缓冲批滚纪律同源：不做整屏搬运式的大块全表比对，增量游标分片推进。该条目是 F33611 快慢分离的保活件，也是异常显性化网络（F33618 镜像同步失败捕获点）的数据源，三者构成"分离-检测-告警"闭环。

### UNX-F33639 · B02 段 ktest 断言面扩表

B02 全 20 条判据注册进 ktest 断言面，与 B01 合计 40 条一条命令全通。判据：注册面 API 断言复用（编号唯一/签名匹配）；失败注入必红三条——针对 ECMP 流一致、重定向老化、策略命中三个代表性判据人为破坏，ktest 必报红；误报率 ≤1% 复测落档。设计上每批扩表条目除了注册还要做"断言面健康度"复查：B01 存量 20 条回归仍全绿（新注册不能弄坏旧的），注册耗时账落档（扩表不能拖慢 fast 档分钟级承诺）。该条目延续 F33619 的基建模式，是双轨产线"轻门禁绿"的执行细节：ktest 输出直接回链批册条目编号，验收对账零翻译。B03–B40 各批扩表条目同模式，不再赘述处一律引用本条判例。
