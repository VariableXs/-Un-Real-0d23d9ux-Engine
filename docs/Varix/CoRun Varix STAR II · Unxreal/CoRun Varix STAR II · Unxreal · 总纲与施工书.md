## 0. 卷首总纲

### 0.1 立项定位（委托原话锚定）

本册是 CoRun Varix STAR II. Unxreal 的唯一总账与施工宪法。立项委托锚点原文摘录：

> 主要让 VARIX 可以像精细的艺术品去完整，几乎完全逼进 WINDOWS 的兼容效果和性能效果一样，不惜一切代价达成；可以使用不同规模的开源项目，只要可以逼进原生的 WINDOWS 的兼容效果和性能效果，这是必须确保的呀；每个功能对应的纯功能代码行数写进 MD 文件里；布局还有字数是 VE Varix STAR II 的总字数的至少 10 倍，功能总数 10 倍；所有功能不可以和现有功能重复，实用；首先需要把所有 30 年的所有功能还有自适应工程的纯功能代码行数、领域全部先列出来写在 MD 文件里，然后再进行每个功能 300 字的深化；全部达到才算结束。

由此衍生四句宪法：

1. **艺术品级逼近 Windows**。兼容效果与性能效果双对标：一切条目的终审形态是"在 Varix 真机上与 Windows 原生行为逐项对照可验证"。对标对象不止于 API 语义，还包括启动时延、内存占用、帧率稳定性、安装体验、中文输入体验、崩溃恢复表现等性能与体验全维度。
2. **开源嫁接合法化**。Wine、Mesa/Gallium、DXVK、vkd3d-proton、ntfs-3g/ntfs3、PipeWire、fcitx5、Xwayland、LTP、gstreamer、cups、wpa_supplicant、openssl 等各规模开源项目按域嫁接，**只跟随上游、绝不 fork**，本地补丁最小化并优先上游化。嫁接接口层（如 winevarix.drv、vxwm 对接层、audio.rs 桥、imepinyin.rs 桥）为自研代码，计入纯功能行数；上游第三方代码本身不计入。
3. **一切计量看行数与判据**。每条功能必须写明纯功能代码行数；只认可运行判据与纯功能代码行数计量——判据建模层、`#[cfg(test)]` 测试段、文档、注释一律不计入纯功能行数（口径与《Varix-内核与STAR全案MD文档全面分析》§2.1b 完全一致：现存 913,130 行中纯功能主干 124,077 行）。
4. **骨架先行、深化到底**。本版先立全部 80 域 64,000 条的领域骨架、ID 段与行数预算，随后按批次逐条 ≥300 字深化，直到 64,000 条全部达到深化标准——全部达到才算结束。

## 1. 十二条铁律

1. **唯一总账**：一切条目以本册编号 `UNX-F0001～F64000` 为准，先骨架后深化；任何会话不得私开编号。
2. **计量宪法**：只认可运行判据与纯功能代码行数计量。判据建模层、`#[cfg(test)]` 测试段、文档与注释不计入纯功能行数；每条深化必须带行数，无行数不算深化。
3. **域账守恒**：每域 800 条、纯功能行数域账锁定 240,000 行；域内条目行数在 120–600 区间按难度浮动，域内总和守恒；80 域总账 19,200,000 行，任何时刻可被断言校验。
4. **诚实三态**：每批只允许 `[已深化] / [骨架] / [未动]` 三态；台账每批回填，禁止第四态，禁止虚报。
5. **防重铁律**：新条目不得与 VARIX 现有功能重复（现有 6,400 VE 条 + 3,840 CGPU 条 + 640 start 条 + 内核现存 124,077 行纯功能所覆盖的一切）；每批 finalize 前跑防重 grep（见 §6）。
6. **年度镜像恒线**：每波（年）闭账必须产出可引导 U 盘镜像并通过双击即用 B 判据复测，否则该波不得闭账。
7. **三桥红线**：GUI 桥、音频桥、输入法桥是中文生命线与双击即用铁门，任何波次不得回退，任何条目不得削弱三桥。
8. **上游跟随**：开源嫁接件只跟随上游不 fork；本地补丁最小化、优先上游化；嫁接接口层自研并计入行数，上游代码不计入。
9. **红线制度**：引导设施红线与硬件数据安全红线全程有效；凡涉及引导链改写、磁盘直写、分区操作的条目，必须双人复核判据方可动工。
10. **断点续写**：一切产线状态落盘断点文件（handoff 机制，见 §6.4），任何会话可冷启动续接；批次推进不依赖单一会话记忆。
11. **判据先行**：条目未写判据不得动工；判据必须可运行、可观测、可复测，并与 20 维验收体系对接。
12. **深化闭环**：全部 64,000 条达到深化标准（≥300 字正文 + 六要素 + 可运行判据 + 行数）才算结束；"全部达到才算结束"。

### 2.3 条目深化体例（六要素）

每条深化必须齐备六要素 + ≥300 字正文：

```
### UNX-F#### · <条目名>
- 域/批：A1/B01｜判据：UNX-F####-J1 <可运行判据>｜纯功能行数：N 行｜状态：[已深化]
- **定位**：解决什么问题、对齐 Windows 的哪个语义
- **语义边界**：做什么、明确不做什么（防灌水防重复）
- **判据**：可运行、可观测、可复测的验收句
- **纯功能行数**：N 行（自研 Rust / 嫁接接口层，上游代码不计）
- **依赖与嫁接源**：依赖条目、上游项目与版本策略
- **风险与回退**：失败模式与回退路径
- 正文 ≥300 字：实现路径、数据结构、与现存内核的衔接点、Windows 对照行为
```

### 2.4 行数计量口径

- **计入**：自研 Rust 实现代码、嫁接接口层代码（drv/桥/适配器）、必要的常量表与语义表。
- **不计入**：`#[cfg(test)]` 测试段、CheckSet 判据聚合器（`fn run_*_checks` 判据建模体）、文档、注释、上游第三方源码。
- 域账：每域锁定 240,000 行；条目行数按难度 120–600 行浮动，域内总和守恒；批次 finalize 时用累计断言校验域账。

## 4. 十六部八十域总地图

规则：每域 800 条（40 批 × 20 条）、域账 240,000 行，80 域合计 19,200,000 行。"判据组要点"为该域条目判据的主轴；"关键依赖"列既有内核实存能力或本册域号。全域三态以台账（§7）滚动登记。

- **定位**：Limine 是现存真引导链的根，本条把"引导即通"升级为"引导即可审计"——帧簿（framebuffer）、内存图、内核 ELF 段映射、rsdp/itmode 等全部 Limine 响应固化为结构化清单，供 A1 域后续各条消费。
- **语义边界**：只做协议响应的采集、校验、固化与报告；不做 ACPI 解析（F0002）、不做内存图合并（F0008），明确防重复。
- **纯功能行数**：320 行（自研 Rust；响应结构体 + 校验器 + 报告格式化，测试段不计）。
- **依赖与嫁接源**：依赖现存 boot 链（已真机通过）；Limine 只跟随上游版本。
- **风险与回退**：协议版本变更导致响应缺失——按"响应可选项缺席降级记账"处理，引导不失败。
- 正文：实现路径分三步。第一步定义 Limine 响应全景枚举（framebuffer/mmap/kernel-file/kernel-address/rsdp/itmode/memmap-info），与现存取用代码逐一对账，把散落各处的 hand-typed 结构收敛为单一 `bootproto` 模块；第二步写逐项校验器：帧簿校验 bpp/pitch/地址对齐，内存图校验区间重叠与可用区连续性，ELF 段校验 vaddr 与链接脚本一致，任何一项异常打引导报告并降级；第三步固化清单进全局 `BootManifest`，向 F0002（ACPI）、F0008（三源合并）、F0012（页表布局）提供唯一事实源，消除现存多处重复解析 Limine 响应的隐患。与 Windows 对照：对齐 Windows 启动日志的"引导环境摘要"可审计性——VARIX 的引导清单要像 bcdedit / 系统信息一样随时可查。判据 UNX-F0001-J1 的复测方式：真机 U 盘引导 → 引导报告打印 → 与Limine 协议文档逐项比对，连续 50 次引导零差异。

#### UNX-F0021 · LAPIC 使能与 EOI 语义全量化
- 域/批：A1/B02｜判据：UNX-F0021-J1｜纯功能行数：380｜状态：[已深化·样板]
- **定位**：现存内核外设全轮询、无 MSI-X，中断面是"成年礼"第一刀。本条实装 LAPIC（IA32_APIC_BASE 检测、Spurious-IRQ、SVR、EOI）全语义，为 F0023 IOAPIC、F0024 MSI-X、A3 SMP 提供单核中断底座。
- **语义边界**：只做本地 APIC 本体（定时器/LVT/EOI/SVR）；不做 IPI 广播（F0026）、不做时钟源选择（F0032）。
- **纯功能行数**：380 行（自研 Rust；MSR 访问封装、LVT 配置、EOI 状态机、错误状态寄存器处理）。
- **依赖与嫁接源**：依赖 F0004（MADT 提供 LAPIC 基址）；对现存轮询栈是升级关系。
- **风险与回退**：虚拟机与真机 LAPIC 版本差异——按 IA32 架构手册版本位分支；异常时回退轮询模式（F0039 双模开关兜底）。
- 正文：实现路径四步。第一步封装 APIC MSR/xMMR 双寻址（xAPIC mmio 与 x2APIC msr 统一接口，为 F0025 铺路）；第二步实装 SVR（spurious vector 第 7 位使能）、EOI 语义——EOI 写入必须与 ISR 位清零严格配对，引入 `eoi_pending` 账本防"EOI 丢失导致中断永不再来"这一经典事故；第三步实装 LVT 定时器（one-shot/periodic/tsc-deadline 三模接口，tsc-deadline 留给 F0030）与 LVT 错误中断（ESR 读清规则严格按手册两次读语义）；第四步对接现存 NVMe/xHCI 轮询路径，做成 per-device `PollOrIrq` 双模枚举（F0039 的地基）。与 Windows 对照：Windows 内核中断路径的首个硬指标是"EOI 正确性"——HAL 层 HalEnableSystemInterrupt/HalEndSystemInterrupt 的语义在 VARIX 对应为 LAPIC 模块的 eoi 语义，判据 J1 在真机上以 10^7 次定时器中断零丢失、零重投递为验收线。

#### UNX-F0039 · 轮询/中断双模设备开关（现存栈升级接管）
- 域/批：A1/B02｜判据：UNX-F0039-J1｜纯功能行数：340｜状态：[已深化·样板]
- **定位**：现存内核 NVMe/xHCI/AHCI/PS2 全轮询（无 MSI-X），这是"图纸 vs 实体"审计里的已知欠账。本条不新建设备驱动（防重：驱动语义归 B4/M5 域），只建**设备级中断/轮询模式切换开关层**，让每个设备可独立选择模式，是中断面与现存栈之间的正式合并层。
- **语义边界**：只做模式抽象、切换协议、事件不丢失保证；不做具体设备寄存器语义（归各设备域）。
- **纯功能行数**：340 行（自研 Rust；trait 定义、切换状态机、事件队列桥）。
- **依赖与嫁接源**：依赖 F0021–F0024（中断底座）；现存轮询函数体零改动挂接。
- **风险与回退**：切换窗口丢事件——双缓冲事件队列 + 切换前 drain 协议兜底。
- 正文：核心是一个 `IrqBackend` trait：`poll()` 与 `irq(vector)` 两种后端，设备驱动只面对统一事件回调，不感知后端。切换协议四态：`Polling → Draining → Arming → Irq`——Draining 保证轮询侧在途事件全部入队后才允许注册中断向量，Arming 先注册向量再关轮询时钟，关闭窗口用 per-device 原子序号账本检测事件空洞，发现空洞立即回退 Polling 并记缺陷账。四设备（NVMe/xHCI/AHCI/PS2）逐个接入，每设备一条独立判据：模式往返切换 1,000 次零丢事件、零重复事件；NVMe 在 MSI-X（F0024）可用时默认 Irq，否则回落 Polling。与 Windows 对照：Windows 的 HAL 对遗留设备同样存在"轮询降级"路径（如 PSA/poll 模式），VARIX 把这条路径制度化、可观测化——`sysinfo` 可列出每设备当前后端与切换历史，这比 Windows 更透明，属于"逼近且超越"的艺术品级打磨点。

## 6. 施工协议

### 6.1 批次 finalize 断言链（五步，全过才算 finalize）

1. **防重断言**：批内每条条目名 + 关键 API 名在以下范围 grep，命中即回炉重写：
   - `docs/VE Varix STAR II · 总纲与施工书.md`（6,400 条）
   - `docs/` 下 CGPU 卷与 start.md（3,840 + 640 条）
   - `kernel/varix/src/**`（现存 124,077 行纯功能主干已覆盖语义）
   - 本册已 finalize 批次。
2. **判据可运行断言**：每条至少 1 条判据，判据句含可观测动作（跑通/输出/落账/对照），纯"实现了/支持了"式判据无效。
3. **行数守恒断言**：批内条目行数求和与批次账一致；域内累计与 240,000 守恒（P2 域提供守恒断言器自动化）。
4. **三态回填断言**：台账（§7）该批状态更新为 `[已深化]`，深化字数、finalize 会话号回填。
5. **深化四项齐备断言**：≥300 字正文 + 六要素 + 判据 + 行数，缺一不算深化。

### 6.2 等锁批次机制

- 同域双会话并行时，按批次号错峰：会话 A 领偶数批、会话 B 领奇数批，或按台账"承接会话"列认领。
- 批次认领先改台账再动工；台账冲突以先回填者为准，后者顺延下一批。
- 跨域依赖条目（如 F1 域依赖 A4）只允许引用已 finalize 的条目，未 finalize 依赖记入该条"风险与回退"。

### 6.3 深化产线节奏

- 每批 20 条深化 ≈ 6,000 字正文；单会话建议吞吐 1–3 批（保质优先）。
- 3,200 批 ÷ 三十波 ≈ 每波 107 批；每波台账闭账条件见 6.5。
- 深化顺序默认按 ID 段顺序推进，允许跨域并行但不得跳段私开。

### 6.4 断点续写（handoff 机制）

每会话收口时在 `docs/unxreal/handoff.json` 落盘（此文件随首批深化创建）：

```json
{
  "phase": "deepen",
  "next_batch": "UNX-A1-B03",
  "domain_ledger_progress": { "A1": { "finalized_batches": 2, "rows_locked": 11620, "rows_budget": 240000 } },
  "open_risks": [],
  "last_session": "<会话标识>",
  "protocol": "见《CoRun Varix STAR II · Unxreal · 总纲与施工书》§6"
}
```

冷启动续接三步：读本册 §7 台账 → 读 handoff.json → 领取下一批。任何会话不得依赖自身记忆推进批次。

### 6.5 每波闭账仪式（年度镜像恒线）

波末五件套，缺一不得闭账：
1. 该波主攻域批次全部 `[已深化]` 且 finalize 断言链全过；
2. 年度可引导 U 盘镜像产出（L1 域构建链，红线双人复核）；
3. 双击即用 B 判据复测通过（三桥无回退）；
4. 20 维验收报告落盘（O3 域体系）；
5. handoff.json 与台账快照归档（P1 域体系）。

### 6.6 红线执行细则

- 引导设施红线：凡 F0001–F0020、L1 域引导链相关条目动工前，双人复核判据；引导链改动必须在诊断模式（F0017）可用状态下进行。
- 硬件数据安全红线：B5/L1 域一切写盘、分区、擦除操作条目，先写保护判据（目标盘校验、只写申报盘、断电演练），后写功能；判据不过禁止动工。
