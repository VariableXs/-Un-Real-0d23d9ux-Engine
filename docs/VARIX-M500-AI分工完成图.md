# VARIX-M500 AI 分工完成图（完整版 · 内核成熟化与生态深化）

> 共 **20 个 AI**（AI-01 ~ AI-20），围绕 **"Varix 内核成熟化与生态深化"** 全域分工，
> 每域 25 项，合计 **500 项新功能**（F001~F500）。
> 系列定位：VARIX-500（地基 ✅）→ VARIABLE-200（并入 ✅）→ **VARIX-M500（成熟化，本系列）**。
> 状态：⬜ 未开始 / 🔶 进行中 / ✅ 完成
> 纪律：
> 1. 每个 AI 只修改自己域的模块（内核侧 `kernel/varix/src/`，用户态侧 `kernel/userspace/`）；
>    **不碰 `src/`、`src-tauri/` 的 Windows 后端**（只增不删）。
> 2. 共享 MD（本图、总步骤图、全景图）编辑前先 `git log` 验 HEAD。
> 3. 完成一项：更新本图 → commit（`m500(ai-XX): Fxxx <功能名>`）→ 推送 GitHub。
> 4. 质量军规 14 条见《总步骤图》0.4（含零重复、每项带仪表、每域 ≥2 项原创 + ≥1 项登月）。
> 5. **AI-19（性能观测）先行**：先有仪表后动刀；依赖图见文末，严禁跳依赖抢跑。

## 协作与提交纪律

1. 提交信息：`m500(ai-XX): Fxxx <功能名>`，一功能一提交或一域一批。
2. `lib.rs`/`mod.rs` 的模块列表多方追加，提交前必须复查。
3. 多会话并行：只挑自己域路径 `git add`，禁止 `git add .`；**禁止 `git pull --rebase --autostash`**。
4. 每域 25 项 CheckSet 全部汇入 `robust::run_kernel_checkup()`，boot 自检随域扩充。
5. `cargo kcheck` / `cargo ktest --lib` / `cargo kbuild` 全绿才提交；QEMU 引导冒烟每域收口必跑。
6. 查重总清单 = VARIX-500（500）+ VARIABLE-200（200）+ 本图（500）= **1200 项**。
