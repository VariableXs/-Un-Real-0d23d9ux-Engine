> M2（窗口系统与桌面核心，A201~A400）已收口，M3（桌面体验与基础应用，A401~A760）承接。
> 本页只写 W3 施工需要知道的东西：接口约定、复用点、坑。

## 1. W3 直接消费的 W2 接口

| W3 域 | 用到的 W2 接口 | 约定 |
|---|---|---|
| AI-17 设计系统（`designsys`） | `widgets::tokens` 令牌引用、`widgets::state_transition` 五态 | 令牌唯一源在 designsys（A401）；widgets 已按"引用令牌"实现（A324），换令牌源只需改 tokens 模块 |
| AI-18 文件管理器（`fileman`） | `clipboard::is_file_target`/`file_entry_count`（A341）、拖放引擎 `drag_*`、`appfw::app_register` | 拖文件到管理器走 `FILE_MANAGER_TARGET` 约定目标位；应用必须先注册进 AppManager |
| AI-19~24 基础应用 | `appfw` 事件循环/窗口托管、`widgets` 全组件、`desktop::shortcut_*` | 每个应用一文件，注册名 ≤NAME_CAP，沙箱位用 `PERM_*` 组合 |
| 全部 | `aurora::w2_integration` 场景 | 新增跨域行为 → 在此加场景，别只写域内单测 |

## 2. 组件接口约定（AI-13 → AI-17/18~24）

- 组件节点统一 `widgets::Node{role,state,rect,parent,label,value}`，布局用 `layout_children`，键盘用 `focus_cycle`；读屏标签走 `role_label`。
- 组件五态：Normal/Hover/Pressed/Disabled/Focused —— 主题包必须覆盖五态 × 亮暗（designsys A404）。
- 列表/表格自带可见窗口裁剪（`list_visible_window`/`table_cell_hit`），虚拟滚动的数据侧由应用提供，组件只管窗口。

## 3. 应用框架约定（AI-12 → AI-18~24）

- 应用状态机：Created→Running→Suspended→Terminated，非法迁移被 `can_transition` 拒绝；别绕过 `app_transition`。
- 事件：`event_enqueue` 满则丢弃计数；应用必须能在事件丢失时自愈（重绘自状态）。
- 关窗确认：`set_confirm_close(true)` 后 `close_window` 返回 `ConfirmNeeded`，应用负责弹 `widgets::dialog`。

## 4. 坑（来自 W2 实测）

1. `paste(seen_seq=0)` 是"跳过新鲜度校验"，不是"粘贴第 0 版"。
2. `Rect` 有四套定义（window/widgets、motion、compositor、workspace 各自独立），跨域传递先转换。
3. `run_kernel_checkup` 已接近 50 域，新增域记得接入并确认 `MAX_DOMAINS`（96）仍够。
4. `desktop::Name` 截断到 `NAME_CAP`，应用名/标签超长会静默截断 —— 长名字先在应用侧校验。
