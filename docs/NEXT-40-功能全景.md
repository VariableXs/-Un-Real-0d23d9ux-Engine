## 域 A：窗口与空间进化（N-01…N-06，AI-2）

### N-01 窗口时间机器（Window Timeline）

**一句话**：把「窗口布局」变成可回放的历史——任意时刻的整套窗口状态（VWM 虚拟窗口 + 嵌入第三方 + 位置/层级/分屏态）都可以快照、命名、一键恢复。

**现状地基**：`winman.rs` 已有完整窗口枚举与取证日志；`embed.rs` 有嵌入会话状态机（EmbedSession）；VWM 前端 store 已维护 z 序/聚焦态/贴靠态。缺的只是「把这些状态序列化成时序快照 + 恢复执行器」。

**详细设计**：
- 快照 = `{ ts, vwm_windows[], embed_windows[](hwnd/进程/位置/tier), desktop_page, scene_ref }`，落盘为 `data/timeline/*.vsnap`（zstd 压缩、纯追加、按天分片）；
- 自动快照触发：布局变化去抖 8s、场景切换前后、环境休眠前；手动快照：任务栏右键「定格此刻」；
- 时间轴 UI：任务栏长按/`Ctrl+Alt+T` 呼出横向时间带，缩略图渲染快照（复用 `capture.rs` 已有的窗口位图捕获）；
- 恢复策略三级：**精确恢复**（进程还活着→仅重摆位置）、**尽力恢复**（进程已死→按 `launcher.rs` 登记项重启再重摆）、**诚实报告**（无法恢复的窗口列表列出，绝不静默失败）；
- 保留策略：近 7 天全量 → 30 天每小时首张 → 90 天每天首张，上限 200MB，超限 FIFO 淘汰并在设置页如实显示。

**为什么是它**：顶级桌面（macOS Stage Manager、Windows Snap Groups）都只解决「当下」，没有任何作品把窗口布局做成**可回放的时间维度**——这是写作/研究工作流「回到上周三下午的工作现场」的杀手级能力。

**依赖/风险**：依赖 `capture.rs`（缩略图）与 `launcher.rs`（重启登记）；风险是嵌入窗口恢复时 tier 判定漂移——必须复跑 C-6 探测器而非读旧快照字段。

**验收**：①同一应用开 5 窗改布局→恢复→位置/层级/z 序逐项一致；②杀掉进程后恢复→走重启路径；③快照损坏时 UI 报错且不影响其余快照；④断电重启后时间轴可读。

### N-02 舞台管理器（Window Stage Manager）

**一句话**：类 macOS Stage Manager 的窗口编组——当前工作的一组窗口居中在「舞台」，其余窗口按组收拢到左侧「侧幕」，点组即整组上台。

**现状地基**：VWM 已有 z 序/聚焦/最小化飞行动效与 `--dur-3` spring token；缺「组」这一层抽象。

**详细设计**：
- 组（Stage）= 虚拟窗口的命名集合，成员关系可自动（同进程/同贴靠布局）或手动（拖拽入侧幕气泡）；
- 上台动效复用 vwm-in spring keyframes（-20% 初速、4% 过冲），侧幕气泡收拢用 flying squash 同款曲线，保证全域动效语言一致；
- 组操作：双击侧幕气泡整组上台、拖拽窗口到气泡入组、`Ctrl+Shift+←/→` 组间轮换；
- 组持久化：`data/stages.json`，跨重启存活；组可与 N-05 场景互引用（一个场景可预设激活某组）；
- 侧幕自动隐藏：全屏窗口激活时侧幕滑出屏幕外，`Win+←` 唤回。

**为什么是它**：把「窗口多到爆炸」的用户从 Alt+Tab 地狱里救出来，与时间机器（N-01）构成「横向编组 + 纵向时间」的完整窗口管理学。

**依赖/风险**：纯前端 VWM 层实现，风险低；注意与既有边缘贴靠的手势冲突（侧幕热区与贴靠热区错开 24px）。

**验收**：①建组→重启→组关系完整；②组上台动画 60fps 无掉帧（bench 归档）；③与贴靠同屏共存不误触；④键盘全可达。

### N-03 窗口规则引擎（Window Rules Engine）

**一句话**：用户可写「当 X 应用启动 → 自动嵌入/独立、落在指定显示器、套用贴靠、进入指定舞台组」的自动化规则，规则中心带实时日志。

**现状地基**：`compat.rs` 已有进程级登记库（L1-L4 分级 + hint）；`shell_watch.rs` 有进程/窗口事件看护（含 anticheat_watcher）；`embed.rs` tier 路由已有显式分臂。规则引擎是把这些「内置策略」外化为「用户可编程策略」。

**详细设计**：
- 规则 = `{ 触发器(进程名/标题正差/窗口类), 条件(显示器/时间/前台应用), 动作(嵌入策略覆盖/tier 覆盖/贴靠/入组/置顶/透明度), 优先级, 启用位 }`；
- 规则文件 `data/rules/*.vrule`（JSON，可导入导出分享）；冲突按优先级+specificity 裁决，裁决日志实时可见；
- 动作执行走既有 IPC 契约（贴靠走 snap.applySnap、嵌入走 embed 策略层），**不新增绕过安全审查的路径**——L4 让位规则不可被用户规则降级（安全分叉不可覆盖原则）；
- 内置规则模板库：IDE 常驻侧屏、聊天软件强制独立、全屏游戏自动免打扰等 12 条一键启用。

**为什么是它**：从「我适应环境」到「环境适应我」，是把已有 compat/embed/snap 三大资产粘合成一个用户可感产品的关键一步。

**依赖/风险**：依赖 `shell_watch.rs` 事件流稳定性；最大风险是规则误伤（如把安全软件规则化）——L4/管理员窗口动作白名单硬编码，规则引擎只能加严不能放宽。

**验收**：①规则触发延迟 < 500ms 且日志留痕；②导入他人规则→与本地规则合并正确；③L4 窗口任何规则下都走让位；④规则语法错误→行级报错不崩溃。

### N-04 任意窗口画中画（Universal PiP）

**一句话**：把任意 VWM 窗口/嵌入第三方窗口一键「抽出来」变成无边框悬浮小窗，置顶、可调透明度、可吸附屏幕角落、记住尺寸。

**现状地基**：`embed.rs` 已实现窗口重父级与 detach（L4 让位臂已有 `attached:false` 路径）；PiP 本质是「受控 detach + 悬浮样式 + 记忆」。

**详细设计**：
- 入口：窗口红绿灯菜单 + 「画中画」按钮 / `Ctrl+Alt+P`；
- 悬浮窗特性：4 档透明度（85/70/50/30%）、角落磁吸（8px 阈值）、双击标题区全屏往返、尺寸档位记忆（按进程记忆）；
- 视频类检测：窗口标题含播放态（复用 imwatch 的标题解析思路）时默认更小贴角；
- 行为边界：PiP 中的窗口仍受 embed 生命周期管辖——宿主关闭时 PiP 随之回收并如实通知；反作弊 L4 窗口禁用 PiP（避免输入注入误判）；
- 多 PiP 管理：任务栏托盘区聚合图标显示 PiP 数量，点开列表一键回收全部。

**为什么是它**：浏览器级体验泛化到一切窗口——看文档写代码、看直播聊天、网课做笔记，全都是高频刚需。

**依赖/风险**：依赖 `embed.rs` detach 稳定性；风险是某些应用 SetParent 抖动——失败路径必须「回原位 + 提示」，绝不卡中间态。

**验收**：①5 类样本应用（Electron/Win32/UWP/Java/游戏）PiP 往返无残留；②透明度/磁吸/尺寸记忆逐项过；③宿主退出→PiP 回收通知；④键盘可完成全部操作。

### N-05 工作区场景（Workspace Scenes）

**一句话**：把「壁纸 + 主题 + 字号 + 任务栏位置 + 打开的窗口组合 + 舞台组 + 免打扰状态」打包成一个具名场景，一键/定时/按前台应用自动切换。

**现状地基**：`envs.rs` 已有环境注册表（envs/registry.json）；设置侧已有 DRESS_PRESETS（theme+wallpaperMode+fontSize+taskbarPos 一键换装）；A-5 向导已验证「预设即状态集合」的产品形态。场景 = 换装预设 + 窗口编排 + 触发器的超集。

**详细设计**：
- 场景清单：`data/scenes/*.vscene`，字段含视觉包（复用换装字段）+ 编排包（N-01 快照引用 + N-02 组引用）+ 行为包（勿扰/声音/IME 默认）；
- 切换动画：场景切换时全屏一次 240ms 的「转场幕」（极光流动），杜绝生硬跳变；
- 触发器三型：手动（开始菜单/命令面板）、定时（时段场景：晨间写作/午后编码/夜间阅读）、上下文（前台进程匹配→建议切换，非强制，toast 询问）；
- 与系统壁障：切换前若有未保存聚焦窗口（标题含「未保存」特征），先弹确认再切换——绝不替用户关窗口。

**为什么是它**：把 Variable 从「好看的空间」升级为「懂节奏的环境」，是同类产品完全没有的「场景即工作流」范式。

**依赖/风险**：聚合依赖 N-01/N-02 落地；风险在状态合并冲突——视觉包切换失败时回滚整套场景并如实报错。

**验收**：①三触发型各自全链路通；②场景往返 100 次无状态漂移；③转场幕动效 60fps；④未保存窗口守卫生效。

### N-06 动效编排系统（Motion Orchestrator）

**一句话**：统一的动效编排内核——所有跨元素动效（窗口开合、面板交错、列表 stagger、图标归位）走同一调度器，自动 FLIP、自动错峰、自动遵循 reduce-motion 与性能预算。

**现状地基**：A-1 tokens.css 已有 --dur/--ease 体系；A-2 已有 vwm spring keyframes 与 reduce-motion 80ms 降级；visual-audit.cjs 已有 0.5% 基线 diff。缺的是**中央编排器**——目前各处动效各自为政。

**详细设计**：
- 内核 `src/lib/motion/`：`orchestrate(elements[], { stagger, flip, spring })` 单入口；批量动效自动按 30ms 错峰、自动合并到单 rAF 批次；
- FLIP 引擎：布局变化自动量测 First/Last、反演播放——图标网格重排、文件架折叠、任务栏溢出全部获得平滑归位；
- 性能预算：动效期间帧预算 8ms，超支自动降级为直接落位（静默，bench 可见）；
- 动效检视器：设置→开发者→「动效实验室」，可视化调节全域 spring 参数并实时预览、导出为个人动效档案 `.vmotion`；
- 契约：所有新功能动效**必须**走编排器（进入 lint 检查：禁止裸 CSS animation 用于编排场景）。

**为什么是它**：顶级作品的「手感」来自全域动效一致性——这是从「各处都还行」到「整体是艺术品」的临门一脚。

**依赖/风险**：横向侵入所有 UI 文件，必须渐进迁移（新功能强制、存量按域分批）；reduce-motion 与高对比度模式必须全程绿。

**验收**：①stagger/FLIP/spring 三模式在 60fps 下逐项过 bench；②reduce-motion 下全部动效 ≤80ms 或消失；③动效实验室导出档案重放一致；④visual-audit 基线 diff < 0.5%。

## 域 B：桌面表达与艺术（N-07…N-12，AI-5）

### N-07 壁纸工坊 2.0（Wallpaper Studio）

**一句话**：从「接入 Wallpaper Engine」进化为「自带创作工具」——视频壁纸、Shader 壁纸（WebGL）、网页壁纸、参数化生成壁纸四引擎 + 可视化参数调节器。

**现状地基**：`wallpaper.rs` 已有 WE 项目接入与壁纸状态管理；`background/` 前端已有原生 WebGL 星空/极光渲染器（证明自渲染管线已在手）。

**详细设计**：
- 四引擎：Video（mp4/webm 循环+静音+硬解）、Shader（fragment shader 单文件 + uniform 时间线）、Web（本地 html 沙箱 iframe，禁网）、Generative（星空/极光/流体的参数化预设，现有渲染器直接产品化）；
- 工坊 UI：左侧素材库/右侧实时预览，底部 uniform 滑杆（亮度/速度/色相/密度等 per-preset 声明）；
- 壁纸包格式 `.vwp`：zip 内含 manifest + 资源 + 参数声明，双击导入；与 WE 项目在壁纸选择器中平级共存；
- 性能纪律：打字时降级渲染（现有行为）扩展到全部引擎；全屏应用时 shader 引擎自动降帧至 10fps；电池模式（联动 N-20）暂停视频引擎；
- 电池/隐私红线：网页壁纸**仅允许本地文件**，manifest 里出现远程 URL 直接拒绝加载并说明原因。

**为什么是它**：审美驱动是 Variable 的立身之本，「能接入别家」到「自己就是创作平台」是质变。

**依赖/风险**：GPU 兼容——shader 编译失败必须降级为静态帧 + 诚实提示，绝不黑屏。

**验收**：①四引擎各自预览/应用/持久化；②`.vwp` 导入导出往返一致；③打字降级/全屏降帧/电池暂停三联动；④坏 shader 文件→优雅降级。

### N-08 主题工坊（Theme Studio）

**一句话**：可视化主题编辑器——在 A-1 OKLCH 语义 token 层之上拖滑杆改色即所见即所得，成品导出为 `.vtheme` 单文件，双击即装，可分享。

**现状地基**：A-1 已建立 `--bg-canvas/--text-*/--accent` 语义层 + 337 个裸色值存量清单；audit.cjs 已有裸色计数器。工坊是 token 层的直接红利变现。

**详细设计**：
- 编辑器三区：色板（每语义 token 一个 OKLCH 拾色器，自带对比度实时校验，WCAG AA 不达标红牌）、字体（字号/字重/行高档位）、形（圆角/阴影/密度档）；
- 实时预览：右侧渲染真实桌面缩样（任务栏+窗口+通知），所见即所得；
- 亮暗联动：一次编辑可存亮/暗/高对比三套变体，切换场景时自动取对应变体；
- 分享格式 `.vtheme`：JSON（含预览缩略图 base64），导入时版本校验+冲突字段报告；
- 主题市场打通 N-27：`.vtheme` 可上架（本质是市场里的一个品类）；
- 裸色迁移：工坊上线同步启动 337 裸色值→语义 token 的渐进迁移（每域一批，audit 计数只降不升作为硬门槛）。

**为什么是它**：让每个用户都能把环境调成自己的艺术品，且分享格式让审美成为社区的流通货币。

**依赖/风险**：依赖 A-1 token 完备度；风险是深色对比度陷阱——强制对比度校验是唯一防线。

**验收**：①编辑→导出→导入→重放一致；②AA 不达标色无法保存（除非显式豁免并标注）；③高对比度变体随系统信号正确切换；④audit 裸色计数在工坊批次后单调下降。

### N-09 桌面小组件系统（Widget Board + SDK）

**一句话**：环境内的小组件生态——时钟/天气/待办/监控/日历/快捷开关等以卡片形式常驻桌面或收纳进「组件板」（侧滑面板），并提供开放 SDK 让第三方/用户自制。

**现状地基**：托盘快捷面板（QuickPanel）已有音量混音/IME/通知骨架；工具中心（tools/）已有多种卡片式工具页；缺的是「可插拔、可布局、第三方可写」的组件容器。

**详细设计**：
- 容器两形态：**桌面常驻**（自由拖放、网格吸附、互不遮挡判定）与**组件板**（边缘侧滑，收纳不占桌面）；
- 内置首批 8 个：世界时钟、本日历、待办（联动写作空间）、性能迷你条（联动 N-19）、快捷启动列、倒计时专注、网络状态、随机灵感卡（从记录库随机抽一条）；
- Widget SDK：`widget-manifest.json`（尺寸档 1x1/2x1/2x2、权限声明、刷新策略）+ 一个 HTML 沙箱（复用 N-07 网页壁纸沙箱技术）；数据通道走白名单 IPC（如只读性能、只读写待办）；
- 生命周期：低电量/全屏时自动暂停刷新（联动 N-20/N-03）；失败 3 次自动收起并通知，绝不占着位置白屏；
- 动效：进出场走 N-06 编排器统一 stagger。

**为什么是它**：小组件是现代桌面信息表达的标准形态，开放 SDK 则把「环境」变成「平台」。

**依赖/风险**：沙箱逃逸是红线——SDK 权限模型沿用 X-2 扩展权限体系，无权限 IPC 直接拒绝；壁纸引擎与组件争 GPU——共享一个降级策略。

**验收**：①8 内置组件全功能；②第三方沙箱组件无网、无越权 IPC（渗透用例）；③全屏/低电自动暂停；④布局持久化跨重启。

### N-10 锁屏与仪式屏（Lock Screen）

**一句话**：环境自己的锁屏——`Win+L` 级全局热键进入，星空/极光全屏 + 大时钟 + 通知静默聚合，解锁回环境原样；也是「专注仪式」的入口。

**现状地基**：`privacy_shield.rs` 已有隐私遮蔽；`kbdhook.rs` 已有全局热键链；启动仪式动画（boot/）证明全屏渲染语言成熟。

**详细设计**：
- 锁屏层：全屏 WebGL 背景复用 N-07 引擎、时钟（可换字体档）、未读通知只显示来源与数量**不显示内容**（隐私红线）；
- 双重角色：**离开锁**（真锁，回来需解锁口令——口令仅本地哈希存储）与**仪式锁**（不设口令，纯专注遮挡，任意键退出）；
- 仪式模式扩展：锁屏上可显示「本轮专注 25:00」倒计时，到点响铃解锁（与 N-31 场景联动）；
- 边界诚实：这是**应用层锁屏**，不替代 Windows 锁屏（系统级安全仍属 OS）——设置页与 README 能力声明都如实标注；环境隐藏（双 Esc）时锁屏自动失效；
- 解锁动效：粒子汇聚→桌面交错淡入（复用启动仪式，动效走 N-06）。

**为什么是它**：把「隐私即默认」的哲学延伸到锁屏形态，同时给了创作者一个「开始工作」的仪式感入口。

**依赖/风险**：热键与系统 Win+L 的注册冲突——注册失败诚实降级为托盘菜单项；忘记口令→提供恢复码（OOBE 时生成，仅一次）。

**验收**：①锁/解 1000 次无泄漏无卡死；②通知零内容泄漏；③口令错误 5 次指数退避；④恢复码可重置口令；⑤双 Esc 环境下锁屏正确失效。

### N-11 实况场景组件（Living Scene Widgets）

**一句话**：超越「工具卡片」的实况组件——天气实况（晴/雨/雪在桌面上真实飘落，联动壁纸光照）、昼夜时钟（壁纸随真实日出日落渐变）、季节轮转（色板随季节偏移）。

**现状地基**：N-09 组件容器 + N-07 壁纸四引擎 + 星空背景已有时间驱动的渲染经验。

**详细设计**：
- 天气引擎：桌面级粒子层（雨/雪/落叶/晴时光斑），天气源为**用户自选**（默认无网——手动设置当日天气，或显式授权一次 HTTP 拉取公开气象 API，全程在 netconsent.rs 网络同意框架内留痕）；
- 昼夜引擎：按本机时区+经纬度（可选手填）计算日出日落，壁纸全局色温从晨蓝→正午白→暮金→夜靛四段渐变，与亮暗主题自动同步；
- 季节轮转：四套色相偏移曲线（春芽/夏碧/秋赭/冬霜）作用于语义 accent token，仅装饰不改可读性 token；
- 性能：粒子层独立于壁纸引擎、帧率联动全屏降级；无 GPU 时粒子层自动关闭只留色温渐变。

**为什么是它**：「环境有生命感」是艺术品的最高阶表达——桌面第一次拥有天气与昼夜。

**依赖/风险**：粒子 O 窗口层与点击穿透（WS_EX_TRANSPARENT + 点击穿透切换）；气象数据如不联网必须可用（默认手工模式）。

**验收**：①四种天气粒子 + 点击穿透正确；②昼夜色温四段渐变按本机时刻正确；③离线手工模式完整可用；④netconsent 框架内网络调用有同意记录可撤销。

### N-12 图标包系统（Icon Pack System）

**一句话**：`.vicon` 图标包格式——一包换尽桌面图标/开始菜单/文件类型图标，含四空间专属视觉语言变体（钢笔尖/节点星图/像素扫描线/金色星盘的换肤体系）。

**现状地基**：`launcher.rs` 已有 IShellItemImageFactory 原生图标提取；四空间图标已有独立视觉语言基线；desktop-icons 网格已成型。

**详细设计**：
- 包格式 `.vicon`：zip + manifest（图标键→资源映射，支持内联 SVG 与 PNG@1x/2x）；优先级：用户包 > 内置语言 > 系统原生提取；

- 预览：安装前显示 12宫格对比预览（原 vs 新）。

**为什么是它**：图标是桌面最强的身份符号，开放图标包是「把审美还给用户」的最后一块拼图，与主题/壁纸构成完整视觉生态三件套。

**依赖/风险**：图标缓存失效策略——换包后全量刷新要节流（分批渐进替换，避免一次卡顿）。

**验收**：①包安装/卸载/缺键回退逐项过；②四空间变体各自生效；③12宫格预览正确；④1000+ 图标场景换包全程无 UI 冻结（>100ms 帧数）。

### N-13 命令面板（Command Palette）

**一句话**：`Ctrl+K`（可改）呼出的全局命令中心——模糊搜索一切：启动应用、执行环境动作、改设置、切场景、直达任意功能页，带最近/频率学习排序。

**现状地基**：开始菜单已有搜索骨架（search.rs + fsindex.rs）；快捷键体系齐全；缺统一「命令」抽象层。

**详细设计**：
- 命令注册表：每功能声明 `id/title/icon/category/keywords/when(条件)/action`，全域统一注册（含第三方插件经 N-26 网关注入的命令）；
- 交互：浮层居中、模糊匹配高亮、方向键+回车、`>` 前缀切命令模式 / 无前缀搜应用 / `?` 搜设置——三类一框；
- 学习排序：本地频率+新近度加权（纯本地统计，无上传）；置顶钉选；
- 万物可执行示例：`贴靠左半屏`、`切换到夜间场景`、`把当前窗口画中画`、`导出本周记录`——每个 N-* 功能上线时**必须**同步注册其命令（写入施工纪律）；
- 链式：命令执行后面板可停留等待参数（如「贴靠」→ 选择目标窗口）。

**为什么是它**：命令面板是现代效率环境的神经中枢，也是把 40 个新功能「缝合」成一个整体的交互骨架——用户不需要记住任何入口在哪。

**依赖/风险**：全局热键占用冲突如实降级；命令表膨胀后搜索延迟须 < 50ms（本地倒排索引）。

**验收**：①内置命令 ≥ 120 条全部可执行；②模糊搜索 p95 < 50ms；③学习排序 3 天使用后命中率可感；④插件命令经权限过滤显示。

### N-14 统一搜索 2.0（Unified Search）

**一句话**：开始菜单搜索进化为全域搜索——应用 + 文件（Everything 级 NTFS USN 索引）+ 记录库全文 + 思维导图节点 + 设置项 + 命令，一框出结果，带内容预览。

**现状地基**：`search.rs`/`fsindex.rs` 已有文件索引雏形；记录库已有全文搜索；N-13 命令注册表可挂接。

**详细设计**：
- USN Journal 增量索引（后台低优先级线程，首次全量索引可暂停/限速，索引进度如实显示）；索引库存 `data/index/`（分片+压缩）；
- 结果五类聚合：应用/文件/内容/命令/设置，每类独立权重，类别 Tab 可锁；
- 内容预览：文件结果悬浮显示前 3 行文本/图片缩略/音频时长；记录结果显示所属文件夹路径；
- 快捷动作：结果行内按钮——文件「用默认程序打开/在文件管理器中定位/复制路径」；
- 高级语法：`ext:md size:>10m modified:week` 等过滤子句，帮助面板内建；
- 隐私：索引范围默认仅用户目录+盘根可选；可加排除目录黑名单；保险箱内容**永不入索引**。

**为什么是它**：搜索是使用频率最高的桌面行为，做到 Everything 级速度 + 环境内数据一框打尽，是效率护城河。

**依赖/风险**：USN 权限（需要管理员一次授权或降级为定时扫描——如实降级路径必须有）；索引体积上限与淘汰策略。

**验收**：①100 万文件盘搜索 p95 < 200ms；②五类聚合正确互斥可 Tab 过滤；③保险箱零泄漏（渗透用例）；④USN 不可用时降级模式如实标注且可用。

### N-15 剪贴板历史中心（Clipboard History）

**一句话**：`Ctrl+Shift+V` 呼出剪贴板历史——文本/富文本/图片/文件路径四种类型、全文检索、固定钉选、按应用来源分组、AES 本地加密落盘。

**现状地基**：全局热键链（kbdhook.rs）+ 通知中心数据管道 + privacy.rs 加密基设。

**详细设计**：
- 监听：Win32 剪贴板序列号轮询（去抖 300ms），类型识别 + 大小上限（图片 >16MB 拒存并提示）；
- 存储：`data/clipboard/` AES-GCM 加密分片（密钥沿用保险箱 KDF 派生），容量 500 条/200MB 上限 FIFO；
- UI：网格卡片（文本卡显前 2 行、图片卡缩略、文件卡显图标+路径），搜索框置顶，钉选区独立；
- 粘贴语义：回车直接写回剪贴板并粘贴到当前焦点窗口（SendInput 仅在此用户显式操作时发生）；多选可合并粘贴；
- 隐私开关：敏感应用（用户配置名单，如密码管理器窗口）期间暂停记录；一键清空 + 定时自动焚毁（联动 N-34）；**「关闭即焚」模式**——历史面板关闭即清空本次会话。

**为什么是它**：高频刚需 + 隐私敏感的双重属性，恰是 Variable「隐私即默认」哲学最能建立信任的场景。

**依赖/风险**：SendInput 焦点窗口判断准确性（焦点漂移时禁止粘贴并提示）；加密密钥丢失→历史诚实清空（宁失勿裸）。

**验收**：①四类型录制/检索/回贴正确；②敏感名单期间零记录（取证用例）；③加密分片离线解析不可读；④容量上限 FIFO 正确。

### N-16 截图标注与贴图（Snip & Pin）

**一句话**：环境级截图工具——区域/窗口/滚动截图、箭头/文字/马赛克标注、OCR 文字提取（可选用本地 NPU/离线引擎）、「贴图」模式把截图钉在桌面上当便签。

**现状地基**：`capture.rs` 已有窗口位图捕获（为缩略图/壁纸服务）；设计系统画布经验（Mindmap 无限画布）可复用于标注层。

**详细设计**：
- 截取：`Ctrl+Alt+S` 区域（十字+放大镜像素级取框）、当前窗口（联动 VWM 枚举）、延时 3s；
- 标注：矢量标注层（箭头/矩形/画笔/文字/序号步进/马赛克——马赛克是真破坏性像素处理并标注「不可逆」警示）；
- OCR：默认关闭；开启后用**本地引擎**（DirectWrite 光栅化 + 本地识别库，或系统 Windows.Media.Ocr 离线语言包），结果可编辑修正后复制——绝不调用云 OCR；
- 贴图（Pin）：截图以无边框小窗钉桌面，可缩放/半透明/置顶，双击进编辑，滚轮调大小——本质是 N-04 PiP 容器装一张图；
- 流向：完成图→复制/存文件/发到记录库（作为带日期的记录附件）/贴图，四选一。

**为什么是它**：截图是创作与研究工作流里被所有桌面忽视的「脏活」，把它做成艺术品级体验（像素级取框、贴图便签）体验提升立竿见影。

**依赖/风险**：滚动截图依赖窗口滚动协议——不可滚动的窗口如实禁用该项而非假装失败；OCR 无语言包时诚实提示安装指引。

**验收**：①三截取模式 + 六标注工具全链路；②OCR 离线识别中英文样张 ≥ 基线；③贴图窗与 PiP 行为一致；④马赛克不可逆警示 + 确认门。

### N-17 快捷键中心（Shortcuts Hub）

**一句话**：所有快捷键的统一司令部——全量列表分类可搜、一键改键、实时冲突检测、 printable 速查表、新手「按键学习模式」（按下任意键即高亮其功能）。

**现状地基**：kbdhook.rs 全局热键链 + README 二十三章快捷键手册（说明快捷键数量已庞大到需要管理）。

**详细设计**：
- 注册表化：所有热键（全局+环境内）统一声明 `{scope, key, title, when, rebindable}`，运行时从注册表驱动绑定——从「散落硬编码」收敛为「单一事实源」；
- 冲突检测：改键时实时标红与他方/系统/常见三方应用（内置常见占用表如 QQ/IDE）的冲突，提供解决建议；
- 学习模式：开关开启后，按下任何键，屏幕角落浮现「该键功能说明卡」——新人上手零成本；

- Profile：快捷键方案档（默认/单手/左手鼠标习惯）一键切换，`.vkeys` 可分享。

**为什么是它**：快捷键体系庞大之后，「可发现性」成为最大敌人；快捷键中心是存量能力的整理者也是新功能的放大器。

**依赖/风险**：改造涉及全局热键注册路径——必须先契约测试（commands_e2e.rs）再迁移，逐批替换。

**验收**：①全量热键均出自注册表（审计脚本验证无散落注册）；②改键+冲突检测+回滚链路；③学习模式卡片全键覆盖；④速查表导出内容与实际绑定零偏差。

### N-18 自动化宏引擎（Macro Engine）

**一句话**：可视化 + 脚本双形态的本地自动化——「录制回放」键鼠宏、触发器（热键/窗口事件/时间/剪贴板变化）驱动的动作序列，兼容导出为人类可读脚本。

**现状地基**：N-03 规则引擎的触发器框架 + N-15 的窗口焦点管理 + N-13 命令注册表（宏的动作库直接复用命令）。

**详细设计**：
- 动作库：环境命令（N-13 全量）+ 键鼠模拟（SendInput，带「仅前台窗口」护栏）+ 窗口管理（N-01/02/04 动作）+ 文件/剪贴板操作 + 提示通知；
- 触发器：热键 / 应用启动退出（shell_watch 事件）/ 时间（cron 子集）/ 剪贴板匹配正则 / 场景切换；
- 录制器：录制键鼠→自动参数化（坐标→窗口相对坐标）→可编辑步骤列表；回放失败即停并报告步骤号；
- 脚本视图：宏可切换为 YAML 脚本编辑（高级用户），双形态同源同步；
- 安全护栏：含「键鼠模拟」的宏在 UAC 提权窗口/密码框焦点时自动暂停（智能判停）；宏运行时屏幕角标提示（可关）；宏库 `.vmacro` 可分享，导入时高亮敏感动作需逐条确认。

**为什么是它**：AutoHotkey 的能力、IFTTT 的易用、Variable 的安全观——自动化是高级用户留存的终极武器。

**依赖/风险**：键鼠模拟的最大风险是失控——硬性护栏（全局急停热键 `Ctrl+Esc` 长按 1s 停一切宏）必须首日就有。

**验收**：①录制→参数化→回放 5 类样本宏成功；②五种触发器全链路；③密码框自动判停（渗透用例）；④急停热键 100% 生效；⑤导入宏敏感动作逐条确认门。

## 域 D：系统集成与硬件（N-19…N-25，AI-3 系统路）

### N-19 性能 HUD 悬浮窗（Perf HUD）

**一句话**：玩家级性能监视——可钉在桌面/贴边的 HUD 条，实时显示 CPU/GPU/内存/磁盘/网络上下行/FPS（前台应用帧率），带 60s 迷你曲线。

**现状地基**：`perf/` 前端已有性能页雏形；`hardware.rs` 已有硬件枚举与传感器读取；`taskman.rs` 有进程级 CPU/内存。

**详细设计**：
- 数据层：PDH 计数器（CPU/磁盘/网络）+ GPU 引擎计数器（如可用）+ 前台应用 FPS（DWM PresentMon 思路的轻量采样，不可用如实隐藏该项）；
- UI 三形态：贴边迷你条（16px 高）、悬浮卡片（N-09 组件形态）、全屏仪表（bench 同款可视化）；60s 滚动曲线用 canvas 自绘（复用 bench 绘图逻辑）；
- 告警线：用户设定阈值（如 CPU>90% 持续 30s）触发通知（走通知中心，遵守勿扰）；
- 开销自律：HUD 自身 CPU < 0.5%、采样周期自适应（可见 500ms / 隐藏 5s / 全屏游戏中暂停）；自身开销在 HUD 尾部诚实显示；
- 每进程下钻：点击卡片展开该数据 top5 进程（联动 taskman 数据）。

**为什么是它**：把「环境懂我的机器」具象化，是性能焦虑用户与开发者的日频工具。

**依赖/风险**：GPU 计数器与 FPS 采样在老机器不可用——全部走如实降级隐藏，绝不显示假数据。

**验收**：①六指标与任务管理器对照误差 < 5%；②自身开销达标；③三形态切换与全屏暂停；④不可用机器上对应项隐藏而非 0。

### N-20 电源与电池管家（Power Manager）

**一句话**：快捷面板级电源中枢——电源模式一键切（平衡/高性能/节能，经 powercfg）、电池健康报告（循环/容量损耗估算）、充电阈值管理（如机型支持）、低电自动化策略。

**现状地基**：`hardware.rs` 硬件查询、QuickPanel 已有面板位、sysmaint.rs 维护调度框架。

**详细设计**：
- 模式切换：powercfg /setactive 三档 + 自建「Variable 自定义档」（调整后台刷新策略：组件/壁纸引擎/索引降频——环境内部节流优先于系统档）；
- 电池健康：容量满充 vs 设计值、循环估算（充放事件计数）、月度趋势图；月报存本地；
- 充电阈值：ACPI/厂商接口探测（ThinkPad/Dell 等常见接口），不可用则如实显示「该机型不支持」；
- 低电策略：20% 提示→15% 自动切换省电场景（联动 N-05）+ 暂停 N-07 视频壁纸/N-09 组件刷新 + 通知中心汇总「已降级清单」；10% 自动保存全部记录库并安全休眠前提示；
- 台式机模式：无电池时面板自动转为「功耗估算」（基于硬件 TDP 名义值的粗估，明确标注为名义估算）。

**为什么是它**：移动创作人群的续航焦虑是真实痛点，且环境自己就是耗电大户——「自己先节流」体现产品责任感。

**依赖/风险**：powercfg 需要特定权限的场景如实降级；电池数据接口差异大——统一抽象层 + 厂商探测表，探测不到就隐藏。

**验收**：①三档切换实际生效（powercfg 查询验证）；②低电四连降级链路正确；③无电池机器自动转型；④月度健康报告生成与导出。

### N-21 网络指挥台（Network Command Center）

**一句话**：从「面板显示状态」升级为「指挥台」——Wi-Fi 管理/VPN 一键连/代理快切/测速/连接历史/用量统计（per-应用），全部在 netconsent 同意框架内。

**现状地基**：`network.rs` 已有网络状态管理；`netconsent.rs` 网络同意框架是全项目的网络纪律基座。

**详细设计**：
- Wi-Fi：扫描列表（信号强度/频段/加密）、已存配置管理、断线自动重连策略（可开关）；
- VPN：调用系统 rasdial 已配置的 VPN 连接（不自带 VPN 协议栈——诚实边界：管理而非提供），一键连断、状态徽标进托盘；
- 代理：系统代理读写 + 常用代理方案档快切（仅设置系统代理项，不做流量代理）；
- 测速：显式点击触发（绝不后台偷跑），本地节点 ping/下载/上传三段式，结果历史图；
- 用量统计：per-应用流量（基于 Win32 过滤平台或 ETW，如权限不可用则降级为总量统计并标注）；月度报表；
- 一切联网动作（测速/天气等）都经 netconsent 框架留痕，指挥台首页就是「本环境网络行为透明账本」——把隐私哲学做成看得见的面板。

**为什么是它**：网络是隐私最敏感的维度，Variable 用「透明账本 + 显式触发」把网络管理做成信任建设本身。

**依赖/风险**：per-应用用量需要管理员/驱动权限——不可用时降级总量并如实标注，绝不编造分应用数据。

**验收**：①Wi-Fi/VPN/代理三链路真机通过；②透明账本与实际调用日志逐条对账；③测速仅显式触发；④降级路径标注真实。

### N-22 存储健康仪表盘（Storage Health）

**一句话**：磁盘健康管理——SMART 数据读取与解读（温度/通电时间/重映射扇区/寿命百分比）、空间分析（目录树 treemap）、大文件雷达（一键找出 Top 体积文件/重复文件）。

**现状地基**：`hardware.rs` 已有磁盘枚举；`recycle.rs`/`sysmaint.rs` 有清理维护管道；文件管理器已有目录遍历。

**详细设计**：
- SMART：物理盘枚举（NVMe/SATA 分协议读取，含厂商专用 SMART 属性解码表常见型号覆盖，读不到的属性如实显示「不可读」）；
- 健康红绿灯：综合判分（温度/磨损/重映射三权重），异常时通知中心预警 + 建议（备份提醒联动 sysmaint 备份）；
- 空间分析：后台低 IO 扫描（可暂停），treemap 可视化 + 钻取；扫描缓存 24h；
- 大文件/重复文件雷达：Top100 大文件、重复文件（同名+同大小 → 可选内容哈希确认），删除走回收站（可撤）；
- 便携盘视角：检测到 U 盘/移动盘时单独出健康卡（联动 usb.rs）。

**为什么是它**：写作用户的全部资产就是数据，磁盘健康是「作品的保险」，与既有备份体系（sysmaint）首尾呼应。

**依赖/风险**：SMART 读取需要物理盘访问权限——失败降级为「基础信息+空间分析」并明确缺失原因。

**验收**：①SMART 三协议样机解读正确（对照 CrystalDiskInfo）；②treemap 钻取与删除回收链路；③重复文件哈希确认无误删路径；④无权限机器降级诚实。

### N-23 设备与外设中心（Device Center）

**一句话**：设备清单 + 即插即用事件流——USB/蓝牙/音频/显示/输入设备统一面板，插拔事件实时通知（「检测到新 U 盘：容量/卷标，点击打开」），每个设备一卡带驱动信息与快捷动作。

**现状地基**：`usb.rs` 已有 USB 设备管理；`hardware.rs`/`audioime.rs` 已有音频/IME 硬件触角。

**详细设计**：
- 设备分类卡：存储（联动 usb.rs 弹窗体系）/输入（键盘鼠标，含当前 DPI/轮询率可读则显示）/音频（输入输出设备切换快捷动作——联动 QuickPanel 混音器）/显示（分辨率/缩放/刷新率，快捷切档）/蓝牙；
- 事件流：WM_DEVICECHANGE 监听 → 通知中心结构化通知（含设备图标、动作按钮）；「设备日记」页保留 30 天插拔历史（本地）；
- 快捷动作：U盘→打开/弹出/检查（联动 N-22 便携盘视角）；耳机插入→询问是否切换音频输出（可设默认策略）；
- 异常检测：设备反复掉线（接触不良特征）→ 建议通知；
- 边界诚实：不做驱动安装/更新（链接到设备管理器），只做「看清 + 快捷动作 + 日记」。

**为什么是它**：插拔设备的瞬间是桌面存在感最强的时刻，抓住这些瞬间就是抓住「环境比 OS 更懂我」的体感。

**依赖/风险**：蓝牙栈差异（详见既有能力诚实声明）——不可用时如实显示状态。

**验收**：①五类设备卡数据真机核对；②插拔事件通知与日记逐条对账；③耳机切换策略三态（问/自动/不动）；④接触不良检测样机触发。

### N-24 预测性启动预热（Predictive Launch）

**一句话**：本地行为模型预测「你接下来要开什么」——在预测置信度高时做零感知预热（预取文件/预建缓存/预开最小化骨架），点开即秒启。

**现状地基**：`launcher.rs` 启动体系 + 本地统计（N-13 学习排序同款数据管道）+ `taskman.rs` 开机启动项管理。

**详细设计**：
- 模型（纯本地）：时间×星期×前台应用×场景（N-05）四维频次表，拉普拉斯平滑；置信度阈值可调（默认高置信才预热）；
- 预热分级：L1 预读文件页缓存 / L2 预建应用缓存目录 / L3 预启进程挂后台（仅白名单应用且用户允许，绝不自动弹窗）；
- 开机阶段应用：开机后按「当日同时段历史」预热前 3 个应用（可关闭，默认 L1 级）；
- 反馈环：预测命中/未命中统计进「洞察」（N-31），设置页透明展示模型行为；一键清空模型数据；
- 纪律红线：绝不预热非白名单进程、绝不模拟输入、绝不联网。

**为什么是它**：「快」是体验的母语，而预测性快是顶级作品与普通作品的分水岭；纯本地模型守住隐私哲学。

**依赖/风险**：误预热的资源浪费——预热动作必须有 5 分钟未使用自动回收；模型冷启动期（前 3 天）只学习不动作。

**验收**：①白名单应用预热后启动时间对比缩短 ≥ 30%；②未命中回收 100% 生效；③模型数据清空即彻底（取证目录扫描）；④冷启动期零预热。

### N-25 健康自愈中心（Self-Healing Center）

**一句话**：环境自己的「医院」——开机自检树（30 项健康检查：索引完整性/数据库事务/配置版本/热键注册率/容器签名/磁盘水位）、故障自动分级、一键修复、安全模式启动（最小环境）。

**现状地基**：`sysmaint.rs` 已有健康检查与自更新回滚；`recovery.rs` 已有恢复文件；`diagnostic.rs` 已有诊断骨架；selfcheck/ 文档已有自检文化。

**详细设计**：
- 自检树：启动时后台跑 30 项检查（每项 {名称/状态/证据/修复器}），异常分级：INFO（记录）/ WARN（通知）/ FAIL（阻塞启动进安全模式）；
- 一键修复：每项异常绑定修复器（重建索引/回滚配置/清事务残留/重导登记库），修复动作全部留痕可回滚；「修复历史」页可查；
- 安全模式：FAIL 级故障时以最小环境启动（无第三方嵌入、无壁纸引擎、无组件、默认主题）——保证「总能进得去、总能修得了」；
- 环境体检报告：每月自动生成体检报告（含 N-22 磁盘/N-19 性能/N-31 洞察数据交叉），存记录库可导出；
- 与 `--repair` CLI 联动：GUI 起不来时的无头修复路径（扩展既有应急包体系）。

**为什么是它**：接管桌面环境的产品，稳定性就是生命线；「自愈」是让用户敢于把它当主力环境的底气。

**依赖/风险**：自检自身不能成为故障源——自检超时 3s 即跳过该项并标记 UNKNOWN，绝不阻塞。

**验收**：①30 项检查注入故障逐项检出且修复有效；②FAIL 注入→安全模式启动→修复→正常重启全链路；③体检报告月度生成；④自检超时跳过机制验证。

## 域 E：开放生态（N-26…N-30，AI-4 智能路）

### N-26 插件运行时 2.0（Plugin Runtime 2.0）

**一句话**：把扩展体系升级为完整插件平台——manifest 声明式权限（沿用 X-2 权限模型）、JS 沙箱运行时、生命周期管理（安装/更新/禁用/卸载零残留）、能力面覆盖 UI（面板/组件/命令）与数据（白名单 IPC）。

**现状地基**：`extensions.rs`（35KB）+ `ext_plugin.rs` 已有扩展骨架与权限面；X-1…X-6 批次已完成扩展生态基座。

**详细设计**：
- Manifest v2：`{ id, version, engine_ver, permissions[], entrypoints{ panel?, widget?, command?, hook? }, sandbox{ net?, fs? } }`；权限与入口一一对应（无 widget 入口则不给组件 API）；
- 运行时：每插件独立 JS 沙箱（无 DOM 直访、IPC 走带权限校验的桥），崩溃自动隔离（坏插件只死自己），CPU/内存配额可配超限熔断；
- 能力面：注册命令（进 N-13）、注册面板页、注册小组件（进 N-09）、订阅事件（窗口/剪贴板/场景——按权限）、读写白名单数据目录；
- 生命周期：安装→权限审查页（逐项说明为什么需要）；更新→版本 diff 权限变化重新确认；卸载→`residue-check` 级零残留验证；
- 调试器：开发者模式 + 插件调试面板（日志/reload/权限模拟），「开发者工具包」文档 + 脚手架模板仓库。

**为什么是它**：开放性是「比肩顶级作品」的必答题，插件平台把 Variable 从产品升维成生态。

**依赖/风险**：沙箱逃逸是存在级风险——权限模型安全评审 + 渗透用例（越权 IPC/原型污染/资源耗尽）是批次门禁。

**验收**：①样例插件四入口全通；②越权调用 100% 拒绝（渗透用例集）；③插件崩溃宿主无恙；④卸载后 residue-check 全绿。

### N-27 插件市场（Marketplace & Registry）

**一句话**：本地优先的插件/主题/壁纸/图标包/宏五品合一的市场——默认「本地目录模式」（U 盘/文件夹即市场，离线可用），可选开启远程 registry 源（自建或社区镜像，经 netconsent 显式同意）。

**现状地基**：`ecosystem.rs` 已有生态骨架；X-6 分发批次已有市场基座；`.vtheme/.vwp/.vicon/.vmacro` 等格式在各域定义。

**详细设计**：
- 五品合一：插件(N-26)/主题(N-08)/壁纸包(N-07)/图标包(N-12)/宏(N-18) 统一上架格式（都是 zip+manifest 家族）；
- 本地模式：指定目录/U 盘即源，扫描→列表→安装，完全离线（这是**默认**形态，对齐便携哲学）；
- 远程模式（可选）：用户手动添加 registry URL（默认不内置任何源），HTTPS+签名清单校验，每次访问 netconsent 留痕；
- 安全：包签名（ed25519，本地信任链），安装页显示权限 diff + 签名状态；无签名→醒目警示可拒绝；
- 更新治理：版本对比、变更日志展示、一键全量更新/回滚；
- 创作者侧：上架向导（从本地已安装导出为包）+ `variable-cli` 打包命令（N-29）。

**为什么是它**：没有市场的生态是孤岛；「本地目录即市场」的设计让开放性与离线哲学同真——这是对「市场=联网」惯性思维的超越。

**依赖/风险**：供应链风险——签名校验失败必须硬拒绝；远程源的 UI 一切默认显式。

**验收**：①五品类本地源安装/卸载全链路；②签名篡改包 100% 拒绝；③netconsent 账本对账；④远程模式关闭后零网络行为（抓包用例）。

### N-28 开放 IPC API 网关（Open API Gateway）

**一句话**：把环境能力通过本地 API 开放给外部——localhost REST + WebSocket 双通道，token 鉴权 + 细粒度 scope，外部脚本/AHK/浏览器扩展/手机都能控制 Variable。

**现状地基**：`aihub.invoke` 已有内部 API 面（X-3）；IPC 契约测试（commands_e2e.rs）保证行为可验证。

**详细设计**：
- 通道：`127.0.0.1` 仅本机监听（默认关闭，显式开启）；REST（查询/动作）+ WS（事件订阅：窗口/通知/场景/设备事件流）；
- 鉴权：启动时生成 token，外部应用首次连接弹授权页（类似 OAuth 本地版），scope 到命令级（如只读窗口枚举 vs 可执行贴靠）；
- API 面（对齐命令注册表）：窗口（枚举/贴靠/PiP/舞台）、场景（切换/查询）、搜索（N-14 查询）、通知（读勿扰状态/发本地通知）、命令面板（代执行已授权命令）；
- 速率限制与审计：每连接 QPS 上限，全部调用进透明账本（与 N-21 同一账本页）；
- SDK：TypeScript 与 Python 官方客户端（薄封装，含类型定义），文档站点随包提供。

**为什么是它**：开放性的终极形态——让 Variable 成为可编程的环境底座，外部任何工具链都能接入。

**依赖/风险**：本机端口暴露的安全面——默认关闭 + token + scope + 审计四重防线；绑定仅 127.0.0.1 硬编码禁止改 0.0.0.0。

**验收**：①REST/WS 全 API 契约测试；②无 token/scope 越权 100% 拒绝；③QPS 限流生效；④默认关闭态零监听（端口扫描用例）。

### N-29 variable-cli（命令行控制台）

**一句话**：官方 CLI——`variable` 命令控制一切：窗口/场景/搜索/通知/插件/体检/打包上架，可脚本化、可进 CI，与应急包 CLI 体系统一。

**现状地基**：已有 `--export-rescue/--repair/--force-raster/--revoke-list` 应急 CLI 骨架（src-tauri main 入口）——扩展为完整命令族。

**详细设计**：
- 命令族：`variable win <ls|snap|pip|stage>`、`variable scene <ls|switch>`、`variable search <q>`、`variable notify <send>`、`variable plugin <ls|install|pack>`、`variable doctor`（N-25 无头化）、`variable macro <run>`、`variable api <token-gen>`；
- 通信：优先连接运行中环境（经 N-28 网关 token）；环境未运行时只支持离线子命令（doctor/pack/api）；
- 输出：人类可读表格与 `--json` 机器格式双模式（CI 友好）；退出码规范（0 成功/1 失败/2 环境未运行）；
- 脚本示例库：PowerShell/bash 各 10 例（启动工作流、每日报告、自动贴靠）；
- 与既有应急 CLI 的关系：旧旗标保留兼容，帮助页统一「应急 | 控制 | 生态」三段式。

**为什么是它**：CLI 是极客尊严与自动化底座，也是 N-28 网关的最佳示范消费者（吃自己的狗粮）。

**依赖/风险**：依赖 N-28 落地顺序（在线命令族）；Windows Terminal 下 ANSI 输出兼容。

**验收**：①全命令族离线/在线双态测试；②`--json` 输出 schema 契约测试；③退出码规范逐条；④示例脚本全部可跑。

### N-30 浏览器伴侣扩展（Browser Companion）

**一句话**：Chrome/Edge 扩展 + 环境内接收端——「发送到 Variable」：网页剪藏进记录库、链接投送到环境通知、下载接管（文件直落环境文件管理器下载架）、与浏览器面板（browsers.rs）双向联动。

**现状地基**：`browsers.rs`（21KB）已有浏览器集成面；记录库富文本可直接接收 HTML 剪藏。

**详细设计**：
- 通道：扩展 ↔ 本机 Variable 经 N-28 本地网关（浏览器扩展原生允许访问 127.0.0.1），token 一次授权；
- 剪藏：右键「存入 Variable」→ 干净化 HTML → 记录库指定文件夹（可带标签/注释），保留来源 URL 与时间；
- 投送：链接/文本一键投环境通知（在桌面上弹通知卡片，点击在系统默认浏览器打开）；
- 下载接管：可选「Variable 下载目录接管」——浏览器下载完成通知环境，文件管理器自动刷新+高亮新文件；
- 隐私：扩展仅声明 127.0.0.1 权限 + 当前标签页读取（显式操作时）；环境侧账本记录扩展全部调用；随时一键断开。

**为什么是它**：浏览器是桌面一半的生活，「环境 ↔ 浏览器」的桥接补全了工作流闭环，且全程走本机环回，零云中转。

**依赖/风险**：浏览器扩展商店审核（可先以开发者模式 sideload 分发）；跨浏览器 manifest v3 兼容。

**验收**：①剪藏往返（URL/内容/时间）一致；②投送与点击打开链路；③下载接管可开关；④断开后账本零新条目（对账用例）。

## 域 F：智能与数据（N-31…N-34）

### N-31 本地使用洞察（Local Insights）（AI-1）

**一句话**：全本地的行为仪表盘——时间都花在哪（应用/空间/场景维度）、通知打扰报告、窗口切换频率、搜索未命中词，一切统计只在本机，可一键焚毁。

**现状地基**：shell_watch 取证日志 + N-13 学习排序的频次数据 + N-24 预测模型数据——三股数据流的自然汇聚点。

**详细设计**：
- 采集：前台应用时长、窗口切换次数、通知接收/处理时长、场景驻留、搜索查询（含未命中）——事件全落本地 `data/insights/`（同样 zstd+按天分片，90 天滚动）；
- 仪表盘四页：今日/本周时间流（应用分色河流图）、专注报告（最长连续时段/打断源 top）、通知报告（来源频次/勿打扰掉的条数）、搜索报告（命中率/未命中词排行）；
- 行动建议（规则非 AI）：「你每天 14:00 被 IM 打断 12 次，建议开午后场景勿扰」——建议卡片一键执行；
- 焚毁：洞察数据独立密钥，一键焚毁不可恢复（复用既有焚毁体系），且「无痕会话」开关（开启期间零记录）。

**为什么是它**：「了解自己如何工作」与隐私并不冲突——Variable 用纯本地证明这一点，这是同类云端时间统计工具做不到的承诺。

**依赖/风险**：数据采集自身开销（<1% CPU）与磁盘上限；无痕会话必须彻底（取证扫描验证）。

**验收**：①四页数据与原始事件逐项对账；②建议规则触发正确；③焚毁后取证扫描零残留；④无痕会话期间事件文件零增长。

### N-32 智能通知整理（Smart Notifications）（AI-4）

**一句话**：通知中心的大脑——本地规则学习各来源的「处理习惯」（立即看/划掉/勿扰时静默），自动分堆（即时/摘要/静默），摘要堆定点批量呈现。

**现状地基**：通知中心 + imwatch 标题解析 + N-31 事件管道。

**详细设计**：
- 学习信号（纯本地频次统计）：来源×时段×用户动作（点开/划掉/静默）三元表，7 天数据起步；
- 三堆策略：即时堆（学习到高互动来源，正常弹出）、摘要堆（低互动来源，收进定点摘要——用户选时段如 12:00/18:00 两次批量）、静默堆（用户反复划掉不点开的来源，建议静默并一键采纳）；
- 场景联动：场景（N-05）可带通知策略覆盖（写作场景=仅即时堆白名单）；
- 透明性：通知设置页显示每来源的学习结论与依据（「你 14 天内划掉了 32 条 XX 通知、点开 0 条」），用户可随时覆盖——**建议权在机器，决定权在用户**；
- 摘要呈现：定点时刻汇总卡片「过去 3 小时 12 条通知：A×5 B×4…」，可展开逐条。

**为什么是它**：通知过载是现代桌面第一公敌；本地学习+完全透明+可推翻，是用 Variable 哲学解最普遍的痛。

**依赖/风险**：冷启动体验（前 7 天无学习）——默认全即时堆，学习启动后才渐次分层。

**验收**：①学习结论与原始行为对账；②三堆路由逐条正确；③用户覆盖优先于学习；④摘要定点触发与展开链路。

### N-33 情绪引擎（Mood Engine）（AI-4）

**一句话**：视觉环境随「语境」自动呼吸——按时段/场景/前台应用/天气（如启用 N-11）微调壁纸亮度、主题色温、动效速度，形成「早晨清醒、深夜沉静」的环境节律。

**现状地基**：N-07 壁纸引擎 uniform 参数 + N-08 主题变体 + N-05 场景 + N-11 昼夜引擎——情绪引擎是它们的「自动驾驶员」。

**详细设计**：
- 情绪向量：`{ 唤醒度(-1..1), 专注度(0..1) }` 二维；输入信号：时段曲线（内置昼夜节律先验）+ 场景标签 + 前台应用类别（游戏=高唤醒/写作=高专注）+ 天气（如授权）；
- 映射表（用户可编辑）：情绪→{ 壁纸亮度/饱和度偏移、accent 色温、动效速度系数(0.8-1.2)、通知声音音调 }；所有偏移都是**温和的**（±15% 内），绝不突变；
- 过渡：任何情绪切换 120s 缓动，全程无感；高对比度/无障碍模式下色温维度自动禁用（可读性优先）；
- 用户控制：情绪引擎默认**开启但保守**；一键暂停回到手动模式；「此刻感受」滑杆可手动校正（也作为学习信号）。

**为什么是它**：环境不再是静态布景而是有节律的生命体——这是「艺术品」与「工具」的分野。

**依赖/风险**：依赖域 B 引擎先行；风险是过度自动引发反感——保守默认+显式暂停+一切可逆是三条底线。

**验收**：①四输入信号各自驱动情绪向量正确；②映射偏移全部在 ±15% 包络内；③120s 过渡无跳变；④高对比度模式色温禁用。

### N-34 数据足迹焚毁 2.0（Footprint Shredder 2.0）（AI-1）

**一句话**：既有焚毁体系的升级——全盘敏感数据雷达（扫描环境数据+可选系统位置：临时目录/回收站/最近文档/缩略图缓存），分级呈现「你留下了什么」，分级焚毁（快速/安全/军用级覆写）。

**现状地基**：privacy.rs/焚毁体系 + fsindex 索引能力 + N-31 数据分片格式（全部已知位置）。

**详细设计**：
- 雷达类别：环境内（记录库已删残留/快照/洞察/剪贴板/锁屏日志）、系统侧（可选扫描：Temp/Recent/缩略图缓存/CRASHDUMP/剪贴板历史系统侧）；每类别显示条目数+体积+最后修改；
- 敏感模式匹配：用户可配正则/关键词（如身份证模式、项目代号），命中项单独成类——**模式库本地存储绝不外传**；
- 焚毁三档：快速（删+清回收站）、安全（单次随机覆写）、军用（3 覆写+改名，仅 HDD 推荐，SSD 显示 TRIM 说明）；环境内分片（zstd 加密）焚毁直接销毁密钥（更快且等价不可恢复）；
- 计划焚毁：复用 sysmaint 调度——「每周日 24:00 自动焚毁 X 类」；
- 预演模式：先跑「会发生什么」报告，确认后执行；全程留焚毁日志（只记类别与数量，不记内容）。

**为什么是它**：「隐私即默认」需要可验证的交付物——焚毁 2.0 就是把承诺变成看得见的报表。

**依赖/风险**：系统侧扫描只读环境外的明确范围（绝不越界扫描全盘私人文件——范围白名单硬编码）；SSD 覆写语义如实说明。

**验收**：①环境内各类别焚毁后取证扫描零残留；②三档焚毁效果验证（HDD 样盘恢复工具对照）；③预演报告与实际执行一致；④计划焚毁按调度触发。

## 域 G：环境可靠性（N-35…N-36，AI-1 容器路）

### N-35 多环境分身（Multi-Instance Sandbox）

**一句话**：一台机器多套 Variable 并行分身——「工作/生活/实验」三环境各自独立的数据目录、主题、插件、登记库，托盘一键切换或并行运行互不串扰。

**现状地基**：`envs.rs` 环境注册表 + `isolation.rs` 隔离体系 + `single_instance.rs` 单实例锁（需升级为「命名实例锁」）+ 容器语义（B-14）。

**详细设计**：
- 实例模型：每实例独立 data 根目录 + 命名互斥锁（`Variable-<name>`）+ 独立 IPC 命名空间；实例清单 `instances.json`（含名称/图标/数据路径/最后启动时间）；
- 启动器：启动参数 `--instance <name>`；首次进入「分身管理器」创建/克隆（从现有环境克隆数据目录）/删除（走焚毁链路）；
- 并行规则：至多一个实例处于「接管桌面」态，其余实例以普通窗口模式运行（不接管 shell）——多分身可同时开但只有一个当桌面，这是硬边界；
- 切换：托盘菜单实例切换 = 当前实例优雅退出（休眠所有窗口状态进 N-01 快照）→ 目标实例接管；
- 隔离验证：实例间 IPC/剪贴板历史/洞察/索引完全隔离（跨实例零读）；可选「共享壁纸库」白名单。

**为什么是它**：把「子环境」能力（容器路资产）外化为用户可感的多身份工作流——工作与生活互不污染。

**依赖/风险**：single_instance 改造是根级改动；接管态互斥必须绝对可靠（两个实例都接管=灾难）——互斥走全局命名互斥量+心跳双保险。

**验收**：①三分身并行运行 24h 无串扰（IPC/数据/热键各自独立）；②接管态互斥压力测试（并发抢启动）；③克隆分身数据完整；④删除分身焚毁彻底。

### N-36 跨设备接力（Session Relay）

**一句话**：局域网内两台装了 Variable 的设备之间「会话接力」——把当前场景（打开的窗口编排/正在编辑的记录/剪贴板）打包加密传到另一台并原样展开，全程局域网直连，零云。

**现状地基**：N-01 快照 + N-05 场景 + 记录库导出体系 + N-28 网关（本机通信的延展）；netconsent 框架管辖网络行为。

**现状地基补充**：无任何依赖云的先例——接力必须延续这一点。

**详细设计**：
- 发现：局域网 mDNS/UDP 广播发现同版本 Variable 设备，列表显式展示（设备名+IP）；**默认关闭**，两端都开启才可见；
- 传输：设备配对（扫码/短码）→ 端到端加密（配对密钥，AES-GCM）→ 点对点 TCP 直连；接力包含：场景定义+窗口编排快照（可执行版）+指定记录条目+剪贴板快照（可选）；
- 展开语义：目标设备按自身显示器/已装应用「尽力展开」——窗口编排里本机没有的应用如实列出「未安装清单」，记录条目合入目标库（冲突走既有导入合并策略）；
- 审计：每次接力两端各自留账（时间/对端/内容类别/大小）；netconsent 账本统一可见；
- 边界诚实：接力的是「工作现场」不是「运行中的程序」——文档明确表述，不制造假期待。

**为什么是它**：多设备创作者的真实高频（书房→客厅、台式→笔记本），而局域网直连+端到端加密让这个能力不必以隐私为代价。

**依赖/风险**：局域网防火墙提示；传输中断恢复（断点续传）；配对密钥的备份与吊销。

**验收**：①双机配对→接力→尽力展开全链路；②未安装应用清单诚实；③中断续传；④两端账本对账一致；⑤功能关闭态零广播零监听。

## 域 H：四大空间进化（N-37…N-40，AI-7 空间路·新）

### N-37 写作空间 2.0：双链与图谱（Library Graph）

**一句话**：写作空间获得 Zettelkasten 灵魂——记录间 `[[双链]]` 引用、反向链接面板、全库关系图谱（力导向可视化，复用 Mindmap 渲染经验）、未引用孤岛报告。

**现状地基**：记录库（层级文件夹+标签+全文搜索+富文本）+ Mindmap 画布渲染能力 + TipTap 可扩展 Mark 体系（自定义引用 Mark 已有先例）。

**详细设计**：
- 双链语法：TipTap 自定义 Mark `[[标题]]`，输入时模糊联想现有记录标题；断链（目标被删/改名）显式标红+「重建/改指」操作；
- 反链面板：阅读记录时右栏显示「谁引用了我」（含上下文摘录）；
- 图谱页：全库力导向图（节点=记录，边=引用，大小=连接度，颜色=文件夹），拖拽/缩放/点选直达；性能上限说明（万级节点 LOD 降级）；
- 图谱洞察：孤岛节点列表（零反链）、枢纽 Top（被引最多）、循环引用检测；
- 与 Mindmap 互通：任一记录「转为导图」生成以它为中心的引用图导图（节点绑定既有能力）。

**为什么是它**：写作空间从「文件夹+标签」的平面时代进入「网络化思维」的立体时代，与导图空间天生互补。

**依赖/风险**：链接解析在标题重命名时的批量更新（事务化，可撤销）；图谱性能（canvas LOD + 边聚合）。

**验收**：①双链创建/联想/断链修复链路；②反链与图谱数据一致性（图谱边数=链接数）；③万节点图谱 panning ≥ 30fps；④重命名批量更新+撤销正确。

### N-38 思维导图 2.0：推演与时间轴（Mindmap Reasoning）

**一句话**：导图从「整理」进化到「推演」——节点加权与概率分支（决策树模式）、时间轴视图（节点排布到时间线做计划）、子图直接推入 FTPE 命运引擎验证走向。

**现状地基**：Mindmap 无限画布 + 节点绑定记录 + FTPE 行为树引擎 + 特质权重体系。

**详细设计**：
- 决策树模式：节点可赋权重/概率/成本三属性，分支自动算期望值与最优路径高亮——用于「选项难抉」场景（换城市/选方案）；
- 时间轴视图：同一张图一键切换到横向时间轴（节点=里程碑），支持拖拽改期、今日线、冲突重叠检测（同一时段两个节点提醒）；
- 节点生命周期态：想法→计划→进行→完成四态着色，完成率汇总角标；
- 与 FTPE 互通：选中子图「推演」→ 导出为 FTPE 行为树草稿（节点→事件，权重→特质影响），在命运引擎里跑沙盘后把结论贴回导图节点（附件形态）；
- 与记录库互通增强：节点可直接挂待办（联动 N-09 待办组件）。

**为什么是它**：三个空间（导图/写作/命运）第一次形成闭环工作流——灵感→整理→推演→结论回流，这是任何单体工具给不了的体验。

**依赖/风险**：导出 FTPE 的语义映射损失要诚实标注（草稿形态）；时间轴与画布双视图的状态同步。

**验收**：①决策树期望值计算与高亮正确（对照手工算例）；②双视图同步；③FTPE 推演往返闭环；④重叠检测提醒触发。

### N-39 项目分析 2.0：健康度与风险雷达（PVCCE Health）

**一句话**：PVCCE 从「读懂代码」进化到「诊断项目」——架构腐化度报告（模块耦合热图）、依赖风险雷达（过期/已知漏洞/许可证冲突）、变更活性分析（git 数据驱动的热点文件识别）。

**现状地基**：PVCCE 七级下钻+词典规则引擎 + `git_panel.rs`（git 数据已接）+ `code.rs` 代码分析面。

**详细设计**：
- 耦合热图：import/引用关系构建模块依赖图，计算扇入扇出/循环依赖/上帝模块（扇出 Top 者标红），热图可视化+下钻到具体引用行；
- 依赖雷达：解析 Cargo.toml/package.json 等依赖清单，本地规则库比对（版本年龄/弃用标记；漏洞库为**可选离线包**——用户导入 OSV 导出数据，绝不在后台联网查询）；
- 变更活性：git log 驱动——热点文件（高频改动=脆弱区）、知识地图（谁改过什么，多作者仓库）、孤儿代码（长期零改动且零引用）；
- 健康度报告：五维（耦合/测试覆盖线索/依赖/活性/文档率）雷达图 + 大白话结论（词典引擎风格：「这个模块像个交通枢纽，什么都要经过它，改它风险很高」）；
- 报告导出：存记录库/导出 HTML 报告（可分享）。

**为什么是它**：PVCCE 的「大白话」基因从「解释代码」延展到「诊断项目」，对老项目维护者是刚需中的刚需。

**依赖/风险**：大型仓库（万文件）分析的性能（增量分析+缓存）；漏洞库离线包的更新节奏如实说明。

**验收**：①耦合指标与手工样例核对；②循环依赖/上帝模块检出；③git 热点分析对照 git log；④健康报告五维生成+大白话结论；⑤万文件仓库增量分析 < 3 分钟。

### N-40 命运推演 2.0：剧本工坊（FTPE Scriptorium）

**一句话**：FTPE 从「推演引擎」进化到「叙事工坊」——推演结果一键生成时间线小说/人物志/年表报告（模板化叙事生成，仍零 AI 依赖），多线并行推演对比（同起点多策略赛马），命运存档与回放。

**现状地基**：FTPE 行为树+特质权重+确定性种子+可重现体系（叙事生成的世界观素材库已具雏形）。

**详细设计**：
- 剧本生成：推演轨迹 → 叙事模板引擎（事件序列套用文体模板：编年体/第一人称回忆录/人物传记/大事年表四模板），词典+规则生成（延续零 AI 纪律），产出直接存写作空间为富文本记录；
- 多线赛马：同一初始状态 N 份种子并行推演（如 10 条命运线），对比视图（关键分叉点对齐展示，差异高亮），选定主线后其余存为「放弃的可能性」存档；
- 命运存档：每次推演完整可打包（初始状态+种子+版本号），`.vfate` 可分享——他人打开**逐比特重放**（可重现性的极致应用）；
- 回放器：时间轴拖动回看任意时刻世界状态，关键事件打书签；
- 与导图联动：推演结论回流 N-38（闭环的另一端）。

**为什么是它**：把「思想实验沙盒」变成创作者真正的生产力工具——设定党写小说、复盘党做决策，都能从这里拿到成品。

**依赖/风险**：叙事模板的表达力上限（诚实标注为「模板生成」而非 AI 创作）；多线推演的算力（后台队列+可取消）。

**验收**：①四模板生成物人工评审达可读基线；②`.vfate` 跨机逐比特重放一致；③10 线赛马对比视图正确；④回放器任意时刻状态一致。

## 附：四条红线（全 40 项共同遵守）

1. **隐私红线**：一切新数据落本机；一切网络行为经 netconsent 显式同意且可永久关闭；默认零联网。
2. **诚实红线**：不可用的能力如实降级/隐藏，绝不显示假数据、绝不假装成功（USN/SMART/GPU/FPS/充电阈值全部如此）。
3. **安全红线**：L4 让位、UAC/密码框判停、沙箱越权拒绝、签名校验失败硬拒绝——安全分叉不可被用户规则/插件/宏放宽。
4. **性能红线**：后台能力（索引/采集/预热/自检）自身开销有硬预算，超预算自动降级；bench 归档无 >10% 回归才可收口。
