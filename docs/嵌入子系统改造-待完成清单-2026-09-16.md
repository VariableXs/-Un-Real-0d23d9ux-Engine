# 嵌入子系统改造 · 待完成清单

日期：2026-09-16
说明：本文件只记录「需要完成什么」。背景分析见《Variable嵌入子系统全面诊断报告-2026-09-15.md》。

## 已确认的目标

> 第三方软件用自己的原生外观：自己的标题栏、自己的最小化 / 最大化 / 关闭按钮、自己的可拖动边框。
> Variable 不画任何窗口框（无标题栏、无红绿灯、无缩放把手、无圆角边框、无占位提示框）。
> 使用软件时不暴露任何 Windows 痕迹；Variable 任务栏实时镜像正在运行的软件。

## M1 · 让软件保留自己的原生外观（核心改动）

- [x] 改嵌入方式：不再把软件切成 Variable 的子窗口，改为让桌面「拥有」它（`GWLP_HWNDPARENT`），软件仍是完整原生窗口
- [x] 完全不修改软件自身的任何窗口样式：保留它自己的标题栏、最小化、最大化、关闭、可拖动边框
- [x] 删除旧的「剥掉软件边框」逻辑及其全部调用点（`restyle_and_reparent` 删除；WS_CHILD + SetParent 的 L2 容器包裹引擎随之下线）
- [x] 补上拥有式嵌入必须同步维护的配套改动（缺一件都不算完成）
  - 边界换算：`embed_bounds` 把「桌面客户区坐标 ×DPR」换算成屏幕坐标（顶层窗只认屏幕坐标）
  - 重复收编闸门：新增 `is_already_embedded`，Steam 收编看护 / embed_launch 兜底两档候选全部过滤（拥有式嵌入下已收编窗口仍在 EnumWindows 里）
  - 任务栏隔离：拥有期间摘掉 `WS_EX_APPWINDOW`（该位会强行给任务栏按钮），解链时按原值还原
  - 退出清扫：新建 `OWNED_HWNDS` 归属总账 + `release_all_owned`，挂在 `RunEvent::Exit`（退出流程第一步 `embedCloseAll` 会把注册表 drain 空，照注册表清扫会一个都救不回来）
  - 自最小化可恢复：`embed_visible` 识别最小化态改走 SW_RESTORE（软件自己的 − 现在真的会最小化，且没有 Windows 任务栏按钮可点）
  - 跨进程焦点：`embed_focus` 补 `SetForegroundWindow`（顶层窗不再在我们的线程队列里，SetFocus 会静默失败）
  - 单会话关闭：`embed_close` 延迟 3s 解除拥有关系，避免不响应 WM_CLOSE 的窗口被永久拽在 Variable 上
- [x] 验收：− □ × 三个按钮全部是软件自己的，且全部真实可用；拖软件自己的边框能改尺寸
  （实机验收 2026-09-16：Win11 新记事本收编后原生标签/菜单/− □ ×/状态栏完整锐利；点 □ 最大化满屏、点还原复原、拖右下角边框缩放全部实测生效；打字 17 字符直通真实窗口）
- [x] 验收：软件在 125% 缩放下位置正确（重点看非全屏 / 多显示器场景的坐标换算）
