# 维护路线（AURORA-1000 · 步骤 1321~1330 验收对象）

> 本文是 AURORA-1000 收官后的长期维护约定。每一步都有验收口径，不搞口头承诺。

## 1321 · 维护节奏

| 节奏 | 内容 | 触发 |
|---|---|---|
| 周更 | 缺陷修复、文档漂移修正 | 每周一跑 `cargo ktest` / `cargo kcheck` 门禁 |
| 月更 | 功能补全、性能调优、依赖升级（一次一包） | 每月第一个周末，ktest+kbuild 全绿才合入 |
| 安全更 | 安全域（AI-35）漏洞修复 | 发现即发，不受节奏限制 |

## 1322 · 版本生命周期

- 语义化版本：`MAJOR.MINOR.PATCH`；内核 ABI 变更升 MAJOR。
- 当前版本支持周期：最新版 **6 个月** 安全+缺陷修复；上一版 **3 个月** 仅安全修复。
- 每个里程碑（M1~M5）打 tag 冻结快照；tag 永不移动。

## 1323 · 缺陷 SLA

| 等级 | 响应 | 修复时限 | 发版阻断 |
|---|---|---|---|
| S0（崩溃/数据丢失） | 24h | 72h | 是（一处红灯不发版，见 AI-40 `releasegate`） |
| S1（功能错误） | 72h | 2 周 | 是 |
| S2（体验缺陷） | 1 周 | 下一个月更 | 否 |
| S3（打磨项） | 下一个月更 | 酌情 | 否 |

缺陷闭环走 AI-38 `bugtrack`：登记 → 分诊 → 修复 → 验证，100% 闭环。

## 1324 · 性能回归守护

- 每版合入前跑性能门禁（AI-33 `regress.rs`）：帧率、冷启动 < 3s、内存 < 1GB、IO 延迟。
- 回退超过基线 5% 即 FAIL，阻断合入；性能漂移由 `drift.rs` 告警。
- 基线数据归档于 `docs/BASELINE.md`，每 M 里程碑更新。

## 1325 · 安全更新通道

- 安全修复走独立分支 → 安全评审（AI-35 威胁模型重审）→ 合入全部受支持版本线。
- 发布签名校验失败一律拒绝安装（AI-39 `sign.rs`），无降级。
- 安全公告随补丁版本同步发布。

## 1326 · 知识归档续写

- 每个 M 里程碑续写 `docs/知识/<M>-<主题>.md`：根因、教训、边界。
- 真机复盘、发布复盘同目录归档；每版首日完成。

## 1327 · 文档即代码续跑

- 每版跑 `gen-numbers.py`：功能全景图数字 vs 代码 CheckSet 项数，零漂移才放行。
- AI-37 `sync_gate.rs` 门禁随 ktest 执行，文档数字与代码不一致即 FAIL。

## 1328 · 真机矩阵续跑

- 每版对四类真机（Intel 12/13 代、AMD 7000、老 H81、笔记本）重跑 38 项矩阵（步骤 1242~1279）。
- 结果登记 `docs/CHECKSET.md`；全绿才可发版（步骤 1287 门禁）。
- 当前状态：**待环境具备**（无 QEMU / 真机），具备后按 `scripts/真机重跑.sh` 协议执行。

## 1329 · 社区反馈闭环

- 反馈入口：issue + discussion；分诊进缺陷 SLA（1323）。
- 闭环链路：反馈 → 复现 → 登记（bugtrack）→ 修复 → 验证 → 发布 → 回帖告知。
- 反馈→修复→发布的周期计入质量仪表（AI-40 `quality.rs`）。

## 1330 · 「下一座山」路线图

- 方向：NOVA 双形态融合 —— Varix 内核形态与桌面端（Tauri launcher）形态统一为一套
  域模型 + 双前端（裸机 framebuffer / Web UI），复用 CheckSet 门禁与文档即代码体系。
- 前置条件：AURORA-1000 真机矩阵全绿；W2/W3/W4 联调门禁收口。
- 立项标准：新一代功能全景图 ≥ 1000 项、施工手册三部曲齐备后再动工。
