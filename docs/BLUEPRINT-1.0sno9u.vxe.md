## 1. 愿景与总纲

### 1.1 一句话定位

> **把一台「预配置完毕的独立电脑」折叠进 U 盘：插上任意 Windows 电脑，双击展开你的整个数字世界——自研桌面、全部软件、全部浏览器与账号、云端 AI 编程矩阵、8TB 级代码与资产库；拔下时宿主机回到原样，一个字节都不留下。**

### 1.2 它不是什么（边界先行）

| 常见误解 | 如实澄清 |
| --- | --- |
| 是虚拟机 | 不是。没有 Hypervisor、没有来宾内核、没有硬件仿真；它是一个**用户态桌面环境 + 自管理运行时**，性能为原生级别 |
| 是双系统 | 不是。不重启、不写引导、不占宿主磁盘分区 |
| 数据绝对不可见 | 运行期间的内存/显存/网络占用宿主任务管理器**完全可见**；「无痕」指不写宿主磁盘与注册表，不指对抗内存取证 |
| 能屏蔽一切宿主操作 | 不能。Ctrl+Alt+Del、Win+L、UAC 等系统级组合键由更高完整性级别进程处理，用户态只能「尽力遮挡」 |
| 本地大模型引擎 | 不是（v1.0sno9u.vxe 明确放弃本地百亿参数推理）。AI 能力 = 云端工具矩阵 + 本地轻量规则引擎；这让硬件门槛从「RTX 3060+」降到「任意集显轻薄本」 |

### 1.3 设计原则（贯穿一切子系统的公理）

1. **隐私与隔离是默认态，联网是显式授权**：默认零出站；每个出站域名逐条授权、托盘常显、一键全断。云 AI 的便利不兑换成隐私的黑箱。
2. **宿主是垫片，不是家**：只借宿主的三样东西——硬件驱动、网络通路、一块屏幕。不写注册表、不留临时文件、不改 PATH、不装服务。
3. **一切皆便携档**：任何第三方软件进入环境都必须以「便携档」存在（独立目录 + 环境变量重定向 + 图标迁移），宿主机安装版永远只是「候选源」。
4. **套娃即秩序**：环境可以开子环境，子环境可以再开子环境；每一层有独立的容器、壁纸、账号与应用集；层与层之间是「宿主关系」的递归，而非共享状态的纠缠。
5. **如实降级**：能力探测失败就显示失败原因和替代入口，绝不假装成功。
6. **绝不伤害**：任何嵌入、捕获、清理路径都不终止用户进程、不删除用户文件；失败路径永远是「保持原状 + 给出重试入口」。
7. **性能是功能**：启动预算（秒级）、帧预算（输入→像素 < 50ms）、IO 预算（U 盘随机读 < 20ms 响应）写进验收标准，不达标视为功能缺陷。

### 1.4 与三类既有形态的对比

| 维度 | 普通安装软件 | 传统虚拟机 | 本引擎（v1.0sno9u.vxe） |
| --- | --- | --- | --- |
| 部署 | 装进宿主，卸载有残留 | 每台电脑装几十 GB 平台软件 | 双击秒开，零安装 |
| 数据归属 | 散落宿主各处 | 固定宿主磁盘 | 全部在 U 盘容器，随盘走 |
| GPU/性能 | 原生 | 虚拟化损耗大 | 原生（无虚拟化层） |
| 账号与凭据 | 留在宿主 | 留在镜像 | 封存在容器加密区，拔盘即锁 |
| 多环境 | 不支持 | 快照笨重 | 子环境套娃，秒级克隆 |

### 2.2 一次启动的生命周期（目标形态）

```
插入 U 盘
  └─ 双击 SystemLauncher.exe（引导器，几 MB）
       ├─ 探测宿主：WebView2 运行时？→ 无则用容器内便携运行时
       ├─ 挂载/打开存储层：VHDX 或 .uxv 容器（加密容器此时验口令）
       ├─ 选择环境档：默认环境 / 上次离开的子环境 / 新建子环境
       ├─ 拉起 L4 桌面环境（已做：启动仪式 → 桌面 → VWM 就绪）
       ├─ 恢复会话：上次打开的窗口布局、VS Code 工作区、终端 cwd、
       │            云 AI 会话引用（账号会话由各工具自身恢复）
       └─ 进入工作态：L3 服务常驻（白名单网络、凭据金库、拷贝队列…）
            └─ 退出：保存冲刷 → 关闭子环境栈 → 卸容器 → 校验 → 零残留离场
```

### 2.3 容量与介质规划（8TB 场景）

- **介质**：推荐 USB 3.2 Gen2 / Thunderbolt 移动 SSD（8TB）为主介质；普通优盘仅适合 ≤64GB 轻量档。
- **文件系统**：容器所在分区 NTFS 或 exFAT（exFAT 规避 4GB 单文件限制的现代实现已可支撑大文件，但 NTFS 提供更稳的事务语义；引导器自动探测并如实提示）。
- **分卷容器**：单容器文件上限取 8TB；自研 `.uxv` 容器支持**多卷条带**（8TB 拆分为 4×2TB 卷，兼容 FAT32 老设备与云盘中转）。
- **冷热分层**：热区（系统 + 工具链 + 活跃项目，≤256GB）常驻；冷区（历史快照、模型缓存、已完成项目归档）按 chunk 存储、按需加载，支持「挂起项目」一键冷冻/解冻。
- **磨损与寿命**：写放大控制（追加式日志段 + 段回收）、随机小写合并成顺序写（写队列聚合，目标：将 U 盘随机写收敛为 90% 顺序写）。

## 3. 子系统规格

> 每节四段式：目标 / 现状 / 目标形态规格 / 扩展点。现状标注以 v1.0.0 代码库为准（详见 MASTER-PLAN 的状态矩阵）。

### 3.1 L1 存储与容器层

**目标**：把「数据目录」升级为「单文件加密容器」，支撑 8TB 与多卷，拔盘即锁。

**现状（半做）**：数据目录（db/media/backups/recovery/apps.json/logs）已是便携事实标准；U 盘向导、拔出保护（1s 轮询 + WAL checkpoint）已做；无单文件容器。

**目标形态规格**：

1. **三档存储后端**（同一套上层 API，可切换）：
   - `DirBackend`：现状目录（开发模式、调试）；
   - `VhdxBackend`：Windows 原生 VHDX 挂载（快速档，需管理员或默认允许挂载的宿主），BitLocker/`Set-VHD` 加密；
   - `UxvBackend`：**自研单文件容器**（终态，免挂载权限）：
     - 结构：`SuperBlock(魔数/版本/卷表) + ChunkIndex(B+ 树) + 追加式 DataSegments + Journal(事务) + Footer(双副本)`；
     - Chunk 尺寸 4MB（大文件流式）+ 64KB（小文件合并），内容寻址（BLAKE3）去重；
     - 透明压缩：LZ4（热）与 Zstd(19)（冷）按 chunk 级自动选择；
     - 加密：容器级 XChaCha20-Poly1305，密钥由口令 KArgon2id 派生；元数据加密，文件名不可枚举；
     - 事务：journal append → commit record → checkpoint；断电恢复 = 重放未提交段；
     - 多卷：卷表记录卷指纹，跨卷引用透明（8TB 分卷场景）；
     - 快照：chunk 级 COW，子环境克隆 = 零拷贝快照（见 3.10）。
2. **统一访问 API**（Rust trait，全部后端实现同一接口）：
   ```rust
   trait StorageBackend {
       fn open(&mut self, cfg: &OpenCfg) -> Result<()>;
       fn read(&self, path: &VPath, range: Option<Range<u64>>) -> Result<Vec<u8>>;
       fn write(&mut self, path: &VPath, data: &[u8]) -> Result<()>;      // 事务
       fn stream_read(&self, path: &VPath) -> Result<Box<dyn ReadSeek>>;  // 视频等大流
       fn snapshot(&mut self, label: &str) -> Result<SnapshotId>;
       fn gc(&mut self) -> Result<GcReport>;                              // 段回收
       fn seal(&mut self) -> Result<()>;                                  // 退出冲刷+锁
   }
   ```
3. **退出冲刷协议**（对应 MASTER-PLAN M2 验收）：关闭 = 挂起任务 → journal 强制刷盘 + `FlushFileBuffers` → 容器 seal（Footer 写双副本 + 随机尾部填充防残影）→ 卸载/锁定。
4. **容量仪表**：任务栏显示容器水位线、读写放大比、剩余寿命估算（SSD TBW 参考）。

**扩展点**：云盘中转卷（冷区放网盘同步目录，热区本地）；多容器聚合挂载（工作容器 + 娱乐容器同时挂）。

### 3.2 L0/L2 引导器与便携运行时

**目标**：任意电脑双击即开，宿主「缺什么就用容器里的什么」。

**现状（半做）**：NSIS 安装器自动部署 WebView2（Win10）；便携模式已做；引导器为普通 exe 启动。

**目标形态规格**：

1. **SystemLauncher 引导器**（几 MB，Rust 静态编译）：
   - 宿主能力探测矩阵：WebView2 版本 / 架构 / 管理员权限可用性 / 显卡驱动 / 网络连通（仅探测，不发包到第三方）；
   - WebView2 缺失 → 优先使用容器内 **Fixed Version Runtime**（约 200MB，随容器携带），免安装零弹窗；
   - Node.js 便携运行时随容器携带（云 AI CLI 的执行底座），版本由容器管理，不碰宿主 PATH；
   - 多显示器拓扑探测，全屏展开到主屏（副屏可作沉浸副舱，见 3.9）。
2. **权限阶梯**（无管理员也能全功能）：
   - 普通用户态：全部桌面功能 + VHDX 免挂载（UxvBackend）+ 嵌入；
   - 可选管理员：仅影响 VHDX 原生挂载速度与个别设备面板能力，功能缺失如实标注。
3. **启动预算**：引导器探测 ≤300ms；桌面可交互 ≤3s（冷启动，SSD 主机实测口径）。

**扩展点**：引导器 UI（选择环境档 / 口令输入）自绘，保持与桌面环境同一视觉语言。

### 3.3 L2 隔离执行档（Isolation Profile）

**目标**：任何第三方工具在环境里运行时，其全部落盘、凭据、缓存都被重定向进容器——这是「零残留」与「账号封存」的统一底座。

**现状（未做，地基已有）**：第三方登记表（apps.json）已有 `path/target/icon/grade`；嵌入通道已做；缺环境变量重定向与配置目录接管。

**目标形态规格**：

1. **登记模型扩展**（`ThirdApp` → `PortableProfile`）：
   ```jsonc
   {
     "id": "tp-...",
     "name": "Claude Code CLI",
     "exec": { "path": "...", "args": [], "cwd": "..." },
     "env": {
       "redirect": {                      // 强制重定向表（对子进程递归生效）
         "HOME": "{container}/home",
         "USERPROFILE": "{container}/home",
         "CLAUDE_CONFIG_DIR": "{container}/home/.claude",
         "APPDATA": "{container}/home/AppData/Roaming",
         "LOCALAPPDATA": "{container}/home/AppData/Local",
         "npm_config_cache": "{container}/cache/npm",
         "GIT_CONFIG_GLOBAL": "{container}/home/.gitconfig"
       },
       "set": { "VARIABLE_ENV": "profile-id" }
     },
     "net": { "allow": ["api.anthropic.com"] },   // 出站白名单（联合 3.11）
     "icon": "data:...", "grade": "portable"
   }
   ```
2. **重定向执行器**：启动子进程时注入完整环境表；对不守规矩的工具（写死 `C:\Users\...`）启用 **Junction 兜底**——探测到残留路径写入时给出一次性提示，引导用户改用支持重定向的参数（不静默改宿主注册表）。
3. **凭据不入宿主的可验证性**：执行档运行期间提供「残留扫描」命令——扫描宿主 `%USERPROFILE%` 顶层与 `Recent`，报告本次会话新增文件（预期为 0；出现即列出并可选清理）。
4. **模板库**：内置常见工具的重定向模板（Claude Code / Codex CLI / ZCode / Gemini CLI / Git / Node / Python venv / VS Code Portable），登记时自动套用。

**扩展点**：按子环境覆盖重定向表（同一工具在不同子环境使用不同账号——套娃账号隔离的关键，见 3.10）。

### 3.4 L4 VWM 虚拟窗口管理器（环境内一切窗口）

**目标**：环境内的每一个窗口——自研应用、第三方软件、浏览器、终端、子环境入口——都是 VWM 虚拟窗口，统一 Z 序/贴靠/多开/动效。

**现状（已做主体）**：VWM 状态机、拖拽/八向缩放/贴靠/最小化飞行/弹簧动效、多开、几何持久化、第三方窗口嵌入（进程树捕获 + SetParent + 30s 等待 + 不杀进程兜底）全部已做。

**目标形态规格**：

1. **布局快照（Workspace Preset）**：把当前全部虚拟窗口的「类型/几何/贴靠区/所属子环境」存为一键可恢复的预设——「开发工作台」（左 VS Code、右终端）、「分析工作台」（浏览器 + 反汇编 + 笔记）等；登录后自动恢复上次布局。
2. **窗口分组与标签页化**：同一虚拟窗口内多标签（如多个终端合并一个窗口），弥补 8TB 工作量下的窗口爆炸。
3. **嵌入 2.0**：
   - 捕获成功后的**长期监护**：窗口销毁检测 → 虚拟窗口转为「已退出」占位卡（可重开），不静默消失；
   - 多嵌入并发（当前为单嵌入）：以 `hwnd → 虚拟窗口 id` 的映射表取代单例状态；
   - 高 DPI 嵌入修正（Per-Monitor v2 感知同步）。
4. **窗口侧栏（任务管理器）**：环境内查看全部子进程树、CPU/内存/网络占用，可结束进程（仅限本环境启动的进程——按执行档标记过滤，绝不误伤宿主进程）。

**扩展点**：窗口组动画编排（一组窗口联动最小化）；VWM 布局随壁纸主题联动换肤。

### 3.5 L5 应用生态：任意软件、浏览器与图标迁移

**目标**：环境内可以运行任意 Win32 软件、任意浏览器（多 profile 账号隔离），并把「完整软件 + 原生图标」整体搬进容器。

**现状（半做）**：开始菜单扫描 / .lnk 解析 / 便携化（整目录复制进数据目录）/ 原生图标提取（HICON→data URL）/ 深度运行检测 / 删除护栏 已做；缺浏览器专用档与「搬迁向导」。

**目标形态规格**：

1. **便携化 2.0（搬迁向导）**：
   - 向导式三步：选宿主已装软件 → 评估可移植性（扫描安装目录：注册表依赖 / 服务依赖 / 许可检测，输出绿/黄/红评估卡）→ 执行搬迁（复制 + 注册表快照导出为 `portable.reg` 供软件自用 + 启动脚本生成）；
   - 评估不通过的项**如实列出缺什么**（如「依赖 Windows 服务 Fax」），不猜测不硬搬；
   - 搬迁产物自动登记为便携档（3.3 模板）并提取图标。
2. **浏览器矩阵**：
   - 每个浏览器（Chrome/Edge/Firefox/Brave/…）以**容器内用户数据目录**运行（`--user-data-dir` 指向容器路径）——所有 Cookie、登录态、扩展、历史全在 U 盘；
   - **多开 profile**：同一浏览器可拉起 N 个独立 profile（工作号 / 个人号 / 注册小号），任务栏各显示为独立窗口组；Firefox 用 `--profile <dir>`；
   - 浏览器便携模板内置（Chrome 系 / Firefox 系两套参数模板），自动适配安装路径探测（注册表 App Paths + 开始菜单）；
   - 首次运行引导导入宿主浏览器的**书签与密码导出文件**（仅本地文件导入，绝不读取宿主浏览器运行数据）。
3. **图标一致性**：延续已做的 HICON 提取，增加**大图标档**（256px Jumbo 提取）与动态图标（.lnk 图标资源索引手动修正）。
4. **自研软件通道**：环境内构建/产出的可执行物（见 3.8 工具链）一键「收入环境」——自动登记 + 图标 + 执行档，形成自研软件生态闭环。

**扩展点**：软件运行画像（每个应用记录 CPU/IO 峰值，用于健康面板与「该软件是否适合便携」的学习型建议）。

### 3.6 L5 云端 AI 编程矩阵（Claude Code / Codex / ZCode / 任意非本地模型）

**目标**：环境是所有云端 AI 编程工具的「统一母舰」：任意 CLI Agent、任意 IDE 插件、任意 Web 模型，账号各自隔离、凭据封存容器、出站逐域授权。

**现状（未做，通道已备）**：终端未做；执行档未做；网络白名单未做（netconsent 单次确认已做，是白名单的地基）。

**目标形态规格**：

1. **AI Hub 面板**（任务栏常驻入口）：
   - 卡片列表：已安装的 AI 工具（CLI 类：Claude Code / Codex / ZCode / Gemini CLI / Aider…；IDE 类：VS Code 插件态的 Copilot / Cursor 账号；Web 类：任意网页模型收藏夹）；
   - 每张卡显示：登录态（由执行档内配置目录推断，不读凭据本体）、出站域名授权状态、今日用量（本地计数，非遥测）；
   - 一键动作：唤起终端并注入 CLI 别名 / 打开对应 Web 模型 / 检查更新（更新包进容器缓存）。
2. **CLI 工具一键装**：`ai install claude-code` → 在容器内 Node 运行时执行 `npm install -g @anthropic-ai/claude-code`，凭据目录按模板重定向；安装源（npm registry）走白名单授权。
3. **账号体系（任意账户登录/注册）**：
   - **凭据金库 2.0**：Vault 从「敏感条目存储」升级为「账号身份管理器」——每条身份 = { 服务名, 登录方式( Token / OAuth 设备码 / 浏览器会话), 备注, 有效期 }；
   - OAuth 类登录（如浏览器流）：在**环境内浏览器 profile**完成，Cookie 留在容器；CLI 类（Token）：Token 存金库，注入执行档环境变量（`ANTHROPIC_API_KEY` 等），不落明文文件；
   - **注册流**：需要注册新账号时，从 AI Hub 直接打开对应注册页（环境内浏览器 + 独立 profile + 容器内 Cookie），形成「注册→登录→绑定 CLI」闭环；
   - 同一工具**多账号切换**：执行档模板支持多 profile（`CLAUDE_CONFIG_DIR=/home/.claude@work` 与 `@personal`），AI Hub 一键切换。
4. **Web 模型全兼容**：任意网页版模型（ChatGPT/Claude/Gemini/…）即环境内浏览器收藏夹 + 独立 profile，不做逆向、不碰接口协议——网页能力=浏览器能力，如实边界。
5. **会话连续性**：CLI 会话目录（各工具自管）随容器走；AI Hub 显示「上次会话时间」；退出/重进不丢上下文。

**扩展点**：本地轻量规则引擎（词典/推演，已做）与云模型互补，形成「离线兜底 + 在线全速」的双轨。

### 3.7 L2 终端服务（ConPTY）

**目标**：环境内一等公民的多标签终端，是所有 CLI（云 AI、Git、编译器、自研语言）的载体。

**现状（未做）**。

**目标形态规格**：

1. **后端**：Windows ConPTY（`CreatePseudoConsole`），每个终端会话 = 一个可复用虚拟窗口；关闭窗口 = 会话保活后台（display:none 保活哲学复用），重开即回。
2. **前端**：V1 嵌入 Windows Terminal Portable（复用 embed 通道，零渲染代码）；V2 自绘 xterm.js 终端（DOM 层，非 GPU 管线，保持 WebView 生态）。
3. **Shell 栈**：默认 PowerShell + Git Bash（容器内便携 Git）；支持声明任意 shell（cmd/wsl 若宿主有则如实提供）；每个子环境独立 `bashrc`/`profile`。
4. **AI 注入**：新标签页可携带执行档（选择某 AI 工具档）——打开即 `claude` 可用、凭据已注入、白名单已生效。

**扩展点**：终端分屏（同一窗口内 2×2）；命令面板直连（Ctrl+Shift+P 把自然语言请求转发给当前激活的 CLI Agent）。

### 3.8 L5 大型高强度编码体系（编辑器 / 工具链 / 自研语言）

**目标**：在 U 盘上完成「克隆仓库 → 阅读 → 大改 → 测试 → 提交」的完整重型工作流，8 小时高强度不掉链子。

**现状（半做）**：代码空间（PVCCE）擅长「读懂大白话」；写作空间富文本很强；缺重型编辑、LSP、Git 面板与工具链。

**目标形态规格**：

1. **VS Code Portable 为重型编辑主力**（3.5 通道登记 + 执行档重定向 + VWM 嵌入）：扩展缓存、工作区状态全在容器；AI 插件（Copilot/Cursor 账号）凭据走金库。
2. **环境内工具链**（全部便携、不碰宿主 PATH）：Node LTS / Python（venv 在容器）/ Rust（musl-msvc 工具链缓存进容器）/ Go / Git（全局配置与 SSH key 在容器 `.ssh`，key 挂金库引用而非明文）；**自研语言工具链**以同样通道接入——编译器/解释器放进 `tools/<lang>/`，登记进开始菜单与终端 PATH（仅环境内生效）。
3. **大文件与大型项目性能预算**：
   - 万文件仓库索引 < 3s（增量）；100MB 单文件打开 < 1.5s（分块映射，禁止整读）；
   - 全库搜索：Rust 侧 ripgrep 式并行扫描（容器后端流式读），10GB 仓库冷缓存 < 8s；
   - `node_modules` 场景：npm cache 在容器（可选项：重依赖项目缓存放宿主临时盘——需用户显式勾选并展示残留代价，见 MASTER-PLAN 风险表）。
4. **Git 深度集成**：环境内 Git 面板（状态/暂存/提交/分支/差异）；SSH 认证走金库签名代理（key 不以明文出现在磁盘会话之外）；提交签名（gpg/ssh）配置随容器。
5. **PVCCE 与编码闭环**：读懂（PVCCE 大白话）→ 修改（VS Code）→ 验证（终端测试）→ 写回（已做的备份+原子写+回滚）。四步在同一环境内不切出去。

**扩展点**：自研语言 LSP 模板（新语言接入 = 实现 LSP server + 图标 + 登记模板三件事）；代码空间与 VS Code 双向跳转（`xref:` 协议扩展到源码行）。

### 3.9 L4/L5 壁纸与沉浸系统（任意壁纸）

**目标**：环境壁纸「什么都能接」，沉浸模式「哪里都能用」。

**现状（已做主体）**：静态/轮播/视频/网页四类 + Wallpaper Engine 全类型（扫描/导入/scene 走官方控制接口）+ system 让位模式 + 多显示器 + 1:1 无滤镜渲染。

**目标形态规格**：

1. **着色器壁纸（新类型 shader）**：内置 GLSL/SWG 壁纸引擎（复用极光 Ray-Marching 管线），社区壁纸 = 单文件 `.frag`；性能档自动降帧。
2. **引擎直连扩展**：Wallpaper Engine 之外，探测 Lively Wallpaper 格式（开源通用）作为第二引擎源。
3. **沉浸模式**：
   - 双击 Esc（已做）临时进出环境；
   - 「专注舱」：一键隐藏图标/任务栏半透明/通知抑制，仅保留当前 VWM 窗口；
   - 副屏副舱：主屏工作、副屏放壁纸/仪表（多显示器已做，扩展为按屏配置）。
4. **壁纸资产管理**：壁纸库入容器（8TB 场景下的视频壁纸即存即用）；取色主题（壁纸主色 → 环境强调色）列入路线。

### 3.10 L3 子环境系统（套娃）

**目标**：环境内可以创建、进入、切换、克隆任意多个「子环境」——每个子环境是独立的容器剖面（自己的壁纸/账号/软件/工作区），并且**子环境内还能再开子环境**。

**现状（未做，地基已有）**：数据目录结构可参数化；VWM/壁纸/登记表均无「环境档」概念。

**目标形态规格**：

1. **环境档（Environment Profile）**：一个子环境 = `{ 存储剖面(容器内子卷或独立容器), 壁纸配置, 第三方登记表副本, 账号身份集, 工作区目录, VWM 布局快照 }`。切换子环境 = 卸载当前剖面挂载 + 挂载目标剖面 + 重载 Shell 状态（窗口关闭由用户确认，防丢工作）。
2. **嵌套规则（套娃深度）**：
   - 深度上限 3 层（性能与用户心智保护），每层是**完整 Variable 实例**以独立进程运行，其窗口经 embed 通道嵌入父环境的 VWM——「环境里的环境」，视觉上就是套娃；
   - 每层独立的出站白名单：子环境默认**继承父层白名单的子集**（只减不增），跨层凭据默认不共享；
   - 嵌套崩溃隔离：子环境进程崩溃 → 父环境 VWM 显示「子环境已停止」占位卡（可重开），父层不受影响。
3. **模板与克隆**：子环境模板（纯净开发档 / 演示档 / 隔离试验档）；克隆 = 容器快照零拷贝 + 首次写时复制，秒级出「平行世界」。
4. **用途锚定**（写进 UI 文案，防止玄学化）：多身份工作分离（甲方/乙方）、项目级全隔离（依赖互斥）、风险隔离（安全分析子环境，见 3.12）、共享电脑的场景分组。

### 3.11 L3 网络层（白名单 / 代理 / 可观测）

**目标**：默认零出站；需要联网的能力（云 AI、Git 远端、浏览器、更新）按域名显式授权，全程可观测、可一键断。

**现状（半做）**：netconsent 单次弹窗已做；无域名级白名单、无代理配置、无流量观测。

**目标形态规格**：

1. **白名单模型**：规则 = `{ 域名, 端口, 授权对象(某执行档/全局), 有效期(永久/本次), 备注 }`；首次出站弹确认卡（显示目标域名与发起工具）→ 授权写白名单；托盘菜单常显「已授权 N 域名」+ 一键全断开关。
2. **执行手段（用户态，如实边界）**：
   - 环境内代理层：环境内工具默认走本地回环代理（环境自管 HTTP/HTTPS 代理），代理按白名单放行/拒绝——这是**主要执行点**；
   - 直连逃逸的兜底：对不走代理的进程，靠 WFP 是内核能力**不可用**；如实降级为「检测到非白名单直连 → 横幅告警 + 该执行档标记」，并把该工具加入「不受信网络行为」名单（用户决定是否继续用）。此边界写进 UI，不装作能硬断。
3. **代理与网络环境**：全局代理配置（HTTP/SOCKS5，含凭据存金库）——公司网/受限网下环境内工具统一走用户自带代理；DNS 解析跟随代理（远端解析，防泄漏）。
4. **流量仪表**：按执行档统计连接数/上下行（环回代理天然可测），任务栏悬浮图。

### 3.12 L5 安全分析工作台（授权防御性分析）

**目标**：为**授权的**防御性安全研究提供一个隔离的分析环境：样本在子环境里跑、工具在容器里装、结论在笔记里写。定位是防御侧的代码/样本分析，不是攻击工具箱。

**现状（半做）**：PVCCE 具备源码级「大白话解剖」；文件管理器有焚毁；缺二进制分析工具面。

**目标形态规格**：

1. **静态分析套件**（全部离线、容器内）：
   - 文件情报卡：哈希（MD5/SHA1/SHA256/BLAKE3）、熵、文件类型魔数、签名链校验、字符串提取（ASCII/UTF16）、导入表概览（PE 解析器，纯 Rust 自研轻量实现）；
   - 反汇编查看器：集成开源反汇编引擎（capstone 的 Rust 绑定）做**只读浏览级**反汇编（不追求 IDA 级交互）；
   - 脚本分析：JS/VBS/宏类样本的静态特征面板（混淆度量、可疑 API 引用高亮）——规则透明、可导出报告。
2. **动态分析（可选档，依赖宿主能力，如实标注）**：
   - 首选路径：联动 **Windows Sandbox**（宿主已开启该功能时）——样本在宿主沙盒里执行，环境只负责编排与报告收集；未开启则如实提示不可用；
   - 环境内直接执行的「危险模式」仅存在于**专用安全子环境**（3.10 克隆的隔离剖面 + 出站白名单清空 + 快照预创建），并在 UI 常驻红色警示；默认不存在该入口。
3. **网络侧观测**：环回代理的连接日志（域名、时间、执行档）可导出为分析证据；对可疑样本的「断网执行」是一键默认。
4. **合规边界（写进 UI 与文档）**：分析对象必须来自用户拥有合法分析授权的场景（自有样本、CTF、授权红队交付物、防御性研究）；不内置任何漏洞利用/攻击模块；样本入容器的「焚毁」清退路径复用已有安全删除。

**扩展点**：YARA 规则本地扫描器；分析报告一键导出（Markdown/PDF）。

### 3.13 L3/L4 基础功能完备化（文件总线 / 剪贴板 / 搜索 / 通知）

**目标**：把「基础功能」做到不输宿主日常体验的完成度——这是高强度使用一天不烦躁的底气。

**现状（半做）**：文件管理器多标签/右键/回收站/焚毁已做；剪贴板随系统；全局搜索已做；通知已做；缺拷贝队列、剪贴板历史、拖拽增强。

**目标形态规格**：

1. **文件操作总线**：统一拷贝/移动/删除队列（后台执行、进度、暂停/取消、冲突策略记忆：覆盖/跳过/重命名/比对）；**跨边界拷贝一等公民**——宿主 ↔ 环境、容器 ↔ 宿主磁盘、环境 ↔ 子环境三向拖拽与剪贴板复制全支持；长路径（>260 字符）与保留名自动处理；8TB 大文件流式拷贝（零整读）。
2. **剪贴板中介**：环境内剪贴板历史（文本/图像/文件引用，金库标记敏感项自动跳过历史）；跨子环境的剪贴板策略（默认互通，安全子环境默认单向禁出）。
3. **搜索体系**：全局搜索（已做四类命中 + 拼音）扩展到：文件名/内容（容器流式索引，增量）、浏览器书签、AI 会话标题、命令面板命令；一个框搜一切。
4. **通知与自动化**：事件总线统一（拷贝完成/下载完成/AI 会话结束/备份完成）→ 通知中心；简单自动化（「当拷贝队列清空→通知」「当子环境退出→自动快照」）以规则卡配置。
5. **命令面板（Ctrl+K）**：模糊搜索一切可执行物（应用/设置/终端命令/AI 工具），键盘流操作的核心入口。

### 3.14 性能工程（全面性能预算）

| 指标 | 预算 | 手段 |
| --- | --- | --- |
| 冷启动到可交互 | ≤ 3s（SSD 主机） | 引导器轻量化、容器索引常驻缓存、启动事件并行化（已做 boot 真实进度为地基） |
| 输入→像素 | < 50ms | WebView 合成已达标；嵌入窗口直通；禁止主线程 IO |
| 帧稳定 | 120Hz 可选 | 背景降档策略已做（bgTier/reduceMotion）；VWM 动效走合成器线程 |
| 容器随机读延迟 | < 20ms（热 chunk） | chunk 缓存（LRU 512MB 起步）+ 预读 |
| 大仓库索引 | 万文件 < 3s | 增量索引 + 并行扫描（Rust 侧） |
| 内存占用（待机） | ≤ 600MB | 子环境按需挂载；渲染 worker 复用（已做） |
| 8TB 卷 GC 暂停 | < 100ms | 分代段回收，增量推进 |

**性能纪律**：每个里程碑合并前跑基准脚本（MASTER-PLAN 附验收命令），回归 > 10% 即阻断合并。

## 5. 安全模型

1. **资产分级**：凭据（金库，最高）/ 源码与文档（容器加密区）/ 缓存（明文区）。
2. **信任根**：容器口令（Argon2id）→ 主密钥 → 分区密钥；金库独立口令（已有基础）。
3. **威胁面**：
   - 宿主机不可信（网吧）：凭据零落盘（执行档）+ 退出残留扫描 + 容器口令锁；浏览器全程环境内 profile；
   - 容器丢失：全容器加密 + 金库独立口令双保险；
   - 恶意样本：专用安全子环境 + Windows Sandbox 优先 + 断网默认；
   - 供应链：工具链更新走白名单域名 + 版本锁文件（容器内 `locks/` 记录各工具版本与哈希）。
4. **对抗性场景的如实声明**：宿主上的键盘记录器、内存扫描、摄像头/屏幕录制**不在防御范围**——用户态应用无法对抗宿主级监控；此为硬边界，文档与 UI 双写明。

## 9. 本蓝图不做的事（负空间声明）

- 不做本地百亿参数模型推理引擎（明确取舍：云端工具矩阵 + 本地规则引擎双轨）；

```

  → 后台: chunk 压缩(LZ4/Zstd) + 去重索引更新
```

## 14. 附录 A：逐子系统实现要点与预判坑位（来自本仓库既有教训）

> 这些不是通用建议，而是**本仓库已经踩过或预判必然踩**的坑。实现对应批次前先读对应条目。

### 14.1 容器层（B-12…B-17）

- **exFAT 上的大文件**：exFAT 无日志、掉电后文件长度可能回退——journal 必须自带双 Footer 校验，不能信任文件系统元数据；NTFS 上也保留同一套校验（介质不可假设）。
- **fsync 顺序**：`FlushFileBuffers` 在容器文件上的代价远高于普通文件（尤其 U 盘）；checkpoint 频率要按「字节数 + 时间」双阈值触发，且退出 seal 是唯一强制全刷点——运行中绝不逐事务全刷（性能纪律）。
- **BLAKE3 去重的内存代价**：8TB 卷的 ChunkIndex 不能全内存常驻；B+ 树节点页缓存（LRU）+ 顶层常驻、底层按需；索引本身也要分 chunk 存储并自我校验。
- **稀疏卷测试**：真造 8TB 文件会写穿 SSD——测试一律用 NTFS 稀疏文件 + 随机写放大模拟（只触达 1% 扇区但走完整代码路径）。
- **加密后随机访问**：XChaCha20 是流密码，必须按 chunk 独立 nonce（chunk 偏移派生），否则重用 nonce 即灾难——在 trait 文档里写死这一约束。

### 14.2 执行档（B-3…B-6）

- **环境变量注入的继承陷阱**：`cmd /C start` 式中间壳会丢自定义环境（本仓库已弃用 start 拼接，改 ShellExecute——执行档必须同样全程 `CreateProcess` 族，杜绝中间壳）。
- **工具写死路径的探测顺序**：先读工具文档确认支持的重定向变量（如 `CLAUDE_CONFIG_DIR`），再考虑 Junction 兜底——Junction 创建需要的权限在无管理员宿主上可能受限，探测失败要如实降级而不是半生效。
- **`USERPROFILE` 与 `HOME` 的分歧**：Node 系读 `USERPROFILE`（Windows 惯例），MSYS/Git Bash 读 `HOME`——两张都要设，且指向**不同镜像路径**（`home/` 与 `home/msys/`）以防工具互相踩。
- **凭据不能只靠环境变量**：Token 注入 `ANTHROPIC_API_KEY` 后，某些 CLI 会把它再落盘明文——残留扫描要覆盖已知落盘点（各工具 config 文件），命中即告警。

### 14.3 终端与嵌入（B-7、B-20、B-25）

- **ConPTY 尺寸同步**：resize 时宿主端 buffer 与前端渲染区尺寸要原子更新，否则滚动区错位；窗口最小化（display:none 保活）期间 ConPTY 仍需 pump 消息，否则恢复后输出洪峰。
- **Electron 嵌入**：VS Code 主窗口是标准顶层窗口（可嵌），但**子弹窗**（命令面板浮窗等）有独立 HWND——嵌入后弹窗会出现在宿主桌面层；V1 接受此瑕疵并写入已知边界，V2 用窗口归属过滤（同 pid 顶层窗口统一重父级）。
- **Per-Monitor DPI**：嵌入窗口的 DPI 感知取自其自身进程清单；宿主 150% 缩放 + 应用 100% 感知时内容会糊——`embed_bounds` 已用物理像素（已做），还需在捕获时读取目标 DPI 感知上下文并同步虚拟窗口缩放（VWM 2.0）。
- **嵌套实例的键盘焦点**：子环境是独立 Variable 进程，其全局键盘轮询线程（kbdhook）会与父层并发——**嵌套模式下子实例必须以参数禁用全局手势**（手势归父层），否则双 Esc 会两层同时反应。这个坑现在写下来，M6 实现时直接规避。

### 14.4 网络层（B-28）

- **环回代理的证书问题**：HTTPS 拦截式代理需要自签 CA 信任——环境内浏览器 profile 可以注入信任，但**云 AI CLI 用系统证书库**，无管理员时注入受限。取舍：代理默认只做「域名裁决 + 隧道放行」（CONNECT 层，不解密内容），不解密就不需要 CA——白名单在 CONNECT SNI 上判断即可，隐私上也更干净（代理看不到明文）。这个设计选择直接规避了一大类坑。
- **直连逃逸检测**：不能靠 WFP（内核），靠的是「环境内默认网关画像」：代理层记录预期活跃连接集，执行档进程的连接数（`GetExtendedTcpTable` 轮询）超出代理侧记录 → 告警。误报率高，所以只告警不阻断（已定边界）。

### 14.5 子环境（B-24…B-26）

- **嵌套的容器互斥**：两层实例同时打开同一 Uxv 容器会互踩 journal——嵌套子环境必须用**独立容器文件或父容器的只读快照剖面**；这条是硬约束，模型设计时就把「剖面 = 打开方式」编码进去。
- **进程树清理**：父环境退出要收子环境栈；但子环境崩溃后其残留子进程（用户在里面启动的软件）不能被父层**误杀**——清理只对「由子环境执行档启动的进程」生效（执行档标记进程树），宿主进程永不触碰（绝不过界原则的自动化版本）。

### 14.6 桌面与性能（横切）

- **translateZ 包含块**（已验证的关键技巧）：任何新的全屏层（命令面板、AI Hub、子环境切换器）都必须活在 `.vwm-app` 包含块语义之内或明确在其外，否则 WebGL 背景与 fixed 定位会串层。
- **vite HMR 断链**（踩过）：验证前端改动前确认 hmr update 日志，防止「改了没生效」的误判消耗批次时间。
- **windows crate feature 门控**（踩过多次）：函数被多 feature 联合门控（如 CreateJobObjectW 曾需 JobObjects+Security），报 configured-out 先查 feature 依赖链。
- **HWND 跨线程**：HANDLE 非 Send 的惯例已立（isize 中转）；嵌入多并发化时同样适用，映射表用 `Mutex<HashMap<isize, WinId>>`。

## 15. 附录 B：尖锐问答（针对本蓝图的诚实回答）

**Q1 既然不是虚拟机，凭什么是「独立环境」？**
独立性的三根柱子：**数据独立**（容器自包含，宿主零落盘）、**运行独立**（自研桌面与窗口体系，宿主 UI 不可见）、**账号独立**（执行档重定向 + 浏览器 profile，凭据不出容器）。它没有进程隔离内核边界，这一点如实承认——所以高风险执行联动 Windows Sandbox 而不是硬扛。独立环境 ≠ 沙盒，本文档从头到尾维持这个区分。

**Q2 公司电脑上用，会被 IT 检测到吗？**
会被看到「一个进程在跑、占多少内存、连了哪些域名」（运行期资源对宿主可见，第 4 节边界），但看不到你磁盘上留下什么（零落盘）。如果公司策略禁止未授权软件，正确的做法是获得授权，而不是指望技术隐藏——本引擎不做进程隐藏、不做反检测，这是产品哲学不是技术缺陷。

**Q3 8TB 现实吗？**
存储架构按 8TB 设计（分卷、冷热分层、GC），但**体验取决于介质**：USB 3.2 Gen2 移动 SSD 上 8TB 可用且流畅；机械移动硬盘能用但索引与启动会慢（预算表不承诺）；普通 U 盘只适合 ≤64GB 轻量档。诚实结论：容量上限是容器的事，体验下限是介质的事。

**Q4 为什么放弃本地大模型？**
算一笔账：本地跑 30B 级模型需要 24GB 显存（RTX 4090 档）与 20GB+ 权重存储，换来的是「断网可用」；云端 CLI（Claude Code 等）在集显轻薄本上全速运行，效果更强、体积近零。本引擎的目标用户是「在任意电脑写代码」，不是「断网跑模型」。本地规则引擎（词典/推演）保留作为离线兜底。这个取舍写进蓝图第 9 节负空间，不摇摆。

**Q5 嵌入的第三方软件会卡吗？**
嵌入只是窗口父子关系变更，渲染仍是应用自己的进程与 GPU 通道——性能与独立运行**无差异**（这正是相对虚拟机方案的核心优势）。已知瑕疵是 Electron 子弹窗归属问题（附录 A 14.3），如实标注。

**Q6 胶囊坏了/丢了怎么办？**
三层恢复：容器 journal 掉电自愈（B-13）；快照（任意环境档可回滚到任意时点）；**外部备份**——引导器提供「胶囊镜像导出」（容器冷区导出为多卷归档，可放网盘）。口令丢了没有后门（Argon2id + 无托管密钥），文档与 UI 都要写明：口令即数据。

**Q7 支持多显示器吗？**
支持（已做）：壁纸按显示器配置、环境全屏主屏。规划：副屏副舱（沉浸仪表/第二工作区）、子环境指定显示器打开。Ctrl+Alt+Del 类系统 UI 仍由 Windows 接管（边界清单）。

**Q8 Linux / macOS 宿主呢？**
v1.0sno9u.vxe 只承诺 Windows 10/11 x64（Win32 嵌入、ConPTY、ShellExecute 全是 Windows 通道）。macOS/Linux 的等价通道完全不同（无 SetParent 等价物、不同 PTY/合成体系），作为远期独立评估项，不在本版本范围。

**Q9 与 WSL / Windows Sandbox 是什么关系？**
互补而非竞争：WSL 适合 Linux 工具链（可从环境终端调用，宿主有则如实提供入口）；Windows Sandbox 用于高风险样本执行（M9 联动）。本引擎的价值层在「桌面环境 + 账号/数据隔离 + AI 矩阵」，不重复造虚拟化轮子。

**Q10 安全分析工作台的合法性边界？**
定位为**授权防御性分析**：自有样本、CTF、授权测试交付物、防御研究。不内置攻击模块、不提供逃逸/免杀能力；样本执行默认断网 + 专用子环境 + Sandbox 优先；UI 常驻合规提示。这些边界写进代码结构（危险入口默认不存在），而不是写在口头协议里。

**Q11 为什么 UI 不做成纯 GPU 自绘？**
评估过（前版方案）：纯着色器 UI 的成本（排版/无障碍/输入法/命中测试）远超收益，而 WebView2 渲染已满足性能预算。资源优先投给容器、执行档、云 AI 矩阵这些「别人没有的东西」，而不是重造一个浏览器排版引擎。若未来帧预算不达标，再评估局部离屏合成（蓝图 3.4 的 VWM 2.0 已预留纹理化路径）。

**Q12 这套东西和「把 portable 软件拷 U 盘」有什么本质区别？**
三个量级差异：① **账号与凭据的系统性封存**（执行档 + Vault 2.0 + 浏览器 profile，而不是靠各软件自觉）；② **一个完整桌面环境**（VWM/贴靠/多开/嵌入，而不是一堆散装窗口）；③ **容器化与套娃**（单文件加密容器 + 快照克隆 + 环境嵌套）。拷 U 盘是文件搬运；本引擎是给这些文件一个「会自己管理自己的家」。

## 16. 附录 C：版本演进与容器 Schema 迁移策略

> 胶囊的寿命以「年」计，容器里存的是数年积累的工作资产——**格式演进不能靠重装**，必须有一等公民的迁移机制。

### 16.1 三层版本号与兼容矩阵

| 层 | 载体 | 规则 |
| --- | --- | --- |
| 引擎版本 | 应用 semver + `1.0sno9u.vxe` 代号 | 向下兼容读取 N-1 个大版本的容器 |
| 容器 Schema 版本 | SuperBlock.schemaVersion（u32） | 只增不减；旧引擎读到不认识的版本 → 明确拒绝并提示升级，绝不猜测性解析 |
| 登记表/配置版本 | apps.json vNext、白名单库版本 | serde default 渐进扩展（既有惯例） |

### 16.2 迁移协议（M2 起生效）

1. **打开时惰性检查**：容器 schemaVersion < 引擎支持 → 提示「此胶囊由旧版本创建，升级后旧引擎将无法打开（附回退说明）」，用户确认后执行；
2. **迁移即事务**：迁移在 journal 中作为原子事务执行，失败自动回滚到旧 schema（迁移前自动打快照，标签 `pre-migrate-v<N>`）；
3. **迁移不重写数据段**：只升级 SuperBlock/索引层；数据 chunk 内容寻址不变——迁移耗时与资产量无关（秒级）；
4. **回退通道**：保留上一个引擎版本的便携运行时于 `system/prev-engine/`（可选下载），配合 pre-migrate 快照实现「升级后悔药」；
5. **字段废弃纪律**：删除字段前必须经过一个「标记 deprecated → 双读 → 移除」的完整大版本周期。

### 16.3 引擎自更新（胶囊内）

- 更新源走白名单（GitHub Releases 域名显式授权）；更新包哈希锁（`locks/engine`）；
- 差量更新：引擎二进制与容器分离，更新只替换 `system/engine/`，容器零接触；
- 更新失败（哈希不符/断电）：旧引擎原样保留，双份引擎目录切换启动（A/B），引导器选健康侧。

| `sys://wintab` | 无 | R→F | ✅ | Win+Tab 切换器唤起 |
| `sys://open-system` | `{kind, path?}` | R→F | ✅ | 快捷键打开 VWM 系统窗口 |
| `sys://quit-request` | 无 | R→F | ✅ | Del+Backspace 真退出（kbdhook） |

**规则**：事件名必须带命名空间前缀（`<域>://<动作>`）；载荷必须是可 JSON 序列化的扁平对象；破坏性载荷变更 = 版本号新事件（`v2` 后缀）+ 旧事件一个版本的退役期。

## 22. 附录 I：扩展包协议（`.uxpack.json`）

> 拓展性的落点：壁纸、AI 提供方、应用模板、语言工具链四类生态内容，全部走**同一个声明式扩展包**格式进环境——不写代码也能扩展。

### I.1 包结构

```
<包名>.uxpack/
├─ uxpack.json          清单（唯一契约入口）
├─ assets/              壁纸/图标/截图
├─ templates/           执行档模板 / 工具链部署脚本
└─ wallpapers/frag/     着色器壁纸（.frag + 元数据）
```

### I.2 清单 Schema（v1）

```jsonc
{
  "uxpack": 1,
  "id": "com.example.devpack",
  "name": "Example Dev Pack",
  "version": "1.0.0",
  "engine": ">=1.2",                     // 引擎 semver 区间
  "kind": ["wallpapers", "ai-providers", "app-templates", "toolchains"],
  "wallpapers": [
    { "type": "image|video|web|shader", "entry": "assets/x.jpg",
      "name": {"zh": "星河", "en": "Galaxy"} }
  ],
  "aiProviders": [
    { "id": "claude-code", "displayName": "Claude Code",
      "runtime": "node", "install": "npm i -g @anthropic-ai/claude-code",
      "env": { "CLAUDE_CONFIG_DIR": "{home}/.claude" },
      "net": ["api.anthropic.com"],      // 请求的出站白名单（安装时弹授权）
      "auth": "token|oauth-browser" }
  ],
  "appTemplates": [
    { "name": {"zh": "..."}, "exec": {...}, "envRedirect": {...}, "icon": "assets/i.png" }
  ],
  "toolchains": [ { "id": "python", "deploy": "templates/py.ps1", "pathAdd": "{root}/runtime/py" } ]
}
```

### I.3 安装与信任模型

- **安装** = 解包进容器 `extensions/<id>/` + 清单登记 + **逐项授权**（出站域名走 netconsent 白名单弹窗；执行档模板展示重定向表供确认）；
- **签名**：v1 可未签名（本地自建包），分发包要求 Ed25519 签名（公钥内置于引擎；密钥轮换走双公钥过渡）；
- **卸载** = 删目录 + 登记回收 + 该包申请的白名单域自动撤销（闭合！扩展的权限随卸载消失）；
- **审计**：扩展清单键面纳入 `tools/audit.cjs`（未知 kind/字段 → 红）。
