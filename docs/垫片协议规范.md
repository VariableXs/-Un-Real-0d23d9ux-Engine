# VARIX 垫片协议规范（任务 22 · AI-V＋AI-B）

> 定位：Variable 前端（Tauri 版与内核 Servo 版共用同一份代码）与后端服务之间的统一 IPC 协议。
> 单一事实源：`tools/shim-protocol.source.json`；双侧类型由 `node tools/gen-shim-protocol.cjs` 同源生成：
> - 前端：`src/lib/shim/protocol.ts`
> - 后端：`src-tauri/src/shim_protocol.rs`
> 禁止手改生成物；改协议 = 改 source.json → 再生成 → 跑双侧用例。

## 1. invoke 名命名空间

- 命令名**原文透传**：现有 `snake_case` 命令名（如 `embed_bounds`、`set_settings`）保持不变，垫片不改名、不加前缀。
- 新增命令必须 `snake_case`，且在任务 23 三色映射表登记归属后才允许进入 `generate_handler!`。
- 能力位目录见 source.json `capabilities[]`；命令 → 服务归属由映射表数据驱动，**加命令不改垫片代码**。

## 2. 参数序列化

- 参数为 JSON 对象，**一次序列化**，禁止二段封装（不得把对象再 stringify 塞进字符串字段）。
- `args` 缺省视为空对象 `{}`。
- 前端 `ipc.ts` 是既有唯一 invoke 出口；垫片新增出口为 `src/lib/shim/shimInvoke.ts`（传输层注入式：Windows 侧包 Tauri invoke，内核侧注入内核传输），零裸 invoke 绕过（沿用 audit.cjs 门禁）。

## 3. 错误码三段式

| 段 | 传输形态 | 语义 |
|---|---|---|
| OK | 载荷直达 | 正常返回，无包装 |
| MAPPED_ERR | `{"__shim_error":{"code","message"}}` | 命令存在但执行失败，code ∈ 错误码表 |
| MISSING | `{"__shim_missing":"<cmd>"}` | 命令在映射表无归属 |

错误码表（retryable 同源自 source.json）：SHIM_INVALID_ARGS / SHIM_UNSUPPORTED / SHIM_TIMEOUT / SHIM_BACKEND_DOWN / SHIM_VERSION_MISMATCH / SHIM_PERM_DENIED / SHIM_INTERNAL。

约束：错误文案必带 i18n 词条（audit i18n 门禁扩展到垫片降级文案）；**零裸错误码直出**（体验红线）；MISSING 降级不得产生半改副作用。

## 4. 事件反向通道

后端→前端 emit，频道名与语义和 Tauri event 同构；枚举见 source.json `events[]`（boot://event、settings://changed、sys://*、embed://*、usb://*、taskbar://state、watch://escape）。新增频道必须先入 source.json 再生成。输入总线预留频道 `shim://input`（任务 26）。

## 5. 版本协商

- 前端启动第一步调 `shim_hello`（`shimInvoke.shimHello()`），应答 `{protocolVersion, backendVersion, capabilities[]}`。
- 判定：`protocolVersion === SHIM_PROTOCOL_VERSION && backendVersion >= SHIM_MIN_BACKEND_VERSION`；不满足抛 `SHIM_VERSION_MISMATCH` 并走降级面。
- 能力位查询 `shimCapability(flag)`；未握手一律 false（调用方按 UNSUPPORTED 降级，不静默）。

## 6. 变更流程

1. 改 `tools/shim-protocol.source.json`（semver 定级：加能力位/错误码=minor；改既有字段语义=major）。
2. `node tools/gen-shim-protocol.cjs` 再生成双侧类型。
3. 跑双侧用例（`npx vitest run src/lib/shim` + `cargo test -p variable --lib`）+ tsc 门禁。
