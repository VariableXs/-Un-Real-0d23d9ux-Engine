## 3. 同步纪律（文件夹 / docs / GitHub 三处一致）

### 3.1 每次提交的固定动作
1. 代码改动 → 仓库对应目录；文档改动 → `docs/`（主册、三份分工册只在这一个目录维护，禁止出现第二份拷贝）。
2. 提交信息格式：`<域/AI-xx>: <一句话>（Fxxx-Fxxx）`。
3. push 失败处理：GitHub 间歇超时是已知常态——**本地提交不丢**，继续干活，网络恢复后 `git push origin main` 按序补推；禁止 force push、禁止跳过钩子。

### 3.2 每个里程碑达成的固定动作
1. 总表本行状态改「里程碑达成」+ 判据证据三件套链接。
2. 主册《Varix STAR I start.md》对应锚点处登记（F200/F375/F400/F550/F575/F600 六锚点递进纪律）。
3. push 后核对远端 hash 与本地一致（`git log origin/main -1` 比对）。

### 3.3 收官同步（M-G 后一次性）
- `docs/` 四册终版 + 《完成报告》新增；
- 全仓库 push 并确认干净（`git status` 零未提交）；
- GitHub 仓库页核对最新 commit 与本地 hash 一致。
